In June 2012, I needed Windows Live Messenger again.

I installed it.

Or tried to.

The process took so long that I wrote a complaint:

installing Messenger took longer than installing the operating system.

Then I offered two possible explanations.

Either I had become old,

or they had overdone it.

That is a perfect little software memory because both explanations can feel true at the same time.

Software gets more complicated.

Users get less patient.

A program remembered as simple returns years later wearing an ecosystem.

Installer.

Updater.

Account integration.

Optional components.

Terms.

Services.

Dependencies.

Progress screens.

Something that once felt like a small tool starts behaving like infrastructure.

The user asks:

I only wanted Messenger.

Software replies:

Excellent. First let us discuss the platform.

This is one of the recurring tragedies of successful applications.

They begin by doing one thing well.

People like them.

Success creates opportunity.

Add features.

Add integration.

Add sharing.

Add identity.

Add monetization.

Add companion services.

Add automatic updates.

Add everything the organization believes will increase value.

Eventually the original task becomes hidden inside the product built around it.

This is sometimes called bloat.

But “bloat” can be too easy a criticism because every added feature was probably requested by someone.

A feature rarely enters software because a developer randomly wanted another menu.

There are business goals.

Security needs.

Compatibility requirements.

User requests.

New devices.

New regulations.

New markets.

The product grows because the world around it grows.

The problem is cumulative.

Each addition is defensible.

The total becomes absurd.

Messenger's installation feeling larger than Windows was obviously rhetorical.

The old entry records perception, not benchmark data.

I did not time both installations with a stopwatch.

The complaint means:

This simple program now demands far more ceremony than I remember.

That is enough.

User experience is comparative.

People do not judge software only by objective speed.

They compare the effort with the mental size of the task.

If I install an operating system, I expect waiting.

The operating system controls the computer.

Large task.

If I install a chat application, I expect:

download,

install,

chat.

When the small task produces large ceremony, every minute feels longer.

This is the same mismatch that made a four-day domain redirect memorable.

Effort should feel proportional to purpose.

When it does not, users become angry.

There is also nostalgia hidden in the complaint.

Messenger belonged to an earlier internet identity.

Contact list.

Status message.

Online.

Away.

Busy.

Nudge.

Chat window.

For many users, it was not merely software.

It was where evenings happened.

You came home.

Logged in.

Saw who was online.

Conversation emerged from presence.

Modern messaging often assumes persistent availability.

Messages wait.

Phones notify.

People are never fully offline.

Messenger culture had a clearer threshold.

Someone could literally not be there.

Offline had meaning.

That made logging in an event.

By 2012, that world was already changing.

Social networks and smartphones were reshaping communication.

Perhaps needing Messenger again felt slightly archaeological even then.

The old entry does not say why I needed it.

That detail is absent.

The installation itself became the story.

This is typical of aging software.

You return for one reason and discover the product has evolved without you.

The interface moved.

The installer changed.

Your old habits no longer fit.

You experience a tiny version of returning to a neighborhood after years away.

The street exists.

The shops are different.

You know where you are and still feel lost.

Then comes the line:

Maybe I got old.

Technology gives us unusually frequent opportunities to feel old because interfaces change faster than most physical environments.

A door handle can remain understandable for decades.

A familiar application can become unrecognizable in three years.

The user blames themselves.

Where is the button?

Why is this difficult now?

Did I forget?

Sometimes yes.

Sometimes the design truly became more complicated.

Aging and product change interact.

You have less willingness to relearn things whose old version already worked.

This is not necessarily cognitive decline.

It can be accumulated standards.

At twenty, a new interface is an adventure.

Later, you have work to do.

You do not want discovery.

You want the function.

Novelty competes with time.

This is why experienced users can become conservative about tools.

Not because they hate progress.

Because migration has cost.

Learn shortcuts.

Transfer data.

Rebuild habits.

Find settings.

Every redesign spends a small amount of user trust.

If the improvement is large enough, fine.

If not, the user asks the most dangerous question in software:

Why did you touch it?

Windows Live Messenger also represents an era when desktop software installation itself was more visible.

Today many services run in browsers or arrive through streamlined app stores.

Installation is less often a ceremony involving downloaded executables and multiple steps.

But software complexity did not disappear.

It moved.

Account creation.

Permissions.

Cloud sync.

Subscription selection.

Two-factor authentication.

Privacy settings.

The friction changes shape.

The human desire remains:

Just let me use the thing.

This sentence should be printed above every product meeting.

Just let me use the thing.

It does not mean features are bad.

It means the path to the core value should remain obvious.

A communication app should help people communicate before asking them to appreciate its ecosystem.

A camera should let you take a photograph.

A writing tool should let you write.

The core action is the contract.

Everything else is optional until proven otherwise.

Successful software organizations can lose sight of this because they experience the product from inside.

Teams see architecture, strategy, integration, roadmap, engagement.

Users see:

I need to send a message.

Different scales.

The best product design translates between them.

The worst makes the user carry organizational complexity.

That is when installation starts feeling longer than an operating system.

The 2012 entry's final ambiguity still works:

Maybe I was getting old.

Maybe they had overdone it.

The mature answer is probably:

both processes were happening.

Software was expanding.

My tolerance for unnecessary ceremony was shrinking.

That combination has only become more familiar.

Every year, technology becomes capable of more.

Every year, I appreciate simplicity more.

Perhaps that is not aging badly.

Perhaps it is finally learning that capability and usability are different achievements.

Messenger could do more.

I only wanted to talk to someone.
