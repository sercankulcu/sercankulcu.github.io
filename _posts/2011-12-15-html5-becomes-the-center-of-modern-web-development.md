By December 2011, "HTML5" had become both a technical specification and a marketing term that redefined expectations for what the web could do. The W3C had published the first public working draft of the HTML5 specification in January 2008, and the final W3C Recommendation would not arrive until October 28, 2014; but browser vendors were implementing features incrementally without waiting for the specification to freeze. The practical trigger for accelerated HTML5 adoption had been Steve Jobs's April 2010 "Thoughts on Flash" open letter, which explained why the iPhone and iPad would never support Adobe Flash and positioned HTML5 as the appropriate open standard for web video and interactive content. Flash had dominated rich internet applications since the late 1990s: at its peak in 2010, approximately 97 percent of web browsers had Flash installed and most video sites (including YouTube and Vimeo) delivered video through Flash players. HTML5's `<video>` and `<audio>` elements offered native browser-level media playback, but the codec debates complicated adoption: Apple supported H.264/MPEG-4 AVC (proprietary, royalty-bearing via MPEG-LA, but hardware-accelerated in Apple devices); Mozilla and Opera refused to ship H.264 support and backed Ogg Theora (royalty-free); Google's acquisition of On2 Technologies produced VP8, which Google open-sourced as WebM in May 2010. YouTube began offering an HTML5 video experiment in January 2010, but codec inconsistency meant developers still needed fallback Flash players for most of the following two years.

The `<canvas>` element, originally introduced by Apple in 2004 for the Dashboard widget system and adopted into Safari's WebKit, enabled scriptable 2D pixel-level drawing directly in the browser without a plugin: game engines, data visualization libraries, and image editors could render to canvas using JavaScript. Web Workers (browsers: Chrome 4, Firefox 3.5, Opera 10.6, IE 10) provided background JavaScript threads that could perform computations without blocking the UI thread. WebSockets (browsers: Chrome 6, Firefox 6, Opera 11) enabled full-duplex persistent connections for real-time applications. The Geolocation API allowed web pages to access the device's location with user permission. localStorage and sessionStorage (Web Storage API, specified alongside HTML5) provided client-side key-value storage beyond the 4KB limit of HTTP cookies, enabling offline-capable web applications when combined with the Application Cache API (later deprecated, replaced by Service Workers). HTML5's semantic markup elements — `<article>`, `<section>`, `<nav>`, `<header>`, `<footer>`, `<aside>`, `<main>` — provided meaning to document structure that `<div>` and `<span>` could not express, improving accessibility (ARIA landmark mapping) and search engine understanding of page structure.

The fragmentation problem in 2011 was real and severe. Internet Explorer 9 (March 2011) was Microsoft's first IE release with significant HTML5 support — including `<video>`, `<canvas>`, SVG inline, CSS3 transitions, and HTML5 form validation — but IE9 did not run on Windows XP, which still held approximately 45 percent of the desktop Windows market. IE8 (34 percent of browser usage in 2011) supported almost none of the new APIs. Firefox 7 and Chrome 15 (released in late 2011) had substantially more complete implementations but their own gaps in WebGL, Web Audio API, and WebRTC. The JavaScript library Modernizr (initial release 2009) became the standard tool for feature detection — testing whether a specific API was available in the current browser rather than inferring support from the user agent string — enabling developers to load polyfills for missing features. The polyfill ecosystem (Respond.js for CSS3 media queries in IE6-8, HTML5Shiv for semantic elements in IE, ExplorerCanvas for `<canvas>`) allowed progressive enhancement: sites used HTML5 features where available and fell back gracefully in older browsers. jQuery (1.7 released November 2011) abstracted cross-browser JavaScript inconsistencies at a lower level. The combined picture in December 2011 was a web platform in rapid transition: the technology was clearly advancing toward becoming a full application platform, but the installed base of IE8 meant that production web applications would need to maintain compatibility for another two to three years before relying on HTML5 APIs without fallbacks.
