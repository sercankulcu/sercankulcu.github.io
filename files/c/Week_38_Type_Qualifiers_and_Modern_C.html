Type Qualifiers, Inlining, and Modern C

The features left over — each small, each occasionally essential. Two of them are promises to the optimizer that it cannot verify, one is the bridge to hardware programming, and one is a control-flow construct most C programmers never use and should recognize when they meet it.

By the end of this week you can
  • Say what volatile actually prevents, and what it does not.
  • Apply restrict correctly and see the difference in the generated code.
  • Use inline and static inline and explain C's inline rules.
  • Write compound literals and anonymous unions where they make code clearer.
  • Say why variable-length arrays are risky and recognize setjmp/longjmp.

1volatile

volatile tells the compiler that an object may change by means it cannot see, so every read must actually read and every write must actually write, in program order, with no caching in registers and no elimination of "redundant" accesses.

/* without volatile, the compiler may hoist the load out of the loop */
while (flag == 0) { }              /* becomes an infinite loop at -O2 */

volatile int flag;
while (flag == 0) { }              /* re-reads memory every iteration */

Three legitimate uses, and only three:

UseWhy
Memory-mapped hardware registersThe device changes the value; reading may itself have an effect. Week 50.
A variable shared with a signal handlerMust be volatile sig_atomic_t. Week 39.
A variable modified across setjmp/longjmpOtherwise its value after a jump is indeterminate.

volatile is not for threads. It guarantees the access happens; it guarantees nothing about atomicity, and nothing about ordering relative to other variables. volatile int counter; counter++; is still a data race — the increment is a load, an add, and a store. Use <stdatomic.h>, which week 41 covers. This misconception is widespread and produces bugs that appear only under load.

2restrict

Week 36 introduced it as a promise: within this scope, the object reached through this pointer is reached through no other. The payoff is visible in the generated code.

void add_plain(int *dst, const int *a, const int *b, size_t n)
{
    for (size_t i = 0; i < n; i++) dst[i] = a[i] + b[i];
}

void add_restrict(int *restrict dst, const int *restrict a,
                  const int *restrict b, size_t n)
{
    for (size_t i = 0; i < n; i++) dst[i] = a[i] + b[i];
}

In the first, dst[i] might alias a[i+1], so the compiler must store and then reload on every iteration — no vectorization. In the second it may load a block of a and b, add them with vector instructions, and store a block.

The promise is unchecked, and violating it is undefined behavior with no diagnostic. This is exactly the contract that distinguishes memcpy from memmove.

register

Obsolete as an optimization — compilers have allocated registers better than humans since the 1980s. It retains one effect: you cannot take the address of a register object, which occasionally documents intent. C23 gives it no new meaning. You will meet it only in old code.

3inline

C's inline rules differ from C++'s and confuse people reliably.

/* In a header — this is the form to use. */
static inline int max_int(int a, int b)
{
    return a > b ? a : b;
}

static inline in a header is the practical answer. Each translation unit gets its own copy with internal linkage, so there is no multiple-definition problem and the compiler inlines it freely. This is the modern replacement for a function-like macro, and it fixes both macro hazards from week 28: arguments are evaluated once, and the result is type-checked.

Plain inline without static provides an inline definition that is not an external definition, so if the compiler chooses not to inline a call you get an undefined reference unless exactly one translation unit also provides an external definition. The rule is unintuitive and the reason most codebases simply write static inline.

In all cases inline is a hint. The compiler inlines small functions at -O2 whether or not you ask, and declines large ones whatever you say.

4Compound literals and anonymous members

A compound literal creates an unnamed object of a given type, in place:

draw_point((Point){ .x = 3, .y = 4 });          /* no temporary variable */

int *table = (int[]){ 1, 1, 2, 3, 5, 8 };       /* an unnamed array */

config = (Config){ 0 };                          /* reset every field */

Its lifetime is that of the enclosing block, so returning a pointer to one from a function is the dangling-pointer bug of week 13 in a new costume.

Anonymous structures and unions (C11) let a nested member be accessed as though it were direct — which makes week 22's tagged union considerably more readable:

typedef struct {
    ValueKind kind;
    union {                          /* no member name */
        int    as_int;
        double as_double;
    };
} Value;

v.as_int = 42;                       /* not v.data.as_int */

5Variable-length arrays

void process(size_t n)
{
    int buffer[n];              /* size decided at run time */
    …
}

Added in C99, made optional in C11 — an implementation may define __STDC_NO_VLA__ and refuse them, and MSVC never supported them. That alone disqualifies them from portable code.

The larger problem is that a VLA is on the stack and there is no way to detect failure. Week 17 established that stack overflow is a fatal signal, not a return value. A size derived from input turns that into a remotely triggerable crash:

void handle(size_t count)      /* count came from the network */
{
    int buffer[count];         /* count = 10000000 kills the process */
}

Use malloc, whose failure you can check, or a fixed-size buffer with an explicit bound. VLAs are worth recognizing in existing code and worth avoiding in new code.

Variably modified parameter types are a different matter and remain useful — week 16's void f(size_t rows, size_t cols, int m[rows][cols]) allocates nothing and lets the compiler compute correct offsets.

6_Noreturn, setjmp, and longjmp

_Noreturn void fatal(const char *message)      /* C11; [[noreturn]] in C23 */
{
    fprintf(stderr, "fatal: %s\n", message);
    exit(EXIT_FAILURE);
}

Declaring that a function never returns lets the compiler drop the code after a call to it and improves its warnings — no "control reaches end of non-void function" after a call to fatal.

Non-local jumps

#include <setjmp.h>

static jmp_buf recovery;

if (setjmp(recovery) == 0) {
    deep_call_chain();              /* may longjmp back here */
} else {
    /* arrived via longjmp: handle the failure */
}

/* somewhere far below */
longjmp(recovery, 1);               /* unwinds straight back */

This is the closest C has to an exception, and it is a blunt instrument. setjmp records the machine state; longjmp restores it, discarding every intervening frame — without running any cleanup. Every file left open and every block allocated between the two is leaked.

Further rules: the jmp_buf is invalid once the function that called setjmp returns, and any local modified between setjmp and longjmp must be volatile or its value is indeterminate afterwards.

Legitimate uses are rare — a parser abandoning a deeply nested descent, or a test harness recovering from a failed assertion. Week 27's error contract is the right tool for everything else.

7Worked example: seeing the qualifiers work

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>
#include <stdbool.h>
#include <setjmp.h>
#include <time.h>

#define N 2000000
#define REPS 50

static double now(void)
{
    struct timespec t;
    clock_gettime(CLOCK_MONOTONIC, &t);
    return (double)t.tv_sec + (double)t.tv_nsec / 1e9;
}

/* ---------- restrict ---------- */

static void add_plain(int *dst, const int *a, const int *b, size_t n)
{
    for (size_t i = 0; i < n; i++) dst[i] = a[i] + b[i];
}

static void add_restrict(int *restrict dst, const int *restrict a,
                         const int *restrict b, size_t n)
{
    for (size_t i = 0; i < n; i++) dst[i] = a[i] + b[i];
}

/* ---------- static inline replaces a macro ---------- */

#define MAX_MACRO(a, b) ((a) > (b) ? (a) : (b))     /* evaluates twice */

static inline int max_int(int a, int b)             /* evaluates once */
{
    return a > b ? a : b;
}

static int side_effect_count = 0;
static int with_side_effect(int v)
{
    side_effect_count++;
    return v;
}

/* ---------- compound literals ---------- */

typedef struct { int x, y; } Point;

static int manhattan(Point a, Point b)
{
    int dx = a.x - b.x, dy = a.y - b.y;
    return (dx < 0 ? -dx : dx) + (dy < 0 ? -dy : dy);
}

/* ---------- anonymous union ---------- */

typedef enum { V_INT, V_DOUBLE, V_TEXT } VKind;

typedef struct {
    VKind kind;
    union {                            /* anonymous: C11 */
        int    as_int;
        double as_double;
        char   as_text[16];
    };
} Value;

static void value_print(const Value *v)
{
    switch (v->kind) {
    case V_INT:    printf("  int    %d\n", v->as_int);       break;
    case V_DOUBLE: printf("  double %g\n", v->as_double);    break;
    case V_TEXT:   printf("  text   \"%s\"\n", v->as_text);  break;
    }
}

/* ---------- _Noreturn ---------- */

_Noreturn static void fatal(const char *msg)
{
    fprintf(stderr, "fatal: %s\n", msg);
    exit(EXIT_FAILURE);
}

/* ---------- setjmp / longjmp ---------- */

static jmp_buf recovery;

static void level_three(int depth)
{
    printf("    level three, depth %d\n", depth);
    if (depth > 2) {
        puts("    jumping back, skipping every frame between");
        longjmp(recovery, depth);       /* no cleanup runs */
    }
}
static void level_two(int depth)   { printf("   level two\n");  level_three(depth); }
static void level_one(int depth)   { printf("  level one\n");   level_two(depth); }

int main(void)
{
    puts("== restrict: the same loop, two contracts ==");
    int *a   = malloc(N * sizeof *a);
    int *b   = malloc(N * sizeof *b);
    int *dst = malloc(N * sizeof *dst);
    if (a == NULL || b == NULL || dst == NULL) fatal("out of memory");

    for (size_t i = 0; i < N; i++) { a[i] = (int)i; b[i] = (int)(i * 2); }

    double t = now();
    for (int r = 0; r < REPS; r++) add_plain(dst, a, b, N);
    double plain_secs = now() - t;

    t = now();
    for (int r = 0; r < REPS; r++) add_restrict(dst, a, b, N);
    double restrict_secs = now() - t;

    printf("  without restrict : %.4f s\n", plain_secs);
    printf("  with restrict    : %.4f s\n", restrict_secs);
    printf("  ratio %.2fx (check the assembly for vector instructions)\n",
           plain_secs / restrict_secs);
    printf("  last element %d, both versions agree\n", dst[N - 1]);

    puts("\n== static inline versus a macro ==");
    side_effect_count = 0;
    int m1 = MAX_MACRO(with_side_effect(3), with_side_effect(5));
    printf("  MAX_MACRO gave %d after %d calls  <-- evaluated twice\n",
           m1, side_effect_count);

    side_effect_count = 0;
    int m2 = max_int(with_side_effect(3), with_side_effect(5));
    printf("  max_int   gave %d after %d calls  <-- evaluated once\n",
           m2, side_effect_count);

    puts("\n== compound literals ==");
    printf("  manhattan((0,0),(3,4)) = %d   no temporaries declared\n",
           manhattan((Point){ .x = 0, .y = 0 }, (Point){ .x = 3, .y = 4 }));

    int *fib = (int[]){ 1, 1, 2, 3, 5, 8, 13 };
    printf("  an unnamed array: ");
    for (int i = 0; i < 7; i++) printf("%d ", fib[i]);
    puts("\n  it lives until the end of this block, and no longer");

    puts("\n== anonymous union ==");
    Value values[] = {
        { .kind = V_INT,    .as_int    = 42 },
        { .kind = V_DOUBLE, .as_double = 3.14 },
        { .kind = V_TEXT,   .as_text   = "hello" }
    };
    for (size_t i = 0; i < 3; i++) value_print(&values[i]);
    printf("  accessed as v->as_int, not v->data.as_int\n");

    puts("\n== volatile ==");
    int          normal = 0;
    volatile int observed = 0;
    for (int i = 0; i < 3; i++) { normal++; observed++; }
    printf("  normal = %d, volatile = %d\n", normal, observed);
    puts("  at -O2 the first may be computed at compile time;");
    puts("  the volatile one must be loaded and stored three times");
    puts("  volatile does NOT make ++ atomic — that is week 41");

    puts("\n== setjmp and longjmp ==");
    int landed = setjmp(recovery);
    if (landed == 0) {
        puts("  first pass, descending:");
        level_one(3);
        puts("  never reached");
    } else {
        printf("  back in main via longjmp with value %d\n", landed);
        puts("  three frames were discarded and no cleanup ran");
        puts("  anything they allocated has leaked");
    }

    puts("\n== why VLAs are avoided ==");
    size_t safe_size = 100;
    printf("  a VLA of %zu ints would be fine\n", safe_size);
    puts("  a VLA of a size taken from input cannot report failure:");
    puts("  too large and the process dies with no way to catch it");
    int *heap = malloc(safe_size * sizeof *heap);
    printf("  malloc can: %s\n", heap ? "allocation checked" : "refused");
    free(heap);

    free(a); free(b); free(dst);
    return EXIT_SUCCESS;
}
gcc -std=c17 -Wall -Wextra -O2 -o modern modern.c
./modern

Confirm restrict in the assembly

The timing difference varies by compiler and may be small — GCC sometimes generates a runtime overlap check and two loop versions, recovering most of the gain without the qualifier. The assembly is the reliable evidence:

gcc -O2 -S modern.c -o modern.s
sed -n '/^add_plain:/,/ret/p'    modern.s | grep -c 'xmm\|ymm'
sed -n '/^add_restrict:/,/ret/p' modern.s | grep -c 'xmm\|ymm'

Vector registers appear in the restrict version, and often not in the other. That is the qualifier doing its job: it removed the possibility the compiler had to defend against.

Violate the promise

add_restrict(a, a, b, N);        /* dst and a are the same array */

This compiles silently and is undefined behavior. The result may be correct, or may be wrong in a way that depends on the vector width. Nothing reports it — which is exactly why restrict must only be applied where you can guarantee the condition.

Watch volatile change the generated code

gcc -O2 -S modern.c -o modern.s
grep -B3 -A6 'observed' modern.s

The plain counter is typically folded to a constant; the volatile one produces three loads and three stores. Then try the loop that shows why it matters:

int flag = 0;
while (flag == 0) { }        /* -O2: the load is hoisted; infinite loop */

Add volatile and the load returns to the loop body. In week 50 that difference is a driver that works versus a driver that hangs.

9Check yourself

What does volatile guarantee, and what does it not?

It guarantees that every read and write in the source produces an actual memory access, in program order, with nothing cached in a register or optimized away. It guarantees nothing about atomicity or about ordering relative to other variables, so it does not make counter++ safe between threads. Its real uses are hardware registers, signal-handler flags, and variables live across longjmp.

Why does restrict let a loop vectorize?

Without it the compiler must assume the destination could overlap a source, so a store might change a value it is about to load — forcing it to reload every iteration and process one element at a time. restrict removes that possibility, so it may load and add whole blocks with vector instructions.

Why is static inline preferred over plain inline in a header?

Because plain inline provides an inline definition that is not an external definition: if the compiler declines to inline a call, the linker needs an external definition that exactly one translation unit must supply. static inline gives each unit its own internal-linkage copy, so there is no multiple-definition problem and no missing-symbol problem.

Why should a variable-length array never be sized from external input?

Because it is allocated on the stack and there is no way to detect failure. Exceeding the stack raises a fatal signal rather than returning an error, so a large value from a file or the network becomes a crash the program cannot catch. malloc returns NULL, which you can check and handle.

What does longjmp fail to do that makes it dangerous?

It discards every stack frame between the jump and the setjmp without running any cleanup — C has no destructors, so open files stay open and allocated blocks leak. It also requires that locals modified in between be volatile, and that the function containing setjmp has not returned. An explicit error contract is almost always the better tool.
