Introduction

What Question Does It Ask?

How does AI catch attacks, and how is it attacked itself?

AI in cybersecurity asks two questions together: how can machine learning catch intrusions, malware and phishing, and how can AI systems themselves be fooled? What sets the field apart is the adversarial setting: on the other side is an attacker trying to evade the model.

Introduction

A Short History

1987

Denning defines intrusion detection as a model that catches abnormal behaviour.

1999

The KDD Cup 1999 intrusion detection dataset is released; it serves as a benchmark for many years.

2002

Paul Graham popularizes the Bayesian spam filter with "A Plan for Spam".

2014

Szegedy et al. show adversarial examples: an invisible change fools a classifier.

2016

DARPA Cyber Grand Challenge: machines find and patch vulnerabilities with no human help.

2023

OWASP publishes its first Top 10 for LLM applications, led by prompt injection.

The Course

Core Concepts

Intrusion detection

Signature-based and anomaly-based approaches.

Malware

Classifying files by static or behavioural features.

Phishing detection

Telling fake emails, domains and web pages apart.

Imbalanced data

Attacks are very rare next to normal traffic.

False alarms

Precision, recall; analyst fatigue.

Adversarial examples

Inputs carefully perturbed to fool a model.

Data poisoning

Slipping malicious samples into training data.

Prompt injection

Hidden instructions that change a language model's goal.

The Course

A Typical Workflow

Example: An organization's gateway collects connection logs; features such as duration, byte count and port are extracted for each connection. A model scores suspicious flows and only the highest-scoring ones go to an analyst. The analyst's decisions become new labels and the model is updated.

Try It

Catch Suspicious Logins

Password-guessing attacks are mixed in with normal logins in the company's login records. The model gives each login an anomaly score. Move the threshold or click the chart; what happens when the attacker adapts?

The score is how surprising a login is compared with normal behaviour: failed attempts, hour, new device, foreign country. The model learned from normal logins only.
AI in cybersecurity learns what is normal and catches deviations, so it also sees attacks with no known signature. But the opponent learns too: the model and its features must be updated continuously.

Risks and Ethics

Dual use

Techniques learned for detection can also produce malware that evades it, or convincing phishing emails.

Unauthorized testing

Scanning another party's network without permission is a crime; experiments belong in an isolated lab, with written consent.

Employee surveillance

Insider threat detection watches employees' email and behaviour; proportionality, GDPR and similar laws set limits.

Automated response

Cutting a connection or locking an account on the model's word alone stops legitimate users on a false alarm.

Practice

Common Misconceptions

Common beliefIn fact
99% accuracy means good intrusion detection.If attacks are very rare, a model that calls everything normal is also 99% accurate; look at precision and false alarm rate.
Once trained, a model keeps catching attacks.Attackers change tactics; the model must be updated continuously with new samples.
AI replaces the security analyst.AI filters and prioritizes alerts; decisions and investigation still rest with people.
Deep networks are robust to attacks.Small, invisible changes (adversarial examples) can easily flip a model's decision.
