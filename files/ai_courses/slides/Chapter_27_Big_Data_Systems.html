Introduction

What Question Does It Ask?

How is data that does not fit on one machine stored and processed?

Big data systems study how to store and process data that does not fit on one machine, or arrives faster than one machine can keep up, by spreading it over many machines. The course deals with the trade-offs between partitioning, replication, fault tolerance and consistency.

Introduction

A Short History

2001

Laney describes the data management challenge as volume, velocity and variety (the 3 Vs).

2003

The Google File System paper: a fault-tolerant distributed file system built from cheap machines.

2004

Dean and Ghemawat publish MapReduce: a simple programming model across thousands of machines.

2006

Hadoop, an open-source counterpart of GFS and MapReduce, becomes its own Apache project.

2010

Spark is released as open source: keeping intermediate results in memory speeds up iterative jobs.

2011

LinkedIn open-sources Kafka: a distributed log system for event streams.

The Course

Core Concepts

Volume, velocity, variety

The size of data, how fast it arrives, how many formats.

Distributed file system

Splitting files into blocks and replicating them across machines.

MapReduce

Map, shuffle, reduce: moving computation to the data.

In-memory processing

Spark: chaining steps without writing to disk.

Stream processing

Processing an unbounded event stream as it arrives.

NoSQL

Key-value, document, wide-column and graph stores.

CAP theorem

Under a network partition, choosing consistency or availability.

Partitioning, replication

Spreading load and not losing data when a machine fails.

The Course

A Typical Workflow

Example: A video site collects billions of view events a day with Kafka, partitions them by date in object storage, computes nightly per-user viewing summaries with Spark and writes the results to tables that analysts can query with SQL.

  8. Replication and consistency models

Try It

Word Count over Search Logs

A site's search logs do not fit on one machine; worker machines must count together how often each word was searched. Go step by step: Map → Shuffle → Reduce. Change the number of workers and the combiner, and watch the time.

A big data course teaches moving computation to the data: Map and Reduce tasks run independently, so adding workers speeds things up, but network traffic and the slowest worker set a limit. The combiner cuts the number of pairs on the network.

Risks and Ethics

Silent data loss

Misconfigured replication or Kafka records deleted when retention expires can destroy data without anyone noticing.

Keep-everything habits

Collecting personal data because storage is cheap widens the breach surface; GDPR and similar laws require purpose limits.

Honouring the right to erasure

A person's data spreads into backups, replicas and derived tables; fully honouring a deletion request is hard.

Cloud bills and energy

A cluster left running or an unnecessary full table scan means a large bill and wasted energy.

Practice

Common Misconceptions

Common beliefIn fact
Big data just means a lot of data.Velocity and variety matter as much as size; the real question is whether the data fits on one machine.
A distributed system is always faster.On small data a single machine (pandas, SQL) is often faster; distribution has overhead.
Doubling the machines halves the time.Shuffles, network traffic and the slowest task limit the speedup.
NoSQL has replaced SQL.NoSQL offers different consistency trade-offs; SQL engines such as Spark SQL and Hive are widespread.
