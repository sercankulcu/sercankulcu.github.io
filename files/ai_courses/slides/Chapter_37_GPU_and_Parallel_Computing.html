Introduction

What Question Does It Ask?

How do thousands of cores share the same computation?

GPU programming studies data-parallel computation, which applies the same operation to thousands of data elements at once. Using a model such as CUDA, the course teaches how to organize threads, use the memory hierarchy efficiently and measure speedup; this is also the hardware that makes deep learning practical.

Introduction

A Short History

1966

Flynn classifies computers as SISD, SIMD, MISD and MIMD.

1967

Amdahl shows that the remaining sequential part limits parallel speedup (Amdahl's law).

1999

NVIDIA GeForce 256 is marketed under the name "GPU".

2007

NVIDIA releases CUDA: the GPU becomes general-purpose programmable in a C-like language.

2012

AlexNet is trained on two GPUs and wins ImageNet; the GPU becomes the engine of deep learning.

2017

The Volta architecture introduces tensor cores: hardware units dedicated to matrix multiplication.

The Course

A Typical Workflow

Example: To add two vectors of two million elements, one thread is assigned to each element: the arrays are copied to GPU memory, the kernel is launched with 256-thread blocks and the result is copied back. Measurement often shows that the time goes into copying data, not into computing.

Try It

Add Thousands of Numbers at Once

Computing a network's loss means adding millions of numbers; a GPU does it as a tree, adding pairs at the same time. Change the thread count and watch step by step; Amdahl's law shows the limit.

Parallel programming teaches splitting work into independent pieces: the sum of n numbers finishes in log n steps. But even a small serial part sets a ceiling on the speedup.

Practice

Common Misconceptions

Common beliefIn fact
A GPU speeds up any program.Only parts with many independent, similar operations speed up; branching and sequential parts do not.
Doubling the cores halves the run time.Amdahl's law: the sequential part sets an upper bound on the achievable speedup.
Computation is the most expensive part.In most GPU programs the bottleneck is memory bandwidth and data transfer between CPU and GPU.
Parallel programming is only for deep learning.Simulation, graphics and scientific computing used GPUs long before deep learning.
