Chapter 1: Introduction

However cleverly a program is written, in the end it works on data held in memory. How that data is represented, how it is organized, and which operations act on it determine both whether the program is correct and how fast it runs. These notes start at the lowest level, with how text, numbers, images, and sound are represented as 0s and 1s. From there they move on to Java's primitive types, type safety, the call stack and the heap, and the difference between copying a value and copying a reference. Generics show how a single class can work with every reference type. At the heart of the chapter is the distinction between an abstract data type and a data structure: an interface says what is to be done, a class says how it is done. We make the distinction concrete with a stack, written in Java and traced line by line. The closing sections survey the ways data can be organized, the questions to ask when choosing a data structure, and the fundamental data structures of this course.

1.1Digital data

A course on data structures is about how data is organized in memory. Before we can talk about organizing anything, though, we need to know what it is we are organizing. A computer's memory holds no letters, no photographs, no songs; all it holds is tiny cells, each storing a 0 or a 1. How does everyday information fit into those cells? That is the question this section answers.

1.1.1What is digital data?

Suppose you record a voice memo on your phone. The speaker's voice travels through the air as a pressure wave. The wave is continuous: it has a value at every instant, and that value keeps changing even between any two measurements. Quantities that vary continuously like this are called analog. The phone's microphone turns the wave into an electrical voltage, and the voltage is still analog. The phone's processor, however, cannot work with a continuous quantity. It needs numbers, or more precisely, sequences of 0s and 1s.

The circuit that turns an analog signal into numbers is called an analog-to-digital converter (ADC). An ADC measures the signal at regular intervals and records each measurement as a number. Playback runs the other way: a digital-to-analog converter (DAC) turns the numbers back into a voltage, and the speaker turns the voltage back into a sound wave. Everything in between is the computer operating on numbers: saving, copying, sending, turning the volume up or down, reducing noise. Figure 1.1 shows the whole chain.

Definition 1.1

Digital data is information such as numbers, text, images, and sound, represented electronically as sequences of 0s and 1s. Text documents, image files, databases, and audio recordings are all examples of digital data.

The key word in this definition is represented. On their own, the 0s and 1s inside a computer mean nothing. The same eight-bit sequence can stand for a letter in one place, a number in another, and the red intensity of a pixel in a third. What gives bits their meaning is a rule that says how to interpret them, called an encoding. A file extension (.txt, .png, .mp3) is a hint of this kind: it tells a program which encoding to use when it reads the bits in the file.

Common mistake

Using “digital” to mean simply “on a computer” and missing the real difference between analog and digital. The difference is whether values vary continuously or come in countable steps. The hand of an analog clock can stop at any position in between. A digital clock shows only certain values, say 14:07 and 14:08, and nothing in between. Some information is inevitably lost in the conversion to digital; the engineer's job is to keep that loss too small for the user to notice.

1.1.2Bits, bytes, and binary numbers

The smallest unit of memory is the bit, short for binary digit. A bit has only two possible values: 0 or 1. In hardware, the two values might be a low or a high voltage in a circuit, or a tiny region of a disk surface magnetized in one of two directions. Telling two states apart is far easier and more reliable than telling ten apart, and that is the main reason computers use binary.

A single bit carries very little information, so bits are used in groups. A group of eight bits is called a byte. The number of values we can represent grows rapidly with the number of bits. One bit gives 2 values. Two bits give 4: 00, 01, 10, and 11. Each additional bit doubles the count, because every existing sequence can be extended with either a 0 or a 1. So n bits can represent 2n different values: 8 bits give 256, 16 bits give 65,536, and 32 bits give 4,294,967,296.

The rule for reading a sequence of bits as a number is the binary number system. In decimal, the digits are multiplied by powers of ten, 1, 10, 100, 1000, and so on, from right to left: 365 = 3·100 + 6·10 + 5·1. Binary applies the same idea with powers of two. In an eight-bit sequence the place values, from left to right, are 128, 64, 32, 16, 8, 4, 2, and 1.

Example 1.1

Let us write 13 in eight bits, and then find the number that the sequence 01000001 represents.

  1. Decomposing 13: The largest power of two that does not exceed 13 is 8, which leaves 13 − 8 = 5. Next, 4 fits into 5, leaving 5 − 4 = 1. Finally, 1 fits into 1, leaving 0. So 13 = 8 + 4 + 1.
  2. Filling in the places: Write 0 in the 128, 64, 32, and 16 places; 1 in the 8 place; 1 in the 4 place; 0 in the 2 place; and 1 in the 1 place. The result is 00001101.
  3. The other direction: In 01000001 the places holding a 1 are 64 and 1, so the value is 64 + 1 = 65.
  4. A check: In 00001011 the places holding a 1 are 8, 2, and 1, which add up to 11, not 13. Shifting a single digit during the decomposition gives an entirely different number.

Units larger than a byte turn up in everyday use as well. A kilobyte (KB) is roughly a thousand bytes, a megabyte (MB) roughly a million, and a gigabyte (GB) roughly a billion. We say “roughly” because some software computes these units with powers of 1024 rather than 1000; 1024 = 210 is a round number in binary.

Common mistake

Confusing bits with bytes. Internet speeds are usually quoted in bits per second (Mbit/s), whereas file sizes are given in bytes (MB). A 100 Mbit/s connection does not transfer 100 MB per second but, at best, 100 / 8 = 12.5 MB.

1.1.3Properties of digital data

Three properties explain why digital data has become so widespread.

  • It is numeric. Data is represented as 0s and 1s, that is, as binary numbers such as 1011 0010. Because everything is a number, every kind of information can be stored on the same hardware and carried by the same circuits. A hard disk has no idea whether it holds a photograph or a novel.
  • It is easy to store. Digital data can be stored electronically and shared easily, on disks, in the cloud, or over a network. More important, copying it is lossless. A vinyl record or a cassette degrades a little with every copy; the millionth copy of a digital file is identical, bit for bit, to the first.
  • It is easy to process. Computers process digital data very fast. An ordinary processor today performs on the order of 109, or a billion, basic operations per second.

The third point also explains why a course on data structures exists at all. A billion operations per second might seem, at first glance, enough to solve any problem instantly. As data grows, however, the work done by a poorly organized program can grow much faster than the data itself. Suppose we have a million records and the program compares every record with every other one. That is 106 · 106 = 1012 comparisons. At 109 operations per second the job takes about 1000 seconds, more than 16 minutes. A program that keeps the same data in a suitable structure can finish in a tiny fraction of a second. The computer knows nothing but 0s and 1s; data structures are the ways we keep those bits in a meaningful and efficient order.

1.1.4Representing text, numbers, images, and sound

Each kind of information has its own encoding rule. Table 1.1 lists four basic kinds with a short example of each; we then look at them one at a time.

Table 1.1: How digital data is represented.
Kind of informationHow is it represented?Example
Textcharacter encodings such as ASCII and Unicode'A' → 65 → 01000001
Numbersintegers and floating-point numbers13 → 00001101 · 3.14 → IEEE 754
Imagescolor values of pixelsred pixel → (R, G, B) = (255, 0, 0)
Sounddigital samples of sound wavesCD quality → 44,100 samples per second

Text. To store text, we assign a number to every character. The table that defines this mapping is called a character encoding. One of the oldest and most widely used encodings is ASCII (American Standard Code for Information Interchange). ASCII represents 128 characters by the numbers 0–127: uppercase letters start at 65 ('A'), lowercase letters at 97 ('a'), and digits at 48 ('0'). Although 128 values fit in 7 bits, in practice each character is stored in a byte. The character 'A', for example, is represented by the number 65, which in turn is the bit sequence 01000001.

ASCII covers only the English alphabet; letters such as the Turkish “ş”, “ğ”, and “ı” are not part of it. The standard that brings all of the world's writing systems together in a single table is Unicode. Unicode gives every character a code point; the code point of “ş”, for instance, is 351. How that number is written out as bytes is governed by a separate rule. UTF-8, the most common format on the Web, still writes ASCII characters in a single byte but uses two or more bytes for characters like “ş”. As a result, a word containing Turkish letters can take up more bytes than it has letters. The Turkish word “Veri” (data) has 4 letters and takes 4 bytes. “Şeker” (sugar), on the other hand, has 5 letters but takes 6 bytes in UTF-8, because “Ş” occupies two. Java's char type is a 16-bit UTF-16 code unit, so in Java “ş” fits in a single char.

Example 1.2

Let us work out how the word “Veri” is laid out in memory under ASCII.

  1. Codes: 'V' = 86, 'e' = 101, 'r' = 114, 'i' = 105.
  2. In binary: 86 = 64 + 16 + 4 + 2 → 01010110. 101 = 64 + 32 + 4 + 1 → 01100101. 114 = 64 + 32 + 16 + 2 → 01110010. 105 = 64 + 32 + 8 + 1 → 01101001.
  3. Result: Memory holds four consecutive bytes: 01010110 01100101 01110010 01101001. Nothing in these 32 bits says that they form a word. Read as an int, the same 32 bits give a very large integer. Their meaning is determined by the encoding that the program reading them uses.

Numbers. Integers are written directly in binary. For negative numbers, computers use a rule called two's complement. We do not need its details here, only its consequence: an n-bit signed integer takes values from −2n−1 to 2n−1 − 1. For 8 bits that range is −128 … 127. Numbers with a fractional part are stored in floating-point format, which is defined by the IEEE 754 standard. Like a number in scientific notation, a floating-point number carries a sign, a part holding the significant digits, and an exponent: a number such as 3.14 is stored approximately as 1.57 · 21. Because the number of significant digits is limited, many decimal fractions can be represented only approximately.

Images. A digital image is a grid of small squares called pixels. The color of each pixel is given by three numbers that say how much red (R), green (G), and blue (B) light is mixed in. Each component is usually one byte, so it takes a value from 0 to 255. A pure red pixel is written (255, 0, 0), white is (255, 255, 255), and black is (0, 0, 0). The image is stored as one long sequence of these triples, laid out row by row.

Sound. Sound becomes numbers when an ADC measures the signal at regular intervals. Each measurement is called a sample, and the number of measurements per second is the sampling rate. Music CDs take 44,100 samples per second; each sample is a 16-bit integer, and a stereo recording keeps separate samples for the left and right channels.

Example 1.3

How many bytes do one minute of uncompressed CD audio and an uncompressed 1920 × 1080-pixel photograph take up?

  1. Audio, one second: 44,100 samples × 2 bytes (16 bits) × 2 channels = 176,400 bytes.
  2. Audio, one minute: 176,400 × 60 = 10,584,000 bytes, or about 10.6 MB.
  3. Photograph: 1920 × 1080 = 2,073,600 pixels. Each pixel takes 3 bytes (R, G, B): 2,073,600 × 3 = 6,220,800 bytes, about 6.2 MB.
  4. Interpretation: The MP3 and JPG files on a phone are far smaller than these figures. Such formats compress data by throwing away detail that the human ear and eye will not notice. Compression, too, is a matter of organizing data: it looks for ways to represent the same information with fewer bits.
Common mistake

Treating a digit character as if it were the number itself. The ASCII code of the character '7' is 55; its value is not 7. If a “7” read from a text file goes into a calculation without first being converted to a number, the result will be wrong. In Java the expression '7' - '0' gives 55 − 48 = 7, which is the quick way to turn a digit character into its numeric value.

1.1.5Kinds of digital data

Digital data can also be classified by how it is organized. Table 1.2 gives one common classification.

In structured data, the fields that make up each record are known in advance. Every row of a student table contains the same fields, say ID number, name, department, and grade point average; this list of fields is called the schema. A CSV (comma-separated values) file is structured too: each line is a record, and each comma-separated column is a field. Searching and sorting structured data is easy, because the place of every value is known.

Semi-structured data has no schema, or only a loose one, but the data describes its own structure through tags. The following JSON (JavaScript Object Notation) fragment describes a student:

{ "id": 101, "name": "Alice", "courses": ["Data Structures", "Physics"] }

Each value is preceded by a tag that says what it is ("id", "name"). Another student's record might have no "courses" field at all, or an extra "phone" field. XML (eXtensible Markup Language) does the same job with opening and closing tags, as in <name>Alice</name>. Semi-structured data lends itself to nesting: a student can contain a list of courses, and each course a list of grades. Nesting of this kind is a tree-shaped organization.

Text, images, and sound, on the other hand, are organized by their content rather than by a schema. The body of an email or the pixels of a photograph are not divided into fields the way a database table is. Such data is often called unstructured.

For data structures, the lesson of this classification is that the external form of the data influences the structure we choose inside the program. CSV lines naturally go into an array or a list. The nested structure of JSON and XML is represented in the program by a tree. And to get from an email address to a person, we use a key–value mapping.

1.2Data structures and algorithms

A program consists of two things: the data it works on and the steps it applies to that data. The two are not independent. How the data is stored determines which steps are easy and which are laborious, and the steps to be performed in turn determine how the data should be stored.

1.2.1Algorithms and data structures

Definition 1.2

An algorithm is a step-by-step plan for carrying out a particular task: an ordered collection of a finite number of unambiguous instructions. Algorithms are among the fundamental building blocks of computer science.

A cooking recipe is the most familiar everyday example of an algorithm: the ingredients are listed, the steps come in order, each step says plainly what to do, and the recipe eventually ends. An algorithm on a computer must have the same properties. Its steps must be clear enough for a computer to carry out, it must contain no vague instructions (“add a pinch of salt”), and it must stop after a finite number of steps.

Definition 1.3

A data structure is a way of organizing and storing data in a computer. It defines how the data is laid out in memory and the operations through which that data is accessed.

A data structure is the infrastructure needed to manage and process data, and an algorithm runs on top of that infrastructure. When the two are chosen well together, software runs efficiently and the problem is solved systematically. The Swiss computer scientist Niklaus Wirth summed up this relationship in the title of his 1976 book: Algorithms + Data Structures = Programs.

An example makes the relationship clear. Suppose we need to look up a name in a phone book of a thousand people. If the names are in random order, the only option is to start at the beginning and check every name in turn. If the name we want is last, or not there at all, that takes a thousand comparisons. If the names are in alphabetical order, an entirely different algorithm becomes possible: look at the middle name; if the name we want comes before it in the alphabet, the whole second half is eliminated, and if it comes after, the whole first half is. Each comparison cuts the number of candidates in half: 1000, 500, 250, 125, 63, 32, 16, 8, 4, 2, 1. We reach an answer in at most 10 comparisons. Simply keeping the same data in a different order has opened the door to an algorithm a hundred times faster. This comes at a price: to preserve the sorted order, every new name must be inserted in its proper place.

Common mistake

Thinking of a data structure as merely “the place where data sits” and of an algorithm as a separate, independent topic. The halving method above does not work on an unsorted list; it gives wrong answers. Whether an algorithm is correct and fast depends on the guarantees provided by the data structure it works on.

1.2.2The cost and the payoff of organization

The basic purpose of a data structure is fast, effective access to data. The slides illustrate this with a kitchen drawer. The same utensils lie jumbled in one drawer and sorted into compartments in another. Finding a spoon in the messy drawer may mean handling every item one by one. In the tidy drawer the spoons have their own compartment, and your hand goes straight to it.

The second lesson of the analogy is less obvious: organization is not free. To put an item into the tidy drawer, you first have to find its compartment, whereas you can toss an item into the messy drawer anywhere. Organization, then, makes adding things slightly harder and finding things much easier. Which arrangement to choose depends on which operation happens more often. If one item goes into the drawer each year but something is looked for every day, organization clearly pays off. If things are thrown in every day and never looked for (think of a wastebasket), organizing is wasted effort.

This trade-off is the essence of choosing a data structure. Every structure makes some operations cheap and others expensive, and that choice directly determines how fast a program runs and how much memory it uses.

1.2.3Basic building blocks: objects, arrays, links

However complex they may look, nearly all data structures are built from three basic parts.

Objects. An object gathers related attributes into a single unit, as named fields. A student's name and ID number could be kept in two separate variables, but then the programmer would have to remember which name goes with which number. In Java, a class that combines the two attributes into one unit looks like this:

class Student {
  String name; // the student's name
  int id;      // student ID number
  Student(String name, int id) { this.name = name; this.id = id; }
}

When a Student object is created, its name and id fields sit together in memory and travel together. Objects are also the basis of the nodes in data structures: a node is a small object that holds a value together with fields pointing to that value's neighbors.

Arrays. An array stores elements of the same type together, in consecutive slots of memory. Contiguity is the array's greatest strength. If we know where the array starts in memory and how many bytes each element takes, the address of element i takes just one multiplication and one addition to compute: start address + i × element size. If the elements are 4-byte ints and the array starts at address 1000, element 5 is at address 1000 + 5 × 4 = 1020. This calculation does not depend on the length of the array; it takes the same time whether the array has ten elements or ten million.

Links. A link is a pointer from one entity to another. In Java such a pointer is called a reference. Links create arbitrary, directed relationships between entities: a student can point to an advisor, a city to its neighboring cities, a song in a playlist to the song that plays next. The elements of a linked structure can be scattered across memory; the order comes from the arrows, not from contiguity. In the figure on the slides, the arrow from the last figure ends in a question mark. A chain has to end somewhere, and in Java that final link, which points to nothing, is expressed by null.

The choice between arrays and links is one of the main themes of this course. An array gives instant access by index, but its size is fixed in advance, and inserting in the middle means shifting elements. A linked structure grows as large as needed, and inserting in the middle takes nothing more than redirecting a few arrows; but reaching element i means starting at the front and following the arrows one at a time.

1.3Data types

A programming language learns from the programmer how to interpret bits. By declaring the type of each variable, the programmer is in effect saying, “read the bits in this memory location as an integer,” or “read them as a character.” This section covers Java's built-in types and how types protect a program from errors.

1.3.1Primitive data types

Java has eight basic types built into the language itself, called primitive types. They represent integers, numbers with fractional parts, logical values, and characters. Table 1.3 lists these types, the space each occupies in memory, and the values each can hold.

The ranges in the table are not arbitrary; they follow directly from the rule in Section 1.1.4. An n-bit signed integer takes values from −2n−1 to 2n−1 − 1. For byte, n = 8: 27 = 128, so the range is −128 … 127. For short, 215 = 32,768. For int, 231 = 2,147,483,648, which is where “about ±2.1 billion” comes from. For long, 263 ≈ 9.22·1018. The positive side falls one short because 0 uses up one of the values in the nonnegative half.

Primitive types share four properties. They are simple, basic types, not built from other types. They occupy a fixed amount of memory: an int takes 32 bits whether it holds 3 or 2 billion. The processor handles them directly; adding two ints is a single machine instruction. Finally, a primitive variable holds its value directly, inside itself. The importance of this last property will become clear in Section 1.4.

One consequence of a fixed size is that every type has a limit. When the limit is exceeded, Java reports no error; instead, the value wraps around to the other end of the range. This is called overflow.

int big = Integer.MAX_VALUE;             // 2147483647
System.out.println(big + 1);             // -2147483648
long wide = (long) big + 1;
System.out.println(wide);                // 2147483648
System.out.println(0.1 + 0.2);           // 0.30000000000000004
Example 1.4

Let us trace step by step what happens in the first two lines of the code above.

  1. Initial value: big holds 2,147,483,647, the largest int value. In binary this number is a 0 followed by 31 ones.
  2. Adding one: Adding 1 to 31 ones sends a carry rippling through every place, leaving a 1 followed by 31 zeros.
  3. Interpretation: In a signed integer, a 1 in the leftmost bit means the number is negative. This bit pattern is the smallest int value, −2,147,483,648, so the program prints −2,147,483,648 for big + 1.
  4. Prevention: When a result might exceed the int range, use long. Methods such as Math.addExact throw an exception on overflow instead of silently wrapping around.

Floating-point types have a different kind of limit: they can represent very large and very small numbers, but each one only approximately. A float holds about 7 significant digits, a double about 15. The number 0.1 is an infinite fraction in binary (much as 1/3 is 0.333… in decimal), so memory can hold only an approximation of it. The last line of the code shows the result: 0.1 + 0.2 prints 0.30000000000000004.

Common mistake

Comparing floating-point numbers with ==. The expression 0.1 + 0.2 == 0.3 evaluates to false. To test two double values for equality, check whether the absolute value of their difference is below some very small tolerance (for example 10−9). For values that must be exact to the cent, such as money, use a long counting cents, or BigDecimal, instead of double.

1.3.2A data type: a set of values plus operations

Thinking of a type only as “the values it can take” leaves something out. The difference between int and String is not just that one holds numbers and the other text; the operations that apply to them differ as well.

Definition 1.4

A data type defines a set of values together with the behavior of those values. The set of values consists of the valid values the type can take. The behavior consists of the operations that can be performed on those values.

Integers come with operations such as addition, subtraction, multiplication, and division. Strings (String), by contrast, support operations such as comparison, concatenation, and taking a substring: "data" + "base" yields the string "database", and "database".substring(0, 4) yields "data". The same + sign does different work for the two types: it adds numbers and concatenates strings. Nothing shows more plainly that behavior belongs to the type.

Division is the best illustration of how a type determines behavior. In Java, the quotient of two ints is again an int; the fractional part is not rounded but simply discarded.

System.out.println(7 / 2);     // 3
System.out.println(7 % 2);     // 1
System.out.println(-7 / 2);    // -3
System.out.println(-7 % 2);    // -1
System.out.println(7.0 / 2);   // 3.5
System.out.println(7 / 2.0);   // 3.5
int n1 = 7, n2 = 8;
double avg1 = (n1 + n2) / 2;     // 7.0
double avg2 = (n1 + n2) / 2.0;   // 7.5

Let us read the code line by line. 7 / 2 is the quotient of two integers: the fractional part of 3.5 is discarded, and the result is 3. 7 % 2 is the remainder operation and gives 1; together, quotient and remainder satisfy 7 = 2 · 3 + 1. -7 / 2 gives −3, not −4, because Java discards the fractional part by truncating toward zero; correspondingly, the remainder is −1: −7 = 2 · (−3) + (−1). When one of the operands is a double, as in 7.0 / 2 or 7 / 2.0, the division is done in floating point and the result is 3.5.

Example 1.5

The last two lines of the code compute the average of 7 and 8 in two ways. Why do the results differ?

  1. First line: (n1 + n2) is an int with the value 15. 15 / 2 is the quotient of two ints, which is 7. Only after the division is finished is this 7 converted to a double, so avg1 receives 7.0. The loss happened before the assignment.
  2. Second line: 2.0 is a double. When one operand is a double, Java promotes the other to double as well: 15.0 / 2.0 = 7.5.
  3. The lesson: The type of the variable that stores the result does not decide how the operation is carried out. What decides it is the types of the operands.

When types are mixed, Java follows definite rules. A char is really a 16-bit number, and in arithmetic it is promoted to int. That is why 'A' + 1 gives 66. When one side of + is a String, on the other hand, the other side is converted to text and appended: "A" + 1 gives the string "A1". Because the operations are evaluated left to right, 1 + 2 + "x" first computes 3 and gives "3x", whereas "x" + 1 + 2 gives "x12".

Common mistake

Forgetting about integer division when computing an average, a percentage, or a ratio. If 7 of 30 students pass, 7 / 30 * 100 gives 0, because 7 / 30 is 0 in integer division. There are two ways to get the right answer. Multiply first: 7 * 100 / 30 gives 23. Or write one of the operands as a floating-point number: 7.0 / 30 * 100 gives about 23.33.

1.3.3Type safety

Not every operation is valid for every type. Multiplying a piece of text by a number has no meaning in Java: write "abc" * 2 and the compiler reports the error without ever running the program. This protective role of types is called type safety. Data types are used to keep errors to a minimum; the restrictions a type imposes tell the programmer what is possible and what is not.

When an error is caught matters a great deal. In statically typed languages such as Java, the types of variables are written in the source code, and the compiler checks, before the program ever runs, that every operation fits the types involved. This is called compile-time checking. An error caught at compile time is seen and fixed by the programmer before the program reaches anyone else. If the same error could surface only at run time, the program might run without trouble for months and then crash in a user's hands the first time execution reached that line.

Type safety is especially valuable in data structures. A data structure may hold thousands of elements, added and removed in many different parts of the program. A single element of the wrong type slipping into the structure causes trouble far away from the source of the error. That is why data structures in Java are written with generics, which tell the compiler what type of element goes into them (Section 1.5).

Common mistake

Assuming that every program that compiles is correct. Type safety catches only operations that violate the types. The types in 7 / 30 * 100 are fine and the program compiles; what is wrong is the programmer's intent. The compiler catches type errors, not logic errors.

1.4The Java memory model

Almost every data structure rests on the idea of a variable “pointing to” data stored somewhere else. Without a firm grasp of this idea, code for linked lists, trees, or graphs is unreadable. This section explains where variables and objects live in memory while a Java program runs.

1.4.1The call stack and the heap

A running Java program uses memory in two main regions. The first is the call stack. Each time a method is called, a stack frame for that call is pushed onto the call stack. The method's parameters and local variables live in this frame. When the method returns, the frame is removed, and all of its local variables disappear with it. Frames are stacked one on top of another, and the most recently opened one is the first to close, which is why the region is called a stack.

The second region is heap memory. Every object created with new, every array, and every String lives on the heap. Objects on the heap are not tied to any method's frame; they can live on after the method that created them has returned.

Definition 1.5

A primitive variable holds its value directly, inside itself. A reference variable, on the other hand, holds not the value of an object on the heap but the object's location, that is, its address. This address, stored in a variable, is called a reference. A reference that points to no object has the value null.

In Java, every type other than the eight primitive types is a reference type: arrays, String, the classes we write ourselves, and every class in the library. The following four lines show the two kinds side by side:

int x = 5;               // primitive: a value
int[] a = {7, 2, 9};     // reference → array
String s = "data";       // reference → object
int[] p = null;          // points to nothing

Figure 1.2 shows the trace these lines leave in memory. All four boxes in the frame are small and the same size. Whether the array has 3 elements or 3 million, the variable a holds only an address; the actual data is on the heap.

Once no reference points to an object, the program has no way left to reach it. Such objects merely take up space. In Java, the garbage collector finds and reclaims them from time to time, so the programmer never has to return memory by hand. In languages such as C this job falls to the programmer, and forgetting it causes memory leaks.

Trying to access the object behind a null reference causes an error at run time. Since p points to no array, the expression p[0] finds no element, and Java throws a NullPointerException. This is the error you will meet most often when working with linked structures.

Common mistake

Confusing the stack region of memory with the stack data structure. The call stack is a stack that Java itself uses to manage method calls; it gets its name from following the last-in, first-out rule. The Stack interface written later in these notes, by contrast, is a data structure programmers use for their own data. The word “heap” has two meanings as well: the heap as a region of memory and the heap data structure used for priority queues are unrelated. The glossary lists the first as heap memory and the second simply as heap.

1.4.2Code trace: value or reference?

The assignment operator = copies the value on its right into the variable on its left. What exactly gets copied, though, depends on the kind of variable. The following eight lines of code show the difference step by step:

int x = 5;
int y = x;
y = 7;
int[] a = {1, 2, 3};
int[] b = a;
b[0] = 9;
b = new int[2];
System.out.println(x + " " + a[0]);

Let us trace the code line by line. Table 1.4 gives the state of the variables and of the objects on the heap after each line; objects are numbered #1, #2, … in the order in which they are created.

Line 6. The line b[0] = 9; follows b to the object it points to and changes that object's cell 0. Since a points to the same object, a[0] is now 9 as well. The ability to reach one object through more than one reference is called aliasing: a and b are two names for the same array.

Line 7. b = new int[2]; creates a new two-element array on the heap and redirects b's arrow to it. Java fills the cells of a new int array with 0. This line does not affect a: what changes is the address stored in b, not object number 1.

Line 8. The expression x + " " + a[0] puts 5, a space, and 9 side by side. The output is 5 9.

The whole trace comes down to a single rule: for a primitive type, = copies the value; for a reference type, it copies the address. Assigning to a reference variable changes where the arrow points. Assigning through the reference, as in b[0] = … or obj.field = …, changes the object itself. The same rule holds for the classes we write ourselves:

Student st1 = new Student("Alice", 101);
Student st2 = st1;         // a second reference, no new object
st2.id = 202;
System.out.println(st1.id);  // 202

st2 = st1 does not create a new student; it draws a second arrow. Because st2.id = 202 changes a field of the shared object, st1.id becomes 202 as well.

Common mistake

Believing that int[] b = a; makes a copy of the array. A real copy requires creating a new array and transferring the elements one by one; Java does this concisely with int[] b = a.clone(); or Arrays.copyOf(a, a.length). Even this copy goes only one level deep, however: if the elements of the array are objects, what gets copied is, once again, their references. A copy of this kind is called a shallow copy.

1.4.3Passing arguments to methods

When a method is called, each argument supplied by the caller is assigned to the corresponding parameter of the method, and this assignment works just like an ordinary =. Java always passes by value: the parameter receives a copy of the argument. For a primitive type, the value copied is the number itself; for a reference type, it is the address. Two swap methods show the consequences clearly:

static void swap(int a, int b) {
  int tmp = a; a = b; b = tmp;
}
static void swap(int[] arr) {
  int tmp = arr[0]; arr[0] = arr[1]; arr[1] = tmp;
}
int p = 1, q = 2;
swap(p, q);
System.out.println(p + " " + q);              // 1 2
int[] nums = {1, 2};
swap(nums);
System.out.println(Arrays.toString(nums));    // [2, 1]
Example 1.6

What are p, q, and nums after the two calls?

  1. The call swap(p, q): A new frame is opened. A copy of 1 is written into a and a copy of 2 into b. The method swaps a and b, so the frame now holds a = 2 and b = 1. When the method returns, the frame is removed. p and q were never touched: they are still 1 and 2.
  2. The call swap(nums): In the new frame, arr receives a copy of the address stored in nums. Both arrows point to the same array. When the method swaps arr[0] and arr[1], the cells of the shared array trade places.
  3. Result: The output is 1 2 and [2, 1]. A method cannot change the caller's primitive variables, but it can change, through a reference, an object that the caller points to.

It is important to know where this rule stops. Had the method executed an assignment such as arr = new int[2];, only the direction of the local arrow arr would have changed; the caller's variable nums would have gone on pointing to the old array. When the method returned, no reference to the new array would remain, and the garbage collector would reclaim it. In short, a method can change the inside of an object, but it cannot make the caller's variable point to a different object.

Common mistake

Saying that “Java passes primitives by value and objects by reference.” This slogan usually predicts the outcome correctly, but it misdescribes the mechanism. Java passes everything by value; for a reference type, the value being copied is an address. The difference shows up when the method assigns a new object to the parameter: under true pass-by-reference the caller's variable would change too, but in Java it does not.

1.4.4String objects and comparison

String is a reference type, but it differs from arrays in one important way: once a String object has been created, its contents cannot be changed. This property is called immutability. Operations such as toUpperCase(), substring(), and + do not modify the existing object; they return the result as a new object.

String s1 = "course";
String s2 = s1;
s2 = s2.toUpperCase();
System.out.println(s1 + " " + s2);      // course COURSE
String u1 = new String("data");
String u2 = new String("data");
System.out.println(u1 == u2);           // false
System.out.println(u1.equals(u2));      // true

After the first two lines, s1 and s2 point to the same "course" object. On the third line, s2.toUpperCase() creates a new "COURSE" object, and the assignment redirects s2's arrow to it. The old object is unchanged; s1 still points to it and prints course. With the array we could change the shared object (b[0] = 9); String offers no such operation. As a result, variables that share the same String cannot affect one another.

The last two lines of the code make a second important point. Each call to new String("data") creates a separate object on the heap. The expression u1 == u2 compares the two references, that is, it asks “do the two arrows point to the same object?”, and the answer is false. u1.equals(u2), by contrast, compares the contents of the objects and returns true.

Common mistake

Comparing two strings with ==. For reference types, == compares addresses, not contents. Java often merges identical strings written directly in the source code into a single object, so == sometimes appears to “work.” For a string read from the keyboard or computed at run time, however, it gives the wrong answer. Always compare contents with equals.

1.5Generics

A stack, a list, or a queue works the same way no matter what it holds. There is no difference at all between the push and pop operations of a stack of integers and those of a stack of student objects. Writing a separate stack class for every element type is wasted effort, and a bug in one copy is repeated in all the others. Generics solve this problem without giving up type safety.

1.5.1The trouble with a non-generic box

Consider the simplest possible “data structure”: a box that stores a single item. To let it accept items of any type, we can use Object, the common ancestor of every class in Java:

public class ObjectBox {
  private Object item;
  public void put(Object x) { item = x; }
  public Object get() { return item; }
}
ObjectBox b = new ObjectBox();
b.put(42);                    // compiles: 42 is an Object too
String z = (String) b.get();  // compiles, but throws ClassCastException at run time

This box accepts anything, and that is exactly the problem. The call put(42) compiles. Since get() returns an Object, a programmer who wants to store the result in a String variable is forced to write a cast ((String)). The compiler has no way of knowing whether the cast is correct, so it compiles the program. The error appears only at run time, when it turns out that the 42 coming out of the box is not a String: a ClassCastException. By the yardstick of Section 1.3.3, this is the worst case: the error is caught not at compile time but at run time.

1.5.2Box<T>: one structure for every type

Definition 1.6

A generic class is a class that takes one or more type parameters. A type parameter is a name that stands for a type not known when the class is written (usually a single capital letter such as T, E, K, or V). When the class is used, the parameter is given a concrete reference type. This feature of the language is called generics.

Here is the generic version of the same box:

public class Box<T> {
  private T item;
  public void put(T x) { item = x; }
  public T get() { return item; }
}

Box<String> b = new Box<>();
b.put("data");
String s = b.get();     // no cast needed
Box<Integer> m = new Box<>();
m.put(42);              // int → Integer
// m.put("x");          // COMPILE-TIME ERROR

The <T> next to the class name declares that T is a type parameter. Inside the class, T is used as though it were a real type: the field item has type T, put takes a T, and get returns a T.

When client code writes Box<String> b, the compiler substitutes String for T for that variable. Now b.put accepts only a String, and b.get() returns a String, so the line String s = b.get(); needs no cast. The empty angle brackets in new Box<>() are called the diamond operator; the compiler infers the type argument from the declaration on the left.

Box<Integer> m, meanwhile, is a box made from the same class, this time for integers. If the commented-out call m.put("x") is restored, the program no longer compiles: the put method of Box<Integer> accepts only an Integer. The error from Section 1.5.1 is now caught at compile time.

Figure 1.4 sums up the relationship: the code is written once and then used, for each type argument, as if it were a separate, type-safe class. The benefits of generics come down to three points. Type checking happens at compile time, so a wrong type is caught before the program runs. No cast is needed for a value taken out of the box. And code duplication disappears.

Common mistake

Using a generic type without a type argument: Box b = new Box();. Java allows this for compatibility with old code and only prints a warning. But the box then reverts to the old box that accepts any Object, and type safety is lost. Always use a generic class with a type argument in angle brackets.

1.5.3Wrapper classes and autoboxing

Type parameters have one important restriction: T can only be a reference type. You cannot write Box<int>. The reason is that, inside a generic class, values of type T are always handled as references, and a primitive value is not a reference; it holds its value directly.

The solution is the wrapper classes that Java provides for every primitive type. A wrapper object is a small heap object that carries a single primitive value: Integer for int, Double for double, Character for char, Boolean for boolean, and so on. That is why a box of integers is written Box<Integer>.

It would be tedious for the programmer to put every primitive value into its wrapper by hand, so Java does the conversion automatically. When an int is supplied where an Integer is expected, it is automatically placed in an Integer object; this is called autoboxing. That is what the comment on the line m.put(42) (“int → Integer”) is about. The reverse happens too: when an Integer is used in arithmetic or assigned to an int variable, the value inside it is extracted; this is called unboxing.

Example 1.7

After 42 has been put into the box Box<Integer> m, the line int sum = m.get() + 8; is executed. Which conversions take place?

  1. m.put(42): 42 is an int, but put expects an Integer. Java creates an Integer object with the value 42 on the heap and stores a reference to it in the field item (autoboxing).
  2. m.get(): returns a reference to the Integer object.
  3. + 8: Addition is done on primitive values. Java extracts the 42 from inside the object (unboxing) and computes 42 + 8 = 50.
  4. Assignment: 50 is an int and is stored directly in sum.

Autoboxing makes code shorter, but it brings two pitfalls. The first is null. The get() method of a Box<Integer> into which nothing has been put returns null. When that value is assigned to an int, Java tries to extract a value from it and throws a NullPointerException. The second pitfall is comparison:

Integer i1 = 127, i2 = 127;
Integer i3 = 128, i4 = 128;
System.out.println(i1 == i2);         // true
System.out.println(i3 == i4);         // false
System.out.println(i3.equals(i4));    // true

Since Integer is a reference type, == compares the addresses of the two objects. Java keeps ready-made objects for the integers from −128 to 127 and reuses them when boxing. So for 127 the two variables point to the same object, and == gives true. For 128 two separate objects are created, and == gives false. equals, which compares contents, gives the right answer in both cases.

Common mistake

Comparing two Integers taken out of a generic structure with ==. In tests with small numbers the code works; on real data, the first value above 127 makes it silently give the wrong answer. Compare wrapper objects with equals, or convert them to int first.

1.5.4Java collections

All of the data structures in Java's standard library are generic. Together they are called the collections. Two of the most frequently used are ArrayList<E> and Map<K,V>. An ArrayList<E> is a list that keeps elements of type E in order and grows as needed. A Map<K,V> maps keys of type K to values of type V, so it takes two type parameters. The following code uses three collections together:

ArrayList<String> list = new ArrayList<>();
list.add("Ann"); list.add("Ben"); list.add("Ann");
HashSet<String> set = new HashSet<>(list);
HashMap<Integer, String> students = new HashMap<>();
students.put(101, "Alice");
students.put(102, "Bob");
students.put(101, "Carol");
System.out.println(list.size() + " " + set.size());     // 3 2
System.out.println(students.size() + " " + students.get(101));  // 2 Carol
System.out.println(students.get(103));                  // null

A list can hold the same element more than once; after the three calls to add, its size is 3. A HashSet is a set and holds each element only once; when it is built from the list, the second “Ann” is dropped and the size is 2. In a HashMap the keys are unique: a second put with the same key does not add a new pair but overwrites the old value. So key 101 now maps to “Carol,” and the map holds 2 pairs. For a key that is not present (103), get returns null.

The type parameters provide protection in this code as well. Had we written students.put("101", "Alice"), the compiler would have seen that the key is a String rather than an Integer and refused to compile the program. The data structures we write ourselves in this course are written the same way, as generic classes.

1.6Non-primitive data structures

A primitive type holds a single number, a single character, or a single logical value. Real programs, however, process hundreds of students, thousands of cities, millions of words at once. This section introduces the structures that hold many values together in a particular arrangement.

1.6.1Composite structures

Structures built from primitive types and from other structures are called non-primitive data structures. They can be grouped roughly by the kind of relationship they establish among their elements:

  • Sequential: arrays and lists. The elements are in a sequence; each element has one before it and one after it.
  • Linked: linked lists. The sequence is formed by references that connect the elements.
  • Hierarchical: trees. Each element can have one element above it and several below it.
  • Network: graphs. Each element can be related to any number of other elements.
  • Indexed: hash tables. An element's location is computed from its own key.
  • Besides these, sets, maps, and many other structures.

Non-primitive structures share three properties. First, they are composite and can contain more than one primitive value, even values of different types. Second, most of them are dynamically sized: they grow as elements are added while the program runs and shrink as elements are removed. Arrays are the exception to this rule; in Java the length of an array is fixed at the moment it is created and never changes afterward. Third, each structure is specialized for certain operations: one hands back the most recently added element quickly, another finds a key quickly, and yet another is well suited to finding a path between two points.

1.6.2The same four values in eight structures

The best way to see how the structures differ is to look at how the same data sits in each of them. Figure 1.5 shows the same values, 7, 2, 9, and 5, in eight different arrangements. Each has its own strengths and weaknesses.

(a) Array. The values sit in consecutive cells with indices 0 through 3. a[2] yields 9 in a single step; thanks to the address calculation of Section 1.2.3, access by index is O(1). The size, however, is fixed: there is no room for a fifth value.

(b) Linked list. Each value is in a separate node, and each node points to the next: 7 → 2 → 9 → 5 → null. A single reference to the head of the list is all we need. Adding a new node changes the direction of only a few arrows, and the size is flexible. The price is that reaching element i means starting at the head and following i arrows, which is O(n).

(c) Stack. The values are piled one on top of another; 7 is at the bottom, and 5, the most recently added, is on top. Insertion (push) and removal (pop) happen only at the top. This discipline is called LIFO (last in, first out). The next pop returns 5.

(d) Queue. The values are lined up in order of arrival: 7 at the front, 5 at the rear. New elements enter at the rear and leave from the front. This discipline is called FIFO (first in, first out). The next removal returns 7. A stack and a queue release the same four values in exactly opposite orders.

(e) Tree. The values form a hierarchy. 7 is the root; 2 and 9 are its children; 5 is a child of 2. Nodes 9 and 5, which have no children, are leaves. There is exactly one path from the root to any node.

(f) Graph. The values are nodes, and the lines between them are edges. In the graph in the figure, each of 7, 2, 9, and 5 is connected to two or three other nodes. What distinguishes a graph from a tree is that the relationship need not be hierarchical: a node can be reached by more than one path, and edges can form cycles. A relationship of this kind is called many-to-many.

(g) Hash table. The values have been placed in a 5-cell array, with each location computed by a hash function h(k). The function in the figure is h(k) = k mod 5, the remainder when the value is divided by 5. We have 5 mod 5 = 0, 7 mod 5 = 2, and 9 mod 5 = 4. 2 mod 5 is also 2, but cell 2 already holds 7. Two values landing in the same cell is called a collision, and hash tables use additional rules to resolve collisions. When collisions are rare, looking up a value amounts to computing its cell and checking there, which is why search in a hash table takes O(1) time on average.

(h) Set. A set holds only distinct elements, and their order does not matter. Adding 7 again to the set {7, 2, 9, 5} leaves it unchanged: {7, 2, 9, 5} ∪ {7} is the same set. A close relative of the set, the map, associates a value with each distinct key (key → value).

Example 1.8

Using the same 5-cell table and the function h(k) = k mod 5, we want to insert 13 and 20 after the values 7, 2, 9, and 5. Which cells do they land in?

  1. 13: 13 = 5 · 2 + 3, so the remainder is 3. Cell 3 is empty, and 13 goes there.
  2. 20: 20 = 5 · 4 + 0, so the remainder is 0. Cell 0 already holds 5; this is a collision.
  3. Observation: The 5-cell table now holds 6 values, and 2 collisions have occurred (2 with 7, and 20 with 5). As the table fills up, collisions become more frequent. That is why a hash table moves to a larger table once it is filled beyond a certain proportion.
Common mistake

Believing that one structure is best at every operation. An array is unbeatable for access by index but slow at inserting in the middle; a linked list is just the opposite. A hash table is very fast at lookup by key but does not return its elements in sorted order. Each of the eight structures gives up some operations in order to make others cheap.

1.7Abstract data types and data structures

The word “stack” can mean two different things. The first is a behavior: elements are added at the top and removed from the top, so the last one in is the first one out. The second is that behavior built in memory: a particular array, a particular index variable, a particular piece of code. Keeping these two levels apart is the key to understanding and designing data structures.

1.7.1What versus how

Definition 1.7

An abstract data type (ADT) specifies which operations can be performed on a kind of data and how those operations behave; it is not concerned with how the operations are carried out. A data structure, by contrast, is a concrete structure that implements an abstract data type: it determines how the data is laid out in memory and the steps by which each operation proceeds.

Lists, stacks, queues, sets, maps, and graphs are abstract data types; each is a description of behavior. Linked lists, arrays, and adjacency matrices are data structures; they are ways of building abstract data types in memory. An ADT focuses on behavior, a data structure on the details of memory and performance.

An analogy makes the distinction sharper. What a car offers its driver is a steering wheel, an accelerator, and a brake pedal; a driver who knows this “interface” can drive any car. Whether the engine runs on gasoline or electricity, or what mechanism the brakes use, is of no concern to the driver. The pedals and the steering wheel correspond to the ADT, the engine and the brake mechanism to the data structure. The same interface can be provided by entirely different mechanisms, and the driver can switch cars without noticing.

Figure 1.6 illustrates the relationship with a list. The List ADT offers four operations: add an element, remove an element, get element i, and report the size. An array can provide these four operations, and so can a linked list. From the user's point of view, the two implementations do the same thing. Where they differ is cost: in an array, get(i) finishes instantly, but adding at the front shifts every element; in a linked list, adding at the front finishes instantly, but get(i) walks the list from the beginning. Saying “a stack is a data structure, and so is an array” and putting the two on the same level. A stack is an ADT: it describes behavior only. 1.7.2From ADT to Java: the interface

Java provides two separate language features for the distinction between “what” and “how.” An interface is the means of writing down the contract of an ADT: it states which methods exist, what each takes, and what each returns, but it contains no method bodies. Here is the interface for the stack ADT:

public interface Stack<E> {
  int size();         // number of elements
  boolean isEmpty();  // is the stack empty?
  void push(E e);     // add on top
  E top();            // return the top element
  E pop();            // remove the top element
}

The interface defines five operations. size() returns the number of elements in the stack, and isEmpty() returns whether the stack is empty. push(e) adds the element e on top. top() returns the top element without removing it, whereas pop() removes the top element and returns it. The interface is generic: E is the type of the elements the stack will hold, and the interface is written only once for every element type.

The interface has no fields and no method bodies. It says nothing about whether the elements will be kept in an array or in linked nodes. That information comes from a class: a class that declares implements Stack<E> must supply all five methods of the interface, complete with bodies. In short, the interface is the contract of the ADT and says what is to be done; the class is the data structure and says how it is done. The same ADT can have several implementations.

Code that uses the stack is called client code. Figure 1.7 shows that the client depends only on the interface. The client creates a stack like this:

Stack<Integer> s = new ArrayStack<>(10);

The type of the variable is the interface (Stack<Integer>), while the object created belongs to a particular class (ArrayStack). All code after this line can use only the operations in the interface, such as s.push(…) and s.pop(). To change the implementation, for example to switch to a stack that uses linked nodes instead of an array, only this line changes: we write new LinkedStack<>() instead of new ArrayStack<>(10). The rest of the client code stays the same.

Common mistake

Declaring the variable with the class type: ArrayStack<Integer> s = …. The program works, but the client is now tied to the class. If it has used a method specific to that class (a debugging method, say), changing the implementation affects all of the client code. A variable declared with the interface type ties the client only to the contract.

1.7.3An implementation: ArrayStack

The idea behind building the stack ADT on an array is simple. The elements are placed in order from the beginning of the array: the first one added goes into cell 0, the second into cell 1, and so on. The top of the stack is the last occupied cell, so a single variable holding that cell's index is all we need; let us call it t (for top).

public class ArrayStack<E> implements Stack<E> {
  private E[] data;         // the elements
  private int t = -1;       // index of the top element
  public ArrayStack(int capacity) {
    data = (E[]) new Object[capacity];
  }
  public int size() { return t + 1; }
  public boolean isEmpty() { return t == -1; }
  public E top() {
    if (isEmpty()) return null;
    return data[t];
  }
  // push and pop
}

Let us read the class line by line.

  • implements Stack<E>: the class accepts the stack contract. The class's type parameter E is passed on to the interface's E.
  • private E[] data: the array that holds the elements. The keyword private prevents access to this field from outside the class. The client cannot modify the array directly; it can use only the operations in the interface. This preserves the rule of the stack: access at the top only.
  • private int t = -1: the index of the top element. An empty stack has no top element, and −1 signals this, because −1 is not a valid array index.
  • The constructor creates an array of the requested capacity. In Java you cannot write new E[capacity]: the type parameter is unknown while the program runs, and Java cannot create an array of an unknown type. So we create an Object array and assign it to data with an (E[]) cast. The compiler issues an “unchecked cast” warning for this line; the cast is safe because the array is used only inside the class and only elements of type E are ever put into it.
  • size(): the elements occupy cells 0 through t, so there are t + 1 of them. For an empty stack this gives −1 + 1 = 0.
  • isEmpty(): the stack is empty if t == -1.
  • top(): if the stack is empty, there is no element to return, and the method returns null. Otherwise it returns the top element, data[t]. The element is not removed from the stack; t does not change.

Figure 1.8 shows an intermediate state. First 5 and then 8 have been added. t is 1 and indicates the cell holding 8. Cells 2 and 3 of the array are empty, waiting for new elements.

Common mistake

Taking t to be “the number of elements.” t is the index of the top element; the number of elements is t + 1. This confusion leads to off-by-one errors both in size() and in the check for a full stack. Some books use a variable that holds the number of elements instead of an index; an empty stack is then represented by 0. Either approach is correct, but the two must not be mixed in the same class.

1.7.4push and pop

The two methods still missing from the class are the ones that modify the stack. The slides present them together with a short piece of client code that uses them:

public void push(E e) {
  if (size() == data.length)
    throw new IllegalStateException("full");
  data[++t] = e;
}
public E pop() {
  if (isEmpty()) return null;
  E e = data[t];
  data[t--] = null;     // clear for GC
  return e;
}
s.push(5); s.push(8);
System.out.println(s.pop());
s.push(3);

push(e). The method first checks whether the array is full: if the number of elements equals the length of the array, there is no room for the new element. In that case the method throws an IllegalStateException; adding to a fixed-capacity stack while it is full is called overflow. If there is room, the line data[++t] = e runs. ++t first increments t and then uses the incremented value as the index. In other words, increment first, then write. Had we written data[t++] = e, the element would have overwritten the old top.

pop(). An empty stack has no element to remove, so in that case the method returns null. If the stack is not empty, the top element is saved in e. The line data[t--] = null does two things: it first writes null into the cell indicated by the old value of t, and then decrements t. The reason for clearing the cell is the garbage collector. If the cell kept pointing to the old element, the object could not be reclaimed even after the client had finished with it. Finally, the saved element is returned.

Common mistake

Clearing the cell in pop before reading the element: data[t--] = null; return data[t];. The first line both erases the element and decrements t; the second returns not the element that should have been removed but the one below it. The correct order is: first save the element in a variable, then clear the cell and decrement t, and finally return the variable.

Example 1.9

The operations push("a"), push("b"), and push("c") are applied to an empty ArrayStack<String> of capacity 2. What happens? And what do pop() and top() return on an empty stack of capacity 3?

  1. push("a"): size() = 0 ≠ 2; t = 0, data = ["a", null].
  2. push("b"): size() = 1 ≠ 2; t = 1, data = ["a", "b"]. The array is now full.
  3. push("c"): size() = 2 = data.length. The method throws an IllegalStateException with the message "full"; the stack is unchanged.
  4. Empty stack: Since t = −1, isEmpty() returns true. Both pop() and top() return null.

The last step of the example reflects a design decision: this class reports an attempt to remove from an empty stack (underflow) not as an error but by returning null. Some libraries throw an exception in this situation. Both approaches are in use, but with a stack that returns null, the client must check whether the returned value is null before using it. Moreover, if null has been pushed onto the stack as an element, there is no way to tell whether a null returned by pop means “the stack was empty” or “null was on top.”

1.7.6The cost of the operations

To compare the operations of a data structure, we look at how much work each operation does. The usual tool for this is Big O notation. We do not need its details here; it is enough to know two meanings. O(1) says that the number of steps an operation takes is constant, independent of the number of elements in the structure. O(n) says that the number of steps grows in proportion to the number of elements n: when the number of elements doubles, the work roughly doubles too.

Table 1.7: Cost of the ArrayStack operations (N: capacity).

Table 1.7 says that every operation is O(1). The justification lies in the code itself. size performs one addition, isEmpty one comparison, and top one comparison and one array access. push performs a comparison, an increment, and a write. pop performs a comparison, a read, a write, and a decrement. None of the methods contains a loop, and array access takes a single step thanks to the address calculation of Section 1.2.3. Whether the stack holds 3 elements or 3 million, every operation finishes in the same number of steps.

Memory, on the other hand, is proportional to the capacity: a stack of capacity N reserves an array of N cells no matter how many elements it holds. This is the price of the array-based implementation. The capacity is fixed, and once it is reached, push throws an exception. Choose a capacity larger than needed and memory is wasted; choose one too small and the stack fills up early. There are two ways around this problem: move to a larger array when the array fills up, or abandon the array and use linked nodes. Either way, the stack ADT does not change; only the class that implements it does. That is the practical payoff of the distinction drawn in Section 1.7.1.

1.8Organizing data and choosing a structure

Before choosing a data structure, we need to see how the data items relate to one another. Are the items independent of each other, do they form a sequence, do they make up a hierarchy, or do they form a complex network? The answer narrows down the list of suitable structures considerably.

1.8.1Four ways to organize data

Figure 1.10 shows the four basic arrangements. Table 1.8 gives the relationship each one establishes among its elements, along with an everyday example.

Table 1.8: Ways to organize data.

Nonpositionalnonethe students in a class

In a nonpositional arrangement there is no relationship among the elements. The students in a class form a group, but there is no such notion as “the student after Alice.” The questions asked of such data concern membership: Is Bob in this class? How many students are there? Sets and maps are the structures that fit this arrangement.

In a sequential arrangement each element has at most one predecessor and at most one successor; the relationship is one-to-one. Among students waiting in line at the cafeteria, everyone has one person in front and one behind, with the first and last person as the only exceptions. Arrays, lists, linked lists, stacks, and queues are sequential structures. What distinguishes them is at which ends of the sequence elements can be added and removed.

In a tree arrangement each element has at most one element above it (its parent) but may have several below it (its children); the relationship is one-to-many. This arrangement appears in a family tree, in a company's organization chart, and in the folder structure on a computer. Each folder has exactly one parent folder but can contain many subfolders.

In a graph arrangement each element can be related to any number of other elements; the relationship is many-to-many. On a road map, roads lead from one city to many others, and each city can be reached from many others. Friendships in social networks and computer networks are graphs too. The graph is the most general arrangement: sequences and trees are restricted special cases of graphs.

Example 1.10

Which arrangement does each of the following fit?

  1. The chapters, sections, and subsections of a book: Each subsection belongs to exactly one section, and each section to exactly one chapter, while a chapter has many sections. The relationship is one-to-many: a tree. The table of contents of these notes is just such a tree.
  2. The stops on a bus route: Each stop has a previous stop and a next stop: sequential.
  3. The prerequisite relationships among courses at a university: A course can have several prerequisites, and a course can be a prerequisite for several others. The relationship is many-to-many: a graph.
  4. A library's list of members: There is no order or hierarchy among the members; what matters is whether a person is a member: nonpositional.

1.8.2Choosing a data structure

To choose the right structure, we must first understand how the data will be used. The following questions are decisive.

  • Can the data structure be filled completely at the start? If all the data is known in advance (the names of the twelve months, for example), the structure is built once and afterward only read. If the data arrives over time, the structure must be able to grow.
  • Can elements be deleted from the data structure? If no deletions are needed, the structure can be kept much simpler. If deletions are frequent, we need a structure that can cheaply close the gap a deleted element leaves behind.
  • Does the order of insertion matter? If elements are to be processed in order of arrival, a queue fits; if the most recent arrival is to be processed first, a stack fits. If order does not matter, consider a set or a map.
  • Can the elements in the data structure be sorted? If the elements can be ordered by size or alphabetically, fast methods such as the halving search of Section 1.2.1 become available.
  • Are the elements processed in a fixed order, or is random access needed too? If access by position (“give me element 5”) is needed often, use an array; if it is enough to traverse from beginning to end, a linked list will also do.

These questions lead to a common conclusion: if the data will not change, prefer static structures; if there are frequent insertions and deletions, prefer dynamic ones. A static structure, such as a fixed-size array, is built once and provides the fastest access. A dynamic structure, such as a linked list, adapts to change but is somewhat slower to access.

Figure 1.11 gathers these questions into a flow. The flow is not a hard rule but a starting point. In real problems, more than one question may get a “yes,” and then several structures are used together.

Example 1.11

We are designing a dictionary app. When the user types a word, its meaning must appear immediately; in addition, the 20 most recently looked-up words must be listed, with the latest one at the top. Which structures are suitable?

  1. Word → meaning: Access by index is not needed (words have no numbers), and frequent insertion in the middle is not the main need either. The answer to “lookup by key?” is yes: the key is the word, the value its meaning. The suitable structure is a map; with a hash table, lookup takes O(1) time on average.
  2. Recently looked-up words: The latest word must appear at the top, so the answer to “must the last added leave first?” is yes. The suitable ADT is a stack. The limit of 20 suggests a structure with a fixed capacity.
  3. A subtle point: When the limit is exceeded, the oldest word must be dropped, but a pure stack removes only from the top. A structure that allows operations at both ends is therefore a better fit. The first “yes” in the flow is a starting point; always recheck the full set of requirements.
Common mistake

Choosing the most familiar structure, usually an array or an ArrayList, for every problem. Answering the question “have we seen this word before?” with a list means scanning the list from beginning to end every time. For a text of a million words, this can add up to comparisons on the order of 1012, as in Section 1.1.3. A set answers the same question in constant time on average.

A linked list suits situations in which the number of elements changes constantly and insertions at the front or in the middle are frequent. In a music player, songs can be added to or removed from a playlist without moving the other songs.

A priority queue removes elements by priority rather than by order of arrival. In an emergency room, patients are seen not in the order they arrive but according to how serious their condition is. This structure is usually built with a special kind of tree called a heap.

Maps and hash tables are the way to get quickly from a key to a value. Going from a student ID to the student's record, or from a word to the number of times it occurs in a text, are typical uses. A web browser's cache is also a map, from addresses to page contents.

The set is the structure for removing duplicates and for answering “is this element present?” quickly. It also supports mathematical operations such as the union and intersection of two sets directly.

The graph models the most general relationships. A map app stores cities or intersections as nodes and roads as edges, and searches this graph for the shortest path between two points. When numbers such as distances are attached to the edges, the graph is called a weighted graph.

Let us choose suitable structures for the following requirements of a multiplayer online game.

  1. Getting from a player's name to the player's data: lookup by key → map (hash table).
  2. Players waiting to join the game, in order of arrival: FIFO → queue.
  3. The regions of the map and the passages between them: each region leads to many others → graph.
  4. The kinds of items in a player's inventory, without repetition: uniqueness → set.
  5. Guild structure (leader, officers, members): hierarchy → tree.

1.11Summary

  • Digital data is text, numbers, images, and sound represented as 0s and 1s. An ADC turns an analog signal into numbers, and a DAC turns the numbers back into a signal. n bits represent 2n values. Text is represented with character encodings (ASCII, Unicode), fractional numbers with IEEE 754, images with the RGB values of pixels, and sound by sampling.
  • An algorithm is a step-by-step plan for carrying out a task; a data structure is a way of organizing and storing data. In Wirth's words: Algorithms + Data Structures = Programs. Every structure makes some operations cheaper and others more expensive. The basic building blocks of structures are objects, arrays, and links.
  • A data type defines a set of values together with its operations. Java's eight primitive types have fixed sizes; when a limit is exceeded, the value wraps around. The quotient of two ints is an int. Type safety catches operations that violate the types at compile time.
  • In Java, local variables live in frames on the call stack, and objects live in heap memory. A primitive variable holds a value; a reference variable holds an address. For primitive types = copies the value, for reference types the address; two references can point to the same object (aliasing). Java passes parameters by value. The garbage collector reclaims objects that can no longer be reached.
  • Generics (Box<T>) let us write a single class for every reference type and catch type errors at compile time. A type parameter cannot be primitive: we use Integer instead of int, and autoboxing handles the conversion. Java's collections are generic.
  • An abstract data type specifies what is to be done (the behavior); a data structure specifies how it is done (the memory layout). In Java, an ADT is written as an interface and a data structure as a class that implements it. If the client uses variables of the interface type, changing the implementation takes a one-line edit.
  • ArrayStack builds a stack from an array and a top index t: in an empty stack t = −1, and size() = t + 1. push increments first and then writes; pop reads first and then clears the cell. All operations are O(1); memory is proportional to the capacity, and once the capacity is reached, push throws an exception.
  • Data can be organized in nonpositional, sequential, tree, and graph arrangements. The choice of structure is driven by the access pattern, how often elements are inserted and deleted, whether order matters, and the kind of relationship; static structures suit data that stays put, dynamic structures data that changes often.

1.13Test Yourself

  1. What is the minimum number of bits needed to represent 1000 different values? How is the number 200 written in eight bits, and what value does the Java expression (byte) 200 produce?

    Answer

    9 bits give 29 = 512 values, which is not enough; 10 bits give 210 = 1024 values. So at least 10 bits are needed. Since 200 = 128 + 64 + 8, it is written 11001000. A byte is signed and holds at most 127; because the leftmost bit is 1, this bit pattern is read as negative: 200 − 256 = −56.

  2. Given int a = 9;, what do the expressions a / 4 * 4 and a * 4 / 4 produce? Why do they differ?

    Answer

    The first gives 8, the second 9. The operations are evaluated left to right. In the first, integer division makes 9 / 4 equal to 2, and the fractional part is lost; 2 · 4 = 8. In the second, 9 · 4 = 36 is computed first, and then 36 / 4 = 9 divides exactly, with no loss.

  3. After the following lines, which arrays do r and r2 point to?

    int[] r = {3, 4, 5};
int[] r2 = r;
r2[2] = r2[0] + r2[1];
r2 = new int[]{0, 0, 0};
r2[0] = 1;
    Answer

    r: [3, 4, 7], r2: [1, 0, 0]. The second line copies only the reference; the third writes 3 + 4 = 7 into cell 2 of the shared array, so r changes too. The fourth line points r2 to a new array, and the fifth changes only that new array.

  4. After the lines StringBuilder sb = new StringBuilder("ab"); StringBuilder sb2 = sb; sb2.append("c");, what does sb contain? What would change if we used String instead of StringBuilder and sb2 = sb2 + "c" instead of append?

    Answer

    sb contains "abc". A StringBuilder is a mutable object; sb and sb2 point to the same object, and append changes its contents. A String, however, is immutable: sb2 + "c" creates a new object, and the assignment merely redirects sb2's arrow to it. In that case sb would remain "ab".

  5. After the lines Box<Double> d = new Box<>(); d.put(2.5);, what value does double x = d.get() * 2; produce? Does the line d.put(3); compile?

    Answer

    x becomes 5.0: 2.5 was automatically boxed into a Double and unboxed for the multiplication. d.put(3) does not compile. 3 is an int, and Java can box it only into an Integer, which is not a Double. The correct call is d.put(3.0).

  6. The calls push(4), push(6), pop(), push(1), top(), pop(), push(2), push(8) are made in this order on an empty ArrayStack<Integer> of capacity 3. What do the calls that return a value return? What are t and data at the end? What happens if push(5) is then called?

    Answer

    The returned values are 6, 1, and 1, in that order: the first pop returns 6, top returns 1 without removing it, and the second pop returns 1. Then 2 and 8 are added. The final state is t = 2, data = [4, 2, 8]; the array is full. In push(5), size() = 3 = data.length, so an IllegalStateException is thrown.

  7. Which of the following are abstract data types and which are data structures: queue, array, map, linked list, set, adjacency matrix?

    Answer

    Queue, map, and set are abstract data types: they describe which operations can be performed. Array, linked list, and adjacency matrix are data structures: they determine how the data is kept in memory. The queue ADT, for example, can be built with an array or with a linked list, and the graph ADT can be stored in an adjacency matrix.

  8. Which structure suits each of the following requirements? (a) Callers waiting at a call center, (b) a company's organization chart, (c) the number of distinct users who visit a website, (d) the prerequisite relationships among courses.

    Answer

    (a) A queue: callers are connected in order of arrival (FIFO). (b) A tree: each employee has exactly one manager, and each manager has many employees (one-to-many). (c) A set: a user who visits several times must be counted only once; the size of the set is the answer. (d) A graph: a course can have several prerequisites and can itself be a prerequisite for several later courses (many-to-many).

  9. The values 10, 24, 3, and 17 are placed in a 7-cell table using h(k) = k mod 7. Which cells do they land in? What would happen if the same values were placed in a 5-cell table using k mod 5?

    Answer

    With mod 7, all four land in cell 3: 10 = 7 + 3, 24 = 21 + 3, 3 = 0 + 3, 17 = 14 + 3. Every insertion after the first is a collision, and lookup can no longer be done in constant time. With mod 5, the cells are 0, 4, 3, and 2, and there are no collisions at all. How evenly the hash function spreads values over the cells is decisive for the speed of the table.

  10. A client has written a 500-line program that begins with the line Stack<String> s = new ArrayStack<>(100);. To escape the stack's capacity limit, the client wants to switch to the LinkedStack class, which uses linked nodes. How many lines change? What would have happened if the variable had been declared with type ArrayStack<String>?

    Answer

    Only the first line changes: new LinkedStack<>() replaces new ArrayStack<>(100). Since the program uses only the five operations of the interface, the remaining lines work exactly as before. Had the variable been declared with the class type, at the very least the type declaration would also have had to change. And if the program had used a method specific to ArrayStack, those lines would have had to be rewritten as well.
