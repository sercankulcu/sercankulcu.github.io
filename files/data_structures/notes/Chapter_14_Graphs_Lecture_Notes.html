Chapter 14: Graphs

Cities and the roads between them, people in a social network and their friendships, the courses in a department and their prerequisites: all three are described by the same abstract structure, a set of objects together with pairwise relationships among them. That structure is a graph. A tree gives every node one parent and forbids cycles; a graph drops both restrictions, so a vertex may be reachable along many routes, and a route may come back to where it started. We begin with the basic vocabulary of graphs, then look at how a graph is stored in memory and how that choice shapes the cost of each operation. Next come breadth-first and depth-first search, together with the algorithms built on them: finding components, testing bipartiteness, topological sorting, and cycle detection. The last two topics are shortest paths (BFS for unweighted graphs, Dijkstra for weighted ones) and minimum spanning trees (Kruskal and Prim).

14.1Basic concepts

Graph algorithms speak a small vocabulary: vertex, edge, degree, path, cycle, connectivity. The words mean roughly what they do in everyday speech, but each has a precise definition, and correctness arguments rest on it.

14.1.1What is a graph?

A city map shows intersections, the roads between them, and much detail besides: lengths, slopes, lanes. To answer “which intersection can I reach from which?” two facts suffice: the intersections, and which pairs are joined directly by a road. The abstract structure built from these two facts is a graph.

Definition 14.1

A graph is a pair G = (V, E), where V is a finite set of vertices (or nodes) and E is a set of edges. Each edge joins two vertices and is written (u, v). We write n = |V| for the number of vertices and m = |E| for the number of edges.

|V| is the size of V. Throughout, n counts vertices, m counts edges, and costs are stated in these terms: “O(n + m) time” grows with vertices plus edges.

Example 14.1

In set notation, the graph of Figure 14.1 is:

  • V = {0, 1, 2, 3, 4}, so n = 5.
  • E = {(0,1), (0,4), (1,2), (1,3), (1,4), (2,3), (3,4)}, so m = 7.

The edges have no direction: (0,1) and (1,0) are one edge, listed once. Picture and sets carry the same information; vertex positions and line shapes are not part of the graph.

A graph generalizes a tree, which has a root, one parent per non-root node, and no cycles. A graph requires none of this:

  • No root. No vertex is special; an algorithm must be told where to start.
  • Cycles. Edges can lead back to the start; in Figure 14.1, 1 → 2 → 3 → 1 is one.
  • Several routes. From 0 to 3 you can go 0 → 1 → 3 or 0 → 4 → 3.

A tree models one-to-many relationships; a graph models many-to-many ones. A person has many friends, each with many friends; a course has several prerequisites and is a prerequisite of several others. The algorithms pay for this flexibility: they may reach a vertex twice and must notice.

Common mistake

Mistaking a drawing of a graph for the graph. The same graph can be drawn in many ways; moving vertices or letting two edges cross creates no new vertex or edge, and a crossing point is not a vertex. A graph is defined by its sets V and E alone.

14.1.2Vertices and edges

A vertex stands for a modeled object: a city, a person, a computer, a web page, a course. It may carry a label, name, or position, but algorithms prefer vertices numbered 0 to n − 1, so per-vertex data can live in arrays indexed by vertex.

Modeled as a graph, “what is the shortest route from Istanbul to Van?” becomes a graph algorithm problem; with road lengths on the edges, Dijkstra's algorithm solves it (14.4.4). Modeling keeps the essence and drops the rest: paving is irrelevant to the shortest route, length is not.

An edge stands for a relationship: a road, a network link, a friendship. If (v, w) is an edge, v and w are adjacent, each a neighbor of the other, and the edge is incident to both. In Figure 14.1, 1 and 3 are neighbors; 0 and 2 are not.

Figure 14.3 shows a typical trait of real networks: many vertices, few neighbors each. Millions of members, but at most a few thousand friends per person, so the edges are a tiny fraction of those possible. Such graphs are sparse, and sparsity decides how to store them (14.2.6).

14.1.3Degree and the handshake lemma

Definition 14.2

In an undirected graph, the degree of a vertex v, written deg(v), is the number of edges incident to v. A vertex of degree 0 is an isolated vertex. An edge joining a vertex to itself is a self-loop, and it contributes 2 to the degree.

An intersection's degree is the number of roads meeting there. A road that leaves an intersection and returns to it is attached at both ends, which is why a self-loop counts twice.

The degrees in Figure 14.4 sum to 1 + 3 + 3 + 2 + 5 + 2 + 0 = 16, and the graph has seven ordinary edges plus a self-loop, eight in all. The sum being exactly twice the edge count is no accident.

Theorem 14.1 (Handshake lemma)

In every undirected graph, the degrees sum to twice the number of edges: Σ deg(v) = 2m.

Ask how often each edge is counted. An edge (u, v) adds 1 to deg(u) and 1 to deg(v) and touches no other degree; a self-loop has u = v and by definition also adds 2. Every edge adds exactly 2, so m edges add 2m. □

At a party, the numbers of hands each guest shook add up to twice the number of handshakes, since each handshake involves two hands. Two consequences:

  • The degrees give the edge count: m = Σ deg(v) / 2. Degrees summing to 30 mean 15 edges.
  • The sum is even, so the number of odd-degree vertices is even. No graph has degrees 3, 3, 2, 2, 1: their sum is 11.
Common mistake

Forgetting to divide the degree sum by two. Each edge is counted once at each end, so the sum is twice the number of edges. The same slip appears in memory estimates: the adjacency lists of an undirected graph hold 2m entries, not m.

14.1.4Directed graphs

Friendship is symmetric, and a two-way road runs both ways. Other relationships go one way: a web page may link to one that does not link back, a prerequisite does not work in reverse, a one-way street runs one way. These are modeled by a directed graph, or digraph.

Definition 14.3

In a directed graph, each edge is an ordered pair (u, v), drawn as an arrow from u to v. u is the edge's tail (its origin) and v its head (its destination); (u, v) ≠ (v, u). The in-degree of a vertex is the number of arrows entering it, and its out-degree the number leaving it.

Common mistake

Treating directed adjacency as two-way. An edge (u, v) makes v a neighbor of u, but without (v, u), u is not a neighbor of v. That does not make u unreachable from v: an indirect path may exist.

14.1.5Paths and cycles

Definition 14.4

A path is a vertex sequence v0, v1, …, vk in which each (vi, vi+1) is an edge. A path repeating no vertex is a simple path. A path that ends where it starts is a cycle; it is a simple cycle if no vertex repeats except the start at the end.

In an unweighted graph a path's length is its number of edges: k + 1 vertices, length k. A path that follows the arrows of a directed graph is a directed path; such a cycle is a directed cycle.

Both cycles in Figure 14.6 have length six, and there are others: C → G → L → C uses the edges C–G, G–L, and L–C. The number of cycles grows fast with the number of edges.

In a tree, exactly one simple path joins any two nodes. In a graph there may be several, and two different simple paths together form a cycle. Istanbul → Ankara → Izmir → Istanbul is a simple cycle of flights: no city is visited twice. Istanbul → Ankara → Izmir → Ankara → Istanbul passes Ankara twice, so it is a cycle but not a simple one.

14.1.7Connected and complete graphs

Definition 14.5

An undirected graph is connected if there is a path between every two distinct vertices. A largest group of vertices that can all reach one another is a connected component. A graph is complete if every two distinct vertices are joined directly by an edge; the complete graph on n vertices is written Kn.

Connectivity asks for a path, completeness for an edge: a complete graph is connected, not necessarily vice versa. “Largest” matters: a component includes every vertex that can reach any of its members. Components split the vertices into disjoint groups; a connected graph has one.

The edge count has two bounds. In a simple undirected graph (no self-loops or parallel edges) each vertex pair has at most one edge, and there are n(n − 1)/2 pairs: n choices, then n − 1, halved because each pair is counted twice. So m ≤ n(n − 1)/2, with equality only when complete: K5 has 5 · 4 / 2 = 10 edges, the complete graph on 10 vertices 10 · 9 / 2 = 45.

A connected graph has m ≥ n − 1. Add edges one by one to an empty graph: it starts with n components, and each edge either merges two or falls inside one, so reaching one component takes at least n − 1 edges. A connected graph with exactly n − 1 edges is a tree, as we will see again with spanning trees (14.5.1).

These bounds separate sparse from dense graphs: m ≈ n is sparse, m ≈ n2 dense. Road and social networks are sparse; small groups where everyone knows everyone are dense.

14.1.8Weighted graphs

Often a connection has a cost: a road's length, a link's latency, a pipeline's price, a line's capacity.

Definition 14.6

In a weighted graph, each edge is assigned a number called its weight. The length or weight of a path is the sum of the weights of its edges. A weighted graph may be undirected or directed.

Example 14.4

In the undirected graph of Figure 14.10, the path 3 → 4 → 1 has length 5 + 3 = 8; in the directed graph, 1 → 4 → 3 has length 3 + 5 = 8.

The direct edge 1–3 weighs 10, yet 1 → 4 → 3 costs 8. A direct edge need not be the shortest path; more edges can be shorter if they are light.

Hence shortest-path algorithms. Without weights the shortest path has the fewest edges; with weights, edge counts mislead and the weight sum decides. An unweighted graph is a weighted one with all weights 1.

14.2Graph representations

A graph can be stored in three forms, each speeding up some operations and slowing others. We take them in turn, compare their costs, and trace how Java builds an adjacency list and matrix.

14.2.1Three representations; the edge list

The three basic ways to store a graph are:

  • Edge list: all edges in a single list, such as [(A,B), (A,E), …].
  • Adjacency list: for each vertex, a list of its neighbors, such as V[i] = {j, k, l}.
  • Adjacency matrix: an n × n array whose cell M[i][j] records whether there is an edge from i to j.

The edge list is the simplest: for Figure 14.11 it is (A, B) (A, E) (B, C) (B, E) (C, D) (D, E). A separate vertex list keeps edgeless vertices, for O(n + m) memory. Adding an edge appends one item: O(1).

Queries are the weakness. Testing adjacency means searching the unordered list for (u, v) or (v, u), O(m) in the worst case, and finding u's neighbors means scanning it all, since u's edges can be anywhere. Traversals ask this for every vertex, so they cost O(n · m). Kruskal's algorithm, which sorts edges by weight and never asks for neighbors, is where the edge list shines (14.5.3).

14.2.2The adjacency matrix

Definition 14.7

The adjacency matrix of a graph whose vertices are numbered 0 to n − 1 is an n × n array matrix with matrix[i][j] = 1 if there is an edge from i to j and 0 otherwise. In a weighted graph the cell holds the edge's weight, and a missing edge is marked with ∞ or some special value meaning the same.

An undirected edge (i, j) goes into both matrix[i][j] and matrix[j][i], so the matrix is symmetric about the diagonal: matrix[i][j] == matrix[j][i]. A directed graph's matrix is not.

The matrix's strength is direct access: a Java array cell is read or written in constant time, so three operations are O(1):

  • Testing for edge i–j reads matrix[i][j].
  • Adding an edge writes 1 into one cell (two if undirected).
  • Removing it writes 0 there.

It has two weaknesses. Listing neighbors scans all n cells of a row, O(n) even for a single neighbor. And the matrix takes n2 cells regardless of edges; in a sparse graph nearly all are 0, memory spent on edges that do not exist.

Example 14.5

A road network of a million vertices (n = 106) needs n2 = 1012 matrix cells, about 125 GB even at one bit each. But three or four roads meet at an intersection, so there are a few million edges: a few filled cells per million.

14.2.4The adjacency list

Definition 14.8

An adjacency list keeps one list per vertex, n lists in all. list[i] holds the neighbors of i (with their weights, in a weighted graph). The lists are usually linked lists or dynamic arrays.

An undirected edge (v, w) goes into two lists: w into v's and v into w's. A directed edge goes only into its source's list. Since only existing edges are stored, memory is n list heads plus the entries: 2m entries if undirected, m if directed, O(n + m) either way.

Lists are strong at traversal: visiting a vertex's neighbors reads its list in O(deg(v)), never touching non-neighbors as the matrix does. Adding an edge appends: amortized O(1) for a dynamic array, O(1) for a linked list.

They are weak at edge queries. Unless sorted, u's list must be scanned for v: O(deg(u)), or O(min(deg u, deg v)) if an undirected graph scans the shorter list. For high-degree vertices this is slow next to the matrix's O(1).

Choose by the graph's structure and its most frequent operation:

Example 14.6

Which representation suits a road network with n = 10,000 vertices and m = 30,000 edges?

  1. Matrix. n2 = 108 cells, of which 2m = 60,000 are filled in an undirected graph: 60,000 / 108 = 0.06%.
  2. List. n heads and 2m entries: 10,000 + 60,000 = 70,000 items, the same order as n + m = 40,000, so memory is O(n + m).
  3. Decision. The graph is sparse (m = 3n): choose the adjacency list. Traversal, too, takes O(n + m) with the list and O(n2) with the matrix.
Common mistake

Confusing the matrix's row scan with getEdge. In a matrix, testing for an edge reads one cell, O(1); what costs O(n) is scanning a row for all neighbors. Lists are the other way around: visiting neighbors is cheap, querying one edge relatively expensive.

14.2.7An adjacency list in Java

With vertices numbered 0 to n − 1, an adjacency list is a list of lists: item i of the outer list is the neighbor list of vertex i.

class Graph {
    private final int n;                                  // vertices: 0..n-1
    private final List<List<Integer>> adj = new ArrayList<>();
    Graph(int n) {
        this.n = n;
        for (int i = 0; i < n; i++)
            adj.add(new ArrayList<>());
    }
    void addEdge(int u, int v) {
        adj.get(u).add(v);
        adj.get(v).add(u);                    // omit this line in a directed graph
    }
    List<Integer> neighbors(int u) { return adj.get(u); }   // O(1)
    int degree(int u) { return adj.get(u).size(); }
}
  • adj is a List<List<Integer>>: one inner ArrayList (dynamic array) per vertex.
  • The constructor stores n and adds n empty lists in O(n). All vertices are known up front, so adj.get(u) is valid for every u.
  • addEdge(u, v) puts v in u's list and u in v's; a directed graph drops the second line. Like ArrayList.add, it is amortized O(1).
  • neighbors(u) returns the list itself, uncopied, in O(1); iterating over it costs the caller O(deg(u)).
  • degree(u) is the list's size, O(1) since ArrayList stores it.

The matrix version is shorter: boolean[][] m = new boolean[n][n]; creates it, m[u][v] = m[v][u] = true; adds an edge, m[u][v] queries. With weights, a list item becomes an int[]{v, w} or a small Edge class, and the matrix an int[][] with Integer.MAX_VALUE for missing edges.

Then the edges. addEdge(0, 1) appends 1 to 0's list, then 0 to 1's; every call does the same. Lists keep insertion order: 1's list is [0, 2, 4] because 0–1, 1–2, and 1–4 arrived in that order.

Six edges produce 2 · 6 = 12 entries. The list lengths 2, 3, 2, 2, 3 sum to 12, the handshake lemma as it shows up in code; degree(1) is the size of 1's list, 3. Each addEdge takes constant time, and memory is O(n + m).

Common mistake

Dropping the second line of addEdge in an undirected graph. The graph silently turns directed: 0–1 is in 0's list but not 1's, so a traversal from 1 never reaches 0. No error, just wrong answers. Conversely, adding a one-way relationship both ways invents return routes.

14.3Traversal: BFS and DFS

Most graph algorithms rest on a systematic exploration of the graph: breadth-first or depth-first search. Both visit the same vertices, in orders that suit different problems. Four applications follow: connected components, bipartiteness, topological sorting, and directed cycle detection.

14.3.1Traversal and visited marks

Definition 14.9

A traversal visits every vertex reachable from a starting vertex, each exactly once, in a systematic order.

There are two basic methods:

  • Breadth-first search (BFS) visits all neighbors of the start, then their neighbors, level by level, using a queue (FIFO: first in, first out).
  • Depth-first search (DFS) goes as deep as it can along one path, backs up at a dead end, and tries another branch, using a stack (LIFO: last in, first out) or recursion.

In a tree one path leads from the root to each node, so descending to children never reaches a node twice. A graph may have cycles and several routes to a vertex, so its traversal must record what it has seen, usually in a boolean[] visited array indexed by vertex.

Common mistake

Running a tree traversal on a graph unchanged. Without visited marks, a cycle traps the traversal forever; even without cycles, a vertex reached by several routes is processed repeatedly, and the cost can grow exponentially. The mark is part of the algorithm's correctness, not a detail.

14.3.2Breadth-first search

Drop a stone into water and the ripples spread in rings, near ones first, then farther ones. BFS works the same way: it finds the vertices one edge from the start, then those two edges away, then three. The vertices k edges from the start form level k.

A queue enforces this order: discovered vertices join the back, and processing takes from the front. All of level 1 enters before any of level 2, so all of level 1 is processed first.

The edges by which BFS discovers vertices form the BFS tree. In Figure 14.18, d is reachable from a or b; a comes first, so d enters along a–d and b–d stays out. Tree paths from the root have the fewest possible edges, the basis of unweighted shortest paths (14.4.1).

BFS finds unweighted shortest paths and discovers near vertices first: “friends of friends” is level 2, and a web crawler scans a site layer by layer. Its weakness is memory: a whole level may wait in the queue, which grows large in wide graphs.

  • visited[s] = true; q.add(s); marks and enqueues the start.

Common mistake

Marking on dequeue. On the triangle 0–1, 0–2, 1–2, such a BFS from 0 prints 0 1 2 2: removing 1 enqueues the still unmarked 2 a second time. In dense graphs the queue grows to O(m) instead of O(n).

Cost. Each vertex enters and leaves the queue once, O(n), and its list is scanned once; the lists total 2m entries, O(m). So BFS takes O(n + m) with lists and O(n2) with a matrix, whose rows have n cells. visited and the queue take O(n) extra memory.

14.3.5Depth-first search

In a maze, you walk a corridor to its end; at a dead end you return to the last fork and try a new corridor. That is DFS: it goes as deep as it can, and at a vertex with no unvisited neighbors it backtracks to try another branch.

Compare Figure 14.18: same graph, different order. BFS visits all of s's neighbors a, b, c next; DFS descends s, a, d, b, finds b's neighbors all seen, backs up to s, and descends to c, then e.

DFS stores only the current path, so on wide, shallow graphs it needs less memory than BFS, and it suits problems where a path is followed to its end (mazes, game trees). But its paths need not be shortest: it reached b by s → a → d → b, three edges, though s–b exists. Its main uses are mazes, cycle detection, connected components, and topological sorting of DAGs.

14.3.6DFS code: recursive and with an explicit stack

The shortest way to write DFS is recursively.

void dfs(int v, boolean[] visited) {
  visited[v] = true;
  System.out.print(v + " ");
  for (int u : adj.get(v))
    if (!visited[u])
      dfs(u, visited);
}

The method marks and prints v, then calls itself on each unvisited neighbor in turn. The loop waits for each call to return, so everything below the first neighbor is finished before the second: “deepest first.” When the neighbors run out, the method returns and the caller resumes; that return is backtracking.

Recursion keeps the stack for us as the call stack: the active dfs frames, in order, are the path from the start to the current vertex. An explicit stack works too:

void dfsStack(int s) {
  boolean[] visited = new boolean[n];
  Deque<Integer> stack = new ArrayDeque<>();
  stack.push(s);  visited[s] = true;
  while (!stack.isEmpty()) {
    int v = stack.peek();
    Integer next = null;
    for (int u : adj.get(v))
      if (!visited[u]) { next = u; break; }
    if (next == null) stack.pop(); // back up
    else { visited[next] = true;
           stack.push(next); }
  }
}

This imitates the recursion step by step. The top (peek) is the current vertex; each round seeks its first unvisited neighbor. Found, it is marked and pushed, like a recursive call; not found (next == null), the top is popped, like a return. The break makes the search descend at the first suitable neighbor.

An explicit stack also avoids StackOverflowError: Java's call stack is limited, and recursive DFS on a path of hundreds of thousands of vertices can overflow it, while an explicit stack lives on the heap.

Cost. Recursive DFS calls dfs once per vertex and walks each list once: O(n + m). The explicit-stack version rescans a list from the start at every peek, skipping marked neighbors again each time a vertex resurfaces, at most its degree plus one times; the worst case approaches Σ deg(v)2. A per-list “where I left off” index restores O(n + m). The code favors simplicity; for small degrees the difference is negligible.

14.3.10Connected components

A traversal visits only its start's component. To find them all, restart from each unassigned vertex; each restart is a new component.

int components(int[] comp) {
  Arrays.fill(comp, -1);
  int count = 0;
  for (int s = 0; s < n; s++)
    if (comp[s] == -1) dfs(s, count++, comp);

void dfs(int v, int c, int[] comp) {
  comp[v] = c;
  for (int u : adj.get(v))

14.3.11Testing whether a graph is bipartite

Definition 14.10

A graph is bipartite if its vertices can be split into two groups so that every edge runs between the groups; no edge joins two vertices of the same group.

Matching problems produce bipartite graphs: students on one side, projects on the other, an edge meaning “this student wants this project.” Two-shift scheduling and conflict-free grouping look the same.

Think of the groups as two colors, every neighbor of a vertex having the other color. BFS tests this: color the start 0 and each newly discovered vertex the opposite of its discoverer. A colored neighbor with the current vertex's color means the graph is not bipartite.

// color[] starts at -1; BFS from s
color[s] = 0;  q.add(s);
while (!q.isEmpty()) {
  int w = q.poll();
  for (int u : adj.get(w))
    if (color[u] == -1) {
      color[u] = 1 - color[w];  q.add(u);
    } else if (color[u] == color[w]) return false;
}
return true;

color starts at −1 (“uncolored”); 1 - color[w] flips 0 and 1. It is BFS plus a color check at colored neighbors.

Example 14.7

Left graph. 0 gets color 0; its neighbors 1 and 5 get 1. Processing 1 colors 2 and 4 with 0; processing 5 finds 4 and 0 opposite, as they should be; processing 2 colors 3 with 1, and no later check conflicts. So color = [0, 1, 0, 1, 0, 1]: evens in one group, odds in the other. Every cycle is even: 0–1–2–3–4–5–0 has six edges, 0–1–4–5–0 and 1–2–3–4–1 four.

Triangle. 0 gets 0; 1 and 2 get 1. Processing 1 finds neighbor 2 with its own color, and the method returns false: three mutually adjacent vertices cannot share two colors.

The general rule: a graph is bipartite if and only if it has no odd-length cycle. Colors alternate around a cycle, and returning to the start with its original color requires an even number of edges; so C5 is not bipartite and C6 is. The test costs O(n + m), like BFS; a disconnected graph is handled by restarting at each uncolored vertex.

14.3.12Topological sorting and Kahn's algorithm

A student must take courses in an order where each follows all its prerequisites. With an arrow u → v when u is a prerequisite of v, this is a directed graph, and the order is a topological order.

Definition 14.11

A topological sort of a directed graph arranges its vertices so that for every arrow u → v, u comes first. A directed graph with no directed cycle is a directed acyclic graph (DAG). Only DAGs have topological orders.

Why cycles rule it out: given a → b → c → a, a must precede b, b precede c, and c precede a, so a precedes itself. Each course on the cycle waits for another, and none can start.

The order need not be unique: courses ready at the same time can go in any order, so the DAG 0 → 1, 0 → 2, 1 → 3, 2 → 3 allows 0 1 2 3 and 0 2 1 3. Uses include course plans, task dependencies, build order, and workflows.

Kahn's algorithm: a vertex of in-degree 0 has no prerequisites and can go first. Once output, its arrows count as deleted, lowering their heads' in-degrees; vertices reaching 0 become ready and wait in a queue.

Kahn(G):
  q = vertices with inDegree 0
  result = []
  while q is not empty:
    u = remove from q
    append u to result
    for each edge (u, v) leaving u:
      inDegree[v]--
      if inDegree[v] == 0:
        add v to q
  if result.size < n:
    there is a cycle
  return result
List<Integer> kahn(List<List<Integer>> adj) {
  int n = adj.size();
  int[] indeg = new int[n];
  for (List<Integer> l : adj)
    for (int v : l) indeg[v]++;
  Queue<Integer> q = new ArrayDeque<>();
  for (int v = 0; v < n; v++)
    if (indeg[v] == 0) q.add(v);
  List<Integer> result = new ArrayList<>();
  while (!q.isEmpty()) {
    int u = q.poll();
    result.add(u);
    for (int v : adj.get(u))
      if (--indeg[v] == 0) q.add(v);
  }
  return result;  // size < n → cycle
}

The Java code has three phases:

  1. Counting. Nested loops increment indeg at each arrow's head, in O(n + m).
  2. Initialization. Vertices of in-degree 0 are enqueued.
  3. Main loop. Dequeue u, append it to the result, and run --indeg[v] for each arrow's head; the prefix decrement yields the new value, and at 0, v is enqueued.

If the result has n vertices when the queue empties, it is a topological order; fewer means a directed cycle, whose vertices each wait for their predecessor, never reach in-degree 0, and are never enqueued.

14.3.14Detecting cycles in a directed graph

In an undirected graph, DFS meeting a marked neighbor other than its parent means a cycle. In a directed graph an arrow to a marked vertex is not enough: the vertex must lie on the current DFS path. Three colors tell the cases apart:

  • white (0): not yet visited;
  • gray (1): visited and on the current DFS path; its call has not finished;
  • black (2): visited and finished; everything reachable from it has been examined.
// color: 0 white, 1 gray (on path), 2 black
boolean hasCycle(int v, int[] color) {
  color[v] = 1;
  for (int u : adj.get(v)) {
    if (color[u] == 1) return true;  // back edge
    if (color[u] == 0 && hasCycle(u, color))
      return true;
  }
  color[v] = 2;
  return false;
}

A gray head means the DFS path leads from it to the current vertex, and the arrow closes a cycle: a back edge. A black head has no path back, or the current vertex would have been visited during its call, so it closes no cycle.

14.4Shortest paths

A map app's route, a router's fastest packet path, a game character's way to its goal: one graph problem. Without weights, length is the edge count and BFS solves it; with weights, length is the weight sum and Dijkstra's algorithm solves it.

14.4.1The unweighted shortest-path problem

Definition 14.12

The single-source shortest-path problem gives a source vertex s and asks for the length of the shortest path from s to every vertex, called that vertex's distance from s. A vertex unreachable from s has distance ∞.

Without weights, each edge counts 1, and BFS solves the problem: a vertex on level k has distance exactly k.

Theorem 14.2 (BFS and shortest paths)

In an unweighted graph, BFS from s discovers the vertices in order of their distance from s. When a vertex is first reached from a vertex w, its distance is distance(w) + 1.

The queue always holds distance-k vertices in front and distance-k + 1 vertices behind. Initially it holds only s, at 0; when w at distance k leaves, its undiscovered neighbors join the back with k + 1, keeping the pattern. Take u at distance k + 1: a path of k + 1 edges reaches it, its next-to-last vertex w' at distance k. No vertex closer than k is adjacent to u, or u would be closer, and all distance-k vertices leave before any at k + 1. So u is discovered from distance k and gets k + 1. □

Two three-edge paths reach 7: 1 → 4 → 6 → 7 and 1 → 3 → 8 → 7. BFS finds one, depending on list order, but the length is 3 either way: shortest paths need not be unique, shortest lengths are.

Common mistake

Adding 1 to ∞. Integer.MAX_VALUE + 1 overflows to −2,147,483,648. In the code, the w that gets 1 added has left the queue, so its distance is finite. Weighted graphs are riskier, which is why Dijkstra's Java version uses long distances and relaxes only from settled vertices.

With weights the problem is the same, but length is the sum of edge weights: distances, times, or costs.

The solution is the algorithm Edsger W. Dijkstra devised in 1956 and published in 1959. It has one requirement: edge weights must not be negative, for reasons that emerge in its correctness proof (14.4.9).

14.4.5Dijkstra's algorithm: idea and pseudocode

Dijkstra's algorithm keeps a tentative distance for each vertex, the length of the shortest path found so far: 0 for the source, ∞ for the rest. Each step:

  1. picks, among vertices not yet settled, the one with the smallest tentative distance, whose distance is now final;
  2. updates its neighbors' distances by relaxation.
Definition 14.13

To relax an edge (u, v) is to test whether going through u beats the known path to v: compute alt = dist[u] + weight(u, v), and if alt < dist[v], set dist[v] = alt and prev[v] = u.

The name pictures an upper bound loosening like a spring. A tentative distance never drops below the true distance; each relaxation either leaves it alone or moves it closer.

Dijkstra(G, s):
  for each vertex v:
    dist[v] = ∞
    prev[v] = undefined
  dist[s] = 0
  Q = all vertices  // priority queue
  while Q is not empty:
    u = Q.removeMin()   // smallest dist[u]
    for each neighbor v of u in Q:
      alt = dist[u] + weight(u, v)
      if alt < dist[v]:
        dist[v] = alt
        prev[v] = u
        // decrease v's priority in Q

Q is a priority queue of unsettled vertices keyed by tentative distance; Q.removeMin() returns the closest. When relaxation lowers a distance, the vertex's priority must drop too. prev[] records each vertex's predecessor on its shortest path, and paths are read backward from it.

Common mistake

Prioritizing by vertex number. The queue must return the vertex with the smallest distance, not the smallest number; that is why the comparator of the Java PriorityQueue<long[]> compares the entry's second element, the distance.

14.4.6Dijkstra in Java

long[] dijkstra(List<List<int[]>> adj, int s, int[] prev) { // weights ≥ 0
    long[] d = new long[adj.size()];
    Arrays.fill(d, Long.MAX_VALUE);  d[s] = 0;  Arrays.fill(prev, -1);
    PriorityQueue<long[]> pq =                     // {vertex, distance}
        new PriorityQueue<>((a, b) -> Long.compare(a[1], b[1]));
    pq.add(new long[]{s, 0});
    while (!pq.isEmpty()) {
        long[] e = pq.poll();  int u = (int) e[0];
        if (e[1] > d[u]) continue;                   // stale entry: skip
        for (int[] k : adj.get(u)) {
            int v = k[0];  long alt = d[u] + k[1];
            if (alt < d[v]) { d[v] = alt; prev[v] = u; pq.add(new long[]{v, alt}); }
        }
    }
    return d;
}
  • Input. adj.get(u) lists u's neighbors as int[]{v, w} pairs, neighbor and weight. The caller allocates prev; dijkstra fills it.
  • Setup. The long array d is filled with Long.MAX_VALUE, standing for ∞; d[s] = 0; prev is filled with −1, “no predecessor.”
  • Queue. Entries are {vertex, distance} pairs; the comparator Long.compare(a[1], b[1]) orders by distance, so poll returns the closest.
  • Stale check. if (e[1] > d[u]) continue; skips an entry whose distance exceeds the vertex's current one.
  • Relaxation. For each neighbor, alt = d[u] + k[1]; if alt < d[v], the distance and prev are updated and a new {v, alt} entry is added.

Java's PriorityQueue has no decrease-key, so the code adds a new entry for v and leaves the old one. When the old entry surfaces, its distance exceeds the since-lowered d[v]: a stale entry, skipped by continue. This is lazy deletion: ignore old entries when they surface instead of removing them.

Common mistake

Taking the stale-entry line for a correctness requirement, or deleting it as useless. With non-negative weights, distances come out right without it: by then d[u] is smaller and the neighbors were relaxed with it, so alt < d[v] fails. The line saves rescanning stale entries' neighbors, which costs real time on dense graphs.

14.4.8Reconstructing the path

To get the path from s to t, follow prev from t until −1. The chain runs backward, so each vertex goes to the front of the list.

List<Integer> path(int[] prev, int s, int t) {
  LinkedList<Integer> p = new LinkedList<>();
  for (int v = t; v != -1; v = prev[v])
    p.addFirst(v);
  if (p.getFirst() != s) return List.of();
  return p;                 // s ... t
}

Starting at v = t, each round prepends v and steps back with v = prev[v], stopping after the source, whose prev is −1. LinkedList.addFirst is constant time, so the cost is O(path length), at most O(n).

The final check catches unreachable targets: prev[t] = −1 stops the chain at once, leaving t first, and a first item other than s yields an empty list.

Theorem 14.3 (Correctness of Dijkstra's algorithm)

If no edge weight is negative, then when Dijkstra's algorithm settles a vertex, its tentative distance equals its true distance from the source.

Let u be the unsettled vertex of smallest tentative distance, and take any path from s to u. It leaves the settled region somewhere first; let y be the first vertex outside and x its predecessor. (x, y) was relaxed when x settled, so dist[y] is at most the length of the path up to y, and dist[u] ≤ dist[y] by the choice of u. The rest of the path has non-negative edges, length ≥ 0. So the path is at least dist[y] ≥ dist[u] long: none is shorter than dist[u]. □

Non-negativity is used once: “length ≥ 0.” A negative edge could later shorten a settled vertex's distance, and the pseudocode then errs. The stale-entry Java version may recover by reprocessing vertices, but loses its time bound, and a negative cycle makes it run forever. Negative weights call for the Bellman-Ford algorithm.

Example 14.11

Take arrows s → a: 2, s → b: 3, b → a: −2, a → c: 1. Dijkstra settles s (0), then a (2), giving c distance 3, then b (3). Via b → a, 3 + (−2) = 1 is a's true distance, but a is already settled at 2, and the pseudocode never revisits it, so c stays at 3 instead of 1 + 1 = 2. Here the Java version re-adds a with 1 and processes it again, correcting c to 2: right answer, but a vertex processed twice.

14.5Minimum spanning trees

A municipality wants water in every village; pipe between any two villages has a cost, and water need only reach each village by some route. Which network costs least? This minimum spanning tree problem also arises in power and communication networks, clustering, and inside other algorithms.

14.5.1Spanning trees and the MST

Definition 14.14

A spanning tree of a connected graph is a connected, acyclic subgraph containing all its vertices; with n vertices it has exactly n − 1 edges. A minimum spanning tree (MST) of a weighted graph is a spanning tree of smallest total edge weight.

Why no cycles? With positive weights, dropping a cycle edge lowers the total while the rest of the cycle keeps its endpoints connected, so the cheapest connected subgraph is a tree. The n − 1 is the lower bound of 14.1.7, met exactly by acyclic connected graphs.

The edges weigh 62 in all; the MST takes nine of them, weighing 14. Spanning trees are far too many to try, so the classic algorithms, Kruskal's and Prim's, are greedy: each step takes the best-looking choice and never revisits it. Greed works here thanks to this property.

Theorem 14.4 (Cut property)

Split the vertices of a graph into two nonempty groups. Among the edges joining the two groups, one of smallest weight belongs to some minimum spanning tree.

Let e = (u, v) be the lightest crossing edge and T an MST without it. T has a path from u to v, which crosses between the groups along some edge f. Adding e and removing f leaves a spanning tree: the one cycle e creates is broken by removing f. As weight(e) ≤ weight(f), the new tree weighs no more than T, so it is an MST containing e. □

Kruskal and Prim apply this theorem in two ways. In Prim, one group is the tree built so far; in Kruskal, the groups are the trees containing the two endpoints of the chosen edge.

14.5.2Disjoint sets (Union-Find)

Kruskal tries edges from lightest to heaviest, asking of each whether it closes a cycle, that is, whether chosen edges already connect its endpoints. Disjoint sets (union-find) answer this quickly, managing non-overlapping sets with two operations:

  • find(x) returns the representative of x's set; two items are in the same set exactly when find gives them the same representative.
  • union(u, v) merges the sets of u and v and returns true if they differ; if they are already the same set, it does nothing and returns false.

The slides use only this behavior; the class below is an implementation that reproduces the parent arrows of their trace.

class UnionFind {
    private final int[] parent, size;
    UnionFind(int n) {                       // each vertex its own set
        parent = new int[n];  size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }
    int find(int x) {                        // find the root, compress the path
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }
    boolean union(int u, int v) {
        int a = find(u), b = find(v);
        if (a == b) return false;            // same set: would close a cycle
        if (size[a] > size[b]) { int t = a; a = b; b = t; }
        parent[a] = b;  size[b] += size[a];      // smaller tree under the larger
        return true;
    }
}

Each set is a tree: parent[x] is x's parent, and the root, its own parent, represents the set. Initially there are n one-vertex trees. Two refinements give speed:

  • Union by size. The smaller tree's root goes under the larger's, keeping heights at most log n; on a tie, u's root goes under v's.
  • Path compression. find links every vertex on its way directly to the root, so repeat queries take one step.

Together they make each operation cost O(α(n)) over a sequence, where α, the inverse Ackermann function, stays ≤ 4 even for n the number of atoms in the universe: in practice, constant time.

14.5.3Kruskal's algorithm

Kruskal(G):
  T = ∅          // chosen edges
  for each vertex v: makeSet(v)
  sort the edges by weight
  for each (u, v), lightest first:
    if find(u) != find(v): // no cycle
      T.add((u, v))
      union(u, v)
    if |T| == n − 1: break
  return T  // MST (if disconnected: forest)

Kruskal's rule: pick the lightest edge that closes no cycle. Starting from n one-vertex sets, it tries edges by increasing weight; an edge joining different sets enters T and merges them, one inside a set is skipped. After n − 1 edges the tree is done.

Midway, the chosen edges form a forest whose trees merge into one. A disconnected graph never reaches n − 1; every edge is tried, giving a minimum spanning forest, one tree per component.

14.5.7Prim's algorithm

Prim(G, s):
  tree = {s}, T = ∅
  add s's edges to the queue
  while |T| < n − 1:
    (u, v) = lightest edge  // u in tree
    if v in tree: skip       // cycle
    add v to tree, (u, v) to T
    add v's edges leaving the tree
      to the queue
  return T

Prim grows one tree from a single vertex, adding each step the lightest edge to a vertex outside it. The cut property makes this safe: the tree must connect to the rest somehow, and this is the cheapest connection.

Like Dijkstra, Prim starts at a vertex and repeatedly takes a priority queue's smallest item, but the key differs: Dijkstra's is the total distance from the source, Prim's the weight of the single edge to the tree. Unlike Kruskal, there is always one tree, so “is the head in the tree?” detects cycles without Union-Find.

14.5.8Prim in Java

The Java version in the slides is the lazy version, built on a priority queue.

List<int[]> prim(List<List<int[]>> adj, int s) {
  int n = adj.size();                 // adj.get(u): {v, w}
  boolean[] inTree = new boolean[n];
  PriorityQueue<int[]> pq = new PriorityQueue<>(
      (a, b) -> Integer.compare(a[2], b[2]));  // {u, v, w}
  List<int[]> T = new ArrayList<>();
  inTree[s] = true;
  for (int[] e : adj.get(s)) pq.add(new int[]{s, e[0], e[1]});
  while (!pq.isEmpty() && T.size() < n - 1) {
    int[] e = pq.poll();               // lightest candidate
    if (inTree[e[1]]) continue;       // stale: would close a cycle
    inTree[e[1]] = true;
    T.add(e);
    for (int[] f : adj.get(e[1]))
      if (!inTree[f[0]]) pq.add(new int[]{e[1], f[0], f[1]});
  }
  return T;
}

Entries are {u, v, w}: tree endpoint, candidate, weight (the comparator's only concern). inTree marks members.

  1. The start s joins, and its edges are enqueued.
  2. Until the queue empties or n − 1 edges are chosen, take the lightest entry.
  3. If candidate e[1] is in the tree, the entry is stale (it would close a cycle), and continue skips it.
  4. Otherwise the candidate joins, the edge enters T, and the new vertex's edges leaving the tree are enqueued.

“Lazy”: when v joins, old entries to it stay queued and are skipped on removal, as with Dijkstra's stale entries.

Cost. Each edge is enqueued at most once, from the endpoint that joins first; later, !inTree[f[0]] blocks it. At most m insertions and removals at O(log m) give O(m log n) time and O(m) queue memory. With a matrix and an array scan, Prim takes O(n2), better for very dense graphs.

Common mistake

Deleting the stale check (if (inTree[e[1]]) continue;). In Dijkstra it only saved time; in Prim it guarantees correctness. Without it, a leftover entry to v adds an edge between two tree vertices, creating a cycle.

Common mistake

Confusing the MST with the shortest-path tree. Dijkstra's prev tree minimizes path lengths from the source; the MST minimizes the edge sum. In the triangle A–B 2, B–C 2, A–C 3, the MST is A–B, B–C (total 4), where A to C has length 4, though the edge A–C has length 3.

14.6Summary

  • A graph G = (V, E) has n vertices and m edges. Unlike a tree, it has no root, may have cycles, and may offer several routes to a vertex. Edges may be directed or not, weighted or not.
  • A vertex's degree counts its incident edges. By the handshake lemma Σ deg(v) = 2m; directed in- and out-degrees each sum to m. Simple undirected graphs have m ≤ n(n − 1)/2, connected ones m ≥ n − 1.
  • A path is a sequence of vertices joined by edges; a cycle ends where it starts. A graph with paths between all vertex pairs is connected; a largest mutually reachable group is a connected component.
  • An adjacency matrix takes O(n2) memory, with O(1) edge queries and O(n) neighbor visits; an adjacency list takes O(n + m), with O(deg v) neighbor visits. Lists suit sparse graphs; matrices suit dense ones with frequent edge queries.
  • BFS goes level by level with a queue, DFS deepest first with a stack or recursion, both O(n + m) with lists. Vertices are marked on entering the queue or stack; without marks, cycles trap the traversal.
  • Three applications follow. Connected components: a new traversal from each uncolored vertex. Bipartiteness: 2-coloring by BFS, possible exactly without odd cycles. Directed cycle detection: three-color DFS, where an arrow to a gray vertex is a back edge.
  • Topological orders exist only for DAGs. Kahn's algorithm dequeues in-degree-0 vertices and deletes their arrows, in O(n + m); fewer than n results reveal a cycle.
  • BFS finds unweighted shortest paths, the first distance found being shortest. For non-negative weights, Dijkstra settles the closest unsettled vertex and relaxes its neighbors, in O((n + m) log n) with a heap or O(n2) by array scan; paths are read backward through prev.
  • A minimum spanning tree connects all vertices with n − 1 edges of least total weight. Kruskal sorts edges and keeps those closing no cycle, via Union-Find; Prim grows one tree by its lightest outgoing edge. Both are O(m log n) and rest on the cut property.

14.8Test Yourself

  1. What are the fewest and the most edges a simple, undirected, connected graph on 8 vertices can have?

    Answer

    At least n − 1 = 7 (the graph is then a tree), at most n(n − 1)/2 = 8 · 7 / 2 = 28 (the complete graph K8).

  2. How many cells are 1 in the adjacency matrix of the directed graph with arrows 0 → 1, 0 → 2, 2 → 1, 3 → 0? How do you read 0's out-degree and 1's in-degree from the matrix?

    Answer

    Each arrow fills one cell: 4 cells. 0's out-degree is the sum of row 0, m[0][1] + m[0][2] = 2; 1's in-degree is the sum of column 1, m[0][1] + m[2][1] = 2.

  3. On the nine-vertex traversal graph (neighbors alphabetical), what does bfs(E) print? How many edges is A from E?

    Answer

    E B C G A D F I H. E's neighbors B, C, G form level 1; A (from B), D (from C), and F (from G) form level 2; I (from A) and H (from D) form level 3. A is on level 2, two edges from E (E → B → A).

  4. On the same graph, what does recursive dfs(F) print?

    Answer

    F A B C D G E H I. From F the search descends to A, then A's first unvisited neighbor B, then C, D, G, and G's neighbor E. It backs up from E and G and visits H below D; finally, back at A, it visits A's last neighbor, I.

  5. What order does kahn() return for the DAG with lists 0: [1, 2] · 1: [4] · 2: [4] · 3: [1] · 4: []?

    Answer

    The in-degrees are [0, 2, 1, 0, 2], so the queue starts with 0, 3. Removing 0 gives indeg[1] = 1 and indeg[2] = 0, enqueuing 2; removing 3 gives indeg[1] = 0, enqueuing 1; removing 2 gives indeg[4] = 1; removing 1 gives indeg[4] = 0, enqueuing 4. The result is 0 3 2 1 4; its size is 5 = n, so there is no cycle.

  6. On the graph with arrows 0 → 1, 1 → 2, 2 → 3, 3 → 1, while examining which arrow does hasCycle(0, color) return true? What is color at that moment?

    Answer

    0, 1, 2, 3 turn gray in turn: color = [1, 1, 1, 1]. When 3 → 1 is examined, 1 is gray, on the current path; the arrow is a back edge, and the cycle found is 1 → 2 → 3 → 1.

  7. Run the Java Dijkstra from A on the undirected graph A–B 1, A–C 4, B–C 2, B–D 6, C–D 3. What are the final d and prev? How many stale entries leave the queue?

    Answer

    d = [0, 1, 3, 6] (A, B, C, D) and prev = [–, A, B, C]. Processing A sets C to 4 and B to 1; processing B lowers C to 3 (adding {C, 3}) and sets D to 7; processing C lowers D to 6 (adding {D, 6}). The old entries {C, 4} and {D, 7} come out stale and are skipped: 2 stale entries.

  8. On the graph A–B 3, A–C 1, B–C 3, B–D 2, C–D 4, C–E 5, D–E 6, which edges does Kruskal choose, and what is the total weight? What changes if the tied edges A–B and B–C are tried in the other order?

    Answer

    In order: A–C 1 (accept), B–D 2 (accept), A–B 3 (accept, merging {A, C} and {B, D}), B–C 3 (reject), C–D 4 (reject), C–E 5 (accept). Four edges are chosen and D–E is never examined; the total is 1 + 2 + 3 + 5 = 11. Trying B–C first accepts B–C and rejects A–B: a different tree (A–C, B–D, B–C, C–E), still totaling 11.

  9. On the graph of the previous question, in what order does lazy Prim from A choose edges (ties alphabetical), and how many stale entries does it skip?

    Answer

    A–C 1, A–B 3, B–D 2, C–E 5. After A–B is chosen, C–B 3 remains queued and is stale, since B is in the tree; when D joins, C–D 4 goes stale too. Both come out before C–E and are skipped: 2 stale entries. The total is again 11.

  10. In a graph whose edges all weigh 5, which algorithm can replace Dijkstra for single-source shortest paths, and why?

    Answer

    BFS. With equal weights a path's length is 5 × number of edges, so the path with the fewest edges is also the shortest; multiply BFS's distances by 5. BFS runs in O(n + m), saving the log n factor of heap-based Dijkstra.
