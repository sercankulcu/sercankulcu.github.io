Question 1: Equal Priorities

In a min-priority queue, Eve and Nina have the same priority (1), and Eve arrived first. What must be done to guarantee that Eve leaves before Nina?

Correct: B. Sequence numbers are always distinct, so they break every tie: when priorities are equal, the smaller sequence number (the earlier arrival) leaves first. A is the strongest distractor: a heap (and Java's PriorityQueue) gives no FIFO guarantee for equal keys.

Question 3: removeMin on an Unsorted Array

removeMin() is called on an unsorted array. What value is returned, and what does the array look like afterward?

First candidate: index 0 (7). In an unsorted array the minimum could be anywhere.

a[1] = 4 < a[0] = 7 → new minimum, minIdx = 1.

a[2] = 9 ≥ 4 → minIdx stays.

a[3] = 2 < 4 → minIdx = 3.

a[4] = 6 ≥ 2 → minIdx stays.

k = 5 = n → scan done: 4 comparisons. Every removeMin scans the whole array → O(n).

min = a[3] = 2 is saved.

The last item (6) fills the gap, n = 4. Order doesn't matter, so no shifting: O(1).

return 2. The remaining array [7, 4, 9, 6] is still unsorted.

public int removeMin() {
  int minIdx = 0;
  for (int k = 1; k < n; k++)
    if (a[k] < a[minIdx]) minIdx = k;
  int min = a[minIdx];
  a[minIdx] = a[n - 1];  n--;
  return min;
}
// a = [7, 4, 9, 2, 6], n = 5

Question 4: n Insertions + n Removals

n items are inserted into an empty priority queue, followed by n calls to removeMin(). What is the total cost with an unsorted list, a sorted list, and a binary heap, respectively?

Correct: C. Unsorted: n·O(1) + n·O(n) = O(n²). Sorted: n·O(n) + n·O(1) = O(n²). Heap: 2n·O(log n) = O(n log n). A is the distractor: insertion into an unsorted list is cheap, but every removeMin scans the whole list. For n = 10⁶ the difference is a factor of about 50,000.

In the priority queue's insert() method, the condition < is changed to <=. After insert(X,3), insert(Y,3), insert(Z,1) on an empty queue, what does remove() return?

Short Answer · Binary Heaps

Question 7: Heap or Not?

In the tree below, every parent is larger than its children. Is this tree a max-heap? If not, which property fails?

Show answer

It is not a max-heap. Heap order holds (20 ≥ 15, 18; 15 ≥ 9; 18 ≥ 10, 7), but the complete binary tree property fails: the last level is not filled from left to right, since 15 has no right child while 18 has children.

In the array representation, this means index 4 is empty: [20, 15, 18, 9, _, 10, 7]. A heap's array must have no gaps; a new item always goes into the first free slot (index n).

Heap = complete binary tree and heap order; both are required.

Question 8: A Valid Min-Heap Array

Which of these is a valid min-heap array (0-based)?

Correct: C. Every i must satisfy a[(i−1)/2] ≤ a[i]: 1 ≤ 3, 2; 3 ≤ 6, 4; 2 ≤ 5. In A, the 4 at index 1 is larger than its child 3 (index 3); having the smallest item at the root is not enough. In B the root 2 > 1, and in D the 2 at index 1 is larger than its child 0 (index 4).

Question 9: The Result of isHeap

What does the call below return?

static boolean isHeap(int[] a) {
  for (int i = 1; i < a.length; i++) {
    int p = (i - 1) / 2;
    if (a[p] < a[i]) return false;
  }
  return true;
}
isHeap(new int[]{9, 6, 8, 3, 7, 8, 1});

Correct: D. i = 1…3 pass (9 ≥ 6, 8; 6 ≥ 3). At i = 4: p = 1, a[1] = 6 < a[4] = 7 → false. C is wrong: the test is strict (<), so equality does not break a heap, and the loop never gets that far anyway. The check takes at most n − 1 comparisons: O(n).

Question 10: Inserting into a Max-Heap

insert(45) is called on the max-heap heap = [50, 30, 40, 10, 20, 35] (n = 6, capacity 8). How many levels does 45 rise, and what is the final array?

n = 6 ≠ 8 → the array is not full, so resize is not called.

45 goes into the first free slot, heap[6]; n = 7. The tree stays complete.

swim(6): i = 6 > 0 → enter the loop.

parent = (6 − 1)/2 = 2. heap[2] = 40 < 45 → no return.

Swap (6 ↔ 2): 45 rises one level, i = 2.

parent = 0: heap[0] = 50 ≥ 45 → return.

Done: 45 rose one level. Final array [50, 30, 45, 10, 20, 35, 40]. At most h swaps → O(log n).

public void insert(int x) {
  if (n == heap.length) resize(2 * n);
  heap[n] = x;  n++;
  swim(n - 1);
}
private void swim(int i) {
  while (i > 0) {
    int parent = (i - 1) / 2;
    if (heap[parent] >= heap[i]) return;
    swap(i, parent); i = parent;
  }
}

Question 12: Why the Larger Child?

After removeMax on a max-heap, the 3 moved to the root has left child 8 and right child 9. Which child should down-heap swap the 3 with?

Correct: B. If 9 moves up, the new root 9 has children 8 and 3, and the order holds. If 8 moved up (A, C), the root 8 would have the child 9: 8 < 9, so heap order breaks. In a min-heap, pick the smaller child instead.

Question 13: removeMax and Down-Heap

removeMax() is called on the max-heap heap = [12, 10, 8, 4, 9, 7, 3] (n = 7). What is returned, and what is the final array?

The largest is always at the root: max = 12.

Swap the root with the last item (0 ↔ 6), n = 6: 12 is outside the heap. The new root 3 breaks the order.

sink(0): children 10 and 8 → the larger is 10, j = 1.

3 < 10 → swap (0 ↔ 1), i = 1.

Children 4 (index 3) and 9 (index 4) → j = 4.

3 < 9 → swap (1 ↔ 4), i = 4.

2·4 + 1 = 9 ≥ n = 6 → a leaf, so the loop ends.

return 12. The new heap is [10, 9, 8, 4, 3, 7]; at most ⌊log₂ n⌋ levels → O(log n).

public int removeMax() {
  int max = heap[0];
  swap(0, n - 1);  n--;
  sink(0);
  return max;
}
private void sink(int i) {
  while (2 * i + 1 < n) {
    int j = 2 * i + 1;
    if (j+1 < n && heap[j+1] > heap[j]) j++;
    if (heap[i] >= heap[j]) return;
    swap(i, j);  i = j;
  }
}

Question 14: Forgetting the Right-Child Bound

This sink forgets the j + 1 < n check. If removeMax() is called on the max-heap [9, 8, 3, 5, 4] (n = 5), what do the first n items of the heap become?

private void sink(int i) {
  while (2 * i + 1 < n) {
    int j = 2 * i + 1;
    if (heap[j + 1] > heap[j]) j++;
    if (heap[i] >= heap[j]) return;
    swap(i, j);  i = j;
  }
}
Show answer
  • max = 9; 9 ↔ 4, n = 4: [4, 8, 3, 5 | 9].
  • i = 0: j = 1 (8 > 3); 4 < 8 → swap: [8, 4, 3, 5 | 9].
  • i = 1: j = 3; because heap[4] = 9 > 5, the buggy code picks j = 4 (a removed item!); 4 < 9 → swap: [8, 9, 3, 5 | 4].

Result [8, 9, 3, 5]: the removed 9 is back, 4 is lost, and 9 > its parent 8 → the heap is broken. The correct result is [8, 5, 3, 4].

Fix: if (j + 1 < n && heap[j + 1] > heap[j]) j++; (when sink is called without first decreasing n, as in buildHeap, the buggy code can also throw ArrayIndexOutOfBoundsException if the array is completely full).

Question 16: Why O(n)?

In a complete binary tree with 15 nodes (h = 3), how many swaps does bottom-up heap construction make in the worst case?

Correct: D. In down-heap, the number of swaps is at most the node's height: 8 leaves·0 + 4·1 + 2·2 + 1·3 = 11 ≤ n. A (34) is the worst case for n insertions into the same tree: the cost of up-heap depends on depth, and most nodes are deep: 2·1 + 4·2 + 8·3 = 34. Still, when items arrive one at a time (online), insertion is the only option.

Question 18: Properties of Heap Sort

Which statement about heap sort is false?

Answer: C (the false statement). Long-distance swaps between the root and the last item can reorder equal keys; heap sort is not stable. D is true: at every step the largest item goes to the end of the array, so a max-heap gives ascending order (a min-heap, descending). A is true: heap sort has no O(n²) worst case like quick sort's.

Question 20: The PriorityQueue Class

Which statement about Java's PriorityQueue class is true?

Correct: A. A heap is not sorted, so finding a particular item means a linear search of the array. B is false and a common mistake: the default is a min-heap; for a max-heap use Comparator.reverseOrder(). There is no FIFO guarantee among ties, and the class is not thread-safe (use PriorityBlockingQueue). offer/poll are O(log n), peek is O(1).

Question 22: Tracing changeKey

The deck's changeKey(i, key) (swim if the key increased, sink if it decreased) is called on the max-heap [30, 24, 28, 9, 20, 26, 11], first as changeKey(3, 29) and then as changeKey(0, 7). Which swaps does each call make, and what is the resulting array?

Show answer
  • changeKey(3, 29): 9 → 29, the key increased → swim(3). Parent (3 − 1)/2 = 1: 24 < 29 → swap. Parent 0: 30 ≥ 29 → stop. Array [30, 29, 28, 24, 20, 26, 11].
  • changeKey(0, 7): 30 → 7, the key decreased → sink(0). Children 29, 28 → swap with 29; i = 1: children 24, 20 → swap with 24; i = 3 is a leaf. Array [29, 24, 28, 7, 20, 26, 11].

Each call follows a single root-to-leaf path: O(log n). The item's index is read from its locator in O(1); without a locator, just finding the item would take O(n). In a location-aware heap, every swap updates the indices of both items.

Question 23: The Heap after remove(e)

In the max-heap [50, 20, 40, 10, 15, 35, 38], the entry at position 3 (10) is deleted with remove(e): swap with the last item, n − 1, then up-heap or down-heap the item that took its place. What is the final array?

Correct: A. 38 lands at index 3; its parent (index 1) is 20 < 38, so it needs an up-heap: 38 ↔ 20; 50 ≥ 38 → stop. B tries only a down-heap: index 3 is a leaf, so nothing happens and the 20 < 38 violation remains. C shifts the array left, which takes O(n) and breaks the order (20 gets the child 35). D forgets the n − 1, so the deleted 10 is still in the heap.

Question 24: Heap Sort Is Not Stable

Records have the form (key, label), and the deck's heapSort compares keys only. When [(4,a), (4,b), (2,c), (1,d)] is sorted, what is the array after each step? Do a and b, which have equal keys, keep their relative order?

Show answer
StepArray (sorted to the right of |)
Build (k = 1, 0)[(4,a), (4,b), (2,c), (1,d)]: no swaps (a[i] ≥ a[j] stops on a tie)
last = 3: (4,a) to the end, (4,b) to the root[(4,b), (1,d), (2,c) | (4,a)]
last = 2: (4,b) to the end[(2,c), (1,d) | (4,b), (4,a)]
last = 1: (2,c) to the end[(1,d) | (2,c), (4,b), (4,a)]

Result: (1,d), (2,c), (4,b), (4,a). In the input a came before b; in the output it comes after: heap sort is not stable. The reason: the root (4,a) travels to the very end in one long-distance swap, while (4,b), with the same key, rises to the root and settles in the slot before it.

If stability matters, add an arrival sequence number to the key or use a stable sort (merge sort, say).
