Algoritmalar ve Ölçüm

Algoritmalar

  • Bir algoritma, bir problemi çözmek için adım adım bir prosedürdür: girdi → adımlar → çıktı.
  • Aynı problemi çözmek için farklı algoritmalar bulunabilir; bazıları diğerlerine göre daha verimli çalışır.
  • Doğru algoritma seçimi kritiktir: iyi bir algoritma, işi daha az kaynak kullanarak yapar.

Algoritmalar ve Ölçüm

İyi Bir Algoritma

Bir problemi etkili bir şekilde çözen algoritmadır. Dört ölçüte bakarız:

Zaman Karmaşıklığı (Time Complexity)Çalışma süresi veya işlem sayısı gibi faktörler zaman karmaşıklığını belirler.
Alan Karmaşıklığı (Space Complexity)Algoritmanın kullandığı bellek miktarı alan karmaşıklığını belirler.
Doğruluk (Correctness)Her geçerli girdi için doğru sonucu üretmelidir. Yanlış sonuç veren bir algoritma kullanışsızdır.
Sağlamlık (Robustness)Çeşitli durumlar ve girdilerle başa çıkabilmeli, farklı senaryolara uyum sağlayabilmelidir.

Algoritmalar ve Ölçüm · Ölçerek analiz

Deneysel Analiz: System.nanoTime()

for (int n = 1000; n <= 64000; n *= 2) {
  int[] a = new int[n];
  for (int i = 0; i < n; i++) a[i] = i; // tekrarsız
  long bas = System.nanoTime();
  tekrarVar(a);                        // ölçülen iş
  long sure = System.nanoTime() - bas;  // ns
  System.out.println(n + " " + sure / 1e6 + " ms");
}
ÖlçSystem.nanoTime() iki okuma arasındaki farkı ns cinsinden verir (duvar saati değil).
TekrarlaJIT ısınması, çöp toplayıcı ve diğer süreçler gürültü yapar: birkaç kez çalıştır, medyanı al.
ÇizSüreyi n'ye karşı çiz; n'yi ikiye katlayınca sürenin kaç katına çıktığına bak.
Dikkat: new int[n] sıfırlarla dolar → tekrarVar (tekrar arayan O(n²) metot) ilk karşılaştırmada true döner. En kötü durumu ölçmek için tekrarsız veri gerekir.

Katlama Deneyi ve Deneysel Analizin Sınırları

Deneysel analizin sınırları (Goodrich §4.1):

  • Sonuçlar donanıma, JVM'e ve yüke bağlıdır; iki algoritma aynı ortamda ölçülmelidir.
  • Yalnız sınırlı sayıda girdi denenebilir; önemli bir girdi kaçabilir.
  • Ölçmek için algoritmanın tamamen kodlanması gerekir.
Katlama deneyi: T(2n)/T(n) ≈ 2k ise T(n) ≈ c·nk. Sınırları aşmak için: ilkel işlemleri sayarak analiz — donanımdan bağımsız, tüm girdiler için, kod çalıştırmadan.

İlkel İşlemleri Sayma: maksimum()

int maksimum(int[] a) {
  int enBuyuk = a[0];
  for (int i = 1; i < a.length; i++) {
    if (a[i] > enBuyuk)
      enBuyuk = a[i];
  }
  return enBuyuk;
}

Asimptotik Gösterim

Zaman Karmaşıklığı ve Büyük O (Big O)

  • Algoritmanın ne kadar sürede çalıştığını, girdi boyutu n'ye bağlı olarak ifade eder.
  • Büyük O gösterimi, çalışma süresi için bir üst sınır belirtir; genellikle en kötü durum için kullanılır.
  • O(1): işlem sayısı girdi boyutuyla büyümez; farklı girdilerde süre birebir aynı olmak zorunda değildir.
  • O(n): girdi büyüdükçe süre doğrusal olarak artar.
Büyük O'da yalnızca en hızlı büyüyen terim önemlidir; sabitler ve küçük terimler atılır:
3n2 + 5n + 2 → O(n2)  ·  4n + 100 → O(n)  ·  7 → O(1)

Asimptotik Gösterim

O, Ω ve Θ: Tanım ve Grafik

Tanım: f(n) = O(g(n)) ⇔ öyle c > 0 ve n₀ ≥ 1 vardır ki her n ≥ n₀ için f(n) ≤ c·g(n). Ω için ≥, Θ için ikisi birden.

Büyük O: n ≥ n₀ = 5 için 2n + 10 ≤ 4·n → f(n) = O(n) (c = 4). Küçük n'de (n < 5) f(n) daha büyük; önemli değil.

Büyük Omega: her n ≥ 1 için 2n + 10 ≥ 2·n → f(n) = Ω(n): f, n'den daha yavaş büyümez (alt sınır).

Büyük Teta: n ≥ 5 için 2n ≤ f(n) ≤ 4n → f(n) = Θ(n): iki doğru arasına sıkışır, büyüme hızı tam olarak n.

Asimptotik Gösterim

Asimptotik Sınırlar ve Durumlar

O(g(n)) · Üst sınırÇalışma miktarı, yeterince büyük n için g(n)'den daha hızlı büyümez.
Ω(g(n)) · Alt sınırÇalışma miktarı, yeterince büyük n için g(n)'den daha yavaş büyümez.
Θ(g(n)) · Sıkı sınırÜst ve alt sınır aynıdır; büyüme hızı g(n) ile aynı sınıftadır.
AnalizNe sorar?Doğrusal arama örneği

Ortalama durumBir girdi dağılımı varsayımı altında beklenen maliyet nedir?Hedefin konumu eşit olasılıklıysa Θ(n)

Amortize analiz: Tek bir işlem pahalı olabilir; uzun bir işlem dizisinin toplam maliyeti işlem sayısına bölünür. Örneğin büyüyen dizide yeniden boyutlandırma O(n), sona ekleme ise amortize O(1)'dir.

Asimptotik Gösterim · Durum analizi

En İyi, Ortalama ve En Kötü Durum

Dizi [4, 8, 15, 16, 23, 42] üzerinde doğrusal arama; her olası hedef için karşılaştırma sayısı:

  • Aynı n için girdiye göre maliyet değişir.
  • En kötü durum bir garanti verir ve hesaplaması kolaydır → genellikle bu raporlanır.
  • Ortalama bir olasılık dağılımı varsayar (burada her hedef eşit olasılıklı).
  • En iyi durum tek başına yanıltıcıdır.

Kod İzleme: adimSay(16) — i her turda ikiye katlanır

adimSay(16): kaç kez ikiye katlayarak n'ye ulaşırız?

Sayaç k = 0.

i = 1 < 16 → gövde çalışır.

k++ → k = 1.

i = 2 < 16 → gövde çalışır.

k++ → k = 2.

i = 4 < 16 → gövde çalışır.

k++ → k = 3.

i = 8 < 16 → gövde çalışır.

k++ → k = 4.

i *= 2 → i = 16; 16 < 16 yanlış → döngü biter.

return 4 = log₂ 16. n'yi 1000 kat büyütmek yalnız ~10 tur ekler → O(log n).

int adimSay(int n) {
  int k = 0;
  for (int i = 1; i < n; i *= 2)
    k++;
  return k;
}

Kod İzleme: toplam()

main, toplam(a)'yı çağırır. Yeni bir çağrı çerçevesi açılır.

Metoda girildi; a aynı diziyi gösterir (kopyalanmaz).

Toplam değişkeni s = 0 ile başlar.

Döngü 1. tur: x = a[0] = 7.

s += x → s = 0 + 7 = 7.

Döngü 2. tur: x = a[1] = 2.

s += x → s = 7 + 2 = 9.

Döngü 3. tur: x = a[2] = 9.

s += x → s = 9 + 9 = 18.

Dizide öğe kalmadı; döngüden çıkılır.

return 18: çerçeve kapanır, değer çağırana döner.

println 18 yazar. Döngü gövdesi n = 3 kez çalıştı → O(n).

int toplam(int[] a) {
    int s = 0;

Kod İzleme: dogrusalArama(a, 23)

Sıralı bir dizide 23 aranıyor; doğrusal arama sıralı olmayı kullanmaz, baştan tek tek bakar.

a[0] = 2 ≠ 23 → i ilerler. Her adımda yalnızca bir öğe elenir.

a[1] = 5 ≠ 23 → i ilerler.

a[2] = 8 ≠ 23 → i ilerler.

a[3] = 12 ≠ 23 → i ilerler.

a[4] = 16 ≠ 23 → i ilerler.

a[5] = 23 == 23 → return 5. 6 karşılaştırma; hedef sonda ya da yoksa n = 10 karşılaştırma → O(n).

int dogrusalArama(int[] a, int hedef) {
    for (int i = 0; i < a.length; i++)
        if (a[i] == hedef) return i;
    return -1;
}

Koddan Karmaşıklığa · Kodu adım adım çalıştır

Kod İzleme: ikiliArama(a, 23)

Arama aralığı tüm dizi: lo = 0, hi = 9.

0 ≤ 9 → aralık boş değil, 1. tur başlar.

mid = (0 + 9) / 2 = 4, a[4] = 16.

16 < 23 → hedef sağ yarıda: lo = mid + 1 = 5. Sol yarı elendi.

5 ≤ 9 → aralık boş değil, 2. tur başlar.

mid = (5 + 9) / 2 = 7, a[7] = 56.

56 > 23 → hedef sol yarıda: hi = mid − 1 = 6. Sağ yarı elendi.

5 ≤ 6 → aralık boş değil, 3. tur başlar.

mid = (5 + 6) / 2 = 5, a[5] = 23.

23 == 23 → bulundu, return 5. Yalnızca 3 tur; doğrusal arama 6 karşılaştırma yapardı. Her tur aralığı yarıya indirir → O(log n).

int ikiliArama(int[] a, int hedef) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = (lo + hi) / 2;
        if (a[mid] == hedef) return mid;
        if (a[mid] < hedef) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

Koddan Karmaşıklığa · Kodu adım adım çalıştır

Kod İzleme: ikiliArama(a, 40) — hedef yok

Bu kez 40 dizide yok: en kötü durum. Aralık tüm dizi.

0 ≤ 9 → aralık boş değil, 1. tur.

1. tur: mid = (0 + 9) / 2 = 4, a[4] = 16.

16 < 40 → lo = 5; sol taraf elendi.

5 ≤ 9 → aralık boş değil, 2. tur.

2. tur: mid = (5 + 9) / 2 = 7, a[7] = 56.

56 > 40 → hi = 6; sağ taraf elendi.

5 ≤ 6 → aralık boş değil, 3. tur.

3. tur: mid = (5 + 6) / 2 = 5, a[5] = 23.

23 < 40 → lo = 6; sol taraf elendi.

6 ≤ 6 → aralık boş değil, 4. tur.

4. tur: mid = (6 + 6) / 2 = 6, a[6] = 38.

38 < 40 → lo = 7; sol taraf elendi.

7 ≤ 6 yanlış → aralık boş, döngü biter.

        if (a[mid] < hedef) lo = mid + 1;
        else hi = mid - 1;

    return -1;

Kod İzleme: tekrarVar()

Dış döngü: i = 0 (a[i] = 4). j, i+1'den başlar.

a[0] = 4 ile a[1] = 7 karşılaştırılır → farklı, j ilerler.

a[0] = 4 ile a[2] = 1 karşılaştırılır → farklı, j ilerler.

a[0] = 4 ile a[3] = 7 karşılaştırılır → farklı, j ilerler.

Dış döngü: i = 1 (a[i] = 7). j, i+1'den başlar.

a[1] = 7 ile a[2] = 1 karşılaştırılır → farklı, j ilerler.

a[1] = 7 ve a[3] = 7 eşit → return true. En kötü durumda (tekrar yoksa) n(n−1)/2 = 6 karşılaştırma yapılırdı → O(n²).

boolean tekrarVar(int[] a) {
    for (int i = 0; i < a.length; i++)
        for (int j = i + 1; j < a.length; j++)
            if (a[i] == a[j])
                return true;
    return false;
}

Koddan Karmaşıklığa · Aynı problem, iki algoritma

Örnek Problem: Önek Ortalamaları

Girdi x[0..n−1]; çıktı a[j] = (x[0] + … + x[j]) / (j + 1). Kullanım: hareketli ortalama, finansal eğilim analizi (Goodrich §4.3).

a[0] = x[0] … x[0] öğelerinin ortalaması = 4.0.

a[1] = x[0] … x[1] öğelerinin ortalaması = 6.0.

a[2] = x[0] … x[2] öğelerinin ortalaması = 6.0.

a[3] = x[0] … x[3] öğelerinin ortalaması = 5.0.

İki çözüm: her j için baştan topla (O(n²)) · birikimli toplamı taşı (O(n)).

Koddan Karmaşıklığa · Kodu adım adım çalıştır

Kod İzleme: onekOrt1 — her j için baştan topla

n = 4; sonuç dizisi a oluşturulur (0.0 ile dolu).

j = 0: top = 0 — her j için toplam baştan başlar.

top += x[0] = 4 → top = 4.0.

a[0] = 4.0 / 1 = 4.0.

j = 1: top = 0 — her j için toplam baştan başlar.

top += x[0] = 4 → top = 4.0.

top += x[1] = 8 → top = 12.0.

a[1] = 12.0 / 2 = 6.0.

j = 2: top = 0 — her j için toplam baştan başlar.

top += x[0] = 4 → top = 4.0.

top += x[1] = 8 → top = 12.0.

top += x[2] = 6 → top = 18.0.

a[2] = 18.0 / 3 = 6.0.

j = 3: top = 0 — her j için toplam baştan başlar.

top += x[0] = 4 → top = 4.0.

top += x[1] = 8 → top = 12.0.

top += x[2] = 6 → top = 18.0.

top += x[3] = 2 → top = 20.0.

a[3] = 20.0 / 4 = 5.0.

return a. Toplama sayısı 1 + 2 + 3 + 4 = 10 = n(n+1)/2 → O(n²).

double[] onekOrt1(double[] x) {
  int n = x.length;
  double[] a = new double[n];
  for (int j = 0; j < n; j++) {
    double top = 0;
    for (int i = 0; i <= j; i++)
      top += x[i];
    a[j] = top / (j + 1);
  }
  return a;
}

Kod İzleme: onekOrt2 — birikimli toplam

top döngüden önce bir kez sıfırlanır ve turlar boyunca korunur.

j = 0: top += x[0] = 4 → top = 4.0 (önceki toplam yeniden kullanıldı).

a[0] = 4.0 / 1 = 4.0.

j = 1: top += x[1] = 8 → top = 12.0 (önceki toplam yeniden kullanıldı).

a[1] = 12.0 / 2 = 6.0.

j = 2: top += x[2] = 6 → top = 18.0 (önceki toplam yeniden kullanıldı).

a[2] = 18.0 / 3 = 6.0.

j = 3: top += x[3] = 2 → top = 20.0 (önceki toplam yeniden kullanıldı).

a[3] = 20.0 / 4 = 5.0.

Aynı sonuç, yalnız 4 toplama (onekOrt1: 10). Tek döngü → O(n).

double[] onekOrt2(double[] x) {
  int n = x.length;
  double[] a = new double[n];
  double top = 0;
  for (int j = 0; j < n; j++) {
    top += x[j];
    a[j] = top / (j + 1);
  }
  return a;
}

Alan ve Doğruluk

Alan Karmaşıklığı

  • Algoritmanın kullandığı bellek miktarını ölçer; genellikle Büyük O gösterimiyle ifade edilir.
  • Bellek kullanımının girdi boyutuna bağlı artışını gösterir (girdinin kendisi çoğu zaman sayılmaz; ek alan).
  • Sınırlı bellek kaynaklarına sahip sistemlerde bellek verimliliği önemlidir.
O(1) · SabitÖrnek: bir değişken oluşturma. Bellek kullanımı girdi boyutuyla değişmez.
O(n) · DoğrusalÖrnek: bir dizinin tüm öğelerini saklama; onekOrt'un a dizisi.
O(n2) · KareÖrnek: n×n boyutunda bir matrisi saklama. Bellek, n'nin karesiyle artar.

Alan ve Doğruluk

Doğruluk (Correctness)

  • Doğru bir algoritma, her geçerli girdi için sonlu sürede beklenen çıktıyı üretir.
  • Hızlı çalışan ama yanlış sonuç veren bir algoritmanın değeri yoktur.

Sağlamlık (Robustness)

  • Algoritmanın beklenmeyen durumlarla başa çıkma yeteneğidir.
  • Sağlam bir algoritma, normal aralığın dışındaki girdileri bile çökmeden veya yanlış sonuç üretmeden işleyebilir.

Sık Yapılan Hatalar

“O = en kötü durum”O bir üst sınır gösterimidir; en iyi / en kötü durum ayrı kavramdır. Her durum için O, Ω, Θ yazılabilir.
“O(1) her zaman hızlıdır”Sabit ama büyük olabilir; küçük n'de 1000·n'lik algoritma, n²'lik olandan yavaş kalabilir.
“İç içe döngü = n²”İç döngü j *= 2 ile ilerliyorsa n log n; sabit sayıda dönüyorsa O(n).
“log tabanı önemlidir”log₂ n ile log₁₀ n arasında yalnız sabit çarpan var: ikisi de O(log n).
(lo + hi) / 2 taşmasıÇok büyük dizilerde int taşar; lo + (hi - lo) / 2 güvenlidir.

Örnek Problemler

  1. Tüm öğe çiftlerini karşılaştıran algoritmanın zaman karmaşıklığı nedir?
  2. f(n) = 5n³ + 2n² + 100 hangi Θ sınıfındadır?
  3. n = 1024 öğeli sıralı dizide ikili arama en kötü durumda kaç tur döner?
  4. for (int i = 1; i < n; i *= 2) döngüsü kaç kez döner?
  5. Doğrusal aramanın en iyi ve en kötü durumu nedir?
  6. A algoritması 100n, B algoritması n² adım atıyor. Hangi n değerleri için A daha hızlıdır?
Cevapları göster
  1. n(n − 1)/2 karşılaştırma → O(n2).
  2. Θ(n³): en hızlı büyüyen terim belirler, sabitler atılır.
  3. ⌊log₂ 1024⌋ + 1 = 11 tur.
  4. i = 1, 2, 4, …: ⌈log₂ n⌉ tur → O(log n).
  5. En iyi: hedef ilk öğe, Θ(1). En kötü: hedef sonda ya da yok, Θ(n).
  6. 100n < n² ⇔ n > 100: büyük n için daha yavaş büyüyen algoritma kazanır.

Alıştırmalar

  1. Kod parçasının Büyük O'su nedir?

  2. f(n) = 3n² + 5n + 2 = O(n²) olduğunu c ve n₀ vererek gösterin.
  3. Katlama deneyinde n iki katına çıkınca süre ≈ 8 katına çıkıyor. T(n) hangi sınıfta?
  4. n = 5 için onekOrt1 ve onekOrt2 kaçar toplama yapar?
  5. for (i = 0; i < n; i++) for (j = i; j < n; j++) s++; sonunda s kaçtır?
  6. O(n²) bir algoritma n = 1000 için 2 saniye sürüyor. n = 4000 için süre yaklaşık kaçtır?
Cevaplar / ipuçları
  1. Dış döngü ⌊log₂ n⌋ tur, iç döngü n → O(n log n).
  2. n ≥ 1 için 5n ≤ 5n² ve 2 ≤ 2n² → f(n) ≤ 10n²: c = 10, n₀ = 1.
  3. 2³ = 8 → O(n³) (kübik).
  4. onekOrt1: 1+2+3+4+5 = 15; onekOrt2: 5.
  5. n + (n − 1) + … + 1 = n(n + 1)/2 → O(n²).
  6. n 4 katına çıkınca süre 4² = 16 katına: ≈ 32 saniye.
