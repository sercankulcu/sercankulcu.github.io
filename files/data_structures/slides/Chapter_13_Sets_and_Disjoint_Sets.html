int firstRepeat(int[] a) {
  Set<Integer> seen = new HashSet<>();
  for (int x : a) {
    if (!seen.add(x))   // not added?
      return x;            // already there: a repeat
  }
  return -1;               // no repeats
}

Set Implementations

Hash-Based Set

  • The set is stored as a hash table that holds keys only, with no values.
  • Each element's position is computed quickly from its hash code.
  • Insertion, removal, and lookup take O(1) on average; with a bad hash, O(n) in the worst case.
  • Java's HashSet uses a HashMap internally.

Start: an empty table with 7 buckets. Position = hashCode(x) mod 7.

add(12): 12 mod 7 = 5 → bucket 5 is empty, so 12 goes in.

add(25): 25 mod 7 = 4 → into bucket 4.

add(7): 7 mod 7 = 0 → into bucket 0.

add(19): 19 mod 7 = 5 → collision! Bucket 5 holds 12; 19 goes at the end of the chain.

add(12) again: bucket 5 is scanned and 12 is found → not added, false is returned. This is what makes a set a set.

contains(26): 26 mod 7 = 5 → only bucket 5 (12, 19) is scanned; 26 is not found → false. The other buckets are never examined.

Tree-Based (Sorted) Set

  • The set is stored as a balanced binary search tree (Java's TreeSet: a red-black tree).
  • Elements are kept sorted; an inorder traversal produces them in order.
  • Lookup, insertion, and removal take O(log n).
  • Elements must be comparable (Comparable or Comparator).
  • TreeSet treats two elements as the same when compare(a, b) == 0, so the ordering must be consistent with equals.

Union and Intersection of Sorted Arrays (Two Pointers)

void unionIntersection(int[] a, int[] b,
    List<Integer> uni, List<Integer> both) {
  int i = 0, j = 0;
  while (i < a.length && j < b.length) {
    if (a[i] < b[j]) uni.add(a[i++]);
    else if (a[i] > b[j]) uni.add(b[j++]);
    else {                     // in both
      uni.add(a[i]);  both.add(a[i]);
      i++;  j++;
    }
  }
  while (i < a.length) uni.add(a[i++]);
  while (j < b.length) uni.add(b[j++]);
}

The sets are in sorted arrays. Like merge in merge sort, two pointers advance in a single pass (Goodrich: generic merge).

a[i] = 1 < b[j] = 3 → 1 is only in a: added to the union, i++.

a[i] = b[j] = 3 → in both: added once to the union and to the intersection; both pointers advance.

a[i] = 5 > b[j] = 4 → 4 is only in b: added to the union, j++.

a[i] = b[j] = 5 → in both: added once to the union and to the intersection; both pointers advance.

a[i] = 7 < b[j] = 8 → 7 is only in a: added to the union, i++.

a[i] = 9 > b[j] = 8 → 8 is only in b: added to the union, j++.

j = 4 = b.length → b is exhausted and the main loop exits. The intersection is complete: no more common elements are possible.

The 9 left in a goes straight into the union, i++.

Nothing is left in b. Union [1, 3, 4, 5, 7, 8, 9], intersection [3, 5]. Each step advances one pointer → at most n + m steps: O(n + m).

Two empty sets: all bits 0.

Add 5 to set b: bit 5 turns on.

OR: 1 if either bit is 1 → union {1, 3, 4, 5}. A single machine instruction.

AND: 1 if both bits are 1 → intersection {3}.

~b flips the bits of b; a & ~b: in a but not in b → difference {1, 4}.

Multiset (Bag)

  • A multiset (or bag) is a set in which the same element can appear more than once.
  • Order still doesn't matter; what matters is how many times each element occurs (its multiplicity).
  • Natural implementation: an element → count map.
  • Examples: word frequencies in a text, a shopping cart, a vote count.

Multisets

A Multiset in Java

class Multiset<E> {
    private final Map<E, Integer> counts = new HashMap<>();
    private int n = 0;                                   // number of elements, repeats included
    void add(E e) { counts.merge(e, 1, Integer::sum); n++; }  // 1 if absent, else +1
    int count(E e) { return counts.getOrDefault(e, 0); }
    boolean remove(E e) {
        Integer c = counts.get(e);
        if (c == null) return false;                     // e is absent
        if (c == 1) counts.remove(e);                       // counter would hit 0: delete entry
        else counts.put(e, c - 1);
        n--;
        return true;
    }
    int size() { return n; }
}

Multisets

Multimap

  • In a multimap, one key can map to several values (course → students).
  • Goodrich ADT: get(k) returns all values; put(k, v), remove(k, v), removeAll(k); size() counts all (k, v) pairs.
  • Java has no built-in class: build one from Map<K, List<V>>.
Map<String, List<String>> m = new HashMap<>();
void put(String k, String v) {   // create an empty list if absent
  m.computeIfAbsent(k, x -> new ArrayList<>()).add(v);
}
List<String> get(String k) {
  return m.getOrDefault(k, List.of());
}

Unlike a multiset, it stores the values themselves, not just how many. With hashing, put / get are O(1)* and remove(k, v) is O(1 + list length).

Disjoint Sets (Union-Find)

Disjoint Sets and Union-Find

  • Disjoint sets: a collection of sets that share no elements. Every element belongs to exactly one set.
  • Union-Find (Disjoint Set Union, DSU) is the data structure that maintains them. It has two main operations:
find(x)Returns the representative (root) of the set containing x.find(x) == find(y) ⇔ same set
union(x, y)Merges the sets of x and y into one.{1,2} ∪ {3} → {1,2,3}

Each set is a tree: every node points to its parent; the root points to itself and represents the set.

Disjoint Sets (Union-Find)

Magnet Example

  • Picture strong magnets: once two touch, they never come apart.
  • As they merge, we want to keep track of which magnet is in which group.
  • First, each magnet gets a number.
  • A merge is a union; "same group?" compares two finds.

14 magnets, each in its own group: 14 disjoint sets. find(x) = x.

union(6, 8): the closest pair, 6 and 8, merge; now find(6) = find(8).

union(3, 4): 3 and 4 attract, forming the new group {3, 4}.

union(2, 3): 2 joins the group {3, 4} → {2, 3, 4}.

union(9, 10), union(13, 14), union(9, 13) → {9, 10, 13, 14}.

union(5, 7), union(7, 11), union(11, 12) → {5, 7, 11, 12}. Five groups remain (1 is alone).

Are 4 and 10 in the same group? find(4) ≠ find(10) → no. union(4, 10) merges the two groups.

The merging goes on until all magnets end up in one group: find(x) gives the same root for everyone.

Disjoint Sets (Union-Find)

The Find and Union Operations

  • find(x) returns the name (root) of the set containing x by following parent links until it reaches the root.
  • This is not the search of a search tree: no value is looked for; we simply climb to the root.
  • union(x, y) replaces two sets with their union by attaching one root below the other.
The sets are disjoint to begin with, so no duplicate check is needed: only one parent link changes.
find(x):
  if x.parent != x:
    x.parent = find(x.parent)  // path compression
  return x.parent

union(x, y):
  root1 = find(x)
  root2 = find(y)
  if root1 != root2:
    // make the root of one set
    // a child of the other's root
    root1.parent = root2

int find(int p) { return id[p]; }  // O(1)
void union(int p, int q) {
  int pid = id[p], qid = id[q];
  if (pid == qid) return;
  for (int i = 0; i < id.length; i++)
    if (id[i] == pid)
      id[i] = qid;           // O(n) scan
}

Disjoint Sets (Union-Find)

Why Do We Need Improvements?

  • find takes as many steps as the node's distance from the root. A bad sequence of unions turns the tree into a chain → O(n) in the worst case.

Start: 5 singleton sets; each node is its own root. We will do union(1,2), union(2,3), union(3,4), union(4,5) in order.

union(1, 2): two singleton sets; both methods put 1 under 2.

union(2, 3): the naive method puts root 2 (a 2-element tree) under the singleton 3 → the chain grows. By size: the singleton 3 goes under 2, the root of the larger tree.

union(3, 4): the naive chain grows one more level; by size, 4 again joins the root.

union(4, 5): the naive tree is now a chain (height n − 1 → find is O(n)); the by-size tree is a star (height 1).

Two simple ideas keep the trees flat: (1) union by size or rank and (2) path compression. Together they give nearly constant time per operation: O(α(n)).

Disjoint Sets (Union-Find)

Union by Size

  • Store each tree's size (number of elements) at its root.
  • When merging, attach the root of the smaller tree to the root of the larger; the new size is the sum of the two.

Two sets: {1, 4, 7} (size 3) and {2, 3, 6, 9} (size 4). Heights 1 and 2.

Naive union: if root 2 of the larger tree goes under the smaller one, the height rises to 3 and 9's find gets longer.

By size: root 1 of the smaller tree goes under root 2 of the larger. The height stays 2, and size[2] = 3 + 4 = 7.

Disjoint Sets (Union-Find)

Union by Rank

  • The rank is an upper bound on the height; a new set has rank 0.
  • The root of lower rank goes under the root of higher rank.
  • If the ranks are equal, the new root's rank goes up by one.
  • This rule keeps the height O(log n) even without path compression.
Path compression lowers the height but does not update the rank, so the rank is only an upper bound.
makeSet(x):
  parent[x] = x
  rank[x] = 0

find(x):   // with path compression
  if x != parent[x]:
    parent[x] = find(parent[x])
  return parent[x]

link(x, y):   // x, y are roots
  if rank[x] > rank[y]:
    parent[y] = x
  else:
    parent[x] = y
    if rank[x] == rank[y]:
      rank[y] = rank[y] + 1

union(x, y):
  link(find(x), find(y))

Disjoint Sets (Union-Find)

Path Compression

Path compression: during find, attach every node you pass directly to the root. Later finds finish in one step.

Start: 3's root is 7, but the path is 3 → 6 → 5 → 7 (3 steps).

find(3): the recursion climbs 3 → 6 → 5 → 7 and finds the root, 7.

On the way back, each node's parent becomes 7: parent[3] = parent[6] = 7 (5 was already on 7). Now find(3) and find(6) take one step, and 10's path is shorter too.

Disjoint Sets (Union-Find)

Java: Node-Based (Object) Union-Find

class SetNode {
  int data;
  int rank;   // bound on height
  SetNode parent;

  SetNode(int data) {
    this.data = data;
    this.parent = this;
    this.rank = 0;
  }
}

SetNode find(SetNode node) {
  if (node != node.parent)
    node.parent = find(node.parent); // compression
  return node.parent;
}
void union(SetNode x, SetNode y) {
  SetNode rootX = find(x);
  SetNode rootY = find(y);
  if (rootX == rootY) return;
  // union by rank
  if (rootX.rank < rootY.rank) {
    rootX.parent = rootY;
  } else if (rootX.rank > rootY.rank) {
    rootY.parent = rootX;
  } else { // equal: pick one
    rootX.parent = rootY;
    rootY.rank++;
  }
}

Disjoint Sets (Union-Find)

Java: Array-Based Union-Find

class UnionFind {
  private final int[] parent, rank;
  UnionFind(int n) {
    parent = new int[n];  rank = new int[n];
    for (int i = 0; i < n; i++) parent[i] = i;
  }
  int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]);
    return parent[x];
  }
  boolean union(int x, int y) {
    int rx = find(x), ry = find(y);
    if (rx == ry) return false;
    if (rank[rx] < rank[ry]) parent[rx] = ry;
    else if (rank[rx] > rank[ry]) parent[ry] = rx;
    else { parent[rx] = ry; rank[ry]++; }
    return true;
  }
}
UsageUnionFind uf = new UnionFind(5);
uf.union(0, 1); uf.union(3, 4);
uf.find(1) == uf.find(0) → true
uf.find(1) == uf.find(3) → false
Why does union return boolean?It returns true if a merge happened: in Kruskal's algorithm, that answers "does this edge form a cycle?"
Deep recursionFor very large n, find can be written with a loop instead.

Code Trace: Iterative find with Path Compression

The chain 4 → 3 → 2 → 1 → 0 (the result of bad unions). find(4) first looks for the root: root = 4.

Loop 1: parent[4] = 3 ≠ 4 → move up, root = 3.

Loop 1: parent[3] = 2 ≠ 3 → move up, root = 2.

Loop 1: parent[2] = 1 ≠ 2 → move up, root = 1.

parent[1] = 0 → root = 0; since parent[0] = 0, the loop ends: root found (4 steps).

Loop 2: parent[4] = 3 is not the root → this node will be compressed.

First the old parent is saved (next = 3), then parent[4] = 0: 4 now links directly to the root.

One step up the path: x = 3.

Loop 2: parent[3] = 2 is not the root → this node will be compressed.

First the old parent is saved (next = 2), then parent[3] = 0: 3 now links directly to the root.

One step up the path: x = 2.

Loop 2: parent[2] = 1 is not the root → this node will be compressed.

First the old parent is saved (next = 1), then parent[2] = 0: 2 now links directly to the root.

One step up the path: x = 1.

parent[1] = 0 = root: 1 already links to the root, so the loop ends.

The root 0 is returned. Every node on the path now links to the root, so later finds take 1 step. No recursion → no risk of stack overflow either.

int find(int x) {
  int root = x;
  while (parent[root] != root) root = parent[root];
  while (parent[x] != root) {    // path compression
    int next = parent[x];
    parent[x] = root;
    x = next;
  }
  return root;
}

int countComponents(int n, int[][] edges) {
  UnionFind uf = new UnionFind(n);
  int count = n;        // n singleton sets
  for (int[] e : edges)
    if (uf.union(e[0], e[1]))
      count--;          // two components merged
  return count;
}

Common Mistakes

1. Changing an element inside a setAn object whose hashCode changes after insertion stays in the wrong bucket, so contains returns false.p.x = 5; set.contains(p) → false
2. equals without hashCodeTwo "equal" objects will probably land in different buckets, so the HashSet holds them twice. Override both together.
3. Removing while iteratingset.remove(x) inside for-each → ConcurrentModificationException.set.removeIf(x -> x % 2 == 0);
4. Linking elements instead of rootsparent[x] = y is wrong: it splits x's tree. Correct:parent[find(x)] = find(y);
5. Forgetting to bump equal ranksWithout rank[ry]++, rank no longer tracks height and the O(log n) guarantee is lost.
6. A compare inconsistent with TreeSet's needsOf distinct objects with compare(a, b) == 0, only one is kept (e.g. when sorting by surname alone).
