Multiple Choice · Digital Data

Question 1: Representing Digital Data

Which of the following statements about representing digital data is false?

13 = 8 + 4 + 1 → 00001101; 00001011 is 11. The other statements are true: JSON/XML are not tables tied to a strict schema (structured data) but tagged, semi-structured data.

Short Answer · Introduction to Data Structures

Question 2: Primitive Types and Division

What does the following code print? Justify each value by the size and behavior of the primitive type involved.

byte b = 127;
b++;
int x = 7 / 2;
double y = 7 / 2;
double z = 7 / 2.0;
System.out.println(b + " " + x
    + " " + y + " " + z);
Show answer

Output: -128 3 3.0 3.5

  • A byte is always 8 bits (−128 … 127). Adding 1 to 127 overflows and wraps around to −128.
  • 7 / 2 divides two ints, so it is integer division → 3 (the fraction is dropped).
  • y: the division is still done in int (3) and only then converted to double → 3.0.
  • z: one operand is a double, so the division is floating-point → 3.5.

A data type determines both the set of values and how operations behave.

Question 4: Passing an Array and an int to a Method

What does the program print? Which assignments inside modify affect a and n?

The array is created on the heap; a holds only a reference to it.

n is a primitive variable; its value sits in the frame.

A new frame: arr gets a copy of the address in a, and k gets a copy of the value of n.

arr[0] = 99: the shared object itself changes → a sees [99, 2] too.

k = 99 changes only the local copy; n is still 1.

arr now points to a new array; the array a points to is unaffected.

The change happens only in the new array; a's array stays [99, 2].

Return: the frame is discarded; no reference to the new array remains, so the garbage collector reclaims it.

Output: 99 2 1. Java passes by value; for a reference type, the value copied is the address.

static void modify(int[] arr, int k) {
  arr[0] = 99;
  k = 99;
  arr = new int[]{0, 0};
  arr[1] = 50;
}
// main:
int[] a = {1, 2};
int n = 1;
modify(a, n);
System.out.println(a[0] + " " + a[1]
    + " " + n);

Question 5: A Generic Box

What is a in the code below? What happens if we uncomment s.put(7)? Why can we not write Box<int>?

Box<Integer> b = new Box<>();
b.put(5);
int a = b.get() + 1;
Box<String> s = new Box<>();
s.put("data");
// s.put(7);
Show answer

a = 6: put(5) boxes the int into an Integer, and b.get() + 1 unboxes it before adding.

s.put(7) is a compile error: for a Box<String>, put accepts only a String. Types are checked at compile time, so the wrong type is caught before the program runs.

The type parameter T must be a reference type; instead of the primitive int, we use the wrapper class Integer.

Question 6: ADT, Interface, and Class

Of this interface and the ArrayStack<E> class, which corresponds to the ADT and which to the data structure? And why does the client declare s with type Stack<Integer>?

public interface Stack<E> {
  int size();
  boolean isEmpty();
  void push(E e);
  E top();
  E pop();
}
// client code:
Stack<Integer> s = new ArrayStack<>(10);
Show answer
  • Interface = the ADT's contract: it states which operations are possible (what); it contains no implementation details.
  • ArrayStack = the data structure: it implements the ADT concretely with an array and an index t (how); the memory and performance details live here.
  • Because the variable has the interface type, the client depends only on the contract. To switch to a linked-list-based LinkedStack, only new ArrayStack<>(10) changes; the rest of the client code stays the same.

One ADT (the stack) can have several implementations.

Question 7: The State of an ArrayStack

On an empty ArrayStack<Integer> of capacity 4 we call, in order, push(3), push(7), pop(), push(9), and top(). At the end, what is the top index t, and what does top() return?

push(3): t = 0; push(7): t = 1; pop() returns 7, clears the cell, t = 0; push(9): t = 1, data[1] = 9. top() returns the top element without removing it → 9, and t is still 1. B forgets that pop decrements t.

Multiple Choice · Fundamental Data Structures

Question 8: Requirements and Structures

Which of the following requirement–data structure pairings is wrong?

To reach the i-th element of a linked list, we walk i nodes from the head → O(n). O(1) access by index is a property of arrays. The other pairings are correct: the back button returns to the most recent page (LIFO), lookup by key fits a map, and a network of relations fits a graph.

Multiple Choice · Fundamental Data Structures

Question 9: Stack or Queue?

Which of the following is implemented with a stack (LIFO) rather than a queue (FIFO)?

With undo, the most recent action is the first one undone (LIFO). Recursive calls, backtracking (mazes), and bracket matching also use a stack. In A, C, and D, whatever arrives first is handled first → queue; C is a distractor, but BFS runs on a queue while DFS runs on a stack.

Question 10: How Maps and Sets Behave

What does the code print?

Map<String, Integer> m = new HashMap<>();
m.put("apple", 3);
m.put("pear", 5);
m.put("apple", 7);
Set<Integer> s = new HashSet<>(m.values());
s.add(5);
System.out.println(m.size() + " " + m.get("apple")
    + " " + m.get("cherry") + " " + s.size());

Keys in a map are unique: the second put("apple", 7) adds no new pair but replaces the value with 7 → 2 pairs. For a missing key, get returns null. Adding 5 again to the set {7, 5} leaves it unchanged → 2. B is a distractor: the first value is not kept but overwritten.

Open-Ended Question · Summary

Question 11: Designing a Library System

Library software must find a book instantly by its ISBN, make borrowers of a popular book wait in order of request, let users browse books through a category/subcategory hierarchy, and cope with a collection that changes often. Which data structures would you choose? Justify each choice by the cost of the operations and by the questions for choosing a data structure.

Sample answer
  • ISBN → book: a map (hash table, HashMap); keys are unique, and search/insert/delete take O(1) on average. A sorted array with binary search finds a book in O(log n) but needs O(n) shifting for frequent insertions.
  • Waiting list: one queue (FIFO) per book; enqueue/dequeue in O(1).
  • Category hierarchy: a tree; each subcategory has exactly one parent (one-to-many).
  • Changing collection: dynamic structures, because insertions and deletions are frequent; the size is not known in advance, so a fixed-size array is a poor fit.

Optional: a graph for the “similar books” relation; a set for tags without duplicates.

Question 12: Organization and Relationship

Which of the following classifications by data organization is wrong?

A user follows many people and is followed by many; there is no single parent, and cycles are possible → graph (many-to-many). C is correct: every employee has exactly one manager. In A the elements have no order or links; in D every car has exactly one predecessor and one successor.

For each case, give the organization of the data (non-positional, linear, tree, graph) and the kind of relationship:

  1. Folders and files on a computer
  2. Items in a shopping cart (order does not matter)
  3. Songs to be played in order from a playlist
  4. Flight routes between cities

If we add a shortcut that points to a folder from somewhere else, what does the folder structure become?

CaseOrganizationRelationship
1. Folderstreeone-to-many
2. Cartnon-positionalnone
3. Playlistlinearone-to-one
4. Flight routesgraphmany-to-many
  • Every item in a folder tree has exactly one parent folder; everything branches out from the root folder.
  • Flights leave a city for many cities and arrive from many cities; there is no single parent.
