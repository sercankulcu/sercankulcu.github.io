Question 1: Degrees and the Handshaking Lemma

In the undirected graph V = {0, 1, 2, 3, 4}, E = {(0,1), (0,4), (1,2), (1,3), (1,4), (2,3), (3,4)}, find the degree of every vertex and verify the handshaking lemma (Σ deg(v) = 2m).

Show answer
v01234
deg(v)24233

Σ deg = 2 + 4 + 2 + 3 + 3 = 14 = 2 · 7 (m = 7). Each edge adds one to the degree of both its ends, so the total is always twice the number of edges.

Consequence: the number of odd-degree vertices (here 3 and 4) is always even.

Multiple Choice · Basic Terms

Question 2: Is This Degree Sequence Possible?

Can a simple undirected graph have vertex degrees 3, 3, 2, 2, 1?

The total, 11, is odd; by the handshaking lemma it must equal 2m, which would require 11 / 2 = 5.5 edges. A is tempting, but no such graph exists; the condition in B is necessary but not sufficient.

In the undirected graph V = {1, …, 5}, E = {(1,2), (1,3), (1,4), (2,5), (3,4), (4,5)}, which of these is a path that is not simple?

Multiple Choice · Basic Terms

Question 4: Directed Edges and Adjacency

A digraph has the edge (u, v) but not (v, u). Which statement is certainly true?

u is the tail (origin) and v the head (destination); adjacency is directed. C is tempting but wrong: there may be a path from v to u through other vertices (v → w → u). D: this edge adds to u's out-degree.

Multiple Choice · Graph Representations

Question 6: Empty Cells in a Weighted Matrix

In the adjacency matrix of a weighted graph, why do cells with no edge hold ∞ (e.g. Integer.MAX_VALUE) rather than 0?

A 0 in an edgeless cell means a fake, free edge (a 0 on the diagonal does make sense, as the distance to itself). B has it backwards: Java already initializes int[][] to 0, which is exactly why ∞ must be filled in explicitly.

Multiple Choice · Graph Representations

Question 8: The Cost of getEdge

In an undirected graph, what does the Graph ADT operation getEdge(u, v) ("Is there an edge u–v?") cost with an edge list, an adjacency list, and an adjacency matrix, respectively?

The edge list scans every edge; with adjacency lists we scan the shorter list; the matrix reads the single cell m[u][v]. C is tempting, but a matrix query does not scan a row: the O(n) row scan is the cost of "visit the neighbors".

Short Answer · Graph Representations

Question 9: Choosing a Representation for a Road Network

Would you store a road network of n = 10⁵ intersections and m = 3 · 10⁵ two-way roads as an adjacency matrix or as adjacency lists? Justify your choice by comparing the memory needed, with numbers.

Show answer

Adjacency lists.

  • Matrix: n² = 10¹⁰ cells (≈ 10 GB even at 1 byte per cell); only 2m = 6 · 10⁵ cells are filled → 0.006%.
  • Lists: n lists + 2m = 6 · 10⁵ entries → O(n + m) ≈ 7 · 10⁵ items, a few MB.

The graph is sparse (m ≈ 3n). Traversal also takes O(n + m) with lists but O(n²) with a matrix. A matrix pays off for dense graphs (m ≈ n²) and frequent "Is there an edge?" queries.

Short Answer · Traversal (BFS / DFS)

Question 10: A Faulty BFS: Where Is the Mark?

This BFS marks a vertex when it leaves the queue, not when it enters. On the triangle with edges 0–1, 0–2, 1–2 (neighbors in increasing order), what does bfs(0) print?

void bfs(int s) {
  boolean[] visited = new boolean[n];
  Queue<Integer> q = new ArrayDeque<>();
  q.add(s);
  while (!q.isEmpty()) {
    int w = q.poll();
    visited[w] = true;   // marked here
    System.out.print(w + " ");
    for (int u : adj.get(w))
      if (!visited[u]) q.add(u);
  }
}
Show answer

Output: 0 1 2 2

  • 0 leaves → 1 and 2 are added: q = [1, 2].
  • 1 leaves → 2 is not yet marked, so it is added again: q = [2, 2].
  • 2 leaves twice and is printed twice.

Fix: mark a vertex as it enters the queue (visited[u] = true; q.add(u);, and visited[s] = true at the start). Then each vertex enters the queue once; otherwise the queue can grow to O(m).

Code Trace · Traversal (BFS / DFS)

Question 11: BFS Order

The neighbor lists are 0: [2, 4] · 1: [3, 5] · 2: [0, 3] · 3: [1, 2, 5] · 4: [0, 5] · 5: [1, 3, 4]. In what order does bfs(0) print the vertices?

0 is marked as it enters the queue.

0 leaves the queue and is printed; its neighbors are 2, 4.

2 and 4 are marked and enqueued (level 1).

2 leaves; its neighbors are 0, 3.

0 is already marked → skip; 3 is added (level 2).

4 leaves; its neighbors are 0, 5.

0 is skipped; 5 is added (level 2).

3 leaves; its neighbors are 1, 2, 5.

1 is added (level 3); 2 and 5 are already marked.

5 leaves; its neighbors 1, 3, 4 are all marked → nothing added.

1 leaves; its neighbors 3, 5 are marked.

The queue is empty → done. Levels: {0}, {2, 4}, {3, 5}, {1}. O(n + m).

void bfs(int s) {
  boolean[] visited = new boolean[n];
  Queue<Integer> q = new ArrayDeque<>();
  visited[s] = true;  q.add(s);
  while (!q.isEmpty()) {
    int w = q.poll();
    System.out.print(w + " ");
    for (int u : adj.get(w))
      if (!visited[u]) {
        visited[u] = true;
        q.add(u);
      }
  }
}

Question 12: Recursive DFS Order

On this graph, whose neighbor lists are in alphabetical order, in what order does the recursive dfs(H) print the vertices?

A: B F I    B: A C E    C: B D E
D: C G H    E: B C G    F: A G
G: D E F    H: D        I: A

H → D → C → B → A (at each step, the first unvisited neighbor alphabetically) → F → G → E; at the dead end DFS backs up and goes from A to I. A is tempting, but it is the BFS order (level by level). D picks E instead of A after B.

Question 13: Connected Components

With n = 8 and edges (0,4), (4,6), (1,2), (5,7), (7,3), what are the array comp[] and the return value after calling components(comp)?

int components(int[] comp) {
  Arrays.fill(comp, -1);
  int count = 0;
  for (int s = 0; s < n; s++)
    if (comp[s] == -1) dfs(s, count++, comp);
  return count;
}
void dfs(int v, int c, int[] comp) {
  comp[v] = c;
  for (int u : adj.get(v))
    if (comp[u] == -1) dfs(u, c, comp);
}
Show answer

comp = [0, 1, 1, 2, 0, 2, 0, 2], return value 3.

  • s = 0: dfs {0, 4, 6} → component 0.
  • s = 1: dfs {1, 2} → component 1.
  • s = 2: already labeled. s = 3: dfs {3, 7, 5} → component 2 (3 comes before 5).

Now "Are u and v in the same component?" is the O(1) test comp[u] == comp[v]. Total O(n + m).

Question 15: Topological Sorting with Kahn

For the DAG with adj: 0: [] · 1: [] · 2: [3] · 3: [1] · 4: [0, 1] · 5: [2, 0], what order does kahn(adj) return?

Count the in-degrees: 0 ← 4, 5 · 1 ← 3, 4 · 2 ← 5 · 3 ← 2.

4 and 5, with in-degree 0, enter the queue: they depend on nothing.

4 leaves and joins the result.

4→0 and 4→1 count as deleted; 0 and 1 each still wait for one prerequisite.

5 leaves and joins the result.

5→2: indeg[2] = 0 → enqueue 2; 5→0: indeg[0] = 0 → enqueue 0.

2 leaves and joins the result.

2→3: indeg[3] = 0 → enqueue 3.

0 leaves; its list is empty, so nothing is updated.

3 leaves and joins the result.

3→1: indeg[1] = 0 → enqueue 1.

1 leaves and joins the result.

The queue is empty. Size 6 = n → no cycle. Order: 4 5 2 0 3 1. O(n + m).

List<Integer> kahn(List<List<Integer>> adj) {
  int n = adj.size();
  int[] indeg = new int[n];
  for (List<Integer> l : adj)
    for (int v : l) indeg[v]++;
  Queue<Integer> q = new ArrayDeque<>();
  for (int v = 0; v < n; v++)
    if (indeg[v] == 0) q.add(v);
  List<Integer> result = new ArrayList<>();
  while (!q.isEmpty()) {
    int u = q.poll();
    result.add(u);
    for (int v : adj.get(u))
      if (--indeg[v] == 0) q.add(v);
  }
  return result;  // size < n → cycle
}

Question 16: Faulty Cycle Detection

The line color[v] = 2 has been forgotten. For the DAG with edges 0→1, 0→2, 1→2, what does hasCycle(0, color) return, and why?

// color: 0 white, 1 gray, 2 black
boolean hasCycle(int v, int[] color) {
  color[v] = 1;
  for (int u : adj.get(v)) {
    if (color[u] == 1) return true;
    if (color[u] == 0 && hasCycle(u, color))
      return true;
  }
  // color[v] = 2;  (forgotten)
  return false;
}
Show answer

It returns true: a false alarm, since there is no cycle.

  • 0 gray → 1 gray → 2 gray; 2 has no outgoing edges and returns false, but 2 stays gray. So does 1.
  • Back at 0, edge 0→2 finds color[2] == 1 → mistaken for a back edge.

The correct rule: a finished vertex turns black (2). Only an edge to a gray vertex (one on the current path) means a cycle; an edge to a black vertex does not. The fixed code returns false.

BFS finds the path with the fewest edges: A→B→D→F (3 edges) = 4 + 10 + 11 = 25. A is tempting, but 20 is the length of the true shortest path A→C→E→D→F (Dijkstra's answer). C is the number of edges, not the weight.

Question 19: The Stale-Entry Check

In the Java Dijkstra, what happens if the marked continue line is deleted (weights ≥ 0)?

long[] e = pq.poll();
int u = (int) e[0];
if (e[1] > d[u]) continue; // stale
for (int[] k : adj.get(u)) {
  int v = k[0];
  long alt = d[u] + k[1];
  if (alt < d[v]) { d[v] = alt;
    pq.add(new long[]{v, alt}); }
}

When a stale entry comes out, d[u] is already smaller and the neighbors were relaxed with that d[u] earlier; alt < d[v] cannot hold again. A is tempting, but the line is there for efficiency, not correctness (stale entries are the duplicates added because Java's PQ has no "decrease key").

Multiple Choice · Minimum Spanning Trees

Question 21: The Cost of Kruskal's Algorithm

For a graph with n vertices and m edges, which phase determines the total running time of Kruskal's algorithm implemented with Union-Find?

2m finds + (n − 1) unions cost only O(m · α(n)), nearly linear; sorting dominates. Since m ≤ n², log m ≤ 2 log n, so O(m log m) = O(m log n). B is tempting, but it would apply only if cycles were checked with DFS instead of Union-Find.

Question 23: Prim's Choice

Which edge does Prim's algorithm add to the tree at each step?

One end of the edge must be in the tree and the other outside; the lightest such edge is chosen. A is Kruskal's rule (with a cycle check). B is Dijkstra's key. D is wrong: the lightest outgoing edge may leave from a vertex added earlier.

Question 24: Stale Entries

In lazy Prim with a priority queue, what happens if the line if (inTree[e[1]]) continue; is deleted?

After v joins the tree, old entries leading to v stay in the queue. Without the check, when such an entry comes out, an edge with both ends in the tree is added to T: a cycle forms and the spanning tree is ruined.

Run the pseudocode Dijkstra from the slides (a vertex removed from Q is settled; only neighbors still in Q are relaxed) from A on this digraph. What distances does it find, what are the correct distances, and at which step does the error begin?

A→B 2   A→C 4
C→B −3  B→D 1
Show answer
Removedd[B]d[C]d[D]
A (0)24∞
B (2)243
D (3)243

Dijkstra: B = 2, C = 4, D = 3. Correct: B = 4 − 3 = 1 (A→C→B), D = 2 (A→C→B→D).

The error begins when B is settled at 2: the assumption that "the smallest distance in the queue cannot be beaten by another route" holds only when weights are ≥ 0. When C is processed, B is no longer in Q, so C→B (−3) is never relaxed, and the wrong d[B] spreads to D.

The Java version with stale entries would re-add B to the queue here and find the right answer, but it loses its time bound. With negative edges, use Bellman-Ford.

Question 27: What Does path() Return?

A BFS has produced prev = [−1, 0, 0, 1, 1, 3, 5, −1]. With this array, what do path(prev, 0, 7) and path(prev, 2, 6) return?

List<Integer> path(int[] prev, int s, int t) {
  LinkedList<Integer> p = new LinkedList<>();
  for (int v = t; v != -1; v = prev[v])
    p.addFirst(v);
  if (p.getFirst() != s) return List.of();
  return p;
}

t = 7: p = [7], and prev[7] = −1 ends the loop; the first element 7 ≠ 0 → empty list (unreachable). s = 2, t = 6: the chain is 6, 5, 3, 1, 0; the first element 0 ≠ 2 → again an empty list. C is tempting: there is a 3-edge path from 2 to 6, but prev[] is the path tree from source 0; a path from 2 needs a fresh BFS from 2. B gives the lists returned without the first-element check. D is wrong: since the condition is v != -1, prev[−1] is never read.
