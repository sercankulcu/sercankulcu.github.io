Soru 1: Eşleme ADT ve Hash Tablosu

Eşleme (Map) ile hash tablosu arasındaki ilişki için aşağıdakilerden hangisi doğrudur?

C doğru: eşleme bir ADT'dir; sıralı dizi, arama ağacı ya da hash tablosuyla gerçekleştirilebilir. A ters çevrilmiştir. B yanlış: anahtarlar tekildir, aynı anahtarla put yalnızca değeri günceller. D yanlış: O(1) (ortalama) hash tablosuna özgüdür; sırasız listede get O(n)'dir.

Soru 3: Doğrudan Adresleme

Anahtarları 9 haneli okul numaraları olan birkaç yüz öğrenci, doğrudan adresleme (anahtar = dizi indisi) ile saklanmak isteniyor. Hangisi doğrudur?

A doğru: her olası anahtar için bir hücre vardır, istenen hücreye tek adımda gidilir; bedeli bellek israfıdır (kullanılan oran ≈ 300 / 10⁹). B yanlış: boş hücreye bakmak da tek adımdır. D aslında hash tablosunun tanımıdır: büyük anahtar uzayını küçük diziye sıkıştırmak için hash fonksiyonu gerekir.

Soru 4: İyi Bir Hash Fonksiyonu

Aşağıdakilerden hangisi iyi bir hash fonksiyonundan beklenen bir özellik değildir?

D beklenemez: anahtar uzayı tablodan büyükse güvercin yuvası ilkesine göre çakışma kaçınılmazdır; amaç çakışmayı azaltmak, onu çözmek ise zincirleme/açık adreslemenin işidir. A en çekici çeldiricidir ama zorunludur: belirleyici olmayan fonksiyonla eklenen öğe bir daha bulunamaz.

Soru 5: Her Anahtar Aynı Kovaya

Bir anahtar sınıfının hashCode() metodu her nesne için 42 döndürüyor (equals doğru yazılmış). Bu anahtarlarla kullanılan ayrı zincirlemeli bir hash tablosu doğru çalışır mı ve işlemlerin maliyeti ne olur?

Cevabı göster

Doğru çalışır ama yavaştır. Sözleşme bozulmaz: eşit nesnelerin hash kodu yine eşittir. Hepsi aynı kovaya düşer; kovada equals ile doğru anahtar bulunur.

Fakat tablo tek bir uzun zincire (bağlı listeye) döner: get, put, remove O(n). Java 8+ HashMap bu kovayı ağaca çevirir; anahtarlar Comparable ise O(log n).

0, 12, 24, 36, 48 anahtarları bölme yöntemiyle (h(k) = k mod N) yerleştiriliyor. N = 12 ve N = 11 için kovaları bulun; N'nin asal seçilmesi neden önerilir?

Soru 7: MAD Sıkıştırma

MAD (çarp-topla-böl) yöntemi h(k) = ((a·k + b) mod p) mod N ile a = 3, b = 4, p = 17, N = 5 alınıyor. h(7) kaçtır?

B: 3·7 + 4 = 25 → 25 mod 17 = 8 → 8 mod 5 = 3. A, son mod N adımını unutmaktır (8 tabloda geçerli bir indis değil). C, mod p atlanıp 25 mod 5 alınmasıdır. D, yalnızca 7 mod 5 (bölme yöntemi) sonucudur.

Soru 8: equals/hashCode Sözleşmesi

Java'daki equals/hashCode sözleşmesi için hangisi doğrudur?

C doğru: eşit anahtarlar aynı kovaya düşmelidir. A bu kuralın tersidir ve yanlıştır: aynı hash kodu yalnızca aynı kovayı gösterir, kovada ayrıca equals ile karşılaştırılır (çakışma). B'yi istemek imkânsızdır. D tipik hatadır: kova hashCode ile seçilir; ezilmezse eşit anahtarlar farklı kovalara düşer.

Soru 9: Unutulan hashCode

Nokta sınıfı equals'ı eziyor ama hashCode'u ezmiyor. Son satır pratikte ne yazdırır ve bu sonuç neden garanti değildir? Hatayı düzeltin.

class Nokta {
  int x, y;
  Nokta(int x, int y) {
    this.x = x; this.y = y;
  }
  public boolean equals(Object o) {
    return o instanceof Nokta p
        && x == p.x && y == p.y;
  }
}
Map<Nokta, String> m = new HashMap<>();
m.put(new Nokta(1, 2), "A");
Nokta q = new Nokta(1, 2);
System.out.println(q.equals(new Nokta(1, 2))
    + " " + m.get(q));
Cevabı göster

Çıktı: true null

İki nokta equals'a göre eşittir. Ama hashCode ezilmediği için Object.hashCode() (nesne kimliği) kullanılır: q'nun kimlik hash'i ilk nesneninkinden farklıdır ve pratikte neredeyse kesinlikle başka bir kovaya düşer; orada eşleşme yoktur → null (kuramsal olarak aynı kovaya düşebilir, garanti değildir; ama doğru çalışma tesadüfe kalmış olur).

Düzeltme: aynı alanlarla hashCode da ezilir:

public int hashCode() {
  return Objects.hash(x, y);
}

(Ya da record Nokta(int x, int y): ikisi de hazır gelir.)

Soru 10: String Hash Kodu İzleme

Aşağıdaki kod (String.hashCode() ile aynı hesap) ne yazdırır?

Önce kendiniz tahmin edin, sonra › ile ilerleyin.

hash("Ece") çağrılır. Karakter kodları: E = 69, c = 99, e = 101.

h = 0 ile başlanır.

0 < 3 → döngü sürer; s.charAt(0) = 'E' (69).

h = 31 · 0 + 69 = 69.

1 < 3 → s.charAt(1) = 'c' (99).

h = 31 · 69 + 99 = 2139 + 99 = 2238. Önceki toplam 31 ile çarpılır: konum sonucu etkiler.

2 < 3 → s.charAt(2) = 'e' (101).

h = 31 · 2238 + 101 = 69378 + 101 = 69479.

3 < 3 yanlış → döngü biter; return 69479 (= 69·31² + 99·31 + 101).

Sıkıştırma: 69479 = 13 · 5344 + 7 → floorMod(69479, 13) = 7.

Çıktı: 69479 7. "Ece" 13 kovalı tabloda kova 7'ye düşer.

int hash(String s) {
  int h = 0;
  for (int i = 0; i < s.length(); i++)
    h = 31 * h + s.charAt(i);
  return h;
}
// main:
int kod = hash("Ece");
int indis = Math.floorMod(kod, 13);
System.out.println(kod + " " + indis);

Soru 12: %, floorMod ve Math.abs

Aşağıdaki satır ne yazdırır?

System.out.println((-7 % 10) + " "
  + Math.floorMod(-7, 10) + " "
  + Math.abs(Integer.MIN_VALUE));

A: Java'da % sonucu bölünenin işaretini alır (−7); floorMod negatifse N ekler (3). Integer.MIN_VALUE'nun pozitif karşılığı int'e sığmaz, Math.abs onu negatif bırakır. Bu yüzden kova indisi için % N ya da Math.abs(h) % N değil, Math.floorMod(h, N) kullanılır; diğer ikisi ArrayIndexOutOfBoundsException'a yol açabilir.

Soru 13: yerlestir() ile Güncelleme

Sunumdaki HashTablosu sınıfıyla (ayrı zincirleme, başa ekleme, getKovaIndisi = floorMod(anahtar, 10)) aşağıdaki işlemler yapılıyor. buyukluk kaç olur ve kova 5'in zinciri neye benzer?

HashTablosu t = new HashTablosu(10);
t.yerlestir(5,  "Ali");
t.yerlestir(15, "Can");
t.yerlestir(25, "Ece");
t.yerlestir(15, "Deniz");
Cevabı göster

buyukluk = 3. Kova 5: (25, "Ece") → (15, "Deniz") → (5, "Ali") → null

  • 5, 15, 25'in hepsi kova 5'e düşer; her yeni düğüm zincirin başına eklenir.
  • yerlestir(15, "Deniz"): zincir taranır, 15 bulunur, yalnızca değeri "Can" → "Deniz" olur ve return edilir: yeni düğüm yok, buyukluk artmaz.

Maliyet: kova O(1) bulunur, zincir taraması O(zincir uzunluğu).

Soru 14: Hatalı sil()

Aşağıdaki sil metodunda bir hata var. 10 kovalı tabloya önce 5 sonra 15 eklendikten sonra sil(5) ve sil(15) çağrılıyor. Hangi çağrı ve neden hata verir? Düzeltin.

public String sil(Integer anahtar) {
  int ki = getKovaIndisi(anahtar);
  HashDugumu ilk = kovalar[ki];
  HashDugumu onceki = null;
  while (ilk != null &&
         !ilk.anahtar.equals(anahtar)) {
    onceki = ilk;  ilk = ilk.sonraki;
  }
  if (ilk == null) return null;
  buyukluk--;
  onceki.sonraki = ilk.sonraki;
  return ilk.deger;
}
Cevabı göster

Zincir: kova 5 = 15 → 5 (başa ekleme).

  • sil(5): 15 ≠ 5 → onceki = 15, ilk = 5 → bağ atlanır, "Ali" döner. Sorun yok.
  • sil(15): silinecek düğüm zincirin başı; döngüye girilmez, onceki null kalır → onceki.sonraki NullPointerException.

Düzeltme: baş düğüm durumu ayrı ele alınır:

if (onceki != null)
  onceki.sonraki = ilk.sonraki;
else
  kovalar[ki] = ilk.sonraki;

Soru 15: Açık Adresleme mi, Zincirleme mi?

Açık adresleme (open addressing) ile ayrı zincirleme karşılaştırıldığında hangisi doğrudur?

D doğru: tüm çiftler dizinin kendisinde durur (önbellek dostu), fakat λ → 1 iken yoklama sayısı patlar. A zincirleme için doğrudur; açık adreslemede yuva başına bir çift olduğundan n ≤ N, yani λ ≤ 1. B yoklama zincirini koparır, "silindi" işareti gerekir. C de yanlış: zincirlemede kovalar listedir, λ > 1 olabilir.

Soru 16: Doğrusal Yoklama İzleme

Döngü bittiğinde tablo nasıl görünür ve her anahtar kaç yoklama yapar?

Önce kendiniz tahmin edin, sonra › ile ilerleyin.

10 mod 7 = 3 (ev yuvası).

i = 0: yuva 3 boş → tablo[3] = 10 (1 yoklama).

17 mod 7 = 3: yuva 3 dolu (10), çakışma.

i = 1: yuva 4 boş → tablo[4] = 17 (2 yoklama).

24 mod 7 = 3: yine yuva 3.

3 (10) ve 4 (17) dolu; i = 2: yuva 5 boş → tablo[5] = 24 (3 yoklama).

3 mod 7 = 3: dördüncü kez yuva 3.

3, 4, 5 dolu; i = 3: yuva 6 boş → tablo[6] = 3 (4 yoklama).

5 mod 7 = 5: ev yuvası farklı ama küme 3–6'nın içinde kalıyor.

5 (24), 6 (3) dolu; i = 2: (5 + 2) mod 7 = 0 boş → başa sarılıp tablo[0] = 5 (3 yoklama).

Sonuç: [5, –, –, 10, 17, 24, 3]; toplam 13 yoklama. Yan yana dolu yuvalar tek bir küme oluşturdu: birincil kümelenme.

Integer[] tablo = new Integer[7];
for (int k : new int[]{10, 17, 24, 3, 5}) {
  int h = k % 7;            // ev yuvası
  for (int i = 0; i < 7; i++) {
    int j = (h + i) % 7;
    if (tablo[j] == null) {
      tablo[j] = k;
      break;
    }                        // dolu: i++
  }
}

Soru 19: İkinci Hash Fonksiyonu

Çift hash'te ikinci fonksiyon olarak neden h₂(k) = k mod 7 yerine h₂(k) = 7 − (k mod 7) kullanılır (N = 13)?

Soru 20: Silinen Yuvayı null Yapmak

N = 7, h(k) = k mod 7, doğrusal yoklama ile 10, 17, 24 eklenir; sonra 17 silinip yuvası null yapılır ve getir(24) çağrılır. Sonuç ne olur ve doğru çözüm nedir?

Cevabı göster

Üçünün de ev yuvası 3: 10 → 3, 17 → 4, 24 → 5.

17'nin yuvası (4) null yapılırsa getir(24): yuva 3 (10 ≠ 24) → yuva 4 boş → "yok" der ve durur. Oysa 24 yuva 5'tedir: yanlış sonuç, yoklama zinciri koptu.

Çözüm: yuvaya özel bir "silindi" (DEFUNCT, tombstone ✗) işareti konur. Arama bu yuvayı dolu gibi atlayıp devam eder; ekleme ise onu boş gibi yeniden kullanabilir.

Soru 21: yuvaBul() ve Silindi İşareti

Tablo [5, –, –, 10, ✗, 24, 3] (N = 7, ✗ = SILINDI). yuvaBul(31) ne döndürür ve yerlestir(31) 31'i hangi yuvaya koyar?

Önce kendiniz tahmin edin, sonra › ile ilerleyin.

N = 7; 17 silinmiş, yuva 4'te ✗ var. h = 31 mod 7 = 3.

i = 0: yuva 3 dolu, 10 ≠ 31 → sonraki yuva.

i = 1: yuva 4 SILINDI → ilk uygun yuva: uygun = 4.

Silindi ≠ boş: break yok, aramaya devam (31 ötede olabilir).

i = 2: yuva 5 dolu, 24 ≠ 31.

i = 3: yuva 6 dolu, 3 ≠ 31.

i = 4: (3 + 4) mod 7 = 0, dolu, 5 ≠ 31.

i = 5: yuva 1 gerçekten boş. uygun zaten 4, değişmez; break: 31 bundan ötede olamaz.

31 yok: return −(4 + 1) = −5.

yerlestir(31): j = −5 < 0 → tablo[−(j + 1)] = tablo[4] = 31. Silindi yuvası yeniden kullanıldı.

private int yuvaBul(int k) {
  int h = Math.floorMod(k, N), uygun = -1;
  for (int i = 0; i < N; i++) {
    int j = (h + i) % N;  // doğrusal
    if (tablo[j] == null ||
        tablo[j] == SILINDI) {
      if (uygun == -1) uygun = j;
      if (tablo[j] == null) break;
    } else if (tablo[j].anahtar == k)
      return j;  // bulundu
  }
  return -(uygun + 1);  // yok: yer kodu
}

Soru 22: Neden −(uygun + 1)?

yuvaBul anahtarı bulamazsa ekleme yerini -uygun yerine neden -(uygun + 1) olarak döndürür?

C: dönüş değeri iki bilgiyi taşır: ≥ 0 ise "bulundu, şu yuvada", < 0 ise "yok, şuraya eklenebilir". Yuva 0 da geçerli bir ekleme yeri olduğundan +1 kaydırması gerekir; çağıran yer -(j + 1) ile asıl yuvayı geri bulur. D en çekici çeldiricidir ama ekleme tam olarak uygun yuvasına yapılır, sonrakine değil.

Soru 23: Yük Faktörü ve Yoklama Sayısı

Doğrusal yoklamada başarısız bir aramanın beklenen yoklama sayısı (Knuth) ½(1 + 1/(1−λ)²)'dir. λ = 0,5 ve λ = 0,8 için bu değeri hesaplayın; sonuç açık adreslemede λ ≤ 0,5 önerisini nasıl açıklar?

Cevabı göster
  • λ = 0,5: ½(1 + 1/0,25) = ½(1 + 4) = 2,5 yoklama.
  • λ = 0,8: ½(1 + 1/0,04) = ½(1 + 25) = 13 yoklama.

Tablo yalnızca %50'den %80'e dolunca başarısız arama ~5 kat pahalanır; λ → 1 iken değer sonsuza gider (kümeler birleşir). Bu yüzden açık adreslemede λ ≤ 0,5 tutulur ve eşik aşılınca tablo ~2 katına büyütülür.

(Karşılaştırma: zincirlemede beklenen maliyet O(1 + λ); λ ≈ 0,75 eşiği yeterlidir.)

Soru 24: Yeniden Boyutlandırma

N = 5 kovalı zincirleme tabloya (başa ekleme, eşik λ > 0,75) 3, 8, 13, 9 ekleniyor. 4. eklemeden sonra tablo yeniN = 2·N + 1 ile büyütülüyor. Büyütmeden önceki ve sonraki kovaları ve λ değerlerini yazın.

Cevabı göster

Önce (k mod 5): kova 3: 13 → 8 → 3, kova 4: 9, diğerleri boş. λ = 4/5 = 0,8 > 0,75 → büyütme.

Sonra (N = 11, k mod 11): 13 → kova 2, 8 → kova 8, 3 → kova 3, 9 → kova 9. λ = 4/11 ≈ 0,36.

Eski konumlar geçersizdir: her anahtar yeni N ile yeniden hash'lenir (rehashing). Aynı kovadaki 3, 8, 13 artık ayrı kovalarda; en uzun zincir 3'ten 1'e indi. Büyütme tek seferde O(n) sürer.

Soru 25: Amortize Maliyet

Yeniden boyutlandırma tek seferde O(n) sürer. Kapasite eşik aşıldıkça yaklaşık 2 katına çıkarılıyorsa, ardı ardına n ekleme yapıldığında ekleme başına ortalama (amortize) maliyet nedir?

A: büyütmeler 1, 2, 4, …, n boyutlarında olur; toplam taşıma 1 + 2 + 4 + … + n < 2n, yani n eklemeye yayılınca ekleme başına O(1). C tek bir eklemenin en kötü maliyetidir, ortalama değil. (Kapasite sabit miktarla, ör. +10 artırılsaydı toplam O(n²), ekleme başına O(n) olurdu.)

Soru 27: HashMap Kova İndisi

Java HashMap'in kova seçimini taklit eden indis metodu için indis(32, 16) ve indis(65568, 16) kaçtır? Karıştırma satırı (h ^ (h >>> 16)) olmasaydı ne olurdu?

static int indis(Object key, int n) { // n = 2^k
  int h = key.hashCode();
  int m = h ^ (h >>> 16); // karıştır
  return m & (n - 1);        // alt k bit
}
Cevabı göster
  • 32 = 0x00000020: h >>> 16 = 0, m = 32, 32 & 15 = 0.
  • 65568 = 0x00010020: h >>> 16 = 1, m = 65568 ^ 1 = 65569, 65569 & 15 = 1.

Karıştırmasız: 32 & 15 = 0 ve 65568 & 15 = 0 → ikisi de kova 0'da çakışırdı. Kova sayısı 2'nin kuvveti olduğundan & (n − 1) maskesi yalnız alt 4 biti görür; XOR üst bitleri de indise katar. Bedeli: bir kaydırma + bir XOR.

Soru 30: ikiToplam()

ikiToplam(new int[]{3, 8, 4, 3, 6}, 6) ne döndürür? Her adımda gor eşlemesinin içeriğini izleyin; algoritmanın zaman karmaşıklığı nedir?

static int[] ikiToplam(int[] a, int hedef) {
  Map<Integer, Integer> gor = new HashMap<>();
  for (int i = 0; i < a.length; i++) {
    int ek = hedef - a[i];
    if (gor.containsKey(ek))
      return new int[]{gor.get(ek), i};
    gor.put(a[i], i);   // değer -> indis
  }
  return null;
}

Tek geçiş, her adım ortalama O(1) → O(n) zaman, O(n) ek bellek (kaba kuvvet O(n²)).

Soru 31: Okul Numarası Hash'i

hash(ab070c0de) = ((ab − 20)·100 + (c − 6)·500 + de) mod 1000 (ab: yıl 20–24, c: bölüm 6/7, de: sıra 00–99) ile 230706015 ve 220707099 numaralarının indislerini bulun. Bu fonksiyon neden hiç çakışma üretmez?

Cevabı göster
  • 230706015: ab = 23, c = 6, de = 15 → 300 + 0 + 15 = 315.
  • 220707099: ab = 22, c = 7, de = 99 → 200 + 500 + 99 = 799.

Yıl 0…4 × 100'lük blok, bölüm 0/500 kaydırma, sıra 0…99: 5 × 2 × 100 = 1000 olası numara 1000 farklı indise birebir gider. Bu bir mükemmel hash (perfect hash) örneğidir; anahtarın yapısı önceden bilindiği için mümkündür. Biçime uymayan girdi (ör. yıl 25) çakışma üretebilir, bu yüzden girdi doğrulanmalıdır.

Soru 32: substring Hatası

calculateHash içinde c satırı yanlışlıkla s.substring(5, 7) yazılırsa calculateHash("240707050") ne döndürür?

public int calculateHash(String s) {
  int ab = Integer.parseInt(s.substring(0, 2));
  int c  = Integer.parseInt(s.substring(5, 6));
  int de = Integer.parseInt(s.substring(7, 9));
  int yil   = (ab - 20) * 100;
  int bolum = (c - 6) * 500;
  return (yil + bolum + de) % 1000;
}

C: substring(5, 7) bitiş hariç 5. ve 6. karakterleri verir: "70" → c = 70. yil = 400, bolum = (70 − 6)·500 = 32000, de = 50 → 32450 % 1000 = 450. A doğru koddaki sonuçtur (substring(5, 6) = "7"). B olmaz: 7 ≤ uzunluk (9) olduğundan indis geçerlidir; hata sessizce yanlış indis üretir.

Soru 34: Değiştirilebilir Anahtar

Bir liste HashMap'e anahtar olarak konduktan sonra değiştiriliyor. Kod ne yazdırır ve neden?

List<Integer> k = new ArrayList<>();
k.add(1); k.add(2);
Map<List<Integer>, String> m =
    new HashMap<>();
m.put(k, "A");
k.add(3);
System.out.println(m.get(k));
System.out.println(m.size());
Cevabı göster

Çıktı: null ve 1 (iki satır).

put sırasında kova, [1, 2] listesinin hash koduyla seçildi. k.add(3) sonrası listenin hashCode()'u değişti; get(k) yeni hash koduyla başka bir kovaya bakar ve bulamaz. Çift hâlâ tablodadır (size() = 1) ama erişilemez durumdadır.

Soru 35: Kullanıcı Adı Müsait mi?

Bir web sitesinde kayıt sırasında "bu kullanıcı adı alınmış mı?" kontrolü saniyede binlerce kez yapılıyor ve yeni kayıtlar sürekli ekleniyor. Hangi veri yapısını, hangi anahtar ve hash fonksiyonu ile, hangi yük faktörü politikasıyla kullanırsınız; neden sıralı dizi + ikili arama değil?

Örnek cevap ve değerlendirme ölçütleri

Yapı: HashSet<String> (ya da HashMap): ortalama O(1) arama ve ekleme.

Anahtar: normalize edilmiş kullanıcı adı (ör. küçük harfe çevrilmiş, boşlukları kırpılmış); aksi hâlde "Ali" ile "ali" farklı sayılır. String.hashCode() tüm karakterleri ve konumlarını kullanır, iyi dağılır.

Yük faktörü: λ ≈ 0,75 eşiğinde ~2 kat büyütme (amortize O(1)); büyük ölçekte beklenen kayıt sayısına göre başlangıç kapasitesi verilerek yeniden boyutlandırma sayısı azaltılır.

Neden sıralı dizi değil: arama O(log n) olsa da her yeni kayıt araya ekleme ve kaydırma gerektirir (O(n)); sürekli kayıt alan sistemde uygun değildir. Sıralı listeleme gerekseydi ağaç düşünülürdü.

Değerlendirme: uygun yapı ve ortalama karmaşıklık · anahtar normalizasyonu · yük faktörü/büyütme politikası · sıralı diziyle gerekçeli karşılaştırma.

Soru 36: Zincirleme mi, Açık Adresleme mi?

İki senaryo için çakışma çözüm yöntemi seçin ve gerekçelendirin: (1) bellek kısıtlı bir gömülü sistemde, kayıt sayısı önceden bilinen ve neredeyse hiç silme yapılmayan bir tablo; (2) eleman sayısı öngörülemeyen, sık ekleme ve silme yapılan bir sunucu önbelleği.

Örnek cevap ve değerlendirme ölçütleri

(1) Açık adresleme (ör. çift hash ya da doğrusal yoklama): düğüm ve referans ek yükü yoktur, veriler ardışık dizidedir (önbellek dostu). Kayıt sayısı bilindiği için N, λ ≤ 0,5 olacak şekilde baştan seçilebilir; silme seyrek olduğundan "silindi" işaretlerinin birikmesi sorun olmaz.

(2) Ayrı zincirleme: λ 1'i aşsa bile çalışmaya devam eder, performans yavaşça düşer (O(1 + λ)); silme yalnızca düğümü zincirden koparmaktır, işaret gerekmez. Açık adreslemede sık silme ✗ yuvalarını biriktirir ve aramaları uzatır, periyodik yeniden hash'leme gerekir. (Java HashMap da bu yolu seçer.)

Her iki durumda da hash fonksiyonu iyi dağılmalı ve eşik aşılınca tablo büyütülmelidir.

Değerlendirme: her senaryoda doğru seçim · bellek düzeni ve λ sınırı (n ≤ N) bilgisi · silme davranışının (DEFUNCT) doğru değerlendirilmesi · O(1 + λ) / yoklama maliyetine atıf.
