The Stack ADT

The Stack

  • Items are added and removed at one end only: the top.
  • Think of a pile of plates or boxes.
  • To reach the bottom item, you must remove everything above it, one at a time.
  • The rule is LIFO (last in, first out), or equivalently FILO (first in, last out).

A new plate goes on top, and you take plates from the top.

UndoThe most recent action is undone first.
Browser “Back”Returns to the most recently visited page.
Function callsThe most recently called function finishes first.

The Stack ADT

push and pop, Step by Step

The stack starts empty: size = 0, nothing on top.

push(10): 10 goes onto the empty stack; the top is now 10.

push(15): 15 goes on top of 10.

push(20): 20 goes on top; size = 3.

top(): reads the top item, 20, but does not remove it.

pop(): 20, the last in, is the first out (LIFO).

pop(): removes 15; the top is now 10.

pop(): removes 10; the stack is empty again.

pop() on an empty stack → underflow error.

The Stack ADT

Time and Space Complexity

OperationTimeWhy?
pushO(1)only the top changes
popO(1)only the top changes
topO(1)the top is known directly
isEmpty, sizeO(1)a counter / index is kept
searching for an itemO(n)items must be removed one by one
  • The basic operations take the same time no matter how many items the stack holds.
  • A stack of n items uses O(n) memory; the operations need only O(1) extra.
  • A dynamic array grows when it fills up, so push is amortized O(1).
A stack buys speed by restricting access: because of the “top only” rule, no basic operation ever shifts or scans the items.

Implementation

Kinds of Stacks

Fixed-Size Stack
  • Capacity is set up front; it can neither grow nor shrink.
  • Pushing onto a full stack → overflow.
  • Popping an empty stack → underflow.
  • Backed by a fixed-size array.
Dynamic-Size Stack
  • Grows and shrinks at run time.
  • Increases its capacity automatically when full (e.g., doubles it).
  • May shrink when it holds far fewer items than its capacity.
  • Implemented with a dynamic array or a linked list.

Popping an empty stack (underflow) is an error in both kinds; overflow happens only in a fixed-size stack.

Implementation

Ways to Implement a Stack

The stack ADT can be implemented with an array or a linked list.

Array-Based push: increment top, then write the item to arr[top].
pop: read arr[top], then decrement top.
Linked-List-Based push: add a new node at the head of the list.
pop: remove the head node and return its value.

Implementation

Array-Based Stack

This is also called a bounded stack: its capacity is fixed when it is created and never changes.

Advantages

  • Simple and easy to implement.
  • No per-node references → saves memory.
  • Memory use is tightly bounded, which makes it safer against attacks that try to exhaust memory.
  • Items are contiguous → cache-friendly.

Watch out for

  • Check that the stack is not full before pushing.
  • Too small a capacity overflows; too large wastes memory.
  • In an array of objects, set a popped cell to null; otherwise the object lingers in memory.

Implementation

Array-Based Stack: Java

public class ArrayStack<E> implements Stack<E> {
    private E[] data;
    private int top = -1;                    // -1 → empty stack
    public ArrayStack(int capacity) { data = (E[]) new Object[capacity]; }
    public boolean isEmpty() { return top == -1; }
    public int size()        { return top + 1; }
    public E top()           { return isEmpty() ? null : data[top]; }
    public void push(E x) {
        if (top == data.length - 1) throw new IllegalStateException("Overflow");
        data[++top] = x;
    }
    public E pop() {
        if (isEmpty()) throw new IllegalStateException("Underflow");
        E x = data[top];
        data[top--] = null;                  // drop the reference
        return x;
    }
}

Java cannot create a generic array directly, so we cast an Object[] (the compiler issues an “unchecked” warning). Every operation is O(1).

Implementation

Dynamic Array: Doubling When Full

public void push(E x) {
  if (top == data.length - 1)
    resize(2 * data.length);
  data[++top] = x;
}
private void resize(int newCap) {
  E[] bigger = (E[]) new Object[newCap];
  for (int i = 0; i <= top; i++)
    bigger[i] = data[i];
  data = bigger;
}
  • When the array is full, we allocate one twice as large and copy the items over, so a push that grows the array takes O(n).
  • Growth is rare: over n pushes the copies total 2 + 4 + 8 + … < 2n, and the total cost is < 3n → push is amortized O(1).
  • Adding a fixed number of cells (+c) each time gives O(n²) in total, O(n) per push; capacity must grow proportionally.

Amortized cost is an average over a long sequence of operations, not the cost of any single one.

Implementation

Linked-List Stack

  • Items live in a chain of linked nodes → the size is flexible.
  • The size changes at run time as needed; no overflow (until memory runs out).
  • Each node stores a reference (next), which costs extra memory.
  • No random access, but reaching the top item (the head of the list) is quick and simple.
  • Insertion and removal happen at the head, so both are O(1).
class Node {
    int data;
    Node next;
    Node(int data) { this.data = data; }   // next = null
}

Why insert at the head? Deleting from the tail of a singly linked list requires finding the node before the tail → O(n).

Start: top = null, size = 0 → empty stack.

top = temp: the new top is 15. Insertion at the head, no shifting → O(1).

size++ → 2.

push returns. Stack (top to bottom): 15 → 10. The last item pushed is on top.

Node top;          // top of the stack
int size;

public void push(int data) {
  Node temp = new Node(data);
  temp.next = top;
  top = temp;
  size++;
}

back(): push the current page onto the forward stack; pop the back stack → News.

The Call Stack: fact(3) Step by Step

main is running and is about to call fact(3). Every call pushes a new stack frame.

The frame for fact(3) is pushed. n <= 1? 3 <= 1 → false.

3 * fact(2) can't be computed until fact(2) finishes. This frame waits, suspended.

The frame for fact(2) is pushed. n <= 1? 2 <= 1 → false.

2 * fact(1) can't be computed until fact(1) finishes. This frame waits, suspended.

The frame for fact(1) is pushed. n <= 1? 1 <= 1 → true.

Base case: return 1. Now the stack starts unwinding.

fact(1) is popped and returns 1. fact(2) resumes: 2 * 1 = 2.

fact(2) is popped and returns 2. fact(3) resumes: 3 * 2 = 6.

fact(3) = 6 is printed. Depth n → O(n) memory; recursion that goes too deep throws StackOverflowError.

int fact(int n) {
  if (n <= 1)
    return 1;
  return n * fact(n - 1);
}
// in main:
System.out.println(fact(3));

String reverse(String str) {
    Deque<Character> stack = new ArrayDeque<>();
    char[] chars = str.toCharArray();
    for (char c : chars)
        stack.push(c);
    for (int i = 0; i < str.length(); i++)
        chars[i] = stack.pop();
    return new String(chars);
}
// in main:
System.out.println(reverse("ABCD"));

Bracket Matching

Let the string S contain only the characters ( ) { } [ ]. S is balanced if and only if

  1. every opening bracket is closed by a bracket of the same type, and
  2. brackets are closed in the right order (the last one opened is the first one closed → LIFO!).
Algorithm: keep the unmatched opening brackets on a stack and scan S from left to right:
  • Opening bracket → push it.
  • Closing bracket → if the stack is empty, unbalanced; otherwise pop, and if the popped bracket is a different type, unbalanced.
  • At the end of S, an empty stack means balanced; anything left over is an unclosed bracket.
{[()]}balanced
([)]wrong order
(()unclosed
())extra closer

Applications

Bracket Matching: Java

boolean isBalanced(String s) {
  Deque<Character> stack = new ArrayDeque<>();
  for (char c : s.toCharArray()) {
    if (c == '(' || c == '[' || c == '{') {
      stack.push(c);
    } else {
      if (stack.isEmpty()) return false;
      char open = stack.pop();
      if (!matches(open, c)) return false;
    }
  }
  return stack.isEmpty();
}
Helper method 
boolean matches(char o, char c) {
  return (o == '(' && c == ')')
      || (o == '[' && c == ']')
      || (o == '{' && c == '}');
}
Empty-stack checkWithout it, input such as "())" or "]" pops an empty stack → exception.
ComplexityO(n) time; in the worst case the stack needs O(n) memory.

Next Greater Element

For each item in an array, find the first larger item to its right, or −1 if there is none.

arr473481
result7848−1−1
  • Brute force: scan to the right of every item → O(n²).
  • With a stack: scan the array right to left, keeping only “candidate” larger values → O(n).
  • From bottom to top, the stack stays in decreasing order (a monotonic stack).
int[] nextGreater(int[] arr) {
    int[] result = new int[arr.length];
    Deque<Integer> stack = new ArrayDeque<>();
    for (int i = arr.length-1; i >= 0; i--) {
        while (!stack.isEmpty() &&
               stack.peek() <= arr[i])
            stack.pop();
        result[i] = stack.isEmpty()
                 ? -1 : stack.peek();
        stack.push(arr[i]);
    }
    return result;
}

Deque<Integer> s = new ArrayDeque<>();

void push(int x) {
  s.push(x);
  if (min.isEmpty() || x <= min.peek())
    min.push(x);
}
int pop() {
  int x = s.pop();
  if (x == min.peek()) min.pop();
  return x;
}
int getMin() { return min.peek(); }

Towers of Hanoi

Towers of Hanoi: Iterative, with a Stack

Rules: each move takes the single top disk; a larger disk never goes on a smaller one.

// Task: move n disks from 'from' to 'to' using 'via'
record Task(int n, char from, char via, char to) {}

void hanoi(int n) {
  Deque<Task> stack = new ArrayDeque<>();
  stack.push(new Task(n, 'A', 'B', 'C'));
  while (!stack.isEmpty()) {
    Task t = stack.pop();
    if (t.n() == 1)
      System.out.println(t.from() + " → " + t.to());
    else {                         // reverse order
      stack.push(new Task(t.n()-1, t.via(), t.from(), t.to()));
      stack.push(new Task(1, t.from(), t.via(), t.to()));
      stack.push(new Task(t.n()-1, t.from(), t.to(), t.via()));
    }
  }
}
An explicit task stack takes the place of the call stack in the recursive solution. When n > 1, three subtasks are pushed in reverse order: 1. n−1 disks from source to auxiliary, 2. 1 disk from source to destination, 3. n−1 disks from auxiliary to destination, so that task 1 ends up on top.

void hanoi(int n) {
  Deque<Task> stack = new ArrayDeque<>();
  stack.push(new Task(n, 'A', 'B', 'C'));
  while (!stack.isEmpty()) {
    Task t = stack.pop();
    if (t.n() == 1)
      System.out.println(t.from() + " → " + t.to());
    else {                         // reverse order
      stack.push(new Task(t.n()-1, t.via(), t.from(), t.to()));
      stack.push(new Task(1, t.from(), t.via(), t.to()));
      stack.push(new Task(t.n()-1, t.from(), t.to(), t.via()));
    }
  }
}

The Stock Span Problem

  • An array holds daily closing prices.
  • The span of a day is the number of consecutive days, counting back from and including that day, whose price is less than or equal to that day's price.
  • In financial analysis it shows “for how many days” a price has not been beaten.

Stock Span

Stock Span: An O(n) Solution with a Stack

int[] span(int[] prices) {
    int[] spans = new int[prices.length];
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(0); spans[0] = 1;
    for (int i = 1; i < prices.length; i++) {
        while (!stack.isEmpty() &&
            prices[i] >= prices[stack.peek()])
            stack.pop();
        spans[i] = stack.isEmpty() ? i + 1
                              : i - stack.peek();
        stack.push(i);
    }
    return spans;
}
What is on the stack?The indices of days not yet beaten (prices decrease from bottom to top).
SpanThe top is the nearest earlier day with a higher price: span = i − top, or i + 1 if the stack is empty.
ComplexityEach index is pushed once and popped at most once → O(n).

Expression Notation

Infix, Prefix, and Postfix Notation

NotationWhere the operator goesA * (B + C) / D
Infixbetween the operandsA * ( B + C ) / D
Prefix · Polish notationbefore the operands/ * A + B C D
Postfix · reverse Polish (RPN)after the operandsA B C + * D /
  • Prefix and postfix need no parentheses and no precedence rules: a stack evaluates the expression in a single left-to-right (or right-to-left) pass.
  • Compilers and interpreters usually translate expressions into postfix form (e.g., stack-based bytecode), and some calculators use RPN.
  • They also appear in symbolic algebra and in work with expression trees.
Careful: the prefix form * A / + B C D is wrong; it means A * ((B + C) / D). The correct prefix, which keeps the left-to-right order of operations, is / * A + B C D.

Expression Notation

Precedence, Associativity, and Converting by Hand

OperatorPrecedenceAssociativity
^ (power)3right to left
* /2left to right
+ −1left to right

Equal precedence groups left to right: A − B + C = (A − B) + C → postfix A B − C +.

By hand: full parenthesization
  1. Parenthesize every operation: ((A * (B + C)) / D)
  2. Postfix: move each operator to the right of its parentheses → A B C + * D /
  3. Prefix: move each operator to the left of its parentheses → / * A + B C D
The operands (A, B, C, D) appear in the same order in all three notations; only the operators move. That makes a quick check on any conversion.

Infix → Postfix: The Algorithm

Read the input from left to right, holding operators and opening parentheses on a stack.

Token readAction
Operand (A, B, 5 …)Write it straight to the output.
(Push it.
)Pop to the output until you reach (; discard the (.
Operator opWhile the top is not ( and has precedence ≥ op, pop it to the output; then push op.
End of inputPop every remaining operator to the output.

The “≥” rule gives left-to-right associativity. For right-associative ^, pop only operators with precedence >. Time O(n).

Expression Notation

Infix → Postfix: Java

String infixToPostfix(String expr) {
  StringBuilder out = new StringBuilder();
  Deque<Character> stack = new ArrayDeque<>();
  for (char c : expr.toCharArray()) {
    if (Character.isLetterOrDigit(c)) out.append(c);
    else if (c == '(') stack.push(c);
    else if (c == ')') {
      while (stack.peek() != '(')
        out.append(stack.pop());
      stack.pop();                  // discard '('
    } else {                        // operator
      while (!stack.isEmpty() &&
          prec(stack.peek()) >= prec(c))
        out.append(stack.pop());
      stack.push(c);
    }
  }
  while (!stack.isEmpty()) out.append(stack.pop());
  return out.toString();
}
int prec(char op) {
  switch (op) {
    case '+': case '-': return 1;
    case '*': case '/': return 2;
    default: return 0;   // '('
  }
}
AssumptionsSingle-character operands, only + − * / (no ^), no spaces, and a valid expression.
Why ( → 0?An incoming operator never pops (; only ) discards it.

Expression Notation

Evaluating a Postfix Expression

  • Read left to right.
  • Number → push it.
  • Operator → pop twice, the right operand first and then the left; push the result.
  • At the end, the one item left on the stack is the answer. No parentheses or precedence → O(n).
int apply(int left, char op, int right) {
  switch (op) {
    case '+': return left + right;
    case '-': return left - right;
    case '*': return left * right;
    default:  return left / right;
  }
}
int evaluatePostfix(String expr) {
  Deque<Integer> stack = new ArrayDeque<>();
  for (char c : expr.toCharArray()) {
    if (Character.isDigit(c)) {
      stack.push(c - '0');
    } else {
      int right = stack.pop();
      int left = stack.pop();
      stack.push(apply(left, c, right));
    }
  }
  return stack.pop();
}

Assumes single-digit numbers, no spaces, and a valid expression.

Infix → Prefix Conversion

  1. Reverse the infix expression.
  2. Swap the parentheses: ( ↔ ).
  3. Run the postfix algorithm, but don't pop on equal precedence; pop only operators with precedence >.
  4. Reverse the output.
StepA * (B + C) / D
1–2. Reverse, swap parenthesesD / ( C + B ) * A
3. Postfix (no pop on equal)D C B + A * /
4. Reverse → prefix/ * A + B C D
In step 3, when * arrives, / of equal precedence is on top and is not popped. After the final reversal this preserves left associativity: first A * (B + C), then / D.
ExampleA + B * C − D / E → − + A * B C / D E
Prefix evaluationLike postfix, but read the expression right to left; the first operand popped is the left one.

Step 2: swapParens

Reversing also flips the direction of the parentheses. This method writes ) for every ( and ( for every ), leaving all other characters unchanged.

String swapParens(String s) {
  StringBuilder sb = new StringBuilder();
  for (char c : s.toCharArray()) {
    if (c == '(') sb.append(')');
    else if (c == ')') sb.append('(');
    else sb.append(c);
  }
  return sb.toString();
}

One pass over the string: O(n) time, O(n) extra memory.

Summary

Common Mistakes

pop / peek on an empty stackCall isEmpty() first; otherwise you get an exception or null, depending on the library. In bracket matching, "())" triggers exactly this bug.
Mixing up top and sizeIn an array stack, top is the index of the last item, so size = top + 1. The stack is full when top == capacity − 1.
Not clearing a popped cellIn an array of objects, skipping data[top--] = null keeps the object from being garbage-collected (a memory leak called loitering).
Operand order in postfixThe first pop is the right operand and the second the left: 5 2 − = 5 − 2 = 3, not 2 − 5.
Iteration orderA for-each over ArrayDeque goes top to bottom, but the legacy Stack goes bottom to top, so their output looks reversed.
Infinite recursionWithout a base case, frames pile up until a StackOverflowError occurs (the call stack overflows).
