Search Trees

Search Trees

  • Each node holds an item, and each item has a key.
  • Items are stored in order of their keys.
  • A search starts at the root and follows a single branch at each node.
  • The cost is proportional to the height h of the tree: O(h).
  • With n nodes, h is ≈ log2 n at best and n − 1 at worst.
The whole story of search trees: operations take O(h), so keeping h small (a balanced tree) makes them O(log n).

Search Trees

Basic Operations

SearchReturns true if the key is in the tree, false otherwise.search(root, 5) → true
InsertionAdds a new item as a leaf in the right place, preserving the order.insert(root, 7)
DeletionRemoves the item with the given key and keeps the order intact.delete(root, 40)
TraversalVisits the items in a fixed order; inorder traversal yields the keys sorted.inorder(root) → 1 2 3 4 6 8

Also: the smallest / largest key, a key's successor / predecessor, and range queries. All O(h).

Search Trees

Kinds of Search Trees

Binary search tree (BST)Each key is greater than every key in its left subtree and less than every key in its right subtree. No balance guarantee.
AVL treeAt every node the subtree heights differ by at most 1 (the balance factor). Rotations keep it balanced.
Red-black treeNode colors and a few rules cap the height at 2·log2(n+1).
Splay treeRotates each accessed node up to the root; O(log n) amortized per operation.

Search Trees

Binary Search Trees

For every node x: all keys in the left subtree < x.key < all keys in the right subtree.

  • The property covers the whole subtree, not just the children: on the right, 7 > 4 holds, but 7 cannot sit left of 6.
  • Duplicate keys are rejected or always sent to one side (say, the right).

BST Operations

Searching for a Key

  • Start at the root; if the keys are equal, we are done.
  • If smaller, continue in the left subtree; if larger, in the right.
  • Reaching null means the key is not in the tree.
boolean search(BinaryTreeNode<E> root, E data) {
    if (root == null)
        return false;            // not found
    int k = data.compareTo(root.data);
    if (k == 0)
        return true;             // found
    else if (k < 0)
        return search(root.leftChild, data);
    else
        return search(root.rightChild, data);
}
Compare objects with compareTo (or equals), not ==, which only checks whether two references are identical.

BST Operations

Inserting a Key

  • Descend as if searching; put the new leaf in the null spot where you land.
  • The new node is always a leaf; O(h).
BinaryTreeNode<E> insert(
        BinaryTreeNode<E> root, E data) {
    if (root == null)
        return new BinaryTreeNode<>(data);
    int k = data.compareTo(root.data);
    if (k < 0)
        root.leftChild = insert(root.leftChild, data);
    else if (k > 0)
        root.rightChild = insert(root.rightChild, data);
    // k == 0: key already present, skip it
    return root;
}
// usage: root = insert(root, 5);
The recursive call's result is assigned back to the child link, so the new node replaces the null link.

TreeNode successor(TreeNode root, int x) {
    TreeNode candidate = null; // smallest key above x
    while (root != null) {
        if (x < root.data) {
            candidate = root;  // root is a candidate
            root = root.left;  // smaller ones are left
        } else
            root = root.right; // keys above x are right
    }
    return candidate;
}

BST Operations

Deleting a Key: Three Cases

First find the node (O(h)). Then, by number of children:

1. LeafNo children. Set the parent's link to null.delete 70
2. One childBypass the node: link the parent straight to the only child.delete 45 · delete 60
3. Two childrenReplace the value with the inorder successor (smallest on the right) or predecessor (largest on the left).delete 40

Example tree

BST Operations

Deletion: A Leaf or One Child

Leaf: 70 has no children. Its parent, 60, sets its right link to null.

70 is gone; the rest of the tree is unchanged.

One child (left): 45 has only a left child, 42. (We start again from the original tree.)

42 takes 45's place as 40's right child: the parent links straight to its grandchild.

One child (right): 60 has only a right child, 70.

70 takes 60's place as 50's right child. The order is preserved.

BST Operations

Deletion: A Node with Two Children

Two children: 40 has a left (30) and a right (45) child, so it cannot simply be removed.

Inorder successor = smallest key in the right subtree: step to 45, then left all the way → 42.

The successor's value (42) is copied into 40's node. The old 42 is now a duplicate.

Delete the old 42 from the right subtree; the successor has no left child, so this is always Case 1 or 2.

Alternatively, use the inorder predecessor (largest key on the left = 30). Both give a valid BST.

BST Operations

The Deletion Code

BinaryTreeNode<E> delete(
        BinaryTreeNode<E> root, E data) {
    if (root == null) return null;   // not found
    int k = data.compareTo(root.data);
    if (k < 0)
        root.leftChild = delete(root.leftChild, data);
    else if (k > 0)
        root.rightChild = delete(root.rightChild, data);
    else if (root.leftChild == null)
        return root.rightChild;  // leaf / right child only
    else if (root.rightChild == null)
        return root.leftChild;   // left child only
    else {                       // two children
        root.data = minValue(root.rightChild).data;
        root.rightChild = delete(root.rightChild, root.data);
    }
    return root;
}
The return value goes into the parent's link: returning the only child or null cuts the node out. Usage: root = delete(root, 40); (if the root is deleted, this assignment installs the new one).

Analyzing BST Operations

  • Search, insertion, and deletion take time proportional to the depth of the deepest node reached: O(h).

Balanced (best)≈ log2 nO(log n)≈ 20

With random insertion order, the average depth of a node is ≈ 2 ln n ≈ 1.39 log2 n (≈ 28 steps for n = 106), while the expected height is ≈ 4.31 ln n ≈ 2.99 log2 n (≈ 60).

void range(TreeNode k, int lo, int hi) {
    if (k == null) return;
    if (lo < k.data)           // candidates on the left
        range(k.left, lo, hi);
    if (lo <= k.data && k.data <= hi)
        System.out.print(k.data + " ");
    if (k.data < hi)           // candidates on the right
        range(k.right, lo, hi);
}

boolean isBST(TreeNode k, long min, long max) {
    if (k == null) return true;
    if (k.data <= min || k.data >= max)
        return false;          // out of range
    return isBST(k.left, min, k.data)
        && isBST(k.right, k.data, max);
}

The student ID is the key; each node carries the whole student object.

BST Operations

Inserting and Finding Students

StudentNode insert(StudentNode root, Student st) {
    if (root == null) return new StudentNode(st);
    if (st.id < root.st.id)
        root.leftChild = insert(root.leftChild, st);     // continue left
    else if (st.id > root.st.id)
        root.rightChild = insert(root.rightChild, st);   // continue right
    return root;                                         // duplicate IDs are skipped
}
Student search(StudentNode root, int id) {
    if (root == null) return null;                // no such record
    if (id == root.st.id) return root.st; // found
    if (id < root.st.id)
        return search(root.leftChild, id);         // continue left
    return search(root.rightChild, id);            // continue right
}

search returns the student object, not a boolean, so a hit also gives the name and the rest of the record. With an int key, == and < work directly.

Balance and AVL Trees

Why Balance Matters

  • A BST's shape depends on the insertion order: insert 1, 2, 3, 4 in order and it becomes a linked list.
  • Arranged differently, the same keys fit in a shorter tree (two options on the right).
Self-balancing search trees repair themselves after each insertion and deletion with small local changes (rotations, recoloring), guaranteeing h = O(log n).

Balance and AVL Trees

AVL Trees

  • Adelson-Velsky and Landis (1962): the first balanced BST.
  • Balance factor: bf(x) = h(left) − h(right). An empty subtree has height −1.
  • AVL condition: bf ∈ {−1, 0, +1} at every node.
  • Consequence: h < 1.44 log2(n + 2), so every operation is O(log n).
  • Each node stores its height; after an update, bf is checked on the way back up to the root.
How to read itThe number at a node's upper right is its bf: positive means left-heavy, negative right-heavy. We rotate at the first (lowest) node with |bf| = 2.

Balance and AVL Trees

Why Is the Height of an AVL Tree O(log n)?

Question: what is the fewest nodes an AVL tree of height h can have? In the sparsest one, the two subtrees of every internal node differ in height by exactly 1.

h = 0: a single node. N(0) = 1.

h = 1: a root and one child. N(1) = 2.

h = 2: root (orange) + sparsest tree of height 1 (left) + sparsest tree of height 0 (right). N(2) = 1 + N(1) + N(0) = 1 + 2 + 1 = 4.

h = 3: root (orange) + sparsest tree of height 2 (left) + sparsest tree of height 1 (right). N(3) = 1 + N(2) + N(1) = 1 + 4 + 2 = 7.

h = 4: root (orange) + sparsest tree of height 3 (left) + sparsest tree of height 2 (right). N(4) = 1 + N(3) + N(2) = 1 + 7 + 4 = 12. The counts grow like Fibonacci numbers: N(h) = F(h+3) − 1.

N(h) = 1 + N(h−1) + N(h−2) > 2·N(h−2) → N(h) > 2h/2 → h < 2 log2 n. Fibonacci gives a tighter bound: h < 1.44 log2(n + 2).

Balance and AVL Trees

Rotation

Right rotation (y left-heavy): x moves up, y becomes x's right child, and x's right subtree T2 moves to y's left.

Left rotation (x right-heavy): the mirror image. Only 3 links change (thick lines) → O(1).

A rotation preserves the BST property (same inorder sequence) but changes subtree heights: one side loses a level, the other gains one.

Single Rotations: LL and RR

LL: 10 went to the left of the left child (20). bf(30) = 2 ✗ and bf(20) = 1: both nodes lean the same way (left).

The number at a node's upper right is its bf. LL takes a single right rotation, RR a single left rotation; the orange link is the one the rotation changes.

Double Rotations: LR and RL

LR: 20 went to the right of the left child (10). bf(30) = 2 but bf(10) = −1: opposite leans (a triangle). A single right rotation still leaves a triangle.

Rotation 1: rotate left at 10 → 20 moves up; the triangle becomes a straight line (LL). bf(30) is still 2.

Rotation 2: rotate right at 30 → the middle key, 20, becomes the root; all bf = 0.

RL: 20 went to the left of the right child (30). bf(10) = −2, bf(30) = 1: a triangle.

Rotation 1: rotate right at 30 → a straight line (RR). bf(10) is still −2.

Rotation 2: rotate left at 10 → 20 is the root; all bf = 0.

LR: rotate left at the child, then right at the unbalanced node. RL: right at the child, then left.

AVL Rotation and Rebalancing Code

int h(AvlNode d) {
    return d == null ? -1 : d.height;
}
int bf(AvlNode d) {
    return h(d.left) - h(d.right);
}
void update(AvlNode d) {
    d.height = 1 +
        Math.max(h(d.left), h(d.right));
}
AvlNode rotateRight(AvlNode y) {
    AvlNode x = y.left;
    y.left = x.right;  // T2 → y.left
    x.right = y;       // y → x.right
    update(y);         // lower node first
    update(x);
    return x;          // new root
}
AvlNode rebalance(AvlNode d) {
    update(d);
    if (bf(d) > 1) {       // left-heavy
        if (bf(d.left) < 0)   // LR
            d.left = rotateLeft(d.left);
        return rotateRight(d); // LL
    }
    if (bf(d) < -1) {      // right-heavy
        if (bf(d.right) > 0)  // RL
            d.right = rotateRight(d.right);
        return rotateLeft(d);  // RR
    }
    return d;
}
// rotateLeft: mirror image (left ↔ right)
// insert/delete as in a BST; on return:
//   return rebalance(root);

As the recursion unwinds, rebalance runs at each node on the path; a deletion may rotate at several nodes (at most O(log n)).

Red-Black Trees

Red-Black Trees

  1. Every node is red or black.
  2. The root is black.
  3. All leaves (NIL, the empty children) count as black.
  4. A red node's children are black: no two reds in a row.
  5. Every path from a node down to its NIL leaves has the same number of black nodes (the black height).

Example: every path from the root to a NIL has 2 black nodes (counting the root, not the NIL)

Red-Black Trees

Why Do the Rules Guarantee Balance?

  • Shortest path: can be all black → b nodes (10–5 in the figure: b = 2).
  • Longest path: reds cannot be adjacent, so at most one red per black → at most 2b nodes (10–20–30–40).
  • Consequence: longest path ≤ 2 × shortest path, which gives h ≤ 2·log2(n + 1).
  • Cost: search, insertion, deletion in O(log n); at most 2 rotations per insertion, 3 per deletion; the rest is recoloring.
A red-black tree is balanced more loosely than an AVL tree (it may be a bit taller), but updates are cheaper. Java's TreeMap/TreeSet and C++'s std::map use it.

Red-Black Trees

Inserting into a Red-Black Tree

Insert the new node as in a BST and color it red (leaving the black height intact). If its parent is red too, rule 4 breaks; look at the uncle (the parent's sibling):

Red uncleRecolor: parent and uncle black, grandparent red. The problem may move up → continue from the grandparent.
Black uncle, triangleIf node, parent, and grandparent zigzag, rotate at the parent → the line case.
Black uncle, lineRotate at the grandparent; the old parent becomes black and the old grandparent red. Done.
  • If the parent is black, nothing needs doing. At the end, the root is always colored black.
  • A NIL uncle counts as black.
  • Deletion is similar but has more cases (the "double black" fix).

void fixUp(Node x) {      // x: new, red
    while (x != root && isRed(x.parent)) {
        Node p = x.parent, g = p.parent;
        Node u = (p == g.left) ? g.right : g.left;
        if (isRed(u)) {                // red uncle
            p.color = u.color = BLACK;
            g.color = RED;
            x = g;                     // move up to g
        } else {                       // black uncle
            if (isTriangle(x, p, g)) { // zigzag
                rotate(p, x);          // make it a line
                Node t = x; x = p; p = t;
            }
            rotate(g, p);              // line
            p.color = BLACK; g.color = RED;
        }
    }
    root.color = BLACK;
}

Splay Trees

Splay Trees

  • Sleator and Tarjan (1985): a self-adjusting BST.
  • Every access (search, insertion, deletion) rotates the node to the root: the splay operation.
  • Nodes store no balance information (no height, no color).
  • One operation can take O(n), but any m operations take O(m log n): O(log n) amortized.
LocalityFrequently accessed keys stay near the root, so the tree acts like a cache.
SimplicityNo extra fields; one splay routine serves every operation.
DrawbackEven a search changes the tree, and a single operation has no guarantee.

Splay Trees

Splay Steps: Zig, Zig-Zig, Zig-Zag

x: the node being splayed, p: its parent, g: its grandparent. Repeat until x is the root.

Zig: x's parent p is the root → a single rotation at p. (This can only be the last step.)

Zig-zig: x and p are children on the same side → rotate at g first, then at p. (Not the same as an AVL single rotation!)

Zig-zag: x and p are on opposite sides → rotate at p, then at g (exactly an AVL double rotation).

void splay(Node x) {
    while (x != root) {
        Node p = x.parent, g = p.parent;
        if (g == null)                 // zig
            rotate(p, x);
        else if (sameSide(x, p, g)) {  // zig-zig
            rotate(g, p);   // grandparent first
            rotate(p, x);
        } else {                       // zig-zag
            rotate(p, x);   // parent first
            rotate(g, x);
        }
    }
}

Multiway Search Trees

B-Trees

  • A balanced multiway search tree whose nodes hold several keys and many children.
  • In a B-tree of order m, a node has at most m children and m − 1 keys; each non-root internal node has at least ⌈m/2⌉ children.
  • Keys within a node are sorted, and all leaves are at the same depth.
  • The height stays O(log n); insertions and deletions split or merge nodes.
Why? One node fills one disk block. Wide and shallow = few disk reads. The basis of database and file-system indexes.

A B-tree of order 4 (a 2-3-4 tree) is equivalent to a red-black tree: merge each black node with its red children and you get a 2-3-4 tree. Insertion and splitting step by step: B-tree simulator.

Multiway Search Trees

Search and Insertion in a B-Tree

1 · Search within the node. To find 30, compare it with the root's keys in order; 20 < 30 < 40 → descend to the middle child, which covers that gap.

30 is found in the leaf. Each level reads just one node (one disk block) → the cost is proportional to the height: O(logm n).

2 · Insert into the leaf. 33 follows the same path and goes into the leaf in sorted position. The leaf now holds 4 keys, over its capacity (m − 1 = 3).

3 · Split the overflow. The middle key (33) moves up to the parent; the rest split into two nodes (25 30 and 35). If the parent overflows too, splitting continues upward; if the root splits, a new root appears and the height grows by one.

When the root splitsA new root appears and the height grows by just one. All leaves remain at the same depth.
DeletionAn underfull node borrows a key from a sibling or merges with it; balance and fill limits are preserved.

Multiway Search Trees · Step by step

B-Tree Insertion and Splitting (m = 3)

Keys inserted in order: 10, 20, 30, 40, 50, 60, 70 · order m = 3 → at most 2 keys and 3 children per node.

Insert 10. It goes into the root leaf in sorted order; 1 key (≤ 2), no split.

Insert 20. It goes into the root leaf in sorted order; 2 keys (≤ 2), no split.

Insert 30 → node [10, 20, 30]: 3 keys, over capacity (m − 1 = 2) → split.

The root splits: the median 20 moves up as a new root; 10 and 30 become separate nodes. The height grows by one; all leaves stay at the same depth.

Insert 40. Go right from the root and add it to the leaf in sorted order; 2 keys (≤ 2), no split.

Insert 50 → node [30, 40, 50]: 3 keys, over capacity (m − 1 = 2) → split.

The median, 40, moves up to the parent; the rest split into two nodes, 30 and 50. The parent has room → the split stops here.

Insert 60. Go right from the root and add it to the leaf in sorted order; 2 keys (≤ 2), no split.

Insert 70 → node [50, 60, 70]: 3 keys, over capacity (m − 1 = 2) → split.

The median, 60, moves up to the parent and the node splits into 50 | 70. But the parent [20, 40, 60] now has 3 keys → the split propagates upward.

The root splits: the median 40 moves up as a new root; 20 and 60 become separate nodes. The height grows by one; all leaves stay at the same depth.

Result: 7 keys on 3 levels; every internal node has 2 children; all leaves at the same depth. A B-tree grows upward: its height increases only when the root splits.

Multiway Search Trees

B+ Trees

Data in the leavesAll keys (and records) live in the leaves; internal nodes hold only routing keys.
Linked leavesThe leaves are linked together, so range queries such as "between 20 and 50" are fast.
Wider internal nodesInternal nodes carry no records, so more keys fit in a block → a shallower tree.

Most relational database indexes are B+ trees.

Multiway Search Trees · Step by step

Range Query in a B+ Tree: 10 to 45

Start at the root: 10 < 20 → the leaf holding the lower bound 10 is under the leftmost child. (Just like a search: O(log n) levels.)

First leaf, [5 10]: skip 5 < 10 and take 10. At the end of the leaf → follow the next-leaf link (without climbing back up).

Second leaf: 20, 25, and 30 are all in range → take them. Follow the link again.

Third leaf: take 40; 50 > 45 → stop. Result: 10 20 25 30 40.

Cost: one descent, O(log n), plus the leaves read. A B-tree would have to climb up and down through internal nodes again and again; the B+ tree's leaf chain gives O(log n + k) (k: number of results).

Common Mistakes

Dropping the return valuedelete(root, 40); breaks the tree when the root is deleted. Write root = delete(root, 40); (likewise for insert).
Checking only the childrenThe BST property covers whole subtrees, so a check must pass the allowed (min, max) range down (isBST).
Comparing objects with ==That compares references. Order keys with compareTo and test equality with equals.
Wrong height-update orderAfter an AVL rotation, update the node that moved down first, then the new root; the reverse gives wrong bf values.
"A BST is always O(log n)"Wrong: sorted input gives h = n − 1. O(log n) is guaranteed only for balanced trees (AVL, red-black).
Forgetting null childrenAn empty subtree has height −1, and in a red-black tree NIL counts as black; hence helpers like h(null) and isRed(null).

Sample Problems

  1. Insert 50, 30, 70, 20, 40, 60, 80 in order into an empty BST. What is the height? What does an inorder traversal print?
  2. If the same keys arrive in the order 20, 30, 40, 50, 60, 70, 80, what are the height and the search cost?
  3. Delete the root 50 from the tree in problem 1 using the inorder successor. What does the tree look like?
  4. Insert 3, 2, 1 into an empty AVL tree. Which case arises, and which rotation fixes it?
  5. Insert 10, 30, 20 into an empty AVL tree. Which case arises, and what is the resulting tree?
  6. In a red-black tree, the longest root-to-NIL path is at most how many times the shortest? Why?
  7. In what order are the rotations done in a splay tree's zig-zig step?
Show answers
  1. h = 2 (perfectly balanced); inorder: 20 30 40 50 60 70 80.
  2. A chain to the right: h = 6; search is O(n) (7 comparisons in the worst case).
  3. The successor 60 is copied into the root; the 60 left of 70 is deleted: 60(30(20, 40), 70(—, 80)).
  4. bf = 2 at 3 and bf = 1 at its left child 2 → LL; a right rotation at 3 → 2(1, 3).
  5. bf = −2 at 10 and bf = +1 at its right child 30 → RL; right at 30, then left at 10 → 20(10, 30).
  6. Twice: every path has the same number of blacks, and reds cannot be adjacent.
  7. First at the grandparent (g), then at the parent (p).

Exercises

  1. Write floor(root, x), which returns the largest key ≤ x (or null if there is none).
  2. Write a method that finds the k-th smallest key in a BST. What is its time complexity?
  3. In what order should 1, 2, …, 7 be inserted into an empty BST to get a perfect tree of height 2?
  4. Insert 1, 2, …, 7 in order into an empty AVL tree. What is the final tree? How many rotations are done?
  5. What is the minimum number of nodes in an AVL tree of height 5?
  6. Why does range(root, lo, hi) take O(h + s) rather than O(n)?
Answers / hints
  1. Mirror successor: if x >= root.data, candidate = root; root = root.right;, else go left. O(h).
  2. An inorder traversal with a counter: the k-th node visited is the answer → O(h + k).
  3. The middle first, then the middles of the halves: e.g., 4, 2, 6, 1, 3, 5, 7.
  4. 4(2(1, 3), 6(5, 7)); inserting 3, 5, 6, and 7 each triggers one left rotation → 4 rotations.
  5. N(5) = 1 + N(4) + N(3) = 1 + 12 + 7 = 20.
  6. Left subtrees of nodes below lo and right subtrees of nodes above hi are never visited (pruning).
