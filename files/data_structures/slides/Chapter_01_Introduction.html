Introduction to Data Structures · The Java memory model

Memory in Java: Stack and Heap

  • A primitive variable holds its value directly.
  • A reference variable holds the address of an object on the heap; new creates the object.
  • Each method call gets a stack frame for its local variables, discarded on return.
  • The garbage collector reclaims unreachable objects; p[0] → NullPointerException.
int x = 5;               // primitive: the value
int[] a = {7, 2, 9};     // reference → array
String s = "data";       // reference → object
int[] p = null;          // refers to nothing

Introduction to Data Structures · Step through the code

Code Trace: Value or Reference?

x = 5: a primitive; the value lives in the frame itself.

y = x: copies the value; x and y are independent.

y = 7: only y changes; x is still 5.

The array lives on the heap; a holds only a reference to it (the arrow).

b = a: copies the reference, not the array; both arrows point to one object.

b[0] = 9: changes the object itself, so a[0] is 9 too (aliasing).

b = new int[2]: b now points to a new, zero-filled array; a is unaffected.

Output: 5 9. Rule: = copies the value of a primitive and the address of a reference.

int y = x;

Generics: One Structure for Every Type

public class Box<T> {
  private T item;
  public void put(T x) { item = x; }
  public T get() { return item; }
}

Box<String> b = new Box<>();
b.put("data");
String s = b.get();     // no cast needed
Box<Integer> m = new Box<>();
m.put(42);              // int → Integer
// m.put("x");          // COMPILE ERROR
  • Types are checked at compile time, so a wrong type never reaches run time.
  • T must be a reference type: no Box<int>; use Integer.
  • Java's collections are generic: ArrayList<E>, Map<K,V>.

Abstract Data Types vs. Data Structures

Abstract Data Type (ADT)
  • Lists, stacks, queues, sets, maps, graphs…
  • Defines which operations exist (the behavior).
  • Ignores implementation details.
Data Structure
  • Linked lists, arrays, adjacency matrices…
  • Concrete structures that implement ADTs.
  • Focus on memory and performance details.

Introduction to Data Structures

From ADT to Java: The interface

public interface Stack<E> {
  int size();         // number of elements
  boolean isEmpty();  // is it empty?
  void push(E e);     // add on top
  E top();            // return the top element
  E pop();            // remove and return the top
}
  • interface = the ADT's contract: what it does.
  • class = the data structure: how it does it.
  • One ADT, many possible implementations.
Stack<Integer> s = new ArrayStack<>(10); — to swap implementations, change only this line; client code stays the same.

Introduction to Data Structures · From ADT to data structure

One Implementation: ArrayStack

public class ArrayStack<E> implements Stack<E> {
  private E[] data;         // the elements
  private int t = -1;       // index of the top element
  public ArrayStack(int capacity) {
    data = (E[]) new Object[capacity];
  }
  public int size() { return t + 1; }
  public boolean isEmpty() { return t == -1; }
  public E top() {
    if (isEmpty()) return null;
    return data[t];
  }
  // push and pop
}
OperationTime
size, isEmpty, topO(1)
push, popO(1)
MemoryO(N) (capacity)
  • Java can't create a generic array directly, hence (E[]) new Object[..].
  • Fixed capacity: push throws once the array is full.

Introduction to Data Structures · Step through the code

Code Trace: push / pop

s is an empty ArrayStack with capacity 4 (t = −1). Call push(5).

size() = 0 ≠ 4 → not full.

++t → t = 0, then data[0] = 5. Increment first, then write.

Call push(8).

size() = 1 ≠ 4 → not full.

++t → t = 1, then data[1] = 8. Increment first, then write.

Call pop(); the result will be printed.

t = 1 → not empty; go on.

e = data[1] = 8: the most recently added element (LIFO).

Clear the cell to null so the object can be collected; t-- → t = 0.

return 8: the call's frame is removed.

8 is printed.

push(3): cell 1, now free, gets reused.

size() = 1 ≠ 4 → not full.

++t → t = 1, then data[1] = 3. Increment first, then write.

Final state: [5, 3], t = 1. Each operation takes a fixed number of steps, whatever n is → O(1).

public void push(E e) {
  if (size() == data.length)
    throw new IllegalStateException("full");
  data[++t] = e;
}
public E pop() {
  if (isEmpty()) return null;
  E e = data[t];
  data[t--] = null;     // let GC reclaim it
  return e;
}
s.push(5); s.push(8);
System.out.println(s.pop());
s.push(3);

Introduction to Data Structures

Choosing a Data Structure

A few questions drive the choice:

  • Can the structure be filled all at once, up front?
  • Will elements be deleted?
  • Does insertion order matter?
  • Can the elements be sorted?
  • Are elements processed in a fixed order, or is random access needed?
Contents won't change? Use a static structure. Frequent insertions and deletions? Use a dynamic one.

Sample Problems

  1. Which data structure fits "undo" in a text editor? Why?
  2. Which structure lets a printer print documents in the order they arrive?
  3. Which structure gives fast lookup of a student's record by student ID?
  4. How would you model a city map to find the shortest route between two points?
  5. Which structure would you use to remove duplicates from a list?
  6. In Java, is the stack ADT written as an interface or a class? Which is ArrayStack?
Show answers
  1. A stack (LIFO): the most recent action is undone first.
  2. A queue (FIFO).
  3. A map / hash table (key: student ID).
  4. A weighted graph: intersections as nodes, roads as edges, distances as weights.
  5. A set.
  6. The ADT is an interface (Stack<E>): it says what to do. ArrayStack is a class that implements it, so it is a data structure.

Summary

Exercises

  1. After int[] a = {1, 2}; int[] b = a; b[1] = 7;, what is a[1]? Why?
  2. Why doesn't Box<int> b; compile? What should you write instead?
  3. Write the character 'B' and the number 13 as 8-bit patterns.
  4. After String s = "data"; String t = s; t = t + "!";, what is s? Why?
  5. Starting from an empty ArrayStack with capacity 3, run push(1), push(2), pop(), push(3), push(4). What are t and the array at the end?
  6. A music player needs a playlist in order, a "recently played" list, and fast search by song title. Which structures fit?
Answers / hints
  1. 7: b = a copies the reference, so both variables point to the same array.
  2. T must be a reference type: write Box<Integer> (autoboxing).
  3. 'B' = 66 = 01000010; 13 = 00001101.
  4. "data": strings are immutable; t + "!" creates a new object, and only t points to it.
  5. t = 2, array [1, 3, 4]: pop returns 2, and 3 takes its place.
  6. A list (play order), a stack (most recently played on top), a map (title → song).
