Iterable Arayüzü

Hiyerarşinin en üstündedir; bir nesnenin öğeleri üzerinde gezinmeyi sağlar. Bir nesne Iterable ise:

iterator()Öğelere sırayla erişen bir Iterator alınabilir.
spliterator()Öğeleri parçalara bölerek paralel işlemeyi destekleyen bir Spliterator alınabilir.
forEach(...)Her öğe için bir işlem (lambda) çalıştırılabilir.
// yazdığımız
for (var x : a) {
    System.out.println(x);
}
// derleyicinin ürettiği (a Iterable ise)
Iterator<T> it = a.iterator();
while (it.hasNext()) {
    var x = it.next();
    System.out.println(x);
}

for-each döngüsü yalnızca a bir dizi ya da Iterable uygulayan bir sınıfın nesnesiyse derlenir. (Diziler için indisli döngüye çevrilir.)

Koleksiyon Arayüzleri · Kodu adım adım çalıştır

Kod İzleme: Kendi Iterable Sınıfımız

for (int x : new Aralik(2, 5)): önce yapıcı, aralık [2, 5).

for-each gizlice iterator() çağırır: isimsiz iç sınıf, k = bas.

hasNext(): 2 < 5 → true

next(): 2 döner, sonra k++ → 3. Gövde x = 2 yazar.

hasNext(): 3 < 5 → true

next(): 3 döner, sonra k++ → 4. Gövde x = 3 yazar.

hasNext(): 4 < 5 → true

next(): 4 döner, sonra k++ → 5. Gövde x = 4 yazar.

hasNext(): 5 < 5 → false; döngü biter.

Sözleşme: öğe yokken next() → NoSuchElementException.

class Aralik implements Iterable<Integer> {
  private final int bas, son;
  Aralik(int b, int s) { bas = b; son = s; }
  public Iterator<Integer> iterator() {
    return new Iterator<Integer>() {
      int k = bas;
      public boolean hasNext() { return k < son; }
      public Integer next() {
        if (k >= son)
          throw new NoSuchElementException();
        return k++;
      }
    };
  }
}

List Arayüzü

  • Java Collections Framework'ün üyesidir, java.util paketindedir.
  • Sıralı bir koleksiyondur (ordered collection, sequence): öğeler eklendikleri konumda kalır.
  • Öğenin nereye ekleneceğini kullanıcı belirler; öğelere tam sayı indeksiyle erişilir (0'dan başlar).
  • Tekrarlanan öğelere ve (çoğu uygulamada) null'a izin verir.
  • Liste içinde arama yapılabilir: indexOf, contains.
List bir arayüzdür, doğrudan new List() yapılamaz; onu gerçekleyen bir sınıf (ArrayList, LinkedList…) kullanılır.

Kod İzleme: subList Bir Görünümdür

5 öğeli bir ArrayList.

subList(1, 3) kopya üretmez: yalnızca başlangıç (offset) ve uzunluk tutan bir görünüm. [1, 3) → B, C.

Görünüm yazdırılırken asıl listenin 1 ve 2 indisleri okunur.

alt.set(0, …) → asıl listede l.set(offset + 0, …): l[1] = X.

alt.add("Y") görünümün sonuna, yani l'nin 3. indisine ekler; D, E sağa kayar, görünüm büyür.

alt.clear() görünümdeki 3 öğeyi (indis 1–3) asıl listeden siler…

…D, E sola kayar. l.subList(a, b).clear() bir aralığı silmenin kısa yoludur.

Sonuç [A, D, E]. Dikkat: l doğrudan yapısal değişirse (add/remove) eski alt geçersizleşir → ConcurrentModificationException.

List<String> l = new ArrayList<>(
    List.of("A", "B", "C", "D", "E"));
List<String> alt = l.subList(1, 3);
System.out.println(alt);
alt.set(0, "X");
alt.add("Y");
alt.clear();
System.out.println(l);

Liste ADT

Değiştirilebilir ve Değiştirilemez Listeler

Değiştirilebilir (mutable)Oluşturulduktan sonra öğe eklenebilir, silinebilir, değiştirilebilir.new ArrayList<>(), new LinkedList<>()
Değiştirilemez (immutable)Oluşturulduktan sonra içeriği değişmez; "değişiklik" yeni bir liste üretir.List.of(...), List.copyOf(...)
List<String> sabit = List.of("Ali", "Veli");
sabit.add("Can");    // UnsupportedOperationException
List<String> yeni = new ArrayList<>(sabit);   // değiştirilebilir kopya
yeni.add("Can");     // [Ali, Veli, Can] — sabit hâlâ [Ali, Veli]
  • Değişmezlik fonksiyonel programlamanın temel mekanizmalarındandır: paylaşım ve paralel kullanım güvenlidir.
  • Kalıcı veri yapıları (persistent data structures) değişmez yapılardır; her "güncelleme" eski sürümü korur ve değişmeyen kısımları paylaşarak tam kopyadan kaçınır.
  • Collections.unmodifiableList(l) yalnızca salt okunur bir görünümdür: alttaki l değişirse o da değişir.

Liste ADT · Kodu adım adım çalıştır

Kod İzleme: Kopya mı, Görünüm mü, Değişmez mi?

List.of değiştirilemez bir liste üretir (ve null kabul etmez).

Yorum açılsaydı: yapısal değişiklik yasak → UnsupportedOperationException (çalışma zamanı hatası, derleme değil).

new ArrayList<>(sabit) öğeleri yeni bir diziye kopyalar; artık iki ayrı nesne var.

Kopya değiştirilebilir: Can eklenir. sabit hâlâ [Ali, Veli].

unmodifiableList kopyalamaz: yeni'yi saran, yazmayı reddeden bir görünüm döndürür.

Yorum açılsaydı: görünüm üzerinden yazmak yasak → UnsupportedOperationException.

Ama alttaki yeni değişebilir: görünüm aynı diziye baktığından değişikliği görür.

Salt okunur ≠ değişmez. Gerçek değişmezlik için List.copyOf(yeni) kullanılır.

List<String> sabit = List.of("Ali", "Veli");
// sabit.add("Can");     → hata
List<String> yeni = new ArrayList<>(sabit);
yeni.add("Can");
List<String> gorunum =
    Collections.unmodifiableList(yeni);
// gorunum.set(0, "Ece"); → hata
yeni.set(0, "Ece");
System.out.println(gorunum);

Tuzak: remove(int) mi, remove(Object) mu?

Liste Integer tuttuğunda iki metot karışabilir: int argüman indeks olarak yorumlanır.

List<Integer> sayilar = new ArrayList<>(List.of(10, 20, 30));
sayilar.remove(1);                    // indeks 1 silinir → [10, 30]
sayilar.remove(Integer.valueOf(10));  // 10 değeri silinir → [30]
sayilar.remove(Integer.valueOf(99));  // yok → false, liste değişmez
sayilar.remove(5);                    // IndexOutOfBoundsException
remove(int index)Silinen öğeyi döndürür.E remove(int)
remove(Object o)Silindi mi, onu döndürür.boolean remove(Object)
Maliyetİkisi de dizi tabanlı listede sonraki öğeleri kaydırır.O(n)

List Metotları · Kodu adım adım çalıştır

Kod İzleme: Hangi remove Çağrılıyor?

[10, 20, 30]. List<Integer>'da iki remove aşırı yüklemesi (overload) de uygulanabilir.

Argüman int: derleyici kutulama gerektirmeyen remove(int index)'i seçer. Silinecek: indis 1.

30 bir sola kayar; silinen öğe döndürülür: a = 20.

Integer argüman → remove(Object o): değer aranır. Integer.valueOf(10).equals(10) → eşleşme indis 0'da.

İlk eşleşme silinir, 30 kayar; dönüş boolean: b = true.

99 aranır: 30 ≠ 99, liste bitti → bulunamadı, liste değişmez, c = false.

remove(5): indis kontrolü 5 < size (1) başarısız → IndexOutOfBoundsException: "Index 5 out of bounds for length 1".

List<Integer> sayilar =
    new ArrayList<>(List.of(10, 20, 30));
Integer a = sayilar.remove(1);
boolean b = sayilar.remove(Integer.valueOf(10));
boolean c = sayilar.remove(Integer.valueOf(99));
sayilar.remove(5);   // IndexOutOfBoundsException

Gezinme · Kodu adım adım çalıştır

Kod İzleme: LinkedList'te İndisli Döngünün Bedeli

6 düğümlü çift yönlü bağlı liste.

adim: get'lerin toplam kaç bağlantı yürüdüğünü sayacak.

get(0): 0 < n/2 = 3 → baştan (first) yürür, 0 bağlantı. Toplam 0.

get(1): 1 < n/2 = 3 → baştan (first) yürür, 1 bağlantı. Toplam 1.

get(2): 2 < n/2 = 3 → baştan (first) yürür, 2 bağlantı. Toplam 3.

get(3): 3 ≥ n/2 = 3 → sondan (last) yürür, 2 bağlantı. Toplam 5.

get(4): 4 ≥ n/2 = 3 → sondan (last) yürür, 1 bağlantı. Toplam 6.

get(5): 5 ≥ n/2 = 3 → sondan (last) yürür, 0 bağlantı. Toplam 6.

Toplam 6 ≈ n²/4 → O(n²). Iterator ise her next()'te 1 bağlantı: toplam n − 1 = 5 → O(n).

List<String> list = new LinkedList<>(
    List.of("A", "B", "C", "D", "E", "F"));
int n = list.size(), adim = 0;
for (int i = 0; i < n; i++) {
  String s = list.get(i);  // node(i) yürür
  adim += Math.min(i, n - 1 - i);
}
System.out.println(adim);

ArrayList: Büyüyebilen Dizi

  • Öğeleri içeride bir dizide tutar. Kapasite (dizinin boyu) ≥ size (öğe sayısı).
  • Dizi dolunca ~1,5 kat büyük yeni bir dizi oluşturulur ve öğeler kopyalanır (O(n)). Bu seyrek olduğundan sona ekleme amortize O(1)'dir.
  • Silmede kendiliğinden küçülmez; trimToSize() ile kapasite size'a indirilebilir.

Gerçek Java: boş new ArrayList<>() ilk eklemede 10 kapasite alır; yeni kapasite = eski + eski/2. Demoda 4'ten başlanıyor.

Kapasite 4, boyut 3 (demo; gerçek Java boş listede ilk eklemede 10 ile başlar). Sırayla D, E, F, G eklenecek.

Amortize Analiz: Neden Katlayarak Büyütülür?

  • Katlayarak büyütme (×2): n eklemede kopyalar 4 + 8 + 16 + … < 2n → işlem başına amortize O(1).
  • Java'nın ×1,5'i de geometrik büyümedir: toplam ≤ 3n, yine O(1) amortize.
  • Sabit artış (+c): kopyalar c + 2c + 3c + … ≈ n²/(2c) → işlem başına O(n).
  • Goodrich–Tamassia: "bankacı" yöntemi: her ucuz eklemeye birkaç "jeton" yatırılır, pahalı büyütmeyi o jetonlar öder.

Grafik, kapasite 4'ten başlayan bir dinamik dizide 40 ekleme için gerçekten sayılmış kopyalardır.

Kod İzleme: LinkedList addLast(e)

Boş LinkedList. addLast("A"), sonra addLast("B") (Java'daki linkLast ile aynı mantık).

l = last = null: eski son düğüm saklanır.

Yeni düğüm: onceki = l (null), sonraki = null.

last = d.

l == null (liste boştu) → first = d: tek düğüm hem ilk hem son.

void addLast(E e) {
  Dugum<E> l = last;
  Dugum<E> d = new Dugum<>(l, e, null);
  last = d;
  if (l == null) first = d;
  else l.sonraki = d;
  size++;
}

Kod İzleme: LinkedList remove(i)

[A, B, C]. remove(1): B'yi bulmak için önce yürümek gerekir.

0 ≤ 1 < 3 → geçerli indis.

x = first (A). Dizideki gibi doğrudan indisle erişim yok.

k = 0 < 1: x = x.sonraki → B.

k = 1 < 1 değil → yürüme biter. i adım yürüdük: O(i). (Java, i > size/2 ise last'tan geriye yürür.)

o = x.onceki = A, s = x.sonraki = C: silinecek düğümün iki komşusu.

o null değil → o.sonraki = s: A artık doğrudan C'yi gösterir (B atlanır).

s null değil → s.onceki = o: C geriye A'yı gösterir. B iki yönden de koptu.

E remove(int i) {
  Objects.checkIndex(i, size);
  Dugum<E> x = first;
  for (int k = 0; k < i; k++) x = x.sonraki;
  Dugum<E> o = x.onceki, s = x.sonraki;
  if (o == null) first = s; else o.sonraki = s;
  if (s == null) last = o; else s.onceki = o;
  size--;
  return x.veri;
}

Kod İzleme: Konumsal Liste addAfter(p, e)

header ⇄ A ⇄ C ⇄ trailer; p, A'nın konumu. addAfter(p, "B") çağrılıyor.

validate(p): p bu listenin geçerli bir düğümü mü? Evet → Dugum'e dönüştürülür.

Komşular belli: o = A, s = A.sonraki = C. İş addBetween'e devredilir.

Yeni düğüm iki komşusunu gösterir; ama henüz kimse onu göstermiyor.

o.sonraki = yeni: ileri yönde A → B → C.

s.onceki = yeni: geri yönde C → B → A. Eski A ⇄ C bağlantıları kalmadı.

size++. Yürüme, kaydırma yok: 4 atama → O(1).

Yeni öğenin konumu döner; ileride addBefore, remove için kullanılabilir.

Position<E> addAfter(Position<E> p, E e) {
  Dugum<E> d = validate(p);
  return addBetween(e, d, d.sonraki);
}
Position<E> addBetween(E e, Dugum<E> o, Dugum<E> s) {
  Dugum<E> yeni = new Dugum<>(o, e, s);
  o.sonraki = yeni;
  s.onceki = yeni;
  size++;
  return yeni;
}

Liste Uygulamaları

Bellekte ArrayList ve LinkedList

ArrayList

Öğe başına ~1 referans (4–8 bayt) + boş kapasite. Ardışık dizi: işlemci önbelleği (cache) sıradaki öğeleri önceden getirir.

LinkedList

Öğe başına bir düğüm nesnesi: nesne başlığı + 3 referans (~24–40 bayt). Her sonraki izlemesi önbellek ıskası olabilir.

Liste Uygulamaları

Vector

  • ArrayList gibi büyüyebilen bir dizidir; öğelere indeksle erişilir, ihtiyaca göre büyür (varsayılan: kapasite iki katına çıkar).
  • Metotları synchronized'dır: tek tek işlemler çok iş parçacıklı ortamda güvenlidir.
  • Bedeli: tek iş parçacığında bile her çağrıda kilit maliyeti.
  • "Kontrol et, sonra yap" gibi bileşik işlemler yine de atomik değildir.
Vector<Integer> v = new Vector<>();
v.add(10);            // [10]
v.add(20);            // [10, 20]
v.get(0);             // 10
v.remove(0);          // [20]
v.size();             // 1
v.capacity();         // 10

// bileşik işlem: dışarıdan kilit gerekir
synchronized (v) {
    if (!v.isEmpty()) v.remove(0);
}
Vector Java 1.0'dan kalma eski (legacy) bir sınıftır. Yeni kodda tek iş parçacığı için ArrayList; çok iş parçacığı için Collections.synchronizedList ya da CopyOnWriteArrayList tercih edilir.

Liste Uygulamaları

Vector: "Kontrol Et, Sonra Yap" Yarışı

Vector'ın her metodu synchronized: iki çağrının arası ise korunmasızdır. İki iş parçacığının olası bir sıralanışı:

Başlangıç: v = [20]. İki iş parçacığı da if (!v.isEmpty()) v.remove(0); çalıştıracak.

T1: isEmpty() kilidi alır, false döner, kilidi bırakır.

T2 araya girer: v hâlâ 1 öğeli, o da false görür. İkisi de silebileceğini sanıyor.

T1: remove(0) → 20. v artık boş.

T2: remove(0) boş vektörde → ArrayIndexOutOfBoundsException. Her metot tek tek senkronize, ama ikisi birlikte atomik değil.

Çözüm: bileşik işlemi synchronized (v) { … } ile tek kilide al. T2, T1 bloğu bitirene kadar bekler.

T2 kilidi alınca v'yi boş görür ve silmez: "kontrol et, sonra yap" artık güvenli.

  • İşlemler yığının üstündeki öğeyi etkiler; geri al / yinele (undo/redo) için kullanışlıdır.

CopyOnWriteArrayList: Yazarken Kopyala

  • Değişiklik (add, set, remove) yapılacağında iç dizi kopyalanır, işlem kopyada yapılır, sonra liste yeni diziyi gösterir.
  • Okumalar kilitsizdir ve çok hızlıdır; yazmalar kısa bir kilitle sıraya girer ve O(n) kopya maliyeti taşır.

Okuyucular iç diziyi kilitsiz okur; iterator, oluşturulduğu andaki diziyi (anlık görüntü) gezer.

add("d"): yazar kilidi alır, diziyi kopyalar ve yeni öğeyi kopyaya ekler → O(n)

Liste referansı yeni diziye döner. Eski iterator A'yı gezmeye devam eder: ConcurrentModificationException olmaz.

UygunSık gezilen, nadiren değişen listeler: olay dinleyicileri (listener), yapılandırma.
Uygun değilBüyük ve sık değişen listeler: her yazma tüm diziyi kopyalar. it.remove() desteklenmez.

Liste Uygulamaları · Kodu adım adım çalıştır

Kod İzleme: CopyOnWriteArrayList add(e)

Liste A = [a, b, c]'yi gösteriyor. Bir okuyucu iterator A üzerinde gezinmiş, "a"yı okumuş (cursor 1). Şimdi add("d").

Yazarlar kilidi alır: aynı anda iki yazar birbirinin kopyasını ezemez. Okuyucular kilit beklemez.

eski = dizi: o anki dizi A.

n = 3.

Arrays.copyOf(eski, 4): tüm öğeler yeni diziye kopyalanır → O(n). A'ya dokunulmaz.

yeni[3] = "d": değişiklik yalnızca kopyada yapılır.

dizi = yeni: tek bir referans ataması; liste artık B'yi gösterir. Okuyucu hâlâ A'da.

true döner, kilit bırakılır.

Okuyucu it.next() → "b", sonra "c": anlık görüntüsünü (A) gezer, "d"yi görmez, ConcurrentModificationException da olmaz.

Yeni bir iterator() B'yi görür: [a, b, c, d]. Hiçbir iterator'ı gösterilmeyen A'yı çöp toplayıcı temizler.

public boolean add(E e) {
  synchronized (kilit) {
    Object[] eski = dizi;
    int n = eski.length;
    Object[] yeni = Arrays.copyOf(eski, n + 1);
    yeni[n] = e;
    dizi = yeni;       // tek referans ataması
    return true;
  }
}

Arrays.asList(): Diziden Liste Görünümü

  • Verilen diziyi List arayüzüyle kullanılabilir kılar; veri kopyalanmaz, dizi ile liste aynı belleği paylaşır.
  • Liste sabit boyutludur ama değiştirilemez değildir: set çalışır (ve diziye yansır), add/remove çalışmaz.
String[] dizi = {"a", "b", "c"};
List<String> liste = Arrays.asList(dizi);
liste.set(0, "x");     // çalışır: dizi[0] de artık "x"
dizi[2] = "z";          // liste de değişir → [x, b, z]
liste.add("d");         // UnsupportedOperationException (boyut sabit)
List<String> esnek = new ArrayList<>(Arrays.asList(dizi));   // bağımsız kopya

Kod İzleme: Arrays.asList Görünümü

3 elemanlı dizi.

Arrays.asList kopyalamaz: dönen liste aynı diziyi saran bir görünümdür → O(1).

liste.set(0, "x") diziye yazar: dizi[0] da x.

Ters yön de geçerli: diziye yazmak listeyi değiştirir.

Yorum açılsaydı: dizinin boyu değişemeyeceğinden add/remove → UnsupportedOperationException.

Bağımsız ve büyüyebilen liste için kopyala: new ArrayList<>(liste) yeni dizi ayırır.

Kopyaya ekleme serbest; dizi ve liste etkilenmez.

Sonuç iki ayrı liste.

String[] dizi = {"a", "b", "c"};
List<String> liste = Arrays.asList(dizi);
liste.set(0, "x");
dizi[2] = "z";
// liste.add("d");  → hata (sabit boyut)
List<String> esnek = new ArrayList<>(liste);
esnek.add("d");
System.out.println(liste + " " + esnek);

Özet

Örnek Problemler

  1. List<Integer> l = new ArrayList<>(List.of(5, 6, 7)); l.remove(1); sonrası liste nedir?
  2. Bir LinkedList'i for (int i…) get(i) ile gezmenin karmaşıklığı nedir? Daha iyisi?
  3. Kapasitesi 10 ve 10 öğesi olan ArrayList'e bir öğe eklenince ne olur?
  4. Arrays.asList(dizi).add(x) neden hata verir? set neden vermez?
  5. Sık okunan, nadiren değişen ve birçok iş parçacığının paylaştığı bir dinleyici listesi için hangi sınıf?
  6. [A, B, C] üzerinde it = listIterator(); it.next(); it.add("X"); sonrası liste ve it.next()?
Cevapları göster
  1. [5, 7]: int argüman indeks sayılır (remove(int)).
  2. O(n²); for-each ya da Iterator ile O(n).
  3. ~1,5 kat (15) kapasiteli yeni dizi oluşturulur, 10 öğe kopyalanır, sonra eklenir (bu adım O(n), ortalama amortize O(1)).
  4. Liste diziye bağlı ve sabit boyutlu; set boyutu değiştirmez, diziye yazar.
  5. CopyOnWriteArrayList.
  6. [A, X, B, C]; it.next() → "B" (add imlecin önüne ekler).

Özet

Alıştırmalar

  1. l = [A, B, C, D]; l.subList(1, 3).clear(); sonrası l? Sonra l.add("E") yapılıp eski görünüm okunursa?
  2. Kapasitesi her dolduğunda 2 artırılan dinamik diziye n ekleme toplam kaç kopya yapar?
  3. Aralik.next(), k >= son denetimini yapmasaydı hangi sözleşme bozulurdu?
  4. Konumsal listede remove(p) neden O(1), LinkedList.remove(int) neden O(n)?
  5. l = new ArrayList<>(List.of(3, 1, 2)); l.remove(Integer.valueOf(1)); l.remove(1); → l?
Cevaplar / ipuçları
  1. [A, D]. l doğrudan değişince eski görünüm geçersizleşir → ConcurrentModificationException.
  2. 2 + 4 + 6 + … ≈ n²/4 → toplam O(n²), işlem başına O(n): sabit artış amortize O(1) vermez.
  3. Öğe yokken NoSuchElementException fırlatma sözleşmesi; aralık dışı değer dönerdi.
  4. Konum düğümün kendisidir (4 bağlantı ataması); indisle silmede önce i. düğüme yürünür.
  5. [3, 2], sonra remove(1) indis siler → [3].
