Koleksiyon Arayüzleri

Iterable Arayüzü

Hiyerarşinin en üstündedir; bir nesnenin öğeleri üzerinde gezinmeyi sağlar. Bir nesne Iterable ise:

iterator()Öğelere sırayla erişen bir Iterator alınabilir.
spliterator()Öğeleri parçalara bölerek paralel işlemeyi destekleyen bir Spliterator alınabilir.
forEach(...)Her öğe için bir işlem (lambda) çalıştırılabilir.
// yazdığımız
for (var x : a) {
    System.out.println(x);
}
// derleyicinin ürettiği (a Iterable ise)
Iterator<T> it = a.iterator();
while (it.hasNext()) {
    var x = it.next();
    System.out.println(x);
}

for-each döngüsü yalnızca a bir dizi ya da Iterable uygulayan bir sınıfın nesnesiyse derlenir. (Diziler için indisli döngüye çevrilir.)

List Arayüzü

  • Java Collections Framework'ün üyesidir, java.util paketindedir.
  • Sıralı bir koleksiyondur (ordered collection, sequence): öğeler eklendikleri konumda kalır.
  • Öğenin nereye ekleneceğini kullanıcı belirler; öğelere tam sayı indeksiyle erişilir (0'dan başlar).
  • Tekrarlanan öğelere ve (çoğu uygulamada) null'a izin verir.
  • Liste içinde arama yapılabilir: indexOf, contains.
List bir arayüzdür, doğrudan new List() yapılamaz; onu gerçekleyen bir sınıf (ArrayList, LinkedList…) kullanılır.

Liste ADT

Değiştirilebilir ve Değiştirilemez Listeler

Değiştirilebilir (mutable)Oluşturulduktan sonra öğe eklenebilir, silinebilir, değiştirilebilir.new ArrayList<>(), new LinkedList<>()
Değiştirilemez (immutable)Oluşturulduktan sonra içeriği değişmez; "değişiklik" yeni bir liste üretir.List.of(...), List.copyOf(...)
List<String> sabit = List.of("Ali", "Veli");
sabit.add("Can");    // UnsupportedOperationException
List<String> yeni = new ArrayList<>(sabit);   // değiştirilebilir kopya
yeni.add("Can");     // [Ali, Veli, Can] — sabit hâlâ [Ali, Veli]
  • Değişmezlik fonksiyonel programlamanın temel mekanizmalarındandır: paylaşım ve paralel kullanım güvenlidir.
  • Kalıcı veri yapıları (persistent data structures) değişmez yapılardır; her "güncelleme" eski sürümü korur ve değişmeyen kısımları paylaşarak tam kopyadan kaçınır.
  • Collections.unmodifiableList(l) yalnızca salt okunur bir görünümdür: alttaki l değişirse o da değişir.

    public static void main(String[] args) {
        List<String> isimler = new ArrayList<>();

Tuzak: remove(int) mi, remove(Object) mu?

Liste Integer tuttuğunda iki metot karışabilir: int argüman indeks olarak yorumlanır.

List<Integer> sayilar = new ArrayList<>(List.of(10, 20, 30));

sayilar.remove(Integer.valueOf(10));  // 10 değeri silinir → [30]
sayilar.remove(Integer.valueOf(99));  // yok → false, liste değişmez
sayilar.remove(5);                    // IndexOutOfBoundsException

Gezerken Silme: ConcurrentModificationException

Yanlış 
for (String s : isimler)
    if (s.startsWith("A"))
        isimler.remove(s);
// ConcurrentModification-
// Exception (fail-fast)
Doğru 
Iterator<String> it =
        isimler.iterator();
while (it.hasNext())
    if (it.next().startsWith("A"))
        it.remove();
// ya da kısaca:
isimler.removeIf(s -> s.startsWith("A"));
  • for-each gizlice bir Iterator kullanır; liste iterator dışından değiştirilirse sonraki next() hatayı fark eder ve durur (fail-fast).
  • it.remove(), next()'ten sonra yalnızca bir kez çağrılabilir; aksi hâlde IllegalStateException.

Gezinme · Kodu adım adım çalıştır

Kod İzleme: ConcurrentModificationException

Boş ArrayList. Her yapısal değişiklik (ekleme/silme) listenin modCount sayacını artırır.

İki add → modCount = 2.

modCount = 3. Şimdi for-each döngüsünün derleyicinin ürettiği hâlini izleyelim.

iterator(): imleç 0; iterator o anki sayacı expectedModCount = 3 olarak saklar.

hasNext(): cursor 0 ≠ size 3 → true.

next(): önce modCount == expectedModCount mu? 3 == 3 ✓ → "Ali", cursor = 1.

"Ali" A ile başlıyor → true.

isimler.remove(s): listeden doğrudan silinir → öğeler sola kayar, modCount = 4. Iterator bundan habersiz (expected hâlâ 3).

hasNext(): cursor 1 ≠ size 2 → true. ("Can" imlecin gerisinde kaldı; hiç gezilmeyecekti!)

next(): modCount 4 ≠ expectedModCount 3 → ConcurrentModificationException. Iterator değişikliği hemen fark edip durur (fail-fast).

List<String> isimler = new ArrayList<>();
isimler.add("Ali"); isimler.add("Can");
isimler.add("Ayşe");            // modCount = 3
// for (String s : isimler) ... derleyici:
Iterator<String> it = isimler.iterator();
while (it.hasNext()) {
  String s = it.next();
  if (s.startsWith("A"))
    isimler.remove(s);          // it dışından!
}

Gezinme · Kodu adım adım çalıştır

Kod İzleme: it.remove() ile Güvenli Silme

Aynı liste [Ali, Can, Ayşe], modCount = 3. Iterator: cursor = 0, lastRet = −1 (henüz öğe döndürmedi).

hasNext(): cursor 0 ≠ size 3 → true.

next(): 3 == 3 ✓ → "Ali"; cursor = 1, lastRet = 0.

"Ali" A ile başlıyor mu? evet.

it.remove(): lastRet'teki öğe silinir; cursor = 0 (kayan öğe atlanmaz), lastRet = −1, expectedModCount = modCount = 4.

hasNext(): cursor 0 ≠ size 2 → true.

next(): 4 == 4 ✓ → "Can"; cursor = 1, lastRet = 0.

"Can" A ile başlıyor mu? hayır.

hasNext(): cursor 1 ≠ size 2 → true.

next(): 4 == 4 ✓ → "Ayşe"; cursor = 2, lastRet = 1.

"Ayşe" A ile başlıyor mu? evet.

it.remove(): lastRet'teki öğe silinir; cursor = 1 (kayan öğe atlanmaz), lastRet = −1, expectedModCount = modCount = 5.

hasNext(): cursor 1 = size 1 → false. Döngü biter; hata yok.

Sonuç [Can]: A ile başlayanlar güvenle silindi. İkinci bir it.remove() (araya next olmadan) → IllegalStateException.

Iterator<String> it = isimler.iterator();
while (it.hasNext()) {
  String s = it.next();
  if (s.startsWith("A"))
    it.remove();   // sayaçları eşitler
}
System.out.println(isimler);

ListIterator Arayüzü

Yalnızca List'lerde bulunur (list.listIterator()). Iterator'a ek olarak iki yönde gezinir ve gezinirken ekleme, silme, güncelleme yapar. İmleç (cursor) öğelerin arasında durur.

MetotGörevi
hasNext() / next()ileride öğe var mı? / sonraki öğeyi döndür, imleci ileri al
hasPrevious() / previous()geride öğe var mı? / önceki öğeyi döndür, imleci geri al
nextIndex() / previousIndex()next() / previous() çağrılsa dönecek öğenin indeksi (başta 0 / −1)
add(e)öğeyi imlecin önüne ekler (sonraki next() etkilenmez)
remove()son next()/previous() ile dönen öğeyi siler
set(e)son next()/previous() ile dönen öğeyi değiştirir

add veya remove'dan hemen sonra, araya yeni bir next/previous girmeden remove/set çağrılırsa → IllegalStateException.

Gezinme · Kodu adım adım çalıştır

Kod İzleme: ListIterator Adım Adım

listIterator(): imleç başta; nextIndex = 0, previousIndex = −1. Turuncu: son döndürülen (lastRet) öğe.

next() → "Ali"; imleç bir ileri, lastRet = 0.

next() → "Ahmet"; lastRet = 1.

set("AHMET"): lastRet'teki öğe ("Ahmet") değişir; imleç yerinde kalır.

add("Ayşe"): imlecin önüne eklenir, imleç eklenenin arkasına geçer (sonraki next yine "Mehmet"); lastRet = −1.

previous() → "Ayşe": geri yönde; imleç bir geri, lastRet = 2.

remove(): lastRet'teki "Ayşe" silinir; lastRet = −1 (hemen ikinci remove/set → IllegalStateException).

ListIterator<String> it = isimler.listIterator();
it.next();          // "Ali"
it.next();          // "Ahmet"
it.set("AHMET");    // [Ali, AHMET, Mehmet]
it.add("Ayşe");     // [Ali, AHMET, Ayşe, Mehmet]
it.previous();      // "Ayşe"
it.remove();        // [Ali, AHMET, Mehmet]

Liste Uygulamaları

ArrayList: Büyüyebilen Dizi

  • Öğeleri içeride bir dizide tutar. Kapasite (dizinin boyu) ≥ size (öğe sayısı).
  • Dizi dolunca ~1,5 kat büyük yeni bir dizi oluşturulur ve öğeler kopyalanır (O(n)). Bu seyrek olduğundan sona ekleme amortize O(1)'dir.
  • Silmede kendiliğinden küçülmez; trimToSize() ile kapasite size'a indirilebilir.

Gerçek Java: boş new ArrayList<>() ilk eklemede 10 kapasite alır; yeni kapasite = eski + eski/2. Demoda 4'ten başlanıyor.

Kod İzleme: ArrayList add(e) ve Büyüme

Kapasite 4, boyut 3 (demo; gerçek Java boş listede ilk eklemede 10 ile başlar). Sırayla D, E, F, G eklenecek.

add(D): boyut 3 == kapasite 4? hayır.

dizi[3] = D, boyut = 4; true döner.

add(E): boyut 4 == kapasite 4? evet → dizi dolu.

yeni = 4 + 4 / 2 = 6: yaklaşık 1,5 kat (Java: eski + eski >> 1).

Arrays.copyOf: 6 yuvalı yeni dizi, 4 öğe tek tek kopyalanır → bu ekleme O(n). Eski dizi çöpe gider.

dizi[4] = E, boyut = 5; true döner.

add(F): boyut 5 == kapasite 6? hayır.

dizi[5] = F, boyut = 6; true döner.

add(G): boyut 6 == kapasite 6? evet → dizi dolu.

yeni = 6 + 6 / 2 = 9: yaklaşık 1,5 kat (Java: eski + eski >> 1).

Arrays.copyOf: 9 yuvalı yeni dizi, 6 öğe tek tek kopyalanır → bu ekleme O(n). Eski dizi çöpe gider.

dizi[6] = G, boyut = 7; true döner. Kapasite her seferinde 1,5 katına çıktığından büyütmeler giderek seyrekleşir: n eklemede toplam kopya O(n) → ekleme amortize O(1).

public boolean add(E e) {
  if (boyut == dizi.length) {
    int yeni = dizi.length + dizi.length / 2;
    dizi = Arrays.copyOf(dizi, yeni);

  dizi[boyut++] = e;

eski = dizi[1] = X (döndürülecek).

public E remove(int i) {

  E eski = dizi[i];
  for (int k = i; k < boyut - 1; k++)

  dizi[--boyut] = null;

LinkedList: Çift Yönlü Bağlı Liste

  • Öğeler bellekte ardışık değildir: her öğe ayrı bir düğüm (node) nesnesidir.
  • Her düğüm veriyi ve önceki / sonraki düğümlerin referansını tutar; liste first ve last'ı bilir.
  • List'in yanında Deque arayüzünü de uygular: yığın ve kuyruk olarak kullanılabilir (Bölüm 4–5).
  • Rastgele erişim yavaştır: get(i) düğümleri tek tek yürür (yakın uçtan başlar) → O(n).

Kod İzleme: LinkedList addLast(e)

Boş LinkedList. addLast("A"), sonra addLast("B") (Java'daki linkLast ile aynı mantık).

l = last = null: eski son düğüm saklanır.

Yeni düğüm: onceki = l (null), sonraki = null.

last = d.

l == null (liste boştu) → first = d: tek düğüm hem ilk hem son.

size = 1.

Yeni düğüm: onceki = l (düğüm(A)), sonraki = null. Geri bağlantı kurulurken hazır.

last = d.

l == null değil → else.

l.sonraki = d: A → B ileri bağlantısı.

size = 2. Dolaşma yok: sona ekleme O(1).

void addLast(E e) {
  Dugum<E> l = last;
  Dugum<E> d = new Dugum<>(l, e, null);
  last = d;
  if (l == null) first = d;
  else l.sonraki = d;
  size++;
}

Kod İzleme: LinkedList remove(i)

[A, B, C]. remove(1): B'yi bulmak için önce yürümek gerekir.

0 ≤ 1 < 3 → geçerli indis.

x = first (A). Dizideki gibi doğrudan indisle erişim yok.

k = 0 < 1: x = x.sonraki → B.

k = 1 < 1 değil → yürüme biter. i adım yürüdük: O(i). (Java, i > size/2 ise last'tan geriye yürür.)

o = x.onceki = A, s = x.sonraki = C: silinecek düğümün iki komşusu.

o null değil → o.sonraki = s: A artık doğrudan C'yi gösterir (B atlanır).

s null değil → s.onceki = o: C geriye A'yı gösterir. B iki yönden de koptu.

size = 2.

return "B". Bağ değiştirmek O(1), ama yürümek O(n) → remove(i) toplamda O(n).

E remove(int i) {
  Objects.checkIndex(i, size);
  Dugum<E> x = first;
  for (int k = 0; k < i; k++) x = x.sonraki;
  Dugum<E> o = x.onceki, s = x.sonraki;
  if (o == null) first = s; else o.sonraki = s;
  if (s == null) last = o; else s.onceki = o;
  size--;
  return x.veri;
}

Vector

  • ArrayList gibi büyüyebilen bir dizidir; öğelere indeksle erişilir, ihtiyaca göre büyür (varsayılan: kapasite iki katına çıkar).
  • Metotları synchronized'dır: tek tek işlemler çok iş parçacıklı ortamda güvenlidir.
  • Bedeli: tek iş parçacığında bile her çağrıda kilit maliyeti.
  • "Kontrol et, sonra yap" gibi bileşik işlemler yine de atomik değildir.
Vector<Integer> v = new Vector<>();
v.add(10);            // [10]
v.add(20);            // [10, 20]
v.get(0);             // 10
v.remove(0);          // [20]
v.size();             // 1
v.capacity();         // 10

// bileşik işlem: dışarıdan kilit gerekir
synchronized (v) {
    if (!v.isEmpty()) v.remove(0);
}
Vector Java 1.0'dan kalma eski (legacy) bir sınıftır. Yeni kodda tek iş parçacığı için ArrayList; çok iş parçacığı için Collections.synchronizedList ya da CopyOnWriteArrayList tercih edilir.

CopyOnWriteArrayList: Yazarken Kopyala

  • Değişiklik (add, set, remove) yapılacağında iç dizi kopyalanır, işlem kopyada yapılır, sonra liste yeni diziyi gösterir.
  • Okumalar kilitsizdir ve çok hızlıdır; yazmalar kısa bir kilitle sıraya girer ve O(n) kopya maliyeti taşır.

Okuyucular iç diziyi kilitsiz okur; iterator, oluşturulduğu andaki diziyi (anlık görüntü) gezer.

add("d"): yazar kilidi alır, diziyi kopyalar ve yeni öğeyi kopyaya ekler → O(n)

Liste referansı yeni diziye döner. Eski iterator A'yı gezmeye devam eder: ConcurrentModificationException olmaz.

UygunSık gezilen, nadiren değişen listeler: olay dinleyicileri (listener), yapılandırma.
Uygun değilBüyük ve sık değişen listeler: her yazma tüm diziyi kopyalar. it.remove() desteklenmez.

eski = dizi: o anki dizi A.

n = 3.

true döner, kilit bırakılır.

Örnek Problemler

  1. List<Integer> l = new ArrayList<>(List.of(5, 6, 7)); l.remove(1); sonrası liste nedir?
  2. Bir LinkedList'i for (int i…) get(i) ile gezmenin karmaşıklığı nedir? Daha iyisi?
  3. Kapasitesi 10 ve 10 öğesi olan ArrayList'e bir öğe eklenince ne olur?
  4. Arrays.asList(dizi).add(x) neden hata verir? set neden vermez?
  5. Sık okunan, nadiren değişen ve birçok iş parçacığının paylaştığı bir dinleyici listesi için hangi sınıf?
  6. [A, B, C] üzerinde it = listIterator(); it.next(); it.add("X"); sonrası liste ve it.next()?
Cevapları göster
  1. [5, 7]: int argüman indeks sayılır (remove(int)).
  2. O(n²); for-each ya da Iterator ile O(n).
  3. ~1,5 kat (15) kapasiteli yeni dizi oluşturulur, 10 öğe kopyalanır, sonra eklenir (bu adım O(n), ortalama amortize O(1)).
  4. Liste diziye bağlı ve sabit boyutlu; set boyutu değiştirmez, diziye yazar.
  5. CopyOnWriteArrayList.
  6. [A, X, B, C]; it.next() → "B" (add imlecin önüne ekler).
