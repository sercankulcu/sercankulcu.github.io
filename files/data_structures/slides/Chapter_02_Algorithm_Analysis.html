Algorithms and Measurement

Algorithms

  • An algorithm is a step-by-step procedure for solving a problem: input → steps → output.
  • One problem can have many algorithms, and some are more efficient than others.
  • Choosing the right one matters: a good algorithm does the job with fewer resources.

Some common algorithms:

SortingPuts data in a given order.bubble sort, merge sort
SearchingFinds a given item in a data set.linear search, binary search
GraphSolves problems on graphs.shortest paths, network flow

Algorithms and Measurement

What Makes a Good Algorithm

A good algorithm solves its problem effectively. We judge it by four criteria:

Time complexityMeasured by running time or by the number of operations.
Space complexityMeasured by the amount of memory the algorithm uses.
CorrectnessIt must give the right result for every valid input; wrong answers make it useless.
RobustnessIt should cope with a wide range of inputs and situations.

Experimental Analysis: System.nanoTime()

for (int n = 1000; n <= 64000; n *= 2) {
  int[] a = new int[n];
  for (int i = 0; i < n; i++) a[i] = i; // distinct
  long start = System.nanoTime();
  hasDuplicates(a);                          // timed work
  long elapsed = System.nanoTime() - start;  // ns
  System.out.println(n + " " + elapsed / 1e6 + " ms");
}
MeasureSubtracting two System.nanoTime() readings gives elapsed ns (not wall-clock time).
RepeatJIT warm-up, garbage collection, and other processes add noise: run several times, take the median.
PlotPlot time against n and see how the time changes when n doubles.
Careful: new int[n] is all zeros → hasDuplicates (an O(n²) duplicate check) returns true on its first comparison. To time the worst case, use distinct data.

Algorithms and Measurement · Measuring

Doubling Experiments and the Limits of Measurement

Limits of experimental analysis (Goodrich §4.1):

  • Results depend on the hardware, the JVM, and the load; compare two algorithms in the same environment.
  • Only a limited set of inputs can be tried; an important one may be missed.
  • The algorithm must be fully implemented before it can be timed.
Doubling experiment: if T(2n)/T(n) ≈ 2k, then T(n) ≈ c·nk. To get past these limits, analyze by counting primitive operations: hardware-independent, valid for all inputs, no code to run.

Asymptotic Notation

Time Complexity and Big O

  • Expresses an algorithm's running time as a function of the input size n.
  • Big O gives an upper bound on running time; it is usually quoted for the worst case.
  • O(1): the operation count does not grow with the input size, though the time need not be identical for every input.
  • O(n): time grows linearly with the input.
Only the fastest-growing term matters in Big O; constants and lower-order terms are dropped:
3n2 + 5n + 2 → O(n2)  ·  4n + 100 → O(n)  ·  7 → O(1)

Asymptotic Notation

O, Ω, and Θ: Definition and Graphs

Definition: f(n) = O(g(n)) ⇔ there exist c > 0 and n₀ ≥ 1 such that f(n) ≤ c·g(n) for every n ≥ n₀. For Ω use ≥; for Θ, both.

Big O: 2n + 10 ≤ 4·n for n ≥ n₀ = 5 → f(n) = O(n) (c = 4). For small n (n < 5) f(n) is larger, which does not matter.

Big Omega: 2n + 10 ≥ 2·n for every n ≥ 1 → f(n) = Ω(n): f grows no more slowly than n (lower bound).

Big Theta: 2n ≤ f(n) ≤ 4n for n ≥ 5 → f(n) = Θ(n): squeezed between two lines, it grows exactly like n.

Asymptotic Notation

Asymptotic Bounds and Cases

O(g(n)) · Upper boundFor large enough n, the work grows no faster than g(n).
Ω(g(n)) · Lower boundFor large enough n, the work grows no more slowly than g(n).
Θ(g(n)) · Tight boundThe upper and lower bounds match; the growth rate is in the same class as g(n).
AnalysisQuestionLinear search
Best caseHow many operations on the most favorable valid input?Θ(1) if the first item is the target
Average caseWhat is the expected cost under an assumed input distribution?Θ(n) if all positions are equally likely
Worst caseWhat cost is guaranteed for every valid input?Θ(n) if the target is last or absent
Amortized analysis: A single operation may be expensive, so we divide the total cost of a long sequence of operations by their number. In a growable array, for example, a resize costs O(n), yet appending is amortized O(1).

Asymptotic Notation · Case analysis

Best, Average, and Worst Case

Linear search on [4, 8, 15, 16, 23, 42]: comparisons for each possible target:

  • For the same n, the cost depends on the input.
  • The worst case is a guarantee and easy to compute → it is what we usually report.
  • The average assumes a probability distribution (here 7 equally likely targets, including the absent 50: 27/7 ≈ 3.86).
  • The best case alone is misleading.

Code Trace: countSteps(16) — i doubles every round

countSteps(16): how many doublings does it take to reach n?

Counter k = 0.

i = 1 < 16 → body runs.

k++ → k = 1.

i = 2 < 16 → body runs.

k++ → k = 2.

i = 4 < 16 → body runs.

k++ → k = 3.

i = 8 < 16 → body runs.

k++ → k = 4.

i *= 2 → i = 16; 16 < 16 is false → loop ends.

int countSteps(int n) {
  int k = 0;
  for (int i = 1; i < n; i *= 2)
    k++;
  return k;
}

main calls sum(a), and a new call frame is pushed.

Inside the method, a refers to the same array (no copy is made).

Code Trace: linearSearch(a, 23)

Searching a sorted array for 23. Linear search ignores the order and checks items one by one from the start.

a[0] = 2 ≠ 23 → i moves on. Each step rules out only one item.

a[1] = 5 ≠ 23 → i moves on.

a[2] = 8 ≠ 23 → i moves on.

a[3] = 12 ≠ 23 → i moves on.

a[4] = 16 ≠ 23 → i moves on.

a[5] = 23 == 23 → return 5. 6 comparisons; with the target last or absent, n = 10 → O(n).

int linearSearch(int[] a, int target) {
    for (int i = 0; i < a.length; i++)
        if (a[i] == target) return i;
    return -1;
}

Code Trace: binarySearch(a, 23)

The search range is the whole array: lo = 0, hi = 9.

0 ≤ 9 → range nonempty, round 1 begins.

mid = (0 + 9) / 2 = 4, a[4] = 16.

16 < 23 → the target is in the right half: lo = mid + 1 = 5. Left half discarded.

5 ≤ 9 → range nonempty, round 2 begins.

mid = (5 + 9) / 2 = 7, a[7] = 56.

56 > 23 → the target is in the left half: hi = mid − 1 = 6. Right half discarded.

5 ≤ 6 → range nonempty, round 3 begins.

mid = (5 + 6) / 2 = 5, a[5] = 23.

23 == 23 → found, return 5. Only 3 rounds; linear search needed 6 comparisons. Each round halves the range → O(log n).

int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = (lo + hi) / 2;
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

Outer loop: i = 0 (a[i] = 4). j starts at i + 1.

a[0] = 4 vs. a[1] = 7 → different, j moves on.

boolean hasDuplicates(int[] a) {
    for (int i = 0; i < a.length; i++)
        for (int j = i + 1; j < a.length; j++)
            if (a[i] == a[j])
                return true;
    return false;
}

From Code to Complexity · One problem, two algorithms

Example Problem: Prefix Averages

Input x[0..n−1]; output a[j] = (x[0] + … + x[j]) / (j + 1). Used for moving averages and financial trend analysis (Goodrich §4.3).

a[0] = average of x[0] … x[0] = 4.0.

a[1] = average of x[0] … x[1] = 6.0.

a[2] = average of x[0] … x[2] = 6.0.

a[3] = average of x[0] … x[3] = 5.0.

Two solutions: re-sum from scratch for each j (O(n²)) · carry a running sum (O(n)).

From Code to Complexity · Step through the code

Code Trace: prefixAverage1 — re-sum from scratch for each j

n = 4; the result array a is created, filled with 0.0.

j = 0: total = 0 — each j re-sums from scratch.

total += x[0] = 4 → total = 4.0.

a[0] = 4.0 / 1 = 4.0.

j = 1: total = 0 — each j re-sums from scratch.

total += x[0] = 4 → total = 4.0.

total += x[1] = 8 → total = 12.0.

a[1] = 12.0 / 2 = 6.0.

j = 2: total = 0 — each j re-sums from scratch.

total += x[0] = 4 → total = 4.0.

total += x[1] = 8 → total = 12.0.

total += x[2] = 6 → total = 18.0.

a[2] = 18.0 / 3 = 6.0.

j = 3: total = 0 — each j re-sums from scratch.

total += x[0] = 4 → total = 4.0.

total += x[1] = 8 → total = 12.0.

total += x[2] = 6 → total = 18.0.

total += x[3] = 2 → total = 20.0.

a[3] = 20.0 / 4 = 5.0.

return a. Additions: 1 + 2 + 3 + 4 = 10 = n(n+1)/2 → O(n²).

double[] prefixAverage1(double[] x) {
  int n = x.length;
  double[] a = new double[n];
  for (int j = 0; j < n; j++) {
    double total = 0;
    for (int i = 0; i <= j; i++)
      total += x[i];
    a[j] = total / (j + 1);
  }
  return a;
}

Code Trace: prefixAverage2 — running sum

total is set to 0 once, before the loop, and carried across rounds.

j = 0: total += x[0] = 4 → total = 4.0 (previous sum reused).

a[0] = 4.0 / 1 = 4.0.

j = 1: total += x[1] = 8 → total = 12.0 (previous sum reused).

a[1] = 12.0 / 2 = 6.0.

j = 2: total += x[2] = 6 → total = 18.0 (previous sum reused).

a[2] = 18.0 / 3 = 6.0.

j = 3: total += x[3] = 2 → total = 20.0 (previous sum reused).

a[3] = 20.0 / 4 = 5.0.

Same result with only 4 additions (prefixAverage1: 10). One loop → O(n).

double[] prefixAverage2(double[] x) {
  int n = x.length;
  double[] a = new double[n];
  double total = 0;
  for (int j = 0; j < n; j++) {
    total += x[j];
    a[j] = total / (j + 1);
  }
  return a;
}

Space and Correctness

Space Complexity

  • Measures how much memory an algorithm uses, usually in Big O notation.
  • Describes how memory use grows with the input size (usually not counting the input itself: extra space).
  • Memory efficiency matters on systems with limited memory.
O(1) · ConstantExample: creating one variable. Memory use does not change with the input size.
O(n) · LinearExample: storing every item of an array, like the array a in prefixAverage.
O(n2) · QuadraticExample: storing an n×n matrix. Memory grows with the square of n.

Space and Correctness

Correctness

  • A correct algorithm produces the expected output for every valid input in finite time.
  • A fast algorithm that gives wrong answers is worthless.

How do we show correctness?

Test casesCompare outputs with known correct results.
Edge casesEmpty input, a single item, the largest/smallest values.
Loop invariantA proof via a property that holds at every step.
CounterexampleA single wrong result proves the algorithm incorrect.

Space and Correctness

Robustness

  • An algorithm's ability to cope with unexpected situations.
  • A robust algorithm handles even out-of-range inputs without crashing or giving wrong results.

How do we test robustness?

Invalid inputCoping with inappropriate or unexpected input.null, negative size
Bad dataCoping with corrupt or missing data.missing rows, wrong format
Large data setsHandling very large inputs.10⁸ records
OverloadHow the algorithm behaves under heavy load.thousands of simultaneous requests

Summary

Common Mistakes

“O means worst case”O denotes an upper bound; best and worst case are a separate idea. Any case can be described with O, Ω, or Θ.
“O(1) is always fast”The constant can be large: an O(1) operation taking 1000 steps per call is slower than an n-step O(n) one while n < 1000.
“Nested loops mean n²”If the inner loop advances by j *= 2, it is n log n; if it runs a fixed number of times, O(n).
“The log base matters”log₂ n and log₁₀ n differ only by a constant factor: both are O(log n).
(lo + hi) / 2 overflowFor very large arrays the int sum overflows; lo + (hi - lo) / 2 is safe.
Comparing arrays with a == b== compares references; use Arrays.equals(a, b) for the contents.

Sample Problems

  1. What is the time complexity of an algorithm that compares every pair of items?
  2. Which Θ class does f(n) = 5n³ + 2n² + 100 belong to?
  3. How many rounds does binary search take in the worst case on a sorted array of n = 1024 items?
  4. How many times does the loop for (int i = 1; i < n; i *= 2) run?
  5. What are the best and worst cases of linear search?
  6. Algorithm A takes 100n steps, algorithm B takes n². For which values of n is A faster?
Show answers
  1. n(n − 1)/2 comparisons → O(n2).
  2. Θ(n³): the fastest-growing term decides; constants are dropped.
  3. ⌊log₂ 1024⌋ + 1 = 11 rounds.
  4. i = 1, 2, 4, …: ⌈log₂ n⌉ rounds → O(log n).
  5. Best: the target is the first item, Θ(1). Worst: the target is last or absent, Θ(n).
  6. 100n < n² ⇔ n > 100: for large n, the slower-growing algorithm wins.

Summary

Exercises

  1. What is the Big O of this code? 
    for (int i = n; i > 1; i /= 2)
  for (int j = 0; j < n; j++) s++;
  2. Show that f(n) = 3n² + 5n + 2 = O(n²) by giving c and n₀.
  3. In a doubling experiment, doubling n multiplies the time by ≈ 8. What class is T(n) in?
  4. How many additions do prefixAverage1 and prefixAverage2 each make for n = 5?
  5. After for (i = 0; i < n; i++) for (j = i; j < n; j++) s++;, what is s?
  6. An O(n²) algorithm takes 2 seconds for n = 1000. About how long will it take for n = 4000?
Answers / hints
  1. The outer loop runs ⌊log₂ n⌋ rounds, the inner loop n → O(n log n).
  2. For n ≥ 1, 5n ≤ 5n² and 2 ≤ 2n² → f(n) ≤ 10n²: c = 10, n₀ = 1.
  3. 2³ = 8 → O(n³) (cubic).
  4. prefixAverage1: 1+2+3+4+5 = 15; prefixAverage2: 5.
  5. n + (n − 1) + … + 1 = n(n + 1)/2 → O(n²).
  6. Quadrupling n multiplies the time by 4² = 16: ≈ 32 seconds.
