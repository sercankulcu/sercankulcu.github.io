Soru 1: ArrayList Çıktısı

Programın çıktısı nedir? remove(1) ile remove(Integer.valueOf(20)) farkını açıklayınız.

List<Integer> l = new ArrayList<>(
        List.of(5, 10, 15, 20, 25));
l.remove(1);
l.remove(Integer.valueOf(20));
l.add(1, 99);
l.set(3, l.get(0) + l.size());
System.out.println(l + " " + l.indexOf(15)
                   + " " + l.contains(25));
Cevabı göster
  • remove(1): int argüman indistir → 10 silinir: [5, 15, 20, 25]
  • remove(Integer.valueOf(20)): nesne argüman değerdir → [5, 15, 25]
  • add(1, 99) → [5, 99, 15, 25]
  • set(3, 5 + 4) → 25'in yerine 9: [5, 99, 15, 9]

Çıktı: [5, 99, 15, 9] 2 false

Soru 2: Gezinirken Silme

Kod çift sayıları silmek için yazılmıştır. Çalıştırınca ne olur? Neden? İki doğru çözüm yazınız.

List<Integer> l = new ArrayList<>(
        List.of(1, 2, 3, 4, 5, 6));
for (Integer x : l)
    if (x % 2 == 0)
        l.remove(x);
System.out.println(l);
Cevabı göster

ConcurrentModificationException. for-each gizli bir Iterator kullanır. 2 silinince listenin değişiklik sayacı (modCount) artar; sonraki next() çağrısı bunu fark eder ve istisna fırlatır.

// Çözüm 1: Iterator.remove
Iterator<Integer> it = l.iterator();
while (it.hasNext())
    if (it.next() % 2 == 0)
        it.remove();

// Çözüm 2: removeIf
l.removeIf(x -> x % 2 == 0);

Sonuç: [1, 3, 5].

Test 1

Kodun çıktısı nedir?

List<Integer> l =
    new ArrayList<>(List.of(1, 2, 3));
l.add(1, 9);
System.out.print(l.get(2));

add(1, 9) indis 1'e ekler ve sonrakileri kaydırır: [1, 9, 2, 3] → get(2) = 2.

List.of(1, 2).add(3) çağrısının sonucu nedir?

List.of değiştirilemez (immutable) liste üretir; derlenir ama çalışma zamanında istisna fırlatır.

Kapasitesi dolu bir ArrayList'e add yapılınca ne olur?

Bu adım O(n) sürer ama seyrek olduğu için ekleme amortize O(1)'dir.

Dinamik Dizi Büyümesi

Kapasitesi dolunca 2 katına çıkan dizi listesine 5, 7, 9, 4, 6 ekleniyor. Kapasiteyi ve kopya sayısını izleyin.

Önce tahmin edin: sonunda kapasite ve toplam kopya sayısı ne olur?

Kapasitesi 2 olan dizi.

5 indis 0'e yazılır.

7 indis 1'e yazılır.

Dizi dolu: 2 eleman yeni diziye kopyalanır, kapasite 4 olur.

9 indis 2'e yazılır.

4 indis 3'e yazılır.

Dizi dolu: 4 eleman yeni diziye kopyalanır, kapasite 8 olur.

6 indis 4'e yazılır.

5 ekleme için toplam 6 kopya: ekleme başına sabit (amortize O(1)).

int[] d = new int[2];
int n = 0, kopya = 0;
void ekle(int x) {
    if (n == d.length) {
        kopya += n;
        d = Arrays.copyOf(d, 2 * d.length);
    }
    d[n++] = x;
}
// ekle: 5, 7, 9, 4, 6
System.out.println(n + " " + d.length);
System.out.println(kopya);

Ucu Açık Soru · Liste

Çalma Listesi Tasarımı

  1. Bir müzik çalar uygulamasında çalma listesi işlemleri: sona şarkı ekleme, şarkı silme, sürükle-bırak ile yer değiştirme, sıradaki/önceki şarkı, karışık çalma. ArrayList mi, LinkedList mi? Her işlem için gerekçelendirin.
  2. Kullanıcı listede gezinirken (iterator ile) şarkı silerse ne olur? Güvenli yöntem nedir?
Örnek cevap ve değerlendirme ölçütleri

1. Tipik bir liste birkaç yüz şarkıdır; işlemlerin çoğu indisle erişimdir (ekranda i. şarkı, karışık çalmada rastgele indis). ArrayList uygundur: get O(1), sona ekleme amortize O(1). Silme ve taşıma O(n) olsa da n küçüktür ve ardışık bellek hızlıdır. LinkedList ancak iterator ile çok sık ekleme/silme yapılıyorsa öne çıkar; indisle erişim O(n)'dir. Sıradaki/önceki için yalnızca "şu anki indis" tutulur. Karışık çalma için indis dizisi karıştırılır (Fisher–Yates).

2. for-each içinde list.remove → ConcurrentModificationException. Güvenli yol: Iterator.remove() ya da removeIf. Silinen şarkı çalan şarkıdan önceyse "şu anki indis" 1 azaltılmalıdır.

Değerlendirme: işlemlere göre karmaşıklık karşılaştırması · n'nin küçük olduğunun fark edilmesi · indis yönetimi · eşzamanlı değişiklik hatası ve çözümü.
