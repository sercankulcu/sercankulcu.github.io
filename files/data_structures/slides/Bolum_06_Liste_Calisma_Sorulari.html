Soru 2: for-each Döngüsünün Arkası

kelimeler bir List<String>'tir. Derleyicinin bu for-each döngüsünü dönüştürdüğü, Iterator kullanan eşdeğer while döngüsünü yazınız.

int say = 0;
for (String s : kelimeler)
    if (s.length() > 3) say++;
Cevabı göster 
int say = 0;
Iterator<String> it =
    kelimeler.iterator();
while (it.hasNext()) {
    String s = it.next();
    if (s.length() > 3) say++;
}

for-each yalnızca sağdaki ifade bir dizi ya da Iterable uygulayan bir sınıfın nesnesiyse derlenir. Iterable'dan iterator() alınır; diziler için ise indisli for döngüsü üretilir. Iterable ayrıca forEach(lambda) ve spliterator() sunar.

Soru 3: Kendi Iterable Sınıfınız

Iterable<Integer> uygulayan GeriSayim sınıfını yazınız: for (int x : new GeriSayim(3)) döngüsü sırayla 3 2 1 üretsin ve Iterator sözleşmesine uysun.

Cevabı göster 
class GeriSayim implements Iterable<Integer> {
  private final int n;
  GeriSayim(int n) { this.n = n; }
  public Iterator<Integer> iterator() {
    return new Iterator<Integer>() {
      int k = n;
      public boolean hasNext() { return k >= 1; }
      public Integer next() {
        if (k < 1)
          throw new NoSuchElementException();
        return k--;
      }
    };
  }
}

Her iterator() çağrısı kendi sayacıyla yeni bir okuyucu döndürür. Sözleşme: öğe yokken next() → NoSuchElementException (aralık dışı değer dönmemeli).

Soru 5: subList Bir Görünümdür

Programın çıktısı nedir?

List<String> l = new ArrayList<>(
    List.of("A","B","C","D","E","F"));
List<String> alt = l.subList(2, 4);
alt.set(0, "X");
alt.add("Y");
System.out.println(alt + " " + l);
alt.clear();
System.out.println(l);
Cevabı göster 
[X, D, Y] [A, B, X, D, Y, E, F]
[A, B, E, F]
  • subList(2, 4) yarı açık aralıktır [2, 4): C, D. Kopya değil, asıl listenin görünümüdür.

Dikkat: l doğrudan yapısal değiştirilirse (add/remove) eski alt geçersizleşir; kullanılırsa ConcurrentModificationException.

Soru 14: Spliterator ile Bölme

ArrayList'in Spliterator'ı kalan aralığı ortadan böler ve ilk yarıyı yeni parçaya verir. Programın çıktısı nedir?

List<String> l = new ArrayList<>(
    List.of("A","B","C","D","E","F"));
Spliterator<String> s1 = l.spliterator();
Spliterator<String> s2 = s1.trySplit();
Spliterator<String> s3 = s1.trySplit();
while (s2.tryAdvance(System.out::print)) { }
System.out.print("|");
while (s3.tryAdvance(System.out::print)) { }
System.out.print("|");
while (s1.tryAdvance(System.out::print)) { }
Cevabı göster

Çıktı: ABC|D|EF

  • İlk trySplit: s1 = [0, 6), orta 3 → s2 = [0, 3) (A B C), s1 = [3, 6).
  • İkinci trySplit: orta (3 + 6) / 2 = 4 → s3 = [3, 4) (D), s1 = [4, 6) (E F).
  • tryAdvance(eylem) sıradaki öğe varsa eylemi uygular ve true döner; kalmadıysa false → döngü biter.

Parçalar ayrı iş parçacıklarında işlenebilir; parallelStream() arka planda bunu yapar.

Soru 15: LinkedList'te İndisli Döngü

get(i) düğümlere yakın uçtan yürür; adim yürünen bağlantı sayısını hesaplar. Program ne yazdırır ve bu döngünün n'ye göre karmaşıklığı nedir?

List<String> list = new LinkedList<>(List.of(
    "A","B","C","D","E","F","G","H"));
int n = list.size(), adim = 0;
for (int i = 0; i < n; i++) {
  String s = list.get(i);
  adim += Math.min(i, n - 1 - i);
}
System.out.println(adim);
Cevabı göster

Çıktı: 12

i = 0 … 7 için yürüme: 0, 1, 2, 3 (baştan, i < n/2) ve 3, 2, 1, 0 (sondan). Toplam 12 ≈ n²/4 → döngü O(n²).

Daha iyisi: for-each, forEach ya da Iterator; her next() tek bağlantı izler, toplam n − 1 = 7 → O(n). ArrayList'te ise get(i) O(1) olduğundan indisli döngü de O(n)'dir.

Soru 17: for-each İçinde Silme

Bu kod çalışınca ne olur? Gizli Iterator'ın cursor ve modCount denetimiyle açıklayınız.

List<Integer> l = new ArrayList<>(
    List.of(1, 2, 3, 4));
for (Integer x : l)
    if (x == 3)
        l.remove(x);
System.out.println(l);
Cevabı göster

Şaşırtıcı biçimde hata yok; çıktı [1, 2, 4].

  • x bir Integer olduğundan remove(Object) çağrılır: 3 değeri silinir.
  • 3 döndürüldüğünde cursor = 3'tür. Silmeden sonra size = 3 → hasNext() (cursor ≠ size) false; next() hiç çağrılmaz, modCount denetimi yapılmaz. 4 hiç gezilmez.
  • x == 2 olsaydı: cursor 2 ≠ size 3 → next() modCount farkını görür → ConcurrentModificationException (fail-fast).

Doğru yol: it.remove() ya da l.removeIf(x -> x == 3).

Soru 18: it.remove() ile Güvenli Silme

Kod A ile başlayan isimleri siler. Iterator'ın cursor, lastRet ve sayaçlarını izleyerek çıktıyı bulunuz.

Önce kendiniz tahmin edin, sonra › ile ilerleyin.

Boş liste + üç add: her yapısal değişiklik sayacı artırır → modCount = 3.

iterator(): imleç başta, henüz öğe döndürülmedi; o anki sayaç expected olarak saklanır.

hasNext(): cursor 0 ≠ size 3 → true.

next(): 3 == 3 ✓ → "Ada"; cursor = 1, lastRet = 0.

A ile başlıyor → it.remove(): lastRet'teki öğe silinir, cursor = 0 (kayan "Can" atlanmaz), lastRet = −1, expected = modCount = 4.

hasNext(): 0 ≠ 2 → true. next(): 4 == 4 ✓ → "Can"; cursor = 1, lastRet = 0.

"Can" A ile başlamıyor; silme yok.

hasNext(): 1 ≠ 2 → true. next() → "Ali"; cursor = 2, lastRet = 1.

it.remove(): "Ali" silinir; cursor = 1, lastRet = −1, sayaçlar yine eşitlenir (5).

hasNext(): cursor 1 = size 1 → false; döngü hatasız biter.

Çıktı [Can]. Satır 7'de l.remove(s) yazılsaydı expected güncellenmez, sonraki next() → ConcurrentModificationException.

List<String> l = new ArrayList<>();
l.add("Ada"); l.add("Can"); l.add("Ali");
Iterator<String> it = l.iterator();
while (it.hasNext()) {
  String s = it.next();
  if (s.startsWith("A"))
    it.remove();
}
System.out.println(l);

Soru 21: Tek Geçişte Silme ve Ekleme

Tek bir ListIterator ile listeyi bir kez gezerek negatif sayıları silen ve her çift sayının hemen arkasına bir kopyasını ekleyen void duzenle(List<Integer> l) metodunu yazınız. Örnek: [2, −1, 3, 4, −6] → [2, 2, 3, 4, 4].

Cevabı göster 
void duzenle(List<Integer> l) {
  ListIterator<Integer> it = l.listIterator();
  while (it.hasNext()) {
    int x = it.next();
    if (x < 0) it.remove();
    else if (x % 2 == 0) it.add(x);
  }
}
  • it.remove() son next() ile döneni siler; okuyucu sayaçları eşitlediği için ConcurrentModificationException olmaz.
  • it.add(x) imlecin önüne ekler; sonraki next() eklenen öğeyi görmez, bu yüzden sonsuz döngü olmaz.
  • Gezerken l.add/l.remove kullanmak fail-fast hatası verirdi.

Soru 24: ArrayList add(i, e) ve Büyüme

Dizi [A, B, C, D, E], kapasite 5. add(2, "X") sonunda dizi, kapasite ve yapılan kopya/kaydırma sayısı ne olur?

Önce kendiniz tahmin edin, sonra › ile ilerleyin.

add(2, "X") çağrıldı: X indis 2'ye girecek.

0 ≤ 2 ≤ boyut (5) → geçerli indis (add için üst sınır boyut'tur).

Dizi dolu: yeni kapasite 5 · 3 / 2 = 7 (≈ 1,5 kat); 5 öğe yeni diziye kopyalanır (O(n)).

k = 5 > 2: dizi[5] = dizi[4]. Sağdan başlanır ki üzerine yazılmasın.

k = 4 > 2: dizi[4] = dizi[3] → D sağa.

k = 3 > 2: dizi[3] = dizi[2] → C sağa.

k = 2 > 2 değil → döngü biter. dizi[2]'de C'nin eski kopyası duruyor.

dizi[2] = X: açılan yere yazılır.

Sonuç [A, B, X, C, D, E], kapasite 7: 5 kopya + n − i = 3 kaydırma → O(n).

public void add(int i, E e) {
  Objects.checkIndex(i, boyut + 1);
  if (boyut == dizi.length)
    dizi = Arrays.copyOf(dizi, boyut*3/2);
  for (int k = boyut; k > i; k--)
    dizi[k] = dizi[k - 1];
  dizi[i] = e;
  boyut++;
}

Soru 25: Katlama mı, Sabit Artış mı?

Kapasitesi 4 olan boş bir dinamik diziye 33 öğe ekleniyor. Dolunca kapasiteyi (1) iki katına çıkaran ve (2) 4 artıran stratejilerde toplam kaç öğe kopyalanır; bu, ekleme başına amortize maliyet hakkında ne söyler?

Cevabı göster

×2: büyütmeler 5., 9., 17., 33. eklemede: 4 + 8 + 16 + 32 = 60 kopya < 2n = 66. Ekleme başına sabit → amortize O(1).

+4: her 4 eklemede bir büyütme: 4 + 8 + 12 + … + 32 = 4·(1 + … + 8) = 144 kopya ≈ n²/(2c). Toplam O(n²) → ekleme başına O(n).

Geometrik büyüme şarttır; Java'nın ×1,5'i de geometriktir (toplam ≤ 3n). Bankacı yöntemiyle: her ucuz ekleme birkaç "jeton" biriktirir, pahalı büyütmeyi o jetonlar öder.

Soru 26: Son Hücreyi null Yapmak

ArrayList'in remove(i) gerçeklemesindeki dizi[--boyut] = null; satırı neden vardır?

public E remove(int i) {
  Objects.checkIndex(i, boyut);
  E eski = dizi[i];
  for (int k = i; k < boyut - 1; k++)
    dizi[k] = dizi[k + 1];

}

Doğru: A. Sola kaydırmadan sonra son öğe iki kez durur; fazla kopya listenin parçası değildir ama referansı tutar. B yanlış: kapasite (dizinin boyu) değişmez, silmede küçülmez. D yanlış: get zaten boyut'a göre sınır denetimi yapar. Silme n − i − 1 kaydırma → O(n); sondan silmek O(1).

Soru 28: LinkedList Bir Deque'dir

Programın çıktısı nedir ve bu çağrılardan hangisi sabit zamanda (O(1)) çalışmaz?

LinkedList<Integer> q = new LinkedList<>();
q.add(5);
q.addFirst(3);
q.push(1);
q.addLast(7);
q.removeLast();
q.pollFirst();
System.out.println(q + " " + q.get(1));
Cevabı göster

Durumlar: [5] → [3, 5] → push = addFirst → [1, 3, 5] → [1, 3, 5, 7] → removeLast → [1, 3, 5] → pollFirst → [3, 5].

Çıktı: [3, 5] 5

LinkedList çift yönlü bağlı listedir; first ve last'ı bildiği için uçlarda ekleme/silme O(1)'dir. List'in yanında Deque'yi de uyguladığından yığın (push/pop) ve kuyruk (offer/poll) olarak kullanılabilir. O(1) olmayan tek çağrı get(1)'dir: düğümlere yakın uçtan yürür → O(n).

Soru 29: Hatalı remove(i)

Çift yönlü bağlı listede (first, last, size) yazılan bu remove(i) hangi durumlarda hatalı çalışır? Düzeltilmiş hâlini yazınız.

E remove(int i) {
  Objects.checkIndex(i, size);
  Dugum<E> x = first;
  for (int k = 0; k < i; k++)
    x = x.sonraki;
  x.onceki.sonraki = x.sonraki;
  x.sonraki.onceki = x.onceki;
  size--;
  return x.veri;
}
Cevabı göster

İlk düğüm silinirken (i = 0) x.onceki, son düğüm silinirken x.sonraki null'dır → NullPointerException. Ayrıca first/last hiç güncellenmez.

Dugum<E> o = x.onceki, s = x.sonraki;
if (o == null) first = s;
else o.sonraki = s;
if (s == null) last = o;
else s.onceki = o;

Bağ değiştirmek O(1), ama i. düğüme yürümek O(i) → toplam O(n). (Java, i ≥ size/2 ise last'tan geriye yürür.)

Soru 30: Konumsal Listede remove(p)

Bekçi (sentinel) header/trailer düğümleri olan çift bağlı konumsal listede (Positional List) E remove(Position<E> p) metodunu yazınız ve neden O(1) olduğunu açıklayınız. validate(p) konumu düğüme dönüştürür.

Cevabı göster 
public E remove(Position<E> p) {
  Dugum<E> d = validate(p);
  Dugum<E> o = d.onceki, s = d.sonraki;
  o.sonraki = s;
  s.onceki = o;
  size--;
  E veri = d.veri;
  d.veri = null;            // konumu geçersiz kıl
  d.onceki = d.sonraki = null;
  return veri;
}

Konum düğümün kendisidir: aramak/yürümek gerekmez, yalnızca birkaç bağlantı ataması → O(1). Bekçiler sayesinde her gerçek düğümün iki komşusu vardır; null denetimi gerekmez. İndisler ekleme/silmede kayar, konum ise öğeye bağlı kalır. LinkedList.remove(int) ise önce i. düğüme yürür: O(n). Java'daki en yakın karşılık ListIterator'dır.

Soru 32: Vector ve Bileşik İşlem

v = [20] iken iki iş parçacığı bu kodu aynı anda çalıştırıyor. Vector'ın her metodu synchronized olduğu hâlde neden istisna oluşabilir ve nasıl düzeltilir?

// T1 ve T2 aynı anda:
if (!v.isEmpty())
    v.remove(0);
Cevabı göster

Her metot tek başına kilitlenir, ama iki çağrının arası korunmasızdır. Olası sıralanış:

  1. T1: isEmpty() → false, kilidi bırakır.
  2. T2: isEmpty() → false (v hâlâ 1 öğeli).
  3. T1: remove(0) → 20; v boş.
  4. T2: remove(0) boş vektörde → ArrayIndexOutOfBoundsException.

"Kontrol et, sonra yap" bileşik işlemi atomik değildir. Çözüm: ikisini tek kilit altına almak.

synchronized (v) {
    if (!v.isEmpty()) v.remove(0);
}

Vector eski (legacy) bir sınıftır ve tek iş parçacığında da kilit bedeli öder; yeni kodda ArrayList, gerekirse Collections.synchronizedList ya da CopyOnWriteArrayList tercih edilir.

Soru 33: Stack Sınıfı

Programın çıktısı nedir?

Stack<Integer> s = new Stack<>();
s.push(5);
s.push(8);
s.push(3);
System.out.println(s.search(5) + " "
    + s.pop() + " " + s.peek() + " "
    + s.search(9) + " " + s);
Cevabı göster

Çıktı: 3 3 8 -1 [5, 8]

  • Yığın (alttan üste) [5, 8, 3]. search(5) üstten 1'den başlayan uzaklığı verir: 3.
  • pop() üsttekini çıkarıp döndürür: 3. peek() üsttekini çıkarmadan döndürür: 8.
  • search(9) → bulunamadı: −1. toString Vector'dan gelir, alttan üste yazar: [5, 8].

Boş yığında pop/peek → EmptyStackException. Stack Vector'dan türediği için LIFO dışı metotlar da taşır; yeni kodda ArrayDeque önerilir.

Soru 34: Gezinirken Yazmak: CopyOnWrite

Programın çıktısı nedir ve neden ConcurrentModificationException oluşmaz?

List<String> l = new CopyOnWriteArrayList<>(
    List.of("a", "b", "c"));
for (String s : l) {
    if (s.equals("b")) l.add("d");
    System.out.print(s);
}
System.out.println(" " + l);
Cevabı göster

Çıktı: abc [a, b, c, d]

  • Iterator, oluşturulduğu andaki iç diziyi (anlık görüntü, snapshot) kilitsiz gezer.
  • add("d") kilidi alır, diziyi kopyalar (O(n)), öğeyi kopyaya ekler ve liste referansını yeni diziye çevirir. Eski dizi değişmediği için okuyucu "d"yi görmez ve hata da olmaz.
  • Aynı kod ArrayList'le ConcurrentModificationException verirdi. Bu okuyucu it.remove()'u desteklemez.

Uygun: sık gezilen, nadiren değişen listeler (olay dinleyicileri, yapılandırma). Uygun değil: büyük ve sık değişen listeler.

Soru 36: Çalma Listesi İçin Yapı Seçimi

Bir müzik uygulamasının çalma listesinde sona şarkı ekleme, şarkı silme, sürükle-bırak ile taşıma, sıradaki/önceki şarkıya geçme ve karışık çalma yapılmaktadır. ArrayList ile LinkedList'ten hangisini seçersiniz? İşlemlerin maliyetleriyle gerekçelendiriniz.

Örnek cevap ve değerlendirme ölçütleri

Tipik bir liste birkaç yüz şarkıdır ve işlemlerin çoğu indisle erişimdir (ekranda i. şarkı, karışık çalmada rastgele indis). ArrayList uygundur: get O(1), sona ekleme amortize O(1). Silme ve taşıma (remove + add(i, e)) O(n) olsa da n küçüktür ve ardışık bellek önbellek dostudur. Sıradaki/önceki için yalnızca "şu anki indis" tutulur; karışık çalma için indis dizisi karıştırılır (Fisher–Yates).

LinkedList ancak konum zaten elde iken (ListIterator ile) çok sık ekleme/silme varsa öne çıkar; indisle erişimi O(n)'dir ve indisli döngü O(n²)'ye çıkar. Liste gezilirken silme yapılacaksa it.remove()/removeIf kullanılmalı; silinen şarkı çalan şarkıdan önceyse şu anki indis 1 azaltılmalıdır.

Değerlendirme: işlem bazında karmaşıklık karşılaştırması · n'nin küçüklüğü ve önbellek etkisinin fark edilmesi · "LinkedList'te ekleme hızlıdır" önermesinin koşuluna (konum elde mi?) değinilmesi · indis yönetimi ve gezinirken güvenli silme.
