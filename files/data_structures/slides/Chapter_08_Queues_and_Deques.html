The Queue ADT

The Queue

  • A linear data structure that is open at both ends.
  • Items leave in the order they arrived: first in, first out (FIFO).
  • Items join at one end (the rear) and leave from the other (the front).
  • Think of the line at a checkout or a ticket window: whoever arrives first is served first.

The Queue ADT

Basic Queue Operations

EnqueueAdds a new item at the rear of the queue.Time: O(1)
DequeueRemoves and returns the item at the front. The first item in is the first out (FIFO).Time: O(1)
Items in the middle are never accessed directly; only the front and rear are used.

Horses walking single file: the one in front passes first, and newcomers join at the back.

Dequeuing from an empty queue is an underflow; enqueuing into a full one, an overflow. Goodrich's interface returns null when the queue is empty; some implementations throw an exception.

The Queue ADT

Queue Operations, Step by Step

Initially the queue is empty: front and rear point to nothing (null).

The first item goes in: a lone item is both the front and the rear.

10 joins at the rear: rear advances, front stays put.

15 joins at the rear. Queue: 20, 10, 15 (front to rear).

20 leaves from the front; front advances to the next item (10).

10 leaves. Now front and rear point to the same item (15).

When the last item leaves, both become null. Items left in the order 20, 10, 15, the order they arrived (FIFO).

Array-Based Queues

A Queue in an Array

  • The items live in an array, and two indices mark the ends of the queue:
    • front: index of the first item.
    • rear: index of the last item.
  • Enqueue increments rear; dequeue increments front. Items never move.
  • Simple and fast, but the array has a fixed capacity.

The item at index 0 was dequeued earlier. Its slot is free now, but a simple array queue cannot reuse it.

Array-Based Queues

The Trouble with a Simple Array Queue

Empty queue, capacity N = 6. rear = −1: no items yet.

enqueue(10): rear++ → 0 → data[0].

enqueue(20): rear++ → 1 → data[1].

enqueue(30): rear++ → 2 → data[2].

enqueue(40): rear++ → 3 → data[3].

dequeue() → 10: front++ → 1. The freed slot is never reused.

dequeue() → 20: front++ → 2. The freed slot is never reused.

dequeue() → 30: front++ → 3. The freed slot is never reused.

enqueue(50): rear = 4.

enqueue(60): rear = 5 = N − 1, the last index of the array.

“Full” with only 3 items: the 3 orange slots are wasted. Shifting costs O(n); the fix is a circular queue.

Fix 1: ShiftingShift the items left on every dequeue → dequeue becomes O(n).
Fix 2: A circular arrayIndices wrap around to the start → every operation is O(1).

Array-Based Queues

The Circular Queue

  • FIFO like an ordinary queue, but after the last slot of the array comes the first slot again.
  • The two ends of the array are logically joined into a ring.
  • Indices advance modulo N: (i + 1) % N.
  • Freed slots are reused, so items never need shifting.
  • Also known as a ring buffer.

Here rear is the free slot where the next item will go: rear = (front + size) % N = (0 + 5) % 8 = 5.

Front to rear: A (6), B (7), C (0), D (1). The mod turns the jump from the end of the array back to the start into one expression.

Array-Based Queues

Full or Empty?

With only the front and rear indices, an empty and a full queue look the same: both indices point to the same slot. Two common fixes:

1. An item counter (size)Empty: size == 0 · Full: size == N
All N slots are used. This is the method used in this course.
2. Leave one slot emptyEmpty: front == rear · Full: (rear + 1) % N == front
No counter is needed, but at most N − 1 items fit.

Array-Based Queues

Circular Queue: Class and Status Queries

public class CircularQueue<E> {
    private E[] data;       // stores the items
    private int front = 0;    // index of the first item
    private int size = 0;  // number of items

    @SuppressWarnings("unchecked")
    public CircularQueue(int capacity) {
        data = (E[]) new Object[capacity];
    }
    public int size()      { return size; }
    public boolean isEmpty()  { return size == 0; }
    public boolean isFull() { return size == data.length; }
    public E first()          { return isEmpty() ? null : data[front]; }
    // enqueue(), dequeue()
}
The rear index is not stored but computed when needed as (front + size) % data.length, so two fields can never disagree.

Array-Based Queues

Circular Queue: enqueue and dequeue

public void enqueue(E item) {           // enqueue
    if (isFull())
        throw new IllegalStateException("full");
    int avail = (front + size) % data.length;
    data[avail] = item;
    size++;
}
public E dequeue() {                  // dequeue
    if (isEmpty())
        throw new IllegalStateException("empty");
    E item = data[front];
    data[front] = null;               // drop the reference
    front = (front + 1) % data.length;
    size--;
    return item;
}

Code Trace: Growing a Full Circular Queue

Full queue (front = 2): the order is A, B, C, D, but the array holds C, D, A, B. Now enqueue(E).

4 == 4 → full. Instead of failing, grow to twice the capacity.

A new array of 8 cells is allocated.

k = 0: temp[0] = data[(2 + 0) % 4] = data[2] = A.

k = 1: temp[1] = data[(2 + 1) % 4] = data[3] = B.

k = 3: temp[3] = data[(2 + 3) % 4] = data[1] = D.

data = temp: the items are now in order (Arrays.copyOf would have kept them scrambled).

front = 0: the front item (A) is now in data[0].

Back in enqueue: (0 + 4) % 8 = 4 → data[4] = E.

size → 5. Growing costs O(n), but because the capacity doubles, enqueue is amortized O(1).

private void resize(int newCap) {
  E[] temp = (E[]) new Object[newCap];
  for (int k = 0; k < size; k++)
    temp[k] = data[(front + k) % data.length];
  data = temp;
  front = 0;
}
public void enqueue(E item) {
  if (size == data.length) resize(2 * data.length);
  data[(front + size) % data.length] = item;
  size++;
}

Linked Queues

A Queue in a Linked List

  • Each queue item is a node (data plus a next reference).
  • front marks the head and rear the tail: insert at the tail, remove at the head.
  • The size is dynamic; there is no capacity limit (no full queue).
  • Each node costs one extra reference and an object allocation.
class Node {
    int data;
    Node next;
    Node(int data) {
        this.data = data;
    }
}
// fields:
Node front, rear;
int size;

Why insert at the tail and remove at the head? In a singly linked list, removing the head is O(1), but removing the tail means finding its predecessor: O(n).

Linked Queues

Enqueue and Dequeue Algorithms

enqueue(x)
  1. Is the queue full? (fixed-capacity array only)
  2. If so, report an overflow and stop.
  3. Otherwise, write x at the rear position.
  4. Advance the rear to the next position.
  5. Increment the item count and report success.
dequeue()
  1. Is the queue empty?
  2. If so, report an underflow and stop.
  3. Otherwise, take the front item.
  4. Advance the front to the next item.
  5. Decrement the item count and return the item.

public void enqueue(int data) {
    Node temp = new Node(data);
    if (isEmpty()) {
        front = temp;
    } else {
        rear.next = temp;
    }
    rear = temp;
    size++;
}

public int dequeue() {
    if (isEmpty())
        throw new NoSuchElementException();
    int result = front.data;
    front = front.next;
    if (front == null)
        rear = null;
    size--;
    return result;
}

Linked Queues

Circular Array or Linked List?

Circular array

  • Contiguous in memory: cache-friendly and fast.
  • No extra reference per item.
  • Fixed capacity: when full, either overflow or copy into a larger array (O(n), amortized O(1)).

Linked list

  • No capacity limit; grows as needed.
  • Every insertion and removal is strictly O(1).
  • Each node costs an extra reference and an object allocation.

Kinds of Queues

Deque Operations, Step by Step

An empty deque. We implement it with a doubly linked list: every node has prev and next.

First node: head = tail = node.

Insert at the tail: node.prev = tail; tail.next = node; tail = node.

Insert at the head: node.next = head; head.prev = node; head = node.

Both ends are held by references, so every insertion is O(1).

Remove from the tail: tail = tail.prev; tail.next = null. The prev reference makes this O(1).

Remove from the head: head = head.next; head.prev = null.

In a singly linked list, removing the tail is O(n), since we must find the node before it. The prev reference makes it O(1).

public void addFirst(E data) {
    Node<E> node = new Node<>(data);

Deque: Removing from Either End

public E removeFirst() {
    if (isEmpty()) return null;
    E data = head.data;
    head = head.next;
    if (head == null)
        tail = null;       // now empty
    else
        head.prev = null;
    size--;
    return data;
}
public E removeLast() {
    if (isEmpty()) return null;
    E data = tail.data;
    tail = tail.prev;
    if (tail == null)
        head = null;       // now empty
    else
        tail.next = null;
    size--;
    return data;
}
When the last item leaves, both ends must become null. Otherwise tail still points to the removed node once head is null: the node cannot be collected, and last() returns a wrong value. An empty deque returns null, as in Goodrich.

A Deque Application: Sliding Window Maximum

k = 3. d holds indices whose values decrease from front to rear, so the maximum is always at the front.

a[0] = 1: 0 goes in at the rear.

a[1] = 3: drop 0:1 from the rear. 1 goes in at the rear.

a[2] = -1: 2 goes in at the rear. Max = 3.

a[3] = -3: 3 goes in at the rear. Max = 3.

a[4] = 5: drop 1 from the front; drop 3:-3 and then 2:-1 from the rear. 4 goes in at the rear. Max = 5.

a[5] = 3: 5 goes in at the rear. Max = 5.

a[6] = 6: drop 5:3 and then 4:5 from the rear. 6 goes in at the rear. Max = 6.

Each index enters once and leaves at most once → O(n) (brute force takes O(n·k)).

int[] windowMax(int[] a, int k) {
  int[] maxes = new int[a.length - k + 1];
  Deque<Integer> d = new ArrayDeque<>(); // indices
  for (int i = 0; i < a.length; i++) {
    if (!d.isEmpty() && d.peekFirst() <= i - k)
      d.pollFirst();        // out of window
    while (!d.isEmpty() && a[d.peekLast()] <= a[i])
      d.pollLast();         // not a candidate
    d.offerLast(i);
    if (i >= k - 1) maxes[i - k + 1] = a[d.peekFirst()];
  }
  return maxes;
}

Applications

Application: A Round-Robin Scheduler

The operating system gives the CPU to processes in turn: the process at the front runs for at most q time units and, if unfinished, rejoins at the rear.

Three processes in the ready queue, with 5, 3, and 2 units of work left. Time slice (quantum) q = 2.

P1 leaves the front (dequeue), runs for 2 units, and rejoins at the rear with 3 left (enqueue).

P2 runs for 2 units and goes back to the rear with 1 left.

P3's 2 units fit in one slice → it finishes at t = 6 and does not rejoin.

P1 runs for another 2 units; 1 is left.

P2 finishes its last unit (t = 9) without using the whole slice.

All done. Completion times: P3 = 6, P2 = 9, P1 = 10.

Simulator: Round-Robin Scheduler (adjustable quantum and processes).

remaining 1 > 0 → q.offer(p): P1 rejoins at the rear.

Not empty → p = q.poll() = P2 (1 left).

run = min(2, 1) = 1; P2 runs for 1 unit → t = 9, 0 left. The slice is not used up.

remaining 0 → P2 is done (t = 9); it does not rejoin.

Not empty → p = q.poll() = P1 (1 left).

run = min(2, 1) = 1; P1 runs for 1 unit → t = 10, 0 left. The slice is not used up.

remaining 0 → P1 is done (t = 10); it does not rejoin.

The queue is empty → the loop ends. Completion: P3 = 6, P2 = 9, P1 = 10. Each round is one poll plus at most one offer: O(1).

void roundRobin(Queue<Process> q, int quantum) {
  int t = 0;
  while (!q.isEmpty()) {
    Process p = q.poll();
    int run = Math.min(quantum, p.remaining);
    t += run;
    p.remaining -= run;
    if (p.remaining > 0) q.offer(p);
    else System.out.println(p.name + " t=" + t);
  }
}

Code Trace: The Josephus Problem (n = 5, k = 3)

Five people stand in a circle. Each round, the first k − 1 = 2 move to the rear and the 3rd is eliminated. A queue rotates the circle naturally.

i = 1: q.offer(q.poll()) → A moves to the rear.

i = 2: q.offer(q.poll()) → B moves to the rear.

C leaves the front and is eliminated. 4 left.

i = 1: q.offer(q.poll()) → D moves to the rear.

i = 2: q.offer(q.poll()) → E moves to the rear.

A leaves the front and is eliminated. 3 left.

i = 1: q.offer(q.poll()) → B moves to the rear.

i = 2: q.offer(q.poll()) → D moves to the rear.

E leaves the front and is eliminated. 2 left.

i = 1: q.offer(q.poll()) → B moves to the rear.

i = 2: q.offer(q.poll()) → D moves to the rear.

B leaves the front and is eliminated. 1 left.

One person is left: the winner is D. n people, k steps: O(n·k) queue operations.

String josephus(Queue<String> q, int k) {
  while (q.size() > 1) {
    for (int i = 1; i < k; i++)
      q.offer(q.poll());      // front to rear
    String out = q.poll();
    System.out.println(out + " eliminated");
  }
  return q.poll();
}

Example: Binary Numbers from 1 to n

Use a queue to generate the binary representations of the numbers from 1 to n.

Example 1n = 3 → {"1", "10", "11"}
Example 2n = 5 → {"1", "10", "11", "100", "101"}
Idea: x has two successors, x + "0" (2x) and x + "1" (2x + 1). Dequeue a number, output it, and enqueue its successors: the numbers come out level by level, in increasing order (breadth-first).

String[] generateBinary(int n) {
    String[] result = new String[n];
    Queue<String> q = new LinkedList<>();
    q.offer("1");
    for (int i = 0; i < n; i++) {
        result[i] = q.poll();
        q.offer(result[i] + "0");
        q.offer(result[i] + "1");
    }
    return result;
}

outbox.pop() → 3 (FIFO: oldest first).

4: pop from inbox, push onto outbox. The transfer reverses the order; the oldest item ends up on top.

outbox.pop() → 4. Output 1, 2, 3, 4 matches the input order. Each item is transferred at most once → dequeue is amortized O(1) (a single call is O(n) in the worst case).

Deque<Integer> inbox = new ArrayDeque<>();
Deque<Integer> outbox = new ArrayDeque<>();
void enqueue(int x) {
  inbox.push(x);
}
int dequeue() {
  if (outbox.isEmpty())
    while (!inbox.isEmpty())
      outbox.push(inbox.pop());
  return outbox.pop();
}

Common Mistakes

Forgetting rear on the last removalWhen a linked queue loses its last node, front = null; without rear = null, rear points to a removed node.
Mixing up full and emptyWith only front and rear, front == rear both when empty and when full; add a size counter or leave one slot empty.
Arrays.copyOf when growingIt scrambles a circular queue that has wrapped around; copy the items in (front + k) % N order.
add / offer, remove / polladd, remove, and element throw exceptions; offer, poll, and peek return false / null.
PriorityQueue is not FIFOQueue<Integer> q = new PriorityQueue<>() hands out items by priority, not by arrival order.
ArrayDeque and nullArrayDeque rejects null items (NullPointerException); a null would be confused with the “empty” result.
