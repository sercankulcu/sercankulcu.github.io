Multiple Choice · Collection Interfaces

Question 1: Coding to the Interface

Which of these lines does not compile?

Correct: C. List is an interface (it says what can be done), so it cannot be instantiated directly; we need a class that implements it (ArrayList, LinkedList, …). D compiles too: ArrayList also implements Iterable, at the top of the hierarchy. Declaring the variable with the interface type lets us switch implementations by changing one line.

Short Answer · Collection Interfaces

Question 2: Behind the for-each Loop

words is a List<String>. Write the equivalent while loop, using an Iterator, that the compiler turns this for-each loop into.

int count = 0;
for (String s : words)
    if (s.length() > 3) count++;
Show answer 
int count = 0;
Iterator<String> it =
    words.iterator();
while (it.hasNext()) {
    String s = it.next();
    if (s.length() > 3) count++;
}

A for-each loop compiles only if the expression on the right is an array or an object of a class that implements Iterable. For an Iterable, the compiler calls iterator(); for an array, it generates an indexed for loop. Iterable also offers forEach(lambda) and spliterator().

Question 3: A Method Collection Lacks

Given this code, which call does not compile?

Collection<String> c =
    new ArrayList<>(List.of("x", "y"));

Correct: B. Collection defines what lists, sets, and queues share (add/remove, size, contains, stream, toArray, bulk operations) but has no indices. Even though the object is an ArrayList, the compiler looks at the variable's type (Collection); get(i) comes with the List interface.

Question 4: subList Is a View

What does the program print?

List<String> l = new ArrayList<>(
    List.of("A","B","C","D","E","F"));
List<String> sub = l.subList(2, 4);
sub.set(0, "X");
sub.add("Y");
System.out.println(sub + " " + l);
sub.clear();
System.out.println(l);
Show answer 
[X, D, Y] [A, B, X, D, Y, E, F]
[A, B, E, F]
  • subList(2, 4) is the half-open interval [2, 4): C, D. It is not a copy but a view of the original list.
  • sub.set(0, …) → l[2] = X; sub.add("Y") appends to the view, which means inserting at index 4 of l.
  • sub.clear() removes the view's 3 elements from the original list: the short way to delete a range.

Careful: if l itself is structurally modified (add/remove), the old sub becomes invalid; using it throws ConcurrentModificationException.

Question 5: A List Made with List.of

What happens when this code runs?

List<Integer> s = List.of(1, 2);
s.set(0, 5);
System.out.println(s);

Correct: D. List.of builds an immutable list; its type is still List, so set compiles (B is wrong) but is rejected at run time. Not only structural changes but also replacing elements is forbidden. List.of also rejects null elements (NullPointerException).

Question 6: add(i, e) and the Return Value of set

What does the code print?

List<String> l = new ArrayList<>(
    List.of("A", "B", "C"));
l.add(3, "D");
String s = l.set(0, "X");
System.out.println(s + l.size());

Correct: A. The valid indices for add(i, e) are 0 … size, so add(3, …) appends (size 4). D is wrong: only index > size would fail (for get/set/remove the limit is index ≥ size). set replaces the element and returns the old one: "A".

Question 8: Generics and Boxing

Which statement about this code is true?

List<Integer> l = new ArrayList<>();
l.add(null);
int x = l.get(0);

Correct: C. The assignment unboxes: l.get(0).intValue(); the element is null, hence the NPE. B is wrong: a type parameter cannot be primitive, so List<int> is not allowed and List<Integer> is right. Thanks to the type parameter, the result of get needs no cast, so D's error cannot happen.

Question 9: An Indexed Loop on LinkedList

get(i) walks the nodes from the nearer end; steps counts the links walked. What does the program print, and what is the loop's complexity in terms of n?

List<String> list = new LinkedList<>(List.of(
    "A","B","C","D","E","F","G","H"));
int n = list.size(), steps = 0;
for (int i = 0; i < n; i++) {
  String s = list.get(i);
  steps += Math.min(i, n - 1 - i);
}
System.out.println(steps);
Show answer

Output: 12

For i = 0 … 7 the walks are 0, 1, 2, 3 (from the front, i < n/2) and 3, 2, 1, 0 (from the back). Total 12 = n²/4 − n/2 ≈ n²/4 → the loop is O(n²).

Better: for-each, forEach, or an Iterator; each next() follows one link, n − 1 = 7 in total → O(n). On an ArrayList, get(i) is O(1), so the indexed loop is O(n) too.

Question 10: The it.remove() Rule

What happens when this code runs?

List<String> l = new ArrayList<>(
    List.of("A", "B", "C"));
Iterator<String> it = l.iterator();
it.next();
it.next();
it.remove();
it.remove();

Correct: D. remove() deletes the element returned by the last next() and may be called only once per next(); on the second call there is nothing to remove. It does not delete "the one before," as A assumes. NoSuchElementException comes from calling next() when no elements are left.

Short Answer · Traversal

Question 11: Removing Inside for-each

What happens when this code runs? Explain with the hidden Iterator's cursor and its modCount check.

List<Integer> l = new ArrayList<>(
    List.of(1, 2, 3, 4));
for (Integer x : l)
    if (x == 3)
        l.remove(x);
System.out.println(l);
Show answer

Surprisingly, there is no error; the output is [1, 2, 4].

  • x is an Integer, so remove(Object) is called and the value 3 is removed.
  • When 3 is returned, cursor = 3. After the removal size = 3, so hasNext() (cursor ≠ size) is false; next() is never called and the modCount check never happens. 4 is never visited.
  • With x == 2: cursor 2 ≠ size 3 → next() sees the modCount mismatch → ConcurrentModificationException (fail-fast).

The right way: it.remove() or l.removeIf(x -> x == 3).

Question 12: Safe Removal with it.remove()

The code removes the names that start with A. Trace the Iterator's cursor, lastRet, and counters to find the output.

An empty list + three adds: every structural change increments the counter → modCount = 3.

iterator(): the cursor is at the start and nothing has been returned yet; the current count is saved as expected.

hasNext(): cursor 0 ≠ size 3 → true.

next(): 3 == 3 ✓ → "Ada"; cursor = 1, lastRet = 0.

It starts with A → it.remove() deletes the element at lastRet; cursor = 0 (the shifted "Ben" is not skipped), lastRet = −1, expected = modCount = 4.

hasNext(): 0 ≠ 2 → true. next(): 4 == 4 ✓ → "Ben"; cursor = 1, lastRet = 0.

"Ben" doesn't start with A; no removal.

hasNext(): 1 ≠ 2 → true. next() → "Ann"; cursor = 2, lastRet = 1.

it.remove() deletes "Ann"; cursor = 1, lastRet = −1, and the counters are synced again (5).

hasNext(): cursor 1 = size 1 → false; the loop ends without error.

Output [Ben]. Had line 7 said l.remove(s), expected would not be updated, and the next next() → ConcurrentModificationException.

List<String> l = new ArrayList<>();
l.add("Ada"); l.add("Ben"); l.add("Ann");
Iterator<String> it = l.iterator();
while (it.hasNext()) {
  String s = it.next();
  if (s.startsWith("A"))
    it.remove();
}
System.out.println(l);

Question 14: A Two-Way Cursor

What does the code print?

List<String> l = new ArrayList<>(
    List.of("A", "B", "C"));
ListIterator<String> it = l.listIterator(1);
System.out.print(it.previous() + it.next()
    + it.next() + it.nextIndex());

Correct: B. The cursor sits between elements. listIterator(1): A | B C. previous() → A (cursor to the start), next() → A again, next() → B; the cursor is now between B and C, so nextIndex() = 2. Option A comes from assuming that a next after a previous moves on "to the one after." To traverse backward from the end, use listIterator(l.size()).

Question 15: ArrayList Capacity

We add 16 elements, one at a time, to an empty list created with new ArrayList<>(). At which adds does the capacity grow, and to what? How many elements do the resizes copy in total?

Show answer

1st0 → 100 (first array allocated)
11th10 → 1510
16th15 → 2215

25 copies in total; at the end size = 16, capacity = 22. New capacity = old + old/2 (about 1.5 times).

  • The size is the number of elements; the capacity is the length of the internal array, always ≥ size.
  • An add that triggers a resize is O(n), but resizes are rare, so appending is amortized O(1).
  • The capacity does not shrink on removal; trimToSize() brings it down to 16.

Question 16: ArrayList add(i, e) and Growth

The array is [A, B, C, D, E] with capacity 5. After add(2, "X"), what are the array, the capacity, and the number of copies and shifts?

add(2, "X") is called: X goes to index 2.

0 ≤ 2 ≤ size (5) → a valid index (for add, the upper bound is size).

The array is full: new capacity 5 · 3 / 2 = 7 (about 1.5 times); the 5 elements are copied into the new array (O(n)).

k = 5 > 2: data[5] = data[4]. We start from the right so nothing is overwritten.

k = 4 > 2: data[4] = data[3] → D moves right.

k = 3 > 2: data[3] = data[2] → C moves right.

k = 2 > 2 is false → the loop ends. data[2] still holds the old copy of C.

data[2] = X fills the gap.

The result is [A, B, X, C, D, E] with capacity 7: 5 copies + n − i = 3 shifts → O(n).

public void add(int i, E e) {
  Objects.checkIndex(i, size + 1);
  if (size == data.length)
    data = Arrays.copyOf(data, Math.max(size + 1, size*3/2));
  for (int k = size; k > i; k--)
    data[k] = data[k - 1];
  data[i] = e;
  size++;
}

Question 17: A Loop That Inserts at the Front

What is the total running time of this loop when l starts as an empty ArrayList, and when it starts as an empty LinkedList?

for (int i = 0; i < n; i++)
    l.add(0, i);

Correct: D. On an ArrayList, inserting at the front shifts every element one place right: 0 + 1 + … + (n − 1) ≈ n²/2. On a LinkedList, add(0, e) links a node in front of the head with no walking: O(1). The amortized O(1) in A holds only for adding at the end.

Question 18: LinkedList Is a Deque

What does the program print, and which method call on q (not counting the implicit toString in println) does not run in constant time (O(1))?

LinkedList<Integer> q = new LinkedList<>();
q.add(5);
q.addFirst(3);
q.push(1);
q.addLast(7);
q.removeLast();
q.pollFirst();
System.out.println(q + " " + q.get(1));
Show answer

The states: [5] → [3, 5] → push = addFirst → [1, 3, 5] → [1, 3, 5, 7] → removeLast → [1, 3, 5] → pollFirst → [3, 5].

Output: [3, 5] 5

LinkedList is a doubly linked list; it knows first and last, so adding and removing at the ends is O(1). Since it implements Deque as well as List, it can serve as a stack (push/pop) or a queue (offer/poll). The only call that is not O(1) is get(1): it walks the nodes from the nearer end → O(n).

Question 19: The Arrays.asList View

What does the code print?

String[] array = {"a", "b", "c"};
List<String> list = Arrays.asList(array);
list.set(0, "x");
array[2] = "z";
System.out.println(list);

Correct: A. Arrays.asList copies nothing: the list and the array share memory, so changes show up in both directions. B comes from assuming the list is a copy. The list is fixed-size but not immutable: set works, while add/remove throw UnsupportedOperationException. For an independent, growable list, use new ArrayList<>(list).

Question 21: A Position Is Not an Index

L is an empty positional list with sentinels. After this code, what does L read from front to back?

Position<String> p = L.addLast("A");
Position<String> q = L.addLast("B");
L.addFirst("C");
L.addAfter(p, "D");
L.remove(q);
L.addBefore(p, "E");

A position is tied to the element's node, not to an index: addFirst("C") does not change the positions of A and B (D is wrong). [A, B] → [C, A, B] → D after A: [C, A, D, B] → remove B: [C, A, D] → E before A: [C, E, A, D]. Option A treats p and q like indices 0 and 1; B confuses addBefore with addAfter. Every operation is O(1).

Question 22: The Add-If-Absent Race

Threads T1 and T2 run the following line at the same time on an empty Vector<Integer> v. When both are done, which statement is true?

if (!v.contains(7)) v.add(7);

A possible order: T1 contains → false (lock released), T2 contains → false, T1 add(7), T2 add(7) → [7, 7]. synchronized protects a single call, not the gap between two calls (B). There is no iterator, so no CME (C). Each call takes and releases a single lock, so there is no deadlock (D). The fix: synchronized (v) { if (!v.contains(7)) v.add(7); }.

Question 23: A Snapshot Iterator

What does the code print?

List<String> l = new CopyOnWriteArrayList<>(
    List.of("a", "b", "c"));
for (String s : l) {
    if (s.equals("a")) l.add("x");
    if (s.equals("b")) l.remove("c");
    System.out.print(s + " ");
}
System.out.println(l);

The for-each iterator walks the array as it was when the loop began (the snapshot [a, b, c]). add and remove create new copies and leave the old array alone: c is printed even though it was removed, and x never appears. The list ends as [a, b, x]. A and C assume the iterator sees the live list; D would happen with an ArrayList. The price: every write is an O(n) copy.

Question 24: Repeated Removal from the Middle

From a list of n elements we remove n/2 elements in a row, starting at position i = n/2: on a LinkedList by calling remove(n / 2) each time; on a positional list by starting at the middle p and repeating s = after(p); remove(p); p = s;. What are the total costs?

remove(int) first walks to the node; even starting from the nearer end, the distances are n/2, n/2 − 1, … → about n²/8 in total = Θ(n²). Unlinking is O(1), but the walk dominates (A). In a positional list the position is the node itself; after(p) and remove(p) are O(1) → O(n) (B). Nothing is halved, so no log n appears (C).
