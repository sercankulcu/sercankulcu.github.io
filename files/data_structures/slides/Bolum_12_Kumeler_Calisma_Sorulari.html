Soru 2: Set Metotlarıyla Küme Cebri

Programın çıktısı nedir? Kullanılan her metodun hangi küme işlemine karşılık geldiğini belirtiniz.

Set<Integer> a =
    new TreeSet<>(List.of(5, 1, 9, 3, 7));
Set<Integer> b =
    new HashSet<>(List.of(3, 4, 5, 6));
Set<Integer> k = new TreeSet<>(a);
k.retainAll(b);
Set<Integer> f = new TreeSet<>(a);
f.removeAll(b);
Set<Integer> u = new TreeSet<>(a);
u.addAll(b);
System.out.println(k + " " + f + " "
    + u.size() + " " + a.add(3));
Cevabı göster

  • removeAll = fark A − B = [1, 7, 9]
  • addAll = birleşim = [1, 3, 4, 5, 6, 7, 9] → boyut 7
  • 3 zaten a'da: add false döner, küme değişmez.

Çıktı: [3, 5] [1, 7, 9] 7 false

Üç metot da kümeyi yerinde değiştirir; a'yı korumak için önce kopya (new TreeSet<>(a)) alınmıştır. TreeSet olduğu için sonuçlar sıralı yazdırılır.

Soru 4: İlk Tekrar Eden Öğe

Dizide ilk tekrar eden öğeyi (yoksa −1) döndüren int ilkTekrar(int[] a) metodunu HashSet ile O(n) sürede yazınız; add metodunun dönüş değerinden nasıl yararlandığınızı açıklayınız.

Cevabı göster 
int ilkTekrar(int[] a) {
  Set<Integer> gorulen = new HashSet<>();
  for (int x : a)
    if (!gorulen.add(x)) // eklenemedi
      return x;        // zaten vardı
  return -1;
}

add(x) öğe zaten kümedeyse kümeyi değiştirmez ve false döner; ayrıca contains çağırmaya gerek kalmaz.

Örnek: ilkTekrar({3, 8, 1, 8, 3}) → 8 (ikinci kez görülen ilk öğe).

Her öğe için bir ortalama O(1) add → toplam O(n), ek bellek O(n). İç içe döngüyle her çifti karşılaştırmak O(n²) olurdu.

Soru 9: İki İmleçle Birleşim ve Kesişim

Sıralı a = {2, 4, 6, 8} ve b = {1, 4, 5, 8, 9} dizileri için metot bittiğinde bir ve kes listeleri ne olur?

Önce kendiniz tahmin edin, sonra › ile ilerleyin.

İki imleç dizilerin başında. Birleştirme sıralamasındaki merge gibi tek geçiş yapılacak.

a[0] = 2 > b[0] = 1 → 1 yalnızca b'de: birleşime eklenir, j++.

a[0] = 2 < b[1] = 4 → 2 yalnızca a'da: birleşime eklenir, i++.

a[1] = b[1] = 4 → ortak öğe: birleşime bir kez, kesişime de eklenir; iki imleç ilerler.

a[2] = 6 > b[2] = 5 → 5 birleşime eklenir, j++.

a[2] = 6 < b[3] = 8 → 6 birleşime eklenir, i++.

a[3] = b[3] = 8 → ortak öğe; i = 4, j = 4.

i = 4 = a.length → ana döngü biter; a'da kalan yok. Kesişim tamam: artık ortak öğe olamaz.

b'de kalan 9 doğrudan birleşime eklenir.

Sonuç: bir = [1, 2, 4, 5, 6, 8, 9], kes = [4, 8]. Her adımda en az bir imleç ilerler → O(n + m).

void birlesimKesisim(int[] a, int[] b,
    List<Integer> bir, List<Integer> kes) {
  int i = 0, j = 0;
  while (i < a.length && j < b.length) {
    if (a[i] < b[j]) bir.add(a[i++]);
    else if (a[i] > b[j]) bir.add(b[j++]);
    else {                  // ortak öğe
      bir.add(a[i]);  kes.add(a[i]);
      i++;  j++;
    }
  }
  while (i < a.length) bir.add(a[i++]);
  while (j < b.length) bir.add(b[j++]);
}

Soru 10: Kesişimin Maliyeti

|A| = n ve |B| = m öğeli iki sırasız listenin kesişimi (1) iç içe döngüyle, (2) A'yı bir HashSet'e koyup B'yi tarayarak hesaplanıyor. İki yöntemin zaman ve ek bellek maliyetini gerekçesiyle karşılaştırınız.

Cevabı göster
YöntemZamanEk bellek
(1) İç içe döngüO(n · m): B'nin her öğesi için A baştan sona taranırO(1)
(2) HashSetO(n + m) ortalama: n add + m contains, her biri O(1)*O(n)

n = m = 10⁵ için ≈ 10¹⁰ karşılaştırma yerine ≈ 2 · 10⁵ işlem. Hash yaklaşımı belleği zamanla takas eder; kötü hash fonksiyonunda en kötü durum yine O(n · m)'e çıkabilir.

Listeler zaten sıralıysa iki imleç yöntemi ek bellek kullanmadan O(n + m) sürer; sıralı değilse önce sıralamak O(n log n + m log m) ekler.

Soru 11: Hash mi, Ağaç mı?

Aşağıdaki işlemlerden hangisinde hash tabanlı küme, dengeli BST tabanlı kümeden asimptotik olarak daha yavaştır?

Doğru: B. Hash tablosu sıra bilgisi tutmaz; ≤ x olan en büyük öğeyi bulmak için tüm öğeler taranır: O(n). Dengeli BST'de O(log n). contains/add hash'te O(1)*, BST'de O(log n). D çekicidir ama hash ile birleşim O(n + m)*, BST ile O(m log(n + m)): hash yine daha hızlıdır.

Soru 13: Bit Vektörü Ne Zaman Uygun Değil?

Soru 16: Çoklu Eşleme (Multimap)

Ders → öğrenciler çoklu eşlemesi Map<String, List<String>> m ile tutuluyor. put(k, v) ve remove(k, v) metotlarını, liste boşalınca anahtar da silinecek biçimde yazınız.

Cevabı göster 
void put(String k, String v) {
  m.computeIfAbsent(k,
      x -> new ArrayList<>()).add(v);
}
boolean remove(String k, String v) {
  List<String> l = m.get(k);
  if (l == null || !l.remove(v))
    return false;
  if (l.isEmpty()) m.remove(k);
  return true;
}

computeIfAbsent, anahtar yoksa boş liste açar ve onu döndürür; böylece ayrı bir containsKey kontrolü gerekmez.

Maliyet (hash ile): put O(1)*, get O(1)*, remove(k, v) O(1 + liste boyu), çünkü listede v aranır.

Çoklu kümeden farkı: yalnızca kaç kez geçtiği değil, anahtara bağlı değerlerin kendisi tutulur. Java'da hazır multimap sınıfı yoktur.

Soru 18: Quick-Find

id = {0, 1, 2, 3, 4, 5} iken sırasıyla union(0,1), union(2,3), union(1,3), union(4,5) çağrılıyor. Son id dizisi nedir ve toplam kaç id hücresine bakılır?

int find(int p) { return id[p]; }
void union(int p, int q) {
  int pid = id[p], qid = id[q];
  if (pid == qid) return;
  for (int i = 0; i < id.length; i++)
    if (id[i] == pid)
      id[i] = qid;
}
Cevabı göster
İşlempid → qidid
union(0,1)0 → 1[1, 1, 2, 3, 4, 5]
union(2,3)2 → 3[1, 1, 3, 3, 4, 5]
union(1,3)1 → 3[3, 3, 3, 3, 4, 5]
union(4,5)4 → 5[3, 3, 3, 3, 5, 5]

Son durum [3, 3, 3, 3, 5, 5]: kümeler {0, 1, 2, 3} ve {4, 5}.

Her union tüm diziyi tarar: 4 × 6 = 24 hücre. find O(1), ama union O(n); n − 1 union toplam O(n²). Bu yüzden ağaç tabanlı (quick-union) yapıya geçilir.

Soru 21: Rütbe ve Yol Kısaltma

6 öğeli yapıda (ebeveyn[i] = i, sira[i] = 0) koddaki beş union çağrısından sonra ebeveyn ve sira dizileri ne olur?

Önce kendiniz tahmin edin, sonra › ile ilerleyin.

union(0,1): kökler 0 ve 1, rütbeler eşit (0) → ebeveyn[0] = 1, sira[1] = 1.

union(2,3): eşit rütbe → ebeveyn[2] = 3, sira[3] = 1.

union(4,5): eşit rütbe → ebeveyn[4] = 5, sira[5] = 1.

union(1,3): 1 ve 3 zaten kök, rütbeler eşit (1) → ebeveyn[1] = 3, sira[3] = 2.

union(4,0): find(4): ebeveyn[4] = 5 ≠ 4 → find(5); 5 kök. kx = 5 (ebeveyn[4] zaten 5).

find(0): 0 → 1 → 3 yolu boyunca özyineleme; 3 köktür.

Dönüşte yol kısaltma: ebeveyn[0] = 1 → 3. 0 artık doğrudan köke bağlı; ky = 3.

sira[5] = 1 < sira[3] = 2 → alçak ağacın kökü 5, 3'e bağlanır: ebeveyn[5] = 3. Rütbe değişmez.

Sonuç: ebeveyn = [3, 3, 3, 3, 5, 3], sira = [0, 1, 0, 2, 0, 1]; tek küme, kök 3. 4 hâlâ 5 üzerinden bağlı; yolu ilk find(4)'te kısalır.

int find(int x) {
  if (ebeveyn[x] != x)
    ebeveyn[x] = find(ebeveyn[x]);
  return ebeveyn[x];
}
boolean union(int x, int y) {
  int kx = find(x), ky = find(y);
  if (kx == ky) return false;
  if (sira[kx] < sira[ky]) ebeveyn[kx] = ky;
  else if (sira[kx] > sira[ky]) ebeveyn[ky] = kx;
  else { ebeveyn[kx] = ky; sira[ky]++; }
  return true;
}
// union(0,1); union(2,3); union(4,5);
// union(1,3); union(4,0);

Soru 23: En Büyük Rütbe

n = 1000 öğeli bir Union-Find yapısında rütbeye göre birleştirme kullanılıyor. Bir kökün ulaşabileceği en büyük rütbe kaçtır?

Doğru: A. Rütbe yalnızca eşit rütbeli iki ağaç birleşince artar; bu yüzden rütbesi r olan ağaçta en az 2^r öğe vardır. 2^9 = 512 ≤ 1000 < 1024 → en fazla ⌊log₂ 1000⌋ = 9. B çekicidir (⌈log₂ 1000⌉), ama rütbe 10 için en az 1024 öğe gerekir. α(n) rütbeyle değil, amortize işlem maliyetiyle ilgilidir.

Soru 24: Union-Find Karmaşıklığı

n öğe üzerinde m tane find/union işlemi, rütbeye göre birleştirme ve yol kısaltma birlikte kullanılarak yapılıyor. Toplam maliyet nedir?

Bellek: ebeveyn ve sira dizileri, O(n).

Soru 25: Hatalı union

ebeveyn = {0, 1, 2} iken union(0, 1); union(0, 2); çağrılıyor. Bu koddan sonra 0 ile 1 neden aynı kümede değildir; kodu nasıl düzeltirsiniz?

void union(int x, int y) {
  if (find(x) != find(y))
    ebeveyn[x] = y;
}
Cevabı göster
  • union(0, 1): ebeveyn[0] = 1 → {0, 1}.
  • union(0, 2): find(0) = 1 ≠ 2 → ebeveyn[0] = 2. 0'ın 1'e olan bağlantısı koparılır.
  • Sonuç: find(0) = 2, find(1) = 1 → kümeler {0, 2} ve {1}. Oysa üçü aynı kümede olmalıydı.

Hata: kökler yerine öğeler bağlanıyor; x'in eski ebeveyn bağlantısı silinir ve x'in ağacı bölünür.

void union(int x, int y) {
  int kx = find(x), ky = find(y);
  if (kx != ky)
    ebeveyn[kx] = ky;   // kökü bağla
}

Düzeltilmiş kodla ebeveyn = [1, 2, 2]: üç öğenin de kökü 2. Rütbe/boyut kuralı da eklenebilir.

Soru 26: Döngüyle find

Özyineleme kullanmadan yol kısaltma yapan int find(int x) metodunu yazınız ve ebeveyn = [1, 2, 3, 4, 4, 0] için find(5)'in diziyi nasıl değiştirdiğini gösteriniz.

Cevabı göster 
int find(int x) {
  int kok = x;
  while (ebeveyn[kok] != kok)   // 1. tur
    kok = ebeveyn[kok];
  while (ebeveyn[x] != kok) {   // 2. tur
    int sonraki = ebeveyn[x];
    ebeveyn[x] = kok;
    x = sonraki;
  }
  return kok;
}

1. tur kökü bulur: 5 → 0 → 1 → 2 → 3 → 4, kök 4.

2. tur yolu yeniden yürür; her düğümün eski ebeveyni saklanır, sonra ebeveyni köke çevrilir: 5, 0, 1, 2 → 4 (3 zaten 4'e bağlı).

Sonuç: ebeveyn = [4, 4, 4, 4, 4, 4].

Özyineleme olmadığından çok uzun zincirlerde yığın taşması (StackOverflowError) riski yoktur; maliyet yine yol uzunluğuyla orantılıdır.

Soru 28: Bağlantısız Çizgede Kruskal

7 düğümlü ağırlıklı bir çizge, 4 ve 3 düğümlü iki bağlantılı bileşenden oluşuyor. Kruskal algoritması (|T| == n − 1 olunca duran sürüm) kaç kenar seçer ve ne döndürür?

Doğru: B. Her bileşen için (k − 1) kenar seçilir: 3 + 2 = 5 = n − (bileşen sayısı). Bileşenler arasında kenar olmadığından n − 1 = 6'ya hiç ulaşılmaz; tüm kenarlar tarandığında döngü biter. A çekicidir ama kapsayan ağaç yalnızca bağlantılı çizgede vardır.

Soru 30: Kruskal'ın Maliyeti

n düğümlü, m kenarlı bir çizgede Union-Find ile uygulanan Kruskal algoritmasının toplam süresini hangi aşama belirler?

Soru 31: equals Var, hashCode Yok

Ogrenci yalnızca equals'ı (numaraya göre) geçersiz kılıyor. Program pratikte ne yazdırır, neden ve nasıl düzeltilir?

class Ogrenci {
  int no;
  Ogrenci(int no) { this.no = no; }
  @Override public boolean equals(Object o) {
    return o instanceof Ogrenci
        && ((Ogrenci) o).no == no;
  }                           // hashCode yok!
}
Set<Ogrenci> s = new HashSet<>();
s.add(new Ogrenci(7));
s.add(new Ogrenci(7));
System.out.println(s.size() + " "
    + s.contains(new Ogrenci(7)));
Cevabı göster

Çıktı (pratikte): 2 false

HashSet önce hashCode ile kovayı bulur; kovadaki öğelerde de equals'tan önce tam hash kodlarını karşılaştırır ve kodlar farklıysa equals'ı hiç çağırmaz. Varsayılan hashCode nesne kimliğine dayandığı için "eşit" iki öğrencinin kodları farklıdır: aynı kovaya düşseler bile ayrı öğe sayılır ve iki kez saklanır. "1 true" ancak iki kimlik hash'i tesadüfen birebir aynı olursa çıkar.

Sözleşme: a.equals(b) ⇒ a.hashCode() == b.hashCode(); ikisi birlikte ezilir.

@Override public int hashCode() {
  return Integer.hashCode(no);
}  // sonrası çıktı: 1 true

Soru 34: Arkadaş Grupları

Bir sosyal ağda arkadaşlıklar sürekli ekleniyor ve sık sık "A ile B aynı grupta mı?" ve "kaç grup var?" diye soruluyor. Union-Find mı kullanırsınız, yoksa her sorguda BFS/DFS mi çalıştırırsınız? Kararınızı maliyetlerle ve yapının sınırlarıyla (ör. arkadaşlık silinmesi) gerekçelendiriniz.

Örnek cevap ve değerlendirme ölçütleri

Union-Find: her yeni arkadaşlık union(a, b), sorgu find(a) == find(b); rütbe + yol kısaltmayla işlem başına amortize O(α(n)), pratikte sabit. Grup sayısı bir sayaçla tutulur: başta n, başarılı her union'da 1 azalır. Bellek O(n).

BFS/DFS: her sorgu O(n + m); sık sorgu ve sürekli eklemede çok yavaştır. Çizge değişmiyor ve tek seferlik analiz yapılıyorsa yeterlidir.

Sınır: Union-Find kümeleri yalnızca birleştirir, bölemez. Arkadaşlık silinirse grup ikiye ayrılabilir ama yapı bunu ifade edemez. Çözümler: etkilenen bileşeni BFS/DFS ile yeniden hesaplamak, silmeler önceden biliniyorsa işlemleri ters sırada işlemek (silme → ekleme) ya da dinamik bağlılık için daha gelişmiş yapılar.

Değerlendirme: iki yaklaşımın karmaşıklık karşılaştırması · grup sayacının tutulması · Union-Find'ın bölme yapamadığının fark edilmesi · silme için makul bir alternatif.
