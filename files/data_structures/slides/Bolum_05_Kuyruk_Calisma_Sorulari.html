Soru 1: FIFO Sırası

Boş bir kuyruğa sırasıyla enqueue(4), enqueue(7), dequeue(), enqueue(1), enqueue(9), dequeue() uygulanıyor. Sonunda first() ne döndürür?

FIFO: ilk dequeue 4'ü, ikincisi 7'yi çıkarır; kuyruk (önden arkaya) 1, 9 → first() = 1. 9 diyen yığın (LIFO) gibi düşünmüştür: önde son eklenen değil, en eski öğe durur.

Soru 2: Taşma ve Alt Taşma

Kapasitesi 3 olan bir dizi kuyruğunda sırasıyla enqueue(A), dequeue(), dequeue(), enqueue(B), enqueue(C), enqueue(D), enqueue(E), first() çağrılıyor. Hangi çağrılar hata durumuna düşer (adıyla) ve sonunda kuyrukta önden arkaya ne kalır?

Cevabı göster
  • enqueue(A) → [A]; ilk dequeue() → A, kuyruk boş.
  • İkinci dequeue(): boş kuyruktan çıkarma → alt taşma (underflow). Goodrich arayüzü null döndürür; bazı uygulamalar istisna fırlatır.
  • B, C, D eklenir → kuyruk dolu (3/3).
  • enqueue(E): dolu kuyruğa ekleme → taşma (overflow); E eklenmez.

Sonuç: kuyruk B, C, D; first() = B döndürür ama çıkarmaz.

Soru 3: Hata Fırlatan Çağrı

Boş bir Queue<Integer> q = new LinkedList<>() üzerinde hangi çağrı NoSuchElementException fırlatır?

Hata fırlatan üçlü add/remove/element; offer/poll/peek özel değer döndürür: boşta poll ve peek null, offer başarıda true. peek'in de hata vereceğini sanmak yaygındır; istisna fırlatan karşılığı element()'tir.

Soru 4: Java Kuyruğu Çıktısı

Programın çıktısı nedir?

Queue<Integer> q = new ArrayDeque<>();
for (int i = 1; i <= 4; i++)
    q.offer(i * 3);
q.poll();
q.offer(q.poll() + q.peek());
System.out.println(q.peek() + " " + q.size()
                   + " " + q);
while (q.size() > 1)
    q.poll();
System.out.println(q.poll() + " " + q.poll());
Cevabı göster
  • Döngü: [3, 6, 9, 12]; poll() 3'ü çıkarır → [6, 9, 12].
  • Argüman soldan sağa: poll() → 6 (kuyruk [9, 12]), peek() → 9; 15 arkaya eklenir → [9, 12, 15].
  • Önde 9, boyut 3.
  • while 9 ve 12'yi atar; sonra poll() → 15, kuyruk boş olduğundan ikinci poll() → null (istisna yok).

Çıktı:

9 3 [9, 12, 15]
15 null

Soru 5: Kuyruğun Kullanım Alanları

Aşağıdakilerden hangisinde kuyruk (FIFO) uygun yapı değildir?

Geri al, en son yapılan işlemi önce geri almalıdır: LIFO, yani yığın. BFS ise kuyruk kullanır: keşfedilen düğümler sıraya alınır ve seviye seviye gezilir (yığın kullanan DFS'dir). Yazdırma ve tamponlarda da önce gelen önce işlenir.

Soru 6: Basit Dizi Kuyruğunun Sorunu

Kapasitesi N = 6 olan basit (dairesel olmayan) dizi kuyruğu on = 0, arka = −1 ile başlıyor. enqueue 10, 20, 30, 40; üç kez dequeue(); enqueue 50, 60 yapılıyor. Son durumda on ve arka nedir ve ardından gelen enqueue(70) neden yapılamaz?

Cevabı göster
  • Eklemede arka++, çıkarmada on++; öğeler kaydırılmaz.
  • Dört ekleme → arka = 3; üç çıkarma (10, 20, 30) → on = 3; 50 ve 60 → arka = 5.
  • Son durum: on = 3, arka = 5; kuyruk 40, 50, 60 (yalnızca 3 öğe).
  • arka = N − 1 olduğu için kuyruk “dolu” görünür; oysa indis 0–2 boştur ve basit dizi kuyruğu boşalan yuvaları yeniden kullanamaz.

Çözüm 1: her dequeue'da öğeleri sola kaydırmak → dequeue O(n). Çözüm 2: dairesel dizi, indis (i + 1) % N ile başa sarar → her işlem O(1).

Soru 7: Ekleme İndisi

Dairesel kuyruk bas (ilk öğenin indisi), boyut (öğe sayısı) ve N = dizi.length ile tutuluyor. ekle() yeni öğeyi hangi indise yazar?

Son öğeden sonraki yuva bas + boyut'tur; % N dizinin sonundan başa sarmayı sağlar. (bas + boyut − 1) % N son öğenin kendisidir; mod'suz A ise dizinin dışına taşabilir (ArrayIndexOutOfBoundsException). D, dequeue sonrası yeni bas'tır.

Soru 9: Bir Yuvayı Boş Bırakma

Dairesel kuyrukta sayaç tutulmuyor; “bir yuvayı boş bırakma” yöntemi kullanılıyor (bas: ilk öğe, arka: sonraki yazma yeri). N = 10 ise kuyruk en fazla kaç öğe saklar ve dolu koşulu nedir?

bas == arka boş koşuludur; dolu ile karışmaması için bir yuva hep boş bırakılır → N − 1 = 9 öğe. Yalnızca bas ve arka ile 10 öğe saklanırsa (A) boş ve dolu kuyrukta ikisi aynı yuvayı gösterir; durumlar ayırt edilemez. Diğer çözüm boyut sayacıdır (dolu: boyut == N).

Soru 11: Dairesel Kuyrukta Başa Sarma

Kapasitesi 4 olan dairesel kuyrukta son satırdaki cikar() ne yazdırır ve sonunda bas ile boyut kaç olur?

Önce kendiniz tahmin edin, sonra › ile ilerleyin.

Dizi 0'larla dolu ama mantıksal olarak boş.

ekle(10): indis (0 + 0) % 4 = 0.

ekle(20): indis (0 + 1) % 4 = 1.

ekle(30): indis (0 + 2) % 4 = 2.

cikar() → 10; bas 0 → 1. Değer dizide kalır ama artık kuyrukta değildir.

cikar() → 20; bas 1 → 2. Değer dizide kalır ama artık kuyrukta değildir.

ekle(40): indis (2 + 1) % 4 = 3.

ekle(50): indis (2 + 2) % 4 = 0. Dizinin sonu geçildi, başa sarıldı.

ekle(60): indis (2 + 3) % 4 = 1. Dizinin sonu geçildi, başa sarıldı. Kuyruk doldu.

cikar() → 30 yazdırılır (en eski öğe). Son durum: bas = 3, boyut = 3; kuyruk 40, 50, 60.

int[] d = new int[4];
int bas = 0, boyut = 0;
void ekle(int x) {
    d[(bas + boyut) % d.length] = x;
    boyut++;
}
int cikar() {
    int x = d[bas];
    bas = (bas + 1) % d.length;
    boyut--;
    return x;
}

Soru 12: cikar() İçinde null Atama

İşaretli dizi[bas] = null; satırı silinirse kuyruğun döndürdüğü sonuçlar değişir mi; bu satır neden yazılır?

public E cikar() {
    if (bosMu())
        throw new IllegalStateException("boş");
    E oge = dizi[bas];
    dizi[bas] = null;          // ← bu satır
    bas = (bas + 1) % dizi.length;
    boyut--;
    return oge;
}
Cevabı göster

Sonuçlar değişmez. Boş/dolu kararını boyut verir; dizi[bas] artık mantıksal olarak kuyruğun dışındadır ve sonraki bir ekle o yuvanın üzerine yazar.

Neden yazılır? Satır yoksa dizi, çıkarılan nesneye referans tutmaya devam eder. Yuva yeniden yazılana kadar çöp toplayıcı o nesneyi serbest bırakamaz; büyük nesnelerde bu bir bellek sızıntısı gibi davranır. null atamak “referansı bırakır”; maliyet yine O(1)'dir.

Soru 13: Dolu Kuyruğu Büyütme

Dolu dairesel kuyrukta dizi = [F, G, C, D, E], bas = 2, boyut = 5. ekle(H) çağrısından sonra dizi, bas ve boyut ne olur?

private void buyut(int yeniKap) {
  E[] yeni = (E[]) new Object[yeniKap];
  for (int k = 0; k < boyut; k++)
    yeni[k] = dizi[(bas + k) % dizi.length];
  dizi = yeni;
  bas = 0;
}
public void ekle(E oge) {
  if (boyut == dizi.length)
    buyut(2 * dizi.length);
  dizi[(bas + boyut) % dizi.length] = oge;
  boyut++;
}
Cevabı göster
  • boyut == 5 → buyut(10).
  • k = 0..4: dizi[2] = C, dizi[3] = D, dizi[4] = E, dizi[0] = F, dizi[1] = G → yeni[0..4] = C, D, E, F, G; bas = 0.
  • H: (0 + 5) % 10 = 5 → dizi[5] = H; boyut = 6.

Sonuç: [C, D, E, F, G, H, _, _, _, _], bas = 0, boyut = 6. Kopyalama mantıksal sırayla yapıldığı için sıra korunur. Büyütme O(n) sürer, ama kapasite iki katına çıktığından ekle amortize O(1)'dir.

Soru 14: Büyütmede Arrays.copyOf

Dolu kuyrukta dizi = [C, D, A, B], bas = 2 (sıra A, B, C, D). Büyütme yandaki satırla yapılıyor ve bas değişmiyor. ekle(E)'den sonra beş kez cikar() sırasıyla ne döndürür?

// buyut() yerine yazılan satır
dizi = Arrays.copyOf(dizi, 2 * dizi.length);
// bas = 2 olarak kalır

copyOf öğeleri aynı indislere kopyalar: [C, D, A, B, _, _, _, _], bas = 2. E, (2 + 4) % 8 = 6'ya yazılır; cikar dizi[2..6]'yı okur: A, B, null, null, E. Başa sarmış C ve D kaybolur. A şıkkı, öğeleri (bas + k) % N sırasıyla kopyalayan doğru buyut'un sonucudur.

Soru 15: Ekleme Sona, Çıkarma Baştan

Tek yönlü bağlı liste ile kuyrukta (on ve arka referanslarıyla) neden ekleme sona, çıkarma baştan yapılır?

Ters yönde (başa ekle, sondan çıkar) de FIFO korunur (D yanlış), ama sondan çıkarmak için yeni arkayı, yani sondan bir önceki düğümü baştan gezerek bulmak gerekir: O(n). Başa ekleme de O(1)'dir (B yanlış). Önerilen yönde iki işlem de O(1).

Soru 16: enqueue Hatası

Bağlı liste kuyruğunun bu enqueue metodunda bir hata var. Boş kuyrukta enqueue(10), enqueue(15) çağrılınca ne olur ve metot nasıl düzeltilir?

public void enqueue(int veri) {
    Dugum gecici = new Dugum(veri);
    if (bosMu()) {
        on = gecici;
    } else {
        arka.sonraki = gecici;
    }
    uzunluk++;
}
Cevabı göster
  • enqueue(10): kuyruk boş → on = düğüm(10); arka hiç atanmadığı için null kalır.
  • enqueue(15): boş değil → arka.sonraki erişimi → NullPointerException.

Düzeltme: if/else'ten sonra yeni düğüm her iki durumda da arka olmalı:

    }
    arka = gecici;      // eklendi
    uzunluk++;

Liste gezinilmediği için her enqueue O(1).

Soru 17: Son Öğede arka

Bu dequeue'da if (on == null) arka = null; satırı unutulmuştur. Boş kuyrukta enqueue(7); dequeue(); rear(); çağrılırsa rear() ne yapar, doğrusu ne olmalıydı?

public int dequeue() {
    if (bosMu())
        throw new NoSuchElementException();
    int sonuc = on.veri;
    on = on.sonraki;
    uzunluk--;
    return sonuc;
}
public int rear() {
    if (arka == null)
        throw new NoSuchElementException();
    return arka.veri;
}
Cevabı göster

dequeue sonrası on = null, uzunluk = 0, ama arka hâlâ silinen düğüm(7)'yi gösterir.

rear() → 7 döndürür: kuyruk boşken var olmayan bir öğe (tutarsız durum). Doğrusu NoSuchElementException fırlatmasıydı. Ayrıca silinen düğüme referans kaldığı için bellekten atılamaz.

Düzeltme: on = on.sonraki; satırından sonra if (on == null) arka = null;. Son öğe çıkınca iki uç birlikte null olmalıdır.

Soru 19: Akış Tamponu Tasarımı

Bir video oynatıcısı ağdan gelen paketleri oynatma hızında tüketmek üzere bir kuyrukta biriktiriyor (üretici-tüketici tamponu). Bu tampon için dairesel dizi mi bağlı liste mi seçersiniz ve tampon dolduğunda ne yapılmalıdır? Gerekçelendirin.

Örnek cevap ve değerlendirme ölçütleri

Yapı: Dairesel dizi (halka tampon). Bellek önceden ayrılır ve üst sınırlıdır, ardışık olduğu için önbellek dostudur, paket başına düğüm nesnesi oluşmaz; enqueue/dequeue O(1). Bağlı liste sınırsız büyür: üretici hızlıysa bellek tükenebilir, her pakette nesne oluşturma ve çöp toplama yükü vardır.

Dolunca: (1) üreticiyi beklet (geri basınç), (2) en eski paketi at (canlı yayında gecikmeyi sınırlar), (3) yeni paketi at, (4) büyüt (amortize O(1) ama bellek sınırsızlaşır). Canlı yayında 2, veri kaybının kabul edilemediği indirmede 1 uygundur.

Değerlendirme: tamponun FIFO rolünü ve hız farkını dengelediğini açıklama · dizi/liste ödünleşimi (kapasite, bellek, önbellek) · taşma (overflow) politikası ve gerekçesi · işlemlerin O(1) olduğunun belirtilmesi.

Soru 20: Kuyruk Türleri

Ekleme yalnızca arka uçtan, çıkarma ise hem önden hem arkadan yapılabilen kuyruk türü hangisidir?

Kısıt girişe (eklemeye) konmuştur: giriş sınırlı deque. Çıkış sınırlı deque'de ise ekleme iki uçtan, çıkarma yalnızca önden yapılır; ad, hangi işlemin kısıtlandığını söyler. Dairesel kuyruk basit kuyruk gibi arkaya ekler, önden çıkarır.

Soru 23: Sıralı Dizinin Maliyeti

Öncelikleri büyükten küçüğe sıralı tutan dizi gerçeklemesinde ekle ve cikar en kötü durumda neden O(n)'dir; cikar'ı O(1) yapmak için dizi nasıl tutulabilir?

Cevabı göster
  • ekle: yeni öğe tüm öğelerden yüksek öncelikliyse n öğenin hepsi bir sağa kayar → O(n).
  • cikar: en yüksek öncelik dizi[0]'dadır; alındıktan sonra kalan n − 1 öğe bir sola kaydırılır → O(n). (Öndeki öğeye bakmak O(1).)
  • İyileştirme: dizi küçükten büyüğe sıralı tutulursa en yüksek öncelik sondadır; dizi[--boyut] ile kaydırmasız O(1) çıkarılır. Ekleme yine O(n) kalır.

İkisini birden O(log n) yapan yapı heap'tir (Bölüm 8).

Soru 24: Deque Çıktısı

ArrayDeque çift uçlu kuyruktur; push/pop baş uçta çalışır. Programın çıktısı nedir?

Deque<String> d = new ArrayDeque<>();
d.offerFirst("A");
d.offerLast("B");
d.push("C");
d.addLast("D");
System.out.print(d.pollLast() + " ");
System.out.print(d.pop() + " ");
d.offerFirst("E");
System.out.print(d.peekLast() + " " + d);
Cevabı göster
  • offerFirst A → [A]; offerLast B → [A, B]
  • push = addFirst → [C, A, B]; addLast D → [C, A, B, D]
  • pollLast → D; pop = removeFirst → C; deque [A, B]
  • offerFirst E → [E, A, B]; peekLast → B (çıkarmaz)

Çıktı: D C B [E, A, B]

Deque FIFO'ya bağlı değildir: yalnızca bir uçtan kullanılırsa yığın, bir uçtan ekleyip diğerinden çıkarılırsa kuyruk olur.

Soru 27: Kayan Pencere Maksimumu

a = {4, 2, 1, 3, 6, 2, 1} için pencereMax(a, 3) ne döndürür?

int[] pencereMax(int[] a, int k) {
  int[] enb = new int[a.length - k + 1];
  Deque<Integer> d = new ArrayDeque<>();
  for (int i = 0; i < a.length; i++) {
    if (!d.isEmpty()
        && d.peekFirst() <= i - k)
      d.pollFirst();   // pencere dışı
    while (!d.isEmpty()
           && a[d.peekLast()] <= a[i])
      d.pollLast();    // aday değil
    d.offerLast(i);
    if (i >= k - 1)
      enb[i - k + 1] = a[d.peekFirst()];
  }
  return enb;
}

Soru 29: Josephus Problemi

Kuyrukta önden arkaya A, B, C, D, E, F varken josephus(q, 2) hangi sırayla eleme yapar ve kimi döndürür?

Önce kendiniz tahmin edin, sonra › ile ilerleyin.

size 6 > 1 → tur başlar. i = 1: A önden alınıp arkaya geçer.

Öndeki B çıkarılır ve elenir. Kalan: 5 kişi.

size 5 > 1 → tur başlar. i = 1: C önden alınıp arkaya geçer.

Öndeki D çıkarılır ve elenir. Kalan: 4 kişi.

size 4 > 1 → tur başlar. i = 1: E önden alınıp arkaya geçer.

Öndeki F çıkarılır ve elenir. Kalan: 3 kişi.

size 3 > 1 → tur başlar. i = 1: A önden alınıp arkaya geçer.

Öndeki C çıkarılır ve elenir. Kalan: 2 kişi.

size 2 > 1 → tur başlar. i = 1: E önden alınıp arkaya geçer.

Öndeki A çıkarılır ve elenir. Kalan: 1 kişi.

size 1 → döngü biter; return E. Eleme sırası B, D, F, C, A; kazanan E. n − 1 tur, her tur k kuyruk işlemi: O(n·k).

String josephus(Queue<String> q, int k) {
  while (q.size() > 1) {
    for (int i = 1; i < k; i++)
      q.offer(q.poll()); // arkaya
    String elenen = q.poll();
    System.out.println(elenen + " elendi");
  }
  return q.poll();
}

Soru 30: Acil Serviste Sıra

Bir acil servis hastaları üç aciliyet seviyesine ayırıyor. Hastaları çağırma sırası için bir kuyruk yapısı tasarlayın ve düşük aciliyetli hastaların hiç çağrılmaması (açlık, starvation) sorununu nasıl önleyeceğinizi açıklayın.

Örnek cevap ve değerlendirme ölçütleri

Yapı: Tek FIFO kuyruğu yalnızca geliş sırasını bilir, aciliyeti bilmez. Seviye başına bir FIFO kuyruk tutulur (öncelikli zamanlayıcıdaki gibi): her seferinde en yüksek seviyeli, boş olmayan kuyruğun önündeki hasta çağrılır; seviye içinde geliş sırası korunur. Alternatif: anahtarı (aciliyet, geliş no) olan öncelikli kuyruk; geliş numarası eşitlerde FIFO'yu sağlar.

Açlık: Yüksek seviyeye sürekli hasta gelirse alttakiler hiç çağrılmayabilir. Çözüm yaşlandırma (aging): bekleme süresi bir eşiği aşan hasta bir üst seviyeye taşınır. Ek olarak azami bekleme süresi veya oran kuralı (ör. 3 yüksek, 1 düşük) uygulanabilir.

Değerlendirme: FIFO'nun sınırını açıklama · uygun yapı (çok seviyeli kuyruk ya da öncelikli kuyruk) · eşit öncelikte adalet · açlığa karşı somut kural (aging).

Soru 32: İki Yığınla Kuyruk

Yorumdaki işlemler sonunda ne yazdırılır ve toplam kaç öğe gelen'den giden'e aktarılır?

Önce kendiniz tahmin edin, sonra › ile ilerleyin.

enqueue(1): gelen.push(1) → O(1).

enqueue(2): gelen.push(2); üst solda.

dequeue: giden boş → gelen'deki 2 ve 1 aktarılır. Aktarım sırayı ters çevirir; en eski öğe (1) üste çıkar.

giden.pop() → 1 yazdırılır (FIFO).

enqueue(3): gelen.push(3). giden'deki 2'ye dokunulmaz.

dequeue: giden boş değil → aktarım yok; giden.pop() → 2.

dequeue: giden boş → gelen'deki 3 aktarılır.

giden.pop() → 3. Çıktı 1 2 3 = giriş sırası; toplam 3 aktarım. Her öğe en çok bir kez aktarılır → dequeue amortize O(1) (tek çağrı en kötü O(n)).

Deque<Integer> gelen = new ArrayDeque<>();
Deque<Integer> giden = new ArrayDeque<>();
void enqueue(int x) {
  gelen.push(x);
}
int dequeue() {
  if (giden.isEmpty())
    while (!gelen.isEmpty())
      giden.push(gelen.pop());
  return giden.pop();
}

Soru 34: ArrayDeque ve null

Queue<String> q = new ArrayDeque<>(); q.offer(null); çalıştırıldığında ne olur?

Soru 35: Deque ile Palindrom

Bir dizenin palindrom (tersten de aynı okunan, ör. “kayak”) olup olmadığını Deque<Character> kullanarak kontrol eden palindromMu(String s) metodunu yazın; karmaşıklığı nedir?

Cevabı göster 
boolean palindromMu(String s) {
    Deque<Character> d = new ArrayDeque<>();
    for (char c : s.toCharArray())
        d.offerLast(c);
    while (d.size() > 1)
        if (!d.pollFirst().equals(d.pollLast()))
            return false;
    return true;
}

Harfler sırayla eklenir; iki uçtan birer harf çıkarılıp karşılaştırılır. “kayak” → true, “kalem” → false. Her harf bir kez girer, bir kez çıkar: O(n) zaman, O(n) ek bellek. Kutulu Character karşılaştırmasında == yerine equals kullanılır.
