Java'da Bellek: Yığın ve Heap

  • İlkel değişken değeri doğrudan tutar.
  • Referans değişken, heap'teki nesnenin adresini tutar; new nesneyi heap'te oluşturur.
  • Her metot çağrısı yığında bir çerçeve açar; yerel değişkenler oradadır, dönüşte silinir.
  • Erişilemeyen nesneleri çöp toplayıcı temizler; p[0] → NullPointerException.

Kod İzleme: Değer mi, Referans mı?

x = 5: ilkel değişken, değer doğrudan çerçevededir.

y = x: değerin kopyası alınır; x ile y birbirinden bağımsızdır.

y = 7: yalnız y değişti; x hâlâ 5.

Dizi heap'te oluşturulur; a yalnızca ona bir referans (ok) tutar.

b = a: dizi kopyalanmaz, referans kopyalanır. İki ok aynı nesneyi gösterir.

b[0] = 9: nesnenin kendisi değişti → a[0] de 9 görünür (takma ad, aliasing).

b = new int[2]: b artık yeni nesneyi gösterir; a etkilenmez. Yeni dizi 0 ile dolar.

Çıktı 5 9. Kural: = ilkel tipte değeri, referans tipte adresi kopyalar.

Bir Gerçekleştirim: DiziYigin

public class DiziYigin<E> implements Yigin<E> {
  private E[] veri;         // öğeler
  private int t = -1;       // üst öğenin indisi
  public DiziYigin(int kapasite) {
    veri = (E[]) new Object[kapasite];
  }
  public int size() { return t + 1; }
  public boolean isEmpty() { return t == -1; }
  public E top() {
    if (isEmpty()) return null;
    return veri[t];
  }
  // push ve pop: sonraki slaytta adım adım
}
İşlemSüre
size, isEmpty, topO(1)
push, popO(1)
BellekO(N) (kapasite)
  • Java'da jenerik dizi doğrudan oluşturulamaz: (E[]) new Object[..].
  • Kapasite sabit: dolunca push hata fırlatır.

Veri Yapılarına Giriş · Kodu adım adım çalıştır

Kod İzleme: push / pop

y, kapasitesi 4 olan boş bir DiziYigin (t = −1). push(5) çağrılır.

size() = 0 ≠ 4 → dolu değil.

++t → t = 0, sonra veri[0] = 5. Önce artır, sonra yaz.

push(8) çağrılır.

size() = 1 ≠ 4 → dolu değil.

++t → t = 1, sonra veri[1] = 8. Önce artır, sonra yaz.

pop() çağrılır; dönen değer yazdırılacak.

t = 1 → boş değil, devam.

e = veri[1] = 8: en son eklenen öğe (LIFO).

Hücre null yapılır (nesne serbest kalsın), t-- → t = 0.

return 8: çerçeve kapanır.

Ekrana 8 yazılır.

push(3): boşalan 1 numaralı hücre yeniden kullanılacak.

size() = 1 ≠ 4 → dolu değil.

++t → t = 1, sonra veri[1] = 3. Önce artır, sonra yaz.

Son durum: [5, 3], t = 1. Her işlem n'den bağımsız, sabit sayıda adım → O(1).

public void push(E e) {
  if (size() == veri.length)
    throw new IllegalStateException("dolu");
  veri[++t] = e;
}
public E pop() {
  if (isEmpty()) return null;
  E e = veri[t];
  veri[t--] = null;     // GC için boşalt
  return e;
}
y.push(5); y.push(8);
System.out.println(y.pop());
y.push(3);

Deneysel Analiz: System.nanoTime()

for (int n = 1000; n <= 64000; n *= 2) {
  int[] a = new int[n];
  for (int i = 0; i < n; i++) a[i] = i; // tekrarsız
  long bas = System.nanoTime();
  tekrarVar(a);                        // ölçülen iş
  long sure = System.nanoTime() - bas;  // ns
  System.out.println(n + " " + sure / 1e6 + " ms");
}
ÖlçSystem.nanoTime() iki okuma arasındaki farkı ns cinsinden verir (duvar saati değil).
TekrarlaJIT ısınması, çöp toplayıcı ve diğer süreçler gürültü yapar: birkaç kez çalıştır, medyanı al.
ÇizSüreyi n'ye karşı çiz; n'yi ikiye katlayınca sürenin kaç katına çıktığına bak.
Dikkat: new int[n] sıfırlarla dolar → tekrarVar (tekrar arayan O(n²) metot, ileride) ilk karşılaştırmada true döner. En kötü durumu ölçmek için tekrarsız veri gerekir.

İlkel İşlemleri Sayma: maksimum()

int maksimum(int[] a) {
  int enBuyuk = a[0];
  for (int i = 1; i < a.length; i++) {
    if (a[i] > enBuyuk)
      enBuyuk = a[i];

Algoritma Analizi

Zaman Karmaşıklığı ve Büyük O (Big O)

  • Algoritmanın ne kadar sürede çalıştığını, girdi boyutu n'ye bağlı olarak ifade eder.
  • Büyük O gösterimi, çalışma süresi için bir üst sınır belirtir; genellikle en kötü durum için kullanılır.
  • O(1): işlem sayısı girdi boyutuyla büyümez; farklı girdilerde süre birebir aynı olmak zorunda değildir.
  • O(n): girdi büyüdükçe süre doğrusal olarak artar.
Büyük O'da yalnızca en hızlı büyüyen terim önemlidir; sabitler ve küçük terimler atılır:
3n2 + 5n + 2 → O(n2)  ·  4n + 100 → O(n)  ·  7 → O(1)

Algoritma Analizi · Asimptotik gösterim

O, Ω ve Θ: Tanım ve Grafik

Tanım: f(n) = O(g(n)) ⇔ öyle c > 0 ve n₀ ≥ 1 vardır ki her n ≥ n₀ için f(n) ≤ c·g(n). Ω için ≥, Θ için ikisi birden.

Büyük O: n ≥ n₀ = 5 için 2n + 10 ≤ 4·n → f(n) = O(n) (c = 4). Küçük n'de (n < 5) f(n) daha büyük; önemli değil.

Büyük Omega: her n ≥ 1 için 2n + 10 ≥ 2·n → f(n) = Ω(n): f, n'den daha yavaş büyümez (alt sınır).

Büyük Teta: n ≥ 5 için 2n ≤ f(n) ≤ 4n → f(n) = Θ(n): iki doğru arasına sıkışır, büyüme hızı tam olarak n.

Kod İzleme: dogrusalArama(a, 23)

Sıralı bir dizide 23 aranıyor; doğrusal arama sıralı olmayı kullanmaz, baştan tek tek bakar.

Algoritma Analizi · Kodu adım adım çalıştır

Kod İzleme: ikiliArama(a, 23)

Arama aralığı tüm dizi: lo = 0, hi = 9.

0 ≤ 9 → aralık boş değil, 1. tur başlar.

mid = (0 + 9) / 2 = 4, a[4] = 16.

16 < 23 → hedef sağ yarıda: lo = mid + 1 = 5. Sol yarı elendi.

5 ≤ 9 → aralık boş değil, 2. tur başlar.

mid = (5 + 9) / 2 = 7, a[7] = 56.

56 > 23 → hedef sol yarıda: hi = mid − 1 = 6. Sağ yarı elendi.

5 ≤ 6 → aralık boş değil, 3. tur başlar.

mid = (5 + 6) / 2 = 5, a[5] = 23.

23 == 23 → bulundu, return 5. Yalnızca 3 tur; doğrusal arama 6 karşılaştırma yapardı. Her tur aralığı yarıya indirir → O(log n).

int ikiliArama(int[] a, int hedef) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = (lo + hi) / 2;
        if (a[mid] == hedef) return mid;
        if (a[mid] < hedef) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

Algoritma Analizi · Aynı problem, iki algoritma

Örnek Problem: Önek Ortalamaları

Girdi x[0..n−1]; çıktı a[j] = (x[0] + … + x[j]) / (j + 1). Kullanım: hareketli ortalama, finansal eğilim analizi (Goodrich §4.3).

a[0] = x[0] … x[0] öğelerinin ortalaması = 4.0.

a[1] = x[0] … x[1] öğelerinin ortalaması = 6.0.

a[2] = x[0] … x[2] öğelerinin ortalaması = 6.0.

a[3] = x[0] … x[3] öğelerinin ortalaması = 5.0.

İki çözüm izleyeceğiz: her j için baştan topla (O(n²)) · birikimli toplamı taşı (O(n)).

Algoritma Analizi · Kodu adım adım çalıştır

Kod İzleme: onekOrt1 — her j için baştan topla

n = 4; sonuç dizisi a oluşturulur (0.0 ile dolu).

j = 0: top = 0 — her j için toplam baştan başlar.

top += x[0] = 4 → top = 4.0.

a[0] = 4.0 / 1 = 4.0.

j = 1: top = 0 — her j için toplam baştan başlar.

top += x[0] = 4 → top = 4.0.

top += x[1] = 8 → top = 12.0.

a[1] = 12.0 / 2 = 6.0.

j = 2: top = 0 — her j için toplam baştan başlar.

top += x[0] = 4 → top = 4.0.

top += x[1] = 8 → top = 12.0.

top += x[2] = 6 → top = 18.0.

a[2] = 18.0 / 3 = 6.0.

j = 3: top = 0 — her j için toplam baştan başlar.

top += x[0] = 4 → top = 4.0.

top += x[1] = 8 → top = 12.0.

top += x[2] = 6 → top = 18.0.

top += x[3] = 2 → top = 20.0.

a[3] = 20.0 / 4 = 5.0.

return a. Toplama sayısı 1 + 2 + 3 + 4 = 10 = n(n+1)/2 → O(n²).

double[] onekOrt1(double[] x) {
  int n = x.length;
  double[] a = new double[n];
  for (int j = 0; j < n; j++) {
    double top = 0;
    for (int i = 0; i <= j; i++)
      top += x[i];
    a[j] = top / (j + 1);
  }
  return a;
}

Algoritma Analizi · Kodu adım adım çalıştır

Kod İzleme: onekOrt2 — birikimli toplam

top döngüden önce bir kez sıfırlanır ve turlar boyunca korunur.

j = 0: top += x[0] = 4 → top = 4.0 (önceki toplam yeniden kullanıldı).

a[0] = 4.0 / 1 = 4.0.

j = 1: top += x[1] = 8 → top = 12.0 (önceki toplam yeniden kullanıldı).

a[1] = 12.0 / 2 = 6.0.

j = 2: top += x[2] = 6 → top = 18.0 (önceki toplam yeniden kullanıldı).

a[2] = 18.0 / 3 = 6.0.

j = 3: top += x[3] = 2 → top = 20.0 (önceki toplam yeniden kullanıldı).

a[3] = 20.0 / 4 = 5.0.

Aynı sonuç, yalnız 4 toplama (onekOrt1: 10). Tek döngü → O(n).

double[] onekOrt2(double[] x) {
  int n = x.length;
  double[] a = new double[n];
  double top = 0;
  for (int j = 0; j < n; j++) {
    top += x[j];
    a[j] = top / (j + 1);
  }
  return a;
}

Algoritma Analizi · Özyineleme

Özyineleme (Recursion)

n! = 1 (n ≤ 1) · n! = n · (n − 1)! (n > 1)
  • Özyineleme: bir metodun kendini daha küçük bir girdiyle çağırması.
  • Taban durum (base case): özyinelemesiz, doğrudan çözülür. Olmazsa çağrılar bitmez → StackOverflowError.
  • Özyinelemeli durum: problemi küçültür, tabana yaklaştırır.
  • Her çağrı çağrı yığınında yeni bir çerçeve açar (kendi n'si).

Algoritma Analizi · Kodu adım adım çalıştır

Kod İzleme: faktoriyel(4) ve çağrı yığını

main, faktoriyel(4)'ü çağırır.

Yeni çerçeve: n = 4. 4 ≤ 1 mi? Hayır.

4 · faktoriyel(3): çarpım için önce faktoriyel(3) bitmeli; bu çerçeve bekler.

Yeni çerçeve: n = 3. 3 ≤ 1 mi? Hayır.

3 · faktoriyel(2): çarpım için önce faktoriyel(2) bitmeli; bu çerçeve bekler.

Yeni çerçeve: n = 2. 2 ≤ 1 mi? Hayır.

2 · faktoriyel(1): çarpım için önce faktoriyel(1) bitmeli; bu çerçeve bekler.

Yeni çerçeve: n = 1. 1 ≤ 1 mi? Evet.

Taban durum: return 1. Artık çağrı yok; değerler geri dönmeye başlar.

faktoriyel(1) = 1 döndü → 2 · 1 = 2, return 2.

faktoriyel(2) = 2 döndü → 3 · 2 = 6, return 6.

faktoriyel(3) = 6 döndü → 4 · 6 = 24, return 24.

Ekrana 24. 4 çağrı, yığın derinliği en fazla 4 + main → zaman ve bellek O(n).

int faktoriyel(int n) {
  if (n <= 1)
    return 1;               // taban durum
  return n * faktoriyel(n - 1);
}

Sık Yapılan Hatalar

“O(1) her zaman hızlıdır”Sabit ama büyük olabilir; küçük n'de 1000·n'lik algoritma, n²'lik olandan yavaş kalabilir.
“İç içe döngü = n²”İç döngü j *= 2 ile ilerliyorsa n log n; sabit sayıda dönüyorsa O(n).
“log tabanı önemlidir”log₂ n ile log₁₀ n arasında yalnız sabit çarpan var: ikisi de O(log n).

Temel Veri Yapıları

Diziler (Arrays)

  • Verileri ardışık olarak bir bellek bloğunda saklar.
  • Tüm öğeler aynı türdedir ve bellekte eşit boyutta yer kaplar.
  • Her öğeye indisiyle doğrudan erişilir: adres = başlangıç + i × öğe boyutu
  • Verileri düzenli saklamak ve hızlı erişim sağlamak için kullanışlı bir veri yapısıdır.
Bir hücreye tıkla: üst sıra indis, alt sıra değer.
int[] a = {7, 2, 9, 5, 1};   // 5 öğeli dizi, indisler 0…4
int x = a[2];                // x = 9, tek adımda erişim
a[4] = 8;                     // indis 4'teki değer güncellenir

Temel Veri Yapıları

Diziler: Avantajlar ve Dezavantajlar

Avantajları

  • Doğrudan indisleme ile verilere hızlı erişim sağlar (O(1)).
  • Verileri düzenli bir şekilde saklar.
  • Kolay bir kullanım sunar.

Dezavantajları

  • Sabit boyuta sahiptir; veri boyutu dinamik olarak değiştirilemez.
  • Araya ekleme ve silme maliyetlidir; sonraki öğelerin kaydırılması gerekir (O(n)).

Dizi: 7, 2, 9, 5 ve 1 boş yer. 4'ü indis 1'e eklemek için önce yer açılmalı.

a[4] = a[3] = 5: sağdan başlanır ki hiçbir değer ezilmesin.

a[3] = a[2] = 9: sağdan başlanır ki hiçbir değer ezilmesin.

a[2] = a[1] = 2: sağdan başlanır ki hiçbir değer ezilmesin.

Açılan yere a[1] = 4. Eklenen yerden sonraki her öğe kaydı → en kötü durumda n kaydırma, O(n).

Temel Veri Yapıları

Bağlı Listeler (Linked Lists)

  • Verileri, birbirine referanslarla bağlanan düğümlerde (node) saklar.
  • Her düğüm, veriyi ve bir sonraki düğümün referansını içerir; "baş" listenin başlangıcını gösterir.
  • Düğümlerin bellekte ardışık olması gerekmez.
  • Verilerin dinamik olarak büyüyüp küçüldüğü ve sık ekleme/silme yapılan durumlarda kullanışlıdır.

Temel Veri Yapıları

Bağlı Listeler: Avantajlar ve Dezavantajlar

Avantajları

  • Veri boyutu dinamik olarak değişebilir.
  • Düğümler listeye eklenebilir, listeden çıkarılabilir.
  • Ekleme ve silme, öğeleri kaydırmadan yalnızca bağlantılar güncellenerek yapılır.

Dezavantajları

  • Erişim, düğümler arasında baştan gezinme gerektirdiği için dizilere göre yavaştır (O(n)).
  • Her düğüm bir de referans taşıdığından daha fazla bellek kullanır.

Liste: 7 → 2 → 9. 4'ü 7 ile 2 arasına ekleyeceğiz.

yeni düğüm (4) bellekte herhangi bir yerde oluşturulur; henüz listeye bağlı değil.

Önce yeni.sonraki = 2: sıra önemli, önce 7'nin bağlantısını değiştirseydik 2'ye giden yolu kaybederdik.

Sonra 7.sonraki = yeni. Yalnızca 2 bağlantı değişti; hiçbir öğe kaydırılmadı. (Ekleme yerine gitmek ise O(n) gezinme ister.)

Temel Veri Yapıları

Yığınlar (Stacks)

  • Verileri son giren, ilk çıkar (LIFO - Last-In, First-Out) mantığına göre saklar.
  • Yeni öğe yığının en üstüne eklenir (push).
  • Çıkarılırken en son eklenen öğe çıkarılır (pop).
  • "Üst" (top), en son eklenen öğeyi gösterir.
  • Tabak yığını gibi düşünülebilir: yalnızca en üstteki alınır.

Temel Veri Yapıları

Yığınların Kullanım Alanları

Özyinelemeli Fonksiyonlar (Recursion)Fonksiyon kendini çağırdığında her çağrı bir yığın çerçevesi olarak saklanır. Böylece fonksiyon tamamlandığında çağrıldığı yere geri dönebilir.
Geri İzleme (Backtracking)Olasılıklar denenip geri adım atılması gerektiğinde yığınlar kullanılır (ör. labirent çözme).
İşlem Geçmişi (Undo/Redo)Kullanıcı işlemlerini geri almak (Undo) veya geri getirmek (Redo) için yığınlar kullanılır.

Temel Veri Yapıları

Kuyruklar (Queues)

  • Verileri ilk giren, ilk çıkar (FIFO - First-In, First-Out) mantığına göre saklar.
  • Öğeler "arka"dan eklenir (enqueue), "ön"den çıkarılır (dequeue).
  • Market kasasındaki sıra gibi: ilk gelen ilk hizmet alır.

Temel Veri Yapıları

Kuyrukların Kullanım Alanları

İstek İşleme (Request Processing)Sunucular gelen istekleri kuyrukta sıraya alır ve sırayla işler; talep yükünü yönetmek için kullanışlıdır.
Yazdırma KuyruğuYazıcıya gönderilen belgeler geliş sırasıyla basılır.
Algoritmalar (Algorithms)Örneğin genişlik öncelikli arama (BFS) algoritması bir kuyruk kullanır.

Temel Veri Yapıları

Ağaçlar (Trees)

  • Verileri hiyerarşik bir yapı içinde saklar.
  • Her ağacın bir kök düğümü (root) vardır; diğer düğümler kökten dallanır.
  • Her düğümün sıfır veya daha fazla çocuğu olabilir; çocuğu olmayan düğümlere yaprak (leaf) denir.
  • Örnekte: kök 1; kökün çocukları 2 ve 3; 2'nin çocukları 4 ve 5.
KökEbeveyni olmayan tek düğüm: 1
Ebeveyn / Çocuk2, hem 4'ün hem 5'in ebeveynidir
YaprakÇocuğu olmayan düğümler: 3, 4, 5
YükseklikKökten en uzak yaprağa kenar sayısı: 2

Temel Veri Yapıları

Eşleme Veri Yapısı (Maps)

  • Anahtar-değer çiftlerini saklar; her anahtar bir değerle eşleştirilir.
  • Anahtarlar benzersizdir ve her biri yalnızca bir değeri temsil eder.
  • Anahtar kullanarak değerlere hızlı erişim sağlar.
  • Büyük veri koleksiyonlarını etkili bir şekilde işlemek için kullanışlıdır.
AnahtarDeğer
"Ad""Ali"
"Soyadı""Veli"
"Yaş"30

Map<String, Object> kisi = new HashMap<>();
kisi.put("Ad", "Ali");   kisi.get("Ad");  // → "Ali"

Temel Veri Yapıları

Eşleme ve Kümenin Arkasında: Hash Tablosu

  • Hash fonksiyonu h(k), anahtarı dizi indisine çevirir → aramadan doğrudan kovaya git.
  • Ortalama O(1) ekleme / arama / silme.
  • İki anahtar aynı kovaya düşerse çakışma (collision): 12 ve 7 → kova 2; zincirle çözülür.
  • Java: HashMap, HashSet. Ayrıntılar Bölüm 9'da.

Eşleme Kullanım Alanları

Veritabanı İşlemleriAnahtarlarla değerlere erişmek için kullanılır. Özellikle NoSQL veritabanlarında yaygındır.
Önbellek YönetimiSık kullanılan verilere hızlı erişim sağlar; ör. web sayfaları URL'lerine göre önbellekte tutulur.
Yapay Zeka ve Veri AnaliziVeri indisleme ve öznitelik eşleştirme için kullanılır; ör. kelime → frekans sayımı.
Yazılım GeliştirmeYapılandırma dosyaları, dil çevirileri ve ortam ayarları eşlemelerle tutulur.

Temel Veri Yapıları

Küme Veri Yapısı (Sets)

  • Benzersiz, tekil öğeler içerir; her öğe yalnızca bir kez bulunabilir.
  • Öğeler genellikle sırasız saklanır.
  • Bir öğenin kümede olup olmadığı hızlıca kontrol edilebilir.
  • Veri analizi, mantıksal işlemler ve veritabanı gibi alanlarda kullanılır.

Temel küme işlemleri (X = {1, 2, 3}, Y = {3, 4}):

Birleşim (∪)X ∪ Y = {1, 2, 3, 4}
Kesişim (∩)X ∩ Y = {3}
Fark (−)X − Y = {1, 2}

Kümeye 3'ü tekrar eklemek kümeyi değiştirmez: {1, 2, 3} ∪ {3} = {1, 2, 3}.

Temel Veri Yapıları

Çizge Veri Yapısı (Graphs)

  • Düğümleri (nodes) ve bu düğümleri birbirine bağlayan kenarları (edges) içerir.
  • Nesneler arasındaki karmaşık ilişkileri modellemek ve analiz etmek için kullanılır.
  • Örnekte A, B, C, D düğümlerdir; çizgiler kenarlardır. A ile B arasında kenar varsa bu iki düğüm komşudur.

Temel Veri Yapıları

Çizge Veri Yapısının Özellikleri

  • Düğümler (Nodes): Çizgenin temel yapı taşıdır ve verileri temsil eder.
  • Kenarlar (Edges): Düğümleri birbirine bağlar ve ilişkileri gösterir.
  • Kenarlar yönlü (oklarla) veya yönsüz (düz çizgilerle) gösterilebilir; kenarlara ağırlık verilebilir.
  • Bir düğümün kendisine bağlanmasına öz döngü denir; çizge türüne göre izin verilebilir veya verilmez.

Örnek Problemler

  1. Metin editöründe "geri al" için hangi veri yapısı uygundur? Neden?
  2. Yazıcıya gelen belgeleri geliş sırasıyla basmak için hangi yapı uygundur?
  3. Öğrenci numarasıyla öğrenci bilgisine hızlı erişim için hangi yapı uygundur?
  4. İki nokta arasındaki en kısa yolu bulmak için şehir haritasını nasıl modellersiniz?
  5. Listedeki tekrar eden öğeleri ayıklamak için hangi yapıyı kullanırsınız?
  6. Tüm öğe çiftlerini karşılaştıran algoritmanın zaman karmaşıklığı nedir?
Cevapları göster
  1. Yığın (LIFO): son yapılan işlem ilk geri alınır.
  2. Kuyruk (FIFO).
  3. Eşleme / hash tablosu (anahtar: öğrenci no).
  4. Ağırlıklı çizge: düğümler kavşak, kenarlar yol, ağırlıklar mesafe.
  5. Küme (set).
  6. O(n2).

  3. 2³ = 8 → O(n³) (kübik).
  4. faktoriyel(5), (4), (3), (2), (1) + main = 6.
  5. 7: b = a referansı kopyalar; iki değişken aynı diziyi gösterir.
  6. onekOrt1: 1+2+3+4+5 = 15; onekOrt2: 5.
