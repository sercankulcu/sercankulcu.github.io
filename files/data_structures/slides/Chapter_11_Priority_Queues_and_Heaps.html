The Priority Queue ADT

The Priority Queue

  • Every item has a priority (its key), and items leave in priority order.
  • Priority, not arrival order, decides who goes next: an ambulance overtakes the traffic.
  • Typical uses: task scheduling, emergency rooms, event-driven simulation.
  • Costs depend on the implementation: with a heap, looking at the top item is O(1) and removing it is O(log n); with an unsorted list even looking is O(n).

The Priority Queue ADT

Basic Concepts

Entry = (key, value)The key carries the priority; the value carries the actual data.(1, "heart attack") · (4, "sprain")
PriorityKeys must be comparable (<, ≤). Usually a smaller key means higher priority (a min-priority queue).
Highest priorityThe item at the "front": the smallest key in a min-queue, the largest in a max-queue.
Equal priorityItems with equal keys are not guaranteed to leave in FIFO order; if that matters, add an arrival sequence number to the key.

Like Goodrich, we define the ADT as a min-priority queue (removeMin), while the heap code uses a max-heap (insert / removeMax). The choice only flips the direction of the comparisons.

List-Based Implementations

Unsorted List vs. Sorted List

Unsorted list
  • insert: append at the end → O(1)
  • min, removeMin: scan the whole list → O(n)
Sorted list
  • insert: find the right slot → O(n)
  • min, removeMin: the minimum is always at one end → O(1)
One is fast at inserting, the other at removing. The binary heap balances the two (both O(log n)).

List-Based Implementations · Step through the code

Code Trace: removeMin() on an unsorted array

Unsorted array a = [5, 9, 3, 7, 4]: insertions go at the end, so the minimum could be anywhere. First candidate: minIdx = 0.

k = 1: a[1] = 9 ≥ a[0] = 5 → minIdx stays.

k = 2: a[2] = 3 < a[0] = 5 → new minimum, minIdx = 2.

k = 3: a[3] = 7 ≥ a[2] = 3 → minIdx stays.

k = 4: a[4] = 4 ≥ a[2] = 3 → minIdx stays.

k = 5 = n → scan done: 4 comparisons. Every removeMin scans the whole array → O(n).

min = a[2] = 3 is saved.

To fill the gap without shifting, the last item (4) moves to index 2; n = 4. Order doesn't matter, so this is O(1).

return 3. The remaining array [5, 9, 4, 7] is still unsorted.

// unsorted array: insert(x) { a[n] = x; n++; }  O(1)
public int removeMin() {        // requires n > 0
  int minIdx = 0;               // index of the minimum
  for (int k = 1; k < n; k++)
    if (a[k] < a[minIdx]) minIdx = k;
  int min = a[minIdx];
  a[minIdx] = a[n - 1];  n--;   // last item fills the gap
  return min;
}

Code Trace: insert(4) on a sorted array

The array is sorted from largest to smallest, so the highest-priority (smallest) item is always last. k = n − 1 = 4: search for the slot from the back.

a[4] = 2 < 4 → 2 belongs after x, so it shifts.

a[5] = a[4] = 2: shifted one to the right (a[4] is a stale copy for now and will be overwritten).

k = 3: move one to the left.

a[3] = 3 < 4 → 3 belongs after x, so it shifts.

a[4] = a[3] = 3: shifted one to the right (a[3] is a stale copy for now and will be overwritten).

k = 2: move one to the left.

a[2] = 5 ≥ 4 → the loop ends. 4 goes at k + 1 = 3.

a[3] = 4, n = 6. The array is still sorted. In the worst case (x is the largest) every item shifts → O(n).

In return, removeMin() is cheap: the minimum (2) is already last → n = 5, return 2. No shifting → O(1).

// sorted array: largest to smallest, min always at a[n-1]
public void insert(int x) {
  int k = n - 1;
  while (k >= 0 && a[k] < x) {    // items smaller than x
    a[k + 1] = a[k];              // shift one to the right
    k--;
  }
  a[k + 1] = x;  n++;
}
public int removeMin() { n--; return a[n]; }

List-Based Implementations

Array and Linked-List Representations

Array representation
  • Items live in an array; keeping it sorted means shifting items on every insertion (O(n)).
  • If the top-priority item sits at the front, every removal shifts the whole array left: O(n).
  • Better: keep the top-priority item at the end → removal is O(1).
Linked-list representation
  • Each item is linked in at the position its priority calls for: finding it is O(n), linking is O(1).
  • The top-priority item is at the head, so removal = deleting the head, O(1).
  • No shifting, but every node carries an extra reference.

This list runs from smallest to largest (min-priority), so the highest-priority item, 3, is at the head. A new node 6 has been created.

Finding the slot: advance until prev.next.value = 7 > 6 → prev = 5. This scan takes O(n).

First newNode.next = prev.next (6 → 7). Order matters: without this link in place, the path to 7 would be lost.

Then prev.next = newNode (5 → 6). Linking is O(1) with no shifting, and removal always happens at the head: O(1).

A Sorted-Array Priority Queue: Code

class Item<T> {
    T data;
    int priority;
    Item(T d, int p) { data = d; priority = p; }
}
// fields of SortedArrayPQ<E>
private Item<E>[] items =
    (Item<E>[]) new Item[10];
private int size = 0;
public boolean isEmpty() { return size == 0; }
public void insert(E data, int p) {
    if (size == items.length)
        items = Arrays.copyOf(items, 2 * size);
    int i = size;
    while (i > 0 && items[i-1].priority < p) {
        items[i] = items[i - 1]; // shift right
        i--;
    }
    items[i] = new Item<>(data, p);
    size++;
}
public E remove() {
    if (isEmpty()) return null;
    E result = items[0].data;
    for (int i = 1; i < size; i++)
        items[i - 1] = items[i];
    items[--size] = null;
    return result;
}

Items are (data, priority) pairs, highest priority first, in items[0]. This simple version ignores the previous slide's advice: insert is O(n) (shift right) and so is remove (shift left). Ascending order would make remove one line (items[--size]) and O(1). The strict < keeps arrival order among equal priorities.

Binary Heaps

The Binary Heap

The binary heap is the most common way to implement a priority queue. It is a binary tree that satisfies two conditions at once:

1. Heap-order propertyEvery node comes before its children: in a max-heap, parent ≥ child. The highest-priority item is at the root.
2. Complete binary tree propertyEvery level except the last is full, and the last fills from left to right → height ⌊log₂ n⌋, and no gaps in the array.
Insertion and removal work along a single path from the root to a leaf → O(log n). A heap is not a binary search tree.

Binary Heaps

Min-Heaps and Max-Heaps

  • The order holds only between parent and child: in the min-heap, 7 and 3 are siblings, so 7 > 3 is fine.
  • Every path from the root down to a leaf is sorted (increasing in a min-heap, decreasing in a max-heap).

Binary Heaps

Complete Binary Trees

HeightLevel d holds at most 2d nodes, so a complete binary tree with n nodes has height h = ⌊log₂ n⌋.n = 7 → h = 2 · n = 1000 → h = 9
Why it mattersA new item always goes into "the leftmost free spot on the last level", and in the array that is exactly index n.

Code Trace: isHeap([10, 8, 9, 3, 5, 7, 4, 6])

isHeap(a) is called on an 8-item array. Every node except the root (index 0) is compared once with its parent.

i = 1: parent p = (1 − 1) / 2 = 0. a[0] = 10 ≥ a[1] = 8 ✓ → continue.

i = 2: parent p = (2 − 1) / 2 = 0. a[0] = 10 ≥ a[2] = 9 ✓ → continue.

i = 3: parent p = (3 − 1) / 2 = 1. a[1] = 8 ≥ a[3] = 3 ✓ → continue.

i = 4: parent p = (4 − 1) / 2 = 1. a[1] = 8 ≥ a[4] = 5 ✓ → continue.

i = 5: parent p = (5 − 1) / 2 = 2. a[2] = 9 ≥ a[5] = 7 ✓ → continue.

i = 6: parent p = (6 − 1) / 2 = 2. a[2] = 9 ≥ a[6] = 4 ✓ → continue.

i = 7: p = 3. a[3] = 3 < a[7] = 6 ✗ → the child is larger than its parent: return false.

Result: false. The first seven items form a valid heap, but 6 is larger than its parent 3. The worst case is n − 1 comparisons → O(n).

static boolean isHeap(int[] a) {  // max-heap?
  for (int i = 1; i < a.length; i++) {
    int p = (i - 1) / 2;           // parent
    if (a[p] < a[i]) return false; // out of order
  }
  return true;
}

Binary Heaps

Array Representation

  • Starting at the root, nodes are written into the array level by level, left to right (level order).
  • Because the tree is complete, the array has no gaps and needs no pointers (references).

The small numbers next to the nodes are their array indices. In these slides indices start at 0, so the root is heap[0].

Binary Heaps

Parent and Child Indices

Childrenleft(i) = 2i + 1 · right(i) = 2i + 2i = 1 → 3 and 4 · i = 2 → 5 and 6
Parentparent(i) = ⌊(i − 1) / 2⌋i = 6 → 2 · i = 5 → 2 · i = 4 → 1
  • Java's integer division already rounds down: (i - 1) / 2. A node has no children when 2i + 1 ≥ n.
  • The 1-based alternative leaves heap[0] empty: children 2k and 2k + 1, parent ⌊k/2⌋. The two are equivalent; pick one and use it consistently.

Insertion and Removal

Insertion: Up-Heap (Sift-Up)

  1. Put the new item in the first free slot (heap[n]). The tree stays complete.
  2. Heap order may now be broken: if the new item is larger than its parent (max-heap), swap them.
  3. Keep moving the item up until it reaches the root or its parent is greater than or equal to it.
CostAt most h = ⌊log₂ n⌋ swaps → O(log n).
Why it worksThe parent that moves down in a swap was already larger than its other child.
Namesup-heap, bubble-up, sift-up, swim; the code in this chapter calls it swim.

Insertion and Removal

Inserting into a Max-Heap: Java Code

public class MaxHeap {
  private int[] heap = new int[4];
  private int n = 0;                // number of items

public void insert(int x) {
  if (n == heap.length) resize(2 * heap.length);
  heap[n] = x;  n++;              // first free slot
  swim(n - 1);
}
private void swim(int i) {        // up-heap
  while (i > 0) {
    int parent = (i - 1) / 2;
    if (heap[parent] >= heap[i]) return;
    swap(i, parent);  i = parent;
  }
}
private void swap(int a, int b) {
  int t = heap[a];  heap[a] = heap[b];  heap[b] = t;
}
}  // MaxHeap
resizeWhen the array fills up, its capacity doubles (amortized O(1)).
swapExchanges heap[a] and heap[b].
StoppingAt the root (i = 0) or once parent ≥ item.

Code Trace: resize(8)

insert(1) is called with n == heap.length = 4 → resize(8). An array's length is fixed, so growing means a new array plus copying.

A new 8-cell array, newArr, is allocated; Java fills an int array with 0s.

k = 0 < n → newArr[0] = heap[0] = 6.

k = 1 < n → newArr[1] = heap[1] = 5.

k = 2 < n → newArr[2] = heap[2] = 2.

k = 3 < n → newArr[3] = heap[3] = 4.

k = 4 = n → the loop ends. n items were copied, so this resize costs O(n).

heap = newArr: the field now refers to the new array, and the old one is left to the garbage collector. Same tree; only the capacity is now 8.

resize returns and insert(1) continues. Because the capacity doubles each time, n insertions copy fewer than 2n items in total → amortized O(1) per insertion.

private void resize(int capacity) {
  int[] newArr = new int[capacity];
  for (int k = 0; k < n; k++)
    newArr[k] = heap[k];        // copy
  heap = newArr;                // old array becomes garbage
}

Insertion and Removal

Removing the Maximum: Down-Heap (Sift-Down)

  1. Save the item at the root (the largest); it is the return value.
  2. Move the last item (heap[n − 1]) to the root and decrease n by one.
  3. Swap the root with its larger child.
  4. Keep moving the item down until it reaches a leaf or is greater than or equal to both children.
Why the larger child?If the smaller child moved up, it would become the parent of a larger sibling. In a min-heap, pick the smaller child instead.
CostTwo comparisons per level, at most h levels → O(log n).

Insertion and Removal

Removing the Maximum: Java Code

public int removeMax() {        // requires n > 0
  int max = heap[0];
  swap(0, n - 1);  n--;         // last item to the root
  sink(0);
  return max;
}
private void sink(int i) {        // down-heap
  while (2 * i + 1 < n) {       // has a left child?
    int j = 2 * i + 1;            // j: larger child
    if (j + 1 < n && heap[j + 1] > heap[j]) j++;
    if (heap[i] >= heap[j]) return;
    swap(i, j);  i = j;           // down one level
  }
}
Empty heapReal code first throws an exception if (n == 0).
shrinkOptional: halve the array once n drops to ¼ of the capacity.
SwapThe maximum stays at the end of the array, which is what heap sort relies on.

Left child 1 (9), right child 2 (6) → the larger is 9, j = 1.

3 < 9 → swap (index 0 ↔ 1); the larger child rises, i = 1.

Left child 3 (8), right child 4 (1) → the larger is 8, j = 3.

3 < 8 → swap (index 1 ↔ 3); the larger child rises, i = 3.

Only a left child: index 7 (2) → j = 7.

heap[3] = 3 ≥ heap[7] = 2 → no smaller than either child, so heap order holds: return.

sink is done, and the array is a valid max-heap again. return 10. The path spans at most ⌊log₂ n⌋ levels → O(log n).

removeMax() #2: the largest item is always at the root → max = heap[0] = 9.

The root and the last item swap (0 ↔ 7); n = 7, so 9 leaves the heap (faded). The tree is still complete; the new root 2 may break the order.

Left child 1 (8), right child 2 (6) → the larger is 8, j = 1.

2 < 8 → swap (index 0 ↔ 1); the larger child rises, i = 1.

Left child 3 (3), right child 4 (1) → the larger is 3, j = 3.

2 < 3 → swap (index 1 ↔ 3); the larger child rises, i = 3.

i = 3: 2·3 + 1 = 7 ≥ n = 7 → no children (a leaf), so the loop ends.

sink is done, and the array is a valid max-heap again. return 9. The path spans at most ⌊log₂ n⌋ levels → O(log n).

public int removeMax() {        // requires n > 0
  int max = heap[0];
  swap(0, n - 1);  n--;         // last item to the root
  sink(0);
  return max;
}
private void sink(int i) {        // down-heap
  while (2 * i + 1 < n) {       // has a left child?
    int j = 2 * i + 1;            // j: larger child
    if (j + 1 < n && heap[j + 1] > heap[j]) j++;
    if (heap[i] >= heap[j]) return;
    swap(i, j);  i = j;           // down one level
  }
}

Insertion and Removal

Min-Heap: insert(1) and removeMin()

Initial min-heap: every parent ≤ its children, and the smallest item (2) is at the root.

insert(1): 1 goes into the first free slot (index 7). Its parent: (7−1)/2 = 3 → 9.

1 < 9 → swap (index 7 ↔ 3).

1 < 5 → swap (index 3 ↔ 1).

1 < 2 → swap (index 1 ↔ 0). At the root → stop.

removeMin(): min = heap[0] = 1 (the root) is the value to return.

Swap the root with the last item (0 ↔ 7); n = 7, and 1 is outside the heap. The new root 9 may break heap order → down-heap.

Children: 2 and 3 → the smaller is 2. 9 > 2 → swap (0 ↔ 1).

Children: 5 and 6 → the smaller is 5. 9 > 5 → swap (1 ↔ 3). Index 3 is a leaf → stop.

Insertion and Removal

Adaptable Priority Queues

Sometimes an item's priority changes while it waits (a distance shrinks in Dijkstra's algorithm, a patient gets worse), or the item has to be removed from the middle. Goodrich defines two extra operations for this:

replaceKey(e, k)Change heap[e.index]; if the key grew, up-heap; if it shrank, down-heap (max-heap).
remove(e)Swap with the last item, n − 1, then up-heap or down-heap the item that took its place.
Why a locator?Without one, finding the entry is O(n); with one it is O(1), so both operations are O(log n).

public void changeKey(int i, int key) {
  int old = heap[i];
  heap[i] = key;
  if (key > old) swim(i);      // increased: move up
  else sink(i);                // decreased: move down
}
private void swim(int i) {       // up-heap
  while (i > 0) {
    int parent = (i - 1) / 2;
    if (heap[parent] >= heap[i]) return;
    swap(i, parent);  i = parent;
  }
}

Heap Construction and Heap Sort

Building a Heap from n Items

Option 1: n insertions

  • Each insertion does an up-heap: O(log n).
  • Total O(n log n).
  • The only option when items arrive one at a time (online).

Option 2: bottom-up

  • If all the items are available up front, take the array as it is.
  • Run down-heap on every node, from the last internal node (⌊n/2⌋ − 1) back to the root.
  • Total O(n).
for (int k = n / 2 - 1; k >= 0; k--)   // from the last internal node to the root
    sink(k);                             // sink k; its subtrees are already heaps

Why Is Bottom-Up Construction O(n)?

Node heightNodesMax swapsTotal

n = 1511
  • Half the nodes are leaves and do no work at all; the few tall nodes are the only ones that do much.
  • In general: Σh (n / 2h+1) · h ≤ n → O(n).
  • With n insertions, the many deep nodes walk long paths instead: in the same tree the worst case is 0 + 2·1 + 4·2 + 8·3 = 34 swaps.
The cost of down-heap depends on a node's height; the cost of up-heap depends on its depth. Most nodes are near the bottom.

Heap Construction and Heap Sort

Heap Sort

Phase 1: build the heapTurn the array into a max-heap bottom-up. O(n)
Phase 2: n − 1 removeMax stepsSwap the root (the largest) with the item at the end, shrink the heap by one, and down-heap the root. O(n log n)
  • The sorted part grows at the end of the array while the heap shrinks at the front; no extra array is needed (in place, O(1) extra memory).
  • O(n log n) even in the worst case: no O(n²) worst case as in quick sort.
  • Not stable: equal keys may change their relative order.
  • A max-heap sorts in ascending order, a min-heap in descending order.

Heap Sort: Java Code

public static void heapSort(int[] a) {
  int n = a.length;
  // 1) build: from the last internal node to the root
  for (int k = n / 2 - 1; k >= 0; k--)
    sink(a, k, n);
  // 2) sort: move the largest to the end
  for (int last = n - 1; last > 0; last--) {
    swap(a, 0, last);
    sink(a, 0, last);           // heap size = last
  }
}
static void sink(int[] a, int i, int n) {
  while (2 * i + 1 < n) {
    int j = 2 * i + 1;
    if (j + 1 < n && a[j + 1] > a[j]) j++;
    if (a[i] >= a[j]) return;
    swap(a, i, j);  i = j;
  }
}

Sorting with a Priority Queue

The general idea: insert every item into a priority queue, then call removeMin n times. Which sorting algorithm we get depends on the implementation:

Implementationn × insertn × removeMinResulting algorithm
Unsorted listO(n)O(n²)Selection sort, O(n²)
Sorted listO(n²)O(n)Insertion sort, O(n²)
Binary heapO(n log n)O(n log n)Heap sort, O(n log n)
Same ADT, different data structure: the running time drops from O(n²) to O(n log n). A concrete case of the ADT vs. data structure distinction.

Heap Construction and Heap Sort

Kinds of Heaps: d-ary, Binomial, Fibonacci

  • d-ary heap: each node has d children; parent (i − 1) / d. Height logd n, so insertion gets faster, but removal compares d children per level.
  • Binomial / Fibonacci heaps: a forest of trees; merging two queues and decreasing a key are fast (Dijkstra, Prim).

* amortized. In practice the binary heap is often the fastest, thanks to its simplicity and cache-friendly array layout.

Code Trace: what PriorityQueue does inside

An empty PriorityQueue. Internally it keeps a binary min-heap in an array (queue), with the smallest item at the root.

offer(5): the heap was empty, so 5 becomes the root (index 0).

offer(1): added at index 1; its parent 5 > 1 → min-heap order is broken.

siftUp (up-heap): 1 moves up to the root → queue = [1, 5]. Cost: O(log n).

offer(8): added at index 2; parent 1 ≤ 8 → no up-heap needed.

peek(): returns the root, 1, but does not remove it → O(1).

poll(): takes the root, 1; the last item, 8, moves to the root; size = 2.

siftDown (down-heap): 8 swaps with its smaller child → queue = [5, 8]. 1 is printed.

poll(): takes the root, 5; the last item, 8, moves to the root; size = 1.

One item is left, so no siftDown is needed. 5 is printed.

size() = 1 (only 8 is left) → O(1). Console output: 1 (peek), 1, 5 (poll), 1 (size).

Application: kthLargest([5, 1, 9, 3, 7, 6], 3)

k = 3: we keep a min-heap of at most k items. Its root is the smallest of the k largest items seen so far.

x = 5: offer(5) → added at the end, up-heap. size = 1.

size = 1 ≤ k = 3 → nothing to drop yet.

x = 1: offer(1) → added at the end, up-heap (it swam up: 1 swap). size = 2.

size = 2 ≤ k = 3 → nothing to drop yet.

x = 9: offer(9) → added at the end, up-heap. size = 3.

size = 3 ≤ k = 3 → nothing to drop yet.

x = 3: offer(3) → added at the end, up-heap (it swam up: 1 swap). size = 4.

size = 4 > k → poll(): the smallest, 1, is dropped (it cannot be among the k largest). Last item to the root, down-heap.

x = 7: offer(7) → added at the end, up-heap. size = 4.

size = 4 > k → poll(): the smallest, 3, is dropped (it cannot be among the k largest). Last item to the root, down-heap.

x = 6: offer(6) → added at the end, up-heap (it swam up: 1 swap). size = 4.

size = 4 > k → poll(): the smallest, 5, is dropped (it cannot be among the k largest). Last item to the root, down-heap.

Loop done: pq holds the three largest items {6, 7, 9}. peek() = 6 → the 3rd largest. Total O(n log k), memory O(k).

static int kthLargest(int[] a, int k) {
  PriorityQueue<Integer> pq = new PriorityQueue<>();
  for (int x : a) {
    pq.offer(x);                    // O(log k)
    if (pq.size() > k) pq.poll();  // drop the smallest
  }
  return pq.peek();       // smallest of the k largest
}

Common Mistakes

"A heap is sorted"It is not; only the root is determined. After inserting 3, 1, 2 into a PriorityQueue, println(pq) → [1, 3, 2].
Index formulas0-based: 2i+1, 2i+2, (i−1)/2. 1-based: 2i, 2i+1, i/2. Mixing the two scrambles the tree.
Right-child boundForget the j + 1 < n check and you read an item outside the heap (one already removed).
Wrong childIn a max-heap, down-heap swaps with the larger child; picking the smaller one breaks the order.
Searching a heapcontains and remove(obj) are O(n). Fast access needs a locator or a map.
Wrong directionPriorityQueue is a min-heap by default; for a max-heap, use Comparator.reverseOrder().
