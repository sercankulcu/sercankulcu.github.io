The Tree Concept

Trees

  • A nonlinear, hierarchical data structure.
  • Made of nodes and the edges that connect them.
  • A single root sits at the top; trees are drawn upside down, growing downward from the root.
  • Every node except the root has exactly one parent, so there are no cycles.
  • A node may have zero or more children.
Rule: a tree with n nodes always has n − 1 edges (each node except the root is joined to its parent by exactly one edge).

The Terms on a Tree

Root: the only node with no parent → A.

Parent / child: D is the parent of H, I, and J; H, I, J are D's children.

Siblings: H, I, J (their parent is D). F and G are not siblings.

Leaves: K, L, F, G, M, I, J (nodes without children).

Internal nodes: A, B, C, D, E, H (nodes with at least one child).

Ancestors: M's ancestors are H, D, A. Conversely, M is a descendant of H, D, and A.

Degree = number of children: A 3, B 2, C 1, D 3 … The degree of the tree = the largest degree = 3.

Depth: the number of edges from the root to the node. E has depth 2 (A→B→E).

Height: the number of edges from the root to the farthest leaf = 3 (A→B→E→K).

Subtree: D and all its descendants (H, I, J, M) form a tree of their own.

The Tree Concept

Paths and Subtrees

  • Path: a sequence of nodes in which consecutive nodes are joined by edges.
    p = (v₀, e₁, v₁, …, ek, vk)
  • start(p) = v₀, end(p) = vk, length(p) = k (the number of edges).
  • In a tree, any two nodes are joined by exactly one simple path; a second path would create a cycle.
  • Subtree: a node together with all its descendants; it is a tree itself. Example: a folder and everything under it.

The Tree Abstract Data Type (Tree ADT)

public interface Tree<E> extends Iterable<E> {
  Position<E> root();
  Position<E> parent(Position<E> p);
  Iterable<Position<E>> children(Position<E> p);
  int numChildren(Position<E> p);
  boolean isInternal(Position<E> p); // has a child
  boolean isExternal(Position<E> p); // a leaf
  boolean isRoot(Position<E> p);     // no parent
  int size();
  boolean isEmpty();
  Iterable<Position<E>> positions(); // all nodes

// Position<E>: E getElement();

The binary tree ADT adds left(p), right(p), and sibling(p) (as in Goodrich et al.).

A position is an abstraction of a "place" that hides the node itself: the user sees only the element and the ADT methods.

The Tree Concept · Step through the code

Code Trace: depth(G) and height(B) with the ADT

depth(G): G is not the root → call depth(E) on its parent, E (moving up).

depth(E): E is not the root → call depth(B) on its parent, B (moving up).

depth(B): B is not the root → call depth(A) on its parent, A (moving up).

depth(A): A is the root → return 0. This is the base case; now the frames start returning.

depth(B) = 1 + 0 = 1 is returned.

depth(E) = 1 + 1 = 2 is returned.

depth(G) = 1 + 2 = 3 is returned. G has depth 3: 3 edges from the root to G (A–B–E–G). Cost: O(d + 1).

Now height(B): the recursion goes down, through the children (depth looks up, height looks down).

height(B): h = 0. Children: D, E. Recurse on the first child, D.

height(D): h = 0; D has no children, so the loop never runs → return 0 (a leaf).

D returned 0: h = max(0, 1 + 0) = 1. Next child: E.

height(E): h = 0. Children: G. Recurse on the first child, G.

height(G): h = 0; G has no children, so the loop never runs → return 0 (a leaf).

G returned 0: h = max(0, 1 + 0) = 1. No children left → return 1.

E returned 1: h = max(1, 1 + 1) = 2. No children left → return 2. Height(B) = 2 (B–E–G); each node is visited once.

int depth(Position<E> p) {
    if (isRoot(p)) return 0;
    return 1 + depth(parent(p));
}
int height(Position<E> p) {
    int h = 0;
    for (Position<E> c : children(p))
        h = Math.max(h, 1 + height(c));
    return h;
}

Binary Trees

Binary Trees

  • Each node has at most two children: a left child and a right child.
  • Position matters: a tree whose only child is a left child differs from one whose only child is a right child.
  • Recursive definition: a binary tree is either empty or consists of a root and two binary trees (the left and right subtrees).

The chain on the left is a valid binary tree too (a skewed tree): nodes need not be spread out evenly.

Binary Trees

Full, Complete, and Perfect

Full binary treeEvery node has either 0 or 2 children; no node has just one.
Complete binary treeEvery level except the last is full, and the last level fills from left to right with no gaps.
Perfect binary treeEvery internal node has 2 children and all leaves have the same depth.
A perfect tree is both full and complete; with height h it has 2h+1 − 1 nodes. Books do not all use "full" and "complete" the same way, so check the definition before you rely on one.

Binary Trees · Step by step

Full Binary Trees: Why Leaves = Internal Nodes + 1?

A one-node tree: the root is a leaf (L). i = 0, l = 1 → l = i + 1.

Give a leaf two children (a full tree allows 0 or 2): the leaf becomes an internal node (i + 1) and two new leaves appear (l − 1 + 2 = l + 1). The difference stays the same.

Give a leaf two children (a full tree allows 0 or 2): the leaf becomes an internal node (i + 1) and two new leaves appear (l − 1 + 2 = l + 1). The difference stays the same.

Give a leaf two children (a full tree allows 0 or 2): the leaf becomes an internal node (i + 1) and two new leaves appear (l − 1 + 2 = l + 1). The difference stays the same.

Each expansion adds 1 to both i and l; since l − i = 1 at the start, every full binary tree has l = i + 1 (by induction). Consequently n = 2i + 1, so n is always odd.

I: internal node, L: leaf; orange: the leaves added in the last step. This property is used in expression trees (every operator has 2 operands) and Huffman trees.

Representations

Array Representation

Nodes are placed in the array level by level, left to right. The root goes at index 1 in a 1-based array, at index 0 in a 0-based one. For the node at index i:

1-based0-based
Left child2i2i + 1
Right child2i + 12i + 2
Parent⌊i / 2⌋⌊(i − 1) / 2⌋

Example: E (i = 5) → children at 10 and 11 (empty), parent at ⌊5/2⌋ = 2 (B).

No references are stored; parent and child are reached with O(1) arithmetic. Ideal for complete binary trees (such as heaps).

Code Trace: Index Arithmetic in the Array Representation

left(2) = 2·2 = 4 → a[4] = D, B's left child (the array is 1-based; a[0] is empty). No references: positions come from arithmetic.

right(2) = 2·2 + 1 = 5 → a[5] = E. The right child always sits right next to the left child.

parent(2) = 2 / 2 = 1 → a[1] = A (the root).

D (i = 4): children 8 → H and 9 → I.

E (i = 5): 10 and 11 > n = 9 → outside the array, so E has no children (a leaf). The check is 2i ≤ n.

parent(9) = 9 / 2 = 4: integer division rounds down (⌊4.5⌋ = 4) → D. Since 8 and 9 are siblings, both give 4.

pathToRoot(a, 9): follow the chain of parents from I up to the root.

9 ≥ 1 → the loop continues; a[9] = I is printed.

i = parent(9) = 4 → D.

4 ≥ 1 → the loop continues; a[4] = D is printed.

i = parent(4) = 2 → B.

2 ≥ 1 → the loop continues; a[2] = B is printed.

i = parent(2) = 1 → A.

1 ≥ 1 → the loop continues; a[1] = A is printed.

i = parent(1) = 0 (the root has no parent).

0 ≥ 1 is false → the loop ends. Output: I D B A. Each step halves the index → O(log n) (as many steps as the depth).

int left(int i)   { return 2 * i; }
int right(int i)  { return 2 * i + 1; }
int parent(int i) { return i / 2; }
void pathToRoot(char[] a, int i) {  // from i up to the root
  while (i >= 1) {
    System.out.print(a[i] + " ");
    i = parent(i);
  }
}

Representations

Wasted Space in Arrays

  • In a skewed tree the indices grow exponentially: 1, 2, 4, 8, 16.
  • 5 nodes need 16 cells, leaving 11 empty. Skewed to the right, the indices would be 1, 3, 7, 15, 31 → 31 cells.
  • In general, a tree of n nodes may need up to 2n − 1 cells.

Array representation

  • No references, fast index arithmetic
  • No gaps for complete trees

But

  • Large waste for sparse or skewed trees
  • Fixed size; growing means copying

Representations

Linked Representation

  • Each tree node is an object: data plus references to its left and right children.
  • A missing child is a null reference.
  • The size is dynamic; memory is allocated only for nodes that exist.
  • Reaching a node means starting at the root and following references.
public class TreeNode {
    int data;
    TreeNode left;    // left child (null if none)
    TreeNode right;   // right child (null if none)

    public TreeNode(int data) {
        this.data = data;   // left = right = null
    }
}
// build a small tree rooted at 9
TreeNode root = new TreeNode(9);
root.left = new TreeNode(2);
root.right = new TreeNode(3);
root.left.left = new TreeNode(4);

Representing General Trees

When a node can have any number of children, two approaches are common:

In the second approach every node again holds two references: first child (down) and next sibling (across). This lets any general tree be stored like a binary tree.

Traversals

Preorder Traversal

  1. Visit the root.
  2. Traverse the left subtree in preorder.
  3. Traverse the right subtree in preorder.

Use: copying a tree, writing the nodes to an array, prefix expressions.

visit(root);
preorder(root.left);
preorder(root.right);

Visit the root, 1; then move to the left subtree.

Visit 2; then its left subtree.

4 is a leaf: visit it; it has no children.

2's right subtree: 5.

The left subtree is done; 1's right subtree: 3.

3's left child is 6.

3's right child is 7. Output: 1 2 4 5 3 6 7

Traversals

Inorder Traversal

  1. Traverse the left subtree in inorder.
  2. Visit the root.
  3. Traverse the right subtree in inorder.

Use: listing the keys of a binary search tree in increasing order, infix expressions.

inorder(root.left);
visit(root);
inorder(root.right);

Keep going left from the root; the first node visited is the leftmost one: 4.

4's subtree is done → its parent, 2.

2's right subtree: 5.

The left subtree is complete → the root, 1.

In the right subtree, again go all the way left: 6.

After 6, its parent, 3.

Finally 7. Output: 4 2 5 1 6 3 7

Traversals

Postorder Traversal

  1. Traverse the left subtree in postorder.
  2. Traverse the right subtree in postorder.
  3. Visit the root.

Use: deleting a tree (children first), computing size/height, postfix expressions.

postorder(root.left);
postorder(root.right);
visit(root);

The leftmost leaf, 4, is visited first.

Then 2's right child, 5.

Both of 2's subtrees are done → 2.

1's right subtree: 6 first.

Then 7.

3's children are done → 3.

The root is visited last: 1. Output: 4 5 2 6 7 3 1

Traversals · Step by step

Three Traversals, One Walk: the Euler Tour

Walk around the tree, starting to the left of the root and keeping your left hand on the edges (an Euler tour). You pass each node three times: on its left, below it, and on its right.

Write a node down when you pass on its left (the first encounter) and you get preorder: A B D E C.

Write it down when you pass below it (left subtree done, right not yet started) and you get inorder: D B E A C.

Write it down when you pass on its right (both subtrees done) and you get postorder: D E B C A. The three traversals are different moments of the same walk, which takes O(n).

Traversals

Level-Order Traversal

  • Starts at the root, scans each level from left to right, then moves down a level.
  • It is breadth-first search (BFS) applied to a tree.
  • Uses a queue (FIFO) instead of recursion: the children of the node that arrived first are processed first.

Use: level-based operations (the sum of each level, the nearest leaf), printing a tree level by level.

Preorder Traversal with a Stack

Push the root. The stack stands in for the call stack of the recursive version.

pop() returns 1, printed at once (preorder: root first).

Push the right child, 3: right goes first, so left ends up on top and is processed first (LIFO).

Push the left child, 2. It is now on top, so the next pop() returns it.

pop() returns 2, printed at once (preorder: root first).

Push the right child, 5: right goes first, so left ends up on top and is processed first (LIFO).

Push the left child, 4. It is now on top, so the next pop() returns it.

pop() returns 4, printed at once (preorder: root first). 4 is a leaf: no children to push.

pop() returns 5, printed at once (preorder: root first). 5 is a leaf: no children to push.

pop() returns 3, printed at once (preorder: root first).

Push the right child, 7: right goes first, so left ends up on top and is processed first (LIFO).

Push the left child, 6. It is now on top, so the next pop() returns it.

pop() returns 6, printed at once (preorder: root first). 6 is a leaf: no children to push.

pop() returns 7, printed at once (preorder: root first). 7 is a leaf: no children to push.

The stack is empty → the loop ends. Output: 1 2 4 5 3 6 7 — the same as recursive preorder.

public void preorderIterative(TreeNode root) {
  if (root == null) return;
  Deque<TreeNode> stack = new ArrayDeque<>();
  stack.push(root);
  while (!stack.isEmpty()) {
    TreeNode temp = stack.pop();
    System.out.print(temp.data + " ");
    if (temp.right != null)
      stack.push(temp.right);  // right first
    if (temp.left != null)
      stack.push(temp.left);   // left on top
  }
}

Push 6 (to be printed later); temp = 6.left = null. Nothing more to the left.

temp is null → pop 6 and print it (everything to its left is done). temp = 6.right = null.

temp is null → pop 3 and print it (everything to its left is done). temp = 3.right = null.

The stack is empty and temp is null → the loop ends. Output: 4 2 5 1 6 3 (left → root → right).

public void inorderIterative(TreeNode root) {
  if (root == null) return;
  Deque<TreeNode> stack = new ArrayDeque<>();
  TreeNode temp = root;
  while (!stack.isEmpty() || temp != null) {
    if (temp != null) {
      stack.push(temp);
      temp = temp.left;
    } else {
      temp = stack.pop();
      System.out.print(temp.data + " ");
      temp = temp.right;
    }
  }
}

Postorder Traversal with a Stack: Code

public void postorderIterative(TreeNode root) {
  TreeNode current = root;
  Deque<TreeNode> stack = new ArrayDeque<>();
  while (current != null || !stack.isEmpty()) {
    if (current != null) {
      stack.push(current);
      current = current.left;
    } else {
      TreeNode temp = stack.peek().right;
      if (temp == null) {
        temp = stack.pop();
        System.out.print(temp.data + " ");
        while (!stack.isEmpty()
           && temp == stack.peek().right) {
          temp = stack.pop();
          System.out.print(temp.data + " ");
        }
      } else {
        current = temp;
      }
    }
  }
}
  • A node must be printed only after both of its subtrees, so the node on the stack is not popped right away: we first look at it with peek.
  • If the top node has a right child, we go into that subtree first.
  • If it has no right child, the node is printed. If the node just printed is the right child of the node now on top, that parent is finished too → it is popped and printed as well.

Level-Order Traversal with a Queue

Add the root to the queue. A queue is FIFO: first in, first out.

poll() returns 4, and prints it.

The left child, 3, joins the back of the queue; it waits behind the nodes ahead of it.

The right child, 7, joins the back.

poll() returns 3, and prints it.

The left child, 5, joins the back of the queue; it waits behind the nodes ahead of it.

The right child, 8, joins the back.

poll() returns 7, and prints it. A leaf: no children to add.

poll() returns 5, and prints it. A leaf: no children to add.

poll() returns 8, and prints it. A leaf: no children to add.

The queue is empty → the loop ends. Output: 4 3 7 5 8 — level by level (preorder would give 4 3 5 8 7).

public void levelOrder(TreeNode root) {
  if (root == null) return;
  Queue<TreeNode> queue = new LinkedList<>();
  queue.add(root);
  while (!queue.isEmpty()) {
    TreeNode temp = queue.poll();
    System.out.print(temp.data + " ");
    if (temp.left != null)
      queue.add(temp.left);
    if (temp.right != null)
      queue.add(temp.right);
  }
}

int evaluate(ExprNode node) {
  if (node.left == null && node.right == null)
    return node.value;           // leaf: operand
  int a = evaluate(node.left);
  int b = evaluate(node.right);
  switch (node.op) {             // internal node: operator
    case '+': return a + b;
    case '-': return a - b;
    case '*': return a * b;
    default:  return a / b;
  }
}

public int findMax(TreeNode root) {
  if (root == null) {
    return Integer.MIN_VALUE;
  }
  int result = root.data;
  int left = findMax(root.left);
  int right = findMax(root.right);
  if (left > result)
    result = left;
  if (right > result)
    result = right;
  return result;
}

int p = 0; // next root in pre[]
TreeNode build(int[] pre, int[] in, int lo, int hi) {
    if (lo > hi) return null;         // empty range
    TreeNode node = new TreeNode(pre[p++]);
    int m = lo; while (in[m] != node.data) m++;
    node.left = build(pre, in, lo, m - 1); // left part
    node.right = build(pre, in, m + 1, hi); // right part
    return node;
}

MethodTimeExtra spaceWhy?
Recursive pre/in/postO(n)O(h)At most h + 2 frames on the call stack (counting the null call)
Pre/in/post with a stackO(n)O(h)An explicit stack takes the place of recursion
Level order with a queueO(n)O(w)w: the number of nodes on the widest level
How big is h?In a balanced tree h ≈ log2 n; in a skewed tree h = n − 1. On very deep trees recursion can throw StackOverflowError → prefer the stack-based version.
How big is w?A perfect tree has ≈ n/2 nodes on its last level, so level order uses more memory on wide trees.

Summary

Common Mistakes

Forgetting the base caseAccessing node.left without first checking node == null throws a NullPointerException. Every recursive tree method starts with the empty tree.
Mixing up height definitionsCounting edges: a leaf has height 0, the empty tree −1. Counting nodes: a leaf has height 1, the empty tree 0. Pick one definition and stick to it.
Full ≠ completeFull: every node has 0 or 2 children. Complete: every level full except the last, which fills from the left. Neither implies the other.
Building a tree from one traversalA single order does not determine the tree. You need inorder plus preorder or postorder; preorder plus postorder is ambiguous when a node has only one child.
Mixing up the index formulas1-based: 2i, 2i + 1, ⌊i/2⌋. 0-based: 2i + 1, 2i + 2, ⌊(i − 1)/2⌋.
Recursion on deep treesA skewed tree has h = n − 1: hundreds of thousands of frames throw StackOverflowError → use the stack- or queue-based version.
