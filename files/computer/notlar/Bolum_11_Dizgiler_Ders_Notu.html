Dizgiler

Programların işlediği verinin büyük bölümü metindir: öğrenci adları, e-posta adresleri, kullanıcının klavyeden yazdığı cümleler, ekrana basılan raporlar. Java'da metin String sınıfının nesneleriyle temsil edilir. Bu not dizgilerin bellekte nasıl tutulduğunu, neden değiştirilemediğini ve en sık kullanılan metotlarını anlatır. İndislerle karakterlere erişim, alt dizgi alma, arama, bölme ve değiştirme işlemleri tek tek ele alınır. Ardından dizgilerin karşılaştırılması gelir: == ile equals arasındaki fark, compareTo ile sözlüksel sıra ve Türkçe harflerin yol açtığı tuzaklar. Klavyeden metin okuma, StringBuilder ile verimli birleştirme ve printf ile biçimli çıktı da notun konuları arasındadır. Son kesimdeki uygulamalar (ters çevirme, palindrom, sesli harf ve kelime sayma, harf frekansı, Sezar şifresi) bütün bu araçları bir araya getirir. Her program JDK 21 ile derlenip çalıştırılmıştır; verilen çıktılar programların gerçek çıktılarıdır.

11.1Dizgi nedir?

Şimdiye kadar yazılan programların çoğu sayılarla çalıştı. Bir sayı int ya da double değişkeninde tutulur ve aritmetik işlemlere girer. Metin ise başka bir yapıdır: harflerin, rakamların, boşlukların ve noktalama işaretlerinin sıralı bir dizisidir. Bu kesim metnin Java'daki iki yapı taşını, char ve String tiplerini tanıtır.

11.1.1Karakter ve dizgi

Tanım 11.1

Karakter (character), metnin tek bir harfi, rakamı, boşluğu ya da işaretidir. Java'da bir karakter char tipindeki bir değişkende tutulur ve tek tırnakla yazılır: 'T', '7', ' '. Dizgi (string), sıfır ya da daha fazla karakterin sıralı dizisidir. Java'da dizgiler String sınıfının nesneleridir ve çift tırnakla yazılır: "Tarkan", "7", "".

Tırnak türü önemlidir. 'T' tek bir karakterdir ve tipi char'dır. "T" ise uzunluğu 1 olan bir dizgidir ve tipi String'dir. İkisi ekranda aynı görünür ama Java için farklı tiplerdir. Bu yüzden bir dizgi bir char değişkenine atanamaz:

public class IlkelDegil {
    public static void main(String[] args) {
        char c = "T";
        System.out.println(c);
    }
}
IlkelDegil.java:3: error: incompatible types: String cannot be converted to char
        char c = "T";
                 ^
1 error

İleti, String tipinin char tipine dönüştürülemeyeceğini söyler. Doğrusu char c = 'T'; yazmaktır.

String sınıfı java.lang paketindedir. Bu paket her Java programına kendiliğinden eklenir; Scanner için gereken import satırı String için gerekmez. Programın içine doğrudan yazılan "Tarkan" gibi bir metne dizgi sabiti (string literal) denir.

11.1.2Dizgi bir nesnedir

char, int ve double gibi ilkel tipler (primitive type) değerlerini doğrudan değişkenin içinde tutar. String ise ilkel bir tip değildir; bir sınıftır. Bir String değişkeni metnin kendisini değil, metni taşıyan nesnenin bellekteki yerini tutar. Bu yer bilgisine referans (reference) denir. Şekil 11.1 iki tipin bellekteki görünümünü karşılaştırır.

Şekildeki iki bellek bölgesinin adı ilerideki bütün çizimlerde geçer. Yığın (stack), metotların yerel değişkenlerinin tutulduğu bölgedir. Heap ise new ile oluşturulan nesnelerin ve dizgilerin bulunduğu bölgedir. Yığındaki bir String değişkeni heap'teki nesneyi bir okla gösterir. Aynı nesneyi birden çok değişken gösterebilir. Dizgilerin karşılaştırılmasında bu paylaşım belirleyicidir.

Tanım 11.2

Bir nesne (object), bir sınıftan üretilmiş, kendi verisini ve metotlarını taşıyan bellek parçasıdır. Referans, bir nesnenin bellekteki yerini gösteren değerdir. String s = "Ada"; bildiriminde s değişkeni bir referanstır; "Ada" ise heap'teki nesnedir.

Nesne olmanın bir sonucu da metotlardır. Bir dizgiye ait işlemler nokta işaretiyle çağrılır: ad.length() dizginin uzunluğunu, ad.charAt(0) ilk karakterini verir. İlkel tiplerin metodu yoktur; c.length() gibi bir yazım derlenmez.

11.1.3Dizgi oluşturma, boş dizgi ve null

Bir dizgi değişkenine dört farklı biçimde ilk değer verilebilir:

String ad = "Tarkan";
String bos = "";
String kopya = new String(ad);
String yok = null;

İlk satır en yaygın biçimdir: ad, "Tarkan" sabitini gösterir. İkinci satırdaki "", hiç karakter içermeyen boş dizgidir. Üçüncü satır new ile yeni bir nesne oluşturur ve ad'ın içeriğini ona kopyalar. Dördüncü satırdaki null, değişkenin hiçbir nesneyi göstermediği anlamına gelir. Şekil 11.2 dört değişkenin bellekteki durumunu gösterir.

Şekildeki dizgi havuzu, heap içinde aynı sabitlerin tek bir kopyasının tutulduğu özel bir bölgedir. Buradaki kural kısadır: sabitle oluşturulan dizgi havuzdan gelir, new ise her zaman yeni bir nesne açar. Uygulamada new String(...) yazmaya neredeyse hiç gerek yoktur; dizgi sabiti tercih edilir.

Boş dizgi ile null sık karıştırılır. Boş dizgi gerçek bir nesnedir; uzunluğu 0'dır ve bütün metotları çağrılabilir. null ise bir nesne değildir; bir değişkenin “henüz hiçbir şeyi göstermiyorum” durumudur. null bir değişken üzerinden metot çağrılırsa program NullPointerException istisnasıyla durur. Aşağıdaki program dört değişkeni yazdırır, sonra yok.length()'i çağırır:

public class Olusturma {
    public static void main(String[] args) {
        String ad = "Tarkan";
        String bos = "";
        String kopya = new String(ad);
        String yok = null;
        char c = 'T';
        System.out.println(ad + " " + ad.length());
        System.out.println("[" + bos + "] " + bos.length());
        System.out.println(kopya + " " + kopya.length());
        System.out.println(yok);
        System.out.println(c);
        System.out.println(yok.length());
    }
}

Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.length()" because "yok" is null

Çıktıda boş dizginin köşeli parantezler arasında hiçbir şey göstermediği ve uzunluğunun 0 olduğu görülür. System.out.println(yok) hata vermez, null yazar. Hata ancak null üzerinden bir metot çağrıldığında oluşur. JDK 21'in iletisi sorunun nedenini de söyler: yok null olduğu için String.length() çağrılamaz.

Sık yapılan hata

Değeri henüz belli olmayan bir dizgi değişkenine null verip sonra metot çağırmak. Değişken bir döngüde ya da koşulda doldurulacaksa ilk değeri "" yapmak çoğu zaman daha güvenlidir. null gerçekten “değer yok” anlamı taşıyorsa metot çağrısından önce s != null denetimi yapılır.

11.1.4+ ile birleştirme

İki dizgiyi uç uca eklemeye dizgi birleştirme (string concatenation) denir. Java'da bunun için + operatörü kullanılır. Aynı operatör sayılarda toplama yapar. Hangisinin yapılacağına işlenenlerin tipi karar verir: iki işlenenden en az biri String ise + birleştirmedir, ikisi de sayıysa toplamadır.

public class Birlestirme {
    public static void main(String[] args) {
        String sayi1 = "12";
        String sayi2 = "34";
        String toplam = sayi1 + sayi2;
        System.out.println(toplam);
        int a = 12, b = 34;
        System.out.println(a + b);
        System.out.println(sayi1 + 3 + 4);
        System.out.println(3 + 4 + sayi1);
        System.out.println(sayi1 + (3 + 4));
        System.out.println("Toplam: " + a + b);
        System.out.println("Toplam: " + (a + b));
        System.out.println("x" + null + 'c' + 2.5 + true);
        System.out.println("Merhaba".concat(" dünya"));
    }
}

Program satır satır şöyle çalışır. sayi1 + sayi2 iki dizgiyi birleştirir; değişkenin adı “toplam” olsa da sonuç "1234"'tür. a + b iki int'i toplar: 46. Sonraki iki satır işlem sırasının etkisini gösterir. + soldan sağa işlenir:

  • sayi1 + 3 + 4: önce "12" + 3 hesaplanır. Bir işlenen dizgi olduğu için 3 dizgiye çevrilir: "123". Sonra "123" + 4 = "1234".
  • 3 + 4 + sayi1: önce 3 + 4 hesaplanır. İkisi de sayıdır: 7. Sonra 7 + "12" = "712".
  • sayi1 + (3 + 4): parantez önce hesaplanır: 7. Sonra "12" + 7 = "127".

"Toplam: " + a + b satırı da aynı tuzağa düşer: soldaki dizgi yüzünden iki sayı da birer birer metne eklenir ve “Toplam: 1234” yazılır. Toplamın yazılması için parantez gerekir: "Toplam: " + (a + b). Bir dizgiye null, char, double ve boolean değerleri de eklenebilir; her biri metin karşılığına çevrilir. concat metodu da iki dizgiyi birleştirir, ancak yalnızca dizgi kabul eder.

Örnek 11.1

int x = 5, y = 2; iken "x+y=" + x + y ve x + y + "=x+y" ifadelerinin değerleri nedir?

Çözüm. İlk ifadede en soldaki işlenen dizgidir. "x+y=" + 5 = "x+y=5", ardından "x+y=5" + 2 = "x+y=52". İkinci ifadede ilk iki işlenen sayıdır: 5 + 2 = 7. Sonra 7 + "=x+y" = "7=x+y". Aynı üç işlenen, sıraları değişince farklı sonuç verir.

11.1.5char bir sayıdır

Bilgisayar karakterleri sayıyla saklar. Her karakterin Unicode standardında bir kod numarası vardır: 'a' 97, 'b' 98, 'A' 65, '0' 48'dir. Java'da char aslında 16 bitlik işaretsiz bir tam sayı tipidir. Bu yüzden bir char aritmetik işlemlere girebilir. Sonucun tipi kurala bağlıdır: char ile bir tam sayı ya da iki char toplanınca sonuç int olur.

public class CharAritmetik {
    public static void main(String[] args) {
        char k = 'a';
        System.out.println(k + 1);
        System.out.println((char) (k + 1));
        System.out.println("" + k + 1);
        System.out.println('a' + 'b');
        System.out.println("" + 'a' + 'b');
        k++;
        System.out.println(k);
    }
}

k + 1 bir int'tir: 97 + 1 = 98. (char) (k + 1) bu sayıyı yeniden karaktere çevirir: b. "" + k + 1 ifadesinde en soldaki boş dizgi bütün ifadeyi birleştirmeye çevirir: önce "a", sonra "a1". 'a' + 'b' ise iki sayının toplamıdır: 97 + 98 = 195. İki karakteri yan yana yazdırmak için başa yine "" konur. k++ ise char değişkenini olduğu yerde bir artırır ve tipi değişmez: b.

Karakterlerin sayı olması dizgi işlemlerinin çoğunda işe yarar. İki küçük harfin farkı alfabedeki uzaklıklarını verir: 'k' − 'a' = 107 − 97 = 10. Bir rakam karakterinden '0' çıkarılınca rakamın sayı değeri bulunur: '7' − '0' = 55 − 48 = 7. Harf frekansı ve Sezar şifresi uygulamaları bu iki fikre dayanır.

public class CharSayi {

        System.out.println('k' - 'a');
        System.out.println((char) ('a' + 10));
        System.out.println((int) 'ç' + " " + ('ç' - 'a') + " " + (int) 'ı' + " " + (int) 'İ' + " " + (int) 'ş');
        System.out.println('7' - '0');
    }
}

11.2Değiştirilemezlik

Dizgilerin en önemli özelliği, oluşturulduktan sonra içeriklerinin değişmemesidir. Bu özellik ilk bakışta garip gelir: s = s + "!" yazınca s değişmiş gibi görünür. Gerçekte değişen nesne değil, değişkenin gösterdiği yerdir.

11.2.1Yeni nesne, aynı eski nesne

Tanım 11.3

Oluşturulduktan sonra içeriği değiştirilemeyen nesneye değiştirilemez (immutable) nesne denir. String değiştirilemez bir sınıftır: hiçbir metodu nesnenin karakterlerini değiştirmez. Dizgiyi “değiştiren” her işlem (birleştirme, büyük harfe çevirme, alt dizgi alma, değiştirme) yeni bir String nesnesi üretir ve onu döndürür. Bu özelliğin adı değiştirilemezliktir (immutability).

Şekil 11.3 en basit örneği gösterir. String s = "Merhaba"; satırından sonra s, yedi karakterlik nesneyi gösterir. s = s + "!"; satırı bu nesneye ünlem eklemez. Önce s + "!" hesaplanır ve sekiz karakterlik yeni bir nesne oluşur. Sonra atama, s'nin okunu bu yeni nesneye taşır. Eski "Merhaba" nesnesi olduğu gibi kalır.

Bunu bir programla da görmek mümkündür. Atamadan önce eski nesneyi gösteren ikinci bir değişken (eski) tutulursa, atamadan sonra iki değişkenin farklı nesneleri gösterdiği anlaşılır:

public class Unlem {
    public static void main(String[] args) {
        String s = "Merhaba";
        String eski = s;
        s = s + "!";
        System.out.println(s);
        System.out.println(eski);
        System.out.println(s == eski);
    }
}
Merhaba!
Merhaba
false

eski hâlâ “Merhaba”yı gösterir. s == eski karşılaştırması, iki değişkenin aynı nesneyi gösterip göstermediğini sorar ve false verir: artık iki ayrı nesne vardır. Hiçbir değişkenin göstermediği nesneler zamanla gereksiz hâle gelir. Java'da bu nesneleri çöp toplayıcı (garbage collector) kendiliğinden temizler; programcının belleği elle geri vermesi gerekmez.

11.2.2toUpperCase örneğini adım adım izlemek

Değiştirilemezliğin pratikteki sonucu şudur: bir dizgi metodunun sonucu kullanılmak isteniyorsa bir değişkene atanmalıdır. Aşağıdaki beş satır bu noktayı gösterir.

String dil = "java";
dil.toUpperCase();
System.out.println(dil); // java
dil = dil.toUpperCase();
System.out.println(dil); // JAVA
java
JAVA

İkinci satır dil.toUpperCase()'i çağırır ama dönen değeri hiçbir yere koymaz. Metot görevini yapar ve yeni bir "JAVA" nesnesi üretir. Ne var ki bu nesneyi gösteren bir değişken yoktur; sonuç kaybolur. dil eski nesneyi göstermeye devam ettiği için üçüncü satır java yazar. Dördüncü satırda aynı çağrının sonucu dil'e atanır; ok yeni nesneye taşınır ve beşinci satır JAVA yazar. Tablo 11.1 beş satırın izleme tablosudur; Şekil 11.4 ise kritik iki anı gösterir.

Sık yapılan hata

Doğrusu ad = ad.trim(); biçiminde sonucu yeniden atamaktır. Bazı geliştirme ortamları dönen değeri kullanılmayan çağrılar için uyarı gösterir.

Bir dizginin tek bir karakterini olduğu yerde değiştirmenin yolu da yoktur. Dizilerde a[0] = 5; yazılabilir, ama dizgilerde buna karşılık gelen bir işlem yoktur. charAt yalnızca okumak içindir; ona değer atanamaz:

public class SetCharAt {
    public static void main(String[] args) {
        String s = "java";
        s.charAt(0) = 'J';
        System.out.println(s);
    }
}
SetCharAt.java:4: error: unexpected type
        s.charAt(0) = 'J';
                ^
  required: variable
  found:    value

İleti, eşittirin solunda bir değişken beklendiğini ama bir değer bulunduğunu söyler. s.charAt(0) bir değer üretir, bir bellek yeri değildir. İlk harfi büyütmek için yeni bir dizgi kurulur: s = Character.toUpperCase(s.charAt(0)) + s.substring(1); Bu satır "Java" üretir.

11.2.3Değiştirilemezlik neden yararlıdır?

Her değişiklikte yeni nesne üretmek israf gibi görünebilir. Java'nın tasarımcıları bu bedeli üç kazanç için ödemeyi seçmiştir:

  • Güvenli paylaşım. Aynı dizgi nesnesini birden çok değişken gösterebilir. Hiçbiri nesneyi değiştiremeyeceği için bir değişken üzerinden yapılan işlem ötekileri etkilemez. Dizgi havuzu bu sayede mümkündür: programdaki bütün "Giresun" sabitleri tek bir nesneyi paylaşır.
  • Öngörülebilirlik. Bir dizgi bir metoda gönderildiğinde metot onu bozamaz. Çağıran taraf, metottan dönünce dizginin aynı kaldığından emindir.
  • Güvenlik. Dosya adları, ağ adresleri ve parolalar dizgilerde taşınır. Denetimden geçmiş bir dosya adının sonradan değiştirilememesi önemli bir güvencedir.

Bedel ise çok sayıda birleştirmenin yavaşlamasıdır. Bir döngüde binlerce kez s = s + x yazılırsa her turda yeni nesne üretilir ve eski içerik kopyalanır. Bu durum için Java değiştirilebilir bir yardımcı sınıf sunar: StringBuilder.

11.3İndisleme

Bir dizginin karakterleri sıralıdır ve her birinin bir sıra numarası vardır. Bu numaraya indis (index) denir. Diziler gibi dizgilerde de sayma 0'dan başlar.

Tanım 11.4

Uzunluğu n olan bir dizginin karakterleri 0, 1, …, n − 1 indislerindedir. İlk karakter 0, son karakter n − 1 indisindedir. Bir karaktere indisiyle erişmeye indisleme (indexing) denir. Java'da s.length() dizginin uzunluğunu, s.charAt(i) i indisindeki karakteri bir char değeri biçiminde döndürür.

11.4.3split ile bölme

Virgülle ayrılmış bir liste, boşluklarla ayrılmış bir cümle ya da noktalı bir tarih, parçalara ayrılarak işlenir. Parçaları ayıran karaktere ayırıcı (delimiter) denir. split metodu dizgiyi ayırıcıların bulunduğu yerlerden keser ve parçaları bir String dizisinde döndürür.

import java.util.Arrays;

public class SplitReplace {
    public static void main(String[] args) {
        String[] p = "a,b,,c".split(",");
        System.out.println(Arrays.toString(p) + " " + p.length); // [a, b, , c] 4
        String s = "ali veli";
        String t = s.replace('l', 'L');
        System.out.println(t); // aLi veLi
        System.out.println(s); // ali veli
        String[] q = "a,b,,".split(",");
        System.out.println(Arrays.toString(q) + " " + q.length);
        String[] r = ",a,b".split(",");
        System.out.println(Arrays.toString(r) + " " + r.length);
        String[] u = "3.14".split(".");
        System.out.println(u.length);
        String[] v = "3.14".split("\\.");
        System.out.println(Arrays.toString(v));
    }
}

Ek satırlar split'in üç kuralını gösterir:

  • Sondaki boş parçalar atılır. "a,b,,".split(",") dört parça değil iki parça verir: [a, b]. Sondaki iki boş parça diziye girmez.
  • Baştaki boş parça kalır. ",a,b".split(",") üç parça verir: [, a, b]. İlk virgülden önceki boş metin bir parça sayılır.
  • Ayırıcı bir düzenli ifadedir. split'e verilen metin düz bir karakter değil, bir kalıptır. Kalıp dilinde nokta “herhangi bir karakter” anlamına gelir. Bu yüzden "3.14".split(".") her karakterden keser, bütün parçalar boş kalır ve sondaki boş parçalar atılınca dizi uzunluğu 0 olur. Noktanın kendisiyle bölmek için split("\\.") yazılır ve sonuç [3, 14] olur.
Tanım 11.5

Düzenli ifade (regular expression), bir metin kalıbını tarif eden küçük bir dildir. Bazı karakterlerin bu dilde özel anlamı vardır: . herhangi bir karakter, + “bir ya da daha fazla”, [0-9] herhangi bir rakam, \s herhangi bir boşluk karakteri anlamına gelir. Özel bir karakteri kendi anlamıyla kullanmak için önüne ters bölü konur. Java dizgi sabitinde ters bölünün kendisi \\ diye yazıldığı için kalıp "\\." ya da "\\s+" biçimini alır.

Örnek 11.3

"23.10.2026".split("\\.") ve "elma, armut,kiraz".split(",") kaç parça verir, parçalar nelerdir?

Çözüm. İlk dizgide iki nokta vardır; üç parça çıkar: "23", "10", "2026". İkinci dizgide iki virgül vardır; yine üç parça çıkar: "elma", " armut", "kiraz". İkinci parçanın başındaki boşluk korunur, çünkü ayırıcı yalnızca virgüldür. Boşluğun da atılması için ya her parçaya strip() uygulanır ya da ayırıcı ",\\s*" (virgül ve ardından sıfır ya da daha fazla boşluk) biçiminde verilir.

11.5Karşılaştırma

İki dizginin aynı olup olmadığını sormak, programlamanın en sık işlerinden biridir: girilen parola doğru mu, kullanıcı “evet” mi yazdı, iki öğrencinin adı aynı mı? Sayılarda bu soru == ile sorulur. Dizgilerde ise == beklenen soruyu sormaz.

11.5.1== ile equals

Bir String değişkeni bir referans tuttuğu için a == b iki referansı karşılaştırır. Soru “iki değişken aynı nesneyi mi gösteriyor?” olur. İki ayrı nesne aynı karakterleri taşısa bile == false verir. İçeriği karşılaştırmak için equals metodu kullanılır.

11.5.3compareTo ve sözlüksel sıra

Eşitlik dışında iki dizginin sırası da sorulabilir: hangisi sözlükte önce gelir? Bu sıraya sözlüksel sıra (lexicographic order) denir. a.compareTo(b) bir tam sayı döndürür. Sonuç negatifse a önce, sıfırsa ikisi eşit, pozitifse a sonra gelir.

Tanım 11.8

a.compareTo(b) iki dizgiyi baştan başlayarak karakter karakter karşılaştırır. İki durum vardır:

  1. İlk farklı karakter k konumundaysa sonuç a.charAt(k) − b.charAt(k)'dır; yani iki karakterin kod farkıdır.
  2. Kısa olan dizginin bütün karakterleri uzun olanın başıyla aynıysa sonuç a.length() − b.length()'dir; yani uzunluk farkıdır.

İki dizgi tamamen aynıysa ikinci kural 0 verir.

String x = "elma";
String y = "armut";
System.out.println(x.compareTo(y)); // 4
String k = "kedi";
System.out.println(k.compareTo("kediler")); // -3

Sunumdaki iki örnek, iki kuralı ayrı ayrı işletir. Şekil 11.14 her ikisinin kritik adımını gösterir.

  • "elma".compareTo("armut"): 0 konumunda 'e' ile 'a' karşılaşır ve farklıdır. Sonuç 'e' − 'a' = 101 − 97 = 4'tür. Pozitif olduğu için “elma”, “armut”tan sonra gelir. Dizgilerin uzunlukları (4 ve 5) sonuca hiç girmez; ilk farklı karakter kararı verir.
  • "kedi".compareTo("kediler"): ilk dört konumda k=k, e=e, d=d, i=i'dir. Ardından “kedi” biter; farklı karakter bulunamamıştır. Sonuç uzunluk farkıdır: 4 − 7 = −3. Negatif olduğu için kısa olan “kedi” önce gelir.

11.5.4Türkçe karakterler ve yerel ayar

Büyük-küçük harf dönüşümü çoğu dilde basittir: a ↔ A, b ↔ B. Türkçede ise noktalı ve noktasız iki ayrı i harfi vardır: i ↔ İ ve ı ↔ I. İngilizcede bu çiftler i ↔ I biçimindedir. Aynı “I” harfinin küçüğü İngilizcede “i”, Türkçede “ı”dır. Java bu farkı yerel ayar (locale) ile çözer. Yerel ayar, bir dilin ve bölgenin yazım kurallarını taşıyan java.util.Locale nesnesidir.

Tanım 11.9

toLowerCase(Locale) ve toUpperCase(Locale), harf dönüşümünü verilen dilin kurallarına göre yapar. Türkçe için yerel ayar Locale.forLanguageTag("tr"), İngilizce için Locale.ENGLISH ile elde edilir. Parametresiz toLowerCase() ve toUpperCase(), programın çalıştığı makinenin varsayılan yerel ayarını kullanır.

import java.util.Locale;

public class TurkceLocale {

11.6Bellek: dizgi havuzu

Bir programda aynı dizgi sabiti pek çok yerde geçebilir: “Giresun”, “evet”, boş dizgi. Her biri için ayrı nesne açmak belleği boşa harcar. Java bu yüzden sabitleri ortak bir havuzda toplar.

11.6.1Havuz ve new

Tanım 11.10

Dizgi havuzu (string pool), Java sanal makinesinin dizgi sabitlerini sakladığı bellek bölgesidir. Aynı içerikli bütün sabitler havuzdaki tek bir nesneyi paylaşır. new String(...) ise havuza bakmaz ve her çağrıda heap'te yeni bir nesne oluşturur.

Paylaşım ancak dizgiler değiştirilemez olduğu için güvenlidir. Değiştirilebilseydi, bir değişken üzerinden yapılan değişiklik aynı sabiti kullanan bütün değişkenleri etkilerdi. Şekil 11.15 üç değişkenin durumunu gösterir.

public class Havuz {
    public static void main(String[] args) {
        String a = "Giresun";
        String c = "Giresun";
        String b = new String("Giresun");
        String d = new String("Giresun");
        System.out.println((a == c) + " " + (a == b) + " " + (b == d));
        System.out.println(a.equals(b) + " " + b.equals(d));
        System.out.println((b.intern() == a) + " " + (b.intern() == b));
    }
}
true false false
true true
true false

İlk satır üç referans karşılaştırması yapar. a == c doğrudur: ikisi de havuzdaki nesneyi gösterir. a == b yanlıştır: b heap'te ayrı bir nesnedir. b == d de yanlıştır: iki new çağrısı iki ayrı nesne üretir. İkinci satırdaki equals sınamaları ise hepsi doğrudur, çünkü içerikler aynıdır.

11.6.2Sabit birleştirme ve intern

Bir dizginin havuzdan gelip gelmediği her zaman koddan kolayca okunmaz. Aşağıdaki program bunun iki ince durumunu gösterir:

String a = "a", b = "b";
String r = a + b;
final String f = "a";
System.out.println(("a" + "b") == "ab");  // true
System.out.println((f + "b") == "ab");    // true
System.out.println(r == "ab");            // false
System.out.println(r.equals("ab"));       // true
System.out.println(r.intern() == "ab");   // true
true
true
false
true
true

Beş sonuç şöyle açıklanır:

  1. ("a" + "b") == "ab" doğrudur. İki işlenen de sabit olduğu için birleştirmeyi program çalışmadan önce derleyici yapar. Derlenmiş kodda "a" + "b" yerine doğrudan "ab" sabiti bulunur ve bu sabit havuzdan gelir.
  2. (f + "b") == "ab" de doğrudur. f, final ile bildirilmiş ve bir sabitle başlatılmıştır. Değeri hiç değişemeyeceği için derleyici onu da bir sabit gibi işler.
  3. r == "ab" yanlıştır. r = a + b satırındaki a ve b sıradan değişkenlerdir. Birleştirme çalışma zamanında yapılır ve sonuç heap'te yeni bir nesnedir.
  4. r.equals("ab") doğrudur; içerikler aynıdır.
  5. r.intern() == "ab" doğrudur. intern() metodu havuza bakar: aynı içerikte bir dizgi varsa onu, yoksa dizgiyi havuza ekleyip onu döndürür. Dönen referans havuzdaki "ab"'dir.

Derleme sırasında değeri belli olan ifadelere sabit ifade (constant expression) denir: dizgi sabitleri, final sabitler ve bunların birleşimleri. Sabit ifadelerin sonucu havuza konur. Değişken içeren her birleştirme ise yeni bir nesne üretir.

intern'ün etkisi Havuz programının son satırında da görülür. b.intern() == a doğrudur: b'nin içeriği havuzda vardır ve intern havuzdaki nesneyi döndürür. b.intern() == b ise yanlıştır: b'nin kendisi havuz dışındaki nesnedir. Uygulamada intern'e nadiren gerek duyulur; burada havuzun işleyişini görünür kılmak için kullanılmıştır.

Sık yapılan hata

Birkaç denemede =='nin doğru sonuç verdiğini görüp dizgileri == ile karşılaştırmaya devam etmek. Denemelerde kullanılan sabitler havuzda paylaşıldığı için == tesadüfen doğru çıkar. Aynı kod, metin klavyeden ya da bir dosyadan geldiğinde yanlış sonuç verir. =='nin doğru çıkması içeriklerin eşit olduğunu değil, nesnenin aynı olduğunu gösterir.

11.7Scanner ile metin girdisi

Klavyeden metin okumak için java.util.Scanner sınıfı kullanılır. Sınıfın iki metin okuma metodu vardır: next() bir kelime, nextLine() bir satır okur. İki metodun davranışını anlamanın anahtarı, klavyeden gelen karakterlerin beklediği tampondur (buffer).

11.7.1next ve nextLine

Kullanıcı bir şey yazıp Enter tuşuna bastığında yazdığı karakterler ve satır sonu karakteri tampona girer. Bu notta satır sonu karakteri ⏎ ile gösterilir. Scanner'ın her okuma metodu tamponun başından karakter alır ve okuma konumunu öne kaydırır. Okunan karakterler bir daha okunmaz.

Tanım 11.11

next(), baştaki boşlukları ve satır sonlarını atlar, ardından boşluk olmayan karakterleri ilk boşluğa ya da satır sonuna kadar okur. Bu parçaya kelime (token) denir. Kelimeden sonraki boşluk ya da ⏎ tamponda kalır. nextLine() ise bulunduğu konumdan satır sonuna kadar her şeyi, boşluklar dahil okur. ⏎'ı tüketir ama sonuca eklemez.

import java.util.Scanner;
// ...

String satir = klavye.nextLine();

11.8Birleştirme ve StringBuilder

+ operatörü birkaç dizgiyi birleştirmek için okunaklı ve yeterlidir. Ancak birleştirme bir döngünün içinde binlerce kez yapılırsa değiştirilemezliğin bedeli belirginleşir.

11.8.1Döngüde + kullanmanın maliyeti

s = s + x satırı s'yi uzatmaz. Her çalıştığında s'nin bütün karakterlerini ve x'i taşıyan yeni bir nesne üretir. Eski nesne çöpe gider. Şekil 11.18 bunu üç turluk bir döngü için gösterir.

Kopyalanan karakter sayısı hesaplanabilir. Her turda tek karakter eklenen bir döngü düşünelim. 1. turda 1 karakterlik, 2. turda 2 karakterlik, n. turda n karakterlik yeni bir nesne kurulur. Toplam kopyalanan karakter sayısı şudur:

1 + 2 + 3 + … + n = n(n + 1) / 2

Bu toplam kabaca n²/2'dir. n = 1.000 için 500.500, n = 100.000 için yaklaşık 5 milyar karakter eder. Aşağıdaki program bu sayıları döngünün içinde sayarak doğrular:

public class Maliyet {
    public static void main(String[] args) {
        for (int n : new int[]{1000, 10000, 100000}) {
            long kopya = 0;
            String s = "";
            for (int i = 0; i < n; i++) {
                kopya += s.length() + 1;
                s = s + "x";
            }
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) {
                sb.append('x');
            }
            System.out.println(n + " " + kopya + " " + (s.length() == sb.length()));
        }
    }
}

n on katına çıktığında kopyalanan karakter sayısı yaklaşık yüz katına çıkar: 500.500'den 50.005.000'e, oradan 5.000.050.000'e. Bu büyüme hızına karesel büyüme denir ve büyük n değerlerinde program belirgin biçimde yavaşlar. StringBuilder ile yapılan ikinci döngüde ise her karakter tampona bir kez yazılır; toplam iş n ile orantılıdır. Satırın sonundaki true, iki yöntemin aynı uzunlukta dizgi ürettiğini gösterir.

11.9.6Sezar şifresi

Sezar şifresi (Caesar cipher), her harfi alfabede sabit sayıda konum ileri kaydıran çok eski bir şifreleme yöntemidir. Kaydırma 3 ise 'a' → 'd', 'b' → 'e' olur. Alfabenin sonundaki harfler başa sarar: 'x' → 'a', 'y' → 'b', 'z' → 'c'.

Başa sarmanın aritmetiği mod işlemidir. Harfin alfabedeki yeri c - 'a' ile 0–25 arasında bir sayıya çevrilir. Kaydırma eklenir ve sonucun 26'ya bölümünden kalan alınır:

yer = (c − 'a' + kaydir) % 26

Kalan her zaman 0 ile 25 arasındadır; bu yüzden sonuç alfabenin dışına taşmaz. Ardından 'a' + yer ile yeniden harfe dönülür.

for (int i = 0; i < metin.length(); i++) {
  char c = metin.charAt(i);
  int yer = (c - 'a' + kaydir) % 26;
  char yeni = (char) ('a' + yer);
  sifreli.append(yeni);
}

        System.out.println("[" + sb + "] " + sb.length() + " " + s.length());
    }
}
[EyEdipAdanadapideye] 19 26

26 karakterlik metinde yedi boşluk vardır: baştaki, sondaki, “Edip”ten sonraki çift boşluk ve üç tek boşluk. Geriye 19 karakter kalır. Bu sayı palindrom örneğindeki temizlenmiş metnin uzunluğuyla aynıdır; harf büyüklüğü dışında sonuç da aynıdır.

11.10printf ile biçimleme

Bir rapor ya da tablo yazdırırken değerlerin hizalı durması, ondalıklı sayıların belirli basamakta kesilmesi istenir. + ile birleştirme bunu kolayca sağlamaz. System.out.printf metodu ise metni bir kalıba göre biçimler (formatting).

Tanım 11.14

printf'in ilk parametresi biçim dizgisidir (format string). Biçim dizgisindeki düz metin olduğu gibi yazılır. % ile başlayan her biçim belirteci (format specifier) ise sıradaki argümanın yerini tutar ve onun nasıl yazılacağını söyler. Belirtecin genel yapısı %[-][genişlik][.duyarlık]tür biçimindedir. Başlıca türler s (metin), d (tam sayı), f (kayan noktalı sayı) ve n'dir (satır sonu).

String ad = "Java"; int adet = 3; double fiyat = 17.5;
System.out.printf("%-8s %3d %7.2f%n", ad, adet, fiyat);
Java       3   17.50
[Java    ][  3][  17.50]
[    Java][3  ][17.5][1.750000e+01]
[Giresun][12345][3][4]
true c 50%

Programın ilk printf satırı sunumdaki örnektir. Üç belirteç üç argümanla sırayla eşleşir. Şekil 11.26 çıktının hücre hücre nasıl oluştuğunu gösterir.

  • %-8s: metin en az 8 karakterlik alana yazılır. Eksi işareti sola yaslar; “Java” dört karakter olduğu için sağına dört boşluk eklenir.
  • %3d: tam sayı 3 karakterlik alana sağa yaslanır; 3'ün önüne iki boşluk gelir.
  • %7.2f: sayı virgülden sonra iki basamakla yazılır (“17.50”, beş karakter) ve 7 karakterlik alana sağa yaslanır; önüne iki boşluk gelir.
  • %n: işletim sistemine uygun satır sonu ekler.

Programın sonraki satırları alanların sınırını köşeli parantezle görünür kılar ve başka biçimleri dener. %8s eksi işareti olmadığı için sağa yaslar. %-3d sola yaslar. %.1f genişlik vermeden bir ondalık yazar. %e bilimsel gösterimdir: 1,75 × 10¹. Dördüncü satır iki önemli kuralı gösterir. Birincisi, genişlik bir alt sınırdır: “Giresun” 7 karakter olduğu için %3s onu kesmez, tamamını yazar. İkincisi, %.0f yarımları yukarı yuvarlar: 2,5 → 3 ve 3,5 → 4. Son satırda %s'nin boolean ve char değerlerini de yazdığı görülür. %% ise yüzde işaretinin kendisidir.

Biçim belirteçleri tablolar için idealdir. Aynı genişlikteki alanlar alt alta yazıldığında sütunlar kendiliğinden hizalanır:

public class Tablo {
    public static void main(String[] args) {
        String[] urun = {"Kalem", "Defter", "Hesap makinesi"};
        int[] adet = {12, 3, 1};
        double[] fiyat = {7.5, 42.0, 349.9};
        System.out.printf("%-15s %5s %9s%n", "Ürün", "Adet", "Tutar");
        for (int i = 0; i < urun.length; i++) {
            System.out.printf("%-15s %5d %9.2f%n", urun[i], adet[i], adet[i] * fiyat[i]);
        }
    }
}
Ürün             Adet     Tutar
Kalem              12     90.00
Defter              3    126.00
Hesap makinesi      1    349.90

Başlık satırı ile veri satırları aynı genişlikleri (15, 5, 9) kullandığı için sütunlar düzgün durur. Metin sütunu sola, sayı sütunları sağa yaslanmıştır; tablolarda alışılmış düzen budur. Tutar sütununda 12 × 7,5 = 90, 3 × 42 = 126 ve 1 × 349,9 = 349,9 iki ondalıkla yazılmıştır.

Ondalık ayırıcı yerel ayara bağlıdır. Aynı program Türkçe ayarlı bir makinede şunu yazar:

Ürün             Adet     Tutar
Kalem              12     90,00
Defter              3    126,00
Hesap makinesi      1    349,90

Sayının kendisi değişmez, yalnızca yazılışı değişir. Sunumdaki örnek de Türkçe makinede “17,50” yazar. Her makinede aynı çıktı isteniyorsa printf(Locale.US, …) biçiminde yerel ayar ilk parametrede verilir.

Biçim dizgisini derleyici denetlemez. Belirteç ile argümanın tipi uyuşmazsa ya da argüman eksikse hata program çalışırken ortaya çıkar:

public class BicimHata {
    public static void main(String[] args) {
        System.out.printf("%d%n", 3.5);
    }
}
Exception in thread "main" java.util.IllegalFormatConversionException: d != java.lang.Double

%d bir tam sayı bekler, 3.5 ise double'dır. İleti, d dönüşümünün Double ile kullanılamayacağını söyler. Java sayıyı yuvarlamaz ya da kesmez, istisna fırlatır. Eksik argümanda da benzer bir istisna oluşur; ilk belirteç yazıldıktan sonra program durur:

public class BicimEksik {
    public static void main(String[] args) {
        System.out.printf("%s ve %s%n", "Ada");
    }
}
Ada ve 
Exception in thread "main" java.util.MissingFormatArgumentException: Format specifier '%s'
Sık yapılan hata

Ondalıklı bir değeri %d ile ya da tam sayıyı %f ile yazdırmak. İkisi de IllegalFormatConversionException fırlatır. int için %d, double için %f kullanılır; her tip için güvenli seçenek %s'dir ama o da biçim denetimi sağlamaz. Satır sonunu unutmak da sık görülür: printf, println gibi kendiliğinden satır atlamaz; %n gerekir.

11.11Unicode ve metin uzunluğu

Java'nın char tipi 16 bittir ve 65.536 farklı değer alabilir. Türkçe harfler de dahil gündelik metinlerin hemen bütün karakterleri bu aralıktadır. Ancak Unicode standardı bugün 150 binden fazla karakter tanımlar: eski yazı sistemleri, matematik simgeleri, emojiler. Bunların bir kısmı tek bir char'a sığmaz.

Tanım 11.15

Unicode'da her karakterin bir numarası vardır; bu numaraya kod noktası (code point) denir. Java dizgileri bu numaraları UTF-16 kodlamasıyla, 16 bitlik kod birimleri (code unit) biçiminde saklar. Bir char bir kod birimidir. U+FFFF'ten büyük kod noktaları iki kod biriminden oluşan bir çiftle saklanır. length() kod birimi sayısını verir, karakter sayısını değil.

public class UnicodeOrnek {
    public static void main(String[] args) {
        String cay = "çay";
        String emoji = "😀";
        System.out.println(cay.length() + " " + emoji.length() + " " + emoji.codePointCount(0, emoji.length()));
        System.out.printf("%X %X %X%n", (int) emoji.charAt(0), (int) emoji.charAt(1), emoji.codePointAt(0));
        String birlesik = "çay";
        System.out.println(birlesik.length() + " " + birlesik.equals(cay));
        System.out.println(java.text.Normalizer.normalize(birlesik, java.text.Normalizer.Form.NFC).equals(cay));
        System.out.println("straße".toUpperCase(java.util.Locale.ROOT) + " " + "straße".length() + " " + "straße".toUpperCase(java.util.Locale.ROOT).length());
    }
}
3 2 1
D83D DE00 1F600
4 false
true
STRASSE 6 7

İlk satırda “çay”ın uzunluğu 3, emojinin uzunluğu 2'dir. codePointCount ise kod noktalarını sayar ve emoji için 1 verir. İkinci satır emojinin iki kod birimini ve gerçek kod noktasını onaltılık tabanda yazar: U+1F600. Bu sayı 65.535'ten büyük olduğu için tek bir char'a sığmaz.

Üçüncü satır daha ince bir durumu gösterir. “ç” harfi Unicode'da iki yolla yazılabilir: tek bir hazır karakter (U+00E7) ya da bir “c” ve onun altına eklenen ayrı bir çengel işareti (U+0327). İkinci yazım ekranda aynı görünür ama uzunluğu 4'tür ve equals ile ilk yazıma eşit değildir. java.text.Normalizer sınıfı iki yazımı aynı biçime getirir; dördüncü satır normalleştirmeden sonra eşitliğin sağlandığını gösterir. Son satırda Almanca “ß” harfi büyük harfe çevrilince iki harfe, “SS”ye dönüşür ve dizgi uzar: 6 karakterlik “straße”, 7 karakterlik “STRASSE” olur.

Bu ayrıntıların günlük programlardaki sonucu şudur: Türkçe metinlerde length() ve charAt beklendiği gibi çalışır. Emoji, birleşik işaretler ya da başka yazı sistemleri içeren metinlerde ise “kullanıcının gördüğü karakter sayısı” length()'ten farklı olabilir. Bu tür metinlerde ters çevirme gibi işlemler de bir çifti ortasından bölüp bozuk karakterler üretebilir.

11.12Özet

  • char tek bir karakteri tek tırnakla ('T'), String karakter dizisini çift tırnakla ("Tarkan") tutar. String ilkel tip değil, java.lang paketindeki bir sınıftır; değişken nesnenin referansını tutar. "" uzunluğu 0 olan gerçek bir nesnedir; null hiçbir nesneyi göstermez ve üzerinden metot çağrılırsa NullPointerException oluşur.
  • +, işlenenlerden biri dizgiyse birleştirme, ikisi de sayıysa toplamadır ve soldan sağa işlenir: "12" + 3 + 4 = "1234", 3 + 4 + "12" = "712". char bir sayıdır: 'a' + 1 = 98, 'k' − 'a' = 10.
  • String değiştirilemezdir. toUpperCase, replace, substring, + yeni bir nesne döndürür; sonuç atanmazsa kaybolur. Değişen nesne değil, değişkenin gösterdiği yerdir. Kimsenin göstermediği nesneleri çöp toplayıcı temizler.
  • İndisler 0'dan length() − 1'e kadardır; sınır dışı indis StringIndexOutOfBoundsException verir. length() dizgilerde metot, dizilerde length alandır.
  • substring(a, b): a dahil, b hariç; uzunluk b − a; geçerli aralık 0 ≤ a ≤ b ≤ length(). indexOf ilk konumu ya da −1 verir. split düzenli ifade alır; ardışık ayırıcılar boş parça üretir, sondaki boş parçalar atılır.
  • replace düz metin, replaceAll düzenli ifade arar. trim yalnızca ASCII boşlukları, strip bütün Unicode boşluklarını siler. format ve printf yerel ayara bağlıdır.
  • == referansı, equals içeriği karşılaştırır; dizgiler her zaman equals ile karşılaştırılır. compareTo ilk farklı karakterin kod farkını, fark yoksa uzunluk farkını verir. Büyük harfler küçüklerden, İngilizce harfler Türkçe harflerden önce gelir; Türkçe sıralama için Collator kullanılır.
  • Türkçede i ↔ İ ve ı ↔ I eşleşir. Parametresiz toLowerCase()/toUpperCase() makinenin diline bağlıdır; teknik metinde Locale.ENGLISH, Türkçe metinde Locale.forLanguageTag("tr") verilir.
  • Aynı sabitler dizgi havuzunda tek nesneyi paylaşır; new her zaman yeni nesne açar. Sabit ifadeler derleme sırasında birleştirilir ve havuza girer; değişkenli birleştirme yeni nesne üretir. intern() havuzdaki nesneyi verir. "sabit".equals(x) null'a karşı güvenlidir.
  • next() bir kelime okur ve ⏎'ı tamponda bırakır; nextLine() satırın kalanını okur ve ⏎'ı tüketir. next() ya da nextInt()'ten sonra satır okunacaksa araya bir nextLine() konur.
  • Döngüde s = s + x her turda yeni nesne üretir; n turda yaklaşık n²/2 karakter kopyalanır. StringBuilder değiştirilebilir bir tampondur: append, insert, reverse aynı nesneyi değiştirir; sonuç toString() ile alınır.
  • Uygulamaların ortak kalıbı karakter taramasıdır. Ters çevirme sondan başa, palindrom iki uçtan içeri doğru tarar. Kelime sayma bir bayrak kullanır. Frekans tablosu hücreyi c - 'a' ile seçer; Sezar şifresi (c - 'a' + k) % 26 ile kaydırır.
  • printf'te %-8s sola, %3d sağa yaslar; %7.2f iki ondalıkla 7 hücreye yazar; %n satır sonudur. Tip uyuşmazlığı çalışma zamanında istisna verir.
  • Dizgiler UTF-16 kod birimlerinden oluşur; Türkçe harfler tek char'a sığar, emoji gibi karakterler iki char tutar. Bu yüzden length() görünen karakter sayısıyla her zaman aynı değildir.

11.14Kendini Dene

  1. int p = 2, q = 5; iken System.out.println(p + q + "x" + p + q); satırı ne yazar?

    Cevap

    + soldan sağa işlenir. İlk iki işlenen sayıdır: 2 + 5 = 7. Sonra 7 + "x" = "7x" olur ve ifade birleştirmeye döner: "7x2", ardından "7x25". Çıktı 7x25'tir.

  2. String s = "dizgi"; s.toUpperCase(); s = s.replace('i', 'ı'); satırlarından sonra s neyi gösterir?

    Cevap

    toUpperCase()'in sonucu atanmadığı için kaybolur; s hâlâ "dizgi"dir. replace'in sonucu ise atanır ve iki 'i' 'ı' olur: s "dızgı"yı gösterir. "dizgi" nesnesi değişmemiştir; yalnızca s'nin oku yeni nesneye taşınmıştır.

  3. String t = "Karadeniz"; için t.length(), t.charAt(4), t.indexOf("de"), t.substring(4, 8) ve t.lastIndexOf('a') değerleri nedir?

    Cevap

    İndisler: K=0, a=1, r=2, a=3, d=4, e=5, n=6, i=7, z=8. Uzunluk 9'dur. charAt(4) 'd'dir. "de" 4 indisinde başlar. substring(4, 8) 4–7 indislerini alır: "deni" (uzunluk 8 − 4 = 4). Son 'a' 3 indisindedir.

  4. "x;;y;z;;".split(";").length kaçtır? Parçalar nelerdir?

    Cevap

    Metin her noktalı virgülden kesilir: "x", "", "y", "z", "", "". Ardışık iki noktalı virgülün arasındaki boş parça kalır, sondaki iki boş parça atılır. Sonuç [x, , y, z], uzunluk 4'tür.

  5. "Masa".compareTo("masa"), "kitap".compareTo("kitaplık") ve "ödev".compareTo("sınav") değerleri nedir? Hangileri gerçek sözlük sırasıyla çelişir?

    Cevap

    İlkinde ilk karakterler 'M' (77) ve 'm'dir (109): 77 − 109 = −32. İkincisinde "kitap", "kitaplık"ın başıdır: 5 − 8 = −3. Üçüncüsünde 'ö' (246) ile 's' (115) karşılaşır: 246 − 115 = 131, yani "ödev" "sınav"dan sonra gelir. Türk alfabesinde ö, s'den önce geldiği için üçüncü sonuç sözlük sırasıyla çelişir.

  6. Türkçe ayarlı bir bilgisayarda "MAIL".toLowerCase().equals("mail") ifadesinin değeri nedir? İfade nasıl düzeltilir?

    Cevap

    Parametresiz toLowerCase() Türkçe kuralları kullanır ve "I"yı "ı"ya çevirir: "maıl". "mail"e eşit olmadığı için değer false'tur. "MAIL" teknik bir sözcük olduğu için toLowerCase(Locale.ENGLISH) yazılır ya da doğrudan "MAIL".equalsIgnoreCase("mail") kullanılır; ikisi de true verir.

  7. String a = "ab"; String b = "a"; String c = b + "b"; final String d = "a"; String e = d + "b"; satırlarından sonra a == c, a == e ve a == c.intern() değerleri nedir?

    Cevap

    b final olmadığı için b + "b" çalışma zamanında yeni bir nesne üretir: a == c false'tur. d final bir sabit olduğu için d + "b" derleme sırasında "ab" sabitine dönüşür ve havuzdan gelir: a == e true'dur. c.intern() havuzdaki "ab"yi döndürür: true.

  8. Kullanıcı önce “42⏎”, sonra “Ali Can⏎” yazıyor. int n = k.nextInt(); String s = k.nextLine(); String t = k.next(); satırlarından sonra s ve t nedir?

    Cevap

    nextInt() 42'yi okur ve ⏎'ı bırakır. nextLine() o ⏎'a kadar okur: s boş dizgidir. next() ikinci satırdaki ilk kelimeyi okur: t "Ali"dir. " Can⏎" tamponda kalır.

  9. “ankara” kelimesi 4 kaydırmalı Sezar şifresiyle şifreleniyor. Sonuç nedir? Şifreyi çözmek için kaç kaydırma kullanılır?

    Cevap

    Harflerin yerleri: a=0, n=13, k=10, r=17. 4 eklenince 4, 17, 14, 21 olur; hiçbiri 26'yı aşmaz. Altı harf sırayla e, r, o, e, v, e'ye dönüşür: "eroeve". Çözmek için 26 − 4 = 22 kaydırma kullanılır.

  10. System.out.printf("[%6.1f][%-4s][%03d]%n", 2.75, "ab", 7); satırı ne yazar?

    Cevap

    %6.1f, 2,75'i bir ondalığa yuvarlar: "2.8" (üç karakter) ve 6 hücreye sağa yaslar; önüne üç boşluk gelir. %-4s, "ab"yi 4 hücreye sola yaslar; sonuna iki boşluk gelir. %03d, 7'yi 3 hücreye sıfırla doldurur: "007". Çıktı [ 2.8][ab ][007]'dir (İngilizce yerel ayarda; Türkçede "2,8").
