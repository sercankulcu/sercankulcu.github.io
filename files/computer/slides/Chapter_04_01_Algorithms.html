Problem Solving

Algorithm First, Code Second

  • Code is one implementation of a solution idea, in one particular language.
  • Code written without an algorithm leads to trial and error and hidden bugs.
  • The right order: understand the problem, solve an example, write the method, then code it.

Algorithm

Properties of a Good Algorithm

An algorithm is a finite sequence of well-defined steps that solves a given problem.

  • It takes zero or more inputs and produces at least one output.
  • Its steps are unambiguous, ordered and executable.
  • It halts after a finite number of steps.
  • It produces the correct result for every valid input.
  • Its resource use stays acceptable as the input grows.

Algorithm

The Algorithm Design Cycle

  • If a hand trace reveals a bug, fix it and go around again; once no bugs remain, start coding.
  • When several solutions exist, compare their correctness, readability and efficiency.

Algorithm

Pseudocode

Pseudocode describes an algorithm's logic without tying it to a programming language.

START
  read A
  read B
  SUM = A + B
  print SUM
END
  • Use short, consistent phrases close to natural language.
  • Indentation shows the scope of conditions and loops.
  • The point is clarity, not syntax.

Examples

Example: Sort Two Numbers

read a, b
if a > b then
    temp = a
    a = b
    b = temp
print a, b
  • Equal values need no swap.
  • A swap takes three assignments.
  • The output must satisfy a ≤ b.
Why temp? Writing a = b; b = a directly overwrites a's old value in the first assignment: for a = 7, b = 3 the result is 3 3.

Examples · Step-by-step trace

Sort Two Numbers Step by Step (a = 7, b = 3)

Read the inputs: a = 7, b = 3. Goal: print the smaller one first.

Condition: 7 > 3 → true, so we enter the swap block.

temp = a = 7: back up a's value first so it isn't lost.

a = b = 3. The old 7 now lives only in temp.

b = temp = 7. Three assignments, and the values have swapped.

Output 3 7: a ≤ b holds. (With a = 2, b = 9 the condition is false and lines 3–5 are skipped.)

Examples

Example: Factorial

read n
if n < 0 then print "error" and stop
result = 1
i = 2
while i ≤ n
    result = result × i
    i = i + 1
print result
  • 0! and 1! are 1: the loop never runs and result stays 1.
  • Loop invariant: at the start of each round, result = (i − 1)!
  • On negative input, report an error and stop.

Example: Palindrome

read text
clean text by the rule
lo = 0, hi = length - 1
while lo < hi
    if the characters differ, return false
    lo = lo + 1, hi = hi - 1
return true
  • Comparison moves from both ends toward the middle.
  • Decide the case and space rules up front (e.g. "Kayak" → "kayak").
  • At most length / 2 comparisons.

Examples

Example: Prime Number

read n
if n < 2 then print "not prime" and stop
i = 2
while i × i ≤ n
    if n % i == 0 then print "not prime" and stop
    i = i + 1
print "prime"
  • The search stops at the first divisor.
  • Square-root bound: if n = a × b, then a and b cannot both exceed √n; any small divisor lies in the range i × i ≤ n.
  • % gives the remainder of a division.

Analysis

Same Problem, Two Algorithms: 1 + 2 + … + n

sum = 0
i = 1
while i <= n
    sum = sum + i
    i = i + 1

A: a loop, n rounds

sum = n * (n + 1) / 2

B: Gauss's formula, one step

Both are correct, but as n grows A does more work while B's stays constant: efficiency matters as much as correctness.

Analysis

Correctness and Efficiency

  • Correctness means the algorithm produces the expected result.
  • Time complexity describes how the operation count grows with input size, written in big-O notation: O(n), O(log n), O(n²).
  • Space complexity measures the extra memory used.
  • On small inputs, the fastest-looking method is not always the clearest one.

Searching

Linear Search

int linearSearch(int[] arr, int target) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] == target) return i;
    }
    return -1;
}
  • Compares elements from first to last; the data need not be sorted.
  • Stops at the first match; returns -1 if there is none.
  • Worst case examines all n elements: O(n).

The code is in Java.

Linear Search Step by Step (target = 5)

Call linearSearch(arr, 5). The array is not sorted, so we check one element at a time from the start.

i = 0: 0 < 5 → true.

arr[0] = 7 == 5 → false.

i = 1: 1 < 5 → true.

arr[1] = 3 == 5 → false.

i = 2: 2 < 5 → true.

arr[2] = 9 == 5 → false.

i = 3: 3 < 5 → true.

arr[3] = 5 == 5 → true → return 3. That took 4 comparisons; for target 4 it would return -1 after 5.

Searching

Binary Search

int binarySearch(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] == target) return mid;
        if (arr[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
  • Works only on sorted data; each step halves the range.
  • Worst case ⌊log₂ n⌋ + 1 rounds: O(log n).
  • lo + (hi - lo) / 2 gives the same result as (lo + hi) / 2 but does not overflow for very large indices.
  • Sorting first just to search once can raise the total cost.

Searching · Run the code step by step

Binary Search Step by Step (target = 34)

The search range is the whole array: lo = 0, hi = 8.

0 ≤ 8 → true: the range is not empty, round 1.

mid = 0 + (8 − 0) / 2 = 4, arr[4] = 21.

21 == 34 → false.

21 < 34 → the target is in the right half: lo = 5. The left half is gone.

5 ≤ 8 → true: the range is not empty, round 2.

mid = 5 + (8 − 5) / 2 = 6, arr[6] = 30.

30 == 34 → false.

30 < 34 → the target is in the right half: lo = 7. The left half is gone.

7 ≤ 8 → true: the range is not empty, round 3.

mid = 7 + (8 − 7) / 2 = 7, arr[7] = 34.

34 == 34 → return 7. Found in 3 rounds; linear search would have taken 8 comparisons.

Sorting

Selection Sort

  • Find the smallest element in the unsorted part.
  • Swap it into the first position of that part.
  • Always n(n−1)/2 comparisons → O(n²); at most n − 1 swaps; O(1) extra memory.
for i = 0 to n-2
    minIdx = i
    for j = i+1 to n-1
        if arr[j] < arr[minIdx] then minIdx = j
    swap arr[i] and arr[minIdx]

Sorting

Bubble Sort

  • Compares adjacent elements and swaps them if they are out of order.
  • Each pass carries the largest remaining element to the end; the next pass is one element shorter.
  • If a pass makes no swaps, the array is sorted and we stop.
  • O(n²) in general; best case (already sorted) is a single pass: O(n).
round = 0
repeat
    swapped = false
    for j = 0 to n-2-round
        if arr[j] > arr[j+1] then
            swap arr[j] and arr[j+1]
            swapped = true
    round = round + 1
until swapped is false

Sorting

Insertion Sort

  • Like arranging playing cards in your hand: the left part is always sorted.
  • Take the next element (the key), shift larger ones one step right, and drop the key into the gap.
  • Worst case (reverse order) O(n²); on a sorted array each key needs one comparison: O(n). O(1) extra memory.
  • Very fast on small or nearly sorted data.
for i = 1 to n-1
    key = arr[i]
    j = i - 1
    while j >= 0 and arr[j] > key
        arr[j+1] = arr[j]
        j = j - 1
    arr[j+1] = key

Sorting · Step-by-step trace

Insertion Sort Step by Step

i = 1: take key = arr[1] = 3, leaving a gap. The left part (0…0) is sorted. j = 0.

j = 0 ≥ 0 and arr[0] = 4 > 3 → true.

4 moved one step right; the gap is now cell 0. j = -1.

j = -1 < 0 → false (we hit the left end), so the loop ends.

arr[0] = 3: the key drops into the gap. Now 0…1 is sorted.

i = 2: take key = arr[2] = 5, leaving a gap. The left part (0…1) is sorted. j = 1.

j = 1 ≥ 0 and arr[1] = 4 > 5 → false, so the loop ends.

arr[2] = 5: the key drops into the gap. Now 0…2 is sorted.

i = 3: take key = arr[3] = 1, leaving a gap. The left part (0…2) is sorted. j = 2.

j = 2 ≥ 0 and arr[2] = 5 > 1 → true.

5 moved one step right; the gap is now cell 2. j = 1.

j = 1 ≥ 0 and arr[1] = 4 > 1 → true.

4 moved one step right; the gap is now cell 1. j = 0.

j = 0 ≥ 0 and arr[0] = 3 > 1 → true.

3 moved one step right; the gap is now cell 0. j = -1.

j = -1 < 0 → false (we hit the left end), so the loop ends.

arr[0] = 1: the key drops into the gap. Now 0…3 is sorted. Done, with 5 comparisons.

Summary

Chapter Summary

  • An algorithm is a clear, finite set of steps that turns input into output.
  • Pseudocode writes an algorithm without committing to a language.
  • Hand tracing and a variety of test cases help assess correctness.
  • Linear search needs no sorting; binary search halves the range on sorted data.
  • Besides correctness, algorithms are compared by time and memory cost.
