The journey of a web request

Goal: Follow what happens when an address is typed into a browser: first how the IP address of the domain name is found (DNS), then how the message is split into packets, carried across routers and reassembled at the receiver.

How to use it

  • Step → animates the next event, ← Back returns to the previous state, Play runs the steps automatically. The → and ← keys also work.
  • Cache: compare the cases where the record is nowhere, in the resolver's cache, or in the browser's cache.
  • Message and Packet size: choose the message and how many characters go into each packet. If Lose one packet is checked, one of the packets is lost at a busy router.
  • New scenario: picks new random paths and delays for the packets.
  • Try it yourself: before some steps a question is asked; correct answers are counted.

What you see

  1. DNS lookup: browser cache → DNS resolver → root server → top-level domain (.tr) server → authoritative server. The answer is cached for the TTL.
  2. Splitting into packets: each packet's header holds a sequence number and the source and destination addresses.
  3. Journey: routers choose the best path for each packet at that moment; packets may take different paths and arrive out of order.
  4. Loss and resending: TCP notices the missing sequence number and the packet is resent.
  5. Reordering: the packets in the receive buffer are sorted by sequence number and the message is reassembled.
