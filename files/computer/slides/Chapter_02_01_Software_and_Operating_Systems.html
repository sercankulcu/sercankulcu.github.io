Operating System

What Is an Operating System?

An operating system is the core system software that manages hardware resources and provides common services to applications.

  • Hides hardware details from applications.
  • Lets several programs share resources safely.
  • Gives the user a graphical or command-line interface.

Operating System

What an Operating System Does

Operating System · Step by step

How Does a Computer Start? Booting Step by Step

The power button is pressed; once voltages settle, the power supply sends the motherboard a “power good” signal. RAM is empty; the OS is still sitting on disk.

The CPU starts running the firmware (UEFI, or the older BIOS) stored in non-volatile memory (ROM/flash) on the motherboard.

POST (power-on self-test): basic hardware such as memory, keyboard and disk is checked. Errors are reported with beeps or a message.

The boot order from the settings is tried (e.g. USB first, then SSD); missing devices are skipped. The boot loader (e.g. Windows Boot Manager: bootmgfw.efi, or GRUB) is loaded into RAM from the small EFI system partition (FAT32) on the disk.

The boot loader loads the kernel into RAM (on Windows, ntoskrnl.exe via winload.efi) and hands over control. The kernel loads drivers and starts the first processes and system services.

The sign-in screen appears; once the user is authenticated, their desktop and startup apps open.

Operating System · Security

Secure Boot and TPM

UEFI

Modern firmware that replaces BIOS: large disks, fast startup and signature checking.

Secure Boot

Only a boot loader and kernel with a trusted digital signature may run; forged or tampered boot code is blocked.

TPM 2.0

A security chip (on the motherboard, in the CPU or in firmware) that stores encryption keys and boot measurements; used by tools such as BitLocker.

Windows 11

Requires UEFI with Secure Boot and TPM 2.0 to install; see Microsoft's current requirements page for details.

There are two partitioning schemes. MBR: goes with BIOS, disks up to 2 TB, at most 4 primary partitions. GPT: goes with UEFI, disks over 2 TB, many partitions.

OS Components

The Kernel

The kernel is the privileged core of the operating system. Applications don't touch the hardware directly; they ask the kernel for services through system calls.

A bug in the kernel can bring down the whole system, which is why access control and isolation matter.

OS Components · Step by step

A System Call Step by Step: Reading a File

A text editor wants to read report.txt. It cannot access the disk itself, so it makes the read system call.

The CPU switches from user mode to kernel mode. Now only kernel code runs.

The file system finds where the file lives on disk and checks that the user has read permission.

The disk driver sends a read command to the disk. When the disk is done, it notifies the CPU with an interrupt.

Memory management: the kernel copies the data into the editor's own memory area in RAM.

The call returns and the CPU switches back to user mode. The editor shows the data. The application never touched the hardware.

Resource Management

Program, Process and Thread

A program is a file sitting on disk; a process is a running instance of it, identified by a process ID (PID). Each process has its own memory space, while threads share the memory of their process.

Resource Management

Process States

  • On a single core, only one process is Running at a time; the other ready processes wait their turn.
  • A Waiting process never gets the CPU; when the event it waits for (disk, keyboard, network) happens, it becomes Ready again.

Resource Management · Step by step

Process State Transitions Step by Step

Process P1 is being created (e.g. the user double-clicked a program): state New.

New → Ready: the OS admits the process; memory is allocated and it joins the ready queue.

Ready → Running: the scheduler picks P1; its context is loaded and the CPU executes P1's instructions.

Running → Waiting: P1 asks for data from the disk. Rather than hold the CPU idle until it arrives, it moves to Waiting.

Waiting → Ready: the disk is done (an interrupt arrives). P1 doesn't run right away; it goes back to the Ready queue first.

Ready → Running: when its turn comes, P1 is picked again and continues where it left off.

Running → Ready: P1's time slice is up; a timer interrupt gives the CPU to another process.

Ready → Running: P1 is picked again and runs the rest of its work.

Running → Terminated: P1 finishes and exits; the OS reclaims its memory and resources.

Resource Management · Step by step

Two Processes, One CPU: Tracing States

Two processes, one core. P1 will compute for 3 ms, read from disk (3 ms), then compute 2 ms more. P2 just computes for 4 ms. Both are Ready; the scheduler picks P1.

t = 0–3: P1 is Running; P2 waits in the ready queue.

t = 3: P1 asks to read from disk (a system call). The disk is slow, so P1 goes to Waiting and gives up the CPU. Context switch.

t = 3–6: P2 is Running while the disk reads P1's data. CPU and disk work in parallel.

t = 6: the disk finishes and signals with an interrupt. P1 becomes Ready but doesn't run yet: P2 has the CPU.

t = 7: P2 completes its 4 ms and is Terminated. Only P1 is left in the ready queue.

t = 7–9: P1 is Running; it finishes its last 2 ms and is Terminated.

Total: 9 ms, and the CPU was never idle. Had the CPU sat idle while P1 waited for the disk, it would have taken 3 + 3 + 2 + 4 = 12 ms. Running another process during I/O (multiprogramming) saves time.

P1: compute 3 ms
P1: read disk (I/O 3 ms)
P1: compute 2 ms, exit
P2: compute 4 ms, exit

Resource Management · Step by step

Time Sharing: Round-Robin CPU Allocation

Three processes are ready: P1 needs 5 ms, P2 3 ms, P3 2 ms. Round-robin scheduling gives each one at most 2 ms in turn.

t = 0–2: the CPU runs P1. Its time slice expires; P1 goes to the back of the queue (3 ms left). Context switch.

t = 2–4: the CPU runs P2. Its time slice expires; P2 goes to the back of the queue (1 ms left). Context switch.

t = 4–6: the CPU runs P3. P3 finishes (t = 6) and leaves the system.

t = 6–8: the CPU runs P1. Its time slice expires; P1 goes to the back of the queue (1 ms left). Context switch.

t = 8–9: the CPU runs P2. P2 finishes (t = 9) and leaves the system.

t = 9–10: the CPU runs P1. P1 finishes (t = 10) and leaves the system. Completion: P3 = 6, P2 = 9, P1 = 10 ms. Because switches are fast, all three seem to run “at the same time”.

Resource Management · Step by step

Deadlock

Process A has acquired the printer and is using it (solid arrow).

Process B has locked the file and is using it.

Process A wants the file without releasing the printer (dashed arrow); B has the file, so A waits.

Process B wants the printer without releasing the file; A has the printer, so B waits.

A → File → B → Printer → A: a circular wait. Neither lets go, so both wait forever: deadlock.

Mutual exclusion one owner
Hold and wait waits while holding
No preemption can't be taken away
Circular wait forms a ring
All four conditions are needed. One fix: everyone requests resources in the same order (printer first, then file), so no circular wait can form.

Resource Management · Step by step

Memory Management Step by Step: Allocation, Protection, Swapping

Start: the operating system (kernel) sits at the start of RAM; the rest is free.

Allocation: 200 KB from 100 to 300 is set aside for A. In this simple model a region is described by base and limit registers (real systems use paging).

B gets 150 KB from 300 to 450. Each process has its own register pair; the OS loads it on every switch.

Valid access: A's address 150 is below the limit (200), so the hardware goes to physical address base + 150 = 250.

Protection fault: A asks for 250; since 250 ≥ 200, the hardware blocks the access and control passes to the kernel. A real system would kill A with an “access violation / segmentation fault”; in the example A's region stays put. B's memory is safe.

Swapping: there is no room for C (190 KB < 250 KB). The waiting process B is written to disk, leaving 340 KB of contiguous free RAM. Disk is far slower than RAM.

C is loaded at 300–550. B waits on disk and is brought back into RAM when it runs again; if there is no room, some other process is swapped out.

Resource Management

Virtual Memory and Paging

  • Each process sees its own virtual address space starting at 0; memory is split into 4 KB pages, and a page table records which frame holds each page.
  • Pages need not be contiguous in RAM; rarely used pages can be moved out to disk (swapped).
  • The swap area is called the page file on Windows and swap on Linux and macOS. Reading from disk (SSD ≈ 0.1 ms) is orders of magnitude slower than RAM (50–100 ns); heavy swapping makes a computer noticeably slow.

Resource Management · Step by step

Address Translation Step by Step: 4100 and 8200

Process A wants to read the data at virtual address 4100. The CPU's memory management unit (MMU) has to translate it.

The address splits in two: page = 4100 / 4096 = 1, offset = 4100 mod 4096 = 4.

Table: page 1 → frame 5. Physical address = 5 × 4096 + 4 = 20484.

Process A wants to read the data at virtual address 8200. The CPU's memory management unit (MMU) has to translate it.

The address splits in two: page = 8200 / 4096 = 2, offset = 8200 mod 4096 = 8.

The table says page 2 is not in RAM → page fault. The program is paused and the OS steps in.

The OS loads the page from disk into free frame 3 and updates the page table.

Table: page 2 → frame 3. Physical address = 3 × 4096 + 8 = 12296. The instruction is restarted and succeeds this time.

Resource Management · Step by step

Page Replacement (LRU) Step by Step

The process has only 3 frames in RAM and requests pages in the order 7, 0, 1, 2, 0, 3, 0, 4. When RAM is full, which page goes to disk? The LRU (least recently used) rule.

Page 7 is not in RAM → page fault; there is a free frame, so it is loaded there from disk.

Page 0 is not in RAM → page fault; there is a free frame, so it is loaded there from disk.

Page 1 is not in RAM → page fault; there is a free frame, so it is loaded there from disk.

Page 2 is missing → page fault; no free frame. Page 7 was used longest ago → evict it, load 2.

Page 0 is already in RAM → hit; only its last-use time is updated.

Page 3 is missing → page fault; no free frame. Page 1 was used longest ago → evict it, load 3.

Page 0 is already in RAM → hit; only its last-use time is updated.

Page 4 is missing → page fault; no free frame. Page 2 was used longest ago → evict it, load 4.

6 page faults in 8 requests. FIFO (first in, first out) gives 7 faults on the same string: it evicts the busy page 0 too when its turn comes. Every fault means a slow disk read.

Resource Management

The File System Tree and Paths

/home/ali/documents/report.txt
  • A file system is a tree: the root at the top, folders as branches, files as leaves.
  • An absolute path starts at the root; a relative path starts at the current folder (from ali: documents/report.txt).
  • Windows writes the same idea with a drive letter: C:\Users\Ali\Documents\report.txt.

Resource Management · Step by step

Opening and Reading a File Step by Step

The editor makes the open system call. The kernel resolves the path one piece at a time, starting at the root folder /.

It looks for home in the root, then for ali inside it. Each folder is a list of the names it contains and where they live on disk.

report.txt is found in ali. The metadata says: size 150 bytes; does the user have read permission? Yes. (Otherwise open returns an error and the file stays closed.)

The kernel creates an open-file entry and gives the process the lowest free number: fd = 3. Numbers 0, 1 and 2 are always open in every process for standard input, output and error.

read asks for 100 bytes; bytes 0–99 are read, n = 100. The offset moves to 100 on its own; the application never sees addresses, only the fd.

Again 100 bytes are requested, but only 50 are left: n = 50, offset 150.

The third read returns n = 0: end of file. The program stops reading here.

close: the entry is removed and number 3 is free again. The OS closes any files left open when the process ends, but a long-running program can run out of descriptors. Windows calls the same idea a handle.

fd = open("/home/ali/report.txt", O_RDONLY)
n = read(fd, buf, 100)
n = read(fd, buf, 100)
n = read(fd, buf, 100)
close(fd)

Security

Users and Permissions

  • A standard account limits system changes in everyday use; an administrator account can make system-wide changes.
  • Least privilege: give users only the rights their job needs.
  • Logging lets important events be reviewed later.
  • In the example, a standard user can open their own file but cannot change a system setting.

Operating System

Virtual Machines vs Containers

Virtual machine

Carries a full guest OS: strong isolation, but more memory and slower startup.

Container

Just the app and its dependencies on a shared kernel: light and fast, weaker isolation.

Summary

Chapter Summary

  • Software defines the work the hardware carries out.
  • The operating system is a management and abstraction layer between applications and hardware.
  • The kernel manages process, memory, device and file resources.
  • Personal, mobile, server, embedded and real-time systems have different priorities.
  • Choosing an OS means weighing applications, hardware, security, support and total cost together.
  • The license sets the rights for open and closed source.
