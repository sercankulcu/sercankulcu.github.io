Loops

Parts of a Loop

  • Initialization: state set up once, before the loop.
  • Condition: tested before each pass (after it in do-while); false means exit.
  • Body: the work done on each pass.
  • Update: moves the condition toward false; forget it and the loop never ends.
These four colors mean the same thing throughout the chapter.

Loops

The for Loop

int n = 4;
int sum = 0;
for (int i = 1; i <= n; i++) {
    sum += i;
}
System.out.println(sum);

initializationconditionbodyupdate

  • Use for when the number of passes is known; all four parts fit on one line.
  • Order: initialization → condition → body → update → condition …
  • i exists only inside the loop.

Code Trace: 1 + 2 + 3 + 4 with for

n = 4: we will add 1 through 4.

The accumulator starts at sum = 0 (nothing added yet).

Initialization: int i = 1 runs only once.

Condition: i <= n → 1 <= 4 → true → enter the body.

Body: sum = 0 + 1 = 1.

Update: i++ → i = 2. Then back to the condition.

Condition: i <= n → 2 <= 4 → true → enter the body.

Body: sum = 1 + 2 = 3.

Update: i++ → i = 3. Then back to the condition.

Condition: i <= n → 3 <= 4 → true → enter the body.

Body: sum = 3 + 3 = 6.

Update: i++ → i = 4. Then back to the condition.

Condition: i <= n → 4 <= 4 → true → enter the body.

Body: sum = 6 + 4 = 10.

Update: i++ → i = 5. Then back to the condition.

Condition: i <= n → 5 <= 4 → false → the loop ends.

After the loop, println prints 10. i is gone: its scope was the loop. Body ran 4 times, condition 5 times.

int sum = 0;
for (int i = 1; i <= n; i++) {
    sum += i;
}

Flexible Forms of the for Loop

HeaderRuns
for (int i = 0, j = 9; i < j; i++, j--)i and j together: (0,9) … (4,5), 5 passes
for (int i = 0; i <= 10; i += 2)0 2 4 6 8 10
for (int i = 5; i >= 1; i--)countdown: 5 4 3 2 1
int k = 0;
for (;;) {            // all parts empty: always true
    k++;
    if (k == 3) break;  // exit is required
}
System.out.println(k);   // 3
  • Initialization, condition and update are each optional.
  • Initialization can declare several variables of one type; the update can hold several comma-separated expressions.

Loops

++i vs. i++

for (int i = 0; i < 3; i++) System.out.print(i + " ");   // 0 1 2
for (int i = 0; i < 3; ++i) System.out.print(i + " ");   // 0 1 2

In the update part of a for, the expression's value is unused; both just add 1 to i, so there is no difference.

  • i++ yields the old value, then increments; ++i increments, then yields the new value.
  • In the table d = {10, 20, 30}; the difference shows only when the value is used. Write i++ for counters; it reads better.

Loops

The while Loop

int num = 5;
int factorial = 1;
while (num > 1) {
    factorial *= num;
    num--;
}
System.out.println(factorial);

initializationconditionbodyupdate

  • The condition is checked before the body.
  • If it is false at the start, the body never runs.
  • Initialization goes before the loop, the update inside the body.

Loops · Step through the code

Code Trace: 5! with while

Initialization: num = 5 (we will compute 5!).

A product accumulator starts at 1 (with 0 the result would always be 0).

Condition: 5 > 1 → true → run the body.

factorial = 1 × 5 = 5.

Update: num-- → 4. The condition moves toward false.

Condition: 4 > 1 → true → run the body.

factorial = 5 × 4 = 20.

Update: num-- → 3. The condition moves toward false.

Condition: 3 > 1 → true → run the body.

factorial = 20 × 3 = 60.

Update: num-- → 2. The condition moves toward false.

Condition: 2 > 1 → true → run the body.

factorial = 60 × 2 = 120.

Update: num-- → 1. The condition moves toward false.

Condition: 1 > 1 → false → exit the loop.

120 is printed: 5 × 4 × 3 × 2 = 120. The body ran 4 times; no need to multiply by 1.

int num = 5;
int factorial = 1;
while (num > 1) {
    factorial *= num;
    num--;
}
System.out.println(factorial);

Loops

The do-while Loop

Scanner in = new Scanner(System.in);
int choice;
do {
  System.out.print("Choice (1/0): ");
  choice = in.nextInt();
  if (choice == 1)
    System.out.println("Hello!");
} while (choice != 0);
System.out.println("Goodbye");

initializationconditionbodyupdate

  • The condition is checked after the body → the body runs at least once.
  • The natural choice for menus and input validation.
  • Don't forget the semicolon after while (…);.

Loops · Step through the code

Code Trace: a do-while menu (input 1, 2, 0)

A Scanner reads from the keyboard (import java.util.Scanner; at the top). The user will type 1, 2, 0.

choice is declared without a value; that's fine, since the condition is first tested after the body.

Pass 1: the body runs without checking the condition; the menu is printed.

The user types 1 → choice = 1.

choice == 1 → true: «Hello!» is printed.

Condition: 1 != 0 → true → back to the top.

Pass 2: the body runs without checking the condition; the menu is printed.

The user types 2 → choice = 2.

choice == 1 → false: nothing happens.

Condition: 2 != 0 → true → back to the top.

Pass 3: the body runs without checking the condition; the menu is printed.

The user types 0 → choice = 0.

choice == 1 → false: nothing happens.

Condition: 0 != 0 → false → the loop ends.

The body ran 3 times and the condition was tested 3 times (a while would test it once more than the body runs).

Scanner in = new Scanner(System.in);

do {
  System.out.print("Choice (1/0): ");
  choice = in.nextInt();
  if (choice == 1)
    System.out.println("Hello!");
} while (choice != 0);
System.out.println("Goodbye");

Branching

break and continue

for (int i = 1; i <= 10; i++) {
    if (i % 3 == 0) continue;
    if (i == 8) break;
    System.out.print(i + " ");
}
System.out.println("| done");
  • continue: skips the rest of the pass and goes to the update (i++).
  • break: ends the nearest enclosing loop at once.
  • Overuse makes the flow hard to follow.

Branching · Step through the code

Labeled break outer: leave both loops at once

i = 1, j = 1: 1·1 = 1 ≠ 4, 1 1 is printed.

j = 2: 1·2 = 2 ≠ 4 → 1 2 is printed.

j = 3: 1·3 = 3 ≠ 4 → 1 3 is printed; the inner loop ends.

i = 2; the inner loop restarts: j = 1, 2·1 = 2 ≠ 4 → 2 1 is printed.

i = 2, j = 2: 2·2 = 4 → break outer. Without printing, control leaves both loops; i = 3 is never tried.

A labeled break jumps to the line after the outer loop: done is printed. Output: 4 number lines + done.

outer:
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 3; j++) {
        if (i * j == 4) break outer;
        System.out.println(i + " " + j);
    }
}
System.out.println("done");

Comparison: a plain break ends only the inner loop

i = 1: 1·j ≠ 4 for j = 1, 2, 3; 1 1, 1 2, 1 3 are printed.

i = 2, j = 1: 2·1 = 2 ≠ 4 → 2 1 is printed.

i = 2, j = 2: 2·2 = 4 → a plain break ends only the inner loop; the outer loop goes on.

i++ → 3; the inner loop restarts: j = 1 → 3 1 is printed.

j = 2 and j = 3: 3·2 = 6, 3·3 = 9 ≠ 4 → 3 2 and 3 3 are printed.

The outer loop ends too and done is printed. A plain break gives 7 number lines, a labeled break 4.

Loops

Infinite Loops

  • If the condition never becomes false, the loop never ends: the program seems “frozen”.
  • Note: with i-- the int eventually wraps around and the loop stops after about 2.1 billion passes; in practice it is infinite.
  • The counter may move the wrong way or never be updated at all.
  • Deliberate while (true) loops still need a break condition inside. If a program hangs, stop it with Ctrl+C.

Loops · Step through the code

The double Counter Trap: x += 0.1

Start: n = 0. The goal: step by 0.1 and loop 10 times.

x = 0.0, condition 0.0 < 1.0 → true.

Body: n = 1.

Update: x = 0.1. 0.1 has no exact binary representation; small errors accumulate.

End of pass 10 (8 passes skipped here): n = 10, x = 0.8999999999999999.

Update: x = 0.9999999999999999, not exactly 1.0. The condition is true: one extra pass.

11. rounds: n = 11.

x = 1.0999999999999999, the condition is false → the loop ends.

11 is printed; 10 was expected.

int n = 0;
for (double x = 0; x < 1.0; x += 0.1) {
    n++;
}
System.out.println(n);

With x != 1.0 the loop would never end, since x never equals 1.0 exactly. Use an int counter, not a real number.

Verification

Loop Invariants

  • A property that holds at the start of every pass.
  • In the sum loop: sum = 1 + 2 + … + (i − 1).
  • When the loop ends (i = n + 1), the invariant tells us the result is correct.

No number processed yet: sum = 0 (the empty sum). The invariant holds from the start.

At the start of pass i = 2, sum holds 1 … 1 added up: 1.

At the start of pass i = 3, sum holds 1 … 2 added up: 3.

At the start of pass i = 4, sum holds 1 … 3 added up: 6.

i = 5 → condition false. The invariant still holds: sum = 1 + 2 + 3 + 4 = 10 → the result is correct.

Verification

Off-by-One Errors (count 1 to 5)

  • < vs. <=, or starting at 0 vs. 1, means one pass too few or too many (“off-by-one”).
  • Test: check the first pass, the last pass and the pass count by hand.

Verification · Step through the code

Checking the Bounds: i < 5 → 5 passes

Start: i = 0, count = 0. Condition 0 < 5 → true.

Round 1: prints i = 0, count becomes 1.

Round 2: prints i = 1, count becomes 2.

Round 3: prints i = 2, count becomes 3.

Round 4: prints i = 3, count becomes 4.

Round 5: prints i = 4, count becomes 5.

i++ → 5; 5 < 5 → false, the loop ends. Exactly 5 passes: i = 0…4.

int count = 0;
for (int i = 0; i < 5; i++) {
    System.out.print(i + " ");
    count++;
}
System.out.println("| rounds: " + count);

Verification · Step through the code

Off-by-One: i <= 5 → 6 passes

Start: i = 0, count = 0. Condition 0 <= 5 → true.

Round 1: prints i = 0, count becomes 1.

Round 2: prints i = 1, count becomes 2.

Round 3: prints i = 2, count becomes 3.

Round 4: prints i = 3, count becomes 4.

Round 5: prints i = 4, count becomes 5.

Round 6: prints i = 5, count becomes 6.

i++ → 6; 6 <= 5 → false. The <= caused one extra pass: count = 6, not the expected 5.

int count = 0;
for (int i = 0; i <= 5; i++) {
    System.out.print(i + " ");
    count++;
}
System.out.println("| rounds: " + count);

Example

Counting Digits

int num = -507;
long rest = num;
if (rest < 0) rest = -rest;
int digits = 0;
do {
    digits++;
    rest /= 10;
} while (rest > 0);
System.out.println(digits);
  • Each / 10 drops the last digit; we count the divisions.
  • Thanks to do-while, 0 also counts as 1 digit; no special case needed.
  • The long copy avoids overflow when negating an extreme value such as -2147483648.

Sum of Digits

int num = 725;

int sum = 0;

Examples · Step through the code

Reversing a Number and Palindromes (1221)

A number that reads the same backward is a palindrome. Let's try 1221.

We work on a copy; the reversed number is built up from 0.

Condition: 1221 > 0 → true.

digit = 1221 % 10 = 1; rev = 0 × 10 + 1 = 1 (earlier digits shift one place left).

rest = 1221 / 10 = 122.

Condition: 122 > 0 → true.

digit = 122 % 10 = 2; rev = 1 × 10 + 2 = 12 (earlier digits shift one place left).

rest = 122 / 10 = 12.

Condition: 12 > 0 → true.

digit = 12 % 10 = 2; rev = 12 × 10 + 2 = 122 (earlier digits shift one place left).

rest = 12 / 10 = 1.

Condition: 1 > 0 → true.

digit = 1 % 10 = 1; rev = 122 × 10 + 1 = 1221 (earlier digits shift one place left).

rest = 1 / 10 = 0.

Condition: 0 > 0 → false.

The reversed number 1221 is printed.

1221 == 1221 → true: 1221 is a palindrome. (For 123 the reverse is 321 → false.)

int num = 1221;
int rest = num, rev = 0;
while (rest > 0) {
    int digit = rest % 10;
    rev = rev * 10 + digit;
    rest /= 10;
}
System.out.println(rev);
System.out.println(rev == num);  // palindrome?

Armstrong Numbers: 153 = 1³ + 5³ + 3³

Armstrong number: equals the sum of its digits each raised to the number of digits. 153 has three digits → cubes.

rest = 153, sum = 0.

Condition: 153 > 0 → true.

r = 3; sum = 0 + 3×3×3 = 27.

rest /= 10 → 15.

Condition: 15 > 0 → true.

r = 5; sum = 27 + 5×5×5 = 152.

rest /= 10 → 1.

Condition: 1 > 0 → true.

r = 1; sum = 152 + 1×1×1 = 153.

rest /= 10 → 0.

Condition: 0 > 0 → false.

1 + 125 + 27 = 153 → true. The other 3-digit Armstrong numbers: 370, 371, 407.

int num = 153;
int rest = num, sum = 0;
while (rest > 0) {
    int r = rest % 10;
    sum += r * r * r;   // 3 digits: cube
    rest /= 10;
}
System.out.println(sum == num);

Decimal to Binary: 13 → 1101

Converting 13 to binary: divide by 2 repeatedly and collect the remainders.

We build the binary result from decimal digits (1s and 0s); place = 1 is the ones place.

Condition: 13 > 0 → true.

13 % 2 = 1 → bin += 1 × 1 → 1.

Next bit is one place left: place = 10; n = n / 2 = 6.

Condition: 6 > 0 → true.

6 % 2 = 0 → bin += 0 × 10 → 1.

Next bit is one place left: place = 100; n = n / 2 = 3.

Condition: 3 > 0 → true.

3 % 2 = 1 → bin += 1 × 100 → 101.

Next bit is one place left: place = 1000; n = n / 2 = 1.

Condition: 1 > 0 → true.

1 % 2 = 1 → bin += 1 × 1000 → 1101.

Next bit is one place left: place = 10000; n = n / 2 = 0.

Condition: 0 > 0 → false.

1101 is printed: 1·8 + 1·4 + 0·2 + 1·1 = 13. (For large numbers int overflows; build the result as a String instead.)

int n = 13;
int bin = 0, place = 1;
while (n > 0) {
    bin += (n % 2) * place;
    place *= 10;
    n /= 2;
}
System.out.println(bin);   // 1101

Exponentiation

int base = 2, exp = 4;
int result = 1;
for (int i = 0; i < exp; i++) {
    result *= base;
}
System.out.println(result);
  • The loop runs exactly exp times; each pass multiplies by the base once.
  • If exp = 0 the loop never runs and result stays 1 (2⁰ = 1).
  • Negative exponents are not handled; large results overflow int.

Example

Prime Numbers

int n = 29;
boolean prime = n >= 2;
for (int i = 2; prime && i <= n / i; i++) {
    if (n % i == 0) prime = false;
}
System.out.println(prime);
  • 0 and 1 are not prime: prime = n >= 2.
  • It is enough to search for divisors up to √n: i <= n / i ≡ i × i ≤ n (no overflow risk).
  • Thanks to prime &&, the loop stops once a divisor is found.

k = 14: 14 % 2 = 0 → prime = false, break (the inner loop ends early).

k = 15: 15 % 3 = 0 → prime = false, break (the inner loop ends early).

k = 16: 16 % 2 = 0 → prime = false, break (the inner loop ends early).

k = 17: no divisor in 2 … 4 → prime = true → printed.

k = 18: 18 % 2 = 0 → prime = false, break (the inner loop ends early).

k = 19: no divisor in 2 … 4 → prime = true → printed.

k = 20: 20 % 2 = 0 → prime = false, break (the inner loop ends early).

k = 21 > 20: done. There are 8 primes in 2..20. (The sieve of Eratosthenes is faster.)

int n = 20;
for (int k = 2; k <= n; k++) {
    boolean prime = true;
    for (int i = 2; i <= k / i; i++) {
        if (k % i == 0) { prime = false; break; }
    }
    if (prime) System.out.print(k + " ");
}

Example

The Fibonacci Sequence

int terms = 5;
long a = 0, b = 1;
for (int i = 0; i < terms; i++) {
    System.out.print(a + " ");
    long next = a + b;
    a = b;
    b = next;
}
  • Each term is the sum of the previous two: 0 1 1 2 3 5 8 …
  • The update order keeps both previous values; writing b = next first would lose the old b.
  • The sequence grows fast; even long overflows after term 93.

Number Guessing Game (while + Random + Scanner)

Random generates random numbers (import java.util.Random; and java.util.Scanner at the top).

A Scanner to read from the keyboard.

nextInt(100) gives 0..99; +1 makes it 1..100. This run picked target = 37 (it differs every run).

guess = 0 can never be the target → the loop is sure to start.

Condition: 0 != 37 → true.

The user types 50; tries = 1.

50 > 37 → «Lower». Possible range 1..49. Guessing the middle each time halves the range.

Condition: 50 != 37 → true.

The user types 25; tries = 2.

25 < 37 → «Higher». Possible range 26..49.

Condition: 25 != 37 → true.

The user types 37; tries = 3.

37 is neither smaller nor larger: both ifs are false, no message.

Condition: 37 != 37 → false → the loop ends.

The number of passes is unknown in advance → while is the right choice.

Random rnd = new Random();
Scanner in = new Scanner(System.in);
int target = rnd.nextInt(100) + 1;  // 1..100
int guess = 0, tries = 0;
while (guess != target) {
  guess = in.nextInt();
  tries++;
  if (guess < target) System.out.println("Higher");
  if (guess > target) System.out.println("Lower");
}
System.out.println("Got it in " + tries + " tries");

Sentinel Value: while (true) + break, input 5, 3, 0

Input queue (numbers to be typed): 5, 3, 0. The condition is true, so the loop never ends by itself; break provides the exit.

nextInt() reads 5 from the queue. 5 == 0 → false, no break.

sum = 0 + 5 = 5. Back to the top (true).

nextInt() → 3. 3 == 0 → false.

sum = 5 + 3 = 8.

nextInt() → 0 (the sentinel). 0 == 0 → true → break: exit the loop; 0 is not added.

Sum: 8 is printed. A sentinel marks the end of the data and is not part of it.

Scanner sc = new Scanner(System.in);
int sum = 0;
while (true) {
    int num = sc.nextInt();
    if (num == 0) break;
    sum += num;
}
System.out.println("Sum: " + sum);

Common Mistakes

  • Putting println in the inner loop prints each character on its own line.
  • < vs. <= yields one character too few or too many.
  • Printing spaces after the stars flips the alignment.
  • Wrongly updating the outer variable in the inner loop breaks the flow.

Chapter Summary

  • Every loop has initialization, condition, body and update parts.
  • Use for when the pass count is known, while while a condition holds, do-while when at least one pass is needed.
  • Counter and accumulator patterns recur in digit, power and series problems.
  • In nested loops the outer loop produces rows, the inner loop the items in each row.
  • Digit pattern (% 10, / 10): digit count, reversing, palindromes, Armstrong; divisor pattern: primes and perfect numbers.
  • Test loops by tracing them by hand with 0, 1 and boundary values.
