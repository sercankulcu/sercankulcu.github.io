Introduction

What Is Hardware?

Hardware is all the physical parts of a computer system. Software tells those parts what to do.

  • Input devices bring data into the system.
  • The CPU executes instructions.
  • RAM holds the running program and its data.
  • Storage keeps data permanently.
  • Output devices present the result.

System Components

The Central Processing Unit (CPU)

  • It fetches, decodes and executes program instructions.
  • The ALU performs arithmetic and logical operations.
  • The control unit manages the data flow and sequencing.
  • Core count, clock speed (GHz), cache and architecture together determine performance.

System Components

Processor Ecosystems

x86-64

The dominant architecture in desktops, laptops and servers.

ARM

The dominant architecture in mobile and energy-efficient systems.

Intel and AMD

x86-64 processors for consumers and servers.

Apple, Qualcomm, MediaTek

Different designs and product families built on ARM.

A brand or model name alone does not determine performance. Generation, power limit, core design and workload all count.

System Components

SoC, Mobile Processors and NPUs

  • SoC (system on a chip): the CPU, GPU, memory controller and other units sit on one chip, saving space and power in phones and thin laptops.
  • NPU (neural processing unit): speeds up AI workloads (speech recognition, photo enhancement, translation) at low power.
  • In most SoCs, RAM is a separate chip placed very close to the SoC; details vary by manufacturer.
Instruction sets: x86-64 (Intel, AMD) dominates desktops and servers; ARM dominates mobile and increasingly laptops; RISC-V is an open, royalty-free instruction set. Efficiency differences come from the design, not only the instruction set.

System Components

Clock Speed and Core Count

  • Clock speed: 3 GHz = 3 billion cycles per second; each cycle advances one step.
  • Core: a unit that runs its own instruction stream; more cores help only if the work can be split.
  • A single-threaded program uses one core even on an 8-core CPU, so “8 cores = 8× speed” is false.

System Components

Motherboard

The motherboard ties the components together physically and electrically and lets them talk over buses.

  • CPU socket: determines which processor family is supported.
  • DIMM slots: hold the RAM modules.
  • PCIe: graphics and expansion cards.
  • M.2 / SATA: storage devices.
  • Chipset: manages traffic between ports and slots.
  • 24-pin / 8-pin: motherboard and CPU power.

System Components

RAM (Random Access Memory)

  • Volatile: contents are lost when power goes off.
  • Fast access: the CPU can reach any address directly.
  • Capacity: affects how many applications run comfortably at once.
  • Compatibility: DDR generation, speed and motherboard support must match.
Even with free disk space, too little RAM slows programs down and forces the disk to be used as temporary memory.

System Components

ROM and Firmware

ROM

Memory that keeps its contents without power. Today firmware usually lives in rewritable flash memory.

Firmware

Low-level software that controls the basic behavior of the hardware.

BIOS / UEFI

Initializes the hardware at power-on and starts loading the operating system.

Updates

Fix compatibility or security issues; never interrupt one midway.

The first software to run at power-on is the firmware (UEFI) in the motherboard's flash chip. It finds the operating system on disk and starts it.

System Components

The Memory Hierarchy

Values are approximate. The CPU keeps frequently used data in the upper levels to avoid slow trips down; RAM is volatile, SSD/HDD are persistent.

System Components · Step by step

Access Time Across the Levels

Registers are inside the processor; access takes less than one clock cycle (< 1 ns). Capacity: hundreds of bytes.

L1 cache is the smallest and fastest cache. L1–L3 range from 1 to 10 ns; L1 is at the low end.

L2 cache is larger but a bit slower (upper part of the range). The scale is logarithmic: gridlines are 1000× apart (1 ns, 1 µs, 1 ms).

RAM 50–100 ns: tens of times slower than L1. The processor caches data to avoid waiting on RAM.

SSD ≈ 0.1 ms = 100,000 ns: about 1000–2000× slower than RAM, but persistent.

HDD 5–10 ms: 50–100× slower than an SSD and 50,000–200,000× slower than RAM; it needs mechanical movement (seek + rotation).

System Components

How Does a Cache Work? (Hits and Misses)

The CPU requests address 1003 (first access). It checks the cache first.

Miss: 1003 is not in the cache → fetched from RAM (~80 ns) and copied into the cache together with its neighbor (1002–1003).

The CPU requests address 1003 (again). It checks the cache first.

Hit: 1003 is in the cache → the value 108 reaches the CPU in about 1 ns.

The CPU requests address 1004 (neighboring address). It checks the cache first.

Miss: 1004 is not in the cache → fetched from RAM (~80 ns) and copied into the cache together with its neighbor (1004–1005).

System Components · Step by step

Caching an Array Sum: Counting Hits and Misses

Array a is in RAM; the cache is empty. Assume a 4-byte int and a 16-byte cache line (block), i.e. 4 elements; hit ≈ 1 ns, miss ≈ 80 ns.

a[0] requested: not in cache → miss. RAM sends the whole block (a[0]…a[3]), not just a[0]: 80 ns.

a[1] requested: block 0 is cached → hit, 1 ns. It came along with the previous miss.

a[2] requested: block 0 is cached → hit, 1 ns. It came along with the previous miss.

a[3] requested: block 0 is cached → hit, 1 ns. It came along with the previous miss.

a[4] requested: not in cache → miss. RAM sends the whole block (a[4]…a[7]), not just a[4]: 80 ns.

a[5] requested: block 1 is cached → hit, 1 ns. It came along with the previous miss.

a[6] requested: block 1 is cached → hit, 1 ns. It came along with the previous miss.

a[7] requested: block 1 is cached → hit, 1 ns. It came along with the previous miss.

Done: sum = 31. 6 of the 8 accesses hit; time 2 × 80 + 6 × 1 = 166 ns. Without a cache it would be 8 × 80 = 640 ns. That is why sequential access is fast: spatial locality. Striding through the array (a[0], a[4], …) would miss every time.

sum = 0
for i = 0, 1, …, 7 do
    sum = sum + a[i]
// 4-byte int, 16-byte line

System Components · Step by step

Multi-Level Cache Reads, Step by Step

The CPU will read addresses A, A, D in turn. Initially L1 holds B, L2 holds C, L3 holds B, C, D; A is only in RAM. Times are approximate.

A requested. Start with the fastest, smallest level: not in L1 (1 ns spent).

Not in L2 either: +3 ns.

Not in L3 either: +10 ns.

Fetched from RAM: +80 ns, total ≈ 94 ns. On the way, the data is copied into every level so the next request is fast.

A requested again: in L1 → hit, ≈ 1 ns. Reusing the same data soon after is fast: temporal locality.

D requested: not in L1 (1 ns).

Not in L2 (+3 ns).

Found in L3: +10 ns, total ≈ 14 ns; copied to L2 and L1. About 7× faster than going to RAM.

Three reads: 94 + 1 + 14 = 109 ns. Reading all from RAM would take 3 × 80 = 240 ns. Real caches evict the least recently used line when full; this example ignores space limits.

In L1?  Yes → read, done
In L2?  Yes → copy to L1, read
In L3?  Yes → copy to L2 and L1, read
Fetch from RAM → copy to L3, L2, L1, read

System Components

Case and Cooling

  • Protection: shields components from physical damage.
  • Airflow: cool air enters at the front, hot air leaves at the back/top.
  • Form factor: determines which motherboard and power supply fit.
  • Cable management: helps airflow and maintenance.
At high temperatures the processor slows itself down (thermal throttling), and component life can shorten.

System Components

The Power Supply (PSU)

Converts alternating current (AC) from the mains into the direct current (DC) voltages the components use.

  • Capacity (W): must cover total demand with a safety margin.
  • Efficiency: higher means less waste heat.
  • Connectors: motherboard, CPU, GPU and storage cables must match.
  • Protection: safeguards against overcurrent and voltage surges.

Storage

Storage Devices

Storage devices keep data when the power is off. When you open and save a document, the data travels like this:

1. The user double-clicks report.docx; the mouse sends this event to the computer (input).

2. The operating system finds the program and document files in persistent storage (SSD).

3. The program and document are copied from the SSD into RAM: the CPU runs from RAM, not directly from the SSD.

4. The CPU fetches instructions from RAM into the cache and registers and executes them (fetch–decode–execute).

5. The result goes through the graphics card to the monitor; the user sees and edits the document (output).

6. On “Save”, the changes are written from RAM to the SSD. Unsaved changes are lost if the power fails.

Storage

Inside an HDD and an SSD

  • HDD: the head must move to the right track and the sector must rotate under it → access takes milliseconds.
  • SSD: the controller reads from several flash chips in parallel → access takes microseconds.

Storage

Storage · Step by step

How an HDD Reads a Sector

The platter spins thousands of times a minute (e.g. 7200 rpm). The sector to read (orange) and the head start in different places; access time has three parts.

1) Seek time: the arm moves the head to the track holding the target sector. It is mechanical, so it takes a few milliseconds (5 ms here).

2) Rotational latency: the head is on the right track, but the sector is not under it yet; we wait for the platter to turn. At 7200 rpm a full turn takes 8.3 ms, so the average wait (half a turn) is ≈ 4.2 ms.

3) Transfer: data is read as the sector passes under the head. 4 KB ÷ 150 MB/s ≈ 0.03 ms: the actual read is tiny compared with the waiting.

Total access ≈ 5 + 4.2 + 0.03 ≈ 9.2 ms. Almost all of it is mechanical waiting, which is why many small files are slow on an HDD (an SSD has no such wait).

Summary

Chapter Summary

  • The CPU executes instructions; the motherboard connects the components.
  • RAM is temporary working space; SSDs and HDDs provide persistent storage.
  • The GPU handles parallel graphics and compute workloads.
  • Input devices bring data into the system; output devices present results to the user.
  • When choosing hardware, compatibility, power, cooling and purpose matter as much as performance.

Exercises

  1. Compute the PPI of a 27-inch, 2560 × 1440 monitor.
  2. How many seconds does it take to copy an 8 GB video to an SSD at 500 MB/s?
  3. How many ms does each frame stay on screen at 144 Hz? Compare with 60 Hz.
  4. CPU 125 W, GPU 220 W, everything else 75 W. With a 30% margin, what power supply do you choose?
  5. Touchscreen, scanner, projector, headset with mic, SSD: input, output or both?
  6. In what order does data move between the SSD, RAM, cache and CPU when a document is opened and saved?
Answers
  1. √(2560² + 1440²) ≈ 2937; ÷ 27 ≈ 108.8 PPI.
  2. 8000 MB ÷ 500 MB/s = 16 s.
  3. 1000 ÷ 144 ≈ 6.9 ms; at 60 Hz ≈ 16.7 ms.
  4. 420 W × 1.3 ≈ 546 W → 550 W.
  5. Input: scanner; output: projector; both: touchscreen, headset with mic, SSD.
  6. SSD → RAM → cache → CPU; save: RAM → SSD.
