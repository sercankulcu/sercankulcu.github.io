Formulas

Formula Basics

Excel formulas start with an equals sign and can contain constants, references, operators and functions.

  • Parentheses make the order explicit: =(B2+C2)/2.
  • A formula recalculates when the cells it refers to change.
  • Keeping constants in their own cells, not buried in formulas, makes maintenance easier.

Formulas

Operator Precedence

PrecedenceOperationExample
1Parentheses=(A1+B1)*2
2Negation (sign)=-A1
3Percentage=A1*10%
4Exponent=A1^2
5Multiplication and division=A1*B1/C1
6Addition and subtraction=A1+B1-C1
7Joining=A1&" TL"
8Comparison=A1>B1

Operations of equal precedence go left to right: =12/3*2 → 8.

Formulas

A Formula Evaluated Step by Step

Excel first replaces references with their values: B1 → 4.

Parentheses come first: (4-1) → 3.

Then the exponent: 3^2 → 9.

Then multiplication: 3*9 → 27.

Addition last: 2+27 → 29.

The result is 29. Without the parentheses, =2+3*4-1^2 → 2+12-1 = 13.

In Excel the sign (negation) is applied before the exponent: -2 becomes (-2) first.

(-2)^2 = 4. To get the mathematical -2² = -4, write =-(2^2) or =0-2^2.

The result is 4.

Formulas

References When Filling Down

Three different formulas go in B1, C1 and D1; all three point to A1 (5).

One row down with the fill handle: A1 is relative, so it became A2; $A$1 and A$1 kept the row fixed.

One more row: the relative reference moved to A3 (15). The absolute and mixed references still point to A1.

Result: when filling down, A$1 behaves like an absolute reference (the row is locked). To see the difference, fill right.

Formulas

References When Filling Right

Row 1 holds data (5, 7, 9, 11). Four kinds of reference go in A3:A6; all point to A1.

One column right: A1 → B1 and A$1 → B$1 (the column moved); $A$1 and $A1 kept the column locked.

In column C, the relative and A$1-style references point to C1 (9); a column letter with a $ never changes.

The rule: $ locks the part right after it. $A$1 locks both, A$1 only the row, $A1 only the column.

Formulas

Mixed References: A Multiplication Table

One formula goes in B2: =$A2*B$1 → 4·1 = 4. Column A and row 1 are locked.

C2: =$A2*C$1 → 8. Copied right, only the unlocked column letter changed (B→C).

D2: =$A2*D$1 → 12. Copied right, only the unlocked column letter changed (B→D).

B3: =$A3*B$1 → 5. Copied down, only the unlocked row number changed.

C3: =$A3*C$1 → 10. Copied down, only the unlocked row number changed.

D3: =$A3*D$1 → 15. Copied down, only the unlocked row number changed.

The last row is filled too: one formula built the whole table; every cell multiplies its row's A value by row 1 of its column.

Formulas · Step by step

F4 and the Absolute Reference Shortcut

=B2*E1 is typed. With the cursor on the E1 reference, press F4. E1 is relative: filled down it becomes E2, E3.

1st F4: $E$1, absolute. Column and row are fixed; the VAT rate is always read from E1.

2nd F4: E$1, mixed. Only the row is fixed; the column letter changes when filled right.

3rd F4: $E1, mixed. Only the column is fixed; the row number changes when filled down.

4th F4: the cycle is complete, back to E1 (relative). When you reach the form you want, press Enter.

F4 works while editing a formula with the cursor on a reference. Laptops may need Fn+F4; on a Mac the shortcut may differ. You can also type the $ yourself.

Formulas · Step by step

A Relative Reference Error in a Copied Formula

Three prices are in column B and the discount rate in a single cell: E1 = 20%. The discounted-price formula goes in C2.

C2: =B2*(1-E1) → 200 × 0.8 = 160. Correct.

Copied down with the fill handle, both references move one row: =B3*(1-E2). E2 is empty, and an empty cell counts as 0 → 150 × 1 = 150. No discount was applied!

C4: =B4*(1-E3) → 80. Excel shows no error message: the results are numbers, so at first glance they don't look wrong. This is the sneakiest relative-reference bug.

The fix: in C2, with the cursor on E1, press F4 → =B2*(1-$E$1). B2 stays relative (each row needs its own price); E1 becomes absolute.

Copied down: =B3*(1-$E$1). It moved to B3 while $E$1 stayed put → 150 × 0.8 = 120.

C4: =B4*(1-$E$1) → 80 × 0.8 = 64. Change the rate to 30% and all three results update at once.

Check: Formulas → Show Formulas (Ctrl + `) shows formulas instead of results. If a reference to a single cell must stay the same on every row, look for the $.

C2: =B2*(1-E1)
C3: =B3*(1-E2)    ← when copied
C4: =B4*(1-E3)
C2: =B2*(1-$E$1)
C3: =B3*(1-$E$1)
C4: =B4*(1-$E$1)

Formulas

Functions on the Same Data

SUM adds only the numbers: 12+7+20+5 = 44. The text “none” and the empty cell are ignored.

AVERAGE = 44 / 4 = 11. The divisor is 4, not 6: only numbers count (an empty cell is not taken as 0).

MAX finds the largest number: 20.

MIN finds the smallest number: 5.

COUNT counts the cells that hold numbers: 4. (For all non-empty cells, use COUNTA.)

Formulas

Lookup with VLOOKUP

VLOOKUP(lookup_value, table, col_index, 0): finds the value in the first column of the table and returns the requested column from the same row. A last argument of 0 (FALSE) means exact match; approximate match (1/TRUE) on sorted data is not for this job.

A2 = “Ali” ≠ “Ece” → move down a row.

A3 = “Ece” = “Ece” → found.

Column 2 of the found row, B3, is returned: 91.

“Mert” isn't in any row of the first column: every row was tried and the result is #N/A (value not available).

Formulas · Step by step

Approximate Match with VLOOKUP: a Grading Scale

Columns D–E hold the grading scale: the first column is the threshold, sorted ascending. The last argument is TRUE: not exact but approximate match. The threshold table is locked with $, so it doesn't shift when the formula is copied down.

C2: looking up 72. The result is the largest threshold less than or equal to 72 in the first column: 0, 50, 60, 70 qualify, 85 doesn't → the row of 70, column 2 → B.

C3: looking up 85. Equality counts too: 85 ≤ 85 → the largest qualifying threshold is 85 → A.

C4: looking up 49. Only 0 qualifies (50 > 49) → F. With exact match (FALSE), scores missing from the table, like 72 or 49, would give #N/A.

C5: looking up −5. No threshold is less than or equal to −5 → #N/A. The smallest threshold should be the smallest possible score (0); invalid scores can be blocked with data validation.

In approximate match Excel doesn't scan row by row; it does a binary search, so the first column must be sorted ascending. On an unsorted scale it can return the wrong letter with no error message.

C2: =VLOOKUP(B2,$D$2:$E$6,2,TRUE)
C3: =VLOOKUP(B3,$D$2:$E$6,2,TRUE)
C4: =VLOOKUP(B4,$D$2:$E$6,2,TRUE)
C5: =VLOOKUP(B5,$D$2:$E$6,2,TRUE)

Formulas · Step by step

Formula Errors Step by Step

#DIV/0!: the formula =B2/C2 gives #DIV/0!. Cause: the divisor C2 = 0 (an empty cell counts as 0). Fix: check the divisor or write =IF(C2=0,"",B2/C2).

#NAME?: the formula =SUMM(B2:B4) gives #NAME?. Cause: Excel doesn't recognize “SUMM” (a misspelled function name; text without quotes gives the same error). Fix: =SUM(B2:B4).

#VALUE!: the formula =B2*2 gives #VALUE!. Cause: B2 holds the text “12 TL” (left-aligned), not a number. Fix: type just 12 in B2 and show “TL” with a number format.

#REF!: the formula =B2+#REF! gives #REF!. Cause: a column the formula used was deleted (invalid reference). Fix: undo with Ctrl+Z or retype the reference.

#N/A: the formula =VLOOKUP(D2,A2:B4,2,0) gives #N/A. Cause: “Selin” isn't in the list (exact match). Fix: check the spelling, add the record, or show a message with IFNA (Excel 2013+).

Data Analysis · Step by step

Multilevel Sort, Filter and SUBTOTAL

Six records in entry order. Below them, three formulas: SUM, SUBTOTAL(9,…) (sum) and SUBTOTAL(1,…) (average). For now all three cover every row: 443 and 73.8.

Two levels in the Sort dialog: Dept A to Z first, and within each dept Score largest to smallest. Computer: Çağla 91, Selin 78, Burak 55. Rows moved as whole units.

Filter: Computer only. Row numbers skip; 5–7 are hidden. SUM is still 443: it adds hidden rows too. SUBTOTAL counts only the visible ones: 91 + 78 + 55 = 224, average 74.7.

A second condition, Score > 75: the two filters narrow together, and Burak (55) is hidden too. SUBTOTAL(9) = 169, SUBTOTAL(1) = 84.5. SUM didn't change.

Clear: the filters go, all rows return, and SUBTOTAL is 443 again. Filtering deleted no data.

Name A to Z: with a Turkish sort locale Ç comes after C and İ after I: Ali, Burak, Can, Çağla, İrem, Selin. The formulas point to C2:C7, so sorting doesn't change their results.
