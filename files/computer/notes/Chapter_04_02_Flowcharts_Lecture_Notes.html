Chapter 4.2: Flowcharts

When an algorithm is first put on paper, a drawing often comes before any text. Boxes show the steps and arrows show their order. Such a drawing is called a flowchart. This chapter introduces the symbols used in flowcharts and the rules of a good diagram. Then come the three kinds of flow that are the building blocks of every algorithm. In sequential flow, steps run one after another. In conditional flow, the path splits according to a question. In repetitive flow, a group of steps runs again and again. Each structure is executed step by step on small examples, and the value of each variable at each step is given in trace tables. Loop patterns such as the counter, the accumulator, and the sentinel value, as well as nested loops, early exit, and flags, are also treated separately. The last sections show how a flowchart is translated into Java code and which inputs a flowchart is tested with.

4.2.1The flowchart

An algorithm is a clear and finite sequence of steps for solving a problem. Steps can also be described in plain prose. But as the text grows longer, it becomes easy to lose track of which step comes after which, and under what conditions a step is skipped or repeated. A flowchart makes this order visible.

4.2.1.1What is a flowchart?

Definition 4.2.1

A flowchart is a drawing that shows the steps of an algorithm with standard symbols and the order in which they run with arrows. The shape of a symbol tells the kind of step (start, process, decision, input/output), the short expression inside tells what the step does, and the arrow tells which step execution moves to.

An everyday example makes the definition concrete. An apartment building has a keypad lock on its door. The small computer inside the lock does the same job each time: it reads the code entered, checks whether it is correct, opens the door if it is, and sounds a warning otherwise. Figure 4.2.1 shows this job as a flowchart.

The diagram is read from top to bottom. Execution begins at the round-ended box labeled Start. An arrow carries execution to the “read the code” box. Next comes the diamond-shaped decision box. It contains a question: “correct?” Depending on the answer, one of two arrows is followed. The path along the Yes arrow opens the door; the path along the No arrow sounds a warning. Both paths finally meet at the same point and reach the End box.

This small drawing shows three basic properties of a flowchart. First, the kind of each step is clear from its shape; the reading step and the deciding step are in different boxes. Second, the order of the steps is fixed by the arrows; the reader does not have to guess which step comes first. Third, the paths leaving a decision box can be followed separately; on each run only one of these paths is used.

4.2.1.2Why draw a diagram?

A flowchart is independent of any programming language. The same diagram can be written in Java, Python, or C. That is why the logic of an algorithm can be discussed before it is decided which language it will be coded in. In a team, people who are not programmers, for example a laboratory manager or a business-process manager, can also read the diagram and ask “what happens in this case?”

The second benefit of drawing a diagram is that errors are seen early. If only one arrow leaves a decision box, nobody has thought about what happens in the other case. A box that no arrow enters never runs. If nothing changes along the path of a backward arrow, the loop goes on forever. Such gaps hide between the lines of code; in a diagram they are noticed from the shape of the drawing.

The third benefit is about learning. For a beginner, one of the hardest concepts is the order of execution. The computer runs lines one at a time and in sequence. It skips some lines according to a condition and repeats others. In a flowchart this order can be followed with a finger. Throughout this chapter, every diagram will be executed this way, box by box.

4.2.2Symbols

The symbols of flowcharts are defined by an international standard: ISO 5807. The standard was published in 1985, and most drawing tools in use today follow it. Five basic symbols are enough for a small algorithm. Additional symbols are used when a diagram grows or when external things such as files and reports are to be shown.

4.2.2.1Basic symbols

Figure 4.2.2 shows the basic symbols together. The job of each is explained below.

Definition 4.2.2

The terminal symbol (start/end) is an oval or a rectangle with rounded ends. It shows where the algorithm begins and where it ends. Every diagram has a single Start and at least one End.

No arrow enters the Start symbol; only an arrow leaves it. An arrow enters the End symbol; none leaves it. A diagram may have more than one End. For example, in the number-guessing game the game ends immediately on a correct guess; in that case drawing a separate End after the text “You got it” simplifies the diagram. Even so, in most cases merging the paths and leading them to a single End makes reading easier.

Definition 4.2.3

The process symbol is a rectangle. It shows a computation or an assignment. An assignment gives a variable a new value: the expression sum = a + b computes the value a + b on the right and writes the result into the variable named sum.

The word variable appears here for the first time. A variable can be thought of as a box in memory that has a name. At any moment the box holds a single value. When a new value is written, the old one is erased. The equals sign in an assignment is different from equality in mathematics. i = i + 1 is meaningless in mathematics, because no number can equal one more than itself. In a flowchart and in a program, however, this statement means “add 1 to the current value of i and write the result back into i.” If i was 4 before, it is 5 after this box runs.

Definition 4.2.4

The decision symbol is a diamond. A question whose answer is “yes” or “no,” that is, a condition, is written inside it: a > b ?. One arrow enters the decision symbol and two leave it; the outgoing arrows are labeled Yes and No.

A condition is a comparison. In flowcharts and in Java there are six comparison operators. These are < (less than), <= (less than or equal), > (greater than), >= (greater than or equal), == (equal), and != (not equal). Two equals signs are used for the equality question, because the single equals sign is reserved for assignment. Some books also use the signs ≤, ≥, and ≠; the meaning is the same.

Definition 4.2.5

The input/output symbol is a parallelogram. It shows the algorithm taking data from outside (“read a”) or giving a result to the outside (“print sum”). Data taken from outside is called input, and the result given to the outside is called output.

The word “read” covers data coming from the keyboard, from a file, or from a sensor. A flowchart is not concerned with where the data comes from; it only says that at this point a value enters the algorithm. Likewise “print” covers writing to the screen, to a printer, or to a file.

Definition 4.2.6

The flow line, or simply arrow, joins two symbols and shows the direction of execution. The connector is a small circle; it shows the point where several paths meet, or that the diagram continues elsewhere.

The arrowhead matters. A line without a head says that two boxes are connected but not which runs first. That is why every flow line has an arrowhead at its end. The connector marks the place where two paths leaving a decision meet again, as in Figure 4.2.1. A connector with a letter inside is paired with another connector carrying the same letter. This way there is no need to draw a long arrow from one corner of the page to the other.

4.2.2.2What goes inside a symbol?

Because the shape of a symbol already tells the kind of step, only a short expression of that step is written inside. A decision symbol gets a question: a > b ?. A process symbol gets a command: sum = a + b. An input/output symbol gets what is read or printed: “read a,” “print sum.” This distinction lets the person reading a diagram know what will happen at a step even before reading the inside of the box.

The question form has one more rule: its answer must have two options. The question “which is larger, a or b?” has the answer “a” or “b,” but leaves the case of equality open. The question a > b ?, on the other hand, always has the answer yes or no: if a = b, the answer is no. That is why a comparison is always written in a decision box.

Example 4.2.1

An algorithm computes a student's average from the midterm and final exam grades and prints the pass/fail result. Its steps are: get the midterm grade; get the final grade; compute the average as midterm × 0.4 + final × 0.6; check whether the average is 50 or above; print the result on the screen. Which symbol does each step get, and what is written inside?

Solution. “Get the midterm grade” is an input: a parallelogram, with “read midterm” inside. The final grade likewise goes in a parallelogram. The average computation is an assignment: a rectangle, with avg = midterm × 0.4 + final × 0.6 inside. “Is it 50 or above” is a question: a diamond, with avg >= 50 ? inside. Printing the result is an output: one parallelogram on each of the Yes and No branches, with “print Pass” and “print Fail” inside. Start is added at the very beginning and End at the very end. If the midterm is 40 and the final is 60, the average is 40 × 0.4 + 60 × 0.6 = 16 + 36 = 52; since 52 ≥ 50, the Yes path is followed and “Pass” is printed.

Common mistake

Writing a computation in a parallelogram. sum = a + b has nothing to do with the screen or the keyboard; it computes a value in memory. It therefore belongs in the process symbol, the rectangle. The parallelogram is only for exchanging data with the outside world. A similar confusion appears when a command is written in a decision box: the sentence “compare a with b and print the larger” is not a question, and it does two jobs at once. The right way is to write a > b ? in the decision box and move the printing to parallelograms on the branches.

The five basic symbols are enough for small algorithms. In some cases the additional symbols of ISO 5807 are used. 4.2.3Diagram design

Knowing the symbols is not enough to draw a diagram. The path from a problem to a diagram has definite steps. When these steps are followed, no case is left out, and the result is a drawing that is easy to read.

4.2.3.1A diagram step by step: the larger of two numbers

The problem is short: two numbers are given and the larger one is to be printed. The diagram is built in five steps.

  1. Determine the input and output. What the algorithm takes from outside and what it gives to the outside is written first. The input is two numbers: a and b. The output is the larger number. Both are shown with parallelograms: “read a, b” and “print the larger.”
  2. Order the steps. Start and End are added. The steps are arranged from top to bottom: reading first, printing last. A value that has not been read cannot be compared; that is why the reading box is always above the decision.
  3. Separate the decisions. Which number is printed depends on a question: is a greater than b? The decision box a > b ? goes in between. The single “print the larger” box now splits into two boxes: “print a” and “print b.”
  4. Connect the arrows. Each box is joined to the next with an arrow. The two arrows leaving the decision are labeled Yes and No. The two branches merge at a connector below and go to End.
  5. Trace with an example. The diagram is executed by hand with an input. For a = 4, b = 9, 4 > 9 is false; the No path is followed, the “print b” box runs, and 9 is printed. The result is correct.

The fifth step is often skipped, but it is the most valuable one. During a hand trace, trying a single input is not enough. The Yes path must also be tried with a = 9, b = 4; in that case 9 is printed. And what if a = b = 5? Since 5 > 5 is false, the No path is followed and b, that is 5, is printed. When the two numbers are equal it does not matter which one is printed; the diagram gives the correct result in this case too. This small experiment shows that the result would not change even if >= were written in the decision box instead of >.

4.2.3.2Readability rules

The same algorithm can be drawn well or badly. Figure 4.2.4 shows the same two-number problem in two ways. In the drawing on the left, the arrows cross each other, the exits of the decision box are unlabeled, and three separate jobs, such as “print b, end, a=b,” are crammed into one box. The drawing on the right flows from top to bottom, the exits of the decision are labeled, and each box contains a single job.

The rules fall under three headings:

  • Direction of flow. The flow runs from top to bottom and from left to right as far as possible. The reader's eye moves in this direction; arrows going the other way are used only in loops, to show the return. Crossing arrows are kept to a minimum; if crossing is unavoidable, a connector is used.
  • Decision labels. Every arrow leaving a decision carries a meaningful label such as Yes/No (or True/False). In an unlabeled decision, which path is chosen in which case is left to guesswork.
  • One job per box. A single basic operation is written in a symbol. If three operations are crammed into one box, it becomes unclear which is done first, and if the box contains a decision, that decision is overlooked. If a diagram grows and no longer fits on the page, it is split into subprocesses.
Common mistake

Drawing only one arrow out of a decision. The student draws the case in mind, for example “if the grade is above 60, print Pass,” and forgets the other case. When the grade is 45, the diagram does not say where execution goes; the flow breaks. Two arrows always leave a decision box. If there is no job to do in the other case, the No arrow goes directly to the merge point.

4.2.3.3Flowchart and pseudocode

The second common way of describing an algorithm is pseudocode.

Definition 4.2.7

Pseudocode is a way of writing the steps of an algorithm in short sentences that resemble a programming language but are not bound by its rules. Lines are read in order; lines inside a decision or loop are shown by indentation.

Figure 4.2.5 shows the algorithm that finds the absolute value of a number in two forms. If the number is negative, its sign is changed; otherwise it stays as it is.

read x
if x < 0 then
    x = −x
print x

The two notations describe the same algorithm and either can be translated into the other line by line. “read x” corresponds to the parallelogram, “if x < 0 then” to the decision box, the indented line x = −x to the rectangle on the Yes branch of the decision, and “print x” to the last parallelogram. The No branch of the decision has no box; the arrow goes straight to the printing box. In pseudocode this case is shown by a single indented line under the “if” line.

Pseudocode has no standard. Some books write “if … then,” others “when … do”; some use = for assignment, others ←. What matters is that each step is clear. In this chapter, pseudocode is written with English words and Java-like symbols: assignment =, equality question ==, remainder %.

4.2.3.4The three structures of structured programming

In a flowchart, arrows can be drawn anywhere. An arrow jumping to a random box in the middle of the diagram is technically possible. In the 1960s, as programs grew, this freedom caused serious problems. The arrows tangled, and it was impossible to follow by how many different paths a box could be reached. Such drawings and programs were called spaghetti code, after a tangle of pasta.

The solution is to use only three patterns instead of drawing arrows at random. Figure 4.2.6 shows these three patterns.

Definition 4.2.8

Structured programming is the approach of building algorithms from only three control structures. The sequence structure: steps run one after another. The selection, or decision, structure: one of two paths runs according to a condition. The repetition, or loop, structure: a group of steps runs again as long as a condition is true.

Theorem 4.2.1 (Böhm–Jacopini)

Every algorithm can be written with only the structures of sequence, selection, and repetition. Corrado Böhm and Giuseppe Jacopini published this result in 1966.

What the theorem says is strong: arrows that jump at random are never needed. Every diagram drawn in spaghetti form has a structured equivalent that does the same job. If necessary, one or two extra variables (for example a flag) are used.

The common property of the three structures is the single entry, single exit rule. One arrow enters each structure from above and one arrow leaves from below. Thanks to this, a structure can be put in place of any box inside another structure. For example, a whole decision structure can be placed instead of the rectangle in the body of a loop. These are called nested structures. Large algorithms are built this way, by nesting small structures. Any part of the diagram can be understood and tested separately through its own entry and exit arrows.

Programming languages adopted this idea too. In older languages the goto statement, which jumps to any line of the program, was common. In Java, goto is a reserved word, that is, it cannot be used as a variable name, but it does nothing in the language. In Java, the flow of execution is built only from lines in sequence, from if/else, and from the while, do, and for loops.

4.2.3.5Drawing tools

No special tool is required to draw a flowchart. The choice depends on what the diagram will be used for:

  • Pen and paper: The fastest way for a first draft; erasing and redrawing is easy. In exams, too, diagrams are drawn by hand.
  • Word and PowerPoint: All the basic symbols are in the Flowchart group of the Insert → Shapes menu. Because connector arrows stick to the boxes, the arrow moves with a box when it is moved.
  • draw.io (diagrams.net): It is free and runs in the browser. It offers ready-made flowchart shapes; the drawing can be exported as PNG, SVG, or PDF.
  • Microsoft Visio: A commercial tool used for corporate process and workflow diagrams.
  • Flowgorithm: It does not merely draw the diagram but runs it. It shows the values of variables step by step and translates the diagram into code in many languages, including Java.
  • Mermaid: The diagram is defined with text and the tool draws it. It is often used in documents and code repositories.

Whatever the tool, the meaning of the symbols and the readability rules are the same. The course's Flowchart Runner simulator, like Flowgorithm, executes a diagram step by step; most of the examples in these notes can be tried there as well.

4.2.4Sequential flow

The simplest of the three structures is sequence. All the control structures are built on this foundation: any section without a decision or loop is sequential flow in itself.

4.2.4.1The sequence structure

Definition 4.2.9

Sequential flow is flow in which the steps run in the order they are written, each after the previous one has finished, and exactly once. It contains no branching or repetition; it has a single entry and a single exit.

Figure 4.2.7 shows the diagram that reads two numbers and prints their sum. All the arrows in the diagram point downward; no box has more than one arrow leaving it.

Start
  read a
  read b
  sum = a + b
  print sum
End

In the pseudocode, the four lines between Start and End are indented; each line corresponds to one box in the diagram.

4.2.4.2Executing sequential flow step by step

To execute a diagram is to do by hand the work the computer would do. We start at the Start box. At each step only one box runs. After a box runs, the new values of the variables and the output, if any, are noted, and then we move to the box the arrow points to. If these notes are collected in a table, the result is a trace table. Table 4.2.4 is the trace table of the execution with input a = 4, b = 7.

The table shows two properties of sequential flow clearly. First, each of the six boxes runs exactly once; there is no repeated or skipped row in the table. Second, once a variable receives a value, it keeps it unless it is changed: a becomes 4 at step 2 and stays 4 to the end. When reading the table, each row describes the state “right after this box has run.”

The Java counterpart of the diagram follows the same order:

import java.util.Scanner;

public class Sum {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int a = in.nextInt();             // read a
        int b = in.nextInt();             // read b
        int sum = a + b;                  // sum = a + b
        System.out.println(sum);          // print sum
    }
}

The structure of the program can be summed up in a few words. The line public class Sum gives the program's name. The main method is where the program starts; the counterpart of the Start box in the diagram is its opening brace, and the counterpart of End is the closing brace. Scanner is the ready-made class Java provides for reading data from the keyboard; in.nextInt() reads an integer from the keyboard. That is why each “read” parallelogram becomes a call to nextInt(). The assignment rectangle corresponds exactly to the line int sum = a + b;, and the “print” parallelogram to the line System.out.println(sum);. At the ends of the lines there are comments beginning with //. The compiler ignores them; here they remind us of each line's counterpart in the diagram.

When the program is run with input 4 and 7, it prints 11. With input −3 and 10, it prints 7. In a sequential program, even when the inputs change, the lines that run and their order never change; only the values do.

4.2.4.3Why order matters

In sequential flow, the positions of the boxes are not arbitrary. If the sum box were moved above the reading boxes, a and b would not yet have values and the sum could not be computed. This mistake is easy to notice. More insidious bugs arise from swapping two assignments.

Example 4.2.2

The values of two variables are to be exchanged; this operation is called a swap. If a = 4, b = 7, then after the operation a = 7, b = 4 must hold. A student puts two boxes in the diagram: first a = b, then b = a. What is the result? How is the correct diagram built?

Solution. The proposed diagram is executed step by step. When the a = b box runs, a takes the value of b: a = 7, b = 7. a's old value, 4, is now nowhere. When the b = a box runs, b takes a's current value: b = 7. The result is a = 7, b = 7; the swap has failed.

The problem is that the first assignment erases a's old value. The solution is to store that value first in a third variable. Such a briefly used variable is called a temporary variable. The correct order is three boxes: temp = a, a = b, b = temp. Execution: temp = 4; a = 7; b = 4. The result is a = 7, b = 4.

import java.util.Scanner;

public class Swap {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int a = in.nextInt();
        int b = in.nextInt();
        int temp = a;                     // a's value is saved
        a = b;
        b = temp;
        System.out.println(a + " " + b);
    }
}

When the program is run with input 4 7, it prints 7 4. The example shows the basic rule of sequential flow: each box works with the values the previous one left behind. An assignment reads the current value of the variable on its right side; not its old or future value.

Common mistake

Reading an assignment like an equality in mathematics. a = b does not say “a and b are equal”; it says “copy the current value of b into a.” After the copy, if b changes, a does not; if a is changed, b is not. Two variables carry the same value only at the moment of the assignment.

4.2.5Conditional flow

A sequential algorithm does the same steps on every input. In most real problems, however, the work to be done depends on the situation: if the grade is below 60 the student fails, if the code is wrong the door does not open, if the temperature is below zero a warning is given. Such choices are shown with the decision symbol.

4.2.5.1The two-way decision

Definition 4.2.10

Conditional flow is flow in which one of two paths is followed according to the result of the condition asked in a decision symbol. If the condition is true, the Yes path runs; if false, the No path. These paths are called branches, and the splitting of the path in two is called branching. The branches merge again at a connector.

Figure 4.2.9 shows the diagram that prints “Pass” or “Fail” according to an exam grade. The passing mark is 60; 60 and above passes.

Start
  read grade
  grade >= 60 ?
    Yes → print "Pass"

Finally, the boundary value of the condition deserves attention. Because the passing mark is “60 and above,” the condition is written grade >= 60. Had grade > 60 been written, a student who scored exactly 60 would fail.

4.2.5.3The one-way decision

In some decisions, only one of the branches has work to do. The absolute-value diagram in Figure 4.2.5 is an example: if the number is negative its sign is changed; if it is not negative, nothing is done. Two arrows still leave the decision here, but the No arrow goes straight to the merge point without passing through any box. In Java this structure is written with an if that has no else part:

import java.util.Scanner;

public class AbsoluteValue {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int x = in.nextInt();
        if (x < 0) {                      // no box on the No branch: no else needed
            x = -x;
        }
        System.out.println(x);
    }
}

The program prints 5 for −5, 8 for 8, and 0 for 0. The three inputs are chosen deliberately: −5 tries the Yes branch, 8 the No branch, and 0 the boundary. Since 0 < 0 is false, 0 stays as it is; its absolute value is 0 anyway.

Another common example of a decision structure is the odd/even test. Whether a number is even is found by looking at the remainder of its division by 2. The remainder operation is written % in Java: 7 % 2 is 1 and 12 % 2 is 0. The decision box gets x % 2 == 0 ?; the Yes branch prints “even” and the No branch prints “odd.”

import java.util.Scanner;

public class EvenOdd {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int x = in.nextInt();
        if (x % 2 == 0) {                 // x % 2 == 0 ?
            System.out.println("even");
        } else {
            System.out.println("odd");
        }
    }
}
Common mistake

Testing for an odd number with the condition x % 2 == 1 ?. This condition works for positive numbers, but in Java the sign of the remainder follows the sign of the dividend: -3 % 2 is −1, not 1. So for −3, x % 2 == 1 comes out false and an odd number is printed as “even.” The question x % 2 == 0 ?, on the other hand, gives the right answer for −3 too: -3 % 2 == 0 is false, and “odd” is printed. When the remainder is compared with zero, the sign problem disappears.

The first number is taken as the largest for now. Then the other numbers are compared with this candidate one by one; if a larger one turns up, the candidate changes.

4.2.5.5The multi-way decision: a decision chain

A decision box has only two exits. When there are more than two options, the decisions are lined up like a chain: each decision is placed on the No branch of the previous one. This is called a multi-way decision.

Figure 4.2.12 sorts a temperature value into one of four classes. The rule by which the chain works is this: the decisions are asked in order from top to bottom; the branch of the first true condition runs, and the decisions after it are never asked. If no condition is true, the bottom No branch runs.

The t = 18 row of Table 4.2.6 reads step by step as follows. The first decision is the question 18 < 0; it is false and the No branch goes to the second decision. 18 < 15 is also false. Each decision in the chain checks only the upper bound. When the question t < 15 is asked, it is certain that t is 0 or greater; otherwise execution would never have reached this decision. So there is no need for a two-sided condition such as “0 ≤ t and t < 15.” This rule also shows which class the boundary values fall into: for t = 15, 15 < 15 is false, the decision moves on along the chain, and 15 is “Mild.” t = 0 is “Cold.”

The order of the decisions matters. If the decisions were lined up in reverse order, that is, if t < 25 ? were asked first, then for t = −5 −5 < 25 comes out true and “Mild” is printed; the “Freezing” branch is never reached. If the number of options is n, n − 1 decisions are needed; for four classes there are three decisions.

In Java, a decision chain is written in the form if … else if … else. Each else if is the No branch of the previous condition; the last else is the case where no condition held:

import java.util.Scanner;

            System.out.println("Cold");

        } else {

}

The program prints “Freezing” for −5, “Cold” for 0 and 10, “Mild” for 15 and 18, and “Hot” for 25 and 30. These seven inputs try the four exits of the chain and every boundary value.

4.2.5.6Compound conditions: AND and OR

Some decisions require two conditions to be evaluated together. A car-rental company requires the customer both to be at least 18 years old and to hold a driver's license. A calendar app prints “Weekend” if the day is Saturday or Sunday. Expressions like these, which combine two conditions, are called compound conditions.

Definition 4.2.11

A compound condition joined with AND is true if both conditions are true; if even one is false, it is false. A compound condition joined with OR is true if at least one of the conditions is true; if both are false, it is false. In Java, AND is written with the operator && and OR with ||.

A compound condition can be written in a single decision box: age >= 18 AND has license ?. If detail is needed in the diagram, it is expanded into two separate decisions. Figure 4.2.13 shows how the two connectives are drawn with two decisions.

In the OR structure, the second decision is on the No branch of the first. If the first decision is Yes, the result is already Yes and there is no need for the second. 4.2.5.7Leap year

The classic example showing the importance of order in a decision chain is the leap-year rule. In the Gregorian calendar the rule has three parts: years divisible by 4 are leap years; but those divisible by 100 are not; and those divisible by 400 are leap years again. In a leap year February has 29 days.

The rule has exceptions, and the exceptions have exceptions. When such a rule is turned into a diagram, the narrowest condition goes first. Divisibility by 400 is a special case of divisibility by 100, and divisibility by 100 is a special case of divisibility by 4. That is why the decisions are asked in the order 400, 100, 4.

Common mistake

Starting the chain with the wide condition. If year % 4 == 0 ? is asked first and “Leap” is printed directly on its Yes branch, 1900 and 2100 are also counted as leap years. Because the 100 and 400 rules concern only years divisible by 4, their turn never comes. The decisions in the chain must be arranged from the narrow condition to the wide one.

4.2.6Repetitive flow

What makes a computer powerful is that it can do the same job thousands of times without getting tired. Adding up the grades of 30 students in a class means doing the same two steps 30 times: read the grade, add it to the total. Instead of drawing these steps 30 times in the diagram, we draw them once and make them repeat with an arrow that goes back.

4.2.6.1The loop structure

Definition 4.2.13

Repetitive flow, or a loop, is flow in which a group of steps runs again and again as long as a condition is true. The repeated steps are called the loop body, and one run of the body is called an iteration. The arrow that returns from the end of the body to the condition forms the loop.

Figure 4.2.16 shows the diagram that prints the numbers from 1 to 5. The diagram has three parts. The i = 1 box gives the initial value of the counter. The decision box i <= 5 ? decides whether the loop continues. The two boxes on the Yes branch, “print i” and i = i + 1, are the loop body. The arrow leaving the end of the body turns left and enters the decision box again.

Start
  i = 1
  i <= 5 ?
    Yes → print i
            i = i + 1
            back to the decision
    No → End

In this diagram the condition is asked before the body. If the condition is false on the very first try, the body never runs. Such loops are called pre-test loops. When the condition is false, the No branch leaves the loop and goes to End.

For the loop to end some day, there must be an operation on the repeat path that changes the condition. Here this operation is i = i + 1. i grows on every iteration and eventually exceeds 5. If this box were forgotten, i would stay 1, 1 <= 5 would come out true every time, and the diagram would print 1 forever. A loop that never ends is called an infinite loop.

In Java, a pre-test loop is written with while. As long as the condition in parentheses is true, the inside of the braces runs again; the closing brace stands in for the returning arrow:

public class OneToFive {

        }                                 // returning arrow: back to the decision

The program prints 1 2 3 4 5. Unlike println, System.out.print adds no line break; the numbers are therefore printed on the same line with a space between them. The System.out.println() line after the loop only ends the line.

4.2.6.3Counter and accumulator

Most loops contain two kinds of variable. One counts which iteration the loop is on; the other holds the result that builds up from iteration to iteration.

Definition 4.2.14

A counter is a variable that tracks how many repetitions have been made; it increases by 1 on every iteration. An accumulator is a variable that holds the partial result; on every iteration a new value is added to it (or multiplied into it). The starting value of the accumulator is chosen according to the operation: 0 for a sum, 1 for a product.

The choice of starting value is not arbitrary. For addition we choose 0, because adding 0 to a number does not change it; after the first iteration, the sum is the first number itself. For a product, 1 plays the same role. If a product accumulator is mistakenly started at 0, it is multiplied by 0 on every iteration and the result is always 0. For example, the product of the numbers from 1 to 5 is 1 × 1 × 2 × 3 × 4 × 5 = 120; if the accumulator starts at 0, we get 0 × 1 × 2 × 3 × 4 × 5 = 0.

4.2.6.5Counter-controlled and sentinel loops

In the loops so far, the number of iterations was known in advance: 5 times, 3 times, n times. In some jobs this number is not known. A teacher entering grades, instead of counting the grades, types a special value at the end. Such a special value is called a sentinel value.

Definition 4.2.15

A counter-controlled loop is a loop whose number of repetitions is known in advance and controlled with a counter. A sentinel value is a special value that signals the end of the data and is chosen so that it cannot occur in the real data. A sentinel-controlled loop is a loop that runs until the sentinel value is read.

If the first input is the sentinel, the body never runs and the counter stays 0. In that case the average computation becomes a division by zero. That is why count > 0 ? is asked before the division. The Java counterpart includes this check as well:

import java.util.Scanner;

public class GradeAverage {
    public static void main(String[] args) {

        int sum = 0, count = 0;

In the Java code the first grade is read once before the loop, and the later grades are read at the end of the body. This is how the diagram's detail “the returning arrow goes to the read box” is written with while. 4.2.6.6Nested loops

The single-entry, single-exit rule of structured programming allows one structure to be placed inside another. A decision can contain another decision on one of its branches. A loop body can contain a second loop.

Definition 4.2.16

A nested loop is a loop that has another loop in its body. The outer one is called the outer loop and the inner one the inner loop. On every iteration of the outer loop, the inner loop runs from start to finish.

The multiplication table is the most familiar example of a nested loop. The outer loop moves through the rows (i), the inner loop through the columns (j); i × j is written in each cell. Figure 4.2.22 shows the 3 × 3 table. The outer loop runs 3 iterations, and the inner loop runs 3 iterations on each outer iteration. The inner body runs a total of 3 × 3 = 9 times.

To keep the diagram small, a 2 × 2 table is drawn. Figure 4.2.23 shows how the two loops fit together.

A large number of nested structures can be a sign that a part of the algorithm should be drawn as a separate subprocess. Three or four levels of nested decisions and loops make both the diagram and the code unreadable.

4.2.6.7The number-guessing game

The computer holds a secret number between 1 and 100. The player guesses; the computer gives a hint, “Higher” or “Lower.” The game ends when the guess is right, and the number of tries is printed. The player's guesses determine how many iterations the loop runs; in this respect the game is a kind of sentinel-controlled loop.

Start
  secret = 37, tries = 0
  read guess
  tries = tries + 1

The secret number is normally chosen at random; here 37 is used so that the trace can be repeated.

import java.util.Scanner;

public class NumberGuess {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int secret = 37;                  // in the game: new java.util.Random().nextInt(100) + 1
        int tries = 0;
        int guess = in.nextInt();

                System.out.println("Higher");
            } else {

            }

        }
        System.out.println("Got it (try " + tries + ")");

The Java program writes the diagram with a slightly different layout. The first guess is read before the loop, and the loop condition becomes guess != secret. The next guess is read at the end of the body. This is the same layout as in the sentinel-controlled loop. With the input 50 25 37 the program prints “Lower,” “Higher,” and “Got it (try 3)”; with 20 40 37 it prints “Higher,” “Lower,” and “Got it (try 3).” If 37 is entered on the first guess, the loop body never runs and “Got it (try 1)” is printed.

The game has a good strategy: guess the middle of the remaining range each time. In the range 1–100 the first guess is 50; if the hint is “Lower,” the range drops to 1–49, and if “Higher,” to 51–100. Each guess splits the range roughly in half. In the worst case the range shrinks as 100, 50, 25, 12, 6, 3, 1; so 7 guesses are always enough. The reason is that 27 = 128 is greater than 100.

4.2.6.8The post-test loop

In some jobs the loop body must run at least once. The user is asked for a number between 1 and 5; if the number entered is invalid, the question is asked again. Whether the number is valid cannot be asked before it is read. In this case it is more natural to put the condition at the end of the body.

Definition 4.2.17

A post-test loop is a loop in which the condition is asked after the body. The body runs first and then the condition is examined; so the body runs at least once. In Java it is written in the form do { … } while (condition);.

Start
  read num
  1 <= num <= 5 ?
    No → print "Invalid", back to read
    Yes → print num
End

In the diagram of Figure 4.2.25, after Start execution goes directly into the read box; there is no decision in between. The decision comes after the reading. On an invalid number the No branch prints “Invalid” and the arrow returns to the read box. This kind of use is called input validation.

In the first iteration 7 is read before the condition has been asked even once. Then comes the decision: is 1 ≤ 7 ≤ 5? Since 7 is greater than 5, the answer is false; “Invalid” is printed. In the second iteration 0 is read; since 0 is less than 1, it is invalid again. In the third iteration 3 is read; 1 ≤ 3 ≤ 5 is true and “Valid: 3” is printed. The body ran 3 times and the condition was also asked 3 times. Unlike a pre-test loop, here the number of decisions equals the number of body runs.

The condition 1 <= num <= 5 in the diagram is mathematical notation. Java does not accept this form; the two comparisons are joined with a compound condition. The invalidity condition becomes “num is less than 1 OR greater than 5”:

import java.util.Scanner;

public class InputValidation {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int num;
        do {
            num = in.nextInt();                   // body: read first
            if (num < 1 || num > 5) {
                System.out.println("Invalid");
            }
        } while (num < 1 || num > 5);           // the condition is asked at the end
        System.out.println("Valid: " + num);
    }
}

With the input 7 0 3 the program prints “Invalid” twice and then “Valid: 3.” If the first input is 4, the body runs once and “Valid: 4” is printed directly. In the code the invalidity condition is written twice: once inside the if for the warning, once in the loop condition. The single decision box in the diagram becomes two separate questions in the code.

Common mistake

Thinking the difference between while and do-while is only a difference of notation. The difference shows up when the condition is false at the first try. If the sum-from-1-to-n diagram were drawn as a post-test loop, then for n = 0 the body would run once and the sum would be 1; yet the right answer is 0. Whenever the body may need to never run, a pre-test loop is chosen.

4.2.6.9The flowchart of a for loop

Counter-controlled loops always contain the same four parts: the counter's starting value, the condition, the body, and the update of the counter. Java offers a shorter notation for this pattern: the for loop.

for (i = 1; i <= n; i++) {
    sum = sum + i;
}
  1. Initialization (i = 1): runs only once, when entering the loop.
  2. Condition (i <= n): asked before every iteration; a for loop is a pre-test loop.
  3. Body: runs if the condition is true.
  4. Update (i++): runs after the body; then the arrow returns to the condition. i++ is a short way of writing i = i + 1.

Figure 4.2.26 is no different from a while diagram. A for loop merely gathers parts 1, 2, and 4 on one line. Some sources show these three parts in the preparation symbol among the additional symbols (a hexagon, “i = 1 → n”).

public class ForSum {
    public static void main(String[] args) {
        int n = 4, sum = 0;
        for (int i = 1; i <= n; i++) {    // initialization; condition; update
            sum = sum + i;                // body
        }
        System.out.println(sum);
    }
}

The program prints 10 for n = 4; it gives the same result as the sum-from-1-to-n program written with while. Which loop to choose is a matter of readability. When the number of repetitions is known in advance, for reads more clearly; when the data stops the loop, while does.

4.2.6.10Early exit, flag, and jump

Suppose we are looking for the first negative number in an array: a = [4, 7, −2, 5, −8]. Once the number sought is found, the remaining iterations are unnecessary. A second arrow going out of the loop from inside the body ends the loop at once.

Definition 4.2.18

An early exit is leaving a loop from inside the body before the loop's condition has become false; in Java it is done with the break statement. A flag is a true/false variable that records whether an event has happened. Continue, on the other hand, does not leave the loop; it skips the rest of that iteration and returns to the update and the condition.

In the diagram the elements of the array are written a[i]: a[1] is the first element of the array and a[2] the second. An array is an ordered list of values of the same type; here there are five numbers, so n = 5.

Table 4.2.18: Search for the first negative number for a = [4, 7, −2, 5, −8].

At i = 1, 4 and at i = 2, 7 are not negative. At i = 3, −2 is found and printed; the loop ends by early exit. 5 and −8 are never looked at. If there were no negative number in the array, the loop would exit through the condition at i = 6 and “None” would be printed.

A loop with an early exit has two exits, and this does not obey the single-exit rule of structured programming. If a single exit is wanted, a flag is used. We start with found = false, set found = true when the target is found, and the loop condition becomes i <= n AND not found ?. When the loop ends, the flag is checked to print the result. In Java both ways are used:

public class FirstNegative {
    public static void main(String[] args) {
        int[] a = {4, 7, -2, 5, -8};
        // way 1: early exit with break (a loop with two exits)
        int i = 0;
        while (i < a.length) {
            if (a[i] < 0) {
                break;                    // target found: leave the loop
            }
            i = i + 1;
        }
        if (i < a.length) {
            System.out.println(a[i]);
        } else {
            System.out.println("None");
        }
        // way 2: a single-exit loop with a flag
        boolean found = false;
        int k = 0;
        while (k < a.length && !found) {
            if (a[k] < 0) {
                found = true;
            } else {
                k = k + 1;
            }
        }
        System.out.println(found ? a[k] + "" : "None");
    }
}

Both ways print −2. In Java, array elements are numbered from 0: a[0] is 4 and a[2] is −2. That is why in the code the counter starts at 0 and the condition is i < a.length; a.length is the number of elements in the array (5). In the flag version, the expression !found means “not found.” The condition k < a.length && !found is a compound condition and works with short-circuit evaluation.

Continue, on the other hand, does not end the loop; it only skips the rest of that iteration. For example, if the sum of the non-negative numbers in the array is wanted, the adding step is skipped when a negative number is reached:

public class ContinueExample {
    public static void main(String[] args) {
        int[] a = {4, 7, -2, 5, -8};
        int sum = 0;
        for (int i = 0; i < a.length; i++) {
            if (a[i] < 0) {
                continue;                 // skip the negative, go to the next iteration
            }
            sum = sum + a[i];
        }
        System.out.println(sum);
    }
}

The program prints 4 + 7 + 5 = 16. At −2 and −8, continue runs; the adding line is skipped, i++ runs, and we return to the condition. In a diagram, continue is shown with an arrow from the middle of the body to the update box.

4.2.7.2Sum from 1 to n in Java

public static void main(String[] args) {
    int n = 3;
    int sum = 0, i = 1;
    while (i <= n) {
        sum = sum + i;
        i = i + 1;
    }
    System.out.println(sum);
}

The translation is done box by box from top to bottom:

  1. The Start symbol is the beginning of the method: main opens.
  2. “read n” is an input symbol. To keep the example short, the input is taken as a constant: int n = 3;. If reading from the keyboard is wanted, this line becomes int n = in.nextInt();.
  3. The process symbol “sum = 0, i = 1” gives the starting values of two variables: int sum = 0, i = 1;.
  4. From the decision i <= n ?, the Yes branch goes to two boxes and an arrow returns to the decision. This is a loop: while (i <= n).
  5. The two rectangles on the Yes branch are the loop body. Both are written inside the braces, in the order shown in the diagram.
  6. The returning arrow is the closing brace of the body block. Execution returns from there to the condition.
  7. The output symbol “print sum” on the No branch is outside the loop: System.out.println(sum);.
  8. The End symbol is the end of the method.

When the program is run for n = 3, execution follows the same path as the diagram, step by step. The first try of the condition, 1 <= 3, is true; sum = 0 + 1 = 1 and i = 2. Then sum becomes 3 and 6. When i = 4, 4 <= 3 is false; the No path is followed and execution leaves the loop block. 6 is printed on the screen. The result is also verified by the formula: 3 × 4 / 2 = 6.

At the end of the translation, every symbol has a code counterpart and every line of code has a symbol counterpart. This one-to-one correspondence is the easiest way to check that the diagram has been translated correctly. If there is a symbol with no counterpart in the program, or a line with no counterpart in the diagram, something is missing or extra in the translation.

Common mistake

Writing one of the body boxes outside the loop block. If while (i <= n) { sum = sum + i; } i = i + 1; is written, the counter's increment is left outside the loop. i never changes, the condition always comes out true, and the program enters an infinite loop. In the diagram, every box on the Yes branch, up to the last box before the returning arrow leaves, is inside the braces.

4.2.7.3Modular diagrams with a subprocess

As diagrams grow, they no longer fit on a single page. It also happens that a job is repeated in several places. In that case part of the work is drawn as a separate diagram and called from the main diagram.

Definition 4.2.19

A subprocess is a separately drawn diagram referred to by a name. In the main diagram it is called with the predefined process symbol. When the subprocess ends, the flow continues in the main diagram from the point where it was called. In Java every subprocess becomes a method.

The sub-diagram in Figure 4.2.30 begins not with Start but with its name and parameters, “Average(x, y, z).” It ends not with End but with “Return.” Parameters are the values the subprocess receives from the place it is called. In the box avg = Average(a, b, c) the main diagram sends the values of a, b, and c to x, y, and z. For a = 70, b = 85, c = 91, the subprocess computes t = 70 + 85 + 91 = 246 and returns 246 / 3 = 82. The main diagram writes this value into the variable avg and continues from the next box.

A subprocess has two benefits. First, the same subprocess can be called from many places but is drawn only once. If an error is found in the average computation, it is fixed in a single place. Second, the main diagram becomes shorter and says “what is done”; “how it is done” stays in the sub-diagram.

import java.util.Scanner;

public class Subprocess {
    // subprocess: Average(x, y, z)
    static int average(int x, int y, int z) {
        int t = x + y + z;
        return t / 3;                     // Return t / 3
    }

    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int a = in.nextInt(), b = in.nextInt(), c = in.nextInt();
        int avg = average(a, b, c);       // predefined process symbol
        System.out.println(avg);
    }
}

The line static int average(int x, int y, int z) is the heading of the sub-diagram: the method's name, its three parameters, and the type of the value it returns (int). The line return t / 3; is the counterpart of the Return symbol. With the input 70 85 91 the program prints 82.

Common mistake

Forgetting integer division. In Java the quotient of two integers is also an integer; the fractional part is discarded. For 70, 85, 91 the sum 246 divides exactly by 3, so there is no visible problem. For 50, 60, 71 the sum is 181; the true average is about 60.33, but the program prints 60. If a fractional result is needed, the method must return double and the division must be written t / 3.0.

4.2.8Verification

That a diagram is correct is tested by executing it by hand on a few inputs. Which inputs to choose is not arbitrary. A small number of well-chosen inputs catch more errors than a large number of badly chosen ones.

4.2.8.1Testing a flowchart

Definition 4.2.20

A test case is a pair of an input and the output expected for it. The diagram is executed with the input and the output found is compared with the expected one. A boundary value is an input at the point where the answer to a condition changes; for example, 60 for grade >= 60.

Test inputs are chosen by five rules:

  1. A normal input is chosen and the arrows are followed step by step.
  2. Inputs are chosen that run every exit of every decision. Every box in the diagram must run at least once.
  3. Boundary values are tried separately.
  4. For each loop, cases are tried in which the body runs zero, one, and many times.
  5. Paths that do not return to the beginning or do not reach End are looked for.

Figure 4.2.31 shows the rules applied to the Pass/Fail diagram. 72 is a normal input and runs the Yes path. 45 runs the other branch; with the two inputs every box has been tried. 60 is the boundary value and would be the only input to expose the error had > been written instead of >= in the decision box.

The reason for rule 4 on loops is this: loop errors often hide at the ends. If the accumulator's starting value is wrong, this shows most clearly in the case where the body never runs. A </<= mix-up in the condition usually causes one iteration too few or too many and is easy to notice in a one-iteration case. Table 4.2.20 gives these three cases for the sum-from-1-to-n diagram.

4.2.8.2Hand tracing with a trace table

The trace table has been used often in this chapter. The pattern can be summed up briefly: each variable is a column and each iteration is a row; the result of the decision is also written in a separate column. A table is indispensable especially in algorithms where variables change in a mutually dependent way. Euclid's algorithm is a nice example.

Euclid's algorithm finds the greatest common divisor (GCD) of two numbers. The idea is this: the common divisors of a and b are the same as the common divisors of b and the remainder of a divided by b. So the pair (a, b) is replaced by the pair (b, a % b). The remainder shrinks on every iteration and finally becomes 0. At that moment a is the GCD we are looking for.

Table 4.2.21: Trace table of Euclid's algorithm for (48, 18). The last column is the next decision asked with the values in that row.

Initially a = 48, b = 18 and 18 != 0 is true. In the first iteration k = 48 % 18 = 12 (48 = 2 × 18 + 12); a = 18, b = 12. In the second iteration k = 18 % 12 = 6; a = 12, b = 6. In the third iteration k = 12 % 6 = 0; a = 6, b = 0. The decision 0 != 0 is false; the loop is exited and 6 is printed. GCD(48, 18) = 6. Check: 48 = 8 × 6, 18 = 3 × 6, and 8 and 3 have no common divisor greater than 1.

The loop ran 3 iterations and the decision was asked 4 times: as in every pre-test loop, the decision ran one more time than the body. The table also shows the importance of order in the diagram. What would happen if the boxes a = b and b = k in the body were swapped, that is, if b = k were done first and then a = b?

In the first iteration b becomes 12, and then with a = b, a also becomes 12. a has taken b's new value, not its old one. In the second iteration 12 % 12 = 0 is found and both become 0. The result comes out 0 instead of 6. This is the same error as the swap error in Example 4.2.2: an assignment has erased a value that was needed later.

import java.util.Scanner;

public class Euclid {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int a = in.nextInt(), b = in.nextInt();
        while (b != 0) {
            int k = a % b;
            a = b;
            b = k;
        }
        System.out.println(a);
    }
}

The program prints 6 for (48, 18), 6 for (270, 192), and 12 for (36, 84). The algorithm works even when a < b. For (18, 48), in the first iteration 18 % 48 = 18 is found and a and b are swapped; the result is again 6.

4.2.9Summary

  • A flowchart shows the steps of an algorithm with standard symbols and the order of execution with arrows. It is independent of the programming language; it lets us discuss the logic before the code and see errors early.
  • There are five basic symbols: start/end (oval), process (rectangle: computation, assignment), decision (diamond: a Yes/No question), input/output (parallelogram: read, print), and the arrow. Paths merge at a connector. Additional symbols (off-page connector, predefined process, preparation, document, data store, annotation) are used in large diagrams.
  • A decision symbol gets a question, a process symbol a command. Assignment (=) and the equality question (==) are different.
  • A good diagram flows from top to bottom, labels the decision exits, and does one job per box. The same algorithm can also be described in pseudocode; the two notations translate into each other line by line.
  • According to the Böhm–Jacopini theorem, every algorithm can be written with only the structures of sequence, selection, and repetition. Each structure has a single entry and a single exit; that is why structures can be nested.
  • In sequential flow, every box runs exactly once and in order. The order of the boxes changes the result; a swap needs a temporary variable.
  • In conditional flow, only one of the branches is followed on each run. With many options, decisions are arranged as a decision chain, from the narrow condition to the wide one; n options need n − 1 decisions. In a compound condition, AND and OR, written && and || in Java, are evaluated with short-circuit evaluation.
  • In repetitive flow, the returning arrow forms the loop. In a pre-test loop the decision runs one more time than the body; if there is no operation on the repeat path that changes the condition, an infinite loop results.
  • The counter holds the number of iterations and the accumulator the partial result; the accumulator starts at 0 for a sum and 1 for a product, before the loop. A sentinel value is a value that cannot occur in the real data; its decision is asked before the boxes that process the data.
  • In a nested loop, the inner loop runs from the start on every iteration of the outer loop; the inner body runs n × m times. In a post-test loop (do-while), the body runs at least once. for is a pre-test loop that gathers initialization, condition, and update on one line.
  • An early exit (break) adds a second exit to a loop; if a single exit is wanted, a flag is used. Continue (continue) only skips the rest of that iteration.
  • A diagram is translated into Java symbol by symbol: read → nextInt(), process → assignment, decision → if, decision + returning arrow → while, print → println, subprocess → method.
  • A diagram is tested with inputs that run every exit of every decision, with boundary values, and with cases where the loop runs zero, one, and many times. In a trace table, each variable is a column and each iteration a row.

4.2.11Test Yourself

  1. Which symbol is each of the following steps drawn with? (a) avg = sum / 3 (b) Is the number negative? (c) Print the result on the screen. (d) Use the “Compute grade average” process drawn on a separate page.

    Answer

    (a) is an assignment: process symbol, rectangle. (b) is a question whose answer is yes or no: decision symbol, diamond; x < 0 ? is written inside. (c) gives data to the outside: input/output symbol, parallelogram. (d) calls a separately drawn subprocess: predefined process symbol, a rectangle with vertical lines on its sides.

  2. A sequential diagram reads a = 5, then runs the boxes b = a * 2, a = b + a, c = a + b in order and prints a, b, and c. What are the variables after each box, and what is the output?

    Answer

    b = a * 2: b = 5 × 2 = 10; a = 5. a = b + a: a = 10 + 5 = 15; a's old value 5 is now gone. c = a + b: c = 15 + 10 = 25. The output is 15 10 25. When c is computed, the new value of a (15) is used.

  3. The decisions in the temperature chain are arranged in reverse order: first t < 25 ? (Yes → “Mild”), then t < 15 ? (Yes → “Cold”), then t < 0 ? (Yes → “Freezing”, No → “Hot”). What is printed for t = −5, 10, 20, and 30? Which exits can never run?

    Answer

    For −5, 10, and 20 the first decision is true and all three print “Mild.” For 30 the first decision is false. Execution reaches the second decision; 30 < 15 and 30 < 0 are false and “Hot” is printed. The “Cold” and “Freezing” branches cannot be reached with any input: the second decision is reached only when t ≥ 25, and such a t is less than neither 15 nor 0. The right order is from the narrow condition to the wide one, that is, t < 0, t < 15, t < 25.

  4. In a loop started with i = 10, the decision is i > 0 ?; on the Yes branch i is printed and i = i − 3 is done. What is the output? How many times do the body and the decision run, and what is i when the loop ends?

    Answer

    The condition is true while i is 10, 7, 4, 1, in turn; these values are printed: 10 7 4 1. After 1 is printed, i = 1 − 3 = −2 and −2 > 0 is false. The body runs 4 times and the decision 5 times; the loop is exited with i = −2.

  5. In a diagram that finds the product of the numbers from 1 to 5, the accumulator was started with product = 0; the body is product = product * i. What does the diagram print? What does the corrected diagram print?

    Answer

    In the first iteration 0 × 1 = 0, and since every later iteration multiplies by 0, the result is 0. The neutral value for a product is 1; starting with product = 1, the iterations give 1, 2, 6, 24, 120 and 120 is printed.

  6. The inputs 70, 85, 0, −1 are entered, in order, into the sentinel-controlled grade-average diagram. What do the sum, counter, and average become? What would have happened if 0 had been chosen as the sentinel instead of −1?

    Answer

    70, 85, and 0 are real grades: the sum is 70 + 85 + 0 = 155 and the counter is 3. When −1 is read the loop ends. The average is 155 / 3 ≈ 51.67. Had the sentinel been 0, the third input would have been interpreted as “data finished”: the sum would be 155, the counter 2, and the average 77.5. Because 0 can be a real grade, it is not suitable as a sentinel.

  7. In a nested loop the outer counter i runs from 1 to 3 and the inner counter j from i to 3. The inner body prints one “*”; at the end of each outer iteration a line break is printed. What is the output, and how many stars are printed in all?

    Answer

    With i = 1, j = 1, 2, 3: three stars. With i = 2, j = 2, 3: two stars. With i = 3, j = 3: one star. The output is the lines ***, **, *, one under another. In total 3 + 2 + 1 = 6 stars are printed. Because the start of the inner loop depends on the outer counter, the inner body runs 6 times, not 3 × 3 = 9.

  8. The body of a loop that starts with count = 10 prints the counter and increases it by 1; the condition is count < 5. What is printed when the loop is drawn as a pre-test (while) and as a post-test (do-while) loop?

    Answer

    In the pre-test loop the condition is asked before the body: 10 < 5 is false and the body never runs; nothing is printed. In the post-test loop the body runs first: 10 is printed and count becomes 11. Then 11 < 5 is asked, it is false, and the loop ends. The output is just 10. The two loops behave differently when the condition is false at the first try.

  9. Euclid's algorithm is executed for (84, 36). What are a, b, and k on each iteration? How many iterations does the loop run, how many times is the decision asked, and what is printed?

    Answer

    Initially: a = 84, b = 36; 36 != 0 is true. Iteration 1: k = 84 % 36 = 12 (84 = 2 × 36 + 12); a = 36, b = 12. Iteration 2: k = 36 % 12 = 0; a = 12, b = 0. 0 != 0 is false; the loop ends. 2 iterations, 3 decisions; 12 is printed. Check: 84 = 7 × 12, 36 = 3 × 12, and 7 and 3 have no common divisor greater than 1.
