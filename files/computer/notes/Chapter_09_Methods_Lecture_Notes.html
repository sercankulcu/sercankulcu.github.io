Chapter 9: Methods

As a program grows, the same jobs start to be written again and again in different places, and the main method becomes too long to read. A method gathers a task under a name. The task is written once and then called by name wherever it is needed. These notes first show how a method is defined and called. Next comes what happens in memory during a call: arguments being copied into parameters, the frame opened for each call, and the call stack these frames form. Return values, void methods and early return are treated separately. Why Java always passes arguments by value is shown step by step with the swap example. The real error messages given by the compiler for overloading, variable-length arguments, scope and shadowing are also examined. The last sections cover good method design and example methods such as even/odd, digit count, primality, GCD and LCM. All the programs in the notes were compiled and run with JDK 21.

9.1What is a method?

In the Java programs written so far, all the work was done in one place, inside the main method. In short programs this is enough. But when a program reaches a few hundred lines, the same computation gets rewritten in three or four places. When a bug is fixed, the other copies are forgotten. What main does, and in what order, also becomes unreadable. Methods are the solution to this problem.

9.1.1Naming a task

In mathematics, a function produces an output for its input: for f(x) = x², f(3) = 9. A function in programming is a similar unit. A piece of code that does a particular task is given a name. This code takes its inputs from outside, does its job and, if necessary, gives a result. Since everything in Java is written inside a class, functions are defined inside a class too, and they are called methods.

Definition 9.1

A method is a named group of statements defined inside a class that does a particular task. A method receives its inputs through its parameters and gives its result as its return value. A method is run by writing its name followed by values in parentheses; this is called a method call.

The methods in Java's own library illustrate this idea well. The call Math.sqrt(16) gives the square root of 16, that is, 4.0. You do not need to know how the square root is computed. Three things need to be known: the name of the method (sqrt), what it asks for (a number) and what it gives (the square root). The internal details are hidden from the user of the method. Figure 9.1 shows this as a black box.

The box in the figure has two inputs on its left and one output on its right. What is inside the box can be seen only by looking at the body of the method. The code that calls the method thinks only “give it these two numbers and get the sum back”. This separation is the most important gain of methods: what a task does is separated from how it does it.

9.1.2Why write methods?

Suppose a student is writing a program that prints the grades of three courses on the screen. The student wants to draw a line before and after each course. Without methods, the loop that draws the line is copied six times. If the length of the line were to change, all six places would have to be corrected; if one is forgotten, the output is inconsistent. If this loop is put into a method named drawLine, a one-line call remains in each of the six places: drawLine(5);. If the length changes, only the argument changes.

The gains of writing methods can be listed as follows:

  • Avoiding repetition. The same code is written once. When a bug is found, it is fixed in one place and the fix applies to every call.
  • Readability. A well-named method call says what is being done. The line if (isPrime(n)) is much easier to read than a loop looking for divisors.
  • Testability. A small method can be tried with a few sample inputs independently of the rest of the program. That digitCount(-507) gives 3 can be checked in a single line.
  • Reuse. A method written once is used in other programs and inside other methods. A method that computes the LCM shortens its work by calling the GCD method.
  • Division of labor. A big problem is split into small subtasks. Each subtask becomes a separate method and is written and tried separately.

9.1.3What happens in a call?

When a method is called, the flow of the program temporarily leaves the place that made the call, goes into the body of the method, and returns to where it left off when the method ends. Figure 9.2 shows this round trip.

This journey consists of the same five steps in every call:

  1. The arguments are evaluated. The values of the expressions inside the parentheses of the call are found. In add(x, 3), the current value of x (5) is read.
  2. The values are copied into the parameters. A new area of memory is opened for the method. The first value is written into the first parameter and the second value into the second parameter: a = 5, b = 3.
  3. The body runs. The statements between the curly braces of the method run in order.
  4. A value is returned. When the return statement is reached, the method ends and the value next to return is sent to the place that called it.
  5. The calling code continues. The returned value takes the place of the call expression. The program continues from the line where the call is.

One point in these steps must not be overlooked: each call works with its own parameters and its own local variables. If the same method is called twice, two separate areas of memory are opened. The second call does not see the variables of the first; when the first call ends, its variables have already been deleted. Pass by value, scope and the call stack all rest on this rule.

9.2Method definition and call

To use a method, you must first define it, that is, write its name, its inputs, the type of its result and its body. A defined method is then called wherever you like and as many times as you like. The definition is made once, the call many times.

9.2.1The first method: add

The add method, which gives the sum of two integers, and the two lines that use it, look like this:

static int add(int a, int b) {
    int sum = a + b;
    return sum;
}

int total = add(5, 3);
System.out.println(total);

The first four lines are the definition. The line static int add(int a, int b) is the header of the method. int says that the method will return an integer. add is the name of the method. The int a, int b inside the parentheses declare that the method expects two integers and that they will be reached inside the method under the names a and b. The two lines between the curly braces are the body of the method: first a + b is written into a variable named sum, and then this value is given back with return. The last two lines are the call: add(5, 3) runs the method with 5 and 3, and the returned value is assigned to total and printed.

These fragments do not compile on their own; they must be inside a class. The complete program is below. The method is written inside the same class as main, outside main. Methods cannot be defined inside one another: writing add inside the curly braces of main is a compile error.

public class Add {
    static int add(int a, int b) {
        int sum = a + b;
        return sum;
    }

    public static void main(String[] args) {
        int total = add(5, 3);
        System.out.println(total);
    }
}
8

The program always starts running from main. Even if add is written before main in the class, it does not run on its own; it runs only when it is called. The order of methods within the class does not matter. add could just as well have been written below main.

The a and b in the definition and the 5 and 3 in the call play different roles and have different names.

Definition 9.2

A parameter, or more fully a formal parameter, is a variable declared with its type in the method header; it says which inputs the method expects. An argument, or actual argument, is a value written inside the parentheses at the time of the call and copied into the parameter.

A parameter is a variable; an argument is a value, or an expression whose value is to be computed. Parameters come to life anew each time the method is called and are filled with the arguments of that call. Arguments are matched to parameters in order: the first argument to the first parameter, the second argument to the second. The number of arguments must equal the number of parameters, and the type of each argument must fit the corresponding parameter. The calls add(5) and add(5, 3, 1) do not compile, because add expects exactly two integers.

Common mistake

Rewriting the type of the argument in the call: add(int 5, int 3). Types are written only in the definition, next to the parameters. In a call there are only values or expressions: add(5, 3). Conversely, forgetting the parameter type in the definition is also an error: static int add(a, b) does not compile. Each parameter's own type is written separately; the form int a, b is not valid in a parameter list.

9.2.2Using the result of a call

The call of a method that returns a value is an expression in Java. After the call runs, the returned value takes its place. So a call can be used anywhere a value can be used: on the right of an assignment, inside an arithmetic operation, in a condition, or as an argument to another method. The following program shows four different uses together:

public class UseAdd {
    static int add(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        int x = 5;
        int t = add(x, 3);                     // a variable and a constant as arguments
        System.out.println(t);
        System.out.println(add(10, 20) * 2);   // the call is part of an expression
        System.out.println(add(add(1, 2), 4)); // the result of a call is an argument to another call
        add(7, 8);                             // the returned value is not used
    }
}
8
60
7

The first call takes a variable and a constant as arguments. Since the value of x is 5, add(5, 3) = 8 is computed. In the second call, add(10, 20) first returns 30, then this value is multiplied by 2 and 60 is printed. In the third line the result of one call becomes an argument to another call. Java first runs the inner add(1, 2) and gets 3; then the outer call runs as add(3, 4) and 7 is printed.

The add(7, 8); in the last line is also a valid statement. The method returns 15, but since this value is not used anywhere, it is discarded. Java does not require the returned value to be used. However, this line adds nothing to the program: add only computes; it does not print anything and does not change any variable. If a method that returns a value is called and its result is thrown away, this is usually a sign of forgetfulness.

If there are several calls in one expression, Java evaluates the arguments and operands from left to right. The small method below prints its argument in square brackets, so that you can tell it has been called, and returns twice its argument:

public class OrderDemo {
    static int twice(int x) {
        System.out.print("[" + x + "] ");
        return 2 * x;
    }

    public static void main(String[] args) {
        int r = twice(3) - twice(1);
        System.out.println(r);
        System.out.println(twice(twice(1)));
    }
}
[3] [1] 4
[1] [2] 4

In the expression twice(3) - twice(1), the call on the left runs first and prints [3], then the one on the right runs and prints [1]. The subtraction is done when both values are ready: 6 − 2 = 4. In the nested call on the last line, the inner twice(1) must run first, because it provides the argument of the outer call. [1] is printed first, then [2], and 4 is printed. Printing to the screen and returning a value are independent of each other. Whatever the method prints, only its return value takes part in the expression.

When execution meets a call, it suspends the line it is on, finishes the method and comes back to the same line.

9.3The call stack

In the add example there were only two methods: main and add. In real programs a method calls another method, and that one calls yet another. At one moment several methods are left “half done”, waiting. Java keeps track of which method is where, and which variables belong to whom, with a stack structure.

9.3.1Stack and frame

Think of plates stacked on top of one another in a cafeteria. A new plate is always put on top, and a plate is always taken from the top. The last plate put on is the first one taken. This arrangement is called last in, first out, and a structure that behaves this way is called a stack. Method calls open and close in exactly this order.

Definition 9.3

A stack frame is the area of memory set aside for a method call. The frame holds the parameters and local variables of that call and the information about where execution should return when the method ends. The call stack is the stack made up of the frames of all the calls currently in progress. Each call puts a new frame on top of the stack; when the method ends, the top frame is removed.

When the program starts, there is a single frame on the stack: the frame of main. When main calls a method, the frame of that method is put on top of main's. If that method calls another, the stack rises one level further. Two rules follow from this arrangement. First, only the method of the topmost frame runs; the ones below wait for the call above them to finish. Second, the method called last finishes first. A method cannot finish before the method it called finishes.

Common mistake

Taking the same names in different methods to be the same variable. The x of avg and an x in main, or the a of add and the a of another method, are completely independent of one another. Each is a separate box of memory in its own frame. A value passes from one method to another in only two ways: as an argument in a call, or as a return value with return.

9.3.3Rules of the stack

The call stack is not specific to Java; method or function calls in C, Python and almost every programming language work in the same way. If the following rules are kept in mind while tracing, the answer to most questions follows on its own:

  • Every call opens a new frame. If the same method is called twice, two separate frames are opened, and the second call does not see the variables of the first.
  • Only the topmost frame runs. Every frame below it is in the middle of a call, waiting for the result of that call.
  • When a method ends, its frame is deleted with all its contents. Local variables and parameters do not carry values from one call to another.
  • The returned value takes the place of the call in the expression where the call was made, and the computation continues from there.
  • The last frame opened is the first to close. Frames close in the reverse of the order in which they were opened.

The stack also has a limit. Java sets aside a stack of limited size for each thread. If methods that call one another without end fill the stack, the program stops with a StackOverflowError. In ordinary programs the stack depth does not go beyond a few or a few dozen frames. The Method Call Stack simulator animates the opening and closing of frames step by step.

9.4The parts of a method definition

A method definition consists of two parts: the header and the body. The header is the face of the method that is visible to the outside world. It says who may call it, what it will return, its name and which inputs it expects. The body contains the statements that do the work of the method.

In the examples in these notes, methods are written in the same class as main and as static. The access modifier is mostly left out, because the methods are called only from the same class anyway.

Definition 9.4

The method signature is the name of a method together with the list of its parameter types, written in order. The signature of the method static int add(int a, int b) is add(int, int). The return type, the parameter names and the modifiers are not part of the signature. A class cannot contain two methods with the same signature.

The signature is the information the compiler looks at when deciding which method to bind a call to. When the compiler sees the call add(5, 3), it looks for a method named add that accepts two ints. It is natural that the parameter names (a, b) are not in the signature, because these names never appear in a call. The return type is not in the signature either, because the call itself carries no hint about the type of the returned value.

9.4.2Method names

Method names follow the same rules as variable names: they start with a letter, may contain letters, digits and underscores, and cannot be one of Java's reserved words. By Java convention, method names start with a lowercase letter, and when several words are joined, the first letter of each later word is capitalized: digitCount, printPositive, max3. Letters outside the basic English alphabet are valid in Java, but they are often avoided so that files open without trouble on different computers.

A good method name says what the method does. Methods that perform an action are named with a verb: drawLine, writeReport, readGrades. Methods that compute a value take the name of that value: average, area, gcd. Methods that return boolean read like a question: isEven, isPrime. When a method named this way is used in a condition, the line reads almost like plain English: if (isPrime(n)), “is n prime?”.

9.4.3The main method and static

The main found in every Java program is also a method, and every word in its header has a reason.

The meaning of the static modifier is as follows. Java is an object-oriented language; most methods belong to an object and are called through that object. A static method, on the other hand, belongs not to an object but to the class itself. No object has to be created first in order to call it. When the JVM starts the program, there are no objects yet. For it to be able to run main, this method must not need an object; that is, it must be static.

9.5The return value

When a method finishes its work, it can give the caller a result, or it can simply do a job without giving anything back. Which of the two it does is determined by the return type in the header. The result is given with the return statement.

9.5.1The return statement

Definition 9.5

The return type is the type of the value the method gives; it is written in front of the name in the header. The return value is the value the method sends to the caller with a return statement. The statement return expression; computes the value of the expression, ends the method at once and returns this value to the place where the call was made.

return does two jobs at once: it sends a value and it ends the method. Statements written after return on the same path do not run. The compiler rejects a statement that comes immediately after return and can never be reached, reporting an “unreachable statement” error.

The type of the returned value must match the return type. A method that returns int can write return 8; but cannot write return "eight";. If the return type is double, return 8; is valid; the int value is widened to double automatically and 8.0 goes to the caller. The reverse is not valid: a method that returns int cannot write return 2.5;, because the fractional part would be lost.

9.5.2void methods

Not every method has to compute a value. A method that draws a line on the screen, writes a report or adds a record to a file has no result to send to the caller. The return type of these methods is void. void means “empty”: the method does not return a value to the call.

9.5.3Early return

For some inputs the method has nothing to do. This case is caught at the start of the method and the method is left at once. This way the real work is written in a flat sequence, not buried inside nested if blocks.

9.6Passing parameters

In a call the value of the argument passes to the parameter. But if the method changes its parameter, does the caller's variable change too? The answer to this question is definite in Java, and it surprises many new programmers.

9.6.1Pass by value

Definition 9.7

Pass by value means that in a call the value of the argument is copied and written into the parameter. The parameter is a separate box of memory from the argument. Whatever the method does to its parameter, the caller's variable is not affected. Java always passes arguments by value.

For primitive types such as int, double, boolean and char, what is passed is the number or the character itself. The caller's variable and the method's parameter are two separate boxes; at the moment of the call, a copy of what is in the first is written into the second. After the copying, the two boxes are independent of each other.

For objects, for example arrays, the situation looks different at first sight. An array variable does not contain the array itself but a reference that shows where the array is in memory. When an array is sent to a method, it is this reference that is copied. Because the copied reference points to the same array, the method can change the elements of the array. But this is also pass by value: the value copied is a reference. If the method assigns a new array to its parameter, the caller's variable still points to the old array.

Thinking that because the parameter and the argument have the same name, the method will change the caller's variable. If a method wants to change a variable of the caller, it returns the new value, and the caller assigns this value to its own variable. The corrected version is:

public class IncReturn {
    static int inc(int x) {
        return x + 1;

    public static void main(String[] args) {
        int num = 5;
        num = inc(num);
        System.out.println(num);   // 6
    }
}

This form shows clearly what is happening: the reader can tell from the assignment that num changes on this line. That a method cannot secretly change the caller's variables may look like a restriction, but it is a guarantee that makes programs understandable. That a call such as calc(x) will not spoil x is known without looking at the body of the method.

9.7Overloading

The area of a square is computed with a single side, the area of a rectangle with two. The two jobs could be given separate names such as squareArea and rectangleArea. But both really compute “area”. Java allows methods that do the same job with different inputs to share the same name.

9.7.1Same name, different parameter list

Definition 9.8

Method overloading is defining several methods with the same name in the same class. The parameter lists of these methods must differ: in the number of parameters, the parameter types, or the order of the types. In short, their signatures must differ. The compiler binds a call to one of these methods by looking at the number and types of the arguments.

static int area(int side) {
    return side * side;
}
static int area(int w, int h) {
    return w * h;
}
// ERROR: only the return type differs
static double area(int side) { … }

The first two methods are valid overloading. area(int side) takes one parameter and area(int w, int h) takes two; their signatures are area(int) and area(int, int). The third method is wrong: its parameter list is the same as the first one's, and only the return type differs.

public class Area {
    static int area(int side) {
        return side * side;
    }

    static int area(int w, int h) {
        return w * h;
    }

    public static void main(String[] args) {
        System.out.println(area(4));
        System.out.println(area(3, 5));
    }
}

The most familiar example of overloading is System.out.println. The calls println(5), println(2.5), println("Hello") and println(true) each go to a separate method: println(int), println(double), println(String) and println(boolean). The programmer does not have to memorize a separate name for each type. Math.abs and Math.max are also overloaded for int, long, float and double.

9.7.2Which method does the compiler choose?

The choice among overloaded methods is made at compile time, before the program runs. The compiler knows the type of every argument in the call and looks for the signature that fits these types. The program below shows this decision for two calls:

In the call area(3, 5) there are two int arguments, and this time only area(int, int) fits: w = 3, h = 5 and 3 × 5 = 15 is returned.

When the type of an argument fits no parameter exactly, the compiler tries widening conversions. A type can be converted to a wider type without losing information: char → int → long → float → double. The compiler first looks for an exactly matching signature. 9.8Variable-length arguments

A method that adds two numbers, another that adds three numbers, a third that adds four… With overloading this road goes on forever. Java offers a syntax that lets a method take as many arguments as wanted.

9.8.1The int... syntax and its rules

Definition 9.9

Variable-length arguments (varargs) are a parameter declared by writing three dots after the parameter type, which accepts zero or more arguments: int... s. The compiler packs the values in the call into an array; inside the method s is an int[] array.

static int add(int... s) {
    int t = 0;
    for (int v : s) t += v;
    return t;
}
add(1, 2, 3)   // 6
add()          // 0
add(new int[]{4, 5})   // 9

Inside the method, s is used like an ordinary array. s.length gives how many arguments arrived. The enhanced for loop for (int v : s) puts the elements of the array into v in turn; one element is processed per iteration. The complete program and its output:

9.9Scope

A variable cannot be used from everywhere it is declared. Java gives each variable the right to be visible in a particular region of the program. The boundaries of this region are drawn by curly braces.

9.9.1Local variables and scope

Definition 9.10

Scope is the region of the program in which a variable can be used by its name. Variables declared inside a method, and the parameters of the method, are called local variables. The scope of a local variable starts at the line where it is declared and ends at the closing curly brace of the block in which it is declared. The scope of parameters is the whole body of the method.

Scope has four rules:

  • Parameters and variables declared inside a method are local.
  • A variable declared in a block, that is, between a pair of curly braces { }, is visible only in that block and in the blocks inside it.
  • Two local variables with the same name cannot be declared in the same scope.
  • A method cannot reach a local variable of another method.

The last rule follows directly from the call stack. The local variables of a method sit in that method's frame. Another method cannot reach that variable: either that frame does not exist yet, or the other method runs in a different frame. The compiler rejects this access from the start:

9.9.4Shadowing: a static field and a local variable

Variables are not declared only inside methods. A variable can also be declared inside the class but outside all the methods. Such a variable is called a field. A static field belongs to the class, is seen by all the methods of the class and lives for the whole program. Unlike local variables, it is not deleted at the end of a call.

Definition 9.11

Shadowing is declaring, inside a method, a local variable with the same name as a field of the class. Within the scope of the local variable, this name refers to the local variable; the field is left in the shade and does not change. The field can still be reached by writing ClassName.fieldName.

public class FieldShadow {
    static int counter = 100;          // static field

    static void test() {
        int counter = 1;               // the local variable shadows the field
        counter += 5;
        System.out.println("local counter = " + counter);
        System.out.println("field counter = " + FieldShadow.counter);
    }

    public static void main(String[] args) {
        test();
        System.out.println("main: " + counter);
    }

The value of the field stays at 100; the notation FieldShadow.counter reaches the field itself and 100 is printed. When test ends, the local counter is deleted and the name counter in main again refers to the field: 100.

That shadowing compiles does not contradict the ban on same-named local variables. The ban prevents two local variables from being visible under the same name at the same time. A field and a local variable, however, are of different kinds, and the field can always be told apart by the class name. Even so, shadowing is often the result of carelessness. The programmer thinks they are changing the field but changes a local copy, and the mistake goes unnoticed for a long time. Giving different names to fields and local variables is the safest way.

9.9.5Lifetime and initial value of a local variable

Scope says where a variable is visible. There is also the question of when the variable exists. A local variable is born when its declaration line runs and dies when its block ends. Each time a method is called, its local variables are born anew. No value is remembered from the earlier call. This is why the num in the second call of printPositive knows nothing about the −3 of the first call.

A counter that has to carry a value from one call to the next therefore cannot be local; it must be a static field. For example, a counter that counts how many times a method has been called, if declared inside the method as int counter = 0;, starts from 0 at every call and can never go beyond 1.

There is one more difference between fields and local variables. A static int field starts at 0 by itself if no value is given. A local variable has no initial value of its own. The compiler does not allow a local variable that has not been given a value to be read:

9.11Method design

A method that compiles and gives the correct result is not always a good method. A hundred-line method that does five jobs at once and both prints its result to the screen and stores it in a field may work, but it is hard to read, test and change. What separates a good method from a bad one is how it is divided and how it is named.

9.11.1Abstraction

Definition 9.12

Abstraction is hiding the details of a task and offering only a name and an interface that show what the task does. The abstraction of a method is its signature and its contract: what it takes, what it returns and under what conditions it works correctly.

A method hides the implementation detail from the calling code. A well-named method says what is done; how it is done stays in the body. A student using Math.sqrt does not know whether the square root is computed with Newton's method or with a special processor instruction, and does not need to.

Abstraction has an important benefit: even if the body changes, callers are not affected as long as the signature stays the same. Suppose a prime-number method was first written with a slow loop that tries all divisors from 2 to n − 1. Later it is replaced with a fast version that looks only up to √n. None of the hundred lines that call isPrime(n) changes; all of them get faster on their own.

9.11.2Decomposition

A big task is divided into subtasks, each with a single responsibility. For each subtask the input, the output and what happens on bad input must be determined. The top-level method combines these subtasks in a meaningful order. A top-level method written this way reads like a table of contents. This approach is called decomposition.

The following program applies the decomposition in the figure to a small example. Because the reading job is short, it has not been made a separate method; it is written in the first three lines of gradeReport. The letter-grade boundaries have been chosen as an example.

import java.util.Scanner;

public class GradeReport {
    static double computeAverage(int a, int b, int c) {
        return (a + b + c) / 3.0;
    }

    static String letterGrade(double avg) {
        if (avg >= 85) return "AA";
        if (avg >= 70) return "BB";
        if (avg >= 60) return "CC";
        if (avg >= 50) return "DD";
        return "FF";
    }

    static void writeReport(double avg, String letter) {
        System.out.println("Average: " + Math.round(avg * 100) / 100.0);
        System.out.println("Letter grade: " + letter);
    }

    static void gradeReport(Scanner input) {
        int g1 = input.nextInt();               // read the grades
        int g2 = input.nextInt();
        int g3 = input.nextInt();
        double avg = computeAverage(g1, g2, g3);
        writeReport(avg, letterGrade(avg));
    }

    public static void main(String[] args) {
        gradeReport(new Scanner(System.in));
    }
}

9.12.1The contract first

Before a method is written, what it will do must be stated clearly. The name of the method should say what it does, the valid range of the parameters should be defined, and the meaning of the return value and what happens on bad input should be known. The sum of this information is called the method's contract.

Definition 9.13

A contract is the agreement between a method and its caller. A precondition is a condition the caller must satisfy (e.g. “n ≥ 0”). A postcondition is the result the method guarantees when the precondition is satisfied (e.g. “returns the number of digits of n”).

9.12.2Even or odd?

9.12.4Is it prime?

A number greater than 1 that has no divisors other than itself and 1 is called a prime number. To find out whether a number is prime, the possible divisors are tried in order. The moment a divisor is found, the answer is settled and the method makes an early return.

static boolean isPrime(int n) {
    if (n < 2) return false;
    for (int i = 2; i <= n / i; i++)
        if (n % i == 0) return false;
    return true;
}

The expression i <= n / i in the loop condition may look strange at first. This condition makes i be tried up to the square root of n. The reason is this: if n can be written as the product of two numbers, that is, n = p × q, then at least one of p and q cannot be greater than √n. If both were greater than √n, their product would exceed n. So if n has a divisor greater than √n, it also has a partner smaller than √n, and that partner would already have been tried. For example, 91 = 7 × 13 and √91 ≈ 9.54. There is no need to wait for 13; the divisor is found when 7 is tried.

The condition i <= n / i is the form of the condition i * i <= n written with integer division. This form prevents the product i * i from exceeding the int limit when n is very large. 9.12.5GCD: Euclid's algorithm

The greatest common divisor (GCD) of two numbers is the largest number that divides both without a remainder. Instead of trying all the numbers from 1 up to the smaller number, the roughly 2,300-year-old Euclid's algorithm offers a much faster way: gcd(a, b) = gcd(b, a % b), and when b = 0 the answer is a.

static int gcd(int a, int b) {
    while (b != 0) {
        int r = a % b;
        a = b;
        b = r;
    }
    return Math.abs(a);
}
System.out.println(gcd(48, 18));  // main

The correctness of the algorithm rests on this observation: every number that divides both a and b also divides the difference a % b = a − k × b. Conversely, every number that divides both b and a % b also divides a. So the pair (a, b) and the pair (b, a % b) have the same common divisors, and therefore the same GCD. The numbers get smaller in each iteration. Finally b = 0 and gcd(a, 0) = a, because every number divides 0.

If the numbers are given in the reverse order, the first iteration swaps them by itself: since 18 % 48 = 18, gcd(18, 48) reaches the state of gcd(48, 18) after the first iteration. The method also works correctly with 0: gcd(7, 0) never enters the loop and returns 7. The Math.abs in the last line makes the result positive for negative inputs: gcd(-12, 18) returns 6, not −6.

public class Gcd {
    static int gcd(int a, int b) {
        while (b != 0) {
            int r = a % b;
            a = b;
            b = r;

        return Math.abs(a);
    }

    static int lcm(int a, int b) {
        if (a == 0 || b == 0) return 0;

9.12.6LCM: calling a method from a method

The least common multiple (LCM) of two numbers is easily found with the GCD: lcm(a, b) = a × b / gcd(a, b). Since the method that computes the GCD has already been written, the lcm method calls it; the real computation is a single line:

static int lcm(int a, int b) {
    if (a == 0 || b == 0) return 0;
    return Math.abs(a / gcd(a, b) * b);
}

There is a reason why the formula in the code is written as a / gcd(a, b) * b instead of a * b / gcd(a, b). Dividing first keeps the intermediate result from growing.         return a * b / gcd(a, b);

The sneaky thing about this bug is that neither the compiler nor the runtime gives any warning.

The first line of lcm also covers an edge case. If one of the numbers is 0, the common multiple is 0; when both numbers are 0, gcd(0, 0) returns 0, and without the check the division 0 / 0 would throw an ArithmeticException. The outer Math.abs makes the result positive for negative inputs: lcm(-4, 6) gives 12.

Calling a method from within a method avoids code duplication. The loop that computes the GCD has not been written again inside lcm. If a bug is found and fixed in gcd, lcm is fixed automatically too.

9.12.7Reuse: max3

To find the largest of three numbers, there is no need to write a new chain of comparisons. The method that gives the larger of two numbers is used twice: first the larger of the first two numbers is found, then this result is compared with the third number.

static int max(int a, int b) {
    if (a > b) return a;
    return b;
}
static int max3(int a, int b, int c) {
    return max(max(a, b), c);
}

9.12.9Pure methods and side effects

Definition 9.14

A side effect is any change a method leaves in the world apart from returning a value: printing to the screen, changing a field, adding a record to a file. A pure method is a method that always returns the same result for the same inputs and has no side effects.

Two small methods show the difference clearly:

public class PureDemo {
    static int square(int x) {
        return x * x;
    }

    static void printSquare(int x) {
        System.out.println(x * x);
    }

    public static void main(String[] args) {
        int t = square(3) + square(4);
        System.out.println(t);
        printSquare(4);
        System.out.println(square(square(2)));
    }
}
25
16
16

square is pure. square(4) is always 16 and can be used anywhere: inside a sum (9 + 16 = 25), as an argument to another call (square(square(2)) = square(4) = 16) or in a condition. printSquare, however, only prints to the screen. Its result cannot be used in another computation. printSquare(3) + printSquare(4) does not even compile, because printSquare is void.

Pure methods are easier to test. It is enough to check square(4) == 16; there is no need to capture screen output or to remember the earlier value of a field. This is why a computing method and a printing method are kept apart. The computation is done in a pure method, and the printing is left to a separate method or to main. When a side effect is unavoidable, for example when a report really must be written, the side effect is named explicitly and confined: the name writeReport says what it does, and it does nothing else.

Printing to the screen is not the only thing that spoils the purity of a method. A method that changes a static field also has a side effect. The result of a method that increases a counter on every call may vary with how many times it has been called. Methods that read from the keyboard or generate random numbers are also not pure, because they can give different results when called with the same input.

9.13Summary

  • A method is a named group of statements defined inside a class that does a task. It takes its input through parameters and gives its result as a return value. A method is defined once and called wherever you like and as many times as you like.
  • The formal parameters written in the definition are variables; the actual arguments written in the call are values. Arguments are matched to parameters in order; their number and types must fit.
  • In a call, the arguments are evaluated and copied into the parameters, the body runs, return sends the value, and the calling code continues with the value that has taken the place of the call.
  • Each call opens its own frame on top of the call stack. Only the topmost frame runs; when the method ends, its frame is deleted together with all its local variables. The last frame opened is the first to close.
  • The header consists of the access modifier, the modifier, the return type, the name and the parameter list. The signature is the name and the list of parameter types; the return type is not part of the signature.
  • main is static, because the JVM calls it when no object exists. A static method cannot directly call a non-static method.
  • A void method does not return a value; its job is a side effect. A void call cannot be part of an expression. Early return filters out special cases at the start of the method.
  • In a method that is not void, every path must end with a return. The returned value must fit the return type; narrowing is not done automatically.
  • Java always passes arguments by value. Even if a method changes its parameter, the caller's variable does not change; this is why a swap method that swaps primitive variables cannot be written. The new value is returned and the caller assigns it.
  • In overloading, methods with the same name have different parameter lists. The compiler makes the choice at compile time, looking first for an exact match and then for the closest widening. Two methods that differ only in return type, and two equally fitting candidates, are compile errors.
  • Variable-length arguments (int... s) are an array inside the method. The parameter comes at the very end of the parameter list; an empty array is passed in a call with no arguments.
  • Scope is the region in which a variable can be used, and it is bounded by curly braces. Two local variables with the same name cannot be declared in the same scope. A local variable with the same name as a field shadows the field. A local variable cannot be read before it has been given an initial value.
  • Math methods are static and overloaded. sqrt and pow return double, and round(double) returns long.
  • A good method does a single task, has a meaningful name, takes few parameters, returns its result and can be tried with independent examples. Abstraction separates what is done from how it is done; decomposition splits a big task into submethods; a contract states the preconditions and postconditions.
  • A method can call another method (lcm → gcd, max3 → max); each call opens its own frame on the stack. A pure method always gives the same result for the same input and has no side effects; this is why it is easy to test and can be reused everywhere.

9.15Test Yourself

  1. The method static double circleArea(double r) { return Math.PI * r * r; } is called in main as double s = circleArea(2 * radius);. What are the parameter, the argument, the return type and the signature in these lines?

    Answer

    The formal parameter is r; it is the variable declared with its type (double r) in the header. The actual argument is the expression 2 * radius; its value is computed first and this value is copied into r. The return type is double. The signature is circleArea(double); the return type and the parameter name are not part of the signature.

  2. Three methods are defined as follows: a() first prints “a1 ”, then calls b(), then prints “a2 ”. b() prints “b1 ”, calls c(), prints “b2 ”. c() only prints “c ”. main calls a(). What is the output? What is the largest number of frames on the stack?

    Answer

    The output is a1 b1 c b2 a2. Each method waits until the method it called finishes and then continues where it left off. While c is running there are 4 frames on the stack: main, a, b and c. The frames close in the reverse of the order in which they were opened: first c, then b, and a last.

  3. For the method static void zeroOut(int n) { n = 0; }, what does int k = 9; zeroOut(k); System.out.println(k); print? How should the method and the call be changed to really zero k?

    Answer

    It prints 9. Java passes by value: n is a copy of k, and n = 0 changes only the copy. When the method ends, n is deleted. The method is written to return a value, static int zeroOut() { return 0; }, and the caller does the assignment itself: k = zeroOut();. In this example, however, the simplest solution is not to use a method at all and write k = 0;.

  4. A class has only static void g(long x) and static void g(double x); both print the type and value of their parameter. Which method do the calls g(5), g(5.5f) and g('x') run?

    Answer

    There is no exact match for any of the calls; the compiler chooses the closest widening. g(5): int → long is closer than to double; long 5 is printed. g(5.5f): float cannot be narrowed to long but widens to double; double 5.5 is printed. g('x'): the long version is chosen through the widening char → int → long; since the code of the character 'x' is 120, long 120 is printed.

  5. For static int count(int... s) { return s.length; }, what do count(), count(5), count(new int[]{1, 2, 3}) and count(1, 2) return? Why does the header static int count(int... s, int k) not compile?

    Answer

    0, 1, 3 and 2, respectively. In the call with no arguments an empty array is passed (its length is 0); if an array is given directly, that array is used. In the second header the varargs parameter is not at the end of the list; the compiler gives the error varargs parameter must be the last parameter, because it cannot know which of the values in the call goes to k.

  6. Which line of the following method gives a compile error, and why? static int sumOfSquares(int n) { for (int i = 1; i <= n; i++) { int sq = i * i; } return sq; }

    Answer

    The line return sq; gives a cannot find symbol error. sq is declared in the body block of the for loop, and its scope ends when the block closes; outside the loop there is no variable with this name. The method also does not achieve its purpose: the squares are not being accumulated. The correct form is to declare int total = 0; before the loop, write total += i * i; in the body, and finish with return total;.

  7. In how many iterations does gcd(105, 30) finish with Euclid's algorithm, and what does it return? What does the lcm method return for the same numbers?

    Answer

    Iteration 1: 105 % 30 = 15 (105 = 3 × 30 + 15); a = 30, b = 15. Iteration 2: 30 % 15 = 0; a = 15, b = 0. The condition becomes false and 15 is returned after 2 iterations. lcm = 105 / 15 × 30 = 7 × 30 = 210. Check: 210 = 2 × 105 = 7 × 30.

  8. In the call isPrime(91), how many iterations does the loop run and what is returned? How many iterations does isPrime(37) run?

    Answer

    91 = 7 × 13. For i = 2, 3, 4, 5, 6 the condition (i ≤ 91 / i) is true and the remainder is not 0. At i = 7, 7 ≤ 91 / 7 = 13 is true and 91 % 7 = 0: false is returned in the 6th iteration. For 37, i = 2…6 is tried (5 iterations); at i = 7, 7 ≤ 37 / 7 = 5 is false and true is returned.

  9. What do Math.round(3.5), Math.round(-3.5), Math.abs(-0.5) and Math.max(-1, -8) return? Why does int r = Math.round(3.5); not compile?

    Answer

    4, −3, 0.5 and −1. Numbers exactly at the half are rounded to the larger value: 3.5 → 4, −3.5 → −3. Math.abs returns double for a double argument. −1 is greater than −8. Because Math.round(double) returns long, the result cannot be assigned directly to an int (possible lossy conversion from long to int); int r = (int) Math.round(3.5); must be written.

  10. For static int triple(int x) { return 3 * x; }, what do triple(triple(2)) and triple(2) * triple(1) give? If the same method printed with System.out.println(3 * x) instead of returning the result, could these two expressions be written?

    Answer

    The first: the inner call gives 6, the outer triple(6) = 18. The second: 6 × 3 = 18. Both are 18. If the method were a void method that printed, neither expression would compile: a void call can be neither an argument to another call nor an operand of a multiplication. A pure method that returns its result can be used in any expression.
