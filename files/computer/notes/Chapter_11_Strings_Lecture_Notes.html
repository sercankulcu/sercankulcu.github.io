Chapter 11: Strings

Most of the data programs process is text: student names, email addresses, sentences typed at the keyboard, reports printed to the screen. In Java, text is represented by objects of the String class. These notes explain how strings are held in memory, why they cannot be changed, and their most frequently used methods. Reaching characters by index, taking substrings, searching, splitting and replacing are treated one by one. Comparison of strings follows: the difference between == and equals, lexicographic order with compareTo, and the traps caused by Turkish letters. Reading text from the keyboard, efficient concatenation with StringBuilder and formatted output with printf are also among the topics. The applications in the last section (reversing, palindromes, counting vowels and words, letter frequency, the Caesar cipher) bring all these tools together. Every program was compiled and run with JDK 21; the outputs given are the real outputs of the programs.

11.1What is a string?

Most of the programs written so far worked with numbers. A number is held in an int or double variable and goes into arithmetic operations. Text is a different structure: an ordered sequence of letters, digits, spaces and punctuation marks. This section introduces the two building blocks of text in Java, the types char and String.

11.1.1Characters and strings

Definition 11.1

A character is a single letter, digit, space or mark of text. In Java a character is held in a variable of type char and is written in single quotes: 'T', '7', ' '. A string is an ordered sequence of zero or more characters. In Java, strings are objects of the String class and are written in double quotes: "Tarkan", "7", "".

The kind of quote matters. 'T' is a single character and its type is char. "T" is a string of length 1 and its type is String. The two look the same on the screen but are different types for Java. This is why a string cannot be assigned to a char variable:

public class WrongType {
    public static void main(String[] args) {
        char c = "T";
        System.out.println(c);
    }
}

                 ^

The message says that the type String cannot be converted to the type char. The correct form is char c = 'T';.

The String class is in the java.lang package. This package is added to every Java program automatically; the import line needed for Scanner is not needed for String. A piece of text written directly in the program, such as "Tarkan", is called a string literal.

11.1.2A string is an object

Primitive types such as char, int and double hold their values directly inside the variable. String, however, is not a primitive type; it is a class. A String variable holds not the text itself but the location in memory of the object that carries the text. This location information is called a reference. Figure 11.1 compares how the two types look in memory.

The names of the two memory regions in the figure appear in all the later drawings. The stack is the region where the local variables of methods are kept. The heap is the region where objects created with new, and strings, live. A String variable on the stack points to the object on the heap with an arrow. Several variables can point to the same object. This sharing is decisive when strings are compared.

Definition 11.2

An object is a piece of memory produced from a class, carrying its own data and methods. A reference is a value that shows where an object is in memory. In the declaration String s = "Ada";, the variable s is a reference; "Ada" is the object on the heap.

One consequence of being an object is methods. Operations belonging to a string are called with the dot: name.length() gives the length of the string and name.charAt(0) its first character. Primitive types have no methods; a notation such as c.length() does not compile.

11.1.3Creating strings, the empty string and null

A string variable can be given an initial value in four different ways:

String name = "Tarkan";
String empty = "";
String copy = new String(name);
String none = null;

The first line is the most common form: name points to the constant "Tarkan". The "" in the second line is the empty string, which contains no characters. The third line creates a new object with new and copies the contents of name into it. The null in the fourth line means that the variable points to no object at all. Figure 11.2 shows the state of the four variables in memory.

The string pool in the figure is a special region inside the heap where a single copy of each constant is kept. The rule here is short: a string created with a literal comes from the pool, while new always creates a new object. In practice there is almost never a need to write new String(...); the string literal is preferred.

The empty string and null are often confused. The empty string is a real object; its length is 0 and all its methods can be called. null is not an object; it is the state of a variable that says “I do not point to anything yet”. If a method is called through a null variable, the program stops with a NullPointerException. The program below prints the four variables and then calls none.length():

11.1.4Concatenation with +

Joining two strings end to end is called string concatenation. In Java the + operator is used for this. The same operator does addition on numbers. Which one happens is decided by the types of the operands: if at least one of the two operands is a String, + is concatenation; if both are numbers, it is addition.

public class Concatenation {
    public static void main(String[] args) {
        String num1 = "12";
        String num2 = "34";
        String total = num1 + num2;
        System.out.println(total);
        int a = 12, b = 34;
        System.out.println(a + b);
        System.out.println(num1 + 3 + 4);
        System.out.println(3 + 4 + num1);

        System.out.println("Total: " + (a + b));
        System.out.println("x" + null + 'c' + 2.5 + true);

The concat method also joins two strings, but it accepts only strings.

Example 11.1

With int x = 5, y = 2;, what are the values of the expressions "x+y=" + x + y and x + y + "=x+y"?

Solution. In the first expression the leftmost operand is a string. "x+y=" + 5 = "x+y=5", then "x+y=5" + 2 = "x+y=52". In the second expression the first two operands are numbers: 5 + 2 = 7. Then 7 + "=x+y" = "7=x+y". The same three operands give a different result when their order changes.

11.1.5A char is a number

Computers store characters as numbers. In the Unicode standard every character has a code number: 'a' is 97, 'b' is 98, 'A' is 65 and '0' is 48. In Java, char is really a 16-bit unsigned integer type. So a char can take part in arithmetic. The type of the result follows a rule: when a char is added to an integer, or two chars are added, the result is int.

        System.out.println((char) (k + 1));

        System.out.println('a' + 'b');
        System.out.println("" + 'a' + 'b');

        System.out.println(k);

}

11.2Immutability

The most important property of strings is that their contents do not change after they are created. At first this property seems strange: when you write s = s + "!", it looks as if s has changed. In reality, what changes is not the object but the place the variable points to.

11.2.1A new object, the same old object

Definition 11.3

An object whose contents cannot be changed after it is created is called an immutable object. String is an immutable class: none of its methods changes the characters of the object. Every operation that “changes” a string (concatenation, converting to uppercase, taking a substring, replacing) produces a new String object and returns it. This property is called immutability.

Figure 11.3 shows the simplest example. After the line String s = "Merhaba";, s points to the seven-character object. The line s = s + "!"; does not add an exclamation mark to this object. First s + "!" is computed and a new eight-character object is created. Then the assignment moves the arrow of s to this new object. The old "Merhaba" object stays as it was.

This can also be seen with a program. If a second variable (old) is kept pointing to the old object before the assignment, it becomes clear after the assignment that the two variables point to different objects:

public class Exclaim {
    public static void main(String[] args) {
        String s = "Merhaba";
        String old = s;
        s = s + "!";
        System.out.println(s);
        System.out.println(old);
        System.out.println(s == old);
    }
}

old still points to “Merhaba”. The comparison s == old asks whether the two variables point to the same object, and it gives false: there are now two separate objects. Objects that no variable points to become unnecessary in time. In Java the garbage collector cleans up these objects automatically; the programmer does not have to give memory back by hand.

Common mistake

Writing lines such as name.trim();, name.toUpperCase(); or name.replace('a', 'e'); on their own and thinking that name has changed. These lines compile and run, but the result is thrown away. 11.2.3Why is immutability useful?

Producing a new object at every change may seem wasteful. Java's designers chose to pay this price for three gains:

  • Safe sharing. Several variables can point to the same string object. Because none of them can change the object, an operation done through one variable does not affect the others. The string pool is possible because of this: all the "Giresun" literals in the program share a single object.
  • Predictability. When a string is passed to a method, the method cannot corrupt it. The calling side is sure that the string is the same when it returns from the method.
  • Security. File names, network addresses and passwords are carried in strings. That a file name that has passed a check cannot be changed afterward is an important guarantee.

The price is that a large number of concatenations slows down. If s = s + x is written thousands of times in a loop, a new object is produced on every iteration and the old contents are copied. For this case Java offers a mutable helper class: StringBuilder.

11.3Indexing

The characters of a string are ordered, and each has a sequence number. This number is called the index. As with arrays, counting in strings starts at 0.

Definition 11.4

The characters of a string of length n are at indices 0, 1, …, n − 1. The first character is at index 0 and the last at index n − 1. Reaching a character by its index is called indexing. In Java, s.length() returns the length of the string, and s.charAt(i) returns the character at index i as a char value.

For the string in Figure 11.5, the following program prints the length and the first and last characters. The index of the last character is found for any string with the expression s.length() - 1; this way the code works whatever the length.

public class Index {
    public static void main(String[] args) {
        String s = "Giresun";
        System.out.println(s.length());
        System.out.println(s.charAt(0));
        System.out.println(s.charAt(s.length() - 1));
        int[] arr = {4, 8, 15};
        System.out.println(arr.length + " " + s.length());
        System.out.println(s.charAt(7));
    }
}

Trying to reach the last character with s.charAt(s.length()). If the length is n, the last index is n − 1; s.charAt(s.length()) is always out of bounds. 11.4String methods

The String class has more than sixty methods. This section covers the ones most often needed in everyday programs. One rule holds for all of them: no method changes the original string. If a result is needed, the method returns it as a new value.

11.4.1length, indexOf, substring and contains

Four basic methods are used together in this program:

isEmpty() gives true only for a string of length 0. isBlank() gives true for the empty string and for a string made up only of whitespace. So for the three-space string " ", the first is false and the second is true. The repeat(3) in the last line writes the string three times side by side: ababab.

"a,b,,c".split(",") cuts the text at three commas and produces four parts: "a", "b", "" and "c". Between two consecutive commas there is nothing; this empty string also goes into the array. The additional lines show three rules of split:

  • Trailing empty parts are dropped. "a,b,,".split(",") gives two parts, not four: [a, b]. The two trailing empty parts do not go into the array.
  • A leading empty part is kept. ",a,b".split(",") gives three parts: [, a, b]. The empty text before the first comma counts as a part.
  • The delimiter is a regular expression. The text given to split is not a plain character but a pattern. In the pattern language, the dot means “any character”. So "3.14".split(".") cuts at every character, all the parts are empty, and once the trailing empty parts are dropped the array length is 0. To split at the dot itself, split("\\.") is written and the result is [3, 14].
Definition 11.5

A regular expression is a small language that describes a text pattern. Some characters have a special meaning in this language: . means any character, + means “one or more”, [0-9] means any digit and \s means any whitespace character. To use a special character with its own meaning, a backslash is put in front of it. Because the backslash itself is written \\ in a Java string literal, the pattern takes the form "\\." or "\\s+".

Example 11.3

How many parts do "23.10.2026".split("\\.") and "elma, armut,kiraz".split(",") give, and what are the parts?

Solution. The first string has two dots; three parts come out: "23", "10", "2026". The second string has two commas; again three parts come out: "elma", " armut", "kiraz". The space at the start of the second part is kept, because the delimiter is only the comma. To remove the space too, either strip() is applied to each part or the delimiter is given as ",\\s*" (a comma followed by zero or more spaces).

11.4.6Substring bounds

substring is the method on which mistakes are most often made. An easy way to remember the rule is to write the indices not on the characters but on the lines between them. In Figure 11.10, there are eight lines, from 0 to 7, among the seven characters of the string "PROGRAM". substring(a, b) takes the characters that lie between line a and line b.

Definition 11.6

11.5Comparison

Asking whether two strings are the same is one of the most frequent jobs in programming: is the entered password correct, did the user type “yes”, do two students have the same name? For numbers, this question is asked with ==. For strings, == does not ask the expected question.

11.5.1== and equals

Because a String variable holds a reference, a == b compares two references. The question becomes “do the two variables point to the same object?”. Even if two separate objects carry the same characters, == gives false. To compare contents, the equals method is used.

Definition 11.7

11.5.3compareTo and lexicographic order

Besides equality, the order of two strings can be asked too: which one comes first in a dictionary? This order is called lexicographic order. a.compareTo(b) returns an integer. If the result is negative, a comes first; if zero, the two are equal; if positive, a comes later.

Definition 11.8

a.compareTo(b) compares the two strings character by character, starting at the beginning. There are two cases:

  1. If the first differing character is at position k, the result is a.charAt(k) − b.charAt(k); that is, the difference of the codes of the two characters.
  2. If all the characters of the shorter string are the same as the beginning of the longer one, the result is a.length() − b.length(); that is, the length difference.

If the two strings are exactly the same, the second rule gives 0.

String x = "elma";
String y = "armut";
System.out.println(x.compareTo(y)); // 4
String k = "kedi";
System.out.println(k.compareTo("kediler")); // -3

The two examples in the slides exercise the two rules separately. Figure 11.14 shows the critical step of each.

  • "elma".compareTo("armut"): at position 0, 'e' meets 'a' and they differ. The result is 'e' − 'a' = 101 − 97 = 4. Because it is positive, “elma” comes after “armut”. The lengths of the strings (4 and 5) do not enter the result at all; the first differing character decides.
  • "kedi".compareTo("kediler"): in the first four positions k=k, e=e, d=d, i=i. Then “kedi” ends; no differing character has been found. The result is the length difference: 4 − 7 = −3. Because it is negative, the shorter “kedi” comes first.

11.5.4Turkish characters and the locale

In English these pairs are i ↔ I. The lowercase of the same letter “I” is “i” in English and “ı” in Turkish. Java solves this difference with the locale. A locale is a java.util.Locale object that carries the writing rules of a language and region.

Definition 11.9

11.6Memory: the string pool

The same string literal can occur in many places in a program: “Giresun”, “yes”, the empty string. Creating a separate object for each would waste memory. This is why Java gathers the literals in a common pool.

11.6.1The pool and new

Definition 11.10

The string pool is the region of memory in which the Java virtual machine keeps string literals. All literals with the same contents share a single object in the pool. new String(...), however, does not look at the pool and creates a new object on the heap on every call.

Sharing is safe only because strings are immutable. If they could be changed, a change made through one variable would affect all the variables using the same literal. Figure 11.15 shows the state of three variables.

public class Pool {
    public static void main(String[] args) {
        String a = "Giresun";
        String c = "Giresun";
        String b = new String("Giresun");
        String d = new String("Giresun");
        System.out.println((a == c) + " " + (a == b) + " " + (b == d));
        System.out.println(a.equals(b) + " " + b.equals(d));
        System.out.println((b.intern() == a) + " " + (b.intern() == b));
    }
}
true false false
true true
true false

The first line makes three reference comparisons. a == c is true: both point to the object in the pool. a == b is false: b is a separate object on the heap. b == d is false too: two new calls produce two separate objects. The equals tests on the second line are all true, because the contents are the same.

11.6.2Constant concatenation and intern

Whether a string comes from the pool is not always easy to read from the code. The program below shows two subtle cases of this:

String a = "a", b = "b";

final String f = "a";

System.out.println((f + "b") == "ab");    // true
System.out.println(r == "ab");            // false
System.out.println(r.equals("ab"));       // true
System.out.println(r.intern() == "ab");   // true
true
true
false
true
true

The five results are explained as follows:

  1. ("a" + "b") == "ab" is true. Because both operands are constants, the compiler does the concatenation before the program runs. In the compiled code, the constant "ab" appears directly instead of "a" + "b", and this constant comes from the pool.
  2. (f + "b") == "ab" is true too. f is declared final and initialized with a constant. Because its value can never change, the compiler treats it as a constant as well.
  3. r == "ab" is false. In the line r = a + b, a and b are ordinary variables. The concatenation is done at run time and the result is a new object on the heap.
  4. r.equals("ab") is true; the contents are the same.
  5. r.intern() == "ab" is true. The intern() method looks at the pool: if a string with the same contents exists there, it returns that one; if not, it adds the string to the pool and returns it. The returned reference is the "ab" in the pool.

Expressions whose value is known at compile time are called constant expressions: string literals, final constants and combinations of them. The result of a constant expression is put in the pool. Every concatenation that involves a variable produces a new object.

The effect of intern can also be seen in the last line of the Pool program. b.intern() == a is true: the contents of b exist in the pool, and intern returns the object in the pool. b.intern() == b is false: b itself is an object outside the pool. In practice intern is rarely needed; it is used here to make the workings of the pool visible.

Common mistake

Seeing == give the right result in a few trials and continuing to compare strings with ==. Because the literals used in the trials are shared in the pool, == comes out right by coincidence. The same code gives a wrong result when the text comes from the keyboard or from a file. == being true shows not that the contents are equal but that the object is the same.

11.6.3Null-safe comparison

equals is a method and is called through an object. If the variable is null, the call cannot be made and a NullPointerException occurs. Writing the same comparison the other way round removes this problem:

public class NullSafe {
    public static void main(String[] args) {
        String x = null;
        System.out.println("constant".equals(x));
        System.out.println(x.equals("constant"));
    }
}
false
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.equals(Object)" because "x" is null

In the line "constant".equals(x), the method is called on "constant", a real object. When the parameter is null, equals does not raise an error; it simply returns false. In the line x.equals("constant"), however, the method is called through null and the program stops. This is why the constant is written on the left: "yes".equals(answer) is safe even if answer is null.

11.7Text input with Scanner

The java.util.Scanner class is used to read text from the keyboard. The class has two methods for reading text: next() reads a word and nextLine() reads a line. The key to understanding the behavior of the two methods is the buffer, where the characters coming from the keyboard wait.

11.7.1next and nextLine

When the user types something and presses Enter, the characters typed and the end-of-line character go into the buffer. In these notes the end-of-line character is shown as ⏎. Each read method of Scanner takes characters from the start of the buffer and moves the reading position forward. Characters that have been read are not read again.

Definition 11.11

next() skips leading spaces and line ends, then reads the non-whitespace characters up to the first space or line end. This part is called a token. The space or ⏎ after the token stays in the buffer. nextLine(), on the other hand, reads everything from its current position to the end of the line, spaces included. It consumes the ⏎ but does not add it to the result.

import java.util.Scanner;
// ...
Scanner in = new Scanner(System.in);
String word = in.next();
in.nextLine();
String line = in.nextLine();

That next() stops at whitespace makes it easy to read the words on a line one by one. “␣␣Ada␣␣␣Can␣Ece␣Su” is entered on a single line to the following program (␣ shows a space):

11.8Concatenation and StringBuilder

The + operator is readable and sufficient for joining a few strings. But if concatenation is done thousands of times inside a loop, the price of immutability becomes noticeable.

11.8.1The cost of using + in a loop

The line s = s + x does not lengthen s. Each time it runs, it produces a new object that carries all the characters of s and x. The old object goes to the garbage. Figure 11.18 shows this for a loop of three iterations.

The number of characters copied can be computed. Consider a loop that appends a single character on each iteration. On iteration 1 a new object of 1 character is built, on iteration 2 one of 2 characters, and on iteration n one of n characters. The total number of characters copied is:

1 + 2 + 3 + … + n = n(n + 1) / 2

This total is roughly n²/2. For n = 1,000 it is 500,500, and for n = 100,000 it comes to about 5 billion characters. The program below verifies these numbers by counting inside the loop:

public class Cost {
    public static void main(String[] args) {
        for (int n : new int[]{1000, 10000, 100000}) {
            long copied = 0;
            String s = "";
            for (int i = 0; i < n; i++) {
                copied += s.length() + 1;
                s = s + "x";
            }
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) {
                sb.append('x');
            }
            System.out.println(n + " " + copied + " " + (s.length() == sb.length()));
        }
    }
}

This rate of growth is called quadratic growth, and for large values of n the program slows down noticeably. In the second loop, with StringBuilder, each character is written to the buffer once; the total work is proportional to n. 11.9.5Character frequency

To count how many times each letter occurs in a text, an int array of 26 cells is used. Cell 0 is the counter for the letter 'a', cell 1 for 'b' and cell 25 for 'z'. The cell of a letter is found with c - 'a', taking advantage of the fact that chars are numbers.

String s = "kavak";

  if (c < 'a' || c > 'z') continue;
  freq[c - 'a']++;
}
for (int k = 0; k < 26; k++)

Skipping the range check on line 5. The 26-cell table is only for lowercase English letters. The check skips characters outside a–z with continue. If uppercase letters are to be counted, they are lowercased first. For Turkish letters, either an alphabet string of 29 letters and indexOf are used, or a wider table is built.

11.9.6The Caesar cipher

The Caesar cipher is a very old encryption method that shifts every letter forward by a fixed number of positions in the alphabet. If the shift is 3, 'a' → 'd' and 'b' → 'e'. The letters at the end of the alphabet wrap around to the start: 'x' → 'a', 'y' → 'b', 'z' → 'c'.

The arithmetic of wrapping around is the mod operation. The place of a letter in the alphabet is converted to a number from 0 to 25 with c - 'a'. The shift is added and the remainder of the result divided by 26 is taken:

pos = (c − 'a' + shift) % 26

The remainder is always between 0 and 25; so the result does not spill outside the alphabet. Then 'a' + pos turns it back into a letter. The program encrypts only lowercase English letters (a–z); spaces, digits, uppercase and Turkish letters are appended unchanged by the check on line 6.

String text = "yazilim";
int shift = 3;
StringBuilder enc = new StringBuilder();
for (int i = 0; i < text.length(); i++) {
  char c = text.charAt(i);
  if (c < 'a' || c > 'z') { enc.append(c); continue; }
  int pos = (c - 'a' + shift) % 26;
  char out = (char) ('a' + pos);
  enc.append(out);
}

        }

        System.out.println(enc);
        System.out.println(shift(enc, 26 - 3));
        System.out.println(shift("kaz", 2));
        System.out.println((-3) % 26);
    }
}

Example 11.10

A program that checks with character frequencies whether two words are anagrams (a rearrangement of the same letters, e.g. “elma” – “alem”).

Solution. If the lengths differ, the words cannot be anagrams. If all the cells are zero in the end, the two words have the same letters in the same numbers.

public class Anagram {
    static boolean isAnagram(String a, String b) {
        if (a.length() != b.length()) return false;

            freq[a.charAt(i) - 'a']++;
            freq[b.charAt(i) - 'a']--;
        }
        for (int k = 0; k < 26; k++)

        return true;

Example 11.13

public class CaesarUpper {
    static String encrypt(String text, int shift) {
        StringBuilder result = new StringBuilder();

            } else {
                result.append(c);
            }
        }
        return result.toString();
    }

11.10Formatting with printf

When a report or a table is printed, we want the values to stay aligned and decimal numbers to be cut at a certain number of digits. Concatenation with + does not provide this easily. The System.out.printf method, however, formats text according to a pattern.

Definition 11.14

The first parameter of printf is the format string. Plain text in the format string is written as it is. Each format specifier that begins with % stands in for the next argument and says how it is to be written. The general structure of a specifier is %[-][width][.precision]type. The main types are s (text), d (integer), f (floating-point number) and n (line end).

  • %-8s: the text is written in a field of at least 8 characters. The minus sign left-aligns it; since “Java” has four characters, four spaces are added to its right.
  • %3d: the integer is right-aligned in a field of 3 characters; two spaces come before the 3.
  • %7.2f: the number is written with two digits after the decimal point (“17.50”, five characters) and right-aligned in a field of 7 characters; two spaces come before it.
  • %n: adds the line end appropriate to the operating system.

Format specifiers are ideal for tables. When fields of the same width are written one below the other, the columns line up on their own:

11.11Unicode and text length

Java's char type is 16 bits and can take 65,536 different values. Almost all the characters of everyday texts, Turkish letters included, are in this range. But the Unicode standard today defines more than 150 thousand characters: old writing systems, mathematical symbols, emojis. Some of these do not fit in a single char.

Definition 11.15

In Unicode every character has a number; this number is called a code point. Java strings store these numbers with the UTF-16 encoding, in 16-bit code units. A char is one code unit. Code points greater than U+FFFF are stored as a pair made up of two code units. length() gives the number of code units, not the number of characters.

public class UnicodeDemo {
    public static void main(String[] args) {
        String tea = "çay";
        String emoji = "😀";
        System.out.println(tea.length() + " " + emoji.length() + " " + emoji.codePointCount(0, emoji.length()));
        System.out.printf("%X %X %X%n", (int) emoji.charAt(0), (int) emoji.charAt(1), emoji.codePointAt(0));
        String combined = "çay";
        System.out.println(combined.length() + " " + combined.equals(tea));
        System.out.println(java.text.Normalizer.normalize(combined, java.text.Normalizer.Form.NFC).equals(tea));
        System.out.println("straße".toUpperCase(java.util.Locale.ROOT) + " " + "straße".length() + " " + "straße".toUpperCase(java.util.Locale.ROOT).length());
    }
}

The second line prints the two code units of the emoji and its real code point in hexadecimal: U+1F600. Because this number is greater than 65,535, it does not fit in a single char.

The third line shows a subtler case. The letter “ç” can be written in two ways in Unicode: as a single ready-made character (U+00E7) or as a “c” plus a separate cedilla mark added beneath it (U+0327). The second form looks the same on the screen but has length 4 and is not equal to the first form under equals. The java.text.Normalizer class brings the two forms to the same representation; the fourth line shows that equality holds after normalization. On the last line, when the German letter “ß” is converted to uppercase it turns into two letters, “SS”, and the string grows longer: the 6-character “straße” becomes the 7-character “STRASSE”.

The consequence of these details for everyday programs is this: in Turkish texts length() and charAt work as expected. In texts containing emojis, combining marks or other writing systems, however, the “number of characters the user sees” can differ from length(). In such texts, operations such as reversing can also split a pair in the middle and produce broken characters.

11.12Summary

  • char holds a single character in single quotes ('T'), and String holds a sequence of characters in double quotes ("Tarkan"). String is not a primitive type but a class in the java.lang package; the variable holds the reference to the object. "" is a real object of length 0; null points to no object, and if a method is called through it, a NullPointerException occurs.
  • + is concatenation if one of the operands is a string and addition if both are numbers, and it is evaluated from left to right: "12" + 3 + 4 = "1234", 3 + 4 + "12" = "712". A char is a number: 'a' + 1 = 98, 'k' − 'a' = 10.
  • String is immutable. toUpperCase, replace, substring and + return a new object; if the result is not assigned, it is lost. What changes is not the object but the place the variable points to. Objects that nobody points to are cleaned up by the garbage collector.
  • Indices run from 0 to length() − 1; an out-of-bounds index gives a StringIndexOutOfBoundsException. length() is a method for strings, while length is a field for arrays.
  • substring(a, b): a included, b excluded; length b − a; valid range 0 ≤ a ≤ b ≤ length(). indexOf gives the first position or −1. split takes a regular expression; consecutive delimiters produce empty parts, and trailing empty parts are dropped.
  • replace searches for plain text and replaceAll for a regular expression. trim removes only ASCII whitespace, while strip removes all Unicode whitespace. format and printf depend on the locale.
  • == compares references and equals compares contents; strings are always compared with equals. compareTo gives the code difference of the first differing character, or the length difference if there is none. Uppercase letters come before lowercase ones and English letters before Turkish ones; for Turkish sorting, Collator is used.
  • In Turkish, i ↔ İ and ı ↔ I are paired. The parameterless toLowerCase()/toUpperCase() depend on the language of the machine; Locale.ENGLISH is given for technical text and Locale.forLanguageTag("tr") for Turkish text.
  • The same constants share a single object in the string pool; new always creates a new object. Constant expressions are concatenated at compile time and enter the pool; a concatenation with a variable produces a new object. intern() gives the object in the pool. "constant".equals(x) is safe against null.
  • next() reads a word and leaves the ⏎ in the buffer; nextLine() reads the rest of the line and consumes the ⏎. If a line is to be read after next() or nextInt(), a nextLine() is put in between.
  • In a loop, s = s + x produces a new object on every iteration; in n iterations about n²/2 characters are copied. StringBuilder is a mutable buffer: append, insert and reverse change the same object; the result is obtained with toString().
  • The common pattern of the applications is a scan of characters. Reversing scans from the end to the start, and the palindrome check scans from both ends inward. Word counting uses a flag. A frequency table selects the cell with c - 'a'; the Caesar cipher shifts with (c - 'a' + k) % 26.
  • In printf, %-8s left-aligns and %3d right-aligns; %7.2f writes with two decimals in 7 cells; %n is the line end. A type mismatch gives an exception at run time.
  • Strings are made up of UTF-16 code units; Turkish letters fit in a single char, while characters such as emojis take two chars. So length() is not always the same as the number of visible characters.

  1. With int p = 2, q = 5;, what does the line System.out.println(p + q + "x" + p + q); print?

    Answer

    + is evaluated from left to right. The first two operands are numbers: 2 + 5 = 7. Then 7 + "x" = "7x", and the expression turns into concatenation: "7x2", then "7x25". The output is 7x25.

  2. After the lines String s = "dizgi"; s.toUpperCase(); s = s.replace('i', 'ı');, what does s point to?

    Answer

    The result of toUpperCase() is lost because it is not assigned; s is still "dizgi". The result of replace, however, is assigned and both 'i's become 'ı': s points to "dızgı". The "dizgi" object has not changed; only the arrow of s has moved to the new object.

  3. For String t = "Karadeniz";, what are the values of t.length(), t.charAt(4), t.indexOf("de"), t.substring(4, 8) and t.lastIndexOf('a')?

    Answer

    The indices: K=0, a=1, r=2, a=3, d=4, e=5, n=6, i=7, z=8. The length is 9. charAt(4) is 'd'. "de" starts at index 4. substring(4, 8) takes indices 4–7: "deni" (length 8 − 4 = 4). The last 'a' is at index 3.

  4. What is "x;;y;z;;".split(";").length? What are the parts?

    Answer

    The text is cut at every semicolon: "x", "", "y", "z", "", "". The empty part between two consecutive semicolons stays; the two trailing empty parts are dropped. The result is [x, , y, z], with length 4.

  5. What are the values of "Masa".compareTo("masa"), "kitap".compareTo("kitaplık") and "ödev".compareTo("sınav")? Which of them contradict true dictionary order?

    Answer

    In the first, the first characters are 'M' (77) and 'm' (109): 77 − 109 = −32. In the second, "kitap" is the beginning of "kitaplık": 5 − 8 = −3. In the third, 'ö' (246) meets 's' (115): 246 − 115 = 131, so "ödev" comes after "sınav". Because ö comes before s in the Turkish alphabet, the third result contradicts dictionary order.

  6. On a computer with a Turkish setting, what is the value of the expression "MAIL".toLowerCase().equals("mail")? How is the expression fixed?

    Answer

    The parameterless toLowerCase() uses Turkish rules and converts "I" to "ı": "maıl". Because it is not equal to "mail", the value is false. Since "MAIL" is a technical word, toLowerCase(Locale.ENGLISH) is written, or "MAIL".equalsIgnoreCase("mail") is used directly; both give true.

  7. After the lines String a = "ab"; String b = "a"; String c = b + "b"; final String d = "a"; String e = d + "b";, what are the values of a == c, a == e and a == c.intern()?

    Answer

    Because b is not final, b + "b" produces a new object at run time: a == c is false. Because d is a final constant, d + "b" becomes the constant "ab" at compile time and comes from the pool: a == e is true. c.intern() returns the "ab" in the pool: true.

  8. The user types “42⏎” first, then “Ali Can⏎”. After the lines int n = in.nextInt(); String s = in.nextLine(); String t = in.next();, what are s and t?

    Answer

    nextInt() reads 42 and leaves the ⏎. nextLine() reads up to that ⏎: s is the empty string. next() reads the first word of the second line: t is "Ali". " Can⏎" stays in the buffer.

  9. The word “ankara” is encrypted with a Caesar cipher with a shift of 4. What is the result? What shift is used to decrypt?

    Answer

    The places of the letters: a=0, n=13, k=10, r=17. Adding 4 gives 4, 17, 14, 21; none exceeds 26. The six letters turn, in order, into e, r, o, e, v, e: "eroeve". To decrypt, a shift of 26 − 4 = 22 is used.

  10. What does the line System.out.printf("[%6.1f][%-4s][%03d]%n", 2.75, "ab", 7); print?

    Answer

    %6.1f rounds 2.75 to one decimal: "2.8" (three characters) and right-aligns it in 6 cells; three spaces come before it. %-4s left-aligns "ab" in 4 cells; two spaces come after it. %03d pads 7 with zeros to 3 cells: "007". The output is [ 2.8][ab ][007] (with the English locale; “2,8” with the Turkish one).
