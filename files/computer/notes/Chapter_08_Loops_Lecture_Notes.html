Chapter 8: Loops

The real power of a computer comes from its ability to do the same job thousands of times without getting tired. In a program, loops provide this repetition. This chapter first introduces the four parts found in every loop: initialization, condition, body, and update. Then come Java's three loops: for, while, and do-while. Each is traced iteration by iteration with a small program. The break and continue statements, which change the flow of a loop, and typical mistakes such as infinite loops and boundary errors are also treated in detail. The second half of the chapter is devoted to examples. Loops that work with the digits of a number, loops that search for divisors, loops that read input from the user, and patterns drawn with nested loops are gathered into a few common templates. All Java programs were compiled and run with JDK 21; the outputs given in the chapter were taken from these runs.

8.1What is a loop?

8.1.1Why do we need repetition?

Consider a program that prints the sum of the numbers from 1 to 4. A one-line solution comes to mind at once: sum = 1 + 2 + 3 + 4;. When the same job is wanted for 1 to 1000, this way does not work. Writing a line with a thousand terms is both tedious and error-prone. Moreover, the upper limit is often not known when the program is written; the user enters it while the program runs.

What these problems have in common is that the same small job is done over and over: “add one more number to the sum, then move on to the next number”. In programming languages, the construct that expresses this kind of repetition is called a loop. The programmer writes the job to be repeated once and says when to stop. The computer does the rest.

Definition 8.1

A loop is a construct that runs a group of statements over and over for as long as a condition is true. The repeated statements are called the loop body, and one run of the body is called an iteration.

Java has three loops: for, while, and do-while. All three can do the same job; the differences between them are when the condition is asked and where the parts are written. That is why we first need to get to know the parts common to every loop.

8.1.2The four parts of a loop

Every loop consists of four parts. In the slides and in this chapter, each part is always shown in the same color. Figure 8.1 gathers these parts in a general flowchart.

  1. Initialization: runs once before the loop and gives starting values to the variables the loop will use. counter = 1 in the figure is such a step.
  2. Condition: a logical expression whose result is true or false. In for and while loops it is asked before every iteration, and in the do-while loop after every iteration. If the result is false, the loop is left.
  3. Body: the work done in every iteration. In the figure it is shown by the “do work” box.
  4. Update: changes the variable used in the condition. For example, counter++ increases the counter by 1. The job of the update is to bring the condition a little closer to its end in every iteration. If the update is forgotten, the condition always stays the same and the loop never ends.

The condition in the figure is the question counter <= n ?. counter starts at 1 and increases by 1 in every iteration. Eventually it passes n and the condition becomes false. This progress is what guarantees that the loop ends. When writing a loop, it should be clearly visible where each of the four parts is. If one of the parts is missing or wrong, the loop either does not run at all, runs one iteration too few or too many, or never ends.

Definition 8.2

A counter is a variable that changes by a fixed amount (usually 1) in every iteration and shows how many iterations have run or which element is next. An accumulator is a variable that, in every iteration, adds a new value to itself or multiplies itself by it. A sum accumulator starts from 0 and a product accumulator from 1.

The reason for the starting values is simple. 0 is the identity element of addition: adding a number to 0 gives that number. The identity element of multiplication is 1. If a product accumulator is mistakenly started at 0, every iteration multiplies by 0, so the result is always 0.

8.2The for loop

8.2.1Syntax and order of execution

When the number of repetitions is known in advance, the most suitable loop is the for loop. Three of the four parts, initialization, condition, and update, are written on the same line, inside the parentheses after the word for. The parts are separated by semicolons. The body goes between braces. The following program adds the numbers from 1 to n:

int n = 4;
int sum = 0;
for (int i = 1; i <= n; i++) {
    sum += i;
}
System.out.println(sum);

When the program runs, only the sum is printed on the screen:

10

Figure 8.2 shows the flow of this program. Although the parts of a for loop are written side by side in the code, they do not run in the order in which they are written. The actual order of execution is as follows:

  1. int i = 1 runs. This step happens only once, when entering the loop.
  2. The condition i <= n is asked. If it is true, the body is entered; if it is false, the loop ends.
  3. The body sum += i runs.
  4. The update i++ runs and the flow returns to step 2, the condition.

In short, the order is “initialization → condition → body → update → condition → body → update …”. The update is written before the body inside the parentheses but always runs after the body. This detail is very important when tracing a loop by hand.

The variable i defined in the header has one more property: it lives only inside the loop. The region of the program in which a variable can be used is called its scope. The scope of an i defined as for (int i = 1; …) is the loop itself. If System.out.println(i); is written after the loop, the compiler does not recognize i and reports an error. If the value of i is needed after the loop, i must be defined before the loop: int i; for (i = 1; i <= n; i++) ….

In general, in a for loop where i increases from 1 to n, the body runs n times and the condition runs n + 1 times. The initialization runs only once.

Common mistake

Defining the accumulator inside the loop. If the line int sum = 0; is moved into the body, two problems arise. First, every iteration resets the sum to 0 and the work of the earlier iterations is lost. Second, the scope of the sum is limited to the body and the println(sum) after the loop does not compile. The accumulator is always defined before the loop and gets its starting value there.

8.2.3Flexible forms of the for header

The three parts of the for header do not always have to be of the form “start at 1, increase by 1”. The counter can start from any value, increase by twos, or count backward. In the initialization part, several variables of the same type can be defined; in the update part, several expressions separated by commas can be written. Table 8.2 gives three example headers and the values they produce.

In the first row there are two counters: i advances from the start and j from the end. In every iteration i increases by 1 and j decreases by 1. The condition i < j stops the loop when the two counters meet. After the iteration (4,5), i = 5 and j = 4; 5 < 4 is false. This pattern is often used in algorithms that move from both ends of an array toward the middle.

Each of the three parts is optional. All three can even be left empty. If the condition part is empty, Java treats it as true and the loop does not end on its own. In such a loop the exit must be provided by a break in the body:

int k = 0;
for (;;) {            // all parts empty: always true
    k++;
    if (k == 3) break;  // exit is required
}
System.out.println(k);   // 3

k increases by 1 in every iteration and when it reaches 3, break ends the loop. The program prints 3. That the parts can be left empty is a convenience but reduces readability. For a job with a counter, an ordinary for header with all three parts filled in is always clearer.

8.2.4i++ versus ++i

Java has two short ways of increasing a variable by 1: i++ (post-increment) and ++i (pre-increment). Both increase i by 1. The difference is in the value of the expression. The expression i++ gives the old value of i and then increases i. ++i first increases i and then gives the new value. Table 8.3 shows this difference with four small examples.

In the first two rows a becomes 6 in both cases; only the value that goes to b differs. In the last two rows idx becomes 1 in both cases. d[idx++] uses the old index (0) and gives 10. d[++idx] first raises the index to 1 and gives 20.

In the update part of a for header, however, the value of the expression is not used anywhere; only its side effect, the increase of i, matters. That is why there is no difference between the following two loops:

for (int i = 0; i < 3; i++) System.out.print(i + " ");   // 0 1 2
for (int i = 0; i < 3; ++i) System.out.print(i + " ");   // 0 1 2

Both print 0 1 2. For readability, i++, the customary form for counters, is preferred. The difference between the two forms appears only when the value of the increment expression is used inside another expression. Such nested use makes code harder to read and is a habit to avoid.

8.3The while loop

8.3.1Syntax and order of execution

The for loop offers a comfortable notation when the number of repetitions is known. In some problems, however, the number of iterations needed is not known in advance. Processing the digits of a number one by one is like that: one iteration is needed for 7 and three for 725. Asking questions until the user makes the right guess is also like that. In these cases the while loop is a more natural choice. After the word while, only the condition is written in parentheses. The initialization comes before the loop and the update is inside the body.

Definition 8.3

The while loop is a loop written as while (condition) { body } that asks the condition before every iteration. The body runs as long as the condition is true. Loops whose condition is asked before the body are called pre-test loops; the for loop is also a pre-test loop.

The following program computes the value of 5!, that is, the product 5 × 4 × 3 × 2 × 1:

int num = 5;
int factorial = 1;
while (num > 1) {
    factorial *= num;
    num--;
}
System.out.println(factorial);

Figure 8.4 has the same form as the for diagram. Only the way the code is written changes: the parts gathered in the header of a for loop are spread over three separate places here. This scattering is the only risk of the while loop. The update inside the body can be forgotten. If that happens, the condition never changes and the loop never ends.

Because the condition is asked before the body, the body of a while loop may never run. If num = 1 is given in the program above, the first check 1 > 1 is false. The body is never entered and 1 is printed. This result is correct, because 1! = 1. In the same way, 1 is printed for num = 0, which agrees with the definition 0! = 1.

The body ran 4 times. The condition num > 1 was chosen because multiplying by 1 does not change the result; num >= 1 would have given the same result and would only have run one extra iteration. Here the counter advances downward. Because the update is num--, num decreases by 1 in every iteration and finally drops to 1. It is this progress that makes the loop end.

The same computation can also be written with for: for (int i = 2; i <= 5; i++) factorial *= i;. Both forms are correct. Because the number of repetitions is known in advance, for is slightly more readable here. The factorial grows very fast: 12! = 479,001,600 fits in an int, 13! = 6,227,020,800 does not. An int can hold at most 2,147,483,647. If 13! is computed with int, Java gives no error; the value silently wraps around and a wrong number such as 1932053504 is printed. That is why long is used in factorial computations. A long is enough up to 20!; 21! does not fit in a long either.

8.4The do-while loop

8.4.1Syntax and order of execution

In some jobs, the body has to run at least once. Consider a menu program. The user cannot make a choice before the menu is printed on the screen; and until the choice is made, the answer to the question “should we exit?” is not known. For this kind of job Java has the do-while loop.

Definition 8.4

The do-while loop is a loop written as do { body } while (condition); that asks the condition after every iteration. The body runs once without looking at the condition; the later iterations depend on the condition. Such loops are called post-test loops.

The following program reads a choice from the user. If the choice is 1, it prints “Hello!”. It repeats this until the user enters 0:

Scanner in = new Scanner(System.in);
int choice;
do {
  System.out.print("Choice (1/0): ");
  choice = in.nextInt();
  if (choice == 1)
    System.out.println("Hello!");
} while (choice != 0);
System.out.println("Goodbye");

The Scanner class is used to read from the keyboard. The line import java.util.Scanner; must be written at the top of the file. The call in.nextInt() waits until the user enters an integer and presses Enter, and returns the number entered.

When Figure 8.5 is compared with the for and while diagrams, the difference is seen at once: the decision box is not at the start of the loop but at its end. The variable choice has been declared before the loop but has not been given a value. Java does not allow an unassigned local variable to be read. No problem arises here, because the condition is asked for the first time after the body, and by that time the line choice = in.nextInt(); has certainly run.

Two details need care in the syntax. First, there is a semicolon at the end of the line while (choice != 0); in for and while loops there is no semicolon at this place. Second, the variable used in the condition must be declared before the loop. If choice had been declared inside the body, its scope would have been limited to the body and it could not have been used in the while line.

If the value entered is outside the range, the question is repeated: do { grade = sc.nextInt(); } while (grade < 1 || grade > 5);. For the input 7, 0, 3 the loop runs three iterations and exits with grade = 3.

Common mistake

Using do-while where the body must not run at all. If the condition is false on the first try, while and do-while behave differently. In the following two loops the condition is false from the start (n = m = 5, limit 3). The do-while still runs once, prints 5, and makes n 6. The body of the while loop never runs and m stays 5. The output is 5 | 6 5. In every case where the body may run zero times, a pre-test loop is chosen.

int n = 5;
do {
    System.out.print(n + " ");
    n++;
} while (n < 3);

int m = 5;
while (m < 3) {
    System.out.print(m + " ");
    m++;
}
System.out.println("| " + n + " " + m);

8.4.3Which loop to choose?

The three loops can be converted into one another. Every for loop can be written as a while loop, and every while loop as a for loop. A do-while can also be written as a while loop with a copy of the body placed in front of it. So the choice is not a matter of capability but of readability. The right loop answers the reader's question “when and how many times does this loop run?” by the shortest route.

Table 8.6: Typical situations and the suitable loop.

There are two options in the last row, because both solutions look natural. The solution written with while reads the first number before the loop and the next one at the end of the loop. The solution written with do-while puts the reading at the start of the body but needs a separate check in the body so that the 0 is not added to the sum. Whichever looks clearer is chosen.

8.5break and continue

8.5.1Skipping an iteration and leaving a loop

A loop normally ends only when its condition is false, and the whole body runs in every iteration. Two statements change this arrangement.

Definition 8.5

break ends the nearest enclosing loop at once; execution continues from the first statement after the loop. continue skips only the rest of that iteration. In a for loop the flow goes to the update (i++), and in a while or do-while loop to the condition; the loop continues.

The following loop counts from 1 to 10. It skips the multiples of 3 and stops when it reaches 8:

for (int i = 1; i <= 10; i++) {
    if (i % 3 == 0) continue;
    if (i == 8) break;
    System.out.print(i + " ");
}
System.out.println("| done");

If the same job can be written clearly with a condition or a flag variable, that way is preferred. The condition prime && i <= n / i in the prime test is an example of this.

8.5.3Labeled break

A plain break ends only the nearest enclosing loop. In two nested loops, a break in the inner loop does not stop the outer loop. When it is necessary to leave both loops at once, Java's labeled break statement is used. A name and a colon are written in front of the outer loop; break name; ends the loop that carries that name.

outer:
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 3; j++) {
        if (i * j == 4) break outer;
        System.out.println(i + " " + j);
    }
}
System.out.println("done");

The label can be any valid Java name; common choices are descriptive names such as outer or search.

8.6Loop errors and verification

Loop errors are often not caught by the compiler. The program compiles, runs, and either gives a wrong result or never ends. This section treats four typical problems: infinite loops, double counters, a broken loop invariant, and boundary errors.

8.6.1Infinite loops

Definition 8.6

An infinite loop is a loop that does not end on its own because its condition never becomes false. The program seems “frozen”: it either prints nothing or prints the same lines endlessly.

Figure 8.9 shows two typical causes. In the first, the update goes in the wrong direction. In the loop for (int i = 0; i < 5; i--), i decreases in every iteration and i < 5 stays true. In the second, the update has not been written at all. If the body of while (i < 5) { … } has no statement that changes i, the condition keeps its value from the first iteration.

The first loop is infinite in theory. In reality, however, int is a bounded type. When i, after dropping to −2,147,483,648, is decreased once more, overflow occurs and the value wraps around to the largest int, 2,147,483,647. This value is not less than 5 and the loop ends. The number of iterations counted with JDK 21 is below:

A modern computer can finish this many iterations in a few seconds; if there is printing in the body it takes hours. In practice this loop too counts as infinite and is not a correct program.

Sometimes a loop is deliberately written as infinite: while (true). Servers, game loops, and reading with a sentinel value use this form. The body of such a loop must certainly have a break condition. If a program gets stuck in an infinite loop, it is stopped on the command line with the Ctrl+C keys; development environments have a stop button for this.

Common mistake

Forgetting the braces. In the line int i = 0; while (i < 5) System.out.print(i); i++;, the body is only the statement print(i). Indentation, or being written on the same line, does not make i++ part of the body. i stays 0 and 0 is printed endlessly. Using braces in loops even when the body is a single statement prevents this mistake from the start.

8.6.2The double counter trap

8.6.3The loop invariant

It is useful to try a loop with a few inputs, but it is impossible to try every input. One way to see that a loop gives the right result for every input is to find a property that stays true unchanged in every iteration.

Definition 8.7

A loop invariant is a property that is true at the start of every iteration of the loop. It is true when entering the loop; an iteration does not break it; and when the loop ends it is still true and at that moment gives the desired result.

In the sum loop from 1 to n, the invariant is this: at the start of every iteration, sum = 1 + 2 + … + (i − 1). That is, sum is the sum of the numbers processed so far. Table 8.11 checks this property at the start of every iteration for n = 4.

The correctness of the invariant is shown in three steps:

  1. Initialization. Before the first iteration, i = 1 and sum = 0. 1 + … + 0 is an empty sum with no terms, and its value is 0. The invariant is true from the start.
  2. Maintenance. Suppose that at the start of an iteration sum = 1 + … + (i − 1). The body adds i to the sum: sum = 1 + … + (i − 1) + i. The update increases i by 1. Written with the new i, this is again of the form 1 + … + (i − 1). The invariant is true at the start of the next iteration too.
  3. Termination. The loop ends when i = n + 1. Writing n + 1 in place of i in the invariant gives sum = 1 + 2 + … + n. This is exactly the desired result.

None of the three steps depends on a specific value of n. That is why the argument holds for every n. In the exponentiation loop the invariant is “at the start of every iteration result = basei”, and in the factorial loop it is “factorial is the product of the numbers multiplied so far”. Being able to state the invariant in one sentence when writing a loop means really knowing what the loop does.

8.6.4Boundary errors

The most common loop error is running one iteration too few or too many. Should the counter start at 0 or 1, should the condition be < or <=? A mistake in these small choices causes the loop to skip the first or last element or to process an extra one.

Definition 8.8

An off-by-one error is an error that appears when a loop runs one iteration fewer or one more than the correct number. It mostly arises from choosing the starting value (0 or 1) or the comparison operator (< or <=) wrongly.

The way to prevent boundary errors is a simple check. After a loop is written, three questions are asked: what value does the counter take in the first iteration, what value does it take in the last, and how many iterations does it run in total? In the form for (int i = a; i < b; i++) the number of iterations is b − a, and in the form for (int i = a; i <= b; i++) it is b − a + 1. These two formulas catch most boundary errors without running the code.

8.7The digit pattern

Most problems solved with loops rest on a few common patterns. Once a pattern is understood, the same skeleton is reused in different problems with small changes. All the examples in this section process the digits of an integer one by one. Counting digits, summing digits, reversal, palindromes, Armstrong numbers, and decimal-to-binary conversion are variations of the same loop.

Definition 8.9

A pattern is a solution skeleton that recurs in many problems. A loop pattern determines the type of the loop, its starting values, its condition, and its update; from problem to problem only the operation in the body changes.

8.7.1% 10 and / 10

Two integer operations lie at the base of the pattern. For a positive integer, num % 10 gives the remainder of dividing the number by 10, that is, the last digit: 725 % 10 = 5. num / 10 is integer division; the fractional part is discarded and the last digit is removed: 725 / 10 = 72. When the two operations are applied one after the other, the number is “consumed” digit by digit from right to left:

725 → (5) → 72 → (2) → 7 → (7) → 0

When the number is 0, no digits are left to process. The skeleton of the pattern rests on this observation:

while (rest > 0) {
    int digit = rest % 10;   // take the last digit
    // ... do something with the digit ...
    rest /= 10;                // drop the last digit
}

The loop runs as many iterations as the number has digits. For a six-digit number, 6 iterations are enough. That is why the digit pattern is fast even for very large numbers: the largest int has ten digits and the loop runs at most 10 iterations.

Two details are repeated in every example. First, the loop consumes not the number itself but a copy of it (rest). When the loop ends, rest is 0 but the original number is preserved; in the palindrome and Armstrong tests the result is compared with it. Second, the sign of negative numbers is dropped first. In Java −725 % 10 = −5; the remainder takes the sign of the dividend. If the sign is not dropped, the condition while (rest > 0) is false from the start and the loop never runs.

8.7.6Converting decimal to binary

8.8.3The prime test

Definition 8.13

An integer greater than 1 that has no positive divisor other than 1 and itself is called a prime number. 0 and 1 are not prime; 2 is the only even prime.

int n = 29;
boolean prime = n >= 2;
for (int i = 2; prime && i <= n / i; i++) {
    if (n % i == 0) prime = false;
}
System.out.println(prime);

There is an idea in every line of the code. The assignment prime = n >= 2 eliminates 0, 1, and negative numbers from the start. The loop searches for a divisor starting from 2. When a divisor is found, prime = false and the prime && in the condition stops the loop. A flag is used here instead of break. The flag keeps the state in a logical variable and makes the exit condition of the loop visible in the header.

The second idea is the limit of the search. If n has a divisor other than 1 and itself, at least one of these divisors is not greater than √n. Because if n = a × b, a and b cannot both be greater than √n; if they were, their product would exceed n. So it is enough to try i up to √n. The i <= n / i in the condition means the same as i × i ≤ n, but i * i can overflow for a very large i; the division does not overflow.

for (int i = 0; i < terms; i++) {

8.9Loops that work with input

In the loops so far, the number of iterations depended on numbers inside the program. In loops that read input from the user, the user decides when the loop ends. In these loops the number of iterations is not known in advance, and the natural choice is while or do-while.

8.9.1A number guessing game

The computer keeps a secret number between 1 and 100. The user guesses; the program guides by saying “Higher” or “Lower”. When the guess is right, the number of the try is printed.

Random rnd = new Random();
Scanner in = new Scanner(System.in);
int target = rnd.nextInt(100) + 1;  // 1..100
int guess = 0, tries = 0;
while (guess != target) {
  guess = in.nextInt();
  tries++;
  if (guess < target) System.out.println("Higher");
  if (guess > target) System.out.println("Lower");
}
System.out.println("Got it in " + tries + " tries");

The java.util.Random class is used to generate random numbers; two import lines, for Random and Scanner, are needed at the top of the file. rnd.nextInt(100) gives a number from 0 to 99; adding 1 makes the range 1..100. A different target comes out on every run.

The reason for giving guess = 0 before the loop is the condition. Because the target is between 1 and 100, 0 can never be the target. So guess != target is certainly true at the first check and the loop is entered. The same job could also be written with do-while; in that case this artificial starting value would not be needed.

8.9.2Reading with a sentinel value

If the user does not say in advance how many numbers they will enter, how can the end of the data be recognized? The common solution is to use a special value that cannot be data as the “finished” marker.

Definition 8.15

A sentinel value is a special value that marks the end of a data sequence and does not itself take part in the data. A sentinel value must be a value that real data can never take.

Scanner sc = new Scanner(System.in);
int sum = 0;
while (true) {
    int num = sc.nextInt();
    if (num == 0) break;
    sum += num;
}
System.out.println("Sum: " + sum);

Common mistake

Checking the sentinel after processing, or choosing a value that could be data as the sentinel. If the line sum += num; is written before the if, the sentinel is also added. While the sentinel is 0 this makes no difference, but if the sentinel were −1, the sum would come out 1 short. In a program such as a grade average, however, 0 can be a real grade. If 0 is chosen as the sentinel, the grade of a student who got 0 is interpreted as “the data is finished”. In such cases a sentinel outside the data range, such as −1, is chosen.

A typical extension of reading with a sentinel is computing an average. Besides the sum, a counter is kept, and after the loop the average is computed as sum / count. Two details must not be forgotten: if no numbers were entered (count = 0), no division is done, and a (double) cast is made before the division. For the input 80, 64, 90, 0 the sum is 234 and the average is 78.0; for 6, 9, 0 the average is 7.5. Without the cast, integer division would give 15 / 2 = 7.

8.10Nested loops

8.10.1Rows and columns

The body of a loop can contain another loop. This structure is called a nested loop. The outer one is called the outer loop and the inner one the inner loop. Tables, grids, multiplication tables, and screen patterns have a row-and-column layout; the natural tool for such output is a nested loop.

for (int row = 0; row < 3; row++) {
  for (int col = 0; col < 4; col++) {
    System.out.printf("(%d,%d) ", row, col);
  }
  System.out.println();
}
(0,0) (0,1) (0,2) (0,3) 
(1,0) (1,1) (1,2) (1,3) 
(2,0) (2,1) (2,2) (2,3)

The basic rule of a nested loop is this: the inner loop runs from start to finish in every iteration of the outer loop. When row = 0, the inner loop runs four times for col = 0, 1, 2, 3 and prints four cells from (0,0) to (0,3). When col becomes 4, the inner loop ends. Then println() ends the line. The outer loop moves to 1 with row++ and the inner loop starts again from col = 0. Because the variable col is defined in the header of the inner loop, it is created anew in every outer iteration and gets the value 0.

The inner body runs a total of number of rows × number of columns = 3 × 4 = 12 times. The %d placeholders in printf are filled in order with the values given after the comma. println(), however, is in the body of the outer loop but outside the inner loop. This position makes the output move to the next line once at the end of each row.

The limit of the inner loop can depend on the variable of the outer loop. In that case the number of times the inner body runs is a sum rather than a product. For example, if i runs from 1 to 4 and j from i to 4, the inner body runs 4 + 3 + 2 + 1 = 10 times. The growing triangle pattern is an example of this structure.

        System.out.printf("%4d", i * j);
    }
    System.out.println();

   2   4   6

When the outer loop has i = 1, the inner loop prints 1, 2, 3 for j = 1, 2, 3. At j = 4 the inner condition becomes false and println ends the line. The same job is repeated for i = 2 and i = 3. The format %4d aligns the numbers in columns: three spaces are added in front of one-digit numbers and two in front of two-digit numbers. When the limits are made 10, the classic 10 × 10 multiplication table comes out; because the largest number is 100, a field of 4 characters is still enough.

8.11Patterns

Screen patterns made of stars or numbers are a classic subject of nested-loop exercises. The patterns themselves are not important; what matters is expressing the layout of an output in numbers and turning those numbers into loop limits. This skill is also needed when working with tables, reports, and matrices.

Definition 8.16

A pattern is output written line by line in which the number of spaces and characters in each line changes regularly with the line number. The outer loop produces the lines, and the inner loops produce the space and character parts of a line.

8.11.1A method for solving pattern problems

A pattern is turned into code in four steps:

  1. Draw. The expected output is drawn on graph paper for a small n (for example n = 4). Each square is one character; spaces count as squares too.
  2. Count. The numbers of spaces and characters in each row are written in a table.
  3. Relate. The numbers are related to the row number. For example, the sequence 3, 2, 1, 0 is n − row, the sequence 1, 2, 3, 4 is row, and the sequence 1, 3, 5, 7 is 2 × row − 1.
  4. Code. The outer loop runs as many times as there are rows. For each part of a row (spaces, stars) an inner loop is written; the limit of the inner loop is the formula found in step 3. At the end of the row, println is called.

8.11.5Common mistakes in patterns

Common mistake

Putting the println call inside the inner loop. In that case the line ends after every star. For n = 3, instead of the growing triangle, 1 + 2 + 3 = 6 lines come out one under the other, with a single star in each. println must be written after the closing brace of the inner loop, inside the outer loop.

Other typical mistakes in patterns are these. If < and <= are confused, one character too few or too many comes out in every row; if the counter starts at 0, < is used, and if it starts at 1, <=. If the space loop is written after the star loop, the spaces fall at the end of the row, are invisible, and the pattern is left-aligned. If the variable of the outer loop is changed by mistake in the inner loop (for example, if row++ is written in the inner header), rows are skipped or the loop never ends. Every pattern is protected from these mistakes by checking it row by row with a trace table for a small n.

8.12Test design

That a loop works correctly with a single input does not show that it will work correctly with every input. Loop errors usually appear at the boundaries: in cases where it should not run at all, run one iteration, or process the largest value. A good test set contains an example of each of these cases.

Definition 8.17

A test case is a pair of an input chosen for a program and the output expected for that input. An edge case is a value at the end of the input range or one that requires special behavior: 0, 1, negative numbers, and the largest or smallest value of a type.

A test set is prepared with these steps:

  1. For each problem an ordinary, “normal” value is chosen.
  2. 0, 1, negative values, and values close to the upper limit are chosen separately.
  3. For each input, the expected result is computed by hand, without running the code.
  4. The program is run. If the result differs from the expected one, the variables are traced iteration by iteration and the iteration in which the first deviation occurs is found.

The same thinking applies to every loop. A sum loop is tried with n = 0 (no iterations), n = 1 (a single iteration), and a large n. A prime test is tried with 0, 1, 2, 4, a square number (for example 25), and a large prime. A pattern program is also run with n = 1 and n = 0. Each of the cases in which the loop runs zero times, once, and many times must be covered by at least one test.

8.13Summary

  • Every loop consists of four parts: initialization, condition, body, and update. The update brings the condition closer to its end; if it is forgotten, the loop never ends.
  • In the for loop, the three parts are gathered in the header and the order is “initialization → condition → body → update → condition …”. In a for loop running from 1 to n, the body runs n times and the condition n + 1 times.
  • while asks the condition before the body and do-while after the body. The body of a while may never run; the body of a do-while runs at least once.
  • If the number of repetitions is known, for is chosen; while the condition holds, while; if at least one iteration is needed, do-while. The three can be converted into one another; the choice is for readability.
  • break ends the nearest loop, and continue skips only the rest of that iteration. A labeled break leaves nested loops at once.
  • An infinite loop arises from an update in the wrong direction or one that is never made. A double counter accumulates rounding error; the loop counter should be an int.
  • A loop invariant is a property that stays true at the start of every iteration; when the loop ends it shows that the result is correct. Against boundary errors, the first iteration, the last iteration, and the number of iterations are checked.
  • The digit pattern (% 10 gives the last digit, / 10 removes it) is used for digit counts, sums of digits, reversal, palindromes, Armstrong numbers, and changing the base.
  • The divisor pattern rests on the check n % i == 0. For perfect numbers it is enough to search up to n / 2, and for the prime test up to √n.
  • A sentinel value is a value that cannot be data; it marks the end of the data and is not itself processed.
  • In a nested loop, the inner loop runs from start to finish in every iteration of the outer loop. In patterns, the outer loop produces the row and the inner loops produce the spaces and characters in the row; the numbers are tied to the row number.
  • Loops are tested with normal, 0, 1, negative, and extreme values; the expected result is computed by hand beforehand.

8.15Try it yourself

  1. What does the loop for (int i = 2; i <= 20; i *= 3) System.out.print(i + " "); print? How many times do the body and the condition run?

    Answer

    i takes the values 2, 6, 18 in turn and 2 6 18 is printed. After 18, i = 18 × 3 = 54 and 54 <= 20 is false. The body runs 3 times and the condition 4 times. The update does not have to be an increase by 1; here the counter advances by multiplication.

  2. After the loop int x = 1; while (x < 100) x *= 2;, what is x? How many iterations does the loop run?

    Answer

    x becomes 2, 4, 8, 16, 32, 64, 128 in turn. Because 64 < 100 is true, one more iteration runs and x = 128; 128 < 100 is false. The loop runs 7 iterations and x = 128. The loop ends at the first value that makes the condition false; this value may have passed the limit.

  3. After int k = 10; do { k -= 4; } while (k > 0); runs, what is k? How many times does the body run? What would happen if the same loop were written as while (k > 0) k -= 4; with the starting value k = −1?

    Answer

    k becomes 6, 2, −2 in turn. The condition is asked at the end of each iteration; it is true for 6 and 2 and false for −2. The body runs 3 times and k = −2. In the while loop starting with k = −1, −1 > 0 is false from the start; the body never runs and k stays −1. With the same starting value, a do-while would run once and k would be −5.

  4. What does the following loop print? for (int i = 1; i <= 10; i++) { if (i % 2 == 0) continue; if (i > 7) break; System.out.print(i + " "); }

    Answer

    Even numbers are skipped with continue. Of the odd numbers, 1, 3, 5, and 7 are printed. At i = 9, 9 is odd, the first condition is false, 9 > 7 is true, and break ends the loop. The output is 1 3 5 7. Because i = 8 is skipped with continue, break gets its turn at 9, not at 8.

  5. With the digit pattern, what are the sum of digits and the reverse of 4096? What do the reverse of 1200 and the palindrome test give? What do the reverse and the palindrome test give for 0?

    Answer

    4096: the digits from right to left are 6, 9, 0, 4. The sum is 6 + 9 + 0 + 4 = 19 and the reverse is 6904; because 6904 ≠ 4096, it is not a palindrome. 1200: the digits are 0, 0, 2, 1 and the reverse is built as 0 → 0 → 2 → 21; the result is 21 and it is not a palindrome. For 0 the while loop never runs; rev stays 0 and because 0 == 0, the test gives true. 0, as a one-digit number, really is a palindrome.

  6. After the following nested loop, what is count? for (int i = 1; i <= 4; i++) for (int j = i + 1; j <= 4; j++) count++; (count is 0 at the start)

    Answer

    For i = 1, j = 2, 3, 4 (3 iterations); for i = 2, j = 3, 4 (2 iterations); for i = 3, j = 4 (1 iteration); for i = 4 the inner loop never runs (5 <= 4 is false). The total is 3 + 2 + 1 + 0 = 6. This number is the number of different pairs that can be chosen from 4 elements: 4 · 3 / 2 = 6.
