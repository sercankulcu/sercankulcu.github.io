Chapter 6: Variables, Data Types and Operators

Every program works with data: a student's age, the price of a product, the average of an exam. A program keeps this data in named boxes in memory, that is, in variables. Every box has a type, and the type determines which values fit in the box. This chapter describes how to declare variables and give them values in Java, the eight primitive types and their ranges, the overflow that occurs when a limit is exceeded, and why decimal numbers cannot be stored exactly. Next come conversions between types, integer division, arithmetic, comparison and logical operators, operator precedence, and short-circuit evaluation. The last sections cover reading data from the keyboard with Scanner, producing formatted output with printf, and small programs that combine these tools. All Java code in the chapter was compiled and run with JDK 21; the outputs shown are the programs' actual outputs.

6.1Variables

Someone who uses a calculator to find the average of the scores 70, 85, and 90 first adds the three numbers, keeps the intermediate result on the display, and then divides by 3. It is also possible to write the intermediate result on a piece of paper. A computer program has the same need: it must store the numbers it reads, the intermediate results, and the final answer somewhere. That place is memory. The program gives a name to every place it sets aside in memory and reaches that place by its name.

6.1.1What is a variable?

Definition 6.1

A variable is a named box in memory set aside for a value of a certain type. A variable has three properties: its name, its type, and its current value. The name and type stay fixed throughout the program; the value can change.

Figure 6.1 shows these three properties together. The name age above the box is the name the programmer has given to this box; in Java it is called an identifier. The value 20 inside the box can change while the program runs: when a new year begins, the age becomes 21. The int below the box is the type. A type determines two things. The first is the size of the box: for int, 32 bits, that is 4 bytes, are allocated. The second is the values that can be put in the box: int is an integer type, so 20 can be put in this box but 20.5 or “twenty” cannot.

The name “variable” comes from mathematics, but its meaning is slightly different. In mathematics, x = x + 1 is an equation with no solution. In programming, this line is a command: “read the value in box x, add 1, and write the result back into box x.” A variable is a box that can hold different values over time; the equals sign is not a claim of equality but a write operation.

6.1.2Declaration and initial value

In Java, a variable must be declared before it is used. A declaration tells the compiler, “I want a box with this name and this type.”

Definition 6.2

A declaration is a statement that specifies the type and name of a variable: int age;. Initialization specifies the variable's starting value. The two can also be written in a single statement: double avg = 82.5;.

The four lines in the slides show different forms of declaration:

int age;          // declaration
age = 20;        // assignment
double avg = 82.5; // both
final int MAX = 100; // constant

The first line is only a declaration: an int box named age is set aside, but no value has been put into it yet. The second line is an assignment: the value 20 is written into the age box. The third line combines the declaration with the initial value; the avg box is set aside and receives the value 82.5 at the same time. The final keyword in the fourth line turns the box into a constant: MAX receives the value 100 once and keeps it throughout the program.

Java calls variables declared inside a method local variables. There is a strict rule for local variables: a variable must definitely have been given a value before it is read. The compiler checks this rule by reading the code, without running the program. The following two-line fragment therefore does not compile:

int age;
System.out.println(age);
error: variable age might not have been initialized
System.out.println(age);
                   ^
1 error

The message says “the variable age might not have been given a value”. The compiler sees that the age box is empty and does not produce the program at all. This rule is a safety measure. Without it, the program could read whatever value happens to be in the box at that moment and produce meaningless results. In some older languages (C, for example) this really happens.

A similar check exists for final variables. Once a value has been given, a second assignment is a compile error:

final int MAX = 100;
MAX = 200;
error: cannot assign a value to final variable MAX
MAX = 200;
^
1 error

Constants are used for values that occur in several places in a program and must not change: the highest score, the VAT rate, the size of an array. Defining a constant instead of writing the number separately everywhere has two benefits. The code becomes readable; the expression score <= MAX says more than score <= 100. Also, if the value changes, only one line has to be corrected.

Common mistake

Assuming that a declared variable automatically gets the value 0. In Java, local variables do not get a value on their own; writing total += 5; after the line int total; gives a “might not have been initialized” compile error. A variable that will hold a running total is explicitly started at zero: int total = 0;.

6.1.3Variables in memory, step by step

The best way to see how variables receive and change values is to trace a program line by line. The example program from the slides is:

age = 20;                 // first assignment
age = age + 1;            // update
double avg = 82.5;        // declare + initialize
avg += 5;                 // compound assignment
final int MAX = 100;      // constant
System.out.println(age);
System.out.println(avg);

The program produces two lines of output:

21
87.5

The third line must be read carefully. The statement age = age + 1; runs in two stages. First the expression to the right of the equals sign is evaluated: the 20 in the age box is read and 1 is added, giving 21. At this stage the box has not changed yet. In the second stage the value 21 is written into the box on the left; the old 20 is erased. A box holds only one value at a time, and the new value overwrites the old one.

In the final state there are three boxes in memory and two lines of output on the screen. If MAX = 200; were written after the sixth line, the program would not compile; the value of a final variable is given once.

6.1.4Assignment and updating

The assignment operator = is Java's most frequently used operator and always works in the same order: first the right side is evaluated, then the value is written into the variable on the left. On the left side there is always a single variable. Lines such as 5 = x; or x + 1 = 7; are meaningless, because 5 and x + 1 are not boxes.

The assigned value must be compatible with the variable's type. The string "Ada" cannot be assigned to an int box; the compiler reports this as a type mismatch error.

In programs it is very common to change a variable's value by using its own old value: adding a new price to a total, increasing a counter by one, subtracting an amount from a balance. Java has a short notation for this.

Definition 6.3

A compound assignment is an operator that combines an arithmetic operation with an assignment: +=, -=, *=, /=, %=. The statement total += price means total = total + price.

Figure 6.4 shows the steps of the operation. The variable on the right (price) is only read; the variable on the left (total) is both read and written. Compound assignment has one more subtlety: the right side is evaluated completely before the operation. The statement i *= 3 + 7 means i = i * (3 + 7), not i = i * 3 + 7. For i = 5 the result is 50, not 22.

Example 6.1

In a shopping cart, the total starts at 0 TL. Two items, one of 45 TL and one of 30 TL, are added in turn, then a discount of 10 TL is applied, and finally the amount is divided into 2 installments. Which statements are written, and what is total after each step?

The result in the last row is 32, not 32.5. Because total is an int, the division is integer division and the fraction is discarded. If the installment amount must be computed down to the hundredth of a lira, the variable must be chosen as double from the start. The quotient of two integers in Java is always an integer.

6.1.5Identifier rules and naming

The names given to variables, methods, and classes are all identifiers. Java limits how an identifier may be written with a few strict rules. A name that violates these rules causes a compile error.

An identifier starts with a letter, an underscore (_), or a dollar sign ($); the following characters can also include digits. A name that starts with a digit confuses the compiler. In the line int 1student = 5; the compiler expects a name after int but meets the digit 1 and cannot make sense of the line:

error: not a statement
int 1student = 5;
^
error: ';' expected
int 1student = 5;
   ^
2 errors

The messages do not state the problem directly; they say “this is not a statement” and “a semicolon was expected”. The compiler reports the error where it finds it, in the way it understands it. That is why, when reading a compiler message, you should look at the whole line the message points to.

Keywords are words that Java reserves for its own purposes: int, double, class, if, final, new, return are a few of them. These words cannot be used as names; the line int class = 5; produces three separate error messages. A lone underscore is not a name in JDK 21 either. The compiler rejects the line int _ = 3; with a message saying that unnamed variables are a preview feature. In newer Java versions _ means “unnamed variable”; in that case too, the variable cannot be reached by its name.

The last rule is the most insidious. Java treats uppercase and lowercase letters as different characters. score and Score are two separate variables and can live side by side in the same program:

int score = 70;
int Score = 90;
System.out.println(score + " " + Score);
70 90

The program compiles without errors and prints two different values. If the programmer thinks they are using the same variable, the error arises silently. For this reason the use of upper and lower case is not left to chance; naming conventions provide this consistency.

Besides the rules the compiler checks, there are also unwritten naming conventions that Java programmers follow. Code that ignores them compiles but tires everyone who reads it.

  • lowerCamelCase: variable and method names. The first word starts with a lowercase letter and the first letter of each following word is a capital: pointsLeft, studentCount, computeAverage. The capital letters between words show the word boundary, like the humps of a camel.
  • UpperCamelCase: class names. Every word starts with a capital letter: StudentGrade, Scanner, String.
  • UPPER_CASE_WITH_UNDERSCORES: final constants. MAXIMUM_MARK, VAT_RATE.

The most important quality of a name is that it describes the role of the value. Names such as x, a1, and temp2 make sense to the person writing the code at that moment; a week later they tell no one anything. The name pointsLeft, on the other hand, hints at both its type and its job. Non-ASCII letters, such as accented ones, are valid in Java identifiers, but in class and in most projects writing with ASCII letters is preferred: student, grade, age. This preference avoids problems that can arise when files move between computers with different character encodings.

Common mistake

Writing pointsLeft in one place and totalscore in another. If the second name has not been declared, the compiler gives a “cannot find symbol” error. Worse, if both names have been declared, the program compiles and the values go into different boxes. Following the naming conventions in the same way everywhere prevents most errors of this kind from the start.

6.2Data types

At the lowest level, memory consists only of bits, that is, 0s and 1s. The bit pattern 01000001 can mean the number 65 in one place and the letter 'A' in another. The type determines how the bits are interpreted. Java requires the type of every variable to be known at compile time. That is why Java is a statically typed language: the compiler checks before the program runs whether every operation fits the types, and it catches many errors already at the first compilation.

6.2.1The basic groups of types

Java types fall into two large families. Primitive types are eight basic types built into the language. In the box of a primitive variable sits the value itself. Reference types are strings (String), arrays, and classes. In the box of a variable of a reference type there is not the object itself but a reference to an object that sits somewhere else in memory.

The groups are chosen according to the nature of the data. Counted values, such as the number of students in a class, a position in an array, or a counter, are integers. Measured values, such as height, temperature, or price, are held as floating-point numbers. A single letter uses char, and a yes/no answer uses boolean. Texts such as names, addresses, and sentences are String objects. This chapter deals mainly with primitive types; String appears only in the context of concatenation and reading input.

6.2.2Primitive types and their sizes

Each of the eight primitive types occupies a fixed number of bits in memory. This number is the same in Java on every computer and every operating system. In some languages, such as C, the size of int can vary from machine to machine; in Java, int is 32 bits everywhere. This consistency makes the same program give the same result everywhere.

The range of a type is computed from its number of bits. With n bits, 2n different bit patterns can be written. For byte there are 28 = 256 different values. Java's integer types are signed: half of these values go to negative numbers, and half go to zero and positive numbers. Because zero takes up a place on the positive side, the range extends from −128 to 127; the number 128 does not fit in a byte. The same computation gives the range −231 … 231 − 1 for int:

231 = 2,147,483,648,   so the int range is −2,147,483,648 … 2,147,483,647

To keep it roughly in mind, the limit of int can be remembered as “about ±2.1 billion” and that of long as “about ±9.2 quintillion” (9.2 × 1018). Although the char type is 16 bits, it is unsigned; it has no negative values and holds the codes from 0 to 65,535.

Values written directly in the program are called literals: 42, 19.90, 'A', true. Literals also have types, and the type can be told from the way they are written:

  • An integer literal without a decimal point (42) is an int. If L is added at the end it becomes a long (42L). A lowercase l is also valid but is not used because it looks too much like the digit 1.
  • A literal with a decimal point (19.90) or one written in scientific notation (3.9e10, that is, 3.9 × 1010) is a double. If F is added at the end it becomes a float (1.5F).
  • In long numbers, underscores can be used to group digits: 8_000_000_000L. Underscores only make reading easier; they do not change the value.

In Java code the decimal separator is always a period. 19.90 is nineteen point ninety in Java; 19,90 is a syntax error. Code fragments and program outputs in this chapter keep exactly the form that Java writes.

Example 6.2

The world population (about 8 billion) is to be held in a variable. Why does the line int population = 8_000_000_000; not compile? Why does the line long population = 8_000_000_000; still not compile?

8 billion is larger than the largest int value, 2,147,483,647; the value does not fit in an int box. But the real problem starts earlier: the literal 8_000_000_000, written without a decimal point and without an L, is itself of type int. While trying to read this literal as an int, the compiler exceeds the limit and reports an error without looking at the type on the left:

error: integer number too large
long population = 8_000_000_000;
                  ^
1 error

Even if the target is long, the message is the same. The correct way is to make the literal itself a long with L: long population = 8_000_000_000L;. This line compiles and System.out.println(population) prints 8000000000.

A similar rule exists for floating-point literals. 1.5 is a double literal; the line float ratio = 1.5; does not compile, with the message “possible lossy conversion from double to float”. When a float is wanted, the literal is written as 1.5F. In most programs this question never arises, because the default choice is already double.

6.2.3How are integers stored in memory?

When choosing an integer type, int is enough in most cases and is the default choice. long is used for large values that int cannot hold: the world population, time in milliseconds, a balance in hundredths of a lira in a bank account. byte and short are usually chosen to save memory in large data arrays. The largest value expected in a computation must be estimated beforehand; a value that may approach the limit of int is made long from the start. The importance of this decision lies in what happens when the limit is exceeded. To understand it, we need a brief look at how integers are represented with bits.

Java stores integers in two's complement representation. In this representation the leftmost bit is the sign bit: if it is 0 the number is zero or positive, and if it is 1 the number is negative. A few examples with byte:

6.2.4Overflow

What happens when the result of an integer operation does not fit in the range of the type? A car's odometer rolls over to 000,000 after 999,999. Java integers behave similarly: the result overflows at one end of the range and re-enters from the other end.

Definition 6.4

Overflow is when the result of an integer operation exceeds the range of the type. In Java, overflow does not cause an error. Only the low bits of the result that fit in the type are stored; the value silently wraps around to the other end of the range.

The example program from the slides shows overflow in both types:

int x = Integer.MAX_VALUE;
x++;
byte b = 127;
b++;
System.out.println(x + " " + b);
-2147483648 -128

Binary addition works by the same carry logic as in the decimal system. When 1 is added to the pattern 0111…1, the sum of the rightmost 1 and 1 is 0 and a carry of 1 remains. The carry moves leftward, zeroing all the 1s, and finally reaches the sign bit. The result is 1000…0. Mathematically the correct answer is 2,147,483,648, but this value is outside the int range. The value of a pattern with sign bit 1 comes out as 2,147,483,648 − 232 = −2,147,483,648. In terms of the odometer analogy, the number overflows at the top of the range and re-enters at the bottom.

There is a subtlety with byte: the result of byte + byte is an int (6.3.5), so b + 1 gives 128 and does not overflow. 8-bit overflow is seen only when the result is brought down to byte with a (byte) cast, or in compound operations such as += and ++; these operations perform the narrowing automatically.

The danger of overflow is that it is silent. The program does not stop and gives no warning; it carries on computing with the wrong number. Overflow does not occur only by adding one to the limit. Even the product of two reasonable-looking numbers can exceed int:

int a = 50000;
int b = 50000;
System.out.println(a * b);
System.out.println((long) a * b);
System.out.println(a * b / 1000);
long wrong = a * b;
System.out.println(wrong);
-1794967296

50,000 × 50,000 = 2,500,000,000 and exceeds the int limit. The first line therefore prints a negative number: 2,500,000,000 − 232 = −1,794,967,296. In the second line the conversion (long) a is made before the multiplication; the operation runs in long and the correct result comes out. The third line shows that overflow also contaminates later operations: the wrong product is divided by 1000 and a wrong quotient is obtained. The fourth line is the most misleading. The result is assigned to a long variable, but the multiplication is still done in int, because the two operands, that is, the two values the operation acts on, are ints. The overflowed result is copied into the long. That the target is a long does not change the type of the operation.

Common mistake

Thinking that writing long result = a * b; makes the multiplication run in long. Java determines the type of an expression only by looking at its operands; it does not look at where the result will be assigned. The product of two ints is an int and overflows if necessary. The correct way is to make one of the operands a long before the operation: long result = (long) a * b; or a * 1L * b.

Writing the limit values of types by hand is both hard and dangerous; a single digit in the number 2147483647 can be mistyped. Java offers these values as ready-made constants:

If you do not want overflow to pass silently, the “exact” methods of the Math class are used. Math.addExact, Math.subtractExact, and Math.multiplyExact perform the operation; if the result does not fit in the type, instead of silently wrapping around they throw an exception. An exception is an error notification that interrupts the normal flow of the program.

int x = Integer.MAX_VALUE;
System.out.println(x + 1);
// -2147483648 (silent overflow)

    Math.addExact(x, 1));
// ArithmeticException:
// integer overflow

The first println shows the silent overflow and prints −2147483648. In the second line Math.addExact(x, 1) is called; because the result does not fit in an int, an ArithmeticException is thrown and the program stops with the message “integer overflow”. For long values the message is “long overflow”. The program stopping looks bad at first glance, but it is much better than continuing with a wrong result: the error is noticed immediately and its location is known.

A surprising example of overflow is the absolute value. Math.abs(Integer.MIN_VALUE) gives −2147483648 again, instead of the expected 2,147,483,648. The cause is that the range is not symmetric: 231, the absolute value of the smallest int, does not fit in an int. Taking its negative causes overflow and the number comes back to itself. The same happens with the expression -Integer.MIN_VALUE.

6.2.6Floating-point numbers

Numbers with a fractional part are stored in Java as floating-point numbers. The name comes from the number being held in a form similar to scientific notation: a series of significant digits and an exponent that indicates where the point goes. In the notation 12,345.678 = 1.2345678 × 104, the point “floats” according to the exponent. This lets the same 64 bits hold both very small (10−300) and very large (10300) numbers.

double is the default type for most approximate computation; it has about 15–16 significant digits. float is half the size and holds about 7 significant digits. The difference is easy to see:

System.out.println(0.1 + 0.2);

6.2.7char and boolean

The char type holds a single character and its literal is written with single quotes: 'A', '7', 'ç'. A computer cannot store letters directly; each character corresponds to a number, and that number sits in the box. This mapping is the job of the Unicode standard. The code of the letter 'A' is 65, that of 'a' is 97, that of the digit '0' is 48, and that of the space character is 32. A Java char is a code unit of the UTF-16 encoding, which stores Unicode text in 16-bit units. All the Turkish letters fit in a single char: 'ç' is stored with code 231, 'ğ' 287, 'ı' 305, 'İ' 304, and 'ş' 351. (Very rarely used characters, such as some emoji, need two chars; this detail does not come up in beginner programs.)

Single quotes and double quotes produce different types. 'A' is a char; the number 65 sits in the box. "A" is a one-letter string, that is, a String object; the variable holds a reference to this object. The two cannot be used in place of each other. The line char c = "A"; does not compile, with the message “String cannot be converted to char”.

The boolean type takes only two values: true and false. The results of comparisons and conditions are booleans. In C, 0 counts as false and every nonzero number counts as true; Java has no such mapping. The line boolean active = 1; gives an “int cannot be converted to boolean” error. This strictness catches a common mistake in conditions at compile time.

6.3Type conversion

Different types often meet in a program. A number of students (int) is multiplied by an average (double), a number (int) is added to the code of a letter (char), a double result is to be written into an int box. At every meeting, Java has to convert a value from one type to another. This operation is called type conversion. Java performs some conversions on its own, while others require the programmer to ask for them explicitly. The criterion for the distinction is a single one: is there a risk of losing information in the conversion?

6.3.1Assignment compatibility: widening and narrowing

Definition 6.5

A widening conversion converts a value to a type with a wider range (for example from int to double). Java performs widening automatically, that is, implicitly. A narrowing conversion converts to a type with a narrower range (for example from double to int). Because narrowing can lose information, it requires an explicit conversion (cast): the target type is written in parentheses in front of the value, (int) 9.8.

Widening is safe, because every value of the narrow type also exists in the wide type. The number 7 can be represented in both int and double; when converted to double it becomes 7.0 and nothing is lost. All of the following assignments compile:

At one link of the chain, however, there is a subtle loss. The step from long to float and from int to float counts as “widening” because the range widens. But float holds only about 7 significant digits. When the number 123,456,789 is converted to float and back, 123,456,792 comes out; the last digits have been rounded. Java gives no warning for this conversion. When working with large integers, choosing double instead of float largely removes the problem.

In narrowing, however, loss of information is the normal case. The double 9.8 does not fit in an int box; the fractional part has to be dropped. Java leaves this decision to the programmer and refuses the assignment unless an explicit cast is written:

The phrase “possible lossy conversion” in the message means that the conversion might lose information. The compiler does not know whether a loss will actually happen; it reports only that it could. When int narrow = (int) ratio; is written, the programmer says explicitly that the loss is accepted, and the line compiles. The same rule applies to literals: the line int x = 5L; gives “possible lossy conversion from long to int” even though the number 5 fits easily in an int, because the type of the literal is long.

A conversion does not change the source variable. The expression (int) ratio reads the 9.8 in the ratio box and produces the value 9; ratio is still 9.8. The conversion affects only the result it produces. Thinking that a conversion permanently changes a variable's type is a common misconception; in Java the type of a variable is determined at the moment it is declared and never changes afterwards.

6.3.5Type promotion

The rule seen in division holds for all binary arithmetic operators.

Definition 6.6

Type promotion is the automatic conversion of a narrower operand to the wider type before the operation in an expression of mixed types. The result is of the wider type: int + double → double, int * long → long. In addition, byte, short, and char operands are first promoted to int in every arithmetic operation.

The second half of the rule is surprising: even the sum of two bytes is an int. Java does no arithmetic directly on these small types; processors work more efficiently with 32-bit operations, and the risk of overflow in the intermediate result is reduced. As a result, the following lines do not compile:

short a = 1, b = 2;
short c = a + b;
error: incompatible types: possible lossy conversion from int to short
short c = a + b;
            ^
1 error

a + b is an int, and narrowing from int to short requires an explicit cast: short c = (short) (a + b);. For the same reason byte b = 10; b = b + 5; does not compile either. This behavior also explains why the expression c + 1 seen in the char arithmetic is an int.

If an expression has several operations, promotion is done separately for each operation. In the expression 1 / 2 * 10.0, first 1 / 2 is computed between two ints and gives 0; only then, when 0 is multiplied by 10.0, is it promoted to double. The result is 0.0, not 5.0. The presence of a double operand somewhere in an expression does not make the whole expression floating-point; promotion happens only in the operation in which that operand takes part.

6.4Operators

Definition 6.7

An operator is a symbol that acts on one or more values: +, *, <, &&. The values an operator acts on are called operands. A combination of operators, variables, and literals that produces a value is called an expression: a + b * 2.

Operators are named according to the number of operands they take. Operators with a single operand, such as -x, !active, and i++, are unary; those with two operands, such as a + b, are binary operators. Every expression has a value and a type. The value of the expression 7 / 2 is 3 and its type is int; the value of the expression 7 > 2 is true and its type is boolean.

These values do not stop the program; they are carried into later operations: ∞ + 5 = ∞, and every arithmetic operation involving NaN is again NaN. The strangest property of NaN is that it is not equal to itself: x == x gives false if x is NaN. That is why a NaN test cannot be done with x == Double.NaN; it always returns false. The correct way is the Double.isNaN(x) method.

Common mistake

Forgetting that the divisor in a floating-point division can be zero. Integer division shows this error immediately with an exception; floating-point division produces Infinity or NaN and silently continues. If the divisor can be zero, it is checked before the division.

6.4.3Increment and decrement

6.4.6Operator precedence and the expression tree

Is the value of the expression 2 + 3 * 4 20 or 14? In mathematics it is known that multiplication is done before addition, and the answer is 14. Java follows the same rule and extends it to all operators.

Definition 6.10

Operator precedence is the set of rules that determines in which order different operators in an expression are applied. Operators of the same precedence are applied from left to right; assignment operators are applied from right to left.

The ladder corresponds to the four rules in the slides. The inside of parentheses is always evaluated first; the unary ! and the type cast are also applied early. Multiplication, division, and remainder come before addition and subtraction. Comparisons are evaluated after arithmetic, and && and || after comparisons; && comes before ||. Operators at the same level are applied from left to right. That is why 10 - 4 - 3 is (10 − 4) − 3 = 3, not 10 − (4 − 3) = 9. 100 / 10 / 5 is likewise (100 / 10) / 5 = 2. Assignment, however, works from right to left: a = b = 4; first writes 4 into b and then writes this value into a.

When the compiler reads an expression, it turns it into an expression tree according to precedence. Literals and variables are at the leaves of the tree and operators are at the inner nodes. The operations at the bottom are evaluated first, and the operation at the root is evaluated last. The expression from the slides shows this process step by step:

6.4.8Short-circuit evaluation

The && and || operators have a property that speeds up their work and makes programs safe.

Definition 6.11

6.5Input and output

The programs so far have always worked with the same numbers; the values were written into the code. A program that converts temperatures or computes a grade average, however, must work with different values every time it runs. These values are taken from the user, usually from the keyboard. In Java the easiest way to read from the keyboard is the Scanner class. The printf method is used to write results neatly aligned and with a given number of decimal places.

6.5.1Input with Scanner

Scanner in = new Scanner(System.in);
System.out.print("Age: ");
int age = in.nextInt();
in.nextLine(); // consume the newline
System.out.print("Name: ");
String name = in.nextLine();

Scanner is in Java's java.util package. Before it is used, the line import java.util.Scanner; is written at the very top of the file, before the class definition. This line tells the compiler where the name Scanner comes from; if it is not written, a “cannot find symbol” error occurs.

  1. Scanner in = new Scanner(System.in);: new creates a Scanner object and connects it to standard input, that is, to the keyboard (System.in). in is the variable that holds a reference to this object; its name can be chosen freely.
  2. System.out.print("Age: ");: writes a prompt that tells the user what to enter. Because print is used instead of println, no line break is added; the user types on the same line.
  3. int age = in.nextInt();: the program stops and waits for the user to type an integer and press Enter. The number read is written into the age variable.
  4. in.nextLine();: the Enter character left at the end of the line is consumed. nextInt() does not read the Enter after the number; this call takes it out of the buffer.
  5. String name = in.nextLine();: the whole line the user typed, spaces included, is read.

Scanner's read methods are chosen according to the expected type: nextInt() reads an int, nextLong() a long, nextDouble() a double, nextBoolean() a boolean. next() reads a single word up to whitespace, and nextLine() reads everything up to the end of the line. The methods that read numbers and words treat whitespace and line breaks in the input as separators and skip them. Whether the user types the numbers 20, 30, and 40 on the same line separated by spaces or on separate lines, three nextInt() calls read all three.

The name variable is an empty string; there is nothing between the square brackets. The user gets no chance to type a second thing. The solution is to call an extra in.nextLine(); after nextInt(), as in the first program in the slides. Common mistake

Trying to read a line with nextLine() immediately after a call to nextInt(), nextDouble(), or next(). The first nextLine() reads the line break left over from the previous line and returns an empty string. If a line is to be read after reading a number, an in.nextLine(); that clears the buffer is put in between.

6.5.4Input validation

It cannot be assumed that the user will always enter the expected value. In a program that asks for an age, “twenty” may be typed, and −5 or 200 may be entered by mistake. When nextInt() meets a word that is not a number where it expects a number, it stops the program:

Age: twenty
Exception in thread "main" java.util.InputMismatchException

To make the program robust against such input, input validation is performed. Validation has two layers. First the type is checked: is what was entered really an integer? Then the range and business rule are checked: is the integer a reasonable age?

Scanner offers methods such as hasNextInt() for type checking. This method looks at the input without reading it: it returns true if the next piece is an integer and false otherwise. The following program does both checks with if statements. The structure if (condition) { … } else { … } runs the first block if the condition is true and the block after else if it is false.

Scanner in = new Scanner(System.in);
System.out.print("Age: ");
if (in.hasNextInt()) {
    int age = in.nextInt();
    if (age >= 0 && age <= 150) {
        System.out.println("Accepted: " + age);
    } else {
        System.out.println("Error: age must be between 0 and 150.");
    }
} else {
    System.out.println("Error: integer expected (example: 20).");
}

When the program is run with three different inputs, it gives these outputs:

Error: integer expected (example: 20).

Age: 200
Error: age must be between 0 and 150.

Age: 20
Accepted: 20

When “twenty” is entered, hasNextInt() returns false; because nextInt() is never called, the program does not crash and writes a clear message. When 200 is entered, the type check passes but the range check fails. 20 passes both checks. Note that the error message states the expected form explicitly: writing “integer expected (example: 20)” instead of “Invalid input” shows the user what to do. In a real program the value is asked for again after a wrong input; this repetition is done with a loop.

6.8Summary

  • A variable is a named box in memory set aside for a value of a certain type; it has a name, a type, and a value. A declaration specifies the type and name, and initialization gives the starting value. A local variable must definitely have been assigned a value before it is read; a final variable is assigned only once.
  • An assignment first evaluates the right side and then writes the result into the variable on the left; the old value is erased. A compound assignment (+=, -= …) updates the variable using its old value and evaluates the right side as a unit.
  • An identifier starts with a letter, _ or $; it contains no spaces, cannot be a keyword, and is case-sensitive. Variables are named in lowerCamelCase, classes in UpperCamelCase, and constants in UPPER_CASE.
  • Java has eight primitive types: byte (8), short (16), int (32), long (64), float (32), double (64), char (16), and boolean. The default choices are int and double. long literals need the suffix L and float literals the suffix F.
  • Integers are stored in two's complement representation. A result that exceeds the range overflows and silently wraps around to the other end: Integer.MAX_VALUE + 1 → −2147483648. To catch overflow, methods such as Math.addExact throw an exception. The type of an expression is determined by its operands; long s = a * b still multiplies in int.
  • Floating-point numbers cannot store decimal fractions such as 0.1 exactly: 0.1 + 0.2 is 0.30000000000000004. double values are compared not with == but with a tolerance. For money, integer hundredths or BigDecimal are used.
  • char holds a UTF-16 code unit as a number ('A' = 65); in arithmetic it is promoted to int. boolean takes only true or false and is not interchangeable with numbers.
  • Widening is automatic and lossless (int → double). Narrowing requires an explicit cast: (int) 9.8 gives 9; the fraction is not rounded but truncated toward zero. In integer narrowing the low bits remain: (byte) 200 is −56. For rounding, Math.round is used.
  • The quotient of two integers is integer division: 5 / 2 is 2. If one of the operands is a double, the other is promoted and 5.0 / 2 is 2.5. (double) (5 / 2), however, does not bring back the lost fraction. byte, short, and char are first promoted to int in operations.
  • % gives the remainder and takes its sign from the dividend. Dividing an integer by zero throws ArithmeticException; floating-point division produces Infinity or NaN.
  • The postfix i++ produces the old value and the prefix ++i the new value. Compound assignment implicitly narrows the result to the type of the left side: b += 5 compiles, b = b + 5 does not.
  • Comparison operators produce booleans; &&, ||, and ! combine boolean values. Operator precedence: parentheses, unary, multiplicative, additive, relational, equality, &&, ||, assignment. Operators at the same level go from left to right. The compiler turns an expression into an expression tree.
  • Short-circuit: in &&, if the left side is false, and in ||, if the left side is true, the right side is not evaluated. The guarding condition (b != 0) is written on the left.
  • + performs concatenation if one of the operands is a string, and works from left to right: "Result: " + 2 + 3 gives “Result: 23” and "Result: " + (2 + 3) gives “Result: 5”. String content is compared with equals.
  • Scanner reads from the keyboard; the input waits in a buffer. nextInt() leaves the line break in the buffer; if a line is to be read next, it is first consumed with a nextLine(). Input is validated first for type, then for range.
  • printf fills the format specifiers (%d, %f, %s, %n …) in the format string with the arguments in order; width, precision, and flags (-, 0, ,) align the output. The decimal separator depends on the locale; under a Turkish locale, printf writes a comma and nextDouble expects a comma.

6.10Test Yourself

  1. After the lines int x = 1_000_000; int y = x * 3000; long z = x * 3000L;, what does System.out.println(y + " " + z); print? Why is y wrong?

    Answer

    The output is -1294967296 3000000000. 1,000,000 · 3,000 = 3,000,000,000 exceeds the int limit, 2,147,483,647. Because both operands are ints, the multiplication is done in int and overflows: 3,000,000,000 − 232 = −1,294,967,296. In z, 3000L is a long literal; x is promoted to long and the multiplication is done in long.

  2. What are the values of the expressions (byte) 300, (int) -7.9, Math.round(-7.5), and (int) Math.round(7.5)?

    Answer

    44, −7, −7, and 8, respectively. The low 8 bits of 300 are kept: 300 − 256 = 44 (positive because the sign bit is 0). (int) -7.9 truncates toward zero: −7. Math.round rounds halves in the positive direction: −7.5 → −7, 7.5 → 8; the latter returns a long, so it has been cast to int.

  3. After the line int a = 7, b = 8; double o = (a + b) / 2;, what is o? What are two forms that give the correct average?

    Answer

    o = 7.0. a + b is 15 and is an int; 15 / 2 becomes 7 by integer division, and then it widens to double and is written as 7.0. The correct forms are (a + b) / 2.0 and (double) (a + b) / 2; both give 7.5. (double) ((a + b) / 2), however, again gives 7.0, because the cast is done after the division.

  4. After the lines int i = 10; int a = i-- - 3; int b = --i * 2;, what are i, a, and b?

    Answer

    i = 8, a = 7, b = 16. The postfix i-- produces the old value (10): a = 10 − 3 = 7; then i becomes 9. The prefix --i first makes i 8 and then uses the new value: b = 8 · 2 = 16.

  5. Does short s = 10; s *= 2.6; compile? If it does, what is s? What can be said about s = s * 2.6;?

    Answer

    It compiles and s = 26. Compound assignment means s = (short) (s * 2.6): 10 · 2.6 = 26.0 (double) is computed and narrowed to short. s = s * 2.6;, however, does not compile; the right side is a double and there is no implicit conversion from double to short (“possible lossy conversion from double to short”).

  6. What are the values of the expressions 5 + 4 % 3 * 2 - 8 / 3 and !(3 > 2) || 4 >= 4 && 1 != 1? In what order is the computation done?

    Answer

    The first is 5. *, /, and % are at the same level and are processed from left to right: 4 % 3 = 1, 1 · 2 = 2, 8 / 3 = 2; then 5 + 2 − 2 = 5. The second is false. The inside of the parentheses, 3 > 2, is true, and with ! it becomes false. && comes before ||: 4 >= 4 is true, 1 != 1 is false, true && false = false. The result is false || false = false.

  7. What do System.out.println(1 + 2 + "3" + 4 + 5); and System.out.println('a' + 2 * 3 + ""); print?

    Answer

    The first prints “3345”: from left to right, first the two ints are added (3), then joined with the string “3” (“33”); after that every operation is concatenation: “334”, “3345”. The second prints “103”: 2 · 3 = 6 is computed first; 'a' is promoted to int and 97 + 6 = 103 is found; finally it is joined with the empty string.

  8. The user types 3 4.5 on the first line and Ali Veli on the second (Locale.US). The program calls nextInt(), nextDouble(), nextLine(), and nextLine() in that order. What do the four calls return?

    Answer

    3, 4.5, "" (empty string), and "Ali Veli". nextInt and nextDouble read the two numbers on the same line; the line break at the end of the first line stays in the buffer. The first nextLine reads up to this line break and returns an empty string. The second nextLine reads the second line. Under a Turkish locale, nextDouble would have thrown an InputMismatchException on the input “4.5”.

  9. What does the line System.out.printf("%-5s|%8.3f|%,d%n", "Paper", 12.34567, 1500000); print under Locale.US? How many characters does each field take?

    Answer

    Paper| 12.346|1,500,000. “Paper” is exactly 5 letters; %-5s adds no spaces. %8.3f rounds 12.34567 to three decimal places (12.346, 6 characters) and puts 2 spaces in front to complete it to 8 characters. %,d adds a thousands separator; under a Turkish locale this field would be 1.500.000 and the second field 12,346.
