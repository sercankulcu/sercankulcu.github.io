All programs shown in the note were compiled and run with JDK 21; the compiler messages and console outputs are taken verbatim from those runs.

5.1Programs and programming languages

A computer does nothing on its own. A calculator app, a game, and a banking system are all made of commands that tell the computer what to do, step by step. Writing these commands is called programming, and the whole of the commands written is called a program. The commands are written in an artificial language that both the computer and the human can work with.

5.1.1What is a program?

Definition 5.1

A program is a whole made of commands that a computer executes to perform a particular task. A program can take input, process data, keep intermediate values in memory, and produce output.

The four elements in the definition appear in every program. Input is the information given to the program from outside: a number typed at the keyboard, the contents of a file, or a measurement from a sensor. Processing is the steps that produce new values from the input: adding, comparing, sorting. State is the current condition of the values the program holds in memory while it runs. Output is the results the program gives to the outside: a line written to the screen, a saved file, or a lit lamp.

Figure 5.1 shows these elements on a small example. The program takes two grades: 70 and 90. In the first step the grades are read. In the second step they are added, and the total, 160, is stored in memory. In the third step the total is divided by 2 and 80 results. In the last step 80 is printed to the screen. For the grades 50 and 60, the same program prints 55. The program does not change; only the input changes. This is what makes a program valuable: it is written once and run over and over with different inputs.

Two things determine a program's behavior. The first is the rules of the language it is written in: what each symbol means and how a number is stored. The second is the method the programmer chose, that is, the algorithm. In the average example, "first add, then divide" is an algorithm. The same algorithm can be written in different languages. This note uses Java as the language.

5.1.2The aspects of a programming language

In natural languages such as English, a sentence also has two aspects: whether it is written correctly and what it says. "Me read the book on table" is defective grammatically. "The table read the book" is well formed but makes no sense. In programming languages, two more aspects are added to these two. A programming language is studied from four aspects.

Definition 5.2

Syntax is the set of rules that determines the valid way of writing a program. Semantics defines what happens when a valid piece of program is executed. The type system ensures that every value has a type and that only operations appropriate to its type are performed on a value. The execution model describes the order in which commands are executed and how values are held in memory.

Figure 5.2 shows these four aspects on a single statement: int total = price * qty;. In terms of syntax, the statement starts with a type name, followed by a name, an equals sign, an expression, and a semicolon. If the semicolon is forgotten, the statement is invalid. In terms of the type system, price and qty are integers (int), and the product of two integers is also an integer. The result can therefore be put into total, which has type int. In terms of meaning, the statement says "multiply price by qty and write the result to total." In terms of the execution model, a box named total is set aside in memory and the result is stored in this box.

In Java, the syntax and type rules are checked before the program is run. This check is done by the compiler. A program with a forgotten semicolon, or one that tries to put text into a number box, is never run; the compiler reports the error with a line number. Mistakes concerning meaning, on the other hand, often show up only while the program is running. A program that forgets to divide when computing an average compiles flawlessly but produces a wrong result.

5.2Source code and tools

The text a programmer writes is called source code. Source code is written for humans: it consists of readable words, numbers, and symbols. A processor, however, understands only its own machine instructions. Several tools are used together to turn source code into a running program.

5.2.1The plain-text source file

A Java program is written to a file with the extension .java. This file is called a source file. A source file is plain text. A plain-text file contains only characters; it has no formatting information such as font, color, bold type, or page layout. A Java file can therefore be opened with Notepad, a code editor such as VS Code, or an integrated development environment. A Word document, on the other hand, is not plain text; it also stores formatting information. If source code is written in Word and saved as .docx, the compiler cannot read the file.

On disk everything is bytes. In a plain-text file, each character is converted to one or more bytes according to a character encoding. Today the most common encoding is UTF-8. In UTF-8, the letters of the English alphabet, digits, and punctuation marks take a single byte, as in ASCII. Figure 5.3 shows the bytes of the word "public": the letter p is 70 in hexadecimal, that is, 112 in decimal. The letters ç, ğ, ı, ö, ş, ü, which are specific to Turkish, take two bytes each in UTF-8.

The encoding is an agreement between the programs that write and read the file. If a file is saved as UTF-8 and read with another encoding, non-ASCII letters get corrupted. The word "Dünya" may appear as "DÃ¼nya". The Java compiler also assumes an encoding when it reads a source file. Since JDK 18 the default encoding has been UTF-8. The examples in this note were compiled with JDK 21 without any extra options; words such as "Dünya", "Satır", and "İndirim" came out correctly. If an older JDK is used, the encoding must be stated explicitly to the compiler with the -encoding UTF-8 option.

Beyond the encoding, two more details should be consistent. The first is line endings: Windows writes a line ending with two characters (CR LF), Linux and macOS with a single character (LF). The Java compiler accepts both. But mixed line endings in the same project cause needless differences in tools that track changes. The second is the file name. In Java, the file name must be the same as the name of the public class inside it: the class Hello is written to the file Hello.java.

Plain text has one more advantage. Version control systems record which line of a file was changed, by whom, and when. Git is the most common example. Because these tools compare line by line, they work best with plain-text files.

5.3Java

Java is one of the most widely used programming languages today. We meet it in banking systems, in Android apps, in big-data tools, and in universities' introductory programming courses. The most important reason for this ubiquity is that Java programs can run independently of the operating system and the processor. This section describes how Java was born, where it is used, and what software is needed to run a Java program.

5.3.1The birth and versions of Java

Java's story begins at Sun Microsystems in 1991. In a project called the "Green project," James Gosling and his team set out to design a language for smart home devices such as television set-top boxes. The language was first called Oak. The home-device market did not attract the expected interest, but in those same years the Web was spreading rapidly. A language that could behave the same way on computers with different operating systems was exactly what the Web needed. The language was released in 1995 under the name Java.

Java's design goal is summed up in a single sentence: write once, run anywhere. A Java program is compiled once. The bytecode the compiler produces runs unchanged on Windows, Linux, or macOS, on a Java Virtual Machine written for that system. The programmer does not have to compile separately for each operating system.

Java's other basic features are these:

  • Object-oriented: Programs are built around classes and objects. Even the smallest Java program is written inside a class.
  • Strong type checking: Every variable has a type, and the compiler catches type mismatches before the program runs.
  • Automatic memory management: The memory of objects that are no longer used is reclaimed automatically by garbage collection. The programmer does not free memory by hand.
  • A large class library: There are ready-made classes for jobs such as printing to the screen, reading files, network connections, and date computation.

Java's owner changed in 2010: Oracle bought Sun Microsystems and has developed the language ever since. Java's source code has been open since 2006 and is published in the OpenJDK project. Today, besides Oracle, organizations such as Eclipse Adoptium (Temurin), Amazon (Corretto), and Microsoft offer OpenJDK-based JDK distributions. The examples in this note were run with the Eclipse Adoptium distribution of JDK 21.

Since 2018 a new Java release has come out every six months: in March and September. Each release receives updates for only a few months. Some releases, however, are declared long-term support (LTS) releases and receive security updates for years. Organizations and courses therefore prefer LTS releases. Java 8, 11, 17, 21, and 25 are LTS releases. This course uses Java 21.

5.3.3JDK, JRE, and JVM

Three abbreviations appear constantly in Java documents: JDK, JRE, and JVM. The three are nested layers; the outer layer contains the inner one.

Definition 5.3

The Java Virtual Machine (JVM) is the software that executes bytecode. The JRE (Java Runtime Environment) is the combination of the JVM and the Java class library: it contains everything needed to run a Java program. The JDK (Java Development Kit) adds the development tools (javac, jar, javadoc …) to the JRE.

In short: JDK = JRE + development tools, JRE = JVM + class library. Figure 5.6 shows this relationship. A user who will only run a ready-made Java program needs just the JRE. A developer who will write and compile programs must install the JDK, because javac exists only in the JDK.

This distinction has changed somewhat today. Since Java 11, Oracle no longer offers a separate JRE package; both developers and users install the JDK. Some distributors still offer the JRE separately. Knowing the three layers as concepts remains important, because error messages and documentation use these names.

The five parts of the JVM do their work in turn during the life of a program. The class loader reads the .class file from disk and brings it into memory. The bytecode verifier checks that the loaded code obeys the rules; for example, that an instruction does not try to use a value that is not on the stack. The interpreter executes the bytecode instructions one by one. The JIT compiler (just-in-time compiler) speeds up the frequently run parts by translating them into the processor's machine code. The garbage collector reclaims unused memory as the program runs.

Common mistake

More than one Java may be installed on a computer, and the command line uses the first one it finds. On the computer where this note was prepared, javac came from JDK 21 while the java on the PATH came from an old Java 8 installation. When Hello.class, compiled with JDK 21, was run with Java 8, this message was received:

Exception in thread "main" java.lang.UnsupportedClassVersionError: Hello has been compiled by a more recent version of the Java Runtime (class file version 65.0), this version of the Java Runtime only recognizes class file versions up to 52.0

The message is clear: the class file is in version 65 (Java 21) format, while the JVM running it recognizes at most version 52 (Java 8). An old JVM cannot run new bytecode. The fix is to make sure that the outputs of java -version and javac -version show the same version.

5.4The first Java program

The traditional first step in learning programming is a program that prints a short greeting to the screen. This program is small, but it contains all the required parts of a Java program. This section first breaks the program into its parts and then traces step by step how the JVM runs it.

5.4.1The parts of the program

The following program is saved in a file named Hello.java:

public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}

When the program is compiled and run, it writes a single line to the console:

> javac Hello.java
> java Hello
Hello

In console sessions, lines starting with > are commands typed by the user; the lines below are the command's output. There is no line under the javac command: when compilation succeeds, the compiler stays silent.

Figure 5.7 shows the program as three nested layers. Let us examine the lines one by one.

  1. public class Hello { is a class declaration. In Java all code lives inside a class. After the class keyword comes the name of the class. public says that the class is accessible from anywhere. The name of a public class must be exactly the same as the file name: the class Hello is written to the file Hello.java. The { at the end of the line opens the body of the class.
  2. public static void main(String[] args) { declares the main method. A method is a unit of work with a name. When the JVM runs a program, it always starts at the main method; for this reason main is the program's entry point.
  3. System.out.println("Hello"); is the statement that does the real work of the program. System.out represents the standard output stream, that is, the console. The println method writes the text given to it to the console and ends the line. The "Hello" in double quotes is a string: a text value made of characters. The statement ends with a semicolon.
  4. The first } closes the body of the main method, and the second } closes the body of the class.

Each of the words at the head of the main method has a job:

Table 5.3: The words in the declaration of the main method.
WordMeaning
publicThe method is accessible from anywhere; the JVM can also call it from outside
staticThe method belongs to the class; no object needs to be created first to call it
voidThe method returns no value
mainThe name of the method; the JVM looks for the entry point by this name
String[] argsThe method's parameter: an array of strings that carries the command-line arguments

Each of these words (access modifiers, static methods, return types, arrays) is a topic in its own right. For the first programs it is enough to write this line as it is. Still, knowing why each word is there makes it easier to understand the message you get when it is written wrong.

5.4.2The signature of the main method

A method's name, parameters, and return type make up its signature. When the JVM runs a class, it looks for a method with exactly the signature public static void main(String[] args). What is interesting is this: a main with a wrongly written signature gives no compile error. To the compiler, a method named Main, or one that returns int, is an ordinary, valid method. The error appears only when the java command tries to start the program.

The table below shows what happens when main is written in different forms in class A in the file A.java. Each version was compiled without errors with javac A.java and then run with java A.

The JavaFX sentence on the last line is a reminder that JavaFX applications with a graphical interface have another way of starting; it is not used in this course. Three conclusions follow from the table:

  • Java is case-sensitive: Main and main are different names.
  • public, static, and void are mandatory. When one is missing, the JVM either cannot find the method at all or finds it and rejects it.
  • The parameter's name is free: a can be written instead of args. The old notation String a[] is also valid. Still, the Java convention is to write String[] args.

In newer versions of Java these rules have been relaxed. From Java 25 on, a main method that is not public or static, or even one with no parameter, can also be launched. This course uses the classic signature that works in Java 21 and in every version.

5.4.4Command-line arguments

The args parameter of the main method is the way to give the program information from the command line. The words written after the class name in the java command are called command-line arguments. The JVM puts these words into an array of strings and passes it to main.

An array is a structure that holds several values of the same type, by sequence number. Each cell in the array has an index, and indices start at 0. args[0] is the first argument and args[1] is the second. args.length gives the number of arguments in the array. The following program uses the arguments:

public class Greet {
    public static void main(String[] args) {
        System.out.println(args.length);
        System.out.println("Hi " + args[0]);
        System.out.println("Hi " + args[1]);
    }
}

The program was run first with two arguments and then with one argument:

> java Greet Ali Veli
2
Hi Ali
Hi Veli
> java Greet Ali
1
Hi Ali
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 1 out of bounds for length 1
	at Greet.main(Greet.java:5)

In the first run the args array is ["Ali", "Veli"] (Figure 5.9, top). Line 3 prints the number of arguments, that is, 2. On line 4 the expression "Hi " + args[0] joins two strings side by side and Hi Ali is printed. Line 5 prints Hi Veli in the same way.

In the second run, both the code and the .class file are the same; there is no need to recompile. Only the input changes. The array has a single cell. Lines 3 and 4 print 1 and Hi Ali. Line 5 tries to access the nonexistent args[1]. In this case the JVM throws an exception: ArrayIndexOutOfBoundsException, that is, "array index out of bounds." The message says that index 1 lies outside an array of length 1. The line below shows that the error occurred in line 5 of the file Greet.java, in the main method. The program stops at that point.

The compiler could not have known this error. At compile time it is not known how many arguments the program will be given. The error appears at run time and depends on the input. If no argument is given at all, the error occurs one line earlier, on line 4:

> java Greet
0
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0
	at Greet.main(Greet.java:4)
Example 5.1

The same Greet program is run with the command java Greet Ayşe "Ali Veli". What is the output?

Command-line arguments are separated by spaces. Double quotes, however, make the space inside part of the argument. So "Ali Veli" is not two arguments but one, and the quotes are not included in the argument. The args array is ["Ayşe", "Ali Veli"], with length 2:

> java Greet Ayşe "Ali Veli"

Hi Ayşe
Hi Ali Veli

Extra arguments, on the other hand, cause no error. In the command java Greet 1 2 3 the length of the array is 3. Since the program uses only the first two cells, the third is ignored:

> java Greet 1 2 3
3
Hi 1
Hi 2

5.4.5print and println

There are two basic ways to write to the console: System.out.print and System.out.println. Both write the value given to them. The difference between them appears after the writing is done. println (print line) adds a newline after writing; the next output starts on the line below. print adds no newline; the next output continues on the same line, where it left off.

In the console, the cursor determines where the text will appear. It is enough to think of the cursor as the place where the next character will be written. Let us follow the cursor's journey in the following program:

        System.out.print("Hello ");
        System.out.println("World");
        System.out.println("Java");
    }
}

Common mistake

Writing the last output of the program with print. The output appears on the screen, but because the line is not ended, the console prompt sticks to the same line: Result: 80C:\docs>. Using println on the last line of the program prevents this mess.

5.5Escape sequences and string concatenation

A string begins with a double quote and ends with a double quote. This simple rule raises two questions. First, what do you do if a double quote has to appear inside the text? Second, how do you put characters that cannot be typed directly at the keyboard, such as a newline or a tab, into a string? Java solves both in the same way: escape sequences.

5.5.1Escape sequences

Definition 5.4

An escape sequence is a notation inside a string or character literal that begins with a backslash (\) and stands for a single special character. The backslash makes the character that follows "escape" from its usual meaning.

Table 5.7: Commonly used escape sequences.

5.5.4String concatenation

The + sign does two different jobs in Java. Between two numbers it adds: the result of 40 + 45 is 85. If at least one operand is a string, it concatenates: the other operand is converted to text and appended. The result of "Score: " + 85 is the string "Score: 85". This second job is called string concatenation.

When an expression contains several + signs, two rules determine the result:

  1. Operations at the same precedence are performed from left to right. The expression a + b + c is evaluated as (a + b) + c.
  2. * and / are always performed before +. Parentheses come before everything.

At each + step the question "is one of the operands a string?" is asked afresh. If the answer is yes, concatenation is done; if no, addition. Once a string has appeared, all the + signs to its right are concatenations, because the intermediate result on the left is now a string.

public class Concat {

5.6The structure of a Java file

The Hello program consisted of a single class. In real programs, two more kinds of declarations can appear before the class at the top of a file: package and import. The parts of a Java file are written in a fixed order.

package school;

import java.util.Scanner;

public class Program {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}

Figure 5.14 shows the structure. The order is as follows:

  1. package school; says which package the class belongs to. A package is a namespace that keeps related classes together; it is similar to folders on a computer. If there is a package declaration, it must be the first statement in the file, and the file lives in a folder with the same name as the package: school/Program.java.
  2. import java.util.Scanner; makes it possible to use a class from another package by its short name. Without this line the class would have to be written everywhere with its full name, java.util.Scanner. import declarations come after the package declaration and before the class. In this example Scanner is not used; it is written only to show the place. An unused import gives no error.
  3. public class Program { … } is the class itself. The name of a public class is the same as the file name.

Note that no import is needed for the System class. The most basic classes such as System and String are in the java.lang package, and this package is added to every file automatically.

A class with a package is compiled and run from the folder one level above the package folder. When running, the full name of the class, including the package name, is written:

> javac school/Program.java
> java school.Program
Hello
> java Program
Error: Could not find or load main class Program
Caused by: java.lang.ClassNotFoundException: Program

When only Program is typed in the last command, the JVM looks for a Program class with no package and cannot find it. The real name of the class is school.Program. The first programs use no package; the classes live in the default, unnamed package. IDEs, however, often add a package declaration when creating a new project. This detail must not be forgotten when a file written in an IDE is compiled on the command line.

5.7Compiling and running

A Java program does not run the moment it is written. It is first compiled and then run. These two steps are done with two separate commands and involve two kinds of files: the compiler reads the .java file, while the JVM runs the .class file. Understanding this distinction well prevents most of the problems beginners run into most often.

5.7.1The compilation pipeline

Definition 5.5

Compilation is checking the source code as a whole and translating it into another language. In Java, the compiler javac translates the source code into a processor-independent intermediate code called bytecode. Bytecode is stored in files with the extension .class and runs on the Java Virtual Machine.

There are five steps from writing a Java program to seeing its output. Let us call all of these steps together the compilation pipeline:

  1. Write. The source code is written in an editor and saved as Hello.java. The file name must be the same as the name of the public class.
  2. Compile. The command javac Hello.java runs the compiler. The compiler reads the whole file before the program has even started to run; it checks the syntax and the types.
  3. Bytecode. If compilation succeeds, the file Hello.class appears in the same folder. This file is not plain text but a binary file. It is the same on Windows, Linux, and macOS.
  4. Run. The command java Hello starts the JVM. This command is given the class name, not the file name; the .class extension is not written. The JVM's class loader brings the .class file into memory, the verifier checks the bytecode, and then main is called.
  5. Output. The JVM interprets the bytecode; it translates the frequently run parts into machine code with the JIT compiler. println writes Hello to the console.

Every .class file begins with the same four bytes: CA FE BA BE in hexadecimal. This "magic number" lets the JVM recognize that the file really is a Java class file. The first eight bytes of the Hello.class file compiled for this note are ca fe ba be 00 00 00 41. The last two bytes are the class file's version number: 41 in hexadecimal is 65 in decimal and denotes Java 21. This is the "class file version 65.0" mentioned when an old JVM rejects a new class file.

If the compiler finds an error, the pipeline stops at the second step:

A program with a compile error does not run at all; not even part of it runs. The compiler checks the whole file, and if it finds even a single error it produces no .class. This is an important difference from interpreted languages that run line by line. In a language such as Python, the lines before the faulty line may run. In Java, an error on line 50 means line 1 will not run either.

5.7.4Working with an IDE

Compiling and running on the command line shows plainly what happens behind the scenes. In daily work, however, most programmers use an IDE. The IDE hides the same steps behind a button.

The main conveniences an IDE provides are these:

  • The ▶ Run button performs the compile and run steps back to back. Changed files are recompiled first; for that reason the stale-.class problem does not arise.
  • Instant error display: the IDE compiles in the background while you type. Compile errors are marked with a red underline; when the pointer is over it, the compiler's message appears.
  • Code completion: when you type System.out., the methods that can be used are listed. Misspelled method names become rarer this way.
  • Automatic indentation and renaming: when a variable's name is changed, it changes everywhere it occurs.
  • Debugger: stops the program at a breakpoint, shows the current values of the variables, and steps through the program line by line.

The common Java IDEs are IntelliJ IDEA, Eclipse, and NetBeans. VS Code does the same jobs with Java extensions. An IDE is a great convenience, but knowing what happens behind the scenes is still necessary. On servers or over remote connections there is often no IDE; there is only the command line. The messages an IDE shows are also javac's messages. Someone who knows the compile steps on the command line can read these messages in any environment.

5.8Bytecode and the JVM

Java's "compile once, run anywhere" principle is possible thanks to bytecode. This section explains why bytecode is processor-independent, what is inside a .class file, and how the JVM executes bytecode.

5.8.1Compile once, run anywhere

In languages such as C, the compiler translates source code directly into the machine code of a particular processor. A program compiled for a Windows computer with an Intel processor does not run on a Mac with an ARM processor; it has to be compiled separately for that one. The Java compiler, however, produces the machine code of no real processor. It produces the instructions of an imaginary processor that does not exist, namely the Java Virtual Machine. These instructions are called bytecode.

What makes the imaginary processor real is the JVM written separately for each platform (Figure 5.19). The Windows JVM and the macOS JVM read the same bytecode. Each runs it on its own processor. Two ways are used for this. The interpreter reads the bytecode instructions one by one and executes them. The JIT compiler translates the frequently run parts, for example a loop that runs thousands of times, into that processor's machine code and runs the machine code directly on later iterations. In this way Java programs are both portable and fast.

Class loading, bytecode verification, and garbage collection are also parts of the runtime. The verifier is especially important. A .class file may have been downloaded from the network or may be corrupted. The verifier checks, before running, that the code obeys the JVM's rules.

5.9The building blocks of the language

When the compiler reads a Java file, it first breaks it into small pieces and then builds larger structures from those pieces, just as letters form words, words form sentences, and sentences form paragraphs. This section starts with the smallest pieces, tokens, and reaches the concepts of expression, statement, and block.

5.9.1Tokens

Definition 5.6

A token is the smallest piece of source code that is meaningful to the compiler. Java has five kinds of tokens: keywords, identifiers, literals, operators, and separators.

Let us get to know the five kinds with Figure 5.21:

  • Keywords are words reserved for the language itself: int, class, public, static, void, if, and so on. Their meanings are fixed, and they cannot be used for any other purpose. int class = 5; cannot be written.
  • Identifiers are names given by the programmer: variable, method, and class names. total, price, Hello, and main are identifiers. An identifier starts with a letter, _, or $ and continues with letters and digits. It cannot contain a space and cannot start with a digit.
  • Literals are values written directly into the code: 3, 120, 2.5, "Hello", 'A', true.
  • Operators are the symbols that perform operations: +, -, *, /, =, >, and so on.
  • Separators are the symbols that determine the structure: ; , . ( ) { } [ ].

Java is a case-sensitive language. count and Count are two different identifiers. System is right and system is wrong. There is no keyword Int; there is only int. Statements usually end with a semicolon; blocks are enclosed in curly braces.

5.9.2Whitespace, indentation, and braces

The following two programs are identical. The first is written on a single line, the second is indented according to Java convention:

public class OneLine { public static void main(String[] args) { System.out.println("Hello"); } }
public class OneLine {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}

Both programs compile and turn into the same bytecode. The main instructions in the javap -c output of the one-line version are the same four as in the Hello program: getstatic, ldc, invokevirtual, return. To the compiler, spaces, tabs, and newlines only separate tokens. x=1; and x = 1; are the same. But publicclass counts as a single word and is not read as two tokens. (The two class files are not byte-for-byte identical, because a .class file also stores line numbers for error messages. The instructions, however, are the same.)

If whitespace does not matter to the compiler, why does indentation matter? Because code is written for humans as much as for the compiler. Indentation shows the reader how blocks are nested. In the Java convention the rules are these:

  • Each new block starts 4 spaces further in than the previous one.
  • The opening brace { stays at the end of the line.
  • The closing brace } is on its own line and lines up with the line that opened it.

When these rules are followed, you can see at a glance which block a } closes. In code with broken indentation it is very hard to notice that a brace is missing.

There is one exception: spaces inside a string are part of the text. "Hello " and "Hello" are different strings; the first has six characters, the second five. print("Hello ") and print("Hello") give different output.

5.9.3Expressions, statements, and blocks

Tokens come together to form expressions, and expressions form statements.

Definition 5.7

An expression is a piece of code that produces a value when evaluated: 2 + 3 → 5, num > 0 → true or false. A statement is a unit of code that completes an action and usually ends with ;: total = 5;, System.out.println(total);. A block groups the statements inside curly braces into a single structure.

The difference is clear from the question: "Is this piece a value or an action?" price * qty is a value (such as 360); by itself it does nothing. total = price * qty;, however, is an action: it computes the value and writes it to total. A statement can contain one or more expressions.

The following piece of code uses all four concepts together. When the piece is placed in the main method of a class and run, a single line is written to the console:

int qty = 3;               // declaration
int total = price * qty;   // expression + assignment
if (total > 300) {         // condition + block
    System.out.println("Discount");

5.10Comments

Code is written not only for the compiler but also for the people who will read it: the programmer returning to their own code months later, teammates, the instructor who grades the course. A comment is text added to the source code for the reader, which the compiler ignores.

5.10.1Three comment styles

Java has three comment styles:

  • A comment that starts with // lasts until the end of the line. It is used for short notes.

  • A comment that starts with /** and ends with */ is a Javadoc comment. The javadoc tool generates API documentation from these comments. They are usually written immediately above class and method declarations.

5.10.2Comment pitfalls

Comments look simple, but they hide a few pitfalls.

Nested multi-line comments. /* … */ comments cannot be nested. A comment ends at the first */ it meets:

public class Nested {
  public static void main(String[] args) {
    /* outer /* inner */ rest */
    System.out.println("Hello");
  }
}
Nested.java:3: error: illegal start of expression
    /* outer /* inner */ rest */
                               ^
1 error

The compiler treats the part /* outer /* inner */ as a comment; the second /* in the middle has no meaning because it is inside the comment. The comment ends at the */ after inner. What remains is rest */, and the compiler takes it for code. rest counts as an identifier and * as the multiplication operator. After the multiplication a value is expected, but a / comes, and no expression can start with /. The compiler says illegal start of expression; the ^ mark points at this last / character. To disable a section that contains /* */, it is safer to comment out the lines one by one with //.

Comment markers inside quotes. // or /* */ inside a string is not a comment; it is part of the text. Let us trace which lines run in the following program:

public class CommentTest {
    public static void main(String[] args) {
        // System.out.println("1");
        System.out.println("2"); // System.out.println("3");
        /* System.out.println("4");
        System.out.println("5"); */
        System.out.println("6 // not a comment");
        System.out.println("7 /* not a comment */");
        System.out.println("a // b");
    }
}

The first line is a comment from start to end. On the second line "2" is printed; what comes after //, that is, the statement that would print 3, is a comment. /* … */ comments out two lines (4 and 5) together. The // and /* */ markers in the last three lines are inside quotes, so they are printed as they are.

Disabling code temporarily. Putting // at the start of a line makes it not run without deleting it. This is a method often used when hunting for a bug. In IDEs, the Ctrl+/ shortcut turns the selected lines into comments in this way and reverses it.

Stale comments. The most insidious pitfall is a comment that contradicts the code:

double price = net * 1.20; // VAT 18%

The code compiles and works correctly: the VAT rate was updated and the code was written for 20%. But the comment states the old rate and misleads the reader. When a comment and the code contradict each other, the compiler runs the code; the code is always what is right. When the code is changed, the related comment must be updated too.

5.11Errors

Every programmer makes mistakes. What sets a good programmer apart is being able to find and fix an error quickly. The first step is to recognize the kind of error. When an error shows up determines who catches it and how to look for it.

5.11.1Kinds of errors

Table 5.16: Kinds of errors.
ErrorWhen?Who catches it?Example

A syntax error is a violation of the language's rules of writing: a missing semicolon, an unclosed parenthesis or quote. A type error is when the syntax is correct but a value is used where it does not fit its type. These two together are called compile errors. A program with a compile error does not turn into a .class file and does not run at all.

A runtime error is when a compiled program meets an operation it cannot perform while running. In Java, the JVM then throws an exception and the program stops unless special provision has been made. A logic error is the most insidious kind: the program compiles, runs without error, and produces a result, but the result is wrong. No tool gives an error message. A logic error can be caught only by someone who compares the result with the expected value.

The earlier errors are caught, the cheaper they are to fix. A compile error is found on the programmer's computer, within seconds. A logic error, however, may be noticed only after the program has reached users. That Java checks types at compile time is therefore an advantage: the programmer sees many mistakes before even running the program.

5.11.2Four errors, four examples

The following four programs give one example of each kind of error. The real message on JDK 21 is given for each.

Syntax error. There is no semicolon at the end of line 3:

public class Bug1 {
    public static void main(String[] args) {
        System.out.println("Hello")
    }
}
Bug1.java:3: error: ';' expected
        System.out.println("Hello")
                                   ^
1 error

The compiler shows where the rule was broken with a line number: Bug1.java:3. ';' expected means "a semicolon was expected." The 1 error on the last line is the total number of errors. No .class is produced. The fix: add ; at the end of the line.

Type error. A string is being put into a variable of type int:

public class Bug2 {
    public static void main(String[] args) {
        int num = "42";
    }
}
Bug2.java:3: error: incompatible types: String cannot be converted to int
        int num = "42";
                  ^
1 error

The syntax is flawless: type, name, equals sign, value, semicolon. But because "42" is inside double quotes, it is not a number but a two-character text. The message says "incompatible types: String cannot be converted to int." The ^ points at the incompatible value. The fix: remove the quotes and write int num = 42;.

Runtime error. The program compiles, but while running an integer is divided by zero:

public class Bug3 {
    public static void main(String[] args) {
        int a = 10, b = 0;
        System.out.println(a / b);
    }
}
> javac Bug3.java
> java Bug3
Exception in thread "main" java.lang.ArithmeticException: / by zero
	at Bug3.main(Bug3.java:4)

javac stays silent: the syntax and the types are correct. The compiler does not check that the value of b will be 0. While the program runs, an integer division by zero is attempted on line 4. Faced with this operation, which is undefined in mathematics too, the JVM throws an ArithmeticException. The message says / by zero and gives the location of the error: Bug3.java, line 4, the main method. The program stops there.

Logic error. The average of two grades is wanted:

public class Bug4 {
    public static void main(String[] args) {
        int a = 70, b = 90;
        System.out.println(a + b / 2);
    }
}
> javac Bug4.java
> java Bug4
115

There is no error message, but the result is wrong. The average of 70 and 90 is 80, and the program prints 115. The reason is operator precedence: / is performed before +. The expression a + b / 2 is evaluated as a + (b / 2): 90 / 2 = 45, 70 + 45 = 115. The fix: write (a + b) / 2; this expression gives (70 + 90) / 2 = 160 / 2 = 80.

Common mistake

Concluding "the program compiled and ran, so it is correct." Compilation shows only that there are no syntax or type errors. A program with a logic error also compiles and runs without trouble. A program can be trusted to be correct only by comparing its output with the expected results for known inputs.

5.11.4Reading an error message

Error messages look frightening at first sight, but they are always written in the same layout. Learning the layout once makes every message easier to read.

The first line of a javac message has the form file:line: error: description (Figure 5.25). In the message Score.java:3: error: ';' expected, the file is Score.java, the line is 3, the kind is error, and the description is ';' expected. The second line shows the offending source line verbatim. The ^ mark on the third line points at the column where the compiler noticed the problem. At the very end the total number of errors is written.

The ^ does not always point at the error itself but at the place where the compiler noticed it. A missing semicolon is noticed where the statement ends, that is, at the end of the line. A missing } is not noticed until the end of the file and is reported as reached end of file while parsing. So if the error cannot be found at the place shown, look at the previous line or at the blocks above.

Runtime messages have a different layout. The first line begins with Exception in thread "main" and gives the type and detail of the exception: java.lang.ArithmeticException: / by zero. The lines below it that begin with at are the stack trace: they list which methods were on the call stack at the moment of the error, starting from the innermost method. at Bug3.main(Bug3.java:4) says the error occurred in the main method of the class Bug3, at line 4 of the file Bug3.java. In the first programs the stack trace is a single line, because only main runs. As methods call one another, the trace gets longer.

5.11.5Fixing errors in order

A program can have more than one error. The compiler does not always report them all at once. The following program has two errors: the semicolon is missing on line 3, and the method name is wrong on line 4.

public class Score {
    public static void main(String[] args) {
        int score = 85
        System.out.printn("Score: " + score);

5.12Before coding

Knowing how to read error messages is important, but the cheapest error is the one never made. Most logic errors can be prevented by a little preparation on paper before the code is written.

5.12.1A program is a recipe

A recipe lists the ingredients, gives the steps in order, and says what will be obtained at the end. A program has the same structure. The inputs correspond to the ingredients, the statements to the steps of the recipe, and the output to the finished dish. In a good recipe it is clear what each step requires and what it produces: "After the dough has risen (precondition), it goes into the oven and bakes for 30 minutes (step); the bread browns (result)."

Figure 5.26 gives the recipe of a program that finds the average of two grades in four steps. The precondition and the value produced by each step are clear:

  1. Take the input. There is no precondition. It produces the values grade1 and grade2.
  2. Validate. Precondition: two grades have been read. Each grade is checked to be between 0 and 100. If there is an invalid grade, the recipe stops here and gives an error message.
  3. Process. Precondition: both grades are valid. The average is computed as (grade1 + grade2) / 2.
  4. Produce the result. Precondition: the average has been computed. A line such as "Average: 80" is printed.

The recipe should be tested by hand before coding. When the steps are followed for 70 and 90, does 80 come out? 160 / 2 = 80; yes. If 101 is entered, which step stops it? The second: because 101 > 100, the validation fails. Testing by hand catches logic errors before any code is written. In the order-of-operations example (a + b / 2), the error could have been seen at the recipe stage, because the recipe clearly says "first add, then divide."

Large recipes are divided into sub-recipes. In a cake recipe, "prepare the cream" can be a recipe of its own. In programs too, large jobs are divided into subtasks; in Java each subtask is written as a method. For the first programs a single main method is enough, but the recipe way of thinking should become a habit from the start.

5.12.2Sample input and expected output

There are four jobs to do before starting to code:

  1. Write down sample inputs and the expected output for each.
  2. Break the solution into steps in natural language or pseudocode.
  3. Determine the boundary cases and what to do on invalid input.
  4. Only then translate the steps into Java constructs.

That is why choosing different kinds of examples matters. A program tested only with typical inputs can hide a mistake such as the fractional part being discarded in the quotient of two integers. For example, for 75 and 80 the correct average is 77.5, but the quotient of two ints gives 77. This mistake does not show up until an input with an odd sum is tried.

5.13Summary

  • A program is a whole made of commands that a computer executes to perform a task; it takes input, processes it, keeps state, and produces output. A programming language is studied from the aspects of syntax, semantics, type system, and execution model.
  • Source code is written in a plain-text .java file. The character encoding (UTF-8), the line endings, and the file name must be consistent. The editor, the IDE, javac, java, javadoc, and version control are the tools on the program's journey.
  • Java was born at Sun Microsystems in 1995; it has been developed by Oracle since 2010, and its source code is in OpenJDK. Its design goal is the principle of write once, run anywhere. A new release comes out every six months; 8, 11, 17, 21, and 25 are LTS releases.
  • JDK = JRE + development tools; JRE = JVM + class library. The JVM executes bytecode; it contains the class loader, the verifier, the interpreter, the JIT compiler, and the garbage collector.
  • All Java code is inside a class. The name of the public class is the same as the file name. The JVM starts running at the method with the signature public static void main(String[] args). A main with a wrong signature compiles but cannot be launched. Java is case-sensitive.
  • Command-line arguments reach main through the args array; indices start at 0, and args.length is the number of arguments. Accessing an argument that does not exist throws ArrayIndexOutOfBoundsException at run time.
  • println adds a newline after writing; print does not. Escape sequences (\n, \t, \", \\, \', \u) put special characters into a string. In Windows paths, a single backslash either gives a compile error or silently produces wrong output.
  • + adds between two numbers and concatenates if one of the operands is a string. Operations are performed left to right; * and / come first: "Score: " + 40 + 45 → Score: 4045, "Score: " + (40 + 45) → Score: 85.
  • javac Hello.java compiles and produces Hello.class; java Hello runs it. When the source changes, it must be recompiled, because the JVM runs only the .class file. If there is a compile error, no .class is produced.
  • Bytecode is processor-independent and is stored in files that begin with CA FE BA BE. The JVM is a stack machine: iload pushes values onto the operand stack, iadd adds the values on the stack, and istore writes the result to a local variable. javap -c shows bytecode in readable form.
  • The compiler splits code into tokens: keyword, identifier, literal, operator, separator. Whitespace only separates tokens; indentation is for the reader. An expression produces a value, a statement completes an action, and a block groups statements.
  • Comments are written with //, /* */, and /** */ and do not enter the bytecode. /* */ cannot be nested; comment markers inside quotes are part of the text.
  • Syntax and type errors are found at compile time, runtime errors while running, and logic errors only when the result is checked. A javac message has the form file:line: error: description; the ^ shows where the error was noticed. The stack trace in a runtime message gives the method and the line of the error. Errors are always fixed starting from the first error.
  • Before coding, sample inputs, expected outputs, boundary cases, and error behavior are determined; the recipe is tested by hand.

5.15Test Yourself

  1. A computer has only a JRE installed and no JDK. Can Hello.java be compiled on this computer? Can a Hello.class compiled on another computer be run?

    Answer

    It cannot be compiled: javac is a development tool and exists only in the JDK. It can be run: the JRE contains the JVM and the class library, which is enough for java Hello. With one condition: the .class file must not have been compiled with a JDK newer than the JRE's version. Otherwise you get an UnsupportedClassVersionError.

  2. What is the output of the following program, and how many lines does it produce?

    public class TY2 {
    public static void main(String[] args) {
        System.out.print("1");
        System.out.print("2\n3");
        System.out.println("4");
        System.out.print("\"5\"");
        System.out.println();
    }
}
    Answer 
    12
34
"5"

    Three lines are produced. "1" and "2" are written on the same line; the \n in "2\n3" ends the line and "3" starts on the line below. println("4") writes "4" on the same line and ends it. Because \" writes a double quote, the third line is "5"; the final println() ends this line.

  3. What is the output of the following program? In each line, which of the + signs is addition and which is concatenation?

    public class TY3 {
    public static void main(String[] args) {
        System.out.println("Result: " + 10 / 4 + 1);
        System.out.println(10 / 4 + 1 + " items");
        System.out.println("Result: " + (10 / 4 + 1));
    }
}
    Answer 
    Result: 21
3 items
Result: 3

    Line 1: / is performed first, 10 / 4 = 2 (integer division). Then "Result: " + 2 is concatenation and gives "Result: 2"; + 1 is also concatenation: Result: 21. Line 2: 10 / 4 = 2, and 2 + 1 is addition because it is between two numbers and gives 3; 3 + " items" is concatenation. Line 3: the parentheses are computed first, 2 + 1 = 3; then concatenation is done.

  4. The program B is below. What happens when it is run with the commands java B and java B Ece? What kind of error is it?

    public class B {
    public static void main(String[] args) {
        System.out.println("First argument: " + args[0]);
    }
}
    Answer 
    > java B
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0
	at B.main(B.java:3)
> java B Ece
First argument: Ece

    When no argument is given, args is an empty array (length 0) and args[0] does not exist. The JVM throws ArrayIndexOutOfBoundsException on line 3. Because the program compiled and the error occurred while running, depending on the input, it is a runtime error. With a single argument the program runs without trouble.

  5. What kind of error is each of the following: syntax, type, runtime, or logic? (a) Public class D { (b) int x = 3.5; (c) Writing 2 * a + b for the perimeter of a rectangle (d) int a = 10, b = 0; then a / b.

    Answer

    (a) A syntax error: Public with a capital letter is not a keyword, and the compiler expects a class declaration at the start of the line. The message: class, interface, enum, or record expected. (b) A type error: 3.5 is a fractional number and does not fit into int. The message: incompatible types: possible lossy conversion from double to int. (c) A logic error: the code compiles and runs, but the correct form is 2 * (a + b). (d) A runtime error: ArithmeticException: / by zero.

  6. Does the statement System.out.println("C:\temp\new"); compile? If it does, what does it print? How is the correct path written?

    Answer

    It compiles, because \t and \n are valid escape sequences. But the output is wrong: \t becomes a tab and \n a newline. The screen shows "C:", a tab's worth of space, and "emp", and "ew" on the next line:

    C:	emp
ew

    The correct way to write it is "C:\\temp\\new" or "C:/temp/new".

  7. For the main method of the following program, what are the first eight instructions in the javap -c output? Why does the order of the iload instructions matter?

    public class Subtract {
    public static void main(String[] args) {
        int a = 2;
        int b = 5;
        int c = b - a;
        System.out.println(c);
    }
}
    Answer 
    public static void main(java.lang.String[]);
  Code:
     0: iconst_2
     1: istore_1
     2: iconst_5
     3: istore_2
     4: iload_2
     5: iload_1
     6: isub
     7: istore_3
     8: getstatic     #7                  // Field java/lang/System.out:Ljava/io/PrintStream;
    11: iload_3
    12: invokevirtual #13                 // Method java/io/PrintStream.println:(I)V
    15: return

    a is in slot 1 and b in slot 2. For b - a, first b (iload_2) and then a (iload_1) are pushed onto the stack. isub subtracts the top value from the value below it: 5 − 2 = 3. In addition the order does not change the result, but in subtraction it does; the loading order follows the order of the operands in the source code. The program prints 3.

  8. Hello.java has been compiled and a Hello.class that prints Hello has been produced. Then in the source "Hello" is changed to "Hi" and saved, and without recompiling, the commands java Hello, java Hello.java, java Hello are run in turn. What does each command print?

    Answer 
    > java Hello
Hello
> java Hello.java
Hi
> java Hello
Hello

    java Hello runs the old bytecode in the .class file and prints Hello. java Hello.java, however, compiles the source file in memory on the spot and runs it, printing Hi; it does not touch the .class file on disk. So the last command again prints Hello. The .class is renewed only by javac.

  9. The following program is compiled. How many compilations are needed for the program to compile without errors? What message is received in each compilation?

    public class Two {
    public static void main(String[] args) {
        System.out.println("A")
        system.out.println("B");
    }
}
    Answer

    Three compilations are needed. The first compilation reports only the syntax error; the lowercase mistake on line 4 is not visible yet:

    Two.java:3: error: ';' expected
        System.out.println("A")
                               ^
1 error

    When ; is added to line 3, the second compilation moves on to semantic checking and reports line 4:

    Two.java:4: error: package system does not exist
        system.out.println("B");
              ^
1 error

    When system is changed to System, the third compilation succeeds. There were two errors, but the compiler showed only one each time.

  10. A program is to be written that takes the side lengths of a rectangle and prints its area. Which sample inputs and expected outputs should be written in a table before coding?

    Answer

    A sample table: typical case, 3 and 4 → 12. A square, 5 and 5 → 25 (it must work when the two sides are equal too). A boundary case, 0 and 7 → 0 or the message "a side cannot be 0"; which of the two is wanted must be decided beforehand. Invalid input, −2 and 4 → an error message (a length cannot be negative). These last two rows bring out, before coding, decisions that were left missing in the problem definition.
