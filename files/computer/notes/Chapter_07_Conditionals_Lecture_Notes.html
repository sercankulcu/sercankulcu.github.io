Chapter 7: Conditionals

So far, the Java programs we have written execute the same lines in the same order every time they run. Real programs behave differently depending on the situation. A score below 60 prints “Fail”; otherwise the program prints “Pass”. A division is skipped when the divisor is zero. A warning appears when the user enters month 13. This chapter describes the constructs that let a program look at a condition and choose one of several paths. We begin with sequential execution and the idea of a condition. Next come if, if-else, the else-if chain, and nested decisions. Logical operators, short-circuit evaluation, the conditional operator, and string comparison let us write decisions more compactly and more safely. The switch construct selects among the discrete values of a single expression. The examples in the last section combine all of these constructs in realistic problems. Every program was compiled and run with JDK 21; the outputs shown are the programs' actual outputs.

7.1Control flow

A program is a list of statements given to the computer. A statement is the smallest complete unit of a program that does one job: declaring a variable, assigning a value, printing a line. In Java every simple statement ends with a semicolon. The order in which the computer executes these statements is called control flow. The language constructs that determine the flow are collectively called control structures.

7.1.1The three basic flows

However large an algorithm is, it can be written with only three forms of flow. Figure 7.1 shows the three side by side.

Definition 7.1

A sequence structure is a flow in which statements run exactly once each, in the order written. A selection structure is a flow in which one of several paths is chosen according to the value of a condition; it is also called a conditional structure. A repetition structure is a flow in which a block of code runs over and over for as long as a condition holds.

Each of these three structures has a single entry and a single exit, so they can be nested inside one another. A branch of a decision can contain a sequence of statements, and the body of a loop can contain a decision. This chapter treats selection in detail. A sequence is the building block of a decision, so we examine it first.

7.1.2Sequence

The following four lines compute the area of a triangle. The base is 8 units and the height is 5 units.

double base = 8;
double height = 5;
double area = base * height / 2;
System.out.println(area);

The lines run from top to bottom. The first line creates the variable base and stores 8 in it. Because the variable's type is double, the integer 8 is converted automatically to 8.0. A conversion from a smaller type to a larger type is called a widening conversion. The second line does the same for height. The third line uses the values of the previous two variables and computes the area. The fourth line prints the result.

Figure 7.2 uses arrows to show the dependencies between lines. The third line needs the values produced by the first and second lines. Every statement can use the state left behind by the statements before it. That is the essence of a sequence.

7.2Conditions and if

At the heart of a selection structure is a question: “Is the score 60 or more?”, “Is the number negative?”, “Is the divisor zero?” Which path the program takes depends on the answer. In Java, this question is written as a condition.

7.2.1Conditions: expressions that produce a boolean

Definition 7.2

A condition is an expression whose value is true or false. The Java type that holds these two values is called boolean. Only an expression that produces a boolean value may appear in the parentheses of an if statement.

Most conditions are built by comparing two values. Java's six comparison operators are listed in Table 7.2. Each takes two numbers and produces a boolean value.

Equality is tested with two equal signs (==). A single equal sign (=) is an assignment. Confusing the two is one of the most common mistakes beginners make. Fortunately, Java catches this confusion at compile time:

    public static void main(String[] args) {
        int x = 7;
        if (x = 5) {

In Java, numbers and booleans are separate types; this strictness eliminates a whole class of errors.

7.2.2The one-way if

The simplest decision does a job if the condition is true and does nothing if it is false. For example, to turn a negative number into a positive one, an operation is needed only when the number is negative:

if (num < 0) {
    num = -num;
}

When execution reaches the if line, the expression in the parentheses is evaluated first. If the result is true, the statements between the braces run. If the result is false, those statements are skipped and execution continues at the line after the closing brace. In both cases the program reaches the next line; the work in between is either done or not. This pattern is traced in detail in the absolute value example.

7.2.3The if-else statement

Many decisions have a separate job for each of two cases. If the score is 60 or more, the program must print “Pass”; otherwise it must print “Fail”. For this we add an else branch to the if.

Definition 7.3

An if-else statement consists of two branches. If the condition is true, the body of the if runs; if it is false, the body of the else runs. On every execution exactly one of the branches runs; never both, and never neither. A branch is each of the paths that can be followed after a decision.

if (score >= 60) {
    System.out.println("Pass");
} else {
    System.out.println("Fail");
}

In Figure 7.3, two arrows leave the decision box. One is labeled true and the other false. For any given score, only one of the two can be followed. At the ends of the arrows the two paths merge again; the program continues from the same point after the decision.

The boundary value in the condition needs care. With score >= 60, 60 falls on the “Pass” side. If score > 60 had been written, a student with exactly 60 would fail. The most common error in a decision is putting the boundary on the wrong side. For this reason a decision is always tested with the boundary value and with its two neighbors (such as 59 and 61). Every possible value goes to exactly one branch: scores from 0 to 59 go to the else branch, and 60 and above go to the if branch.

7.2.5Blocks, braces, and the empty statement

A group of statements between braces is called a block. Java's rule is this: the body of an if and the body of an else is a single statement. A block counts as one statement, however many statements it contains. When the body is a single simple statement, the braces may be omitted:

if (score >= 60)
    System.out.println("Pass");
else
    System.out.println("Fail");

This form is short, but it has two traps. The first appears when a second line is added to the body. The indentation suggests that the added line also belongs to the if, but the compiler does not look at indentation. Without braces, the if controls only the single statement that immediately follows it; the second line runs in every case.

public class NoBraces {
    public static void main(String[] args) {
        int x = 2;
        if (x > 5)
            System.out.println("A");
            System.out.println("B");
        System.out.println("C");
    }
}
B
C

For x = 2, 2 > 5 is false. Only println("A") is skipped. Although the “B” line is indented, it is outside the if and it runs. If the programmer meant to control both A and B, the two lines must be enclosed in braces.

The second trap is a semicolon accidentally placed at the end of the if line. A lone semicolon is also a statement in Java: the empty statement, which does nothing. When you write if (x > 0);, the body of the if becomes this empty statement. The line below is no longer controlled by the condition.

public class EmptyStatement {
    public static void main(String[] args) {
        int x = -3;
        if (x > 0);
            System.out.println("Positive");
        System.out.println("Done");
    }
}
Positive
Done

Although x = −3, “Positive” is printed. −3 > 0 is false and the empty statement is skipped, but there is nothing else to skip. The compiler does not count this line as an error because nothing breaks the rules. The mistake shows up only in the program's output.

Common mistake

Adding a second line to the body of a one-line if later and forgetting the braces. Because the indentation looks right, the error goes unnoticed. For this reason many coding guidelines require braces even when the body is a single line. Braces also make the if (...); mistake visible: a line such as if (x > 0); { stands out when read.

7.3Multiway decisions

Decisions with two options are built with if-else. What happens when there are more than two options? Converting a score to a letter grade needs four options: 90 and above is A, 80–89 is B, 70–79 is C, and below 70 is F. A decision of this kind is called a multiway decision.

7.3.1The else-if chain

Definition 7.4

An else-if chain is a multiway decision built by putting a new if in the body of each else. The conditions are tried in order from top to bottom. The branch of the first condition that is true runs; the rest of the chain is skipped without being checked. If no condition holds, the final else, if there is one, runs.

if (score >= 90) {
    grade = 'A';
} else if (score >= 80) {
    grade = 'B';
} else if (score >= 70) {
    grade = 'C';
} else {
    grade = 'F';
}

Seeing that the chain actually consists of nested if-else statements makes the rule easier to understand. The body of the first else is the second if; the body of its else is the third if. Because the code would shift a little further right at every level, Java programmers write else if on the same line and keep all the branches aligned. As far as the language is concerned, there is no separate keyword else if; it is only a writing habit.

Figure 7.5 shows the shape of the chain. The false arrow of each decision box leads to the next decision. The true arrows go down to the assignment boxes. All paths finally merge at the “print grade” box. In one run, at most one assignment box runs.

7.3.2Tracing the chain step by step

Here is the short form of the letter-grade program. Because the branches are single statements, no braces are used; the conditions and assignments are aligned to keep the code readable.

int score = in.nextInt();
char grade;
if (score >= 90)      grade = 'A';
else if (score >= 80) grade = 'B';
else if (score >= 70) grade = 'C';
else                grade = 'F';
System.out.println(grade);

The char grade; on the second line declares the variable but gives it no value. One of the branches of the chain assigns the value. Let the program run for 75, 95, and 50.

For 75, the first two conditions are false: 75 >= 90 and 75 >= 80. The third condition, 75 >= 70, is true, so grade = 'C' is executed. Even if no further conditions remained in the chain, the rule would be the same: after the chosen branch, execution jumps directly to the end of the chain. For 95, the first condition is true; the other two conditions are never evaluated. For 50, all three conditions are false and the else runs.

The boundaries of the chain should be tested too. The program was also run for 90, 89, 80, 70, and 69. It printed A, B, B, C, and F, respectively. A difference of a single unit between 90 and 89, or between 70 and 69, changes the grade; each threshold includes its own value.

7.3.3The order of thresholds

Each condition in the chain sets a lower bound on its own: “at least 80”, “at least 70”. No upper bound is written. The condition of the B branch does not have to be score >= 80 && score < 90, because execution reaches B's condition only if A's condition is false; at that point it is already known that the score is less than 90. In a chain, every condition automatically carries the knowledge that the previous conditions were false.

This convenience carries a responsibility: the thresholds must be written from largest to smallest. The following program shows what happens when the order is reversed.

import java.util.Scanner;

public class ReversedThresholds {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int score = in.nextInt();
        if (score >= 60) System.out.println("D");
        else if (score >= 70) System.out.println("C");
        else if (score >= 80) System.out.println("B");
        else if (score >= 90) System.out.println("A");
        else System.out.println("F");
    }
}
D

For 85, the first condition 85 >= 60 is true and D is printed. The rest of the chain is skipped. The program also prints D for 95. Every score of 60 and above gets a D. The C, B, and A branches cannot be reached with any input. Such code does not produce a compile error; the mistake shows up only when it is tested with an input whose correct output is known.

Common mistake

Arranging the thresholds from smallest to largest in a chain built on lower bounds. The general rule is: ask the narrower condition first. Every score that satisfies “at least 90” also satisfies “at least 70”. If the broader condition is asked first, the narrower one never gets its turn.

7.3.4Independent ifs versus an else-if chain

If the same three conditions are written one under another without the else keywords, a completely different program results. This form is called independent ifs: none of them is in the else branch of the previous one, and each is checked independently of the others.

int score = 95;
if (score >= 90) System.out.println("A");
if (score >= 80) System.out.println("B");
if (score >= 70) System.out.println("C");

For score = 95, all three conditions are true and three lines are printed. The first if printing A does not affect the second if; the second if is still tested. One expects a student to receive a single letter, but three letters appear. When the same conditions are linked with else if, only the first true branch runs:

In the independent form, a later assignment overwrites an earlier one. Because only a single letter is visible on the screen, the output “looks right”, but the grade is wrong.

public class IndependentGrade {
    public static void main(String[] args) {
        int score = 95;
        char grade = 'F';
        if (score >= 90) grade = 'A';
        if (score >= 80) grade = 'B';
        System.out.println(grade);
    }
}
B

Independent ifs are not always wrong. When each of several independent questions is to be asked separately, it is the right structure. For example, on an application form, separate warnings are written for “Is the name empty?”, “Is the e-mail invalid?”, and “Is the age under 18?” One being true should not prevent the others from being asked. The rule of choice is this: use else if when only one of the options can apply, and independent ifs when each can apply on its own.

7.3.5The final else and a variable that was never assigned

The else at the end of the chain catches the case in which no condition holds. This branch is not mandatory. But if it is deleted from the letter-grade program, the Java program does not compile:

public class UnassignedGrade {
    public static void main(String[] args) {
        int score = 75;
        char grade;
        if (score >= 90)      grade = 'A';
        else if (score >= 80) grade = 'B';
        else if (score >= 70) grade = 'C';
        System.out.println(grade);
    }
}
UnassignedGrade.java:8: error: variable grade might not have been initialized

The message means “the variable grade might not have been given a value”. The compiler examines all paths. When all three conditions are false, no value is assigned to grade. If execution reached the println(grade) line along that path, there would be no value to print. Java does not allow an unassigned local variable to be read. This rule prevents programs in which “it is unclear what the variable holds” already at compile time.

The problem can be solved in two ways: either the final else is put back, or the variable is given an initial value when it is declared (char grade = 'F';). The first way is clearer: the code shows one by one which letter each possible score goes to.

7.4Nested decisions

Some questions make sense only after the answer to another question is known. For permission to drive a vehicle, age is checked first. If the person is under 18, there is no point asking whether they have a license. If the age is sufficient, the second question is asked: do they have a license?

7.4.1A decision inside a branch

Definition 7.5

A nested decision is a selection structure placed inside one of the branches of another selection structure. The inner condition is checked only when the outer condition selects that branch.

int age = in.nextInt();
boolean license = in.nextBoolean();
if (age >= 18) {
  if (license)
    System.out.println("Can drive");
  else
    System.out.println("Get a license first");
} else {
  System.out.println("Too young");
}

Figure 7.8 shows the structure. There is a second decision box in the true branch of the outer decision. This box is reached only when the age condition is satisfied. The program has three possible outputs, each at the end of a separate path.

In the code, nextBoolean() reads the word true or false from the keyboard and converts it to a boolean value. The form if (license) is also worth noting. license is already a boolean variable; there is no need to write if (license == true). The variable itself is the condition.

7.4.3Using && instead of nesting

A nested structure shifts the code a little further right at every level. At a depth of three or four levels, it is hard to follow which else belongs to which if. In many cases, nested decisions can be turned into a flat chain by combining them with the logical AND (&&):

import java.util.Scanner;

public class LicenseAnd {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int age = in.nextInt();
        boolean license = in.nextBoolean();
        if (age >= 18 && license)
            System.out.println("Can drive");
        else if (age >= 18)
            System.out.println("Get a license first");
        else
            System.out.println("Too young");
    }
}

7.4.4The dangling else

When braces are not used in nested ifs, an ambiguity arises. In the following code there is a single else but two ifs. Which one does the else belong to?

int a = -1, b = 5, x = 0;
if (a > 0)
    if (b > 0)
        x = 1;
    else
        x = 2;
System.out.println(x);
Definition 7.6

The dangling else is the situation in nested ifs without braces in which the notation does not make clear which if an else is attached to. Java's rule is definite: an else is attached to the nearest preceding if that does not yet have an else. Indentation does not change this rule.

In the code, the else is written aligned with the inner if; here the indentation agrees with the rule. Even so, a programmer might take the else to belong to the outer if. Let the initial values be a = −1, b = 5, x = 0. The steps are as follows:

  1. a > 0 is evaluated: −1 > 0 is false.
  2. The body of the outer if is skipped. This body is a single statement consisting of the inner if and its else. Therefore the else is skipped as well.
  3. x never changes; 0 is printed.
0

A programmer who believes the else belongs to the outer if expects 2. In reality the else is attached to the inner if, and since the inner if is never reached, it does not run either. The rule becomes even clearer when the same code is tried with different inputs:

Common mistake

Working out what the code does by looking at the indentation. Indentation is meant only for the reader; to the Java compiler, spaces and line breaks are meaningless. Writing every body with braces in nested ifs removes the ambiguity entirely. The “format code” command of development environments also rearranges the indentation to match the structure the compiler sees; a dangling else moves to its real place after formatting.

7.5Decisions with logical operators

Real decisions often depend on more than one condition. An application is accepted if the person is 18 or older and has a document. A day is part of the weekend if it is Saturday or Sunday. The Java counterparts of the connectives “and”, “or”, and “not” are the logical operators.

7.5.1&&, || and !

7.5.2Short-circuit evaluation

&& and || evaluate the left side first. If the left side alone determines the result, the right side is not evaluated at all.

Definition 7.8

Short-circuit evaluation: in the expression a && b, if a is false, the result is false whatever b is, and b is not evaluated. In a || b, if a is true, the result is true and b is not evaluated. The right side is evaluated only when it is needed to determine the result.

In this example, short-circuiting is only a small time saving. Its real importance appears where the right side can be evaluated safely only when the left side is true. A divisor that must not be zero in a division is such a condition:

If b = 0, the left side is false and a / b is never evaluated. Division by zero with integers is an error that stops the program. Short-circuiting places the right side of the condition under the protection of the left side. Order matters: had a / b > 1 && b != 0 been written, the division would be performed before the check.

7.5.3De Morgan's laws

If we need to write the case in which the application is rejected, the most direct way is to put ! in front of the acceptance condition: !(age >= 18 && hasDoc). This form is correct but hard to read. The reader must first think about the inside of the parentheses and then about its opposite. De Morgan's laws let us distribute ! into the parentheses and obtain a flatter condition.

Theorem 7.1 (De Morgan's laws)

For all boolean values a and b,

!(a && b) == (!a || !b) and !(a || b) == (!a && !b)

hold. When ! is distributed into the parentheses, && and || swap places and each term is negated.

The proof is by truth table. There are only four combinations of values that a and b can take; if both sides give the same value in all four, the equality holds in every case. Table 7.11 gives the four rows. The table was produced by a Java program that computed the four combinations one by one.

Example 7.1

How can the case in which a temperature is not between 15 and 30 (both bounds included) be written without using !?

Solution. The inside of the range is t >= 15 && t <= 30. The outside is its opposite: !(t >= 15 && t <= 30). By De Morgan's law, && turns into || and each term is negated: !(t >= 15) → t < 15, !(t <= 30) → t > 30. The result is t < 15 || t > 30. A temperature cannot be below 15 and above 30 at the same time, so if && had been kept in the condition, no value would satisfy it.

7.6The conditional operator ?:

When the only job of a decision is to give a variable one of two values, if-else takes four lines:

int max;
if (a > b) max = a;
else       max = b;

Java offers a shorter notation for this pattern.

Definition 7.9

The conditional operator (also called the ternary operator because it takes three operands) is written as condition ? value1 : value2. If the condition is true, the value of the expression is value1; if it is false, the value is value2. Only the selected value is evaluated.

An if-else is a statement: it does something but does not produce a value. The conditional operator, however, is an expression: it produces a value. It can therefore be used on the right side of an assignment, in the argument of a method, or inside another expression.

int a = 7, b = 12;
int max = (a > b) ? a : b;
System.out.println(max);

The steps are as follows. First the condition is evaluated: 7 > 12 is false. Because the condition is false, the value after the colon (:), that is, b, is chosen. The value of the expression is 12 and it is assigned to max. The program prints 12:

12

The conditional operator can also be nested. An expression that finds the sign of a number as “+”, “-”, or “0” looks like this:

String sign = n > 0 ? "+" : n < 0 ? "-" : "0";

The conditional operator groups from the right. The expression is read as n > 0 ? "+" : (n < 0 ? "-" : "0"). For n = −5, the first condition is false; the part in parentheses is evaluated, and since −5 < 0 is true, “-” is chosen. This is a short and correct expression, but three or four levels of nested conditional operators become unreadable. The conditional operator is most useful for short selections between two values. When the options multiply, an else-if chain or a switch is clearer.

The two values of a conditional operator must have compatible types. int m = a < b ? a : "none"; does not compile, because one branch of the expression is an int and the other is a string, and the result cannot be put into an int variable.

7.8switch

An else-if chain can build any multiway decision. In some decisions, however, all the conditions test the same variable in the same way: month == 1, month == 2, … month == 12. Grouping the twelve months into seasons would need a long || chain. The switch construct makes decisions of this kind shorter and more readable.

7.8.1When to use switch

switch compares the value of a single expression with a series of constants and goes to the matching option. In Figure 7.13, the month value is routed to one of five options. The options are written with case labels. Each label carries one or several constant values. If no label matches, default is chosen.

In an else-if chain, the conditions are tried in order. In a switch, the program goes directly to the case that matches the value; the labels in between are not “tried and passed”. A switch is therefore suitable for choices made among the discrete values of a single variable: a month number, a day number, a menu option, an operator sign. Range conditions (“if the score is greater than 85”) and complex conditions that depend on several variables are written with if-else.

The value in a case label must be a constant known at compile time: 4, 'A', "+". A variable cannot be a label:

public class VariableCase {
    public static void main(String[] args) {
        int month = 4, limit = 4;
        switch (month) {
            case limit -> System.out.println("equal");
            default -> System.out.println("different");
        }
    }
}

7.8.2The switch expression

In the newer notation introduced in Java 14, each case is written with an arrow (->) and a switch can produce a value.

Definition 7.10

A switch expression is a switch that produces the value of the selected case as its result: x = switch (…) { … };. 7.8.5Classic switch, break, and fall-through

Before the arrow form, a switch in Java was written only with a colon (:). This classic notation is still valid today and is often seen in old code. In a classic switch, case labels are only entry points. The program enters at the matching label and runs all the code below until it sees break or reaches the end of the switch.

Definition 7.12

Fall-through is what happens in a classic switch when the code of a case finishes without a break: execution passes into the code of the next case. The label of the next case is not checked in the process. The break statement exits the switch.

int day = 2;

  case 2: System.out.println("Tue");
  case 3: System.out.println("Wed"); break;
  default: System.out.println("None");

Execution passes to the line below, the code of case 3:. That the label is 3 does not matter; a label is only an entry point. “Wed” is printed. The break on this line exits the switch and default does not run (Figure 7.15). The same program printed only “Mon” for day = 1, only “Wed” for 3, and “None” for 9.

Fall-through is sometimes used on purpose: so that several cases do the same job, the labels are written one under another and the code is put only under the last one. In the arrow form, this need is met by the comma-separated list. The following program separates weekdays from weekend days without needing fall-through:

Common mistake

Forgetting break in a classic switch. The program compiles and may even work correctly for most inputs; the error shows up only when the case missing its break is selected, through the extra lines it prints. Another misconception is to think that default always runs last. default can also be written in the middle of a switch, and the fall-through rule applies to it too: if it has no break, execution falls into the code of the case below it.

7.9.3Leap year

The Earth takes about 365.2425 days to complete one orbit around the Sun. The calendar balances this surplus with leap years, that is, years of 366 days. The rule of the Gregorian calendar has three steps:

  1. years divisible by 4 are leap years;
  2. but years divisible by 100 are not leap years;
  3. but years divisible by 400 are leap years again.

The rule can be collected into a single boolean expression: “divisible by 4 and not divisible by 100” or “divisible by 400”.

Example 7.2

A program that prints whether the integer entered is positive, negative, or zero.

import java.util.Scanner;

A program that computes the body mass index from height (in meters) and weight in kilograms, BMI = weight / height², and prints its category. The limits: below 18.5 is underweight, from 18.5 to 25 is normal, and 25 and above is overweight.

import java.util.Scanner;

Example 7.4

Do three side lengths form a triangle? If so, is the triangle equilateral, isosceles, or scalene?

Solution. For three sides to form a triangle, the sum of any two sides must be greater than the third (the triangle inequality). First the opposite of this condition is checked: if any sum is equal to or smaller than the third side, there is no triangle. By De Morgan's law, the opposite of “all three inequalities are true” is “at least one is false”; that is why the terms are joined with ||. Then the type of triangle is tested from the narrow condition to the broad one: first equality of all three sides, then equality of any two sides.

import java.util.Scanner;

public class Triangle {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int a = in.nextInt(), b = in.nextInt(), c = in.nextInt();
        if (a + b <= c || a + c <= b || b + c <= a)
            System.out.println("Not a triangle");
        else if (a == b && b == c)
            System.out.println("Equilateral");
        else if (a == b || b == c || a == c)
            System.out.println("Isosceles");
        else
            System.out.println("Scalene");
    }
}

The program printed Equilateral for (3, 3, 3), Isosceles for (3, 3, 5) and (5, 3, 5), and Scalene for (3, 4, 5). For (1, 2, 3), since 1 + 2 = 3, it printed “Not a triangle”; these sides form a straight line. For (2, 9, 4), since 2 + 4 = 6 < 9, the same result came out. The equilateral condition must be asked before the isosceles one, because every equilateral triangle also satisfies the isosceles condition.

A program that finds the smaller of two numbers with the conditional operator and then extends this to three numbers.

Example 7.7

A check for “score outside the range 0–100” is to be added to the letter-grade program. Where in the chain should this check be written?

Solution. At the very beginning of the chain. If the check were put at the end, an invalid score, for example 105, would satisfy the first condition (105 >= 90) and receive an A; the check would never get its turn. −5 would similarly receive an F. Filtering out invalid cases at the start of the chain makes the later conditions work only with valid scores.

import java.util.Scanner;

    public static void main(String[] args) {

        int score = in.nextInt();
        if (score < 0 || score > 100)
            System.out.println("Invalid score");
        else if (score >= 90)
            System.out.println('A');
        else if (score >= 80)
            System.out.println('B');
        else if (score >= 70)
            System.out.println('C');
        else
            System.out.println('F');

}

7.10Summary

  • Every algorithm can be written with three flows: the sequence structure, the selection structure, and the repetition structure. In a sequence, statements run once each in the order written; each statement uses the values left by the previous ones.
  • A condition is a boolean expression that produces the value true or false. Equality is tested with ==; = is an assignment, and if (x = 5) does not compile. The notation 10 < x < 20 does not compile either; the correct form is x > 10 && x < 20.
  • if runs its body if the condition is true; if-else runs exactly one of its two branches. Without braces, the body is a single statement; the compiler does not look at indentation. The semicolon in a line if (…); is an empty statement.
  • In an else-if chain, the conditions are tried from top to bottom; the first true branch runs and the rest are skipped. In a chain built on lower bounds, the thresholds are written from largest to smallest. Independent ifs, on the other hand, are all checked.
  • If the final else is deleted, a variable assigned in the branches causes the “might not have been initialized” error. Java does not allow an unassigned local variable to be read.
  • In a nested decision, the inner condition is checked only when the outer condition selects that branch. Deep nesting can be flattened with &&. A dangling else attaches to the nearest if that has no else; the ambiguity is removed with braces.
  • && requires both sides to be true, || requires at least one side to be true; ! reverses. Both short-circuit: if the result is already determined by the left side, the right side is not evaluated. That is why b != 0 && a / b > 1 is safe. The single-character & and | always evaluate both sides.
  • De Morgan's laws: !(a && b) = !a || !b, !(a || b) = !a && !b. The opposites of the comparisons: >= ↔ <, > ↔ <=, == ↔ !=.
  • The conditional operator condition ? v1 : v2 is an expression that produces a value; it is used for short selections between two values and groups from the right.
  • For strings, == compares references and equals compares content. A string read from the keyboard gives false when compared with == to a literal carrying the same text. Always compare strings with equals.
  • switch chooses among the discrete values of a single expression; case labels are constants. A switch expression produces a value and must cover all values; for int and String, default is mandatory. The value of a branch with a block is given with yield.
  • In a classic switch, without break execution falls through into the code of the next case. In the arrow form (->) there is no fall-through. For ranges and complex conditions if-else is suitable; for the discrete values of a single expression, switch is suitable.
  • Lessons of the examples: the even test is done with % 2 == 0, because in Java -7 % 2 = -1. The absolute value of Integer.MIN_VALUE overflows in int. Math.sqrt gives NaN for a negative number, and floating-point division by zero gives Infinity. In the “candidate and compare” pattern, the candidate is initialized with one of the inputs.

7.12Try it yourself

  1. With p = 4 and q = 9, the line if (p > 3 || ++q > 0) p = p * 2; runs. What are p and q afterwards?

    Answer

    The left side 4 > 3 is true. || short-circuits and ++q never runs; q stays 9. Because the condition is true, p = 4 × 2 = 8. Result: p = 8, q = 9.

  2. With t = 15, what is the value of the expression t % 3 == 0 && t % 5 == 0 ? "FizzBuzz" : t % 3 == 0 ? "Fizz" : "other"? What happens for t = 9 and t = 7?

    Answer

    The conditional operator groups from the right; the expression reads “if the first condition is true, FizzBuzz; otherwise (if the second condition is true, Fizz; otherwise other)”. 15 is divisible by both 3 and 5: “FizzBuzz”. 9 is divisible by 3 but not by 5: the first condition is false and the second is true, “Fizz”. 7 is divisible by neither: “other”.

  3. What does the following code assign for score = 72? What happens for score = 90 and score = 40?

    if (score >= 50) {
    if (score >= 85) grade = "Excellent";
    else grade = "Pass";
} else grade = "Fail";
    Answer

    For 72, the outer condition 72 >= 50 is true and the inner condition 72 >= 85 is false: grade = "Pass". For 90, both conditions are true: "Excellent". For 40, the outer condition is false and the inner if is never checked: "Fail". The braces attach the inner else to the inner if and the outer else to the outer if.

  4. How can the condition if (!(temp < 15 || rain)) be written so that the ! operator remains only in front of the boolean variable? Is the condition true for temp = 30, rain = false?

    Answer

    By De Morgan's law, || turns into && and each term is negated: temp >= 15 && !rain. The opposite of < is >=. For 30 and false, 30 >= 15 is true and !false is true; the condition is true. In the original form too, 30 < 15 is false, rain is false, their OR is false, and its negation is true.

  5. A classic switch has the lines case 1: score += 10;, case 2: score += 20; break;, case 3: score += 30;, default: score += 5;. score starts at 0 each time. What is score for k = 1, 2, 3, and 4?

    Answer

    k = 1: there is no break in case 1, so execution falls into case 2: 10 + 20 = 30, then break. k = 2: only 20. k = 3: there is no break in case 3, so execution falls into default: 30 + 5 = 35. k = 4: no case matches, default: 5. Result: 30, 20, 35, 5.

  6. With char grade = 'B';, what is the value of switch (grade) { case 'A', 'B' -> "good"; case 'C' -> "fair"; default -> "poor"; }? What happens if the default line is deleted from this expression?

    Answer

    'B' is in the list of the first case: the value is "good". There is no fall-through in the arrow form; the second case does not run. If default is deleted, the program does not compile: a char can take more than 65 thousand values and a switch expression must cover all values. The compiler gives the message “the switch expression does not cover all possible input values”.

  7. With a = 5 and b = 0, what do the lines if (b == 0 || a / b > 2) and if (b == 0 | a / b > 2) do?

    Answer

    In the first line the left side is true; || short-circuits and the division is never evaluated. The condition is true and the body runs. In the second line, | evaluates both sides: the integer division 5 / 0 throws ArithmeticException: / by zero and the program stops.

  8. The user types “Ada” on the keyboard and this text is read into the variable name. What are the values of name == "Ada", name.equals("ada"), and name.equalsIgnoreCase("ada")?

    Answer

    name == "Ada" is false: the string read from the keyboard is a new object, while the literal is in the pool; the references differ. name.equals("ada") is false: the contents differ in letter case (“A” ≠ “a”). name.equalsIgnoreCase("ada") is true: letter case is ignored.
