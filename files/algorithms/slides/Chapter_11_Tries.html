Trie Basics

The Trie (Prefix Tree)

  • A tree-like data structure that stores strings for fast lookup.
  • The root is empty; each step down from the root represents one character.
  • Words are stored as paths from the root; common prefixes are stored only once.
  • Applications: autocomplete, spell checking, IP routing.
The name comes from retrieval (E. Fredkin, 1960). A double circle marks a node where a word ends.

Trie Basics

Why a Trie?

We want every word in a dictionary that starts with "an". How do different structures answer this?

Array / listCompare against every word: O(n · L) for n words. Slows down as the dictionary grows.
Hash tableFinds a whole word in O(L) on average, but cannot answer prefix queries: the hashes of "an" and "and" are unrelated.
TrieFollow branch "a", then "n" (2 steps); every word below that node starts with "an".
Search time in a trie depends on the length (L) of the key, not on the number of words stored.

Trie Basics

Basic Components

RootAn empty node; it represents no character and is where every search begins.
NodesThe path from the root to a node is a prefix; each node holds links to its children.
EdgesLinks between nodes; each edge carries one character.
End-of-word markisEnd: a word ends at this node.

The colored node represents the prefix "an"; "an" is not a word (unmarked), but it is a prefix of "and" and "ant".

Implementation

The Trie Node Class

public class TrieNode {
  TrieNode[] children;  // 'a'..'z'
  boolean isEnd;  // word ends here?

  public TrieNode() {
    isEnd = false;
    children = new TrieNode[26];
  }
}
  • Each node holds 26 child references, all null initially.
  • The character is not stored in the node: it is implied by which index of the parent the node sits at.
  • isEnd: is the path from the root to here a word?

The root's children array after inserting and, ant, dad, do: only 2 of the 26 cells are used (⁄ = null).

Insertion

Insertion

public void insert(String word) {
  TrieNode node = root;
  for (char ch : word.toCharArray()) {
    int i = ch - 'a';
    if (node.children[i] == null)
      node.children[i] = new TrieNode();
    node = node.children[i];
  }
  node.isEnd = true;
}
  1. Start at the root.
  2. For each character of the word, look at the matching child: children[ch − 'a'].
  3. If the child is null, create a new node; otherwise (a shared prefix) reuse the existing node.
  4. Move to that child.
  5. When the characters run out, set isEnd = true on the last node.
Time: O(L) (L = word length); at most L new nodes are created. Inserting the same word twice leaves the structure unchanged.

Search

Search

public boolean search(String word) {
  TrieNode node = root;
  for (char ch : word.toCharArray()) {
    int i = ch - 'a';
    if (node.children[i] == null)
      return false;
    node = node.children[i];
  }
  return node.isEnd;
}
  • Start at the root.
  • For each character, follow the matching branch (child).
    • If the branch is missing (null), the word is not in the trie.
  • At the end of the word, check isEnd:
    • true → the word is found;
    • false → not a word; it is only a prefix of a stored word.
Time: O(L). Even with a million words in the trie, "dad" is found in at most 3 steps.

startsWith("da") and startsWith("dog")

The trie holds and, ant, dad, do (ringed node = word end). First startsWith("da"): node is set to the root.

ch = 'd', i = 3: children[3] is set → node moves down to that child ("d").

ch = 'a', i = 0: children[0] is set → node moves down to that child ("da").

ch = 'o', i = 14: children[14] is set → node moves down to that child ("do").

Prefix Counter: countPrefix in O(P)

void insert(String word) { if (search(word)) return;
  TrieNode d = root;
  d.count++;
  for (char ch : word.toCharArray()) {
    int i = ch - 'a';
    if (d.children[i] == null) d.children[i] = new TrieNode();
    d = d.children[i];
    d.count++;          // one more word passed
  }
  d.isEnd = true;
}
int countPrefix(String prefix) {
  TrieNode d = root;
  for (char ch : prefix.toCharArray()) {
    d = d.children[ch - 'a'];
    if (d == null) return 0;
  }
  return d.count;
}

Wildcard Search: "d.d"

boolean wildcard(TrieNode d, String s, int j) {
  if (d == null) return false;
  if (j == s.length()) return d.isEnd;
  char ch = s.charAt(j);
  if (ch != '.')
    return wildcard(d.children[ch - 'a'], s, j + 1);
  for (int i = 0; i < 26; i++)
    if (wildcard(d.children[i], s, j + 1)) return true;
  return false;
}

  • Trie: and, ant, dad, do. Call wildcard(root, pattern, 0).
  • A normal letter narrows the search to one path; '.' tries every non-null branch (backtracking). The first match propagates true upward.
  • Worst case 26k branches for k wildcards, but empty branches return at once: the real cost is bounded by the paths that exist in the trie. A hash table can answer this only by scanning every word.

Spell Checking: Edit Distance on a Trie

  • Question: which dictionary words are within edit distance (insert / delete / replace) at most 1 of "dod"?
  • Instead of computing the distance to each word separately, traverse the trie depth-first; each node derives one DP row from its parent's row.
  • A common prefix's row is computed once: the "d" row serves both dad and do.
  • Pruning: if the row's minimum exceeds k, no word in the subtree can be within k; the minimum of row "an" is 2 > 1, so and and ant are never visited.
node"" d o dlastaction
a1 1 2 3—continue
an2 2 2 3—prune (min 2)
d1 0 1 2—continue
da2 1 1 2—continue
dad3 2 2 11suggest
do2 1 0 11suggest

The last cell of a row is the distance between the node's word and "dod".

Suggestions: dad (o → a) and do (delete the final d). O(|query|) work per row; thanks to pruning, most of the dictionary is never visited. The same traversal works with a weighted distance that makes adjacent keyboard letters cheap; as k grows, pruning weakens and the number of visited nodes rises quickly.

Autocomplete: complete("te")

First findNode("te") walks t → e from the root to node "te" (like a prefix query).

Starting at node "te", the subtree is traversed depth-first.

"te" is not a word (isEnd = false) → not added to the list.

"tea" is marked → added to result. No children; the loop passes over 26 empty indices.

The call returns; drop the last letter (path = "te") → backtracking.

Recursive call: collect("ted").

"ted" is marked → added to result. No children; the loop passes over 26 empty indices.

The call returns; drop the last letter (path = "te") → backtracking.

Recursive call: collect("ten").

"ten" is marked → added to result. No children; the loop passes over 26 empty indices.

The call returns; drop the last letter (path = "te") → backtracking.

List<String> complete(String prefix) {
  List<String> result = new ArrayList<>();
  TrieNode d = findNode(prefix);
  if (d != null)
    collect(d, new StringBuilder(prefix), result);
  return result;
}
void collect(TrieNode d, StringBuilder path,
           List<String> result) {
  if (d.isEnd) result.add(path.toString());
  for (int i = 0; i < 26; i++)
    if (d.children[i] != null) {
      path.append((char) ('a' + i));
      collect(d.children[i], path, result);
      path.setLength(path.length() - 1);
    }
}

longestCommonPrefix(): Code Trace

Trie: kar, kart, karton. Walk down from the root through nodes that have one child and are unmarked.

The root is unmarked; count its children: only 'k' is set → count = 1, only = 10.

Append 'k', d = "k". This node also has a single child ('a', only = 0).

Append 'a', d = "ka"; its single child is 'r' (only = 17).

Append 'r', d = "kar". "kar" is a word → the loop ends: even with a single child, the word "kar" does not share a longer prefix.

Returns "kar". With only kart and karton in the trie, the walk would continue to "kart" and stop at its end mark: "kart".

String longestCommonPrefix() {
  StringBuilder sb = new StringBuilder();
  TrieNode d = root;
  while (!d.isEnd) {
    int only = -1, count = 0;
    for (int i = 0; i < 26; i++)
      if (d.children[i] != null) { count++; only = i; }
    if (count != 1) break;  // branch or leaf
    sb.append((char) ('a' + only));
    d = d.children[only];
  }
  return sb.toString();
}

Deletion

Deletion: Three Cases

1. The word is a prefix of another wordThe last node has children → just set isEnd = false; no node is removed.
2. The word has a tail of its ownWorking back from the end, remove nodes that are childless and unmarked; stop at the shared prefix.
3. The word is not in the trieA branch is missing or the last node is unmarked → nothing changes.
Question: If the trie holds "apple" and "app", how does the structure change when "app" is deleted?
Show answer

Only the isEnd mark of the last 'p' node is cleared. The node cannot be removed, because "apple" continues below it (case 1).

Deletion · Step by step

Deletion Step by Step: app, apple, apt

Start: app, apple, apt (6 nodes excluding the root). Both scenarios below start from this trie.

delete("app"): follow a → p → p; node "app" is marked, so the word exists.

isEnd = false. The node has a child ('l'), so it is not removed → case 1. "apple" is still found.

delete("apple") (again from the original trie): follow a-p-p-l-e; "apple" is found.

Node 'e' loses its mark; it has no children → its parent removes it (children[4] = null).

Node 'l' is now childless and unmarked → it is removed too.

Node "app" is marked (another word) → deletion stops here. Result: app, apt; 4 nodes excluding the root (case 2).

Deletion

Deletion: Recursive Code

// true: the parent may remove d
boolean delete(TrieNode d, String k, int j) {
  if (j == k.length()) {        // end of word
    if (!d.isEnd) return false;
    d.isEnd = false;
    return isEmpty(d);          // childless?
  }
  int i = k.charAt(j) - 'a';
  TrieNode c = d.children[i];
  if (c == null) return false;  // no such word
  if (delete(c, k, j + 1)) {
    d.children[i] = null;       // remove the child
    return !d.isEnd && isEmpty(d);
  }
  return false;
}
  • Call: delete(root, word, 0); the root's return value is ignored.
  • First descend to the end of the word; removal decisions are made on the way back (bottom-up).
  • A node is removed only if it has no children and is unmarked.
  • isEmpty(d): are all 26 children null? (O(M)).
  • Time: O(L · M) with an array; O(L) if a child count is kept.
  • In the counting version, if the word exists (check with search first), do d.count-- at each node on the way down.

isEmpty(dad) = true: the node has no children → return true; the parent may remove it.

delete(da) returned true → d.children[3] = null: node "dad" is cut off.

"da" is unmarked and now childless → true: this node can be removed too.

delete(d) returned true → d.children[0] = null: node "da" is cut off.

"d" is unmarked but has the child 'o' for "do" → isEmpty is false → false. Deletion stops here.

// true: the parent may remove d
boolean delete(TrieNode d, String k,
            int j) {

    if (!d.isEnd) return false;
    d.isEnd = false;
    return isEmpty(d);   // childless?

Analysis

Pros and Cons

Pros

  • Fast prefix-based search: autocomplete.
  • Word lookup in O(L) time (L: word length).
  • Overlapping prefixes are stored once: shared memory.
  • Traversal yields words in lexicographic order; no hash collisions.

Cons

  • High memory use, especially with large alphabets.
  • Space complexity O(N · M) (N: number of nodes, M: alphabet size).
  • No gain for sets with few common prefixes (e.g. random keys).
  • Many small objects: not cache-friendly.

A hash table also reads all L characters to compute the key's hash, so for exact lookup the two are of the same order. The trie's edge is in prefix and ordered queries. S: number of nodes in the subtree of the prefix node.

Analysis

Lexicographic Order with a Trie: Sorting Strings

  • Input order: dog, ant, do, and, dad. Insert them all into a trie.
  • Traverse the trie in preorder from the root, visiting children in 'a' → 'z' order and emitting a word at each marked node.
  • Output: and, ant, dad, do, dog. A node is emitted before its children, so a prefix comes before its extensions (do < dog).
  • With N total characters and a fixed alphabet, insertion is O(N) and traversal O(N·M) (M = 26 child checks): no need for the O(n log n) comparisons of a comparison sort, each costing O(L).
  • The same idea underlies burst sort and string versions of MSD radix sort.

Applications and Variants

Applications

AutocompleteSearch boxes, IDEs: descend to the typed prefix's node and suggest the words in its subtree (most frequent first).
Spell checkingThe dictionary lives in a trie; for an unknown word, search the trie for nearby words via small edits (insert / delete / replace).
IP routingLongest prefix match with a binary trie (alphabet {0, 1}): address 0110… goes to the longest of 0* / 01* / 011*, namely 011*.
Word games and T9Boggle / word puzzles: abandon a path as soon as it is not a prefix (pruning). Suggesting words from a key sequence.
Longest prefix match: routes 0* → A, 01* → B, 011* → C. For address 0110…, descend 0 → 1 → 1 from the root; there is no '0' branch. The last route seen on the way is C → the packet goes to C.

longestMatch(): Routing with a Binary Trie

Binary trie (alphabet {0, 1}); some nodes carry a route. addr = "0110": d = root, best = null.

k = 0: no route at the root. Bit '0' → d = "0".

k = 1: node "0" has A → best = A. Bit '1' → d = "01".

k = 2: "01" has B → best = B (the longer prefix wins). d = "011".

k = 3: "011" has C → best = C. No '0' branch → d = null, return C.

New address "1001": k = 0, no route at the root; d = "1".

k = 1: "1" has D → best = D. No '0' branch → return D. Without a more specific route, the general one applies.

"1101": descend 1 → 11 → 110. "11" is an internal node (no route), so best stays D.

k = 3: "110" has E → best = E; no '1' branch → E. The number of steps is bounded by the address length.

String longestMatch(String addr) {
  BitNode d = root;
  String best = null;
  for (int k = 0; k < addr.length(); k++) {
    if (d.route != null) best = d.route;  // longer prefix
    d = d.children[addr.charAt(k) - '0'];
    if (d == null) return best;
  }
  return d.route != null ? d.route : best;
}

Applications and Variants

The Maximum XOR Pair with a Binary Trie

  • Question: which pair in [3, 10, 5, 25, 2, 8] maximizes a ⊕ b? Brute force tries n² pairs.
  • Insert the numbers into a 5-bit binary trie, starting from the most significant bit.
  • For each x, descend from the root and at every bit take the opposite branch if it exists: that bit of the result becomes 1. A 1 in a higher bit outweighs all lower bits combined, so the greedy choice is correct.
  • For x = 5 = 00101 we want 11010: 1 ✓ (25), 1 ✓, 0 ✓, no 1 → 0, no 0 → 1: we reach 11001 = 25, 5 ⊕ 25 = 28.
Methodtimen = 10⁵, B = 30
All pairsO(n²)≈ 5·10⁹ operations
Binary trieO(n·B)≈ 6·10⁶ steps

Applications and Variants

Ternary Search Tries

  • Each node holds one character and three links: left (smaller), mid (equal, go to the next character), right (larger).
  • A node's left/right chain is a small binary search tree over the “sibling” children of a trie.
  • Word ends are marked in the node (ring). Insertion order shapes the tree: the first word inserted becomes the “spine”.
kar, kal, at, ve, kasnodeslinks
Trie with 26-element arrays1010 × 26 = 260
TST99 × 3 = 27
A search for L characters takes L mid steps plus a binary search among siblings at each level: O(L + log n) on average. With a large alphabet (Unicode), a TST keeps memory and speed in balance where arrays cannot (Bentley and Sedgewick, 1997).

boolean search(String s) {
  TstNode d = root;
  int i = 0;
  while (d != null) {
    char ch = s.charAt(i);
    if (ch < d.c) d = d.left;
    else if (ch > d.c) d = d.right;
    else if (i == s.length() - 1) return d.end;
    else { d = d.mid; i++; }
  }
  return false;
}

Applications and Variants

Compressed Tries (Radix / Patricia)

Standard trie: 8 nodes
Compressed trie: 6 nodes
  • Chains of single-child, unmarked nodes are merged into one edge, which now carries a substring ("an", "ad").
  • Every internal node has at least 2 children (or an end-of-word mark), so the number of nodes is O(n) (n: number of words).
  • Patricia (Morrison, 1968) is the binary-alphabet version of this idea; it is used in IP routing tables.

Applications and Variants

Suffix Tries

Insert every suffix of the text T = "abab" into a trie:

abab · bab · ab · b

  • P is a substring of T ⇔ P is a prefix of some suffix ⇔ P is a path from the root.
  • Query: startsWith(P) → O(m) (m = |P|), independent of the text length. E.g. "ba" is present, "bb" is not.
  • The price: up to O(n²) nodes for a text of length n.
  • Suffix tree = compressed suffix trie: O(n) nodes, built in O(n) time by Ukkonen's algorithm.

TrieNode suffixTrie(String t) {
  TrieNode root = new TrieNode();
  for (int s = 0; s < t.length(); s++) {
    TrieNode d = root;
    for (int j = s; j < t.length(); j++) {
      int i = t.charAt(j) - 'a';
      if (d.children[i] == null)
        d.children[i] = new TrieNode();
      d = d.children[i];
    }
    d.isEnd = true;  // suffix done
  }
  return root;
}

Applications and Variants

Aho–Corasick: Many Patterns in One Pass

  • The patterns (he, she, his, hers) go into a trie; the text is read once, left to right.
  • Failure link (dashed): the longest proper suffix of the node's string that is in the trie. "she" → "he", "sh" → "h", "hers" → "s".
  • When a branch is missing, fall back along the failure link; this is the multi-pattern counterpart of KMP's prefix table.
  • Output sets merge along the failure chain: the "she" node also reports he.

Common Mistakes

Forgetting isEndChecking only that the path exists counts every prefix as a word: "da" appears to be found.
Confusing search with startsWithA prefix query ignores the last node's mark; an exact search must check it.
Characters outside the alphabet'A' − 'a' = −32, 'ş' − 'a' = 254: out of array bounds. Lowercase the input or use a HashMap.
Deleting a shared nodeDeleting the whole path also destroys the other words that share the prefix. Remove only childless, unmarked nodes.
Stating complexity in terms of nTrie operations are not O(log n) or O(n) but O(L): independent of the number of words.
Underestimating memoryEach node holds 26 references; millions of nodes take hundreds of MB. A sparse trie needs a HashMap or compression.

Insert the words in order: car, cart, care, cat, dog (trie with 26-element arrays).

Exercises

  1. int countWords(TrieNode d): count the trie's words.
  2. int countPrefix(String prefix): return the number of words with this prefix in O(P).
  3. String longestCommonPrefix(): find the longest common prefix of all words in the trie.
  4. Write a trie with HashMap<Character, TrieNode> children for Turkish letters.
  5. How many nodes, with root, does the trie of A, to, tea, ted, ten, i, in, inn have?
  6. Search "abab"'s suffix trie for "bab" and "bb"; how many comparisons?
Answers / hints
  1. DFS: (d.isEnd ? 1 : 0) + the sum of countWords over all non-null children. O(N · M).
  2. An int count per node, incremented by insert on its path; the prefix node's count is the answer.
  3. From the root, descend while there is one child and isEnd is false; the characters passed are the answer.
  4. children.get(ch) / children.computeIfAbsent(ch, x -> new TrieNode()); no index arithmetic.
  5. A, t, to, te, tea, ted, ten, i, in, inn = 10 nodes + root = 11.
  6. "bab": path b → a → b exists (3 steps). "bb": no 'b' after b → not found (2 steps).
