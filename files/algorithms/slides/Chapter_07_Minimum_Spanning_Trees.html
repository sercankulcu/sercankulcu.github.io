The MST Concept

Spanning Trees and Minimum Spanning Trees

  • G = (V, E): a connected, undirected graph with weighted edges.
  • A spanning tree is a connected, acyclic subgraph that contains every vertex. It always has exactly V − 1 edges.
  • A minimum spanning tree (MST) is a spanning tree with the smallest total edge weight.
  • Adding an edge to a tree creates a cycle; removing one splits the tree in two.
A graph can have very many spanning trees (nn−2 for a complete graph on n vertices, by Cayley's formula). Instead of trying them all, greedy algorithms find an MST directly. In the graph at right the MST weighs w(T) = 1 + 2 + 3 + 5 = 11.

The MST Concept

Example: The "MST" Graph

  • 15 vertices, 20 edges. The 14 bold edges (= V − 1) form the minimum spanning tree: total weight 141.
  • The thin edges are left out: each closes a cycle with the bold edges and is the heaviest edge on that cycle (e.g. 15, 16, 18, 25, 40, 50).
  • Heavy edges (20, 24, 25) can still be chosen: none of them is the heaviest on any cycle. For example, the cycle closed by 40 contains all three; the heaviest on that cycle is 40.

The MST Concept

The Cut Property and the Cycle Property

Cut propertyFor every cutthat splits the vertices into two sets, the lightest edge crossing the cut belongs to an MST.

{a, b} | {c, d, e}: crossing edges ae = 1, be = 4, bc = 5 → ae is safe.

Cycle propertyThe heaviest edge on any cycle (if unique) is in no MST.

cycle b–c–e: 4, 5, 6 → ec = 6 is never chosen.

Kruskal and Prim rely on the cut property, reverse-delete on the cycle property. If all weights are distinct, the MST is unique.

The MST Concept

Greedy MST Algorithms

All four algorithms are greedy: each step takes the locally best edge (or throws away the worst), and that choice is never undone.

AlgorithmIdeaHelper structureTime

The MST Concept

Where Are MSTs Used?

Network designConnecting cities with the least cable: power, water, fiber and road networks. Borůvka's starting point was the power grid of Moravia.
ClusteringDeleting the k − 1 heaviest edges of the MST leaves k clusters (single-linkage clustering).
Approximation algorithmsFor the metric traveling salesman problem (TSP), an MST-based tour is at most twice the optimum.
Image processingSegmentation, with pixels as vertices and color differences as weights.
Circuit designConnecting pins with the shortest total wire (a first step in VLSI routing).
Other graph problemsEvery path in the MST is a bottleneck path (its largest edge is as small as possible); the basic approximation for Steiner trees.

Kruskal

Kruskal's Algorithm

  • Builds a tree of minimum total weight that connects all vertices; a greedy approach.
  • Developed by Joseph Kruskal (1956).
  • At first every vertex is a separate tree (a forest); step by step these trees are merged.
  • Edges are sorted from lightest to heaviest; an edge that closes no cycle is taken, one that closes a cycle is skipped.

Strengths

  • Well suited to sparse graphs (E ≈ V).
  • Simple: an edge list plus union-find is enough.
  • On a disconnected graph it gives a minimum spanning forest.

Weaknesses

  • The cost of sorting edges: O(E log E).
  • On dense graphs (E ≈ V²) Prim can be faster.
  • Cycle checks need an extra structure (union-find).

Kruskal

Kruskal: Steps and Pseudocode

  1. Sort all edges of the graph by weight.
  2. Take the next edge with the smallest weight from the sorted list.
  3. If it joins two vertices in different trees (closes no cycle), add it and merge the two trees.
  4. If it joins two vertices of the same tree, it closes a cycle: skip it.
  5. Repeat steps 2–4 until V − 1 edges are chosen (or the edges run out).
KRUSKAL(G):
  MST = [ ]
  dsu.makeSets(V)
  edges.sort(by increasing weight)
  for each (u, v, weight) in edges:
    if dsu.find(u) ≠ dsu.find(v):
      MST.add((u, v, weight))
      dsu.union(u, v)
  return MST

"Are they in the same tree?" is answered in nearly constant time by the union-find (disjoint-set) structure.

Kruskal

Union-Find (Disjoint Sets)

  • Keeps a collection of disjoint sets. Each set is a tree whose root is the set's representative. The parent array parent[]: parent[i] is i's parent, and a root has parent[r] = r.
  • makeSets(V): each vertex is its own set → parent[i] = i.
  • find(x): climb to the root and return it.
  • union(x, y): hang one root under the other.
  • In Kruskal: if find(u) == find(v), u and v are in the same tree → the edge closes a cycle.
int find(int[] parent, int i) {
  if (parent[i] != i)
    parent[i] = find(parent, parent[i]); // compress
  return parent[i];
}
void union(int[] parent, int x, int y) {
  parent[find(parent, x)] = find(parent, y);
}
Two improvements: path compression and union by rank. Together they give O(α(V)) amortized per operation; α (the inverse Ackermann function) is ≤ 4 in practice.

Cycle Checking with Union-Find

makeSets(5): every vertex is the root of its own set, parent[i] = i. Edges: ac 1, de 2, ab 3, bc 4, bd 5, cd 6, ce 7.

ac = 1: find(a) = a, find(c) = c → different → the edge joins the MST; parent[a] = c.

de = 2: find(d) = d, find(e) = e → different → the edge joins the MST; parent[d] = e.

ab = 3: find(a) = c, find(b) = b → different → the edge joins the MST; parent[c] = b.

bc = 4: find(b) = b (path b), find(c) = b → same root: a cycle, so skip the edge.

bd = 5: find(b) = b, find(d) = e → different → the edge joins the MST; parent[b] = e.

The MST is complete (4 edges, w = 11). But the forest has become a long chain: find(a) follows a→c→b→e (3 steps).

Path compression: as find(a) returns, it points every vertex on the path straight at the root (parent[a] = parent[c] = e). Later lookups take 1 step.

Union-Find: Tracing find and union

Initially each element is the root of its own set: parent[i] = i. union(0, 1): find(0) = 0, find(1) = 1 → parent[0] = 1; 0 now hangs under 1.

union(1, 2): find(1) = 1, find(2) = 2 → parent[1] = 2. A root was hung under a root, and the chain grew: 0 → 1 → 2.

union(2, 3): parent[2] = 3. Chain 0 → 1 → 2 → 3: find(0) now takes 3 steps.

parent[0] = 1 ≠ 0: 0 is not a root → call find(1).

parent[1] = 2 ≠ 1: 1 is not a root → call find(2).

parent[2] = 3 ≠ 2: 2 is not a root → call find(3).

parent[3] = 3: 3 is a root. Return root 3; the recursion starts to unwind.

On return, parent[2] = 3 (it already pointed to the root; unchanged).

On return, parent[1] = 3: 1 now points straight to the root (2 → 3). Path compression.

On return, parent[0] = 3: 0 now points straight to the root (1 → 3). Path compression.

find(0) = 3. All of 0, 1, 2 on the path now point directly to 3: later find calls finish in one step.

union(4, 0): find(4) = 4, find(0) = 3 (one step!) → parent[4] = 3. All elements are in one set with root 3.

int find(int[] parent, int i) {
  if (parent[i] != i)
    parent[i] = find(parent, parent[i]); // compress
  return parent[i];
}
void union(int[] parent, int x, int y) {
  parent[find(parent, x)] = find(parent, y);
}

void kruskal(int V, List<Edge> es) {
  Collections.sort(es);         // ascending
  int[] parent = new int[V + 1];
  for (int i = 1; i <= V; i++) parent[i] = i;
  List<Edge> tree = new ArrayList<>();
  int k = 0;
  while (tree.size() < V - 1) {
    Edge e = es.get(k++);
    int x = find(parent, e.u);
    int y = find(parent, e.v);
    if (x != y) {               // different trees
      tree.add(e);
      parent[x] = y;            // union
    }
  }
}

Kruskal: Complexity Analysis

OperationHow oftenCost
Sorting the edges by weight1O(E log E)
makeSets(V)1O(V)
find (2 per edge)≤ 2EO(E · α(V)) — path compression + rank
O(E log V) — rank only
unionV − 1
  • Total: O(E log E); sorting dominates. Since E ≤ V², log E ≤ 2 log V, so O(E log E) = O(E log V).
  • If the edges are already sorted (or the weights are small integers, so counting sort applies), the time is nearly linear: O(E · α(V)).
  • Memory: edge list + parent array (parent) → O(V + E).
With union by rank alone, union-find operations take O(log V) in the worst case; adding path compression brings the amortized cost per operation to O(α(V)). Either way, sorting determines the total.

Prim

Prim's Algorithm

  • Builds a minimum-weight tree that connects all vertices; a greedy algorithm.
  • Robert C. Prim (1957); V. Jarník found it earlier (1930), and E. W. Dijkstra rediscovered it (1959).
  • Pick a start vertex; at each step, add the non-tree vertex that connects to the tree by the cheapest edge.
  • At any moment there is a single tree (unlike Kruskal's forest).

Strengths

  • Good for dense graphs: O(V²) with a matrix.
  • No edge sorting needed.
  • Works naturally with an adjacency list or matrix.

Weaknesses

  • Performance depends on the data structure (array, binary heap, Fibonacci heap).
  • On a disconnected graph it spans only the start vertex's component.

Prim

Prim: Steps, Keys and Parents

  1. Choose a start vertex and add all its edges to a priority queue.
  2. From the queue, take the lightest edge leading to a vertex not yet in the tree.
  3. Add the new vertex on that edge to the tree.
  4. Add the new vertex's edges to the queue; repeat steps 2–4 until every vertex is in the tree.
key[v]The weight of the cheapest edge found so far that connects v to the tree. ∞ at first, 0 at the source.
parent[v] (π)The tree end of that cheapest edge. At the end, the edges (parent[v], v) form the MST.

For the vertex taken from the queue, for each non-tree neighbor v: if weight(u, v) < key[v], update the key and the parent.

PRIM(G, source):

This "lazy" version may add a vertex to the queue several times; the visited check throws away stale entries. The queue holds at most E entries → O(E log E).

void prim(int[][] G, int src) {
  int V = G.length;
  int[] key = new int[V];
  int[] parent = new int[V];
  boolean[] inTree = new boolean[V];
  Arrays.fill(key, Integer.MAX_VALUE);
  key[src] = 0;
  parent[src] = -1;
  for (int s = 0; s < V - 1; s++) {
    int u = minKey(key, inTree);
    inTree[u] = true;
    for (int v = 0; v < V; v++)
      if (G[u][v] != 0 && !inTree[v]
          && G[u][v] < key[v]) {
        key[v] = G[u][v];
        parent[v] = u;
      }
  }
}

(5,2) is the smallest entry: 5 enters the tree (edge 2–5, weight 2). No key of a non-tree neighbor decreased.

(4,4) is the smallest entry: 4 enters the tree (edge 3–4, weight 4). No key of a non-tree neighbor decreased.

(4,6) comes out, but 4 is already in the tree: it is a stale entry, skipped with continue (lazy deletion).

The queue is empty. MST edges (parent[v], v): 1–3 (2), 1–2 (3), 2–5 (2), 3–4 (4); total 11.

void primPQ(int src) {
  Arrays.fill(key, INF);
  key[src] = 0;
  PriorityQueue<int[]> pq =
      new PriorityQueue<>((a, b) -> a[1] - b[1]);
  pq.add(new int[] { src, 0 });
  while (!pq.isEmpty()) {
    int u = pq.poll()[0];
    if (inTree[u]) continue;  // stale
    inTree[u] = true;
    for (Edge e : adj.get(u))
      if (!inTree[e.v] && e.w < key[e.v]) {
        key[e.v] = e.w; parent[e.v] = u;
        pq.add(new int[] { e.v, e.w });
      }
  }
}

How Prim Differs from Dijkstra

The two algorithms have almost the same code: start at a source, extract the vertex with the smallest key from a priority queue, and relax its neighbors. The only difference is what the key means.

Prim (MST)Dijkstra (shortest paths)
key[v]the cheapest single edge joining v to the treelength of the whole path from the source to v
Updatew(u,v) < key[v]dist[u] + w(u,v) < dist[v]
Resulttree of minimum total weightshortest-path tree (SPT)
Sourcedoes not affect the result (same weight)determines the result
Negative weightsno problemfails

In the five-vertex example, the shortest-path tree from 1 can use the edge (1,4) = 6; the MST takes (3,4) = 4 instead.

Borůvka

Borůvka's (Sollin's) Algorithm

  • The oldest MST algorithm: Otakar Borůvka, 1926 (the Moravian power grid). Also known as Sollin's algorithm.
  • At first every vertex is an independent component.
  • In each round every component picks the cheapest edge leaving it; all the picks are added at once.
  • Components are merged with union-find until only one is left. On a connected graph it yields |V| − 1 edges.

Strengths

  • Components choose independently: well suited to parallel execution.
  • At most ⌈log₂ V⌉ rounds.

Weaknesses

  • Harder to code than Kruskal or Prim.
  • With equal weights a consistent tie-breaker (e.g. edge index) is essential; otherwise a cycle can form.

Borůvka

Borůvka: Steps and Pseudocode

  1. At first each vertex counts as a component (set) on its own.
  2. For each component, find the lightest edge connecting it to another component.
  3. Add all the edges found and merge the components they connect (no edge is added twice).
  4. Repeat steps 2 and 3 until one component remains; stop if a round adds no edge (disconnected graph → forest).

Note: Borůvka does not sort the edges; each round scans all edges once and keeps the lightest per component.

BORUVKA(G):
  MST = [ ]
  numComp = |V|
  while numComp > 1 do:
    cheapest = [ ]  // per component
    for each e = (u, v, weight) in E:
      cu = dsu.find(u)
      cv = dsu.find(v)
      if cu ≠ cv:
        cheapest[cu] = min(cheapest[cu], e)
        cheapest[cv] = min(cheapest[cv], e)
    added = false
    for each (u, v, weight) in cheapest:
      if dsu.find(u) ≠ dsu.find(v):
        MST.add((u, v, weight))
        dsu.union(u, v)
        numComp -= 1
        added = true
    if not added: break   // forest
  return MST

Borůvka

Borůvka: Java Code and Complexity

while (numComp > 1) {
  Edge[] cheapest = new Edge[V];
  for (Edge e : edges) {         // 1) cheapest
    int k1 = find(parent, e.u), k2 = find(parent, e.v);
    if (k1 == k2) continue;         // same comp.
    if (cheapest[k1] == null || e.w < cheapest[k1].w)
      cheapest[k1] = e;
    if (cheapest[k2] == null || e.w < cheapest[k2].w)
      cheapest[k2] = e;
  }
  boolean added = false;
  for (Edge e : cheapest) {      // 2) add them
    if (e == null) continue;
    int k1 = find(parent, e.u), k2 = find(parent, e.v);
    if (k1 == k2) continue;         // already in
    tree.add(e);
    parent[k1] = k2;                // union
    numComp--;
    added = true;
  }
  if (!added) break;  // forest
}
  • In each round every component merges with at least one other → the number of components at least halves.
  • Number of rounds ≤ ⌈log₂ V⌉; each round scans all edges once: O(E).
  • Total: O(E log V). No sorting is done; no "weight order" is needed.
  • If edges are added at the same time, a consistent tie-breaker is needed; in this sequential code the find(k1) == find(k2) check already prevents cycles.
  • If a round adds no edge (added false), the loop exits: a minimum spanning forest for a disconnected graph.

Reverse-Delete

The Reverse-Delete Algorithm

  • A greedy MST algorithm (Kruskal proposed it in his 1956 paper).
  • Sorts the edges by weight in decreasing order.
  • Starting from the heaviest edge, deletes every edge whose removal keeps the graph connected.
  • Relies on the cycle property: a deleted edge is the heaviest edge on some cycle.
Kruskal's mirror imageKruskal adds the lightest, reverse-delete deletes the heaviest edges. One starts from the empty graph, the other from the full graph.
UseMostly of theoretical and teaching value; since every deletion needs a connectivity test, it is usually slow in practice.

Reverse-Delete

Reverse-Delete: Steps, Pseudocode, Complexity

  1. Sort all edges by weight in decreasing order.
  2. Delete the next heaviest edge.
  3. If the graph is no longer connected, put the deleted edge back.
  4. Repeat steps 2 and 3 until every edge has been processed.
Complexity: one BFS/DFS per edge (or a union-find rebuild) → O(E · (V + E)). The O(E log E) cost of sorting is small next to that.
REVERSE_DELETE(G):
  MST = all edges
  edges.sort(by decreasing weight)
  for each (u, v, weight) in edges:
    MST.remove((u, v, weight))
    dsu.reset()
    for each (x, y) in MST:
      dsu.union(x, y)
    root = dsu.find(V[0])
    if dsu.find(v) ≠ root for some v:
      MST.add((u, v, weight))  // put back
  return MST

The connectivity test looks at every vertex; if at least one vertex is cut off from the root, the deleted edge is put back once.

void reverseDelete(int V, List<Edge> es) {
  es.sort((a, b) -> b.w - a.w); // descending
  int i = 0;
  while (i < es.size()) {
    Edge e = es.remove(i);      // try deleting
    if (!isConnected(V, es)) {
      es.add(i, e);             // put back
      i++;
    }
  }
}

TopicKey points

Propertiesthe lightest edge across a cut is safe; the heaviest edge on a cycle is out; distinct weights → unique MST
Kruskalsort the edges; if find(u) ≠ find(v), add the edge and merge the trees — O(E log E)

Summary

Common Mistakes

Confusing the MST with a shortest-path treeThe MST minimizes total weight; the MST path between two vertices need not be a shortest path.
Checking cycles by adjacencyIn Kruskal, "are u and v directly connected?" is not enough; ask whether they are in the same component (find).
Adding up distances in PrimWriting key[u] + w gives Dijkstra. In Prim the key is the weight of a single edge.
Fearing negative weightsMST algorithms work correctly with negative weights too (they only compare); the problem is specific to Dijkstra.
Disconnected graphsThere is no MST, only a minimum spanning forest. while (tree.size() < V − 1) runs past the end of the edge list.
Applying them to directed graphsThese algorithms are for undirected graphs. The directed counterpart (minimum spanning arborescence) is the Chu–Liu/Edmonds algorithm.
