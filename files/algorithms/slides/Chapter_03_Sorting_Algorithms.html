Introduction

Sorting Algorithms

  • From shopping lists to social media posts, the digital world is full of data.
  • To use data efficiently we need to keep it organized.
  • Sorting algorithms arrange the items of a list according to some criterion:
    • numeric value,
    • alphabetical order,
    • date …
  • The order can be ascending (smallest first) or descending.
  • Formally: the input is ⟨a₁, a₂, …, aₙ⟩; the output is a permutation of the same numbers with a′₁ ≤ a′₂ ≤ … ≤ a′ₙ.
Sorted data makes many tasks easy: binary search in O(log n), finding duplicates, merging, the median, the k smallest or largest items.

Introduction

Kinds of Sorting Algorithms

Different sorting algorithms work on different principles:

AlgorithmKey idea
Bubble sortCompares adjacent items and swaps them if they are out of order.
Insertion sortInserts the next item into its place in the sorted part.
Selection sortFinds the smallest item and moves it to the front, then sorts the rest.
Shell sortInsertion sort that starts with distant items and shrinks the gap.
Merge sortSplits the array in half, sorts the halves, then merges them.
QuicksortPartitions around a pivot and sorts the two parts recursively.
HeapsortBuilds a max-heap and repeatedly moves the largest item to the end.
Counting / Radix sortNo comparisons; counts the keys or distributes them digit by digit.
TimsortA hybrid of insertion sort and merge sort; the object sort of Java and Python.

Introduction

Evaluating a Sorting Algorithm

TimeComparisons and swaps (moves) in the best, average and worst case: Θ(n²), Θ(n log n), Θ(n + k) …
Extra memorySpace needed beyond the input. An algorithm that uses O(1) extra memory sorts in place.
StabilityAn algorithm is stable if items with equal keys keep their relative order.
Comparison-based?Algorithms that only ask "a ≤ b?" need Ω(n log n) comparisons in the worst case. Counting and radix sort escape this bound.
AdaptivityAn algorithm that runs faster on nearly sorted input is adaptive: insertion sort, bubble sort with a flag, Timsort.
OnlineAn algorithm that can sort data as it arrives is online: insertion sort.

These bounds count one comparison as O(1); for strings of length L each comparison can cost O(L) (see Chapters 10–11).

Bubble Sort

Bubble Sort

  • On each pass the larger items move toward the end of the array, rising like bubbles in water.
  • Adjacent items are compared in pairs.
  • If the left one is larger, they are exchanged (swap).
  • After pass i, the i largest items are in their final places; the next pass is one item shorter.
  • If a pass makes no swaps, the array is sorted → early exit.

Bubble Sort

Bubble Sort: Java Code

boolean swapped;
for(int i = 0; i < n - 1; i++) {
  swapped = false;
  for(int j = 0; j < n - 1 - i; j++) {
    if(arr[j] > arr[j+1]) {
      int temp = arr[j];
      arr[j] = arr[j+1];
      arr[j+1] = temp;
      swapped = true;
    }
  }
  if(swapped == false) break;
}
  • Outer loop (i): at most n − 1 passes.
  • Inner loop (j): adjacent pairs in the unsorted part; the last i items are already in place, hence j < n − 1 − i.
  • The swap takes three assignments using temp.
  • The swapped flag: if a whole pass makes no swap, the array is sorted → break.
Because the test is > (not ≥), equal items are never swapped: bubble sort is stable.

Insertion Sort

Insertion Sort

  • Like sorting a hand of playing cards: each new card is slipped into its place among the sorted cards in your hand.
  • The array has two parts: a sorted part (on the left) and an unsorted part.
  • Take the first item of the unsorted part and insert it at its correct position in the sorted part.
  • To make room, the larger items are shifted one place to the right.
  • Invariant: at the start of each outer step, arr[0..i−1] is sorted.

Insertion Sort

Insertion Sort: Java Code

for(int i = 1; i < n; i++) {
  int key = arr[i];
  int j = i - 1;
  while(j >= 0 && arr[j] > key) {
    arr[j+1] = arr[j];
    j = j - 1;
  }
  arr[j+1] = key;
}
  • Start at i = 1: the one-element arr[0..0] is already sorted.
  • key: the item to insert. It is saved first because the shifts overwrite its cell.
  • while: as long as the item on the left is larger, shift it one place right.
  • When the loop ends, the free slot is j + 1.
It shifts rather than swaps: one assignment per step instead of 3. That is why insertion sort is noticeably faster than bubble sort.

Selection Sort

Selection Sort

  • The array has two parts: sorted and unsorted.
  • At each step:
    • Find the smallest item in the unsorted part.
    • Swap it with the item at the front of the unsorted part.
    • After the swap it joins the sorted part.
  • n − 1 passes in total; at most one swap per pass.

Selection Sort

Selection Sort: Java Code

public void sort(int[] arr) {
  int n = arr.length;
  for(int i = 0; i < n - 1; i++) {
    int minIdx = i;
    for(int j = i + 1; j < n; j++) {
      if(arr[j] < arr[minIdx]) {
        minIdx = j;
      }
    }
    int temp = arr[minIdx];
    arr[minIdx] = arr[i];
    arr[i] = temp;
  }
}
  • minIdx holds the index of the smallest item (not its value): the swap at the end needs the index.
  • The inner loop scans the whole unsorted part; the scan is no shorter even if the input is sorted.
  • One swap per pass: at most n − 1 in total.
Where writes are expensive (e.g. flash memory), the small number of swaps is selection sort's only real advantage.

Shell Sort

Shell Sort

  • D. Shell (1959): a generalization of insertion sort.
  • First, items a gap apart are insertion-sorted; small items far away jump a long distance in one move.
  • The gap shrinks (n/2, n/4, …); the last pass has gap = 1, i.e. plain insertion sort — but by now the array is nearly sorted.
  • In place, unstable; the time depends on the gap sequence: worst case Θ(n²) with n/2 gaps, O(n1.5) with Hibbard's (2ᵏ − 1).
void shellSort(int[] arr) {
  int n = arr.length;
  for (int gap = n / 2; gap > 0; gap /= 2)
    for (int i = gap; i < n; i++) {
      int key = arr[i], j;
      for (j = i; j >= gap && arr[j - gap] > key; j -= gap)
        arr[j] = arr[j - gap];
      arr[j] = key;
    }
}

Merge Sort

Merge Sort

  • A divide-and-conquer algorithm.
  • Invented by John von Neumann in 1945.
  • O(n log n) even in the worst case.
  • Stable; merging needs extra memory (O(n)).
How does it work?

1. Divide: split the list into two sublists, and keep splitting until each has one item.

2. Conquer: sort each half the same way (recursively).

3. Combine: merge the sorted sublists until a single sorted list remains.

A one-item list is sorted by definition; this is the recursion's base case. The real work happens in the merge step.

Merge Sort

Example: [38, 27, 43, 3, 9, 82, 10]

Seven items: since mid = ⌊(left + right)/2⌋, the left half gets one extra item ([38, 27, 43, 3] and [9, 82, 10]).

Merge Sort: Java Code

void mergeSort(int[] arr, int left, int right) {
  if (left < right) {
    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);
    mergeSort(arr, mid + 1, right);
    merge(arr, left, mid, right);
  }
}
void merge(int[] A, int p, int q, int r) {
  int[] L = Arrays.copyOfRange(A, p, q + 1);
  int[] R = Arrays.copyOfRange(A, q + 1, r + 1);
  int i = 0, j = 0, k = p;
  while (i < L.length && j < R.length) {
    if (L[i] <= R[j]) A[k++] = L[i++];
    else              A[k++] = R[j++];
  }
  while (i < L.length) A[k++] = L[i++];
  while (j < R.length) A[k++] = R[j++];

Quicksort

Quicksort

  • C. A. R. Hoare (1959). Also divide and conquer, but most of the work happens in the divide step.
  • Choose a pivot item.
  • Split the array into two parts around the pivot (partitioning): ≤ x on the left, ≥ x on the right.
  • Sort the two parts recursively. No merge step is needed.
After partitioning the pivot is in its final place: it sits at exactly that index in the sorted array.

Quicksort

The Partitioning Procedure

Lomuto: pivot = last item

partition(A, p, q):
  pivot = A[q]        // choose pivot
  i = p - 1           // end of ≤ zone
  for j = p to q - 1:
    if A[j] <= pivot:
      i = i + 1
      swap(A[i], A[j])
  swap(A[i + 1], A[q])  // place the pivot
  return i + 1          // pivot index

Same idea: pivot = first item

PARTITION(A, p, q):
  x = A[p]            // pivot
  i = p
  for j = p + 1 to q:
    if A[j] <= x:
      i = i + 1
      swap(A[i], A[j])
  swap(A[p], A[i])
  return i

Invariant: A[p..i] ≤ pivot, A[i+1..j−1] > pivot, A[j..] not yet examined. One pass: Θ(n) time, O(1) extra memory.

int partition(int[] arr, int lo, int hi) {
  int pivot = arr[hi];
  int i = lo - 1;
  for (int j = lo; j < hi; j++) {
    if (arr[j] <= pivot) {
      i++;
      swap(arr, i, j);
    }
  }
  swap(arr, i + 1, hi);
  return i + 1;
}

Heapsort

Heapsort

  • Sorts using the heap data structure; O(n log n) on average and in the worst case.
  • Max-heap: every node is greater than or equal to its children → the largest item is at the root.
  • The tree is not a separate structure; it is the array itself: the children of arr[i] are 2i + 1 and 2i + 2, its parent (i − 1) / 2.
How it works
  1. Turn the array into a max-heap.
  2. Move the largest item (the root) to the end of the array.
  3. Restore the max-heap on the rest (sift the root down).
  4. Repeat until all items are sorted.

void heapSort(int[] arr) {
  int n = arr.length;
  for (int i = n / 2 - 1; i >= 0; i--)   // 1) build heap
    heapify(arr, n, i);
  for (int i = n - 1; i > 0; i--) {      // 2) sort
    swap(arr, 0, i);                   // max to the end
    heapify(arr, i, 0);                // sift root down
  }
}
void heapify(int[] arr, int n, int i) {
  while (true) {
    int largest = i, left = 2 * i + 1, right = 2 * i + 2;
    if (left < n && arr[left] > arr[largest]) largest = left;
    if (right < n && arr[right] > arr[largest]) largest = right;
    if (largest == i) return;          // in place
    swap(arr, i, largest);
    i = largest;                       // keep sifting
  }
}
  • Building the heap: the leaves (i ≥ n/2) are already one-item heaps; sift down from i = n/2 − 1 toward the root. Total O(n) (most nodes are near the bottom).
  • Sorting: n − 1 times, move the root to the end and sift down in O(log n) → O(n log n).
  • O(n log n) even in the worst case, with O(1) extra memory (in place).
  • Unstable: the root–last swap can reorder equal keys.

A heap can also be built by inserting items one by one (sift up); that too gives a valid max-heap, but takes O(n log n). The bottom-up construction used here (Floyd's method) is O(n).

Linear-Time Sorting

A Lower Bound for Comparison Sorting

  • Any algorithm that only asks "ai ≤ aj?" can be drawn as a decision tree.
  • Each leaf is an ordering (a permutation); to be correct the tree needs n! leaves.
  • A binary tree of height h has at most 2h leaves: 2h ≥ n! ⇒ h ≥ log₂(n!) = Ω(n log n).
  • Consequence: merge sort and heapsort are asymptotically optimal.
  • Going faster needs information beyond comparisons: small integer keys → counting, radix.

Linear-Time Sorting

Counting Sort

  • Items are never compared with each other.
  • Input: A[1 … n], A[j] ∈ {1, 2, …, k}.
  • Output: B[1 … n], sorted.
  • Temporary: counters C[1 … k].

Idea: if we know how many items have key ≤ i, the last item with key i goes exactly at that position.

for i = 1 to k
  C[i] = 0
for j = 1 to n
  C[A[j]] = C[A[j]] + 1   // C[i] = |{key = i}|
for i = 2 to k
  C[i] = C[i] + C[i−1]    // C[i] = |{key ≤ i}|
for j = n downto 1
  B[C[A[j]]] = A[j]
  C[A[j]] = C[A[j]] − 1

int[] countingSort(int[] arr) { // elements ≥ 0
  if (arr.length == 0) return arr;
  int max = Arrays.stream(arr).max().getAsInt();
  int[] count = new int[max + 1];
  for (int x : arr) count[x]++;
  for (int i = 1; i <= max; i++) count[i] += count[i - 1];
  int[] output = new int[arr.length];
  for (int i = arr.length - 1; i >= 0; i--) {
    output[count[arr[i]] - 1] = arr[i];
    count[arr[i]]--;
  }
  return output;
}

  • Scanning the last loop from back to front makes it stable → the basis of radix sort.

Linear-Time Sorting

Radix Sort

  • Sorts non-negative integers digit by digit, starting from the least significant digit (the ones): LSD.
  • Each pass does a stable sort (counting sort, k = 10) on that digit.
  • Stability is essential: sorting by the tens digit must preserve the order of the ones.
  • d digits, base b: Θ(d · (n + b)). Θ(n) if d is constant.
  • Extra memory Θ(n + b); not in place.
int[] radixSort(int[] arr) { // elements ≥ 0
  if (arr.length == 0) return arr;
  int max = Arrays.stream(arr).max().getAsInt();
  for (long exp = 1; max / exp > 0; exp *= 10)
    arr = countByDigit(arr, (int) exp);
  return arr;
}
int[] countByDigit(int[] arr, int exp) {
  int n = arr.length;
  int[] output = new int[n], count = new int[10];
  for (int x : arr) count[(x / exp) % 10]++;
  for (int i = 1; i < 10; i++) count[i] += count[i - 1];
  for (int i = n - 1; i >= 0; i--) {
    int b = (arr[i] / exp) % 10;
    output[--count[b]] = arr[i];
  }
  return output;
}

i = 2: x = 41, b = 1. --count[1] = 0 → output[0] = 41. 41 and 11 share a digit; scanning right to left puts 41 (earlier in the input) to the left of 11: stable.

i = 1: x = 15, b = 5. --count[5] = 4 → output[4] = 15.

i = 0: x = 32, b = 2. --count[2] = 2 → output[2] = 32.

output = [41, 11, 32, 23, 15]: sorted by the ones digit. The next pass, exp = 10, looks at the tens digit; stability preserves the order of the ones.

int[] countByDigit(int[] arr, int exp) {
  int n = arr.length;
  int[] output = new int[n], count = new int[10];
  for (int x : arr) count[(x / exp) % 10]++;
  for (int i = 1; i < 10; i++) count[i] += count[i - 1];
  for (int i = n - 1; i >= 0; i--) {
    int b = (arr[i] / exp) % 10;
    output[--count[b]] = arr[i];
  }
  return output;
}

Linear-Time Sorting

Bucket Sort

  • Suppose the input consists of numbers uniformly distributed over [0, 1).
  • Create n buckets; a value x goes into bucket ⌊n · x⌋.
  • Sort each bucket (with insertion sort) and concatenate the buckets in order.
  • Expected time Θ(n); worst case Θ(n²) if every item lands in one bucket.
  • The tenth algorithm in the simulator; it makes an assumption about the distribution.

Timsort

Timsort: A Hybrid Sort

  • Tim Peters (2002, Python). Java uses Timsort for object arrays (Arrays.sort(Object[]), List.sort) and Python for sorted.
  • It exploits the sorted stretches (runs) common in real data: short runs are extended with insertion sort, and runs are combined with merge sort.
  • Stable; O(n log n) worst case, Θ(n) on sorted input; O(n) extra memory.
static final int MIN_RUN = 4;
void timSort(int[] arr) {
  int n = arr.length;
  for (int i = 0; i < n; i += MIN_RUN)            // 1) runs
    insertionSort(arr, i, Math.min(i + MIN_RUN - 1, n - 1));
  for (int size = MIN_RUN; size < n; size *= 2)  // 2) merge
    for (int left = 0; left < n; left += 2 * size) {
      int mid = left + size - 1;
      int right = Math.min(left + 2 * size - 1, n - 1);
      if (mid < right) merge(arr, left, mid, right);
    }
}

This version is simplified with fixed-length runs (real Timsort uses minrun 32–64, natural run detection and "galloping").

Common Mistakes

Running off the arrayIn bubble sort the inner loop must be j < n − 1 − i; writing j < n overflows at arr[j+1].
Not saving the keyIn insertion sort, if key is not saved first, the first shift overwrites it.
Tracking the minimum by valueIn selection sort, without the index the swap cannot be done.
Breaking stabilityUsing < instead of <= in merge, or scanning front to back in counting sort, reorders equal keys.
Including the pivot in the recursionWriting quickSort(arr, lo, p) processes the pivot again; with two items left it can recurse forever.
"Quicksort is always n log n"On sorted input a fixed pivot gives Θ(n²) and recursion n deep (StackOverflowError).
