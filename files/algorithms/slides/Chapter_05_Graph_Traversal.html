Introduction

Graphs Are Everywhere

  • The world is a network: cities are linked by roads, people by relationships, computers by cables.
  • A graph G = (V, E) consists of vertices V and the edges E that join them.
  • Graph algorithms explore and make sense of these networks: shortest paths, clustering, connectivity, flow…
  • Uses: social networks, maps and navigation, network routing, compilers, games.

Cities are vertices, roads are edges.

V = number of vertices, E = number of edges. Running times are stated in terms of these two: O(V + E), O(V²)…

Introduction

Kinds of Graphs

Directed

Edges are traversed only in the direction of the arrow.

Undirected

Edges can be traversed both ways.

Weighted

Each edge carries a weight (cost, distance).

Bipartite

Edges only join vertices in different sets.

Cyclic

Some path returns to its start, such as A–D–C–B–A.

Tree

Connected and acyclic; exactly one path between any two vertices.

Complete

Every pair of vertices is joined: n(n−1)/2 edges.

Not simple

Has parallel edges and self-loops; a simple graph has neither.

Traversal

Graph Traversal

  • A traversal visits every (reachable) vertex exactly once to explore the graph's structure systematically.
  • There are two main strategies; they differ in which data structure supplies the next vertex:
Depth-First Search (DFS)

Uses a stack (LIFO). It starts at a vertex and goes as deep as it can; when the neighbors run out it backtracks.

Breadth-First Search (BFS)

Uses a queue (FIFO). It visits vertices at distance 1, then distance 2, … level by level.

A visited array is essential: unlike a tree, a graph can have cycles. Without marking visited[], the algorithm circles the same cycle forever.

DFS

DFS: The Idea

  • In a maze, follow a corridor until it dead-ends; then back up to the last fork and try a corridor you have not taken yet.
  • In the recursive version the call stack remembers where to back up to; the iterative version uses an explicit stack.
  • The visited vertices, with the edges that first reached them, form a DFS tree.
  • The visit order depends on the order of neighbors; one graph can have several valid DFS orders.
Vertex states

white: not yet discovered
yellow: discovered, still in progress (on the stack)
dark: finished, all neighbors examined

DFS answers: "Is it reachable?", "Is there a cycle?", "How many components?", "In what order?" (topological sort), "What are the strongly connected components?" (Tarjan).

DFS · Step by step

DFS Step by Step: Visit Order

Start: no vertex is visited yet. DFS starts at the root; each vertex gets its visit number.

Visit the root (1). Pick its first neighbor and go deeper.

Descend to the first undiscovered neighbor of 1: 2. The stack grows.

Descend to the first undiscovered neighbor of 2: 3. The stack grows.

Descend to the first undiscovered neighbor of 3: 4. The stack grows.

4, 3 and 2 have no undiscovered neighbors left → backtrack. Visit the next child of 1: 5.

Descend to the first undiscovered neighbor of 5: 6. The stack grows.

Descend to the first undiscovered neighbor of 6: 7. The stack grows.

7 and 6 have no undiscovered neighbors left → backtrack. Visit the next child of 5: 8.

8 and 5 have no undiscovered neighbors left → backtrack. Visit the next child of 1: 9.

Descend to the first undiscovered neighbor of 9: 10. The stack grows.

All vertices visited; the stack is empty. Visit order: 1, 2, 3, …, 10: each branch was followed to its end before backtracking.

DFS

Recursive DFS: Pseudocode

Standard pseudocode

procedure DFS(G, v) is
  label v as discovered
  for all directed edges from v to w
      that are in G.adjacentEdges(v) do
    if vertex w is not labeled
        as discovered then
      call DFS(G, w)

Plain version

DFS(node, visited):
  if node is not
        in visited:
    add node to visited
    process node (e.g., print it)
    for each neighbor of node:
      DFS(neighbor, visited)
  • The left version checks a neighbor before calling; the right one checks at the start of the call. Both give the same order; the right one makes extra calls that return at once.
  • To cover every vertex of a disconnected graph, restart DFS from each unvisited vertex (each restart finds one connected component).

DFS

Iterative DFS: Pseudocode

Standard pseudocode

procedure DFS_iterative(G, v) is
  let S be a stack
  S.push(v)
  while S is not empty do
    v = S.pop()
    if v is not labeled as discovered then
      label v as discovered
      for all edges from v to w
          in G.adjacentEdges(v) do
        S.push(w)

Plain version

DFS(start):
  create an empty stack
  push start onto the stack
  while the stack is not empty:
    current = pop the stack
    if current is not
          in visited:
      add current to visited
      for each neighbor of current:
        push neighbor onto the stack
  • An explicit stack instead of recursion: no risk of StackOverflowError on very deep graphs.
  • Marking happens on pop, so a vertex can enter the stack several times (stack size O(E)).
  • Since neighbors are pushed, the last one pushed comes out first: the order is the reverse of the recursive version. To match it, push the neighbors in reverse.

void dfs(int v, boolean[] visited) {
  visited[v] = true;
  System.out.print(v + " ");
  for (int w : adj[v])
    if (!visited[w])
      dfs(w, visited);
}

void dfsStack(int s) {
  boolean[] visited = new boolean[n];
  Deque<Integer> stack = new ArrayDeque<>();
  stack.push(s);
  while (!stack.isEmpty()) {
    int v = stack.pop();
    if (!visited[v]) {
      visited[v] = true;
      System.out.print(v + " ");
      for (int w : adj[v])
        stack.push(w);
    }
  }
}

DFS

DFS: Analysis and Uses

Complexity

  • Each vertex is marked once: O(V).
  • Each adjacency list is scanned once; the lists have total length E (2E if undirected): O(E).
  • Total: O(V + E) with adjacency lists, O(V²) with a matrix (a row of V entries per vertex).
  • Extra memory: visited[] O(V) plus the stack: O(V) for recursion (the longest path); O(E) for the "mark on pop" version.

Where is it used?

  • Reachability, counting connected components
  • Cycle detection: an edge to a vertex on the stack (yellow) = a back edge
  • Topological sort: reverse finishing order
  • Strongly connected components (Tarjan, Kosaraju)
  • Bridges and articulation points, solving mazes and puzzles, backtracking
DFS does not find shortest paths: the first path it finds to a target may be a long detour. For the fewest edges you need BFS.

BFS

BFS: The Idea

  • Like ripples from a stone in water: first everything 1 edge away, then everything 2 edges away…
  • It models news spreading: a person tells all their friends, who tell their own friends.
  • The queue (FIFO) keeps the order: first discovered, first processed.
  • A vertex is marked when it is enqueued, so each vertex enters the queue at most once.
  • In an unweighted graph it finds the path with the fewest edges from the start to every vertex.
Levels

L0 = {s}
L1 = neighbors of s
L2 = new neighbors of L1
…
Every vertex in Lk is at distance exactly k from s.

BFS Step by Step: Level by Level

Start: all vertices are white (undiscovered). Yellow = discovered, waiting in the queue · dark = processed.

The start vertex 1 is marked discovered and enqueued.

Dequeue 1; its undiscovered neighbors 2, 3, 4, 5 are marked and enqueued (level 1).

Dequeue 2; its undiscovered neighbors 6, 7 are marked and enqueued (level 2).

Dequeue 3; its undiscovered neighbor 8 is marked and enqueued (level 2).

Dequeue 4; no undiscovered neighbors.

Dequeue 5; no undiscovered neighbors.

Dequeue 6; no undiscovered neighbors.

Dequeue 7; no undiscovered neighbors.

Dequeue 8; no undiscovered neighbors → the queue is empty and BFS ends.

Result: visit order 1, 2, 3, 4, 5, 6, 7, 8. First the vertices at distance 1 (2, 3, 4, 5), then those at distance 2 (6, 7, 8): level by level.

BFS

BFS: Pseudocode

Standard pseudocode

procedure BFS(G, root) is
  let Q be a queue
  label root as explored
  Q.enqueue(root)
  while Q is not empty do
    v := Q.dequeue()
    for all edges from v to w
        in G.adjacentEdges(v) do
      if w is not labeled as explored then
        label w as explored
        w.parent := v
        Q.enqueue(w)

Plain version

BFS(start):
  create an empty queue
  mark start as discovered
  enqueue start
  while the queue is not empty:
    current = dequeue
    for each neighbor of current
      if neighbor is undiscovered
        mark neighbor as discovered
        neighbor.parent = current
        enqueue neighbor
  • The w.parent := v links form the BFS tree; following them from the target back to the root gives the shortest path.
  • Mark a vertex when it is enqueued, not when it is dequeued; otherwise the same vertex enters the queue many times.

void bfs(int s) {
  boolean[] visited = new boolean[n];
  Queue<Integer> queue = new LinkedList<>();
  visited[s] = true; queue.add(s);
  while (!queue.isEmpty()) {
    int v = queue.poll();
    System.out.print(v + " ");
    for (int w : adj[v])
      if (!visited[w]) {
        visited[w] = true;
        queue.add(w);
      }
  }
}

BFS in a Maze: Try Every Path at Once

The entry cell is enqueued with distance 0. Walls (dark) are not vertices; every open cell is a vertex and adjacent open cells share an edge.

At each step the wave advances one cell in every direction: cells at distance 1 and 2. Yellow = the current frontier.

A single corridor: the wave moves down. The number in each cell is the fewest steps from the entry.

At distance 5 the path forks: the wave spreads right and down. BFS "tries every path at once".

Both branches advance together: one toward the upper room, one downward.

Distance 10: the wave has reached the upper corridor and, below, the bottom corridor.

The bottom corridor nears the exit; the upper branch wanders into dead ends.

The exit is reached in 14 steps. When BFS first reaches a cell, that distance is guaranteed to be the shortest.

Rebuilding the path

List<Integer> path(int[] parent, int s, int t) {
  LinkedList<Integer> path = new LinkedList<>();
  for (int v = t; v != -1; v = parent[v])
    path.addFirst(v);   // walk back from t
  if (path.getFirst() != s)
    return null;       // t unreachable
  return path;
}
Valid only for unweighted graphs (or graphs with all weights equal). Weighted graphs need Dijkstra.

Dequeue 3. Neighbor 1 is already discovered, skip it; 8 is discovered: distance 1 + 1 = 2, parent 3.

Dequeue 4 (distance 1). Its only neighbor, 1, is already discovered: nothing new is enqueued.

Dequeue 5 (distance 1). Its only neighbor, 1, is already discovered: nothing new is enqueued.

Dequeue 6 (distance 2). Its only neighbor, 2, is already discovered: nothing new is enqueued.

Dequeue 7 (distance 2). Its only neighbor, 2, is already discovered: nothing new is enqueued.

void bfsDist(int s) {
  Arrays.fill(dist, -1);
  Arrays.fill(parent, -1); dist[s] = 0;
  Queue<Integer> queue = new LinkedList<>();
  queue.add(s);
  while (!queue.isEmpty()) {
    int v = queue.poll();
    for (int w : adj[v])
      if (dist[w] == -1) {  // new
        dist[w] = dist[v] + 1;
        parent[w] = v;
        queue.add(w);
      }
  }
}

Tarjan SCC

Strongly Connected Components

  • In a directed graph, u and v are mutually reachable if there is a path from u to v and from v to u.
  • A strongly connected component (SCC) is a maximal set of vertices in which every vertex can reach every other.
  • Every vertex belongs to exactly one SCC; a single vertex can be an SCC on its own ({8}).
  • "A vertex plus everything reachable from it" is not an SCC: 8 reaches every other vertex, yet none of them reaches 8.
  • Tarjan's algorithm (1972) finds all SCCs with a single DFS.

SCCs: {1, 2, 3}, {4, 5}, {6, 7}, {8}

Shrinking each SCC to one vertex gives the component graph, which is acyclic (a DAG): communities in social networks, mutually dependent modules in compilers, solving 2-SAT.

Tarjan SCC

Tarjan: Principles and Steps

  1. It is DFS-based: try the vertices in turn and start a DFS from each unvisited one.
  2. During the DFS each visited vertex gets an index: its discovery order (1, 2, 3, …). Vertices on the current DFS path whose SCC is not yet known are kept on a stack.
  3. For each vertex we compute its lowlink: the smallest index reachable from its DFS subtree using at most one edge to a vertex still on the stack.
    • Tree edge v → w: on return, lowlink(v) = min(lowlink(v), lowlink(w))
    • Edge to a w on the stack: lowlink(v) = min(lowlink(v), index(w))
    • Edge to a w in a finished SCC: ignored.
  4. When v is finished, if lowlink(v) = index(v), v is the root of an SCC: popping the stack down to v (inclusive) yields that SCC.
If lowlink(v) < index(v), v's subtree can reach an older stack vertex; v is in that vertex's SCC and is not a root.

Tarjan Step by Step: index, lowlink

Directed graph with 8 vertices. Next to each vertex we write index,lowlink. White = unvisited, yellow = on the stack, colored = SCC found.

SCC(1): index = lowlink = 1; push 1.

SCC(2): index = lowlink = 2; push 2.

SCC(3): index = lowlink = 3; push 3.

2 is finished; lowlink 1 < index 2 → not a root, it stays on the stack. Back at 1: lowlink(1) = 1 is unchanged. At 1, lowlink = index = 1 → 1 is a root: popping down to 1 gives an SCC: {1, 2, 3}.

SCC(4): index = lowlink = 4; push 4.

4 → 2 is ignored (2 is in a finished SCC, not on the stack). 4 → 3 is ignored (3 is in a finished SCC, not on the stack). SCC(5): index = lowlink = 5; push 5.

SCC(6): index = lowlink = 6; push 6.

6 → 3 is ignored (3 is in a finished SCC, not on the stack). SCC(7): index = lowlink = 7; push 7.

7 is finished; lowlink 6 < index 7 → not a root, it stays on the stack. Back at 6: lowlink(6) = 6 is unchanged. At 6, lowlink = index = 6 → 6 is a root: popping down to 6 gives an SCC: {6, 7}.

Back at 5: lowlink(5) = 5 is unchanged. Edge 5 → 4: 4 is on the stack → lowlink(5) = min(5, index(4) = 4) = 4.

SCC(8): index = lowlink = 8; push 8.

8 → 5 is ignored (5 is in a finished SCC, not on the stack). 8 → 7 is ignored (7 is in a finished SCC, not on the stack). Self-loop 8 → 8: 8 is on the stack, but lowlink = min(8, 8) = 8 stays the same.

At 8, lowlink = index = 8 → 8 is a root: popping down to 8 gives an SCC: {8}.

Result: 4 SCCs. Each SCC was found the moment its root (the vertex with index = lowlink: 1, 6, 4, 8) finished; they appear in reverse topological order.

Tarjan SCC

Tarjan: Pseudocode

TARJAN_SCC(G):
  index = 1
  stack = [ ]
  SCCs = [ ]
  for each v in V:
    if v.index is undefined:
      SCC(v)
  return SCCs
SCC(v):
  v.index = v.lowlink = index++
  stack.push(v)
  for each (v, w) in E:
    if w.index is undefined:
      SCC(w)
      v.lowlink = min(v.lowlink, w.lowlink)
    else if w is on the stack:
      v.lowlink = min(v.lowlink, w.index)
  if v.lowlink == v.index:
    scc = [ ]
    repeat until w == v:  // at least once
      w = stack.pop()
      scc.add(w)
    SCCs.add(scc)
  • In the figure the index starts at 1 (index = 1); starting at 0 gives the same SCCs.
  • "Is it on the stack?" is answered in O(1) time by an onStack[] array kept alongside the stack.

void scc(int v) {
  index[v] = low[v] = ++counter;
  stack.push(v); onStack[v] = true;
  for (int w : adj[v]) {
    if (index[w] == 0) {
      scc(w);
      low[v] = Math.min(low[v], low[w]);
    } else if (onStack[w])
      low[v] = Math.min(low[v], index[w]);
  }
  if (low[v] == index[v]) {
    int w;
    do {
      w = stack.pop(); onStack[w] = false;
      System.out.print(w + " ");
    } while (w != v);
    System.out.println();
  }
}

Tarjan SCC

Complexity and Kosaraju

Tarjan's running time: O(V + E)

  • V vertices, E edges.
  • Each vertex is visited, pushed and popped once: O(V).
  • Each edge is examined once: O(E).
  • Extra memory: index, lowlink, onStack and the stack: O(V).

Kosaraju's algorithm

  1. DFS pushes vertices in finishing order.
  2. Build the transpose of the graph.
  3. DFS on the transpose in pop order; each DFS tree is an SCC.

On the "Tarjan Step by Step" graph Kosaraju finds the same SCCs: {1, 2, 3}, {4, 5}, {6, 7}, {8}.

Kosaraju: SCCs with Two DFS Passes

Pass 1: DFS on the original graph. dfs1(0): mark 0. The stack (top on the right) is empty; a vertex is pushed only when it finishes.

Neighbor 1 is unvisited → dfs1(1): mark 1.

Neighbor 2 is unvisited → dfs1(2): mark 2.

Neighbor 3 is unvisited → dfs1(3): mark 3. (2's first neighbor, 0, is already visited and was skipped.)

4's only neighbor, 3, is already visited: 4 finishes → push it. The stack accumulates the finishing order.

dfs1(4) returned; 3 has no other neighbor: 3 finishes and is pushed.

2, 1 and 0 finish in turn and are pushed. 0 is on top: the last to finish, it lies in a source component.

Pass 2: visited is cleared and the arrows are reversed. Pop 0; on the transpose dfs2(0) reaches 0 → 2 → 1 and prints them: SCC {0, 1, 2}.

Pop 1, but it is already visited (printed with 0's component): skip. The same happens to 2 next.

2 is visited too: skip.

Pop 3, unvisited: on the transpose dfs2(3) reaches 3 → 4 (the reversed edge 3 → 2 leads to visited 2 and is skipped). SCC {3, 4}.

Pop 4, visited: skip. The stack is empty; two SCCs found: {0, 1, 2} and {3, 4}.

void kosaraju() {
  for (int v = 0; v < n; v++)  // pass 1
    if (!visited[v]) dfs1(v);
  Arrays.fill(visited, false); // pass 2
  while (!stack.isEmpty()) {
    int v = stack.pop();
    if (!visited[v]) {   // new SCC
      dfs2(v); System.out.println(); }
  }
}
void dfs1(int v) {
  visited[v] = true;
  for (int w : adj[v])
    if (!visited[w]) dfs1(w);
  stack.push(v);       // v finished
}

Applications

Topological Sort

In-degrees: 0:0, 1:1, 2:2, 3:1, 4:1, 5:1, 6:2, 7:1

  • In a directed acyclic graph (DAG), an ordering where u comes before v for every edge u → v: course prerequisites, build order, task scheduling.
  • Kahn (BFS-based): enqueue the vertices of in-degree 0; when a vertex is removed, delete its edges and enqueue any vertex whose in-degree drops to 0.
  • DFS-based: list vertices in finishing order, then reverse the list.
Kahn0 1 7 2 3 4 5 6
DFS (reverse finish)0 7 1 2 4 3 5 6
Both are valid: a topological order is not unique. If fewer than V vertices come out, the graph has a cycle (add the edge 2 → 0 from the DFS example and no ordering exists). Time O(V + E).

Topological Sort: Tracing Kahn's Algorithm

A directed acyclic graph (DAG). First count each vertex's in-degree: how many edges enter it? The small numbers next to the vertices are the indeg[] values.

Vertex 0 is the only one with in-degree 0: it has no prerequisites, so it is enqueued.

Dequeue and print 0; its edges count as deleted, so the in-degrees of 1, 2 and 7 drop by 1. 1 and 7 reach zero and are enqueued.

Dequeue and print 1; its edges count as deleted, so the in-degree of 2 drops by 1. 2 reaches zero and is enqueued.

Dequeue and print 7. It has no outgoing edges; no in-degree changes.

Dequeue and print 2; its edges count as deleted, so the in-degrees of 3 and 4 drop by 1. 3 and 4 reach zero and are enqueued.

Dequeue and print 3; its edges count as deleted, so the in-degree of 5 drops by 1. 5 reaches zero and is enqueued.

Dequeue and print 4; its edges count as deleted, so the in-degree of 6 drops by 1. Nothing reaches zero (6 still has 1 prerequisite).

Dequeue and print 5; its edges count as deleted, so the in-degree of 6 drops by 1. 6 reaches zero and is enqueued.

Dequeue and print 6. It has no outgoing edges; no in-degree changes. The queue is empty and all 8 vertices came out, so there is no cycle. Order: 0 1 7 2 3 4 5 6.

void kahn() {
  int[] indeg = new int[n];
  for (int v = 0; v < n; v++)
    for (int w : adj[v]) indeg[w]++;
  Queue<Integer> queue = new LinkedList<>();
  for (int v = 0; v < n; v++)
    if (indeg[v] == 0) queue.add(v);
  while (!queue.isEmpty()) {
    int v = queue.poll();
    System.out.print(v + " ");
    for (int w : adj[v])
      if (--indeg[w] == 0) queue.add(w);
  }
}

Bipartiteness Test with BFS

Undirected graph: the cycle 0-1-3-2 and the triangle 3-4-5. color = −1 means uncolored; source 0 gets color 0 (green) and is enqueued.

Dequeue 0 (color 0). Its uncolored neighbors 1 and 2 get the opposite color (1) and are enqueued.

Dequeue 1 (color 1). Uncolored neighbor 3 gets the opposite color (0) and is enqueued. Neighbor 0 already has the opposite color: the edge joins the two sets, fine.

Dequeue 2 (color 1). Neighbors 0 and 3 already have the opposite color: the edges join the two sets, fine.

Dequeue 3 (color 0). Uncolored neighbors 4 and 5 get the opposite color (1) and are enqueued. Neighbors 1 and 2 already have the opposite color: the edges join the two sets, fine.

Dequeue 4; neighbor 3 has a different color (fine), but neighbor 5 has the same color (1). Both ends of an edge fell into one set: there is an odd cycle, like the triangle 3-4-5 → false.

boolean isBipartite(int s) {
  Arrays.fill(color, -1);
  color[s] = 0; queue.add(s);
  while (!queue.isEmpty()) {
    int v = queue.poll();
    for (int w : adj[v])
      if (color[w] == -1) {
        color[w] = 1 - color[v];
        queue.add(w);
      } else if (color[w] == color[v])
        return false;  // same color
  }
  return true;
}

Summary

Common Mistakes

Forgetting the visited arrayOn a cyclic graph DFS recurses forever and BFS's queue never empties. That is where the myth "BFS fails on cyclic graphs" comes from; with marking it works fine.
Marking on dequeue in BFSThe same vertex gets enqueued by many neighbors; the result may still be right, but the queue grows to O(E). Mark on enqueue instead.
Expecting shortest paths from DFSThe first path DFS finds to a target is not the shortest. Use BFS when unweighted, Dijkstra when weighted.
The order of stack DFSPushing neighbors in order reverses the result (0 7 2 … ≠ 0 1 2 …). To get the recursive order, push them in reverse.
Skipping the "on the stack?" check in TarjanOnly a w on the stack gets min(…, index(w)); a w whose SCC is already found is ignored. Otherwise roots are lost.
Disconnected graphsA traversal from one source sees only its component. To cover the whole graph, restart from every unvisited vertex.
