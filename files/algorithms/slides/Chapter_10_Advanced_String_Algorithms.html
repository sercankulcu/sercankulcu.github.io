Introduction

String Algorithms: Four Problem Families

Four families of algorithms that work on strings:

String SortingLexicographic order: strings are arranged as in a dictionary by comparing character codes. Radix sort: groups strings without comparisons, treating each character as a digit.
ParsingRegular expressions: strings that describe a search pattern. Finite state machines (FSM): automata that read the input one character at a time and change state.
SimilarityLevenshtein distance: the minimum number of single-character edits that turn one string into another. LCS: the longest common subsequence, in order but not necessarily contiguous.
TransformationSuffix array: the starting indices of all suffixes in sorted order. Burrows–Wheeler transform (BWT): a reversible transform obtained by sorting rotations; the first stage of bzip2.

String Sorting

Lexicographic Order

  • Lexicographic (alphabetical) order arranges items by the positions of their characters in the alphabet or code table.
  • Comparison starts with the first characters; if they are equal, move on to the next ones.
  • The first differing character decides: "apple" < "banana" because 'a' < 'b'.
  • If one string runs out, the shorter one (the prefix) comes first: "car" < "cart".
ComparisonDecided by
apple · bananaa < b (1st character)
apple · apricotp < r (3rd character)
car · cart"car" runs out
Zebra · apple'Z' (90) < 'a' (97)
The computer's "alphabet" is the character code (ASCII / Unicode): every uppercase letter comes before every lowercase one, and ç, ğ, ı, ö, ş, ü come after z. For Turkish dictionary order use java.text.Collator.

Example: Comparing "apple" and "apricot"

Call compare("apple", "apricot"). A negative result means a comes first, a positive one means b does (String.compareTo works the same way).

At most as many characters as the shorter string can be compared: n = min(5, 7) = 5.

k = 0 < n: the loop continues with character 1.

Read x = 'a' (97), y = 'a' (97).

'a' == 'a': equal characters decide nothing; move on to the next one.

k = 1 < n: the loop continues with character 2.

Read x = 'p' (112), y = 'p' (112).

'p' == 'p': equal characters decide nothing; move on to the next one.

k = 2 < n: the loop continues with character 3.

Read x = 'p' (112), y = 'r' (114).

'p' ≠ 'r': first differing character found (character 3).

return 112 − 114 = −2 < 0 → apple comes before apricot. The remaining characters are never examined.

int compare(String a, String b) {
  int n = Math.min(a.length(), b.length());
  for (int k = 0; k < n; k++) {
    char x = a.charAt(k), y = b.charAt(k);
    if (x != y)
      return x - y;   // first difference
  }
  return a.length() - b.length();
}

String Sorting

Lexicographic Order: Words and Numbers

  • Numbers sorted as strings are compared character by character from the left: "11" < "2" because '1' < '2'. Likewise, 123, 45, 6, 789 are already in lexicographic order.
  • For numeric order, convert to integers or left-pad with zeros to equal length ("02" < "11").

String Sorting

Comparison-Based String Sorting

void lexSort(String[] a) {
  int n = a.length;
  for (int i = 0; i < n - 1; i++)
    for (int j = i + 1; j < n; j++)
      if (a[i].compareTo(a[j]) > 0) {
        String tmp = a[i];
        a[i] = a[j];
        a[j] = tmp;
      }
}
  • Each position receives the lexicographically smallest of the remaining strings via swaps.
  • compareTo reads at most W characters (W: longest string).
  • Time: O(N²) comparisons × O(W) = O(N² · W).
  • With merge sort, O(N log N) comparisons → O(W · N log N).
InputOutput
eabcdf, abcde, bcdea, cdeab, deabcgabcde, bcdea, cdeab, deabcg, eabcdf
banana, orange, grape, apple, kiwiapple, banana, grape, kiwi, orange

Comparison sorts need Ω(N log N) comparisons. Radix sort makes no comparisons, so this lower bound does not apply to it.

String Sorting · Step by step

LSD Radix Sort: Strings

LSD: right to left, each pass a stable counting sort on that character (short strings get an empty character); equal keys keep the order of the previous pass. Example: cab, dab, bad, dad, fad, ace, bee, bed, add, ebb (W = 3).

Pass 1 (character 3): distribute into buckets by the last character; strings in the same bucket (cab, dab) keep their input order.

Pass 2 (character 2): by the middle character; in bucket 'a', cab, dab, bad, dad, fad keep the previous order (b < d).

Pass 3 (character 1): by the first character; the array is now in lexicographic order: ace, add, bad, bed, bee, cab, dab, dad, ebb, fad.

String Sorting

LSD Radix Sort: Java Code

void lsdSort(String[] a) {
  int W = maxLen(a);               // longest string
  for (int d = W - 1; d >= 0; d--)
    countSort(a, d);               // right to left
}
void countSort(String[] a, int d) {
  int[] cnt = new int[256];        // ASCII
  for (String s : a) cnt[ch(s, d)]++;
  for (int r = 1; r < 256; r++) cnt[r] += cnt[r - 1];
  String[] aux = new String[a.length];
  for (int i = a.length - 1; i >= 0; i--)   // stable
    aux[--cnt[ch(a[i], d)]] = a[i];
  System.arraycopy(aux, 0, a, 0, a.length);
}
int ch(String s, int d) {          // short string → 0
  return d < s.length() ? s.charAt(d) : 0;
}
  • Count: cnt[c] is the number of strings whose d-th character is c.
  • Prefix sums: cnt[c] now marks where bucket c ends.
  • Placement runs from back to front, so equal keys keep their order (stability).
  • ch returns 0 for a string that is too short: "car" comes before "cart".

One pass costs O(N + R), with alphabet size R = 256; W passes → O(W · (N + R)).

String Sorting

MSD Radix Sort: Left to Right

  1. Split all strings into buckets by their first character (B, C, M, W).
  2. Recursively sort each bucket on the next character.
  3. Stop at a one-element bucket or at the end of a string (\0).
Green cells are the characters that must be read to fix the word's place (its distinguishing prefix). MSD examines only these: one character suffices for MIDNIGHT, five for COMPARISON / COMPUTER.

With long common prefixes MSD also reads every character. Since an R = 256 count array is expensive for small buckets, practical versions switch to insertion sort for small subarrays.

String Sorting

Time Complexity and Comparison

  • LSD: W passes (W: length of the longest string), each pass over N strings + R buckets → O(W · (N + R)).
  • With a fixed alphabet (R = 256) the cost is O(W · N): longest string length × number of items.

Regular Expressions

Regular Expressions

  • A regular expression (regex) is a string that describes a search pattern.
  • Used to find, validate, extract or replace every part of a text that matches the pattern.
  • It automates text processing: log analysis, form validation, data cleaning, lexical analysis (lexers) in compilers.
  • Theory: every regular expression has an equivalent finite state machine (Kleene's theorem).

Parse Tree: A URL Example

A grammar for http://didit.csail.mit.edu:4949/:

url  ::= 'http://' host
         ':' port '/'
host ::= word '.' host
       | word
word ::= [a-z]+
port ::= [0-9]+
The grammar looks recursive, but it is only tail recursion; the equivalent regex is http://([a-z]+\.)*[a-z]+:[0-9]+/. Nested structures such as balanced parentheses cannot be described by a regex; they need a context-free grammar and a parser.

Finite State Machines

Finite State Machines

  • A finite state machine (FSM) is a mathematical model that processes a string one character at a time.
  • It has finitely many states; its only memory is the current state.
  • Simple and easy to understand, yet it handles complex string analysis tasks (lexical analysis, protocols, pattern search).
Formal definition: M = (Q, Σ, δ, q₀, F)
States QThe distinct states the machine can be in.
Alphabet ΣThe set of input symbols.
Start state q₀Where processing begins.
Transitions δδ(state, symbol) → new state.
Accept states F ⊆ QIf the machine is in one of these when the string ends, the string is accepted.

Finite State Machines

Kinds of FSM: DFA, NFA, ε-NFA

DFADeterministic finite automaton: every (state, symbol) pair has exactly one transition. Simple to run: O(n).
NFANondeterministic finite automaton: a (state, symbol) pair may have zero, one or several transitions. The machine is in a set of states at once.
ε-NFAAn NFA that allows empty transitions (epsilon, ε) that read no symbol. Built directly from a regex (Thompson's construction).
  • All three recognize the same languages (the regular languages): subset construction turns any NFA into a DFA, though the number of states can grow to 2ⁿ in the worst case.
  • grep, lex/flex and compiler lexers use this chain.

Finite State Machines

Using It: Simulating a DFA

  1. Enter the start state.
  2. For each character, update the state from the transition table.
  3. When the string ends, check whether the final state is an accept state.
boolean accepts(int[][] delta, boolean[] accept,
                String s) {
  int state = 0;                    // start state
  for (char c : s.toCharArray())
    state = delta[state][c - '0'];  // one transition
  return accept[state];              // accepting?
}
The transition table has size int[|Q|][|Σ|]. Each character costs one table lookup: a string of length n is processed in O(n) time, with no backtracking.

Finite State Machines

Example: A Machine That Recognizes "nice"

  • A machine that recognizes "nice": each state stands for the prefix read so far (ε, n, ni, nic, nice).
  • If the expected character does not arrive (≠n, ≠i, …), the machine moves to Error and stays there (a trap state).
  • "nice" → 1 → 2 → 3 → 4 → 7: accept. "nine" → 1 → 2 → 3 → 6: reject (the third character 'n' ≠ 'c').
  • Any character after Success → Error ("nicer" is rejected); self-loops that are not drawn are implied.

Finite State Machines

Example: An Automaton That Searches for "ACACAGA"

textGACACACAGA
state0123454567
  • State q = length of the longest prefix of the pattern that matches the end of the text read so far. All undrawn transitions go to 0. Reaching state 7 means a match (here at position 3).
  • When the 7th character 'C' arrives, go back 5 → 4: the end of "ACACAC" can continue as the prefix "ACAC". This is the automaton form of KMP's prefix function: preprocessing O(m · |Σ|), search O(n).

dfaSearch(dfa, "GACACACAGA", 7)

The automaton for ACACAGA is built in advance. State q = length of the longest pattern prefix that matches the end of the text. Only forward transitions are drawn here; the back transitions are on the previous slide. Initially q = 0.

t[0] = 'G' extends no prefix of the pattern: q stays 0.

t[1] = 'A' is the next pattern character: 0 → 1.

t[2] = 'C' is the next pattern character: 1 → 2.

t[3] = 'A' is the next pattern character: 2 → 3.

t[4] = 'C' is the next pattern character: 3 → 4.

t[5] = 'A' is the next pattern character: 4 → 5.

t[6] = 'C' is not the expected 'G', but q is not reset: "ACACAC" ends with the prefix "ACAC" → 5 → 4. No backing up in the text.

t[7] = 'A' is the next pattern character: 4 → 5.

t[8] = 'G' is the next pattern character: 5 → 6.

'A' takes 6 → 7 = m: pattern found; return i − m + 1 = 9 − 7 + 1 = 3.

int dfaSearch(int[][] dfa, String t, int m) {
  int q = 0;                     // state
  for (int i = 0; i < t.length(); i++) {
    q = dfa[q][t.charAt(i)];
    if (q == m)
      return i - m + 1;          // match
  }
  return -1;
}

Parsing Numbers with an FSM: Code Trace

Input "$20.99 or 5.". State START, buffer empty.

'$' is neither a digit nor a dot; state stays START, nothing happens.

'2' is a digit and the state is START → DIGIT; appended to the buffer.

'0' is a digit: state stays DIGIT; append to the buffer.

'.' arrives → move to DECIMAL; the dot is appended to the buffer.

'9' is a digit: state stays DECIMAL; append to the buffer.

'9' is a digit: state stays DECIMAL; append to the buffer.

' ' is not part of a number: the number ends, 20.99 is printed; back to START.

'o' is neither a digit nor a dot; state stays START, nothing happens.

'r' is neither a digit nor a dot; state stays START, nothing happens.

' ' is neither a digit nor a dot; state stays START, nothing happens.

'5' is a digit and the state is START → DIGIT; appended to the buffer.

'.' arrives → move to DECIMAL; the dot is appended to the buffer.

Input exhausted; the state is DECIMAL, so the buffer is printed: 5.. The trailing dot was included in the number (a flaw).

void findNumbers(String s) {
  State d = State.START;
  StringBuilder buf = new StringBuilder();
  for (char c : s.toCharArray()) {
    boolean digit = Character.isDigit(c);
    if (digit) {
      if (d == State.START) d = State.DIGIT;
      buf.append(c);
    } else if (c == '.' && d != State.DECIMAL) {
      d = State.DECIMAL;
      buf.append(c);
    } else if (d != State.START) {  // number ended
      System.out.println(buf);
      buf.setLength(0);
      d = State.START;
    }
  }
  if (d != State.START) System.out.println(buf);
}

Edit Distance

Levenshtein Distance (Edit Distance)

  • Levenshtein distance (V. Levenshtein, 1965) is a metric that measures how different two strings are.
  • It is the minimum number of single-character edits needed to turn one string into the other.
  • Used in autocorrect and predictive text, spell checking, DNA sequence comparison and fuzzy search.
  • Metric properties: d(a, a) = 0, d(a, b) = d(b, a), triangle inequality.
InsertionAdd a character: "sittin" → "sitting"
DeletionRemove a character: "shine" → "shin"
SubstitutionReplace one character with another: "kitten" → "sitten"
kitten → sitten (k→s) → sittin (e→i) → sitting (+g): d = 3. No shorter sequence exists; dynamic programming proves it.

Edit Distance

Edit Examples

HONDA → HYUNDAI: substitute O→Y, insert U, insert I: d = 3

substitution insertion deletion

  • (a) rain → sain → shin → shine · (b) shine → rhine → raine → rain (delete e) · (c) shine → tshine → trhine → traine → train (delete e). A struck-through orange letter is deleted.
  • The distance is symmetric: (a) and (b) are inverses of each other; insertions and deletions swap roles.

Edit Distance

Computing Levenshtein Distance

D[i][j] = minimum cost of turning the first i characters of a into the first j characters of b.

D[i][0] = i (i deletions) · D[0][j] = j (j insertions)
if ai = bj then D[i][j] = D[i−1][j−1]
otherwise D[i][j] = 1 + min( D[i−1][j] delete, D[i][j−1] insert, D[i−1][j−1] replace )
  • Dynamic programming: each subproblem is solved once and stored in an (m+1) × (n+1) table; the answer is in the bottom-right corner.
  • A cell depends only on its upper, left and upper-left neighbors → fill the table row by row.
  • Time O(m · n); memory O(m · n), or O(min(m, n)) with two rows if only the distance is needed.

Edit Distance

Levenshtein: Java Code

int levenshtein(String a, String b) {
  int m = a.length(), n = b.length();
  int[][] D = new int[m + 1][n + 1];
  for (int i = 0; i <= m; i++) D[i][0] = i;  // delete
  for (int j = 0; j <= n; j++) D[0][j] = j;  // insert
  for (int i = 1; i <= m; i++)
    for (int j = 1; j <= n; j++)
      if (a.charAt(i - 1) == b.charAt(j - 1))
        D[i][j] = D[i - 1][j - 1];            // equal
      else
        D[i][j] = 1 + Math.min(D[i - 1][j - 1], // replace
                  Math.min(D[i][j - 1],         // insert
                           D[i - 1][j]));       // delete
  return D[m][n];
}
  • Table index i corresponds to string index i − 1: row 0 of D is for the empty prefix.
  • Examples: kitten → sitting = 3, ercan → sercan = 1, apple → banana = 5.

Edit Distance · Step through the code

levenshtein("kar", "ark")

a = "kar" (rows), b = "ark" (columns). Column 0 holds i deletions and row 0 holds j insertions: the cost of converting to or from the empty prefix.

'k' ≠ 'a' → 1 + min(replace 0, insert 1, delete 1) = 1.

'k' ≠ 'r' → 1 + min(replace 1, insert 1, delete 2) = 2.

a[0] = b[2] = 'k' → free: D[1][3] = up-left = 2.

a[1] = b[0] = 'a' → free: D[2][1] = up-left = 1.

'a' ≠ 'r' → 1 + min(replace 1, insert 1, delete 2) = 2.

'a' ≠ 'k' → 1 + min(replace 2, insert 2, delete 2) = 3.

'r' ≠ 'a' → 1 + min(replace 2, insert 3, delete 1) = 2.

a[2] = b[1] = 'r' → free: D[3][2] = up-left = 1.

'r' ≠ 'k' → 1 + min(replace 2, insert 1, delete 3) = 2.

D[3][3] = 2: delete the leading k of "kar" (ar), then append k (ark). The green path shows these two edits.

int levenshtein(String a, String b) {
  int m = a.length(), n = b.length();
  int[][] D = new int[m + 1][n + 1];
  for (int i = 0; i <= m; i++)
    D[i][0] = i;            // delete
  for (int j = 0; j <= n; j++)
    D[0][j] = j;            // insert
  for (int i = 1; i <= m; i++)
    for (int j = 1; j <= n; j++)
      if (a.charAt(i-1) == b.charAt(j-1))
        D[i][j] = D[i-1][j-1];  // equal
      else
        D[i][j] = 1 + Math.min(D[i-1][j-1],
            Math.min(D[i][j-1], D[i-1][j]));
  return D[m][n];
}

  • The LCS is the longest common subsequence that keeps relative order but need not be contiguous; it is found with a DP table like Levenshtein's (diagonal + 1 on a match, otherwise max(up, left)).
  • If only insertions and deletions are allowed, the distance is m + n − 2 · LCS: 6 + 7 − 8 = 5; Levenshtein, which also allows substitutions, brings it down to 4.
  • Longest common substring: on a match L[i][j] = L[i−1][j−1] + 1, otherwise 0; the answer is the largest value in the table (ercan · sercan → "ercan").
  • A similarity ratio: 1 − d / max(m, n). kitten · sitting: 1 − 3/7 ≈ 0.57.

Searching with a Suffix Array

  • Since the suffixes are sorted, those that start with the pattern P form a contiguous range in SA.
  • Both ends of the range are found by binary search: O(log n) steps × O(m) per comparison = O(m log n).
  • Far less memory than a suffix trie: just n integers.
  • Add the LCP array (longest common prefix of adjacent suffixes) and the longest repeated substring is found in O(n).

search("banana", sa, "an")

t = "banana", SA = [5, 3, 1, 0, 4, 2], p = "an". The suffixes starting with "an" form a contiguous range of the sorted array; two binary searches find its ends.

mid = 3: "banana" ≥ "an" → hi = mid. Range [0, 3).

mid = 1: "ana" ≥ "an" → hi = mid. Range [0, 1).

mid = 0: "a" < "an" → lo = mid + 1. Range [1, 1).

First loop done: the first suffix not less than "an" is at rank 1 → first = 1. For the second search, hi is reset to the end of the array.

mid = 3: "banana" does not start with "an" → hi = mid.

mid = 2: "anana" starts with "an" → lo = mid + 1.

Result [1, 3): ranks 1 and 2 → SA values 3 and 1. "an" occurs in banana at positions 3 and 1; 5 comparisons sufficed (each binary search takes at most ⌊log₂ 6⌋ + 1 = 3).

int[] search(String t, int[] sa, String p) {
  int lo = 0, hi = sa.length;
  while (lo < hi) {   // first >= p
    int mid = (lo + hi) / 2;
    if (t.substring(sa[mid])
          .compareTo(p) < 0) lo = mid + 1;
    else hi = mid;
  }
  int first = lo;
  hi = sa.length;
  while (lo < hi) {   // not prefixed by p
    int mid = (lo + hi) / 2;
    if (t.startsWith(p, sa[mid]))
      lo = mid + 1;
    else hi = mid;
  }
  return new int[] { first, lo };
}

String Transforms

The Burrows–Wheeler Transform (BWT)

  • The Burrows–Wheeler transform (BWT, 1994) rearranges the input: it changes no characters, only their positions.
  • It brings equal characters together: characters that precede similar contexts end up next to each other.
  • It improves the performance of compression algorithms.
  • It is reversible: the original data can be recovered from the transform.

Steps

  1. Generate all cyclic rotations of the input string.
  2. Sort the rotations alphabetically.
  3. Form a new string from the last characters of the sorted rotations (column L).
  4. Store the row number of the original string in the sorted list (or append a unique $).
The bzip2 pipeline: BWT → Move-to-Front (repeats become small numbers) → Run-Length Encoding → Huffman coding.

String Transforms · Step by step

BWT Example: BANANA

Input: BANANA

1. All rotations: BANANA, ANANAB, NANABA, ANABAN, NABANA, ABANAN (moving the first character to the end).

2. Sorted: ABANAN, ANABAN, ANANAB, BANANA, NABANA, NANABA. The original string is in row 3 (counting from 0).

3. Last characters (column L): NNBAAA. Output: (NNBAAA, 3). Equal letters are grouped: NN, AAA.

String Transforms

BWT Example: abraca

  • Last column of the sorted matrix: L = caraab.
  • The original "abraca" is in row 1 of the sorted matrix (counting from 0); this index is stored for the inverse transform.
  • The first column (F = aaabcr) is just L's letters in sorted order; knowing L gives F.
The direct method generates n rotations with substring and sorts them with Arrays.sort → O(n² log n) time, O(n²) memory. In practice it is derived from the suffix array in O(n) via L[i] = T[SA[i] − 1] (T is the text with $ appended; L[i] = $ if SA[i] = 0; the formula is for the $ version). The $ and cyclic BWTs differ: cyclic BANANA → NNBAAA, BANANA$ → ANNB$AA.

inverseBWT("annb$aa")

L = "annb$aa" (the BWT of banana$). rank[i]: which occurrence of its character L[i] is in L (from 0). E.g. L[6] = a, the third a → 2.

C[c] = number of characters smaller than c = the row where c starts in column F: $ → 0, a → 1, b → 4, n → 5.

i = 0: L[0] = 'a' is prepended → s = "a". LF(0) = C['a'] + rank[0] = 1 + 0 = 1.

i = 1: L[1] = 'n' is prepended → s = "na". LF(1) = C['n'] + rank[1] = 5 + 0 = 5.

i = 5: L[5] = 'a' is prepended → s = "ana". LF(5) = C['a'] + rank[5] = 1 + 1 = 2.

i = 2: L[2] = 'n' is prepended → s = "nana". LF(2) = C['n'] + rank[2] = 5 + 1 = 6.

i = 6: L[6] = 'a' is prepended → s = "anana". LF(6) = C['a'] + rank[6] = 1 + 2 = 3.

i = 3: L[3] = 'b' is prepended → s = "banana". LF(3) = C['b'] + rank[3] = 4 + 0 = 4.

Rows 0 → 1 → 5 → 2 → 6 → 3 → 4 were visited; the next row would end in $, so the loop stops after n − 1 = 6 rounds. Result: banana.

String inverseBWT(String L) {   // with $
  int n = L.length();
  int[] rank = new int[n];
  int[] cnt = new int[256];
  int[] C = new int[256];
  for (int i = 0; i < n; i++)
    rank[i] = cnt[L.charAt(i)]++;
  for (int c = 1; c < 256; c++)
    C[c] = C[c - 1] + cnt[c - 1];
  StringBuilder s = new StringBuilder();
  int i = 0;                   // $ row
  for (int k = 0; k < n - 1; k++) {
    char c = L.charAt(i);
    s.insert(0, c);
    i = C[c] + rank[i];        // LF(i)
  }
  return s.toString();
}

Common Mistakes

Mistaking code order for the alphabet"Zebra" < "apple" and "şeker" > "zeytin". Case and Turkish letters need a Collator or normalization.
Sorting numbers as strings"10" < "9". For numeric order, convert to integers or zero-pad to equal length.
An unstable sub-sort in LSDEvery pass must be stable, or the order from earlier passes is lost. In counting sort, place items from back to front.
Unescaped dot, greedy .*a.b also matches "a+b"; <.*> swallows the whole line. Use \. and the lazy .*?. Expressions like (a+)+$ cause exponential backtracking.
Off-by-one in the DP tableThe table is (m+1) × (n+1); D[i][j] compares charAt(i − 1). Not initializing the first row/column breaks the result.
Confusing subsequence and substringLCS does not require contiguity; longest common substring does. In BWT, forgetting to store the row index or the $ makes the transform irreversible.
