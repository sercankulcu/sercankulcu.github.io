Introduction

A Road Network Is a Graph

  • Intersections are vertices, roads are edges, and road lengths or travel times are weights.
  • The length of a path = the sum of its edge weights.
  • A shortest path between two vertices is a path of minimum total weight; its length is written δ(s, v).
  • Example: from Home to School, Home–1–2–4–School = 4 + 2 + 3 + 3 = 12; Home–1–4–School has fewer edges but costs 13.
In a weighted graph, the path with the fewest edges need not be the shortest. Navigation, network routing (OSPF, RIP), pathfinding in games and logistics all solve this problem.

Introduction

The Basic Operation: Relaxation

Each vertex keeps two values:

  • d[v]: the shortest-path estimate so far (∞ at first, 0 at the source)
  • π[v]: the vertex before v on that path (its predecessor)
RELAX(u, v, w):
  if d[u] + w(u, v) < d[v]:
    d[v] = d[u] + w(u, v)
    π[v] = u

d[u] + w = 5 + 3 = 8 < 9 → d[v] = 8, π[v] = u

Every algorithm in this chapter relies on relaxation; they differ in the order in which they relax edges and how many times. d[v] can only decrease and never drops below the true δ(s, v).

Introduction

Properties of Shortest Paths

Optimal substructure

Every subpath of a shortest path is itself a shortest path. If s ⇝ u ⇝ v is shortest, so is s ⇝ u. Dynamic programming and greedy methods rest on this.

Triangle inequality

For every edge (u, v), δ(s, v) ≤ δ(s, u) + w(u, v). Relaxation fixes edges that violate it.

Negative cycle

If a cycle of negative total weight is reachable from the source, each lap makes the path shorter: the shortest path is undefined (−∞).

Simple paths

Without negative cycles a shortest path has no cycle, so it has at most V − 1 edges. That is where Bellman-Ford's V − 1 passes come from.

To rebuild a path, follow π from the target back to the source and list the vertices in reverse. Together, all π edges form a shortest-path tree.

Dijkstra

Dijkstra's Algorithm

  • Finds shortest paths from a source vertex to every other vertex (single-source).
  • Devised by Edsger W. Dijkstra in 1956 and published in 1959.
  • Correct only on graphs whose edge weights are nonnegative.
  • Greedy: at each step it picks the not-yet-settled vertex with the smallest d value and settles it.
  • The neighbors of the chosen vertex are relaxed.
The ripple analogyA ripple from a stone dropped at the source reaches the vertices in order of distance: the nearest first, then the next… Dijkstra settles vertices in exactly this order. The set of settled vertices is called S.

Dijkstra

Dijkstra: The Steps

Step 1: Choose the start vertex and set its distance to 0; every other vertex gets ∞.

Initialization: d[s] = 0, d[v] = ∞, π[v] = undefined, S = ∅.

Step 2: From the chosen vertex, compute distances to its not-yet-processed neighbors.

Candidate distance for neighbor v: d[u] + w(u, v).

Step 3: If a shorter path is found, update the neighbor's distance (relaxation).

If d[u] + w(u, v) < d[v], d[v] and π[v] change.

Step 4: Mark the processed vertex (add it to S) and select the unmarked vertex with the smallest distance.

The selection uses an array or a priority queue.

Step 5: Repeat steps 2–4 until every vertex is processed.

Unreachable vertices keep distance ∞.

Dijkstra

Dijkstra: Pseudocode

DIJKSTRA(G, source):
  dist = [ ]; visited = [ ]
  pq = { }
  for each v in V:
    dist[v] = infinity
    visited[v] = 0
  dist[source] = 0
  pq.add(source, 0)
  while pq is not empty do:
    u = pq.extractMin()   // smallest distance
    if visited[u] == 0:
      visited[u] = 1
      for each (u, v) in G[u]:
        if dist[u] + weight(u, v) < dist[v]:
          dist[v] = dist[u] + weight(u, v)
          pq.add(v, dist[v])
  return dist
Lazy deletion: a vertex may enter the queue several times; when a stale entry comes out, the visited check skips it. To recover paths, relaxation also stores prev[v] = u.

void dijkstra(int src) {
  int[] dist = new int[V + 1];
  int[] prev = new int[V + 1];

    new PriorityQueue<>((a, b) -> a[1] - b[1]);

  while (!pq.isEmpty()) {
    int u = pq.poll()[0];
    if (visited[u]) continue; // stale entry

        dist[v] = dist[u] + w;
        prev[v] = u;
        pq.add(new int[] { v, dist[v] });

    }
  }
}

void printPath(int[] prev, int[] dist,
            int src, int target) {
  if (dist[target] == INF) {   // unreachable
    System.out.print("no path"); return;
  }
  Deque<Integer> stack = new ArrayDeque<>();
  for (int v = target; v != src; v = prev[v])
    stack.push(v);         // walk back
  stack.push(src);
  while (!stack.isEmpty())
    System.out.print(stack.pop() + " ");
}

A stack turns the vertices collected backward into the right order.

Dijkstra

Why Does Dijkstra Fail on Negative Edges?

  • The correctness proof relies on this: once u is settled, any path leaving S has length at least d[u], because edges are nonnegative and a path can only grow.
  • A negative edge breaks that assumption: a vertex processed later can open a shorter path to an already settled vertex.
  • Adding a constant to every weight is no fix: paths with more edges are penalized more, so the shortest path changes.
  • With negative edges, use Bellman-Ford.

A is settled; relaxation gives d[B] = 2, d[C] = 3.

Smallest d: B (2). Dijkstra settles B, assuming "no shorter path to B can exist".

C is processed: d[C] + (−2) = 1 < 2, but B is already in S. The result d[B] = 2 is wrong; the true δ(A, B) = 1 (A → C → B).

Bellman-Ford

The Bellman-Ford Algorithm

  • Finds shortest paths from a source vertex to every other vertex (single-source).
  • Named after Richard Bellman (1958) and Lester Ford Jr. (1956); E. F. Moore gave the same method in 1959.
  • Handles negative edge weights.
  • Detects negative cycles reachable from the source.
  • Slower than Dijkstra: O(V · E).
How it worksIt keeps an array of shortest-path estimates, all ∞ except 0 at the source. It examines every edge in turn and updates the estimates, repeating this sweep V − 1 times. There is no vertex selection and nothing greedy: it is dynamic programming, where pass i builds shortest paths of at most i edges from the previous pass.

Bellman-Ford

Bellman-Ford: The Steps

Step 1: Set the start vertex's distance to 0 and every other vertex's to ∞.

π[v] = undefined.

Step 2: Examine the edges one by one and update distances by relaxation; repeat this pass V − 1 times.

The edge order is fixed within a pass; it affects how many passes are needed, not the result.

Step 3: Once a vertex's distance improves, its neighbors' distances may improve in later checks.

Each pass pushes the improvement at least one edge further along the path.

Step 4: To check for negative cycles, examine every edge once more; if some edge still relaxes, a negative cycle is reachable from the source.

Without such a cycle no edge relaxes after V − 1 passes.

Bellman-Ford

Why V − 1 Passes? Complexity

  • Without negative cycles every shortest path has at most V − 1 edges.
  • Invariant: after pass i, d[v] = δ(s, v) for every v that has a shortest path with at most i edges.
  • Pass i is sure to relax the path's i-th edge; V − 1 passes complete every path.
  • Each pass examines E edges: O(V · E) time in total, O(V) extra memory.

Sparse, E ≈ VO(V²)

Early exit: if no d changes during a pass, later passes cannot change anything either; leave the loop.

Floyd-Warshall

The Floyd-Warshall Algorithm

  • Finds shortest paths between all pairs of vertices.
  • Found independently by Bernard Roy (1959), Stephen Warshall (1962, transitive closure) and Robert Floyd (1962, shortest paths).
  • Works with negative edge weights and detects negative cycles (in which case shortest paths are undefined).
  • Uses dynamic programming, keeping the results in a V × V matrix D.
Single-source or all-pairs?Bellman-Ford and Dijkstra find shortest paths from one source. Floyd-Warshall computes shortest paths between all pairs at once with three nested loops. The code is tiny, and it is practical on dense graphs.

Floyd-Warshall

Floyd-Warshall: Steps and Recurrence

  1. Step 1: Fill D with the edge weights: D[i][i] = 0, and ∞ where there is no direct edge.
  2. Step 2: Take intermediate vertices k = 1, 2, …, n in turn; for every pair (i, j)…
  3. Step 3: Compute the length of the path through k, D[i][k] + D[k][j], and compare it with the current D[i][j].
  4. Step 4: If it is shorter, write the new value into the matrix (and update Π as well).
SubproblemD(k)[i][j]: the length of a shortest i ⇝ j path whose intermediate vertices all come from {1, …, k}.
D(k)[i][j] = min( D(k−1)[i][j], D(k−1)[i][k] + D(k−1)[k][j] )
Either k is not on the path, or the path passes through k once. D(n) is the answer.

Floyd-Warshall

Floyd-Warshall: Complexity

  • Time Θ(V³): three nested for loops, each running V times.
    • the first (outermost) loop runs over all intermediate vertices (k),
    • the second over all source vertices (i),
    • the last over all target vertices (j).
  • Memory Θ(V²): D can be updated in place; row and column k do not change during pass k.
For all pairsTime

V × Dijkstra (array)O(V³)
V × Dijkstra (heap)O(V(V + E) log V)

Loop order matters: k must be outermost. With k inside, the result is wrong.

Floyd-Warshall: Java

void floydWarshall(int[][] d) {  // V x V
  for (int k = 0; k < V; k++)       // via
    for (int i = 0; i < V; i++)     // from
      for (int j = 0; j < V; j++)   // to
        if (d[i][k] != INF
            && d[k][j] != INF
            && d[i][k] + d[k][j] < d[i][j]) {
          d[i][j] = d[i][k] + d[k][j];
          prev[i][j] = prev[k][j];
        }
  for (int i = 0; i < V; i++)
    if (d[i][i] < 0)
      throw new IllegalStateException(
          "Negative cycle");
}
  • The matrix is updated in place; no separate copy of D(k) is needed.
  • The INF check prevents overflow when adding to Integer.MAX_VALUE.
  • prev[i][j] = prev[k][j]: on the new path, the vertex before j is the same as on the k ⇝ j path.
  • Negative cycle: some vertex has a negative distance to itself (D[i][i] < 0).

A* Search

The A* (A-Star) Search Algorithm

  • A search algorithm that finds a shortest path between two points (start → goal).
  • Developed in 1968 by Peter Hart, Nils Nilsson and Bertram Raphael.
  • Combines Dijkstra's actual cost (uniform-cost search) with the goal estimate of greedy best-first search.
  • It needs a good estimate function (a heuristic) to work well.
  • Time and memory grow quickly as the number of vertices increases.
How it worksEach vertex has an estimate h(n) of its distance to the goal. At every step, among the vertices in the open list, it picks the one with the smallest sum of actual cost and estimated cost. This way it heads toward the goal while still keeping the cheapest path.

A* Search

How Does A* Work? f(n) = g(n) + h(n)

g(n): actual costThe cost of the path found so far from the start to n (the "g-cost"). Same as d[n] in Dijkstra.
h(n): heuristicThe estimated cost from n to the goal (the "h-cost"), such as straight-line or Manhattan distance.
f(n) = g(n) + h(n)The estimated total cost of a solution through n. The vertex with the smallest f in the open list is expanded.
Selection ruleAlgorithmBehavior
g(n) onlyDijkstraspreads equally in all directions; correct but expands many vertices
h(n) onlyGreedy best-firstrushes toward the goal; fast, but no shortest-path guarantee
g(n) + h(n)A*heads toward the goal; with a suitable h, guarantees a shortest path
Vertices that look close to the goal by the heuristic get priority, but thanks to g a vertex reached by an expensive path is held back.

A* Search

A*: The Steps

1. Set g(start) = 0 and add it to the open list (a priority queue). All other vertices get g = ∞.

Open list: discovered but not yet expanded vertices.

2. Remove the vertex with the smallest f = g + h from the open list; put it on the closed list.

The rule is the sum f = g + h, not g or h alone.

3. If it is the goal, stop: rebuild the path from the predecessors.

The goal is final when removed, not when added.

4. Otherwise, for each neighbor v let g' = g(u) + w(u, v); if g' is smaller, update g, f and the predecessor and add v to the open list.

Dijkstra's relaxation. A closed v with a better g is reopened (never with a consistent h).

5. Go back to step 2. If the open list empties, there is no path.

The choice is from the whole open list, not just the last vertex's neighbors.

A* Search

Properties of a Heuristic

Admissibleh(n) ≤ h*(n): it never overestimates the true remaining cost. Then, when A* removes the goal, the path it found is shortest.
Consistenth(u) ≤ w(u, v) + h(v) and h(goal) = 0. With a consistent h, a vertex is final once it enters the closed list (it is never reopened).
Grid heuristics4 directions: Manhattan |Δx| + |Δy|. 8 directions: octile 14·min + 10·(max − min). Free plane: Euclidean distance.
Extreme casesh = 0 → A* = Dijkstra. h = h* (perfect) → only vertices on a shortest path are expanded. h > h* → fast, but no shortest-path guarantee.

A* Search

A*: Running Time

  • Worst-case time and memory in terms of the search tree O(bd):
    • b: branching factor (average number of neighbors), d: depth of the goal (number of steps in the solution).
  • On a finite graph with a consistent h, A* does at most O((V + E) log V) work, like Dijkstra.
  • The better the heuristic, the fewer vertices are expanded: with a perfect estimate (h = h*) only the d vertices on the path are expanded.
  • Its weak point is memory: the open and closed lists grow; variants such as IDA* and SMA* bound the memory.
O(bd) is the bound for the worst case (a useless h, e.g. h = 0), not for a perfect estimate; with a perfect estimate the search is linear in the path length.

Related Methods

BFS: Shortest Paths in an Unweighted Graph

  • When all edges are equal (weight 1), the shortest path = the path with the fewest edges.
  • Breadth-first search (BFS) visits vertices level by level, in order of distance from the source: d[v] = d[u] + 1.
  • A FIFO queue replaces Dijkstra's priority queue: O(V + E).
  • Example (graph at right): the shortest path 0 → 6 is 0 → 2 → 4 → 6 (3 edges).
  • Bidirectional search: run BFS from both the source and the target and stop when the two waves meet; about 2·bd/2 vertices are expanded.

Numbers: BFS level (edge count). Green: the BFS tree.

Common Mistakes

Dijkstra with negative edgesA shorter path to a settled vertex can appear later; the result is silently wrong. Negative edges need Bellman-Ford.
∞ + w overflowInteger.MAX_VALUE + w wraps around to a negative number and looks "shorter". That is why d[u] != INF is checked first.
Floyd-Warshall loop orderThe intermediate-vertex loop k must be outermost; the order i, j, k gives wrong results.
Number of passesBellman-Ford may need all V − 1 passes (Example 2); one pass is not always enough. The check pass is separate.
Stopping at the goal in A*Stop when the goal is removed from the open list, not when it is added. An h that overestimates can miss the shortest path.
Negative weight on an undirected edgeAn undirected negative edge is a negative cycle by itself: u → v → u.

Worked Problems

Directed graph: A→B 4, A→C 2, C→B 1, B→D 5, C→D 8, C→E 10, D→E 3; source A.

  1. In what order does Dijkstra settle the vertices? What are the final d values?
  2. Write the shortest path from A to E using the π array.
  3. If the edges are examined in alphabetical order (A→B, A→C, B→D, C→B, C→D, C→E, D→E), how many relaxations happen in each pass of Bellman-Ford?
  4. What is the final Floyd-Warshall D matrix for the graph 1→2 (4), 2→3 (1), 1→3 (7), 3→1 (−2)? Is there a negative cycle?
  5. V = 1000, E = 5000, and there are negative edges. Which algorithm, and roughly how many operations?
Show answers
  1. A, C, B, D, E; d = A:0, B:3, C:2, D:8, E:11 (B improves via C, 2 + 1).
  2. π[E] = D, π[D] = B, π[B] = C, π[C] = A → A → C → B → D → E = 2 + 1 + 5 + 3 = 11.
  3. Pass 1: 5 (B=4, C=2, D=9, B=3, E=12); pass 2: 2 (D=8, E=11); passes 3–4: 0 → early exit is possible.
  4. D = [[0, 4, 5], [−1, 0, 1], [−2, 2, 0]]; the diagonal is 0 → the cycles 1→2→3→1 = +3 and 1→3→1 = +5, no negative cycle.
  5. Bellman-Ford: V · E = 1000 · 5000 = 5 · 10⁶ relaxation attempts (Dijkstra is unreliable with negative edges).
