Java & programming

The Java needed to read and trace the code in the decks and to write your own solutions.

J

Java basics: types, conditions, loops

int · long · double · if · for · while

The code in the decks is written in Java, so you should be able to trace on paper how many times a loop runs and how each variable changes. The roughly ±2.1 billion limit of int and integer division (7 / 2 = 3) are frequent sources of bugs.

Why it matters

Every code-trace slide uses these constructs, and the classic overflow bug in binary search comes from the int limit.

Needed inChapter 1.1 · Insertion Sort: CodeChapter 1.2 · Counting StepsChapter 3 · Binary Search: Implementation Details

Self-check

int a = 7, b = 2; double d = a / b; What is d?

3.0. The division is done on integers (3) and only then converted to double. For 3.5 write (double) a / b.

Example (Java) 
int sum = 0;
for (int i = 1; i <= 10; i++) {
    if (i % 2 == 0) sum += i;       // add the even numbers
}
System.out.println(sum);            // 30
long big = 50_000L * 50_000;        // would overflow as int
System.out.println(big);            // 2500000000
[ ]

Arrays and 2D arrays

0-based index · length · int[][]

Sorting, searching and dynamic programming tables all work on arrays. You should know that indices run from 0 to length − 1, that an array is passed to a method by reference, and that a 2D array is traversed row by row.

Why it matters

Sorting algorithms work in place on an array, DP tables are 2D arrays, and an adjacency matrix is a 2D array too.

Needed inChapter 2 · Bubble Sort: CodeChapter 6 · Table-Filling TraceChapter 4.1 · Storing a Graph in Memory

Self-check

After int[] a = {3, 1, 2}; what happens when a[3] is read?

An ArrayIndexOutOfBoundsException is thrown; the valid indices are 0, 1 and 2.

Example (Java) 
int[] a = new int[5];              // [0, 0, 0, 0, 0]
a[a.length - 1] = 9;               // last element
int[][] dp = new int[3][4];        // 3 rows, 4 columns
for (int i = 0; i < dp.length; i++)
    for (int j = 0; j < dp[i].length; j++)
        dp[i][j] = i + j;
System.out.println(dp[2][3]);      // 5

Methods and parameter passing

return value · pass by value · array reference

Algorithms are usually written as methods: the input is a parameter and the result is the return value. Java passes everything by value, but for arrays and objects the value copied is a reference, so a swap inside a method changes the caller's array.

Why it matters

All sorting algorithms use helper methods that swap or shift elements; the partition method returns the final position of the pivot.

Needed inChapter 2 · Bubble Sort: CodeChapter 2 · The Partition Procedure

Self-check

Does writing a = new int[10]; inside a method change the caller's array?

No. Only the method's local reference is bound to the new array; the caller still sees the old one.

Example (Java) 
static void swap(int[] a, int i, int j) {
    int t = a[i]; a[i] = a[j]; a[j] = t;     // the caller's array changes
}
static void increment(int x) { x++; }        // the caller's variable does not

int[] d = {5, 7};
swap(d, 0, 1);               // d = [7, 5]
int y = 1;
increment(y);                // y is still 1
System.out.println(d[0] + " " + y);   // 7 1
↻

Recursion and the call stack

base case · recursive call · depth

Merge sort, quicksort, DFS, backtracking and divide-and-conquer algorithms are recursive. You should know that each call is pushed onto the call stack with its own local variables, that a missing base case leads to StackOverflowError, and that recursion depth costs memory.

Why it matters

Fast exponentiation, merge sort, recursive DFS and the backtracking template are all written directly with recursion.

Needed inChapter 1.1 · Computing a PowerChapter 4.1 · Recursive DFS: PseudocodeChapter 13 · General Template

Self-check

How many times does power(2, 10) execute the power method, counting the first call?

5 times: n = 10, 5, 2, 1, 0.

Example (Java) 
static int power(int a, int n) {          // a to the power n, n >= 0
    if (n == 0) return 1;                    // base case
    int half = power(a, n / 2);              // the problem is halved
    return (n % 2 == 0) ? half * half : half * half * a;
}

System.out.println(power(2, 10));         // 1024; depth about log2(n)
OOP

Classes, objects and comparators

class · Comparable · Comparator · generics

Concepts such as edges, vertices, jobs or items are represented by small classes. Sorting and priority queues need a compareTo method or a Comparator to compare elements: in Kruskal we sort edges by weight, in activity selection we sort activities by finish time.

Why it matters

Most greedy algorithms start with a sort, and Dijkstra and Prim put comparable objects into a priority queue.

Needed inChapter 4.3 · Kruskal: Steps & PseudocodeChapter 12 · Activity Selection Problem

Self-check

Why is return w - o.w; risky inside compareTo?

For large positive and negative values the subtraction can overflow int and flip the sign; Integer.compare cannot overflow.

Example (Java) 
static class Edge implements Comparable<Edge> {
    final int u, v, w;
    Edge(int u, int v, int w) { this.u = u; this.v = v; this.w = w; }
    public int compareTo(Edge o) { return Integer.compare(w, o.w); }
}

List<Edge> edges = new ArrayList<>();
edges.add(new Edge(0, 1, 7));
edges.add(new Edge(1, 2, 3));
Collections.sort(edges);                           // ascending by weight
edges.sort((a, b) -> Integer.compare(b.w, a.w));   // descending: Comparator
System.out.println(edges.get(0).w);                // 7
⊞

Java collections

ArrayList · HashMap · ArrayDeque · PriorityQueue

The Java code in the decks uses ready-made structures often: ArrayList for adjacency lists, ArrayDeque for the BFS queue and the DFS stack, PriorityQueue for Dijkstra and Prim, HashMap for memoization. Knowing the cost of each basic operation is a precondition for computing an algorithm's total running time correctly.

Why it matters

BFS is written with a queue, Dijkstra with a priority queue and memoization with a map.

Needed inChapter 4.1 · BFS: PseudocodeChapter 4.2 · Dijkstra: Java TraceChapter 6 · Memoization Trace

Self-check

How long do add and poll take in a PriorityQueue? And contains(x) and remove(x)?

add and poll take O(log n); contains(x) and remove(x) scan the internal array and take O(n).

Example (Java) 
Deque<Integer> queue = new ArrayDeque<>();
queue.offer(1); queue.offer(2);
int first = queue.poll();                         // 1 (first in, first out)

PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> Integer.compare(x[1], y[1]));
pq.add(new int[] {7, 40});
pq.add(new int[] {3, 15});
int[] smallest = pq.poll();                       // [3, 15]

Map<Integer, Long> memo = new HashMap<>();
memo.put(10, 55L);
System.out.println(first + " " + smallest[0] + " " + memo.get(10));   // 1 3 55

Reading and tracing pseudocode

← assignment · 1-based indices · trace table

The decks and textbooks often give algorithms in pseudocode: ← is assignment, arrays may start at 1, and “for j ← 2 to n” includes the last value. When translating to Java you must account for these differences and be able to write the value of each variable at every step in a trace table.

Why it matters

Graph, flow and branch-and-bound algorithms are first given in pseudocode and then in Java.

Needed inChapter 1.1 · Insertion Sort: CodeChapter 4.2 · Dijkstra: PseudocodeChapter 4.4 · Pseudocode

Self-check

How are the loops written when the pseudocode above is translated to 0-based Java?

The outer loop becomes for (int j = 1; j < n; j++), and the inner condition becomes i >= 0 && A[i] > key.

Example 
INSERTION-SORT(A, n)
  for j ← 2 to n
      key ← A[j]
      i ← j − 1
      while i > 0 and A[i] > key
          A[i + 1] ← A[i]
          i ← i − 1
      A[i + 1] ← key

Testing and debugging

edge cases · assertions · small inputs

Even a correct idea must be implemented carefully and tested. Testing with empty input, a single element, repeated values, sorted and reverse-sorted arrays, disconnected graphs and overflow-prone large values should be a habit.

Why it matters

Each chapter's “common mistakes” slide collects such edge cases.

Needed inChapter 2 · Common MistakesChapter 3 · Binary Search: Implementation Details

Self-check

When does mid = (low + high) / 2 give a wrong result in binary search?

When low + high exceeds the int range the sum overflows and becomes negative; low + (high − low) / 2 is safe.

Example (Java) 
int[] empty = {}, one = {4}, equal = {2, 2, 2}, rev = {5, 4, 3, 2, 1};
for (int[] t : new int[][] {empty, one, equal, rev}) {
    int[] k = t.clone();
    Arrays.sort(k);
    for (int i = 1; i < k.length; i++)
        if (k[i - 1] > k[i]) throw new AssertionError("not sorted");
}
System.out.println("all tests passed");

Basic data structures

The structures algorithms work on, and the cost of their basic operations.

→

Linked lists

node · next · O(1) insertion at the front

Like an array it stores a sequence, but the elements are not contiguous in memory; each node points to the next. Inserting at the front takes O(1), accessing the i-th element takes O(n). Adjacency lists, chaining in hash tables and the O(1) implementation of an LRU cache rely on linked lists.

Why it matters

Hash tables with chaining and the O(1) LRU cache use linked lists.

Needed inChapter 3 · Insertion with ChainingChapter 9 · LRU: O(1) Implementation

Self-check

Why does deleting the last element of a singly linked list take O(n)?

The next field of the second-to-last node must be set to null, and reaching that node requires walking from the head.

Example (Java) 
static class Node {
    int value; Node next;
    Node(int value, Node next) { this.value = value; this.next = next; }
}

Node head = null;
for (int x = 1; x <= 3; x++) head = new Node(x, head);    // 3 → 2 → 1
for (Node n = head; n != null; n = n.next) System.out.print(n.value + " ");
⇅

Stacks and queues

LIFO · FIFO · push/pop · offer/poll

A stack works last in, first out (LIFO) and a queue first in, first out (FIFO); in both the basic operations take O(1). DFS works with a stack (or the recursion's call stack) and BFS with a queue; backtracking undoes choices in stack order.

Why it matters

Iterative DFS uses an explicit stack; BFS and Edmonds-Karp use a queue.

Needed inChapter 4.1 · Stack-Based DFS TraceChapter 4.1 · BFS: IdeaChapter 4.4 · Augmenting Path with BFS (Java)

Self-check

1, 2, 3 are added in this order to a queue and to a stack. Which element leaves each first?

1 leaves the queue first and 3 leaves the stack first.

Example (Java) 
Deque<Character> stack = new ArrayDeque<>();
for (char c : "abc".toCharArray()) stack.push(c);
StringBuilder sb = new StringBuilder();
while (!stack.isEmpty()) sb.append(stack.pop());
System.out.println(sb);                     // cba
▲

Heaps and priority queues

complete binary tree · array layout · O(log n)

In a min-heap every node is smaller than its children, so the smallest element is at the root. Stored as an array, the children of node i are at 2i + 1 and 2i + 2 and its parent at (i − 1) / 2. Insertion and extracting the minimum take O(log n); heapsort, Dijkstra, Prim, Huffman and the running median rely on it.

Why it matters

Heapsort, the complexity of Dijkstra, building the Huffman tree and the running median rely on heaps.

Needed inChapter 2 · Heap SortChapter 4.2 · Dijkstra: ComplexityChapter 12 · Huffman: StepsChapter 9 · Running Median

Self-check

Building a heap by inserting n elements one by one takes O(n log n). How long does bottom-up heap construction take?

O(n); most nodes are close to the leaves, so the total sift-down work stays linear.

Example 
array:  [2, 5, 3, 9, 6, 4]
index:   0  1  2  3  4  5
children of 2: 5 and 3   (index 1, 2)
children of 5: 9 and 6   (index 3, 4)
child of 3:    4         (index 5)

Hash tables

hash function · collision · O(1) on average

A hash table turns a key into an array index with a hash function and inserts and searches in O(1) on average. When two keys land in the same cell, the collision is resolved by chaining or linear probing; performance drops as the load factor grows. Memoization, “visited” sets and the hash comparison of Rabin-Karp rely on this idea.

Why it matters

Search with hashing, Rabin-Karp and memoization all use hash tables.

Needed inChapter 3 · Hash Search: IdeaChapter 3 · Load FactorChapter 5 · Rabin-Karp

Self-check

What is the worst-case search time in a hash table, and when does it happen?

O(n), when all keys fall into the same cell (the same chain).

Example (Java) 
int m = 7;
int[] keys = {10, 17, 24};
for (int k : keys) System.out.print(k % m + " ");   // 3 3 3 → collision
Set<String> visited = new HashSet<>();
visited.add("A");
System.out.println(visited.contains("A"));          // true
T

Trees and binary search trees

root · parent · child · leaf · height

A tree with n nodes has n − 1 edges, and there is exactly one path between any two nodes. The terms root, parent, child, leaf, depth and height are used unchanged for DFS/BFS trees, MSTs, union-find, tries and state-space trees. A binary search tree keeps smaller keys in the left subtree and larger keys in the right; if the tree is balanced, search takes O(log n).

Why it matters

The BFS tree, spanning trees, tries and state-space trees are described with the same terms.

Needed inChapter 4.1 · BFS Tree & Shortest PathsChapter 4.3 · Spanning Trees & MSTChapter 5 · Basic ComponentsChapter 13 · State-Space Tree

Self-check

At most how many nodes can a binary tree of height h have?

2^(h+1) − 1 (taking the height of a single node as 0).

Example 
        8            height 2; leaves 1, 6, 14
      /   \
     3     10        parent of 3 is 8, its children are 1 and 6
    / \      \
   1   6      14     inorder traversal: 1 3 6 8 10 14

Graph representations

G = (V, E) · adjacency list · adjacency matrix

A graph consists of vertices and edges; edges may be directed or undirected, weighted or unweighted. An adjacency matrix uses V² memory and answers an edge query in O(1); an adjacency list uses O(V + E) memory and makes traversal of sparse graphs O(V + E). You should recognize the terms degree, path, cycle, connectivity and bipartiteness.

Why it matters

All graph chapters and the TSP examples in branch and bound assume a graph representation.

Needed inChapter 4.1 · Storing a Graph in MemoryChapter 4.1 · Types of GraphsChapter 4.2 · Graphs & Shortest Paths

Self-check

Which representation suits a road network with 10,000 vertices and 30,000 edges?

An adjacency list: a matrix needs 10⁸ cells, while the list needs about V + 2E = 70,000 entries for an undirected graph.

Example (Java) 
int V = 4;
List<List<Integer>> adj = new ArrayList<>();
for (int i = 0; i < V; i++) adj.add(new ArrayList<>());
int[][] edges = {{0, 1}, {0, 2}, {2, 3}};
for (int[] e : edges) {                    // undirected: add both directions
    adj.get(e[0]).add(e[1]);
    adj.get(e[1]).add(e[0]);
}
System.out.println(adj.get(0));            // [1, 2]

Discrete mathematics & proof

The language used to define algorithms and prove them correct.

∈

Sets, functions and relations

∪ ∩ \ · |A| · f: A → B · relation

Algorithms are described in the language of sets: G = (V, E), the set of visited vertices, the cut (S, V − S) in MSTs, the subset of items chosen in a knapsack. You should know union, intersection, difference, Cartesian product and subsets; the domain and codomain of a function; and the reflexive, symmetric and transitive properties of relations.

Why it matters

The cut property, the transitive closure of Floyd-Warshall and the feasible solutions of branch and bound are defined with sets.

Needed inChapter 4.3 · Cut & Cycle PropertiesChapter 4.2 · Floyd-Warshall AlgorithmChapter 14 · Basic Concepts

Self-check

How many subsets does a set of n elements have, and which brute-force method costs that much?

2ⁿ; trying every choice in subset sum or 0/1 knapsack.

Example 
A = {1, 2, 3},  B = {2, 3, 4}
A ∪ B = {1, 2, 3, 4}    A ∩ B = {2, 3}    A \ B = {1}
|A × B| = 3 · 3 = 9     number of subsets of A: 2³ = 8
"is reachable from" is reflexive and transitive; in an undirected graph it is also symmetric.
∀

Logic and quantifiers

∧ ∨ ¬ ⇒ · ∀ ∃ · De Morgan

Loop conditions, pruning conditions and definitions are logical statements. You should be able to read quantified sentences such as “for all n ≥ n₀, f(n) ≤ c · g(n)”, negate a statement correctly (De Morgan) and tell “p ⇒ q” apart from “q ⇒ p”.

Why it matters

Big-O is defined with quantifiers, and the inner loop of insertion sort stops on a compound condition.

Needed inChapter 1.2 · Definition of Big-OChapter 1.1 · Insertion Sort: Code

Self-check

What is the negation of “every vertex has at least one neighbour”?

“There is at least one vertex with no neighbour.” ∀ and ∃ swap and the inner statement is negated.

Example 
¬(a ∧ b)  ≡  ¬a ∨ ¬b                         (De Morgan)
exit condition of while (i > 0 && A[i] > x):  i <= 0 || A[i] <= x
f(n) = O(g(n))  ⇔  ∃c > 0, ∃n₀, ∀n ≥ n₀ : f(n) ≤ c · g(n)
∴

Proof techniques: direct, contradiction, counterexample

direct proof · proof by contradiction · counterexample

We show that an algorithm is correct on every input with a proof, and that it is wrong with a single counterexample. The correctness of greedy algorithms is usually proved by contradiction or an exchange argument, while the claim “greedy change-making is always optimal” falls to a counterexample.

Why it matters

The correctness of greedy choices, the cut property of MSTs and 2-approximation ratios are established by proof.

Needed inChapter 12 · Coin Change ProblemChapter 12 · Why Earliest Finish?Chapter 7 · Proof of the 2-Approximation

Self-check

Which technique does the proof that √2 is irrational use?

Contradiction: assuming √2 = p/q in lowest terms forces both p and q to be even, contradicting the assumption.

Example 
Claim: greedy change-making gives the fewest coins in every coin system.
Counterexample: coins {1, 3, 4}, amount 6
  greedy:  4 + 1 + 1  → 3 coins
  optimal: 3 + 3      → 2 coins        ⇒ the claim is false.
n+1

Induction and loop invariants

base case · inductive step · initialization–maintenance–termination

Induction proves a statement for every n by showing that P(1) holds and that P(k) ⇒ P(k + 1). A loop invariant is its adaptation to algorithms: a statement that holds before the loop (initialization), is preserved by each iteration (maintenance) and gives the result when the loop ends (termination). The correctness of recursive algorithms is also proved by induction.

Why it matters

The correctness of sorting algorithms and the solutions of recurrences are shown by induction.

Needed inChapter 1.1 · Insertion Sort: ExampleChapter 1.2 · f3: Unrolling the Recurrence

Self-check

Show by induction that 1 + 3 + 5 + … + (2n − 1) = n².

For n = 1: 1 = 1². If it holds for k, the sum for k + 1 is k² + (2k + 1) = (k + 1)².

Example 
Insertion sort, invariant: "at the start of iteration j, A[0..j−1] is sorted."
  Initialization: j = 1 → A[0..0] is a single element, sorted.
  Maintenance:    A[j] is shifted into place → A[0..j] is sorted.
  Termination:    j = n → A[0..n−1], the whole array, is sorted.

Tools for analysis

Sums, logarithms and growth intuition for computing running times.

Σ

Summation notation and series

arithmetic · geometric · harmonic

The cost of nested loops and recursion trees is written as a sum. Three series are essential: an arithmetic series grows quadratically; a geometric series with ratio below 1 converges to a constant, and one with ratio above 1 is of the order of its largest term; the harmonic series grows logarithmically.

Why it matters

Loop counting, summing the levels of a recursion tree and the expected number of comparisons of randomized quicksort use these series.

Needed inChapter 1.2 · f2: The SumChapter 1.2 · Loop PatternsChapter 8 · Expected Comparisons

Self-check

How many times does the body of for (i = 1; i < n; i *= 2) for (j = 0; j < i; j++) run?

1 + 2 + 4 + … < 2n times, i.e. Θ(n) (a geometric series).

Example 
Σ (i = 1..n) i       = n(n + 1) / 2          = Θ(n²)
Σ (i = 0..k) 2^i     = 2^(k+1) − 1             (1 + 2 + 4 + … + 2^k)
Σ (i = 0..∞) (1/2)^i = 2
H(n) = Σ (i = 1..n) 1/i ≈ ln n               = Θ(log n)
log

Logarithm and exponent rules

log₂ n · exponent rules · change of base

Every algorithm that halves its input (binary search, merge sort, heaps) produces logarithmic depth: reducing n to 1 takes log₂ n halvings. You should know the exponent and logarithm rules, that the base of a logarithm does not matter asymptotically, and the approximation 2¹⁰ ≈ 10³.

Why it matters

The step count of binary search, the n^(log_b a) term of the master theorem and the n^1.585 exponent of Karatsuba are computed with logarithms.

Needed inChapter 1.1 · O(log n): Binary SearchChapter 3 · How Many Steps?Chapter 1.2 · The Three CasesChapter 11 · Karatsuba Analysis

Self-check

About how many comparisons does binary search make at most on a sorted array of one billion elements?

About 30, because 2³⁰ ≈ 1.07 · 10⁹.

Example 
log2(1,024) = 10       log2(10^6) ≈ 20       log2(10^9) ≈ 30
a^(m+n) = a^m · a^n     (a^m)^n = a^(m·n)     log(x·y) = log x + log y
n^(log_b a) = a^(log_b n)              appears in the master theorem
log_3 n = log_2 n / log_2 3            the base only changes a constant factor
⌊ ⌋

Floor and ceiling

⌊x⌋ · ⌈x⌉ · integer division

When an array is split in two, the halves have ⌊n/2⌋ and ⌈n/2⌉ elements; in Java, n / 2 gives the floor for positive numbers. Floor and ceiling appear in the middle index of binary search, the parent index in a heap, the height of a binary tree and approximation ratios.

Why it matters

The split step of merge sort, the middle index of binary search and the index arithmetic of heaps use floor and ceiling.

Needed inChapter 2 · Merge Sort: RecursionChapter 3 · Binary Search AlgorithmChapter 2 · Heap Sort: Example

Self-check

What is −7 / 2 in Java? What is ⌊−7/2⌋?

Java gives −3 (it truncates toward zero), while ⌊−3.5⌋ = −4. Math.floorDiv gives the floor for negative numbers.

Example 
⌊7/2⌋ = 3      ⌈7/2⌉ = 4      ⌊n/2⌋ + ⌈n/2⌉ = n
height of a heap with n nodes ⌊log2 n⌋:  n = 10 → 3
Java: 7 / 2 == 3,  (7 + 2 − 1) / 2 == 4     for positive a, b: ⌈a/b⌉ = (a + b − 1) / b
O

Intuition for asymptotic growth

1 < log n < n < n log n < n² < 2ⁿ < n!

For large n the dominant term decides: 3n² + 100n + 7 = Θ(n²). You should be able to order the growth classes and, assuming roughly 10⁸–10⁹ simple operations per second, estimate which complexity is feasible for which n. O is an upper bound, Ω a lower bound and Θ a tight bound.

Why it matters

Every chapter compares algorithms by their complexity, and growth classes decide which method fits a given input size.

Needed inChapter 1.1 · Growth RatesChapter 1.2 · Asymptotic RulesChapter 1.2 · Common Growth Classes

Self-check

Which grows faster eventually, n¹⁰⁰ or 1.01ⁿ?

1.01ⁿ; every exponential with base greater than 1 eventually overtakes every polynomial.

Example 
approximate operation counts for n = 10^6
  n log2 n ≈ 2 · 10^7     → under a second
  n²       = 10^12        → hours
  2^n      : even n = 60 gives ≈ 10^18 → infeasible
T(n)

Intuition for recurrences

T(n) = aT(n/b) + f(n) · recursion tree

The running time of a recursive algorithm is written in terms of itself: merge sort solves two halves and merges in linear time, so T(n) = 2T(n/2) + n. Familiarity with solving a recurrence by unrolling it, or by summing the work on each level of a recursion tree, makes the master theorem much easier to follow.

Why it matters

Recurrences are solved with the master theorem, and every divide-and-conquer algorithm is analysed with a recurrence.

Needed inChapter 1.2 · Recurrence RelationsChapter 1.2 · f4: Recursion TreeChapter 11 · Recursion Tree

Self-check

What is the recurrence of binary search and its solution?

T(n) = T(n/2) + O(1), whose solution is Θ(log n).

Example 
T(n) = 2T(n/2) + n
  level 0:  n                    = n
  level 1:  n/2 + n/2            = n
  level 2:  4 · n/4              = n
  … log2 n levels                ⇒ T(n) = Θ(n log n)
T(n) = T(n − 1) + 1  ⇒ Θ(n)        T(n) = 2T(n − 1) + 1  ⇒ Θ(2^n)

Probability & counting

For measuring search spaces and the behaviour of randomized algorithms.

n!

Combinatorics: permutations and combinations

product rule · n! · C(n, k) · 2ⁿ

The cost of brute force, backtracking and branch and bound is the size of the search space; counting it requires the product rule, n! permutations, C(n, k) combinations and the 2ⁿ subsets. For example, n-city TSP has (n − 1)! tours once the starting city is fixed.

Why it matters

Generating permutations, the brute-force solution of TSP and the size of the N-queens search tree are found by counting.

Needed inChapter 1.1 · O(n!): PermutationsChapter 7 · Comparison with Brute ForceChapter 13 · Brute Force & Pruning

Self-check

In how many ways can 8 queens be placed on an 8 × 8 board with one queen per row? And if the columns must also differ?

8⁸ = 16,777,216 ways; with distinct columns 8! = 40,320 ways.

Example 
P(n, k) = n! / (n − k)!          C(n, k) = n! / (k! · (n − k)!)
C(5, 2) = 10       5! = 120        2^10 = 1,024
n = 10 cities: 9! = 362,880 tours      n = 20 cities: 19! ≈ 1.2 · 10^17 tours
P

Probability basics

sample space · independence · conditional probability

Computing the success and error probabilities of randomized algorithms requires sample spaces, events, complements, independent events and conditional probability. A key pattern: if one trial fails with probability p, all of k independent trials fail with probability p^k; this is how the error of Monte Carlo algorithms is reduced.

Why it matters

The error analysis of Miller–Rabin and Karger's algorithm uses exactly this pattern.

Needed inChapter 8 · Probability RefresherChapter 8 · Reducing the Error ProbabilityChapter 8 · Karger's Minimum Cut

Self-check

An algorithm finds the right answer with probability 1/2 in one run. What is the probability that at least one of 10 independent runs finds it?

1 − (1/2)¹⁰ = 1023/1024 ≈ 0.999.

Example 
P(A ∪ B) = P(A) + P(B) − P(A ∩ B)
A and B independent  ⇔  P(A ∩ B) = P(A) · P(B)
Miller–Rabin: error ≤ 1/4 per round  ⇒  ≤ (1/4)^20 ≈ 9 · 10^−13 after 20 rounds
E

Expected value and linearity of expectation

random variable · E[X] · indicator variable

Results such as the expected O(n log n) running time of randomized quicksort are stated as expected values. Linearity of expectation, E[X + Y] = E[X] + E[Y], holds even when the variables are dependent; splitting a complicated count into a sum of 0/1 indicator variables and adding their probabilities is a standard technique.

Why it matters

The analyses of randomized quicksort, QuickSelect and randomized paging are carried out with expected values.

Needed inChapter 8 · Expected ComparisonsChapter 8 · Quicksort AnalysisChapter 9 · Randomized Paging

Self-check

Randomized quicksort has worst case O(n²). Why is it called “expected O(n log n)”?

Because the pivot is random, the running time is a random variable; for every input its mean is O(n log n), and O(n²) occurs only with very small probability.

Example 
Die: E[X] = (1 + 2 + … + 6) / 6 = 3.5
Number X of elements left in place by a random permutation of n elements:
  X = X1 + … + Xn,  Xi = 1 (if element i stays),  P(Xi = 1) = 1/n
  E[X] = n · (1/n) = 1
Repeating a trial with success probability p until the first success: E[number of trials] = 1/p

M

Matrix operations

row–column product · identity matrix · block form

The straightforward product of two n × n matrices performs n³ multiplications in three nested loops; Strassen reduces this with block matrices. For adjacency matrices, the distance table of Floyd-Warshall and the matrix–vector product in power iteration you should know the row–column product, the identity matrix and splitting a matrix into blocks.

Why it matters

Matrix multiplication is the O(n³) example of complexity analysis, the subject of Strassen's algorithm and the core step of power iteration.

Needed inChapter 1.1 · O(n³): Matrix MultiplicationChapter 11 · Matrix MultiplicationChapter 7 · Power IterationChapter 4.2 · Floyd-Warshall: Steps

Self-check

What is [[1, 2], [3, 4]] · [[0, 1], [1, 0]]?

[[2, 1], [4, 3]]; multiplying on the right by this permutation matrix swaps the columns.

Example (Java) 
static int[][] multiply(int[][] a, int[][] b) {
    int n = a.length;
    int[][] c = new int[n][n];
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            for (int k = 0; k < n; k++)
                c[i][j] += a[i][k] * b[k][j];    // n³ multiplications in total
    return c;
}

int[][] c = multiply(new int[][] {{1, 2}, {3, 4}}, new int[][] {{0, 1}, {1, 0}});
System.out.println(Arrays.deepToString(c));      // [[2, 1], [4, 3]]
mod

Modular arithmetic and GCD

a mod m · (a · b) mod m · gcd · prime

Hash functions, the rolling hash of Rabin-Karp, pseudo-random number generators and the Miller–Rabin test work with modular arithmetic. You should know that taking the remainder at every step of additions and multiplications does not change the result, how to compute the GCD with Euclid's algorithm, and the definition of a prime.

Why it matters

Euclid's algorithm, the rolling hash, Miller–Rabin and pseudo-random numbers use modular arithmetic.

Needed inChapter 1.1 · Euclid's AlgorithmChapter 5 · Rabin-Karp: How It WorksChapter 8 · Miller–Rabin: Code

Self-check

Compute (17 · 23) mod 5 by reducing before multiplying.

17 mod 5 = 2 and 23 mod 5 = 3; 2 · 3 = 6 and 6 mod 5 = 1.

Example (Java) 
static int gcd(int a, int b) {
    return b == 0 ? a : gcd(b, a % b);
}

System.out.println(gcd(48, 18));                          // 6
long M = 1_000_000_007L, h = 0;
for (char c : "abc".toCharArray()) h = (h * 31 + c) % M;  // basis of a rolling hash
System.out.println(h);                                     // 96354
01

Binary numbers and bit operations

& | ^ ~ << >> · powers of 2 · subset masks

Computers store numbers in binary; powers of 2, shifts and masks shorten many algorithms. The bits of an integer can represent a subset; 1 << k gives 2^k and x & (x − 1) clears the lowest set bit. The O(1) safety test in N-queens and iterating over all subsets for small n are done with bit masks.

Why it matters

Radix sort works digit by digit, and the N-queens solution uses bit masks.

Needed inChapter 13 · O(1) Safety TestChapter 5 · Radix Sort

Self-check

What is 13 in binary? What are 13 >> 1 and 13 & 1?

1101₂; 13 >> 1 = 6 (110₂) and 13 & 1 = 1 (the number is odd).

Example (Java) 
int n = 3;
for (int mask = 0; mask < (1 << n); mask++) {           // 2³ = 8 subsets
    StringBuilder s = new StringBuilder("[");
    for (int i = 0; i < n; i++)
        if ((mask & (1 << i)) != 0) s.append(i);
    System.out.print(s.append("] "));
}
// [] [0] [1] [01] [2] [02] [12] [012]
System.out.println((16 & (16 - 1)) == 0);              // true: 16 is a power of 2
opt

Decision and optimization problems

objective function · constraint · feasible solution · lower/upper bound

Greedy, dynamic programming, approximation and branch-and-bound algorithms solve optimization problems: among the solutions that satisfy the constraints (feasible solutions) we look for one that maximizes or minimizes the objective function. The decision version of the same problem (“is there a solution of value at least K?”) is used in the discussion of P, NP and NP-completeness. In a maximization problem the value of every feasible solution is a lower bound on the optimum.

Why it matters

The knapsack problem, NP-hardness, approximation ratios and the bounds of branch and bound are all stated in this language.

Needed inChapter 6 · 0/1 Knapsack ProblemChapter 7 · P, NP & NP-HardChapter 14 · Choosing a Bound

Self-check

In a maximization problem a greedy algorithm finds a feasible solution of value 40, and the fractional relaxation has value 46. In which range is the optimum?

40 ≤ OPT ≤ 46: the feasible solution gives a lower bound and the relaxation an upper bound.

Example 
0/1 knapsack, capacity W = 5
  items (weight, value): 1 = (2, 3), 2 = (3, 4), 3 = (4, 5)
  feasible: {1, 2} → weight 5, value 7       infeasible: {2, 3} → weight 7
  optimization: what is the largest value?             → 7
  decision: is there a feasible choice of value ≥ 8?   → no

Self-check

If 20% of a program stays sequential, what is the largest speedup possible with unlimited processors?

1 / 0.2 = 5 times (Amdahl's law).

Example (Java) 
final AtomicInteger counter = new AtomicInteger();
Runnable job = () -> { for (int i = 0; i < 100_000; i++) counter.incrementAndGet(); };
Thread t1 = new Thread(job), t2 = new Thread(job);
t1.start(); t2.start();
t1.join(); t2.join();
System.out.println(counter.get());   // always 200000; an unprotected int++ may give less
