Java temelleri: tipler, koşullar, döngüler

int · long · double · if · for · while

Sunumlardaki kodlar Java ile yazılmıştır; bir döngünün kaç kez döndüğünü ve hangi değişkenin nasıl değiştiğini kâğıt üzerinde izleyebilmelisiniz. int türünün yaklaşık ±2,1 milyarlık sınırı ve tam sayı bölmesi (7 / 2 = 3) sık hata kaynağıdır.

Neden gerekli?

Her bölümdeki kod izleme slaytları bu yapıları kullanır; ikili aramadaki taşma hatası da tam sayı sınırından kaynaklanır.

Kendini sına: int a = 7, b = 2; double d = a / b; ifadesinden sonra d kaçtır?

3.0. Bölme tam sayılarla yapılır (3), sonra double'a çevrilir. 3.5 için (double) a / b yazılmalıdır.

Örnek (Java)

    if (i % 2 == 0) toplam += i;     // çift sayıları topla

Diziler ve iki boyutlu diziler

0 tabanlı indis · length · int[][]

Sıralama, arama ve dinamik programlama tablolarının hepsi dizi üzerinde çalışır. İndislerin 0'dan length − 1'e gittiğini, dizinin metoda referans olarak geçtiğini ve iki boyutlu dizinin satır satır gezildiğini bilmelisiniz.

Neden gerekli?

Sıralama algoritmaları dizide yerinde çalışır; DP bölümünde tablolar iki boyutlu dizidir; komşuluk matrisi de iki boyutlu bir dizidir.

Bölüm 2 · Kabarcık: KodBölüm 6 · Tablo Doldurma İzlemeBölüm 4.1 · Çizgeyi Bellekte Tutmak
Kendini sına: int[] a = {3, 1, 2}; tanımından sonra a[3] okunursa ne olur?

ArrayIndexOutOfBoundsException fırlatılır; geçerli indisler 0, 1 ve 2'dir.

Örnek (Java) 
int[] a = new int[5];              // [0, 0, 0, 0, 0]
a[a.length - 1] = 9;               // son öğe
int[][] dp = new int[3][4];        // 3 satır, 4 sütun
for (int i = 0; i < dp.length; i++)
    for (int j = 0; j < dp[i].length; j++)
        dp[i][j] = i + j;
System.out.println(dp[2][3]);      // 5

Metotlar ve parametre geçişi

dönüş değeri · değerle geçiş · dizi referansı

Algoritmalar genellikle bir metot olarak yazılır: girdi parametre, sonuç dönüş değeridir. Java her şeyi değerle geçirir; ancak dizi ve nesnelerde kopyalanan şey referanstır, bu yüzden metot içindeki takas çağıranın dizisini değiştirir.

Neden gerekli?

Sıralama algoritmalarının hepsi takas ya da kaydırma yapan yardımcı metotlar kullanır; parçalama metodu pivotun son konumunu döndürür.

Bölüm 2 · Kabarcık: KodBölüm 2 · Parçalama Prosedürü
Kendini sına: Bir metodun içinde a = new int[10]; yazmak, çağıranın dizisini değiştirir mi?

Hayır. Yalnızca metodun yerel referansı yeni diziye bağlanır; çağıran eski diziyi görmeye devam eder.

Örnek (Java) 
static void takas(int[] a, int i, int j) {
    int t = a[i]; a[i] = a[j]; a[j] = t;     // çağıranın dizisi değişir
}
static void artir(int x) { x++; }            // çağıranın değişkeni değişmez

int[] d = {5, 7};
takas(d, 0, 1);              // d = [7, 5]
int y = 1;
artir(y);                    // y hâlâ 1
System.out.println(d[0] + " " + y);   // 7 1

Özyineleme ve çağrı yığını

taban durum · özyinelemeli çağrı · derinlik

Birleştirme sıralaması, hızlı sıralama, DFS, geri izleme ve böl ve fethet algoritmaları özyinelemelidir. Her çağrının kendi yerel değişkenleriyle çağrı yığınına eklendiğini, taban durum yoksa StackOverflowError alınacağını ve özyineleme derinliğinin bir bellek maliyeti olduğunu bilmelisiniz.

Neden gerekli?

Bölüm 1'de hızlı üs alma ve birleştirme sıralaması, Bölüm 4.1'de özyinelemeli DFS, Bölüm 13'te geri izleme şablonu doğrudan özyinelemeyle yazılır.

Bölüm 1.1 · Bir Sayının Üssünü AlmaBölüm 4.1 · Özyinelemeli DFS: Sözde KodBölüm 13 · Genel Şablon
Kendini sına: us(2, 10) çağrısı, ilk çağrı dahil kaç kez us metodunu çalıştırır?

5 kez: n = 10, 5, 2, 1, 0.

Örnek (Java) 
static int us(int a, int n) {             // a üzeri n, n >= 0
    if (n == 0) return 1;                    // taban durum
    int yarim = us(a, n / 2);                // problem yarıya iner
    return (n % 2 == 0) ? yarim * yarim : yarim * yarim * a;
}

System.out.println(us(2, 10));            // 1024; derinlik yaklaşık log2(n)
OOP

Sınıflar, nesneler ve karşılaştırıcılar

class · Comparable · Comparator · generic türler

Kenar, düğüm, iş ya da eşya gibi kavramlar küçük sınıflarla temsil edilir. Sıralama ve öncelikli kuyruk, öğeleri karşılaştırabilmek için compareTo metodu ya da bir Comparator ister: Kruskal'da kenarları ağırlığa, etkinlik seçiminde etkinlikleri bitiş zamanına göre sıralarız.

Neden gerekli?

Açgözlü algoritmaların çoğu bir sıralamayla başlar; Dijkstra ve Prim öncelikli kuyruğa karşılaştırılabilir nesneler koyar.

Bölüm 4.3 · Kruskal: Adımlar ve Sözde KodBölüm 12 · Etkinlik Seçimi Problemi
Kendini sına: compareTo içinde return w - o.w; yazmak neden risklidir?

Büyük pozitif ve negatif değerlerde çıkarma int sınırını aşıp işareti bozabilir; Integer.compare taşmaz.

Örnek (Java) 
static class Kenar implements Comparable<Kenar> {
    final int u, v, w;
    Kenar(int u, int v, int w) { this.u = u; this.v = v; this.w = w; }
    public int compareTo(Kenar o) { return Integer.compare(w, o.w); }
}

List<Kenar> kenarlar = new ArrayList<>();
kenarlar.add(new Kenar(0, 1, 7));
kenarlar.add(new Kenar(1, 2, 3));
Collections.sort(kenarlar);                           // ağırlığa göre artan
kenarlar.sort((a, b) -> Integer.compare(b.w, a.w));   // azalan: Comparator
System.out.println(kenarlar.get(0).w);                // 7

Java koleksiyonları

ArrayList · HashMap · ArrayDeque · PriorityQueue

Sunumlardaki Java kodları hazır yapıları sık kullanır: komşuluk listesi için ArrayList, BFS kuyruğu ve DFS yığını için ArrayDeque, Dijkstra ve Prim için PriorityQueue, bellekleme için HashMap. Her birinin temel işleminin maliyetini bilmek, algoritmanın toplam süresini doğru hesaplamanın ön koşuludur.

Neden gerekli?

BFS kuyrukla, Dijkstra öncelikli kuyrukla, bellekleme bir sözlükle (map) yazılır.

Bölüm 4.1 · BFS: Sözde KodBölüm 4.2 · Dijkstra: Java İzlemeBölüm 6 · Bellekleme İzleme
Kendini sına: PriorityQueue'da add ve poll işlemleri ne kadar sürer? contains(x) ve remove(x) ne kadar sürer?

add ve poll O(log n) sürer; contains(x) ve remove(x) iç diziyi taradığı için O(n) sürer.

Örnek (Java) 
Deque<Integer> kuyruk = new ArrayDeque<>();
kuyruk.offer(1); kuyruk.offer(2);
int ilk = kuyruk.poll();                          // 1 (ilk giren ilk çıkar)

PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> Integer.compare(x[1], y[1]));
pq.add(new int[] {7, 40});
pq.add(new int[] {3, 15});
int[] enKucuk = pq.poll();                        // [3, 15]

Map<Integer, Long> bellek = new HashMap<>();
bellek.put(10, 55L);
System.out.println(ilk + " " + enKucuk[0] + " " + bellek.get(10));   // 1 3 55

Sözde kod okuma ve izleme

← atama · 1 tabanlı indis · izleme tablosu

Sunumlar ve kaynak kitaplar algoritmaları çoğunlukla sözde kodla verir: ← atamadır, diziler 1'den başlayabilir ve “for j ← 2 to n” son değeri de içerir. Kodu Java'ya çevirirken bu farkları gözetmeli ve her adımdaki değişken değerlerini bir izleme tablosuna yazabilmelisiniz.

Neden gerekli?

Çizge, akış ve dal sınır algoritmaları önce sözde kodla, sonra Java ile verilir.

Bölüm 1.1 · Eklemeli Sıralama: KodBölüm 4.2 · Dijkstra: Sözde KodBölüm 4.4 · Sözde Kod
Kendini sına: Yukarıdaki sözde kod 0 tabanlı Java'ya çevrilirken döngüler nasıl yazılır?

Dış döngü for (int j = 1; j < n; j++) olur; iç döngünün koşulu i >= 0 && A[i] > anahtar olur.

Örnek 
EKLEMELİ-SIRALA(A, n)
  for j ← 2 to n
      anahtar ← A[j]
      i ← j − 1
      while i > 0 and A[i] > anahtar
          A[i + 1] ← A[i]
          i ← i − 1
      A[i + 1] ← anahtar

sınır durumları · assert · küçük girdiyle deneme

Doğru bir fikir bile dikkatli uygulanmalı ve sınanmalıdır. Boş girdi, tek öğe, tekrarlı değerler, sıralı ve ters sıralı diziler, bağlı olmayan çizgeler ve taşmaya yatkın büyük değerlerle deneme yapmayı alışkanlık hâline getirmelisiniz.

Örnek (Java)

Bağlı liste

düğüm · next · O(1) başa ekleme

Bir dizi gibi sıralı veri tutar, ancak öğeler bellekte ardışık değildir; her düğüm bir sonrakini gösterir. Başa ekleme O(1), i. öğeye erişim O(n) sürer. Komşuluk listeleri, hash tablosunda zincirleme ve LRU önbelleğinin O(1) uygulaması bağlı listeye dayanır.

Neden gerekli?

Zincirleme ile hash tablosu ve LRU önbelleğinin O(1) uygulaması bağlı liste kullanır.

Bölüm 3 · Zincirleme ile EklemeBölüm 9 · LRU: O(1) Uygulama
Kendini sına: Tek yönlü bağlı listede son öğeyi silmek neden O(n) sürer?

Sondan bir önceki düğümün next alanını null yapmak gerekir; o düğüme ulaşmak için baştan yürümek zorundayız.

Örnek (Java) 
static class Dugum {
    int deger; Dugum next;
    Dugum(int deger, Dugum next) { this.deger = deger; this.next = next; }
}

Dugum bas = null;
for (int x = 1; x <= 3; x++) bas = new Dugum(x, bas);    // 3 → 2 → 1
for (Dugum d = bas; d != null; d = d.next) System.out.print(d.deger + " ");

Yığın ve kuyruk

LIFO · FIFO · push/pop · offer/poll

Yığın son giren ilk çıkar (LIFO), kuyruk ilk giren ilk çıkar (FIFO) ilkesiyle çalışır; ikisinde de temel işlemler O(1) sürer. DFS bir yığınla (ya da özyinelemenin çağrı yığınıyla), BFS bir kuyrukla çalışır; geri izleme de seçimleri yığın düzeninde geri alır.

Neden gerekli?

Yinelemeli DFS açık bir yığın, BFS ve Edmonds-Karp bir kuyruk kullanır.

Bölüm 4.1 · Yığınla DFS İzlemeBölüm 4.1 · BFS: FikirBölüm 4.4 · BFS ile Artış Yolu (Java)
Kendini sına: 1, 2, 3 sırasıyla eklenen bir kuyruktan ve bir yığından ilk çıkan öğeler hangileridir?

Kuyruktan 1, yığından 3 çıkar.

Örnek (Java) 
Deque<Character> yigin = new ArrayDeque<>();
for (char c : "abc".toCharArray()) yigin.push(c);
StringBuilder sb = new StringBuilder();

Heap ve öncelikli kuyruk

tam ikili ağaç · dizi gösterimi · O(log n)

Min-heap'te her düğüm çocuklarından küçüktür, bu yüzden en küçük öğe kökte durur. Dizi olarak saklandığında i. düğümün çocukları 2i + 1 ve 2i + 2, ebeveyni (i − 1) / 2 konumundadır. Ekleme ve en küçüğü çıkarma O(log n) sürer; heap sort, Dijkstra, Prim, Huffman ve çevrimiçi ortanca buna dayanır.

Neden gerekli?

Heap sort, Dijkstra'nın karmaşıklığı, Huffman ağacının kurulması ve çevrimiçi ortanca heap'e dayanır.

Bölüm 2 · Heap SortBölüm 4.2 · Dijkstra: KarmaşıklıkBölüm 12 · Huffman: AdımlarBölüm 9 · Çevrimiçi Ortanca
Kendini sına: n öğeyi tek tek ekleyerek heap kurmak O(n log n) sürer. Aşağıdan yukarı heap kurma ne kadar sürer?

O(n); düğümlerin çoğu yaprağa yakın olduğundan toplam aşağı kaydırma işi doğrusal kalır.

Örnek

3'ün çocuğu:     4        (indis 5)

Hash tablosu

hash fonksiyonu · çakışma · ortalama O(1)

Anahtarı bir hash fonksiyonuyla dizi indisine çevirip ortalama O(1) sürede ekleme ve arama yapar. İki anahtar aynı hücreye düşerse çakışma zincirleme ya da doğrusal yoklamayla çözülür; yük faktörü büyüdükçe performans düşer. Bellekleme, “ziyaret edildi” kümeleri ve Rabin-Karp'ın hash karşılaştırması bu fikre dayanır.

Neden gerekli?

Bölüm 3 hash ile aramayı ayrıntılı işler; Rabin-Karp ve bellekleme de hash kullanır.

Bölüm 3 · Hash ile Arama: FikirBölüm 3 · Yük FaktörüBölüm 5 · Rabin-Karp
Kendini sına: Hash tablosunda arama en kötü durumda ne kadar sürer ve bu ne zaman olur?

O(n); tüm anahtarlar aynı hücreye (aynı zincire) düştüğünde.

Örnek (Java) 
int m = 7;
int[] anahtarlar = {10, 17, 24};
for (int k : anahtarlar) System.out.print(k % m + " ");   // 3 3 3 → çakışma
Set<String> ziyaret = new HashSet<>();
ziyaret.add("A");
System.out.println(ziyaret.contains("A"));                // true

Ağaçlar ve ikili arama ağacı

kök · ebeveyn · çocuk · yaprak · yükseklik

n düğümlü bir ağaçta n − 1 kenar vardır ve iki düğüm arasında tek bir yol bulunur. Kök, ebeveyn, çocuk, yaprak, derinlik ve yükseklik terimleri DFS/BFS ağaçlarında, MST'de, union-find'da, trie'de ve durum uzayı ağaçlarında aynen kullanılır. İkili arama ağacında sol alt ağaç küçük, sağ alt ağaç büyük anahtarları tutar; ağaç dengeli ise arama O(log n) sürer.

Neden gerekli?

Çizge gösterimleri

G = (V, E) · komşuluk listesi · komşuluk matrisi

Çizge düğümler ve kenarlardan oluşur; kenarlar yönlü ya da yönsüz, ağırlıklı ya da ağırlıksız olabilir. Komşuluk matrisi V² bellek kullanır ve kenar sorgusu O(1) sürer; komşuluk listesi O(V + E) bellek kullanır ve seyrek çizgelerde gezinmeyi O(V + E) yapar. Derece, yol, döngü, bağlılık ve iki parçalılık terimlerini tanımalısınız.

Neden gerekli?

Bölüm 4'ün tüm alt bölümleri ve dal sınırdaki TSP örnekleri çizge gösterimini varsayar.

Bölüm 4.1 · Çizgeyi Bellekte TutmakBölüm 4.1 · Çizge TürleriBölüm 4.2 · Çizge ve En Kısa Yol
Kendini sına: 10 000 düğümlü ve 30 000 kenarlı bir yol ağı için hangi gösterim uygundur?

Komşuluk listesi: matris 10⁸ hücre ister, liste yönsüz çizgede yaklaşık V + 2E = 70 000 kayıtla yetinir.

Örnek (Java) 
int V = 4;
List<List<Integer>> komsu = new ArrayList<>();
for (int i = 0; i < V; i++) komsu.add(new ArrayList<>());
int[][] kenarlar = {{0, 1}, {0, 2}, {2, 3}};
for (int[] e : kenarlar) {                 // yönsüz: iki yöne de ekle
    komsu.get(e[0]).add(e[1]);
    komsu.get(e[1]).add(e[0]);
}
System.out.println(komsu.get(0));          // [1, 2]

Mantık ve niceleyiciler

Tümevarım ve döngü değişmezi

taban adım · tümevarım adımı · başlangıç–koruma–sonlanma

Tümevarım, P(1)'in doğru olduğunu ve P(k) ⇒ P(k + 1) olduğunu göstererek her n için ispat yapar. Döngü değişmezi bunun algoritmalara uyarlanmış hâlidir: döngüden önce doğru olan (başlangıç), her turda korunan (koruma) ve döngü bitince sonucu veren (sonlanma) bir önerme. Neden gerekli?

Sıralama algoritmalarının doğruluğu ve özyineleme bağıntılarının çözümü tümevarımla gösterilir.

Kendini sına: 1 + 3 + 5 + … + (2n − 1) = n² olduğunu tümevarımla gösterin.

n = 1 için 1 = 1². k için doğruysa, k + 1 için toplam k² + (2k + 1) = (k + 1)² olur.

Örnek 
Eklemeli sıralama, değişmez: "j. turun başında A[0..j−1] sıralıdır."

  Koruma:    A[j] doğru yere kaydırılır → A[0..j] sıralı olur.
  Sonlanma:  j = n → A[0..n−1], yani dizinin tamamı sıralıdır.

Kendini sına: Rastgele hızlı sıralamanın en kötü durumu O(n²) iken neden “beklenen O(n log n)” denir?

Pivot rastgele seçildiği için süre bir rastgele değişkendir; her girdi için bu değişkenin ortalaması O(n log n)'dir, O(n²) ise yalnızca çok küçük bir olasılıkla görülür.

Örnek

Kendini sına: [[1, 2], [3, 4]] · [[0, 1], [1, 0]] çarpımı nedir?

[[2, 1], [4, 3]]; sağdan bu permütasyon matrisiyle çarpmak sütunların yerini değiştirir.

Örnek (Java) 
static int[][] carp(int[][] a, int[][] b) {
    int n = a.length;
    int[][] c = new int[n][n];
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            for (int k = 0; k < n; k++)
                c[i][j] += a[i][k] * b[k][j];    // toplam n³ çarpma
    return c;
}

int[][] c = carp(new int[][] {{1, 2}, {3, 4}}, new int[][] {{0, 1}, {1, 0}});
System.out.println(Arrays.deepToString(c));      // [[2, 1], [4, 3]]

İkili sayılar ve bit işlemleri

Kendini sına: 13 sayısının ikili gösterimi nedir? 13 >> 1 ve 13 & 1 kaçtır?

1101₂; 13 >> 1 = 6 (110₂) ve 13 & 1 = 1 (sayı tektir).

Örnek (Java) 
int n = 3;
for (int maske = 0; maske < (1 << n); maske++) {        // 2³ = 8 alt küme
    StringBuilder s = new StringBuilder("[");
    for (int i = 0; i < n; i++)
        if ((maske & (1 << i)) != 0) s.append(i);
    System.out.print(s.append("] "));
}
// [] [0] [1] [01] [2] [02] [12] [012]
System.out.println((16 & (16 - 1)) == 0);              // true: 16 ikinin kuvveti

İş parçacığının ne olduğunu, iki iş parçacığı aynı değişkeni korumasız güncellerse yarış durumu oluşacağını ve programın sıralı kalan kısmının hızlanmayı sınırladığını önceden sezmeniz yeterlidir.

Kendini sına: Bir programın %20'si sıralı kalıyorsa sınırsız sayıda işlemciyle en çok kaç kat hızlanabilir?

1 / 0,2 = 5 kat (Amdahl yasası).

Örnek (Java) 
final AtomicInteger sayac = new AtomicInteger();
Runnable is = () -> { for (int i = 0; i < 100_000; i++) sayac.incrementAndGet(); };
Thread t1 = new Thread(is), t2 = new Thread(is);
t1.start(); t2.start();
t1.join(); t2.join();
System.out.println(sayac.get());   // her zaman 200000; korumasız int++ ile daha az çıkabilir

Aramaya ya da süzgece uyan konu yok.
