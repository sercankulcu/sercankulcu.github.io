Chapter 8: Network Flow

A city's water network, a country's highway system, and the links of a data center all ask the same question: how much can be sent from one point to another without exceeding the carrying limits of the links? On graphs this question is written as the maximum flow problem. The chapter first defines flow networks, the constraints a flow must satisfy, and the value of a flow. It then builds the concepts that all the algorithms share: the residual network, the augmenting path, and the cut. The max-flow min-cut theorem proves why a flow that has been found is optimal. The Ford-Fulkerson method, Edmonds-Karp, Dinic's algorithm, and the push–relabel algorithm are then run step by step on the same example networks. The code of each is traced line by line, and the source of its running-time bound is shown. The chapter closes with a comparison of the algorithms and applications such as bipartite matching.

8.1Flow networks

The questions asked about graphs so far have mostly concerned paths: is there a path between two vertices, which path is shortest, which tree connects all vertices most cheaply? Network flow asks something different. Finding one path is not enough; many paths are used at once, and they share edges. Every edge has a carrying limit. The question is how much all the paths can carry together.

This question comes up often in everyday life. Water in a pipeline, traffic on a road network, and data packets in a computer network are all flows. Each pipe carries at most its own capacity. Water does not accumulate at junctions: whatever enters a junction also leaves it. These two observations become the two basic constraints of the flow network model.

8.1.1The maximum flow problem

The model is a directed graph with two special vertices. The vertex the flow leaves is called the source, and the vertex it arrives at is the sink. The source is written s and the sink t. Every edge has a capacity: the largest amount that can pass through that edge per unit time.

Definition 8.1

A flow network consists of a directed graph G = (V, E), two distinct vertices s, t ∈ V, and a function that assigns each edge (u, v) a nonnegative capacity c(u, v) ≥ 0. For a pair (u, v) that is not in the graph, c(u, v) = 0 is assumed. The maximum flow problem is to find the largest amount of flow that can be sent from the source to the sink without exceeding the capacities.

The same small network is used for much of the chapter. Figure 8.1 shows it. There are six vertices and seven edges; the edge labels are capacities. The source is S and the sink is T.

That the maximum flow is 7 must be seen from two sides. First, 7 units can be sent; a flow that shows this will be given shortly. Second, more than 7 cannot be sent. This second claim is clear at once from the source. The capacities of the two edges leaving S sum to 4 + 3 = 7. Every unit leaving the source has to use one of these two edges. Hence no more than 7 can reach the sink. This simple observation is the first example of the cut concept that comes later.

The same reasoning can be made at the sink. The capacities of the edges entering T sum to 2 + 6 = 8. This is also an upper bound, but it is looser than 7. The smaller of the two bounds is the valid one. An upper bound that is always correct is this: the maximum flow cannot exceed the sum of the capacities leaving the source or the sum of the capacities entering the sink. This bound is not always tight; the bottleneck can also lie in the middle of the network.

8.1.2Flows and their constraints

A flow assigns each edge the amount passing through it. For this assignment to make sense, two rules must hold.

Definition 8.2

A flow is a function that assigns each edge (u, v) a number f(u, v) and satisfies the following two constraints:

  • Capacity constraint: for every edge, 0 ≤ f(u, v) ≤ c(u, v).
  • Flow conservation: for every vertex v other than s and t, Σu f(u, v) = Σw f(v, w); that is, the flow in equals the flow out.

The value of a flow is |f| = Σv f(s, v) − Σv f(v, s): the net flow leaving the source.

The capacity constraint expresses the carrying limit of a pipe. A flow cannot be negative; a pipe does not run backward. Nor can it exceed the capacity. The conservation constraint says that intermediate vertices are not storage tanks. Every unit that enters an intermediate vertex must leave it somewhere. The source and the sink are exempt from this rule: the source produces flow and the sink consumes it.

The subtraction term in the definition of the value may seem unnecessary at first. In our example network no edge enters the source, so this term is zero. In a general network, however, there may be edges returning to the source. If 5 units leave the source and 1 unit returns, 4 units have actually been sent into the network. This is why the value is the net flow leaving the source. Thanks to conservation, this net flow equals the net flow entering the sink: since no intermediate vertex accumulates flow, everything leaving the source eventually arrives at the sink.

Let us check that the flow in Figure 8.2 is valid.

In this flow some edges are filled to their limit. An edge with f(u, v) = c(u, v) is called a saturated edge; no more flow can be sent through it. In the flow shown, S→A, S→C, A→B, and B→T are saturated. That both edges leaving the source are saturated explains why the flow cannot be increased. Saturated edges are part of the cuts that explain why the maximum flow cannot be larger.

Common mistake

Thinking that the value of a flow is the sum of the flows on all edges. In the flow shown, the edge flows sum to 4 + 3 + 4 + 2 + 2 + 5 + 5 = 25, but the value of the flow is 7. The same unit of flow passes through many edges along its path and is counted again on each. The value is read only from the edges at the source (or the sink).

8.1.3Multiple sources and sinks

Real problems rarely have a single source and a single sink. Several factories ship goods to several warehouses; several servers stream data to several groups of users. The way to solve this without a separate algorithm is a small graph transformation.

Two new vertices are added to the network: a supersource S and a supersink T. For each old source si an edge S → si is added, and for each old sink tj an edge tj → T. These edges are given unlimited (∞) capacity. The new edges therefore never become a bottleneck; the flow is limited only by the edges of the old network. In the new network the maximum flow from S to T equals the total flow that can be sent from all the sources to all the sinks in the old network. In practice, any number larger than the sum of all capacities of the old network can stand in for ∞.

The transformation can be adapted to other restrictions. For example, if factory s1 can produce at most 50 units, the edge S → s1 is given capacity 50 instead of ∞. The same idea is used in problems where vertices also have capacities: a vertex is split into two parts, and an edge with the vertex's capacity is placed between the two parts. This method will be taken up again under applications.

8.2The residual network and augmenting paths

The first way to find a maximum flow that comes to mind is a greedy method. Find a path from the source to the sink through edges that are not full, send as much flow along it as it can carry, and keep doing this until no path is left. This method sometimes gives the correct result and sometimes does not. The problem is that early decisions cannot be undone. A badly chosen path can fill edges in a way that other paths could have used better. The solution is to build the possibility of undoing flow already sent into the model. The structure that does this is the residual network.

8.2.1The residual network

Definition 8.3

Under a flow f, the residual capacity of an edge is defined in two ways. For every edge (u, v) of the original network:

  • Forward edge: cf(u, v) = c(u, v) − f(u, v). This is the amount that can still be sent through the edge.
  • Reverse edge: cf(v, u) = f(u, v). This is the amount of the flow already sent that can be undone.

The residual network Gf consists only of the edges with cf > 0.

The residual network shows the changes that can still be made under the current flow. A forward edge says “I can send more in this direction.” A reverse edge says “I can take back part of what I sent in this direction.” Figure 8.4 shows this on a single edge. The edge u → v of capacity 5 carries 3 units of flow. In the residual network this edge turns into two edges: the forward edge u → v for the remaining 2 units and the reverse edge v → u for the 3 units that can be undone.

The two extreme cases are instructive too. If the flow is zero, the capacity of the reverse edge is zero and the reverse edge does not enter the residual network; the residual network is identical to the original network. If the edge is saturated, the capacity of the forward edge is zero and only the reverse edge remains in the residual network. Each original edge produces at most two edges in the residual network. The number of edges of the residual network is therefore at most 2E.

Example 8.2

Let us build the residual network of the flow in Figure 8.2. Two numbers are computed for each edge: the forward residual capacity c − f and the reverse residual capacity f.

8.2.2What a reverse edge means

A reverse edge is not a physical pipe. There need not be a real connection in the direction v → u. A reverse edge is a bookkeeping entry: it shows that flow previously sent from u to v can be cancelled. “Sending” δ units along a reverse edge means reducing f(u, v) by δ.

Why does this cancellation help? If an augmenting path uses the reverse edge v → u, the path replaces the old flow arriving at v from u with its own. The old flow from u to v is now freed, and along the rest of the path it goes from u in another direction. In effect the flow is rearranged: some units abandon their old routes and switch to new ones. Conservation continues to hold at every vertex. Thanks to reverse edges the algorithm can correct its first wrong choices. A concrete example of this correction appears in the second Ford-Fulkerson example.

Common mistake

Interpreting a reverse edge as a real edge added to the network, or as “sending flow backward.” Flow does not increase in the direction of the reverse edge; the flow on the forward edge decreases: f(u, v) −= δ. For this reason no edge has negative flow in the final flow, and reverse edges add no capacity to the original network.

8.2.3Augmenting paths and bottlenecks

Definition 8.4

An augmenting path is a directed path from the source to the sink in the residual network Gf. The bottleneck of the path is the smallest residual capacity among its edges: cf(p) = min { cf(u, v) : (u, v) ∈ p }.

Every edge on an augmenting path has positive residual capacity. That is, the path passes either through forward edges that carry less than their capacity or through the reverse directions of edges that carry flow. The most flow that can be sent along the path is the capacity of its narrowest edge. This is the flow counterpart of the saying that a chain is only as strong as its weakest link.

If the flow is initially zero everywhere, the residual network is identical to the original network and an augmenting path is an ordinary directed path. Augmenting paths are usually found with depth-first search (DFS) or breadth-first search (BFS). Which search is used does not change the value of the resulting flow, but it changes greatly how many steps the algorithm takes. This difference is the starting point of the Edmonds-Karp algorithm.

8.2.4Augmenting the flow along a path

Once an augmenting path p and its bottleneck δ = cf(p) have been found, the flow is updated as follows. For every edge (u, v) on the path:

  • If (u, v) is an edge of the original network (a forward edge), f(u, v) is increased by δ.
  • If (u, v) is a reverse edge, that is, the original edge is (v, u), then f(v, u) is decreased by δ.
Theorem 8.1 (Augmentation)

Let f be a flow, p an augmenting path in the residual network, and δ = cf(p). The f' obtained by the update above is again a flow, and |f'| = |f| + δ.

Capacity. On a forward edge the new flow is f(u, v) + δ ≤ f(u, v) + cf(u, v) = c(u, v). On a reverse edge the new flow is f(v, u) − δ ≥ f(v, u) − cf(u, v) = 0. In both cases the flow stays in the interval [0, c].

Conservation. Consider an intermediate vertex v on the path. The path enters v along one edge and leaves along one edge. If the incoming edge is a forward edge, the flow into v increases by δ; if it is a reverse edge, the flow out of v decreases by δ. In either case the “in minus out” difference of v changes by +δ. By a similar argument for the outgoing edge, the difference changes by −δ. The total change is zero; conservation is not broken.

Value. Since the path is simple, it uses the source only once, on its first edge. This edge leaves the source. If it is a forward edge, the flow leaving the source increases by δ; if it is a reverse edge, the flow entering the source decreases by δ. In both cases the net outflow increases by δ. □

This theorem is the foundation of all augmenting-path algorithms. With every augmentation the value of the flow strictly increases and the flow remains valid. Two questions remain. When no augmenting path is left, is the flow really maximum? How many augmentations are needed? The first question is answered with cuts. The answer to the second depends on how the path is chosen.

The update has two more important consequences. The residual capacity of the bottleneck edge is exactly δ; after the update this residual capacity drops to zero. So with every augmentation at least one edge on the path leaves the residual network. Also, for every edge on the path, δ units of residual capacity appear in the opposite direction. The residual network thus changes a little with each augmentation: some edges disappear and some reverse edges appear.

8.3Cuts

To prove that a flow is maximum, we must show that no larger flow exists. Trying all flows one by one is impossible. The cut concept instead gives an upper bound as a single number. The edges between the side containing the source and the side containing the sink are like a “border gate” that the flow must pass through. The width of the gate limits the flow that can pass.

8.3.1The s–t cut and its capacity

Definition 8.5

An s–t cut (S, T) is a partition of the vertex set V into two disjoint sets with s ∈ S and t ∈ T. The capacity of the cut is the sum of the capacities of the edges going from S to T:

c(S, T) = Σu ∈ S, v ∈ T c(u, v)

A cut of smallest capacity is called a minimum cut.

In the definition a cut is a partition of the vertices, not a set of edges. The cut edges come out of this partition: the edges with one endpoint in S and the other in T. If these edges are deleted from the network, no directed path from the source to the sink remains. In computing the capacity, only the edges going from S to T are counted. Edges going from T to S are not added to the capacity, because they are not what prevents the flow from reaching the sink.

In the cut of Figure 8.6 the edge B→C also crosses the dashed line, but it goes from the T side to the T side; both of its endpoints are in T. For this reason it is not counted. Similarly, both endpoints of the edge S→A are on the S side.

Example 8.3

The example network has four intermediate vertices: A, B, C, D. Each can be placed on the S side or the T side, so there are 24 = 16 s–t cuts in all. Let us compute a few.

  • S = {S}: the cut edges are S→A and S→C; 4 + 3 = 7.
  • S = {S, A, B}: the cut edges are S→C (3), B→C (3), B→T (2); total 8.
  • S = {S, C}: S→A (4) and C→D (6); total 10. The edge B→C goes from T to S and is not counted.

Common mistake

Taking the minimum cut to be the partition that cuts the fewest edges. A minimum cut minimizes the capacity sum, not the number of edges. Cutting a single edge of capacity 100 is more expensive than cutting three edges of capacity 1. The number of edges measures the same thing as the capacity only when all capacities are 1.

8.3.2Net flow across a cut

The net flow across a cut is found by subtracting the total flow on the edges going from T to S from the total flow on the edges going from S to T:

f(S, T) = Σu ∈ S, v ∈ T f(u, v) − Σu ∈ S, v ∈ T f(v, u)

Unlike capacity, net flow also counts the edges in the backward direction, because flow that comes back must be subtracted from the flow that crosses over.

Theorem 8.2 (Cuts and flows)

For every flow f and every s–t cut (S, T), f(S, T) = |f|. Hence |f| ≤ c(S, T).

For every vertex in S, write the “out minus in” difference and add up these differences. For the source the difference is |f| by definition. The other vertices of S are intermediate vertices (the sink is in T); by conservation their differences are zero. So the total is |f|.

The same sum can also be computed edge by edge. An edge with both endpoints in S appears once in the outflow of one vertex and once in the inflow of another; their contributions cancel. Only the edges crossing the cut remain. Those going from S to T appear with a plus sign in the total, and those going from T to S with a minus sign. This is exactly f(S, T). Therefore f(S, T) = |f|.

For the inequality, use f(u, v) ≤ c(u, v) on forward edges and f(v, u) ≥ 0 on reverse edges: |f| = f(S, T) ≤ Σ c(u, v) − 0 = c(S, T). □

What the theorem says agrees with intuition. All the flow leaving the source must cross the cut somewhere to reach the sink. If some flow comes back, it too has to cross forward at least one more time. In the end the net amount crossing the cut equals the amount sent into the network. Let us test the flow of Figure 8.2 on the cut {S, A}: the forward edges are A→B (4) and S→C (3), there is no reverse edge; the net flow is 7. On the cut {S, C} the forward edges are S→A (4) and C→D (5), and the reverse edge is B→C (2); the net flow is 4 + 5 − 2 = 7. The two cuts differ, but the net flow is the same.

The second half of the theorem says that every cut is an upper bound for every flow. The value of any flow cannot exceed the capacity of any cut. Hence the maximum flow cannot exceed the capacity of the minimum cut. This is an inequality. The real surprise is that the inequality is always an equality.

8.3.3The max-flow min-cut theorem

Theorem 8.3 (Max-flow min-cut)

For a flow f the following three statements are equivalent (Ford and Fulkerson, 1956):

  1. f is a maximum flow.
  2. The residual network Gf has no augmenting path.
  3. For some cut (S, T), |f| = c(S, T).

Consequently, the value of the maximum flow equals the capacity of the minimum cut.

(1) ⇒ (2). If there were an augmenting path in the residual network, then by Theorem 8.1 the flow could be increased by the bottleneck. This contradicts the maximality of f.

(2) ⇒ (3). Let S be the set of vertices reachable from the source in the residual network, and T = V − S. The source is in S. Since there is no augmenting path, the sink is not in S; (S, T) is an s–t cut. For an edge (u, v) with u ∈ S and v ∈ T we must have f(u, v) = c(u, v); otherwise cf(u, v) > 0 and v would also be reachable. For the same reason, on an edge (v, u) going from T to S we must have f(v, u) = 0; otherwise the reverse edge u → v would be in the residual network. By Theorem 8.2, |f| = f(S, T) = Σ c(u, v) − 0 = c(S, T).

(3) ⇒ (1). No flow can exceed the capacity of any cut. If |f| = c(S, T), then no flow can be larger than c(S, T), and therefore than |f|. □

The theorem has three separate uses. First, it proves the correctness of augmenting-path algorithms: it is safe to stop when no path is left. Second, it gives an easily checked certificate that a flow is maximum. A flow whose value equals the capacity of some cut is maximum without any other computation. Third, it shows how to find a minimum cut: the vertices reachable from the source in the final residual network form the S side.

The flow found in our example network has value 7, and the capacity of the cut {S} is also 7. The third statement of the theorem holds; the flow is maximum. In the residual network built in Example 8.2 no vertex other than S could be reached from the source. The reachable set is only {S}, and this is exactly the cut in the proof.

8.3.4Finding the minimum cut

The proof of the theorem is also an algorithm. After a maximum flow has been found, a search is run from the source in the final residual network. The visited vertices form the S side. The original edges with one endpoint visited and the other not are the edges of the minimum cut. The following Java method does this. It uses the res matrix holding the residual capacities and a copy of the original capacities.

List<int[]> minCut(int src, int[][] capacity) {
  boolean[] visited = new boolean[V];
  Queue<Integer> queue = new LinkedList<>();
  queue.add(src);
  visited[src] = true;
  while (!queue.isEmpty()) {          // BFS in the final residual network
    int u = queue.poll();
    for (int v = 0; v < V; v++)
      if (!visited[v] && res[u][v] > 0) {
        visited[v] = true;
        queue.add(v);
      }
  }
  List<int[]> cut = new ArrayList<>();
  for (int u = 0; u < V; u++)          // original edges from S to T
    for (int v = 0; v < V; v++)
      if (visited[u] && !visited[v] && capacity[u][v] > 0)
        cut.add(new int[]{u, v});
  return cut;
}

The first half of the method is an ordinary BFS. The only difference is that the existence of an edge is tested with res[u][v] > 0: the search moves only through the residual network. The second half scans all pairs of vertices and adds to the list those pairs with visited[u] true and visited[v] false that have an edge in the original network. The capacity condition matters. Reverse edges occupy space in the residual matrix but do not exist in the original network; they cannot be cut edges.

With an adjacency matrix the BFS takes O(V²) and the pair scan takes O(V²). The total time is O(V²), which is negligible next to the cost of finding the maximum flow. The extra memory is O(V + k) for the visited array, the queue, and the result list, where k is the number of edges in the cut. When the method is later run on the final residual network of the second Ford-Fulkerson example, it returns the edges S→1 (10) and 3→4 (9). The total, 19, equals the maximum flow in that network.

8.3.5Overview of network flow algorithms

8.4The Ford-Fulkerson method

8.4.1The idea of the method

The Ford-Fulkerson method rests on the work published by L. R. Ford Jr. and D. R. Fulkerson in 1956. It finds the maximum flow between two vertices in a directed graph with capacities. The idea is a natural consequence of the concepts built so far: the flow starts at zero, and as long as an augmenting path is found in the residual network, the flow is increased along that path by the bottleneck. When no path is left, the loop stops; the max-flow min-cut theorem guarantees that the result is optimal.

Most sources call Ford-Fulkerson a method rather than an “algorithm.” The reason is that it does not specify how the augmenting path is to be found. Any path is accepted. The version that searches for the path with DFS is usually known as Ford-Fulkerson; the version that uses BFS has a name of its own: Edmonds-Karp. That the choice of path affects the running time but not the result will be clear in the comparison of these two versions.

8.4.2The steps of the algorithm

  1. Initialization. f(u, v) = 0 on all edges. Since the flow is zero, the residual capacity of every edge is its own capacity; the residual network is identical to the original network.
  2. Path search. An augmenting path p is searched for in the residual network from the source to the sink. Only edges with cf > 0 are used.
  3. Bottleneck. δ = min cf(u, v), (u, v) ∈ p is computed. This is the most flow that can be sent along the path.
  4. Augmentation. δ units of flow are sent along the path: on forward edges f(u, v) += δ, on reverse edges f(v, u) −= δ; |f| += δ. At least one edge on the path becomes saturated.
  5. Repeat. Steps 2–4 are repeated until no augmenting path is left. When the loop ends, |f| is maximum.

In an implementation the flow and the residual capacity need not be stored separately. Only the residual capacities can be kept. When flow is added, the residual capacity of the forward edge decreases by δ and that of the reverse edge increases by δ. The flow on an edge is recomputed when needed as f(u, v) = c(u, v) − cf(u, v). The Java code on the slides follows this route.

8.4.4Example 2: using a reverse edge

In the first example no augmenting path used a reverse edge. To see why reverse edges are necessary, a somewhat larger network is needed. In the network of Figure 8.10 the source is S and the sink is T; the intermediate vertices are numbered 1 to 4.

This time the order of the paths is deliberately bad: the first path makes a decision that must be corrected later.

  1. p = S → 1 → 4 → T: residual capacities 10, 8, 10; the bottleneck is 1 → 4 (8). |f| = 8.
  2. p = S → 3 → 4 → T: only 10 − 8 = 2 units are left on 4 → T. The bottleneck is 2; |f| = 10. 4 → T becomes saturated.
  3. p = S → 3 → 4 → 1 → 2 → T: 3 → 4 has 9 − 2 = 7, the reverse edge 4 → 1 has 8 (the flow sent to 1 → 4 in the first step), 1 → 2 has 4, and 2 → T has 10 units. The bottleneck is 4; |f| = 14.
  4. p = S → 1 → 4 → 2 → T: 2 units were left on S → 1. On 1 → 4 there is now room for 8 − 4 = 4 units. The bottleneck is 2; |f| = 16.
  5. p = S → 3 → 4 → 2 → T: the bottleneck is 3 → 4 (9 − 6 = 3 left). |f| = 19.

The third step is the heart of the example. When the reverse edge 4 → 1 is used, the flow on 1 → 4 drops from 8 to 4. What this means is the following: the 4 units that previously went from 1 to 4 now arrive at 4 from 3. The 4 units freed up at 1 head for the sink along 1 → 2. Conservation is not broken at any vertex. The total flow into 4 and the total flow out of 1 do not change; only their routes change.

In the final residual network S → 1 is saturated; 1 unit is left on S → 3, but the only edge leaving 3, 3 → 4, is saturated. The set reachable from the source is {S, 3}. The original edges leaving this set are S → 1 and 3 → 4; both are full. The edge 1 → 3 goes from the T side to the S side and carries no flow. This is a perfect example of the conditions in the proof: forward edges full, reverse edges empty.

8.4.5Why are reverse edges necessary?

Consider a greedy method that never uses reverse edges in the same network. This method searches only for paths through forward edges that are not full.

Example 8.4

Let the first choice again be S → 1 → 4 → T, and send 8 units. Then:

  • S → 3 → 4 → T: 2 units (4 → T becomes saturated). Total 10.
  • S → 1 → 2 → T: 2 units, since 2 units are left on S → 1. Total 12.
  • S → 3 → 4 → 2 → T: there are 7 units on 3 → 4, 6 on 4 → 2, and 8 on 2 → T; 6 units. Total 18.

Now S → 1 is full. From S one can go only to 3, and from there to 4. Both exits of 4 (4 → 2 and 4 → T) are full. The method gets stuck and stops at 18. Yet the maximum flow is 19.

The loss is a single unit, but the principle matters. The first path loaded 8 units onto the edge 1 → 4. Part of this flow should actually have gone through 1 → 2, which would have freed room on the edge 3 → 4. A method that works with forward edges only cannot undo this decision. In the residual network with reverse edges, however, the edge 4 → 1 makes it possible to undo part of this decision: the flow coming from 1 is redirected to 2, and the flow coming from 3 to 4. The result is 19, equal to the minimum cut. There is a general rule here: in the residual network with reverse edges, the method reaches the maximum whatever order the paths are chosen in.

Common mistake

Forgetting reverse edges. Searching with forward edges only is a greedy algorithm and may miss the maximum (18 < 19 in the example). In code the reverse edges are often a single line: res[v][u] += flow. If this line is deleted, the program still runs and returns a number; the problem is noticed only when the result is verified.

8.4.6Pseudocode

The pseudocode of the method is below. Here the flow values are kept in a separate flow table, and the residual capacity is computed when needed as capacity − flow.

FORD_FULKERSON(G, source, sink):
  flow[u, v] = 0, for each (u, v) in E     // 0 at the start
  maxFlow = 0
  while an augmenting path exists:
    path = DFS(G, source, sink, flow)            // edges with c − flow > 0
    delta = ∞                                    // smallest residual capacity on the path
    v = sink
    while v ≠ source:
      u = path.parent[v]
      delta = min(delta, capacity[u, v] − flow[u, v])
      v = u
    v = sink                                     // update the flows on the path
    while v ≠ source:
      u = path.parent[v]
      flow[u, v] += delta
      flow[v, u] −= delta                        // reverse edge
      v = u
    maxFlow += delta
  return maxFlow, flow

The outer loop runs as long as an augmenting path is found. The DFS call searches for a path through edges of positive residual capacity and reports the path through a parent array (parent[] in the code) that stores the predecessor of each vertex. The path itself is not stored as a list; it is read back from the sink to the source by following parent.

The first inner loop finds the bottleneck. v starts at the sink; at each step u = path.parent[v], the vertex from which v was reached. delta is limited by the smallest residual capacity seen so far. The loop ends when it reaches the source. The second inner loop walks the same path once more and updates the flow: delta is added in the forward direction and subtracted in the backward direction. The subtraction in the backward direction follows from keeping the flow in a skew-symmetric table: flow[v, u] = −flow[u, v]. In this representation the residual capacity of the reverse edge is capacity[v, u] − flow[v, u] = 0 − (−flow[u, v]) = flow[u, v], the same value as in the definition.

This skew-symmetric representation simplifies the code. There is no need for a separate “is it a reverse edge?” question; forward and reverse edges are handled by the same formula. There is one subtlety: if there are original edges in both directions between two vertices (for example both 1 → 2 and 2 → 1), the flows of the two edges can cancel in the same cell. In the matrix representation this causes no problem, because only the net flow matters.

8.4.7Java: an augmenting path with DFS

The Java implementation on the slides keeps the residual capacities in the matrix res[u][v]. At the start this matrix is filled with the capacities; the residual capacity of reverse edges is zero. The DFS that finds the augmenting path is as follows:

boolean dfs(int u, int sink,
            boolean[] visited, int[] parent) {
  visited[u] = true;
  if (u == sink) return true;
  for (int v = 0; v < V; v++) {
    if (!visited[v] && res[u][v] > 0) {
      parent[v] = u;
      if (dfs(v, sink, visited, parent))
        return true;
    }
  }
  return false;   // no path to the sink from this branch
}

The method takes four parameters: the current vertex u, the sink, the visited marks, and the parent array that records the path. The first line marks u as visited. This way the same vertex is not entered again and the search does not fall into a cycle. If u is the sink, a path has been found and true is returned.

The loop tries all vertices in order; in an adjacency matrix, “neighbor” means a v with res[u][v] > 0. When an unvisited neighbor with positive residual capacity is found, parent[v] = u is written and the search continues from v. If the recursive call returns true, this true is passed up at once; the rest of the loop is not tried. If all neighbors are tried and the sink cannot be reached, the method returns false: there is no path to the sink from this branch.

The visited marks are not cleared on return. This is important. If there is no path to the sink from a vertex, reaching that vertex by another route does not change the outcome; trying it again is wasted work. This way each vertex is visited at most once. With an adjacency matrix each visit scans V cells; one DFS takes O(V²). With an adjacency list the same search takes O(V + E).

When flow is added, res[u][v] −= d and res[v][u] += d are performed. The reverse edge is not created separately; the second line brings it into existence by itself. On the next call the DFS sees this cell as positive and uses the reverse edge like an ordinary edge. This assignment is the only place where the code “knows” about reverse edges.

8.4.9Complexity and integrality

The running time of Ford-Fulkerson depends on the structure of the network and on the capacities. Each round has two parts. Finding an augmenting path (DFS or BFS) and updating the flow take O(E); an adjacency list is assumed. The real question is the number of rounds.

Theorem 8.4 (Integrality)

If all capacities are integers, then at every step of the Ford-Fulkerson method the flow and the residual capacities are integers. The method makes at most |f*| augmentations and finishes in O(E · |f*|) time. The maximum flow found has an integer value.

By induction: at the start the flow is zero and the residual capacities equal the capacities; all are integers. If the residual capacities are integers, the bottleneck is also an integer and is at least 1. The update adds integers to or subtracts them from integers, so integrality is preserved. Every augmentation raises the value of the flow by at least 1, and the value cannot exceed |f*|. So at most |f*| augmentations are made, each taking O(E). □

The integrality property has an important application. In problems such as matching, each edge is either used or not; half an edge is meaningless. If the capacities are set to 1, the theorem guarantees that the maximum flow is 0 or 1 on every edge. The flow can then be read directly as a selection.

The bound has a flaw: O(E · |f*|) is not polynomial. The running time of an algorithm is measured by the length of the input, that is, the number of bits needed to write it. A capacity of 109 is written with about 30 bits, but |f*| can be as large as the number itself. Bounds of this kind are called pseudo-polynomial. If the capacities are small integers there is no problem. With large capacities, however, the method can slow down badly if it chooses paths poorly.

If capacities may be irrational numbers, the situation is even worse. In known examples, with badly chosen paths the augmentations become smaller and smaller and the method never terminates; the flow value does not even converge to the maximum flow. Since computers store capacities with finite precision, this does not occur in practice. But it should be kept in mind as the price of the method's “any path” freedom.

8.4.10A bad choice of paths

In the network of Figure 8.15 the maximum flow is 2000: each of the paths s → a → t and s → b → t carries 1000 units. Two augmentations suffice. Now consider a bad choice of paths. Let the first path be s → a → b → t. Because of the middle edge the bottleneck is 1. This augmentation creates the reverse edge b → a. Let the second path be s → b → a → t; because of the reverse edge the bottleneck is again 1, and a → b becomes empty again. If these two paths continue to be chosen in turn, every augmentation adds only 1 unit. Reaching the maximum takes 2000 augmentations.

If the capacities were 109, the same choice would require 2 · 109 augmentations. Yet the network has only four vertices and five edges. DFS does not always make this bad choice. For example, a DFS that tries neighbors in index order finishes in 4 augmentations on this network: first s → a → b → t (1), then s → a → t (999), s → b → a → t (1), and s → b → t (999). But no rule prevents DFS from making the bad choice. For this reason the time bound remains O(E · |f*|).

Edmonds-Karp, the version that works with BFS, chooses shortest paths. In this network the shortest paths have two edges: s → a → t and s → b → t. Each carries 1000 units; 2 augmentations suffice. The three-edge path through the middle is never chosen. How BFS removes the dependence on the size of the capacities is the subject of the next section.

Common mistake

Thinking that Ford-Fulkerson runs in polynomial time. O(E · |f*|) depends on the values of the capacities; in a network of the same structure, the time can grow as the capacities grow. Edmonds-Karp and Dinic remove this dependence.

8.5The Edmonds-Karp algorithm

8.5.1The idea: the shortest augmenting path

The Edmonds-Karp algorithm is a variant of the Ford-Fulkerson method. Jack Edmonds and Richard Karp published it in 1972; Dinic reached the same idea independently in 1970. The algorithm fixes the method's one free decision: the augmenting path is found by breadth-first search. Because BFS advances from the source layer by layer, the first path by which it reaches the sink is the one with the fewest edges. In every round Edmonds-Karp chooses this shortest augmenting path.

Here “short” means the number of edges, not capacity or weight. The capacities of the edges do not affect the length of a path. This choice may look arbitrary at first. But the root of the trouble in the bad-path example was that a long, narrow path was chosen again and again. Choosing the shortest paths prevents such vicious circles. The steps of the algorithm are as follows:

  1. Use BFS to find the shortest augmenting path from the source to the sink in the residual network.
  2. Send the bottleneck amount of flow along the path and update the reverse edges.
  3. Repeat these two steps until BFS cannot reach the sink.

It is useful to note from the start that BFS has two different uses in network flow. Edmonds-Karp uses BFS directly to find an augmenting path, and after each BFS it processes a single path. Dinic's algorithm, by contrast, uses BFS to tell whether the sink is still reachable and to build a level graph; in that graph it processes many paths at once.

8.5.2Complexity: O(V · E²)

Each round consists of one BFS and one path update: O(E). The real contribution of Edmonds-Karp is that the number of augmentations has a bound independent of the capacities. The justification of this bound rests on two observations.

Let d(v) denote the number of edges on the shortest path from the source to a vertex v in the residual network. First observation: as Edmonds-Karp runs, the value d(v) of no vertex decreases. An augmentation removes some edges on the path from the residual network and adds some reverse edges. Each added reverse edge is the reverse of an edge (u, v) on a shortest path; that is, it goes from v to u in a pair with d(v) = d(u) + 1. Such an edge moves a vertex one step farther away and cannot shorten any path.

Second observation: The edge that determines the bottleneck in an augmentation is called a critical edge; it leaves the residual network after the augmentation. In every augmentation at least one edge is critical. When an edge (u, v) is critical, d(v) = d(u) + 1. For the same edge to return to the residual network, an augmenting path must use its reverse edge (v, u). At that moment d'(u) = d'(v) + 1. Since distances do not decrease, d'(u) = d'(v) + 1 ≥ d(v) + 1 = d(u) + 2. So the distance of u grows by at least 2 between two times the edge is critical.

Theorem 8.5 (Edmonds-Karp)

The Edmonds-Karp algorithm makes at most O(V · E) augmentations and finishes in O(V · E²) time. The time does not depend on the values of the capacities.

Each time an edge becomes critical, the distance of the vertex at its tail grows by at least 2. The distance starts at 0 and can be at most V − 1 for a reachable vertex; if the vertex becomes unreachable, the edge is never used again. So an edge becomes critical at most about V/2 times. The residual network has at most 2E edges. Since at least one edge is critical in every augmentation, the number of augmentations is O(V · E). Since each augmentation takes O(E), the total time is O(V · E) · O(E) = O(V · E²). □

The meaning of the bound is clear in the worst-case network. Whether the capacities are 1000 or 109, Edmonds-Karp finishes in 2 augmentations. The time no longer depends on |f*|; the algorithm runs in polynomial time. The price is a full BFS in every augmentation. The bound is pessimistic: in practice the number of augmentations stays far below V · E. In networks with V = 6 and E = 9 the bound allows about 27 augmentations; in the examples of these notes the number of augmentations is between 3 and 4.

8.5.3Java: an augmenting path with BFS

The only difference between Edmonds-Karp and Ford-Fulkerson is the function that searches for the path; the main loop is the same. The BFS version is as follows:

boolean bfs(int src, int sink, int[] parent) {
  boolean[] visited = new boolean[V];
  Queue<Integer> queue = new LinkedList<>();
  queue.add(src);
  visited[src] = true;
  parent[src] = -1;
  while (!queue.isEmpty()) {
    int u = queue.poll();
    for (int v = 0; v < V; v++)
      if (!visited[v] && res[u][v] > 0) {
        queue.add(v);
        parent[v] = u;
        visited[v] = true;
      }
  }
  return visited[sink];
}

In every call the method creates a new visited array. The queue starts with the source; the source counts as visited and parent[src] = -1 is written. This −1 is a marker that tells, when the path is read back, that the source has been reached. In the loop the vertex u at the head of the queue is removed. Then all v are tried in order. Every v that is unvisited and has res[u][v] > 0 is added to the queue, has its parent recorded as u, and is immediately marked visited.

It matters that the mark is set when the vertex is added to the queue. If the vertex were marked when it leaves the queue, the same vertex could enter the queue from several different parents. The parent value would also change with the last parent to add it, and the BFS tree would be corrupted. Marking early ensures that every vertex enters the queue exactly once and through its parent closest to the source.

The method returns visited[sink]: if the sink was reached, an augmenting path exists. The parent array holds the BFS tree; following it from the sink to the source gives the path with the fewest edges. This code does not stop when it reaches the sink but continues until the queue is empty. The result does not change, because the sink's parent was written when it was first reached; stopping early only saves a little time. With an adjacency matrix one BFS takes O(V²), with an adjacency list O(V + E).

The main loop is as follows:

int edmondsKarp(int s, int t) {
  int maxFlow = 0;
  int[] parent = new int[V];
  while (bfs(s, t, parent)) {
    int flow = Integer.MAX_VALUE;
    for (int v = t; v != s; v = parent[v])
      flow = Math.min(flow, res[parent[v]][v]);
    for (int v = t; v != s; v = parent[v]) {
      int u = parent[v];
      res[u][v] -= flow;  // forward
      res[v][u] += flow;  // reverse
    }
    maxFlow += flow;
  }
  return maxFlow;
}

The condition while (bfs(s, t, parent)) runs a new BFS in every round. The first for loop walks from the sink toward the source. parent[v] is the previous vertex on the path; res[parent[v]][v] is the residual capacity of that edge. flow falls to the smallest of these values. Its initial value is Integer.MAX_VALUE, so the first comparison always takes the value of a real edge. The second loop walks the same path once more: flow is subtracted from the forward residual capacity and added to the reverse residual capacity. At the end of the round maxFlow grows. When BFS cannot reach the sink, the loop ends and the result is returned.

The memory use is O(V²) for the res matrix and O(V) for parent, visited, and the queue. A matrix is wasteful for sparse networks. For large sparse networks an adjacency list is used, with each edge holding a link to its reverse edge; the Java code of Dinic's algorithm uses this representation.

8.5.8Example 3: on the residual network

In the third example the algorithm is followed directly on the residual network. One can see step by step how each augmentation changes the residual network.

At the start the residual network equals the capacities. BFS first finds the two-edge path s → 4 → t. The bottleneck is s → 4 (2); 2 units are pushed. The residual capacity of s → 4 drops to 0, and the reverse edge 4 → s becomes 2. 1 unit is left on 4 → t.

Now there is no two-edge path. BFS finds the three-edge path s → 1 → 2 → t; the bottleneck is 2 → t (3). 3 units are pushed. 1 unit is left on s → 1 and on 1 → 2; 2 → t becomes saturated. In the next BFS the sink cannot be reached from 2. The path s → 1 → 3 → t is found; since 1 unit is left on s → 1, 1 unit is pushed.

The edges leaving the source are saturated; no augmenting path is left. The maximum flow is |f*| = 2 + 3 + 1 = 6: 3 units go along s → 1 → 2 → t, 1 unit along s → 1 → 3 → t, and 2 units along s → 4 → t. The minimum cut is ({s}, the rest), and its capacity is 4 + 2 = 6. In this network the set {s, 1, 2, 3} also gives a cut of capacity 6; once again the minimum cut is not unique.

In this example no path used a reverse edge. Some edges were never filled either: 3 → 2 and 4 → 3 stay empty, and there is 1 unit of spare room on 4 → t. A maximum flow need not fill every edge; the edges of a minimum cut are always full.

8.6Dinic's algorithm

Edmonds-Karp processes a single path after each BFS. Yet the information BFS finds is far richer than a single path: it gives the distance from the source to every vertex. Using these distances, all the shortest paths of the same length can be saturated in a single stage. Yefim Dinitz used this idea in the algorithm he published in 1970; the algorithm is known in the Western literature as Dinic's algorithm.

8.6.1The level graph and the blocking flow

Definition 8.6

A BFS from the source in the residual network gives the level of every vertex v: level(v) is the number of edges on the shortest residual path from the source to v. The level graph is the subgraph of the residual network consisting only of the edges (u, v) that satisfy level(v) = level(u) + 1.

A flow in the level graph that leaves at least one saturated edge on every s–t path is called a blocking flow.

In the level graph every edge goes forward by one level. Edges between vertices of the same level, and edges that go backward, are discarded. Therefore every s–t path in the level graph is one of the shortest s–t paths in the residual network. Moreover the level graph is acyclic: the level increases at every step, so one cannot return to the same vertex.

A blocking flow is not a maximum flow. It only blocks all the paths in the level graph; no s–t path is left in the level graph. But in the whole residual network, longer augmenting paths may remain through edges that do not skip a level and through newly created reverse edges. This is why Dinic works in phases: in each phase it recomputes the levels and finds a new blocking flow.

8.6.2The steps of the algorithm

  1. Initialization. The flow on all edges is 0; the residual network is the same as the original network.
  2. BFS. A BFS from the source determines the level of every vertex. BFS uses only edges with positive residual capacity. If the sink has no level, that is, if the sink cannot be reached, the flow is maximum and the algorithm stops.
  3. DFS. Augmenting paths that go forward by one level at each step are searched for with DFS. Only edges with level(v) = level(u) + 1 are followed. Edges found to be dead ends are not tried again during that phase.
  4. Update. The smallest residual capacity on each path found is added to the total flow; the residual capacities of the edges and their reverse edges are updated. When no path remains, the blocking flow of this phase has been found.
  5. New phase. Return to step 2.

In every phase the distance from the source to the sink grows by at least 1. Since the distance can be at most V − 1, there are at most V − 1 phases. This is the first factor in the algorithm's running-time bound.

Let us run the algorithm on the network of Figure 8.25. This network is the same as that of the second Ford-Fulkerson example; only the names of vertices 2 and 3 are swapped. We therefore know that the maximum flow is 19.

8.6.4Pseudocode

The main loop and the BFS of Dinic's algorithm are below.

DINIC(G, source, sink):
  flow = [ ]       // 0 for every edge
  maxFlow = 0
  while BFS(G, source, sink, flow):
    // level graph built
    while a blocking flow remains:
      delta = DFS(G, source, sink,
                  flow, level, ∞)
      maxFlow += delta
  return maxFlow

BFS(G, source, sink, flow):
  level[v] = −1, for each v
  level[source] = 0
  queue.add(source)
  while queue is not empty:
    u = queue.remove()
    for each (u, v) in G[u]:
      if level[v] < 0 and
           capacity[u,v] − flow[u,v] > 0:
        level[v] = level[u] + 1
        queue.add(v)
  return level[sink] ≥ 0

The outer loop runs as long as BFS reaches the sink; each round is a phase. The inner loop calls DFS again and again until the blocking flow is complete. Each DFS finds a path and returns the flow of that path; when it returns 0 the phase ends. The BFS is very similar to the BFS in Edmonds-Karp. The difference is that the level is recorded instead of the parent. The level of unreached vertices is −1. BFS returns true if the level of the sink is not negative.

DFS(G, u, sink, flow, level, lim):
  if u == sink: return lim
  for each (u, v) in G[u]:
    left = capacity[u,v] − flow[u,v]
    if level[v] == level[u] + 1
         and left > 0:
      delta = DFS(G, v, sink, flow, level,
                  min(lim, left))
      if delta > 0:
        flow[u, v] += delta
        flow[v, u] −= delta   // reverse
        return delta
  return 0

The lim parameter of DFS is the bottleneck of the path from the source to u. It starts at ∞ at the source and shrinks at every edge to min(lim, left). When the sink is reached this value is returned; it is the bottleneck of this path. On the way back each edge increases its flow by delta and the flow of the reverse edge decreases. The level condition (level[v] == level[u] + 1) ensures that the search advances only in the level graph.

8.6.5Java: level-based DFS and the current-arc array

The DFS in the pseudocode tries all edges from the beginning on every call. Even when an edge is known to be a dead end, it is tried again on the next call. This needlessly lengthens the phase. The Java implementation avoids this with a small array:

int dfs(int u, int t, int flow, int[] next) {
  if (u == t) return flow;
  for (; next[u] < adj[u].size(); next[u]++) {
    Edge e = adj[u].get(next[u]);
    if (level[e.to] == level[u] + 1 && e.flow < e.cap) {
      int d = dfs(e.to, t, Math.min(flow, e.cap - e.flow), next);
      if (d > 0) {
        e.flow += d;                           // forward edge
        adj[e.to].get(e.rev).flow -= d;        // reverse edge
        return d;
      }
    }
  }
  return 0;   // no level path left from u to t
}

The edges are kept in adjacency lists. Each Edge object carries the target vertex, the capacity, the flow, and a rev field. rev is the position of the reverse edge in the target vertex's list. So the expression adj[e.to].get(e.rev) reaches the reverse edge in O(1). When an edge is added, two objects are created together: the forward edge with its capacity and the reverse edge with capacity 0.

next[u] is the index of the next edge to try at u; this structure is called the current arc. The for loop starts at next[u], and the counter is incremented directly in this array. If no flow reaches the sink through an edge (d == 0), the loop moves on to the next edge with next[u]++, and this edge is never tried again during that phase. If flow does reach the sink, the method returns without incrementing next[u]. The edge may still have room; the next call starts from the same edge.

The condition e.flow < e.cap says that the residual capacity is positive. For reverse edges the capacity is 0 and the flow is negative: −f. The condition becomes −f < 0, that is, f > 0, and the residual capacity comes out as 0 − (−f) = f. Forward and reverse edges are handled by the same line. At the start of every phase the next array is reset and the levels are recomputed by BFS.

Common mistake

Incrementing next[u] in every case. When flow gets through, the edge may not be saturated; if the counter is incremented, the remaining capacity of the edge goes unused in that phase. The algorithm still gives the correct result, but the blocking flow is left incomplete and the number of phases grows. Conversely, if the counter is never used, dead-end edges are tried again and again and the per-phase bound of O(V · E) is lost.

8.6.7Complexity: O(V² · E)

Theorem 8.6 (Dinic)

Dinic's algorithm makes at most V − 1 phases. With the current-arc array each phase takes O(V · E). The total time is O(V² · E).

Number of phases. At the end of a phase every s–t path in the level graph contains a saturated edge. The new edges in the residual network of the next phase are only reverse edges, and these go back one level in the level graph. An s–t path of the same length as before could consist only of edges of the level graph; all of these paths are blocked. So the distance from the source to the sink strictly increases. Since the distance lies between 1 and V − 1, there are at most V − 1 phases.

Time per phase. BFS takes O(V + E). The work of the DFS runs splits into two parts. Each successful DFS follows a path of at most V − 1 edges and saturates at least one edge on it. A saturated edge is not used again in that phase; so there are at most E successful DFS runs, and their total cost is O(V · E). In unsuccessful attempts the counter advances one step; at most once per edge, O(E) in total. Per phase, O(V · E).

Total: O(V) · O(V · E) = O(V² · E). □

Comparing Dinic's bound with Edmonds-Karp's makes the gain clear. In networks with E ≥ V we have V² · E ≤ V · E²; the gap grows as the network gets denser. For V = 1000 and E = 10,000, the value of V · E² is 1011 and the value of V² · E is 1010.

In special networks the bound is even better. If all capacities are 1, the number of phases is bounded by O(√E) and each phase takes O(E): in total O(E · √E). In unit networks, such as bipartite matching, where at most one unit of flow passes through each vertex, the time drops to O(E · √V). This is the bound of the Hopcroft-Karp algorithm; Hopcroft-Karp is in fact a form of Dinic's algorithm adapted to matching.

In practice Dinic's algorithm is the maximum-flow algorithm most used in competitive programming. Its code is short and it usually runs far below its bound. In most networks the number of phases is far smaller than V; in the example of these notes 2 phases were enough.

8.7Push–relabel

8.7.1The idea: letting water run downhill

All the algorithms so far work globally: at every step they look for a complete path from the source to the sink. The push–relabel algorithm, published by A. Goldberg and R. Tarjan in 1988, takes a completely different route. It does not search for augmenting paths. Each operation concerns a single vertex and its neighbors; the algorithm reaches the maximum flow by repeating these local operations.

It helps to think of the algorithm as a water system. At the start, all the pipes leaving the source are filled to the brim. The water collects at the source's neighbors. Every vertex has a height, and water flows only from a higher vertex to a lower one. A vertex that cannot pass its accumulated water to any neighbor is raised; this is called a relabel. Passing water to a neighbor is called a push. Excess water that cannot reach the sink returns to the source once its height exceeds the height of the source. When no vertex holds any accumulated water, the water that has reached the sink is the maximum flow.

8.7.2Preflow and excess flow

The structure in the intermediate steps of the algorithm is not a flow; the conservation constraint is violated. More water may enter a vertex than leaves it. This relaxed structure is called a preflow.

Definition 8.7

A preflow is a function f that obeys the capacity constraint and, in place of conservation, satisfies the following condition: for every vertex v other than the source,

e(v) = Σu f(u, v) − Σw f(v, w) ≥ 0

e(v) is called the excess flow of v: the total flow in minus the total flow out. A vertex other than the source and sink with e(v) > 0 is an active vertex.

In a preflow, conservation is relaxed in only one direction: a vertex can accumulate flow, but it cannot give away flow it does not have. The excess is never negative. Conservation means that e(v) = 0 at all intermediate vertices. So when no active vertex remains, the preflow has become a true flow. The algorithm runs until that moment.

8.7.3The height function and initialization

The algorithm assigns each vertex an integer h(v). The initialization is as follows:

  • The flow on all edges is 0.
  • h(s) = |V|, the number of vertices; all other vertices have h = 0.
  • Every edge leaving the source is saturated: f(s, v) = c(s, v) and e(v) = c(s, v).

Two invariants are maintained throughout the algorithm. First, h(s) = |V| and h(t) = 0 never change; the source and the sink are not relabeled. Second, for every edge (u, v) in the residual network, h(u) ≤ h(v) + 1. This second invariant says that the height can drop by at most 1 along an edge. Slopes cannot be steep.

The second invariant has an important consequence: h(u) is a lower bound on the residual-network distance from u to the sink. If there is a residual path with k edges from u to the sink, the height drops by at most 1 on each edge; since the height of the sink is 0, h(u) ≤ k.

Theorem 8.7 (No s–t path)

As long as the invariants hold, there is no path from the source to the sink in the residual network. Hence, if the algorithm stops when no active vertex remains, the flow obtained is maximum.

If there were a path from the source to the sink in the residual network, as a simple path it would have at most |V| − 1 edges. By the observation just made, we would need h(s) ≤ |V| − 1. But h(s) = |V|. A contradiction. When no active vertex remains, the preflow is a flow and its residual network has no augmenting path; by the max-flow min-cut theorem it is a maximum flow. □

This viewpoint shows that the algorithm works the other way around from the Ford-Fulkerson family. Ford-Fulkerson maintains a valid flow at every moment and runs until no augmenting path is left. Push–relabel maintains the condition “no augmenting path” at every moment and runs until the preflow is a valid flow. The initial value h(s) = |V| establishes this condition. Because the edges leaving the source are saturated, no edge leaves the source in the residual network; the invariant holds at the start as well.

8.7.4The push and relabel operations

Push: push(u, v). The condition has three parts: e(u) > 0; cf(u, v) > 0, that is, the edge has a gap between capacity and flow; and h(u) = h(v) + 1. Under these conditions δ = min(e(u), cf(u, v)) units of flow are pushed: f(u, v) increases (or f(v, u) decreases if it is a reverse edge), e(u) −= δ, e(v) += δ. If the push saturates the edge it is called a saturating push, otherwise a non-saturating push. In a non-saturating push, δ = e(u) and the excess of u is emptied completely.

Relabel: relabel(u). The condition: e(u) > 0, but h(u) ≤ h(v) for every edge (u, v) in the residual network; that is, it cannot push to any neighbor. The operation is h(u) = 1 + min h(v), with the minimum taken over the edges (u, v) in the residual network. With this new value at least one push becomes possible: the lowest neighbor is exactly one step below.

Both operations preserve the invariants. A push is made only on an edge with h(u) = h(v) + 1. On the reverse edge (v, u) that may be created, h(v) = h(u) − 1 ≤ h(u) + 1; the invariant holds. In a relabel, h(u) is chosen exactly one more than the smallest of its residual neighbors; the invariant is preserved on the edges leaving u. On the edges entering u, an increase of h(u) only relaxes the condition.

Flow is pushed from high to low, and heights only increase. A vertex with excess flow always has a path to the source in the residual network: this flow came from the source along some path, and the reverse edges of that path are in the residual network. So the min in the relabel is always defined. Excess that cannot reach the sink is pushed back toward the source once it rises above |V|, the height of the source.

Common mistake

Mixing up the direction of the push or the initial height. Flow is pushed only from high to low, when h(u) = h(v) + 1. Pushing to a neighbor of equal height breaks the invariant. At the start h(s) = |V| must hold; if the source is left at 0, the excess cannot return to the source and the “no augmenting path” guarantee is lost.

In the following steps the same thing happens between C and D. The 6 units of C go to D; D pushes 5 of them to the sink, because the capacity of D → t is 5. The remaining 1 unit goes back and forth between C and D. When the heights exceed 7, the height of A, C pushes this unit to A (the flow on A → C drops from 6 to 5); A then pushes it to the source.

When no active vertex remains, the maximum flow is the flow into the sink: 7 + 5 = 12. The flow out of the source is also 9 + 3 = 12. The minimum cut is S = {s, A, B, C, D}, T = {t}: A → t (7) + D → t (5) = 12.

The order of selection in the example is not the only option. The Java functions on the slides can also be run with a main loop that picks the first active vertex in index order each time. On the same network this loop performs 38 operations (relabels and pushes) and again finds 12. The order changes the number of operations, not the result.

8.7.6Pseudocode

The initialization part of the algorithm is as follows:

PUSH_RELABEL(G, source, sink):
  height[source] = |V|
  height[v] = 0, v ≠ source
  excess[v] = 0, for each v
  flow[e] = 0, for each edge e
  // preflow: saturate the source edges
  for each (source, v) ∈ E:
    c = capacity[source, v]
    flow[source, v] = c
    flow[v, source] = −c
    excess[v] = c
    excess[source] −= c

The flow is kept in a skew-symmetric table: when a source edge is saturated, flow[v, source] = −c is written. The excess of the source becomes negative; the source is a special vertex in this respect. The main loop is as follows:

while some u has excess[u] > 0:
  // u ≠ source, u ≠ sink
  if residual(u,v) > 0 and
       height[u] == height[v]+1:
    // push
    delta = min(excess[u], residual(u,v))
    flow[u,v] += delta
    flow[v,u] −= delta
    excess[u] −= delta
    excess[v] += delta
  else:
    // relabel
    m = ∞
    for each (u, v) in G[u]:
      if flow[u,v] < capacity[u,v]:
        m = min(m, height[v])
    height[u] = m + 1
return excess[sink]
// residual = capacity − flow

The loop runs as long as an active vertex u is found. If the push condition holds for some neighbor v of u, a push is made; if not, u is relabeled. The relabel part finds the smallest height among the neighbors in the residual network, that is, among the edges with flow < capacity, and writes one more than it. When the loop ends, the excess of the sink is returned; this is the total flow that has reached the sink.

8.7.7Java: push() and relabel()

In the Java implementation each Node object holds its own height and excess fields and the list of its outgoing edges. The push operation is as follows:

boolean push(Node n) {
  for (Edge e : n.edges) {
    if (n.height > e.to.height
        && e.flow != e.cap) {
      int flow = Math.min(
        e.cap - e.flow, n.excess);
      n.excess -= flow;
      e.to.excess += flow;
      e.flow += flow;
      updateReverse(e, flow);
      return true;   // pushed
    }
  }
  return false;
}

The method tries the edges of the vertex in order. The expression n.height > e.to.height in the condition looks looser than the theoretical condition h(u) = h(v) + 1. But because of the invariant the two are the same: on an edge in the residual network h(u) ≤ h(v) + 1, so h(u) > h(v) is possible only when h(u) = h(v) + 1. e.flow != e.cap says that the edge is in the residual network.

When the condition holds, the amount pushed is the smaller of the residual capacity and the excess. The vertex's excess decreases, that of the target vertex increases, the flow on the edge grows, and updateReverse reduces the flow of the reverse edge by the same amount. Reverse edges are stored as edges with capacity 0 and negative flow. The method returns true after the first successful push. If no edge is suitable it returns false and the vertex is relabeled:

void relabel(Node n) {
  int minH = Integer.MAX_VALUE;
  for (Edge e : n.edges) {
    // only edges in the residual network
    if (e.flow != e.cap
        && e.to.height < minH) {
      minH = e.to.height;
      n.height = minH + 1;
    }
  }
}

The loop finds the lowest among the neighbors in the residual network and sets the height to one more than that. The assignment is made inside the loop, but since the last assignment made corresponds to the smallest height, the result is correct. The main loop combines the two methods: while there is an active vertex, if (!push(n)) relabel(n);. The result is the excess of the sink.

A push takes O(1); a relabel takes time proportional to the degree of the vertex. The code scans the edge list from the start on every call. This is a choice made for simplicity; efficient implementations keep a “next edge” pointer similar to the next array in Dinic's algorithm.

8.7.8Complexity

The running time is found by counting how many times each type of operation can be performed. Table 8.10 summarizes the results.

Table 8.10: The total number of push–relabel operations.
OperationTotal countReason
RelabelO(V²)the height of every vertex is ≤ 2|V| − 1 and only increases
Saturating pushO(V · E)for an edge to be saturated again, the heights at both endpoints must rise by ≥ 2
Non-saturating pushO(V² · E)via the potential function Σ h(v) (active v)

Relabels. An active vertex has a path to the source in the residual network. This path has at most |V| − 1 edges, and the height drops by at most 1 on each edge. Hence h(u) ≤ h(s) + |V| − 1 = 2|V| − 1. Since every relabel raises the height by at least 1, a vertex is relabeled at most 2|V| − 1 times; in total O(V²). In our example, for |V| = 6 the bound is 11; the highest label reached was 8.

Saturating pushes. When an edge (u, v) is saturated, h(u) = h(v) + 1. For it to be saturated again in the same direction, a push must first be made from v to u; for that h(v) must rise to h(u) + 1, that is, increase by at least 2. Then u must rise by 2 as well. Since heights cannot exceed 2|V|, each edge is saturated O(V) times; in total O(V · E).

Non-saturating pushes. The sum of the heights of the active vertices, Φ, is used as a potential. A non-saturating push makes u inactive and decreases Φ by at least 1 (even if v becomes active, h(v) = h(u) − 1). Relabels raise Φ by O(V²) in total, and saturating pushes by at most O(V · E) · 2V. Hence the number of non-saturating pushes is O(V² · E).

The generic algorithm takes O(V² · E) in the worst case. A relabel scans at most as many edges as the degree; the total scan is O(V · E) and does not change the dominant term. The rule for choosing the active vertex improves the bound. If the active vertices are kept in a FIFO (first-in first-out) queue, the time drops to O(V³). If the active vertex with the highest label is chosen each time, the time is O(V² · √E).

In practice two heuristics speed the algorithm up a great deal. The gap heuristic notices that no vertex is left at some height value. In that case the vertices above that value cannot reach the sink; the heuristic moves them directly above |V|. The long “playing catch” stretches of the example are shortened to a single step this way. Global relabeling occasionally runs a BFS backward from the sink and sets all heights to the true distances. With these heuristics push–relabel is one of the fastest general-purpose maximum-flow methods.

A rough rule for choosing can be given. If the capacities are small integers, Ford-Fulkerson is enough and is the shortest code. As a general-purpose implementation Dinic is a good default: its code is short, its bound is good, and it is fast in practice. On very large and dense networks push–relabel, together with its heuristics, is usually the fastest. All the algorithms find the same value |f*|. The distribution of the flow over the edges may differ. The minimum cut is in every case read from the final residual network.

8.8.3Applications

The power of maximum flow comes from the fact that many problems with no apparent connection to flow can be turned into a flow network. After the transformation, any of the algorithms described in this chapter is used.

Bipartite matching. Consider two groups, such as workers and jobs, or students and projects. Each worker is joined by an edge to the jobs he or she can do. Each worker can take at most one job, and each job at most one worker. The goal is the largest possible number of matched pairs. This problem is turned into a flow network as follows: a source is joined to all the workers, and all the jobs are joined to a sink; the worker–job edges stay as they are. All capacities are 1.

Since the edge from the source to a worker has capacity 1, at most one unit of flow leaves that worker; a worker is assigned to at most one job. The edge from a job to the sink imposes the same limit on jobs. The integrality theorem guarantees that the maximum flow is 0 or 1 on every edge. The worker–job edges that carry flow form a matching, and the value of the flow is the size of the matching. In the network of Figure 8.35, worker a1 can do b1 and b2, a2 can do only b1, and a3 can do b2 and b3. The maximum flow is 3; everyone gets a job.

Edge-disjoint paths. What is the largest number of paths between two vertices that share no edge? This question concerns the robustness of networks: how many links must fail before communication is cut? Every edge is given capacity 1; the maximum flow equals the number of edge-disjoint paths. Menger's theorem says that this number equals the smallest number of edges that must be deleted to separate the two vertices. This is the unit-capacity special case of the max-flow min-cut theorem.

Vertex capacities. In some problems the constraint is on vertices rather than edges: at most a certain number of vehicles can pass through an intersection per hour. Each vertex v is split into two vertices: an input vin and an output vout. An edge vin → vout with capacity c(v) is placed between them. The edges entering v are attached to vin, and those leaving v are attached to vout. All the flow passing through the vertex is forced to use this single edge.

Image segmentation. To separate foreground from background in a photograph, each pixel becomes a vertex. The source stands for “foreground” and the sink for “background.” The probability that a pixel is foreground becomes the capacity of the edge from the source, and the probability that it is background the capacity of the edge to the sink. Edges between neighboring pixels reward keeping similar pixels on the same side. The minimum cut gives the partition that minimizes the total “mislabeling cost.”

Network reliability, transportation, and logistics. The smallest total capacity that must be cut to split a communication network in two is a minimum cut. Maximum flow or minimum cut is also a basic tool in pipelines, traffic planning, airline scheduling, and project selection. In most of these problems the real work is building the right network; the algorithm is ready.

8.9Common mistakes

Most mistakes in network flow problems come from a few confusions of concepts. The list below gathers them.

  • Forgetting reverse edges. Searching with forward edges only is a greedy algorithm and may miss the maximum; on the second example network the result is 18 instead of 19.
  • Computing the bottleneck from capacities. The bottleneck is the smallest of the residual capacities, not of the capacities: c − f on a forward edge and f on a reverse edge. After the second augmentation some edges are partly full, so looking at capacities gives a wrong and too large bottleneck.
  • Taking the minimum cut to be the one with the fewest edges. A minimum cut cuts the smallest total capacity, not the fewest edges.
  • Counting edges from T to S. Only edges going from S to T enter the cut capacity; backward ones are not added. In computing the net flow across a cut, however, flows in the backward direction are subtracted. The two computations must not be confused.
  • Taking the value of a flow to be the sum of the edge flows. The value is only the net flow leaving the source; the same unit is not counted again on every edge of its path.
  • Treating Ford-Fulkerson as polynomial. O(E · |f*|) depends on the values of the capacities. Edmonds-Karp, which works with BFS, removes this dependence.
  • Measuring “shortest” in Edmonds-Karp by capacity. The shortest path is the one with the fewest edges. Choosing the path of largest capacity is a separate heuristic, and the bound of Edmonds-Karp does not hold for it.
  • Relaxing the level condition in Dinic's algorithm. DFS must follow only edges with level(v) = level(u) + 1. If edges within the same level are allowed, DFS can enter a cycle and the bound on the number of phases becomes invalid.
  • Mixing up the direction of the push. Flow is pushed from high to low, only when h(u) = h(v) + 1; at the start h(s) = |V| must hold.
  • Reading the minimum cut from the wrong residual network. The cut is read from the vertices reachable from the source in the final residual network, after the algorithm has finished. A set read from the residual network of an intermediate step may give a cut, but not necessarily a minimum one.

8.10Summary

  • Flow network: a directed graph of a source, a sink, and edges with capacities. A flow obeys the capacity constraint (0 ≤ f ≤ c) and conservation at intermediate vertices (in = out). The value |f| is the net flow leaving the source. Multiple sources and sinks are reduced to a single-source problem with a supersource and a supersink joined by edges of infinite capacity.
  • Residual network: the residual capacity of a forward edge is c − f and that of a reverse edge is f. The reverse edge makes it possible to undo flow already sent. An augmenting path is an s–t path in the residual network; the bottleneck is the smallest residual capacity on the path. Augmenting along the path by the bottleneck gives a valid flow and increases its value by the bottleneck.
  • Cut: c(S, T) is the sum of the capacities of the edges going from S to T. The net flow across every cut equals |f|; hence |f| ≤ c(S, T). The maximum flow equals the minimum cut. The S side of the minimum cut is the set of vertices reachable from the source in the final residual network.
  • Ford-Fulkerson: uses any augmenting path. With integer capacities it terminates, finds a flow of integer value, and takes O(E · |f*|). A bad choice of paths can require as many augmentations as the capacity.
  • Edmonds-Karp: chooses the shortest augmenting path with BFS. Distances do not decrease, and each edge becomes critical O(V) times; O(V · E) augmentations and O(V · E²) time.
  • Dinic: in each phase builds a level graph with BFS and finds a blocking flow with DFS and the current-arc array. At most V − 1 phases, O(V · E) per phase; in total O(V² · E). It is much faster on unit capacities.
  • Push–relabel: starts with h(s) = |V| and builds a preflow by saturating the source edges. Flow is pushed from high to low; if it cannot be pushed, the vertex is relabeled. When no active vertex remains, the preflow is a maximum flow. The generic version runs in O(V² · E), the FIFO version in O(V³).
  • Applications: bipartite matching, edge-disjoint paths, networks with vertex capacities, image segmentation, and network reliability are modeled as maximum flow or minimum cut.

    Answer

  2. In the second example network (Figure 8.10), what is the capacity of the cut S = {S, 1, 3}? Why is this cut not a minimum cut?

    Answer

    The edges going from S to T are 1 → 2 (4), 1 → 4 (8), and 3 → 4 (9): 4 + 8 + 9 = 21. The edges S → 1, S → 3, and 1 → 3 have both endpoints on the S side. Since the maximum flow is 19, a cut of capacity 21 cannot be minimum; the minimum cut is {S, 3} (19).

    S → A → B → T (2), S → C → D → T (3), and S → A → B → C → D → T (2). The first two paths have 3 edges, the third 5. There are 3 augmentations; the fourth BFS cannot reach the sink. In total 4 BFS runs, maximum flow 7.

  4. Which paths does Ford-Fulkerson with a DFS that tries neighbors in index order (s, 1, 2, 3, 4, t) find on the network of Figure 8.17? How many augmentations does Edmonds-Karp make on the same network?

    Answer

  5. How many phases does Dinic's algorithm make on the first example network? What are the levels and the blocking flow in each phase?

    Answer

    Phase 1: the levels are S = 0; A, C = 1; B, D = 2; T = 3. B → C is not used because it goes back a level. The blocking flow is S → A → B → T (2) and S → C → D → T (3); |f| = 5. Phase 2: the levels are S = 0, A = 1, B = 2, C = 3, D = 4, T = 5; the path is S → A → B → C → D → T (2), |f| = 7. The third BFS cannot reach the sink. 2 phases, 3 BFS runs.

  6. In the first example network, if the capacity of the edge B → T is raised from 2 to 5, does the maximum flow change? In how many phases does Dinic finish?

    Answer

    It does not change; it stays 7. The capacity of the cut ({S}, the rest) is still 4 + 3 = 7, and this edge is not in that cut. Dinic finishes in a single phase: in the level graph S → A → B → T carries 4 and S → C → D → T carries 3 units. The second BFS cannot reach the sink.

  7. In the first example network, if at most 3 units of flow can pass through vertex B, how is the problem modeled and what is the maximum flow?

    Answer

    B is split into the vertices Bin and Bout; an edge of capacity 3 is placed between them. The edges become A → Bin (4), Bout → C (3), and Bout → T (2). The maximum flow is 6: for example 3 units through B (2 directly to the sink, 1 to C), and 3 units through S → C. The minimum cut consists of the edges S → C (3) and Bin → Bout (3): 6.

  8. What is the largest number of edge-disjoint paths from S to T in the second example network? How is this number reached with maximum flow?

    Answer

    Set all capacities to 1 and compute the maximum flow. The result is 2; for example S → 1 → 2 → T and S → 3 → 4 → T. Since only two edges leave the source (the cut {S} has capacity 2), a third edge-disjoint path is impossible.

  9. Push–relabel is started on the first example network. What are the initial heights and excesses? If A is chosen as the active vertex, what are the first two operations?

    Answer

    h(S) = 6, and h = 0 at all other vertices. S → A and S → C are saturated: e(A) = 4, e(C) = 3. The residual neighbors of A are B (h = 0) and S (a reverse edge, h = 6); neither is one step below. First a relabel: h(A) = 1 + min(0, 6) = 1. Then a push: δ = min(e(A), cf(A, B)) = min(4, 4) = 4; e(A) = 0, e(B) = 4.
