Chapter 5.2: Interrupt Functions

An 8086 program does not have to drive the hardware from scratch every time it wants to print text on the screen, read a key from the keyboard, or find out the time. The BIOS in the computer's ROM, and DOS running on top of it, offer these jobs as ready-made routines. A program reaches these routines through a software interrupt: it writes the service number into register AH and the parameters into the other registers, then executes an INT n instruction. These notes cover the services of the four most used interrupts: INT 10h manages the screen, INT 16h the keyboard, INT 21h the DOS character, string, date and time services, and INT 1Ah the clock counter. Writing directly to screen memory without the BIOS, the BIOS data area, and the proper ways to terminate a program are also covered. Each service is shown at register level by the step-by-step trace of a short program.

5.2.1BIOS and DOS services

5.2.1.1Service layers

Writing a single character to the screen means several separate jobs at the hardware level. The code of the character is written to the right cell of the video card's memory. The color byte of the cell is set. The new position of the cursor is reported to the controller on the video card through an I/O port. If the end of the line has been reached, output moves to the next line, and at the end of the screen all the lines are scrolled up by one. It is both laborious and dangerous for every program to do these jobs itself. When the video card changes, all the programs would have to be rewritten.

IBM PC compatible computers solve this problem with layers. Figure 5.2.1 shows four layers. At the bottom is the hardware: the video card, the keyboard controller, the disk and the clock. Hardware is reached directly through I/O ports (IN, OUT) and memory addresses. One level up is the BIOS. The BIOS routines know the details of the hardware and hide them behind a fixed interface. DOS, above it, offers more abstract services such as file, string, date and program management. At the top is the application program, which only calls these services.

Definition 5.2.1

The BIOS (Basic Input/Output System) is a collection of routines that live in the ROM on the motherboard and drive the hardware directly. It works without an operating system. When the computer is switched on, it tests the hardware, writes the addresses of its own routines into the interrupt vector table, and loads the operating system from the disk. DOS (Disk Operating System) is the operating system that runs on top of the BIOS and offers file, memory and program management.

The tool a program uses to reach a BIOS or DOS service is the software interrupt. The INT n instruction makes the processor read entry number n of the interrupt vector table in memory and branch to the address found there. The return address and flags are pushed on the stack; when the service routine finishes, it returns to the program with IRET. The subject here is not this mechanism itself but the services it offers. What matters is this: the program does not have to know the address of the service in memory. It knows only its number.

The benefit of using numbers instead of addresses is great. The BIOSes of different manufacturers place their routines at different addresses. Which version of DOS is loaded also changes the addresses. The vector table is filled at boot with the real addresses of that machine. So a program that says INT 10h reaches its own screen routine on every PC compatible machine. On the 8086, an INT n instruction takes 51 clock cycles; a direct far CALL takes 28. The cost is nearly twice the time; in return you get portability.

The same job can be done at different layers. There are three ways to write a character to the screen: DOS's INT 21h/02h service, the BIOS INT 10h/0Eh service, and writing directly to screen memory (segment B800h). The upper layer is more portable; its output can also be redirected to a file. The lower layer is faster and more flexible; it gives full control over color and position. A program chooses the layer according to the need and can mix layers in the same program.

5.2.1.2The service-call pattern

An interrupt number corresponds not to a single service but to a family of services. INT 21h does hundreds of jobs such as writing a character, writing a string, opening a file, reading the time and ending the program. Which job is to be done is decided by the number written to register AH before the interrupt. This number is called the service number or function number. Because AH is 8 bits wide, an interrupt can have at most 256 services.

Definition 5.2.2

The service-call pattern has four steps: (1) AH ← the service number; (2) the other parameters are written to registers such as AL, BX, CX, DX, DS:DX or ES:BP; (3) INT n is executed; (4) the result is read from registers (AL, AX, CX, DX) or flags (ZF, CF). Which register carries what is defined separately for each service.

The shortest example is making DOS print a letter on the screen:

mov ah, 02h    ; service: print char
mov dl, 'A'    ; parameter
int 21h        ; call DOS

The first line loads 02h into AH: DOS's "write character" service. The second line puts the ASCII code of the character to be written, 41h, into DL. This service expects the character in DL. The third line calls the interrupt. The processor reads the vector at address 0000:0084h (21h × 4 = 84h) and branches to the DOS routine. The routine writes the character where the cursor is, advances the cursor by one, and returns with IRET. The program continues from the instruction after int 21h.

What the processor does at the hardware level in this pattern is clear. MOV AH, 02h is a two-byte instruction (B4 02); the BIU takes it from the prefetch queue, the EU writes the register, and no memory bus cycle is needed. INT 21h, on the other hand, pushes three words on the stack (FLAGS, CS, IP) and reads two words from the vector table: five memory bus cycles. The service routine itself is hundreds of instructions. So even printing a single character takes thousands of clock cycles. This time is too short for the user to notice, but it becomes visible in a loop that fills the screen character by character.

Services may change the registers they use. This is the most error-prone side of the pattern. For example INT 21h/02h puts the character in DL into AL on return; INT 21h/09h sets AL to 24h. A value kept in AL is lost after these calls. Values that will be needed later are kept in a register the service does not touch, or on the stack. Some services also use AL for a sub-selection. The VESA video card services are an example: in the service called with AX = 4F00h, AH = 4Fh selects the family and AL = 00h selects the job within that family.

Common mistake

Leaving a character that was read in AL and putting another INT 21h call in between. For example, a key is first read with AH = 01h, then AH = 02h, DL = 0Dh is called for a carriage return. This call makes AL 0Dh and the key that was read is lost. The value read must be copied to another register such as BL right after the call.

5.2.1.3ASCII and control characters

Every character written to the screen and read from the keyboard is a number. On the PC these numbers come from the ASCII (American Standard Code for Information Interchange) encoding. ASCII assigns characters to the codes 0–127. The codes 20h–7Eh are printable characters: space, digits, letters and punctuation. The codes 00h–1Fh are control characters. These carry meaning not as a shape on the screen but as an action.

The codes of the printable characters are not randomly scattered; a few regularities make programs shorter. Table 5.2.3 summarizes them. The codes of the digits start at 30h: '0' = 30h, '9' = 39h. The numeric value of a digit is therefore found by subtracting 30h from its code. Conversely, a number from 0 to 9 becomes a printable digit when 30h is added. Uppercase letters are 41h–5Ah and lowercase letters 61h–7Ah. The difference between the two groups is exactly 20h, a single bit: bit 5. To convert a lowercase letter to uppercase, bit 5 is cleared (SUB AL, 20h or AND AL, 0DFh); to convert uppercase to lowercase, it is set (OR AL, 20h).

Starting a new line takes two separate characters: CR (0Dh) and LF (0Ah). This distinction is a legacy of the typewriter. CR returns the print head to the start of the line; LF pushes the paper up one line. Figure 5.2.2 compares the three cases. If only CR is sent, the cursor returns to the start of the line and the next text lands on top of the same line. If only LF is sent, the cursor goes down one line but its column does not change; the text drifts to the right like a staircase. When both are sent together, the cursor comes to the start of the next line.

Letters outside the English alphabet (such as the Turkish ç, ğ, ı, ö, ş, ü) are not in 7-bit ASCII. DOS shows them with codes between 128 and 255, according to the active code page; for Turkish this page is CP857. The same byte may appear as a different letter in another code page. For this reason the example programs in the slides and in these notes use no such letters in strings: plain ASCII text only.

Example 5.2.1

AL = 37h ('7') and BL = 32h ('2') are two digit characters. To print their sum as a single digit, 30h is first subtracted from both: 07h and 02h. The sum is 09h. To print it, 30h is added: 39h = '9'. If the characters were added directly, 37h + 32h = 69h = 'i' would result. ASCII codes are names of characters, not numbers; they are converted to numbers before arithmetic.

All the BIOS services related to the screen are gathered under INT 10h. Selecting the screen mode, moving the cursor, writing colored characters, printing a string in a single call, clearing a region of the screen and drawing pixels in graphics mode are all done with these services. Selecting a mode also clears the screen. So the two lines often seen at the start of programs are the shortest way to get a clean 80×25 screen:

mov ah, 00h
mov al, 03h    ; or mov ax, 0003h
int 10h        ; clean 80×25 screen

AH and AL can be loaded together with a single MOV AX, 0003h instruction. Since AH is the high byte of AX it becomes 00h, and since AL is the low byte it becomes 03h. This three-byte instruction is both shorter and faster than two separate two-byte MOVs.

In mode 03h the screen is 25 rows and 80 columns (Figure 5.2.3). Rows are numbered from 0 to 24 and columns from 0 to 79. The top-left corner is (0, 0) and the bottom-right corner is (24, 79). In the BIOS services the row number is given in DH and the column number in DL. The emu8086 screen window is in this mode by default; it supports graphics modes only to a limited extent.

5.2.2.2The cursor

The cursor is the position on the screen where the next character will be written. The BIOS keeps a cursor position for each display page. AH = 02h moves the cursor to row DH and column DL; AH = 03h reads the cursor position into DH and DL. Both services expect a display page number in BH. In 80×25 mode the video card's memory is large enough to hold several screens; VGA has 8 pages (0–7). Only one of the pages is visible. Page 0 is normally used.

Row and column can be loaded together with a single MOV DX instruction. mov dx, 0C28h puts 0Ch = 12 in DH and 28h = 40 in DL: the middle of the screen. The code below first moves the cursor to the middle, then reads the position and moves it one to the right.

; move the cursor to the middle
mov ah, 02h
mov bh, 0
mov dx, 0C28h  ; row 12, column 40
int 10h
; move the cursor one right
mov ah, 03h
mov bh, 0
int 10h        ; DH, DL = position
inc dl
mov ah, 02h
int 10h

The first four lines move the cursor to (12, 40). The next three lines read the position; on return DH = 12, DL = 40, and the shape of the cursor is written to CH, CL. INC DL makes the column 41. The last two lines write the new position. BH is not reloaded because it did not change after the 03h call. Figure 5.2.4 shows these steps and the cell's place in screen memory.

The cursor position is not merely a BIOS variable; it is also held in the video card's hardware. In color text mode, two registers of the display controller (the CRTC) determine in which cell the cursor blinks. The BIOS writes to these registers with OUT instructions through I/O ports 3D4h (index) and 3D5h (data). The AH = 02h call spares the program this port detail. The same position is also stored in the BIOS data area; characters written with INT 21h also start from this cursor position.

Every cell also has a place in screen memory. In mode 03h, 2 bytes are used per cell and the rows follow one another. The offset of the (row, column) cell is computed as follows:

offset = (row × 80 + column) × 2

For (12, 40) we get (960 + 40) × 2 = 2000 = 07D0h. For (1, 4) it is (80 + 4) × 2 = 168 = 00A8h. At the even address is the character's code, and at the odd address after it is its color.

5.2.2.3The attribute byte

In text mode the color of each cell is determined by one byte. This byte is called the attribute byte. Figure 5.2.5 shows the bits of the byte. The low four bits (bits 3–0) are the foreground, that is the color of the text. Bits 2–0 turn on the red, green and blue components; bit 3 makes the color brighter. Bits 6–4 are the color of the background: again red, green, blue. Bit 7 turns on blinking of the character.

Definition 5.2.3

The attribute byte is the byte that determines the foreground and background color and the blinking of a character cell in text mode. Written in hexadecimal, the high digit gives the background and the low digit the foreground: attribute = background × 16 + foreground. If bit 7 = 1 the character blinks (depending on the BIOS setting, the background can instead be shown bright).

The sixteen colors come from all the combinations of four bits. Table 5.2.6 gives the numbers and names. The bright colors (8–F) are formed by adding bit 3 to their dark counterparts: 1 is blue, 9 light blue; 4 is red, C light red. Two exceptions stand out: 6 is brown, not yellow, and its bright version E is yellow. 7 is light gray and F is white.

Example 5.2.2

The default attribute is 07h: background 0 (black), foreground 7 (light gray). For white text on a blue background, background 1 and foreground F are chosen: 1 × 16 + 15 = 31 = 1Fh. Yellow text on a red background is 4Eh. 8Fh = 1000 1111b, because bit 7 is set, is blinking white text on a black background. Since only three bits are given to the background, a light green (A) background cannot be chosen directly: if A0h is written, the top 1 bit falls on bit 7 and blinking is turned on over a green background.

The attribute explorer in the slides produces the attribute byte and the INT 10h/09h call that uses it when a foreground and a background are selected. The same calculation is also easy by hand: the two color numbers are written side by side as two hexadecimal digits.

5.2.2.4Writing characters: 09h and 0Eh

INT 10h offers two main services for writing characters, and the two behave very differently. AH = 09h takes the character from AL and its color from BL, and writes the same character CX times side by side. It does not advance the cursor. AH = 0Eh is teletype output: it writes the character where the cursor is and advances the cursor by one. At the end of a line it moves to the next line, and on the last line it scrolls the screen up. It also interprets the characters CR, LF, BS and BEL as commands. Table 5.2.7 puts the differences side by side.

That 09h does not advance the cursor looks odd at first, but it suits the purpose of the service. To draw the top edge of a frame, the same character is written CX times side by side; the program decides where the cursor goes. There are two common ways to write colored plain text. In the first, each character is written in color with 09h and CX = 1, and then the cursor is moved one to the right with 02h. In the second, the whole string is written in a single call with 13h.

Common mistake

Writing characters one after another with 09h without moving the cursor. Each new character is written over the previous one and only the last is visible on the screen. After 09h the cursor is either advanced by hand with AH = 02h or the colored cell is written over with 0Eh.

5.2.2.5Code trace: mode, cursor, 09h and 0Eh

The following program uses four services one after another. First it clears the screen and moves the cursor to (1, 4), writes three yellow stars on a red background there, and then writes 'A' and 'B' with teletype. The purpose of the program is to show the difference between 09h and 0Eh in cursor and color handling in one place.

org 100h
mov ax, 0003h    ; AH=00h, AL=03h
int 10h          ; clears screen
mov ah, 02h      ; set cursor
mov bh, 0        ; page 0
mov dx, 0104h    ; DH=1, DL=4
int 10h
mov ah, 09h      ; char + attribute
mov al, '*'
mov bl, 4Eh      ; yellow on red
mov cx, 3        ; 3 times
int 10h          ; cursor stays!
mov ah, 0Eh      ; teletype
mov al, 'A'
int 10h          ; cursor moves
mov al, 'B'
int 10h
ret

The program is a .COM program: it begins with org 100h, and at the start the general registers are zero. The first two lines set mode 03h. The screen is cleared and the cursor comes to (0, 0). The next four lines move the cursor. The mov dx, 0104h instruction writes 01h to DH and 04h to DL. Because of the little-endian layout the bytes of the instruction are BA 04 01. After int 10h the cursor is at (1, 4) but there is nothing on the screen yet.

Then the 09h call is prepared. AL = 2Ah ('*'), BL = 4Eh, CX = 3 are loaded. BH is still 0; it does not need to be written again. After the call, the cells (1, 4), (1, 5) and (1, 6) hold yellow stars on a red background. The cursor, however, has not budged: it is still at (1, 4).

In the last part AH = 0Eh is loaded and 'A' is put in AL. INT 10h writes 'A' at (1, 4), where the cursor is; that is, over the first star. Then it moves the cursor to (1, 5). Because the 0Eh service does not change AH, only AL is changed for the second character. 'B' is written over the second star at (1, 5) and the cursor moves to (1, 6). AB* appears on the screen. Because 0Eh takes no attribute in text mode, 'A' and 'B' keep the color 4Eh left by the stars: yellow on red.

5.2.2.6Writing strings: 13h

AH = 13h writes a string, in color, in a single call. It is found in the BIOS of the AT and later computers. It has many parameters: AL gives the write mode, BH the page, BL the attribute, CX the length of the string, DH and DL the starting position. The address of the string is in ES:BP. This differs from DOS's string service (DS:DX) and is often confused with it. No marker such as '$' is looked for at the end of the string; the length is taken from CX.

Common mistake

Putting the string address in DS:DX for 13h and using DX twice. In this service DX is the position; if mov dx, offset msg is written, the position is spoiled, and BP points to some random place. 5.2.2.7Window scrolling and clearing the screen: 06h

AH = 06h scrolls a rectangular region of the screen, that is a window, up by AL lines. The lines vacated at the bottom of the window are painted with the space character in the BH attribute. If AL = 0 is given, instead of scrolling, the whole window is cleared. This feature is the standard way of clearing the screen without changing mode and in the color you want. AH = 07h does the same job downward.

5.2.3Direct access to video memory

5.2.3.1B800h text memory

INT 10h services always end up doing the same job: writing bytes to the video card's memory. This memory appears in the processor's address space like ordinary RAM. In the 8086's 1 MB address space the range A0000h–BFFFFh is reserved for video cards. In color text modes the video memory starts at physical address B8000h; a program reaches it with segment B800h. The video card's controller reads this memory from beginning to end dozens of times per second and draws each cell on the screen. A value written to memory appears on the screen on the next scan.

Definition 5.2.4

Video memory is the memory, mapped into the processor's address space, that holds the content the video card shows on the screen. In mode 03h it is 4000 bytes (80 × 25 × 2) starting at B800:0000h. Each cell occupies two bytes: at the even address the ASCII code of the character, at the odd address after it the attribute byte.

Writing directly to memory is much faster than calling the BIOS. An INT 10h call executes hundreds of instructions, while a direct write is a single MOV instruction. There is a price, though. A direct write does not move the cursor and does not update the cursor information the BIOS keeps. The output also does not go through DOS redirection. The program computes the cell address itself and must know which mode the video card is in. emu8086 supports this memory; the cells written appear in the screen window.

Writing to a cell as a word places the character and its color in one instruction. The 8086 is little-endian: the low byte of a word is written to the lower address and the high byte to the higher address. That is why the character is put in the AL half of AX and the attribute in the AH half. Figure 5.2.8 shows this layout. Because the address of the word is even, the 8086 does this write in a single bus cycle: all 16 bits of the data bus are used, and the BHE and A0 lines are active together. Writing a word to an odd address would take two separate bus cycles.

5.2.3.2Code trace: writing to B800h

The following program first puts a yellow 'A' on a red background in cell (1, 4). Then, with REP STOSW, it fills the first three cells of the screen with the period character. In the form in the slides, the second part uses CX = 2000 to fill the whole screen; here CX = 3 so that it stays traceable.

org 100h
mov ax, 0B800h
mov es, ax
mov di, (1*80+4)*2  ; 00A8h
mov ax, 4E41h
mov es:[di], ax
xor di, di
mov ax, 072Eh
mov cx, 3           ; first 3 cells
cld
rep stosw
ret

The first two lines make ES B800h. An immediate value cannot be written directly into a segment register; there is no 8086 instruction MOV ES, 0B800h. So the value is first put into AX. The 0 at the start of the number is there so that the assembler does not take B800h for a name. The expression (1*80+4)*2 in the third line is evaluated at assembly time; only the result, 00A8h, goes into the machine code. No multiplication is done while the program runs.

MOV ES:[DI], AX names the ES segment explicitly. In a memory access with DI the default segment is DS; here DS points to the program's segment, so the segment prefix (the 26h byte) is mandatory. When the instruction runs, the physical address is B800h × 16 + 00A8h = B80A8h. 41h is written to this address and 4Eh to address B80A9h. The character appears on the screen at once, and the cursor stays where it was. According to the 8086 manual this instruction takes 9 + EA cycles; for [DI] the EA adds 5 cycles and the segment prefix adds 2: about 16 clock cycles. Writing the same character with INT 10h takes hundreds of times as long.

In the second part XOR DI, DI zeroes DI; this is one byte shorter than MOV DI, 0. AX = 072Eh means AL = 2Eh ('.') and AH = 07h (light gray). CLD clears the direction flag (DF), so the string instruction moves forward, increasing DI. In each iteration REP STOSW writes ES:[DI] ← AX, increases DI by 2 and decreases CX by 1; it stops when CX reaches zero. After three iterations DI = 0006h and CX = 0.

Common mistake

Putting the character and the attribute the wrong way round: if mov ax, 414Eh is written, the low byte 4Eh ('N') is the character and 41h is the color, blue text on a red background. 5.2.3.3Mode 13h and the pixel address

Mode 13h is VGA's graphics mode with 320 × 200 resolution and 256 colors. It is selected with mov ax, 0013h and int 10h. The greatest convenience of this mode for the programmer is the structure of the memory: each pixel is a single byte, and the pixels follow one another row by row. The video memory is 64,000 bytes (320 × 200) from A000:0000h to A000:F9FFh. The value of the byte is the color number of the pixel; the video card converts this number to a real color in a palette table. The first 16 colors of the default palette are the same as the text colors: 0Eh is yellow, 0Fh is white.

Each row is 320 = 140h bytes. The offset of pixel (x, y) is therefore computed as follows:

offset = y × 320 + x

For pixel (100, 50), 50 × 320 + 100 = 16,100 = 3EE4h. The last pixel (319, 199) is at 199 × 320 + 319 = 63,999 = F9FFh, the last byte of the memory. Figure 5.2.10 shows the offsets of the first rows and of the last row.

The BIOS offers a pixel service in this mode too. AH = 0Ch writes the color in AL to the pixel at column CX (x, 0–319) and row DX (y, 0–199); BH is the page and is 0 in mode 13h. AH = 0Dh reads the pixel's color into AL with the same CX, DX. Working with coordinates is easy, but one interrupt call per pixel is slow.

Example 5.2.4

The offset of pixel (160, 100) in the middle of the screen is 100 × 320 + 160 = 32,160 = 7DA0h; its physical address is A0000h + 7DA0h = A7DA0h. The top-right corner (319, 0) is at 013Fh, and the bottom-left corner (0, 199) is at 199 × 320 = 63,680 = F8C0h.

5.2.3.4Drawing a diagonal

A diagonal starting at the top-left corner is made of the pixels (0, 0), (1, 1), (2, 2) … First, the version that uses coordinates with the BIOS:

mov ax, 0013h
int 10h          ; 320×200, 256 colors
xor cx, cx       ; x = 0
xor dx, dx       ; y = 0
mov bh, 0        ; page
dot: mov ax, 0C0Eh  ; AH=0Ch, AL=yellow
int 10h
inc cx           ; one right
inc dx           ; one down
cmp dx, 200
jb dot           ; 200 pixels

The loop reloads AX on every iteration. The reason is that some BIOSes change AX in the 0Ch service; the safe way is to set AH and AL before every call. CX and DX increase together. When DX reaches 200 the JB does not jump and the loop ends having drawn 200 pixels. Since the screen is 320 pixels wide, the diagonal reaches the bottom edge, not the right edge.

The same line can also be drawn by writing directly to A000h memory. This time we work with offsets instead of coordinates:

mov ax, 0013h
int 10h
mov ax, 0A000h
mov es, ax
xor di, di       ; (0,0) → offset 0
mov al, 0Eh      ; yellow
mov cx, 200
draw: mov es:[di], al
add di, 141h     ; 320 + 1
loop draw
mov ah, 0
int 16h          ; wait for a key
mov ax, 0003h
int 10h          ; back to text mode

Why is 141h added? +140h (320) goes to the same column of the next row down, +1 to the next column right. Together they make 141h = 321 and give the next pixel on the diagonal. The last pixel (199, 199) is at 199 × 321 = 63,879 = F987h. For the opposite diagonal descending from the top-right corner, 13Fh (320 − 1) is added at each step. At the end the program waits for a key and then returns to text mode; this way the user can see the line and the DOS prompt does not stay on a graphics screen.

The speed difference between the two versions is large. In the direct version the loop body is three instructions: a memory write, an addition and LOOP. In the BIOS version an interrupt is called for every pixel, and the interrupt routine itself computes the address from the coordinates. emu8086's graphics support is limited: drawing with the 0Ch service is slow, and a direct write to A000h may not be visible in every version. In a PC emulator such as DOSBox both versions are fully visible.

5.2.4INT 16h: keyboard services

5.2.4.1Scan code and ASCII

When a key is pressed, the controller inside the keyboard sends a number that indicates the key's place on the keyboard. On the PC this number is read from I/O port 60h and, through the interrupt controller, gives rise to the IRQ 1 hardware interrupt. The BIOS keyboard interrupt routine (INT 09h) takes this number and finds its ASCII equivalent by looking at the state of Shift and Caps Lock. It then writes the two together as a word into the keyboard buffer in memory. The program reads keys from this buffer with INT 16h. This way keys pressed while the program is busy are not lost; they wait in line in the buffer.

Definition 5.2.5

The scan code is the code that indicates the physical position of the key pressed on the keyboard. The same key gives the same scan code whether or not Shift is held: 1Eh for 'a' and 'A'. The ASCII code, on the other hand, indicates the key's current meaning, that is, the character produced: 61h for 'a', 41h for 'A'.

5.2.4.2Code trace: read a key, print it in uppercase

The following program reads keys until Enter is pressed. It converts lowercase letters to uppercase and writes them, and writes other characters as they are. The program uses together the fact that INT 16h does not echo and the bit 5 rule of the ASCII layout.

org 100h
read:
mov ah, 0        ; wait for key
int 16h          ; AH=scan, AL=ASCII
cmp al, 0Dh      ; Enter?
je done
cmp al, 'a'
jb echo
cmp al, 'z'
ja echo
sub al, 20h      ; lower → upper
echo:
mov ah, 0Eh

done:
ret

The loop starts at the read label. INT 16h waits for a key. CMP AL, 0Dh checks for Enter; if equal, JE ends the program. Then two comparisons test whether AL is in the range 'a'–'z'. JB and JA are unsigned comparison jumps: JB jumps when CF = 1; JA jumps when CF = 0 and ZF = 0. If AL is below 'a' or above 'z', it is not a letter, so control goes straight to echo. If it is inside the range, SUB AL, 20h clears bit 5. The echo part writes the character with teletype and the loop returns to the start.

5.2.4.3Polling without waiting

AH = 00h stops the program until a key arrives. A game or an animation, however, must keep working while it waits for a key. For this AH = 01h is used: the service returns at once and reports with ZF whether there is a key. If ZF = 1 there is no key in the buffer. If ZF = 0 there is a key and it is in AX, but it is not removed from the buffer. To actually take the key, the program then calls AH = 00h. Asking about the state of a device again and again in a loop is called polling.

org 100h
xor dx, dx       ; work counter
poll:
inc dx           ; background work
mov ah, 01h      ; key ready?
int 16h          ; ZF=1 → none
jz poll
mov ah, 00h      ; take the key
int 16h
ret

DX stands for the work done while waiting; it increases by one on each iteration. In a real program an animation frame would be drawn here or a calculation advanced. In the trace there is no key at the first two polls, and at the third the user has pressed the x key.

Common mistake

Seeing the key with 01h and not taking it with 00h. Because 01h does not remove the key from the buffer, the same key still looks "available" on the next iteration of the loop; the program reacts to a single key endlessly. After responding to the key, the buffer is emptied with AH = 00h.

5.2.5.4Code trace: printing a string

Definition 5.2.6

5.2.5.5Buffered line input

Getting a name or a number from the user takes more than reading keys one by one. When the user types something wrong they erase it with Backspace, and when they press Enter the line is finished. AH = 0Ah has DOS do this editing. The program only prepares a buffer and puts its address in DS:DX. DOS reads keys until Enter is pressed, echoes them, and allows correction with Backspace and Esc. The program does not run in the meantime; the call returns when the line is finished.

Definition 5.2.7

The 0Ah buffer has three parts. In byte 0 the program writes the capacity: the maximum number of characters to be accepted, Enter included. In byte 1 DOS writes the number of characters read (Enter is not counted). The text begins at byte 2 and the code of Enter, 0Dh, is appended to its end. The capacity cannot be 0.

Figure 5.2.12 shows the state after Ali is typed and Enter is pressed in a buffer defined as buffer db 10, ?, 10 dup(?). Byte 0 = 0Ah (10 characters), byte 1 = 03h, then 'A', 'l', 'i' and 0Dh. The text does not end with '$'; to print it with 09h, the program puts '$' in place of 0Dh. When the buffer is full, DOS does not accept further keys and the bell rings; only Enter and Backspace keep working.

Not setting the first byte of the buffer, or reading the text from buffer+0. If the capacity is left 0, the service behaves unpredictably. The text always starts at buffer+2; buffer+0 and buffer+1 are numbers, and if they are written to the screen meaningless characters appear.

5.2.6Date and time

Example 5.2.6

AAM runs with AL = 23h (35): 35 ÷ 10 = 3, remainder 5. AH = 03h, AL = 05h, that is AX = 0305h. ADD AX, 3030h converts both bytes to ASCII at once: AX = 3335h, AH = '3', AL = '5'. When AH and then AL are written, 35 appears on the screen. For AL = 07h, AX = 0007h → 3037h, and 07 appears on the screen: AAM adds the leading zero to single-digit values by itself.

5.2.7INT 1Ah and the BIOS data area

5.2.7.1The tick counter and the real-time clock

On the PC two separate pieces of hardware keep time. The first is the 8253/8254 programmable timer. Channel 0 divides a 1,193,182 Hz clock by 65,536 and produces the IRQ 0 interrupt about 18.2 times per second. The BIOS routine attached to this interrupt (INT 08h) increments a counter in memory each time. This counter is called the tick counter; it holds the number of ticks since midnight. Because the counter is in memory, it is lost when the computer is switched off.

The second, found in the AT and later computers, is the real-time clock (RTC). The RTC is a battery-powered CMOS chip and keeps running while the computer is off. It keeps the hour, minute, second and date in its own registers as BCD; they are read through I/O ports 70h and 71h. At boot, DOS gets its time from the RTC and then advances it with the tick counter. INT 1Ah offers a BIOS interface to both clocks.

Definition 5.2.8

Packed BCD (packed binary-coded decimal) is a representation that puts two decimal digits in one byte: the high four bits (the high nibble) hold the tens digit and the low four bits the ones digit. The minute 35 is stored in packed BCD as 35h = 0011 0101b; in binary it is 23h = 0010 0011b.

The benefit of BCD is that the hexadecimal notation directly shows the decimal value: 35h reads as "thirty-five". No division is needed to write it on the screen; the two nibbles are separated and 30h is added to each. The high nibble is separated by shifting four bits to the right, the low nibble by masking with 0Fh. The 8086 has no constant shift count greater than 1; the shift count is given in CL.

5.2.7.3The BIOS data area

The BIOS keeps the state of the hardware at a fixed place in memory: in segment 0040h, physically in the area starting at 00400h. This area is called the BIOS data area. 5.2.7.4Waiting with the tick counter

The tick counter is a ready-made clock for short waits. The program reads the starting value and then waits in a loop until the counter has advanced by the desired amount. The code below also tests Caps Lock in the keyboard flags and checks whether there is a key waiting in the buffer.

; wait about 1 second
mov ax, 0040h
mov es, ax
mov bx, es:[006Ch]   ; starting tick
wait1:
mov ax, es:[006Ch]   ; current tick
sub ax, bx           ; ticks elapsed
cmp ax, 18           ; 18 ticks ≈ 0.99 s
jb wait1
; Caps Lock on? Any key waiting?
test byte ptr es:[0017h], 40h
jnz caps_on          ; bit 6 = 1
mov ax, es:[001Ah]   ; buffer head
cmp ax, es:[001Ch]   ; buffer tail
je buf_empty

Common mistake

Adding the wait time to the start value and looking for the counter to equal the resulting end value: cmp ax, target / jne wait1. The counter can pass the target at a moment when the loop does not read it in that very iteration, and the loop then runs until the next wraparound. It is safe to take a difference and ask "has at least this much passed?" with JB.

5.2.8Program termination

5.2.8.1Three ways and the exit code

When a program has finished its work, it must give control back to DOS. The processor knows nothing of an "end of the program"; it always executes the byte IP points to as an instruction. If the termination instruction is forgotten, the processor runs the bytes after the program, often the program's data, as instructions. The result is unpredictable: garbage may be printed on the screen, the system may lock up. DOS offers three ways to end a program (Table 5.2.32).

Definition 5.2.9

The PSP (Program Segment Prefix) is the 256-byte area DOS places in front of every program. The command line, the address of the environment variables and return information are kept here. Its first two bytes are CD 20, that is the INT 20h instruction. Because COM programs are loaded right after the PSP, the code begins at ORG 100h.

Why RET ends a COM program can be understood from the stack. When DOS starts a COM program, it sets SP to FFFEh and puts the word 0000h there. If the program has left the stack balanced, that is, every PUSH has been followed by a POP and every CALL by a RET, the last RET loads this 0000h into IP. CS is still the program's segment and CS:0000h is the start of the PSP. There INT 20h runs and the program ends. If an extra word is left on the stack, RET takes that word for an address and jumps to some random place.

The recommended way is INT 21h/4Ch. It works in both COM and EXE programs, does not depend on the value of CS, and gives DOS an exit code. The exit code is in AL: 0 means success, nonzero values mean an error. A batch file (.BAT) can test this code with IF ERRORLEVEL 1 and take different paths.

5.2.8.2COM and EXE templates

emu8086 offers two templates for a new program. In the COM template code, data and stack are in a single 64 KB segment. In the EXE template each sits in a separate segment.

org 100h

Before accessing the data segment, the program must set DS itself: mov ax, @data and mov ds, ax. @data is the segment value of the data segment; DOS fills in this value at load time.

5.2.9Application: printing the result in binary

5.2.9.1The program

The program in this part combines many services with a small calculation. First 5 + 10 − 1 = 14 is computed and the result is written to BL. Then the eight bits of BL, starting from the most significant bit (MSB), are printed on the screen one by one as the character '0' or '1'. At the end the binary suffix 'b' is written and a key press is awaited. The expected output is 00001110b.

org 100h

; 15 - 1 = 14 = 0Eh = 00001110b

; print the binary suffix b
mov dl, 'b'
int 21h
; wait for a key press

int 16h

The number does not need to be "made binary" in memory or in a register; it is binary already. Printing means converting each bit to an ASCII character: 30h for a 0 bit, 31h for a 1 bit. On each iteration the loop looks at bit 7, writes the character, and shifts the number one bit left. The next bit thus takes the place of bit 7. After eight iterations all the bits have been written from left to right.

5.2.9.2Reading bits with TEST and SHL

TEST BL, 10000000b ANDs BL with the mask bit by bit but writes the result nowhere; it only sets the flags. The mask has a single 1 bit, at bit 7. If bit 7 of BL is 0 the AND result is 0 and ZF = 1 is set. If bit 7 = 1 the result is 80h and ZF = 0. JZ jumps when ZF = 1. TEST also always clears CF and OF.

SHL BL, 1 shifts all the bits one place left. The bit that leaves from bit 7 goes to CF and a 0 enters at bit 0. The next bit is now in the place of bit 7. Because TEST does not store its result, it does not spoil BL; the only instruction that changes it, deliberately, is SHL.

The same job can also be done by looking at CF after SHL: first SHL BL, 1, then JC tests whether the bit that left was 1. In this order the shift must be done before printing, because the value of the bit is now in CF, not in BL. There is also a reason for redoing MOV AH, 2 on every iteration: INT 21h/02h does not spoil AH, but if another service is added to the loop later, AH will already be protected.

int 21h
mov dl, ' '
int 21h
jmp read
done: ret
hex db '0123456789ABCDEF'

The scan code arrives in AH and is saved in DH, because AL and AH will change with the XLAT and 02h calls. XLAT performs AL ← [BX + AL]: it converts a number from 0 to 15 into the character in the table. The high digit is separated by shifting four bits right, the low digit by masking with 0Fh. When the a and 1 keys are pressed, 1E 02 appears on the screen; Esc ends the program.

Exercise 4. Write a program that prints a line read with 0Ah in reverse.

org 100h
mov dx, offset buffer
mov ah, 0Ah
int 21h            ; read a line
mov ah, 02h
mov dl, 0Ah        ; next line (Enter echoed a CR)
int 21h
mov cl, [buffer+1] ; count read
mov ch, 0
jcxz done
mov si, offset buffer+1
add si, cx         ; last character
std                ; backwards
rev:
lodsb
mov dl, al
int 21h
loop rev
cld
done: ret
buffer db 20, ?, 20 dup(?)

The text starts at buffer+2 and its length is in [buffer+1]. The last character is at address buffer + 2 + count − 1 = buffer + 1 + count; SI is set there. STD sets the direction flag and LODSB does AL ← [SI] on each iteration and decreases SI by one. Because CX = count, LOOP writes each character once. For an empty line (count 0) JCXZ never enters the loop; otherwise LOOP would take CX from 0 to FFFFh and run 65,536 iterations. At the end of the program CLD returns the direction flag to its default. When Micro is typed, orciM appears on the next line.

Exercise 5. Print the date in the format DD.MM.YYYY. What method do you use for the year?

org 100h
mov ah, 2Ah
int 21h            ; CX=year DH=month DL=day
mov bx, cx         ; save the year
mov al, dl
call print2        ; DD
mov dl, '.'
int 21h
mov al, dh
call print2        ; MM
mov dl, '.'
int 21h
mov ax, bx         ; year
mov cx, 0          ; digit counter
mov si, 10
div10:
xor dx, dx
div si             ; DX:AX / 10
push dx            ; remainder = digit
inc cx
test ax, ax
jnz div10
mov ah, 02h
emit:
pop dx
add dl, 30h
int 21h
loop emit
ret
print2:            ; AL (0-99) → 2 digits, DH preserved
push dx
aam
add ax, 3030h
push ax
mov dl, ah
mov ah, 02h
int 21h
pop ax
mov dl, al
mov ah, 02h
int 21h
pop dx
ret

Since the day and month are smaller than 99, AAM is enough; the print2 procedure preserves the month in DH on the stack. The year is a 16-bit number and cannot be split with AAM. The year is divided by 10 repeatedly: DIV SI divides DX:AX by 10, writing the quotient to AX and the remainder to DX. The remainders come out in the order ones, tens, hundreds, thousands; the order of writing is the reverse. So the remainders are pushed on the stack and then popped and written. DX is zeroed before every division, because DIV takes the dividend as DX:AX. For January 7, 2026, 07.01.2026 is written on the screen.

Exercise 6. How is the '$' character printed with mov ah, 09h / int 21h?

It cannot be printed; 09h counts the first '$' as the end of the string and does not write it. For '$' the 02h service is used: mov ah, 02h, mov dl, '$' (24h), int 21h. INT 10h/0Eh with AL = 24h does the same job.

Exercise 7. What is the offset, within segment A000h, of pixel (160, 100) in mode 13h?

100 × 320 + 160 = 32,160 = 7DA0h. The physical address is A7DA0h.

Exercise 8. INT 1Ah/02h returned DH = 59h. What is written on the screen? With what value would the same second arrive from INT 21h/2Ch?

59h is packed BCD: high nibble 5, low nibble 9; 59 is written on the screen. INT 21h/2Ch gives the second in binary: 59 = 3Bh, that is DH = 3Bh.

Exercise 9. How many ticks are needed for a wait of about 5 seconds with the tick counter at 0040:006C?

5 × 18.2065 ≈ 91 ticks. At 54.9 ms per tick, 91 ticks is 4.998 seconds.

5.2.11Summary

  • The BIOS is a set of ROM routines that drive the hardware directly; DOS, on top of it, offers file, string, clock and program services. A program reaches both with INT n, without knowing the address of the service.
  • The service-call pattern: AH ← service number, parameters in the other registers, INT n, result in registers or flags. Services change some registers: INT 21h/02h makes AL = DL, 09h makes AL = 24h.
  • A new line takes CR LF (0Dh, 0Ah). Digit = code − 30h; uppercase and lowercase letters differ in bit 5.
  • INT 10h: 00h selects the mode and clears the screen; 02h/03h set and read the cursor. 09h writes in color but does not advance the cursor; 0Eh writes teletype and advances the cursor. 13h writes the string at ES:BP of length CX; 06h scrolls or clears a window.
  • Attribute = background × 16 + foreground; bit 7 is blink. 07h is the default, 1Fh is white on blue, 4Eh is yellow on red.
  • In mode 03h the video memory is at B800:0000h; the cell is at address (row × 80 + column) × 2, with the character in the even byte and the attribute in the odd byte. In mode 13h, from A000:0000h there is one byte per pixel and the address is y × 320 + x.
  • INT 16h/00h waits for a key and gives the scan code in AH and ASCII in AL; for extended keys AL = 00h. 01h polls without waiting: ZF = 1 means no key.
  • INT 21h: 01h reads and echoes, 02h writes DL, 09h writes a '$'-terminated string, 0Ah reads a buffered line. DOS output can be redirected; BIOS output cannot.
  • The 0Ah buffer: byte 0 capacity, byte 1 number read, the text starts at byte 2 and ends with 0Dh.
  • INT 21h/2Ah and 2Ch give the date and time in binary (printed with AAM); INT 1Ah/02h gives the RTC time in packed BCD (printed with SHR and AND).
  • The BIOS data area is in segment 0040h: keyboard flags at 0017h, buffer head and tail at 001Ah and 001Ch, tick counter at 006Ch. The tick rate is 18.2065 Hz, one tick ≈ 54.9 ms.
  • A program ends with RET (only a COM program with a balanced stack), INT 20h (COM) or the recommended INT 21h/4Ch; AL is the exit code. An EXE program sets DS itself with @data.

5.2.13Test Yourself

  1. In mode 03h, with the cursor at (24, 0), INT 10h is called with AH = 09h, AL = '-', BL = 1Eh, CX = 80. What appears on the screen, and where does the cursor stay?

    Answer

    A yellow '-' on a blue background is written into all 80 cells of the last row. 09h does not advance the cursor and does not scroll the screen; the cursor stays at (24, 0). If the same row were written 80 times with 0Eh, after the last character the cursor would try to move to the next line and the screen would scroll up one line.

  2. What is the attribute byte of blinking white text on a red background?

    Answer

    Bit 7 = 1 (blink), background 100b (red), foreground 1111b (white): 1100 1111b = CFh.

  3. In mode 03h, at what offset is the character byte of the first cell (24, 0) of the last row? What is its physical address?

    Answer

    (24 × 80 + 0) × 2 = 3840 = 0F00h. The character is at B800:0F00h and the attribute at B800:0F01h. The physical address is B8000h + 0F00h = B8F00h.

  4. While reading into a buffer defined as buffer db 4, ?, 4 dup(?) with INT 21h/0Ah, the user types abcdef and presses Enter. What are the first six bytes of the buffer?

    Answer

    Because the capacity is 4 including Enter, at most 3 characters are accepted; the bell rings at d, e and f. The buffer becomes 04 03 61 62 63 0D: the capacity, the count 3, 'a', 'b', 'c' and Enter.

  5. What is AL after the instructions mov ah, 02h, mov dl, 'Z', int 21h?

    Answer

    INT 21h/02h puts DL into AL on return: AL = 5Ah ('Z'). If a value had been kept in AL before, it is lost.

  6. The time is 23:00. A program that reads the time from DOS (INT 21h/2Ch) sends CH to the routine that prints BCD (SHR/AND). What appears on the screen? What would appear if CH read from the RTC were sent to the routine that uses AAM?

    Answer

    DOS gives binary: CH = 23 = 17h. The BCD routine separates the nibbles as 1 and 7 and writes 17. The RTC gives CH = 23h; AAM counts this as binary 35 (23h = 35) and 35 is written. In both cases the correct value is 23.

  7. How many ticks are needed for a wait of about 3 seconds with the tick counter? Can a 10 ms wait be measured this way?

    Answer

    3 × 18.2065 ≈ 54.6; about 55 ticks. 10 ms cannot be measured: one tick is about 54.9 ms and the counter cannot tell apart intervals shorter than that.

  8. In mode 13h, what is the offset of pixel (200, 150)? What are the offsets of the pixels one to the right and one below?

    Answer

    150 × 320 + 200 = 48,200 = BC48h. The one to the right, (201, 150), is at BC49h; the one below, (200, 151), is at BC48h + 140h = BD88h.

  9. In the BIOS data area the buffer head is read as 003Ch and the buffer tail as 0020h. How many keys are waiting?

    Answer

    Because the buffer is circular, the tail may have fallen behind the head. From the head to the end of the area (003Ch–003Dh) there is one word, and from the start of the area to the tail (001Eh–001Fh) one word: 2 keys. The general formula is (tail − head + 32) mod 32, divided by 2: (20h − 3Ch + 20h) = 4 bytes.

  10. An EXE program ends with RET instead of MOV AX, 4C00h · INT 21h. What happens?

    Answer

    There is no 0000h word placed by DOS on the EXE's stack and CS does not point to the PSP. RET loads whatever it finds at the top of the stack into IP and jumps to a random address in the code segment. The program may lock up. An EXE program is ended with INT 21h/4Ch.
