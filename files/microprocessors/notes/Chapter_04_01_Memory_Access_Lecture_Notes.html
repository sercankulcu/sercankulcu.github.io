Chapter 4.1: Memory Access

Most of what an 8086 program does is to bring a value from memory into a register or to put a value in a register back into memory. Addition, comparison, printing text on the screen, and walking through an array cannot be done without these moves. Which byte in memory the processor reaches is decided by the square brackets inside the instruction. These notes describe what may be written inside the square brackets, that is, the addressing modes. From the base and index registers and a displacement, an effective address is computed. The effective address combines with a segment register and becomes the 20-bit physical address put on the address bus. Which segment is chosen can send the same relative location to an entirely different byte. The notes do this calculation in both directions and show how a segment override changes the default segment. Next come the size of an access (byte or word), byte order, and the rules of the MOV and XCHG instructions. Example programs are traced step by step at the register and memory level; the last example writes a letter directly into the memory of the color text screen.

4.1.1Memory operands

4.1.1.1Square brackets and address registers

The 8086 has fourteen registers, and only eight of them are used for general work. A program's data, on the other hand, mostly sits in memory: variables, arrays, tables, the contents of the screen, the stack. To work with this data the processor goes to memory every time, reads the byte or word it wants, and writes the result back to memory when it is done. So the first step in learning an instruction set is learning how an instruction says which memory cell it means.

In assembly language a memory cell is denoted with square brackets. The instruction MOV AX, BX copies the number in BX into AX. The instruction MOV AX, [BX], on the other hand, uses the number in BX as an address; it reads the word at that address from memory and puts it into AX. The square brackets mean “the place pointed to by what is inside.” Compared with pointer notation in C, BX is the pointer itself and [BX] is like *p.

On the 8086 not every register can be written inside square brackets. Only four registers can hold a memory address: BX, BP, SI, and DI. Of these, BX and BP are called base registers and SI and DI index registers. A base register usually holds the start address of a block of data, for example an array or a record. An index register counts the position within this block. A constant number written in the instruction can also be added to these four registers. The constant is called the displacement.

The source of this restriction is the hardware. In the instruction's machine code, only a three-bit field tells how the memory operand is to be computed. Three bits mean eight options, and the designers of the 8086 allotted these eight options to the most useful combinations of BX, BP, SI, and DI. AX, CX, DX, and SP are not on this list. That is why, however natural a notation such as MOV AL, [CX] may look, the assembler rejects it; the processor has no circuit to produce such an address.

Definition 4.1.1

The rule that determines where an instruction's operand is found and how its address is computed is called the addressing mode. On the 8086 the address of a memory operand is written inside square brackets. The address is the sum of three parts: a base register (BX or BP), an index register (SI or DI), and a displacement. Each of these three parts is optional, but at least one must be present.

The eight rows of the table correspond to the eight values of the three-bit field in the machine code. This field is called R/M and sits in the lowest three bits of the instruction's second byte, the ModR/M byte. The highest two bits of the same byte are the MOD field; it selects which column of the table is used. MOD = 00 means no displacement, MOD = 01 means d8 is present, and MOD = 10 means d16 is present. MOD = 11 shows that the operand is not memory but a register. Three columns times eight rows make 24; all the memory addressing forms of the 8086 are in these 24 cells.

One row looks odd. The first cell of the seventh row does not have [BP]; in its place is d16, that is, only a constant address. The designers allotted the combination R/M = 110 and MOD = 00 to direct addressing: the address of an instruction such as MOV AL, [1234h] is written with this code. No code was left for [BP] without a displacement. If the programmer writes MOV AL, [BP], the assembler quietly encodes it as [BP + 0], that is, with MOD = 01 and d8 = 00. The instruction grows by a byte but works correctly. Table 4.1.2 shows the machine code the assembler produces for a few instructions.

The opcode 8A in the table means “move a byte from memory or a register to an 8-bit register.” The middle three bits of the ModR/M byte (the REG field) select the destination register: 000 for AL, 001 for CL. The address is written low byte first, like all multi-byte numbers on the 8086: 34 12. If an instruction with a direct address loads into AL or AX, the assembler chooses a shorter special form: MOV AL, [1234h] is encoded in three bytes as A0 34 12.

4.1.1.3The combination rule

The structure of the table can be reduced to a few simple rules. Once these rules are memorized, you can tell whether a notation is valid without looking at the table. Figure 4.1.1 shows the rule as a three-column choice: at most one item is taken from each column.

Definition 4.1.2

The combination rule. A memory operand contains at most one base register (BX or BP) and at most one index register (SI or DI). At most one displacement is added to them. BX and BP, or SI and DI, cannot be used together in the same address. The order in which the parts are written does not matter.

The default segment rule. If BP is in the address, the access goes to the SS (stack) segment; otherwise to the DS (data) segment.

The essence of the segment concept is this: the 8086 sees memory through 64 KB windows, and a segment register tells on every access which window to use. DS is used for data and SS for the stack. Since BP was designed to access data on the stack, addresses built with it automatically go to the SS window. The four examples in the slides apply these rules:

  • [BX+5]: base + d8. No BP, segment DS.
  • [BX+SI]: base + index. Segment DS.
  • [DI+BX-4]: the assembler reads this as [BX+DI-4]. The order does not matter; the machine code is 8A 41 FC. Here FC is the 8-bit two's complement of −4. Segment DS.
  • [BP+SI+300]: base + index + d16. Since 300 does not fit in the range −128…127, a 16-bit displacement is needed. Since BP is in the address, the segment is SS.

4.1.1.4Displacement

The displacement is a signed constant added to the address calculation and held inside the instruction's machine code. Its 8-bit form (d8) carries values between −128 and +127, and its 16-bit form (d16) values between −32,768 and +32,767. Because in 16-bit addition −1 and FFFFh give the same result, d16 actually covers the whole range 0000h–FFFFh. Example values: for d8, 22, 55h, −1; for d16, 300, 5517h, −259.

The source of the displacement is either a number or the relative location of a variable. When [BX + arr] is written, the assembler puts the address of the name arr within the segment, that is, its relative location, as the displacement. If the notation contains more than one constant, the assembler adds them into a single number at assembly time: [BX + 2 + 3] is the same instruction as [BX + 5]. The constant can be written inside or outside the square brackets; the notations [BX+5], 5[BX], and [BX]+5 all produce the bytes 8A 47 05. The C-like notation arr[SI] comes from this flexibility. The constant can also be negative: the instruction [SI-1] accesses the byte one before the one SI points to and is encoded as 8A 44 FF.

The assembler decides which of the two forms to choose by looking at the value. If the value is in the range −128…127, the short form (d8) is chosen and the instruction is a byte shorter. Otherwise the long form (d16) is needed. [BX+127] is three bytes (8A 47 7F) and [BX+128] is four bytes (8A 87 80 00). The number 128 fits in 8 bits but would be read as −128 when signed; that is why the 16-bit form is used. Since the relative location of variable names is usually greater than 127, notations such as arr[SI] almost always use d16.

The processor performs sign extension on an 8-bit displacement before adding it to 16-bit registers. If the highest bit is 1, the upper byte is filled with FFh, and if 0, with 00h (Figure 4.1.2). FC thus becomes FFFCh. Adding FFFCh to a number is the same as subtracting 4 once the carry that overflows the 16-bit limit is discarded.

This last point is a general property of address calculation. The effective address is always computed in 16 bits, and if the result does not fit in 16 bits, the overflowing bit is discarded; the address wraps around. With BX = FFFFh, the access [BX+2] goes not to 10001h but to 0001h. The 8086 does not carry an address overflowing the end of a segment into the next segment; it returns it to the start of the same segment.

Example 4.1.1

With SI = 0010h, from which relative location does the instruction MOV AL, [SI+0FFF8h] read?

The addition gives 0010h + FFF8h = 1 0008h. The 17th bit of the result is discarded and the effective address is 0008h. FFF8h is the 16-bit two's complement of −8; the instruction actually goes to the same place as [SI-8]. The assembler notices this too and chooses the short form: both notations produce the bytes 8A 44 F8. The processor turns the byte F8 back into FFF8h by sign extension.

Common mistake

Falling into the forbidden combination when wanting to use the sum of two registers as an address. MOV AX, [SI+DI] is invalid. If one of the two index registers is first copied to a base register, the job is done: MOV BX, SI followed by MOV AX, [BX+DI]. The same route works for [BX+BP]: one of BP or BX is transferred to SI or DI. In the copy, which register is chosen can also change the default segment; an address with BP goes to SS.

4.1.2Types of addressing modes

4.1.2.1Where does the operand live?

The twenty-four combinations cover all the cases where the operand is in memory. But an instruction's operand does not have to be in memory. A constant can be written directly into the instruction, or the operand can sit in a register. Books therefore name the addressing modes according to the question “where is the operand?” Table 4.1.4 gives the classification in the slides.

Table 4.1.4: Types of addressing modes for data operands. The last column shows that in modes without BP the default segment is DS.

DirectMOV AX, [1000h]DS:1000h
Register indirectMOV AX, [BX]DS:BX
BasedMOV AX, [BP+4]SS:BP+4

In immediate mode the operand is the instruction itself. The machine code of MOV AX, 5 is B8 05 00; the number 5 sits in the last two bytes of the instruction. The processor has already read this value while fetching the instruction and does not go to memory a second time. An immediate value can only be a source. Since nothing can be written into a constant, MOV 5, AX is meaningless.

In register mode the operand is inside the processor. The instruction MOV AX, BX completes inside the execution unit without ever going out onto the data bus. It is therefore the fastest mode; on the 8086 it takes 2 clock periods. It is selected by writing MOD = 11 in the ModR/M byte: MOV AX, BX = 8B C3, that is, the bits C3 = 11 000 011.

All the remaining modes go to memory. In these the processor first computes an effective address (EA). The effective address is the operand's location within the segment, that is, a relative location. Then this relative location is combined with the segment register:

physical address = segment × 10h + EA

The names of the modes describe how the effective address is built. In direct mode the EA is the 16-bit constant inside the instruction. In register indirect mode the EA is the contents of a register (BX, BP, SI, or DI). In based mode the EA is the sum of BX or BP and a displacement. In indexed mode SI or DI is used instead of the base. In based-indexed mode a base and an index are added, and an optional displacement is added to that. Naming differs slightly among books. Some call [BX+4] “register relative,” others “based.” But the calculation is the same everywhere.

Definition 4.1.3

The effective address (EA) is, for a memory operand, the 16-bit sum of the base register, index register, and displacement in square brackets. If the sum exceeds FFFFh, the overflowing bit is discarded. The EA is the relative location within the segment. The physical address is the 20-bit address obtained by adding the EA to 16 times the chosen segment register.

4.1.2.2String, I/O, and relative modes

There are three more modes. They do not use the square-bracket notation. The operand is either not written in the instruction at all, or it lives in an address space separate from memory, or the address is computed relative to IP.

In string mode the operands are implicit. The instruction MOVSB moves a byte from address DS:SI to address ES:DI with no operand written beside it. The source is always DS:SI and the destination always ES:DI. After each operation SI and DI advance automatically. They increase if the direction flag DF = 0 and decrease if DF = 1. The step is 1 for a byte operation and 2 for a word operation. The details of string instructions are a separate topic. What matters here is that in these instructions the address calculation has the same structure as register indirect mode, and that the destination is looked for in the ES segment, not DS.

MOVSB           ; ES:[DI] ← DS:[SI], then SI and DI advance by one

In I/O mode the operand is an input/output port. The 8086's ports live in their own 64 K address space, separate from memory. When the processor accesses a port, it puts the port number on the address bus and makes the M/IO̅ line 0. Thus I/O devices, not memory chips, respond. Data passes only through AL or AX. If the port number is in the range 0–255, it can be written inside the instruction. Larger numbers are put in DX.

IN  AL, 45h      ; read a byte from port 45h
OUT DX, AX       ; write AX to the port in DX

In relative mode the instruction holds not the target itself but a signed displacement to be added to IP. Jump instructions use this mode. The new IP is the sum of the address of the instruction right after the jump and the displacement. In short jumps the displacement is 8 bits and reaches the range −128…+127 bytes. For example, a JNZ again at the end of a loop can be encoded as 75 FA. FA is the 8-bit two's complement of −6. Since the instruction is two bytes, the jump goes 4 bytes back from the start of the instruction. Relative addressing has a big advantage: even if the program is moved elsewhere in memory, the displacements do not change.

JNZ again       ; 75 FA: IP ← address of the next instruction − 6
Common mistake

Carrying the notation of other processors over to the 8086. Instruction names are written joined: MOVSB is correct, MOVS B is not. In the OUT instruction the port comes first and then the data register: OUT 50h, AL. The notation IN A, 45 belongs to the 8085 processor. On the 8086 the accumulator is called AL or AX, and hexadecimal numbers are written with the h suffix.

4.1.2.3Code trace: six addressing modes

The small COM program below reads values from the same six-byte table with different modes. The result of each step is given in the trace table.

ORG 100h
MOV BX, OFFSET table
MOV SI, 2

MOV AL, [table+1]  ; direct
MOV CL, [BX]       ; indirect

The line ORG 100h tells the assembler that the program will start at relative location 0100h. In COM programs code, data, and stack are in the same 64 KB segment. emu8086 loads this segment at paragraph 0700h: CS = DS = ES = SS = 0700h. Adding up the instruction lengths, RET falls at 0115h and table at 0116h. The six bytes of the table are at relative locations 0116h–011Bh; their physical addresses are 07116h–0711Bh.

The OFFSET operator in the line MOV BX, OFFSET table gives not the contents of the variable but its relative location. This value is known at assembly time and is written into the instruction as an immediate value: BB 16 01. As a result BX = 0116h. BX is now a pointer to the start of the table. MOV SI, 2 puts 2 into the index register.

Read one by one, the difference of each mode is plain. MOV AH, 7 is immediate mode: the number 7 is the second byte of the instruction B4 07, and memory is not visited separately. MOV AL, [table+1] is direct mode. The assembler computes the expression table+1 as 0116h + 1 = 0117h and embeds this address in the instruction. The instruction takes its short accumulator form, A0 17 01. The byte at 0117h is 22h, the second element of the table. Since AH was set to 07h earlier, AX = 0722h.

MOV CL, [BX] is register indirect mode. The address is not written in the instruction; the processor takes it from BX at run time. EA = 0116h and the byte read is 11h. MOV CH, [BX+4] is based mode: EA = 0116h + 4 = 011Ah, and the value read is 55h, the fifth element of the table. CX = 5511h. The difference between these two instructions is the addition of a constant offset. When accessing the fields of a record, BX holds the start of the record and the displacement the position of the field within the record.

MOV DL, [BX+SI] is based-indexed mode: EA = 0116h + 0002h = 0118h, DL = 33h. The last instruction adds an 8-bit displacement to that: EA = 0116h + 2 + 3 = 011Bh, DH = 66h. Since BP is used in none of these six accesses, the segment is always DS. The physical address is found as DS × 10h + EA = 07000h + EA.

The final state of the program is AX = 0722h, BX = 0116h, CX = 5511h, DX = 6633h, SI = 0002h. RET pulls the value 0000h from the stack and IP = 0000h. At relative location 0000h of the segment where the COM program was loaded sits the INT 20h instruction placed by DOS, and the program ends. Since the MOV instructions do not change the flags, the flags stay as at the start throughout the trace: only IF = 1.

4.1.3Effective address calculation

4.1.3.1Step by step: with DS

The effective address calculation is done with an addition inside the execution unit (EU). The result is handed to the bus interface unit (BIU) to be combined with the segment register. The BIU's own adder shifts the segment left by 4 bits, adds the EA, and puts the 20-bit address on the lines A19–A0. These two stages can be followed with an example:

MOV AL, [BX + SI + 4]   ; DS = 1000h, BX = 0200h, SI = 0030h
  1. Take the base register BX = 0200h.
  2. Add the index register SI = 0030h: 0230h.
  3. Add the 8-bit displacement +4.
  4. EA = 0200h + 0030h + 0004h = 0234h. The addition is 16-bit; there is no overflow here.
  5. Since BP is not in the address, the segment is DS. Physical address = 1000h × 10h + 0234h = 10000h + 0234h = 10234h. AL takes the byte at this address.

Multiplying the segment by 10h means appending a zero on the right in hexadecimal: 1000h → 10000h. In binary, this means shifting the 16-bit number left by 4 bits and putting 0 into the lowest four bits. The physical address is therefore easy to compute: write a 0 after the segment, write the EA right-aligned beneath it, and add the two numbers.

4.1.3.2Step by step: with BP

If BP is in the address, the same calculation is done with the SS segment. The second example in the slides reads a word and uses a negative displacement:

MOV AX, [BP + DI - 2]   ; SS = 2000h, BP = 0100h, DI = 0010h
  1. Take the base register BP = 0100h.
  2. Add the index register DI = 0010h: 0110h.
  3. The displacement is −2; it sits in the machine code as the byte FE and becomes FFFEh by sign extension.
  4. EA = 0100h + 0010h + FFFEh = 1 010Eh → 010Eh. The overflowing bit is discarded; the result is the same as 0110h − 2.
  5. Because BP is used, the segment is SS: 20000h + 010Eh = 2010Eh. Since AX is a word, two bytes are read: AL ← [2010Eh], AH ← [2010Fh].

The machine code of this instruction is 8B 43 FE. The ModR/M byte 43 = 01 000 011: MOD = 01 (d8 present), REG = 000 (AX), R/M = 011 ([BP+DI]). “SS” is not written anywhere in the instruction. The segment choice comes from the R/M field itself: if the R/M value is a combination that contains BP, the hardware selects SS, otherwise DS.

Reading a word has a subtlety on the data-bus side. The 8086's data bus is 16 bits, but memory is addressed byte by byte. The two bytes of a word at an even address arrive together in a single bus cycle. Since 2010Eh in this example is even, the read is a single cycle. Had the word started at an odd address, for example at 2010Fh, the processor would first have read the low byte from the high half of the bus and then, in a separate cycle, the high byte from the low half of the bus. The result is the same, but the access is one bus cycle, that is, at least 4 clock periods, longer. That is why assemblers have the EVEN directive, which aligns word variables to even addresses.

4.1.3.3The effective address calculator

The calculator in the slides performs the same calculation interactively. From the base column you choose BX, BP, or none; from the index column SI, DI, or none; and you enter a displacement. Register and segment values can be written in hexadecimal, and the displacement in decimal (−2) or hexadecimal (1Ah). For a valid combination the tool gives the EA, the default segment, and the physical address. It is suitable for checking a calculation done by hand. On paper the same calculation rests on three rules: do the addition in 16 bits, choose SS if BP is present, and multiply the segment by 10h.

Example 4.1.2

DS = 3000h, SS = 4000h, BX = 0010h, BP = FFFEh, SI = 0005h. What are the effective and physical addresses of the operands [BX+SI+20h] and [BP+4]?

The first operand has no BP. EA = 0010h + 0005h + 0020h = 0035h, segment DS: 30000h + 0035h = 30035h.

For the second operand, EA = FFFEh + 0004h = 1 0002h. The 17th bit is discarded and EA = 0002h. Since BP is present, the segment is SS: 40000h + 0002h = 40002h. Without the wraparound the address would have come out as 50002h. This value is outside the SS segment, and the 8086 does not produce such an address.

4.1.4Segment and offset

4.1.4.1From segment:offset to the physical address

The 8086's address bus has 20 lines: A19–A0. With 20 bits, 220 = 1,048,576 different bytes, that is, 1 MB, can be addressed. The processor's registers, however, are 16 bits, and a single register can span only a 64 KB area. The designers solved this mismatch by combining two 16-bit numbers. The first number says which block of memory is used, and the second the position within that block.

Definition 4.1.4

The value in a segment register (CS, DS, SS, ES) is called the segment. An address that comes from the effective address calculation or from a register such as IP or SP is called the offset. An address is written in the form segment:offset. The physical address is found with

physical address = segment × 10h + offset

The segment points to a block of memory starting on a 16-byte boundary, and the offset to the byte within that block.

In the example in the slides, DS = 1234h and SI = 7890h. The address is written 1234:7890. The calculation is done in four steps (Figure 4.1.7):

  1. Take the segment and the offset: 1234h and 7890h.
  2. Multiply the segment by 10h, that is, shift it left 4 bits: 12340h. In hexadecimal notation this is appending a 0 on the right.
  3. Right-align the offset to enter the addition: 07890h.
  4. Add the two numbers: 12340h + 07890h = 19BD0h.

Adding digit by digit gives 0 + 0 = 0, 4 + 9 = 13 = Dh, 3 + 8 = 11 = Bh, 2 + 7 = 9, 1 + 0 = 1. Since no digit produces a carry, the result is easy to read. An example with carries is the pair 1A5D:FFF3. In the calculation 1A5D0h + 0FFF3h, start from the right: 0 + 3 = 3; D + F = 13 + 15 = 28 = 1Ch, write C in the digit and carry 1; 5 + F + 1 = 21 = 15h, write 5 in the digit; A + F + 1 = 26 = 1Ah, write A in the digit; 1 + 0 + 1 = 2. The result is 2A5C3h. In hexadecimal addition, if a digit exceeds 15, 16 is subtracted and a carry of 1 is passed to the next digit.

In hardware this addition is done by a separate 20-bit adder inside the BIU. The 16 bits of the segment register are fed to the upper 16 inputs of the adder, with 0 wired to the lowest 4 inputs. This wiring is the entire circuit for “multiplying by 10h”; there is no separate multiplier. The adder's output goes to the address latches and from there to the lines A19–A0. When fetching instructions, the BIU uses the same adder with CS and IP.

One consequence of multiplying the segment by 16 is that segments can begin only at addresses that are multiples of 16. This 16-byte unit is called a paragraph. The number in a segment register says at which paragraph the segment starts. Since a segment's offset is 16 bits, a segment is at most 216 = 64 KB long. Because two consecutive segment values start only 16 bytes apart, segments overlap one another. The same physical byte can be reached with many different segment:offset pairs. For example, the pairs 0700:0100, 0710:0000, and 06F0:0200 all point to address 07100h.

What happens if the sum overflows 20 bits? The sum of the pair FFFF:0010 is FFFF0h + 0010h = 100000h; 21 bits are needed. The 8086 has no 21st line, and the overflowing bit is discarded. The address wraps around to 00000h, the start of memory. Addresses from FFFF:0010 to FFFF:FFFF thus fall in the region 00000h–0FFEFh.

4.1.4.2Address lines and memory capacity

The relationship between the number of address lines and the memory size is familiar from decoders in digital design. n address lines produce 2n different binary patterns, and each pattern selects one memory location. How many bits a location holds is determined by the number of data lines:

capacity = 2n × data width

The 8086's 20 address lines select 220 = 1,048,576 locations. Since each location is a byte, the capacity is 1 MB and addresses range from 00000h to FFFFFh. The limit of a segment comes from the offset: 16 bits → 216 = 65,536 bytes = 64 KB. Table 4.1.9 gives the capacity for different numbers of lines.

In an 8086 system, chips of this kind are connected side by side to build an 8- or 16-bit data bus.

The question can also be asked the other way around: how many address lines are needed at minimum for a given capacity? For this, find the first power of 2 equal to or greater than the capacity. If memory is byte-addressed, 232 = 4 GB is not enough for 6 GB; 233 = 8 GB suffices and 33 lines are needed. For 4 KB, 212 = 4096 is exactly enough; 12 lines are needed (A0–A11).

Common mistake

Confusing bits with bytes. A chip with 20 address lines and 16 data lines holds 220 × 16 bits = 16 Mbit. That is 2 MB, not 16 MB. When writing a capacity, it must be stated clearly whether the unit is bits or bytes. The 8086's memory is byte-addressed; there, 20 lines mean 1 MB.

4.1.4.3The reverse calculation: from the physical address to segment:offset

When a physical address is given and the segment and offset are wanted, there is no single answer. Because segments overlap, many pairs give the same address. The right question is the range of values the segment register can take. In the example in the slides, address 2A5C3h is to be accessed with DS:SI.

The largest DS. This is the case where SI is smallest. DS × 10h must not exceed 2A5C3h. Taking the first four hexadecimal digits of the address gives DS = 2A5Ch. DS × 10h = 2A5C0h, leaving SI = 2A5C3h − 2A5C0h = 0003h. Had DS been 2A5Dh, 2A5D0h would already have been greater than 2A5C3h.

The smallest DS. This is the case where SI is largest. SI can be at most FFFFh. In this case DS × 10h ≥ 2A5C3h − FFFFh = 1A5C4h must hold. Dividing 1A5C4h by 10h gives 1A5C.4h. Since DS is an integer, it is rounded up: DS = 1A5Dh. Then SI = 2A5C3h − 1A5D0h = FFF3h.

How many pairs? Each time DS increases by one, the start of the segment moves ahead by 10h and, for the same address, SI decreases by 10h. DS can take any value from 1A5Dh to 2A5Ch. The number of pairs is 2A5Ch − 1A5Dh + 1 = 0FFFh + 1 = 1000h = 4096.

Such a calculation is always checked in the forward direction. 1A5Dh × 10h + FFF3h = 1A5D0h + FFF3h = 2A5C3h. 2A5Ch × 10h + 0003h = 2A5C0h + 3 = 2A5C3h. Both ends give the same physical address.

The length of the range is not the same for every address. For very small addresses, the lower bound of DS runs against 0. For example, for address 00345h, DS is at least 0000h and at most 0034h, and there are only 35h = 53 pairs. For addresses of 0FFF0h and above, the range is always 4096 pairs. This count does not take the wraparound at the 1 MB boundary into account; wrapped pairs such as FFFF:0355 also go to 00345h.

4.1.4.4The segment override prefix

The default segment rule chooses the right segment in most cases. Sometimes, however, a program wants to reach a byte outside the data segment. For this, the name of a segment register and a colon are written in front of the square brackets. This notation is called a segment override prefix.

MOV AX, 0B800h
MOV ES, AX          ; ES = video memory
MOV BX, 0
MOV AL, ES:[BX]     ; read ES:0000
MOV AL, [BX]        ; read DS:0000
MOV DL, SS:[SI]     ; read SS:SI

In machine code the prefix is a one-byte code placed in front of the instruction: ES: = 26h, CS: = 2Eh, SS: = 36h, DS: = 3Eh. When the processor reads this byte, it changes the default segment only for the instruction that follows. The prefix does not carry over to the next instruction. MOV AL, ES:[BX] thus becomes 26 8A 07: a 26 has been added in front of the code 8A 07 of the unprefixed MOV AL, [BX]. 2 clock periods are also added to the EA calculation.

A prefix is needed in three cases:

  • To access data in another segment without changing DS. Video memory is the most frequent example.
  • To access data on the stack with a register other than BP: SS:[BX].
  • To access a table in the code segment: CS:[SI]. Some programs place constant tables next to the code; even if DS points elsewhere, the table is read with CS.

Not every prefix can change every access. IP is always used with CS and SP always with SS; these pairings are wired into the hardware. Instruction fetch is done from CS:IP and stack operations (PUSH, POP, CALL, RET) from SS:SP. ES:DI, the destination of string instructions, cannot be changed either. The string source DS:SI, on the other hand, can be redirected to another segment with a prefix.

Definition 4.1.5

The default segment is the segment used in a memory access when there is no prefix. It is CS for instruction fetch (with IP), SS for stack operations (with SP), SS for addresses containing BP, ES for the string destination (with DI), and DS for all other data accesses. A segment prefix changes the default segment of data accesses only for that instruction.

Common mistake

Accessing a variable through BP, getting the right result in a COM program, and then moving the code to an EXE program. In a COM program CS = DS = SS, so [BP] and DS:[BP] go to the same byte and the error is invisible. In an EXE program with separate segments the same code reads from the stack. The error is noticed not at assembly time but when wrong values appear.

4.1.4.7Changing a segment register

The values of segment registers can be changed, but each has its own rules.

PUSH DS            ; save DS
MOV  AX, 0B800h
MOV  DS, AX        ; temporary
MOV  BYTE PTR [0], 'Z'
POP  DS            ; variables back

MOV  AX, new_stack
MOV  SS, AX        ; right after it
MOV  SP, 0400h     ; set SP

DS. Variable names in assembly are only offsets. If the program changes DS, the same name goes to a byte in another segment. The first four lines of the code temporarily set DS to B800h to write a Z in the top left corner of the screen. BYTE PTR [0] thus goes to B8000h. When the job is done, POP DS restores the old value. Had PUSH and POP not been used, all subsequent variable accesses would have gone to video memory. A safer way is to use ES without touching DS at all. ES is the default segment for no access other than the string destination.

SS and SP. The two change together. After SS is changed, SP must take a value that suits the new segment. If an interrupt came between the two instructions, the processor would push the return address to a wrong place formed by the new SS and the old SP. The 8086 prevents this in hardware: after an instruction that does a MOV or POP to a segment register, no interrupt is accepted until the next instruction finishes. That is why MOV SP, … is written right after MOV SS, AX, and the SS:SP pair is never half set.

CS. It cannot be written with MOV. If CS changes, the next instruction is fetched from an entirely different place and the old value of IP becomes meaningless. CS therefore changes together with IP: far JMP, far CALL, far RET, INT, and IRET load both at once. Reads such as MOV AX, CS, on the other hand, are free.

4.1.5Data type and byte order

4.1.5.1byte ptr and word ptr

A memory address points to a single byte. The 8086, however, can read and write a byte (8 bits) or a word (16 bits, two bytes) starting at the same address. Which one an instruction does is written in the lowest bit of the opcode, the W bit: W = 0 means byte and W = 1 means word. This is the difference between the opcodes 8A and 8B. To set this bit correctly, the assembler must know the size of the access.

In most instructions the size can be told from the other operand. In MOV [BX], AL, AL is 8 bits and a byte is written. In MOV [BX], AX, AX is 16 bits and a word is written. But in MOV [BX], 5 neither operand has a size of its own. The square brackets say only an address. The number 5 fits both in a byte (05) and in a word (05 00). The assembler cannot decide in this case. Some assemblers report an error, others guess a size. If the guess is wrong, the program silently corrupts the neighboring byte.

Definition 4.1.6

A data type specifier is the addition that tells the assembler whether a memory operand is a byte or a word. byte ptr [BX] means a one-byte access and word ptr [BX] a two-byte access. emu8086 also recognizes their short forms: b.[SI] for byte, w.[DI] for word.

The specifier is for the assembler only; the processor does not see it. MOV BYTE PTR [BX], 5 is encoded as C6 07 05 (3 bytes) and MOV WORD PTR [BX], 5 as C7 07 05 00 (4 bytes). The whole difference is the opcode's W bit (C6 → C7) and the length of the constant. Figure 4.1.11 shows reading at the same address with two different sizes.

Table 4.1.12: Where the access size is known from.

4.1.5.3Little-endian order

In the previous trace we saw that words sit “reversed” in memory: 1234h was stored in memory as 34 12. This is not a coincidence but the 8086's byte-order rule.

Definition 4.1.7

The order that writes the low byte of a multi-byte value to the low address and the high byte to the next address is called little-endian (low byte first). Conversely, the order that writes the high byte first is big-endian. The 8086 and the entire x86 family are little-endian.

The counterpart of the rule at the register level is very tidy. The instruction MOV [0200h], AX writes AL to 0200h and AH to 0201h. MOV AX, [0200h] does the opposite: the byte at 0200h goes to AL and the one at 0201h to AH. The low half of a register always matches the low address. One benefit of little-endian arises from this. If a byte is read from the address of a word variable, the low byte arrives. A small number such as 0034h gives the same value at the same address whether read as a word or as a byte.

The emu8086 memory window shows bytes in address order. That is why words look reversed in the window: 1234h → 34 12. The rule also applies to constants in machine code. MOV AX, 1234h is encoded as B8 34 12 and MOV AX, 0B800h as B8 00 B8. Addresses obey the same rule: MOV AX, [1000h] = A1 00 10.

Common mistake

Reading a memory dump left to right and assembling the word that way. If 0200h holds 34h and 0201h holds 12h, then after MOV AX, [0200h] AX = 1234h, not 3412h. The low address is the low byte. The same misreading is made when reading machine code: the address in the instruction A1 00 10 is 1000h, not 0010h.

4.1.5.4Code trace: index in a word array

When byte order and byte addressing come together, a common mistake appears. To reach the i-th element of a word array, 2i, not i, must be put in the index register. The program below follows first the wrong and then the right way.

org 100h
mov si, 1            ; index 1
mov ax, arr[si]      ; BUG!
shl si, 1            ; index × 2
mov bx, arr[si]      ; arr[1]
mov si, 2            ; index 2
shl si, 1            ; SI = 4
mov cx, arr[si]      ; arr[2]
ret
arr dw 1234h, 5678h, 9ABCh

Adding up the instruction lengths, arr starts at 0117h. The three words are laid out in memory in little-endian as 34 12 78 56 BC 9A between 0117h and 011Ch. arr[0] = 1234h is at 0117h, arr[1] = 5678h at 0119h, and arr[2] = 9ABCh at 011Bh.

By the little-endian rule, the 12h at 0118h goes to AL and the 78h at 0119h to AH: AX = 7812h. This value is not any element of the array. The shl si, 1 in step 3 shifts SI left by one bit, that is, multiplies by 2: SI = 2. In a word array the byte offset is index × 2. In step 4, EA = 0119h and BX = 5678h = arr[1] arrives correctly. Steps 5 and 6 do the same job for index 2: SI = 2, then 4. In step 7, EA = 011Bh and CX = 9ABCh = arr[2]. Shifting is the shortest and fastest way to multiply by 2; D1 E6 is a two-byte instruction.

Unlike MOV, the shl instruction also updates the flags. Shifting 1 by one bit gives 2; since the bit shifted out is 0, CF = 0, and since the result is nonzero, ZF = 0. The auxiliary carry flag AF is undefined after shift instructions. When walking a word array with a loop, SI is advanced on each iteration with ADD SI, 2. INC SI is only for byte arrays.

4.1.6The MOV instruction

4.1.6.1Definition and rules

MOV, used in all the previous examples, is the 8086's most frequently used instruction. A significant part of the code that compilers produce consists only of MOVs.

Definition 4.1.8

The instruction MOV destination, source copies the value in the source to the destination. The source does not change. The source can be an immediate value (a constant), a general-purpose register, a segment register, or a memory location. The destination is a general-purpose register, a segment register (except CS), or a memory location.

The rules of MOV are gathered in five points:

  1. No value is assigned to CS and IP with MOV. CS can be read as a source; IP does not appear in any MOV.
  2. The two operands must be the same size: both bytes or both words.
  3. The two operands cannot both be memory.
  4. An immediate value cannot be loaded into a segment register, and one segment register cannot be copied directly to another.
  5. MOV does not affect the flags.

Most of the rules come from the structure of the machine code. A MOV instruction contains at most one ModR/M byte, and this byte can define only one memory operand. The second operand is a register in the REG field or a constant at the end of the instruction. There is no room for two memory operands. Segment registers have separate opcodes: 8E moves to a segment register and 8C from one. Their second operand is always a general register or a memory word selected by ModR/M. That is why there is no instruction from segment to segment or from a constant to a segment.

That the flags do not change is also a deliberate choice. After a comparison, a value may need to be brought into a register before the conditional jump. If MOV disturbed the flags, the result of the comparison would be lost.

The two examples in the slides apply the rules. MOV AX, BX copies the value in BX to AX; BX does not change. MOV [SI], 10h, on the other hand, wants to write 10h to the address DS:SI that SI points to. The destination is a memory location, the source is a constant, and the size is ambiguous. The correct notation is MOV BYTE PTR [SI], 10h.

4.1.7Example program: printing an 'A' on the screen

4.1.7.1The program and its machine code

What has been described so far comes together in a small program. The program writes a character directly into the video memory of the color text screen. No service of the operating system is used; writing to the screen amounts to putting a word at a particular memory address.

ORG 100h          ; for a .com program
MOV AX, 0B800h    ; AX = B800h
MOV DS, AX        ; DS = B800h
MOV CL, 'A'       ; CL = 41h
MOV CH, 11011111b ; CH = DFh
MOV BX, 15Eh      ; BX = 015Eh
MOV [BX], CX      ; B800:015E ← CX
RET               ; back to DOS

Each line of the program introduces an element. ORG is a directive; it determines the program's start address and is not translated into machine code. Everything after the semicolon is a comment; the assembler ignores it. MOV copies a value between source and destination. Since a constant cannot be assigned directly to DS, B800h is first loaded into AX. 'A' is a character constant and is the same as the ASCII code 41h. 11011111b is a constant written in binary and equals DFh. MOV [BX], CX writes the word in CX to the address DS:BX.

The physical addresses are B8000h + 015Eh = B815Eh and B815Fh. The character byte coming first and the color byte second fits the layout of video memory exactly. That is why the character was put in the low half and the color in the high half. The display card reads these two bytes on the next scan, and a colored 'A' appears in the cell.

The letter stays on the screen, because video memory is independent of the program. DS remaining B800h causes no problem either; after the program ends, DOS sets up its own registers again.

4.1.7.3Text-mode video memory

In the 80 × 25 text mode the screen consists of 25 rows and 80 columns. Each cell holds 2 bytes in video memory: first the character, then the color. A row is 80 × 2 = 160 bytes and the whole screen takes 25 × 160 = 4000 bytes. If rows and columns are counted from 0, the relative address of a cell is found as follows:

relative address = (row × 80 + column) × 2

The 015Eh in the program comes from this formula: (2 × 80 + 15) × 2 = 175 × 2 = 350 = 15Eh. The letter was written in row 2, column 15 (Figure 4.1.18). The calculation can also be done in reverse. 015Eh = 350 is divided by two: 175. Since 175 = 2 × 80 + 15, it is row 2, column 15.

The bits of the attribute byte encode the color. DFh = 1101 1111b is read as follows:

  • Bit 7 = 1: blinking of the character on a real screen; bright background in emu8086.
  • Bits 6–4 = 101: background color magenta (5).
  • Bits 3–0 = 1111: foreground color bright white (15).

The foreground color selects one of 16 colors with four bits, and the background color one of 8 colors with three bits. The basic colors are 0 black, 1 blue, 2 green, 3 cyan, 4 red, 5 magenta, 6 brown, 7 light gray; 8–15 are their bright versions, and 14 is yellow. The 1Eh in the earlier example thus means yellow text (1110) on a blue background (001), and 07h gray text on a black background.

Example 4.1.3

What would the code look like that writes a yellow 'X' on a green background at row 10, column 40 of the screen? The color byte is 2Eh.

The relative address is (10 × 80 + 40) × 2 = 840 × 2 = 1680 = 690h. The ASCII code of the character 'X' is 58h. Since the character is in the low byte and the color in the high byte, the word to write is 2E58h. 2Eh = 0010 1110b: background 010 (green), foreground 1110 (yellow).

MOV AX, 0B800h
MOV DS, AX
MOV BX, 690h
MOV WORD PTR [BX], 2E58h

WORD PTR is necessary in the last instruction; otherwise the size of the constant stays ambiguous. The code writes 58h to B8690h and 2Eh to B8691h.

4.1.8.3XCHG: swapping

Swapping the places of two values is a basic operation of many algorithms, such as sorting. The 8086 has a separate instruction for it.

Definition 4.1.9

The instruction XCHG destination, source exchanges the contents of the two operands in a single instruction. One operand can be a register and the other a register or memory. Memory with memory, segment registers, and constants cannot be used. The two operands must be the same size. XCHG does not affect the flags.

MOV CX, 10   ; CX = 000Ah
MOV DX, 20   ; DX = 0014h
XCHG CX, DX  ; swap

When numbers carry no suffix, they are taken as decimal. After the first instruction CX = 10 = 000Ah, and after the second DX = 20 = 0014h. After XCHG, CX = 0014h and DX = 000Ah. The flags do not change. The machine code of the instruction is 87 CA: 87 is the word swap, and CA = 11 001 010 means REG = CX, R/M = DX.

  • Register ↔ register: XCHG AX, BX.
  • Register ↔ memory: XCHG AL, [SI]. The writing order does not matter; XCHG [SI], AL is the same instruction.
  • There is no memory ↔ memory.
  • Segment registers and constants cannot be used. Swapping with a constant is meaningless anyway: nothing can be written into a constant.
  • The sizes must be the same; the flags do not change.
  • The form XCHG AX, reg has a special one-byte code: 90h + register number. XCHG AX, BX = 93. XCHG AX, AX changes nothing and its code is 90. This byte is also the NOP (no operation) instruction.

Without XCHG, a temporary register would be needed for the swap:

MOV AX, CX    ; AX ← CX (backup)
MOV CX, DX    ; CX ← DX
MOV DX, AX    ; DX ← old CX

This way spends three instructions and one more register. The old value of AX is also lost. XCHG is ahead in time too. On the 8086 register-to-register MOV takes 2 periods and XCHG 4; three MOVs take 6 periods. The one-byte swap with AX takes 3 periods. A swap between a register and memory is expensive: 17 periods plus the EA time. The reason is that the processor first reads from memory and then writes to memory; two separate bus cycles are needed.

The use of XCHG with memory has a special importance in multiprocessor systems. Because the read and the write are done in a single instruction, the chance of another processor accessing the same byte in between is narrowed. When used with the LOCK prefix, the 8086 keeps the LOCK̅ pin active for the duration of the instruction and does not hand the bus to another bus master. The locks that ensure a resource is used by only one processor at a time are built on this mechanism.

4.1.8.7Writing a constant to memory

ORG 100h
MOV BYTE PTR [4000h], 65  ; 'A'
MOV WORD PTR [4002h], 65
RET

Let DS:4000h–4003h initially be 00 99 00 99. The first instruction writes 65 as a single byte. 65 = 41h is the ASCII code of the letter 'A'. The machine code is C6 06 00 40 41 and takes five bytes: the opcode, ModR/M, two address bytes, and one data byte. IP becomes 0105h. 4001h does not change.

The second instruction writes the same constant with WORD PTR. 65 is now the word 0041h; 41h goes to 4002h and 00h to 4003h. The 99h at 4003h is erased. The instruction is six bytes, C7 06 02 40 41 00, and IP advances to 010Bh. The constant has no size of its own; the PTR specifier determines it. The number 65 in the source is the same in both instructions, but it enters the machine code once as one byte and once as two.

4.1.8.8Working with 8-bit halves

Each of AX, BX, CX, and DX has two 8-bit halves that can be used with separate register names: AH and AL, BH and BL, and so on. Writing to one half does not affect the other half. This makes it possible to hold two small values in a single register and to process the bytes of a word separately.

Copying the low byte. In the code below, AL is copied to BL.

MOV AX, 1234h   ; AH = 12h, AL = 34h
MOV BX, 0FFFFh
MOV BL, AL      ; BL only

The first instruction makes AX = 1234h: AH = 12h, AL = 34h. The second fills BX with FFFFh so that the effect can be seen. The third instruction (8A D8) changes only BL: BL = 34h. BH = FFh stays in place and BX = FF34h. Copying from a 16-bit register to an 8-bit register (MOV BL, AX) is invalid; the sizes must be the same.

Adding to the high byte. When arithmetic is done on the halves, the carry is seen not to pass from one half to the other.

MOV AX, 00FFh   ; AH = 00h, AL = FFh
ADD AH, 01h     ; AH only
ADD AL, 01h     ; AL only
MOV AX, 01FFh
ADD AX, 1       ; 16 bits
Table 4.1.26: Adding to the high and low byte (flags: CF, ZF, SF, AF, PF).
StepInstructionMachine codeAXCFZFSFAFPF
1MOV AX, 00FFhB8 FF 0000FFh00000
2ADD AH, 01h80 C4 0101FFh00000
3ADD AL, 01h04 010100h11011
4MOV AX, 01FFhB8 FF 0101FFh11011
5ADD AX, 105 01 000200h00011

In step 2, AH = 00h + 01h = 01h and AX = 01FFh. The result is not zero and there is no carry. Since 01h has an odd number of 1 bits, PF = 0. In step 3, AL = FFh + 01h is computed. The 8-bit result is 00h and a carry comes out as the ninth bit: CF = 1, ZF = 1. A carry also comes out of the low four bits, so AF = 1. There are zero 1s in 00h; zero is an even number and PF = 1. The carry does not pass to AH: AX = 0100h. This is an 8-bit addition and AH is not part of the operation.

In step 4, AX is set to 01FFh again. Because MOV does not change the flags, the flags of the previous step (CF = 1, ZF = 1) remain as they were. In the 16-bit addition of step 5, 01FFh + 1 = 0200h. This time the carry has passed from AL to AH, because the operation is 16 bits. Since no carry comes out of 16 bits, CF = 0. AF is 1 again; F + 1 in the low four bits produces a carry. PF looks only at the low byte of the result: PF = 1 for 00h. The instruction ADD AX, 1 is encoded in the short AX-specific form as 05 01 00.

Common mistake

Thinking the carry of an 8-bit addition passes to the other half of the register. ADD AL, 1 with AL = FFh does not increment AH; it only makes CF = 1. If a 16-bit value is to be added to in 8-bit pieces, ADC (add with carry) is used on the high half: ADD AL, 1 followed by ADC AH, 0.

4.1.8.9Assignment with number bases

In assembly source code, constants can be written in different bases. Whichever base is used, the assembler converts the number to a binary value and writes it into the machine code. The program below uses three bases together.

mov al, 00000101b ; binary
mov bl, 0ah       ; hex
mov cl, 10o       ; octal
add al, bl        ; 5 + 10 = 15
sub al, cl        ; 15 - 8 = 7

Example 4.1.4

How is the number 200 written in binary, octal, and hexadecimal? Do MOV AL, 200 and MOV AL, 0C8h produce the same machine code?

Since 200 = 128 + 64 + 8, the binary is 11001000b. With groups of three bits, 11 001 000 = 3 1 0, that is, 310o; with groups of four bits, 1100 1000 = C 8, that is, 0C8h. A 0 is put in front because C is a letter. Both instructions produce B0 C8; the base only changes how the source code reads.

Most errors in memory access do not give an assembly error. The program runs but reads from the wrong address or corrupts the wrong byte. These errors are found in emu8086 by checking the effective address and physical address in the memory window. Table 4.1.29 collects the most frequent ones.

Forgetting to shift the segment when computing a physical address. For DS = 2000h, BX = 0150h the physical address is 20000h + 0150h = 20150h, not 2000h + 0150h = 2150h. Common mistake

4.1.10Exercises and solutions

The six exercises in the slides are solved here with their intermediate steps.

1. With DS = 3000h, BX = 0010h, SI = 0005h, what are the effective and physical addresses of the operand [BX+SI+20h]?

There is no BP in the address; the segment is DS. EA = 0010h + 0005h + 0020h = 0035h. The physical address is 3000h × 10h + 0035h = 30000h + 0035h = 30035h.

2. With SS = 4000h, BP = FFFEh, what are the effective and physical addresses of the operand [BP+4]?

EA = FFFEh + 0004h = 1 0002h; it wraps in 16 bits and EA = 0002h. Since BP is present, the segment is SS: 40000h + 0002h = 40002h.

3. Which of the notations [BX+BP], [DI+SI], [BX+DI+300], [DX] are valid?

Only [BX+DI+300] is valid: one base, one index, and one d16. [BX+BP] contains two base registers and [DI+SI] two index registers. DX cannot be used in address calculation at all.

4. If [0500h] = 78h and [0501h] = 56h, what is AX after MOV AX, [0500h]? What is AL after MOV AL, [0501h]?

When reading a word, the low address is the low byte: AL = 78h, AH = 56h, AX = 5678h. The second instruction reads only the byte at 0501h: AL = 56h.

5. What does the code look like that writes a yellow 'X' on a green background at row 10, column 40 of the screen? The color byte is 2Eh.

The solution is given in detail in Example 4.1.3. The relative address is (10 × 80 + 40) × 2 = 1680 = 690h; the word to write is 2E58h.

MOV AX, 0B800h
MOV DS, AX
MOV BX, 690h
MOV WORD PTR [BX], 2E58h

6. How is the program that prints 'A' on the screen written with ES without changing DS?

B800h is loaded into ES instead of DS and the ES: prefix is added to the write instruction. DS stays in the program's segment (0700h).

MOV AX, 0B800h
MOV ES, AX
MOV CL, 'A'
MOV CH, 11011111b
MOV BX, 15Eh
MOV ES:[BX], CX      ; 26 89 0F

The machine code of the write instruction is its unprefixed form (89 0F) with 26 added in front. At the end of the program B815Eh = 41h, B815Fh = DFh, and DS = 0700h stays.

4.1.11Summary

  • Addressing: a memory operand has the form [base + index + displacement]. The base is BX or BP, the index SI or DI, and the displacement d8 or d16; each is optional. BX and BP, or SI and DI, cannot be used together. These rules give 24 combinations and are encoded in the MOD and R/M fields of the ModR/M byte.
  • Mode types: the immediate and register modes do not go to memory. The direct, register indirect, based, indexed, and based-indexed modes compute an effective address. String instructions use DS:SI and ES:DI implicitly; I/O instructions go to a separate port space, and jumps to an address relative to IP.
  • The effective address is computed in 16 bits and wraps: with BP = FFFEh, [BP+4] → 0002h. d8 is sign-extended. EA calculation takes 5–12 clock periods on the 8086; a segment prefix adds 2.
  • Segment choice: SS if BP is in the address, otherwise DS. A segment prefix (ES: = 26h, CS: = 2Eh, SS: = 36h, DS: = 3Eh) changes this for a single instruction. CS:IP, SS:SP, and the string destination ES:DI cannot be changed.
  • Physical address = segment × 10h + EA; 1234:7890 → 19BD0h. At most 4096 segment:offset pairs lead to one physical address. n address lines select 2n locations; the 8086's 20 lines give 1 MB, and the 16-bit offset gives the 64 KB segment.
  • Size: byte ptr / word ptr (b. / w. in emu8086) specify the access size; if the other operand is a register, the size is known from it. The 8086 is little-endian: the low byte at the low address. In a word array the byte offset is index × 2.
  • MOV copies and does not affect the flags. There is no MOV from memory to memory, from a constant to a segment register, or from segment to segment; CS and IP cannot be destinations.
  • XCHG swaps two operands in one instruction; segment registers, constants, and two memory operands cannot be used. It does not affect the flags.
  • Video memory is in the B800h segment. Each cell is a character + attribute byte; relative address = (row × 80 + column) × 2.

4.1.13Test Yourself

  1. With ES = 5000h and DI = FFF0h, from which physical address does the instruction MOV AL, ES:[DI+20h] read?

    Answer

    EA = FFF0h + 0020h = 1 0010h; it wraps in 16 bits and EA = 0010h. The prefix selects ES: 50000h + 0010h = 50010h. Without the wraparound, 60010h would have been found; this address is outside the ES segment.

  2. How many bytes is the instruction MOV AL, [BP+SI+5] and which segment does it access? What is the ModR/M byte?

    Answer

    The segment is SS, because BP is in the address. Since the displacement 5 is in the range −128…127, d8 is chosen: MOD = 01. REG = 000 (AL), R/M = 010 ([BP+SI]). ModR/M = 01 000 010 = 42h. The instruction is 8A 42 05, that is, 3 bytes.

  3. Starting at DS:0300h, memory holds the bytes 78 56 34 12. What are AX and BL after MOV AX, [0301h] and MOV BL, [0303h]? What happens on the data bus in the first instruction?

    Answer

    AX: the 56h at 0301h goes to AL and the 34h at 0302h to AH; AX = 3456h. BL = 12h. 0301h is an odd address. The 8086 reads a word starting at an odd address with two separate bus cycles; the result is the same, but the access takes 4 clock periods longer.

  4. What is AX when the following program finishes?

    org 100h
mov bx, offset t
mov si, 3
mov al, [bx+si]
mov ah, [bx+si-2]
ret
t db 10h,20h,30h,40h,50h
    Answer

    [bx+si] is byte number 3 of t (counting from 0): AL = 40h. [bx+si-2] is byte number 1: AH = 20h. AX = 2040h. Since the program is 12 bytes long, t is at 010Ch; the result is independent of this address.

  5. Physical address 45678h is to be reached with DS:SI. What are the smallest and largest values DS can take? How many different pairs are there?

    Answer

    Largest DS: the first four digits, 4567h; SI = 45678h − 45670h = 0008h. Smallest DS: DS × 10h ≥ 45678h − FFFFh = 35679h, that is, DS ≥ 3567.9h → 3568h; SI = 45678h − 35680h = FFF8h. The number of pairs is 4567h − 3568h + 1 = 1000h = 4096.

  6. What is the capacity of a memory chip with 18 address lines and 8 data lines? What if it had 18 address lines and 4 data lines?

    Answer

    218 = 262,144 locations; each location is 1 byte → 256 KB. With 4 data lines each location is 4 bits: 262,144 × 4 bits = 1,048,576 bits = 128 KB.

  7. Which of the following are accepted by an 8086 assembler? MOV ES, [BX] · MOV [SI], DS · MOV AX, [DX] · XCHG [SI], [DI] · MOV BYTE PTR [DI], 300

    Answer

    The first two are valid: a segment register can be loaded from memory (8E 07) and written to memory (8C 1C). [DX] is invalid; DX is not an address register. XCHG cannot take two memory operands. 300 does not fit in a byte (at most 255); the assembler reports an error.

  8. What is the relative address in video memory of the last cell of the 80 × 25 text screen (row 24, column 79)? At which physical address is this cell's color byte?

    Answer

    (24 × 80 + 79) × 2 = 1999 × 2 = 3998 = 0F9Eh. The character is at B8000h + 0F9Eh = B8F9Eh and the color byte at the next address, B8F9Fh. Since the whole screen is 4000 bytes, the last byte is 0F9Fh.

  9. How many clock periods do the instructions MOV AX, [BX+SI+6] and MOV AX, [BX+DI+6] take on the 8086? What changes if the EA comes out as an odd address?

    Answer

    MOV from memory to a register is 8 periods plus the EA time. For [BX+SI+d] the EA is 11 and for [BX+DI+d] 12 periods: 19 and 20 periods. If the EA is odd, the word is read in two bus cycles and 4 periods are added to the time: 23 and 24 periods.
