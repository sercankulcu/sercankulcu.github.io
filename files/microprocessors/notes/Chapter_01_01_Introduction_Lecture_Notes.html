Chapter 1.1: Introduction

The same idea runs inside the control board of a washing machine, the engine controller of a car, and a laptop: a programmable chip that reads instructions from memory one after another and carries them out. This chapter introduces that chip, the microprocessor, from the outside in. It first places the microprocessor in a computer system, shows the buses that connect it to memory and to input/output devices, and explains how it differs from a microcontroller. It then follows the fetch–decode–execute cycle that repeats for every instruction, step by step, on 8086 machine code. The internal structure of the processor, the clock signal, and the three quantities that determine a program’s running time (instruction count, cycles per instruction, clock frequency) are worked out with numerical examples. The later sections cover instruction set architectures (CISC, RISC, EPIC), special-purpose processor types, and the evolution of the Intel x86 family from the 4004 to the Core i7. The chapter ends with the features that determine performance in modern processors, such as caches, multiple cores, and power management. All code examples are written in 8086 assembly, and each one is traced in a table that shows how the registers, flags, and memory change.

1.1.1The microprocessor and the computer system

The shortest way to understand the microprocessor is to look at the job it does in a computer. This section defines the microprocessor, explains the buses that join it to memory and to input/output devices, and shows how the same processor takes a different form in a microcontroller.

1.1.1.1What is a microprocessor?

At the center of every computer sits a unit that executes instructions. It is called the central processing unit (CPU). In the first computers the CPU was built from cabinets full of vacuum tubes, relays, or discrete transistors. As integrated-circuit technology advanced, the same circuits first fit onto a few boards and then onto a single piece of silicon. The microprocessor is the product of that last step.

Definition 1.1.1

A microprocessor is the central processing unit of a computer implemented on a single chip. It is a programmable device: the machine-language instructions stored in memory determine what it does. It reads these instructions in order and carries them out.

The word “programmable” in the definition separates the microprocessor from the circuits built in digital design courses. An adder circuit only adds; a counter only counts. What such a circuit does is fixed by its wiring, and changing its function means rewiring it. The wiring of a microprocessor, by contrast, never changes. What changes is the instructions in memory. The same chip edits text under one program and drives a motor under another. This flexibility has made the microprocessor a part of almost every electronic product today.

The microprocessor’s work can be summarized in three steps. First the processor takes input: a key pressed on a keyboard, a temperature measured by a sensor, or a file read from a disk. Then it performs arithmetic and logic operations on that data: it adds, subtracts, compares, and masks bits. Finally it produces the desired output: it writes a character on the screen, turns a motor, or lights an LED. Throughout these three steps the processor talks to memory constantly. It reads both the instructions it will execute and the data it will work on from memory, and it writes intermediate results back to memory. Figure 1.1.1 shows this relationship.

A simple calculator is an everyday example of this flow. The keys are the input; addition is the processing; the result that appears on the display is the output. The small processor inside the calculator runs a program that reads the keys, adds the numbers, and writes the digits to the display. Changing that program means making the same chip do a different job.

The only language a microprocessor understands is machine language. In machine language every instruction is a sequence of bytes. On the 8086, for example, the bytes B0 05 mean “load 5 into register AL.” Because people find it hard to memorize such numbers, programs are mostly written in assembly language. Assembly gives the machine instructions short names such as MOV, ADD, and JMP, called mnemonics. A translator program, the assembler, converts this text into machine code. In this chapter instructions are written in assembly, and the corresponding machine-code bytes are given where needed.

1.1.1.2The computer system and its buses

A microprocessor cannot work alone. It needs a memory that holds instructions and data, and input/output (I/O) devices that connect it to the outside world. These three parts, the CPU, memory, and I/O devices, are joined by a common bundle of wires. This bundle is called a bus. The bus that connects all parts of the system is called the system bus.

Definition 1.1.2

A bus is a group of parallel conducting lines that carry the same kind of information between units. A computer system has three buses:

  • Address bus: selects the memory cell or I/O port the processor will access. It is unidirectional; only the processor generates the address.
  • Data bus: carries the data being read or written. It is bidirectional; on a read, data flows from memory to the processor, and on a write, from the processor to memory.
  • Control bus: carries timing and control signals such as read, write, memory or I/O select, clock, and interrupt.

How a memory read proceeds shows clearly how the three buses share the work. The processor puts the address of the cell it wants to read on the address bus. Then it activates the read signal on the control bus (the RD pin on the 8086). The memory decodes the pattern on the address lines, selects the corresponding cell, and drives its contents onto the data bus. The processor captures the value on the data bus and releases the read signal. A write proceeds in a similar way; this time the processor drives the data onto the data bus, and the write signal (WR) is active on the control bus. Each of these steps happens in a fixed order tied to the clock signal. The time a read or write takes from start to finish is called a bus cycle.

The width of the buses, that is, the number of lines each has, sets the limits of the system. Each line of the address bus carries a 0 or a 1. With n lines, 2n different patterns can be formed, and each pattern selects one memory cell. An n-line address bus therefore addresses 2n bytes of memory. The 8086 address bus has 20 lines: 220 = 1,048,576 bytes, that is, 1 MB of memory. The width of the data bus is the number of bits transferred in one bus cycle. The 8086 data bus is 16 bits wide; in one bus cycle it carries 2 bytes, that is, one word.

Example 1.1.1

How many bytes of memory do address buses with 16, 20, and 24 lines address?

  • 16 lines: 216 = 65,536 bytes = 64 KB (1 KB = 1024 bytes; 65,536 / 1024 = 64). The 8080 and 8085 are like this.
  • 20 lines: 220 = 1,048,576 bytes = 1024 KB = 1 MB. The 8086 and 8088 are like this.
  • 24 lines: 224 = 16,777,216 bytes = 16 MB. The 80286 is like this.

Looking at it the other way, selecting every byte of 1 MB individually takes log2(220) = 20 lines. Each additional line doubles the addressable memory.

The 8086 has an interesting detail in its design: the processor is 16-bit, but its address bus is 20 bits. A 20-bit address cannot be held directly in 16-bit registers. The 8086 solves this by combining two 16-bit values, the segment and the offset. The physical address is found by multiplying the segment value by 16 and adding the offset. Throughout this chapter, addresses are mostly written with the offset alone, for example 0100h, and the segment value is taken as fixed.

Common mistake

Confusing the width of the data bus with the amount of addressable memory. The conclusion “the 8086 is 16-bit, so it addresses 64 KB of memory” is wrong. It is the address bus, not the data bus, that determines addressable memory: the 8086’s 20 address lines reach 1 MB. A 16-bit register can directly point only to a 64 KB window within a segment; the segment register slides this window around within the 1 MB.

1.1.1.3Microprocessor and microcontroller

In a computer built around a microprocessor, memory and I/O devices are separate chips. On an 8086 board, the processor sits next to RAM chips, the ROM chip that holds the program, an interface chip for I/O, and a timer chip. The chips are joined by buses on the board. This arrangement is flexible: the amount of memory and the peripherals are chosen to fit the need. The price is board area, cost, and power consumption.

Many applications do not need this flexibility. The board of a washing machine runs a single program for years, makes do with a few kilobytes of memory, and manages a few buttons and a few motors. For jobs like this, devices were developed that put the CPU, memory, and peripherals on a single chip.

Definition 1.1.3

A microcontroller (MCU) puts the CPU together with RAM, Flash/ROM program memory, I/O ports, timers, and peripherals such as the analog-to-digital converter (ADC) on the same chip. For this reason it is also called a “computer on a chip.” A microprocessor (MPU), by contrast, contains only the CPU; memory and peripherals are added externally.

Examples of microprocessors include the 8086, the Intel Core i7, and the AMD Ryzen. Examples of microcontrollers are the 8051, the PIC, the AVR in Arduino boards, and the STM32 family. Table 1.1.1 compares the two types on eight criteria.

Example 1.1.2

Which type is chosen for a washing-machine controller and for a laptop?

The washing machine has a single, unchanging job: read the buttons, monitor the water level and temperature, and drive the motor and valves. The program is small; cost and power matter. A microcontroller is chosen for this job. A laptop, on the other hand, runs an operating system, wants gigabytes of memory, and the user may open a new application at any moment. Because it needs high performance and large memory, a microprocessor is chosen.

The difference between a microprocessor and a microcontroller is about what is packed onto the chip; the operating principle of the CPU inside is the same. Both fetch, decode, and execute instructions from memory. Both have registers, an arithmetic logic unit, and flags. This course studies the 8086 microprocessor. The concepts learned on the 8086’s buses, registers, and instructions carry over with the same logic when you move to a microcontroller.

1.1.2The instruction cycle

Everything a microprocessor does is nothing more than the repetition of a single cycle. The processor takes an instruction from memory, works out what it asks for, does the work, and puts the result in place. Then it repeats the same thing for the next instruction. This section defines the stages of the cycle, traces the cycle on the machine code of a three-instruction 8086 program, and shows how the program counter directs the flow.

1.1.2.1Fetch, decode, execute

Definition 1.1.4

The instruction cycle is the sequence of stages the processor repeats for every instruction:

  1. Fetch: reads the instruction from memory at the address the program counter points to.
  2. Decode: decodes the opcode; determines which operation is to be performed on which operands.
  3. Execute: carries out the decoded instruction; computes in the ALU, moves data, or jumps.
  4. Result: writes the result to a register or to memory and updates the flags.

Some books count the fourth stage as part of execution and call the cycle simply “fetch–decode–execute.” Whichever naming is chosen, the order is the same. As long as the processor is on, this cycle runs without ever stopping. The arrow in the figure returns from the last stage to the first; the only situation in which the cycle ends is when the processor is halted.

A different part of the processor handles each stage. The bus interface does the fetching: it puts the address in the program counter on the address bus, issues the read signal, and takes in the bytes arriving on the data bus. The control unit does the decoding: it interprets the opcode byte as if looking it up in a table and generates the control signals that determine which units will work. In execution the ALU comes into play, or data is moved from one register to another. In the result stage the value is written to the register file or to memory.

Because the stages run in sequence, the number of instructions executed per unit time is limited: while fetching goes on the ALU waits idle, and while execution goes on the bus waits idle. Fast processors close this gap by overlapping the stages. While one instruction is executing, the next is being decoded and the one after that is being fetched. This arrangement is called a pipeline; it is the basic technique of RISC processors. The 8086 uses a simple form of this idea: while the execution unit works, the bus interface unit prefetches the upcoming instruction bytes and holds them in a 6-byte queue.

1.1.2.2Tracing machine code

To see the cycle concretely, take a program of three instructions:

mov al, 5     ; B0 05
add al, 3     ; 04 03
hlt           ; F4

The assembler translates this text into five bytes of machine code. The program is loaded into memory starting at address 0100h: B0 is at 0100h, 05 at 0101h, 04 at 0102h, 03 at 0103h, and F4 at 0104h. The first byte is the opcode. B0 means “load an 8-bit constant into register AL,” and the constant is in the byte right after the opcode. A constant embedded in the instruction like this is called an immediate value. The opcode 04 means “add an 8-bit immediate to AL.” F4 is the HLT instruction; it takes no operand and is a single byte.

On the 8086 the program counter is called the instruction pointer (IP). IP always holds the offset of the next byte to be fetched. Initially IP = 0100h. Figure 1.1.5 shows four moments of the cycle.

The steps of the trace are as follows:

  1. Fetch. The 0100h in IP is put on the address bus. Memory returns the byte B0. From the opcode the control unit learns that the instruction is 2 bytes long and fetches the byte 05 as well. IP grows by the instruction length: 0100h + 2 = 0102h.
  2. Decode. The control unit decodes B0 as “load an 8-bit constant into AL”; the constant is 05h.
  3. Execute and result. 05h is written to register AL. The ALU is not used. The MOV instruction changes no flags; the flags keep their previous values.
  4. Fetch. The cycle starts again. The 04 03 at 0102h is fetched; IP becomes 0104h.
  5. Decode. 04 = “add an 8-bit constant to AL.” The operands are the 05h in AL and the constant 03h.
  6. Execute and result. The ALU computes 05h + 03h = 08h and writes the result to AL. Because the result is not zero, the zero flag is ZF = 0. Because there is no carry out of the top bit, the carry flag is CF = 0.
  7. Fetch and decode. The F4 at 0104h is fetched; IP becomes 0105h. F4 is decoded as HLT, and the processor stops until an interrupt or a reset arrives.

ADD updates not only ZF and CF but all six of the 8086’s status flags. In the result 08h = 0000 1000b the top bit is 0, so the sign flag is SF = 0. Because the sum of two positive numbers stays positive, the overflow flag is OF = 0. In the low four bits 5 + 3 = 8 fits in 4 bits, so the auxiliary carry flag is AF = 0. The low byte of the result has an odd number (one) of 1 bits, so the parity flag is PF = 0. Only ZF and CF are shown in the table.

Two details of this trace matter. First, IP is incremented as soon as an instruction is fetched; while the instruction executes, IP already points to the next one. Jump instructions steer the flow by changing this value. Second, the processor does not know whether bytes are “instruction” or “data.” The 05 at 0101h is read as a constant, not as an opcode, because when the control unit decodes B0 it knows a constant follows. Had IP gone to 0101h by mistake, the processor would have treated 05 as an opcode and executed an entirely different instruction.

On a real 8086, fetching works a little differently from this description. While the execution unit (EU) is busy with one instruction, the bus interface unit (BIU) prefetches the next bytes and stores them in a 6-byte prefetch queue. When the EU finishes an instruction, the bytes of the next one are usually already waiting in the queue, so there is no need to wait for memory. From the programmer’s point of view nothing changes: instructions still run in order with the same effects.

Common mistake

It is often assumed that IP grows by 1 with every instruction. IP holds a byte address, not an instruction count, and it grows by the length of the instruction. 8086 instructions are 1 to 6 bytes long: hlt is 1 byte, mov al, 5 is 2, and mov cx, 3 is 3. To find the address of an instruction, add up the lengths of the instructions before it.

1.1.2.3Three basic functions

Although a processor’s instruction set may contain hundreds of instructions, every one of them serves one of three functions.

Arithmetic and logic operations. Addition, subtraction, comparison, AND, OR, XOR, and shifts belong to this group. These operations are performed by the arithmetic logic unit (ALU). Newer processors also work with floating-point numbers; a separate floating-point unit (FPU) handles that work. Examples on the 8086: ADD AX, BX (add BX to AX), CMP AL, 10 (compare AL with 10), AND AL, 0Fh (clear the upper four bits of AL).

Data movement. Data is copied from one place to another among registers, memory, and I/O. This is the most common operation in programs; most of the code compilers generate consists of move instructions. Examples: MOV AX, [1234h] (read the word in memory into AX), MOV [BX], AL (write AL to the address BX points to), IN AL, 60h (read a byte from I/O port 60h).

Changing the program counter. The program counter holds the address of the next instruction. Writing a new value into it makes the flow jump elsewhere. Conditional jumps look at the flags and decide whether to jump; every if and every loop in a program is built this way. Examples: JMP label (jump unconditionally), JZ is_zero (jump if ZF = 1), CALL subroutine (save the return address and jump to the subroutine).

Every program is a combination of these three functions: computing, moving, and changing the order. A sorting program reads numbers (movement), compares them (computation), and swaps or skips them depending on the result (changing the order).

1.1.2.4The program counter and loops

In sequential flow IP increases by itself. To build a loop, a backward address must be written into IP. The following program computes the sum 3 + 2 + 1. The numbers on the left are the offsets of the instructions in memory (in hexadecimal).

0100  mov  cx, 3     ; count = 3
0103  mov  ax, 0     ; sum = 0
0106  again: add ax, cx
0108  loop again     ; CX--, jump if CX≠0
010A  hlt            ; halt

mov cx, 3 puts the count into CX; this instruction, which loads a 16-bit constant into a 16-bit register, is 3 bytes (B9 03 00). mov ax, 0 clears the sum and is also 3 bytes. add ax, cx adds two registers and is 2 bytes. loop again first decrements CX by 1; if CX is not zero it jumps to the label again, and if it is zero it moves on to the next instruction. loop is 2 bytes and changes no flags. hlt stops the processor.

Common mistake

It is often assumed that loop first tests CX and then decrements it. The order is the reverse: CX is decremented first, and then the new value is tested. So if a loop is entered with CX = 0, the first loop makes CX FFFFh and the body runs 65,536 times.

1.1.3Structure of the microprocessor

Different units of the processor take care of the stages of the instruction cycle. This section introduces those units, explains the clock signal that drives them all in step, and shows how to compute the running time of a program. It ends with what the bit width of a processor means and how a 16-bit processor adds 32-bit numbers.

1.1.3.1Structural components

The inside of a microprocessor consists of four main units: the control unit, the registers, the ALU, and the bus interface. These units are joined by an internal data bus on the chip. The bus interface connects the internal world to the external buses, that is, to memory and I/O devices. Figure 1.1.6 shows this arrangement.

Arithmetic logic unit (ALU). It performs arithmetic (+, −) and logic (AND, OR, NOT, XOR) operations on binary numbers, as well as comparison and shifting. The full adders, multiplexers, and shifters built in digital design are the building blocks of the ALU. The ALU takes its two inputs, produces a result according to the operation-select signals from the control unit, and writes properties of the result into the flags. If the result is zero, the zero flag (ZF) becomes 1. If a carry came out of the top bit, the carry flag (CF) is set; if the top bit of the result is 1, the sign flag (SF) is set. If the signed result did not fit, the overflow flag (OF) is set. Conditional jumps look at these flags.

Control unit (CU). It is the conductor of the processor. It decodes the instruction; it determines which register is connected to the internal bus, which operation the ALU performs, and when the memory read and write signals are issued. A control unit can be built in two ways. In a hardwired control unit the signals for each instruction are generated directly by logic gates; this is fast but gets hard to design for complex instruction sets. In a microprogrammed control unit each instruction is translated into a sequence of steps stored in a small ROM on the chip, called microcode. The 8086 is a microprogrammed processor.

Registers. These are small, very fast storage cells inside the processor. Each register is a latch built from flip-flops and can be read and written in one clock cycle. Going to memory costs a bus cycle, that is, several clock cycles. For this reason programs keep frequently used values in registers. Registers are grouped by purpose: general-purpose (data) registers, address and pointer registers, the status (flags) register, and the program counter. On the 8086 the general-purpose registers are AX, BX, CX, and DX. SP, BP, SI, and DI are pointer and index registers. IP is the program counter and FLAGS is the flags register; CS, DS, SS, and ES are the segment registers.

Bus interface. It drives the address, data, and control buses. Every byte to be read from or written to memory passes through this unit. On the 8086 this unit is called the bus interface unit (BIU). The BIU computes the physical address, runs the bus cycles, and prefetches instruction bytes and holds them in a 6-byte queue. The part that decodes and executes the instructions is the execution unit (EU). Because the two units work at the same time, fetching and execution overlap.

Clock and timing. All units of the processor advance in step with the pulses of the clock signal. A register takes its new value only on a clock edge; each step of a bus cycle falls on a specific clock cycle. The duration of one pulse is T = 1/f.

Cache, FPU, and cores. On the 8086 these units are not on the chip. Modern processors, however, have a cache, a floating-point unit, several cores, and a graphics unit on the same chip. These units are among the main features added to processors since the 8086.

Example 1.1.3

While the add ax, bx instruction executes, what does each unit do?

The BIU fetches the bytes 03 C3 from the address IP points to and puts them in the queue (most likely while the previous instruction was executing). The EU takes the bytes from the queue; the control unit decodes the opcode 03 as “add a word to a register” and the byte C3 as “destination AX, source BX.” The control unit connects AX and BX through the internal bus to the ALU inputs and selects addition in the ALU. The ALU computes the sum; the result is written to AX and the flags are updated. Because there is no memory access, the bus interface is idle during this time and can fetch the bytes of the next instruction.

1.1.3.2The clock signal and the period

The clock signal is a square wave that alternates between 0 and 1 at a given frequency. On the 8086 this signal is produced by the 8284A clock generator chip and fed to the processor’s CLK pin. The clock signal does the same job as the clock of the synchronous circuits in digital design: it makes all flip-flops change state at the same moment.

Definition 1.1.5

The clock frequency f is the number of pulses of the clock signal per second, measured in hertz (Hz). One pulse is called a clock cycle, or simply a cycle. The duration of a cycle is the period:

T = 1 / f

An instruction usually takes several clock cycles. On the 8086 a memory access, that is, one bus cycle, is at least four clock cycles. These cycles are called T states and are named T1, T2, T3, and T4. Roughly, the address is put on the bus in T1 and the read or write signal becomes active in T2. In T3 the data becomes valid on the bus, and in T4 the bus cycle ends. If the memory is slow, wait states (Tw) are inserted between T3 and T4.

f = 5 MHz = 5 × 106 Hz. The period is T = 1 / (5 × 106) s = 0.2 × 10−6 s = 200 ns. Because a bus cycle takes four cycles, it lasts 4 × 200 ns = 800 ns. 1.1.3.3Clock rate, CPI, and execution time

The clock period gives the duration of one cycle, but it does not by itself say how long a program will take. Two more quantities are needed: the number of instructions the program executes, N, and how many cycles an instruction takes on average.

Definition 1.1.6

Cycles per instruction (CPI) is the average number of clock cycles spent per instruction in a program. The CPU time of a program of N instructions is:

CPU time = N × CPI × T = N × CPI / f

The number of instructions executed per second is f / CPI. When this number is given in millions, its unit is MIPS (million instructions per second).

The three factors of the formula correspond to three different levels of design. N is determined by the program and the compiler. CPI depends on the processor’s architecture: pipelining, caches, and parallel execution units lower CPI. f depends on the fabrication technology and the circuit design. Improving one often worsens another. For example, simplifying instructions lowers CPI but increases N.

1.1.3.4Counting the clock cycles of a loop

CPI is an average. To find the running time of a real program, the cycle counts of the individual instructions are added up. Intel’s 8086 datasheet gives a cycle count for each instruction. The following loop computes the sum 4 + 3 + 2 + 1; the comment on each instruction gives its cycle count.

org 100h
mov cx, 4        ; 4 cycles
mov ax, 0        ; 4 cycles
again: add ax, cx ; 3 cycles
loop again       ; 17 / 5 cycles
hlt              ; 2 cycles

Cycle counts vary with the type of instruction. A mov that loads an immediate value into a register takes 4 cycles. A register-to-register add takes 3 cycles; it is short because there is no memory access. The loop instruction has two durations: a taken loop takes 17 cycles and a not-taken loop takes 5. The difference comes from the jump emptying the prefetch queue. The bytes waiting in the queue are now invalid, because the flow has gone to another address; the BIU has to start fetching again from the target address. hlt takes 2 cycles.

Common mistake

When computing the time of a loop, all passes are wrongly counted of the loop instruction with the same duration. A taken and a not-taken loop take different times (17 and 5 cycles). In a loop that runs n times, loop jumps n − 1 times and falls through on the last pass.

1.1.3.5The growth of clock rates

The clock rates of Intel processors rose from megahertz to gigahertz in forty years. In the 16-bit era the 8086 was produced in 5, 8, and 10 MHz versions. The 8088 ran at 5 and 8 MHz; the 8088 in the IBM PC runs at 4.77 MHz. The 80186/80188 started at 6 MHz, and the 80286 started with 6, 8, 10, and 12.5 MHz versions. In the 32-bit era the 80386 ran in the 16–33 MHz range and the 80486 in the 16–100 MHz range. The DX2 and DX4 versions of the 80486 use a clock multiplier: the on-chip clock is two or three times the external bus clock. The Pentium started at 60 and 66 MHz. In the 64-bit era the Core 2 runs in the 1.2–3 GHz range. The first-generation Core i7 is in the 2.66–3.33 GHz range, the Core i5 in 2.4–3.6 GHz, and the Core i3 in 2.93–3.33 GHz.

The rise from 5 MHz to about 3 GHz is an increase of roughly 600 times in thirty years. Around 2005 this increase stopped. As the clock frequency rises, more transistors switch every second; dynamic power grows in proportion to the frequency and to the square of the supply voltage. The limit of removing the heat the chip produces had been reached. After that, performance gains came mostly from increasing the number of cores and finishing more instructions per cycle, that is, from lowering CPI.

1.1.3.7A 32-bit addition on a 16-bit processor

To see the practical effect of bit width, let us add two 32-bit numbers on the 16-bit 8086: a = 0001FFFFh = 131,071 and b = 00030002h = 196,610. These numbers do not fit in a 16-bit register. 1.1.4Instruction set architectures

Processors can be classified in many ways. Three questions stand out: How are the instructions designed? How much data does an instruction process? What is the processor optimized for? This section takes up the first question, the instruction set architecture: CISC, RISC, and EPIC. Pipelining, the most important technique these architectures rely on, is also followed step by step.

1.1.4.1Overview of processor types

The instruction set of a processor is the full collection of instructions it can execute. The instruction set architecture (ISA) covers these instructions and also the registers, addressing modes, data types, and the way instructions are encoded in memory. The ISA is the contract between software and hardware: two processors that implement the same ISA run the same machine code, however different their internal circuits may be. The three approaches take their names from the following:

  • CISC: Complex Instruction Set Computer.
  • RISC: Reduced Instruction Set Computer.
  • EPIC: Explicitly Parallel Instruction Computing.

1.1.4.2CISC

The CISC approach aims to perform complex operations with a single instruction. Its roots go back to the 1960s and 1970s. In those years memory was expensive and slow, and programs were mostly written by hand in assembly. Doing a job with one instruction both saved memory and made the programmer’s work easier.

Definition 1.1.8

In a CISC architecture a single instruction can include several low-level operations, such as loading from memory, an arithmetic operation, and storing back to memory. Instructions have several addressing modes and direct memory operands. Instruction lengths vary; the number of registers is relatively small; the control unit is usually microprogrammed.

The 8086 is a typical CISC processor. Its instructions are 1 to 6 bytes long; the number of bytes after the opcode varies with the operands. The control unit therefore learns how many bytes an instruction has only after decoding its first bytes, so decoding is complex. There are four general-purpose registers (AX, BX, CX, DX). Many instructions can use memory directly as an operand. Two typical examples:

ADD [BX], AX   ; mem = mem + AX
REP MOVSB      ; copy CX bytes

ADD [BX], AX adds AX to the memory word BX points to: in a single instruction it reads memory, adds, and writes the result back to memory. REP MOVSB copies a block of memory CX bytes long from the place SI points to the place DI points to; one instruction takes the place of a loop. Other examples of the CISC family are the Intel 80386, 80486, and Pentium series, the Motorola 68000, 68020, and 68040, the DEC VAX, and the IBM System/360.

1.1.4.3RISC

Measurements made in the late 1970s gave an interesting result. The code compilers generated used only a very small fraction of the complex instructions in CISC instruction sets. Most of a program consisted of simple load, store, add, and jump instructions. The complex instructions, meanwhile, enlarged the control unit and slowed the simple instructions too. The RISC approach was born from this observation.

Definition 1.1.9

A RISC architecture has a small number of simple, fixed-length instructions (for example, all 32 bits). Only load/store instructions access memory; arithmetic and logic operations are done only between registers. To reduce memory accesses there are many registers (32 or more). The control unit is hardwired and instructions execute in a pipeline. The goal, in the ideal case, is to complete one instruction every clock cycle (CPI ≈ 1).

Fixed-length instructions make decoding easier: every instruction starts at the same place, and the opcode and register numbers are always in the same bit fields. Because only load/store instructions access memory, the great majority of instructions finish in the same time. This regularity is a precondition for pipelining. The complexity does not disappear; it moves to the compiler: the work of one CISC instruction takes several instructions in RISC, and arranging those instructions in a suitable order is the compiler’s job.

Examples of RISC are the IBM RS/6000 (POWER), the Motorola MC88100, the DEC Alpha 21064, 21164, and 21264, MIPS, and SPARC. The most widespread RISC family today is ARM: nearly all phones and tablets, and Apple’s M-series computers, contain ARM cores. RISC-V is an open instruction set that requires no license fee and is spreading quickly both in academia and in embedded systems.

The RISC goal of “one instruction per cycle” does not mean an instruction finishes in a single cycle. An instruction still passes through several stages. Thanks to the pipeline, one instruction completes every cycle; what increases is not the time of a single instruction (its latency) but the number of instructions finished per unit time (the throughput).

1.1.4.4Pipelining

Definition 1.1.10

A pipeline is a technique that divides instruction execution into consecutive stages and executes different stages of consecutive instructions in the same cycle. Each stage is a separate hardware unit and hands its work to the next stage every cycle.

The classic RISC pipeline has five stages: IF (instruction fetch), ID (instruction decode and register read), EX (execute), MEM (memory access), and WB (write back the result to a register). An assembly line in a factory is a good analogy. Even if the complete assembly of a car takes five hours, the line turns out one car every hour, because five stations work on five different cars at the same time.

Figure 1.1.11 shows four independent instructions (I1–I4) passing through the pipeline. The cycles proceed as follows:

  • Cycle 1: I1 is fetched (IF). The other stages are idle.
  • Cycle 2: while I1 is decoded (ID), I2 is fetched. Two instructions are in different stages at the same time.
  • Cycle 3: I1 executes, I2 is decoded, I3 is fetched: three instructions in three stages.
  • Cycle 4: four instructions are in the pipeline at once.
  • Cycle 5: I1 reaches the WB stage and completes. The pipeline is full; from now on one instruction finishes every cycle.
  • Cycles 6, 7, 8: I2, I3, and I4 complete in turn.
Theorem 1.1.1 (Pipeline completion time)

In a k-stage pipeline, n instructions with no dependencies among them finish in

k + n − 1

cycles. Without the pipeline each instruction would take k cycles, and a total of k × n cycles would be needed.

The reasoning behind the formula is simple. The first instruction passes through the pipeline from start to finish in k cycles. After that, one more instruction finishes every cycle; the remaining n − 1 instructions need n − 1 more cycles. The total is k + (n − 1). In the example k = 5, n = 4: 5 + 4 − 1 = 8 cycles. Without the pipeline, 4 × 5 = 20 cycles would be needed.

Example 1.1.6

In a 5-stage pipeline, in how many cycles do 100 instructions finish? How many cycles are needed without the pipeline?

With the pipeline, k + n − 1 = 5 + 100 − 1 = 104 cycles. Without the pipeline, 5 × 100 = 500 cycles. The speedup is 500 / 104 ≈ 4.8 times. As the number of instructions grows, the speedup k n / (k + n − 1) approaches k, the number of stages: for 1000 instructions, 5000 / 1004 ≈ 4.98.

This ideal picture does not always hold. An instruction may need a result that the instruction just before it has not yet written (a data dependency). Until the outcome of a conditional jump is known, it is not known which instruction to fetch (a control dependency). In these cases empty cycles enter the pipeline; this is called a pipeline stall. To reduce stalls, modern processors forward results directly between stages and predict the outcome of jumps in advance.

The 8086’s pipeline is much simpler than this five-stage structure: there are only two stages, fetch (BIU) and execute (EU). The 17 cycles a taken loop takes are also a price of the pipeline: the jump invalidates the prefetched bytes and requires the queue to be refilled.

Common mistake

It is often thought that a pipeline speeds up a single instruction. The time of a single instruction (its latency) is not shortened by the pipeline; it even grows a little because of the registers between stages. What shrinks is the total time of many instructions; the pipeline increases throughput.

1.1.4.5The same job, two approaches

It is instructive to see the difference between the two approaches on a single task: adding the value of a register to a number in memory, that is, memory[addr] += x. On a CISC processor (the 8086) this job is one instruction:

ADD [BX], AX     ; 1 instruction
                 ; read, add, write

On a RISC processor (ARM) it takes three instructions. r1 holds the address and r0 the value to add; in ARM assembly, comments start with the @ sign:

LDR r2, [r1]       @ load
ADD r2, r2, r0     @ add
STR r2, [r1]       @ store

LDR (load register) loads the word in memory into r2. ADD r2, r2, r0 is a three-operand addition: r2 ← r2 + r0. STR (store register) writes the result back to memory. The CISC code is short and takes little space in memory, but the instruction takes many cycles. The three RISC instructions are simple, and each flows smoothly through the pipeline. Because the summed value stays in a register, there is no need to go back to memory if other operations will be done on this number.

The two approaches have blended together today. Since the Pentium Pro, x86 processors translate complex instructions internally into simple RISC-like micro-operations (µops) and execute these micro-operations in a pipeline. From the outside the instruction set is CISC; inside, execution is like RISC.

  3. Write. The result is written back to memory with a second bus cycle: num = 012Ah.

1.1.4.8EPIC

Superscalar processors start more than one instruction in the same cycle. It is the hardware that finds out, at run time, which instructions are independent of each other and can execute together. This hardware is a large, power-hungry circuit. The EPIC approach takes this decision away from the hardware and gives it to the compiler.

Definition 1.1.11

In an EPIC architecture the compiler, not the hardware, decides which instructions can run in parallel and writes this explicitly into the code. Instructions are encoded in 128-bit bundles: each bundle holds three 41-bit instructions and a 5-bit template.

The template field says which kind of execution unit (integer, memory, floating-point, branch) each of the three slots in the bundle goes to, and where a group of instructions that can execute in parallel ends. The processor reads this information and dispatches the instructions straight to the units; no large circuit is needed to search for dependencies. In this way many instructions can execute at once without needing a high clock frequency. The bit boundaries are consistent too: since each instruction takes 41 bits, instruction 0 spans bits 5 to 45, instruction 1 bits 46 to 86, and instruction 2 bits 87 to 127.

The only well-known commercial example of EPIC is the IA-64, the joint architecture of Intel and HP, and the Itanium processors that implement it (2001–2021). The approach did not achieve the expected success. Situations the compiler cannot know at compile time, for example whether a memory access will hit in the cache, limited the parallelism; producing good code put too much burden on the compiler. The Itanium also ran existing x86 software slowly. In the market, AMD’s x86-64 architecture, which extended x86 to 64 bits, won.

1.1.5Processors by data-processing style and application

The instruction set architecture describes how instructions are designed. A second way to tell processors apart is to look at how many data items an instruction processes: a scalar processor handles one, while vector and array processors handle many. A third way is what the processor is optimized for: signal processing, symbolic computation, or graphics. This section introduces these types in turn and uses two small 8086 programs to show the cost of scalar processing.

1.1.5.1Scalar and vector processing

Adding two arrays element by element, that is, C[i] = A[i] + B[i], is a task that comes up constantly in scientific computing and in audio and image processing. A scalar processor does this job with a separate add instruction for each element. A vector processor adds all the elements of the array with a single instruction.

The gain of vector processing does not come only from the addition itself. A scalar processor fetches and decodes an instruction again for each element, decrements and tests the loop counter, and increments the index. A vector processor pays this overhead once. With four elements the gain looks small, but with vectors of a thousand elements the difference becomes very large.

1.1.5.2A scalar loop: code trace

The 8086 is a scalar processor. The following program computes the sum c = a + b for byte arrays of four elements.

org 100h
mov si, 0
mov cx, 4
again: mov al, a[si]  ; read one item
add al, b[si]         ; one add
mov c[si], al         ; write one item
inc si
loop again
ret
a db 3, 5, 7, 9
b db 10, 20, 30, 40
c db 4 dup(0)

SI is the common index of the arrays; CX is the loop counter. The notation a[si] denotes the byte at the address found by adding SI to the start address of array a. In the loop body three instructions do the real work: mov al, a[si] reads one element, add al, b[si] does one addition, and mov c[si], al writes the result. The remaining two, inc si and loop again, are loop overhead. 4 dup(0) reserves a space of four bytes filled with zeros.

1.1.5.3The vector processor

Definition 1.1.12

A vector processor is a processor that performs mathematical operations with a single instruction on arrays of data called vectors. It processes several data elements at the same time, or one after another in a deep pipeline. It has long vector registers and vector load/store units.

For this kind of work a vector processor is much faster than a scalar processor, which works with a single data element. Applications that work with large arrays, such as weather forecasting, physics simulations, and artificial-intelligence models, therefore benefit from vector processing. The famous historical example is the Cray-1 supercomputer (1976). Today vector processing has entered general-purpose processors as extensions: SSE and AVX on x86, NEON and SVE on ARM, and the V extension on RISC-V. For example, a 256-bit AVX register holds eight 32-bit numbers and adds all eight with one instruction.

1.1.5.4The array processor and Flynn’s taxonomy

Definition 1.1.13

An array processor is a processor in which a single control unit broadcasts the same instruction to many processing elements (PEs). Each PE works on data in its own local memory. This arrangement is also called SIMD (single instruction, multiple data).

The difference between a vector processor and an array processor lies mostly in the organization of the hardware. A vector processor can process elements one after another in a single deep pipeline. In an array processor there is a separate processing element for each element, and the elements really are processed at the same time. Array processors are optimized for parallel computation. They are used in supercomputers, servers, and GPUs; they are rare in general-purpose computing. A historical example is the ILLIAC IV.

The classification proposed by Michael Flynn in 1966 divides processors into four groups by the number of instruction and data streams:

1.1.5.5Scalar and superscalar processors

Definition 1.1.14

A scalar processor processes scalar, that is, non-vector, data, one data element per instruction.

Simple scalar processors work only with integers. Powerful ones also handle floating-point numbers; in these, the integer unit (ALU) and the floating-point unit (FPU) are on the same chip. A scalar processor can have a CISC or a RISC architecture; the two classifications are independent of each other. The most common type in general-purpose computing is the scalar processor.

A scalar processor can also execute several instructions at once. A superscalar processor is a scalar processor that starts more than one instruction per clock cycle by means of several pipelines or execution units. Each instruction still works on a single data element; the parallelism lies in the instruction stream, not in the data. The first superscalar processor in the x86 line is the Pentium: it has two pipelines named U and V, and two suitable instructions enter one pipeline each in the same cycle.

In the ideal case in the figure, the superscalar processor starts twice as many instructions in the same time; CPI drops to 0.5. In practice this ratio falls. Two instructions can run in the same cycle only if they are independent of each other: if the second uses the result of the first, it has to wait. On the Pentium the instructions the V pipeline could execute were also limited.

1.1.5.6The digital signal processor (DSP)

Definition 1.1.15

A digital signal processor (DSP) is a processor optimized for operations on digital signals. A digital signal is a sequence of samples that represent sensory information such as sound and images. A DSP has an instruction set and hardware specialized for signal processing: multiply-accumulate (MAC) in a single cycle, circular-buffer addressing, and zero-overhead loops.

DSPs are used in audio processing and filtering, in image processing, and in telecommunications infrastructure (modems, base stations). Well-known examples are the Texas Instruments TMS320 and Analog Devices SHARC families.

The most basic operation in signal processing is the digital filter. A FIR filter (finite impulse response) computes each output sample as a weighted sum of the last N input samples:

y[n] = Σk=0N−1 h[k] · x[n − k]

Here h[k] are the filter coefficients and x the input samples. Each output sample needs N multiplications and N additions. For a 48 kHz audio signal, a filter with 100 coefficients needs 4.8 million multiplications and 4.8 million additions per second. A DSP performs each term in a single cycle with one MAC (multiply-accumulate) instruction:

A ← A + h[k] × x[n − k]

Here A is the accumulator. Circular-buffer addressing automatically wraps the address back to the start when the end of the buffer holding the last N samples is reached, so no bounds checking is done in software. A zero-overhead loop keeps the loop counter in hardware and spends no cycles on the jump at the end of the loop.

1.1.5.7Multiply-accumulate: code trace

How the same computation is done on the 8086 shows clearly why the DSP is a separate type. The following program computes a filter sum with three coefficients: y = h[0]·x[0] + h[1]·x[1] + h[2]·x[2].

org 100h
mov si, 0
mov bx, 0        ; sum
mov cx, 3        ; term count
again: mov al, h[si]

add bx, ax       ; accumulate

h db 2, 3, 1

1.1.5.8The symbolic processor

Definition 1.1.16

A symbolic processor is a processor designed to compute on symbols, lists, and rules instead of numbers. It is also called a PROLOG or LISP processor.

Symbolic processors concentrate on semantic computation and on the rules of symbolic logic. They process mathematical expressions as symbols; they can simplify complex expressions and take derivatives. Application areas are expert systems, machine intelligence, and rule-based inference. The following Prolog fragment is an example of this kind of computation:

father(ali, veli).
grandpa(X, Z) :- father(X, Y),
                 father(Y, Z).

The first line is a fact: Ali is Veli’s father. The rule that follows requires, for X to be Z’s grandfather, that X be the father of some Y and that Y be the father of Z. The program does not compute numbers; it draws conclusions by looking for matches among facts and rules. The main parts of this work in hardware are list processing, matching, and backtracking.

The LISP machines of the 1980s (for example those of Symbolics) and Japan’s Fifth Generation Computer project were of this kind. As general-purpose processors got faster, the advantage of special hardware disappeared. Today this work is done in software on general-purpose processors.

1.1.5.9The graphics processing unit (GPU)

Definition 1.1.17

A graphics processing unit (GPU) is a processor made up of many simple cores, designed to accelerate two- and three-dimensional graphics.

A screen frame consists of millions of pixels, and the color of each pixel is computed with the same formula, only on different data. The GPU exploits this structure: thousands of simple cores run the same program on different pixels. This arrangement is a form of SIMD; GPU vendors call it SIMT (single instruction, multiple threads). The GPU produces real-time, high-quality graphics; it is effective at rendering tasks such as shading, texturing, and rasterization. It is used in graphics cards and accelerator cards.

CPUs and GPUs are designed for different goals. A CPU has a few powerful cores; the aim is to reduce the latency of a single thread and to run complex, branch-heavy flows quickly. Most of the chip area goes to cache and control circuitry. A GPU has thousands of simple cores; the aim is to increase total throughput, not the time of a single job. Any job that works on parallel data benefits from this structure. GPGPU (general-purpose computing on GPU) is the use of the GPU, through programming environments such as CUDA or OpenCL, for non-graphics work such as scientific computing and deep learning.

1.1.6Evolution of the Intel x86 family

The 8086 was not born in a vacuum. Before it lies a short but rapid history of 4-bit and 8-bit processors, and after it a family that is still going today. This section follows that history starting from the transistor, lists the innovations each processor generation brought, and discusses the strengths and weaknesses of the x86 architecture.

1.1.6.1From the transistor to the microprocessor

The history of the microprocessor can be summarized by three inventions.

  • 1947, the transistor. At Bell Laboratories, John Bardeen, Walter Brattain, and William Shockley invented the transistor; the invention was announced in 1948. The transistor did the switching and amplifying that the vacuum tube did, with a semiconductor that was much smaller, more durable, and used less power. The microelectronics revolution began this way.
  • 1958, the integrated circuit. At Texas Instruments, Jack Kilby demonstrated the first integrated circuit (IC). Many transistors and their connections could be fabricated together on a single piece of semiconductor. Complex circuits thus became small and cheap.
  • 1971, the first microprocessor. The Intel 4004 fit an entire CPU on a single chip. The microprocessor could now take on the job of a computer’s central processing unit by itself.

The result is visible everywhere today. Computers shrank from the size of a room to a desktop, and from there to a pocket. At every step they became smaller, more powerful, faster, and cheaper.

1.1.6.2Timeline

The name x86 comes from the common “86” ending of the names 80186, 80286, 80386, and 80486 that followed the 8086. All members of the family can run 8086 code. This property is called backward compatibility, and it is the basis of x86’s success of more than forty years: every new processor runs the software users already have, unchanged. There is also a consequence: when a present-day Core i7 is powered on, it starts in real mode, behaving like an 8086 and working with 20-bit addresses. The wider features are reached only when software switches the processor to another mode.

1.1.6.7Transistor count and Moore’s law

Definition 1.1.18

Moore’s law is an observation by Gordon Moore, one of the founders of Intel. In the form Moore put forward in 1965 and corrected in 1975, the number of transistors per chip doubles roughly every two years.

The observation is not a law of nature but a target the semiconductor industry held to for decades. It is easy to check. From the 4004 (1971, 2,300 transistors) to the Core 2 Quad (2008, 820 million), 37 years passed. The ratio is 820 × 106 / 2300 ≈ 356,500 and lies between 218 = 262,144 and 219; that is, about 18 doublings. Doubling every two years over 37 years comes to 37 / 2 ≈ 18.5 doublings. Over this range the observation held with surprising accuracy. The growth in transistor count is the raw material of all the innovations described in this chapter, such as caches, pipelines, and multiple cores.

1.1.6.8The 8080 and the 8086

The structure, organization, and technology of microprocessors changed radically in a short time. This change runs from the first general-purpose microprocessor, the 8080, to the 29,000-transistor 8086, and from there to the four-core Core 2 with 820 million transistors. The processor of this course is the 8086; comparing it with its predecessor, the 8080, shows which step was taken and why.

The 8080 (1974) is cited as the first general-purpose microprocessor. Its data bus is 8 bits and its address bus 16 bits; it addresses 64 KB of memory. It was used in the first personal computers, for example the Altair 8800.

The 8086 (1978) is a 16-bit processor: its data bus is 16 bits, and it has more 16-bit registers than the 8080. Its address bus is 20 bits and it addresses 1 MB of memory. It works only in real mode; there is no memory protection. Its most important innovation is that it prefetches instructions before executing them and holds them in a 6-byte instruction queue. While the BIU fills the queue, the EU executes the previous instruction; fetching and execution overlap. The 8086 has no cache; the speed gain comes from this queue. An on-chip cache came to x86 only with the 80486.

Example 1.1.7

Roughly what is the gain from the queue? On the 8086, a 2-byte instruction would, without the queue, first be fetched with one bus cycle (4 cycles) and then executed. For a 3-cycle instruction such as add ax, cx this would come to 4 + 3 = 7 cycles. When the queue is full, the fetch has already been done while earlier instructions executed, and the instruction finishes in 3 cycles. This is why the cycle counts in the datasheet are given under the assumption “queue full.” On jumps the queue is flushed, so the gain is lost; this is the reason a taken loop takes 17 cycles.

1.1.6.9The 80286, 80386, and the 80486

The 80286 (1982) addresses 16 MB of memory with its 24-bit address bus. Besides real mode, it offers a 16-bit protected mode. Its data bus and registers are still 16 bits.

The 80386 (1985) is Intel’s first 32-bit microprocessor. It supports multitasking in hardware. It brings 32-bit protected mode, paging, and virtual 8086 mode; it addresses 4 GB of memory. Virtual 8086 mode lets an operating system running in protected mode run old 8086 programs, each in its own isolated environment.

The 80486 (1989) brings an on-chip cache (8 KB) and an instruction pipeline. It adds page write protection (the WP bit of the CR0 register). It contains an integrated math coprocessor (FPU) for complex arithmetic; this unit had previously been a separate chip, the 80387.

Definition 1.1.19

Protected mode is the operating mode that isolates each program’s memory from the others. If a program tries to access memory that was not allocated to it, the processor blocks the access and notifies the operating system. A program’s bug therefore cannot crash the operating system or other programs. This is the foundation of modern operating systems.

The real mode of the 8086 has no such protection. A program can write anywhere in the 1 MB, for example to the operating system’s own code or to the interrupt vector table. This is why it was common in the DOS era for a faulty program to lock up the whole computer.

1.1.6.10The Pentium family

The Pentium (1993) is superscalar; two instructions can run at the same time in two pipelines (U and V). It uses branch prediction in x86 for the first time: it predicts the outcome of a conditional jump from its earlier behavior and fills the pipeline along the predicted path. The page size extension (PSE) improves paging by using 4 MB pages alongside 4 KB pages. Instruction and data caches are separate.

The Pentium Pro (1995) changes execution fundamentally with three techniques: advanced branch prediction, out-of-order execution through data-flow analysis, and speculative execution. In out-of-order execution, an instruction whose operands are ready executes without waiting for an earlier instruction that is waiting on a result; the results are still committed in program order. In speculative execution, instructions on the predicted branch path are executed before the outcome is confirmed; if the prediction turns out wrong, the results are discarded. Intel called the combined use of these three techniques “dynamic execution.” The Pentium Pro puts the level 2 (L2) cache inside the same package. With PAE (physical address extension), 32-bit virtual addresses are translated to 36-bit physical addresses and up to 64 GB of memory can be reached.

The Pentium II (1997) combined MMX technology, integer SIMD instructions for multimedia, with the Pentium Pro core. It handles video, audio, and graphics data efficiently. MMX had first appeared in early 1997 with the “Pentium MMX”; the Pentium II took it over.

The Pentium III (1999) brought SSE (Streaming SIMD Extensions): 70 new instructions and floating-point SIMD. It supports three-dimensional graphics software. The highest clock speed is 1.4 GHz.

The Pentium 4 (2000) added floating-point improvements for multimedia (first SSE2, then SSE3). With a very deep pipeline called NetBurst it reached up to 3.8 GHz and brought Hyper-Threading. Hyper-Threading lets a single core execute two threads at the same time; the operating system sees one core as two logical processors. The very deep pipeline allowed high frequency, but the number of stages flushed on every mispredicted branch also grew, and power consumption rose. The clock-speed race reached its limit with this generation.

1.1.6.11Core and Core 2

The Core (Core Duo, 2006) is a low-power design of mobile origin. Two cores sit on the same die and share the L2 cache; it is the first Intel processor in which two cores on the same die share a cache. Virtualization technology (VT-x) was added with this generation.

The Core 2 (2006) uses the 64-bit architecture (Intel 64): a 64-bit register set and addressing modes. The Core 2 Quad offers four cores in a single package; inside the package there are two dual-core dies.

Intel’s first dual-core desktop processor was the Pentium D, released in 2005. In this processor the two cores had separate L2 caches and communicated with each other over the external bus; in the 2006 version the two cores were placed in the same package as two separate dies. Sharing a cache lets cores use common data without going to memory.

A die and a package are different things. A die is a single piece of chip cut from the silicon wafer. The package is the outer casing that carries the die (or several dies) and has the pins and the heat spreader. The “processor” in the user’s hand is the package.

1.1.6.12Strengths and weaknesses of the x86 architecture

There are four reasons for x86’s long life.

  • Compatibility: old software runs unchanged on new x86 processors. Code written for the 8086 in 1978 can still run today.
  • Performance: every new processor generation has been faster and more efficient than the one before.
  • Versatility: a wide range of uses, from personal computers to servers, and from embedded systems to mobile devices.
  • Broad industry support: a large community of hardware and software vendors supports x86; this support has been the driving force of innovation and progress.

The same history also explains the architecture’s weak points.

  • Complex instruction set: thousands of instructions and variable-length encoding complicate the decoder hardware; optimizing code for performance becomes harder. Backward compatibility requires keeping even old instructions that are no longer used.
  • Power consumption: the evolution of x86 brought a significant increase in power consumption. In devices where battery life is critical this is a major problem.
  • Heat dissipation: the more powerful processors get, the hotter they run; cooling costs and noise rise.
  • Cost and licensing: only companies with a license agreement (for example AMD) can make x86 processors; competition is limited.

For these reasons ARM (RISC) dominates phones and tablets, while x86 is strong on the desktop and in servers. In recent years ARM-based processors have entered laptops and servers too.

1.1.7Modern processor features

The difference between the 8086 and today’s processors is not only in clock speed. This section first shows with a numerical example why clock speed alone is not a measure of performance. It then lists the features that determine the performance of today’s processors and explains the memory hierarchy.

1.1.7.1Clock speed alone is not performance

The CPU-time formula is the basis of this section:

CPU time = N × CPI × T = N × CPI / f

Here N is the number of instructions executed, CPI is the average number of clock cycles per instruction, and f is the clock frequency (T = 1/f). The formula makes it clear that clock frequency is only one of three factors.

Example 1.1.8

The same program (N = 109 instructions) runs on two processors. Processor A: f = 2 GHz, CPI = 2. Processor B: f = 1.5 GHz, CPI = 1. Which is faster?

A: 109 × 2 / (2 × 109) = 1 s
B: 109 × 1 / (1.5 × 109) ≈ 0.67 s

B, with the lower clock, is 1 / 0.67 = 1.5 times, that is, 50% faster. A executes 2 × 109 / 2 = 109 instructions per second, and B executes 1.5 × 109 / 1 = 1.5 × 109.

Clock speed is “cycles per second,” not “instructions per second.” Instructions per second is f / CPI, and architecture (pipelining, caches, superscalar design) lowers CPI. The move from the Pentium 4 to the Core generation is a historical example of this. Core processors had lower clock speeds, but their CPI was lower too. They ran faster than the Pentium 4 and also used less power.

Common mistake

It is a mistake to compare two processors by clock speed alone. Clock speed is enough only to compare two processors of the same architecture with the same CPI. Across different architectures CPI, and even N for the same program, can differ; the right comparison is the time of the same program on the two processors.

1.1.7.2Features that determine performance

Clock speed: the number of clock cycles per second (GHz). The instruction rate also depends on CPI.

Instruction set architecture (ISA): architectures such as CISC and RISC affect efficiency and complexity. The ISA is the contract between software and hardware.

Cache: a small, very fast memory that keeps frequently used data next to the processor. Its levels are called L1, L2, and L3.

Multiple cores: let several tasks truly run at the same time and raise total performance. To speed up a single program, however, the program must be divided into threads.

Virtualization: lets several operating systems, that is, virtual machines, run on the same hardware isolated from one another. Hardware support is called VT-x on Intel and AMD-V on AMD.

Power management: when load falls, the clock frequency and supply voltage are lowered; this is called DVFS (dynamic voltage and frequency scaling). Idle cores are put into sleep states (C-states). Intel’s SpeedStep and Turbo Boost technologies work on this principle: Turbo Boost briefly raises the frequency of some cores when the thermal and power limits allow. Since dynamic power is roughly proportional to C V2 f, lowering the voltage reduces power quadratically.

Graphics processing: modern processors include an integrated graphics processing unit (iGPU); graphics-intensive tasks are handled faster and more efficiently without a separate graphics card.

Security features: hardware-level encryption (AES-NI instructions), secure boot, and isolated secure regions (TPM, SGX, ARM TrustZone).

Connectivity: especially in mobile and embedded chips, network units such as Wi-Fi, Bluetooth, and Ethernet are inside the chip.

Machine learning: special units have been added for artificial intelligence: neural processing units (NPUs), matrix accelerators (Intel AMX), and vector dot-product instructions.

System on chip (SoC): the CPU, GPU, NPU, memory controller, and I/O are combined on one chip. This trend is a return, on a larger scale, to the microcontroller’s “everything on one chip” idea. The processors in phones and Apple’s M series are SoCs.

1.1.7.3Caches and the memory hierarchy

Over the years processor speed has grown much faster than memory speed. While a present-day processor finishes several instructions in one cycle, a read from main memory takes 50–100 ns, that is, hundreds of cycles. If every access went to main memory, the processor would spend most of its time waiting. The solution is to use memories of different speeds and sizes together in a hierarchy.

Definition 1.1.20

A cache is a small, fast memory that keeps a copy of the frequently used part of the data in main memory next to the processor. The principle of locality is the tendency of programs to access the same data again within a short time (temporal locality) and to access data at nearby addresses one after another (spatial locality).

The reason a cache works is the principle of locality. The instructions of a loop are read again on every pass; the elements of an array are read from consecutive addresses. The cache keeps this small working set close to the processor, and the great majority of accesses are found in the cache. The average access time therefore falls far below that of RAM.

Example 1.1.9

Access to the cache takes 1 ns and access to main memory takes 100 ns. If 95% of accesses are found in the cache, what is the average access time?

95% of accesses take 1 ns. In the remaining 5%, the cache is looked at first (1 ns), and when the data is not found, main memory is accessed (100 ns):

average = 1 + 0.05 × 100 = 1 + 5 = 6 ns

The 100 ns access time of main memory falls to 6 ns on average; an improvement of about 17 times. If the hit rate rises to 99%, the average becomes 1 + 0.01 × 100 = 2 ns.

The 8086 had no cache; a memory access took only four clock cycles anyway, and processor and memory speeds were close to each other. This balance broke down in the late 1980s. The 80486 brought the on-chip cache, the Pentium separate instruction and data caches, the Pentium Pro the L2 in the same package, and the Core i7 an L3 shared among the cores.

Common mistake

It is often thought that a cache speeds up the RAM or compresses the data. A cache does not speed up the RAM itself and does not compress data. It only keeps a copy of the frequently used data nearby; because most accesses are served without ever going to RAM, the average time falls. In a program with poor locality, for example one that accesses addresses scattered randomly in memory, the gain from the cache is small too.

1.1.8Common mistakes

  • Confusing the data bus with the address bus. The address bus determines the addressable memory (2n bytes); the data bus determines the number of bits carried in one access. The 16-bit 8086 addresses 1 MB.
  • Assuming IP grows by 1 with every instruction. IP holds a byte address and grows by the length of the instruction; 8086 instructions are 1–6 bytes.
  • Confusing the instruction cycle, the bus cycle, and the clock cycle. The clock cycle is the smallest unit of time. A bus cycle on the 8086 is at least 4 clock cycles. An instruction cycle can contain one or several bus cycles and can also include clock cycles that are not bus cycles.
  • Counting a taken and a not-taken loop with the same duration. On the 8086 a taken loop takes 17 cycles and a not-taken one takes 5; in a loop with n passes there are n − 1 jumps.
  • Adding the high half with add in a multiword addition. The carry from the low half is added only by adc.
  • Thinking the pipeline speeds up a single instruction. The pipeline raises throughput, not latency; n instructions finish in k + n − 1 cycles.
  • Equating clock speed with performance. The time is N × CPI / f; a processor with a low clock but a low CPI can be faster.
  • Basing the definition of “n-bit processor” on the external data bus. The definition rests on register and ALU width: the 8088’s external bus is 8 bits but the processor is 16-bit; the Pentium’s external bus is 64 bits but the processor is 32-bit.
  • Thinking the cache speeds up the RAM. The cache only keeps a copy of frequently used data nearby; its gain comes from the principle of locality.

1.1.9Exercises and solutions

These exercises are the worked versions of the questions on the exercise slide of the presentation.

1.1.9.1Clock period and bus cycle

Question. On a 5 MHz 8086, what are the clock period and the duration of a 4 T bus cycle?

Solution. T = 1 / f = 1 / (5 × 106) s = 200 ns. A bus cycle is four cycles: 4 × 200 ns = 800 ns.

1.1.9.2A 24-bit address bus

Question. How many bytes of memory can a 24-bit address bus address? Which processor has one?

Solution. 224 = 16,777,216 bytes. Since 1 MB = 220 bytes, this is 24 = 16 MB. The 80286 has a 24-bit address bus.

1.1.9.3100 instructions on a five-stage pipeline

Question. In a 5-stage pipeline, in how many cycles do 100 instructions finish? How many cycles are needed without the pipeline?

Solution. k + n − 1 = 5 + 100 − 1 = 104 cycles. Without the pipeline, 5 × 100 = 500 cycles are needed. The speedup is 500 / 104 ≈ 4.8 times.

1.1.9.4Execution time

Question. How many seconds does a program of N = 2 × 109 instructions take on a 3 GHz processor with CPI = 1.5?

Solution. 2 × 109 × 1.5 / (3 × 109) = 1 s.

1.1.9.5Microprocessor or microcontroller?

Question. For a washing-machine controller and for a laptop, is a microprocessor or a microcontroller chosen? Why?

Solution. For the washing machine, a microcontroller: it is cheap, uses little power, and does a single fixed job; memory and I/O are inside the chip. For the laptop, a microprocessor: high performance, gigabytes of memory, and an operating system are needed.

1.1.9.6An EPIC bundle

Question. How are the 128 bits of an EPIC bundle divided?

Solution. Three 41-bit instructions take 3 × 41 = 123 bits; the remaining 5 bits are the template: 123 + 5 = 128.

1.1.10Summary

  • The microprocessor is a programmable CPU chip that runs the instructions in memory with the fetch–decode–execute cycle. The microcontroller also carries memory and peripherals on the same chip; it is used in cheap, low-power systems dedicated to a single job.
  • The CPU talks to the outside world over three buses: the address bus (unidirectional; n lines address 2n bytes), the data bus (bidirectional), and the control bus. The 8086 has a 20-bit address bus (1 MB) and a 16-bit data bus.
  • The instruction cycle consists of the fetch, decode, execute, and result stages. IP holds the address of the next instruction and grows by the length of the instruction; jumps write a new value into IP.
  • The CPU consists of the ALU, the control unit, the registers, and the bus interface. On the 8086 the BIU prefetches instructions and holds them in a 6-byte queue, and the EU executes them.
  • The period is T = 1/f; on the 8086 a bus cycle is at least 4 T. CPU time = N × CPI / f. Clock speed alone is not a measure of performance.
  • The time of a loop is found by adding up the cycle counts of the instructions; in loops with small bodies, the cost of the jumps determines the time.
  • A 16-bit processor holds 32-bit numbers in register pairs and adds them with add + adc.
  • CISC offers rich, variable-length instructions; RISC offers simple fixed-length instructions + load/store + a pipeline; EPIC offers compiler-driven parallelism. In a k-stage pipeline, n instructions finish in k + n − 1 cycles.
  • Vector and array (SIMD) processors process many data items with one instruction; a DSP does multiply-accumulate in one cycle; a GPU exploits data parallelism with thousands of simple cores; symbolic processors process rules and symbols.
  • Intel 4004 (1971) → 8080 (8-bit) → 8086 (1978, 16-bit, 1 MB) → 80286 (protected mode) → 80386 (32-bit) → 80486 (cache, FPU) → Pentium (superscalar) → Core 2 (64-bit, multicore). Backward compatibility is x86’s greatest strength.
  • Modern processors gain performance from caches, multiple cores, virtualization, power management, and special accelerators. The gain from a cache comes from the principle of locality.

1.1.12Test Yourself

  1. The loop examined in the clock-cycle count (mov cx, 4 … hlt, 78 cycles) takes how many microseconds on a 10 MHz 8086?

    Answer

    At 10 MHz, T = 100 ns. The cycle count does not depend on the frequency: 78 × 100 ns = 7.8 µs. The time is half the 15.6 µs at 5 MHz.

  2. If mov cx, 5 is written instead of mov cx, 4 in the same loop, how many cycles does the loop take and what is AX?

    Answer

    The body runs five times; loop jumps four times and falls through once: 4 + 4 + 5 × 3 + 4 × 17 + 5 + 2 = 98 cycles. AX = 5 + 4 + 3 + 2 + 1 = 15. At 5 MHz the time is 98 × 200 ns = 19.6 µs.

  3. If the program in the IP trace started at address 0200h instead of 0100h, would the machine code of loop again change?

    Answer

    It would not. loop stores not the target address but the displacement relative to the next instruction. The label would be at 0206h and the next instruction at 020Ah; the displacement is still −4 (FCh) and the code is still E2 FC.

  4. DX:AX = 0000FFFFh and CX:BX = 00000001h, and add ax, bx and adc dx, cx are executed. What are AX, DX, CF, and ZF after each instruction?

    Answer

    add ax, bx: FFFFh + 0001h = 10000h; AX = 0000h, CF = 1, ZF = 1. adc dx, cx: 0000h + 0000h + 1 = 0001h; DX = 0001h, CF = 0, ZF = 0. The result is DX:AX = 00010000h = 65,536.

  5. With AL = 05h, add al, 0FBh is executed. What are AL, ZF, and CF?

    Answer

    05h + FBh = 100h. The 9th bit does not fit in AL: AL = 00h, CF = 1. Because the result is zero, ZF = 1. In the signed interpretation 5 + (−5) = 0 is a correct result, and OF stays 0.

  6. In a 6-stage pipeline, in how many cycles do 50 independent instructions finish? How many cycles are needed without the pipeline?

    Answer

    6 + 50 − 1 = 55 cycles. Without the pipeline, 6 × 50 = 300 cycles. The speedup is 300 / 55 ≈ 5.5 times.

  7. If the scalar loop (c = a + b with four elements) were applied to arrays of 100 elements, how many instructions would execute? How many of them would be additions?

    Answer

    2 + 100 × 5 = 502 instructions; 100 of them are additions. The remaining 402 instructions are reads, writes, loop overhead, and setup.

  8. A processor runs at 2.4 GHz with CPI = 0.8. How many million instructions does it execute per second? How many seconds does a program of 6 × 109 instructions take?

    Answer

    f / CPI = 2.4 × 109 / 0.8 = 3 × 109 instructions/s, that is, 3000 MIPS. The time is 6 × 109 / (3 × 109) = 2 s.

  9. Access to the L1 cache takes 2 ns and access to main memory takes 80 ns, and 90% of accesses are found in the cache. What is the average access time?

    Answer

    2 + 0.10 × 80 = 2 + 8 = 10 ns. This is an 8-fold improvement over main memory.

  10. How many address lines are needed to address 4 GB of memory? How many lines would have to be added to the 8086’s address bus?

    Answer

    4 GB = 22 × 230 = 232 bytes, that is, 32 lines. 12 lines would have to be added to the 8086’s 20; the 80386’s address bus is 32 bits.
