Introduction

Program Flow Control

  • Normally the CPU executes instructions in memory order: after each instruction, IP (Instruction Pointer) advances by the instruction's length.
  • Flow control instructions load a new value into IP and move execution somewhere else.
  • This is how decisions (if/else) and loops (for/while) are built at the machine level.
Unconditional jumpJMP target: always jumps.
Conditional jumpsSingle-flag tests, plus signed and unsigned comparisons.
LoopsLOOP, LOOPE/LOOPZ, LOOPNE/LOOPNZ, JCXZ.

Unconditional Jump

JMP: Unconditional Jump

  • JMP target transfers control to another point in the program unconditionally; it does not change the flags.
  • It can jump both forward and backward.
  • A near jump reaches anywhere in the current code segment (64 KB = 65,536 bytes, offsets 0000h–FFFFh); only IP changes.
  • A far jump changes CS and IP together and moves to another segment.
  • If the target is close, the assembler can pick the 2-byte short form automatically.

Labels

  • To define a label, write its name followed by :: again:
  • It may contain letters, digits and characters such as _, but it cannot start with a digit.
  • It can stand on its own line or in front of an instruction: back: jmp stop
  • A label takes no memory; the assembler turns it into an address (offset).
  • Instruction and register names (mov, ax …) cannot be labels; each label is defined once.

Unconditional Jump

Computing the Displacement

Forward jump: the distance is measured from the address after the jump → +2.

At run time the CPU computes IP ← next IP + rel8 = 010Ah + 4 = 010Eh.

Backward jump: the distance is negative and stored in two's complement: −6 → FAh. 010Eh + FFFAh = 0108h (the carry out is dropped).

Conditional Jumps

The Idea of a Conditional Jump

  • Jcc target: if the condition (cc) holds, IP ← target; otherwise the next instruction runs.
  • The condition depends on the flags set by an earlier instruction (usually CMP, SUB, ADD, TEST, DEC).
  • Jump instructions themselves do not change the flags.

Conditional Jumps

Encoding and Synonyms

  • On the 8086, conditional jumps have a fixed length: 2 bytes = opcode + a 1-byte displacement (rel8).
  • rel8 is always signed: relative to the next instruction, a jump can go 128 bytes back or 127 bytes forward.
  • Different names for the same condition (synonyms) assemble to the same machine code: JE = JZ, JNE = JNZ, JC = JB = JNAE, JNC = JNB = JAE.
  • Conditional jumps with 16-bit displacements (0F 8x) came only with the 80386; the 8086 does not have them.

Comparison

The CMP Instruction

  • Use CMP dest, src to compare numbers.
  • CMP performs a SUB: dest − src, but it discards the result; it only sets the flags (CF, ZF, SF, OF, PF, AF).
  • The conditional jump that follows decides based on these flags.
  • Operands: register–register, register–memory, memory–register, register/memory–immediate. Two memory operands are not allowed.
CMP 05h, 02h5 − 2 = 3 → 03hZF = 0, CF = 0, SF = 0, OF = 0
CMP 07h, 07h7 − 7 = 0 → 00hZF = 1, CF = 0, SF = 0, OF = 0
Example 1: 5 − 2 = 3 → the result is not zero, ZF = 0. Example 2: 7 − 7 = 0 → the result is zero, ZF = 1, and JE/JZ jumps.

Comparison

How Does CMP AL, BL Set the Flags?

Positive difference: no flag is set except PF (PF = 1 because 03h = 0000 0011 has two 1s).

Equal numbers: the result is 0 → ZF = 1. Equal whether signed or unsigned.

Subtracting a larger number needs a borrow → CF = 1; the result FEh = −2 → SF = 1, no overflow.

127 − (−128) = 255 does not fit in a signed byte → OF = 1. Unsigned, 127 < 128 (CF = 1); signed, 127 > −128 (SF = OF).

FBh is 251 unsigned and −5 signed. Unsigned: 251 > 3 (CF = 0); signed: −5 < 3 (SF ≠ OF). Same bits, different decision!

Comparison

Why SF = OF?

  • CMP A, B computes A − B. Without overflow the sign of the result is correct: SF = 1 ⇔ A < B.
  • With overflow (OF = 1) the result did not fit in 8/16 bits and the sign bit is flipped.
  • So the true sign is SF XOR OF: SF ≠ OF ⇔ A < B, SF = OF ⇔ A ≥ B.

In the overflow rows, SF alone would give the wrong answer; combined with OF the decision is correct.

Code Trace: Same Bits, JA and JG

AL = FBh: unsigned 251, signed −5. BL = 3. CL, CH, DL will mark which jump was not taken.

CMP AL, BL: FBh − 03h = F8h. No borrow → CF = 0; negative result → SF = 1; no overflow → OF = 0.

JA: CF = 0 and ZF = 0 → jumps (251 > 3). The CL = 1 line is skipped.

JG: ZF = 0 but SF ≠ OF → no jump (−5 < 3).

CH = 1: in the signed comparison AL is not greater. One CMP, two different decisions.

AL = 7Fh = 127. Now compare 127 with 80h (−128).

7Fh − 80h = FFh: signed 127 − (−128) = 255 does not fit → OF = 1, the result's sign bit SF = 1. Borrow → CF = 1.

JG: ZF = 0 and SF = OF (1 = 1) → jumps: 127 > −128 is true. SF alone would have said “less”.

DL stays 0. Result: CH = 1 (−5 > 3 is false), DL = 0 (127 > −128).

MOV  CL, 1       ; if JA failed
a1:  JG  g1      ; signed: -5 > 3 ?
MOV  CH, 1       ; JG not taken
g1:  MOV AL, 7Fh ; 127
CMP  AL, 80h     ; 127 - (-128)
JG   g2          ; SF = OF ?

The if / else Pattern

High Level

if (ax == bx) {
    ; block A
} else {
    ; block B
}
while (cx > 0) {     ; unsigned
    ; body
}

Assembly

    cmp ax, bx
    jne not_eq     ; the OPPOSITE test
    ; block A
    jmp after
not_eq:
    ; block B
after:
top: cmp cx, 0
    jbe done       ; cx <= 0 → exit
    ; body
    jmp top
done:
Skipping a block with the opposite condition keeps the code in the same order as the high-level version. Forget the jmp after at the end of block A, and block B runs too.

Comparison · Step through the code

Code Trace: if / else and while

if (AX == BX) DX = 1; else DX = 2; then, with CX = 2, while (CX > 0) DX += CX. AX = 12, BX = 30.

CMP AX, BX: 12 − 30 → ZF = 0 (not equal), borrow → CF = 1.

JNE not_eq: the opposite condition holds → block A is skipped.

Block B: DX = 2. The next line is after; the JMP after in block A was not needed on this path.

CX = 2. CMP CX, 0: 2 > 0 → CF = 0, ZF = 0; JBE does not jump, the body is entered.

Body: DX = 2 + 2 = 4; CX = 1.

JMP top: the condition is tested again; 1 > 0 → JBE does not jump.

DX = 4 + 1 = 5; CX = 0 → DEC sets ZF = 1.

Back at the top: CX = 0 → ZF = 1, JBE done jumps. Because the condition is tested first, CX = 0 would never enter the loop.

Result DX = 5: block B (2) + 2 + 1.

MOV  BX, 30
CMP  AX, BX
JNE  not_eq      ; OPPOSITE test
MOV  DX, 1       ; block A: AX = BX
JMP  after
not_eq: MOV DX, 2 ; block B: AX ≠ BX
after: MOV CX, 2 ; while (CX > 0)
top: CMP CX, 0
JBE  done        ; CX ≤ 0 → exit
ADD  DX, CX      ; body
DEC  CX
JMP  top
done: RET

Comparison

Out-of-Range Conditional Jump

  • On the 8086 a conditional jump reaches only −128…+127 bytes.
  • If the target is farther, the assembler reports an error. Fix: invert the condition, short-jump over the next instruction, and reach the far target with a JMP (near, ±32 KB).
  • emu8086 does this rewrite itself, turning an out-of-range Jcc into an inverted short jump plus a JMP; assemblers such as MASM report an error.

Wrong (target too far)

cmp al, 0
je  far_away    ; out of range!
; ... 200 bytes of code ...
far_away:

Right

cmp al, 0
jne cont        ; opposite test, short
jmp far_away    ; near JMP (E9)
cont:
; ... 200 bytes of code ...
far_away:

Loops

How Does LOOP Work?

  • Loops repeat a block of code depending on a condition.
  • LOOP target: CX is decremented first; if it is not zero, jump to the label. Same effect as DEC CX + JNZ, but the flags are preserved.
  • LOOPE / LOOPZ jumps while CX ≠ 0 and ZF = 1; LOOPNE / LOOPNZ while CX ≠ 0 and ZF = 0.
  • JCXZ: jumps to the label when CX is zero.
  • With CX = 0 on entry, the first decrement makes CX FFFFh → the body runs 65,536 times.

JCXZ and LOOP / DEC–JNZ

Guarding against a zero-pass loop

mov cx, n        ; n known at run time
jcxz skip        ; skip if CX = 0
again:
    ; body
    loop again
skip:

Without JCXZ, LOOP with CX = 0 first makes CX FFFFh and the body runs 65,536 times.

Loops · Step through the code

Code Trace: JCXZ Guard and DEC–JNZ

The pass count n = 0 is in CX. An unguarded LOOP would first make CX FFFFh and run the body 65,536 times.

JCXZ skip: CX = 0 → the loop is never entered. AX stays 0.

Second loop: counter BX = 3 (DEC–JNZ can use any register).

STC: CF = 1. Think of it as information that must survive the loop.

Pass 1: AX = 1. DEC BX → 2, ZF = 0 → JNZ jumps back. CF is still 1.

Pass 2: AX = 2, BX = 1.

Pass 3: AX = 3. DEC BX → 0, ZF = 1. INC/DEC did not touch CF: CF = 1.

JNZ: ZF = 1 → no jump, the loop ends.

Result AX = 3, CF = 1 preserved. LOOP does not change flags either, but works only with CX.

MOV  CX, 0       ; n = 0
MOV  AX, 0
JCXZ skip        ; CX = 0 → skip
again: INC AX
LOOP again
skip: MOV BX, 3  ; n = 3, counter BX
STC              ; CF = 1
again2: INC AX
DEC  BX          ; CF is kept
JNZ  again2
RET

add al, vector[bx]  ; add element
inc bx              ; next element
loop next           ; until CX = 0
mov m, al           ; store in m
ret
vector db 5, 4, 5, 2, 1
m db 0

Code Trace: Printing Hello on the Screen

jmp start: the data (msg) sits between instructions, so it is jumped over; otherwise bytes such as 'H' (48h) would be taken as instructions.

SI = 0: first character.

AL = msg[0] = 'H' = 48h.

48h − 0 ≠ 0 → ZF = 0, je does not jump.

AH = 0Eh, INT 10h → prints H.

SI = 1, jmp next_char goes back to the top.

Next pass: AL = 'e' (65h), ZF = 0 → prints e, SI = 2.

Next pass: AL = 'l' (6Ch), ZF = 0 → prints l, SI = 3.

Next pass: AL = 'l' (6Ch), ZF = 0 → prints l, SI = 4.

Next pass: AL = 'o' (6Fh), ZF = 0 → prints o, SI = 5.

AL = msg[5] = 0: end of the string (null terminator).

0 − 0 = 0 → ZF = 1, je stop jumps.

ret: the screen shows Hello.

org     100h
jmp     start
msg db 'Hello', 0
start:
mov     si, 0          ; source index = 0
next_char:
mov     al, msg[si]    ; get the char
cmp     al, 0          ; compare with 0
je      stop           ; stop if 0
mov     ah, 0eh        ; teletype function
int     10h            ; print char in AL
inc     si             ; next character
jmp     next_char      ; loop back
stop:
ret

Palindrome Check: The Idea

  • Palindrome: a string that reads the same forward and backward (123321, kayak).
  • DI points to the start of the string and SI to its end; the characters are compared, DI moves forward and SI backward.
  • Comparing half the length is enough (shr cx, 1 → CX / 2). With an odd length the middle character is not compared.
  • str_size = $ - msg: $ is the current address; msg and str are at the same address, so the result is the constant 6, the string length (it takes no memory).
  • INT 21h / AH = 09h prints the string at DS:DX up to the '$' character; 0Dh, 0Ah are carriage return and line feed.

Addresses assume org 100h and a 2-byte short jmp start (0100h): str starts at 0102h.

Code Trace: Palindrome (1/2) Setup

jmp start: jumps over the data section.

AH = 09h: DOS string output function.

DX = offset str = 0102h.

INT 21h: prints 123321 and a line break ('$' is not printed).

lea di, str: DI = 0102h (first character).

SI = DI = 0102h.

SI = 0102h + 6 = 0108h: one past the string (0Dh).

dec si: SI = 0107h, the last character '1'.

CX = str_size = 6.

6 − 1 ≠ 0 → ZF = 0, je does not jump.

shr cx, 1: 0110b → 0011b, CX = 3. The bit shifted out is 0 → CF = 0.

org 100h
jmp start
msg:
str db '123321'
str_size = $ - msg     ; = 6
db 0Dh,0Ah,'$'
start:
mov ah, 9              ; print up to '$'
mov dx, offset str
int 21h
lea di, str            ; DI = address of str
mov si, di
add si, str_size       ; SI = last + 1
dec si                 ; SI = last char
mov cx, str_size
cmp cx, 1              ; one character?
je is_palindrome       ; one char is a palindrome
shr cx, 1              ; CX = length / 2

Equal → ZF = 1, jne does not jump.

AH = 09h, DX = offset msg1 = 0142h.

Why cmp cx, 1? With length 1, shr cx, 1 makes CX 0; entering a LOOP-based loop with CX = 0 would run the comparison 65,536 times. Length 0 has the same danger: guard it with jcxz.

Summary

JMPUnconditional; IP ← target. Short (EB, −128…+127), near (E9, within segment), far (EA, CS:IP).
Displacementtarget − address of the next instruction; stored in two's complement if negative.
JccTests the flags without changing them; on the 8086 short only (2 bytes).
CMPA SUB that keeps no result; the Jcc that follows makes the decision.
UnsignedJA, JAE, JB, JBE → CF and ZF.
SignedJG, JGE, JL, JLE → ZF, SF and OF.
LOOP familyCX is decremented, flags are preserved; LOOPE/LOOPNE also test ZF.
PitfallsLOOP with CX = 0, not saving CX in nested loops, executing data as code.

Exercises

  2. After mov al, 80h / cmp al, 1, do JA and JG jump?
  3. How many times does mov cx, 0 / d: loop d run? How do you prevent it?
  4. Write code that sets BX = 1 if the unsigned number in AX is greater than 100, and BX = 0 otherwise.

Hints / answers
  1. Next IP = 0122h; 0100h − 0122h = −22h = DEh → 75 DE.
  2. 80h − 01h = 7Fh: CF = 0, ZF = 0 → JA jumps (128 > 1). SF = 0, OF = 1 → SF ≠ OF → JG does not jump (−128 < 1).
  3. 65,536 times; put a jcxz before it.
  4. mov bx, 0 / cmp ax, 100 / jbe done / mov bx, 1 / done:
  5. 200 + 100 = 300 = 12Ch → AL = 2Ch, CF = 1 (carry). Keep the sum in AX and use adc ah, 0, or add in 16 bits.
