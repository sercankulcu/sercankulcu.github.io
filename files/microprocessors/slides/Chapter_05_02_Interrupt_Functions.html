Introduction

BIOS and DOS Services

  • BIOS (Basic Input/Output System): routines in ROM on the motherboard that drive the hardware directly. They work without an operating system and fill the interrupt vector table at boot.
  • DOS sits on top of the BIOS and provides file, string, clock and program management. For its own work it usually calls the BIOS.
  • Both layers are reached through software interrupts (INT n); the caller does not need to know the service’s address.
The same job can be done at different layers: a character on screen via INT 21h/02h (DOS), INT 10h/0Eh (BIOS), or by writing straight into B800h video memory. Higher layers are more portable; lower layers are faster and more flexible.

Introduction

The Service Call Pattern

  1. AH ← service number (8 bits: at most 256 services)
  2. Other parameters: AL, BX, CX, DX, DS:DX, ES:BP …
  3. INT n (10h, 16h, 21h …)
  4. Results come back in registers: AL, AX, CX, DX, ZF/CF …
mov ah, 02h    ; service: print char
mov dl, 'A'    ; parameter
int 21h        ; call DOS
InterruptProviderPurpose
INT 10hBIOSvideo: mode, cursor, characters, strings
INT 16hBIOSkeyboard
INT 1AhBIOStick counter, real-time clock
INT 13hBIOSdisk
INT 20hDOSterminate program (COM)
INT 21hDOShundreds of services: I/O, files, clock, exit
A service may change the registers it uses (INT 21h/02h and 09h change AL, for example); keep values you need later in another register or on the stack. Some services also use AL as a subfunction (INT 10h, AX = 4F00h: VESA).

INT 10h Video

Cursor Position: AH = 02h / 03h

  • Row in DH (0–24), column in DL (0–79); the top-left corner is (0, 0).
  • BH = display page. 80×25 mode has 8 pages (0–7); page 0 is the usual one.
  • Both in one instruction: mov dx, 0C28h → DH = 12, DL = 40 (the middle of the screen).
  • AH = 03h reads the position: DH, DL on return, plus the cursor shape in CH, CL.
  • Characters written through INT 21h also start at this cursor position.
; move the cursor to the middle
mov ah, 02h
mov bh, 0
mov dx, 0C28h   ; row 12, column 40
int 10h

; move the cursor one right
mov ah, 03h
mov bh, 0
int 10h        ; DH, DL = position
inc dl
mov ah, 02h
int 10h
In video memory, the offset of cell (row, column) = (row × 80 + column) × 2. For example (1, 4) → 84 × 2 = 00A8h; the character is at the even address, the attribute at the odd one.

INT 10h Video · Step through the code

Code Trace: Mode, Cursor, 09h and 0Eh

AH = 00h (set mode), AL = 03h (80×25 16-color text). One instruction loads both registers.

int 10h: the mode is set, the screen is cleared and the cursor goes to (0,0).

AH = 02h: set the cursor position.

BH = display page (0–7 in text mode; normally 0).

DX = 0104h → DH = 1 (row), DL = 4 (column). The top-left corner is (0,0).

The cursor moves to row 1, column 4. Nothing on the screen yet.

AH = 09h: write AL at the cursor CX times with attribute BL.

The character to write: AL = '*' (2Ah).

BL = 4Eh: background 4 (red), foreground E (yellow).

Repeat count CX = 3.

*** appears, but 09h does not move the cursor: it is still at (1,4).

AH = 0Eh: teletype output.

AL = 'A'.

'A' is written at the cursor (1,4), over the first star; the cursor moves to (1,5).

AL = 'B'. AH is still 0Eh.

'B' goes to (1,5): the screen shows AB*. In text mode 0Eh takes no attribute; the cells keep their 4Eh color.

09h does not move the cursor; after writing, advance it separately with AH = 02h.

org 100h
mov ax, 0003h    ; AH=00h, AL=03h
int 10h          ; clears screen
mov ah, 02h      ; set cursor
mov bh, 0        ; page 0
mov dx, 0104h    ; DH=1, DL=4
int 10h
mov ah, 09h      ; char + attribute
mov al, '*'
mov bl, 4Eh      ; yellow on red
mov cx, 3        ; 3 times
int 10h          ; cursor stays!
mov ah, 0Eh      ; teletype
mov al, 'A'
int 10h          ; cursor moves
mov al, 'B'
int 10h
ret

Code Trace: A Colored String with AH = 13h






AH = 13h (write string). AL = 01h: every character gets attribute BL, and the cursor moves after writing.


BH = 0 (page), BL = 1Eh: yellow (E) on blue (1).


CX = number of characters. There is no terminator such as '$'.


DH = 2, DL = 5: where writing starts.


The string’s address must be in ES:BP (not DS:DX!). In a COM program ES = DS: BP = 0112h.


Welcome is written from row 2, column 5; the cursor goes to (2,12).


With AL = 00h the string would still be written but the cursor would stay put. With AL = 02h/03h the string is made of character, attribute pairs.




org 100h
mov ax, 1301h    ; AH=13h, AL=01h
mov bx, 001Eh    ; BH=0, BL=1Eh
mov cx, 7        ; string length
mov dx, 0205h    ; row 2, col 5
lea bp, msg      ; ES:BP → string
int 10h
ret
msg db 'Welcome'

INT 10h Video

  
Output Without the BIOS: B800h Video Memory

  

    

      
    
        
  • In mode 03h the screen is held in 4000 bytes of memory starting at B800:0000h (80 × 25 × 2).
    • 
        
  • Each cell is 2 bytes: character (even address) + attribute (odd address).
    • 
        
  • The video card shows whatever is written there at once: much faster than an interrupt call.
    • 
        
  • Written as a word it is little-endian: 4E41h → 41h ('A') at the low address, 4Eh as the attribute.
    • 
      

    

    
; yellow-on-red 'A' at cell (1,4)
mov ax, 0B800h
mov es, ax
mov di, (1*80+4)*2  ; 00A8h
mov ax, 4E41h
mov es:[di], ax

; fill the screen with '.'
xor di, di
mov ax, 072Eh
mov cx, 2000
cld
rep stosw

  


  
Writing directly does not move the cursor and does not update the cursor position the BIOS keeps. emu8086 supports this memory too.






  
INT 10h Video · Step through the code

  
Writing Directly to Video Memory

  


org 100h
mov ax, 0B800h
mov es, ax
mov di, (1*80+4)*2  ; 00A8h
mov ax, 4E41h
mov es:[di], ax
xor di, di
mov ax, 072Eh
mov cx, 3           ; first 3 cells
cld
rep stosw
ret

    




ES = B800h: the segment of the mode 03h text screen. A segment register cannot take an immediate, so it goes through AX.


Cell (1, 4): (1 × 80 + 4) × 2 = 168 = 00A8h. The product is computed at assembly time.


AX = 4E41h: AL = 41h ('A', the character), AH = 4Eh (attribute: yellow on red).


MOV ES:[DI], AX: little-endian → B80A8h ← 41h, B80A9h ← 4Eh. The character appears at once; the cursor stays put.


DI = 0: the top-left corner.


AX = 072Eh ('.' + 07h light gray), CX = 3.


CLD: DF = 0, DI counts up.


REP STOSW: ES:[DI] ← AX, DI += 2, CX times → the first 3 cells become '.'; DI = 0006h, CX = 0. (For the whole screen, CX = 2000.)


RET: the program ends.



      

    

  






  
INT 10h Video

  
Mode 13h: 320×200, 256 Colors

  

    

      
    
        
  • mov ax, 0013h / int 10h: 320 × 200 graphics mode. Video memory is A000:0000h – A000:F9FFh (64,000 bytes).
    • 
        
  • Each pixel is 1 byte: a color number (palette entry). The first 16 colors match the text colors: 0Eh yellow, 0Fh white.
    • 
        
  • 320 = 140h bytes per row: offset = y · 320 + x.
    • 
        
  • Example: (100, 50) → 50 · 320 + 100 = 16,100 = 3EE4h.
    • 
      

      

        
INT 10h / AH = 0Ch: write pixel

        
          
ALcolor

          
BHpage (0 in mode 13h)

          
CX / DXx (column 0–319) / y (row 0–199)

        
      

      
AH = 0Dh, with the same CX, DX, reads the pixel’s color into AL.

    

    

  






  
INT 10h Video

  
A Diagonal Line: Through the BIOS and Through A000h

  

    

      
INT 10h / 0Ch: by coordinates

      
mov ax, 0013h
int 10h          ; 320×200, 256 colors
xor cx, cx       ; x = 0
xor dx, dx       ; y = 0
mov bh, 0        ; page
dot: mov ax, 0C0Eh   ; AH=0Ch, AL=yellow
int 10h
inc cx           ; one right
inc dx           ; one down
cmp dx, 200
jb  dot           ; 200 pixels

      
Why 141h? +140h (320) goes to the same column one row down, +1 one column right: 141h = 321. The last pixel (199, 199) is at 199 · 321 = F987h. For the anti-diagonal from the top right, add 13Fh (320 − 1).

    

    

      
A000h memory: by offset

      
mov ax, 0013h
int 10h
mov ax, 0A000h
mov es, ax
xor di, di       ; (0,0) → offset 0
mov al, 0Eh      ; yellow
mov cx, 200
draw: mov es:[di], al
add di, 141h     ; 320 + 1
loop draw
mov ah, 0
int 16h          ; wait for a key
mov ax, 0003h
int 10h          ; back to text mode

      
Writing to memory directly is much faster than an interrupt call per pixel.

    

  

  
emu8086’s graphics support is limited: 0Ch draws slowly, and direct writes to A000h may not show in every version; in DOSBox they show fully.

Drawing a Diagonal into Mode 13h Memory

  


org 100h
mov ax, 0A000h
mov es, ax
xor di, di       ; (0,0) → offset 0

ES = A000h: mode 13h video memory (320 × 200, 1 byte per pixel).


DI = 0: pixel (x, y) = (0, 0), offset y · 320 + x = 0.


AL = 0Eh (yellow), CX = 4: draw the first 4 pixels.


ES:[0000h] ← 0Eh: pixel (0, 0). ADD DI, 141h → DI = 0141h (one row down + one right). LOOP: CX = 3.


ES:[0141h] ← 0Eh: pixel (1, 1). ADD DI, 141h → DI = 0282h (one row down + one right). LOOP: CX = 2.


ES:[0282h] ← 0Eh: pixel (2, 2). ADD DI, 141h → DI = 03C3h (one row down + one right). LOOP: CX = 1.


ES:[03C3h] ← 0Eh: pixel (3, 3). ADD DI, 141h → DI = 0504h (one row down + one right). LOOP: CX = 0. The loop ends.


RET. With 200 passes the last pixel (199, 199) would be at 199 · 321 = F987h.

INT 16h Keyboard · Step through the code

  
Code Trace: Read Until Enter, Echo in Upper Case






AH = 00h: wait for a key from the keyboard buffer and take it.


The user pressed O (Shift+o): AL = 4Fh (ASCII), AH = 18h (scan code).


4Fh ≠ 0Dh.


Not Enter; carry on.


'O' (4Fh) < 'a' (61h) → CF = 1.


Not lower case → straight to echo.


AH = 0Eh (teletype). AL holds the character to print.


O on the screen.


Back for the next key.


AH = 00h: wait for a key from the keyboard buffer and take it.


The user pressed k: AL = 6Bh, AH = 25h.


6Bh ≠ 0Dh.


Carry on.


'k' ≥ 'a' → CF = 0.


May be lower case; carry on.


6Bh − 7Ah: borrow → CF = 1, ZF = 0. So 'k' < 'z'.


ja needs CF = 0 and ZF = 0; CF = 1 → no jump: lower case.


Bit 5 is cleared: 6Bh − 20h = 4Bh = 'K'.


AH = 0Eh (teletype). AL holds the character to print.


K on the screen.


Back for the next key.


AH = 00h: wait for a key from the keyboard buffer and take it.


The user pressed Enter: AL = 0Dh, AH = 1Ch.


AL = 0Dh → ZF = 1.


Enter → done.


The program ends at Enter. INT 16h/00h does not echo the key; the program did the echoing.




org 100h
read:
mov ah, 0        ; wait for key
int 16h          ; AH=scan, AL=ASCII
cmp al, 0Dh      ; Enter?
je done
cmp al, 'a'
jb echo
cmp al, 'z'
ja echo
sub al, 20h      ; lower → upper
echo:
mov ah, 0Eh
int 10h          ; print it
jmp read
done:
ret










  
INT 16h Keyboard · Step through the code

  
Code Trace: Polling Without Waiting, AH = 01h






DX = 0: this counter counts the work done while waiting.


Background work: DX = 0001h.


AH = 01h: ask for the key status (no wait).


No key in the buffer → ZF = 1.


ZF = 1 → back to poll; the program does not freeze.


Background work: DX = 0002h.


AH = 01h: ask for the key status (no wait).


Still no key → ZF = 1.


Keep polling.


Background work: DX = 0003h.


AH = 01h: ask for the key status (no wait).


A key arrived: ZF = 0, AL = 'x' (78h), AH = 2Dh. The key stays in the buffer.


ZF = 0 → leave the loop.


AH = 00h to take the key out of the buffer.


The same key is read and removed from the buffer: AL = 'x', AH = 2Dh.


Games and animations use this pattern: keep running, react when a key is pressed.




org 100h
xor dx, dx       ; work counter
poll:
inc dx           ; background work
mov ah, 01h      ; key ready?
int 16h          ; ZF=1 → none
jz poll
mov ah, 00h      ; take the key
int 16h
ret

INT 21h DOS

  
INT 10h/0Eh or INT 21h/02h?


BIOS · INT 10h, AH = 0Eh
  • The character is in AL.
  • Goes straight to the video BIOS; no DOS needed.
  • Works in boot code too.
  • A color can be given (BL, in graphics modes).
DOS · INT 21h, AH = 02h
  • The character is in DL.
  • A DOS call; output can be redirected (to a file, a printer).
  • On return AL = DL.
  • Checks for Ctrl+Break.
Both print one character and advance the cursor; the choice depends on where the program will run. They can be mixed in one program.






  
INT 21h DOS · Step through the code

  
Code Trace: Read a Character, New Line, Write a Character






AH = 01h: wait for a character from the keyboard and echo it.


The user pressed k: AL = 6Bh, and 'k' appears on the screen.


Later INT 21h calls will change AL, so it is saved in BL.


AH = 02h: write the character in DL.


DL = 0Dh (carriage return).


The cursor returns to the start of the line (no visible change).


DL = 0Ah (line feed).


The cursor moves down a line. New line = CR + LF.


BL = 6Bh + 1 = 6Ch = 'l'.


DL = 'l'.


l is printed. After 02h, AL also holds the character written.


The program ends.




org 100h
mov ah, 01h      ; read + echo
int 21h          ; AL = char
mov bl, al       ; save it
mov ah, 02h      ; write char
mov dl, 0Dh      ; CR: line start
int 21h
mov dl, 0Ah      ; LF: next line
int 21h
inc bl           ; next letter
mov dl, bl
int 21h
ret

INT 21h DOS

  
AH = 0Ah: Buffered Line Input

  


The program prepares the buffer: buffer db 10, ?, 10 dup(?). Byte 0 = at most 10 characters (Enter included).


The user types A: the character goes to position 2 and is echoed. Backspace can correct mistakes.

INT 1Ah and BIOS Data

  
INT 1Ah: Tick Counter and Real-Time Clock

  

    

      

        
AHFunctionReturns

        
          
00hread tick counterCX:DX = ticks since midnight, AL = midnight-rollover flag

          
02hread RTC timeCH = hour, CL = minute, DH = second (BCD), DL = daylight saving; CF = 1: error

          
04hread RTC dateCH = century, CL = year, DH = month, DL = day (BCD); CF = 1: error

        
      

      
The RTC is the battery-backed CMOS clock (AT and later); it keeps running while the computer is off.

    

    

      
Packed BCD → ASCII (CL = 35h, i.e. minute 35)

      

        
35h = 0011 0101b
Each 4 bits is one decimal digit: high nibble 3, low nibble 5.

        
shr dl, cl (CL = 4) → 03h
The high digit is shifted right. On the 8086 a shift count above 1 must be in CL.

        
and dl, 0Fh → 05h
The low digit is masked out.

        
+30h → '3' 33h, '5' 35h
Each digit becomes an ASCII digit. INT 21h/2Ch returns the same minute in binary, CL = 23h, which needs AAM instead.

      

    

  

  
Among the interrupts emu8086 supports, INT 1Ah has only 00h (tick counter); 02h works under real DOS or DOSBox. In emu8086, read the time with INT 21h/2Ch.






  
INT 1Ah and BIOS Data · Step through the code

  
Code Trace: Printing the RTC Time as HH:MM:SS






AH = 02h: read the BIOS real-time clock (RTC).


The result is packed BCD: CH = 14h (hour 14), CL = 35h (minute 35), DH = 07h (second). DL = 00h (no daylight saving).


CF = 0: the read succeeded. CF = 1 would mean the clock is not running; the program would end without printing.


CL is about to get the shift count, so the minute is copied to BL first.


CL = 4: SHR DL, CL will shift 4 bits (the 8086 has no immediate shift count above 1).


BH = hour = 14h. The procedure expects the value in BH; INT 21h/02h does not touch BH.


The procedure is called for the hour (skipping colon, straight to putbcd).


DL = BH = 14h = 0001 0100b.


shr dl, cl: 0001 0100b → 0000 0001b. DL = 01h, the high digit.


+30h: DL = 31h = '1'.


AH = 02h: write the character in DL.


'1' on the screen. DOS copies DL into AL (AL = 31h).


DL = BH = 14h again, for the second digit.


and dl, 0Fh: the high 4 bits are cleared: 0000 0100b = 04h.


+30h: DL = 34h = '4'.


'4' on the screen → 14. AH is still 02h, so no reload is needed.


Return from the procedure.


BH = minute = 35h (saved in BL).


This time the colon entry is called: it prints ':' first, then falls into putbcd.


DL = ':' (3Ah).


AH = 02h.


':' on the screen → 14:. Execution then falls through into the putbcd label.


35h → 03h (high digit).


'3' (33h) on the screen.


35h AND 0Fh = 05h.


'5' on the screen → 14:35.


Return.


BH = second = 07h. INT 21h/02h left DH alone.


colon again, for the seconds.


DL = ':'.


':' on the screen → 14:35:.


07h → 00h (high digit).


'0' (30h) on the screen.


07h AND 0Fh = 07h.


'7' on the screen → 14:35:07.


Return.


The screen shows 14:35:07. INT 21h/2Ch would return the same time in binary (CH = 0Eh, CL = 23h); in BCD the hex digits are the decimal digits.

INT 1Ah and BIOS Data

  
The BIOS Data Area (Segment 0040h)

  

    
AddressSizeContents

    
      
0040:0010wordequipment list (the value INT 11h returns)

      
0040:0013wordbase memory in KB (INT 12h)

      
0040:0017bytekeyboard flags: bit 0 right Shift, 1 left Shift, 2 Ctrl, 3 Alt, 4 Scroll Lock, 5 Num Lock, 6 Caps Lock, 7 Insert

      
0040:001Awordbuffer head: offset of the next key to read

      
0040:001Cwordbuffer tail: offset of the next free slot (head = tail → buffer empty)

      
0040:001E–003D32 byteskeyboard buffer: 16 words (ASCII + scan code), circular; at most 15 keys

      
0040:0049bytecurrent video mode (03h, 13h, …)

      
0040:004Awordcolumns on screen (80 in mode 03h)

      
0040:00508 wordscursor position for the 8 pages (low byte column, high byte row)

      
0040:006Cdwordtick counter: number of ≈ 18.2 Hz interrupts since midnight

      
0040:0070bytemidnight-passed flag (INT 1Ah/00h returns it in AL and clears it)

    
  

  
Physical address = 00400h + offset: 0040:006C = 0046Ch = 0000:046C. INT 16h and INT 1Ah use this area; a program can read it directly too.






  
INT 1Ah and BIOS Data

  
Reading the BIOS Data Area

  

    

      
; wait about 1 second
mov ax, 0040h
mov es, ax
mov bx, es:[006Ch]  ; starting tick
wait1:
mov ax, es:[006Ch]  ; current tick
sub ax, bx          ; ticks elapsed
cmp ax, 18          ; 18 ticks ≈ 0.99 s
jb  wait1

; Caps Lock on? Any key waiting?
test byte ptr es:[0017h], 40h
jnz caps_on         ; bit 6 = 1
mov ax, es:[001Ah]  ; buffer head
cmp ax, es:[001Ch]  ; buffer tail
je  buf_empty

    

    

      
1,193,182 Hz ÷ 65,536 = 18.2065 Hz
With a divisor of 65,536 the 8253/8254 timer raises IRQ 0 at this rate; each interrupt adds one to 0040:006C.

      
1 tick = 65,536 ÷ 1,193,182 s ≈ 54.9 ms
18 ticks ≈ 0.989 s · 5 s ≈ 91 ticks
Delays are measured in ticks; the resolution is about 55 ms.

      
1800B0h = 1,573,040 ticks a day
When the counter reaches this value it resets and the 0040:0070 flag is set.

      
The difference with sub ax, bx
Only the low word is read. Because we take a difference, the result is right even if the low word wraps from FFFFh to 0000h; only the midnight reset spoils it.

    

  

  
emu8086 does not update the whole BIOS data area as a real PC does; the tick counter and keyboard buffer examples work fully in DOSBox.

At startup DS = ES = 0700h: DOS points them at the PSP. CS = 0721h (code), SS = 0710h (stack). @data is the data segment value → AX = 0720h.


MOV DS, AX: DS = 0720h now points at the data segment. Without this line DS:DX would point into the PSP and print garbage.


DX = offset msg = 0000h: msg is at the start of the data segment.


AH = 09h.


INT 21h: from DS:DX = 0720h:0000h up to '$' → Welcome.


AX = 4C00h, INT 21h: back to DOS with exit code 0. RET cannot be used in an EXE (no PSP address on top of the stack).

Add, Subtract and Print the Result




org 100h
mov al, 5       ; 00000101b
mov bl, 10      ; 0Ah = 00001010b
; 5 + 10 = 15 = 0Fh = 00001111b
add bl, al
; 15 - 1 = 14 = 0Eh = 00001110b
sub bl, 1
mov cx, 8       ; print result in binary


print:
mov ah, 2   ; print function
mov dl, '0'
test bl, 10000000b  ; test top bit
jz zero
mov dl, '1'
zero:
int 21h
shl bl, 1
loop print
; print the binary suffix b
mov dl, 'b'
int 21h
; wait for a key press
mov ah, 0
int 16h
ret




  • Computes 5 + 10 − 1 = 14 = 0Eh; the result is in BL.
  • The loop runs 8 times (CX = 8): each pass tests the most significant bit (MSB) of BL, prints '0' or '1', and shifts BL left by one.
  • Finally it prints the suffix 'b' and waits for a key. Expected output: 00001110b.






  
Application

  
Reading Bits with TEST and SHL




TEST BL, 10000000b: BL is ANDed with the mask but not changed. If the result is 0, bit 7 = 0 → ZF = 1 and JZ jumps.


SHL BL, 1: every bit moves left; bit 7 goes out into CF and a 0 enters bit 0. The next bit moves into the tested position (bit 7).


After 8 passes BL’s bits have been printed from MSB to LSB: 00001110, then b.


Alternative: SHL BL,1 and then JC on CF. In that order, though, the shift must come before printing.






  
Application · Step through the code

  
Code Trace (1/2): The Calculation






AL = 5 = 05h = 00000101b. MOV does not affect the flags.


BL = 10 = 0Ah = 00001010b.


ADD BL, AL: BL = 0Ah + 05h = 0Fh (15). No carry (CF = 0); the result has four 1 bits → PF = 1.


SUB BL, 1: BL = 0Eh (14) = 00001110b. Three 1 bits → PF = 0. No borrow: CF = 0.


CX = 8: the LOOP counter, one pass per bit.

Common Mistakes

  

    
Forgotten '$'INT 21h/09h prints memory until it finds a '$': the screen fills with garbage.

    
DS not set (EXE)DX is right but the segment is wrong: mov ax, @data / mov ds, ax.

    
AL gets clobbered02h and 09h change AL; save a character you read in another register before printing.

    
Cursor after 09hINT 10h/09h does not move the cursor; the next output lands on top.

    
DS:DX with 13hThe BIOS string service expects the address in ES:BP.

    
The 0Ah bufferSet the first byte (capacity); the text starts at buffer+2 and does not end with '$'.

    
LF aloneA new line needs CR + LF (0Dh, 0Ah).

    
No exitForget RET/4Ch and the data is executed as instructions.
