I/O Basics

Device Control

  • x86 CPUs can control a wide range of devices. The basic I/O port numbers vary from system to system and can be changed with suitable hardware (e.g. an address decoder).
  • In an embedded system the assembled .bin file is burned into a Read-Only Memory (ROM) chip.
  • At power-up the system reads the program from ROM, loads it into RAM and runs it. Many modern devices (washing machines, printers, modems…) work this way.

I/O Basics

Port-Mapped and Memory-Mapped I/O

Port-mapped (isolated) I/O
  • The 8086 has a separate 64 K I/O address space.
  • Accessed only with IN/OUT; the M/IO' pin marks an I/O cycle.
  • Uses no memory addresses.
  • All of emu8086's virtual devices work this way.
Memory-mapped I/O
  • Device registers live at memory addresses.
  • Any MOV/ADD/CMP instruction works on them.
  • Example: the PC text screen starts at B800:0000; a byte written there shows up on screen.
Polling: the CPU reads the device's status bit in a loop until it is “ready”. Simple, but the CPU can do nothing else while waiting. The alternative is for the device to send the CPU an interrupt.

I/O Basics

The 8255 Programmable Peripheral Interface (PPI)

  • Three 8-bit ports (A, B and C, which splits into two 4-bit halves) plus a control register; A1, A0 select the register, CS' comes from the address decoder.
  • After RESET all ports are inputs; write the control word first.

On the 8086 even addresses move over D0–D7 (low bank); to put the registers on even addresses, wire 8255.A0 ← A1, A1 ← A2 (310h, 312h, 314h, 316h). On the 8088, A0 ← A0, A1 ← A1 is enough. Port > 255: access through DX.

I/O Basics

8255 Control Word (Mode 0)

D7D6 D5D4D3D2D1D0
1 = mode setgroup A mode
00 = mode 0		port APC7–PC4group B mode
0 = mode 0		port BPC3–PC0
direction bits:1 = input, 0 = output (D4, D3, D1, D0)

1 00 0 0 0 1 0b = 82h

Wanted: A output (LEDs/relays), B input (switches), both halves of C output, all mode 0.

D7 = 1: mode set · D6 D5 = 00 and D2 = 0: mode 0

Mode 0 is simple I/O without handshaking; modes 1 and 2 are for strobed (handshake) transfers.

D4 = 0 (A output) · D3 = 0 (C upper output)
D1 = 1 (B input) · D0 = 0 (C lower output)

Result: 1000 0010b = 82h. For A input, B output, C input you would get 1001 1001b = 99h.

If D7 = 0, it is bit set/reset (BSR):
D3–D1 = bit number in C, D0 = new value

0Fh (0000 1111b) → PC7 = 1, 0Eh → PC7 = 0. The other C bits are untouched.

mov al, 82h    ; A out, B in, C out
out dx, al
mov dx, 311h   ; port B
in  al, dx     ; read switches
mov dx, 310h   ; port A
out dx, al     ; drive the LEDs
mov dx, 313h
mov al, 0Fh    ; BSR: PC7 = 1
out dx, al

8255: Control Word, Read, Write, BSR

org 100h
mov dx, 313h   ; control register
mov al, 82h    ; A,C out; B in
out dx, al
mov dx, 311h   ; port B
in  al, dx     ; read switches
mov dx, 310h   ; port A
out dx, al     ; drive the LEDs
mov dx, 313h
mov al, 0Fh    ; BSR: PC7 = 1
out dx, al
ret

After RESET all three ports are inputs. The switches on port B are set to 1001 0110b = 96h (port map: 311h = 96h). DX = 313h, AL = 82h.

OUT 313h ← 82h = 1 00 0 0 0 1 0b: mode 0; A output, C upper output, B input, C lower output.

DX = 311h: port B. Since 311h > 255, the port number goes in DX.

IN AL, DX: the switches are read → AL = 96h.

DX = 310h: port A.

OUT 310h ← 96h: port A is an output, so the LEDs mirror the switches (lit: bits 7, 4, 2, 1).

DX = 313h, AL = 0Fh = 0000 111 1b: D7 = 0 → not a mode word but bit set/reset (BSR).

OUT 313h ← 0Fh: D3–D1 = 111 → PC7, D0 = 1 → PC7 = 1. The port directions (82h) stay, the other C bits are kept.

Port values come from the interpreter's I/O log (switch input 96h is an example). A BSR word changes only the selected C bit.

Waiting with INT 15h / AH = 86h




; wait 5 seconds (5 million µs)
mov cx, 4Ch    ; 004C4B40h = 5,000,000
mov dx, 4B40h
mov ah, 86h
int 15h


    

  • BIOS function INT 15h, AH = 86h: waits CX:DX microseconds.
    • 

  • CX is the high word, DX the low word: a 32-bit delay.
    • 





5 s = 5 × 1,000,000 = 5,000,000 µs
Convert the time to microseconds.


5,000,000 ÷ 16 = 312,500 rem. 0
312,500 ÷ 16 = 19,531 rem. 4
19,531 ÷ 16 = 1,220 rem. 11 (B)
1,220 ÷ 16 = 76 rem. 4
76 ÷ 16 = 4 rem. 12 (C)
4 ÷ 16 = 0 rem. 4
Repeated division by 16: read the remainders from last to first → 4C4B40h.


0 0 4 C | 4 B 4 0
CX = 004Ch · DX = 4B40h
The 32-bit value 0000 0000 0100 1100 0100 1011 0100 0000b is split in two.


1 s → 1,000,000 = 000F4240h → CX = 000Fh, DX = 4240h
Another example: a 1-second delay.

Software Delays: LOOP and Clock Cycles




; ≈ 1 ms delay (4.77 MHz 8086)
mov cx, 281    ; 4 clocks
delay:
loop delay     ; 280 × 17 + 1 × 5 clocks


InstructionClocks


MOV CX, imm4


LOOP (CX ≠ 0, jumps)17


LOOP (CX = 0, falls through)5




Total = 4 + 17(N − 1) + 5 = 17N − 8 clocks.






4.77 MHz: 1 clock ≈ 0.2096 µs
1 ms = 4,770 clocks
Time = number of clocks ÷ clock frequency.


17N − 8 = 4,770 → N ≈ 281.06
N = 281 → 4,769 clocks ≈ 0.9998 ms
CX takes an integer, so pick the nearest value.


5 MHz: 1 ms = 5,000 clocks → N ≈ 294.6
N = 295 → 5,007 clocks ≈ 1.0014 ms
The same N = 281 lasts only 0.954 ms at 5 MHz: the delay depends on the clock speed.


Longest: CX = 0 → 65,536 passes
17 · 65,536 − 8 = 1,114,104 clocks ≈ 233.6 ms
Longer delays need nested loops. Called as a procedure, it also costs CALL (19) and RET (8) clocks.






These figures are approximate: interrupts, memory wait states and the prefetch queue can stretch the time. emu8086 doesn't model instruction timing; the loop runs at the speed of your PC and the step-delay setting. In emu8086, timed waits use INT 15h/86h.

Counting Clocks in a Delay Loop

  


org 100h
mov cx, 4      ; 4 clocks
delay:
loop delay     ; 17 clocks, last one 5
ret

    




CX = 4. mov cx, imm takes 4 clocks; at 4.77 MHz, 1 clock ≈ 0.2096 µs.


LOOP 1: CX = 3 ≠ 0 → jumps (back to itself): 17 clocks. Total 21.


LOOP 2: CX = 2, again 17 clocks. Total 38.


LOOP 3: CX = 1, 17 clocks. Total 55.


LOOP 4: CX = 0 → falls through: only 5 clocks. Total 60 = 17 · 4 − 8 clocks.


60 clocks ÷ 4.77 MHz ≈ 12.6 µs. With CX = N the loop takes 17N − 8 clocks; for 1 ms we found N = 281.

The Traffic Light Program






The table is assumed at 0124h (ORG 100h; the address depends on the assembler). sit_end = 012Eh.


AX = all_red = 0249h (a constant, EQU).


Write port 4: every direction red.


SI = 0124h: start of the table (situation).


AX ← [SI] = 030Ch.


OUT 4, AX: the lamps switch to the new state (SI = 0124h).


CX = 004Ch (high word of the delay).


DX = 4B40h (low word).


AH = 86h: BIOS wait function.


INT 15h: wait 5 seconds.


SI = 0126h: next word.


CMP SI, sit_end (012Eh): SI < sit_end → CF = 1.


JB: CF = 1, back to next.


… wait and advance SI … OUT 4, AX: SI = 0126h → port 4 = 069Ah.


… wait and advance SI … OUT 4, AX: SI = 0128h → port 4 = 0861h.


… wait and advance SI … OUT 4, AX: SI = 012Ah → port 4 = 0861h.


… wait and advance SI … OUT 4, AX: SI = 012Ch → port 4 = 04D3h.


CMP SI, sit_end (012Eh): SI = sit_end → CF = 0.


JB: CF = 0, no jump: end of table.


SI = 0124h: restart the table.


JMP next: endless loop.


… wait and advance SI … OUT 4, AX: SI = 0124h → port 4 = 030Ch.




#start=Traffic_Lights.exe#

out 4, ax
mov si, offset situation
next:
mov ax, [si]

Stepper Motor


Stepper Motor (Port 7)




    

  • The motor can turn clockwise (CW) or counterclockwise (CCW).
    • 

  • Bits 0, 1, 2 of the byte written to port 7 switch the three electromagnets.
    • 

  • A half step is 11.25°, a full step 22.5°.
    • 

  • Half step: two magnets on, then one magnet on, alternately.
    • 

  • Full step: one, two, two magnets and an “all off” byte, in turn.
    • 

  • When the motor is ready for a new command, it sets bit 7 of the byte read from the port.
    •

Stepper Motor


Real Hardware: A Unipolar Stepper and the ULN2003




    

  • A unipolar motor has two center-tapped windings: four half-windings A, B, A̅, B̅; the center taps go to +V (5 or 6 wires).
    • 

  • The winding current (hundreds of mA) is far more than a port pin can drive, so a ULN2003 goes in between: 7 Darlington channels, up to 500 mA each.
    • 

  • Input = 1 → the output pulls to ground → current flows through that half-winding.
    • 

  • The back-EMF when current is cut is clamped by the ULN2003's internal diodes, with COM tied to +V.
    • 

  • The motor runs open loop: there is no “ready” bit, and the delay between steps sets the speed. Too short a delay and it misses steps.
    • 











Stepper Motor


Real Motor: Drive Sequences






DrivePort A sequence (B̅ A̅ B A = bits 3…0)


One phase (wave), full step01h 02h 04h 08h


Two phase, full step03h 06h 0Ch 09h


Half step01h 03h 02h 06h 04h 0Ch 08h 09h




    

  • With two-phase drive, two half-windings always carry current: more torque.
    • 

  • Half step interleaves the two sequences: the step angle halves (e.g. 1.8° → 0.9°).
    • 

  • Play the sequence backwards and the motor turns the other way.
    • 

  • emu8086's virtual motor is a simple 3-magnet model (bits 0–2, bit 7 ready); its tables (110b, 100b, …) don't apply to a real 4-phase motor.
    •

Real Motor: Driving the Half-Step Sequence

  


org 100h
fwd:
inc pos         ; reverse: dec pos
mov bx, pos
and bx, 7        ; index 0–7

Windings: bit 0 = A, bit 1 = B, bit 2 = A̅, bit 3 = B̅. With pos = 6, INC → 7; AND BX, 7 keeps the index in 0–7 → BX = 7.


AL ← half[7] = 09h = 1001b → windings B̅ and A: the field swings between them (≈ 315°). Written to port A.


CALL delay / RET: the delay between steps sets the motor speed. JMP fwd.


pos = 8 → AND 7 → BX = 0: the sequence wraps around.


half[0] = 01h → A only: the field is at 0° (a half step).


Wait and repeat.


pos = 9 → BX = 1.


half[1] = 03h → A + B: 45°. Each OUT advances the field one half step (45° winding angle); read the table backwards and the motor reverses.

Real Hardware: The 7-Segment Display







    

  • Common cathode (CC): common pin to ground; bit = 1 lights a segment.
    • 

  • Common anode (CA): common pin at +5 V; bit = 0 lights it, so the code is the inverse of the CC code (NOT AL).
    • 

  • Each segment gets a current-limiting resistor.
    • 

  • emu8086's port 199 LED display decodes the number itself; with a real display, the program produces the code.
    •

Code Table, XLAT and Multiplexed Scanning






; digit (0–9) to segment code
mov bx, offset segtab
mov al, 3        ; digit
xlat              ; AL = [BX + AL] = 4Fh
; not al          ; if common anode
mov dx, 310h     ; 8255 port A
out dx, al
ret
segtab db 3Fh,06h,5Bh,4Fh,66h
    db 6Dh,7Dh,07h,7Fh,6Fh


    

  • Multiplexing: the segment lines of all 4 digits share port A; each digit's common pin goes to port C through its own transistor.
    • 

  • Only one digit is lit at a time; ≈ 4 ms per digit → a full pass every 16 ms ≈ 62 Hz. The eye sees no flicker (above ≈ 50 Hz).
    • 

  • Blank everything before switching digits, or the previous code shows faintly on the next digit (ghosting).
    • 





scan:

next_dig:
mov dx, 312h      ; port C: digit select
mov al, 0

xlat

out dx, al

out dx, al        ; only this digit lit
call delay_4ms

cmp si, 4
jb  next_dig

BX = table start, SI = 0. The number to show is 2026 (the digits array); all 4 digits share their segment lines on port A.


Digit 1: first port C ← 00h (all blank, no ghosting). AL = digits[0] = 2; XLAT → AL = 5Bh.


Port A ← 5Bh (segments), port C ← 01h: only digit 1 is lit. INC SI, CMP, JB → next digit.


Digit 2: first port C ← 00h (all blank, no ghosting). AL = digits[1] = 0; XLAT → AL = 3Fh.


Port A ← 3Fh (segments), port C ← 02h: only digit 2 is lit. INC SI, CMP, JB → next digit.


Digit 3: first port C ← 00h (all blank, no ghosting). AL = digits[2] = 2; XLAT → AL = 5Bh.


Port A ← 5Bh (segments), port C ← 04h: only digit 3 is lit. INC SI, CMP, JB → next digit.


Digit 4: first port C ← 00h (all blank, no ghosting). AL = digits[3] = 6; XLAT → AL = 7Dh.


Port A ← 7Dh (segments), port C ← 08h: only digit 4 is lit. INC SI, CMP, JB → SI = 4, the loop ends.


Each of the four digits lit once in turn. At ≈ 4 ms per digit a full pass takes 16 ms (≈ 62 Hz): the eye sees all four at once.

Thermometer


Thermometer and Heater (Ports 125, 127)




    

  • IN AL, 125: reads the current air temperature (°C, a signed byte).
    • 

  • OUT 127, AL: AL = 1 turns the heater on, AL = 0 turns it off.
    • 

  • With the heater on, the temperature slowly rises; with it off, it falls.
    • 

  • Goal: a thermostat that keeps the temperature within 60–80 °C.
    • 

  • The temperature can be negative, so comparisons use signed jumps (JL, JLE, JG).
    • 











Thermometer · Step through the code


The Thermostat Program






Port 125 will return 55, 70 and 85 °C in turn. The heater starts off.


AX = CS = 0700h.


DS = 0700h (an immediate can't go straight into a segment register).


IN AL, 125 → temperature 55 °C.


CMP AL, 60: 55 − 60 → SF = 1, OF = 0.


JL (SF ≠ OF): 55 < 60 → low.


AL = 1.


OUT 127, AL: heater on.


JMP ok.


JMP start: new reading.


IN AL, 125 → temperature 70 °C.


CMP AL, 60: 70 − 60 → SF = 0, OF = 0.


JL (SF ≠ OF): no jump.


CMP AL, 80 → ZF = 0, SF = 1.


JLE: 60 ≤ 70 ≤ 80 → ok (leave the heater alone).


JMP start: new reading.


IN AL, 125 → temperature 85 °C.


CMP AL, 60: 85 − 60 → SF = 0, OF = 0.


JL (SF ≠ OF): no jump.


CMP AL, 80 → ZF = 0, SF = 0.


JLE: no jump.


JG: 85 > 80 → high.


AL = 0.


OUT 127, AL: heater off.


JMP start: new reading.




; make DS equal to CS:
mov ax, cs
mov ds, ax

in  al, 125

cmp al, 80

jg  high

mov al, 1
out 127, al   ; heater on
jmp ok
high:

ok:

jg high could just as well be jmp high: if JLE didn't jump, the temperature is already above 80.

CodeNameEffect

db 13, 9: 13 = CR (carriage return), 9 = horizontal tab (HT). Vertical tab (VT) is 11 = 0Bh.

0Ah, 0Dh is LF + CR; the usual order is CR + LF, but together they give the same result.

Robot


Robot Program: Find the Lamp and Switch It On




#start=robot.exe#
main_loop: CALL wait_ready
       MOV  AL, 4       ; examine
       OUT  9, AL
       CALL wait_data
       IN   AL, 10
       CMP  AL, 0FFh    ; wall?
       JE   turn
       CMP  AL, 8       ; lamp off?
       JNE  advance
       CALL wait_ready
       MOV  AL, 5       ; lamp on
       OUT  9, AL
       JMP  main_loop
turn:   MOV  AL, 3       ; turn right
       JMP  send
advance: MOV AL, 1       ; forward
send: PUSH AX         ; keep command
       CALL wait_ready
       POP  AX
       OUT  9, AL
       JMP  main_loop


    

  • Before every command, wait until the busy bit (bit 1) is zero.
    • 

  • After an examine (4), wait for the data ready bit (bit 0), then read port 10.
    • 

  • Wall: turn right; unlit lamp: switch it on; otherwise move forward.
    • 

  • The wait routines are called with CALL: the return address is on the stack.
    • 










Robot


Robot: Wait Routines and Pitfalls




wait_ready PROC
b1:    IN   AL, 11
       TEST AL, 010b    ; busy?
       JNZ  b1
       RET
wait_ready ENDP

wait_data PROC
v1:    IN   AL, 11
       TEST AL, 001b    ; new data?
       JZ   v1
       RET
wait_data ENDP




Preserve ALwait_ready overwrites AL with IN. On the send path AL holds the command, so PUSH AX before the call and POP AX after; otherwise the status byte would be sent to the port.


Error bitA “forward” into a wall sets the error bit (bit 2); read and check the status.


The cost of pollingThe CPU is fully tied up in the wait loop; real systems prefer interrupts.
