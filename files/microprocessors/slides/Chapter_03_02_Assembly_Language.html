Assembly Language

Assembly Language

  • A low-level language: each instruction corresponds to exactly one machine instruction.
  • Instead of raw numbers it uses readable mnemonics: MOV, ADD, JMP…
  • Writing it requires knowing the machine: registers, memory, the system bus.
  • It is the best way to understand how a computer is organized and how a program really runs.
  • Every processor family has its own assembly language; this course uses the Intel 8086 and emu8086.
One line, three views

Assembly: MOV AX, 5

Machine code in hex: B8 05 00

What the CPU sees:
10111000 00000101 00000000

The 16-bit value 0005h is stored low byte first (05 00).

Assembly Language

The Assembler and emu8086

AssemblerTranslates mnemonics and labels into machine code and variable names into addresses. Examples: MASM, TASM, NASM.
emu8086Editor + assembler + 8086 emulator. Shows registers, memory and flags step by step.
.COM / .EXE.COM is the simple single-segment format, at most 64 KB (ORG 100h). .EXE may use several segments.

Examples in this course use emu8086 syntax; most also assemble with MASM/TASM.

Assembly Language

Why Assembly?

A program written in assembly language:

Pros

  • Is smaller (no unnecessary code).
  • Is faster, since it does only what it has to.
  • Can do what high-level languages cannot: port I/O, interrupt handling, direct access to flags.
  • Is indispensable for boot loaders, device drivers and embedded systems.

Cons

  • Not portable: 8086 code does not run on ARM.
  • Tedious to write, read and debug.
  • Unproductive for large projects; modern compilers usually generate code that is fast enough.
In practice a mixed approach is common: the program is written in a high-level language and only small, time-critical parts in assembly.

Labels and Names

start:  MOV CX, 3   ; code label
again:  INC AX
        LOOP again  ; an address
        RET
num     DB 7        ; data name
  • A code label ends with a colon and stands for the address of an instruction (its offset within CS); it generates no code itself.
  • A variable name has no colon; the assembler records its name, type (DB, DW…) and address.
  • A name starts with a letter or underscore, never a digit; letters, digits and underscores may follow.
  • Instruction, register and directive names (MOV, AX, DB, END…) are reserved.
  • Case does not matter: again and AGAIN are the same label; defining both gives a “duplicate definition” error.

Working with Registers

Operand Types and Implicit Operands

RegisterMOV AX, BX: the value comes from inside the processor; the fastest kind.
ImmediateMOV AX, 5: the value is part of the instruction bytes; it can only be a source.
MemoryMOV AX, [BX]: the value is read from memory in a bus cycle.
InstructionExplicit operandImplicit operand(s)
MUL BLBLAL (multiplicand), AX (product)
DIV BLBLAX (dividend), AL (quotient), AH (remainder)
LOOP againagainCX (counter)
CBW—AL → AX
PUSH AXAXSS:SP (top of stack)
XLAT—AL (index and result), BX (table address)

An implicit operand is not written, yet it changes: MUL BL also overwrites AH. A program that needs to keep a register’s value must know the implicit operands of the instructions it uses.

Working with Registers · Step through the code

Code Trace: Implicit Operands of MUL, SHR and LOOP

ORG 100h
MOV AL, 12
MOV BL, 10
MUL BL         ; AX = AL × BL
MOV CL, 2
SHR AX, CL     ; count in CL
MOV CX, 3      ; LOOP counter
again:
ADD AX, 1
LOOP again     ; CX - 1
RET

AL = 12, BL = 10. AH starts at 0.

MUL BL names only BL; the multiplicand is implicitly AL and the product implicitly AX: AX = 120 = 0078h. The product fits in 8 bits, so CF = 0.

SHR AX, CL: a shift count above 1 must be in CL. 120 ÷ 4 = 30 → AX = 001Eh.

CX = 3: the implicit counter of LOOP. CL is part of CX, so the old count 2 is gone.

Pass 1: AX + 1 = 31; LOOP decrements CX: CX = 2, not zero → again.

Pass 2: AX + 1 = 32; LOOP decrements CX: CX = 1, not zero → again.

Pass 3: AX + 1 = 33; LOOP decrements CX: CX = 0, the loop ends.

RET. The program never decrements CX explicitly, yet LOOP changed it three times: AX = 0021h = 33.

AX, CL and CX were “hidden” operands in this program; the special roles of the registers come from these implicit uses.

Working with Registers

Register or Memory?

Register
  • Inside the CPU; no bus cycle needed.
  • Very few of them (the 8086 has 14 16-bit registers).
  • Ideal for intermediate results and counters.
Memory
  • Outside the CPU; each access takes at least one bus cycle (4 clock cycles on the 8086).
  • Large: up to 1 MB.
  • Holds the program code, variables, arrays and the stack.
Good assembly code keeps frequently used values in registers and goes to memory only when it must. Keeping a loop counter in CX instead of memory, for example, speeds up the loop.

14 registers: 8 general-purpose + 4 segment + IP + FLAGS.

Working with Registers

Instruction Timing: Register vs. Memory

Instruction (8086)Clocks
MOV AX, BX2
MOV AX, 54
MOV AX, num10
MOV CX, [BX]8 + 5 = 13
ADD AX, BX3
ADD AX, num9 + 6 = 15
INC CX2
INC count (word)15 + 6 = 21
  • A memory operand adds the effective address calculation (EA) time: direct address 6, [BX] 5, [BX+SI] 7 clocks.
  • Instructions that write memory take longer: INC count reads, then writes (two bus cycles).
  • Loading AX from a direct address uses the short accumulator form: 10 clocks.
  • In a loop that runs 1000 times, incrementing a counter in CX costs 1000 × 2 = 2000 clocks; in memory, 1000 × 21 = 21,000. At 5 MHz that is 4.2 ms instead of 0.4 ms.
These are best-case times from the Intel 8086 data sheet; word access at an odd address and a flushed prefetch queue make them longer. The ratio holds: a memory-operand instruction is several times slower than its register form.

IP and Flags · Step through the code

Code Trace: How Does IP Advance?

The program is loaded at CS:0100h; IP = 0100h points to the first instruction.

MOV AX, 5 (B8 05 00) is fetched: IP = 0103h; once executed, AX = 0005h.

Three more bytes: IP = 0106h, BX = 0002h.

INC AX is a single byte (40h): IP = 0107h, AX = 0006h.

ADD AX, BX is 2 bytes: IP = 0109h, AX = 0008h.

RET pops 0000h off the stack: IP = 0000h, SP = 0000h. The INT 20h at PSP:0000 ends the program.

ORG 100h
MOV AX, 5     ; 3 bytes
MOV BX, 2     ; 3 bytes
INC AX        ; 1 byte
ADD AX, BX    ; 2 bytes
RET           ; 1 byte

IP and Flags · Step through the code

Code Trace: Which Instructions Touch the Flags?

ORG 100h
STC              ; CF = 1
MOV AL, 0FFh     ; flags kept
INC AL           ; CF untouched
MOV CX, 0        ; ZF kept
DEC AL
ADD AL, 1        ; new CF
CLC
NOT AL           ; flags kept
RET

STC: CF = 1. It sets a flag directly.

MOV AL, 0FFh: AL changed, none of the flags did. MOV does not affect flags.

INC AL: FFh + 1 = 00h → ZF = 1, AF = 1, PF = 1. CF is still 1: INC and DEC never touch the carry flag.

MOV CX, 0: the result is zero, but ZF is not recomputed; it keeps the value from the previous instruction.

DEC AL: 00h − 1 = FFh → SF = 1, ZF = 0. CF is still 1: DEC does not record the borrow in CF.

ADD AL, 1: FFh + 1 = 100h → AL = 00h. ADD rewrites every status flag: this time CF = 1 is ADD’s own carry.

CLC: CF = 0.

NOT AL: AL = FFh, yet ZF is still 1. NOT changes no flags; to test the result, follow it with TEST AL, AL or CMP.

MOV, NOT, XCHG, LEA, PUSH and POP leave the flags alone; INC and DEC change all but CF. Before a conditional jump, check which instruction last set the flag.

A First Program

.COM Program Template

ORG 100h          ; .COM: code starts at 0100h

MOV AX, 5         ; AX = 5
MOV BX, 3         ; BX = 3
ADD AX, BX        ; AX = AX + BX = 8
MOV CL, AL        ; CL = 08h

RET               ; back to DOS

num DB 0          ; variables go after RET
  • ORG 100h: a .COM program is loaded at offset 0100h of its segment; the first 256 bytes (the PSP) belong to DOS.
  • Instructions execute top to bottom, in order.
  • RET returns to the operating system.
  • Variables go at the end (after RET) so the CPU never executes them as instructions.
  • A .COM program starts with CS = DS = ES = SS, IP = 0100h, SP = FFFEh.
In emu8086, new → COM template opens the template; emulate loads the program into the emulator, and single step shows how the registers change after each instruction.

A First Program · Step through the code

Code Trace: A .COM Program in Memory

ORG 100h       ; code at 0100h
MOV AX, 5
MOV BX, 3
ADD AX, BX     ; AX = 8
MOV CL, AL     ; CL = 08h
RET            ; back to DOS
num DB 0       ; data

The program is loaded at 0700:0100. CS = DS = ES = SS = 0700h, IP = 0100h, SP = FFFEh; the top of the stack holds 0000h.

MOV AX, 5 (3 bytes): AX = 0005h, IP = 0103h.

MOV BX, 3 (3 bytes): BX = 0003h, IP = 0106h.

ADD AX, BX (2 bytes): AX = 0008h, IP = 0108h.

MOV CL, AL (2 bytes): CL = 08h, IP = 010Ah.

RET pops 0000h: IP = 0000h, SP = 0000h. The INT 20h at PSP:0000 ends the program; num at 010Bh is never executed.

The instructions are 3, 3, 2, 2 and 1 bytes long; IP advances by each length. The data sits after RET, so it is never executed.

The Program in Memory, Byte by Byte

OffsetBytesSource lineNote

0106h03 C3ADD AX, BXC3 = 11 000 011: register–register, AX, BX

  • The .COM file is exactly these 12 bytes: there is no header; DOS copies them into memory starting at 0100h.
  • ORG 100h produces no bytes; it only sets where the first byte goes.
  • One instruction can have several encodings: 01 D8 is also valid for ADD AX, BX. MASM picks 03 C3; both do the same thing.
  • Nothing in memory tells code from data: had IP reached 010Bh, the 00 there would have been decoded as an instruction.

Syntax Rules

Number bases 25 or 25d decimal · 19h hex · 00011001b binary · 31o octal. All the same value: 25.
Hex starting with a letter Prefix a 0: 0FFh, 0B800h. Written as FFh, the assembler takes it for a name (label or variable).
Characters 'A' → ASCII code 41h. MOV CL, 'A' and MOV CL, 41h produce the same machine code.
Signed numbers -1 is stored as FFh in 8 bits and FFFFh in 16 bits (two’s complement).
Case The assembler ignores case: mov, MOV, Mov are the same; so are var1 and VAR1.
Comments Anything after ; is a comment. Good habit: say “why”, not “what”.

PUSH immediate and SHL AX, 2 are valid from the 80186 on. MASM rejects them when assembling for the 8086; emu8086 accepts them, but the code will not run on a real 8086.

A First Program

Assembly Error or Logic Error?

Assembly (syntax) errorThe assembler finds it and reports the line number; no program is produced.
  • MOV AL, BX: size mismatch
  • JMP strt: undefined label
  • MOV AL, 300: constant too large
Logic errorThe program assembles and runs, but the result is wrong; the assembler cannot tell.
  • Forgetting RET: data executed as code
  • Using JA for signed numbers
  • ADD instead of ADC: the carry is lost
  • Not loading DS in an .EXE
Logic errors are found by single-stepping: after each instruction, compare the expected register and flag values with the emulator’s. The first instruction where they differ is where the bug is.

Summary

Exercises

  1. With AX = 0ABCDh, what are AX, AL and BX after MOV AH, 0?
  2. With AX = 1234h and BL = 03h, what is AX after MUL BL? What happens to the 12h in AH?
  3. On an 8 MHz 8086, a loop runs 2000 times. How many clocks and milliseconds are saved by using INC CX (2 clocks) instead of INC count (21 clocks)?
  4. With AL = 80h, give AL, CF, ZF, SF and OF after ADD AL, 80h.
  5. A program starts at 0100h. What is IP after four instructions of 3, 2, 1 and 4 bytes?
  6. Why are MOV CX, AL and MOV ES, 0B800h wrong? Fix them.
Answers
  1. AX = 00CDh, AL = CDh; BX is unchanged.
  2. MUL BL multiplies AL (34h = 52) by BL: 52 × 3 = 156 = 009Ch. The product goes into all of AX; the 12h in AH is lost.
  3. 2000 × (21 − 2) = 38,000 clocks; one clock is 1/8 MHz = 0.125 µs → 4.75 ms.
  4. 80h + 80h = 100h → AL = 00h, CF = 1, ZF = 1, SF = 0, OF = 1 (−128 + −128 does not fit).
  5. 0100h + 10 = 010Ah.
  6. Size mismatch → MOV CL, AL (or MOV CH, 0 + MOV CL, AL); no immediate into a segment register → MOV AX, 0B800h · MOV ES, AX.
