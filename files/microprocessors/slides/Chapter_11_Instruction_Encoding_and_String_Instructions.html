Instruction Encoding

Machine Code Format

D (direction)1: the REG field is the destination; 0: the REG field is the source.
W (word)0: byte (8-bit) operation; 1: word (16-bit) operation.
ModR/MMOD says whether the operand is a register or memory, R/M picks the addressing form, REG the other register.
Common instructions have shorter special forms: inc ax = 40h (1 byte), mov ax, imm16 = B8h + 2 bytes, add al, imm8 = 04h + 1 byte.

  • For [bp] the assembler emits [bp+0] (MOD = 01, d8 = 0), because MOD = 00, R/M = 110 is reserved for a direct address.
  • A segment prefix overrides the default: mov al, es:[bx] → prefix 26h.

Instruction Encoding

Encoding Step by Step: MOV CL, [BX+SI+12h]

Instruction: move a byte from memory into CL. Form: MOV reg, r/m (opcode + ModR/M + displacement).

Opcode of the MOV r/m ↔ reg family: 100010.

D = 1: the REG field is the destination. W = 0: byte operation. Byte 1 = 1000 1010b = 8Ah.

MOD = 01: memory + 8-bit displacement. REG = 001 (CL). R/M = 000 ([BX+SI]). Byte 2 = 01 001 000b = 48h.

12h is appended as an 8-bit displacement. Result: 8A 48 12. With a 16-bit displacement it would be MOD = 10 and 4 bytes.

Instruction Encoding

MOD = 00, R/M = 110: Not [BP] but [d16]

mov [1000h], bl → 88 1E 00 10

88h10001000d = 0, w = 0
1Eh00011110REG = BL
MOD = 00 and R/M = 110 → a 2-byte address follows: 00 10 = 1000h. The instruction is 4 bytes. For [BP] the assembler uses MOD = 01, d8 = 0.
InstructionCodeNote
mov [1000h], alA2 00 10short form for AL, 3 bytes
mov [1000h], al88 06 00 10general form, 4 bytes (same effect): ModR/M 06h = 00 000 110
mov [1000h], bl88 1E 00 10no short form for BL
mov [bp], bl88 5E 005Eh = 01 011 110: [BP+d8], d8 = 0; segment SS
A decoder that wrongly took 1Eh as [BP] would read 88 1E as a 2-byte mov [bp], bl, and the address bytes would become a new instruction: 00 10 = add [bx+si], dl. Every later boundary shifts and memory gets corrupted.

Instruction Encoding

Same Bytes, Different Instructions: Decoding from the Wrong Offset

11 bytes in memory. Code or data? The CPU can't tell: whatever byte CS:IP points to, it takes as an opcode.

Offset 0: B4h = MOV AH, imm8 (B0h + 4) → takes 1 immediate byte: mov ah, 02h.

B2h = MOV DL, imm8 → mov dl, 41h (41h = 'A').

CDh = INT imm8 → int 21h: AH = 02h, DOS prints the 'A' in DL.

B8h = MOV AX, imm16 → 2 bytes, little-endian: mov ax, 4C00h.

int 21h, AH = 4Ch: the program exits. Decoding from offset 0 gives the code the programmer wrote.

Now shift IP by one byte (offset 1). 02h = ADD r8, r/m8; ModR/M B2h = 10 110 010 → MOD = 10 (d16), REG = DH, R/M = [BP+SI]; d16 = CD41h → 4 bytes: the 'A' and INT's opcode are swallowed.

21h = AND r/m16, r16; ModR/M B8h = 10 111 000 → [BX+SI+d16], REG = DI; d16 = 4C00h. This instruction writes to memory.

The final CD 21 lands in the same place in both decodings: the decoding has resynchronized. But AX = 4C00h was never loaded, so INT 21h runs with whatever AH holds. The meaning comes not from the bytes but from where IP starts.

The 8086 has no hardware distinction between code and data: a JMP into data or a miscomputed IP executes the bytes as instructions. A disassembler, too, has to know where to start.

Data Transfer · Step through the code

Code Trace: Printing a Byte in Hex with XLAT

BX gets the offset of the lookup table: BX = 011Dh.

The byte to print: AL = 3Ch (0011 1100b).

On the 8086 a shift count above 1 must be in CL.

shr al, cl: 0011 1100 → 0000 0011. AL = 03h (high nibble).

xlat: AL ← [DS:BX + AL] = hex_tab[3] = '3' (33h).

The character is copied to DL (the INT 21h/02h argument).

AH = 02h: the DOS print character service.

DOS prints '3' (AL also takes DL's value).

Reload the same byte: AL = 3Ch.

and al, 0Fh: the high nibble is masked off → AL = 0Ch.

hex_tab[12] = 'C' (43h).

DL = 43h. AH is still 02h, so no need to reload it.

'C' is printed → output 3C.

The program ends. XLAT translates through a table of up to 256 bytes in a single instruction.

org 100h
mov bx, offset hex_tab
mov al, num       ; AL = 3Ch
mov cl, 4
shr al, cl         ; high nibble
xlat               ; AL = [BX+AL]
mov dl, al
mov ah, 2
int 21h            ; print DL
mov al, num
and al, 0Fh        ; low nibble
xlat
mov dl, al
int 21h
ret
num  db 3Ch
hex_tab db '0123456789ABCDEF'

Data Transfer

Loading Addresses: LEA, LDS, LES

  • lea si, msg ≡ mov si, offset msg; the difference: LEA also handles addresses computed at run time: lea si, [bx+di+4].
  • LEA doesn't touch memory or the flags, so it doubles as an adder: lea ax, [bx+si] → AX = BX + SI.
  • lds si, ptr: SI ← [ptr], DS ← [ptr+2]. les di, ptr does the same with ES.
  • A far pointer is stored in memory offset first, segment second.
mov bx, 0010h
mov di, 0004h
lea ax, [bx+di+2]  ; AX = 0016h
mov ax, [bx+di+2]  ; AX = [0016h]

; video memory: B800:0000
les di, screen     ; DI=0000h ES=B800h
mov al, 'A'
stosb             ; 'A' in the corner
lds si, screen     ; SI=0000h DS=B800h
lodsb             ; AL = 'A' (corner)
ret
screen dw 0000h, 0B800h
LEA gives the address, MOV the contents: the difference between lea ax, [bx+di+2] and mov ax, [bx+di+2] is an exam favorite.

Data Transfer · Step through the code

Address or Contents? LEA, MOV and LES

org 100h
lea bx, vals        ; BX ← address
mov di, 2
lea ax, [bx+di+2]   ; AX ← EA
mov ax, [bx+di+2]   ; AX ← [EA]
les di, screen       ; far pointer
mov al, 'A'
stosb               ; ES:[DI] ← AL
ret
vals  dw 1111h, 2222h, 3333h
screen dw 0000h, 0B800h

LEA gives the address of the vals variable: BX = 0114h. Memory is not read.

DI = 2.

LEA AX, [BX+DI+2]: only the effective address is computed → AX = 0114h + 2 + 2 = 0118h. Memory is untouched, no flags change.

MOV AX, [BX+DI+2]: the contents at the same EA are read → AX = 3333h (the 3rd word of vals).

LES DI, screen: the far pointer in memory (offset first, segment second) → DI = 0000h, ES = B800h.

AL = 41h ('A').

STOSB: ES:[DI] = B800h × 10h + 0000h = B8000h ← 41h; DF = 0, so DI = 1. An 'A' in the top-left corner of the screen.

RET: the program ends.

String Processing

Repeat Prefixes: REP, REPE, REPNE

PrefixRepeat whileUsed with
REPCX ≠ 0MOVS, STOS
REPE / REPZCX ≠ 0 and ZF = 1CMPS, SCAS: "while equal"
REPNE / REPNZCX ≠ 0 and ZF = 0CMPS, SCAS: "while not equal"
1. If CX = 0, stop (the instruction may never run).
2. Execute the string instruction once, update SI/DI.
3. CX ← CX − 1 (flags unchanged).
4. For REPE/REPNE, test the ZF condition; stop if it fails, otherwise go back to 1.
; copy a 100-byte block
cld
lea si, src
lea di, dst
mov cx, 100
rep movsb

; fill the screen with blanks
mov ax, 0B800h
mov es, ax
xor di, di
mov ax, 0720h   ; ' ' + attribute
mov cx, 2000    ; 80×25
rep stosw

String Processing · Step through the code

Code Trace: Copying with MOVSB

DF = 0: copy forward.

SI = 010Eh: source string.

DI = 0112h: destination area ('....').

Byte count CX = 4.

movsb: one byte copied; SI = 010Fh, DI = 0113h. Flags unchanged.

CX = 0003h.

movsb: one byte copied; SI = 0110h, DI = 0114h. Flags unchanged.

CX = 0002h.

movsb: one byte copied; SI = 0111h, DI = 0115h. Flags unchanged.

CX = 0001h.

movsb: one byte copied; SI = 0112h, DI = 0116h. Flags unchanged.

CX = 0000h.

dst = 'ABCD'. mov cx, 4 + rep movsb does the same in one instruction.

org 100h
cld
lea si, src     ; DS:SI source
lea di, dst      ; ES:DI destination
mov cx, 4
copy_lp:
movsb              ; [DI]←[SI], SI++, DI++
loop copy_lp         ; = rep movsb
ret
src db 'ABCD'
dst  db 4 dup('.')

String Processing · Step through the code

Code Trace: Converting to Uppercase with LODSB + STOSB

cld: DF = 0 → string instructions increment SI/DI.

SI points to the source: SI = 0110h (msg).

The destination is the same string: DI = 0110h. In a COM program ES = DS, so ES:DI points to the same place.

5 characters to process.

lodsb: AL = [DS:SI] = 6Dh, then SI = 0111h.

Clear bit 5: AL = 4Dh.

stosb: [ES:DI] ← AL, then DI = 0111h.

CX = 0004h.

lodsb: AL = [DS:SI] = 69h, then SI = 0112h.

Clear bit 5: AL = 49h.

stosb: [ES:DI] ← AL, then DI = 0112h.

CX = 0003h.

lodsb: AL = [DS:SI] = 63h, then SI = 0113h.

Clear bit 5: AL = 43h.

stosb: [ES:DI] ← AL, then DI = 0113h.

CX = 0002h.

lodsb: AL = [DS:SI] = 72h, then SI = 0114h.

Clear bit 5: AL = 52h.

stosb: [ES:DI] ← AL, then DI = 0114h.

CX = 0001h.

lodsb: AL = [DS:SI] = 6Fh, then SI = 0115h.

Clear bit 5: AL = 4Fh.

stosb: [ES:DI] ← AL, then DI = 0115h.

CX = 0000h.

msg = 'MICRO'. A LODS/STOS pair is the standard pattern for transforming an array in place.

org 100h
cld               ; DF = 0: forward
lea si, msg
mov di, si        ; write in place
mov cx, 5
next_ch:
lodsb             ; AL = [SI], SI++
and al, 0DFh      ; uppercase
stosb             ; [DI] = AL, DI++
loop next_ch
ret
msg db 'micro'

String Processing · Step through the code

Code Trace: Finding a Character with REPNE SCASB

Scan forward.

DI = 0113h: the string to scan must be at ES:DI.

At most 7 comparisons.

Character to find: AL = 'h' (68h).

repne scasb: compares against 'p','u','s','h'; on the 4th comparison ZF = 1 and it stops. Each pass does DI++ and CX−−: DI = 0117h, CX = 0003h.

ZF = 1 (found) → no jump.

DI points one past the match; step back: DI = 0116h.

Subtract the start: DI = 3 → 'h' is at index 3 (counting from 0).

Had it not been found, the scan would end with CX = 0 and ZF = 0, and jne not_found would jump.

org 100h
cld
lea di, msg
mov cx, 7          ; length
mov al, 'h'        ; target
repne scasb        ; search
jne not_found
dec di             ; match position
sub di, offset msg
not_found:
ret
msg db 'pushing'

Unconditional Jump: JMP

KindCodeRangeExample

Indirect nearFF /4IP ← register/memoryjmp bx, jmp jmp_tab[bx]

  • Short and near jumps are relative: target = address of the next instruction + displacement, so the code can be moved in memory.
  • Indirect jumps build a jump table (switch-case): shl bx, 1 / jmp hex_tab[bx].
  • EB FE jumps to itself (an endless loop): FEh = −2 and the instruction is 2 bytes.

Summary

Summary

EncodingAn instruction is 1–6 bytes: opcode (D, W) + ModR/M + displacement + immediate; prefixes go in front.
ModR/MMOD = 11 register, 00/01/10 memory; MOD = 00, R/M = 110 is a direct address, so [BP] is encoded with d8 = 0.
Data transferXLAT: AL ← [DS:BX + AL]. LEA gives the address, MOV the contents; LDS/LES load a far pointer. No flags change.
StringsDS:SI → ES:DI, DF sets the direction, REP/REPE/REPNE repeat up to CX times; with CX = 0 the instruction never runs.
JMPShort (EB d8) and near (E9 d16) jumps are relative; far and indirect jumps use absolute addresses.
Flag effectsMoves, string moves and jumps leave the flags alone; never put a flag-changing instruction between CMP and Jcc.

Summary

Exercises

  1. Encode mov dx, [bp+di+8] (opcode 100010, d = 1, w = 1).
  2. DS = 1000h, BX = 0200h, AL = 05h: from which physical address does xlat load AL?
  3. farptr dd holds the bytes 34 12 00 B8. What are ES and DI after les di, farptr?
  4. How many bytes does rep movsb copy when CX = 0?
  5. CLD, CX = 5, SI = 0100h, DI = 0200h; repe cmpsb finds a mismatch at byte 3. CX, SI, DI and ZF afterwards?
  6. A jmp short at 0150h jumps to 0130h. What is its machine code?
  7. Count the spaces in a string with repne scasb.
Hints / answers
  1. MOD = 01, REG = 010 (DX), R/M = 011 ([BP+DI]) → 8B 53 08; segment SS.
  2. EA = BX + AL = 0205h → 10000h + 0205h = 10205h.
  3. Offset first, then segment: DI = 1234h, ES = B800h.
  4. 0: REP tests CX first; with CX = 0 the instruction never runs.
  5. Three comparisons: CX = 2, SI = 0103h, DI = 0203h, ZF = 0. The mismatch is at SI − 1 = 0102h.
  6. The next instruction is at 0152h; 0130h − 0152h = −22h = DEh → EB DE.
  7. Count each hit; while CX ≠ 0, repeat repne scasb (DI resumes where it stopped).

Summary

Exercises (2)

  1. Which instruction is 8A 1E 34 12? What do the same bytes decode to one byte later (from offset 1)?
  2. Encode mov es, dx and mov al, [0020h].
Hints / answers
  1. mov bl, [1234h] (8Ah: d = 1, w = 0; 1Eh = 00 011 110 → MOD = 00, R/M = 110: d16). From offset 1: 1E = push ds, 34 12 = xor al, 12h.
  2. 8E C2 (11 000 010: sreg = ES, R/M = DX); A0 20 00 (the short AL form, address little-endian).
