Addressing Modes

Memory Access

  • Memory is addressed through the BX, SI, DI and BP registers.
  • Combining these registers (and a constant) inside [ ] reaches different memory locations; these combinations are the addressing modes.
Register(s) only+ d8 (8-bit displacement)+ d16 (16-bit displacement)
[BX + SI][BX + SI + d8][BX + SI + d16]
[BX + DI][BX + DI + d8][BX + DI + d16]
[BP + SI][BP + SI + d8][BP + SI + d16]
[BP + DI][BP + DI + d8][BP + DI + d16]
[SI][SI + d8][SI + d16]
[DI][DI + d8][DI + d16]
d16 (direct address)[BP + d8][BP + d16]
[BX][BX + d8][BX + d16]

These 24 combinations are all the memory choices of the mod/rm field in 8086 machine code. A bare [BP] is encoded by the assembler as [BP + 0] (d8 = 0).

Addressing Modes

The Combination Rule

Rules
  • BX and BP never appear in the same mode.
  • SI and DI never appear in the same mode.
  • Modes with BP use the SS segment; modes without BP use DS.
Examples
  • [BX+5] → base + d8 (DS)
  • [BX+SI] → base + index (DS)
  • [DI+BX-4] → [BX+DI-4], order does not matter (DS)
  • [BP+SI+300] → base + index + d16 (SS)

Addressing Modes

Displacement

d88-bit signed displacement (−128 … +127). Examples: 22, 55h, -1.
d1616-bit signed displacement. Examples: 300, 5517h, -259.
  • A displacement can be a number or the offset of a variable: [BX + arr].
  • The assembler folds several constants into one: [BX + 2 + 3] → [BX + 5].
  • It may be written inside or outside [ ]; the machine code is the same: [BX+5] = 5[BX] = [BX]+5.
  • It is signed, so it can be positive or negative: [SI-1].
  • The assembler picks the short form (d8) when the value is in −128…127, otherwise the long form (d16).
The effective address is computed in 16 bits and wraps around: with BX = FFFFh, [BX+2] → EA = 0001h.

Addressing Modes

String, I/O and Relative Modes

Three more modes: the operand is not written at all, lives in an address space separate from memory, or is found relative to IP.

String modeString instructions have implicit operands: source DS:SI, destination ES:DI. After each operation SI and DI increase when DF = 0 and decrease when DF = 1 (byte ±1, word ±2).
MOVSB ; ES:[DI] ← DS:[SI]

IN  AL, 45h

Relative modeThe instruction holds not the target but a signed distance added to IP: IP = address of next instruction + distance. Short jumps use an 8-bit distance (−128 … +127).
JNZ again ; 75 FA = −6

Mnemonics are written as one word (MOVSB, not MOVS B). OUT takes the port first, then the data register: OUT 50h, AL; IN A, 45 is 8085 syntax.

Code Trace: Six Addressing Modes

ORG 100h

MOV AL, [table+1]  ; direct

BX = 0116h: the offset of table (OFFSET is computed at assembly time).

SI = 2: the index register.

Immediate mode: 7 is inside the instruction; no memory access. AH = 07h.

Direct mode: the address is in the instruction: [0117h] → AL = 22h.

Register indirect: EA = BX = 0116h → CL = 11h.

Based: EA = BX + 4 = 011Ah → CH = 55h.

Based-indexed: EA = BX + SI = 0118h → DL = 33h.

Base + index + d8: EA = BX + SI + 3 = 011Bh → DH = 66h. No BP is used, so the segment is always DS.

DS = 0700h is assumed for the .COM program; physical address = DS × 10h + EA.

Effective Address Step by Step

MOV AL, [BX + SI + 4] · DS = 1000h, BX = 0200h, SI = 0030h

Base register BX = 0200h.

Add the index register SI = 0030h.

8-bit displacement: +4.

Effective address EA = 0200h + 0030h + 0004h = 0234h (16 bits).

No BP → segment DS. Physical address = 10000h + 0234h = 10234h. AL gets the byte at that address.

Access Through BP

MOV AX, [BP + DI - 2] · SS = 2000h, BP = 0100h, DI = 0010h

Base register BP = 0100h.

Add the index register DI = 0010h.

Signed displacement −2 (FEh in machine code).

EA = 0100h + 0010h − 2 = 010Eh.

BP is used, so the segment is SS: 20000h + 010Eh = 2010Eh. AX ← [2010Eh] (2 bytes: 2010Eh and 2010Fh).

Addressing Modes · Step through the code

Code Trace: Accessing a Matrix Element

org 100h
mov bx, 2*4          ; row 2
mov si, 1            ; column 1
mov al, mat[bx+si]   ; mat[2][1]
mov si, 3            ; column 3
mov ah, mat[bx+si]   ; mat[2][3]
sub bx, 4            ; row 1
mov dl, mat[bx+si]   ; mat[1][3]
ret
mat db 11h,12h,13h,14h
    db 21h,22h,23h,24h
    db 31h,32h,33h,34h

BX = 2 × 4 = 0008h: row 2 starts 8 bytes into the matrix (row × row length).

SI = 1: the column within the row. The base register selects the row, the index register the column.

mat[bx+si]: EA = 0119h + 8 + 1 = 0122h → AL = 32h (row 2, column 1). The displacement is the offset of mat (d16).

SI = 3: another column in the same row. BX is unchanged, so the row stays fixed.

EA = 0124h → AH = 34h. Same instruction; only the index changed.

sub bx, 4: one row up (BX = 0004h). The column (SI = 3) is kept.

EA = 0119h + 4 + 3 = 0120h → DL = 24h (row 1, column 3).

ret: AX = 3432h, DL = 24h. Three elements were read with a single addressing pattern.

Row-major order: address of element[row][col] = mat + row × number of columns + col. For a word matrix, both terms are doubled.

On the 8086 the execution unit computes the effective address with a separate addition; that time is added to the instruction’s own time.

  • MOV AX, BX: 2 clocks (no memory).
  • MOV CL, [BX]: 8 + 5 = 13 clocks.
  • MOV CL, [BX+DI+4]: 8 + 12 = 20 clocks.
  • A word at an odd address needs +4 clocks for the second bus cycle.

Keeping a value that a loop reads often in a register removes this calculation from every pass.

Figures are from the table in the Intel 8086 user’s manual; from the 80286 on, address calculation has its own unit and these differences shrink.

Segment and Offset

Segment and Offset

  • The value in a segment register (CS, DS, SS, ES) is the segment; the value in an addressing register (BX, SI, DI, BP) is the offset.
  • The segment selects a block of memory and the offset a specific location in it; together they form the physical address.

DS = 1234h, SI = 7890h. Notation: 1234:7890.

The segment is multiplied by 10h (shifted left 4 bits): 12340h.

The offset is aligned for the addition: 7890h.

12340h + 7890h = physical address 19BD0h.

Segment and Offset

Address Lines and Memory Capacity

n address lines select 2n locations. The number of data lines sets the bits per location:

capacity = 2n × data width

  • 8086: 20 lines → 220 = 1,048,576 locations = 1 MB (00000h–FFFFFh).
  • A segment’s limit comes from the offset: 16 bits → 216 = 64 KB.
  • The reverse question: how many lines at least? Take the first power of 2 that covers the capacity: for 6 GB, 232 = 4 GB is not enough, so 33 lines (8 GB).
Address / data linesCapacity
12 / 84096 × 1 B = 4 KB
16 / 464 K × 4 bits = 32 KB
16 / 864 KB (one segment)
20 / 81 MB (8086)
24 / 1616 M × 2 B = 32 MB
32 / 84 GB (80386)

On a memory chip the number of data lines is the word width; for a capacity in bytes, divide the bit count by 8.

Segment and Offset

Working Backwards: DS:SI from a Physical Address

We want to reach physical address 2A5C3h through DS:SI. There is no single answer; we find the range DS can take.

Largest DSMake SI as small as possible: DS = first four digits = 2A5Ch, SI = 2A5C3h − 2A5C0h = 0003h.
Smallest DSSI can be at most FFFFh: DS × 10h ≥ 2A5C3h − FFFFh = 1A5C4h → DS ≥ 1A5C.4h → 1A5Dh, SI = FFF3h.
How many pairs?Each step up in DS lowers SI by 10h: 2A5Ch − 1A5Dh + 1 = 1000h = 4096 pairs.

Always check with the forward calculation: 1A5Dh × 10h + FFF3h = 1A5D0h + FFF3h = 2A5C3h.

Segment and Offset

Segment Override Prefix

Writing a segment override prefix before the brackets replaces the default segment:

MOV AX, 0B800h
MOV ES, AX          ; ES = video memory
MOV BX, 0
MOV AL, ES:[BX]     ; read ES:0000
MOV AL, [BX]        ; read DS:0000
MOV DL, SS:[SI]     ; read SS:SI

The prefix is a 1-byte code placed before the instruction in machine code (ES: → 26h, CS: → 2Eh, SS: → 36h, DS: → 3Eh).

When is it needed?
  • To reach data in another segment (e.g. video memory) without changing DS.
  • To reach stack data through a register other than BP: SS:[BX].
  • To read a table stored in the code: CS:[SI].

IP always pairs with CS and SP always with SS; these cannot be overridden.

Code Trace: Video Memory Through ES

ORG 100h
MOV AX, 0B800h
MOV ES, AX         ; ES = video
MOV BX, 00A0h      ; row 1
MOV BYTE PTR ES:[BX], 'K'
MOV BYTE PTR ES:[BX+1], 1Eh
MOV AL, [BX]       ; DS:00A0h
MOV DL, ES:[BX]    ; B800:00A0h
RET

AX = B800h: the segment of the color text screen. In video memory one cell = character + color.

ES = B800h. DS still holds the program’s segment (0700h), so variable access is unaffected.

BX = 00A0h = 160 = (1 × 80 + 0) × 2: the first cell of row 1.

The ES: prefix (byte 26h in machine code): B8000h + 00A0h = B80A0h ← 'K' (4Bh).

B80A1h ← 1Eh: yellow on blue. A yellow K appears on the screen.

No prefix → default DS: 07000h + 00A0h = 070A0h is read (the program’s PSP area, 00h here). Same offset, different byte.

ES:[BX] goes to video memory again: DL = 4Bh ('K').

The video cell is assumed to start as 20h 07h (space, gray). The prefix affects only its own instruction; DS does not change.

data ends

AX = 0710h: the paragraph number of the data segment (set by the loader). When an EXE starts, DS does not point to its data.

DS = 0710h. The stack segment SS = 0711h is a separate block; in this program DS ≠ SS.

BP = 0003h: the offset of x. The offset is right; the trouble is the segment.

[bp] pairs with SS by default: 07113h is read, AL = 00h. Not 'D', but a byte from the stack.

ds:[bp]: the prefix overrides the default, 07103h is read → BL = 44h ('D').

The same offset goes into SI: SI = 0003h.

[si] uses DS by default: CL = 44h. Use BX/SI/DI for data and BP for the stack.

AH = 4Ch, AL = 0: the program returns to DOS with exit code 0.

In a .COM program CS = DS = SS, so this bug stays hidden; it shows up in an .EXE program with a separate stack segment.

DSVariable names are only offsets; once DS changes, the same name reaches a byte in another segment. Wrap a temporary change in PUSH DS / POP DS, or use ES.
SS and SPChange them together. After a MOV or POP into a segment register, the 8086 accepts no interrupt until the next instruction finishes, so SS:SP is never left half-set.
CSCannot be written with MOV; a far JMP/CALL/RET or INT/IRET changes CS and IP together.

ES is used by default only as the string destination, which makes it the safest way to reach a second data block (video memory, a buffer).

Data Type

Specifying the Data Type

  • Type specifiers tell the assembler the size of the data being accessed:
    • byte ptr [BX]: a byte (8-bit) access.
    • word ptr [BX]: a two-byte (16-bit, one word) access.
  • emu8086 also accepts shorter forms:
    • b.[SI]: the value at the address in SI, as a byte.
    • w.[DI]: the value at the address in DI, as a word.
  • Often the assembler infers the type itself: if the other operand is a register, its size wins.
InstructionWhere does the size come from?
MOV [BX], ALAL is 8 bits → a byte is written
MOV [BX], AXAX is 16 bits → a word is written
MOV [BX], 5ambiguous! → MOV BYTE PTR [BX], 5 or MOV WORD PTR [BX], 5

word ptr: 2 bytes are written. The low byte (34h) goes to the low address: 34 12.

byte ptr: only 0200h changes → FF 12. 0201h is untouched.

Data Type

Little-Endian Order

  • The 8086 is little-endian: the low byte of a 16-bit value is stored at the low address, the high byte at the next one.
  • MOV [0200h], AX → [0200h] = AL, [0201h] = AH. MOV AX, [0200h] does the reverse.
  • That is why words look “reversed” in the emu8086 memory window: 1234h → 34 12.
  • The rule also applies to constants in machine code: MOV AX, 1234h → B8 34 12.

Data Type · Step through the code

Code Trace: The Word-Array Index Bug

org 100h
mov si, 1            ; index 1
mov ax, arr[si]      ; BUG!
shl si, 1            ; index × 2
mov bx, arr[si]      ; arr[1]
mov si, 2            ; index 2
shl si, 1            ; SI = 4
mov cx, arr[si]      ; arr[2]
ret
arr dw 1234h, 5678h, 9ABCh

SI = 1, meaning “the second element”. But SI is a byte distance.

arr[si] = 0118h: the high byte of arr[0] and the low byte of arr[1] are read → AX = 7812h. Neither 1234h nor 5678h.

shl si, 1: index × 2 → SI = 2. In a word array, byte distance = index × 2.

EA = 0119h → BX = 5678h = arr[1]. The right element.

SI = 2: this time index 2 (the third element).

shl si, 1: SI = 4. A shift is the shortest way to multiply by 2.

EA = 011Bh → CX = 9ABCh = arr[2].

When a loop walks a word array, advance SI with ADD SI, 2 on every pass; INC SI is for byte arrays only.

The MOV Instruction

The MOV Instruction

  • MOV dest, source copies the source value into the destination; the source is unchanged.
  • Source: an immediate (constant), a general-purpose register, a segment register or a memory location.
  • Destination: a general-purpose register, a segment register (not CS) or a memory location.
  • It cannot load CS or IP.
  • Both operands must be the same size: both bytes or both words.
  • Only one operand may be memory.
  • MOV does not affect the flags.
MOV AX, BXCopies the value in BX into AX. BX is unchanged.
MOV [SI], 10hWrites 10h to the address in SI (DS:SI). The size is ambiguous, so the correct form is MOV BYTE PTR [SI], 10h.

The MOV Instruction · Step through the code

Code Trace: Block Copy Through a Register

org 100h
mov si, offset src
mov di, offset dst
mov cx, 4
copy:
mov al, [si]         ; memory → AL
mov [di], al         ; AL → memory
inc si
inc di
loop copy
ret
src db 'ABCD'
dst db 4 dup('.')

SI = 0112h: the offset of the source.

DI = 0116h: the offset of the destination. Two pointers, two separate buffers.

CX = 4: the number of bytes to copy (the LOOP counter).

mov al, [si]: memory to register → AL = 'A' (41h). There is no memory-to-memory MOV, so AL is the stopover.

mov [di], al: register to memory → [0116] = 41h.

inc si: the source pointer moves to the next byte.

inc di: so does the destination pointer. The two pointers advance together.

loop copy: CX = 3 ≠ 0 → back to the top.

Pass 2 (summary): 'B' copied, SI = 0114h, DI = 0118h, CX = 2.

Pass 3 (summary): 'C' copied, CX = 1.

Pass 4 (summary): 'D' copied, CX = 0 → LOOP falls through. The destination now holds ABCD.

ret: SI and DI point just past the buffers (0116h, 011Ah).

Each byte costs two memory accesses and a register. String instructions do the same job in one instruction (REP MOVSB: DS:SI → ES:DI).

Moving a Register Value into Memory

DS:2000h is empty (00 00).

BX = 1234h; IP = 0103h.

BX is written to memory: [2000h] = 34h, [2001h] = 12h. The instruction is 4 bytes → IP = 0107h.

RET: IP = 0000h. BX is unchanged. Physical address: 07000h + 2000h = 09000h.

ORG 100h
MOV BX, 1234h     ; BB 34 12
MOV [2000h], BX   ; 89 1E 00 20
RET

Swapping Two Registers

CX = 10 = 000Ah (numbers are decimal by default).

DX = 20 = 0014h.

XCHG swaps the two operands in one instruction: CX = 0014h, DX = 000Ah. Flags are not affected.

MOV CX, 10   ; CX = 000Ah
MOV DX, 20   ; DX = 0014h
XCHG CX, DX  ; swap

MOV Examples

XCHG Rules

XCHG dest, source
  • Register ↔ register: XCHG AX, BX
  • Register ↔ memory: XCHG AL, [SI]
  • No memory ↔ memory.
  • No segment registers or immediates.
  • Sizes must match; flags are unchanged.
  • XCHG AX, reg is a one-byte instruction (XCHG AX, AX = NOP = 90h).

Without XCHG a swap would need a temporary register:

MOV AX, CX    ; AX ← CX (backup)
MOV CX, DX    ; CX ← DX
MOV DX, AX    ; DX ← old CX

That costs 3 instructions and an extra register; XCHG does it in one.

MOV Examples · Step through the code

Code Trace: Swapping with XCHG

ORG 100h
MOV SI, OFFSET num
MOV AL, 5Ah
XCHG AL, [SI]      ; AL ↔ [SI]
MOV CX, 1111h
MOV DX, 2222h
MOV AX, CX         ; backup
MOV CX, DX
MOV DX, AX         ; swapped
XCHG CX, DX        ; one instr.
RET
num DB 0A5h

SI = 0116h: the address of num; in memory num = A5h.

AL = 5Ah.

XCHG AL, [SI]: AL ↔ memory. AL = A5h, num = 5Ah. No temporary register needed.

CX = 1111h.

DX = 2222h. Now the same swap without XCHG.

MOV AX, CX: a backup of CX in AX (AX’s old value is lost).

MOV CX, DX: CX = 2222h. The old CX survives only in AX.

MOV DX, AX: DX = 1111h. The swap took 3 instructions and a register.

XCHG CX, DX: swapped back in one instruction: CX = 1111h, DX = 2222h; AX is untouched.

XCHG leaves the flags alone; there is no memory ↔ memory or segment-register exchange.

Copying One Register into Another

SI gets a memory address (an offset): 3000h.

DI = SI = 3000h. What is copied is the address, not the data in memory.

SI and DI now point to the same cell: AL = [3000h] = 5Ah.

AL is written to [DI+1] = 3001h → 5A 5A.

MOV SI, 3000h  ; SI = address
MOV DI, SI     ; DI = SI
MOV AL, [SI]   ; DS:3000h
MOV [DI+1], AL ; DS:3001h

Writing a Constant to a Memory Address

DS:4000h … 4003h: 00 99 00 99.

65 = 41h = 'A' is written as a single byte. Machine code C6 06 00 40 41 (5 bytes) → IP = 0105h. [4001h] is unchanged.

WORD PTR: 0041h is written → [4002h] = 41h, [4003h] = 00h (the 99h is overwritten). The instruction is 6 bytes → IP = 010Bh.

RET: IP = 0000h. A constant has no size of its own; the PTR specifier sets it.

ORG 100h
MOV BYTE PTR [4000h], 65  ; 'A'
MOV WORD PTR [4002h], 65
RET

Copying a Register’s Low Byte into Another

AX = 1234h: AH = 12h, AL = 34h.

BX = FFFFh, to make the effect visible.

AL (the low byte of AX) is copied to BL: BL = 34h. BH is unchanged → BX = FF34h.

MOV AX, 1234h   ; AH = 12h, AL = 34h
MOV BX, 0FFFFh
MOV BL, AL      ; BL only

MOV Examples · Step through the code

Adding to a Register’s High Byte

AX = 00FFh.

AH = 00h + 01h = 01h → AX = 01FFh. Nonzero result, no carry.

AL = FFh + 1 = 00h, CF = 1, ZF = 1. The carry does not reach AH: AX = 0100h.

For comparison, AX is 01FFh again. MOV leaves the flags alone.

16-bit addition: 01FFh + 1 = 0200h; the carry passed from AL into AH, CF = 0.

MOV AX, 00FFh   ; AH = 00h, AL = FFh
ADD AH, 01h     ; AH only
ADD AL, 01h     ; AL only
MOV AX, 01FFh
ADD AX, 1       ; 16 bits

Loading Binary, Octal and Hex Values

00000101b = 5 → AL = 05h.

0Ah = 10 → BL = 0Ah. It starts with a letter, hence the leading 0.

10o (octal) = 1×8 + 0 = 8 → CL = 08h.

AL = 5 + 10 = 15 = 0Fh. PF = 1 (0000 1111: four 1 bits).

AL = 15 − 8 = 7 = 07h. No borrow → CF = 0; PF = 0 (three 1 bits).

mov al, 00000101b ; binary
mov bl, 0ah       ; hex
mov cl, 10o       ; octal
add al, bl        ; 5 + 10 = 15
sub al, cl        ; 15 - 8 = 7

Exercises

  1. DS = 3000h, BX = 0010h, SI = 0005h: EA and physical address of [BX+SI+20h]?
  2. SS = 4000h, BP = FFFEh: EA and physical address of [BP+4]?
  3. Which of [BX+BP], [DI+SI], [BX+DI+300], [DX] are valid?
  4. If [0500h] = 78h and [0501h] = 56h, what is AX after MOV AX,[0500h]? AL after MOV AL,[0501h]?
  5. Write code that puts a yellow 'X' on green at row 10, column 40 of the screen (color 2Eh).
  6. How would you change the previous program to write to video memory through ES without touching DS?
Answers
  1. EA = 0035h; physical = 30000h + 0035h = 30035h.
  2. EA = FFFEh + 4 = 0002h (wraps around); physical = 40002h.
  3. Only [BX+DI+300].
  4. AX = 5678h; AL = 56h.
  5. Offset (10×80+40)×2 = 1680 = 690h: MOV AX,0B800h · MOV DS,AX · MOV BX,690h · MOV WORD PTR [BX],2E58h.
  6. MOV AX,0B800h · MOV ES,AX · … · MOV ES:[BX],CX.
