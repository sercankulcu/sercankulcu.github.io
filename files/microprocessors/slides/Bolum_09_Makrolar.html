Giriş

Öğrenme Çıktıları

Makro tanımı

MACRO / ENDM ile parametreli makro yazmak.

Genişletme

Derleyicinin makro çağrısını nasıl metin olarak açtığını izlemek.

Makro mu, prosedür mü?

Boyut, hız ve kullanım açısından iki yöntemi karşılaştırıp doğru olanı seçmek.

LOCAL

Etiket içeren makrolarda Duplicate declaration hatasını önlemek.

Uygulama

PUTC (ekrana karakter) ve POWER (üs alma) makrolarını adım adım çalıştırmak.

Tuzaklar

Parametre yan etkileri, yazmaç bozulması ve sınır durumlarını fark etmek.

Makro Kavramı

Makrolar

  • Makrolar prosedürlere benzer: tekrar eden bir kod parçasına ad verir.
  • Ancak çalışma zamanında çağrılmazlar; derleme aşamasında gerçek komutlarla değiştirilen geçici yapılardır.
  • Kod içinde kullanılmayan makrolar görmezden gelinir: makine koduna hiçbir bayt eklemezler.
  • Makrolar, prosedürlerden farklı olarak, kullanıldıkları kodun üzerinde (önce) tanımlanmalıdır; derleyici makroyu tanımadan çağrıyı açamaz.

Makro Kavramı

Makro Tanımlama

name    MACRO  [parametreler,...]
        <komutlar>
        ENDM
nameMakronun adı; çağırırken komut gibi yazılır.
parametrelerVirgülle ayrılmış biçimsel adlar (isteğe bağlı). Çağrıdaki değerler bunların yerine metin olarak konur.
ENDMMakro gövdesini bitirir. Prosedürdeki gibi ad tekrar yazılmaz.
Parametreler yazmaç, bellek ya da sabit olabilir: derleyici yalnızca metni değiştirir; sonuçta oluşan komutun geçerli olup olmadığına genişletmeden sonra bakılır.

Makro Kavramı · Kodu adım adım çalıştır

Açılmış Kodu Çalıştırmak

Yükleme sonrası CX = 0012h: programın boyutu 5 × 3 + 2 + 1 = 18 bayt. SP = FFFEh.

AX = 0001h.

BX = 0002h.

CX = 0003h. Birinci çağrı bitti; hiçbir CALL/RET yok.

AX = 0004h.

BX = 0005h.

CX ← DX = 0000h (DX başlangıçta sıfır).

RET: program biter.

ORG 100h
MOV AX, 00001h   ; MyMacro 1, 2, 3
MOV BX, 00002h
MOV CX, 00003h
MOV AX, 00004h   ; MyMacro 4, 5, DX
MOV BX, 00005h
MOV CX, DX
RET

SP hiç değişmedi: makro yığın kullanmaz (gövdesinde PUSH/POP yoksa). Prosedürde CALL/RET SP'yi değiştirirdi.

Makro Kavramı · Kodu adım adım çalıştır

Tuzak: Parametreler Metindir

MyMacro BX, AX, 0 çağrısının amacı: AX ← BX, BX ← AX (takas) sanılıyor.

AX = 1111h.

BX = 2222h.

Makronun 1. satırı: MOV AX, p1 → MOV AX, BX → AX = 2222h.

2. satır: MOV BX, AX. Programcı “eski AX” (1111h) bekliyordu ama AX bir önceki satırda değişti → BX = 2222h.

CX = 0.

Sonuç: AX = BX = 2222h. 1111h kayboldu.

ORG 100h
MOV  AX, 1111h
MOV  BX, 2222h
MOV  AX, BX  ; MyMacro BX,AX,0
MOV  BX, AX  ; p2 = AX (bozuk!)
MOV  CX, 0
RET

Makro parametresi bir değişken değil, yerine konan bir metindir: değeri, kullanıldığı satırda okunur. Makro gövdesinin değiştirdiği yazmaçlar parametre olarak geçirilmemelidir.

Makro Kavramı

Parametre Türleri: Aynı Makro, Farklı Açılım

TOPLA MACRO x, y, z
  MOV AX, x
  ADD AX, y
  MOV z, AX
ENDM
ÇağrıAçılımDurum
TOPLA a, b, cMOV AX, a · ADD AX, b · MOV c, AXgeçerli
TOPLA BX, 5, CXMOV AX, BX · ADD AX, 5 · MOV CX, AXgeçerli
TOPLA a, b, 7MOV 7, AXhedef sabit olamaz
TOPLA k, b, c (k DB)MOV AX, kboyut uyuşmazlığı
TOPLA a, bMOV , AXeksik işlenen
  • Parametre yazmaç, değişken, sabit ya da ifade olabilir; hangisinin kabul edileceğini makro değil, açılımda oluşan komut belirler.
  • Hata makronun kullanıldığı satırda bildirilir, ama nedeni gövdedeki bir satırdır: hata iletisini anlamak için açılım düşünülür.
  • Eksik parametre boş metinle değiştirilir. MASM'da z:REQ parametreyi zorunlu yapar, y:=<1> ona varsayılan değer verir.

Makro Kavramı · Kodu adım adım çalıştır

Kod İzleme: TOPLA ile İki Açılım

org 100h
mov ax, a      ; TOPLA a, b, c
add ax, b
mov c, ax
mov ax, c      ; TOPLA c, 5, d
add ax, 5
mov d, ax
ret
a dw 1200h
b dw 0345h
c dw ?
d dw ?

1. açılım TOPLA a, b, c: x yerine a yazıldı → AX = 1200h.

ADD AX, b: 1200h + 0345h = 1545h.

MOV c, AX: c = 1545h. Bellekten belleğe toplama olmadığı için makro AX'i ara yazmaç olarak kullanır.

2. açılım TOPLA c, 5, d: aynı gövde, başka metin. x = c → AX = 1545h.

y = 5 bu kez bir sabit: ADD AX, 5 → AX = 154Ah.

MOV d, AX: d = 154Ah. İki açılım 6 komut üretti; makro AX'i bozdu ve bunu çağıran bilmelidir.

RET. Toplam kod 2 × (3 + 4 + 3) = 20 bayt + RET; her TOPLA kullanımı gövdeyi yeniden yazar.

Makro: TOPLA MACRO x, y, z / MOV AX, x / ADD AX, y / MOV z, AX / ENDM. Kod, iki çağrının açılmış hâlidir.

Makro Kavramı

Parametre İfadeleri ve İşlem Önceliği

ALAN MACRO en, boy
  MOV AX, en*boy
ENDM

FARK MACRO p, q
  MOV CX, p-q
ENDM
  • Parametre bir değer değil metindir: ifadenin yerine konduğu satırda işlem önceliği yeniden uygulanır.
  • ALAN 2+3, 4: çarpma önce yapılır, AX = 14 olur; beklenen 20 idi.
  • Çözüm: gövdede parametreleri paranteze almak: (en)*(boy), (p)-(q).
ÇağrıAçılımSonuç

düzeltilmiş ALAN 2+3, 4MOV AX, (2+3)*(4)AX = 0014h (20)
FARK 10, 4+1MOV CX, 10-4+1CX = 0007h
ALAN BX, 2MOV AX, BX*2hata: * yalnız sabitlerle

İfade derleme anında hesaplanır; yazmaç içeren bir ifade çalışma anında çarpılamaz. Yazmacı çarpmak için MUL ya da SHL komutu gerekir.

Makro ve Prosedür


Prosedür Özellikleri




    

  • Prosedür CALL komutu ile çağrılır.
    • 

  • Prosedür belleğin belirli bir adresinde tek kopya olarak bulunur.
    • 

  • Çağrıldığında CPU kontrolü bu bölgeye aktarır; RET ile kontrol programın ana kısmına geri döner.
    • 

  • Dönüş adresini saklamak için yığın kullanılır.
    • 

  • Aynı prosedür 100 kez çağrılırsa dosya boyutu çok az artar: yakın CALL komutu yalnızca 3 bayt yer kaplar.
    • 

  • Parametre geçirmek için yığın veya yazmaçlar kullanılır.
    • 

  • Prosedür, adı ve ENDP direktifiyle sonlandırılır.
    • 



YAZ_A PROC
      PUSH AX
      MOV  AL, 'A'
      MOV  AH, 0Eh
      INT  10h
      POP  AX
      RET
YAZ_A ENDP

      CALL YAZ_A  ; 3 bayt
      CALL YAZ_A  ; 3 bayt

Makro Özellikleri




    

  • Makro sadece adı yazılarak kullanılır (CALL yok).
    • 

  • Makrolar program kodunda doğrudan genişletilir.
    • 

  • Aynı makro 100 kez kullanılırsa derleyici makroyu 100 kez genişletir; çalıştırılabilir dosyanın boyutu giderek büyür.
    • 

  • Parametre geçirmek için makro adının ardından değerler yazılır.
    • 

  • Makroyu sonlandırmak için ENDM direktifi yeterlidir.
    • 

  • Makro tanımında etiketler varsa ve makro birden fazla kez kullanılırsa Duplicate declaration hatası alınabilir; değişken, etiket ve prosedür adları için LOCAL direktifi kullanılır.
    •

Kural: kısa ve sık kullanılan, hız gerektiren kod → makro; uzun ve çok yerde kullanılan kod → prosedür. İkisi birlikte de kullanılabilir: makro, parametreleri yazmaçlara koyup bir prosedürü çağırabilir.






Makro ve Prosedür


Boyut Hesabı: 1, 10 ve 100 Kullanım




1 kullanım: makro 8 bayt; prosedür 8 bayt gövde + 1 bayt RET + 3 bayt CALL = 12 bayt. Burada makro daha küçük.


10 kullanım: makro 80 bayt; prosedür 9 + 30 = 39 bayt.


100 kullanım: makro 800 bayt; prosedür 9 + 300 = 309 bayt. Fark kullanım sayısıyla büyür.


Hız tarafında tersi geçerlidir: her CALL + RET çifti 8086'da yaklaşık 19 + 8 = 27 saat turu ve iki yığın erişimi ekler. Makroda bu maliyet yoktur.






Makro ve Prosedür


Karar Alıştırması: Makro mu, Prosedür mü?




Beş durum: her birinde kod boyutu (kaç kopya?) ve hız (CALL/RET maliyeti) birlikte tartılır.


1. Ekrana tek karakter yazmak, 200 yerde → kısa gövde (8 bayt) ama 200 kopya = 1600 bayt. Prosedür 9 + 600 = 609 bayt. Boyut önemliyse prosedür; hız önemliyse makro.


2. İki yazmacı takas eden 1 satırlık iş → XCHG zaten tek komut; makro okunabilirlik için yeterli, prosedür gereksiz yük (makro).


3. 300 baytlık sıralama algoritması, 3 yerde → makro 900 bayt, prosedür 300 + 9 bayt: açıkça prosedür.


4. Sıkı bir döngü içinde her turda yapılan 2 komutluk iş → CALL/RET maliyeti işin kendisinden büyük: makro.


5. Parametreleri yazmaçlara koyup ortak kodu çağırmak → ikisi birlikte: makro YAZ_SAYI x → MOV AX, x + CALL print_num (emu8086.inc de böyle çalışır).

Makro Parametreyi Hazırlar, Prosedür İşi Yapar

  


org 100h
mov  al, 4       ; YAZ_RAKAM 4
call rakam_yaz
mov  al, 7       ; YAZ_RAKAM 7
call rakam_yaz
ret
rakam_yaz:
add  al, '0'     ; rakam → ASCII
mov  ah, 0Eh
int  10h
ret

    




Makro YAZ_RAKAM d, derlemede iki satıra açıldı: mov al, d + call rakam_yaz. Gövdenin asıl işi prosedürde, tek kopya. İlk kopya: AL = 04h.


CALL, dönüş adresini (CALL'dan sonraki komut, 0105h) yığına iter: SP = FFFCh. IP ← rakam_yaz.


Prosedür gövdesi: AL + 30h = 34h ('4'), AH = 0Eh, INT 10h ekrana 4 yazar.


RET yığından 0105h'yi çeker: SP = FFFEh, yürütme makronun ilk kopyasından sonraki satırda sürer.


Makronun ikinci kopyası: AL = 07h. Her kopya yalnız 5 bayt (2 bayt MOV + 3 bayt CALL).


Yine CALL: bu kez dönüş adresi 010Ah. Aynı prosedür, farklı dönüş adresi.


Aynı tek prosedür kopyası çalışır: AL = 37h ('7'). Ekranda 47.


RET → 010Ah. Yığın yine boşaldı; çağıranın SP'si korunmuş oldu.


Program biter. Makro parametreyi yazmaca koydu, ortak kod prosedürde: emu8086.inc'deki DEFINE_... + makro ikilisi de böyle çalışır.



      

    

  

  
Makro: YAZ_RAKAM MACRO d / mov al, d / call rakam_yaz / ENDM. 10 kullanımda kod 10 × 5 + 7 = 57 bayt; gövdenin tamamı makroda olsaydı 10 × 8 = 80 bayt.

Etiketler ve LOCAL


Etiket İçeren Makrolar: Sorun




Gövdesinde etiket olan bir makro iki kez kullanılırsa, genişletme sonucu aynı etiket iki kez tanımlanmış olur:


BEKLE MACRO
ilk:  DEC CX
      JNZ ilk
ENDM

MOV CX, 5
BEKLE
MOV CX, 9
BEKLE


Derleyicinin gördüğü:


MOV CX, 5
ilk:  DEC CX    ; 1. kopya
      JNZ ilk
MOV CX, 9
ilk:  DEC CX    ; 2. kopya !
      JNZ ilk


emu8086: Duplicate declaration hatası. Hangi ilk:'e atlanacağı belirsizdir.

Etiketler ve LOCAL · Kodu adım adım çalıştır


MyMacro2'yi Çalıştırmak (AX = 2)






Etiketler LOCAL ile benzersiz adlara dönüştürülmüş hâli.


AX = 2.


CMP AX, 2: 2 − 2 = 0 → ZF = 1.


JE: ZF = 1 olduğundan ??0000'a (label1) atlanır.


INC AX → AX = 3.


ADD AX, 2 → AX = 5.


Program biter.




ORG 100h
MOV  AX, 2       ; MyMacro2 öncesi
CMP  AX, 2       ; MyMacro2 başlar
JE   ??0000
CMP  AX, 3
JE   ??0001
??0000:
INC  AX
??0001:
ADD  AX, 2       ; MyMacro2 biter
RET




AX = 3 olsaydı label2'ye atlar, AX = 5 olur. AX = 7 → hiçbir atlama yok, label1'e düşer: INC + ADD → AX = 10.






  
Etiketler ve LOCAL · Kodu adım adım çalıştır

  
LOCAL ile İki Kopya, İki Ayrı Etiket

  


org 100h
mov cx, 3
??0000: dec cx   ; BEKLE (1. kopya)
jnz ??0000
mov cx, 2
??0001: dec cx   ; BEKLE (2. kopya)
jnz ??0001
ret

    




Makroda LOCAL ilk var. Derleyici her açılımda ilk yerine yeni bir ad koydu: 1. kopyada ??0000 (0103h), 2. kopyada ??0001 (0109h). CX = 3.


1. tur: DEC CX → CX = 2, ZF = 0; JNZ ??0000'a (0103h) döner.


2. tur: CX = 1, ZF = 0 → yine 0103h.


3. tur: CX = 0 → ZF = 1; JNZ atlamaz, 1. kopya bitti.


CX = 2: makronun ikinci kullanımı için sayaç.


2. kopya: DEC CX → CX = 1; JNZ ??0001'e (0109h) döner, 1. kopyanın etiketine değil.


CX = 0, ZF = 1: döngü biter. Aynı etiket adı iki kez tanımlanmadığı için Duplicate declaration hatası yok.


RET: program biter. Toplam 3 + 2 = 5 DEC çalıştı.



      

    

  

  
Makro: BEKLE MACRO / LOCAL ilk / ilk: DEC CX / JNZ ilk / ENDM; ana programda mov cx, 3 / BEKLE / mov cx, 2 / BEKLE.






  
Etiketler ve LOCAL · Kodu adım adım çalıştır

  
Kod İzleme: BUYUK p, q, r ile İki Açılım

  


org 100h
mov ax, x      ; BUYUK x, y, m1
cmp ax, y
jge ??0000
mov ax, y
??0000: mov m1, ax
mov ax, y      ; BUYUK y, 4, m2
cmp ax, 4
jge ??0001
mov ax, 4
??0001: mov m2, ax
ret
x  dw 7
y  dw -3
m1 dw ?
m2 dw ?

    




1. açılım BUYUK x, y, m1: AX = x = 7.


CMP AX, y: 7 − (−3) = 10 → SF = 0, OF = 0.


JGE işaretli karşılaştırır: SF = OF → ??0000 etiketine atlanır. LOCAL bu kopyadaki ok etiketini ??0000 yaptı.


m1 = 7.


2. açılım BUYUK y, 4, m2: AX = y = −3 (FFFDh); CMP AX, 4: −3 − 4 = −7 → SF = 1, OF = 0.


SF ≠ OF: JGE ??0001 atlamaz. İkinci kopyanın etiketi ??0001; birincisiyle çakışmadı.


Büyük olan ikinci parametre: AX = 4.


m2 = 4; RET. JAE kullanılsaydı −3 (FFFDh) işaretsiz 65533 sayılır ve m2 = −3 olurdu.



      

    

  

  
Makro: BUYUK MACRO p, q, r / LOCAL ok / MOV AX, p / CMP AX, q / JGE ok / MOV AX, q / ok: MOV r, AX / ENDM. Birinci çağrıda parametreler değişken, ikincide biri sabit.






PUTC Makrosu


PUTC: Ekrana Karakter Yazdırma




; karakter yazar, imleci ilerletir
PUTC  MACRO  char
      push  ax
      mov   al, char
      mov   ah, 0eh
      int   10h
      pop   ax
ENDM

ORG  100h
START:
      PUTC  'A'
      PUTC  'B'
      RET


    

  • Makro, char parametresindeki karakteri yazar ve imleci bir sağa ilerletir.
    • 

  • INT 10h, AH = 0Eh: BIOS teletype çıkışı. AL'deki karakter imleç konumuna yazılır; 0Dh, 0Ah, 07h, 08h gibi kontrol karakterleri yorumlanır.
    • 

  • push ax / pop ax: makro AX'i kullandığı için çağıranın AX değerini korur. Makronun “görünmez” yan etkisi kalmaz.
    • 

  • Bu makro emu8086.inc kütüphanesindeki PUTC makrosunun aynısıdır.
    • 



PUTC 'B''den sonraki RET programı bitirir; o olmasa işlemci program sonundaki rastgele baytları çalıştırmaya devam ederdi.

POWER Makrosu


Üs Alma: POWER Makrosu




POWER macro b, e, r
    mov ax, 1        ; geçici sonuç = 1
    mov cx, e        ; üs → CX
    mov bx, b        ; taban → BX
powerloop:
    mul bx           ; DX:AX = AX * BX
    loop powerloop   ; e kez tekrarla
    mov r, ax        ; sonucu yaz
endm


ORG 100h
start:
    POWER base, exponent, result
    ret
base     dw 2     ; taban
exponent dw 3     ; üs
result   dw ?     ; sonuç


    

  • Sonuç r = be: AX'i 1 ile başlatıp e kez taban ile çarpar.
    • 

  • MUL BX: DX:AX ← AX × BX (işaretsiz). DX de değişir!
    • 

  • LOOP: CX'i 1 azaltır, CX ≠ 0 ise etikete atlar.
    • 









POWER Makrosu · Kodu adım adım çalıştır


POWER 2, 3 Adım Adım






Veriler kodun hemen arkasında: base = 0113h, exponent = 0115h, result = 0117h (kod 19 bayt).


AX = 1 (geçici sonuç).


CX ← [0115h] = 3 (üs).


BX ← [0113h] = 2 (taban).


1. tur: DX:AX = 1 × 2 = 0002h.


LOOP: CX = 2 ≠ 0 → powerloop.


2. tur: AX = 2 × 2 = 0004h.


LOOP: CX = 1 → powerloop.


3. tur: AX = 4 × 2 = 0008h.


LOOP: CX = 0 → döngüden çık.


result ← AX: [0117h] = 0008h = 23.


RET: program biter.




ORG 100h
mov ax, 1        ; POWER açılımı
mov cx, exponent
mov bx, base
powerloop:
mul bx
loop powerloop
mov result, ax
ret
base     dw 2    ; 0113h
exponent dw 3    ; 0115h
result   dw ?    ; 0117h




MUL sonrası DX = 0 olduğundan CF = OF = 0. Sonuç 16 biti aşsaydı (ör. 216) DX ≠ 0 ve CF = 1 olurdu; makro yalnızca AX'i sakladığı için sonuç yanlış olurdu.






POWER Makrosu


POWER Makrosunun Tuzakları






1. Üs = 0CX = 0 iken LOOP önce CX'i azaltır: FFFFh → döngü 65 536 kez döner; b0 = 1 olmalıydı. Çözüm: JCXZ.


2. Etiketpowerloop LOCAL değil: ikinci kullanımda Duplicate declaration.


3. Yazmaç bozulmasıAX, BX, CX ve (MUL yüzünden) DX değişir.


4. TaşmaSonuç 65 535'i aşarsa yüksek kısım DX'te kalır ve yazılmaz.




Düzeltilmiş sürüm:


POWER MACRO b, e, r
      LOCAL p_loop, p_end
      PUSH BX
      PUSH CX
      PUSH DX
      MOV  AX, 1
      MOV  CX, e
      MOV  BX, b
      JCXZ p_end   ; e = 0 → 1
p_loop: MUL BX
      LOOP p_loop
p_end: MOV r, AX
      POP  DX
      POP  CX
      POP  BX
ENDM

Düzeltilmiş POWER 7, 2 Adım Adım

  


org 100h
push bx          ; POWER açılımı
push cx
push dx
mov  ax, 1
mov  cx, us
mov  bx, taban
jcxz ??0001      ; us = 0 → 1
??0000: mul bx
loop ??0000
??0001: mov sonuc, ax
pop  dx
pop  cx
pop  bx
ret
taban dw 7
us    dw 2
sonuc dw ?

    




Çağıranın yazmaçları BX = 0AAAh, CX = 0BBBh, DX = 0CCCh. Düzeltilmiş makro önce üçünü de yığına saklar: SP = FFF8h.


AX = 1, CX ← us = 2, BX ← taban = 7. Yazmaçlar artık makronun.


JCXZ: CX = 2 ≠ 0, atlama yok. us = 0 olsaydı doğrudan ??0001'e gidilir, sonuç 1 olurdu (LOOP'un 65 536 tur tuzağı yok).


1. MUL: DX:AX = 1 × 7 = 0007h. MUL, DX'i de yazar (DX = 0).


LOOP: CX = 1 ≠ 0 → ??0000.


2. MUL: DX:AX = 7 × 7 = 0031h = 49.


LOOP: CX = 0 → döngüden çık.


sonuc ← AX: [011Fh] = 0031h = 7². Etiketler LOCAL ile ??0000 / ??0001 adını aldı.


Üç POP, PUSH'ların tersi sırada: DX = 0CCCh, CX = 0BBBh, BX = 0AAAh geri geldi; SP = FFFEh. Makro yalnız AX'i değiştirdi.


RET: program biter.



      

    

  

  
Kod, düzeltilmiş makronun POWER taban, us, sonuc açılımıdır; LOCAL adları derleyicinin ürettiği biçimde gösterildi.

Makro Kütüphaneleri · Kodu adım adım çalıştır

  
emu8086.inc: PRINT 'OK' Açılımı

  


org 100h
push ax          ; PRINT 'OK'
push si
jmp  ??0003      ; veriyi atla
??0001 db 'OK', 0
??0003: lea si, ??0001
??0000: mov al, cs:[si]
cmp  al, 0
jz   ??0002
inc  si
mov  ah, 0Eh
int  10h
jmp  ??0000
??0002: pop si
pop  ax
ret

    




PRINT 'OK' açıldı. Makro AX ve SI'yı kullanacağı için önce ikisini yığına saklar.


Dizgi, makronun içinde kodun arasına gömülü (0104h: 'O', 'K', 0). JMP, işlemcinin bu baytları komut sanmaması için üzerinden atlar.


SI ← dizginin adresi 0104h. LOCAL adları (??0000…) her PRINT için yenidir.


AL ← CS:[SI] = 4Fh ('O'). Dizgi kod kesiminde olduğu için CS: öneki kullanılır. 0 değil → devam.


SI bir ilerler, INT 10h/0Eh ekrana O yazar, JMP döngü başına döner.


AL = 4Bh ('K'); sonlandırıcı değil.


Ekranda OK.


AL = 00h: CMP → ZF = 1, JZ çıkışa atlar.


SI ve AX yığından geri alınır: makro çağıranın yazmaçlarını bozmadı.


RET: program biter. Tek satırlık PRINT 'OK', 27 baytlık kod + veri üretti.

Kod İzleme: REPT ile Üretilen Kare Tablosu

  


org 100h
lea  bx, kare
mov  al, 5
xlat           ; AL = kare[5]
mov  dl, al
mov  al, 7
xlat           ; AL = kare[7]
add  al, dl
ret
kare db 0, 1, 4, 9, 16, 25, 36, 49

    




Tablo REPT ile derlemede üretildi; bellekte yalnızca 8 bayt var. LEA BX, kare: BX = 010Fh.


AL = 5: karesi aranan sayı, aynı zamanda tablo indisi.


XLAT: AL ← [BX + AL] = kare+5 = 25 (19h). Çarpma yapılmadı, tablodan okundu.


DL = 19h: ilk sonuç saklanır.


AL = 7, XLAT → kare+7 = 49 (31h).


ADD AL, DL: 49 + 25 = 74 (4Ah) = 5² + 7².


RET. XLAT 11 saat turudur; 8086'da 8 bitlik MUL ise 70–77 tur sürer.



      

    

  

  
Tablonun kaynağı: n = 0 / kare LABEL BYTE / REPT 8 / DB n*n / n = n + 1 / ENDM. Kod bu bloğun açılmış hâliyle çalıştırıldı. EQU sabiti değiştirilemez; = ile tanımlanan sembol her turda yeni değer alır.

İleri Makro Özellikleri · Kodu adım adım çalıştır

  
Kod İzleme: KAYDIR AX ve KAYDIR BX, 3

  


org 100h
mov ax, 5
mov bx, 3
shl ax, 1      ; KAYDIR AX
mov cl, 3      ; KAYDIR BX, 3
shl bx, cl
ret

    




AX = 5, BX = 3: kaydırılacak değerler.


KAYDIR AX: n boş, IFB dalı seçildi → tek komut SHL AX, 1. AX = 000Ah (5 × 2).


KAYDIR BX, 3: n = 3, ELSE dalı → MOV CL, 3. 8086'da 1'den büyük kaydırma sayısı CL'de verilir.


SHL BX, CL: 3 × 2³ = 0018h (24). Aynı makro iki farklı uzunlukta kod üretti: 2 bayt ve 4 bayt.


RET. KAYDIR AX açılımı CL'ye dokunmadı; yalnız ikinci açılım CL'yi değiştirdi.



      

    

  

  
Kod, KAYDIR makrosunun iki çağrısının açılmış hâlidir. Hangi dalın yazılacağına derleyici karar verdi; çalışma anında karşılaştırma yapılmadı.

Makroda Hata Ayıklama ve Listeleme




Açılımı görmekemu8086'nın öykünücü penceresindeki komut listesi, makro adlarını değil açılmış komutları gösterir; tek adım çalıştırma da bu komutlar üzerinde ilerler.


Liste dosyasıMASM'da .LISTMACROALL açılımın bütün satırlarını, .LISTMACRO yalnız kod üretenleri listeler, .NOLISTMACRO açılımı gizler.


Hata satırıGövdedeki bir hata, makronun kullanıldığı her satırda ayrı ayrı bildirilir. Aynı hata birkaç kez görülüyorsa neden çoğunlukla gövdededir.


Önce elle açmakYeni bir makro, gövdesi önce düz kod olarak yazılıp denenerek geliştirilir; çalıştıktan sonra parametreli makroya dönüştürülür.




Makro etiketleri LOCAL ile ??0000 gibi adlar aldığı için öykünücüdeki atlama hedefleri kaynaktaki adlarla görünmez; hangi kopyanın çalıştığını bu numaralar gösterir.
