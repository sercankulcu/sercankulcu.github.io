Variables

Variables

  • A variable stands for a memory location.
  • For a programmer the name var1 is far easier to use than the address 5A73:235B.
  • The assembler supports two basic types:
    • BYTE (8 bits): name DB value (Define Byte)
    • WORD (16 bits): name DW value (Define Word)
  • There is also DD (Define Doubleword, 32 bits): 4 bytes.
counter DB 10h     ; BYTE
sum     DW 0FFFFh  ; WORD

Variables

Names and Initial Values

  • A variable name must start with a letter; letters and digits may follow.
  • Register and instruction names (AX, MOV…) cannot be variable names.
  • A variable may have no name: it still has an address.
  • It can hold any numeric value (binary, decimal, hex, character).
  • Use ? for a variable with no initial value (emu8086 stores 00).

Variables · Step through the code

Code Trace: Is FFh 255 or −1?

ORG 100h
MOV AL, x        ; FFh
ADD AL, 1        ; 255 + 1 ?
MOV AL, x
CBW              ; signed: −1
MOV BX, y        ; FFFEh
NEG BX           ; −(−2)
RET
x DB -1
y DW -2

In memory x = FFh, y = FE FF (FFFEh, little-endian). AL = x = FFh: 255 unsigned, −1 signed.

ADD AL, 1: unsigned, 255 + 1 = 256 does not fit in a byte → AL = 00h, CF = 1. Signed, −1 + 1 = 0 is correct: OF = 0.

AL is FFh again.

CBW treats AL as signed: MSB = 1 → AH = FFh, AX = FFFFh = −1 (16 bits).

BX = y = FFFEh: 65534 unsigned, −2 signed.

NEG BX: 0 − (−2) = 0002h. The instruction chose the meaning: ADD/CF read the pattern as unsigned, CBW/NEG as signed.

DB/DW store only the bit pattern; the instruction that uses the value decides whether it is signed or unsigned.

Variables

Variable Type and Size Checking

  • The assembler keeps a type with every variable name: DB → BYTE (1), DW → WORD (2), DD → DWORD (4).
  • If the other operand is a register, the sizes must match; otherwise assembly stops.
  • With an immediate, the variable’s type sets the size: MOV w, 5 writes a word.
  • Operands like [BX] have no type; with an immediate they need BYTE PTR or WORD PTR.
  • BYTE PTR changes the type for that instruction only; the definition stays the same.
Instruction (w DW 1234h, b DB 5)Result
MOV AL, werror: 1 byte / 2 bytes
MOV AL, BYTE PTR wAL = 34h (low byte)
MOV AL, BYTE PTR w+1AL = 12h (high byte)
MOV w, 5w = 0005h (word)
MOV AX, berror: 2 bytes / 1 byte
MOV [BX], 5error: size unknown
MOV b, werror: memory to memory
INC bb = 6 (byte increment)
Type checking happens at assembly time and catches many easy-to-miss errors. The processor knows no types at run time; it reads or writes the size the instruction encodes.

Variables · Step through the code

Code Trace: Two Names for the Same Memory (LABEL)

ORG 100h
MOV AX, wval       ; WORD
MOV BL, bytes      ; low
MOV BH, bytes+1    ; high
MOV bytes, 0FFh    ; one byte
MOV CX, wval       ; word
RET
wval LABEL WORD
bytes DB 34h, 12h

wval LABEL WORD reserves nothing; it only gives address 0115h a second name of type WORD. MOV AX, wval reads both bytes: AX = 1234h.

bytes is the BYTE-typed name of the same address: BL = 34h. No PTR needed.

bytes+1 is the second byte: BH = 12h. BX = 1234h, thanks to little-endian order.

The type is BYTE, so MOV bytes, 0FFh writes only address 0115h: memory is FF 12.

Read through the WORD name, the change shows: CX = 12FFh. Two names, one memory location.

RET. LABEL produced no bytes; the program grew only by the two-byte definition.

name LABEL type gives the next byte a new name and type. To process a buffer both byte by byte and word by word, it reads better than writing PTR everywhere.

Memory Layout

Example Code

ORG 100h
MOV AL, var1   ; AL ← var1
MOV BX, var2   ; BX ← var2
RET            ; end program
VAR1 DB 7      ; BYTE, 7
var2 DW 1234h  ; WORD, 1234h
  • Code first, variables after RET: the CPU never reaches them.
  • The assembler turns the source into a sequence of bytes and replaces variable names with memory locations.
  • It is case-insensitive: VAR1 and var1 are the same variable.

Memory Layout · Step through the code

Code Trace: var1 and var2

The program is loaded at 0B56:0100; DS = CS = 0B56h, IP = 0100h.

MOV AL, [0108h]: the value of VAR1 → AL = 07h. IP = 0103h.

MOV BX, [0109h]: 34h is the low byte, 12h the high byte → BX = 1234h. IP = 0107h.

RET (C3 at 0107h) pops 0000h: IP = 0000h, and the INT 20h in the PSP ends the program. Everything from 0108h on is data.

MOV BX, var2   ; BX ← var2
RET            ; end program

var2 DW 1234h  ; WORD, 1234h

Memory Layout

What Does the Assembler Do?

  • It turns the source into a sequence of bytes and replaces variable names with offsets: MOV AL, var1 → MOV AL, [0108h].
  • When a .COM file is loaded, DS gets the value of CS (so do ES and SS).
  • An offset is the distance from the start of the segment.
  • VAR1 is at offset 0108h; its full address is 0B56:0108.
  • var2 is at offset 0109h; its full address is 0B56:0109.
    • As a WORD it takes 2 bytes (0109h and 010Ah).
    • The low byte sits at the low address: 34h comes before 12h (little-endian).
The segment value (0B56h) depends on where DOS loads the program and may differ on every run; the offsets are fixed at assembly time.

Memory Layout

The ORG 100h Directive

  • Tells the assembler the address where the program will be loaded; it is used when names are replaced with addresses.
  • Used for .COM files; most examples in this course use the emu8086 .COM template.
  • The operating system keeps data about the program in the first 256 bytes of the segment (the PSP); the command-line arguments live there.
  • .EXE files load at offset 0000h and use a separate segment for variables.
  • Directives are not translated into machine code.

Memory Layout

Alignment: Where Does a Word Start?

a  DB 5          ; 0200h
   EVEN          ; 0201h: pad
w  DW 1234h      ; 0202h (even)
  • The 8086 data bus is 16 bits: a word at an even address is read in one bus cycle.
  • A word at an odd address needs two cycles; the 8086 copes by itself, just slower (4 clocks per access).
  • MASM/TASM's EVEN rounds the location counter up to even, adding a pad byte if needed. Definitions are only shifted, not reordered.
  • On the 8088 (8-bit bus) every word takes two cycles anyway; alignment doesn't matter there.
Example: MOV AX, w takes 10 clocks on the 8086, 14 if w is odd-addressed. Read 1000 times in a loop: 4000 clocks, 0.8 ms at 5 MHz. Bytes need no alignment.

Arrays

Arrays

  • Think of an array as a chain of variables: a group of values stored in consecutive memory locations.
  • Quoted text is converted automatically into a byte array (ASCII codes).
  • Elements are reached through memory addresses: the first element is at the array’s address, the rest follow.
a DB 48h, 65h, 6Ch, 6Ch, 6Fh, 00h
b DB 'Hello', 0

a and b hold the same bytes: 48h 'H', 65h 'e', 6Ch 'l', 6Ch 'l', 6Fh 'o', 00h (end of string).

Arrays · Step through the code

Code Trace: Accessing Array Elements

a[3] means a + 3 bytes: AL = 6Ch ('l').

Index register SI = 0.

a[SI] = [a + SI]: BL = 48h ('H').

SI = 1: the next byte.

BH = a[1] = 65h ('e'). BX = 6548h.

The array is of type byte, so the size is known: a[1] ← 45h ('E'). The array now reads “HEllo”.

RET. The array definition sits after the code, where nothing is executed.

ORG 100h
MOV AL, a[3]   ; a + 3
MOV SI, 0
MOV BL, a[SI]  ; a + 0
INC SI
MOV BH, a[SI]  ; a + 1
MOV a[SI], 'E' ; a[1] ← 45h
RET
a DB 48h,65h,6Ch,6Ch,6Fh,0

Arrays

Access Patterns and DUP

Reaching an element
  • A constant index in brackets: MOV AL, a[3]
  • Through the memory index registers (BX, SI, DI, BP): MOV SI, 3 · MOV AL, a[SI]
  • Equivalent forms: a[SI] = [a + SI] = [SI + a]
  • The index counts bytes, not elements.
The DUP operator For large arrays: count DUP(value(s))
  • c DB 5 DUP(9) = c DB 9, 9, 9, 9, 9
  • d DB 5 DUP(1, 2) = d DB 1, 2, 1, 2, 1, 2, 1, 2, 1, 2
  • buffer DB 100 DUP(?): 100 uninitialized bytes
  • table DW 10 DUP(0): 10 words = 20 bytes
DW can define arrays of numbers (w DW 1000h, 2000h); what it cannot define is text strings (DW 'Hello' is invalid). Values above 255 or below −128 need DW.

Arrays · Step through the code

Code Trace: Indexing a DW Array

w[0]: the first word → AX = 1111h.

The second element is at w[2] (each element is 2 bytes): BX = 2222h.

The index of element i = 2 × i: for the third element, SI = 4.

CX = w[SI] = 3333h.

w[1] reads from the middle of an element: bytes 11h, 22h → DX = 2211h. A common mistake!

ORG 100h
MOV AX, w[0]   ; element 1
MOV BX, w[2]   ; element 2
MOV SI, 4
MOV CX, w[SI]  ; element 3
MOV DX, w[1]   ; careful!
RET
w DW 1111h, 2222h, 3333h

Arrays

From Definition to Bytes

Type a DB / DW / DD line to see its bytes. Numbers (decimal, h, b, o), 'text' (DB only), ? and n DUP(…) are supported. Above each cell: the byte offset from the start of the variable.

Strings and Terminators

s1 DB 'Welcome', 0             ; zero-terminated
s2 DB 'Welcome$'               ; '$'-terminated (INT 21h / AH = 09h)
s3 DB 13, 10, 'Line', 13, 10, '$'  ; CR LF: carriage return + line feed
s4 DB 7, 'Welcome'             ; length-prefixed: first byte = 7
s5 DB "Ali's", 0               ; single quote inside double quotes
FormatHow is the end found?Where is it used?
zero-terminatedwhen the byte read is 0emu8086.inc PRINT_STRING, the C language
'$'-terminatedwhen the byte read is 24hthe DOS print-string service
length-prefixedas many bytes as the first byte saysthe DOS buffered-input buffer (AH = 0Ah)
  • Space taken in memory = number of characters + terminator: 8 bytes for s1. Forget the terminator and printing runs on, treating the bytes after the string as characters.
  • A '$'-terminated string cannot print '$' itself. Codes for Turkish letters (ç, ğ, ş…) depend on the code page in use; they are not in ASCII’s 0–127 range.

Arrays

Character Constants and ASCII Arithmetic

CharactersASCII codes
'0' … '9'30h … 39h
'A' … 'Z'41h … 5Ah
'a' … 'z'61h … 7Ah
space · '$'20h · 24h
CR · LF0Dh · 0Ah
  • To the assembler a quoted character is just a number: MOV AL, 'A' = MOV AL, 41h.
  • Digit character to number: SUB AL, '0' ('7' = 37h → 7). The other way: ADD AL, '0'.
  • Upper and lower case differ by 20h, i.e. only bit 5: SUB AL, 20h or AND AL, 0DFh converts to upper case, OR AL, 20h to lower case.
AND AL, 0DFh is only correct for letters. Applied to '1' (31h) it gives 11h and ruins the digit, so first check that AL is a letter ('a' ≤ AL ≤ 'z').

Arrays · Step through the code

Code Trace: Converting a String to Upper Case

ORG 100h
LEA SI, s
again:
MOV AL, [SI]
CMP AL, 0          ; terminator?
JE done
CMP AL, 'a'
JB next
CMP AL, 'z'
JA next
SUB AL, 20h        ; 'a' - 'A'
MOV [SI], AL
next:
INC SI
JMP again
done:
RET
s DB 'Ab1c', 0

LEA SI, s: SI = 0119h, the first byte of the string 'Ab1c' with terminator 0.

'A' (41h): not 0; CMP AL, 'a' → 41h < 61h, JB jumps. Already upper case, so nothing is written; SI moves on.

'b' (62h): 'a' ≤ 62h ≤ 'z' → SUB AL, 20h = 42h ('B'), and MOV [SI], AL writes it back.

'1' (31h): below 'a', skipped. Without the letter check, 31h − 20h = 11h would have ruined the digit.

'c' (63h) → 43h ('C'). The string is now 'AB1C'.

The byte read is 0: CMP AL, 0 → ZF = 1, JE done. The loop stopped at the terminator without knowing the length.

The string was changed in place: each byte is read and, if it is a letter, written back to the same address minus 20h. A terminator (0) took the place of a length.

Arrays

Two-Dimensional Arrays (Tables)

mat DB 3 DUP(4 DUP(0)) ; 3 × 4
tab DW 3 DUP(4 DUP(0)) ; 24 bytes
  • Memory is one-dimensional; a table is laid out in row-major order: all columns of row 0, then row 1…
  • Offset = (row × number of columns + column) × element size.
  • In a word table, [1][2] is at (1 × 4 + 2) × 2 = 12 bytes.
  • Nested DUP reserves rows and columns together: 3 times (4 times 0).
If the number of columns is a power of 2, a shift replaces the multiply: two SHLs for row × 4. The number of rows does not affect the layout; it only bounds the row index.

Arrays · Step through the code

Code Trace: Reading mat[2][1]

NCOLS EQU 4
ORG 100h
MOV AL, row        ; AL = 2
MOV BL, NCOLS      ; BL = 4
MUL BL             ; AX = 2 × 4
ADD AL, col        ; + 1
MOV SI, AX         ; SI = 9
MOV DL, mat[SI]    ; mat[2][1]
RET
mat DB 11h, 12h, 13h, 14h
    DB 21h, 22h, 23h, 24h
    DB 31h, 32h, 33h, 34h
row DB 2
col DB 1

AL ← row = 2. Target: mat[2][1]. The table is at 0112h, 3 rows × 4 columns of bytes.

NCOLS EQU 4 is built into the instruction: BL = 04h (number of columns).

MUL BL: AX = AL × BL = 2 × 4 = 0008h. Row 2 starts at byte 8 of the table.

ADD AL, col: 8 + 1 = 9. AH is already 0, so AX = 0009h.

The offset goes into an index register: SI = 0009h. AL cannot be an index; only BX, SI, DI, BP can address memory.

mat[SI] = [0112h + 9]: DL = 32h. Row 2, column 1.

RET. The constant is named NCOLS on purpose: COL EQU 4 would be the same name as col DB 1, since the assembler ignores case, and give a “duplicate definition” error.

Row and column were read from variables at run time; the same code works for every element. In a word table the result would also be multiplied by 2.

Addresses

Getting a Variable’s Address

LEA (Load Effective Address)Loads the address (offset) of a variable into a register: LEA BX, VAR1. It also works for indexed variables: LEA BX, a[SI].
OFFSETAn assembler operator; it supplies the variable’s offset value at assembly time: MOV BX, OFFSET VAR1.
A variable’s address is very handy for passing parameters to a procedure: instead of a large array, the procedure gets just its 16-bit address.
InstructionWhat goes into BX?
MOV BX, VAR1 (VAR1 DW)the value of VAR1 (its contents)
LEA BX, VAR1 · MOV BX, OFFSET VAR1the address of VAR1 (its offset)

Addresses · Step through the code

Code Trace: Updating a Variable Through LEA

The code starts at 0100h; the assembler placed VAR1 at 010Dh (12 bytes of code + RET).

AL = the value of VAR1 = 22h.

BX = the address of VAR1 = 010Dh. BX is now a pointer to VAR1.

VAR1 is updated through [BX]: [010Dh] = 44h.

VAR1 is read again: AL = 44h. A variable can be reached by its name or through a pointer.

RET. END is the directive that marks the end of the source file.

ORG 100h
MOV AL, VAR1          ; value
LEA BX, VAR1          ; address
MOV BYTE PTR [BX], 44h
MOV AL, VAR1          ; new value
RET
VAR1 DB 22h
END

Addresses

Are LEA and OFFSET the Same?

The same program with OFFSET

ORG 100h
MOV AL, VAR1
MOV BX, OFFSET VAR1
MOV BYTE PTR [BX], 44h
MOV AL, VAR1
RET
VAR1 DB 22h
END
  • In emu8086, LEA BX, VAR1 and MOV BX, OFFSET VAR1 assemble to the same machine code: BB 0D 01 (3 bytes, MOV BX, 010Dh). VAR1 = 010Dh in both programs.
  • A real 8086 assembler such as MASM encodes LEA as its own instruction: 8D 1E 0D 01 (4 bytes).
  • The difference: LEA BX, a[SI] computes the address at run time (a + SI); OFFSET gives only a constant address.
  • Only BX, SI, DI, BP may appear inside square brackets.

Addresses · Step through the code

Code Trace: LEA a[BX] vs. OFFSET a

ORG 100h
MOV BX, 2
LEA SI, a[BX]      ; SI = a + BX
MOV DI, OFFSET a   ; fixed address
ADD DI, BX         ; add by hand
MOV AL, [SI]
INC BX
LEA SI, a[BX]      ; new address
MOV AH, [SI]
RET
a DB 'ABCD'

BX = 2: the index. The array a starts at 0116h: 'A' 'B' 'C' 'D'.

LEA SI, a[BX]: the address is computed at run time: 0116h + 2 = 0118h. Memory is not read.

OFFSET a is a constant known at assembly time: DI = 0116h. It cannot include BX.

With OFFSET the same address needs an extra ADD: DI = 0118h = SI.

AL = [SI] = 43h ('C').

BX = 3.

LEA recomputes with the current BX: SI = 0119h.

AH = [SI] = 44h ('D'). AX = 4443h.

LEA computes the address from registers at run time; OFFSET gives only a constant address known at assembly time.

Pointer Variables

ORG 100h
MOV BX, p          ; 010Bh
LEA SI, p          ; 010Fh
MOV DI, OFFSET arr
RET
arr   DB 'KAYA'    ; 010Bh
p     DW arr       ; 010Fh, holds 010Bh
far_p DD arr       ; offset + segment
  • If the value of a DW is a variable name, the address of that variable is stored: p is a pointer variable.
  • The pointer lives in memory, so it can change: ADD p, 2 moves it further into the array.
  • To use it, first load it into an address register: MOV BX, p · MOV AL, [BX].
  • A far pointer defined with DD holds offset and segment together; LDS SI, far_p or LES DI, far_p loads it in one instruction.

MOV BX, pthe address stored in p (the array’s address)010Bh

Addresses · Step through the code

Code Trace: A Pointer in Memory

ORG 100h
MOV BX, p          ; contents of p
MOV AL, [BX]       ; arr[0]
ADD p, 2           ; advance
MOV BX, p
MOV AH, [BX]       ; arr[2]
RET
arr  DB 'KAYA'
p    DW arr        ; address

MOV BX, p reads the contents of p. Since p = DW arr, BX = 0112h, the array’s address.

MOV AL, [BX]: the byte the pointer points to: AL = 4Bh ('K').

ADD p, 2: the pointer in memory now points to 0114h. BX is unchanged; it still holds the old address.

The pointer is reloaded: BX = 0114h.

MOV AH, [BX]: AH = 59h ('Y'). AX = 594Bh.

RET. The array’s address never appears in the code; the pointer in memory decided which element was read.

A pointer variable keeps an address in memory; with so few registers it is how you track where many arrays are. Load it into BX, SI or DI before each use.

Constants

Constants (EQU)

  • Like variables, but they exist only at assembly time; they take no memory.
  • Once defined, a constant’s value cannot change.
  • They let different parts of a program use the same value, updated in one place.
  • Definition: name EQU <any expression>
  • The assembler replaces the name with its value at every use: MOV AX, k → MOV AX, 5 (B8 05 00).
k      EQU 5
ROWLEN EQU 80

MOV AX, k         ; AX = 5
MOV BX, ROWLEN*2  ; BX = 160
MOV CL, k+1       ; CL = 6
k EQU 5k DB 5
Memorynone1 byte
MOV AL, kAL ← 5 (immediate)AL ← [k] (from memory)
Can it change?noyes: MOV k, 7

Constants · Step through the code

Code Trace: EQU Is Built into the Instruction

k      EQU 5
ROWLEN EQU 80
ORG 100h
MOV AX, k         ; MOV AX, 5
MOV BX, ROWLEN*2  ; MOV BX, 160
MOV CL, k+1       ; MOV CL, 6
MOV DL, v         ; from memory
RET
v DB 5            ; takes 1 byte

k EQU 5: the assembler records k = 5 in its symbol table. No memory is reserved and no machine code is produced.

ROWLEN = 80 also exists only at assembly time. The program starts at 0100h; its first byte is the code of MOV AX, k.

MOV AX, k → MOV AX, 5 (B8 05 00): 5 is inside the instruction, an immediate. AX = 0005h.

ROWLEN*2 was computed at assembly time: 160 = 00A0h → BX = 00A0h.

k+1 = 6 → CL = 06h. No addition happens at run time.

v is a variable: the instruction carries its address (010Dh) and the value is read from memory: DL = 05h. v takes 1 byte; k takes none.

Machine codes follow the MASM/emu8086 encoding: B8 iw (MOV AX, imm), BB iw (MOV BX, imm), B1 ib (MOV CL, imm), 8A 16 addr (MOV DL, [addr]).

Constants

The Location Counter ($) and Size Operators

  • The assembler keeps the offset where the next byte will go in a counter: the location counter. In source code it is read as $.
  • Right after an array, $ − arr is the array’s size in bytes. If the array grows or shrinks, the constant stays correct by itself.
  • The EQU line must come immediately after the array; any definition in between is counted too.
  • MASM’s TYPE, LENGTHOF and SIZEOF operators read the same information from the variable’s definition.
s DB 'Welcome', 0
n EQU $ - s        ; 8
w DW 10 DUP(0)
ExpressionValueMeaning
n8size of s in bytes
TYPE s1element size (DB)
LENGTHOF s8number of elements
TYPE w2element size (DW)
LENGTHOF w10number of elements
SIZEOF w20LENGTHOF × TYPE
All of these are assembly-time constants: MOV CX, LENGTHOF w builds 10 into the instruction and takes no memory. For a word array, take the loop count from LENGTHOF and the byte length from SIZEOF.

Constants · Step through the code

Code Trace: Size with $, Maximum with a Loop

ORG 100h
JMP start
arr DB 12, 47, 5, 31
n EQU $ - arr      ; 4
big DB ?
start:
MOV CX, n          ; CX = 4
MOV SI, 0
MOV AL, arr[SI]    ; first guess
check:
CMP AL, arr[SI]
JAE skip           ; AL >= element
MOV AL, arr[SI]    ; new guess
skip:
INC SI
LOOP check
MOV big, AL
RET

JMP start skips the data. n EQU $ − arr = 4 was computed at assembly time: CX = 0004h. The first element is the first guess: AL = 12.

Pass 1: 12 is compared with 12; JAE jumps (equal). SI = 1, LOOP: CX = 3.

Pass 2: 12 < 47 → CF = 1, JAE does not jump; AL = 47 (2Fh). SI = 2, CX = 2.

Pass 3: 47 ≥ 5 → skipped, AL unchanged. SI = 3, CX = 1.

Pass 4: 47 ≥ 31 → skipped. LOOP: CX = 0, the loop ends.

MOV big, AL: the largest element, 2Fh = 47, is stored; RET.

The loop count is not hard-coded; add an element and n changes by itself. JAE compares unsigned; use JGE for signed arrays.

Example Programs · Step through the code

Code Trace: Moving Data Between Variables

jmp start makes the CPU jump over the data; otherwise the data bytes would be executed as instructions.

value1 → AX = 000Ah. There is no direct memory-to-memory MOV, so a register sits in between.

AX → value2: 0A 00 in memory. Now value1 = value2 = 10.

end start: the end of the source; start is the program’s entry point.

ORG 100h
jmp start
value1 DW 10    ; a 2-byte variable

Code Trace: Adding Variables

Start: result is defined with ?; emu8086 stores 00 00, but do not rely on that value.

AX = value1 = 0105h.

ADD can take a memory operand directly: 0105h + 0103h = 0208h. Flags: CF = 0, ZF = 0, PF = 0 (08h has a single 1 bit).

result ← AX: 08 02 in memory (little-endian).

Result: result = 0208h = 520 (261 + 259).

ORG 100h
jmp start
value1 DW 105h  ; initially 105h
value2 DW 103h  ; initially 103h
result DW ?     ; undefined
start:
MOV AX, value1  ; AX ← value1
ADD AX, value2  ; AX ← AX + value2
MOV result, AX  ; result ← AX
RET
end start

Notes on Comparison

CMPCMP a, b computes a − b and discards the result; only the flags (CF, ZF, SF, OF, PF, AF) are updated.
Signed / unsignedJGE, JG, JL: signed (SF, OF). JAE, JA, JB: unsigned (CF). With value1 = −1 (FFFFh) and value2 = 5, JGE does not jump but JAE does.
Why RET?The data definitions come right after the code; without RET the CPU would execute the bytes 0A 00 05 00… as instructions. Fix: RET (or a jmp start at the top).
ImprovementThe MOV AX, value1 under greater_or_equal is redundant; AX already holds value1. The jump can go straight to store_max.

Doubleword Variables

org 100h
jmp start
mydouble dd 12345678h  ; double word
mywords  dw 5678h      ; 2 separate words
         dw 1234h
mybytes  db 78h        ; 4 separate bytes
         db 56h
         db 34h
         db 12h
data dd 00010010001101000101011001111000b
start:  ; load data into DX:AX
mov ax, word ptr data
mov dx, word ptr [data+2]
ret

All four definitions produce the same bytes in memory:

  • DD is 32 bits = 4 bytes; the lowest byte is at the lowest address.
  • The 8086 has no 32-bit register: the value is held in the pair DX:AX (DX the high word, AX the low word).

Code Trace: A 32-Bit Load into DX:AX

The first two bytes of data (78 56) → AX = 5678h. word ptr states the size explicitly, since data is a DD.

The two bytes at data+2 (34 12) → DX = 1234h. DX:AX = 1234:5678h = 12345678h.

mov ax, word ptr data      ; data+0
mov dx, word ptr [data+2]  ; data+2
ret
data dd 12345678h

Common Mistakes with Variables

Confusing value and addressMOV SI, arr loads the first word; for the address use LEA SI, arr.
Memory-to-memory movesThere is no MOV v1, v2; the value goes through a register.
Indexing a word arrayElement 3 is at w[4]: the index counts bytes.
Trusting ?total DW ? may not be zero; start with MOV total, 0.
Forgetting the suffixDW 10 is decimal 10 (000Ah); for hex write 10h.
Name clashesCOL EQU 4 and col DB 1 are the same name: “duplicate definition”.
Data in the path of the codeWithout RET or JMP, data bytes are taken for instructions.
Forgetting the terminatorWithout 0 or '$', printing runs on into the bytes that follow.

Exercises

  1. If x DB 5, 6 · y DW 0ABCDh · z DB 'OK' start at 0200h, give the address and value of every byte.
  2. How many bytes does table DW 10 DUP(?) take? What is the offset of the 7th element (index 6)?
  3. For y above, what is AL after MOV AL, BYTE PTR y and after MOV AL, BYTE PTR y+1?
  4. What is the difference between LEA SI, a[BX] and MOV SI, OFFSET a?
  5. Write code that stores the sum of two DW variables in a third and sets ovf DB 1 if the sum overflows (CF = 1).
  6. Which pair of instructions adds 1 to dd 0FFFFFFFFh held in DX:AX?
Answers
  1. 0200: 05, 0201: 06, 0202: CD, 0203: AB, 0204: 4F ('O'), 0205: 4B ('K').
  2. 20 bytes; offset 6 × 2 = 12 = 0Ch.
  3. CDh and ABh.
  4. LEA computes a + BX at run time; OFFSET is only the constant address of a.
  5. MOV AX,v1 · ADD AX,v2 · MOV v3,AX · JNC done · MOV ovf,1 · done:
  6. ADD AX,1 · ADC DX,0 (carries into the high word).
