The FLAGS Register

Arithmetic and Logic Instructions

  • The results of arithmetic and logic instructions affect the CPU's status flags.
  • The flags live in the 16-bit FLAGS register; each bit is a flag that is either 0 or 1.
  • The 8086 uses 9 of these 16 bits: 6 status flags (describe the result) and 3 control flags (steer the CPU's behavior).
  • Conditional jumps (JZ, JC, JO …) make their decisions from these flags.

Dashed bits are unused on the 8086.

The FLAGS Register

CF or OF?

The CPU adds bits and nothing more; the interpretation is the programmer's. CF says whether the result is right as unsigned, OF whether it is right as signed.

AL + operandunsigned viewsigned viewALCFOF

OF rule: if two numbers of the same sign add up to a result of the other sign, OF = 1. Adding two numbers of different signs never sets OF.

Code Trace: CF, OF and the Other Flags

AL = 9Ch: unsigned 156, signed −100. The flags start at 0; MOV does not change them.

156 + 112 = 268 > 255 → AL = 0Ch, CF = 1. Signed −100 + 112 = 12 is correct → OF = 0. 0Ch has two 1s → PF = 1.

AL = 50h (80). The flags stay from the previous ADD.

80 + 80 = 160 is correct unsigned (CF = 0), but two positives gave a negative sum (A0h = −96) → OF = 1, SF = 1.

A0h + A0h: unsigned 320 (CF = 1), signed −96 + (−96) = −192 (OF = 1). AL = 40h: both views are wrong.

AL = FFh. CF = 1 is still there.

INC AL: FFh + 1 = 00h → ZF = 1, AF = 1; but INC leaves CF alone: CF = 1 is left over from the previous addition.

CMC complements CF: CF = 0. The other flags do not change.

MOV  AL, 50h     ; 80

The FLAGS Register

Flags After ADD, Step by Step

MOV AL, 64h (100) and ADD AL, 32h (50). Bits are added from right to left.

The result is 96h = 1001 0110b. Unsigned it is 150 (right); signed it is −106 (wrong!).

CF: did a carry come out of the leftmost bit? No → CF = 0 (150 ≤ 255).

OF: two positive numbers gave a negative sum (the carries into and out of bit 7 differ) → OF = 1.

SF = bit 7 of the result = 1. The result is not zero: ZF = 0.

PF: 1001 0110b has four 1s → even → PF = 1. AF: the low nibbles give 4 + 2 = 6, no carry → AF = 0.

Result: AL = 96h; CF = 0, ZF = 0, SF = 1, OF = 1, PF = 1, AF = 0.

Group 1: Two Operands

Rules and Affected Flags

  • After a two-operand instruction the result is always stored in the first operand (dest).
  • CMP and TEST only affect the flags; they store no result.
  • ADD/SUB: adds the second operand to / subtracts it from the first.
  • CMP: subtracts the second operand from the first without storing the result.
  • AND/OR/XOR: operate on corresponding bits of the two operands; TEST is like AND but only affects the flags.
InstructionCFZFSFOFPFAF
ADD, SUB, CMP✓✓✓✓✓✓
AND, OR, XOR, TEST0✓✓0✓?

✓: set by the result · 0: always cleared · ?: undefined. Logic instructions always clear CF and OF.

Group 1: Two Operands · Step through the code

Code Trace: ADD, SUB, CMP

AL = F0h. MOV does not change the flags (all 0 at the start).

F0h + 20h = 110h; 10h fits in 8 bits, the 1 that falls out → CF = 1. Signed: −16 + 32 = 16 is correct → OF = 0.

BL = 7. The flags stay from the previous ADD.

7 − 9 = −2 = FEh. A borrow occurred → CF = 1; MSB = 1 → SF = 1. 7 − 9 borrows in the low nibble → AF = 1.

CMP AL, 10h: 10h − 10h = 0 → ZF = 1. AL is unchanged: that is how equality is tested.

FEh − 0: ZF = 0, SF = 1, CF = 0. Unsigned FEh > 0, signed −2 < 0.

FEh + 2 = 100h → BL = 00h, CF = 1, ZF = 1. Signed: −2 + 2 = 0 is correct → OF = 0.

mov al, 0F0h     ; 240
add al, 20h      ; 240 + 32 = 272
mov bl, 7
sub bl, 9        ; 7 - 9
cmp al, 10h      ; AL - 10h
cmp bl, 0
add bl, 2        ; FEh + 2

Group 1: Two Operands · Step through the code

32-Bit Addition with ADC

The first 32-bit number is loaded into DX:AX: low word FFFFh…

…high word 0001h → DX:AX = 0001FFFFh (131071).

The second number is CX:BX = 00020001h (131073).

FFFFh + 0001h = 10000h → AX = 0000h, CF = 1: a carry for the high word.

ADC = ADD + CF: 0001h + 0002h + 1 = 0004h. Result DX:AX = 00040000h (262144) ✓

; DX:AX = 0001FFFFh, CX:BX = 00020001h
mov ax, 0FFFFh
mov dx, 0001h
mov bx, 0001h
mov cx, 0002h
add ax, bx      ; low words
adc dx, cx      ; high + CF

SBB (subtract with borrow) does multi-word subtraction the same way: SUB first, then SBB.

Group 1: Two Operands · Step through the code

32-Bit Subtraction with SBB

The first number is DX:AX = 00040000h (262144): high word in DX, low word in AX.

The subtrahend is CX:BX = 00010001h (65537).

0000h − 0001h: the low word is too small, so a borrow occurs → AX = FFFFh, CF = 1.

SBB = SUB − CF: 0004h − 0001h − 1 = 0002h. Result DX:AX = 0002FFFFh (196607) ✓

; DX:AX = 00040000h, CX:BX = 00010001h
mov ax, 0000h
mov dx, 0004h
mov bx, 0001h
mov cx, 0001h
sub ax, bx      ; low words
sbb dx, cx      ; high - CF

Rule: SUB on the lowest word, SBB on every word after it. Instructions in between must not disturb CF (MOV, INC, LOOP preserve it).

Logic Operations

Masking: AND, OR, XOR, TEST

AND clears bits: bit 5, which is 0 in the mask, is cleared and the rest are kept → lowercase becomes uppercase.

OR sets bits: bit 5, which is 1 in the mask, becomes 1 → uppercase becomes lowercase.

XOR flips bits: bit 5, which is 1 in the mask, changes → the letter switches case.

TEST tests bits: the result 01h ≠ 0 → ZF = 0, so bit 0 = 1 and the number is odd. BL is unchanged.

Logic Operations · Step through the code

Code Trace: AND, OR, XOR, TEST

AL = 'a' = 61h = 0110 0001b.

61h AND DFh = 41h = 'A'. 41h has two 1s → PF = 1. CF = OF = 0.

41h OR 20h = 61h = 'a'. Three 1s → PF = 0.

61h XOR 20h = 41h = 'A' (bit 5 flipped).

BL = '7' = 37h (an ASCII digit).

37h AND 0Fh = 07h: now the number 7.

07h AND 01h = 01h ≠ 0 → ZF = 0: the number is odd. BL is unchanged.

XOR with itself → 00h, ZF = 1, PF = 1 (zero 1s, even).

mov al, 'a'      ; 61h
and al, 0DFh     ; uppercase
or  al, 20h      ; lowercase
xor al, 20h      ; flip case
mov bl, '7'      ; 37h
and bl, 0Fh      ; number 7
test bl, 1       ; odd?
xor bl, bl       ; BL = 0

Group 2: Multiply and Divide

DIV and IDIV

InstructionByte operandWord operand
DIV (unsigned)AL = AX / operand
AH = remainder (modulus)		AX = (DX AX) / operand
DX = remainder (modulus)
IDIV (signed)AL = AX / operand

Flags

MUL / IMUL set only CF and OF meaningfully: if the result exceeds the operand size (the upper half is needed), CF = OF = 1. The rest are undefined.

After DIV / IDIV all flags are undefined.

Divide error

If the divisor is 0, or the quotient does not fit in its destination (AL / AX), the CPU raises INT 0 (divide error).

IDIV truncates the quotient toward zero; the remainder has the sign of the dividend.

Group 2: Multiply and Divide

Multiply and Divide Step by Step

MOV AL, 200, MOV BL, 3. 200 = C8h, which is −56 signed.

MUL BL: 200 × 3 = 600 = 0258h → AX. The result did not fit in AL (AH ≠ 0) → CF = OF = 1.

Same bits with IMUL BL: −56 × 3 = −168 = FF58h. A different result! −168 does not fit in a byte → CF = OF = 1.

AL = FEh (−2), BL = 5: IMUL BL → −10 = FFF6h. AH is just the sign extension of AL → CF = OF = 0: the result fit in AL.

DIV BL: AX = 23, BL = 5 → quotient AL = 4, remainder AH = 3. New AX = 0304h.

IDIV BL: −23 / 5 → quotient AL = FCh (−4), remainder AH = FDh (−3). Check: −4 × 5 + (−3) = −23.

AX = 1000h (4096), DIV BL (2): the quotient 2048 does not fit in AL → divide error, INT 0. A word division (DX:AX / BX) was needed.

DX:AX = FFFFFFFFh, DIV BX (BX = 1): the divisor is not zero, but the quotient FFFFFFFFh does not fit in AX → INT 0 again. Rule: in word division, if DX ≥ divisor the quotient cannot fit (in byte division, AH ≥ divisor).

Group 2: Multiply and Divide

Preparing to Divide: CBW, CWD

  • Division needs a dividend twice as wide as the operand: AX for byte division, DX:AX for word division.
  • Before unsigned division, clear the upper half: MOV AH, 0 or XOR DX, DX.
  • Before signed division, sign-extend: CBW (AL → AX), CWD (AX → DX:AX).
  • Forgetting DX is a classic bug: an old value left in DX enlarges the dividend and can cause a divide error.
; unsigned: 1000 / 7
mov ax, 1000
xor dx, dx      ; DX:AX = 1000
mov bx, 7
div bx          ; AX = 142, DX = 6

; signed: -1000 / 7
mov ax, -1000
cwd             ; DX = FFFFh
idiv bx         ; AX = -142, DX = -6

Code Trace: DIV, CWD and IDIV

AX = 2000 = 07D0h. In word division the dividend is DX:AX; what DX holds matters too.

XOR DX, DX: the upper half is zero for unsigned division → DX:AX = 2000.

Divisor BX = 9.

DIV BX: 2000 / 9 → AX = 222 (00DEh), DX = 2. The flags are undefined.

AX = −2000 = F830h. DX still holds the previous remainder (2): DX:AX is now a wrong dividend.

CWD: the sign bit of AX is 1 → DX = FFFFh. DX:AX = FFFFF830h, −2000 in 32 bits.

IDIV BX: −2000 / 9 → AX = FF22h (−222), DX = FFFEh (−2). The remainder has the sign of the dividend.

AX = 2000, but DX = FFFEh was not cleared: DX:AX = FFFE07D0h, about 4.29 billion.

DIV BX: the quotient does not fit in 16 bits (DX ≥ divisor) → the CPU raises INT 0 and the program stops. Fix: XOR DX, DX before dividing.

MOV  AX, 2000
XOR  DX, DX      ; DX:AX = 2000
MOV  BX, 9
DIV  BX          ; unsigned div
MOV  AX, -2000
CWD              ; sign-extend
IDIV BX          ; signed div
MOV  AX, 2000    ; DX not cleared!
DIV  BX
RET

Signed Numbers · Step through the code

Signed Overflow: JO and CBW

AL = BL = A4h: −92 (256 − 92 = 164 = A4h).

A4h + A4h = 148h → AL = 48h = +72. Two negatives gave a positive sum → OF = 1 (CF = 1 too, but it does not matter in the signed view).

OF = 1, so JO jumps to the widen label. The true result −184 is outside −128 … 127.

AL = A4h, CBW: MSB = 1 → AH = FFh, AX = FFA4h (−92 in 16 bits).

The first number is saved in DX; the second (BL) is moved into AL and extended too: AX = FFA4h.

FFA4h + FFA4h = 1FF48h → AX = FF48h = −184 ✓. The result fits in 16 bits: OF = 0.

mov al, -92      ; A4h
mov bl, -92
add al, bl       ; 8-bit add
jo  widen        ; if OF = 1
jmp done
widen:
mov al, -92      ; first number
cbw              ; AL -> AX
mov dx, ax
mov al, bl       ; second number
cbw
add ax, dx       ; 16-bit add
done:
ret

JO (jump if overflow) jumps if OF = 1, JNO if OF = 0. If a signed byte sum can overflow, first widen the operands to words with CBW.

Signed Byte Sum with CBW

SI points to the start of the array, CX = 4 elements, BX = 0 (sum cleared).

AL = 64h (+100). MSB = 0 → CBW AH = 00h, AX = 0064h.

BX = BX + AX = 0064h (100).

AL = E2h (−30). MSB = 1 → CBW AH = FFh, AX = FFE2h.

BX = BX + AX = 0046h (70).

AL = 5Ah (+90). MSB = 0 → CBW AH = 00h, AX = 005Ah.

BX = 00A0h (160). Adding bytes, 70 + 90 = 160 > 127 → AL = A0h (−96), OF = 1.

AL = F9h (−7). MSB = 1 → CBW AH = FFh, AX = FFF9h.

BX = BX + AX = 0099h (153).

The loop is done; total = 0099h = 153 ✓ is written to memory. With MOV AH, 0 instead of CBW, −30 = E2h would be added as 226.

SI = arr, CX = 3 words. The (32-bit) total in memory is 0000:0000.

AX = 7530h (30000). Positive → CWD gives DX = 0000h.

Low word: 0000h + 7530h = 7530h, CF = 0.

High word: 0000h + 0000h + CF(0) = 0000h. Total 00007530h.

The high word stays 0000h: total 0000D6D8h = 55000.

Group 2: Multiply and Divide · Step by step

32 × 32-Bit Multiplication: Partial Products

The 8086 multiplies at most 16 × 16 bits. 32-bit numbers are split into words: A × B = A1·B1·232 + (A1·B0 + A0·B1)·216 + A0·B0. Four MULs; the results are added by word position with ADD/ADC; the result is 64 bits.

A = 9ABCDEF0h and B = EDCBFEDCh are split into 16-bit halves: A = A1:A0, B = B1:B0.

A0 × B0 is not shifted: it lands in the two lowest words of the result (z1:z0).

A1 × B0 and A0 × B1 are both multiplied by 216: they go into columns z2:z1.

A1 × B1 is multiplied by 232: it goes into columns z3:z2.

Column sums: z1 = 257D1h → write 57D1h, carry 2; z2 = 22835h → write 2835h, carry 2. Each ADD gives at most one carry: hence the ADC chain in the code.

Result: 8FBC 2835 57D1 B640h. Check (decimal): 2596069104 × 3989569244 = 10357197452617037376 ✓

32 × 32-Bit Multiplication: Code Trace

AX = A0 = DEF0h, MUL [y]: A0 × B0 = DEF0h × FEDCh = DDF1:B640h (DX:AX). DX ≠ 0, so MUL sets CF = 1.

The first partial product is written to words z0 (bits 0–15) and z1 (bits 16–31).

A1 × B0 = 9ABCh × FEDCh = 9A0B:8190h. Shifted 16 bits left: it is added into z1 and z2.

z1 + AX = DDF1h + 8190h → z1 = 5F81h, CF = 1.

z2 = 0 + DX + CF = 9A0Ch. z2 was 0 before, so no new carry arises here.

A0 × B1 = DEF0h × EDCBh = CF14:F850h. This too is added at the z1–z2 position.

z1 = 5F81h + F850h → 57D1h, CF = 1.

z2 = 9A0Ch + CF14h + CF → 6921h, CF = 1: the carry must go into z3!

ADC [z+6], 0: carries only the carry → z3 = 0001h.

A1 × B1 = 9ABCh × EDCBh = 8FBA:BF14h, shifted 32 bits left: z2–z3.

z2 = 6921h + BF14h → 2835h, CF = 1.

z3 = 0001h + 8FBAh + CF = 8FBCh. Result z3:z2:z1:z0 = 8FBC 2835 57D1 B640h ✓

Group 3: One Operand

INC, DEC, NOT, NEG

  • Operands: REG (AX, BX, … SP) or memory ([BX], [BX+SI+7], a variable). No immediates.
  • INC and DEC affect only ZF, SF, OF, PF, AF; they leave CF alone.
  • NOT affects no flags at all! It inverts every bit of the operand (one's complement).
  • NEG affects CF, ZF, SF, OF, PF, AF. It negates the operand (two's complement): invert every bit, then add 1. E.g. 5 → −5, −2 → 2.

Group 3: One Operand

NEG: Two's Complement Step by Step

x = 5 = 0000 0101b.

NOT: every bit is inverted → 1111 1010b = FAh (−6). One's complement.

+1: FBh = 1111 1011b = −5. NEG does both steps in one instruction; CF = 1 (x ≠ 0).

x = FEh (−2): NOT → 01h, +1 → 02h. The negative of a negative is positive.

Special case: x = 80h (−128). NOT → 7Fh, +1 → 80h: +128 does not fit in a byte → OF = 1.

x = 0: the result is 0, CF = 0 (the only case where NEG leaves CF = 0), ZF = 1.

Group 3: One Operand · Step through the code

Code Trace: INC, DEC, NOT, NEG

AL = FFh (255 / −1).

FFh + 1 = 00h, ZF = 1. ADD would have set CF = 1; INC leaves CF alone → CF stays 0.

00h − 1 = FFh, SF = 1. There was a borrow, but CF still did not change.

BL = 7Fh = +127, the largest positive byte.

7Fh + 1 = 80h = −128: signed overflow → OF = 1, SF = 1.

NOT: 80h → 7Fh. The flags did not change at all (SF still shows 1).

NEG: −127 = 81h. CF = 1 (operand ≠ 0), SF = 1, OF = 0.

mov al, 0FFh
inc al          ; FFh + 1
dec al          ; 00h - 1
mov bl, 7Fh     ; +127

not bl

Shift and Rotate

Shifts: SHL/SAL, SHR, SAR

Shift countOn the 8086 only 1 or CL: shl ax, 1, shr al, cl. An immediate count such as shl al, 4 is valid from the 80186 on. OF is defined only when the count is 1.
SAR and IDIV round differently: −7 (F9h) sar 1 → FCh = −4; idiv 2 → −3.

Shift and Rotate

Rotates: ROL, ROR, RCL, RCR

No bit is lost in a rotate. Only CF and (when the count is 1) OF change; SF, ZF, PF are not affected. RCL/RCR are used for multi-word shifts: shl ax, 1 + rcl dx, 1 → DX:AX × 2.

Fast Multiplication and Division by Shifting

; AX ← AX × 3 = AX×2 + AX
mov bx, ax     ; save
shl ax, 1      ; AX × 2
add ax, bx     ; ×2 + ×1

; unsigned ÷ 8 and remainder
mov dx, ax
and dx, 0007h  ; rem = low 3 bits
mov cl, 3
shr ax, cl     ; quotient

; signed ÷ 4
mov cl, 2
sar ax, cl     ; −7 → −2
  • On the 8086 mul takes 70–133 and div 80–162 clocks; a shl reg, 1 takes just 2.
  • Multiplying/dividing by powers of 2 becomes a shift; other constants become shifts plus additions.
  • Remainder of division by 2n: the low n bits, via and.
  • Signed division uses SAR; for a negative dividend SAR rounds toward −∞ while IDIV rounds toward zero: for −7, SAR 2 → −2, IDIV 4 → −1.
Example: AX = 25 → BX = 25, AX = 50 → 50 + 25 = 75.

37 × 10 and 370 ÷ 16 by Shifting

org 100h

shl ax, 1      ; AX × 2
mov bx, ax     ; save
shl ax, 1      ; AX × 4
shl ax, 1      ; AX × 8
add ax, bx     ; ×8 + ×2

AX = 37 = 0025h = 0000 0000 0010 0101b.

SHL AX, 1: bits move one place left, 0 enters from the right → AX = 74 (004Ah). 2 clocks; MUL takes more than 70.

BX = 74: ×2 is saved.

SHL → AX = 148 (×4).

SHL → AX = 296 (×8).

ADD AX, BX: 296 + 74 = 370 = 0172h = 37 × 10.

BX = 370: a copy for the division.

AND BX, 000Fh: low 4 bits = 370 mod 16 = 2.

CL = 4: on the 8086 a shift count above 1 goes in CL.

SHR AX, CL: 4 bits right = ÷ 16 → AX = 23 (0017h). 23 × 16 + 2 = 370.

RET: the program ends.

org 100h

BCD Arithmetic

Binary Coded Decimal (BCD)

  • BCD (Binary Coded Decimal): each decimal digit is kept in its own 4-bit group (0000–1001).
  • Unpacked BCD: one digit per byte. Packed BCD: two digits per byte.
  • The CPU adds in binary; special instructions adjust the result to BCD.
RepresentationThe number 14Byte(s)

Packed BCD0001 0100b14h

BCD Arithmetic

BCD Adjust Instructions

InstructionWhen?Effect
AAAafter unpacked additionadjust AL to BCD, carry into AH
AASafter unpacked subtractionadjust AL, borrow from AH
AAMafter unpacked multiplicationAH = AL / 10, AL = AL mod 10
AADbefore unpacked divisionAL = AH × 10 + AL, AH = 0

The adjust instructions work only on AL (and AH), so BCD addition/subtraction is done byte by byte. Example: 83h − 38h = 4Bh → DAS → 45h (83 − 38 = 45).

BCD Arithmetic · Step through the code

Code Trace: 9 + 5 with AAA

AH = 09h: the first digit, 9.

AL = 05h: the second digit, 5. AX = 0905h.

09h + 05h = 0Eh (14): correct in binary but not BCD (E > 9). No nibble carry → AF = 0.

AH = 0: the tens digit is cleared. AX = 000Eh.

AAA: the low nibble of AL is E > 9 → AL + 6 = 14h, AH + 1, AF = CF = 1; the high nibble of AL is cleared → AX = 0104h → “14”.

30h is added to each digit: AX = 3134h = '1','4'.

BL = '4' is saved, AL = '1'.

AH = 0Eh (teletype).

'1' is printed.

AL = '4'.

'4' is printed. The screen shows 14.

RET.

mov     al, 05h

AAM and AAD

AAM · after multiplication
mov al, 7
mov bl, 8
mul bl      ; AX = 0038h (56)
aam         ; AH = 05h, AL = 06h

Divides AL by 10: quotient to AH, remainder to AL. 56 → “5”, “6”.

AAD · before division
mov ax, 0504h  ; '54' unpacked
aad            ; AX = 0036h (54)
mov bl, 6
div bl         ; AL = 09h, AH = 00h

AL = AH × 10 + AL, AH = 0: the two digits become a binary number, then a normal DIV.

For packed BCD use DAA: MOV AL,38h / ADD AL,45h → AL = 7Dh, DAA → AL = 83h (38 + 45 = 83).

BCD Arithmetic · Step through the code

Code Trace: AAM, AAD and DAA

Two single-digit numbers: AL = 6, BL = 9.

MUL BL: AX = 6 × 9 = 54 = 0036h. A binary result; to print it, split it into digits.

AAM: AL / 10 → AH = 5 (quotient), AL = 4 (remainder). AX = 0504h: unpacked “54”.

AX = 0702h: unpacked BCD “72” (AH = 7, AL = 2).

AAD: AL = 7 × 10 + 2 = 72 = 48h, AH = 0. Converted to binary before the division.

DIV BL: 72 / 8 → AL = 9, AH = 0 (remainder). Without AAD, 0702h = 1794 would be divided.

AL = 19h: packed BCD “19” (two digits in one byte).

19h + 28h = 41h: a binary addition. 9 + 8 = 17 overflowed the low nibble → AF = 1; 41h is wrong as BCD.

DAA: AF = 1 → AL + 06h = 47h. The result is “47” = 19 + 28 ✓

Example: Temperature Conversion · Step through the code

Code Trace: °C → °F

CL = 15 (°C) = 0Fh.

AL = 9.

IMUL CL: AX = 9 × 15 = 135 = 0087h. 135 does not fit in a signed byte (>127) → CF = OF = 1; but the full result is in AX.

CL = 5 (the divisor).

IDIV CL: AX / 5 = 135 / 5 → AL = 1Bh (27), AH = 0 (remainder). The flags are undefined.

27 + 32 = 59 = 3Bh → AX = 003Bh. 15 °C = 59 °F ✓

RET. Final state in emu8086: AX = 003Bh, CX = 0005h.

f = c × 9 / 5 + 32. Multiply first, then divide: in integer division 9/5 would be 1 and the result would be wrong.

Example: Temperature Conversion

Why IMUL / IDIV? Limits

Negative temperatures

c = −10: IMUL → AX = FFA6h (−90), IDIV → AL = EEh (−18), +32 → 0Eh = 14 °F ✓

With MUL/DIV, F6h would be taken as 246 and the result would be meaningless.

Integer division

IDIV drops the fraction (toward zero): c = 1 → 9/5 = 1 → 33 °F (really 33.8). The remainder (AH) can be checked for rounding.

Valid range for °C → °F

The result is in the signed byte AL: c ∈ [−71, 53]. At c = 54, AL = 81h (OF = 1, wrong); at c = 72 the quotient does not fit in AL → divide error.

Valid range for °F → °C

f − 32 must fit in a byte: f ∈ [−96, 127]. For a wider range use word operations (AX, CWD, IDIV BX).

Summary

Summary

Flags

CF unsigned, OF signed overflow; ZF zero; SF the MSB; PF an even number of 1s in the low byte; AF the nibble carry.

Group 1

Result in the first operand; CMP/TEST flags only. Logic instructions set CF = OF = 0.

Group 2

Implicit AL/AX/DX. Byte: AX = AL × op, AL = AX / op (AH remainder). Word: DX:AX.

Group 3

INC/DEC preserve CF; NOT changes no flags; NEG is two's complement.

Shifts and rotates

Count 1 or CL. SHL ×2, SHR unsigned ÷2, SAR signed ÷2 (rounds toward −∞); rotates lose no bits, RCL/RCR form a 9 (17)-bit ring with CF.

BCD

AAA/AAS after addition/subtraction, AAM after multiplication, AAD before division.

Pitfalls

Prepare AH/DX before dividing; use IMUL/IDIV for signed data; check range overflows with the flags.

Exercises

  1. What are AL, CF, OF, SF, ZF, PF after MOV AL, 0C0h / ADD AL, 0C0h?
  2. After CMP AL, BL, which flag tells unsigned “AL < BL”, and which flags tell signed “AL < BL”?
  3. With AX = 0FFFFh and BX = 0FFFFh, what are DX, AX, CF after MUL BX?
  4. What happens on DIV BL with AX = 0100h and BL = 0?
  5. Change the array addition program for word (DW) arrays.
  6. Write a program that counts the 1 bits in a byte using SHL/TEST and a loop. Compare with PF.
Hints / answers
  1. C0h + C0h = 180h → AL = 80h; CF = 1, OF = 0 (−64 + −64 = −128 fits), SF = 1, ZF = 0, PF = 0 (a single 1 bit).
  2. Unsigned: CF = 1. Signed: SF ≠ OF.
  3. 65535² = FFFE0001h → DX = FFFEh, AX = 0001h, CF = OF = 1.
  4. Division by zero → divide error (INT 0).
  5. vec1 dw …, mov ax,[si], add ax,[bx], mov [di],ax; the pointers advance with add si,2.
  6. CX = 8 passes; each pass tests a bit with TEST AL,80h, INCs a counter if it is 1, then SHL AL,1. PF only tells whether the number of 1s is even or odd.

Exercises (2)

  1. What happens on DIV BX with DX = 0005h, AX = 0000h, BX = 0005h?
  2. What are AL and OF after MOV AL, 70h / ADD AL, 30h? How do you get the correct sum in 16 bits?
  3. Compute 00012345h − 0000ABCDh with SUB/SBB. What is CF after SUB?
  4. In a 32 × 32-bit multiplication, which words of the result do the four partial products add into?
  5. With DX = 0000h, AX = 0FFFh, CF = 0, what is DX:AX after SHL AX, 1 and RCL DX, 1?
Hints / answers
  1. DX ≥ BX: the dividend 50000h = 327680 gives the quotient 10000h = 65536, which does not fit in AX → divide error (INT 0), even though the divisor is not zero.
  2. AL = A0h, OF = 1 (112 + 48 = 160 > 127). Widen both numbers separately with CBW and add in 16 bits: 00A0h = 160.
  3. 2345h − ABCDh = 7778h, CF = 1 (borrow); 0001h − 0000h − 1 = 0000h → 00007778h (30584).
  4. A0·B0 → z1:z0; A1·B0 and A0·B1 → z2:z1; A1·B1 → z3:z2. Carries move up a word with ADC.
  5. AX = 1FFEh, the bit shifted out is 0 → CF = 0; RCL shifts a 0 into DX → DX = 0000h. DX:AX = 00001FFEh (0FFFh × 2).
