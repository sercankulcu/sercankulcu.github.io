Summary

At a Glance

Every RPL parent switch in 6TiSCH forces a node to give up its cells and negotiate new ones. Two new objective functions widen the switching threshold for nodes that matter most: those with many neighbours (SR1) or many transmit cells (SR2).

I · Introduction

RPL Routing on Top of 6TiSCH

  • IEEE 802.15.4e TSCH gives industrial IoT reliable, bounded-latency links; 6TiSCH joins TSCH networks to IPv6.
  • RPL builds a DODAG, a tree-like graph rooted at the border router. The root starts with a DIO broadcast; nodes answer with DAO messages. DIOs are paced by the Trickle timer.
  • Each node computes a rank, its distance from the root. To avoid loops it may only choose parents with a lower rank.
  • The objective function (OF) defines how rank is computed and how the preferred parent is chosen. Standard choices: OF0 and MRHOF (minimum rank with hysteresis).
Link cost

MRHOF usually uses ETX, the expected number of transmissions per packet: good links give low rank.

Hysteresis

A candidate must beat the preferred parent by a threshold: 96 rank units (0.75 ETX) in MRHOF implementations, 192 (1.5 ETX) in RFC 6719.

III · Fig. 2 · Interactive

Why a Busy Router Should Not Switch

  • Topology after Fig. 2: green root, orange critical router. Cells (timeslot and channel) are allocated per parent and must be re-negotiated after a switch.
  • Meanwhile all packets of the subtree wait in node 4's buffer; overflow is dropped.
  • With a low, fixed threshold, similar-rank parents cause frequent switches: parent flapping.

II · Related Work

Related Work

MRHOF and OF0

RFC 6719 and RFC 6550: rank from link metrics such as ETX or hop count; RPL does not mandate a particular OF.

Link quality estimation

Better ETX estimates in 6TiSCH lead to paths with fewer transmissions (Fanucchi et al., 2019).

Dense 6TiSCH meshes

Jin et al. (2020) raised the delivery ratio, but at the cost of higher end-to-end delay and more energy.

Congestion control

Farag et al. (2020) switch parent when a queue backlog factor exceeds a threshold, using a metric of path length, link quality and queue load.

Gap: none of these studies optimizes the parent-switching threshold itself, which stays fixed for every node.

III · Proposed Mechanism · Algorithms 1–2

SR1 and SR2: A Threshold That Grows with Importance

input: parent_1, parent_2
if tx_cells == 0:
    cost(preferred) += max_link_metric
else:
    if tx_cells > 0 and neighbours > 1 and n < 6:
        threshold = n × etx_divisor
    else:
        threshold = 6 × etx_divisor
    if |cost_1 − cost_2| < threshold:
        return preferred parent
return lower-cost parent

n = neighbours (SR1) or tx_cells (SR2)
No transmit cells yet

The current parent gets a penalty of the maximum link metric, so a node without cells is free to move.

SR1: neighbour count

A node with many neighbours likely routes for others; its threshold grows to n ETX.

SR2: transmit cells

Cells mirror the traffic through the node; more cells mean a costlier switch.

Capped

The threshold stops at 6 ETX, so a switch is never made impossible.

IV · Discussion

What the Results Show

Stability first

Both functions cut parent switches sharply in lossy networks; SR1, driven by neighbour count, is the most stable.

Fewer losses during re-allocation

Each avoided switch saves releasing and re-negotiating cells, the window in which buffered packets are lost.

Lower delay

Packets wait less in intermediate buffers, especially when link quality is poor.

Good links

At Rx 90% MRHOF switches far less (≈111 times) and all three functions deliver packets with similar ratio and delay.

Trade-off: a wider threshold also reacts later when a parent really degrades. The 6 ETX cap limits, but does not remove, this delay.

V · Conclusion and Future Work

Conclusion

  • Two objective functions for RPL in 6TiSCH make the parent-switching threshold depend on live node state: neighbour count (SR1) or allocated transmit cells (SR2).
  • Nodes switch parents far less often, which raises packet delivery and lowers delay compared with MRHOF, most clearly on low-quality links.
  • Future work: tune the threshold with reinforcement learning.
