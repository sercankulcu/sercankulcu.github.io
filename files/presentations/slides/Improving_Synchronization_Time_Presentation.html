Summary

At a Glance

Steerable antennas reach farther and suffer less interference, but their narrow beam makes it hard for a new node to hear the network. A new scan packet lets nodes learn their neighbours' directions before they synchronize; beacons are then sent and heard in those directions.

I–II · Introduction and Background

Smart Antennas Help, Until a Node Has to Join

Steerable (ESPAR) antennas

  • stronger transmission in the chosen direction, longer range
  • ignore interference from unwanted directions
  • more parallel transfers on the same frequency
  • electronically steered, cheap enough for IoT nodes

The price

  • a node must know which direction to use for each neighbour
  • a narrow beam covers little: work an omni antenna does once must be repeated around the node
  • joining the network and finding neighbours takes longer
  • existing fixes for slow network formation assume omni antennas
Schedules now have three dimensions: time slot, frequency channel and antenna direction.

Minimal schedule

Until it has its own schedule, every node uses one or more shared cells for EBs, join traffic and RPL messages.

Waiting costs energy

Nodes far from the root wait for nearer neighbours to join first, with the radio always on.

Dense networks

Collisions in the shared cell slow formation even with omni antennas; a narrow beam slows it further.

III.B · Fig. 2, Algorithms 1–2

The Scan Packet

  • Synchronized nodes send Enhanced Beacons; unsynchronized nodes send the new scan packet.
  • Unsynchronized nodes keep their radio on, so they hear scan packets with high probability.
  • The receiver stores the sender's MAC ID with its own current antenna direction and RSSI: a virtual neighbour list built before synchronization.
  • After it receives an EB and synchronizes, a node stops sending scan packets and starts sending EBs.
  • In the shared cell, EBs are sent, and nodes listen, towards listed neighbours instead of random directions.
  • The radio layer must report direction and RSSI to the MAC layer, so both layers were redesigned.
Algorithm 1: neighbour discovery 
id ← extract_id(packet)
n  ← get_neighbor(id, list)
if n is null:              # new neighbour
    insert(create(id, current_dir, current_rssi))
else if current_rssi > n.rssi:
    n.dir  ← current_dir    # better direction
    n.rssi ← current_rssi
Algorithm 2: direction in the shared cell 
i ← random(list_size)
if i is 0:
    return random(2π)      # P = 1 / (neighbours + 1)
else:
    return list[i].dir     # towards a known neighbour

IV · Discussion

What Drives Synchronization Time?

Density

More nodes mean more neighbours in reach but more collisions in the shared cell. Omni antennas suffer most; narrow beams shield steerable nodes.

Direction knowledge

Random beams rarely meet. Scan packets turn guesses into aimed transmissions and receptions.

Channels

More frequency resources lengthen joining: an unsynchronized node must find the right channel as well as the right direction.

Desynchronization

A node that misses EBs for too long leaves the network and must join again, lengthening total formation time.

Dedicated autonomous cells per neighbour remove contention altogether and give short, size-independent synchronization times.

V · Conclusion

Conclusion

  • 6TiSCH was designed for omni antennas; steerable antennas slow down joining and neighbour discovery.
  • Scan packets let nodes discover neighbours before synchronization; shared-cell traffic then follows known directions, improving synchronization time by about 25% depending on density.
  • Copying control messages to autonomously allocated cells in each neighbour's direction gives a solution that does not depend on network size.
  • Future work: machine learning for more efficient use of shared cells.

V · Conclusion

Check Questions

  1. Which two phases must complete before a 6TiSCH network is fully functional?
  2. Why does a steerable antenna make joining harder than an omni antenna?
  3. What does a node store when it hears a scan packet, and why can it hear one before it is synchronized?
  4. Why does Algorithm 2 still pick a random direction with probability 1/(neighbours + 1)?
  5. Why is the omni antenna fastest at 25 nodes but slowest at 75?
Show answers
  1. Synchronization through Enhanced Beacons, then building the RPL tree with DIO messages.
  2. The beam covers only part of the surroundings; the node must also find the right direction, and random directions rarely line up.
  3. The sender's MAC ID, its own current antenna direction and the RSSI; unsynchronized nodes keep the radio on while they search.
  4. So that new nodes, not yet in the list, can still be discovered.
  5. In small networks it reaches everyone at once; in dense ones its wide coverage causes more collisions and lost packets.
