The Hashing Idea

Bringing Search Cost Down to a Constant

StructureSearchInsertDeleteNote
Unsorted arrayO(n)O(1)O(n)append at the end, scan from the front
Sorted arrayO(lg n)O(n)O(n)binary search + shifting

A hash table does not compare keys: it computes the position from the key. The price: no sorted traversal, min/max or range queries; the worst case is O(n).

The Hashing Idea

The Simplest Case First: A Direct-Address Table

typedef struct { int used; char name[16]; } rec;
rec T[10];               /* key = index     */

rec *da_search(int k) {
  return T[k].used ? &T[k] : NULL;
}
The problem

For 9-digit keys such as student numbers, |U| = 109: the table does not fit, and most of it stays empty.

The solution

A hash function that maps keys to a small range, h: U → {0, …, m−1}.

Since m < |U| (the pigeonhole principle), collisions are unavoidable. Two questions remain: how to choose a good h, and how to resolve collisions?

The Hashing Idea

Abstract Data Type: The Dictionary

typedef struct { int key; /* + value */ } item;

bool hash_insert(item x);   /* update if found */
item *hash_search(int key); /* NULL if absent  */
bool hash_delete(int key); /* false if absent */
Dictionary

A key → value mapping; each key appears at most once.

Uses

Compiler symbol tables (Horowitz's motivating example), caches, duplicate detection, set implementations.

The C standard library has no ready-made hash table (POSIX has a limited hsearch), so a C programmer must know how to write one.

Hash Functions

What Makes a Hash Function Good

Fast

O(key length) to compute; a few arithmetic operations.

Spreads evenly

Keys should spread over the m buckets as evenly as possible (the simple uniform hashing assumption).

Uses all the bits

Functions that look only at the last digits cluster on patterned data.

Deterministic

The same key always goes to the same bucket; randomness may enter only when the function is chosen.

Hash Functions

Division Method: h(k) = k mod m

k1020304050601727
k mod 1000000077
k mod 11109876565
  • m = 10: everything but the last digit is ignored; 10, 20, …, 60 land in the same bucket.
  • A good rule is to choose m as a prime not close to a power of 2 (CLRS).
  • If m = 2p, h(k) is just the lowest p bits of k: avoid it.
unsigned h_div(unsigned k, unsigned m) { return k % m; }

In C, % can give a negative result for a negative number: keep the key unsigned or use ((k % m) + m) % m.

Hash Functions

Multiplication Method: h(k) = ⌊m · (k·A mod 1)⌋

  • A is a constant with 0 < A < 1; the fractional part of k·A is multiplied by m.
  • The choice of m is not critical; m = 2p is fine.
  • Knuth suggests A ≈ (√5 − 1)/2 = 0.6180339887…
  • Example (CLRS): k = 123456, p = 14 (m = 16384) → h(k) = 67.
/* w = 32 bit, m = 2^p; s = A * 2^32 */
uint32_t h_mul(uint32_t k, int p) {
  const uint32_t s = 2654435769u;
  return (uint32_t)(k * s) >> (32 - p);
}
In the integer version the product k·s overflows modulo 232; the overflow is discarded (same as taking the fractional part). The top p bits of the remaining 32 bits are h(k). The floating-point version gives the same result: ⌊16384 · 0.…⌋ = 67. (Needs <stdint.h>.)

Hash Functions

Folding and Mid-Square Methods

The key x = 12320324111220 is split into three-digit parts that are added up (Horowitz's example):

Shift folding

The parts are added as they are: 699.

Folding at the boundaries

Every other part is reversed (like folding paper): 897.

Mid-square

Compute k² and take the middle r bits: m = 2r. The middle bits depend on all the bits of k.

If the result exceeds the table size, also take mod m.

Hash Functions

String Keys: Polynomial (Horner) Hashing

unsigned str_hash(const char *s, unsigned m) {
  unsigned h = 0;
  for (; *s != '\0'; s++)
    h = (h * 31 + (unsigned char)*s) % m;
  return h;
}
unsigned long djb2(const char *s) {  /* Bernstein */
  unsigned long h = 5381;
  int c;
  while ((c = (unsigned char)*s++) != 0)
    h = h * 33 + c;
  return h;       /* then: h % m */
}
Summing is bad

Adding character codes sends anagrams such as "abc" and "cba" to the same bucket.

Polynomial

h = c₀·31n−1 + … + cn−1: one multiplication per character with Horner's rule. Position information enters the hash.

Overflow

Taking % m at each step keeps values small; unsigned overflow is well defined in C (mod 2w).

  for (; *s != '\0'; s++)
    h = (h * 31 + (unsigned char)*s) % m;
  return h;
}

Check: the full polynomial is 3287903, and 3287903 mod 11 = 3; taking the mod at each step does not change the result.

Open Addressing

Collisions: Two Basic Remedies

The birthday paradox

In a class of 23, the chance that two people share a birthday is ≈ 50.7%. 23 keys in m = 365 slots: collisions come surprisingly early.

Open addressing

All items live inside the table; α ≤ 1. An empty slot is found by following a probe sequence.

Chaining

Each bucket heads a linked list; α > 1 is possible. Insertion is O(1).

Open Addressing

Linear Probing: h(k, i) = (h(k) + i) mod m

Insert 22, 1, 13, 11, 24, 33 in order. Home addresses: 0, 1, 2, 0, 2, 0.

22 → home 0: slot 0.

1 → home 1: slot 1.

13 → home 2: slot 2.

11: slot 0 is full (22) → try the next slot.

11: slot 1 is full (1) → try the next slot.

11: slot 2 is full (13) → try the next slot.

11 → home 0, probe sequence 0, 1, 2, 3: slot 3.

24: slot 2 is full (13) → try the next slot.

24: slot 3 is full (11) → try the next slot.

24 → home 2, probe sequence 2, 3, 4: slot 4.

33: slot 0 is full (22) → try the next slot.

33: slot 1 is full (1) → try the next slot.

33: slot 2 is full (13) → try the next slot.

33: slot 3 is full (11) → try the next slot.

Primary clustering: occupied slots form a contiguous block, and every new key that lands in it makes it bigger. 33 needed 6 probes.

Open Addressing

Open Addressing in C: Slot State and Insertion

#define M 11
typedef enum { EMPTY, USED, DELETED } state_t;
typedef struct {
  int key;          /* assumes key >= 0 */
  state_t state;
} slot;
slot table[M];          /* global: all 0 = EMPTY */
Initial state

A global array starts zeroed; since EMPTY = 0, every slot is empty.

Insertion

Start at the home address and write into the first slot that is not USED; at most m probes.

A slot is in one of three states: EMPTY (never used), USED, DELETED (tombstone). Insertion may reuse a DELETED slot, but it must first check with search that the key is not already in the table.

int insert(int k) {
  int i = k % M;                 /* home addr */
  for (int d = 0; d < M; d++, i = (i + 1) % M) {
    if (table[i].state != USED) { /* free slot */
      table[i].key = k;
      table[i].state = USED;
      return i;
    }
  }
  return -1;                     /* table full */
}

int search(int k) {
  int i = k % M;
  for (int d = 0; d < M; d++, i = (i + 1) % M) {
    if (table[i].state == EMPTY) return -1;
    if (table[i].state == USED &&
        table[i].key == k) return i;
  }
  return -1;
}
bool erase(int k) {
  int i = search(k);
  if (i < 0) return false;
  table[i].state = DELETED;   /* tombstone */
  return true;
}

Quadratic Probing: h(k, i) = (h(k) + I²) mod m

Same keys: 22, 1, 13, 11, 24, 33. Probes jump 1, 4, 9, 16… away from the home address.

22 → home 0: slot 0.

1 → home 1: slot 1.

13 → home 2: slot 2.

11: slot 0 is full (22) → try the next slot.

11: slot 1 is full (1) → try the next slot.

11 → home 0, probe sequence 0, 1, 4: slot 4.

24: slot 2 is full (13) → try the next slot.

24 → home 2, probe sequence 2, 3: slot 3.

33: slot 0 is full (22) → try the next slot.

33: slot 1 is full (1) → try the next slot.

Primary clustering goes away; keys with the same home address still follow the same sequence (secondary clustering). If m is prime and α ≤ 1/2, an empty slot is guaranteed to be found.

Open Addressing

Double Hashing: h(k, i) = (h₁(k) + i · h₂(k)) mod m

The step size depends on the key: 11 → h₂ = 2, 24 → h₂ = 5, 33 → h₂ = 4.

22 → home 0: slot 0.

1 → home 1: slot 1.

13 → home 2: slot 2.

11: slot 0 is full (22) → try the next slot.

11: slot 2 is full (13) → try the next slot.

11 → home 0, probe sequence 0, 2, 4: slot 4.

24: slot 2 is full (13) → try the next slot.

24 → home 2, probe sequence 2, 7: slot 7.

33: slot 0 is full (22) → try the next slot.

33: slot 4 is full (11) → try the next slot.

33 → home 0, probe sequence 0, 4, 8: slot 8.

h₂(k) must never be 0 and must be coprime to m (automatic if m is prime). The probe sequence is specific to the key, so clustering is minimal.

Chaining

Separate Chaining: One List per bucket

#define MZ 5
typedef struct node {
  int key;
  struct node *next;
} node;
node *bucket[MZ];           /* all NULL */
bool chain_insert(int k) {
  int i = k % MZ;
  node *np = malloc(sizeof *np);
  if (np == NULL) return false;  /* no memory */
  np->key = k;
  np->next = bucket[i];         /* at the head */
  bucket[i] = np;
  return true;
}
Insert at the head

The order in the list does not matter: inserting at the head is O(1). (If duplicates are not allowed, search first.)

Search

Only the list of its own bucket is scanned: 1 + α/2 nodes on average.

Easy deletion

Deleting from a linked list is enough; no tombstone is needed.

  node *p = bucket[k % MZ];
  while (p != NULL && p->key != k)
    p = p->next;
  return p;                 /* or NULL */
}

Code Trace: chain_erase(7)

chain_erase(7): 7 is in the middle of the chain (22 → 7 → 12).

i = 7 % 5 = 2.

p is at the head of the list; prev = NULL.

bool chain_erase(int k) {
  int i = k % MZ;
  node *p = bucket[i], *prev = NULL;
  while (p != NULL && p->key != k) {
    prev = p;
    p = p->next;
  }
  if (p == NULL) return false;        /* absent */
  if (prev == NULL) bucket[i] = p->next;
  else prev->next = p->next;
  free(p);
  return true;
}

Load Factor and Deletion

The Deletion Trap: Emptying a Slot Cuts Searches Short

We will delete 13. 24's home address is 2; since slots 2 and 3 were full, 24 went to 4.

If we make the slot EMPTY…

…search(24) sees an empty slot at the home address and reports “absent”. Yet 24 is in the table!

The right way is to mark the slot with a tombstone (DELETED).

Search does not treat a tombstone as empty and keeps going; insertion, however, may reuse a tombstone.

In tables with many deletions tombstones pile up and searches get longer: rehash periodically (cleanup). Chaining does not have this problem.

Resizing (Rehashing)

typedef struct {
  slot *a;      /* dynamic array of m slots */
  int m, n;     /* size, used slots */
} Table;
/* after inserting: */
if (2 * t->n > t->m)             /* α > 1/2 */
  resize(t, next_prime(2 * t->m));
Why rehash?

h(k) = k mod m depends on m: items land in different slots in the new table; copying is not enough.

Amortized O(1)

If the size doubles each time, n insertions copy at most 2n items in total: constant per insertion.

Tombstones

Rehashing also clears out the tombstones.

Resizing · run the code step by step

n = 3, m = 5 → α = 0.6 > 0.5: the table grows to 11 slots (≈ 2m, prime).

The old array's address and size are saved.

calloc returns 11 zeroed slots: all EMPTY (= 0).

Memory allocated; the table is linked to the new array, n = 0.

old[0] is EMPTY: skipped.

old[1] is EMPTY: skipped.

old[2] = 7 USED → rehash: 7 % 11 = 7 → slot 7. (Its old home address was 7 % 5 = 2.)

old[3] = 12 USED → rehash: 12 % 11 = 1 → slot 1. (Its old home address was 12 % 5 = 2.)

old[4] = 3 USED → rehash: 3 % 11 = 3 → slot 3. (Its old home address was 3 % 5 = 3.)

The old array is freed. New α = 3/11 ≈ 0.27.

bool resize(Table *t, int new_m) {
  slot *old = t->a;
  int old_m = t->m;
  slot *a = calloc(new_m, sizeof *a); /* EMPTY */
  if (a == NULL) return false;
  t->a = a; t->m = new_m; t->n = 0;
  for (int i = 0; i < old_m; i++)
    if (old[i].state == USED)
      table_insert(t, old[i].key);
  free(old);
  return true;
}

Lab: Open Addressing

Summary

Chaining or Open Addressing?

Chaining

  • α > 1 is possible; it never fills up, it just slows down.
  • Deletion is simple, no tombstones.
  • More robust against a poor hash.
  • A pointer plus malloc cost per node; not cache-friendly.

Open addressing

  • No extra pointers; contiguous memory, cache-friendly.
  • α ≤ 1; the cost explodes as α → 1.
  • Deletion needs tombstones.
  • Needs good probing (double hashing) against clustering.
Rule of thumb: if the item count is unpredictable and deletions are frequent, chain; if memory and speed are critical, deletions are rare and α can be kept low, use open addressing.

Summary

Common Mistakes

1A negative key makes k % m negative, writing outside the array.
2Choosing m as 10 or a power of 2, so only the last digits/bits matter.
3Marking a deleted slot EMPTY in open addressing: searches stop halfway.
4Looping forever on a full table: limit the number of probes to m.
5Not checking the result of malloc; using a node after free.
6Copying items at their old indices when resizing (without rehashing).

  4. ½(1 + 1/0.01) = 50.5 probes: the cost explodes as α → 1.
  5. Additive: 97 + 98 = 195 → both 195 % 11 = 8. Polynomial: "ab" = 97·31 + 98 = 3105 → 3; "ba" = 98·31 + 97 = 3135 → 0.
  6. The same key may already sit in a slot past the tombstone; without the check it enters the table twice.

Summary

Chapter Summary

The idea

Compute the position from the key: O(1) search/insert/delete on average.

Hash function

Division (m prime), multiplication (A ≈ 0.618), folding, polynomial string hash.

Open addressing

Linear, quadratic, double hashing; clustering and tombstones.

Chaining

A linked list per bucket; O(1) insertion at the head, easy deletion.

Load factor

Keep α = n/m small; resize past the threshold.

Limits

No order information; worst case O(n); universal hashing as protection.
