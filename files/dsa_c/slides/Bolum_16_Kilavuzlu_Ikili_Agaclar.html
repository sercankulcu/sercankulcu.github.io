Giriş

Öğrenme Çıktıları

Boş göstergeleri saymak

n düğümlü ikili ağaçta n+1 NULL gösterge olduğunu kanıtlamak.

Kılavuz kurmak

Sol NULL → kök ortada öncel, sağ NULL → kök ortada ardıl kuralını uygulamak.

Ayırt etmek

solKilavuz / sagKilavuz bayrakları ve başlık düğümüyle yapıyı eksiksiz tanımlamak.

Yığıtsız dolaşmak

kokortada_ardil_bul ile O(1) ek bellekle kök ortada (ve kök önde) dolaşmak.

Ekleme yapmak

saga_ekle'nin iki durumunu tek yordamda birleştirmek; sola_ekle'yi türetmek.

İyi kod yazmak

Açık tanımlı yordam, anlamlı açıklama satırı, NULL denetiminin yeri.

Neden Kılavuz?

n düğümde n+1 NULL gösterge

  • Her düğümde 2 gösterge alanı → ağaçta toplam 2n gösterge.
  • Kök dışındaki her düğüme babasından bir gösterge gelir → n − 1 gösterge dolu.
  • Geri kalan 2n − (n−1) = n + 1 gösterge NULL: göstergelerin yarıdan fazlası boşa!
“A year spent in artificial intelligence is enough to make one believe in God.”

— Alan J. Perlis (notlarda bölüm başında)

Kesikli kısa çizgiler NULL göstergeler; üç örnekte de NULL sayısı n + 1.

Neden Kılavuz?

Fikir: boş göstergeleri yol gösterici yapmak

  • A. J. Perlis ve C. Thornton, NULL göstergelerin ağaçtaki diğer düğümleri göstermek için kullanılabileceğini gösterdiler; bu göstergelere kılavuz (thread) dediler.
  • Kazanç: kök ortada dolaşım için yığıt ya da özyineleme gerekmez; her düğümden ardılına doğrudan gidilir.
  • Bedel: her göstergenin çocuk mu kılavuz mu olduğunu söyleyen birer bit.
Bölüm 7'deki özyineli dolaşım O(h) çağrı yığını, iteratif dolaşım O(h) yığıt kullanıyordu. Kılavuzlu ağaçta ek bellek O(1).

Kurma Kuralları

Kılavuzlu ikili ağaç kurma kuralları

  1. p->solcocuk == NULL ise p->solcocuk, kök ortada dolaşımda p'den önce ziyaret edilen öğeyi gösterir: NULL, p'nin kök ortada önceli (inorder predecessor) ile değiştirilir.
  2. p->sagcocuk == NULL ise p->sagcocuk, p'den sonra ziyaret edilen öğeyi gösterir: NULL, p'nin kök ortada ardılı (inorder successor) ile değiştirilir.

Kesikli kırmızı oklar kılavuzlardır. Kılavuzlar, ağacın kök ortada sırasını ağacın içine “örer”.

Kurma Kuralları

Kılavuzları tek tek kurmak

Sıradan ikili ağaç: 9 düğüm, 10 NULL gösterge (kesikli). Kök ortada sıra: H D I B E A F C G.

H'nin sol göstergesi NULL → kök ortada önceli başlık'yı gösterir (öncel/ardıl yok: şimdilik havada, başlık düğümüne bağlanacak).

H'nin sağ göstergesi NULL → kök ortada ardılı D'yı gösterir.

I'nin sol göstergesi NULL → kök ortada önceli D'yı gösterir.

I'nin sağ göstergesi NULL → kök ortada ardılı B'yı gösterir.

E'nin sol göstergesi NULL → kök ortada önceli B'yı gösterir.

E'nin sağ göstergesi NULL → kök ortada ardılı A'yı gösterir.

F'nin sol göstergesi NULL → kök ortada önceli A'yı gösterir.

F'nin sağ göstergesi NULL → kök ortada ardılı C'yı gösterir.

G'nin sol göstergesi NULL → kök ortada önceli C'yı gösterir.

G'nin sağ göstergesi NULL → kök ortada ardılı başlık'yı gösterir (öncel/ardıl yok: şimdilik havada, başlık düğümüne bağlanacak).

Dikkat: ağacı kök ortada dolaşıma göre kuruyoruz

Kılavuzlar kök ortada öncel/ardıla göre kurulur; kök önde ve kök sonda dolaşım da (daha dolambaçlı yoldan) bu kılavuzlarla yapılabilir.

Kök Ortada Dolaşım

Kök ortada ardılı bulmak

  1. p->sagKilavuz == TRUE ise p->sagCocuk (kılavuz olduğu için) zaten p'nin ardılıdır.
  2. p->sagKilavuz == FALSE ise sağ çocuktan başlanıp solCocuk bağları solKilavuz TRUE oluncaya dek izlenir: sağ alt ağacın en soldaki düğümü ardıldır.
kilavuz_gost kokortada_ardil_bul(kilavuz_gost L) {
  // L ile işaret edilen (NULL olmayan) öğenin ardılı
  kilavuz_gost p = L->sagCocuk;
  if (!L->sagKilavuz)        // sağ alt ağaç var mı
    while (!p->solKilavuz)   // en soluna dek in
      p = p->solCocuk;
  return p;
}

Notlarda 3. satırdaki ;; ve “Sol Çocuk sağından ilerle” yorumu düzeltildi.

kokortada_ardil_bul(): başlık, A ve I için

kokortada_ardil_bul(başlık): p = başlık->sagCocuk = başlık.

sagKilavuz FALSE: başlık'nin gerçek bir sağ alt ağacı var; ardıl oranın en solunda.

başlık->solKilavuz FALSE → sola: p = A.

A->solKilavuz FALSE → sola: p = B.

B->solKilavuz FALSE → sola: p = D.

D->solKilavuz FALSE → sola: p = H.

H->solKilavuz TRUE: daha sola gidilemez → en soldaki düğüm.

H döndürülür: başlık'nin kök ortada ardılı. (Başlığın ardılı = ilk ziyaret edilen düğüm.)

kokortada_ardil_bul(A): p = A->sagCocuk = C.

sagKilavuz FALSE: A'nin gerçek bir sağ alt ağacı var; ardıl oranın en solunda.

C->solKilavuz FALSE → sola: p = F.

F->solKilavuz TRUE: daha sola gidilemez → en soldaki düğüm.

F döndürülür: A'nin kök ortada ardılı.

kokortada_ardil_bul(I): p = I->sagCocuk = B.

I'nin sağ göstergesi bir kılavuz (TRUE): ardıl doğrudan B. Döngüye girilmez.

B döndürülür: I'nin kök ortada ardılı.

kilavuz_kokortada_dolas(): – H D I B E A F C G –

p = L: başlıktan başla. Yığıt yok, özyineleme yok; tek bir gösterge yeter.

p = ardıl(başlık) = H (sağ alt ağacın en solu); yazdırılır.

p = ardıl(H) = D (kılavuzla doğrudan); yazdırılır.

p = ardıl(D) = I (sağ alt ağacın en solu); yazdırılır.

p = ardıl(I) = B (kılavuzla doğrudan); yazdırılır.

p = ardıl(B) = E (sağ alt ağacın en solu); yazdırılır.

p = ardıl(E) = A (kılavuzla doğrudan); yazdırılır.

p = ardıl(A) = F (sağ alt ağacın en solu); yazdırılır.

p = ardıl(F) = C (kılavuzla doğrudan); yazdırılır.

p = ardıl(C) = G (sağ alt ağacın en solu); yazdırılır.

G'nin ardılı (kılavuzla doğrudan) başlık: ağaç dolaşıldı → break.

void kilavuz_kokortada_dolas(kilavuz_gost L) {
  kilavuz_gost p = L;        // L: başlık düğümü
  for (;;) {
    p = kokortada_ardil_bul(p);
    if (p == L) break;       // başlığa dönüldü mü
    printf("%c ", p->veri);
  }
}

Kök Ortada Dolaşım

Kılavuzlu dolaşımın maliyeti

  • Her kılavuz ve her gerçek sol/sağ bağ en çok bir kez izlenir → O(n) zaman.
  • Ek bellek O(1): yalnızca p göstergesi (özyineli dolaşımda O(h) çağrı yığını, iteratifte O(h) yığıt).
  • Herhangi bir düğümden ardılına, dolaşımı baştan yapmadan geçilebilir.
Hocadan “Bu iki zât diyor ki; “Kök-ortada dolaşıma göre kurduğum bu ağacı döngüsel olarak hem postorder hem de preorder dolaşabilirim.” Preorder’ı siz yazabilirsiniz, postorder’ı yazmak önceki sorduğumdan zordur.” — Mustafa Ege, VYA2 s. 19
Hocadan “Bir problemin çözümüne yönelik makaleleri okudun, O(n²)’de çözülebilmiş. Oturdun, çalıştın ve O(n1.89)’a düşüren bir algoritma yazdın. Büyük iş yaptın! Literatüre senin algoritman geçer.” — Mustafa Ege, VYA2 s. 19

kilavuz_gost kokonde_ardil_bul(kilavuz_gost p) {
  if (!p->solKilavuz)        // sol çocuk varsa o
    return p->solCocuk;
  while (p->sagKilavuz)      // sağ kılavuzlarla çık
    p = p->sagCocuk;
  return p->sagCocuk;        // ilk gerçek sağ çocuk
}

Sol çocuk varsa ardıl odur; yoksa sağ kılavuzlarla yukarı çıkılıp ilk gerçek sağ çocuğa geçilir. Kök sonda için baba bilgisi gerekir (daha zor).

Kök Ortada Dolaşım

Morris dolaşımı: kılavuzları geçici kurmak PDF dışı

void morris_kokortada(agac_gost L) {
  while (L) {
    if (!L->solcocuk) {             /* sol yok: yaz, sağa */
      printf("%c", L->veri);  L = L->sagcocuk;
    } else {
      agac_gost p = L->solcocuk;    /* kök ortada önceli */
      while (p->sagcocuk && p->sagcocuk != L)
        p = p->sagcocuk;
      if (!p->sagcocuk) {           /* geçici kılavuz kur */
        p->sagcocuk = L;  L = L->solcocuk;
      } else {                      /* kılavuzu sök */
        p->sagcocuk = NULL;
        printf("%c", L->veri);  L = L->sagcocuk;
      }
    }
  }
}

J. M. Morris (1979). Bayrak alanı gerekmez: kılavuz dolaşım sırasında kurulup sökülür; ağaç o sırada değiştiği için eşzamanlı okumaya uygun değildir.

Kök Ortada Dolaşım

Morris dolaşımı adım adım: A(B(D,E),C) PDF dışı

Başlangıç: yığıt yok. Solu olan her düğümde, öncelinin (boş) sağ göstergesine geçici kılavuz kurulacak.

A'nin önceli E; sağı boş → kılavuz E → A kurulur, sola inilir.

B'nin önceli D; sağı boş → kılavuz D → B kurulur, sola inilir.

D'nin solu yok: yazılır, sağa (ya da geçici kılavuzla) geçilir → B.

Öncel D'den kılavuzla B'ye dönüldü: kılavuz sökülür, B yazılır, sağa.

E'nin solu yok: yazılır, sağa (ya da geçici kılavuzla) geçilir → A.

Öncel E'den kılavuzla A'ye dönüldü: kılavuz sökülür, A yazılır, sağa.

C'nin solu yok: yazılır, sağa (ya da geçici kılavuzla) geçilir → NULL.

Bitti: DBEAC. Ağaç eski hâline döndü; ek bellek O(1), zaman O(n).

Düğüm Ekleme

Kılavuzlu ağaca düğüm ekleme

  • Ekleme tek başına kolay bir yordam değildir, biraz girifttir.
  • Sağa ve sola ekleme biçimi farklı → iki ayrı yordam: saga_ekle, sola_ekle.
  • Sağa eklemede iki durum: (1) babanın sağ alt ağacı yok, (2) var.
  • BST'de ekleme hep çocuğu olmayan yere tek atamaydı; burada kılavuzların (kırmızı okların) da doğru yeri göstermesi gerekir.
cocuk->sagCocuk  = baba->sagCocuk;
cocuk->sagKilavuz = TRUE;  // babanın sağı yoktu
cocuk->solCocuk  = baba;
cocuk->solKilavuz = TRUE;
baba->sagCocuk   = cocuk;
baba->sagKilavuz = FALSE;  // TRUE idi

baba->sagKilavuz = FALSE: babanın sağı artık kılavuz değil, çocuk. Ekleme bitti: 6 aktarma.

Düğüm Ekleme

Durum 2: babanın sağ alt ağacı var

  • İstenen: D, B'nin çocuğu iken X'i B'nin çocuğu yap; ama D alt ağacı kaybolmasın, kırmızı göstergeler yine doğru yerleri göstersin.
  • X'in önceli B olur. D alt ağacının en solundaki E'nin eski önceli B idi; şimdi E, X'in ardılı oldu.
  • Öyleyse: çocuk, babanın eski ardılının önceli yapılmalıdır.
  • Notlardaki durum 2 kodu: 2. satır cocuk->sagKilavuz = FALSE (babanın alt ağacı şimdi çocuğun alt ağacı); E'nin sol kılavuzu ayrıca düzeltilmelidir.
SONUÇ: 2. durum için babanın eski ardılının öncel bilgisini günlemek ve 2 numaralı aktarmayı cocuk->sagKilavuz = baba->sagKilavuz yazmak suretiyle her iki durumun da üstesinden gelen tek bir yordam yazılabilir.

Düğüm Ekleme · Kodu adım adım çalıştır

saga_ekle(B, X): tek yordam, 2. durum

cocuk->sagCocuk = baba->sagCocuk: X'in sağına B'nin eski sağ alt ağacı (D) gelir.

cocuk->sagKilavuz = baba->sagKilavuz (FALSE): babanın alt ağacı artık çocuğun alt ağacı; siyahlık korunur.

cocuk->solCocuk = baba: X'in önceli B.

cocuk->solKilavuz = TRUE: kırmızı ok.

baba->sagCocuk = cocuk: B → X gerçek bağ.

baba->sagKilavuz = FALSE: zaten FALSE idi; 1. durum için gerekli, burada zararsız. “Kodun doğru çalıştığına hemen karar vermeyin!”

cocuk->sagKilavuz FALSE → X'in sağ alt ağacı var: X'in ardılının sol kılavuzu hâlâ B'yi gösteriyor, düzeltilmeli.

p = kokortada_ardil_bul(X) = E (D'nin en solu). E'nin eski önceli B idi.

p->solCocuk = cocuk: E'nin sol kılavuzu artık X'i gösterir. Çocuk, babanın eski ardılının önceli yapıldı.

void saga_ekle(kilavuz_gost baba,
               kilavuz_gost cocuk) {
  // cocuk'u baba'nın sağ çocuğu yapar (kılavuzlu)
  kilavuz_gost p;
  cocuk->sagCocuk   = baba->sagCocuk;
  cocuk->sagKilavuz = baba->sagKilavuz;
  cocuk->solCocuk   = baba;
  cocuk->solKilavuz = TRUE;
  baba->sagCocuk    = cocuk;
  baba->sagKilavuz  = FALSE;
  if (!cocuk->sagKilavuz) { // babanın alt ağacı var mı
    p = kokortada_ardil_bul(cocuk);
    p->solCocuk = cocuk;     // ardılın önceli çocuk
  }
}

Düğüm Ekleme

saga_ekle satır satır (notlardaki açıklamalar)

[1] Açık tanım

Adı belli, giden parametreler belli, dönüş değeri belli.

[4–5]

Çocuğun sağ gösterge ve sağ kılavuzu babadan alınır: 1. durumda kırmızılık (TRUE), 2. durumda siyahlık (FALSE) korunur.

[6–7]

Çocuğun kök ortada önceli baba: sol gösterge babaya, sol kılavuz TRUE (kırmızı).

[9]

Babanın sağ kılavuzuna FALSE: 2. durumda gereksiz ama zararsız; 1. durumda gerekli.

[10–12]

Çocuğun sağ kılavuzu FALSE ise (2. durum) ardılın sol kılavuzu çocuğa çevrilir; 1. durumda yalnızca bir test yapılıp dönülür.

Düzeltmeler

Notlarda baba->SagCocuk, baba->SagKilavuz (büyük S) derlenmez; “babanın sol çocuğu yoksa” → sağ çocuğu. Açıklama numaraları kodla hizalandı.

Düğüm Ekleme

NULL mı kontrolü nerede yapılmalı?

Hocadan “saga_ekle yordamı, müstakil olarak kullanılmayıp, başka bir yordam içinde kullanılacağı için NULL mı kontrolünü burada yapmaya gerek yoktur. Bu kontrolü, saga_ekle yordamını kullanan yordamda yapmak gerekir. Ama saga_ekle yordamını müstakil olarak birisi kullanacaksa o zaman bunu da kontrol etmeliyiz.” — Mustafa Ege, VYA2 s. 21
  • Örnek: kılavuzlu arama ağacına eklerken sağa mı sola mı ekleneceği bulununca, tek atama yerine saga_ekle ya da sola_ekle çağrılır; baba zaten NULL değildir.
  • Kodun giriş kısmında denetim yapılmıyorsa bu açıklamada belirtilmelidir: “baba ve cocuk NULL olmamalı”.
  • Genel kütüphane yordamı yazıyorsanız savunmacı denetim ekleyin (assert ya da hata dönüşü).

Düğüm Ekleme

SORU: sola ekleme yordamını düşününüz

Çocukla işaret edilen öğeyi, babanın sol çocuğu olacak biçimde kılavuzlu ağaca ekleyen sola_ekle yordamını yazınız.

  • Sol ↔ sağ, öncel ↔ ardıl yer değiştirir: babanın eski önceli, çocuğun önceli olur; onun sağ kılavuzu çocuğa çevrilir.
  • Kök ortada öncel bulma: sol alt ağaç varsa onun en sağı, yoksa sol kılavuz.
Önce kendiniz deneyin; çözüm bir sonraki slaytta.

Düğüm Ekleme

Çözüm: sola_ekle ve kokortada_oncel_bul

kilavuz_gost kokortada_oncel_bul(kilavuz_gost L) {
  kilavuz_gost p = L->solCocuk;
  if (!L->solKilavuz)
    while (!p->sagKilavuz) p = p->sagCocuk;
  return p;
}
void sola_ekle(kilavuz_gost baba, kilavuz_gost cocuk) {
  cocuk->solCocuk   = baba->solCocuk;
  cocuk->solKilavuz = baba->solKilavuz;
  cocuk->sagCocuk   = baba;
  cocuk->sagKilavuz = TRUE;      // ardılı baba
  baba->solCocuk    = cocuk;
  baba->solKilavuz  = FALSE;
  if (!cocuk->solKilavuz) {      // baba'nın sol alt ağacı vardı
    kilavuz_gost p = kokortada_oncel_bul(cocuk);
    p->sagCocuk = cocuk;         // öncelin ardılı çocuk
  }
}

Kılavuzlu ağaç

  • Yığıtsız O(1) bellekli dolaşım
  • Her düğümden ardıl/öncel O(h)'de, dolaşımda amortize O(1)
  • NULL alanlar boşa gitmez

Bedeli

  • Her düğümde 2 bayrak
  • Ekleme/silme daha girift
  • Her yordam kılavuzları gözetmeli

Sık yapılan hatalar

1Kılavuz bayrağına bakmadan solCocuk/sagCocuk'u gerçek çocuk sanmak (sonsuz döngü).
2Başlık düğümünü unutmak: H'nin sol ve G'nin sağ kılavuzu havada kalır.
3Sağa eklemede 2. durumda ardılın sol kılavuzunu güncellememek.
4cocuk->sagKilavuz'u sabit TRUE yazıp 2. durumu bozmak.
5Boş ağaçta başlığın solKilavuz = TRUE olduğunu unutup kökü aramak.
6Büyük/küçük harf: SagCocuk ≠ sagCocuk (C büyük/küçük harfe duyarlıdır).

Özet

Alıştırmalar

  1. A(B(D, E), C(–, F)) ağacının kılavuzlarını çiziniz; kaç kılavuz vardır?
  2. Kök ortada öncel bulan kokortada_oncel_bul yordamını yazınız.
  3. Kılavuzlu ağacı kök ortada tersten (G C F A …) dolaşan yordamı yazınız.
  4. Boş ağaca (yalnız başlık) ilk düğümü sola_ekle(baslik, x) ile eklemek doğru mu?
  5. Kök sonda dolaşım kılavuzlarla neden zordur? Hangi ek bilgi işi kolaylaştırır?
  6. Kılavuzlu ikili arama ağacına ekleme yordamını saga_ekle/sola_ekle kullanarak yazınız.
İpuçları / cevaplar
  1. n = 6 → n + 1 = 7 kılavuz (2'si başlığa).
  2. Ardıl bulmanın aynası: sol kılavuz TRUE ise doğrudan; değilse sol çocuktan sağa sağa (Sola ekleme çözümünde).
  3. Başlıktan başla, kokortada_oncel_bul ile başlığa dönene dek.
  4. Evet: başlığın sol kılavuzu TRUE olduğu için çocuk iki kılavuzuyla başlığı gösterir, başlığın solKilavuz'u FALSE olur.
  5. Bir düğümün kök sonda ardılı babaya bağlıdır; baba göstergesi eklemek işi kolaylaştırır.
  6. Arama: kılavuz bayrağı TRUE olan yere gelince dur; x küçükse sola_ekle, büyükse saga_ekle.

Özet

Bölüm özeti

n + 1 NULL

2n göstergenin n−1'i dolu; kalanlar kılavuz olur.

Kurallar

Sol NULL → öncel, sağ NULL → ardıl; bayraklar ayırt eder; başlık asılı kılavuzları toplar.

Ardıl

Sağ kılavuz TRUE ise doğrudan; değilse sağ alt ağacın en solu.

Dolaşım

Yığıtsız O(n) zaman, O(1) bellek; kök önde de mümkün.

Ekleme

saga_ekle: kılavuz bayrağını babadan kopyala; 2. durumda ardılın önceli çocuk.

Kod kalitesi

Açık tanım, anlamlı açıklama, NULL denetiminin yeri, tek yordam.
