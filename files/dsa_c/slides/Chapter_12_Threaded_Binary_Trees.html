Why Threads?

n+1 NULL Pointers in n Nodes

  • Each node has 2 pointer fields → 2n pointers in the tree.
  • Every node except the root is pointed to by its parent → n − 1 pointers are used.
  • The remaining 2n − (n−1) = n + 1 pointers are NULL: more than half the pointers are wasted!
“A year spent in artificial intelligence is enough to make one believe in God.”

— Alan J. Perlis

Short dashed lines are NULL pointers; in all three examples there are n + 1 of them.

Why Threads?

The Idea: Make the Null Pointers Point the Way

  • A. J. Perlis and C. Thornton showed that NULL pointers can be used to point to other nodes of the tree; they called these pointers threads.
  • The gain: an inorder traversal needs no stack and no recursion; from each node we go straight to its successor.
  • The price: one bit per pointer saying whether it is a child or a thread.
Recursive traversal uses an O(h) call stack, iterative traversal an O(h) stack. A threaded tree needs O(1) extra space.

Threading Rules

Rules for Building a Threaded Binary Tree

  1. If p->left_child == NULL, p->left_child points to the node visited just before p in inorder: the NULL is replaced by p's inorder predecessor.
  2. If p->right_child == NULL, p->right_child points to the node visited just after p: the NULL is replaced by p's inorder successor.

The dashed red arrows are threads. They “weave” the tree's inorder sequence into the tree itself.

Threading Rules

Two Dangling Threads and the Header Node

  • H's left thread and G's right thread have nothing to point to: they dangle.
  • We add a head node: the root of the actual tree is reached through L->left_child.
  • The two dangling threads point to the head; the head's right pointer always points to itself, with right thread FALSE.
  • In an empty tree the left pointer also points to the head, with left thread TRUE; it becomes FALSE once a node is inserted.

Inorder Traversal

Finding the Inorder Successor

  1. If p->right_thread == TRUE, p->right_child (being a thread) already is p's successor.
  2. If p->right_thread == FALSE, start at the right child and follow left_child links until left_thread is TRUE: the leftmost node of the right subtree is the successor.
thread_ptr insucc(thread_ptr L) {
  // successor of the (non-NULL) node L
  thread_ptr p = L->right_child;
  if (!L->right_thread)        // right subtree?
    while (!p->left_thread)   // go to its leftmost
      p = p->left_child;
  return p;
}

insucc(): for the Head, A and I

insucc(head): p = head->right_child = head.

right_thread is FALSE: the head has a real right subtree; the successor is its leftmost node.

head->left_thread FALSE → go left: p = A.

A->left_thread FALSE → go left: p = B.

B->left_thread FALSE → go left: p = D.

D->left_thread FALSE → go left: p = H.

H->left_thread TRUE: cannot go further left → the leftmost node.

Returns H: the head's inorder successor. (The head's successor = the first node visited.)

insucc(A): p = A->right_child = C.

right_thread is FALSE: A has a real right subtree; the successor is its leftmost node.

C->left_thread FALSE → go left: p = F.

F->left_thread TRUE: cannot go further left → the leftmost node.

Returns F: A's inorder successor.

insucc(I): p = I->right_child = B.

I's right pointer is a thread (TRUE): the successor is B directly. The loop is skipped.

Returns B: I's inorder successor.

thread_ptr insucc(thread_ptr L) {
  // successor of the (non-NULL) node L
  thread_ptr p = L->right_child;
  if (!L->right_thread)        // right subtree?
    while (!p->left_thread)   // go to its leftmost

}

p = succ(D) = I (leftmost of the right subtree); printed.

p = succ(A) = F (leftmost of the right subtree); printed.

p = succ(F) = C (directly via the thread); printed.

p = succ(C) = G (leftmost of the right subtree); printed.

G's successor (directly via the thread) is the head: the traversal is done → break.

void tinorder(thread_ptr L) {
  thread_ptr p = L;        // L: the header node
  for (;;) {
    p = insucc(p);
    if (p == L) break;       // back at the head?
    printf("%c ", p->data);
  }
}

Inorder Traversal

The Cost of Threaded Traversal

  • Each thread and each real left/right link is followed at most once → O(n) time.
  • Extra space O(1): just the pointer p (recursive traversal needs an O(h) call stack, iterative an O(h) stack).
  • From any node we can move to its successor without restarting the traversal.

Instructor “You read the papers on a problem; it has been solved in O(n²). Sitting down and writing an algorithm that brings it down to O(n1.89) is a big deal! That algorithm goes into the literature.”

Preorder Traversal with the Same Threads

succ(head) = A (left child).

succ(A) = B (left child).

succ(B) = D (left child).

succ(D) = H (left child).

succ(H) = I (right child reached via the right threads through D).

succ(I) = E (right child reached via the right threads through B).

succ(E) = C (right child reached via the right threads through A).

succ(C) = F (left child).

succ(F) = G (right child reached via the right threads through C).

G: following the right threads leads to the head → head: the traversal ends.

thread_ptr presucc(thread_ptr p) {
  if (!p->left_thread)        // left child if any
    return p->left_child;
  while (p->right_thread)      // climb the threads
    p = p->right_child;
  return p->right_child;        // first real child
}

If there is a left child, it is the successor; otherwise climb the right threads and step to the first real right child. Postorder needs parent information (harder).

Inorder Traversal

Morris Traversal: Temporary Threads

void morris_inorder(tree_ptr L) {
  while (L) {
    if (!L->left) {             /* no left: print, right */
      printf("%c", L->data);  L = L->right;
    } else {
      tree_ptr p = L->left;    /* inorder predecessor */
      while (p->right && p->right != L)
        p = p->right;
      if (!p->right) {           /* add a temp thread */
        p->right = L;  L = L->left;
      } else {                      /* remove the thread */
        p->right = NULL;
        printf("%c", L->data);  L = L->right;
      }
    }
  }
}

J. M. Morris (1979). No flag fields needed: threads are added and removed during the traversal; since the tree changes meanwhile, it is unsafe for concurrent readers.

Inorder Traversal

Morris Traversal Step by Step: A(B(D,E),C)

Start: no stack. At each node with a left subtree, a temporary thread goes into its predecessor's (empty) right pointer.

A's predecessor is E; its right is empty → add thread E → A, go left.

B's predecessor is D; its right is empty → add thread D → B, go left.

D has no left: print it, go right (or along the temporary thread) → B.

Back at B through the thread from its predecessor D: remove the thread, print B, go right.

E has no left: print it, go right (or along the temporary thread) → A.

Back at A through the thread from its predecessor E: remove the thread, print A, go right.

C has no left: print it, go right (or along the temporary thread) → NULL.

Done: DBEAC. The tree is restored; extra space O(1), time O(n).

Inserting a Node

Inserting a Node into a Threaded Tree

  • Insertion is not a simple routine on its own; it is a bit tricky.
  • Inserting to the right and to the left differ → two routines: insert_right, insert_left.
  • Inserting to the right has two cases: (1) the parent has no right subtree, (2) it has one.
  • In a BST, insertion was a single assignment at an empty child slot; here the threads (red arrows) must also point to the right places.
child->right_child  = parent->right_child;
child->right_thread = TRUE;  // parent: no right
child->left_child  = parent;
child->left_thread = TRUE;
parent->right_child   = child;
parent->right_thread = FALSE;  // was TRUE

Case 1: insertion in 6 assignments.

Case 1: Inserting Under a Parent with No Right Subtree

child->right_child = parent->right_child: the parent's right thread (its successor) moves to the child. (Whether it is the head does not matter.)

child->right_thread = TRUE: the parent had no subtree, so the child cannot either → red arrow.

child->left_child = parent: the child's inorder predecessor is the parent.

child->left_thread = TRUE: this is a thread too (red).

parent->right_child = child: a real (black) link from parent to child.

parent->right_thread = FALSE: the parent's right is now the child, not a thread. Done: 6 assignments.

Inserting a Node

Case 2: the Parent Has a Right Subtree

  • Goal: D is B's child, and we make X B's child instead; but the D subtree must not be lost, and the red pointers must still point to the right places.
  • X's predecessor becomes B. E, the leftmost node of the D subtree, used to have B as its predecessor; now E is X's successor.
  • So: the child must become the predecessor of the parent's old successor.
  • In the case 2 code, line 2 is child->right_thread = FALSE (the parent's subtree is now the child's); E's left thread must also be fixed.
RESULT: by updating the predecessor of the parent's old successor in case 2, and writing assignment 2 as child->right_thread = parent->right_thread, we get a single routine that handles both cases.

Inserting a Node · Run the code step by step

insert_right(B, X): One Routine, Case 2

child->right_child = parent->right_child: B's old right subtree (D) goes to X's right.

child->right_thread = parent->right_thread (FALSE): the parent's subtree is now the child's; the link stays black.

child->left_child = parent: X's predecessor is B.

child->left_thread = TRUE: red arrow.

parent->right_child = child: real link B → X.

parent->right_thread = FALSE: it was FALSE already; needed for case 1, harmless here. “Don't conclude too soon that the code works!”

child->right_thread FALSE → X has a right subtree: the left thread of X's successor still points to B and must be fixed.

p = insucc(X) = E (leftmost of D). E's old predecessor was B.

p->left_child = child: E's left thread now points to X. The child became the predecessor of the parent's old successor.

void insert_right(thread_ptr parent,
               thread_ptr child) {
  // make child the right child of parent
  thread_ptr p;
  child->right_child   = parent->right_child;
  child->right_thread = parent->right_thread;
  child->left_child   = parent;
  child->left_thread = TRUE;
  parent->right_child    = child;
  parent->right_thread  = FALSE;
  if (!child->right_thread) { // parent had a subtree?
    p = insucc(child);
    p->left_child = child;     // succ's pred is child
  }
}

Where Should the NULL Check Go?

Instructor “insert_right is not used on its own but inside another routine, so there is no need for a NULL check here. That check belongs in the routine that calls insert_right. But if someone is going to use insert_right on its own, then we must check this too.”
  • Example: when inserting into a threaded search tree, once we know whether to go right or left, we call insert_right or insert_left instead of a single assignment; the parent is never NULL.
  • If the routine does not check its inputs, the comment must say so: “parent and child must not be NULL”.
  • A general library routine adds defensive checks (assert or an error return).

What Should a Comment Say?

/* BAD: repeats the code */
if (!child->right_thread)  // right thread FALSE?
/* GOOD: states intent */
if (!child->right_thread)  // parent had a subtree?
  • A comment should say what the code means to do; it should not repeat the code.
  • Then a reader can say “the intent is right but the code is wrong”: debugging gets easier.
Instructor “Don't you dare write ‘is the parent's right child FALSE’ here! The next reader shouldn't say ‘I already know that.’ Comments should say things the code doesn't.”

Reducing to One Routine, and Software Engineering

Instructor “If we write a separate routine for each case, the fun is gone: noChild_insertRight, hasChild_insertRight, noChild_insertLeft, hasChild_insertLeft. If we can merge them into one without adding complexity, good! … ‘We'll nest if… if…, and write every case in one routine.’ Avoid that. In that case, keep separate routines.”
  • First analyze the 3–5 different cases; then decide the routine's name, return value and parameters.
  • Define the common work in a common way (here: copying the thread flag from the parent).
  • Result: code that is not fragmented; simple, readable, easy to maintain.

QUESTION: Think About the Insert-Left Routine

Write insert_left, which inserts the node pointed to by child into the threaded tree as the left child of parent.

  • Left ↔ right and predecessor ↔ successor swap: the parent's old predecessor becomes the child's predecessor, and its right thread is redirected to the child.
  • Finding the inorder predecessor: the rightmost node of the left subtree if there is one, else the left thread.

Inserting a Node

Solution: insert_left and inpred

thread_ptr inpred(thread_ptr L) {
  thread_ptr p = L->left_child;
  if (!L->left_thread)
    while (!p->right_thread) p = p->right_child;
  return p;
}
void insert_left(thread_ptr parent, thread_ptr child) {
  child->left_child   = parent->left_child;
  child->left_thread = parent->left_thread;
  child->right_child   = parent;
  child->right_thread = TRUE;      // successor: parent
  parent->left_child    = child;
  parent->left_thread  = FALSE;
  if (!child->left_thread) {      // parent had a left subtree
    thread_ptr p = inpred(child);
    p->right_child = child;         // pred's succ is child
  }
}

  • Stackless traversal in O(1) space

The price

  • 2 flags per node
  • Insert/delete are trickier
  • Every routine must maintain the threads

Common Mistakes

1Taking left_child/right_child for a real child without checking the thread flag (infinite loop).
2Forgetting the header node: H's left thread and G's right thread dangle.
3Not updating the successor's left thread in case 2 of inserting right.

5Searching for the root in an empty tree, forgetting the head's left_thread = TRUE.
6Case: Right_child ≠ right_child (C is case-sensitive).

Chapter Summary

n + 1 NULL

n−1 of the 2n pointers are used; the rest become threads.

Rules

Left NULL → predecessor, right NULL → successor; flags tell them apart; the head collects the dangling threads.

Successor

Directly if the right thread is TRUE; otherwise the leftmost node of the right subtree.

Traversal

Stackless, O(n) time, O(1) space; preorder works too.

Insertion

insert_right: the thread flag is copied from the parent; in case 2 the child becomes the successor's predecessor.

Code quality

Clear definition, meaningful comments, the right place for the NULL check, one routine.
