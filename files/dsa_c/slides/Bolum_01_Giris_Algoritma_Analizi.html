Temeller · s. 1

Sistem Yaşam Döngüsü (System Life Cycle)

Yazılımlar, aşamaları aşağıdaki gibi olan bir süreçten geçer:

Gereksinimler: Proje, amacını belirten şartlarla başlar: programcıya hangi girdiler verilecek, hangi çıktılar üretilecek?

Çözümleme: Problem parçalara ayrılır. İki yol var: aşağıdan yukarı (bottom-up) ya da yukarıdan aşağı (top-down).

Tasarım: Veri nesneleri (→ ADT) ve işlemler (→ algoritma) tanımlanır; ikisi de dilden bağımsızdır. Tasarıma ayrılan zaman arttıkça hata azalır.

İnceltme ve kodlama: Seçilen veri yapıları üzerinde algoritmalar kodlanır. Veri gösterimi, algoritmanın etkinliğini belirler.

Doğrulama: Doğruluk ispatı, geniş test verisiyle sınama ve hata giderme. Her biri başlı başına bir araştırma konusu.

Horowitz–Sahni, s. 1–4 · VYA1 s. 2–3

Temeller

Çözümleme: Aşağıdan Yukarı mı, Yukarıdan Aşağı mı?

Aşağıdan yukarı (bottom-up)

  • Problem parçalara bölünür, her parçaya ayrı odaklanılır.
  • Modüller doğrudan görülür; problem modül modül çözülür.
  • Proje konusunda tecrübeliysek tercih edilir.

Yukarıdan aşağı (top-down)

  • Önce bir ana plan: “Amaç ne?”, “Son ürün ne olacak?”
  • Problem alt parçalara bölünür; daha çok zaman harcanır.
  • Geri dönüş ve hata olasılığı daha azdır; tecrübemiz yoksa tercih edilir.
Tasarım aşamasında öğrenci kütüğünün hangi alanları içereceğine karar veririz, ama onu dizi mi, bağlaçlı liste mi, ağaç mı ile gerçekleştireceğimizi erteleyebiliriz. Erteleme, daha etkili bir gerçekleştirimi seçme fırsatı verir.

Kodlama ve Doğrulama

Doğruluk ispatı

Matematiksel tekniklerle program doğruluğu ispatlanır; büyük projede baştan sona ispat neredeyse imkânsız. Doğruluğu ispatlanmış algoritmaları kullanmak hatayı azaltır.

Sınama (testing)

Çalışan kod ve tüm senaryoları kapsayan test verisi gerekir. Sözdizimi hatası vermeden çalışan program doğru demek değildir.

Hata giderme

İspat ve testler hatayı gösterirse, tasarım ve kodlama kararlarına göre hata ayıklanır.

İşletim zamanı

Hatasız ama yavaş çalışan bir programın da fazla değeri yoktur: doğruluk ile verimlilik ayrı sorulardır.

Algoritma Nedir?

Algoritma, belirli bir görevi yerine getiren sonlu sayıda komut dizisidir. Her algoritma şu ölçütleri sağlamalıdır:

ÖlçütAnlamı
GirdiDışarıdan sıfır ya da daha fazla nicelik alınır.
ÇıktıEn az bir nicelik üretilir.
Kesinlik (definiteness)Her komut açık ve tek anlamlıdır: “x’e 6 ya da 7 ekle” olmaz.
Sonluluk (finiteness)Her durumda, sonlu adım sonra sona erer.
Etkinlik (effectiveness)Her komut, kâğıt kalemle yapılabilecek kadar temel ve uygulanabilirdir.
Sonlanmayan program (ör. işletim sistemi) algoritma değil, bir hesaplama yöntemidir. Algoritmayı doğal dil, akış şeması ya da C ile ifade edebiliriz; biz C kullanacağız.

Horowitz–Sahni, s. 5 · Zenginleştirme

Temeller

Soyut Veri Türü (Abstract Data Type)

Veri türü = nesneler + işlemler. ADT: nesnelerin ve işlemlerin belirtiminin (specification), gösterimden ve gerçekleştirimden (implementation) ayrıldığı veri türü.

Belirtim: NE yapılır?

İşlem adları, parametre türleri, sonuç türü ve işlemin ne yaptığı. Kullanıcı yalnızca bunu bilir.

Gerçekleştirim: NASIL?

Verinin bellekte gösterimi (struct, dizi…) ve işlemleri yapan kod. Kullanıcıdan gizlenir.

ADT Kesir
  nesneler: pay/payda, payda ≠ 0
  işlemler:
    olustur(p, q)  → Kesir   /* kurucu */
    topla(a, b)    → Kesir   /* dönüştürücü */
    esit(a, b)     → Boolean /* gözlemci */
    yaz(a)                   /* raporlayıcı */
    sil(a)
Kurucu yeni örnek yaratır, dönüştürücü var olandan yeni değer üretir, gözlemci/raporlayıcı bilgi verir. Aynı ADT farklı veri yapılarıyla gerçekleştirilebilir.

Temeller · Zenginleştirme

C’de Soyutlama: Başlık Dosyası + struct

/* kesir.h : arayuz (NE?) */
#ifndef KESIR_H
#define KESIR_H
typedef struct kesir Kesir; /* opak */

Kesir *kesir_olustur(int pay, int payda);
Kesir *kesir_topla(const Kesir *a,
                   const Kesir *b);
int  kesir_esit(const Kesir *a,
                const Kesir *b);
void kesir_yaz(const Kesir *k);
void kesir_sil(Kesir *k);
#endif
/* kesir.c : gerceklestirim (NASIL?) */
#include <stdio.h>
#include <stdlib.h>
#include "kesir.h"

struct kesir { int pay, payda; };

Kesir *kesir_olustur(int pay, int payda) {
  Kesir *k;
  if (payda == 0) return NULL;
  k = malloc(sizeof *k);
  if (k == NULL) return NULL;
  k->pay = pay;
  k->payda = payda;
  return k;
}
typedef struct kesir Kesir; eksik (opak) tür bildirir: kesir.h’yi kullanan dosya yapının alanlarını göremez, yalnızca Kesir * tutar. Alanlar kesir.c’de gizlidir → ADT’nin C’deki karşılığı.

Temeller · Zenginleştirme

Gerçekleştirimin Kalanı ve Kullanımı

Kesir *kesir_topla(const Kesir *a,
                   const Kesir *b) {
  return kesir_olustur(
      a->pay * b->payda
        + b->pay * a->payda,
      a->payda * b->payda);
}
int kesir_esit(const Kesir *a,
               const Kesir *b) {
  return a->pay * b->payda
      == b->pay * a->payda;
}
void kesir_yaz(const Kesir *k) {
  printf("%d/%d\n", k->pay, k->payda);
}
void kesir_sil(Kesir *k) { free(k); }
/* main.c : yalnizca arayuzu bilir */
#include "kesir.h"

int main(void) {
  Kesir *a = kesir_olustur(1, 2);
  Kesir *b = kesir_olustur(1, 3);
  Kesir *t = NULL;
  if (a && b) t = kesir_topla(a, b);
  if (t) kesir_yaz(t);  /* 5/6 */
  kesir_sil(a); kesir_sil(b);
  kesir_sil(t);  /* free(NULL) zararsiz */
  return 0;
}
Sözleşme

kesir_olustur payda 0 ise ya da bellek yoksa NULL döner; çağıran bunu denetler.

Sahiplik

Her olustur/topla sonucu çağırana aittir; kesir_sil ile bırakılır.

Seçmeli Sıralama · s. 5

Seçmeli Sıralama (Selection Sort)

Sıralı olmayan bir diziyi küçükten büyüğe sıralamak istiyoruz. Her turda kalan kısmın en küçüğünü bul, başa (i. konuma) taşı:

for (i = 0; i < n; i++) {
    list[i] .. list[n-1] arasini incele;
    en kucuk tamsayi list[min] olsun;
    list[i] ile list[min]'i takas et;
}

Seçmeli Sıralama · s. 7

Seçmeli Sıralama: C Gerçekleştirimi

#include <stdio.h>
#include <stdlib.h>
#define MAX_SIZE 101
#define SWAP(x, y, t) ((t) = (x), (x) = (y), (y) = (t))
void sort(int list[], int n);

int main(void) {
  int i, n, list[MAX_SIZE];
  printf("Dizi boyunu giriniz: ");
  if (scanf("%d", &n) != 1 || n < 1 || n > MAX_SIZE) {
    printf("Hatali n degeri!\n");
    return 1;
  }
  for (i = 0; i < n; i++) list[i] = rand() % 100;
  sort(list, n);
  for (i = 0; i < n; i++) printf("%d ", list[i]);
  return 0;
}
void sort(int list[], int n) {
  int i, j, min, temp;
  for (i = 0; i < n - 1; i++) {
    min = i;
    for (j = i + 1; j < n; j++)
      if (list[j] < list[min])
        min = j;
    SWAP(list[i], list[min], temp);
  }
}
Karşılaştırma sayısı: (n−1) + (n−2) + … + 1 = n(n−1)/2 → O(n²). Takas en fazla n−1 kez.

Seçmeli Sıralama · Kodu adım adım çalıştır

Kod İzleme: sort({29, 10, 14, 37, 13}, 5)

sort(list, 5) çağrıldı. Dizi adresiyle geçer: yordam, main’in dizisini değiştirecek.

1. tur: i = 0. Şimdilik en küçük list[0] = 29 kabul edilir (min = 0).

list[1] = 10 < list[0] = 29 → yeni en küçük: min = 1.

list[2] = 14 ≥ list[1] = 10 → min değişmez.

list[3] = 37 ≥ list[1] = 10 → min değişmez.

list[4] = 13 ≥ list[1] = 10 → min değişmez.

SWAP: list[0] ↔ list[1] → 10 yerine oturdu. Sıralı bölge 1 öğe.

2. tur: i = 1. Şimdilik en küçük list[1] = 29 kabul edilir (min = 1).

list[2] = 14 < list[1] = 29 → yeni en küçük: min = 2.

list[3] = 37 ≥ list[2] = 14 → min değişmez.

list[4] = 13 < list[2] = 14 → yeni en küçük: min = 4.

SWAP: list[1] ↔ list[4] → 13 yerine oturdu. Sıralı bölge 2 öğe.

3. tur: i = 2. Şimdilik en küçük list[2] = 14 kabul edilir (min = 2).

list[3] = 37 ≥ list[2] = 14 → min değişmez.

list[4] = 29 ≥ list[2] = 14 → min değişmez.

min = i → takas kendisiyle yapılır, dizi değişmez. Sıralı bölge 3 öğe.

4. tur: i = 3. Şimdilik en küçük list[3] = 37 kabul edilir (min = 3).

list[4] = 29 < list[3] = 37 → yeni en küçük: min = 4.

SWAP: list[3] ↔ list[4] → 29 yerine oturdu. Sıralı bölge 4 öğe.

i = n − 1: son öğe kendiliğinden en büyüktür, döngü biter. Toplam 10 = 5·4/2 karşılaştırma.

void sort(int list[], int n) {
  int i, j, min, temp;
  for (i = 0; i < n - 1; i++) {
    min = i;
    for (j = i + 1; j < n; j++)
      if (list[j] < list[min])
        min = j;
    SWAP(list[i], list[min], temp);
  }
}

Seçmeli Sıralama

SWAP: Makro mu, Fonksiyon mu?

Makro (s. 5)

#define SWAP(x, y, t) \
        ((t) = (x), (x) = (y), (y) = (t))

int temp;
SWAP(list[i], list[min], temp);
  • Çağrı maliyeti yok: önişlemci metni yerine koyar.
  • Geçici değişken t dışarıdan verilir.

Fonksiyon (s. 6)

void swap(int *x, int *y) {
  int temp = *x;
  *x = *y;
  *y = temp;
}

swap(&list[i], &list[min]);
  • Tür denetimi var; temp yerel olur.
  • Değişkenlerin adresleri gönderilmelidir.
Dikkat: makro argümanları birden çok kez değerlendirir. SWAP(a[i++], a[j], t) i’yi iki kez artırır! Notlarda fonksiyonun adı da SWAP; makroyla çakışmasın diye burada swap yazdık.

Seçmeli Sıralama · Kodu adım adım çalıştır

Kod İzleme: swap(&a, &b)

main’in çerçevesinde a = 3, b = 8.

Çağrı: değerler değil adresler kopyalanır. x → a, y → b.

temp = *x: x’in gösterdiği yerdeki değer (3) okunur.

*x = *y: y’nin gösterdiği 8, x’in gösterdiği yere, yani a’ya yazılır.

*y = temp: b’ye 3 yazılır. Takas main’in değişkenlerinde gerçekleşti.

swap’ın çerçevesi yok oldu (x, y, temp gitti) ama etkisi kaldı.

void swap(int *x, int *y) {
  int temp = *x;
  *x = *y;
  *y = temp;
}

int main(void) {
  int a = 3, b = 8;
  swap(&a, &b);
  printf("%d %d\n", a, b);
}

Performans Analizi · s. 19

Bellek Karmaşıklığı (Space Complexity)

Programın işini tamamlaması için gereken bellek miktarı: S(P) = c + SP(I)

Sabit kısım c

Girdi/çıktı büyüklüğünden bağımsız: kodun kendisi, basit değişkenler, sabitler.

Değişken kısım SP(I)

I girdisinin özelliklerine (çoğunlukla boyutuna) bağlı kısım. Çözümlemede bununla ilgileniriz.

float abc(float a, float b, float c) {
  return a + b + b * c
         + (a + b - c) / (a + b) + 4.00;
}
/* yalniz sabit bellek: S_abc(I) = 0 */
Hocadan“Her şey kısıtlı imiş gibi kod yazmalısınız. Bellek bol nasıl olsa diye boşa bellek harcayamazsınız.”— Mustafa Ege, VYA1 ders notları

Performans Analizi · s. 19–20

sum ve rsum: Değişken Bellek

float sum(float list[], int n) {
  float tempsum = 0;
  int i;
  for (i = 0; i < n; i++)
    tempsum += list[i];
  return tempsum;
}

float rsum(float list[], int n) {
  if (n)
    return rsum(list, n - 1) + list[n - 1];
  return 0;
}
  • sum’a dizinin ilk öğesinin adresi gider → Ssum(n) = 0. Öğeler değerle kopyalansaydı Ssum(n) = n olurdu.
  • rsum kendini n+1 kez çağırır; her çağrı yığıtta bir çerçeve açar → Srsum(n) ∝ n.

Performans Analizi · s. 21

Zaman Karmaşıklığı (Time Complexity)

T(P) = derleme zamanı + işletim zamanı. Derleme bir kez yapılır; biz işletim zamanı tP ile ilgileniriz.

tP(n) = ca·ADD(n) + cs·SUB(n) + cl·LDA(n) + cst·STA(n)
Sabitler c

Her işlemin süresi: derleyiciye ve makineye bağlı, önceden bilmek zor.

Adım sayısı

Bunun yerine program adımlarını sayarız: makineden bağımsız, anlamlı bir birim.

Performans Analizi · Kodu adım adım çalıştır

Kod İzleme: count ile sum(list, 3)

Global count = 0. Her program adımında bir artacak.

Atama bir adım → count = 1.

for testi 0 < 3 doğru → bir adım (count = 2).

tempsum += list[0] → 3; count = 3.

for testi 1 < 3 doğru → bir adım (count = 4).

tempsum += list[1] → 4; count = 5.

for testi 2 < 3 doğru → bir adım (count = 6).

tempsum += list[2] → 8; count = 7.

Son test 3 < 3 yanlış; o da bir adım → count = 8.

return: count = 9 = 2·3 + 3. Tablodaki 2n + 3 doğrulandı.

float sum(float list[], int n) {
  float tempsum = 0; count++;
  int i;
  for (i = 0; i < n; i++) {
    count++;             /* for testi */
    tempsum += list[i]; count++;
  }
  count++;  /* for'un son testi */
  count++;  return tempsum;
}

  count++;               /* if testi */
  if (n) {
    count++;             /* toplama + return */
    return rsum(list, n - 1) + list[n - 1];
  }
  count++;
  return 0;
}

Büyük O (Big-O) Gösterimi

Tanım: Tüm n ≥ n0 için f(n) ≤ c·g(n) olacak biçimde c > 0 ve n0 sabitleri varsa f(n) = O(g(n)) yazılır: “algoritmanın karmaşıklığı g(n) derecesindedir”.

  • Tsum(n) = 2n + 3 = O(n)
  • Trsum(n) = 2n + 2 = O(n)
  • Tadd = 2·rows·cols + 2·rows + 1 = O(rows·cols) → O(n²)
Hocadan“Zaman, bellekten daha önemli!”— Mustafa Ege, VYA1 ders notları

O bir üst sınırdır; “=” burada “elemanıdır” anlamında tek yönlü okunur. (s. 30)

Amortize Analize Kısa Giriş

Bazı işlemler bazen pahalı, çoğunlukla ucuzdur. Amortize analiz, n işlemlik bir dizinin toplam maliyetini n’e böler. Örnek: doluysa kapasitesi ikiye katlanan dizi (realloc).

1. ekleme: kopyalama yok. Maliyetler şimdiye dek: 1 = 1.

2. ekleme: dizi doluydu: 1 öğe yeni diziye kopyalandı. Maliyetler şimdiye dek: 1 + 2 = 3.

3. ekleme: dizi doluydu: 2 öğe yeni diziye kopyalandı. Maliyetler şimdiye dek: 1 + 2 + 3 = 6.

5. ekleme: dizi doluydu: 4 öğe yeni diziye kopyalandı. Maliyetler şimdiye dek: 1 + 2 + 3 + 1 + 5 = 12.

8. ekleme: kopyalama yok. Maliyetler şimdiye dek: 1 + 2 + 3 + 1 + 5 + 1 + 1 + 1 = 15.

n eklemede kopyalamalar 1 + 2 + 4 + … < 2n → toplam < 3n. Tek bir ekleme O(n) sürebilir, ama ekleme başına amortize maliyet O(1). (Kapasiteyi sabit sayıda artırsaydık O(n) olurdu.)

Sihirli Kare (Magic Square) Problemi

Her satır, sütun ve köşegen: 65

1’den n²’ye kadar sayılar n×n kareye, her satır, sütun ve iki ana köşegenin toplamı eşit olacak biçimde yerleştirilir: toplam n(n²+1)/2 (5×5 için 65).

Coxeter kuralı (n tek): İlk satırın ortasına 1 yaz. Hep sol üst çapraza git; kare doluysa bulunduğun karenin altına in. Tablonun dışına taşarsan karşı kenardan dön (sarmal). n² adımda biter → O(n²).

Kod İzleme: sihirli(3, k)

İlk satırın ortası: i = 0, j = 1 → 1 yazılır.

s = 2: sol üst çapraz (2, 0) boş (satır taştı → en alt satır) → oraya geçilir.

s = 3: sol üst çapraz (1, 2) boş (sütun taştı → en sağ sütun) → oraya geçilir.

s = 4: sol üst çapraz (0, 1) dolu (orada 1 var) → bir aşağı: (2, 2).

s = 5: sol üst çapraz (1, 1) boş → oraya geçilir.

s = 6: sol üst çapraz (0, 0) boş → oraya geçilir.

s = 7: sol üst çapraz (2, 2) dolu (orada 4 var) → bir aşağı: (1, 0).

s = 8: sol üst çapraz (0, 2) boş (sütun taştı → en sağ sütun) → oraya geçilir.

s = 9: sol üst çapraz (2, 1) boş (satır taştı → en alt satır) → oraya geçilir.

s = 10 > 9: döngü biter. Her satır, sütun ve köşegenin toplamı 15 = 3·(9+1)/2.

void sihirli(int n, int k[][MAX]) {
  int i = 0, j = (n - 1) / 2, s, r, c;
  k[i][j] = 1;        /* k sifirlanmis olmali */
  for (s = 2; s <= n * n; s++) {
    r = (i - 1 < 0) ? n - 1 : i - 1; /* yukari */
    c = (j - 1 < 0) ? n - 1 : j - 1; /* sol */
    if (k[r][c]) i = (i + 1) % n; /* in */
    else { i = r; j = c; }
    k[i][j] = s;
  }
}

long fakt(long n) {
  if (n <= 1) return 1;
  return n * fakt(n - 1);
}

long fibo(long n) {
  if (n <= 1) return n;   /* f0 = 0, f1 = 1 */
  return fibo(n - 1) + fibo(n - 2);
}

long komb(int n, int m) {
  if (m == 0 || m == n) return 1;
  return komb(n - 1, m) + komb(n - 1, m - 1);
}

  2. n ≥ 1 için 10n² + 100n + 1000 ≤ 1110n²: c = 1110, n₀ = 1 (başka seçimler de olur).
  3. Yine n(n−1)/2; karşılaştırma sayısı girdiden bağımsızdır (yalnız takas sayısı değişir).
  4. Oran (10⁶·log 10⁶)/(10³·log 10³) = 2000 → ≈ 20 sn.
  5. 10⁶ çerçeve yığıtı taşırabilir (stack overflow); döngülü sum güvenlidir.
  6. Toplam 7·50/2 = 175; ilk satır: 28 19 10 1 48 39 30.

Özet

Bölüm Özeti

Süreç

Gereksinim → çözümleme → tasarım → kodlama → doğrulama. Gerçekleştirimi ertelemek daha iyi seçim sağlar.

Soyutlama

ADT = belirtim ⟂ gerçekleştirim. C’de: başlık dosyası + opak struct.

Sayma

Bellek: c + SP(I). Zaman: program adımları (sum 2n+3, rsum 2n+2).

Sınıflama

O üst, Ω alt, Θ sıkı sınır. En kötü durum garantidir; amortize analiz dizinin toplamına bakar.

Büyüme

Küçük n yanıltır; 2ⁿ ve n! kısa sürede umutsuzlaşır. Algoritma donanımdan önce gelir.

Ölçüm

clock() + tekrar + ortalama; G/Ç ölçüm dışında.
