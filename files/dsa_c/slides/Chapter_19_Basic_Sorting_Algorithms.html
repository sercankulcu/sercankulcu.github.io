Sorting Concepts

Sorting: Records, Keys, Internal/External

  • Records made of fields form a list when kept in memory and a file when kept outside it.
  • The field(s) that identify a record uniquely form the key; sorting is done by key.
  • Internal sorting: all the data is in memory. External sorting: auxiliary storage such as disk or tape is used; the number of disk accesses dominates.

Sorting Concepts

Stability and In-Place Sorting

Stable

Records with equal keys keep their relative order. Sort stably by first name, then by surname, and people with the same surname stay in first-name order (the basis of radix sort).

In-place

Uses only O(1) (by some definitions O(lg n)) extra memory beyond the input. Selection, insertion and bubble sort are in place; counting sort is not (arrays c and b).

A macro trap

Writing the macro as {int t = A; A=B; B=t;} fails to compile inside if (…) SWAP(…); else; do { … } while (0) closes that trap. The idiom if (less(A, B)) SWAP(A, B); swaps when A < B (compare-exchange).

Selection Sort

Selection Sort

void selection(int a[], int L, int R) {
    for (int i = L; i < R; i++) {
        int min = i;
        for (int j = i + 1; j <= R; j++)
            if (less(a[j], a[min]))
                min = j;
        SWAP(a[i], a[min]);
    }
}
  1. Find the smallest element in the list.
  2. Swap it with the element in the first position.
  3. Repeat on the remaining sublist, starting from the 2nd element.
Invariant

After each outer pass, a[L..i] is sorted and holds the smallest elements of the array.

Why scan to the end?

To pick the minimum, the remaining sublist must be scanned to its end, even if the data is already sorted.

Selection Sort

Analysis of Selection Sort

(n−1) + (n−2) + … + 2 + 1 = n(n−1)/2 ≈ n²/2

  • The number of comparisons is independent of the input: best = average = worst ≈ n²/2.
  • The number of exchanges is n − 1: when the last element is reached, it is already in place.
  • Complexity O(n²); O(1) extra memory (in place).
  • Long-distance swaps make it not stable (the earlier 3a/3c example).

Insertion Sort

Insertion Sort: Two Versions

void insertion(int a[], int L, int R) {
    for (int i = L + 1; i <= R; i++) {
        int v = a[i];      // to insert
        int j = i - 1;     // a[L..i-1] sorted
        while (j >= L && a[j] > v) {
            a[j + 1] = a[j]; // shift right
            j--;
        }
        a[j + 1] = v;
    }
}
void insertion1(int a[], int L, int R) {
    for (int i = R; i > L; i--) // sentinel
        if (a[i] < a[i-1]) SWAP(a[i], a[i-1]);
    for (int i = L + 2; i <= R; i++) {
        int v = a[i], j = i;
        while (less(v, a[j - 1])) {
            a[j] = a[j - 1];
            j--;
        }
        a[j] = v;
    }
}
  • Each pass takes one element from the input and inserts it at the right place in the sorted prefix (like arranging playing cards).
  • insertion1 on the right is the improved version of the left one: it first moves the minimum to a[L]; thanks to this sentinel, the inner loop needs no j > L test.
  • Writing the condition as j >= 0 is wrong; if the subarray starts at L > 0 it overruns. The correct test is j >= L.

Insertion Sort

Insertion Sort: Best and Worst Case

Best: Ω(n)

On sorted input, each element is compared only with the rightmost value of the sorted list; it is larger, so it stays put: n − 1 comparisons in total.

Worst: O(n²)

On reverse-sorted input, each element is compared with the whole sorted list and inserted at the far left; the sorted part shifts right every pass: 1 + 2 + … + (n−1) = n(n−1)/2.

Insertion sort is stable (a[j] > v is strict, so equal elements are not passed) and in place. On nearly sorted data it is almost linear.

Insertion Sort

Average-Case Analysis: The Possible Cases for j = 3

Case 1: 8 > 10 is false → 1 comparison.

Case 2: 8 > 7 true, 6 > 7 false → 2 comparisons.

Case 3: 8 > 5 true, 6 > 5 true, 3 > 5 false → 3 comparisons.

Case 4: 8 > 2, 6 > 2, 3 > 2 all true; at j = −1, j >= 0 is false and a[j] > v is never tested, so it costs the same as the previous case → 3 comparisons.

Element j lands in one of j + 1 positions: 1 comparison in 1 case, 2 in 1 case, 3 in 2 cases. The cases are equally likely; only the last count, “3 comparisons”, occurs twice. Average: (1 + 2 + 3 + 3)/4 = 2.25.

Insertion Sort

Average Case: The Expected Number of Comparisons

E(Cj) = (1/(j+1))·[2j + Σk=1j−1 k] = (j+2)/2 − 1/(j+1)

E(Y) = Σj=1N−1 E(Cj) = (N² + 3N)/4 − HN ≈ N²/4

  • Cj, the number of comparisons to insert element j, is a random variable; E(Cj) is its expected value.
  • HN = 1 + 1/2 + … + 1/N is the harmonic number: HN = ln N + O(1).
  • On average ≈ N²/4 comparisons and ≈ N²/4 half-exchanges (shifts, not swaps) → O(n²).

Bubble Sort

Bubble Sort

void bubble(int a[], int L, int R) {
    int i, j;
    for (i = L; i < R; i++)
        for (j = R; j > i; j--)
            if (a[j] < a[j-1]) SWAP(a[j], a[j-1]);
}
Instructor “It can be coded more carefully so that it exits at once if the array is sorted. If a whole pass makes no swaps, there is no need for the next pass.”

Start: [7, 2, 9, 5, 1]. Each pass compares neighbors from right to left.

Pass i = 0: the smallest remaining value 1 bubbles up to a[0] → [1, 7, 2, 9, 5].

Pass i = 1: the smallest remaining value 2 bubbles up to a[1] → [1, 2, 7, 5, 9].

Pass i = 2: the smallest remaining value 5 bubbles up to a[2] → [1, 2, 5, 7, 9].

Pass i = 3: no swap; the smallest remaining value 7 is already in a[3] → [1, 2, 5, 7, 9].

Bubble Sort · Step through the code

Code Trace: bubble2(a, 0, 4) with Early Exit

Pass i = 0 begins; the swap flag is cleared.

a[4] < a[3] → swap: [2, 1, 3, 4, 5]; swapped = 1.

a[3] = 4 ≥ a[2] = 3 → no swap.

a[2] = 3 ≥ a[1] = 1 → no swap.

a[1] < a[0] → swap: [1, 2, 3, 4, 5]; swapped = 1.

swapped = 1 → the array cannot be assumed sorted yet; go to the next pass.

Pass i = 1 begins; the swap flag is cleared.

a[4] = 5 ≥ a[3] = 4 → no swap.

a[3] = 4 ≥ a[2] = 3 → no swap.

a[2] = 3 ≥ a[1] = 2 → no swap.

No swap in this pass → the array is sorted; early exit. Two useless passes were skipped.

void bubble2(int a[], int L, int R) {
    for (int i = L; i < R; i++) {
        int swapped = 0;    // any swap this pass?
        for (int j = R; j > i; j--)
            if (less(a[j], a[j - 1])) {
                SWAP(a[j], a[j - 1]);
                swapped = 1;
            }
        if (!swapped) return; // sorted: exit early
    }
}

Bubble Sort

Analysis of Bubble Sort

  • Comparisons: n(n−1)/2 ≈ n²/2 in every case (without early exit).
  • Exchanges: n²/2 in the worst case (reverse sorted); on average as many as the inversions, ≈ n²/4.
  • Complexity O(n²); the early-exit version is O(n) on sorted input.
  • Only neighbors are swapped and equal elements never are → stable, in place.

Bubble Sort

Inversions: a Common Measure

Inversion: a pair with i < j and a[i] > a[j]. [7, 2, 9, 5, 1] → (7,2), (7,5), (7,1), (2,1), (9,5), (9,1), (5,1)

  • A neighbor swap (bubble) or a one-position shift (insertion) removes exactly one inversion.
  • So in both, the number of swaps/shifts = the number of inversions: 7 for this array (the traces also made 7 shifts).
  • A reverse-sorted array has n(n−1)/2 inversions; a random one has n(n−1)/4 on average (each pair is inverted with probability ½).
  • Every algorithm that works on neighbors is Ω(n²) on average: Shell sort and quicksort, with long-distance swaps, break through this wall.

Counting Sort

Counting Sort

int counting_sort(const int a[], int b[],
                  int r, int k) {
    int *c = malloc((k + 1) * sizeof *c);
    if (c == NULL) return -1;
    for (int i = 0; i <= k; i++) c[i] = 0;  // L1
    for (int j = 0; j <= r; j++) c[a[j]]++; // L2
    for (int i = 1; i <= k; i++)            // L3
        c[i] += c[i - 1];
    for (int j = r; j >= 0; j--) {          // L4
        b[c[a[j]] - 1] = a[j];
        c[a[j]]--;
    }
    free(c);
    return 0;
}

void shell_sort(int a[], int n) {
    for (int h = n / 2; h > 0; h /= 2) // gap
        for (int i = h; i < n; i++) {
            int v = a[i], j = i;
            while (j >= h && a[j - h] > v) {
                a[j] = a[j - h];    // shift back h
                j -= h;
            }
            a[j] = v;
        }
}

Shell and Bucket Sort

Shell Sort (1959)

  • The weakness of insertion sort: an element moves only one position at a time; O(n²) on reverse-sorted input.
  • Shell: first sort distant elements (gap h), then shrink h; the last pass uses h = 1, so the result is always correct.
  • The cost depends on the gap sequence: worst case O(n²) for h = n/2, n/4, … (Shell's); O(n3/2) for Knuth's 1, 4, 13, 40, …
  • In place, but long-distance moves make it not stable.
Combined use

When properties of the data are known, Shell sort and bucket sort can be used together.

In practice

Short code and good practical speed: a favorite in embedded systems and for small to medium arrays.

Shell and Bucket Sort

Bucket Sort

Input: 10 numbers in [0, 1); 10 buckets, each 0.1 wide.

Distribute: value x goes into bucket ⌊10·x⌋ (e.g. .78 → 7, .17 → 1). O(n).

Each bucket is sorted on its own (by insertion sort): cheap, since buckets are small.

Concatenate the buckets in order → sorted output. O(n) on average for a uniform distribution.

If the input is uniformly distributed over the range, each bucket holds O(1) elements on average → O(n) on average (CLRS). If everything falls into one bucket, the worst case is the cost of sorting within the bucket (O(n²) with insertion sort). Extra memory O(n + number of buckets).

Shell and Bucket Sort

Bucket Sort: An Implementation in C

typedef struct bnode { double x; struct bnode *next; } bnode;

int bucket_sort(double a[], int n) {        /* 0 <= a[i] < 1 */
    bnode **bucket = calloc(n, sizeof *bucket);
    bnode *pool = malloc(n * sizeof *pool);
    if (!bucket || !pool) { free(bucket); free(pool); return -1; }
    for (int i = 0; i < n; i++) {           /* scatter + sorted insert */
        bnode **p = &bucket[(int)(a[i] * n)];
        while (*p && (*p)->x <= a[i]) p = &(*p)->next;
        pool[i].x = a[i]; pool[i].next = *p; *p = &pool[i];
    }
    int k = 0;                              /* gather the buckets */
    for (int b = 0; b < n; b++)
        for (bnode *q = bucket[b]; q; q = q->next) a[k++] = q->x;
    free(bucket); free(pool);
    return 0;
}
  • n buckets; the value a[i] is inserted in order into linked list ⌊a[i]·n⌋ (insertion sort within the bucket).
  • Thanks to <=, equal values go to the end → stable. The nodes come from a single pool array: two allocations instead of n separate mallocs, and one pair of frees.

Optimal Sorting Time

Optimal Sorting Time: The Decision Tree

Tests are ellipses, decisions (orderings) rectangles. For n = 3 there are 3! = 6 leaves.

Input a = 5, b = 8, c = 2. Root: a < b? 5 < 8 → yes.

b < c? 8 < 2 → no: c must come before b.

a < c? 5 < 2 → no.

Leaf c < a < b → 2, 5, 8. For this input, 3 comparisons = the length of the path.

Every comparison sort is a decision tree: each internal node is a less() call, each leaf an ordering of the input. The worst-case number of comparisons = the tree's height.

Optimal Sorting Time

Theorem: The Lower Bound for Comparison Sorting

Theorem. Every decision tree that sorts n distinct elements has depth (number of levels) at least ⌈log₂(n!)⌉ + 1; so in the worst case at least ⌈lg(n!)⌉ comparisons are needed.
  • There are at least n! leaves (one per ordering).
  • A binary tree of height h has at most 2h leaves: 2h ≥ n! ⇒ h ≥ lg(n!).
  • Stirling: ⌈lg(n!)⌉ = n lg n − n lg e + Θ(lg n) ≈ n lg n − 1.4427 n.
  • Result: comparison sorting is Ω(n lg n); counting, bucket and radix sort make no comparisons, so the bound does not apply to them.

Summary

Which One When?

Swaps/writes are expensive

Selection: exactly n − 1 swaps.

Small or nearly sorted

Insertion: stable, in place, O(n) when nearly sorted; also used on the small pieces in quicksort.

Teaching / sortedness test

Bubble with early exit: detects a sorted array in one pass; rarely used in production.

Small integer range

Counting: O(n + k), stable; if k ≫ n, memory and time are wasted.

Medium size, no extra memory

Shell: a few lines of code, clearly faster than O(n²).

Uniform on [0,1)

Bucket: O(n) on average.

Common Mistakes

1Keeping the minimum value in selection sort: the swap needs its index (min).
2Not saving v = a[i] before shifting in insertion sort: the first shift overwrites a[i].
3Writing j >= 0: for a subarray a[L..R] the bound is j >= L.
4Getting the direction wrong in if (less(A, B)) SWAP(A, B): it swaps when A < B.
5Ignoring k in counting sort: a negative value or one above k writes outside c[].
6Running L4 of counting sort left to right: it still sorts, but stability is lost.

Chapter Summary

Three O(n²) algorithms

Same class, different character: selection makes few swaps, insertion is fast on nearly sorted data, bubble can stop early.

Average case

The expected value over all n! orderings: ≈ n²/4 comparisons for insertion. Not the mean of best and worst!

Non-comparison

Counting O(n+k) and bucket O(n) on average: knowledge of the data (range, distribution) buys speed.

Concepts

Stability (order of equal keys) and in-place operation (extra memory) drive the choice of algorithm.

Shell

Insertion sort with gaps; the final pass with h = 1 guarantees correctness.

Lower bound

Comparison sorting cannot beat ⌈lg n!⌉ ≈ n lg n comparisons → the touchstone for advanced sorting algorithms.
