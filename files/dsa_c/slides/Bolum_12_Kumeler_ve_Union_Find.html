Ayrık Kümeler

Kümelerde birleşim (union) ve bulma (find)

Evren {0, 1, …, n−1}; kümeler ikili ayrık (pairwise disjoint): S₁ ∩ S₂ = S₂ ∩ S₃ = S₁ ∩ S₃ = ∅. n = 10 için:

Her küme bir ağaçtır; bağlar çocuklardan atalara doğrudur (oklar yukarı).

Hocadan“Çok çok temel bir veri yapısıdır, ama birçok problemde kullanırız. Öğrenmelisin ki, kullanabilesin.”— Mustafa Ege, VYA2 ders notları, s. 33

Ayrık Kümeler

İki işlem ve birleşimin iki biçimi

1 · Ayrık küme birleşimi

Si ∪ Sj = {x : x ∈ Si ∨ x ∈ Sj}. Birleşme sonrası kümeler bağımsız olarak bulunmaz: S₁ ∪ S₂ = {0, 6, 7, 8, 1, 4, 9}.

2 · Küme_bul(i)

i öğesini içeren kümeyi bulur (kümenin adı = ağacın kökü).

Kökler 0, 4, 2. Birleşim için köklerden birinin ata bilgisi diğer kökü gösterecek şekilde günlenir.

S₁ ∪ S₂: 4'ün atası 0 yapılır; S₂ ağacı 0'ın alt ağacı olur.

S₂ ∪ S₁: bu kez 0'ın atası 4 yapılır. İkisi de doğrudur; hangisinin seçileceği maliyeti etkiler.

Ayrık Kümeler

Kümenin adı: kök düğüm

Küme adıbağ (kök)
S₁→ 0
S₂→ 4
S₃→ 2

Adlar metin olarak gerekiyorsa ayrı bir tabloda kökü gösteren bir bağ tutulur.

Birleşim ve Küme_bul algoritmalarını incelerken her küme adını ağacın kökü ile ilişkilendireceğiz: “S₁ kümesi” yerine “0 nolu küme” diyeceğiz.

Böylece Küme_bul(8) == Küme_bul(6) sorusu “8 ile 6 aynı kümede mi?” demektir.

Hocadan“Bakın! Önce problemi bir matematikçi gibi, programlama bilmeyen birisi gibi ele alıyoruz; öncelikle problemi çizge teorisindeki terminoloji ile doğru ifade edebilmeliyiz.”— Mustafa Ege, VYA2 ders notları, s. 33

Küme_bul(i)

Ata bilgisi negatif bir değer olana (köke) dek ilerler; kökü döndürür.

Birleşim(i, j)

i ve j kümeleri (kökleri) aktarıldıktan sonra biri diğerinin alt ağacı olacak şekilde günlenir: O(1).

Ön koşul

i ve j kök olmalıdır; değilse önce Kume_Bul_1 ile kökler bulunur.

Kume_Bul_1(9): 9 hangi kümede?

ata[9] = 4 ≥ 0 → i = ata[i] = 4.

ata[4] = −1 < 0: kök. return 4 → 9, 4 nolu kümede.

return 0: artık 9, 0 nolu kümede. Maliyet = düğümün derinliği.

Ağırlıklı Kural

Ağırlıklı kural (weighting rule)

Tanım: i ağacındaki düğüm sayısı j ağacındakinden azsa j, i'nin atası; aksi hâlde i, j'nin atası yapılır. (Düğüm sayısı çok olan ata olur.)

Hocadan“Sual: Acaba her kümede (ağaçta) kaç düğüm olduğu bilgisi için ayrı bir dizi mi tutmamız gerekir? El-Cevap: Kökler dışındaki tüm düğümler için ata dizisinde pozitif değerler tutuluyordu. Öyleyse köklere ilişkin düğüm sayısı bilgisi de ata dizisinde negatif olarak tutulabilir.”— Mustafa Ege, VYA2 ders notları, s. 34

Ağırlıklı Kural

Birlesim_2: kökte eksi düğüm sayısı

void Birlesim_2(int i, int j) {
  /* ağırlıklı kural; i ve j kök olmalı */
  int p = ata[i] + ata[j];  /* -(toplam düğüm) */
  if (ata[i] > ata[j]) {    /* i'de daha az düğüm */
    ata[i] = j;             /* i'yi j'ye bağla */
    ata[j] = p;             /* j'nin sayısını günle */
  } else {                  /* j'de az ya da eşit */
    ata[j] = i;
    ata[i] = p;
  }
}
Kökte −sayı

Kökteki değer −(düğüm sayısı): tek öğeli küme −1, 8 öğeli küme −8.

Neden >?

Değerler negatif: ata[i] > ata[j], i'nin daha az düğümü olduğu anlamına gelir (−2 > −4).

Maliyet

Hâlâ O(1); ek dizi gerekmez.

Ağırlıklı Kural

Lemma: ağırlıklı birleşimle derinlik logaritmiktir

Lemma (VYA2 s. 35; Horowitz)T, Birlesim_2 ile çeşitli kümelerin birleşimi sonucu elde edilmiş m düğümlü bir ağaç ise T'nin derinliği (düzey sayısı) ⌊lg m⌋ + 1'den büyük olamaz.
  • İspat fikri (tümevarım): bir düğümün derinliği yalnızca onun ağacı daha küçük ya da eşit bir ağaca bağlanınca 1 artar.
  • O zaman düğümün yer aldığı ağaç en az iki katına çıkar.
  • m düğüme en çok lg m kez iki katına çıkılabilir → derinlik ≤ ⌊lg m⌋ + 1.
Hocadan“Matematik bölümü olsaydık ‘İspatlayınız.’ diye soru devam edecekti. […] Bakın, karmaşıklığı n'den ⌊lgn⌋+1'e düşürdük. Algoritma geliştirme bu, işte! Ama yerimizde durmuyoruz, devam…”— Mustafa Ege, VYA2 ders notları, s. 35

Azaltma Kuralı

Azaltma kuralı (collapsing rule)

Son durumdaki yapıda Küme_bul(7) köke 3 ilerlemede ulaşır. Program Küme_bul(7)'yi tekrar tekrar işletirse maliyet katlanır. Düğüm sayısı az olanı çok olana eklesek bile derinlik artabiliyor; derinliği denetleyemediğimize göre bir adım ileri gideriz:

TanımEğer j, i düğümünden köke olan yol üzerinde bir düğüm ise (i kök değil) j düğümü doğrudan köke bağlanır.
Hocadan“Bunun graf teorideki karşılığı ‘kaplama’ ya da ‘kapama’. Graf teori ödevlerinden birinde, ben söylemeyeceğim, ama siz bunu kullanmalısınız. Problem farklı, alt yapısı bu.”— Mustafa Ege, VYA2 ders notları, s. 35

Azaltma Kuralı

Kume_bul_2: önce kökü bul, sonra yolu köke bağla

int Kume_bul_2(int i) {
  int r, s;
  for (r = i; ata[r] >= 0; r = ata[r])
    ;                   /* kökü bul */
  while (i != r) {      /* yolu azalt */
    s = ata[i];         /* i'nin atasını sakla */
    ata[i] = r;         /* i'yi doğrudan köke bağla */
    i = s;              /* atasına geç */
  }
  return r;
}
1. geçiş (for)

r kökü bulur (ata bilgisi negatif).

2. geçiş (while)

Yol üzerindeki her düğüm doğrudan r'ye bağlanır. Köke zaten bağlı bir düğüm için de (gereksiz ama zararsız) bir kez çalışır.

Kazanç

Aynı yoldaki sonraki aramalar bir çırpıda köke ulaşır.

Azaltma Kuralı

Lemma (Tarjan ve van Leeuwen): neredeyse sabit

Lemma (VYA2 s. 36)Her biri tek düğümlü kümelerle başlanıp f küme bulma ve u birleştirme (ağırlıklı kural + azaltma kuralı) herhangi bir karışık sırada uygulandığında gereken en çok zaman T(f, u) olsun. u ≥ n/2 için:

k₁·(n + f·α(f+n, n)) ≤ T(f, u) ≤ k₂·(n + f·α(f+n, n))

  • α: ters Ackermann fonksiyonu; çok yavaş artar.
  • Evrendeki atom sayısı kadar öğe için bile uygulamada α ≤ 4.
  • İşlem başına maliyet n'e bölünce neredeyse O(1).
/* Ackermann: çok hızlı büyür */
A(m, n) = n + 1                  m = 0
        = A(m-1, 1)              m > 0, n = 0
        = A(m-1, A(m, n-1))      m > 0, n > 0
Hocadan“Düşünün; 1 milyon eleman var, ben O(1)'de buluyorum, sen daha arıyorsun listede… Hani dedik ya, aynı işe girecek olan matematikçi ile mühendisin farkı budur işte!”— Mustafa Ege, VYA2 ders notları, s. 36

  • Ters: α(m, n) = min{ i ≥ 1 : A(i, ⌊m/n⌋) ≥ lg n } — A çok hızlı büyüdüğü için α çok yavaş büyür.

Not: Notlardaki “A(3,4) = 16” ifadesi yukarıdaki tanımla uyuşmaz (bu tanımla A(3,4) = 125); Horowitz'in kullandığı farklı Ackermann tanımında (A(1,j) = 2j …) A(3,1) = 16'dır. Sonuç değişmez: uygulamada α ≤ 4.

Sınav sorusu: Ackermann fonksiyonunu özyineli yazınız

Final sorusu (VYA2 s. 36)Ackermann fonksiyonunu özyineli olarak yazınız. Ardından A(1, 2) çağrısının çağrı yığınını adım adım gösteriniz.
Çözüm
unsigned long ackermann(unsigned long m,
                        unsigned long n) {
  if (m == 0) return n + 1;
  if (n == 0) return ackermann(m - 1, 1);
  return ackermann(m - 1, ackermann(m, n - 1));
}

A(1,2) = A(0, A(1,1)) = A(0, A(0, A(1,0))) = A(0, A(0, A(0,1))) = A(0, A(0, 2)) = A(0, 3) = 4. Uyarı: A(4, 2) bile hiçbir bilgisayarda bitmez; yığın taşar.

Uygulama · kodu adım adım çalıştır

Kod izleme: bağlı bileşen sayma

Kenarlar u–v: (0,1), (2,3), (1,4), (3,2). Kaç bağlı bileşen var?

Her düğüm kendi kümesi: ata = −1, sayi = 6.

Kenar (0, 1): Kume_bul_2(0) = 0, Kume_bul_2(1) = 1.

0 ≠ 1: farklı bileşenler → Birlesim_2(0, 1), sayi = 5.

Kenar (2, 3): Kume_bul_2(2) = 2, Kume_bul_2(3) = 3.

2 ≠ 3: farklı bileşenler → Birlesim_2(2, 3), sayi = 4.

Kenar (1, 4): Kume_bul_2(1) = 0, Kume_bul_2(4) = 4.

0 ≠ 4: farklı bileşenler → Birlesim_2(0, 4), sayi = 3.

Kenar (3, 2): Kume_bul_2(3) = 2, Kume_bul_2(2) = 2.

a == b = 2: 3 ile 2 zaten aynı bileşende; kenar bir çevrim kapatır, sayı değişmez.

return 3: bileşenler {0,1,4}, {2,3}, {5}. Toplam O(n + m·α).

int bilesen_say(int n, int m, int u[], int v[]) {
  for (int i = 0; i < n; i++) ata[i] = -1;
  int sayi = n;               /* her düğüm ayrı */
  for (int e = 0; e < m; e++) {
    int a = Kume_bul_2(u[e]), b = Kume_bul_2(v[e]);
    if (a != b) {             /* farklı bileşen */
      Birlesim_2(a, b);
      sayi--;
    }
  }
  return sayi;
}

Kruskal'a ön bakış: çevrim denetimi = Küme_bul

Kenarları ağırlığa göre sırala; her düğüm ayrı küme.

0–1 (1): Küme_bul(0) = 0 ≠ Küme_bul(1) = 1 → ekle, birleştir.

2–3 (2): Küme_bul(2) = 2 ≠ Küme_bul(3) = 3 → ekle, birleştir.

0–2 (3): Küme_bul(0) = 0 ≠ Küme_bul(2) = 2 → ekle, birleştir.

1–2 (4): ikisi de 0 kümesinde → çevrim oluşturur, reddet.

1–3 (5): ikisi de 0 kümesinde → çevrim oluşturur, reddet.

3–4 (6): Küme_bul(3) = 0 ≠ Küme_bul(4) = 4 → ekle, birleştir.

n − 1 = 4 kenar seçildi: minimum yayılım ağacı, toplam ağırlık 12.

2009 Ara Sınav 2 · Soru 2 (VYA2 s. 86) — veriler notlardaki kümelerle yeniden kurulmuşturBirlesim_2 ve Kume_bul_2 verilmiştir; kümeler S₁ = {0, 6, 7, 8}, S₂ = {1, 4, 9}, S₃ = {2, 3, 5} (şekildeki ağaçlar).

Sık yapılan hatalar

1Birleşime kök yerine rastgele düğüm vermek: ata[i] = j i'nin alt ağacını koparır.
2Aynı kümedeki iki kökü birleştirmek (i == j): kök kendini gösterir, sonsuz döngü.
3Ağırlıklı kuralda negatif değerlerin karşılaştırmasını ters yorumlamak (−2 > −4 “daha az düğüm”).
4Birleşimde kökteki düğüm sayısını (p) günlemeyi unutmak.
5Kume_bul_2'de atayı saklamadan (s) bağlamak: yol kaybolur.
6Başlangıçta ata dizisini −1 ile doldurmamak.

Özet

Alıştırmalar

  1. n = 6, ata tümüyle −1. Birlesim_2(0,1); Birlesim_2(2,3); Birlesim_2(0,2); Birlesim_2(4,5) sonrası ata?
  2. Ağırlıklı kural kullanılırken 16 düğümlü bir ağacın derinliği en çok kaçtır?
  3. Ağırlık yerine yükseklik (rank) tutan bir birleşim kuralı yazın. Ne değişir?
  4. Kume_bul_2'yi özyineli yazın (tek satırlık yol sıkıştırma).
  5. Kruskal'da bir kenarın reddedilmesi neden çevrim demektir?
  6. n düğüm, m kenarlı bir çizgede bileşen sayısını bulmanın maliyeti nedir?
Cevapları göster
  1. [-4, 0, 0, 2, -2, 4] (0 kökünde 4 düğüm; 4 kökünde 2).
  2. ⌊lg 16⌋ + 1 = 5 düzey.
  3. Kökte −(yükseklik) tutulur; eşitse biri bağlanır ve yükseklik 1 artar. Derinlik yine O(lg n); azaltma ile rank üst sınır olur.
  4. int bul(int i) { return ata[i] < 0 ? i : (ata[i] = bul(ata[i])); }
  5. Uçlar zaten aynı kümede, yani aralarında seçilmiş kenarlardan oluşan bir yol var; kenar yolu çevrime kapatır.
  6. O(n + m·α(m+n, n)) — pratikte doğrusal.

Bölüm özeti

Model

Ayrık kümeler = kökü küme adı olan, çocuktan ataya bağlı ağaçlar.

Gösterim

Tek ata dizisi; kökte negatif değer.

Kötü durum

Rastgele bağlama zincir üretir: n bulma O(n²).

Ağırlıklı kural

Küçük ağaç büyüğe: derinlik ≤ ⌊lg m⌋ + 1.

Azaltma kuralı

Yol köke bağlanır; sonraki aramalar bir çırpıda.

Sonuç

İkisi birlikte: işlem başına α ≤ 4 — neredeyse O(1).
