Multiple Choice · Quicksort

Question 1: Result of partition

a = [6, 2, 9, 1, 8, 5]: partition(a, 0, 5) is called. What happens to the array, and which value is returned?

A: Pivot v = 5. i stops at 6 (position 0), j stops at 1 (position 3) → swap: [1, 2, 9, 6, 8, 5]. Then i stops at 9 (2), j at 2 (1); the indices have crossed. The pivot is swapped with a[2]: [1, 2, 5, 6, 8, 9], returns 2. Left ≤ 5 ≤ right; on this input the right part also happened to stay sorted.

Step-by-Step Trace · Quicksort

Question 2: Items Equal to the Pivot

a = [3, 8, 3, 1, 3]: partition(a, 0, 4) is traced. What do the scans do at items equal to the pivot, and what is the return value?

Pivot v = a[4] = 3. The array has two more items equal to the pivot.

a[0] = 3: 3 < 3 is false → i stops at 0. An equal item also stops i.

a[3] = 1: 3 < 1 is false → j stops at 3.

i < j → swap: [1, 8, 3, 3, 3].

i stops at 8 (1); j stops at the equal item 3 (2): 3 < 3 is false.

Swap: [1, 3, 8, 3, 3]. An equal 3 moved to the left.

i stops at 8 (2), j at 3 (1): i ≥ j, the loop exits.

The pivot goes to a[2]: [1, 3, 3, 3, 8], returns 2. The equal items were spread over both sides and the split fell in the middle; this is why stopping at equal items is useful.

int partition(int a[], int L, int R) {
    int i = L - 1, j = R, v = a[R]; // pivot a[R]
    for (;;) {
        while (less(a[++i], v))
            ;
        while (less(v, a[--j]))
            if (j == L) break;
        if (i >= j) break;
        SWAP(a[i], a[j]);
    }
    SWAP(a[i], a[R]);
    return i;
}

Multiple Choice · Quicksort

Question 3: All Equal

All 1024 items are equal. Which statement is true for quicksort1?

C: less(a[++i], v) and less(v, a[--j]) are false for equal items; both scans stop at every item, swap, and meet in the middle. The instrumented program gave 9218 comparisons and a depth of 11 levels; for sorted 1024 items, 525,822 comparisons and 1024 levels.

Classic Question · Quicksort

Question 4: Counting on Sorted Input

quicksort1 is called on the sorted array [1, 2, 3, 4, 5, 6]. How many partition calls are made and how many comparisons are made in partition? In total, how many quicksort1 calls are there, and at most how many quicksort1 frames are on the call stack at the same time?

Show answer
  • The pivot is always the largest of the piece and stays in place; for sizes 6, 5, 4, 3, 2 there are 5 partition calls.
  • In a piece of m items the i scan goes up to a[R] in m comparisons and the j scan stops at the first comparison: m + 1. Total: 7 + 6 + 5 + 4 + 3 = 25.
  • Each partition spawns two calls: 1 + 2·5 = 11 calls (all the right-hand ones are empty).
  • The left calls nest with 6, 5, 4, 3, 2, 1 items: at most 6 frames.

In general ≈ n²/2 comparisons and depth n: for large n the stack can overflow (verified with the instrumented program).

Spot the Bug · Quicksort

Question 5: The j == L Check

In this partition version the check in the j loop has been deleted. Consider a = [5, 7, 6, 1]: partition(a, 0, 3). What does it do? Why is the same check not needed in the i loop?

int partition(int a[], int L, int R) {
    int i = L - 1, j = R, v = a[R];
    for (;;) {
        while (less(a[++i], v))
            ;
        while (less(v, a[--j]))
            ;
        if (i >= j) break;
        SWAP(a[i], a[j]);
    }
    SWAP(a[i], a[R]);
    return i;
}
Show answer

Pivot v = 1, the smallest of the array. i stops at a[0] = 5. j passes 6, 7, 5 (all greater than 1) and, with a[--j], a[−1]is read: an out-of-bounds access, undefined behavior. The scan may keep reading until some random value stops it, and the swap may even write outside the array.

The i scan is unprotected but safe: at the latest at i = R, with a[R] = v, less(v, v) is false and the scan stops. There is no such guard at the left end; if (j == L) break; is needed. In the median-of-3 version a[L] ≤ pivot, so the guard is there naturally.

Question 6: Quick Sort with an Explicit Stack

quicksort2(a, 0, 6), a = [3, 7, 1, 6, 2, 5, 4]. Which (L, R) pairs are pushed and popped, and in what order? At most how many pairs wait on the stack?

The first problem (0, 6) is pushed: first R = 6, then L = 0; L is on top.

(0,6) popped: partition → pivot 4 goes to position 3. The parts are equal (3 and 3): first the right (4,6), then the left (0,2) are pushed; the smaller or equal part is on top.

(0,2): pivot a[2] = 1 is the smallest and goes to position 0; the array is [1, 2, 3, …]. The right part (1,2) is larger → pushed first, then the empty left part (0,−1).

(0,−1) popped: empty range → continue.

(1,2): pivot 3 goes to position 2. The left part (1,1) is larger → pushed first, then the empty right part (3,2).

(3,2) popped: empty range → continue.

(1,1) single item → continue. The left half a[0..3] is done.

(4,6): partition → [.., 5, 6, 7], pivot 6 goes to position 5. Equal parts: (6,6), then (4,4) are pushed.

(4,4) single item → continue.

(6,6) was skipped too; the stack is empty: [1, 2, 3, 4, 5, 6, 7]. At most 3 (L, R) pairs (6 ints) waited on the stack at the same time.

void quicksort2(int a[], int L, int R) {
  stack_init(); push2(L, R);
  while (!stack_empty()) {
    L = pop(); R = pop();
    if (R <= L) continue;
    int i = partition(a, L, R);
    if (i - L > R - i) {   /* larger first */
      push2(L, i - 1);
      push2(i + 1, R);
    } else {
      push2(i + 1, R);
      push2(L, i - 1);
    }
  }
}

Multiple Choice · Improving Quicksort

Question 7: If the Smaller Part Is Pushed First

quicksort2: the branch condition is reversed, so the smaller part is pushed first (at the bottom) and the larger part last (on top). What happens on 1000 sorted items?

B: On sorted input every split yields an empty part and a part of n − 1 items. With the large part left on top and processed at once, the empty parts pile up at the bottom: one pair per level. In the instrumented run the stack reached 2000 ints (4 in the correct version); with STACK_MAX = 64, UBSan reported an array-bound error. Processing the smaller part first keeps the depth at O(lg n).

Question 8: Comparison by Subtraction

qsort comparator is written as shown below. If the array contains INT_MIN and 1, what happens?

int diff(const void *p, const void *q) {
    return *(const int *)p - *(const int *)q;
}
/* qsort(a, n, sizeof a[0], diff); */

D: Signed overflow is undefined; in practice the result wraps around to a large positive number and INT_MIN is considered greater than 1. The UBSan of zig cc stopped on this line with "signed integer overflow". The safe idiom is (x > y) - (x < y). B is wrong: the subtraction is done on values converted to int.

Coding Question · The C Library and Hybrids

Question 9: A Two-Key Comparator

typedef struct { char name[12]; int grade; } student; is the record type. To sort an array of it using qsort first by grade in descending order and, for equal grades, alphabetically by name, write the comparator int by_grade_then_name(const void *p, const void *q). What is the result for (Can 85), (Ali 70), (Banu 85), (Ece 90), (Deniz 70)?

Show answer 
int by_grade_then_name(const void *p, const void *q) {
  const student *x = p, *y = q;
  if (x->grade != y->grade) /* by grade, desc. */
    return (y->grade > x->grade) -
           (y->grade < x->grade);
  return strcmp(x->name, y->name); /* by name */
}

Result: Ece 90, Banu 85, Can 85, Ali 70, Deniz 70.

qsort is not stable; if the order of equal items matters, a secondary key is added to the comparator. The conversion void * → const student * is performed implicitly in C; no subtraction, with its overflow risk, was used.

Multiple Choice · The C Library and Hybrids

Question 10: Introsort

Introsort starts as quicksort. What does it do on a piece whose recursion depth exceeds ≈ 2⌊lg n⌋?

C: When the depth limit is exceeded, the piece is sorted with heap sort; since heap sort is in place and O(n lg n) in the worst case, the overall worst case stays O(n lg n). Insertion sort is used only on small pieces (A would be O(n²) on a large piece); merge sort needs extra memory.

Question 11: merge with a Reversed Copy

a = [2, 6, 8, 9, 1, 5, 7]: merge(a, b, 0, 3, 6) is called. How is b filled, and where do i and j point at each step?

Left half a[0..3] = 2 6 8 9, right half a[4..6] = 1 5 7; both are sorted.

The left half is copied into b[0..3] as it is; the loop exits with i = L = 0.

The right half is copied into b[4..6] in reverse: b increases from both ends toward the middle. j = R = 6.

b[j] = 1 < b[i] = 2 → a[0] = 1; j--.

b[j] = 5 ≥ b[i] = 2 → a[1] = 2; i++.

b[j] = 5 < b[i] = 6 → a[2] = 5; j--.

b[j] = 7 ≥ b[i] = 6 → a[3] = 6; i++.

b[j] = 7 < b[i] = 8 → a[4] = 7; j--.

b[j] = 9 ≥ b[i] = 8 → a[5] = 8; i++.

b[j] = 9 ≥ b[i] = 9 → a[6] = 9; i++. In the last step i = 4 and j = 3 met in the middle; since the largest item is 9, no bound check was needed.

void merge(int a[], int b[], int L, int m, int R) {
    int i, j, k;
    for (i = m + 1; i > L; i--) b[i - 1] = a[i - 1];
    for (j = m; j < R; j++) b[R + m - j] = a[j + 1];
    for (k = L; k <= R; k++)
        if (less(b[j], b[i]))
            a[k] = b[j--];
        else
            a[k] = b[i++];
}

Multiple Choice · Merge Sort

Question 12: Counting on 12 Items

mergesort(a, b, 0, 11) on 12 items makes how many mergesort calls and how many merge calls? Since this merge makes one comparison per item, what is the total number of comparisons?

A: The number of calls is 2n − 1 = 23, the number of merges n − 1 = 11. Each merge makes R − L + 1 comparisons: 12 → 6 + 6 → 3 + 3 + 3 + 3 → each 3 is split into 2 + 1. The levels give 12 + 12 + 12 + 8 (four two-item merges) = 44 (verified with a counter).

Coding Question · Merge Sort

Question 13: Stable merge

The reversed-copy (bitonic) merge is not stable. Write the routine that merges the sorted a[L..m] and a[m+1..R] left to right in a temporary array, taking, on a tie, the left item: int merge_stable(int a[], int L, int m, int R). Allocate the temporary array on the heap.

Show answer 
int merge_stable(int a[], int L, int m, int R) {
  int n = R - L + 1;
  int *t = malloc(n * sizeof *t);
  if (t == NULL) return -1;
  int i = L, j = m + 1, k = 0;
  while (i <= m && j <= R)
    t[k++] = (a[j] < a[i]) ? a[j++] : a[i++];
  while (i <= m) t[k++] = a[i++];   /* the rest */
  while (j <= R) t[k++] = a[j++];
  memcpy(a + L, t, n * sizeof *t);
  free(t);
  return 0;
}

The right-hand item is taken only if it is strictly smaller. On a tie the left one comes first and the relative order is preserved. Unlike the bitonic version, when one of the halves is exhausted the rest is copied by separate loops. Instead of calling malloc on every call, allocating the array b once and passing it as a parameter is faster.

Multiple Choice · Heap Sort

Question 14: Building a Heap

a[1..7] = [2, 9, 4, 7, 1, 8, 3] is heapified from the bottom up (for i = 3, 2, 1 we call heapify). What is the result?

D: i = 3: the children of 4 are 8 and 3 → 8 moves up: [2, 9, 8, 7, 1, 4, 3]. i = 2: 9 is larger than its children (7, 1), stays. i = 1: 2 sinks: 9 moves up, then of the children of a[2], 7 moves up, and 2 goes to a[4]: [9, 7, 8, 2, 1, 4, 3]. A max-heap is not a sorted array (A).

Question 15: Moving the Largest to the End Twice

Max-heap a[1..7] = [9, 7, 8, 2, 1, 4, 3]: the first two rounds of the sorting phase (i = 6 and i = 5) are traced. After each heapify, what is the array?

The max-heap is ready. i = 6: SWAP(a[1], a[7]) will move the largest, 9, to the end.

9 is in place (green). The 3 at the root breaks the heap; heapify(a, 1, 6).

t = 3. The children are 7 and 8 → j = 3. 3 < 8: 8 is moved up (a[1] = 8).

j = 6: a single child (j < n is false). 3 < 4: 4 moves up (a[3] = 4).

j = 12 > 6: the loop ends, a[6] = 3. The new root 8 = the largest of the rest.

i = 5: SWAP(a[1], a[6]) → 8 goes to the end. heapify(a, 1, 5).

The children are 7 and 4 → j = 2. 3 < 7: 7 moves up.

j = 4: the children are 2 and 1, the larger is 2. 3 ≥ 2: break, a[2] = 3. The array is [7, 3, 4, 2, 1, 8, 9].

void heapify(int a[], int root, int n) {
    int t = a[root], j;
    for (j = 2 * root; j <= n; j *= 2) {
        if (j < n && a[j] < a[j + 1]) j++;
        if (t >= a[j]) break;
        a[j / 2] = a[j];
    }
    a[j / 2] = t;
}
/* round i: SWAP(a[1], a[i + 1]);
          heapify(a, 1, i); */

Classic Question · Radix Sort

Question 16: Digit Passes

LSD radix sort (appending to the back of the buckets, buckets collected from 0 to 9) is applied to the list 329, 457, 657, 839, 436, 720, 355. What is the list after each pass? Why does it start from the least significant digit?

Show answer
passlist
ones720 355 436 457 657 329 839
tens720 329 436 839 355 457 657
hundreds329 355 436 457 657 720 839

In the ones pass 457 and 657 fall into the same bucket (7) and their arrival order is preserved. In the tens pass 329 (2) is appended behind 720 (2). While the last pass sorts by the most significant digit, among equal hundreds digits the order from the earlier passes is preserved (thanks to stability); that is why the result is completely sorted. 3 passes × O(n + 10).

Multiple Choice · Radix Sort

Question 17: Inserting at the Front of the Bucket

In LSD radix sort, while the list 329, 457, 657, 839, 436, 720, 355 is distributed, each item is inserted at the front of its bucket instead of the back (the collection is unchanged). What is the list after three passes?

B: Inserting at the front reverses the arrival order in every bucket: the passes become unstable. In the last pass, items with equal hundreds digits (329 and 355, 436 and 457) stay in reverse order (found by simulation). D is the intermediate list after the ones pass. LSD sorting is correct only with stable passes.

Question 18: Sorting with a Linked merge

Linked (index-based) merge sort is called with the keys 40, 10, 30, 20 in a[1..4]; initially all link fields are 0, a[0] is a temporary head. mergesort(a, 1, 4) sorts the right half first, then the left half. After each merge, what are the link fields and the return values?

int merge(element a[], int first, int second) {
  int last = 0;            /* a[0]: temp head */
  int i1 = first, i2 = second;
  while (i1 && i2)
    if (a[i1].key <= a[i2].key) {
      a[last].link = i1; last = i1;
      i1 = a[i1].link;
    } else {
      a[last].link = i2; last = i2;
      i2 = a[i2].link;
    }
  a[last].link = i1 ? i1 : i2;
  return a[0].link;
}
Show answer
#(L, R)[1][2][3][4]return
1(3, 4)00034
2(1, 2)01032
3(1, 4)04132
  • #1: 30 > 20, so 4 (20) is linked first, the second list ends, a[4].link = 3: 20 → 30.
  • #2: 40 > 10: 10 → 40, head 2.
  • #3: 10 ≤ 20 → 2; 40 > 20 → a[2].link = 4; 40 > 30 → a[4].link = 3; the second list ended, a[3].link = 1.

Head 2: 10 → 20 → 30 → 40. The records did not move, only the link fields changed (verified in C).

Multiple Choice · Summary

Question 19: Which Algorithm?

10⁶ records are stored in a linked list. The order of equal keys must be preserved and O(n lg n) is required even in the worst case. Which is the most suitable?

C: Merge sort is n lg n in every case, is stable with the classic merge, and on a linked list works by changing only links; the O(n) extra memory worry of arrays disappears too. Quick sort and heap sort are not stable, and both rely on random access in an array; the worst case of quick sort is n². Radix sort, on the other hand, requires the keys to be fixed-length integers.
