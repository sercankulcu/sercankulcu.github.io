The Stack ADT

The Stack: Last In, First Out

A stack is an ordered list in which all insertions and deletions happen at one end only. For S = {a0, a1, …, an−1}, a0 is the bottom and an−1 is the top. The last item in is the first one out: LIFO (last-in-first-out).

Cars parked in a one-car-wide dead end: the last one in (D) has to leave first.

Don't confuse the stack ADT with the heap data structure (Chapter 13) or with the heap memory that malloc manages.

The Stack ADT

How a Stack Grows and Shrinks

A pushed → A is now on top; top = 0.

B pushed → B is now on top; top = 1.

C pushed → C is now on top; top = 2.

D pushed → D is now on top; top = 3.

E pushed → E is now on top; top = 4.

Deletion happens only at the top: the first item removed is E, the last one added. D is on top again; top = 3.

  • Push order: A, B, C, D, E.
  • Pop order (if we removed them all): E, D, C, B, A, exactly reversed.
  • To reach an item in the middle (say B), everything above it must be popped first.
  • This restriction is not a flaw but a contract: “the last job opened is the first one closed.”

The Stack ADT

An ADT says what the operations do, not how. The same interface can be implemented with a fixed array, a growable array, or a linked list (Horowitz–Sahni, ADT 3.1).

The Stack ADT

Where Stacks Show Up

Call stack

Every function call pushes a frame holding its return address and local variables.

Expression evaluation

Compilers use a stack to convert infix to postfix and to evaluate postfix.

Backtracking

At a dead end in a maze, go back to the most recent fork.

Bracket matching

Every closing bracket must match the most recently opened one.

Undo

An editor pushes every action; Ctrl+Z undoes the latest one.

Depth-first search

DFS keeps the vertices still to visit on a stack.

The Stack ADT

push and pop Only at the Top

Push four times, then pop: items come out in reverse order. Popping an empty stack is underflow.

Array-Based Stack

Array-Based Stack: the top Index

Empty: top < 0

An empty stack has top = −1. Popping from it is an underflow error.

Full: top ≥ MAX_STACK_SIZE − 1

Pushing onto it is an overflow error.

Item count = top + 1

Mixing the two up is the classic off-by-one bug.

What goes wrong?

C does not check array bounds: an unchecked push overwrites neighboring memory.

Array-Based Stack

Array-Based Stack: C Definitions

#include <stdio.h>
#include <stdlib.h>
#define MAX_STACK_SIZE 101

typedef struct {
    int key;
    /* other fields */
} element;

element stack[MAX_STACK_SIZE];

void stack_full(void) {
    printf("Stack is full!!!\n"); exit(-1);
}
void stack_empty(void) {
    printf("Stack is empty!!!\n"); exit(-2);
}
  • element: the record stored on the stack; for now its only field is key.
  • The stack is a global array; top is passed in by address from the caller.
  • The error routines print a message and end the program with exit.
Instructor “Do it this way and you get a zero, maybe even negative points. How many times have we covered this here?”

Array-Based Stack

Push and Pop Routines

void push(int *top, element item) {
    if (*top >= MAX_STACK_SIZE - 1)  /* any room? */
        stack_full();         /* warn and exit */
    stack[++*top] = item;     /* bump the index first */
}                             /* then store the item */

element pop(int *top) {
    if (*top < 0)
        stack_empty();        /* warn and exit if empty */
    return stack[(*top)--];   /* return, then decrement */
}
stack[++*top]

*top is incremented first, then the item is written at the new index: on an empty stack, −1 → 0.

stack[(*top)--]

The item at the old index is read first, then *top is decremented. The parentheses matter: *top-- would decrement the pointer itself.

Instructor “Normally, a variable that appears as ‘*param’ in a routine's formal parameter list must also be used as ‘*param’ inside the routine.”

Array-Based Stack

A Precedence Trap in C: * with ++/--

ExpressionHow C parses itResult
++*top++(*top): increment the int it points toCorrect (push)
(*top)--use the int it points to, then decrement itCorrect (pop)
*top--*(top--): decrement the pointer, read the old addressWrong: top is unchanged
*top++*(top++): advance the pointerWrong
Rule

Postfix ++/-- binds tighter than unary *; prefix ++ and * share a level and associate right to left.

Why pass the address?

top belongs to the caller; we pass &top so the routine can change it (C passes arguments by value).

void push(int *top, element item) {
  if (*top >= MAX_STACK_SIZE - 1)
    stack_full();  /* "Stack is full!!!", exit */
  stack[++*top] = item;
}
element pop(int *top) {
  if (*top < 0)
    stack_empty(); /* "Stack is empty!!!", exit */
  return stack[(*top)--];
}

Array-Based Stack

Better Design: the Stack as an Object

#include <stdbool.h>
#define CAP 100

typedef struct {
    int data[CAP];
    int top;               /* -1 when empty */
} Stack;

void stack_init(Stack *s) { s->top = -1; }
bool stack_empty(const Stack *s) { return s->top < 0; }
bool stack_full(const Stack *s)  { return s->top == CAP - 1; }
int  stack_size(const Stack *s)  { return s->top + 1; }
bool stack_top(const Stack *s, int *x) {
    if (stack_empty(s)) return false;
    *x = s->data[s->top];  return true;
}
  • The array and top live in one struct, so two stacks can coexist in a program without interfering.
  • No globals: every routine takes the stack as a parameter.
  • On error the routine returns false instead of calling exit; the caller decides what to do.
Instructor “Global variables are forbidden! Inside, use a stack, a queue, local variables, whatever you need. But no globals!”

bool push(Stack *s, int x) {
  if (s->top == CAP - 1) return false; /* overflow */
  s->data[++s->top] = x;
  return true;
}
bool pop(Stack *s, int *x) {
  if (s->top < 0) return false;   /* underflow */
  *x = s->data[s->top--];
  return true;
}

Array-Based Stack

Write It as a Component: stack.h and stack.c

/* stack.h: all the client sees */
#ifndef STACK_H
#define STACK_H
#include <stdbool.h>
typedef struct Stack Stack;  /* opaque */
Stack *stack_create(int capacity);
void stack_destroy(Stack *s);
bool push(Stack *s, int x);
bool pop(Stack *s, int *x);
bool stack_empty(const Stack *s);
#endif

Client code cannot see inside the struct; it only calls the operations. Even if the implementation switches from an array to a linked list, client code stays the same.

/* stack.c: implementation */
struct Stack { int *data; int top, cap; };

Stack *stack_create(int cap) {
  Stack *s = malloc(sizeof *s);
  if (s == NULL) return NULL;
  s->data = malloc(cap * sizeof *s->data);
  if (s->data == NULL) {
    free(s);  return NULL;
  }
  s->top = -1;  s->cap = cap;
  return s;
}
void stack_destroy(Stack *s) {
  if (s) { free(s->data); free(s); }
}

Input "VISIT"; an empty stack is set up.

pop → 'V', s[4] = 'V'.

The stack is empty: pop returns false and the loop ends. Result: "TISIV". n pushes + n pops → O(n).

void reverse(char *s) {
  Stack st;  int c, i;
  stack_init(&st);
  for (i = 0; s[i] != '\0'; i++)
    push(&st, s[i]);    /* assume CAP suffices */
  for (i = 0; pop(&st, &c); i++)
    s[i] = (char)c;
}

Linked Stack

Implementing a Stack with a Linked List

A, B, C pushed in that order: top points to the head of the list.

  • Each item is a node: data plus a link to the next node.
  • Insert and delete at the head: both O(1), no shifting.
  • No capacity limit: overflow happens only if malloc fails.
Why the head and not the tail? Popping at the tail means stepping back from the last node, and finding the previous node in a singly linked list costs O(n). Hence top = head of the list.
Instructor “Top holds the head of the list. Deleting means moving back from the last item, so either you keep the tail with two pointers or you keep the head with one.”

malloc allocates a new node; if it is not NULL we continue. Its fields are still undefined.

new_node->data = 30.

new_node->link = *top: the new node points to the old top (node(20)). Order matters: link first, then change *top.

*top = new_node: the caller's top now points to 30. Stack: 30 → 20 → 10.

After three pushes: 30 → 20 → 10 → NULL. Each push does a constant amount of work: O(1).

bool push(node **top, int x) {
  node *new_node = malloc(sizeof *new_node);
  if (new_node == NULL) return false; /* no memory */
  new_node->data = x;
  new_node->link = *top;  /* point to old top */
  *top = new_node;        /* new top */
  return true;
}

bool pop(node **top, int *x) {
  node *old = *top;        /* no malloc! */
  if (old == NULL) return false;  /* empty */
  *x = old->data;
  *top = old->link;        /* advance top */
  free(old);               /* release memory */
  return true;
}

Linked Stack

Who Owns the Memory in a Linked Stack

typedef struct node {
    int data;
    struct node *link;
} node;

void stack_clear(node **top) {
    while (*top != NULL) {
        node *old = *top;
        *top = old->link;
        free(old);
    }
}                  /* afterwards *top == NULL */
  • old is a pointer variable, not a new node: it needs no malloc.
  • Save the link first (*top = old->link), then call free: the other way round reads freed memory.
  • Call stack_clear before the program ends: every malloc needs a matching free.
Instructor “You don't need to malloc space for every pointer. There's no such rule!”
Instructor “If you don't learn pointers now, you may still not know them in your senior year.”

If the maximum size is known, use a fixed array; if not, a growable array is usually fastest in practice. A linked stack suits cases where the nodes already live in other structures or are created and destroyed one at a time.

The Call Stack

The Call Stack Overflows Too

The call stack is a stack: each call pushes a frame holding the return address, parameters, and locals, and return pops it. The most recently called function finishes first.

Infinite recursion

Recursion with no base case, or one it never reaches, pushes a frame per call; when the system stack (typically a few MB) fills up, the program crashes with a stack overflow.

Large local arrays

A local array such as int a[1000000]; lives in the frame and can overflow the stack on its own. Put large data on the heap with malloc.

Returning a local's address

return &local; is a bug: once the frame is popped, other calls reuse that memory (a dangling pointer).

Removing recursion

Any recursive algorithm can be turned into a loop that maintains its own stack.

Multiple Stacks

Multiple Stacks: Start with Two

  • Stack 1 grows up from 0, stack 2 grows down from m−1.
  • Empty: top1 = −1, top2 = m.
  • Full: top1 + 1 == top2, when the two meet.
Advantage: even if one stack holds few items and the other many, no cell is wasted; the array fills only when the total reaches m. With three or more stacks, this trick no longer works.

/* stack i: boundary[i]+1 .. boundary[i+1] */
bool push(int i, int x) {
  if (top[i] == boundary[i+1]) return false; /* full */
  memory[++top[i]] = x;
  return true;
}
bool pop(int i, int *x) {
  if (top[i] == boundary[i]) return false; /* empty */
  *x = memory[top[i]--];
  return true;
}

Multiple Stacks

Sharing Memory Among n Stacks: Pros and Cons

A one-dimensional array (memory[MEMORY_SIZE]) can be split into n segments to hold n stacks; each stack's top and boundary values are kept in two auxiliary arrays.

Pros

  • One malloc, one array: easy to manage.
  • push/pop are still O(1).
  • The same idea works for queues (n queues).

Cons

  • When one segment fills, you get a “full” error even if memory has room elsewhere.
  • Shifting stacks to make room costs O(m): shifting is expensive.
  • Segment sizes are hard to predict in advance.
Horowitz–Sahni's fix: stack_full(i) looks for free space first to the right, then to the left, and shifts the stacks in between by one cell. In the worst case every push can cost O(m).

Common Mistakes

1Popping an empty stack or pushing onto a full one: skipping the bounds check.
2Writing *top--: it decrements the pointer; the correct form is (*top)--.
3Confusing the value of top with the item count (count = top + 1).
4In a linked push, writing *top = new_node first and losing the old list.
5In pop, reading the value after free, or never freeing the node.
6Calling malloc for a temporary pointer that doesn't need it, and leaking memory.
