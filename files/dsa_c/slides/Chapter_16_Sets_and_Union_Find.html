Disjoint Sets

Union and find on sets

The universe is {0, 1, …, n−1} and the sets are pairwise disjoint: S₁ ∩ S₂ = S₂ ∩ S₃ = S₁ ∩ S₃ = ∅. For n = 10:

Each set is a tree; links point from children to parents (arrows go up).

From the lecture“A very, very basic data structure, yet we use it in many problems. You have to learn it to be able to use it.”

Disjoint Sets

Two operations, and two ways to unite

1 · Disjoint set union

Si ∪ Sj = {x : x ∈ Si ∨ x ∈ Sj}. After a union the two sets no longer exist separately: S₁ ∪ S₂ = {0, 6, 7, 8, 1, 4, 9}.

2 · find(i)

Returns the set that contains i (the set's name = the root of its tree).

The roots are 0, 4 and 2. To unite two sets, make one root's parent link point to the other root.

S₁ ∪ S₂: 4's parent becomes 0; the tree of S₂ becomes a subtree of 0.

S₂ ∪ S₁: this time 0's parent becomes 4. Both are correct; the choice affects the cost.

Array Implementation

First version: find1 and union1

int find1(int i) {
  for (; parent[i] >= 0; i = parent[i])
    ;                /* climb to a root */
  return i;
}
void union1(int i, int j) {
  parent[i] = j;     /* put tree i under j */
}
find(i)

Follows parent links until it reaches a negative entry (the root) and returns the root.

union(i, j)

Given two roots, makes one tree a subtree of the other: O(1).

Precondition

i and j must be roots; otherwise call find1 first.

Analysis

Analysis of find1 and union1

/* start with n singleton sets */
union1(0, 1);
union1(1, 2);
...
union1(n-2, n-1);
find1(0);
find1(1);
...
find1(n-1);
  • n−1 unions, each constant → O(n) in total; no problem there.
  • The tree degenerates into a chain of depth n.
  • For the element i at level n−i, find1 takes O(n−i): n−1 steps for 0, n−2 for 1, …
  • One find1 can cost O(n); n of them cost Σ i = O(n²).
This sequence ruins the tree. The culprit is not the union itself but which tree is attached to which. The fix: the weighting rule.

Weighting Rule

The weighting rule

Definition: if tree i has fewer nodes than tree j, make j the parent of i; otherwise make i the parent of j. (The tree with more nodes becomes the parent.)

From the lecture“Question: do we need a separate array for the number of nodes in each tree? Answer: every non-root node already stores a nonnegative value in the parent array. So the node count of a root can be stored there too, as a negative number.”

Weighting Rule

union2: the root stores minus the node count

void union2(int i, int j) {
  /* weighting rule; i, j are roots */
  int p = parent[i] + parent[j]; /* -(size) */
  if (parent[i] > parent[j]) {  /* i smaller */
    parent[i] = j;      /* i under j */
    parent[j] = p;      /* j's new size */
  } else {              /* j not larger */
    parent[j] = i;
    parent[i] = p;
  }
}
−count at the root

A root holds −(number of nodes): −1 for a singleton, −8 for an 8-element set.

Why >?

The values are negative: parent[i] > parent[j] means i has fewer nodes (−2 > −4).

Cost

Still O(1), with no extra array.

Weighting Rule

Question: how badly can the tree degenerate?

From the lecture“The algorithm must be correct, efficient and well engineered. But that is not the end: we ask which data hurts it most. Whatever happens behind the scenes, how long can my code run at most? That is what computer science and computer engineering are about!”
From the lecture“‘Do you all know C, Java and so on?’ Yes, they do. ‘Fine, you are all hired, same salary!’ The computer engineer says: ‘Wait a minute! I am a computer engineer. How can it be the same salary? Ask me a question and watch how I solve it!’”
The worst case for the weighting rule is uniting two trees of equal size every time (as in the union2 traces). Each union deepens every node of the smaller tree by 1, but the tree at least doubles.

Weighting Rule

Lemma: weighted union keeps the depth logarithmic

Lemma (Horowitz)If T is a tree with m nodes built by a sequence of union2 operations, then the depth (number of levels) of T is at most ⌊lg m⌋ + 1.
  • Proof idea (induction): a node gets deeper by 1 only when its tree is attached to a tree that is no smaller.
  • Then the tree containing the node at least doubles.
  • A size can double at most lg m times before reaching m → depth ≤ ⌊lg m⌋ + 1.
From the lecture“In a mathematics department the question would go on: ‘Prove it.’ […] We brought the cost down from n to ⌊lg n⌋+1. That is algorithm design! But we do not stop here, on we go…”

Collapsing Rule

The collapsing rule

In the final tree, find(7) reaches the root in 3 steps. If a program calls find(7) over and over, the cost piles up. Even when the smaller tree goes under the larger one the depth can grow; since we cannot control the depth, we go one step further:

DefinitionIf j is a node on the path from i to its root (i not the root), then j is linked directly to the root.
From the lecture“In graph theory this corresponds to a ‘closure’. You will need it in one of the graph theory assignments; I won't say which one. The problem looks different, but this is what lies underneath.”

Collapsing Rule

find2: find the root, then link the path to it

int find2(int i) {
  int r, s;
  for (r = i; parent[r] >= 0; r = parent[r])
    ;                   /* find the root */
  while (i != r) {      /* collapse path */
    s = parent[i];      /* save the parent */
    parent[i] = r;      /* link i to root */
    i = s;              /* move up */
  }
  return r;
}
Pass 1 (for)

r finds the root (the negative entry).

Pass 2 (while)

Every node on the path is linked straight to r. It also runs once for a node already linked to the root (useless but harmless).

Payoff

Later finds on the same path reach the root in one step.

Collapsing Rule

Lemma (Tarjan and van Leeuwen): almost constant

LemmaStart with singleton sets and let T(f, u) be the maximum time for f finds and u unions (weighting rule + collapsing rule) in any interleaved order. For u ≥ n/2:

k₁·(n + f·α(f+n, n)) ≤ T(f, u) ≤ k₂·(n + f·α(f+n, n))

  • α is the inverse Ackermann function; it grows extremely slowly.
  • Even for as many elements as there are atoms in the universe, α ≤ 4 in practice.
  • Divided by the number of operations, the cost is almost O(1).
/* Ackermann: grows very fast */
A(m, n) = n + 1                  m = 0
        = A(m-1, 1)              m > 0, n = 0
        = A(m-1, A(m, n-1))      m > 0, n > 0
From the lecture“There are a million elements; one finds them in O(1), the other is still searching a list… As we said, this is the difference between the mathematician and the engineer applying for the same job!”

Collapsing Rule

The Ackermann function and its inverse

n = 0n = 1n = 2n = 3n = 4
m = 012345
m = 123456
m = 2357911
m = 35132961125
m = 41365533265536−3……
  • A(5, 1) = 22…2 − 3 (a tower of 65536 twos): unimaginably large.
  • Inverse: α(m, n) = min{ i ≥ 1 : A(i, ⌊m/n⌋) ≥ lg n }. Since A grows so fast, α grows very slowly.

The Ackermann function has several definitions. With the one above, A(3,4) = 125; with Horowitz's definition (A(1,j) = 2j …), A(3,1) = 16. The conclusion is the same either way: in practice α ≤ 4.

Exam question: write the Ackermann function recursively

Exam questionWrite the Ackermann function recursively. Then show the call stack of A(1, 2) step by step.
Solution
unsigned long ackermann(unsigned long m,
                        unsigned long n) {
  if (m == 0) return n + 1;
  if (n == 0) return ackermann(m - 1, 1);
  return ackermann(m - 1, ackermann(m, n - 1));
}

A(1,2) = A(0, A(1,1)) = A(0, A(0, A(1,0))) = A(0, A(0, A(0,1))) = A(0, A(0, 2)) = A(0, 3) = 4. Even A(4, 2) never finishes on any computer; the stack overflows.

Code trace: counting connected components

Edges u–v: (0,1), (2,3), (1,4), (3,2). How many connected components are there?

Every node is its own set: parent = −1, count = 6.

Edge (0, 1): find2(0) = 0, find2(1) = 1.

0 ≠ 1: different components → union2(0, 1), count = 5.

Edge (2, 3): find2(2) = 2, find2(3) = 3.

2 ≠ 3: different components → union2(2, 3), count = 4.

Edge (1, 4): find2(1) = 0, find2(4) = 4.

0 ≠ 4: different components → union2(0, 4), count = 3.

Edge (3, 2): find2(3) = 2, find2(2) = 2.

a == b = 2: 3 and 2 are already in one component; the edge closes a cycle and the count stays.

return 3: the components are {0,1,4}, {2,3}, {5}. Total O(n + m·α).

int components(int n, int m, int u[], int v[]) {
  for (int i = 0; i < n; i++) parent[i] = -1;
  int count = n;              /* all separate */
  for (int e = 0; e < m; e++) {
    int a = find2(u[e]), b = find2(v[e]);
    if (a != b) {             /* new component */
      union2(a, b);
      count--;
    }
  }
  return count;
}

Offline LCA

Tarjan's lowest common ancestor algorithm.

Kruskal's algorithm: sort the edges by weight; if find gives different roots for the ends of an edge, take the edge and unite the two sets; if it gives the same root, the edge closes a cycle and is rejected. Cost: sorting O(m lg m) + union-find ≈ O(m·α).

Complexity summary

VersionUnionFind (worst)n−1 unions + m finds

Memory: just the parent array of n integers. Since α ≤ 4, the last row is linear in practice.

A union alone is always O(1); the cost is set by the tree depth, that is, by find. The weighting rule bounds the depth; the collapsing rule shortens the paths.

Summary

Common mistakes

1Passing an arbitrary node instead of a root to union: parent[i] = j cuts off i's subtree.
2Uniting a root with itself (i == j): the root points to itself, an infinite loop.
3Misreading the comparison of negative counts in the weighting rule (−2 > −4 means “fewer nodes”).
4Forgetting to update the node count (p) at the root after a union.
5Relinking in find2 without saving the parent (s) first: the rest of the path is lost.
6Not filling the parent array with −1 at the start.

  3. The root stores −(height); on a tie one root goes under the other and the height grows by 1. The depth is still O(lg n); with collapsing, rank becomes an upper bound.
  4. int find(int i) { return parent[i] < 0 ? i : (parent[i] = find(parent[i])); }
  5. The ends are already in the same set, so a path of chosen edges joins them; the new edge would close that path into a cycle.
  6. O(n + m·α(m+n, n)), linear in practice.

Summary

Chapter summary

Model

Disjoint sets = trees with child-to-parent links, named by their roots.

Representation

A single parent array; a negative value marks a root.

Worst case

Linking without a rule can build a chain: n finds cost O(n²).

Weighting rule

Smaller tree under larger: depth ≤ ⌊lg m⌋ + 1.

Collapsing rule

The path is linked to the root; later finds take one step.

Result

Together: α ≤ 4 per operation, almost O(1).
