Introduction

The problem: the 7 Bridges of Königsberg

On the Pregel river, two islands (A, D) and two banks (B, C) are joined by 7 bridges. Can you cross every bridge exactly once and return to the start?

Euler (1736) made the land masses vertices and the bridges edges: what matters is not the shape but the connections (notation, not drawing).

Such a walk exists only if every vertex has even degree. Here all degrees are odd (5, 3, 3, 3) → no such walk.

This is regarded as the birth of graph theory. Euler (pronounced Oiler) stated the result as a theorem; its proof is left to Graph Theory courses (4th year: “Graph Theory and Combinatorics”).

Definitions and Terminology

Definition: G = (V, E)

A graph G consists of two finite sets: a nonempty set V of vertices (nodes) and a possibly empty set E of edges (arcs). Undirected: (v0, v1) ≡ (v1, v0); directed (digraph): <v0, v1> ≠ <v1, v0> — <tail, head>: the arrow leaves the tail and points into the head.

GraphV(G)E(G)
G1{0, 1, 2, 3}{(0,1), (0,2), (0,3), (1,2), (1,3), (2,3)}
G2{0, …, 6}{(0,1), (0,2), (1,3), (1,4), (2,5), (2,6)}
G3{0, 1, 2}{<0,1>, <1,0>, <1,2>} — both are listed in a digraph

E is a subset of the Cartesian product V × V (it need not contain every pair).

Definitions and Terminology

Terminology: Adjacent Vertices, Subgraphs

Adjacent

If (v0, v1) is an edge of an undirected graph, v0 and v1 are adjacent, and the edge is incident on both.

Subgraph

If G′ is a subgraph of G, then V(G′) ⊆ V(G) and E(G′) ⊆ E(G). A single vertex is also a subgraph.

Definitions and Terminology

Path, Connectivity and Degree

  • Path: a sequence of vertices from vp to vq such that (vp, vi1), (vi1, vi2), …, (vin, vq) are edges.
  • If there is a path from v0 to v1, they are connected; if every distinct pair (vi, vj) is joined by a path, G is connected.
  • Degree: the number of edges incident on the vertex. In G2 d(0) = 2, in G1 d(1) = 3, in G2 d(4) = 1.
  • In a digraph, degree = in-degree + out-degree. In G3 d(0) = 1 + 1 = 2; d(1) = 1 + 2 = 3; d(2) = 1 + 0 = 1.

Vertex 0 in G3: d = 1 + 1 = 2

“In G3, d = 1 + 1 = 2” refers to vertex 0: a degree is always stated for a particular vertex.

Definitions and Terminology

Theorem 1: The Sum of Degrees = 2e

In a graph G with n vertices and e edges, 2e = d0 + d1 + … + dn−1. Proof: each edge adds exactly 2 to the degree sum of its two endpoints. It holds for simple and non-simple (multi-edge) graphs. Simple graph: at most one edge between two vertices, no self-loops.

Edge 1 added: each endpoint's degree rose by 1 → the sum rose by 2.

Edge 2 added: each endpoint's degree rose by 1 → the sum rose by 2.

Finding a degree

Count the 1s in the row (or column): O(n). In a digraph the row gives out-degree, the column in-degree; together O(2n). In G3 out-degree d(2) = 0, in-degree d(2) = 1.

Counting edges

Count all the 1s and divide by 2: O(n²). By symmetry half the matrix is enough; still O(n²/2) = O(n²).

G4: two components

Common mistake: writing row 1 as 1 0 1 0 … and row 7 as … 0 0 1. The matrix of an undirected graph must be symmetric; these rows break symmetry. Correct: row 1 1 0 0 1 0 0 0 0 (neighbors 0, 3), row 7 0 0 0 0 0 0 1 0 (neighbor 6).

Code Trace: degree(a, 3, 1)

degree(a, 3, 1): finding the degree of vertex 1 in G3.

The counters are set to zero.

Row 1, column 0: a[1][0] = 1 → out = 1.

Row 1, column 1: a[1][1] = 0 → out = 1.

Row 1, column 2: a[1][2] = 1 → out = 2.

Column 1, row 1: a[1][1] = 0 → in = 1.

Column 1, row 2: a[2][1] = 0 → in = 1.

int degree(int a[][MAX_V], int n, int v)
{
    int j, out = 0, in = 0;
    for (j = 0; j < n; j++)
        out += a[v][j];      /* row    */
    for (j = 0; j < n; j++)
        in += a[j][v];      /* column */
    return out + in;
}

2. Adjacency Lists

Instead of each matrix row, a linked list: graph[i] points to the list of i's neighbors. Drawback: an undirected graph uses 2 nodes per edge.

#define MAX_V 50   /* max number of vertices */
typedef struct node *node_ptr;
typedef struct node {
    int vertex;         /* the neighbor's number  */
    node_ptr link;      /* next neighbor in list   */
} node;                 /* don't forget ';' and the name */
node_ptr graph[MAX_V];   /* one list per vertex */

G1 represented with adjacency lists

Number of edges

Count all the nodes and divide by 2 (Theorem 1): O(n + e). In graph theory, complexity is usually stated in terms of e.

Degree

In an undirected graph, counting the nodes in list i is enough: O(di).

Representations

Adjacency Lists: Undirected and Directed Examples

Undirected (G4): the benefit of sorted lists

If the lists are sorted, in each list we can count the nodes whose number is below the head's (e.g. (1,0)) and skip the rest; we visit half the vertices, but it is still O(n + e).

Directed (G3)

<0,1> ≠ <1,0> → every edge must be counted. Out-degree is easy from the lists; in-degree requires scanning every list. The fix: also keep the inverse (transpose) lists, built in a single pass.

Representations

A Sparse Graph: 11 Vertices, 2 Edges

Lists: graph[1] → 4, graph[4] → 1, graph[7] → 8, graph[8] → 7. The other 7 heads are NULL.

Total: 11 heads + 2e = 4 nodes. Matrix: 11 × 11 = 121 cells.

11 vertices, 2 edges, 9 components. The matrix wastes 117 of its 121 cells; the lists hold only 11 heads + 4 nodes. Consider lists for sparse graphs and a matrix for dense ones — but always decide by the operations to be performed.

void add_edge(int u, int v)   /* u -> v */
{
    node_ptr p = malloc(sizeof(node));
    if (p == NULL) exit(1);       /* no memory */
    p->vertex = v;
    p->link = graph[u];   /* at front: O(1) */
    graph[u] = p;
}

Who Builds the Graph?

Instructor: “Edges come in, and they must be added to the structure. I looked and drew it; a program can't just look and draw! The algorithm has to do the work.”
Insert at the front

Each edge is placed in O(1); the list ends up in the reverse of arrival order. Total build time O(n + e).

Insert at the end

Keeps the order, but each time you must walk to the NULL (O(d)); or keep a last pointer for each list.

Sorted insertion

Keeping each list sorted by vertex number: edge counting and traversal order become predictable; insertion is O(d).

Freeing

At the end of the program, every graph[i] list must be walked and freed.

Inverse adjacency lists · Run the code step by step

Code Trace: transpose()

First the rev[] heads are set to NULL.

Edge <0,1>: 0 is added to list rev[1] (<1,0>).

Edge <1,0>: 1 is added to list rev[0] (<0,1>).

Edge <1,2>: 1 is added to list rev[2] (<2,1>).

adj[2] is empty: no edges leave 2.

Each node was looked at once: the transpose was built in O(n + e). Now in-degree is also found in O(d).

void transpose(node_ptr adj[], node_ptr rev[],
               int n)
{
    int i;
    node_ptr p;
    for (i = 0; i < n; i++) rev[i] = NULL;
    for (i = 0; i < n; i++)
        for (p = adj[i]; p; p = p->link)
            insert(rev, p->vertex, i); /* <j,i> */
}

3. Sequential Representation with an Array

Undirected, n vertices, e edges: a single array int vertex[n + 2*e + 1]. The first n + 1 cells are starting indices; the neighbors of i are in vertex[vertex[i]] … vertex[vertex[i+1] − 1].

The array for G4. Each edge is still stored twice, but there are no pointers.

Ex. 1: from [0] = 9 (incl.) to [1] = 11 (excl.): indices 9 and 10 → neighbors 1, 2.

Ex. 2: [1] = 11, [2] = 13 → indices 11, 12 → neighbors 0, 3.

Ex. 3: [7] = 22, [8] = 23 → only index 22 → a single neighbor, 6.

Instructor: “Storing is one issue; the efficiency of the algorithms that will run on that data is another… This structure is not efficient for many insertions and deletions. The computers in a network, say, are fixed; if the problem is to store them, this structure may suit.”

void print_adj(const int vertex[], int i)
{
    int k;
    for (k = vertex[i]; k < vertex[i + 1]; k++)
        printf("%d ", vertex[k]);
    printf("\n");
}

{
    edge_ptr p = graph[v];
    while (p) {
        if (p->vertex1 == v) {      /* v: vertex1 */
            printf("%d ", p->vertex2);  p = p->list1;
        } else {                    /* v: vertex2 */
            printf("%d ", p->vertex1);  p = p->list2;

}

Adding an Edge to an Adjacency Multilist

  • Traversal: follow list1 if v is vertex1, list2 if v is vertex2. Stop at NULL. “Any more? Follow the link!”
  • Insertion: you could walk the list to NULL and append; but inserting at the front saves the walk: O(1).
  • An undirected graph needs one head array; a digraph keeps a tail array as well.
  • The gain: only e nodes instead of 2e.
void ml_add_edge(int u, int v)
{
    edge_ptr p = malloc(sizeof(edge));
    if (p == NULL) exit(1);
    p->marked = 0;
    p->vertex1 = u;  p->vertex2 = v;
    p->list1 = graph[u];  /* u's list */
    p->list2 = graph[v];  /* v's list */
    graph[u] = graph[v] = p;  /* front of both */
}

Basic Graph Operations: Traversal

  • Given an undirected G = (V, E) and a vertex v, visit every vertex reachable from v (visit = print its data field).
  • Depth-first search (DFS) resembles preorder traversal of a tree.
  • Breadth-first search (BFS) resembles level-order traversal of a tree.
  • Both use a graph stored as adjacency lists; the lists are sorted.

Traversals

Depth-First Search (DFS)

  • Visit v; pick an unvisited w from v's list and continue the search from w.
  • A stack is needed to remember our place in the list; when u has nowhere left to go, pop a vertex from the stack and continue.
  • A recursive routine makes this seemingly complex scheme easy: the stack is the call stack.
  • The global array visited[] must start out FALSE.
#include <stdio.h>
#include <stdbool.h>
#define TRUE  true
#define FALSE false
bool visited[MAX_V];   /* don't forget ';' */
void dfs(int v)   /* depth-first search */
{
    node_ptr w;
    visited[v] = TRUE;    /* visited */
    printf("%d ", v);
    for (w = graph[v]; w; w = w->link)
        if (!visited[w->vertex])
            dfs(w->vertex);
}

Traversals

What Does the DFS Result Depend On?

Start vertex

From 0: 0 1 3 7 4 5 2 6. The start need not be 0: from 6, 6 2 0 1 3 7 4 5; from 4, 4 1 0 2 5 7 3 6. Same vertices, different order.

Effect of list order

Had 0's list been {2, 1} instead of {1, 2}, the order would be 0 2 5 7 3 1 4 6. Whether lists were built by inserting at the front or end, or kept sorted, changes the traversal.

Analysis

dfs is called at most once per vertex; each list is scanned once: O(n + e). There are at most n(n − 1)/2 edges.

Data structure

With a matrix, finding v's neighbors would take O(n), O(n²) in total. With lists we traverse in linear time.

The traversal produced a tree (the depth-first spanning tree). Adding one more edge to it creates a cycle, and it is no longer a tree.

Traversals

Breadth-First Search (BFS)

  • Start at v and mark it; then visit all the vertices on v's list.
  • Then the unvisited neighbors of the first vertex on v's list, then those of the second…
  • A visited vertex goes into a queue (first in, first out); when a list is finished, a vertex is taken from the queue and its list is scanned.
  • The search ends when the queue is empty.
Instructor: “Just as depth-first search by its nature required a stack, this one requires a queue.”
void bfs(int v)   /* breadth-first search */
{
    node_ptr w;
    queue_ptr front = NULL, rear = NULL;
    printf("%d ", v);
    visited[v] = TRUE;
    addq(&front, &rear, v);
    while (front) {
        v = deleteq(&front, &rear);
        for (w = graph[v]; w; w = w->link)
            if (!visited[w->vertex]) {
                printf("%d ", w->vertex);
                addq(&front, &rear, w->vertex);
                visited[w->vertex] = TRUE;
            }
    }
}

Traversals

The Dynamic Queue Used by BFS

typedef struct queue *queue_ptr;
typedef struct queue {
    int vertex;
    queue_ptr link;
} queue;
void addq(queue_ptr *f,
          queue_ptr *r, int d)
{
    queue_ptr p = malloc(sizeof(queue));
    if (p == NULL) exit(1);
    p->vertex = d;  p->link = NULL;
    if (*f) (*r)->link = p;  else *f = p;
    *r = p;
}
int deleteq(queue_ptr *f,
             queue_ptr *r)
{
    queue_ptr p = *f;   /* f != NULL */
    int d = p->vertex;
    *f = p->link;
    if (*f == NULL) *r = NULL;
    free(p);
    return d;
}
A prototype such as int deleteq(queue_ptr *), taking only the front pointer, is not enough. When the queue empties, the rear pointer must become NULL too, so deleteq also gets r.

Traversals

BFS: Analysis and Beyond

Analysis

Each vertex enters the queue once → the while loop runs n times. The lists hold 2e nodes in all: d0 + … + dn−1 = 2e. Total O(n + e); with a matrix O(n²).

What does it give?

Visits in order of number of edges (level) from the start; the shortest-path tree of an unweighted graph.

Beyond

The ideas of depth-first/breadth-first search reappear in AI when a search space is traversed as a tree: minimax, B* search, branch and bound.

DFS or BFS?

DFS: stack/recursion, goes deep (components, cycles, topological thinking). BFS: queue, layer by layer (path with fewest edges).

Instructor: “In game problems too, if they say ‘the moves could be these,’ that means it expands breadth-first.”

Components and Beyond

Analysis: n × O(n + e)?

The outer for runs n times, and the inner dfs() was O(n + e). Is the complexity their product, O(n²)?

Instructor: “Is it? Is it? Is it? Does it really run that long? No! … ‘I'll just multiply them all and state the result.’ Wrong!”
Why O(n + e)?

With a single component, the first iteration runs in O(n + e) and every visited[] becomes TRUE; for the other values of i the if is skipped. The components are disjoint, so the total work is O(n + e).

With a matrix?

Each dfs call searches for neighbors in O(n) → finding components is O(n²). “If that is written efficiently too…”

Components and Beyond

Theorem: A Connected Graph Has at Least n − 1 Edges

  • Theorem: a graph needs at least n − 1 edges to be connected.
  • It is one-way: n − 1 edges are necessary but not sufficient; a graph with n − 1 edges may or may not be connected. With fewer it is certainly not connected.
  • At most: if all vertices are adjacent to each other (the complete graph Kn), (n − 1) + (n − 2) + … + 1 = n(n − 1)/2. So e can be quadratic in n.
  • In a connected graph: n − 1 ≤ e ≤ n(n − 1)/2.
Instructor: “Tic-tac-toe… ‘How do I spoil my opponent's move?’ I expect these concepts will settle better once you read about it.”

bool has_cycle(int v, int parent)
{
    node_ptr w;
    visited[v] = TRUE;
    for (w = graph[v]; w; w = w->link)
        if (!visited[w->vertex]) {
            if (has_cycle(w->vertex, v)) return TRUE;
        } else if (w->vertex != parent)
            return TRUE;          /* back edge */
    return FALSE;
}

Cycle Detection: Undirected and Directed

Undirected

In DFS, a visited neighbor that is not the parent = a back edge = a cycle. O(n + e).

Directed

An edge to a vertex “currently on the stack” (gray) is a cycle; three colors: white/gray/black. A topological sort routine also catches cycles.

Why does it matter?

With prerequisite tasks, a cycle means the project never finishes; in an MST, a cycle means an extra edge.

With a matrix

The same DFS becomes O(n²) with a matrix.

Bipartite Graph Test

  • V can be split into two sets with every edge joining different sets: a bipartite graph (e.g. K3,3, students–courses).
  • Test: two-color with BFS, giving each neighbor the opposite color. If an edge joins two same-colored vertices, it is not bipartite.
  • Theorem: a graph is bipartite ⇔ it has no odd-length cycle.
  • Same cost as BFS: O(n + e); start it separately for each component.

Common Mistakes

1Assuming <v,u> exists in a digraph because <u,v> does; taking the matrix to be symmetric.
2In BFS, marking a vertex when it leaves the queue instead of when it enters → the same vertex is queued several times.
3Forgetting to reset visited[] to FALSE before each traversal (a global array!).
4Multiplying the outer for by DFS and calling components O(n(n + e)).
5Not checking the result of malloc when building lists; not freeing the lists at the end of the program.
6Appending each edge at the end and walking the list from the start each time; missing the O(1) insert at the front.
