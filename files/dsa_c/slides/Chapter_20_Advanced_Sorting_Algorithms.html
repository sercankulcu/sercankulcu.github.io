Quicksort

Quicksort

  • Developed by C. A. R. (Tony) Hoare in 1962.
  • Divide and conquer: split the problem recursively into subproblems until they are small enough to solve directly.
  • Time proportional to n lg n on average; n² in the worst case. Uses only a small auxiliary stack.
  • Not stable, yet one of the fastest general-purpose algorithms known. The standard C library has qsort.

    quicksort1(a, i + 1, R);
}

Quicksort

partition()

int partition(int a[], int L, int R) {
    int i = L - 1, j = R, v = a[R]; // pivot a[R]
    for (;;) {
        while (less(a[++i], v))
            ;
        while (less(v, a[--j]))
            if (j == L) break;
        if (i >= j) break;
        SWAP(a[i], a[j]);
    }
    SWAP(a[i], a[R]);
    return i;
}
  • [2] The pivot (partitioning element) is v = a[R].
  • [4] i stops at the first element from the left that is greater than or equal to v. No bounds test is needed: at worst a[R] = v stops it at i = R.
  • [6–7] j stops at an element from the right that is less than or equal to v; j == L keeps this loop in bounds.
  • [9] Both elements are on the wrong side → swap. [8] When i and j meet, the loop ends; [11] the pivot goes to a[i]: left ≤ v ≤ right.

Quicksort

Assessment: Why Is It Quick?

Right position + smaller problem

Bubble and selection sort also put one element in place at each step, but the next subproblem still has n − 1 elements. Quicksort places the pivot and also splits the problem into two smaller pieces.

Recursion tree

The quicksort1(a, 0, 9) trace makes 17 calls for 10 elements: every non-trivial call put a pivot in its final place (green cells in the trace).

Quicksort

Quicksort: Worst and Best Case

Worst: a sorted array

The pivot a[R] is always the largest and stays put; the next call is one element smaller:
n + (n−1) + … + 1 = n(n+1)/2 = O(n²)

Best: splitting exactly in half

At each step i and j advance n steps in total, leaving two subproblems of size n/2:
Cn = 2Cn/2 + n = 2kCn/2k + k·n = n lg n

Instructor “Now you'll be wondering: ‘What's so quick about it?’”
The best case is n lg n; the optimal sorting bound was n lg n − 1.44n. So the leading coefficient is still 1, with an excess of 1.44n.

Quicksort

Average-Case Analysis: The Recurrence

Cn = (n + 1) + (1/n) Σk=1n (Ck−1 + Cn−k),   C0 = C1 = 0

  • The split point k, 1 ≤ k ≤ n, is equally likely: running partition() on all n! orderings gives equal frequencies.
  • n + 1: the comparisons with the pivot in partition(); a split at k leaves subarrays of (k−1) and (n−k) elements.
  • The two sums contain the same terms: Σ(Ck−1 + Cn−k) = 2 Σk=0n−1 Ck ⇒ n·Cn = n(n+1) + 2 Σ Ck−1 … (1)

Quicksort

Average Case: The Subtraction Trick and the Result

  • Replace n by n − 1 in (1): (n−1)Cn−1 = n(n−1) + 2 Σk=1n−1 Ck−1 … (2)
  • (1) − (2): n·Cn − (n−1)Cn−1 = 2n + 2Cn−1 ⇒ n·Cn = (n+1)Cn−1 + 2n
  • (dividing by n(n+1)) Cn/(n+1) = Cn−1/n + 2/(n+1): now it unrolls by iteration.
  • Unrolling gives Cn ≈ 2(n+1)(1/4 + … + 1/(n+1)) ≤ 2(n+1) ln n.

Cn ≈ 2n ln n = 2 ln 2 · n lg n ≈ 1.39 n lg n

Improving Quicksort

Non-Recursive Quicksort (quicksort2)

void quicksort2(int a[], int L, int R) {
  stack_init(); push2(L, R);
  while (!stack_empty()) {
    L = pop(); R = pop();
    if (R <= L) continue;
    int i = partition(a, L, R);
    if (i - L > R - i) {       // larger part first
      push2(L, i - 1); push2(i + 1, R);
    } else {
      push2(i + 1, R); push2(L, i - 1);
    }
  }
}
#define STACK_MAX 64  /* > 2·lg n */
static int stack[STACK_MAX], top;
void stack_init(void) { top = 0; }
int stack_empty(void) { return top == 0; }
void push(int x) { stack[top++] = x; }
int pop(void) { return stack[--top]; }
#define push2(A, B) \
  do { push(B); push(A); } while (0)
  • Goal: use our own stack instead of the system stack. push2(A,B) pushes B first, then A, so L is popped first.
  • [7–11] The larger part is pushed first, the smaller one last: the last pushed is popped first, so the smaller part is always processed next → the stack depth stays O(lg n) (at most ≈ lg n pairs).
  • The memory recurrence Tn = Tn/2 + 2 ⇒ Tn = 2 lg n (as in binary search).

Improving Quicksort

Improved Quicksort: Median-of-3 + Insertion Sort

#define M 10    /* leave pieces smaller than this */
void quicksort3(int a[], int L, int R) {
    if (R - L <= M) return;
    SWAP(a[(L + R) / 2], a[R - 1]);
    if (a[R-1] < a[L]) SWAP(a[R-1], a[L]); // a[L] <= a[R-1]
    if (a[R] < a[L]) SWAP(a[R], a[L]);     // a[L] <= a[R]
    if (a[R] < a[R-1]) SWAP(a[R], a[R-1]); // a[R-1] <= a[R]
    int i = partition(a, L + 1, R - 1);
    quicksort3(a, L, i - 1);
    quicksort3(a, i + 1, R);
}
void sort(int a[], int L, int R) {
    quicksort3(a, L, R);
    insertion(a, L, R);   /* the small pieces left */
}
if (less(A, B)) SWAP(A, B) means “swap if A < B”; with the arguments in the order (a[L], a[R-1]) it puts the larger one in a[L] and breaks the partition (tested with random arrays: an element larger than the pivot stays on its left). So the arguments are given in reverse order: the result is a[L] ≤ a[R−1] ≤ a[R].

Improving Quicksort

Why Median-of-3 and a Small-Piece Threshold?

Median-of-three

a[L], the middle element and a[R] are put in order; their median moves to a[R−1] and becomes the pivot. Quicksort did worst and insertion sort best on sorted data: the n² case on sorted input disappears.

Natural sentinels

Since a[L] ≤ pivot ≤ a[R], partitioning runs on L+1..R−1; the end elements stop the scans.

Threshold M

Pieces with R − L ≤ M are left unsorted; one final insertion pass in sort() fixes them all in nearly linear time. About 10% faster for 5 ≤ M ≤ 25.

Its limit

Median-of-3 rescues sorted and reverse-sorted input, but specially crafted bad inputs can still cause n² → the cure is introsort.

void quicksort3(int a[], int L, int R) {
    if (R - L <= M) return;
    SWAP(a[(L + R) / 2], a[R - 1]);
    if (a[R-1] < a[L]) SWAP(a[R-1], a[L]); // a[L] <= a[R-1]
    if (a[R] < a[L]) SWAP(a[R], a[L]);     // a[L] <= a[R]
    if (a[R] < a[R-1]) SWAP(a[R], a[R-1]); // a[R-1] <= a[R]
    int i = partition(a, L + 1, R - 1);
    quicksort3(a, L, i - 1);
    quicksort3(a, i + 1, R);
}

int ascending(const void *p, const void *q) {
    int x = *(const int *)p;
    int y = *(const int *)q;
    return (x > y) - (x < y);  // -1, 0, +1
}

C Library and Hybrids

Hybrid Sorts: Combining Algorithms

Quicksort + insertion

On small pieces the cost of recursion dominates; pieces below M are finished by insertion sort (quicksort3 + sort).

Introsort (Musser, 1997)

Starts with quicksort; if the recursion depth exceeds ≈ 2⌊lg n⌋, it switches to heap sort on that piece → worst case O(n lg n). Small pieces go to insertion sort. Common in C++ std::sort implementations.

Timsort (Peters, 2002)

Merge + insertion sort; finds already sorted runs in the data and merges them. Stable; Python's sort and Java's Arrays.sort for object arrays.

The common idea

Good asymptotic behavior at scale (n lg n) + a low constant on small inputs (insertion) + insurance against the worst case.

Merge Sort

Merge Sort

  1. A list of 0 or 1 elements is already sorted.
  2. Otherwise split the list into two halves as equal as possible.
  3. Sort each half by applying merge sort recursively.
  4. Merge the two sorted sublists into one sorted list.
  • John von Neumann, 1945; divide and conquer.
  • Idea 1: sorting a small list takes fewer steps.
  • Idea 2: building a sorted list from two sorted lists is cheaper than from two unsorted ones.
void mergesort(int a[], int b[], int L, int R) {
    if (R <= L) return;
    int m = (R + L) / 2;
    mergesort(a, b, L, m);
    mergesort(a, b, m + 1, R);
    merge(a, b, L, m, R);
}
void merge(int a[], int b[], int L, int m, int R) {
    int i, j, k;
    for (i = m + 1; i > L; i--) b[i - 1] = a[i - 1];
    for (j = m; j < R; j++) b[R + m - j] = a[j + 1];
    for (k = L; k <= R; k++)
        if (less(b[j], b[i]))
            a[k] = b[j--];
        else
            a[k] = b[i++];
}

The auxiliary array b[] (same size as a) is passed as a parameter; it cannot be used without being defined.

Merge Sort · Step through the code

Code Trace: merge(a, b, 0, 2, 6)

Loop 1: the left half a[0..2] is copied as is to b[0..2]; the loop exits with i = L = 0.

Loop 2: the right half is copied to b[3..6] in reverse → b increases from both ends toward the middle (bitonic). The loop exits with j = R = 6.

b[j] = 4 ≥ b[i] = 3 → a[0] = b[0]; i++.

b[j] = 4 < b[i] = 5 → a[1] = b[6]; j--.

b[j] = 5 ≥ b[i] = 5 → a[2] = b[1]; i++.

b[j] = 5 < b[i] = 7 → a[3] = b[5]; j--.

b[j] = 6 < b[i] = 7 → a[4] = b[4]; j--.

b[j] = 10 ≥ b[i] = 7 → a[5] = b[2]; i++.

b[j] = 10 ≥ b[i] = 10 → a[6] = b[3]; i++.

Done: a = [3, 4, 5, 5, 6, 7, 10]. At the end i = 4, j = 3: the two indices met in the middle; no bounds test was needed. Of the equal 5s, the left one (b[i]) was taken first.

void merge(int a[], int b[], int L, int m, int R) {
    int i, j, k;
    for (i = m + 1; i > L; i--) b[i - 1] = a[i - 1];
    for (j = m; j < R; j++) b[R + m - j] = a[j + 1];
    for (k = L; k <= R; k++)
        if (less(b[j], b[i]))
            a[k] = b[j--];
        else
            a[k] = b[i++];
}

Merge Sort

Merge Sort: Time and Space Complexity

an = a⌈n/2⌉ + a⌊n/2⌋ + n,   a1 = 0

n = 2k: an = 2an/2 + n ⇒ an = Θ(n lg n)

  • 16 elements split into 8 + 8, 17 into 8 + 9; merge takes n steps.
  • Number of calls Tn = 2Tn/2 + 1 ⇒ 2n − 1 (19 calls for 10 elements, 9 of which merge).
  • Independent of the input order: best = average = worst = n lg n.
  • Drawback: O(n) extra memory. Avoiding it raises the cost; if no extra memory is allowed, heap sort is preferred.
  • Because it merges sorted runs in sequence, it is the basis of external sorting on disk.
Stability

The classic merge (taking the left one on ties) is stable (quicksort and heap sort are not). The reverse-copy (bitonic) merge here is not stable: [2a, 2b, 2c, 2d] → [2a, 2b, 2d, 2c] (checked in Python).

Instructor “Since splitting the input in half is the clever part, this one splits it in half too. But in the earlier ones the pivot landed in its right place in one step; here nothing does. It builds a new sorted array by exploiting the fact that the two arrays are already sorted.”

Merge Sort

Sorting Alphabetic Data: Linked Merge Sort

typedef struct {
    int key;       /* + large data fields */
    int link;      /* index of the next item, 0 = end */
} element;

int mergesort(element a[], int L, int R) {
    if (R <= L) return L;          /* one-item list */
    int m = (R + L) / 2;
    int right = mergesort(a, m + 1, R);
    int left = mergesort(a, L, m);
    return merge(a, left, right);  /* head index */
}

merge() links two sorted lists through their link fields and returns the head index.

  • Copying large records (e.g. alphabetic data) is slow. The fix: build a linked list inside the array with a link field; only indices change.
  • The data is in a[1..n]; a[0] is a temporary head during merge. Initially every link is 0.
  • mergesort returns the head index of the sorted sublist.
  • Common mistakes: returning a value from a void function; i1 instead of i2 in the else branch; returning a[c].link instead of a[0].
  • In C the order in which arguments are evaluated is unspecified; here the order is written out explicitly.

int merge(element a[], int first, int second) {
    int last = 0;               // a[0]: temp head
    int i1 = first, i2 = second;
    while (i1 && i2)
        if (a[i1].key <= a[i2].key) {
            a[last].link = i1; last = i1;
            i1 = a[i1].link;
        } else {
            a[last].link = i2; last = i2;
            i2 = a[i2].link;
        }
    a[last].link = i1 ? i1 : i2;
    return a[0].link;
}

Heap Sort

Heap Sort

void heapify(int a[], int root, int n) {
    int t = a[root], j;
    for (j = 2 * root; j <= n; j *= 2) {
        if (j < n && a[j] < a[j + 1]) j++; // larger
        if (t >= a[j]) break;   // t fits here
        a[j / 2] = a[j];        // move child up
    }
    a[j / 2] = t;
}
void heapsort(int a[], int n) {     /* a[1..n] */
    int i;
    for (i = n / 2; i >= 1; i--)     /* build heap */
        heapify(a, i, n);
    for (i = n - 1; i >= 1; i--) {   /* sort */
        SWAP(a[1], a[i + 1]);    /* largest to the end */
        heapify(a, 1, i);            /* fix the heap */
    }
}
  • O(n lg n) like merge sort, but it uses no extra memory (in place).
  • The array a[1..n] (index 0 unused) is viewed as a complete binary tree: the children of a[i] are a[2i] and a[2i+1].
  • heapify(a, root, n): with the left and right subtrees of root already max heaps, finds the right place for the root value.
  • Leaves are skipped: heapify nodes ⌊n/2⌋, ⌊n/2⌋−1, …, 1 from the back → a max heap.
  • Then the largest at the root moves to the end and the heap is fixed for the remaining i elements.
  • A j or i declared in a for header cannot be used after the loop (out of scope in C99).

Heap Sort

Heap Sort: Time Complexity

  • Rough analysis: heapify makes at most lg n moves and is called n/2 times → building the heap costs n lg n.
  • Careful analysis: k = number of levels ≈ lg(n+1); level i has at most 2i−1 nodes, each moving at most (k − i) levels:

Σi=1k 2i−1(k − i) = 2k − k − 1 ≤ 2n = O(n)

  • The term Σ i·2i−1 comes from differentiating the geometric series S(y) = (yk+1 − 1)/(y − 1) and setting y = 2.
  • The sorting phase: n − 1 calls of heapify(a, 1, i) → O(n lg n). Total O(n lg n), also in the worst case; O(1) extra memory; not stable.
  • A bound of “≤ 2n” means O(n), not o(n) (being bounded by 2n is not little-o).

Heap Sort

Heap Sort Variants, and Knowing Your Data

When?

For fewer than 50,000 items heap sort is a good choice (≈ 2n lg n comparisons). For larger data there is bottom-up heapsort, which makes fewer comparisons, and theoretically even better variants.

The bottom-up idea

The hole at the root sinks along the larger children to a leaf without comparing with t; then t is placed by moving up. Mostly one comparison per level instead of two.

Instructor “As with counting sort, if we know some properties of the data to sort, we can choose an approach accordingly. In that sense Shell sort and bucket sort are used together. You should know the basic few.”

Radix Sort

Radix Sort

  • Sorting by several keys: e.g. people by surname, and those with the same surname by first name.
  • Keys K0, K1, …, Kr−1: K0 is the most significant (MSD), Kr−1 the least significant (LSD). In the example, the surname is most significant.
  • LSD radix sort: sort first by the least significant digit, then by more significant ones in turn, and finally by the MSD.
  • Each pass must be stable: the order from the previous pass is kept for equal digits.
  • It never compares numbers with each other → a non-comparison sort.
#define MAX_DIGIT 3
#define RADIX 10
typedef struct node *node_ptr;
struct node {
    int digit[MAX_DIGIT];  /* 179 → {1, 7, 9} */
    node_ptr next;
};

K0: hundreds (MSD) · K1: tens · K2: units (LSD). Range [0, 999]. A typedef with no type name, like typedef struct node {…};, is meaningless.

Radix Sort

Radix Sort: Analysis

O(MAX_DIGIT · (RADIX + n + RADIX)) = O(MAX_DIGIT · (RADIX + n))

  • In the example O(3 · (10 + n)): it looks linear, but like counting sort it is a special case: the number of digits and the radix are taken as constants.
  • The data must be (a) nonnegative, (b) integers, (c) in a small range. With a larger range it still sorts, but the cost grows fast.
  • Extra memory: 2·RADIX pointers (the list is relinked in place).
Instructor “Sorting only integers is a drawback. It can be adapted to floating-point types, but by the time you finish adapting it, the other algorithms will have finished sorting.”

Which One When?

General purpose, in memory

Quicksort (median-of-3 + insertion sort on small pieces) or the library qsort.

Worst-case guarantee

Heap sort (in place) or introsort.

Stability / linked lists / disk

Merge sort: stable, merges sorted runs, the basis of external sorting.

Large records

Sort indices/links, not the records (linked merge sort).

Fixed-length integers/keys

Radix: d passes × O(n + r).

Small range

Counting sort.

Common Mistakes

1Forgetting the j == L test in the j loop of partition(): if the pivot is the smallest, the scan runs off the start of the array.
2Always taking a[R] as the pivot on sorted input: the depth becomes n and the stack overflows. Cure: median-of-3 or a random pivot.
3Pushing the pieces in arbitrary order in the non-recursive version: the stack grows to O(n).
4Calling malloc for b[] on every merge sort call (slow), or never allocating it.
5Mixing 1-based heap indices with a 0-based array in heapify: children 2i, 2i+1 are right only in a[1..n].
6return x - y; in a qsort comparator: overflow; or an inconsistent (non-transitive) comparator.

Chapter Summary

Quicksort

Places the pivot and splits the problem: best n lg n, average 1.39 n lg n, worst n².

Improvements

Smaller piece first (lg n stack), median-of-3, insertion sort on small pieces; qsort and introsort.

Merge sort

n lg n in every case, O(n) extra memory; the linked version never copies large records.

Heap sort

Building the heap is O(n), sorting O(n lg n); in place but not stable.

Radix sort

Stable buckets from LSD to MSD: O(d(n + r)); nonnegative integers in a small range.

Analysis tools

Recurrences, iteration, the subtraction trick, differentiating a series: all the course's analysis tools meet here.
