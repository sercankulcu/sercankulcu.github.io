Recursion

Recursive Algorithms

When the logic that solves the whole problem also applies to its subproblems, a recursive algorithm can be used.

Direct recursion

A function calls itself: fact → fact.

Indirect recursion

A function it calls calls it back: A → B → A.

Base case

The smallest instance, solved without recursion. Without it the calls never end (the stack overflows).

Recursive step

Reduces the problem to a smaller instance; every call must move toward the base case.

From the instructor“‘Doesn’t this recursive solution eat a lot of memory?’ Too early for that question. First learn to write the code; only once you can compute its complexity can you say so. You can’t judge recursion before you can write it.”

Recursion

The Stack Activation Frame

  • A function call uses the system stack.
  • Before control passes to the function, some bookkeeping is done: where to return, saving the parameters…
  • This communication and control structure is called a stack frame.
  • Initially the frame holds two values: the return address and a pointer to the previous frame.
  • Every recursive call means a new frame → at depth d the extra space is O(d).

long fact(int n) {
  if (n <= 1)
    return 1;              /* base case */
  return n * fact(n - 1);
}

int main(void) {

  return 0;

Recursion or Iteration?

/* recursive */
long fact(int n) {
  return n <= 1 ? 1 : n * fact(n - 1);
}

/* iterative */
long fact_iter(int n) {
  long f = 1;
  while (n > 1)
    f *= n--;
  return f;
}

Recursion

Tail Recursion

If the recursive call is the last thing a function does (nothing is left to do after it returns), it is called tail recursion.

long fact_tail(int n, long acc) {
  if (n <= 1) return acc;
  return fact_tail(n - 1, n * acc);  /* last: call */
}
/* first call: fact_tail(n, 1) */
fact is not tail-recursive

n * fact(n-1): a multiplication waits after the return, so the frame must be kept.

Accumulator parameter

acc carries the partial result; nothing is left to do on return.

The compiler

A tail call can become a jump (O(1) stack). The C standard does not guarantee this; gcc/clang usually do it when optimizing.

Binary Search

Binary Search

We search a sorted array for a value: return its index if found, −1 otherwise. Each step looks at the middle element and discards half of the range.

Test array

#define COMPARE(x, y) ((x) < (y) ? -1 : (y) < (x) ? 1 : 0)
From the instructor“Return i, not list[i]. Why? So that the error value −1 can’t be confused with an array element that happens to be −1.”

int binsearch(int list[], int searchnum,
              int left, int right) {
  while (left <= right) {
    int middle = (left + right) / 2;
    switch (COMPARE(list[middle], searchnum)) {
      case -1: left = middle + 1; break;
      case 0: return middle;
      case 1: right = middle - 1;
    }
  }
  return -1;
}

Binary Search

Recursive Binary Search

int binsearch(int list[], int x, int l, int r) {
  int m;
  if (l > r) return -1;          /* empty range */
  m = (l + r) / 2;
  switch (COMPARE(list[m], x)) {
    case -1: return binsearch(list, x, m + 1, r);
    case 0:  return m;
    case 1:  return binsearch(list, x, l, m - 1);
  }
  return -1;                     /* unreachable */
}
  • Instead of looping, it calls itself on a smaller range.
  • Base cases: found (case 0) or the range is empty (l > r). For brevity x = searchnum, l/r = left/right, m = middle.
  • Both recursive calls are tail calls: they return the result unchanged.
A common mistake: writing while instead of if in the recursive version. Every branch exits with return, so the loop runs once and the result is correct, but it is misleading: it should be if.

Binary Search

Complexity of Binary Search

Each round at least halves the range: n → n/2 → n/4 → … → 1.

T(n) = T(n/2) + c ⇒ T(n) = O(log n)
  • At most ⌊log₂ n⌋ + 1 rounds.
  • Extra space for the iterative version: O(1).
  • Recursive version: one frame per level → O(log n).
  • Precondition: the array must be sorted and indexable in O(1) (useless on a linked list).

Towers of Hanoi

The Towers of Hanoi Problem

The source tower holds n disks, each larger than the one above it. Goal: move them all to the target tower, using the auxiliary tower.

  1. Move one disk at a time.
  2. Never place a disk on top of a smaller disk.
Recursive solution: to move the largest disk to the target, there must be a moment when the n−1 disks above it are on the auxiliary tower: n−1 disks source→aux, the largest disk source→target, n−1 disks aux→target. h(n) = h(n−1) + 1 + h(n−1).
From the instructor“Some problems can only be solved recursively.”

In theory any recursion can become a loop with an explicit stack; the point is that recursion is the only natural way to express such problems.

void hanoi(int n, char *from, char *via,
           char *to) {
  if (n == 1)
    printf("%s -> %s\n", from, to);
  else {
    hanoi(n - 1, from, to, via);
    printf("%s -> %s\n", from, to);
    hanoi(n - 1, via, from, to);
  }
}

Permutations

The Permutation Problem [O(n!)]

We want to print every arrangement of a set of n ≥ 1 elements: there are n! of them. {a, b, c} → abc, acb, bac, bca, cab, cba.

The recursive idea

The permutations of {a, b, c, d} are:
• a followed by the permutations of {b, c, d}
• b followed by the permutations of {a, c, d}
• c followed by the permutations of {a, b, d}
• d followed by the permutations of {a, b, c}

Implementation by swapping

Bring each element in turn to position i with a swap, permute the remaining n−i−1 positions recursively, then swap back to restore the array (backtracking!).

void perm(char *list, int i, int n) {
  int j, temp;
  if (i == n) {                  /* one arrangement */
    for (j = 0; j < n; j++) printf("%c", list[j]);
    printf("\n");
  } else
    for (j = i; j < n; j++) {
      SWAP(list[i], list[j], temp);
      perm(list, i + 1, n);
      SWAP(list[i], list[j], temp);
    }
}

Recursion Tree and Complexity

Root: no fixed prefix · each level fixes one position · leaves: the 6 arrangements in output order

Number of calls

1 + n + n(n−1) + … + n! calls; n! leaves.

Time

Each leaf prints n characters → O(n·n!). The common shorthand O(n!) misses this factor of n.

Why swap back?

Sibling branches must see the same starting array; the second SWAP repairs it.

Backtracking

Brute Force and Backtracking

Brute force

Generate every candidate and test each one. It relies on raw computing power; there may be 2ⁿ, n! … candidates.

Backtracking

Build the solution step by step; as soon as a partial solution breaks a rule, prune that branch, undo the last choice and try the next.

void backtrack(partial_solution) {
  if (is_complete) { print; return; }
  for (each candidate choice)
    if (satisfies_rules) { choose; backtrack(...); undo_choice; }
}
From the instructor“Keep looking for a better solution: when solving problems with data structures, never be fully sure of your choice. Keep writing, keep discussing; tell yourself, ‘There is a better method, we just haven’t found it.’”

Backtracking

The Satisfiability (SAT) Problem

(x1 ∧ ¬x2) ∨ (¬x1 ∧ x3) ∨ ¬x3

x1, x2, … are Boolean variables taking true/false; ∧, ∨, ¬ are the operators. Question: is there an assignment that makes the formula true?

  • 3 variables → 2³ = 8 possible assignments: {F,F,F}, {F,F,T}, …
  • n variables → 2ⁿ cases; brute force is O(2ⁿ). Even split evenly over m processors it is O(2ⁿ/m): still exponential.
  • SAT is NP-complete; no polynomial-time algorithm is known. 2-SAT is solvable in polynomial time, 3-SAT is NP-complete.

Backtracking

SAT: Evaluation by Postorder Traversal

typedef enum { L_NOT, L_AND, L_OR, L_TRUE, L_FALSE } logical;
typedef struct node *tree_ptr;
struct node {
  tree_ptr left_child, right_child;
  logical data;
  short value;
};

void post_order_eval(tree_ptr t) {
  if (t) {
    post_order_eval(t->left_child);
    post_order_eval(t->right_child);
    switch (t->data) {
      case L_NOT: t->value = !t->right_child->value; break;
      case L_AND: t->value = t->left_child->value
                         && t->right_child->value; break;
      case L_OR:  t->value = t->left_child->value
                         || t->right_child->value; break;
      case L_TRUE:  t->value = 1; break;
      case L_FALSE: t->value = 0; break;
    }
  }
}
  • Postorder: both children first, then the node itself.
  • A ¬ node keeps its single operand in the right child.
  • Leaves: for each assignment the variables’ values are stored as L_TRUE/L_FALSE.
Names like enum { not, and, or, true, false } clash with the C99 <stdbool.h> macros and C23 keywords, and typedef struct node {…}; is a typedef that names nothing. Here we use prefixed names that do not clash.

SAT Variants and Precomputing

CIRCUIT-SAT

Is there an input assignment that makes the output of a given logic circuit 1?

Formula SAT

A propositional formula built with ∧, ∨, ¬, as above.

3-CNF-SAT

An ∧ of ∨-clauses, each with 3 literals: (x1 ∨ ¬x1 ∨ ¬x2) ∧ (x3 ∨ x2 ∨ x4) ∧ (¬x1 ∨ ¬x3 ∨ ¬x4).

Precomputing

The formula tree is built once; each assignment changes only the leaves. A data structure prepared once for work done many times boosts efficiency a lot.

The n-Queens Problem

Place n queens on an n×n chessboard so that no queen attacks another: no two queens share a row, column or diagonal.

  • One queen per row → a solution is an array q[0..n−1].
  • Brute force: nⁿ candidates (one queen per row; 16.8 million for n = 8).
  • Backtracking: go row by row; if no column fits, return to the previous row.
  • Diagonal test: |q[i] − c| == r − i.
int q[8];  /* q[r]: column of the queen in row r */

int is_safe(int r, int c) {
  int i;
  for (i = 0; i < r; i++)
    if (q[i] == c || abs(q[i] - c) == r - i)
      return 0;         /* same column or diagonal */
  return 1;
}

Horowitz–Sahni; Sedgewick. There are 2 solutions for n = 4 and 92 for n = 8.

int place(int r, int n) {
  int c;
  if (r == n) return 1;             /* solved */
  for (c = 0; c < n; c++)
    if (is_safe(r, c)) {
      q[r] = c;
      if (place(r + 1, n)) return 1;
    }
  return 0;                  /* backtrack */
}

The Knight’s Tour on a Chessboard

The knight must visit every square, each exactly once. It moves in an L: 2 across + 1 up/down, or 2 up/down + 1 across.

Δj+1+2+2+1−1−2−2−1
  • Backtracking: try a move; at a dead end, undo the last move and try the next. It always finds a solution, but it is essentially brute force: very slow on 8×8.
  • Heuristic: a “smart” choice; it finds near-optimal solutions without guarantees (like Minesweeper).

Backtracking is not “rewinding the scenario from the end”: it builds the partial solution forward and undoes the last choice at a dead end.

Backtracking

Warnsdorff’s Heuristic (1823)

“Move the knight to the square with the fewest onward moves, but not zero.” Onward moves: the number of free squares reachable directly from that square. Corners and edges are used up first, so dead ends don’t pile up at the end.

The rule is named after H. C. von Warnsdorff. Ties are broken by the order in the move table (0…7).

Common Mistakes

1Forgetting the base case, or writing a step that never reaches it → stack overflow.
2Not returning the result of the recursive call: calling binsearch(...) and discarding the value.
3Using binary search on an unsorted array or a linked list.
4Returning the value found: it can be confused with −1; return the index.
5Forgetting to undo a choice in backtracking (the second SWAP, pick[i] = 0).
6Running an exponential algorithm on large n because “the machine is fast”.

Chapter Summary

Recursion

Base case + shrinking step. Each call is a stack frame; tail recursion can become a loop.

Binary search

Halves the range of a sorted array: O(log n). Return the index; −1 means not found.

Hanoi

h(n) = 2h(n−1) + 1 = 2ⁿ − 1. The call tree = the history of the stack.

Permutations

Swap + recurse + swap back: n! lines of output, O(n·n!).

Backtracking

Build a partial solution, prune and undo when a rule breaks: n-queens, subsets (SAT was solved by brute force here).

Heuristics

Warnsdorff: the square with the fewest onward moves. Never stop looking for a better solution.
