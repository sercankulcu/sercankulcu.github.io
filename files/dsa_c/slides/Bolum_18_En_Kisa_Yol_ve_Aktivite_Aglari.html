En Kısa Yol

Tek Kaynaktan Tek Hedefe: Brute Force

K4 düzlemsel; K5 düzlemsel değil

K4 (0 → 3), n = 4 için 5 yol: 0-1-2-3, 0-1-3, 0-2-1-3, 0-2-3, 0-3

K5 (0 → 4), n = 5 için 1 + 3 + 6 + 6 = 16 yol: 0-1-2-3-4, 0-1-2-4, 0-1-3-2-4, 0-1-3-4, 0-1-4, 0-2-1-3-4, 0-2-1-4, 0-2-3-1-4, 0-2-3-4, 0-2-4, 0-3-1-2-4, 0-3-1-4, 0-3-2-1-4, 0-3-2-4, 0-3-4, 0-4

Tam çizgede yol sayısı: 1 + (n−2) + (n−2)(n−3) + … + (n−2)! ≈ 1 + O(n) + O(n²) + … ≈ O(nⁿ) (kaba ama doğru modelleme). Tek bir hedef için bile!
Hocadan: “Görüldüğü gibi brute force yöntemiyle tek bir kaynaktan tek bir hedefe en kısa yolu bulurken bile karmaşıklık O(nⁿ) oldu… Elbette mantık doğru, ama böyle çözmeyeceğiz.” — Mustafa Ege, VYA2 ders notları, s. 52

Dijkstra

Etkin Çözüme Doğru: Açgözlü (Greedy) Fikir

  • S: en kısa yolu kesinleşmiş düğümler (başta yalnız kaynak 0).
  • w ∉ S için uzaklik[w]: 0’dan başlayıp yalnızca S’deki düğümlerden geçerek w’de biten en kısa yolun uzunluğu.
  • uzaklik[u] en küçük olan u seçilir ve S’ye eklenir.
  • u’nun eklenmesi, u üzerinden geçen yeni yollar açar: uzaklik[u] + maliyet(<u,w>) < uzaklik[w] ise uzaklik[w] günlenir (u–w arasında ara düğüm yok).

u’nun komşularına u üzerinden yeni yollar

Bu, Edsger Dijkstra’nın (1959) algoritmasıdır. Kenar ağırlıkları negatif olmamalıdır (bkz. Bellman-Ford).

Dijkstra

Adım Adım: v0’dan Tüm Düğümlere (s. 52)

S = {v0}. Komşuların uzaklıkları doğrudan kenar maliyetleri: v1 = 10, v3 = 30; diğerleri ∞.

En küçük uzaklıklı v1 (10) S’ye katılır. Güncellenen: v2 = 20.

En küçük uzaklıklı v2 (20) S’ye katılır. Güncellenen: v4 = 30.

En küçük uzaklıklı v3 (30) S’ye katılır. Güncellenen: v5 = 50, v6 = 32.

En küçük uzaklıklı v4 (30) S’ye katılır. Güncellenen: v5 = 40. v5’e v4 üzerinden daha kısa yol bulundu (50 → 40)!

En küçük uzaklıklı v6 (32) S’ye katılır. Güncelleme yok. Notlarda sıra v1…v5, v6 diye verilmiş; ama 32 < 40 olduğu için önce v6 seçilir (sonuç aynı).

En küçük uzaklıklı v5 (40) S’ye katılır. Güncelleme yok.

Dijkstra

C Kodu (düzeltilmiş): Maliyet Matrisi ve minimumBul

#include <limits.h>
#define MAX_DUGUM 6
#define SONSUZ 1000      /* baglanti yok (notlardaki gibi) */
int maliyet[][MAX_DUGUM] = {
    {   0,   50,  10, 1000,   45, 1000},
    {1000,    0,  15, 1000,   10, 1000},
    {  20, 1000,   0,   15, 1000, 1000},
    {1000,   20, 1000,   0,   35, 1000},
    {1000, 1000, 1000,  30,    0, 1000},   /* eksik satir */
    {1000, 1000, 1000,   3, 1000,    0}};  /* 100 -> 1000 */
int minimumBul(int uzaklik[], int n, short gidildi[])
{
    int i, min = INT_MAX, pos = -1;
    for (i = 0; i < n; i++)
        if (uzaklik[i] < min && !gidildi[i]) {
            min = uzaklik[i];  pos = i;
        }
    return pos;
}

Notlardaki koddaki hatalar:

  • Matriste 6 satır olmalı; 4. satır (<4,3> = 30) eksik, 5. satırda 1000 yerine 100 yazılmış.
  • Parametre listesinde maliyet[][MAX_DUGUM]’dan sonra virgül eksik.
  • !gidildi(w) → !gidildi[w] (dizi, fonksiyon değil).
  • INT_MAX için <limits.h>; FALSE/TRUE tanımları.
  • minimumBul −1 dönebilir (erişilemeyen düğüm kalmışsa); çağıran denetlemeli.

Dijkstra

EnKisaYolBul(): Ana Yordam

void EnKisaYolBul(int v, int maliyet[][MAX_DUGUM],
                  int uzaklik[], int onceki[],
                  int n, short gidildi[])
{
    int i, u, w;
    for (i = 0; i < n; i++) {                  /* A1 */
        gidildi[i] = FALSE;
        uzaklik[i] = maliyet[v][i];
        onceki[i] = v;             /* yol icin eklendi */
    }
gidildi[v] = TRUE;  uzaklik[v] = 0;
for (i = 2; i < n; i++) {            /* n-2 tur */
    u = minimumBul(uzaklik, n, gidildi);
    if (u < 0) break;                /* kalan yok */
    gidildi[u] = TRUE;
    for (w = 0; w < n; w++)
        if (!gidildi[w] &&
            uzaklik[u] + maliyet[u][w] < uzaklik[w]) {
            uzaklik[w] = uzaklik[u] + maliyet[u][w];
            onceki[w] = u;
        }
}
}
  • A1: başlangıç değerleri — uzaklıklar doğrudan kenar maliyetleri.
  • A2: dış döngü n − 2 tur: son kalan düğümün uzaklığı zaten kesindir (notlardaki “n−1 adet yol bul” yorumu yanıltıcı).
  • A3: minimumBul O(n).
  • A4: tüm w’ler için gevşetme (relaxation) O(n).
  • onceki[]: yolu bulmak için eklendi (notlardaki ödev).

EnKisaYolBul · Kodu adım adım çalıştır

Kod İzleme: EnKisaYolBul(0, …)

A1 sonrası: uzaklik = 0’ın satırı (1000 = ∞); onceki[] = 0. Kaynak işaretlenir.

minimumBul: işaretsizler arasında en küçük uzaklık 2 (10). Kesinleşti.

w = 3: 10 + 15 = 25 < eski değer → uzaklik[3] = 25, onceki[3] = 2.

minimumBul: işaretsizler arasında en küçük uzaklık 3 (25). Kesinleşti.

w = 1: 25 + 20 = 45 < eski değer → uzaklik[1] = 45, onceki[1] = 3.

minimumBul: işaretsizler arasında en küçük uzaklık 1 (45) — 1 ile 4 eşit (45); < olduğu için küçük indis 1 seçilir. Kesinleşti.

1 üzerinden hiçbir uzaklık kısalmadı (ör. 45 + 10 = 55 > 45).

minimumBul: işaretsizler arasında en küçük uzaklık 4 (45). Kesinleşti.

4 üzerinden hiçbir uzaklık kısalmadı (4’ten tek çıkış <4,3>, 3 zaten işaretli).

n − 2 = 4 tur bitti. Sonuç: 2 → 10, 3 → 25, 1 → 45, 4 → 45; 5’e yol yok (1000 kaldı).

Dijkstra

Analiz ve Yapıları İyileştirmek

Kitaptaki algoritma

n + n[n + n] = n + 2n² = O(n²) — sırasıyla A1, A2, A3, A4’ten.

Min öncelikli kuyruk

Uzaklıklar min-heap’te: A3’teki n yerine log n. Komşuluk listesiyle A4’teki n yerine derece(v).

İyileştirilmiş toplam

Notlar O(n lg n) der; doğrusu her gevşetme de heap’i güncellediği için O((n + e) log n) (Fibonacci heap: O(e + n log n)).

Üç algoritma

Brute force O(nⁿ) · matris O(n²) · heap + liste O((n + e) log n). Yoğun çizgede O(n²) sürüm hâlâ iyidir.

Hocadan: “Minimum öncelikli kuyruğu öğrendikten sonra dizide en küçük elemanı aramak ne kadar hantal kalıyor değil mi? Ne kadar abes! Ne kadar ayıp!” — Mustafa Ege, VYA2 ders notları, s. 53

“Adam matristeki en büyük elemanı bulana kadar, ben v0’dan tüm düğümlere olan en kısa yolları buluyorum.” (s. 53)

Önceller dizisi · Kodu adım adım çalıştır

Kod İzleme: yol_yaz(onceki, 0, 1)

h = 1 ≠ 0: önce öncülün yolu yazılmalı → yol_yaz(…, 3).

h = 3 ≠ 0: önce öncülün yolu yazılmalı → yol_yaz(…, 2).

h = 2 ≠ 0: önce öncülün yolu yazılmalı → yol_yaz(…, 0).

h = s = 0: kaynağa ulaşıldı → 0 yazılır, dönülür.

yol_yaz(2)’e dönüldü: “ -> 2” yazılır.

yol_yaz(3)’e dönüldü: “ -> 3” yazılır.

yol_yaz(1)’e dönüldü: “ -> 1” yazılır.

Yol: 0 -> 2 -> 3 -> 1, maliyet 10 + 15 + 20 = 45. Önce hedeften geriye yürüdük, yazarken çağrı yığını sırayı düzeltti.

void yol_yaz(int onceki[], int s, int h)
{
    if (h == s) {
        printf("%d", s);
        return;
    }
    yol_yaz(onceki, s, onceki[h]);   /* once oncul */
    printf(" -> %d", h);
}

Dijkstra

Yolu Bulmak: Önceller Dizisi

Hocadan: “Şimdi maliyeti bulduk da yolu nasıl bulacağız? Maliyeti ben buldum, yolu da sen bul! … Hangi yoldan gidileceği belli olmadığından dolayı forward çözemezsiniz. Tek bir diziyle çözülebilir: önceller dizisi… Tersten kullanacaksın.” — Mustafa Ege, VYA2 ders notları, s. 54
Neden tek dizi yeter?

Her düğümün en kısa yolu, öncülünün en kısa yolu + bir kenardır (optimal alt yapı). Yollar bir ağaç oluşturur: en kısa yol ağacı.

Güncelleme

Gevşetme başarılıysa onceki[w] = u. Maliyet değiştikçe öncül de değişir.

Tersten kullanmak

onceki[] ile hedeften kaynağa yürünür; özyineleme ya da yığıt ile ters çevrilip yazılır.

Erişilemeyen düğüm

uzaklik[h] ≥ SONSUZ ise “yol yok” yazılmalı; onceki[] anlamsızdır.

Dijkstra 1’i 4 ile kesinleştirir (ondan küçük aday yok). Sonra 2 → 1 kenarı (−3) 1’e 2 maliyetle ulaşır; ama 1 artık işaretlidir. 3 de yanlış kalır.

Varsayım

Dijkstra, seçilen düğüme daha sonra daha ucuz bir yoldan gelinemeyeceğini varsayar; bu yalnızca w ≥ 0 iken doğrudur.

Çözüm

Bellman-Ford: tüm kenarları n − 1 tur gevşet. Negatif döngü varsa en kısa yol tanımsızdır; n. turda hâlâ gevşeme olursa bunu yakalar.

Bellman-Ford (ek konu) · Kodu adım adım çalıştır

Kod İzleme: Bellman-Ford (kaynak 0)

d[] = ∞, kaynak d[0] = 0.

Tur 1, 0→1 (4): d[0] + 4 = 4 daha küçük → d[1] = 4.

Tur 1, 0→2 (5): d[0] + 5 = 5 daha küçük → d[2] = 5.

Tur 1, 1→3 (2): d[1] + 2 = 6 daha küçük → d[3] = 6.

Tur 1, 2→1 (-3): d[2] + -3 = 2 daha küçük → d[1] = 2.

Tur 2, 0→1 (4): 0 + 4 = 4 ≥ d[1] = 2, değişmez.

Tur 2, 0→2 (5): 0 + 5 = 5 ≥ d[2] = 5, değişmez.

Tur 2, 1→3 (2): d[1] + 2 = 4 daha küçük → d[3] = 4.

Tur 2, 2→1 (-3): 5 + -3 = 2 ≥ d[1] = 2, değişmez.

Tur 3: hiçbir kenar gevşemez (d zaten kesin). Genelde n − 1 tur gerekir: en kısa yol en çok n − 1 kenarlıdır.

n. turda da gevşeme yok → negatif döngü yok, return 0. Sonuç d = [0, 2, 5, 4]. Maliyet O(n·e).

for (i = 0; i < n; i++) d[i] = SONSUZ;
d[s] = 0;
for (t = 1; t <= n - 1; t++)          /* n-1 tur */
    for (j = 0; j < e; j++) {
        u = K[j].u;  v = K[j].v;
        if (d[u] != SONSUZ && d[u] + K[j].w < d[v])
            d[v] = d[u] + K[j].w;
    }
for (j = 0; j < e; j++)               /* n. tur */
    if (d[K[j].u] != SONSUZ &&
        d[K[j].u] + K[j].w < d[K[j].v]) return -1;
return 0;              /* -1: negatif dongu var */

Kod İzleme: Floyd-Warshall

A⁻¹ = maliyet matrisi (Horowitz örneği; 2 → 1 doğrudan kenar yok).

k = 0: artık yollar 0 düğümünden (ve daha küçük numaralılardan) geçebilir.

A[2][0] + A[0][1] = 3 + 4 = 7 < ∞ → A[2][1] = 7.

k = 1: artık yollar 1 düğümünden (ve daha küçük numaralılardan) geçebilir.

A[0][1] + A[1][2] = 4 + 2 = 6 < 11 → A[0][2] = 6.

k = 2: artık yollar 2 düğümünden (ve daha küçük numaralılardan) geçebilir.

A[1][2] + A[2][0] = 2 + 3 = 5 < 6 → A[1][0] = 5.

Bitti: FA = tüm çiftler arası en kısa uzaklıklar. Üç iç içe döngü → O(n³); negatif kenar olabilir, negatif döngü olamaz.

for (i = 0; i < n; i++)
    for (j = 0; j < n; j++)
        A[i][j] = maliyet[i][j];
for (k = 0; k < n; k++)              /* ara dugum k */
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            if (A[i][k] + A[k][j] < A[i][j])
                A[i][j] = A[i][k] + A[k][j];

Düğüm Aktif Ağlar (AoV) ve Öncül İlişkisi

  • AoV (activity on vertex/node): aktiviteler düğüm, öncül ilişkileri (precedence relation) kenar: i dersi j’nin öncülüyse <i, j>.
  • C3 ve C6, C7’nin yakın öncülleridir (immediate predecessors).
  • C9, C10, C12, C13, C7’nin yakın ardıllarıdır (immediate successors).
  • C14, C3’ün bir ardılıdır ama yakın ardılı değildir.

Tanım: Topolojik Sıra (Topological Order)

Düğümlerin öyle bir doğrusal sırası ki, i, j’nin öncülüyse sırada i, j’den önce gelir. Topolojik sıra birden çok olabilir; çizgede döngü varsa hiç yoktur.

Topolojik Sıra Bulmak: Öncülsüz Düğümü Sil (s. 55)

a) v0’ın öncülü yok → ilk seçilecek düğüm.

Döngü Tespiti ve Analiz

Döngüyü de bulur

Döngü, A ve B’nin karşılıklı olarak birbirinin öncülü olmasıdır — bu bir hatadır. “Döngü varsa proje hiç bitmeyecektir.” Bir turda yığıt boşsa ama düğüm kalmışsa döngü vardır.

Analiz

İlk for O(n), ikinci for O(n); else bloğu dj (çıkış derecesi). Toplam O(Σdi + n) = O(n + e).

Sıra neye bağlı?

Yığıta eklenme sırası komşuluk listesindeki sıraya bağlıdır; kuyruk kullanılsaydı (Kahn) başka ama yine geçerli bir sıra çıkardı.

Çizgenin yapısı

e, çizgenin bağlanışına göre O(n) ile O(n²) arasında değişir.

Aktivite Ağları

Kenar Aktif Ağlar (AoE)

v0 başlangıç, v8 bitiş: 11 aktivite (kenar), 9 olay (düğüm)

AoE (activity on edge/arc)

AoV’nin tersine yönlü kenarlar aktiviteleri (süreleriyle), düğümler olayları temsil eder.

Olay (event)

Projenin tamamlanması için ulaşılması gereken ara aşama: “bitmesi gereken iş bir düğümle ifade ediliyor”.

Paralellik

a0, a1, a2 paralel başlar; a3 ve a4 bitince a6, a7 başlar; a10 için a7 ve a8 bitmiş olmalıdır.

Aktivite Ağları

Graph Drawing: AoV’den AoE’ye, Yapay Aktivite

AoV’de 4 aktivitesi 2 ve 3’ü bekler; AoE’de bu, maliyeti 0 olan bir yapay kenarla gösterilir.

Yapay aktivite (dummy activity)

Maliyeti 0 olan kenar. Ör. yukarıdaki projede a6 ve a7’nin a3, a4 ve a5 bitince başlaması istenseydi <v5, v4> yapay aktivitesi gerekirdi.

Minimum arc problem

Çizgeyi en az sayıda yapay aktiviteyle çizme problemi: NP-zor. Notlara göre dünyada birkaç yüksek lisans ve bir doktora tezi var.

Yöntemler

PERT (Program Evaluation and Review Technique, 1958), CPM (Critical Path Method, 1950’lerin sonu), RAMPS (Resource Allocation and Multi-Project Scheduling).

Notlarda PERT “Program/Project Evolution…” ve CPM “1950” diye geçiyor; PERT’in açılımı Evaluation, CPM 1957–59 (DuPont) dönemidir.

Özet

Bölüm Özeti

En kısa yol

Brute force O(nⁿ); Dijkstra açgözlüdür, w ≥ 0 ister: O(n²) ya da O((n + e) log n).

Yol

Önceller dizisi tek başına yeter; tersten (özyineleme/yığıt) yazdırılır.

Genellemeler

Negatif kenar: Bellman-Ford O(ne). Tüm çiftler: Floyd-Warshall O(n³).

AoV ve topolojik sıra

Sayaç + gömülü yığıt; O(n + e); döngüyü de yakalar.

AoE ve zamanlar

İleri: max ile en erken; geri (ters çizge): min ile en geç. Bolluk = geç − erken.

Kritik yol

Bolluğu 0 olan aktiviteler; projenin süresini belirler.
