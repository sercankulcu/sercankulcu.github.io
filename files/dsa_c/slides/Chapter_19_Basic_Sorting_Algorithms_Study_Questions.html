Multiple Choice · Sorting Concepts

Question 1: Braces-Only SWAP

The SWAP macro is defined with braces only instead of do { … } while (0). What happens when the program is compiled and run?

#define SWAP(A, B) { int t = A; A = B; B = t; }
int main(void) {
    int a = 2, b = 1;
    if (a > b)
        SWAP(a, b);
    else
        printf("sorted\n");
    printf("%d %d\n", a, b);
    return 0;
}

B: SWAP(a, b); expands to { … };. The semicolon after the block is an empty statement; the if ends with the block and the else is left dangling (zig cc: "expected expression"). do { … } while (0) behaves as a single statement and swallows the semicolon.

Multiple Choice · Sorting Concepts

Question 2: Stable Sorting

Records (Ali, 70), (Can, 85), (Ece, 70), (Banu, 85), (Deniz, 60) arrive in this order. Which is the output of a stable sort by grade in ascending order?

C: A stable sort keeps records with equal keys in their input order: Ali comes before Ece, Can before Banu. A and D reverse the 70s, B and D reverse the 85s. A program run with insertion sort (a[j] > v) also gave C.

Step-by-Step Trace · Selection Sort

Question 3: Is Selection Sort Stable?

selection(a, 0, 4) is called with a = [3a, 5, 3b, 1, 2] (3a and 3b are the same value; the labels only help track the order). Is the order of equal items preserved?

The two 3s are labelled: 3a first, 3b second. A stable sort must keep this order.

Pass i = 0: a[0..4] is scanned; the smallest is a[3] = 1.

SWAP(a[0], a[3]): 1 moves to the front; 3a jumps to position 3 and ends up behind 3b.

Pass i = 1: a[1..4] is scanned; the smallest is a[4] = 2.

SWAP(a[1], a[4]): 2 moves forward, 5 jumps to position 4.

Pass i = 2: a[2..4] is scanned; the smallest is a[2] = 3b.

min = i: the item is swapped with itself; the array does not change.

Pass i = 3: a[3..4] is scanned; the smallest is a[3] = 3a.

min = i: the item is swapped with itself; the array does not change.

The result is sorted but 3b is before 3a: because of the long-distance swap, selection sort is not stable.

void selection(int a[], int L, int R) {
    for (int i = L; i < R; i++) {
        int min = i;
        for (int j = i + 1; j <= R; j++)
            if (less(a[j], a[min]))
                min = j;
        SWAP(a[i], a[min]);
    }
}

Multiple Choice · Selection Sort

Question 4: Counting in Selection Sort

On an array of n = 8 items that is already sorted, selection makes how many comparisons and how many SWAP calls?

A: The inner loop does not know the array is sorted: 7 + 6 + … + 1 = 28 comparisons. SWAP is called at the end of every outer pass; since min = i, the item is swapped with itself: 7 calls, 0 real moves. The number of comparisons does not depend on the input.

Spot the Bug · Selection Sort

Question 5: Keeping the Minimum Value

In this selection sort, min holds the value instead of the index. For a = [4, 2, 5, 1], what is the array after selection(a, 0, 3)? Fix the bug.

void selection(int a[], int L, int R) {
    for (int i = L; i < R; i++) {
        int min = a[i];
        for (int j = i + 1; j <= R; j++)
            if (a[j] < min)
                min = a[j];
        SWAP(a[i], min);
    }
}
Show answer

Result [1, 1, 1, 1]:

  • i = 0: min = 1. SWAP(a[0], min) writes 1 into a[0], while 4 goes into the local min and is lost: [1, 2, 5, 1].
  • i = 1: the smallest is again 1 (a[3]) → [1, 1, 5, 1]. i = 2: → [1, 1, 1, 1].

The smallest item is copied into a[i], but the old value of a[i] is not written into the cell it came from; values multiply and 4, 2 and 5 are erased. A swap needs the index: int min = i;, if (a[j] < a[min]) min = j;, SWAP(a[i], a[min]);

Output Question · Insertion Sort

Question 6: Comparisons and Shifts

Counters have been added to insertion sort (the comma operator increments the counter first, then compares). What does the program print?

long comparisons = 0, shifts = 0;
void insertion_count(int a[], int L, int R) {
  for (int i = L + 1; i <= R; i++) {
    int v = a[i], j = i - 1;
    while (j >= L &&
           (comparisons++, a[j] > v)) {
      a[j + 1] = a[j];  j--;  shifts++;
    }
    a[j + 1] = v;
  }
}
/* main: int a[] = {3, 7, 4, 1, 5};
   insertion_count(a, 0, 4);
   printf("%ld %ld", comparisons, shifts); */
Show answer

Output: 8 5

  • i = 1 (7): 3 > 7 is false → 1 comparison.
  • i = 2 (4): 7 shifted, 3 stopped it → 2 comparisons, 1 shift.
  • i = 3 (1): 7, 4, 3 shifted; when j = −1, j >= L is false and a[j] is never tested → 3 comparisons, 3 shifts.
  • i = 4 (5): 7 shifted, 4 stopped it → 2 comparisons, 1 shift.

The number of shifts equals the number of inversions: (3,1), (7,4), (7,1), (7,5), (4,1) = 5.

Multiple Choice · Insertion Sort

Question 7: The j >= 0 Bound

Instead of the inner loop condition j >= L, j >= 0 has been written. For a = [9, 8, 5, 3, 4], what is the array after insertion(a, 2, 4)?

while (j >= 0 && a[j] > v) {
    a[j + 1] = a[j];
    j--;
}
a[j + 1] = v;

D: Only a[2..4] should be sorted. When 3 is placed, 5, 8 and 9 are shifted right: [3, 9, 8, 5, 4]. Then 4 shifts 9, 8, 5 and stops behind 3: [3, 4, 9, 8, 5]. The part outside the subarray is corrupted, and the subarray is not sorted either. With the correct bound the result is A.

Multiple Choice · Bubble Sort

Question 8: Swaps in Bubble Sort

bubble sorts the array [3, 5, 1, 4, 2]. How many swaps does it make?

B: An adjacent swap removes exactly one inversion, so the number of swaps equals the number of inversions: (3,1), (3,2), (5,1), (5,4), (5,2), (4,2) = 6. Without early exit, the number of comparisons is n(n − 1)/2 = 10 for every input (counted in C).

Step-by-Step Trace · Counting Sort

Question 9: Stability in Counting Sort

counting_sort is called with a = [2, 0, 2, 1, 0, 2], r = 5, k = 2 (the labels track equal items). How are the arrays c and b filled?

L1–L2: c[x] = how many times the value x occurs: two 0s, one 1, three 2s.

L3 cumulative sum: c[x] = number of items less than or equal to x. The 2s will go to b[3..5].

L4 starts from the right: a[5] = 2c → b[5] (the rightmost 2); c[2] = 5.

L4: a[4] = 0b → b[1]; c[0] becomes 1.

L4: a[3] = 1 → b[2]; c[1] becomes 2.

L4: a[2] = 2b → b[4]; c[2] becomes 4.

L4: a[1] = 0a → b[0]; c[0] becomes 0.

L4: a[0] = 2a → b[3]; c[2] becomes 3.

Result [0a, 0b, 1, 2a, 2b, 2c]: the order of equal items is preserved. Because the scan goes from the right, the last copy of each value is written into the rightmost free slot.

/* L1 */
for (int i = 0; i <= k; i++) c[i] = 0;
/* L2 */
for (int j = 0; j <= r; j++) c[a[j]]++;
/* L3 */
for (int i = 1; i <= k; i++)
    c[i] += c[i - 1];
/* L4 */
for (int j = r; j >= 0; j--) {
    b[c[a[j]] - 1] = a[j];
    c[a[j]]--;
}

Multiple Choice · Counting Sort

Question 10: L4 Left to Right

counting_sort: if the L4 loop is written as for (int j = 0; j <= r; j++), what happens?

A: c[x] still points to the last position of the block of x's. Scanning from the left writes the first copy of x at the right end of the block and the last one at the left end: values correct, equal items reversed. For plain numbers the difference is invisible, but sorting by digit needs stability and the result breaks.

Coding Question · Counting Sort

Question 11: Counting Sort with Negative Values

Write the routine that stably sorts n integers with values in the range [lo, hi] (possibly negative): int counting_range(const int a[], int b[], int n, int lo, int hi). Allocate the counter array on the heap; return −1 on error.

Show answer 
int counting_range(const int a[], int b[], int n,
                   int lo, int hi) {
  if (hi < lo) return -1;
  int k = hi - lo + 1;
  int *c = calloc(k, sizeof *c);       /* zeroed */
  if (c == NULL) return -1;
  for (int j = 0; j < n; j++) c[a[j] - lo]++;
  for (int i = 1; i < k; i++) c[i] += c[i - 1];
  for (int j = n - 1; j >= 0; j--)     /* stable */
    b[--c[a[j] - lo]] = a[j];
  free(c);
  return 0;
}

The value x is counted in cell c[x − lo], so −2 falls to index 0. For a = [3, −2, 0, 3, −1, −2], lo = −2, hi = 3, b = [−2, −2, −1, 0, 3, 3]. Time and memory are O(n + k).

Step-by-Step Trace · Shell and Bucket Sort

Question 12: Fewer Shifts with Shell Sort

shell_sort is called with [5, 1, 6, 2, 4, 3] (h = 3, 1). In which steps do shifts occur? How does the total number of shifts compare with that of plain insertion sort?

The number of inversions is 8: plain insertion sort would make 8 shifts.

Gap h = 3: the pairs (a[0], a[3]), (a[1], a[4]), (a[2], a[5]) are insertion-sorted separately.

i = 3: v = 2, one shift of 3 positions back → a[0] = 2. Total shifts: 1.

i = 5: v = 3, one shift of 3 positions back → a[2] = 3. Total shifts: 2.

Last round h = 1: ordinary insertion sort, but the array is now almost sorted.

i = 1: v = 1, one shift of 1 position back → a[0] = 1. Total shifts: 3.

i = 4: v = 4, one shift of 1 position back → a[3] = 4. Total shifts: 4.

h = 0: done. 4 shifts in total; the two long-distance shifts in the h = 3 round removed 6 of the 8 inversions at once.

void shell_sort(int a[], int n) {
    for (int h = n / 2; h > 0; h /= 2)
        for (int i = h; i < n; i++) {
            int v = a[i], j = i;
            while (j >= h && a[j - h] > v) {
                a[j] = a[j - h];
                j -= h;
            }
            a[j] = v;
        }
}

Question 13: Buckets

bucket_sort is called with n = 5 and a = [0.42, 0.32, 0.23, 0.52, 0.25]. Which bucket does each number fall into? What are the bucket lists once the distribution is done? Is this input good for bucket sort?

Show answer

Bucket number ⌊5x⌋: 0.42 → 2, 0.32 → 1, 0.23 → 1, 0.52 → 2, 0.25 → 1.

bucket01234
list—0.23 → 0.25 → 0.320.42 → 0.52——

Each number is inserted into its list in sorted order (0.23 before 0.32; 0.25 between the two). Concatenating the buckets in order gives [0.23, 0.25, 0.32, 0.42, 0.52].

Because the numbers are clustered in [0.2, 0.6), three of the five buckets stay empty and one holds three items. The weaker the uniform-distribution assumption, the larger the share of insertion sort inside the buckets; in the worst case O(n²).

Multiple Choice · Optimal Sorting Time

Question 14: Lower Bound for Six Items

At least how many comparisons must a comparison-based algorithm that sorts 6 distinct items make in the worst case?

C: The decision tree has at least 6! = 720 leaves. Since 2⁹ = 512 < 720 ≤ 1024 = 2¹⁰, the height is at least ⌈lg 720⌉ = 10. Selection sort makes 15 comparisons on every input, 5 more than the lower bound.

Coding Question · Summary

Question 15: Sorting Records Stably

typedef struct { char name[12]; int grade; } student; records must be sorted by grade in ascending order in a stable and in-place way. Write the routine void sort_students(student a[], int n) using insertion sort.

Show answer 
void sort_students(student a[], int n) {
  for (int i = 1; i < n; i++) {
    student v = a[i];  /* copy of the record */
    int j = i - 1;
    while (j >= 0 && a[j].grade > v.grade) {
      a[j + 1] = a[j];  /* struct assignment */
      j--;
    }
    a[j + 1] = v;
  }
}

Stability comes from the strict > comparison: shifting stops at an equal grade, so the item stays behind its equal. >= would make equal items swap places. A struct assignment copies all fields; for large records it is cheaper to sort an array of indices or pointers. The input (Ali, 70), (Can, 85), (Ece, 70), (Banu, 85), (Deniz, 60) gives Deniz, Ali, Ece, Can, Banu.

Multiple Choice · Summary

Question 16: Which Algorithm?

An array of 100,000 records, almost sorted (only a few records are out of place), is to be sorted stably without extra memory. Which is the most suitable?

D: Insertion sort is stable and in place; on nearly sorted data the number of shifts equals the number of inversions, which is very small. Selection is blind to the input (≈ n²/2 comparisons) and unstable; Shell is unstable; counting sort needs extra memory and makes sense only for a small integer range.
