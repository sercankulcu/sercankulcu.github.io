Shortest Paths

Single Source, Single Target: Brute Force

K4 is planar; K5 is not

K4 (0 → 3), 5 paths for n = 4: 0-1-2-3, 0-1-3, 0-2-1-3, 0-2-3, 0-3

K5 (0 → 4), 1 + 3 + 6 + 6 = 16 paths for n = 5: 0-1-2-3-4, 0-1-2-4, 0-1-3-2-4, 0-1-3-4, 0-1-4, 0-2-1-3-4, 0-2-1-4, 0-2-3-1-4, 0-2-3-4, 0-2-4, 0-3-1-2-4, 0-3-1-4, 0-3-2-1-4, 0-3-2-4, 0-3-4, 0-4

Number of paths in a complete graph: 1 + (n−2) + (n−2)(n−3) + … + (n−2)! ≈ 1 + O(n) + O(n²) + … ≈ O(nⁿ) (a rough but valid model). And that is for a single target!
Instructor: “As you see, brute force costs O(nⁿ) even for the shortest path from one source to one target… The logic is right, of course, but this is not how we will solve it.”

Dijkstra

Toward an Efficient Solution: The Greedy Idea

  • S: vertices whose shortest paths are final (initially just the source 0).
  • For w ∉ S, dist[w] is the length of the shortest path that starts at 0, passes only through vertices in S, and ends at w.
  • Pick the u with the smallest dist[u] and add it to S.
  • Adding u opens new paths through u: if dist[u] + cost(<u,w>) < dist[w], update dist[w] (no intermediate vertex between u and w).

new paths to u's neighbors through u

This is Edsger Dijkstra's algorithm (1959). Edge weights must not be negative (see Bellman-Ford).

Dijkstra

Step by Step: From v0 to All Vertices

S = {v0}. The neighbors' distances are the edge costs: v1 = 10, v3 = 30; the rest are ∞.

v1 (10) has the smallest distance and joins S. Updated: v2 = 20.

v2 (20) has the smallest distance and joins S. Updated: v4 = 30.

v3 (30) has the smallest distance and joins S. Updated: v5 = 50, v6 = 32.

v4 (30) has the smallest distance and joins S. Updated: v5 = 40. A shorter path to v5 through v4 was found (50 → 40)!

v6 (32) has the smallest distance and joins S. No updates. The order depends on distance, not on vertex number; 32 < 40, so v6 comes first.

v5 (40) has the smallest distance and joins S. No updates.

Dijkstra

C Code: The Cost Matrix and choose

#include <limits.h>
#define MAX_VERTICES 6
#define INF 1000         /* no edge */
int cost[][MAX_VERTICES] = {
    {   0,   50,  10, 1000,   45, 1000},
    {1000,    0,  15, 1000,   10, 1000},
    {  20, 1000,   0,   15, 1000, 1000},
    {1000,   20, 1000,   0,   35, 1000},
    {1000, 1000, 1000,  30,    0, 1000},   /* missing row */
    {1000, 1000, 1000,   3, 1000,    0}};  /* 100 -> 1000 */
int choose(int dist[], int n, short found[])
{
    int i, min = INT_MAX, pos = -1;
    for (i = 0; i < n; i++)
        if (dist[i] < min && !found[i]) {
            min = dist[i];  pos = i;
        }
    return pos;
}

Details:

  • Write !found[w]; !found(w) calls the array as if it were a function.
  • <limits.h> for INT_MAX; FALSE/TRUE must be defined.
  • choose may return −1 (no unmarked vertex left); the caller must check. An unreachable vertex can also be chosen: INF (1000) < INT_MAX.

Dijkstra

shortest_path(): The Main Function

void shortest_path(int v, int cost[][MAX_VERTICES],
                   int dist[], int pred[],
                   int n, short found[])
{
    int i, u, w;
    for (i = 0; i < n; i++) {                  /* A1 */
        found[i] = FALSE;
        dist[i] = cost[v][i];
        pred[i] = v;               /* kept for the path */
    }
    found[v] = TRUE;  dist[v] = 0;
    for (i = 2; i < n; i++) {        /* n-2 rounds */
        u = choose(dist, n, found);
        if (u < 0) break;            /* none left */
        found[u] = TRUE;
        for (w = 0; w < n; w++)
            if (!found[w] &&
                dist[u] + cost[u][w] < dist[w]) {
                dist[w] = dist[u] + cost[u][w];
                pred[w] = u;
            }
    }
}
  • A1: initial values; the distances are the direct edge costs.
  • A2: the outer loop runs n − 2 rounds: the last remaining vertex's distance is already final.
  • A3: choose is O(n).
  • A4: relaxation for every w, O(n).
  • pred[] is kept to trace the path back.

Dijkstra

Analysis, and Better Structures

The textbook algorithm

n + n[n + n] = n + 2n² = O(n²), from A1, A2, A3 and A4 in turn.

Min priority queue

Keep the distances in a min heap: log n instead of n in A3. With adjacency lists, degree(v) instead of n in A4.

Improved total

A common mistake is to say O(n lg n); every relaxation also updates the heap, so the right bound is O((n + e) log n) (Fibonacci heap: O(e + n log n)).

Three algorithms

Brute force O(nⁿ) · matrix O(n²) · heap + lists O((n + e) log n). On dense graphs the O(n²) version is still good.

        printf("%d", s);

    printf(" -> %d", h);
}

Dijkstra

Finding the Path: The Predecessor Array

Instructor: “We have the cost, but how do we find the path? Cost found, now the path! … Since we don't know which way to go, it can't be solved forward. One array is enough: the predecessor array… used backward.”
Why is one array enough?

Each vertex's shortest path is its predecessor's shortest path plus one edge (optimal substructure). The paths form a tree: the shortest-path tree.

Update

On a successful relaxation, pred[w] = u. When the cost changes, so does the predecessor.

Using it backward

pred[] walks from the target back to the source; recursion or a stack reverses it for printing.

Unreachable vertex

If dist[h] ≥ INF, print “no path”; pred[] is meaningless.

Why Dijkstra Fails with Negative Edges (Extra Topic)

Dijkstra finalizes 1 at 4 (no smaller candidate). Then edge 2 → 1 (−3) reaches 1 at cost 2, but 1 is already marked. 3 stays wrong too.

Assumption

Dijkstra assumes a chosen vertex can never be reached later by a cheaper path; that holds only when w ≥ 0.

Fix

Bellman-Ford: relax every edge for n − 1 rounds. With a negative cycle shortest paths are undefined; a relaxation in round n detects it.

Bellman-Ford (extra topic) · Step through the code

Code Trace: Bellman-Ford (Source 0)

d[] = ∞, source d[0] = 0.

Round 1, 0→1 (4): d[0] + 4 = 4 is smaller → d[1] = 4.

Round 1, 0→2 (5): d[0] + 5 = 5 is smaller → d[2] = 5.

Round 1, 1→3 (2): d[1] + 2 = 6 is smaller → d[3] = 6.

Round 1, 2→1 (-3): d[2] + (−3) = 2 is smaller → d[1] = 2.

Round 2, 0→1 (4): 0 + 4 = 4 ≥ d[1] = 2, no change.

Round 2, 0→2 (5): 0 + 5 = 5 ≥ d[2] = 5, no change.

Round 2, 1→3 (2): d[1] + 2 = 4 is smaller → d[3] = 4.

Round 2, 2→1 (-3): 5 + (−3) = 2 ≥ d[1] = 2, no change.

Round 3: no edge relaxes (d is already final). In general n − 1 rounds are needed: a shortest path has at most n − 1 edges.

No relaxation in round n either → no negative cycle, return 0. Result d = [0, 2, 5, 4]. Cost O(n·e).

k = 0: paths may now pass through vertex 0 (and lower-numbered ones).

for (i = 0; i < n; i++)

Activity-on-Vertex (AOV) Networks and Precedence

  • AOV (activity on vertex): activities are vertices, the precedence relation gives the edges: <i, j> if course i is a prerequisite of j.
  • C3 and C6 are immediate predecessors of C7.
  • C9, C10, C12 and C13 are immediate successors of C7.

Definition: Topological Order

A linear order of the vertices in which i comes before j whenever i is a predecessor of j. There can be several topological orders; if the graph has a cycle there is none.

It goes back to the planning methods (PERT, 1958) developed during the Cold War to speed up missile (Polaris) production. Two valid topological orders of the courses (checked by program):

C1, C2, C4, C5, C3, C6, C8, C7, C10, C13, C12, C14, C15, C11, C9
C4, C5, C2, C1, C6, C3, C8, C15, C7, C9, C10, C11, C12, C13, C14

Check

For every edge <i, j>, does i come before j in the order? All 14 edges pass.

Uses

Course plans, build order (make), task scheduling, spreadsheet cells, earliest times.

The Topological Sort Function

void topsort(hdnodes graph[], int n)
{
    int i, j, k, top = -1;
    node_pointer p;
    for (i = 0; i < n; i++)      /* count 0: push */
        if (!graph[i].count) {
            graph[i].count = top;  top = i; }
    for (i = 0; i < n; i++) {
        if (top == -1) { printf("cycle"); break; }
        j = top;  top = graph[top].count;
        printf("%d ", j);
        for (p = graph[j].link; p; p = p->link) {
            k = p->vertex;
            if (--graph[k].count == 0) {
                graph[k].count = top;  top = k; }
        }
    }
}
Instructor: “There is no stack anywhere, yet we wrote comments saying ‘push’ and ‘pop’. That is exactly why comments matter. It does use a stack, but how?”
  • Vertices with no predecessors left are chained together through their count fields: count now means “the vertex below me on the stack”. This resembles the parent array of disjoint sets.
  • The pair count--; if (!count) is written here as --count == 0 (same meaning).

Cycle Detection and Analysis

It finds cycles too

A cycle means A and B each precede the other, which is an error. “With a cycle the project never ends.” If the stack is empty in some round while vertices remain, there is a cycle.

Analysis

The first for is O(n), the second O(n); the inner for runs dj times (out-degree). Total O(Σdi + n) = O(n + e).

What decides the order?

The push order follows the order of the adjacency lists; with a queue (Kahn) you would get a different but still valid order.

Graph structure

Depending on how the graph is connected, e ranges from O(n) to O(n²).

Activity Networks

Activity-on-Edge (AOE) Networks

v0 start, v8 finish: 11 activities (edges), 9 events (vertices)

AOE (activity on edge/arc)

Unlike AOV, directed edges are activities (with durations) and vertices are events.

Event

A milestone the project must reach: “the work that must be finished is expressed by a vertex”.

Parallelism

a0, a1 and a2 start in parallel; a6 and a7 start once a3 and a4 finish; a10 needs a7 and a8 finished.

Activity Networks

Graph Drawing: From AOV to AOE, Dummy Activities

In AOV, activity 4 waits for 2 and 3; in AOE this needs a dummy edge of cost 0.

Dummy activity

An edge of cost 0. E.g. if a6 and a7 above had to wait for a3, a4 and a5, the dummy activity <v5, v4> would be needed.

Minimum arc problem

Drawing the graph with the fewest dummy activities is NP-hard, a research topic with thesis-level work on it.

Methods

PERT (Program Evaluation and Review Technique, 1958), CPM (Critical Path Method, late 1950s), RAMPS (Resource Allocation and Multi-Project Scheduling).

Early/Late Times

The Critical Path

Critical paths: v0-v1-v4-v6-v8 and v0-v1-v4-v7-v8 (length 18)

  • Summing activity durations, the longest path from v0 to v8 is the critical path. There may be more than one.
  • Here 6 + 1 + 9 + 2 = 18 and 6 + 1 + 7 + 4 = 18 → the project ends at the earliest in 18 days.
  • If its prerequisites finish as fast as possible, when does an activity start? How late can it start without delaying the project?
  • To the crews on critical tasks: “Finish in 4 days, don't let it slip to 5. If it's done in 3, I'll be happy.” An operations research problem.

Early/Late Times

Earliest Start Times

  • If ai = <k, m>, then early(i) = earliest[k]: the activity starts when the event at its tail occurs.
  • E.g. a1: k = v0 → 0; a5: k = v3 → 5 (a2); a8: k = v5 → 5 + 2 = 7.
  • Two paths lead to v4: a3 ends at the earliest at 6 + 1 = 7, a4 at 4 + 1 = 5. Both must finish → wait for the longer (7).
  • earliest[m] = max { earliest[k] + dur(<k,m>) }, k ∈ P(m) (immediate predecessors).
  • The array starts at 0: day 0 of the project (e.g. “May 8”); with 10, everything would shift by 10.
  • Compute in topological order: the predecessors' values must be known first.
/* in topsort, before decrementing count: */
if (earliest[k] < earliest[j] + p->duration)
    earliest[k] = earliest[j] + p->duration;

A duration field is added to the list node; the value is updated when a longer path is found.

Latest Start Times

  • A backward pass: reverse every arrow and work in the topological order of that graph (v8 first, v0 last). Structure: the inverse adjacency lists, built in O(n + e).
  • Last vertex: latest[n−1] = earliest[n−1] = 18. The array starts filled with 18.
  • ai = <k, m>: late(i) = latest[m] − dur. v7 at the latest 18 − 4 = 14, v6 at the latest 18 − 2 = 16.
  • With several successors take the smallest: latest[k] = min { latest[m] − dur }. E.g. v0: 6 − 6 = 0 via v1, 6 − 4 = 2 via v2, 8 − 5 = 3 via v3 → 0. Taking the largest (3) would delay v1 and push the project to 21.
if (latest[k] > latest[j] - p->duration)
    latest[k] = latest[j] - p->duration;

  • Slack = latest − earliest (ai = <k,m>: latest[m] − dur − earliest[k]). E.g. a4: earliest 4, latest 6 → it can slip 2 days.
  • An activity with slack 0 is critical: it must start at its earliest time. Project-management software charts the slack.

  • The critical activities form one (or more) paths from v0 to v8: the critical path.
  • The whole computation: forward pass O(n + e) + transposed lists O(n + e) + backward pass O(n + e) = O(n + e).
  • In a DAG the “longest path” is easy in topological order; in a general graph the longest simple path is NP-hard.
  • Free float: slack usable without delaying the earliest time of any successor; 0 for a2 and a5, 3 for a8.

Common Mistakes

1Using Dijkstra on a graph with negative edges.
2Choosing INT_MAX for ∞ and overflowing in dist[u] + cost.
3Taking the min for earliest times and the max for latest times (it is the other way round!).
4Computing a latest time before its successors are final: the order must be the topological order of the reversed graph (or the forward order reversed).
5Starting the topological order at an arbitrary vertex; treating a vertex as final before its predecessors are processed.
6Trying to build the path forward instead of using the predecessor array backward.

Chapter Summary

Shortest paths

Brute force O(nⁿ); Dijkstra is greedy and needs w ≥ 0: O(n²) or O((n + e) log n).

The path

The predecessor array alone is enough; print it backward (recursion/stack).

Generalizations

Negative edges: Bellman-Ford O(ne). All pairs: Floyd-Warshall O(n³).

AOV and topological order

Counts + an embedded stack; O(n + e); it also detects cycles.

AOE and times

Forward: earliest with max; backward (reversed graph): latest with min. Slack = late − early.

Critical path

The activities with zero slack; they set the project's length.
