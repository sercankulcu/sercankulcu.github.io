Multiple Choice · Shortest Paths

Question 1: Counting Paths by Brute Force

In the complete graph K6 (vertices 0..5), how many different paths from 0 to 5 repeat no vertex?

C: The intermediate vertices are an ordered selection from {1, 2, 3, 4}: 1 (direct) + 4 + 4·3 + 4·3·2 + 4! = 1 + 4 + 12 + 24 + 24 = 65 (counted with Python; 5 in K4, 16 in K5). The last term (n − 2)! quickly dominates; even for a single target, brute force grows exponentially.

Question 2: Finalization Order

Dijkstra is run from 0 on the directed graph in the figure. In which order are the vertices finalized (added to S)?

A: At first 1 → 10, 2 → 3. 2 is chosen and 1 → 7, 3 → 11, 4 → 5. The smallest is 4 (5); it has no outgoing edge. Then 1 (7) is chosen and 3 → 9. The last one left is 3 (9). The order is decided by distance, not by vertex number.

Question 4: Path with a Stack

At the end of Dijkstra, pred = {0, 2, 0, 1, 2} has been found (source 0). With the non-recursive path writer print_path2: what do the calls print_path2(pred, 0, 3), print_path2(pred, 0, 4) and print_path2(pred, 0, 0) print?

void print_path2(int pred[], int s, int h) {
    int path[MAX], k = 0;
    while (h != s) {
        path[k++] = h;
        h = pred[h];
    }
    printf("%d", s);
    while (k > 0)
        printf(" -> %d", path[--k]);
    printf("\n");
}
Show answer

Output:

0 -> 2 -> 1 -> 3
0 -> 2 -> 4
0
  • h = 3: the values 3, 1, 2 are pushed onto the path array (from target to source); the second loop prints them in reverse order (like a stack).
  • If h = s, the first loop never runs and only the source is printed.
  • For an unreachable h, pred[h] stays at its initial 0 and "0 -> h" is printed by mistake. First, dist[h] < INF should be checked.

Multiple Choice · Dijkstra

Question 5: Dijkstra with a Heap

If the distances are kept in a binary min-heap and the graph in adjacency lists, what is the running time of Dijkstra? (n vertices, e edges)

D: Extracting the minimum n times costs O(n lg n). Each edge is relaxed at most once and every successful relaxation needs a heap update (O(lg n)): O(e lg n). Believing O(n lg n) is a common mistake; the cost of the relaxations is forgotten. B is the bound obtained with a Fibonacci heap, not a binary heap. In a dense graph (e ≈ n²) the matrix-based O(n²) version is better.

Question 6: Forgetting the found Check

min_vertex has lost the term !found[i] in its condition. On the graph with edges 0→1 (10), 0→2 (3), 1→3 (2), 1→4 (6), 2→1 (4), 2→3 (8), 2→4 (2), 3→4 (7), which distances does shortest_path(0, …) find? Why?

int min_vertex(int dist[], int n,
           short found[])
{
    int i, min = INT_MAX, pos = -1;
    for (i = 0; i < n; i++)
        if (dist[i] < min) {
            min = dist[i];  pos = i;
        }
    return pos;
}
Show answer

In every round the smallest distance is the source's (0): min_vertex always returns 0. Relaxation via 0 is tried again but no value shrinks. All three rounds are wasted.

Result [0, 10, 3, ∞, ∞]: only the direct edges. For 1, 10 stays instead of 7; 3 and 4 appear unreachable (verified by simulation).

Fix: if (dist[i] < min && !found[i]). A finalized vertex must never be chosen again.

Question 7: Bellman-Ford and Edge Order

Source 0. The edges are stored in the array E in the order 2→3, 1→2, 0→1, 0→2. In which round does which value change, and what is the result?

Edge array E in this order: 2→3 (−2), 1→2 (−3), 0→1 (4), 0→2 (6). d[0] = 0.

Round 1: 2→3 and 1→2 are skipped because d[2] and d[1] are still ∞. 0→1: d[1] = 4.

Round 1, 0→2 (6): d[2] = 6.

Round 2, 2→3 (-2): d[3] = 4.

Round 2, 1→2 (-3): d[2] = 1.

Round 3, 2→3 (−2): d[3] = −1. Because the edge order is bad, the information advanced one edge per round; n − 1 = 3 rounds were needed.

In round n no edge relaxes: no negative cycle, return 0. Result d = [0, 4, 1, −1].

for (i = 0; i < n; i++) d[i] = INF;
d[s] = 0;
for (t = 1; t <= n - 1; t++)          /* n-1 rounds */
    for (j = 0; j < e; j++) {
        u = E[j].u;  v = E[j].v;
        if (d[u] != INF && d[u] + E[j].w < d[v])
            d[v] = d[u] + E[j].w;
    }
for (j = 0; j < e; j++)               /* round n */
    if (d[E[j].u] != INF &&
        d[E[j].u] + E[j].w < d[E[j].v]) return -1;
return 0;

Question 8: Negative Cycle

Floyd-Warshall is run on a graph with weights 0→1: 1, 1→2: −3, 2→0: 1 (containing a cycle of total weight −1). What is observed at the end?

B: The three nested loops always terminate. Since going around the cycle always decreases the distance, the shortest path is undefined, and this shows on the diagonal: the diagonal of the final matrix came out as −1, −1, −2 (verified in C). That is why a diagonal check catches a negative cycle.

Multiple Choice · Activity Networks

Question 10: Not a Topological Order

The edges of an AoV network: A→C, B→C, C→E, B→D, D→E, E→F. Which of the following orders is not a topological order?

D: B is a predecessor of C (B→C); in D, C comes before B. In the other three orders the start of every edge comes before its end. A topological order is often not unique; to verify one, every edge is checked individually.

Question 11: Topological Order with a Counted Stack

Lists: 0: 2 · 1: 2, 3 · 2: 4 · 3: 4, 5 · 4: 5. What does topological_order(graph, 6) print? How is the stack kept in the count fields?

Counters = predecessor counts: 2 → 2, 3 → 1, 4 → 2, 5 → 2.

0 and 1 pushed: count[0] = −1 (bottom), count[1] = 0, top = 1. Count = "the vertex below me".

1 is popped and printed; 3 (count now 0) is pushed; the count of 2 is 1.

3 is popped and printed; counts of 4 and 5 are 1.

0 is popped and printed; 2 (count now 0) is pushed.

2 is popped and printed; 4 (count now 0) is pushed.

4 is popped and printed; 5 (count now 0) is pushed.

5 is popped and printed. Order 1 3 0 2 4 5: last in, first out.

for (i = 0; i < n; i++)  /* count 0: push */
  if (!graph[i].count) {
    graph[i].count = top;  top = i; }
for (i = 0; i < n; i++) {
  if (top == -1) { printf("cycle"); break; }
  j = top;  top = graph[top].count;
  printf("%d ", j);
  for (p = graph[j].link; p; p = p->link) {
    k = p->vertex;
    if (--graph[k].count == 0) {
      graph[k].count = top;  top = k; }
  }
}

Multiple Choice · Activity Networks

Question 12: Network with a Cycle

On the network with edges 0→1, 1→2, 2→3, 3→4, 4→2, what does topological_order(graph, 5) print?

A: Only 0 has no predecessors. 0 is printed and the count of 1 drops to 0; 1 is printed and the count of 2 goes from 2 to 1 (because of the edge 4→2). The stack empties but three vertices remain: in the third round top == -1 is seen and "cycle" is printed. 2, 3 and 4 wait for one another; the project never finishes.

Question 14: min Instead of max

In the AoE network in the figure, when computing the earliest times, if max is replaced with min among the predecessors, what value do we get for v5?

B: v3 = min(3 + 6, 5 + 2) = 7 and v5 = min(7 + 5, 11 + 3) = 12. But v3 happens only when both a2 and a3 are done: 9; the project takes 14 days. For the earliest time take the max, for the latest time the min; the reverse is a common mistake.

Question 15: Topological Order with a Queue

Write the routine (Kahn's method) that counts the in-degrees in a directed graph given by an adjacency matrix and enqueues the vertices with no predecessors: int topo_kahn(int n, int adj[][N], int order[]). It returns the number of vertices written; if that is less than n, the graph has a cycle.

Show answer 
int topo_kahn(int n, int adj[][N], int order[]) {
  int indeg[N] = {0}, queue[N];
  int front = 0, rear = 0, count = 0;
  for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
      indeg[j] += adj[i][j];        /* in-degree */
  for (int i = 0; i < n; i++)
    if (indeg[i] == 0) queue[rear++] = i;
  while (front < rear) {
    int v = queue[front++];
    order[count++] = v;
    for (int j = 0; j < n; j++)
      if (adj[v][j] && --indeg[j] == 0)
        queue[rear++] = j;
  }
  return count;
}

For the network with edges 0→2, 1→2, 1→3, 2→4, 3→4, 3→5, 4→5, the order is 0 1 2 3 4 5 (with the counted stack 1 3 0 2 4 5; both are valid). On a network with a cycle only 0 and 1 are written and the return value is 2 < 5. O(n²) with a matrix, O(n + e) with lists.

Multiple Choice · Summary

Question 16: Which Algorithm?

In a directed acyclic graph (DAG) some edges are negative. What is the fastest way to find all shortest paths from a single source?

C: In a DAG the vertices are processed in topological order and the outgoing edges of each vertex are relaxed once. When a vertex is reached, all its predecessors have been processed and its distance is final; negative edges are no problem. B also gives the correct result but is slow; A can go wrong with negative edges; D is for all pairs.
