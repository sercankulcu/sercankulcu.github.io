A Traversal Splits the Edges in Two

When DFS or BFS visits every vertex of a connected graph, the edges fall into two groups:

T: tree edges

Edges that were followed to a new vertex (thick red). There are exactly n − 1 of them.

N: nontree edges

Edges never followed (dashed). In DFS they are back edges, in BFS cross edges.

Spanning Trees

Definition: Spanning Tree

Definition: a spanning tree is a tree made of edges of the graph that connects all the vertices: n vertices, n − 1 edges, no cycle.
Isomorphism

K4 is a complete graph. a and b are two different spanning trees (a is a path, b a star); c, d and e are isomorphic to a: a ≡ c ≡ d ≡ e.

How many?

K4 has 16 spanning trees (Cayley: nⁿ⁻² = 4² = 16): 12 paths + 4 stars. Once weights come in, “how many?” is asked again.

Spanning Trees

Question: How Many Spanning Trees Are There?

n − 1 of the e edges can be chosen in C(e, n − 1) ways; each choice is checked for a cycle and isomorphic copies are removed. Here 8 of the C(5, 3) = 10 choices are trees.

First find one spanning tree (e.g. with DFS).

Add a nontree edge: exactly one cycle appears.

Remove (A,B) from the cycle → a different spanning tree. Put it back and remove the next one.

Remove (B,C) from the cycle → a different spanning tree. Put it back and remove the next one.

Remove (C,D) from the cycle → a different spanning tree. Put it back and remove the next one.

Repeat for every nontree edge. This graph has 8 spanning trees, but the method is long and produces duplicates.

The algorithm is long, so it is not a sensible choice. (For the exact count, use Kirchhoff's matrix-tree theorem, an advanced topic.)

Spanning Trees

Properties of Spanning Trees

BFS spanning tree: 8 vertices, 7 edges (thick red); the 3 nontree edges are dashed.

Adding the nontree edge (6,7) creates exactly one cycle: 6-2-0-1-3-7-6. It is no longer a tree.

Deleting any tree edge, e.g. (0,2), splits the tree: {2, 5, 6} breaks off. A spanning tree is a minimal connected subgraph.

  • Exactly n − 1 edges, no cycle, connected: any two of these imply the third.
  • There is a unique path between any two vertices.
  • Adding a nontree edge creates a single cycle; removing any edge of that cycle gives a new spanning tree (the generation method relies on this).
  • Uses: dropping redundant links in a network, broadcast trees, circuit equations (Kirchhoff).

Minimum Cost

Minimum Cost Spanning Tree (MST)

  • The edges of an undirected graph can be weighted: G(V, E, w) instead of G(V, E).
  • The spanning tree(s) with the least total edge cost: the minimum spanning tree.
  • Ex. a: edge costs are the costs of links between computers.
  • Ex. b: power or fiber for 7 villages: a feasibility study gives the km of cable between village pairs. Pairs with no link cost ∞ (not shown).

Algorithms and the Greedy Approach

Algorithms

Kruskal, Prim, Sollin (Borůvka), and also reverse-delete. This chapter covers the first two.

Design methods

Backtracking, greedy, dynamic programming…

Greedy = stubborn

Each step makes the best choice for the moment and never revises it; there is no going back.

Three rules

1) Never take an edge that forms a cycle. 2) Prefer the cheapest edge. 3) Choose exactly n − 1 edges for n vertices.

Why is it correct? (extra) Cut property: for any cut that splits the vertices in two, the cheapest edge crossing the cut is in some MST. Kruskal and Prim pick such an edge at every step, so the greedy choice is never regretted.

“Beauty is the purgation of superfluities.” — Michelangelo

Kruskal

Kruskal's Algorithm (1956)

T = {};                    /* chosen edges */
while (|T| < n-1 && E ≠ Ø) {
    choose a least-cost edge (v,w) from E;
    E = E - {(v,w)};
    if ((v,w) does not create a cycle in T)
        T = T ∪ {(v,w)};
    else
        discard (v,w);
}
if (|T| < n-1)
    printf("no spanning tree\n");
  • T: chosen edges, E: remaining edges, |T|: number of chosen edges.
  • The loop runs until n − 1 edges are chosen; it also stops if no edges are left before that → the graph is not connected.
  • In Kruskal the chosen edges may form separate pieces (a forest); at the end there is a single tree.
  • Joseph B. Kruskal, 1956; its correctness is proved. “Reading the proof makes it clearer.”

How Not to Code Kruskal

  • Observation: first there were 2 components, then 3, then back to 2. “Got it! I'll keep the chosen edges in adjacency lists.”
  • The unchosen edges sit in an array. Bad: each time, search for the minimum, delete it, shift the rest. Better: keep the edges sorted by cost (end1, end2, cost).
  • (0,5) arrives: search the lists, neither 0 nor 5 is there → new list. (3,2) and (6,1) also start new lists. (1,2): in different lists → no cycle, merge the two lists.
  • (3,6): both in the same list → cycle! It works, but it pays a search cost every time.

Kruskal

How to Code Kruskal: Two Questions, Two Data Structures

1) Which edge is cheapest?

A min priority queue (min heap). Inserting edges one by one is O(e log e); turning the array into a heap bottom-up is O(e). Or sort the edges once (qsort).

2) Does it form a cycle?

No cycle if the ends belong to two different sets: union-find. Do find(3) and find(2) return the same root?

Instructor: “So the instructor had taught us these data structures all along and we never noticed!! And there we were, keeping lists… Look how useful the sets we learned in primary school turn out to be.”
Cost: |E|·lg|E| + |V|·(lg|E| + Θ(1)); with a bottom-up heap, 2|E| + |V|·lg|E| (Θ(1): inverse Ackermann, α ≤ lg|E|). In the worst case the cycle-forming edges may force e deleteMins rather than n − 1; a safe upper bound is O(e log e) = O(e log n).

Kruskal

C: Sets (Union-Find) and the Comparator

typedef struct { int u, v, w; } edge;

int find(int parent[], int i)    /* root: < 0 */
{
    while (parent[i] >= 0) i = parent[i];
    return i;
}
void unite(int parent[], int a, int b)   /* roots */
{
    if (parent[a] <= parent[b]) {  /* a is larger */
        parent[a] += parent[b];  parent[b] = a;
    } else {
        parent[b] += parent[a];  parent[a] = b;
    }
}
int cmp(const void *x, const void *y)
{
    return ((const edge *)x)->w - ((const edge *)y)->w;
}
  • parent[i] < 0: i is a root and −parent[i] is the set size (initially all −1).
  • Weighted union: the smaller set goes under the larger → tree height O(log n), find O(log n).
  • Add path compression and the amortized cost per operation is ≈ O(α(n)), constant in practice.
  • cmp: compares costs for qsort (small integers, so no overflow).

Prim

Prim's Algorithm

T  = {};
TV = {0};           /* tree vertices: start at 0 */
while (|T| < n-1) {
    pick a least-cost (u,v) with u ∈ TV, v ∉ TV;
    if (there is no such edge) break;
    TV = TV ∪ {v};
    T  = T  ∪ {(u,v)};
}
if (|T| < n-1)
    printf("no spanning tree\n");
  • Jarník (1930), Prim (1957), Dijkstra (1959) → the DJP or Prim–Jarník algorithm.
  • Kruskal may choose disconnected edges; Prim grows the chosen edges as a single tree.
  • Candidate edges: one end in TV, the other end not in TV.
  • A single tree keeps growing; no cycle check is needed (v ∉ TV already guarantees it).

Prim

Coding Prim: The Real Difficulty

  • The cheapest candidate edge must be found in one move.
  • When an edge is chosen, new edges enter the candidate set and some leave it (those with both ends now in TV): set A becomes set B.
  • When 0 is chosen, the data structure should see only (0,1) and (0,5) and not even look at the rest.
  • Solution (extra): for each v ∉ TV, lowcost[v] = cheapest link to TV. O(n²) with arrays; O(e log n) with a min heap.

in_tree[0] = 1;                    /* TV = {0} */
for (v = 0; v < n; v++)
    lowcost[v] = w[0][v], closest[v] = 0;
for (k = 1; k < n; k++) {
    u = cheapest(lowcost, in_tree, n); /* O(n) */
    if (u < 0) break;             /* no tree */
    in_tree[u] = 1;  total += lowcost[u];
    for (v = 0; v < n; v++)
        if (!in_tree[v] && w[u][v] < lowcost[v])
            lowcost[v] = w[u][v], closest[v] = u;
}

Prim

Speeding Up Prim with a Heap (Extra Topic)

/* adjacency lists + min-heap (key = lowcost) */
heap_push(H, 0, 0);
while (!heap_empty(H)) {
    u = heap_pop_min(H);         /* O(log n) */
    if (in_tree[u]) continue;    /* stale entry */
    in_tree[u] = 1;
    for (p = graph[u]; p; p = p->link)
        if (!in_tree[p->vertex] &&
            p->weight < lowcost[p->vertex]) {
            lowcost[p->vertex] = p->weight;
            closest[p->vertex] = u;
            heap_push(H, p->vertex, p->weight);
        }
}

Other MST Algorithms: Sollin (Borůvka), Reverse-Delete

Initially every vertex is a component of its own.

Round 1: each component picks its cheapest outgoing edge (yellow): (0,5)=10, (1,6)=14, (2,3)=12, (3,4)=22. Components left: 3.

Round 2: each component picks its cheapest outgoing edge (yellow): (4,5)=25, (1,2)=16. Components left: 1. Total 99.

  • Sollin / Borůvka (1926): in each round every component picks its cheapest outgoing edge; the number of components at least halves → at most log n rounds, O(e log n). Well suited to parallelism.
  • Reverse-delete: try the edges in decreasing cost; delete an edge if doing so keeps the graph connected. The reverse of Kruskal.
  • All rely on the same cut/cycle properties and (with distinct weights) find the same tree.

An MST Is Not a Shortest-Path Tree

MST

Minimizes the total edge cost and has no root. Distance from 0 to 1 along the tree: 85.

Shortest-path tree

Minimizes each vertex's distance from 0: d(1) = 28, but the total edge cost is 105 > 99.

Common Mistakes

1Checking for a cycle in Kruskal by asking “were both ends chosen before?” (wrong: they may be in different pieces).
2In Prim, not dropping candidate edges whose ends are both in TV.
3Confusing an MST with a shortest-path tree: the MST minimizes the total cost, shortest paths minimize individual distances.
4Forgetting the |T| < n − 1 check for a disconnected graph.
5Uniting non-root vertices in union-find (call find first!).
6Using INT_MAX for ∞ and overflowing when adding.

Exercises

  1. In the 7-village example, what would the MST and its cost be if edge (3,6) cost 11 instead of 18?
  2. When can Kruskal and Prim give different trees on the same graph?
  3. On the 8-vertex sample graph, list the edges of the DFS and BFS spanning trees starting from 7.
  4. How many spanning trees does K4 have? How many are paths, how many stars?
  5. If the edge weights are integers in 1..10, how does Kruskal's sorting step drop to O(e)?
  6. Why is the O(n²) version of Prim poor on sparse graphs?
Answers / hints
  1. Order: (0,5)=10 add, (3,6)=11 add, (2,3)=12 add, (1,6)=14 add, (1,2)=16 cycle, (3,4)=22 add, (4,6)=24 cycle, (4,5)=25 add → MST {(0,5),(3,6),(2,3),(1,6),(3,4),(4,5)}, cost 94.
  2. Only when some edges have equal weights; the total cost is still the same.
  3. With sorted lists, DFS(7): (7,3),(3,1),(1,0),(0,2),(2,5),(2,6),(1,4); BFS(7): (7,3),(7,4),(7,5),(7,6),(3,1),(5,2),(1,0).
  4. 16: 12 paths + 4 stars.
  5. With counting (bucket) sort: O(e + 10).
  6. Every round scans all n vertices: O(n²) ≫ O(e log n) (when e ≈ n).

Summary

Chapter Summary

Spanning tree

An acyclic subgraph with n − 1 edges that connects every vertex; DFS and BFS each produce one.

Minimum cost

The spanning tree of least total weight; the greedy choice is correct (cut property).

Kruskal

Try edges in increasing cost; catch cycles with union-find: O(e log e).

Prim

One tree grows by its cheapest edge: O(n²) with arrays, O(e log n) with a heap.

Data structure

Same idea, different structure: list search O(e·n) → sets O(e log e).

Choice

Sparse graph: Kruskal or heap-based Prim; dense graph: array-based Prim.
