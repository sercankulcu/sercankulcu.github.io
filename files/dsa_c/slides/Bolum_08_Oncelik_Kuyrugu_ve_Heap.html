Öğrenme Çıktıları

Tanımlamak

Öncelik kuyruğunu ve maksimum/minimum yığını (heap) tanımlamak; yığını ikili arama ağacından ayırmak.

Gösterimi kurmak

Tam ikili ağacı 1 tabanlı dizide saklamak: ata i/2, çocuklar 2i, 2i+1.

Ekleme ve silme

maksimum_yigin_ekle ve maksimum_yigin_al yordamlarını adım adım izlemek.

Analiz etmek

Ekleme ve silmenin neden O(lg n) olduğunu, en iyi durumun Ω(1) olduğunu göstermek.

Karşılaştırmak

Sırasız/sıralı dizi ve liste ile yığını maliyet tablosu üzerinden kıyaslamak.

Genişletmek

Aşağıdan yukarı yığın kurmanın (heapify) O(n) olduğunu açıklamak; d-ary yığını tanımak.

Öncelik Kuyruğu

Öncelik kuyruğu: ilk çıkan en öncelikli öğe

Kuyruktan ilk alınacak (silinecek) öğe, geliş sırasına göre değil en yüksek ya da en düşük değere göre belirlenir.

  • Maksimum öncelik kuyruğu (max priority queue): önce en yüksek değer ele alınır.
  • Minimum öncelik kuyruğu (min priority queue): önce en düşük değer ele alınır.
Hocadan“Priority queue diyoruz, bakalım kuyruğu ne kadar biliyoruz? Bazen bir şeyleri bilmek de sakıncalı olabilir. Bildiğimiz kuyrukta sondan eklenir, baştan alınır. Bu ise ondan farklı…”

Öncelik Kuyruğu

Öncelik kuyruğuna neden gereksinim duyarız?

1 · Fotokopi makinesi

Her kullanıcı sabit ücret ödüyor (3 sayfa da 30 sayfa da aynı). Kazancı en büyük yapmak için kullanım süresi en kısa olana öncelik verilir → minimum öncelik kuyruğu.

2 · Havaalanı

İniş isteyen uçaklardan yakıtı en az olana öncelik verilmelidir → minimum öncelik kuyruğu.

Gerçek sistemlerde de böyledir: örneğin işletim sistemi işlemleri (process) öncelik kuyruğuna koyar.

Hocadan“Kazancımı maksimum yapmak istiyoruz. Kullanma süresi minimum olana öncelik vererek kazanç maksimize edilir. (Çakaall!)”
Hocadan“‘Kuyruğun arkasındasın. Yakıtın az, ama kuyruk böyle. Ne yapalım?’ diyemeyiz.”

Ekle

Öğeyi önceliğiyle birlikte yapıya koy.

Al / Sil

En öncelikli öğeyi döndür ve yapıdan çıkar.

Öncelik kuyruğu bir arayüzdür; farklı veri yapılarıyla gerçekleştirilebilir. Yığın (heap) yalnızca biridir, ama en dengelisidir: ekleme ve silme O(lg n).
Hocadan“Yığınlar, eğer nerede ve nasıl kullanılacağını kavrayabilirseniz, çok çok önemli bir veri yapısıdır.”

Yığın Yapısı

Yığın bir dizide tam ikili ağaç olarak durur

Dizinin 0. indisi kullanılmaz; kök yigin[1].

0 tabanlı dizide: ata (i−1)/2, çocuklar 2i+1, 2i+2.

Dizi sıralı değildir; yalnızca 1. indisteki öğenin en öncelikli (ilk alınacak) öğe olduğu garanti edilir. Tam ikili ağaçta boşluk olmadığından işaretçiye gerek kalmaz.

Yığın Yapısı

Yığın denince akla tam ikili ağaç gelmeli, arama ağacı değil

  • Tam ikili ağaç: tüm düzeyler dolu, son düzey soldan sağa doğru dolu.
  • Arama ağacında sol < kök < sağ; yığında yalnızca ata ≥ çocuk (sol-sağ arasında sıra yok).
Hocadan“‘Hocam bir ikili arama ağacı çizer misiniz?’ Genel istek üzerine çizelim, bununla karıştırmıyoruz!”

Yığın Yapısı

Tanım: maksimum yığın ve minimum yığın

Maksimum yığın (max heap): tam ikili ağaçta her düğümün değeri çocuklarından küçük değilse.

Minimum yığın (min heap): tam ikili ağaçta her düğümün değeri çocuklarından büyük değilse.

Bu tanımlar maksimum/minimum öncelik kuyruğu kullanabilmek için verilmiştir.

Yığın Yapısı

Hızlı kontrol: hangisi maksimum yığın?

Her k ≥ 2 için yigin[k/2] ≥ yigin[k] mi? Yalnızca ata–çocuk çiftlerine bak; kardeşler ve kuzenler arasında sıra aranmaz.

Cevap
  1. (a) Evet: 50≥30, 50≥40, 30≥10, 30≥20, 40≥35.
  2. (b) Hayır: 4. indisteki 35, atası 30'dan büyük.
  3. (c) Evet: tam ağaç ve her ata ≥ çocuk (1 ile 2'nin 8'den küçük olması önemli değil).

Yığın Yapısı

C ile tanımlar: dizi, sayaç ve makrolar

#define ELEMAN_SAYISI 200   /* maksimum eleman + 1 */
#define YIGIN_DOLUMU(n) ((n) == ELEMAN_SAYISI - 1)
#define YIGIN_BOSMU(n)  (!(n))

typedef struct {
  int x;          /* öncelik (anahtar) */
  /* diğer alanlar */
} eleman;

eleman yigin[ELEMAN_SAYISI];  /* [0] kullanılmaz */
int n = 0;                    /* öğe sayısı */
Kapasite

1..199 indisleri kullanılır; n == 199 ise yığın doludur.

Makrolarda parantez

(n), YIGIN_BOSMU(a+b) gibi çağrılarda öncelik hatasını önler.

Notlardaki kodda düzeltme: dizi eleman yigin[eleman_sayisi - 1] (199 öğe, indis 0..198) tanımlanmıştı; oysa dolu sayılmadan önce n 199'a çıkabilir ve yigin[199] dizinin dışına yazılır. Horowitz'teki gibi boyut ELEMAN_SAYISI olmalıdır.

Ekleme

Maksimum yığına öğe ekleme: önce yere koy, sonra kaydır

Başlangıç: 14, 12, 7, 10, 8, 6. Sırasıyla 15, 109, 107, 3, 15 eklenecek.

Önce yeni yer açılır: tam ağacın ilk boş konumu (7).

15 > 7: ata 7 aşağı kaydırılır, boşluk 3. konuma çıkar.

15 > 14: ata 14 aşağı kaydırılır, boşluk 1. konuma çıkar.

15, 1. konuma yazılır. Yığın özelliği yeniden sağlandı.

Hocadan“Eklenecek elemanın yeri kesinlikle hazırdır. Bundan kuşku yok. Önce o yere eklersin. Sonra eyvah! Çocuğundan büyük olmak zorundaydı. Öyleyse uygun konuma kaydırırız.”

Ekleme

maksimum_yigin_ekle: takas değil, kaydırma

void maksimum_yigin_ekle(eleman item) {
  if (YIGIN_DOLUMU(n)) {
    yigin_dolu();             /* hata iletisi */
    return;
  }
  int i = ++n;
  while (i != 1) {            /* i == 1: kökteyiz */
    if (item.x <= yigin[i / 2].x) break;
    yigin[i] = yigin[i / 2];  /* atayı aşağı kaydır */
    i /= 2;                   /* bir üst ataya bak */
  }
  yigin[i] = item;
}
Boşluk (delik) yöntemi

Takas yok: büyük atalar birer düzey aşağı kaydırılır, öğe en sonda bir kez yazılır (takas 3, kaydırma 1 atama).

Döngü koşulu

i != 1: kökte ata yoktur. item.x <= ata olduğunda yerleşim yeri bulunmuştur.

Dolu yığın

yigin_dolu() bir hata iletisi yordamıdır; ekleme yapılmadan dönülür.

Silme

maksimum_yigin_al: düzeltilmiş sürüm

bool maksimum_yigin_al(eleman *cikan) {
  if (YIGIN_BOSMU(n)) return false;
  *cikan = yigin[1];          /* kök döndürülecek */
  eleman deger = yigin[n--];  /* yeri aranacak */
  int i = 1, j = 2;
  while (j <= n) {
    if (j < n && yigin[j].x < yigin[j + 1].x) j++;
    if (deger.x >= yigin[j].x) break;
    yigin[i] = yigin[j];      /* çocuğu yukarı al */
    i = j; j *= 2;
  }
  yigin[i] = deger;
  return true;
}
Notlardaki hata

Boş yığında return 0; yazılmıştı: derleme hatası (tamsayı bir struct'a dönüşmez).

Düzeltme

Notlardaki öneri uygulandı: bool dönüş (başarı/başarısızlık) ve alınan öğe işaretçi parametre ile döndürülür.

j < n neden?

yigin[j+1] okumadan önce sağ çocuğun var olduğunu garanti eder.

Heapify: diziyi yerinde yığına çevirmek

void yigin_kur(eleman a[], int n) {
  for (int k = n / 2; k >= 1; k--) {
    eleman deger = a[k];
    int i = k, j = 2 * k;
    while (j <= n) {
      if (j < n && a[j].x < a[j + 1].x) j++;
      if (deger.x >= a[j].x) break;
      a[i] = a[j];
      i = j; j *= 2;
    }
    a[i] = deger;
  }
}
Fikir

Yapraklar (k > n/2) zaten tek öğelik yığındır. k = n/2'den köke doğru her düğümü aşağı kaydır: iki çocuğu yığın olan bir kök düzeltilir.

Ne kazandırır?

n kez ekle O(n lg n) sürer; aşağıdan yukarı kurma O(n).

İleri Konular

Heapify neden O(n)?

Düğümlerin yarısı yapraktır ve hiç inmez; çeyreği en çok 1, sekizde biri en çok 2 düzey iner… Toplam iş:

Σh≥0 ⌈n / 2h+1⌉ · O(h) = O(n · Σ h/2h) = O(2n) = O(n)

Örnekte 15 düğümlü tam ağaç için toplam iniş en çok 0·8 + 1·4 + 2·2 + 3·1 = 11 < n. Tek tek ekleme ise alttaki düğümleri de köke kadar çıkarabilir: n lg n.

Öncelik kuyruğu

İlk alınacak öğe en yüksek (max) ya da en düşük (min) değerli öğedir.

Yığın

İlk boş konuma aç, büyük ataları aşağı kaydır: O(lg n).

Kökü al, sondaki öğeye kökten yer ara, büyük çocukları yukarı al: O(lg n).
