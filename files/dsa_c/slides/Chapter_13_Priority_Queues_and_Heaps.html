Priority Queues

Priority queue: the highest-priority item leaves first

The item removed first is chosen not by arrival order but by the highest or lowest value.

  • Max priority queue: the highest value is served first.
  • Min priority queue: the lowest value is served first.
Instructor“We say priority queue; let's see how well we know the queue. Sometimes knowing things can get in the way. In the queue we know, you add at the rear and take from the front. This one is different…”

Priority Queues

Why do we need priority queues?

1 · Photocopier

Every user pays a flat fee (3 pages or 30, same price). To maximize revenue, serve the shortest job first → a min priority queue.

2 · Airport

Among planes waiting to land, the one with the least fuel must go first → a min priority queue.

Real systems work the same way: an operating system, for example, keeps processes in a priority queue.

Instructor“We want to maximize our revenue. Giving priority to the shortest usage time maximizes it.”
Instructor“We can't say ‘You're at the back of the queue. You're low on fuel, but that's the queue. What can we do?’”

Insert

The item goes into the structure together with its priority.

Delete

The highest-priority item is returned and removed from the structure.

A priority queue is an interface; many data structures can implement it. The heap is just one, but it balances both: insert and delete in O(lg n).

Heap Structure

A heap lives in an array as a complete binary tree

Index 0 of the array is unused; the root is heap[1].

NodeIndex
root1
parent of ii / 2
left child2i
right child2i + 1
last itemn

In a 0-based array: parent (i−1)/2, children 2i+1, 2i+2.

The array is not sorted; the only guarantee is that the item at index 1 has the highest priority (is removed first). A complete binary tree has no gaps, so no pointers are needed.

Heap Structure

A heap means a complete binary tree, not a search tree

  • Complete binary tree: every level is full, and the last level fills from left to right.
  • In a search tree left < root < right; in a heap only parent ≥ child (no order between left and right).
Instructor“‘Sir, could you draw a binary search tree?’ By popular demand, let's draw one; we are not confusing the two!”

Heap Structure

Definition: max heap and min heap

Max heap: a complete binary tree in which every node's key is no smaller than its children's.

Min heap: a complete binary tree in which every node's key is no larger than its children's.

These definitions let us implement max/min priority queues.

Heap Structure

Quick check: which is a max heap?

Is heap[k/2] ≥ heap[k] for every k ≥ 2? Only parent–child pairs matter; no order is required between siblings or cousins.

Answer
  1. (a) Yes: 50≥30, 50≥40, 30≥10, 30≥20, 40≥35.
  2. (b) No: 35 at index 4 is larger than its parent 30.
  3. (c) Yes: complete, and every parent ≥ child (it does not matter that 1 and 2 are smaller than 8).

Definitions in C: array, counter and macros

#define MAX_ELEMENTS 200   /* max items + 1 */
#define HEAP_FULL(n) ((n) == MAX_ELEMENTS - 1)

typedef struct {
  int x;          /* priority (key) */
  /* other fields */

element heap[MAX_ELEMENTS];  /* [0] unused */
int n = 0;                    /* item count */
Capacity

Indices 1..199 are used; the heap is full when n == 199.

Parentheses in macros

(n) prevents precedence bugs in calls like HEAP_EMPTY(a+b).

Common mistake: declaring the array as element heap[MAX_ELEMENTS - 1] (199 items, indices 0..198). Before the heap counts as full, n can reach 199 and heap[199] writes past the end; the size must be MAX_ELEMENTS.

Insertion

Inserting into a max heap: take the new slot, then sift

Start: 14, 12, 7, 10, 8, 6. We will insert 15, 109, 107, 3, 15 in turn.

First a new slot opens: the first free position of the complete tree (7).

15 > 7: parent 7 moves down; the hole rises to position 3.

15 > 14: parent 14 moves down; the hole rises to position 1.

15 is written at position 1. The heap property holds again.

Insertion

insert_max_heap: shifting, not swapping

void insert_max_heap(element item) {
  if (HEAP_FULL(n)) {
    heap_full();             /* error message */
    return;
  }
  int i = ++n;
  while (i != 1) {            /* i == 1: at root */
    if (item.x <= heap[i / 2].x) break;
    heap[i] = heap[i / 2];  /* move parent down */
    i /= 2;                   /* go up a level */
  }
  heap[i] = item;
}
The hole method

No swaps: larger ancestors shift down one level each, and the item is written once at the end (a swap costs 3 assignments, a shift 1).

Loop condition

i != 1: the root has no parent. When item.x <= parent, the slot is found.

Full heap

heap_full() is an error-message routine; we return without inserting.

General—0 … ⌊lg n⌋O(lg n)
A complete binary tree with n items has ⌈lg(n+1)⌉ levels. The loop climbs one level per iteration, so the cost is at most lg n and at least 1: time complexity O(lg n).

Deletion

Deleting from a max heap: take the root, place the last item

Data: 30, 15, 28, 11, 14, 3, 6, 10, 9. The first item out is 30 at the root.

The root (30) is taken. The last item 9 is removed and becomes the candidate for the hole at the root.

The larger of the two children (28) is larger than temp (9) → moved up.

9 settles at position 3.

At each step three values matter: the two children and the last item. The largest goes to the slot i points to; i marks the slot to fill, j the children.

Deletion

delete_max_heap: the corrected version

bool delete_max_heap(element *out) {
  if (HEAP_EMPTY(n)) return false;
  *out = heap[1];          /* root is returned */
  element temp = heap[n--];  /* find its slot  */
  int i = 1, j = 2;
  while (j <= n) {
    if (j < n && heap[j].x < heap[j + 1].x) j++;
    if (temp.x >= heap[j].x) break;
    heap[i] = heap[j];      /* move child up    */
    i = j; j *= 2;
  }
  heap[i] = temp;
  return true;
}
Common mistake

Writing return 0; for an empty heap is a compile error (an integer does not convert to a struct).

The fix

The suggested solution: return a bool (success/failure) and pass the removed item back through a pointer parameter.

Why j < n?

It guarantees the right child exists before heap[j+1] is read.

Deletion

Deletion cost and the journey of the last item

It may stop midway

In the 1st deletion, 9 settled at position 3 without sinking three levels.

It may go to the bottom

In the 2nd deletion, 10 sank to a leaf (position 5): the worst case.

Cost

The loop goes down one level per iteration: at most ⌊lg n⌋ iterations, 2 comparisons each → O(lg n).

A by-product

Deleting n times yields the items in decreasing order: this is the idea behind heap sort.

Deletion's best case is Ω(1) too: if the last item is ≥ both children of the root it settles at once (e.g. when 2 items are left).

Heap *heap_create(int capacity) {
  Heap *h = malloc(sizeof *h);

Deletion

When priority changes over time: the planes' fuel

Observation

Each plane burns fuel at a different rate: fuel levels must be updated every second by an interrupt.

In the heap

An item whose priority rises moves up, one whose priority falls moves down: O(lg n). Position k is kept in an index table.

/* priority of the item at k rose: sift it up */
void increase_key(int k, int key) {
  element e = heap[k];
  e.x = key;
  while (k != 1 && e.x > heap[k / 2].x) {
    heap[k] = heap[k / 2];
    k /= 2;
  }
  heap[k] = e;
}

Advanced Topics

Heapify: turning an array into a heap in place

void build_heap(element a[], int n) {
  for (int k = n / 2; k >= 1; k--) {
    element temp = a[k];
    int i = k, j = 2 * k;
    while (j <= n) {
      if (j < n && a[j].x < a[j + 1].x) j++;
      if (temp.x >= a[j].x) break;
      a[i] = a[j];
      i = j; j *= 2;
    }
    a[i] = temp;
  }
}
The idea

Leaves (k > n/2) are already one-item heaps. From k = n/2 up to the root, each node sifts down: a root whose two children are heaps gets fixed.

What do we gain?

n calls to insert take O(n lg n); bottom-up construction takes O(n).

The inner loop

Identical to the loop inside delete_max_heap (adjust in Horowitz).

i = 6, j = 12: continue from the hole's new position.

j = 12 > n: i = 6 is a leaf; the loop ends.

a[6] = temp (5). The subtree rooted at 1 is now a heap: 12, 9, 8, 3, 1, 5, 7.

k = 0: the loop is done. The whole array is a max heap: 12, 9, 8, 3, 1, 5, 7.

void build_heap(element a[], int n) {
  for (int k = n / 2; k >= 1; k--) {
    element temp = a[k];
    int i = k, j = 2 * k;
    while (j <= n) {
      if (j < n && a[j].x < a[j + 1].x) j++;
      if (temp.x >= a[j].x) break;
      a[i] = a[j];
      i = j; j *= 2;
    }
    a[i] = temp;
  }
}

Advanced Topics

Why is heapify O(n)?

Half the nodes are leaves and never move; a quarter move at most 1 level, an eighth at most 2… Total work:

Σh≥0 ⌈n / 2h+1⌉ · O(h) = O(n · Σ h/2h) = O(2n) = O(n)

For the 15-node complete tree in the example, the total is at most 0·8 + 1·4 + 2·2 + 3·1 = 11 < n. Inserting one by one may instead lift low nodes all the way to the root: n lg n.

Advanced Topics

d-ary heap: every node has d children

Binary (d = 2)d-ary (0-based)
parent(i−1)/2(i−1)/d
children2i+1, 2i+2d·i+1 … d·i+d
height≈ lg n≈ logd n
insert / increase keyO(lg n)O(logd n) — faster
delete rootO(lg n)O(d · logd n) — compares d children

With many inserts/decrease-keys and few deletes (e.g. Dijkstra on dense graphs), choosing d > 2 pays off; a shallow tree is cache-friendly.

Summary

Chapter summary

Priority queue

The first item out has the highest (max) or the lowest (min) value.

Heap

Complete binary tree + parent ≥ child. In a 1-based array the parent is i/2, the children 2i and 2i+1.

Insertion

Open the first free slot, shift larger ancestors down: O(lg n).

Deletion

Take the root, find a slot for the last item starting at the root, move larger children up: O(lg n).

Why a heap?

Other structures push one operation to Θ(n); a heap keeps both logarithmic.

Beyond

Heapify in O(n), d-ary heaps, binomial and Fibonacci heaps.
