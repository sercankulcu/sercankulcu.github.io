Giriş

Öğrenme Çıktıları

Fikri açıklamak

Anahtardan konumu hesaplayarak ortalama O(1) arama yapan hash tablosunu tanımlamak.

Fonksiyon seçmek

Bölme, çarpma, katlama ve dizgi hash'ini hesaplamak; iyi fonksiyonun özelliklerini saymak.

Çakışmayı çözmek

Doğrusal/karesel yoklama, çift hash ve zincirlemeyi adım adım uygulamak.

C ile yazmak

Ekleme, arama ve silme yordamlarını malloc/free ve boş durumlarıyla yazmak.

Silmeyi doğru yapmak

Açık adreslemede neden mezar taşı (tombstone) gerektiğini göstermek.

Analiz etmek

Yük faktörünün maliyete etkisini ve yeniden boyutlandırmanın amortize maliyetini açıklamak.

Hash Fikri

Arama maliyetini sabite indirmek

Hash tablosu karşılaştırma yapmaz: anahtardan konumu hesaplar. Bedeli: sıralı dolaşım, en küçük/en büyük ve aralık sorguları desteklenmez; en kötü durum O(n)'dir.

Bu bölüm ders notlarında (VYA1/VYA2) yer almaz; dersin bütünlüğü için Horowitz–Sahni Bölüm 8 ve CLRS Bölüm 11 temel alınarak eklenmiştir.

Hash Fikri

Önce en basiti: doğrudan adresleme tablosu

typedef struct { int var; char ad[16]; } kayit;
kayit T[10];               /* anahtar = indis */

kayit *da_ara(int k) {
  return T[k].var ? &T[k] : NULL;
}
Sorun

Öğrenci numarası gibi 9 haneli anahtarlarda |U| = 109: tablo sığmaz, çoğu boş kalır.

Çözüm

Anahtarı küçük bir aralığa eşleyen bir hash fonksiyonu h: U → {0, …, m−1}.

Hash Fikri

Anahtar → hash → kova

TerimAnlamı
kova / yuva (bucket, slot)tablonun bir konumu, 0 … m−1
ev adresih(k): anahtarın ilk bakılan yeri
çakışma (collision)k₁ ≠ k₂ ama h(k₁) = h(k₂)
eş anlamlılar (synonyms)aynı ev adresine düşen anahtarlar
yük faktörü αn / m (dolu oranı)
m < |U| olduğundan (güvercin yuvası ilkesi) çakışma kaçınılmazdır. İki soru kalır: iyi bir h nasıl seçilir, çakışma nasıl çözülür?

Hash Fikri

Soyut veri türü: sözlük (dictionary)

typedef struct { int anahtar; /* + değer */ } oge;

bool hash_ekle(oge x);      /* varsa günceller */
oge *hash_ara(int anahtar); /* yoksa NULL      */
bool hash_sil(int anahtar); /* yoksa false     */
Sözlük

Anahtar → değer eşlemesi; her anahtar en çok bir kez bulunur.

Kullanım

Derleyicide sembol tablosu (Horowitz'in çıkış örneği), önbellek, tekrar denetimi, küme gerçekleştirimi.

C standart kitaplığında hazır bir hash tablosu yoktur (POSIX'te sınırlı hsearch vardır); bu yüzden C programcısı kendi tablosunu yazmayı bilmelidir.

Hash Fonksiyonları

İyi bir hash fonksiyonunun özellikleri

Hızlı

Hesaplaması O(anahtar uzunluğu); birkaç aritmetik işlem.

Düzgün dağıtan

Anahtarlar m kovaya olabildiğince eşit dağılmalı (simple uniform hashing varsayımı).

Tüm bitleri kullanan

Yalnızca son basamaklara bakan fonksiyonlar örüntülü veride kümelenir.

Deterministik

Aynı anahtar her zaman aynı kovaya gider; rastgelelik yalnızca fonksiyon seçilirken olabilir.

Hash Fonksiyonları

Bölme yöntemi: h(k) = k mod m

k1020304050601727
k mod 1000000077
k mod 11109876565
  • m = 10: son basamak dışında her şey yok sayılır; 10, 20, …, 60 aynı kovaya düşer.
  • m için 2'nin kuvvetine yakın olmayan bir asal sayı seçmek iyi bir kuraldır (CLRS).
  • m = 2p ise h(k) yalnızca k'nin en düşük p bitidir: kaçınılmalı.
unsigned h_bolme(unsigned k, unsigned m) { return k % m; }

C'de % negatif sayıda negatif sonuç verebilir: anahtarı unsigned tut ya da ((k % m) + m) % m kullan.

Hash Fonksiyonları

Çarpma yöntemi: h(k) = ⌊m · (k·A mod 1)⌋

  • 0 < A < 1 sabit; k·A'nın kesir kısmı m ile çarpılır.
  • m'nin seçimi kritik değildir; m = 2p seçilebilir.
  • Knuth'un önerisi A ≈ (√5 − 1)/2 = 0,6180339887…
  • Örnek (CLRS): k = 123456, p = 14 (m = 16384) → h(k) = 67.
/* w = 32 bit, m = 2^p; s = A * 2^32 */
uint32_t h_carpma(uint32_t k, int p) {
  const uint32_t s = 2654435769u;
  return (uint32_t)(k * s) >> (32 - p);
}
Tamsayı sürümünde k·s çarpımı 232'ye göre taşar; taşan kısım atılır (kesir kısmını almakla aynı). Kalan 32 bitin en üst p biti h(k)'dir. Kayan noktalı sürüm aynı sonucu verir: ⌊16384 · 0,…⌋ = 67. (<stdint.h> gerekir.)

Hash Fonksiyonları

Katlama (folding) ve orta-kare yöntemleri

Anahtar x = 12320324111220 üç haneli parçalara bölünüp toplanır (Horowitz örneği):

Kaydırmalı katlama

Parçalar olduğu gibi toplanır: 699.

Sınırda katlama

Çift sıradaki parçalar ters çevrilir (kâğıt katlar gibi): 897.

Orta-kare

k² hesaplanır, ortadaki r bit alınır: m = 2r. Orta bitler k'nin tüm bitlerine bağlıdır.

Sonuç tablo boyutundan büyükse ayrıca mod m alınır.

Hash Fonksiyonları

Dizgi anahtarlar: polinom (Horner) hash

unsigned dizgi_hash(const char *s, unsigned m) {
  unsigned h = 0;
  for (; *s != '\0'; s++)
    h = (h * 31 + (unsigned char)*s) % m;
  return h;
}
unsigned long djb2(const char *s) {  /* Bernstein */
  unsigned long h = 5381;
  int c;
  while ((c = (unsigned char)*s++) != 0)
    h = h * 33 + c;
  return h;       /* sonra: h % m */
}
Toplama kötüdür

Harf kodlarını toplamak "abc", "cba" gibi anagramları aynı kovaya atar.

Polinom

h = c₀·31n−1 + … + cn−1: Horner kuralıyla her karakterde bir çarpma. Konum bilgisi hash'e girer.

Taşma

Her adımda % m almak değerleri küçük tutar; unsigned taşması C'de tanımlıdır (mod 2w).

Dizgi hash'i · kodu adım adım çalıştır

Kod izleme: dizgi_hash("kedi", 11)

dizgi_hash("kedi", 11) çağrılır.

h = 0 ile başlanır.

*s = 'k' ≠ '\0' → döngü sürer.

h = (0·31 + 107) % 11 = 107 % 11 = 8.

*s = 'e' ≠ '\0' → döngü sürer.

h = (8·31 + 101) % 11 = 349 % 11 = 8.

*s = 'd' ≠ '\0' → döngü sürer.

h = (8·31 + 100) % 11 = 348 % 11 = 7.

*s = 'i' ≠ '\0' → döngü sürer.

h = (7·31 + 105) % 11 = 322 % 11 = 3.

*s == '\0': dizgi bitti.

return 3: "kedi" anahtarının ev adresi 3. Maliyet dizgi uzunluğuyla doğrusal.

unsigned dizgi_hash(const char *s, unsigned m) {
  unsigned h = 0;
  for (; *s != '\0'; s++)
    h = (h * 31 + (unsigned char)*s) % m;
  return h;
}

Denetim: tam polinom 3287903 ve 3287903 mod 11 = 3; her adımda mod almak sonucu değiştirmez.

Açık Adresleme

Çakışma: iki temel çözüm yolu

Doğum günü paradoksu

23 kişilik bir sınıfta iki kişinin doğum gününün aynı olma olasılığı ≈ %50.7. m = 365 yuvaya 23 anahtar: çakışma şaşırtıcı derecede erken gelir.

Açık adresleme

Tüm öğeler tablonun içinde; α ≤ 1. Yoklama (probe) dizisiyle boş yuva aranır.

Zincirleme

Her kova bir bağlı listenin başı; α > 1 olabilir. Ekleme O(1).

Açık Adresleme

C ile açık adresleme: yuva durumu ve ekleme

#define M 11
typedef enum { BOS, DOLU, SILINDI } durum_t;
typedef struct {
  int anahtar;          /* anahtar >= 0 varsayılır */
  durum_t durum;
} yuva;
yuva tablo[M];          /* global: hepsi 0 = BOS */
Başlangıç

Global dizi sıfırla başlar; BOS = 0 olduğu için tüm yuvalar boştur.

Ekleme

Ev adresinden başla, DOLU olmayan ilk yuvaya yaz; en çok m deneme (sonraki slayt).

Yuva üç durumdan birindedir: BOS (hiç kullanılmadı), DOLU, SILINDI (mezar taşı). Ekleme SILINDI yuvayı yeniden kullanabilir; ancak aynı anahtarın tabloda zaten olmadığı önce ara ile denetlenmelidir.

Açık adresleme · kodu adım adım çalıştır

Kod izleme: ekle(33) — doğrusal yoklama

ekle(33): tabloda 22, 1, 13, 11, 24 var (yuva 0–4 dolu blok).

Ev adresi i = 33 % 11 = 0.

d = 0 < 11: 0. deneme, yuva 0.

Yuva 0 DOLU (22) → sonraki: i = (0+1) % 11.

d = 1 < 11: 1. deneme, yuva 1.

Yuva 1 DOLU (1) → sonraki: i = (1+1) % 11.

d = 2 < 11: 2. deneme, yuva 2.

Yuva 2 DOLU (13) → sonraki: i = (2+1) % 11.

d = 3 < 11: 3. deneme, yuva 3.

Yuva 3 DOLU (11) → sonraki: i = (3+1) % 11.

d = 4 < 11: 4. deneme, yuva 4.

Yuva 4 DOLU (24) → sonraki: i = (4+1) % 11.

d = 5 < 11: 5. deneme, yuva 5.

Yuva 5 BOS → buraya yazılacak.

tablo[5] = {33, DOLU}.

return 5: 6 yoklama. Birincil kümelenme yüzünden ev adresinden 5 yuva uzağa düştü.

int ekle(int k) {
  int i = k % M;                 /* ev adresi */
  for (int d = 0; d < M; d++, i = (i + 1) % M) {
    if (tablo[i].durum != DOLU) {  /* BOS/SILINDI */
      tablo[i].anahtar = k;
      tablo[i].durum = DOLU;
      return i;
    }
  }
  return -1;                     /* tablo dolu */
}

int ara(int k) {
  int i = k % M;
  for (int d = 0; d < M; d++, i = (i + 1) % M) {
    if (tablo[i].durum == BOS) return -1;
    if (tablo[i].durum == DOLU &&
        tablo[i].anahtar == k) return i;
  }
  return -1;
}
bool sil(int k) {
  int i = ara(k);
  if (i < 0) return false;
  tablo[i].durum = SILINDI;   /* mezar taşı */
  return true;
}

Zincirleme

Zincirleme (separate chaining): kova başına bir liste

#define MZ 5
typedef struct dugum {
  int anahtar;
  struct dugum *sonraki;
} dugum;
dugum *kova[MZ];           /* hepsi NULL */
bool zincir_ekle(int k) {
  int i = k % MZ;
  dugum *yeni = malloc(sizeof *yeni);
  if (yeni == NULL) return false;  /* bellek yok */
  yeni->anahtar = k;
  yeni->sonraki = kova[i];         /* başa ekle */
  kova[i] = yeni;
  return true;
}
Başa ekle

Liste sırası önemsiz: başa ekleme O(1). (Tekrar istenmiyorsa önce aranmalı.)

Arama

Yalnızca kendi kovasının listesi dolaşılır: ortalama 1 + α/2 düğüm.

Silme kolay

Bağlı listeden silmek yeter; mezar taşı gerekmez.

Zincirleme · kodu adım adım çalıştır

Kod izleme: zincir_ara(12) ve zincir_ara(17)

zincir_ara(12): kova 12 % 5 = 2.

p = kova[2]: listenin başı (22).

p->anahtar = 22 ≠ 12 → ilerle.

p = p->sonraki → düğüm(7).

p->anahtar = 7 ≠ 12 → ilerle.

p = p->sonraki → düğüm(12).

p->anahtar == 12: döngü koşulu yanlış, dur.

return p: bulundu (3 düğüm gezildi).

zincir_ara(17): kova 17 % 5 = 2.

p = kova[2]: listenin başı (22).

p->anahtar = 22 ≠ 17 → ilerle.

p = p->sonraki → düğüm(7).

p->anahtar = 7 ≠ 17 → ilerle.

p = p->sonraki → düğüm(12).

p->anahtar = 12 ≠ 17 → ilerle.

p = p->sonraki → NULL.

p == NULL: liste bitti, döngüden çık.

return NULL: 17 tabloda yok. Tüm zincir (3 düğüm) tarandı.

dugum *zincir_ara(int k) {
  dugum *p = kova[k % MZ];
  while (p != NULL && p->anahtar != k)
    p = p->sonraki;
  return p;                 /* NULL: yok */
}

Zincirleme · kodu adım adım çalıştır

Kod izleme: zincir_sil(7)

zincir_sil(7): 7 zincirin ortasında (22 → 7 → 12).

i = 7 % 5 = 2.

p listenin başında, onceki = NULL.

22 ≠ 7 → döngüye gir.

onceki = 22'nin düğümü, p = 7'nin düğümü.

p->anahtar == 7 → döngü biter.

p NULL değil: anahtar bulundu.

onceki NULL değil → onceki->sonraki = p->sonraki: 22 artık doğrudan 12'yi gösterir; 7 zincirden çıktı.

free(p): düğümün belleği geri verilir. Bundan sonra p kullanılmamalı (sarkan işaretçi).

return true. Baştaki düğüm silinseydi (onceki == NULL) kova[i] güncellenirdi.

bool zincir_sil(int k) {
  int i = k % MZ;
  dugum *p = kova[i], *onceki = NULL;
  while (p != NULL && p->anahtar != k) {
    onceki = p;
    p = p->sonraki;
  }
  if (p == NULL) return false;           /* yok */
  if (onceki == NULL) kova[i] = p->sonraki;
  else onceki->sonraki = p->sonraki;
  free(p);
  return true;
}

Silmede tuzak: yuvayı boşaltmak aramayı keser

13'ü sileceğiz. 24'ün ev adresi 2; 24, 2 ve 3 dolu olduğu için 4'e yerleşmişti.

Yuvayı BOS yaparsak…

…ara(24) ev adresinde boş yuva görür ve “yok” der. Oysa 24 tabloda!

Doğrusu yuvayı mezar taşı (SILINDI) ile işaretlemektir.

Arama mezar taşını boş saymaz, devam eder; ekleme ise mezar taşını yeniden kullanabilir.

Çok silme yapılan tablolarda mezar taşları birikir ve aramalar uzar: periyodik olarak yeniden hash'lemek (temizlik) gerekir. Zincirlemede bu sorun yoktur.

Mezar taşı · kodu adım adım çalıştır

Kod izleme: sil(13), ardından ara(24)

sil(13) çağrılır; önce yeri bulunmalı.

Ev adresi i = 13 % 11 = 2.

Yuva 2 DOLU ve anahtar 13 → return 2 (1 yoklama).

ara 2 döndürdü; i ≥ 0, silinecek öğe var.

tablo[2].durum = SILINDI: mezar taşı.

return true.

Ev adresi i = 24 % 11 = 2.

Yuva 2: mezar taşı: silinmiş, aramaya devam → i = 3.

Yuva 3: başka anahtar (11) → i = 4.

Yuva 4 DOLU ve anahtar 24 → return 4 (3 yoklama).

int ara(int k) {
  int i = k % M;
  for (int d = 0; d < M; d++, i = (i + 1) % M) {
    if (tablo[i].durum == BOS) return -1;
    if (tablo[i].durum == DOLU &&
        tablo[i].anahtar == k) return i;
  }
  return -1;
}
bool sil(int k) {
  int i = ara(k);
  if (i < 0) return false;
  tablo[i].durum = SILINDI;   /* mezar taşı */
  return true;
}

α sabit tutulursa tüm işlemler ortalama O(1)'dir. Pratik eşik: açık adreslemede α ≤ 0,5–0,7, zincirlemede α ≤ 1 civarı. Eşik aşılınca tablo büyütülür.

Yük Faktörü ve Silme

Yeniden boyutlandırma (rehashing)

typedef struct {
  yuva *a;      /* m yuvalık dinamik dizi */
  int m, n;     /* boyut, dolu yuva sayısı */
} Tablo;
/* ekledikten sonra: */
if (2 * t->n > t->m)             /* α > 1/2 */
  yeniden_boyutla(t, sonraki_asal(2 * t->m));
Neden yeniden hash?

h(k) = k mod m, m'ye bağlıdır: öğeler yeni tabloda başka yuvalara düşer; kopyalamak yetmez.

Amortize O(1)

Boyut her seferinde iki katına çıkınca n ekleme için toplam kopyalama ≤ 2n: ekleme başına sabit.

Mezar taşları

Yeniden hash'leme mezar taşlarını da temizler.

Yeniden boyutlandırma · kodu adım adım çalıştır

Kod izleme: yeniden_boyutla(t, 11)

n = 3, m = 5 → α = 0,6 > 0,5: tablo 11 yuvaya büyütülecek (≈ 2m, asal).

Eski dizinin adresi ve boyutu saklanır.

calloc sıfırlanmış 11 yuva verir: hepsi BOS (= 0).

Bellek alındı; tablo yeni diziye bağlanır, n = 0.

eski[0] BOS: atla.

eski[1] BOS: atla.

eski[2] = 7 DOLU → yeniden hash: 7 % 11 = 7 → yuva 7. (Eski yeri 7 % 5 = 2 idi.)

eski[3] = 12 DOLU → yeniden hash: 12 % 11 = 1 → yuva 1. (Eski yeri 12 % 5 = 2 idi.)

eski[4] = 3 DOLU → yeniden hash: 3 % 11 = 3 → yuva 3. (Eski yeri 3 % 5 = 3 idi.)

Eski dizi free edilir. Yeni α = 3/11 ≈ 0,27.

return true. Tüm öğeler yeniden eklendi: O(n + m).

bool yeniden_boyutla(Tablo *t, int yeni_m) {
  yuva *eski = t->a;
  int eski_m = t->m;
  yuva *a = calloc(yeni_m, sizeof *a);  /* BOS */
  if (a == NULL) return false;
  t->a = a; t->m = yeni_m; t->n = 0;
  for (int i = 0; i < eski_m; i++)
    if (eski[i].durum == DOLU)
      tablo_ekle(t, eski[i].anahtar);
  free(eski);
  return true;
}

Özet

Zincirleme mi, açık adresleme mi?

Zincirleme

  • α > 1 olabilir; dolmaz, yavaşlar.
  • Silme basit, mezar taşı yok.
  • Kötü hash'e karşı daha dayanıklı.
  • Düğüm başına işaretçi + malloc maliyeti; önbellek dostu değil.

Açık adresleme

  • Ek işaretçi yok; bellek bitişik, önbellek dostu.
  • α ≤ 1; α → 1 iken maliyet patlar.
  • Silme için mezar taşı gerekir.
  • Kümelenmeye karşı iyi yoklama (çift hash) seçilmeli.
Kural: öğe sayısı öngörülemiyorsa ve çok silme varsa zincirleme; bellek ve hız kritikse, silme az ve α düşük tutulabiliyorsa açık adresleme.

Alıştırmalar

  1. m = 7, h(k) = k mod 7, doğrusal yoklama: 10, 17, 24, 3 sırayla eklenince tablo ne olur?
  2. Aynı anahtarları zincirleme (başa ekleme) ile yerleştirin; en uzun zincir kaç düğümdür?
  3. m = 11 ve karesel yoklamada 0, 1, 4, 9, 16, 25 (mod 11) yoklama dizisini yazın.
  4. α = 0,9 olan doğrusal yoklamalı tabloda başarısız arama kaç yoklama bekler?
  5. "ab" ve "ba" için toplama hash'i ve 31 tabanlı polinom hash'i (mod 11) hesaplayın.
  6. Açık adreslemede ekle, SILINDI yuvaya yazmadan önce neden ara çağırmalıdır?
Cevapları göster
  1. 10 → 3, 17 → 3 dolu → 4, 24 → 3, 4 dolu → 5, 3 → 3, 4, 5 dolu → 6: yuva 3–6 = 10, 17, 24, 3.
  2. Hepsi kova 3'te: 3 → 24 → 17 → 10 (4 düğüm). Kötü hash seçimi zinciri uzatır.
  3. 0, 1, 4, 9, 5, 3 (16 mod 11 = 5, 25 mod 11 = 3).
  4. ½(1 + 1/0,01) = 50,5 yoklama: α → 1 iken maliyet patlar.
  5. Toplama: 97 + 98 = 195 → ikisi de 195 % 11 = 8. Polinom: "ab" = 97·31 + 98 = 3105 → 3; "ba" = 98·31 + 97 = 3135 → 0.
  6. Aynı anahtar mezar taşından sonraki bir yuvada zaten olabilir; kontrol edilmezse tabloya iki kez girer.
