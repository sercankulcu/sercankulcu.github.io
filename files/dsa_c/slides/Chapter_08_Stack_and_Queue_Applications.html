Maze

The Maze Problem

In an m×p matrix, 0s are open paths and 1s are walls. The entrance is [1][1] (S) and the exit [6][6] (E): we want a path from entrance to exit.

  • Moves are horizontal, vertical, and diagonal: 8 directions.
  • To avoid checking “am I leaving the matrix?” at every step, the matrix is surrounded by a border of 1s.
  • Visited cells are marked in the mark matrix, so no cell is entered twice.
  • At a dead end we back up to the most recent fork: last in, first out → a stack.

  • element: the record pushed on the stack: which cell (row, col) and, if we come back, which direction to try next (dir).
  • mark: visited cells (zero at the start because it is global).
  • maze: an 8×8 matrix with a border of 1s; the interior is 6×6.
  • The stack never holds more entries than there are open cells (13 here).

The path Routine

void path(void) {
  short int row, col, next_row, next_col;
  int i, dir, found = FALSE;
  element position;
  stack[0].row = stack[0].col = 1;
  stack[0].dir = 1;     /* push the start */
  mark[1][1] = 1;  top = 0;
  while (top > -1 && !found) {
    position = pop(&top);     /* next one */
    row = position.row;
    col = position.col;
    dir = position.dir;       /* which way */
    while (dir < 8 && !found) {
      next_row = row + move[dir].vert;
      next_col = col + move[dir].horiz;
      if (next_row == EXIT_ROW &&
          next_col == EXIT_COL)
        found = TRUE;         /* the exit? */
      else if (!maze[next_row][next_col] &&
               !mark[next_row][next_col]) {
        mark[next_row][next_col] = 1;
        position.row = row;   /* came from */
        position.col = col;
        position.dir = ++dir; /* resume dir */
        push(&top, position);
        row = next_row;  col = next_col;
        dir = 0;
      } else ++dir;           /* try another */
    }                         /* back up */
  }

If found, the stack positions (0…top), the last position and the exit are printed; otherwise “The maze does not have a path”. (Lines split for readability; logic unchanged.)

Maze

Assessment and the Worst Case

  • The eight-entry look-up table shortened the code and made the job easier.
  • The program does a brute-force search of the maze with a stack.
  • A worst-case analysis needs the worst-case input; the order in which directions are scanned decides it.
  • Input 1: the first path tried is long but correct → only pushes, no pops.
  • Input 2: the first path tried is long and wrong → it is followed to the end and the stack is emptied one by one; the solution is reached only after every cell off the correct path has been visited. This is the worst-case input.

Maze

Complexity, and a Comparison with a Queue

Time

Each open cell is pushed at most once (mark), and at most 8 directions are tried per cell: O(m·p) for an m×p maze.

Memory

The stack grows at most to the number of open cells: O(m·p); mark is O(m·p) too.

Stack (DFS)

The path found need not be the shortest. In this maze it went into the (2,3)→(1,3)→(1,4)→(1,5) dead end and came back; the path it found has 9 cells.

Queue (BFS)

Expands cells in order of distance, so it guarantees the shortest path. Here it finds the same 9-cell path, but in general the DFS path can be longer.

Expression Notations

Evaluating Expressions

Compilers also use stacks to evaluate logical and arithmetic expressions. How does a compiler cope with expressions like these?

Precedence

x = a / b − c + d * e − a * c

Value

((4 / 2) − 2) + (3 * 3) − (4 * 2) = 1

Parentheses

a / (b − c) + d * (e − a) * c

  • Reading left to right, we can't apply an operator right away: a higher-precedence operator may follow it.
  • The solution has two phases: first convert the expression to postfix according to precedence, then evaluate the postfix in a single pass. Both use a stack.

Converting by Hand: Parenthesize, Move, Erase

a / b − c + d * e − a * c

The starting expression.

((((a / b) − c) + (d * e)) − (a * c))

1. Fully parenthesize by precedence and associativity.

((((a b /) c −) (d e *) +) (a c *) −)

2. Move each operator to the right parenthesis that closes it.

a b / c − d e * + a c * −

3. Erase the parentheses: postfix. (For prefix, move each operator to its left parenthesis: − + − / a b c * d e * a c.)

The order of the operands never changes; only the operators move. That observation is the basis of the stack algorithm: operands go straight to the output, and operators wait on the stack until their moment comes.

Postfix Evaluation

Tokens: get_token

typedef enum { lparen, rparen, plus, minus,
    times, divide, mod, eos, operand } precedence;

precedence get_token(const char *expr, char *symbol, int *n) {
    *symbol = expr[(*n)++];
    switch (*symbol) {
        case '(':  return lparen;
        case ')':  return rparen;
        case '+':  return plus;
        case '-':  return minus;
        case '/':  return divide;
        case '*':  return times;
        case '%':  return mod;
        case '\0': return eos;
        default:   return operand;
    }
}
  • The expression is read one character at a time; each character is a token.
  • Operands are assumed to be single digits. To turn a digit into a number: symbol − '0'. The ASCII code of '2' is 50 and of '0' is 48: 50 − 48 = 2.
  • The expression ends with '\0' → eos.
  • expr could have been a global array; here it is passed as a parameter.

Postfix Evaluation

Postfix Evaluation: eval (Global Version)

float eval(void) {
    char symbol;  precedence token;
    float op1, op2;
    int n = 0, top = -1;
    token = get_token(expr, &symbol, &n);
    while (token != eos) {
        if (token == operand)
            push(&top, symbol - '0');
        else {
            op2 = pop(&top);   /* right operand first */
            op1 = pop(&top);
            push(&top, apply(token, op1, op2));
        }
        token = get_token(expr, &symbol, &n);
    }
    return pop(&top);   /* the one left is the result */
}
  • An operand is pushed; an operator pops two operands, applies itself, and pushes the result.
  • The first one popped is op2 (the right operand): 6 2 − means 6 − 2, not 2 − 6.
  • At the end exactly one item must remain on the stack; otherwise the expression is malformed.
  • apply picks among the five operators with a switch; case mod: (int)op1 % (int)op2, since % doesn't work on floats.

float eval(const char *expr) {
  float y[MAX_SIZE], op1, op2;  int top = -1;
  for (int n = 0; expr[n] != '\0'; n++) {
    char c = expr[n];
    if (isdigit(c)) y[++top] = c - '0';
    else {
      op2 = y[top--];  op1 = y[top--];
      switch (c) {
        case '+': y[++top] = op1 + op2; break;
        case '-': y[++top] = op1 - op2; break;
        case '*': y[++top] = op1 * op2; break;
        case '/': y[++top] = op1 / op2; break;
      }
    }
  }
  return y[top];
}

Infix → Postfix

Infix → Postfix: the Algorithm

  • Operand: written straight to the output.
  • Operator: while the operator on the stack has precedence greater than or equal to the incoming one, pop it to the output; then push the incoming operator (popping on ties = left associativity).
  • ( : always pushed; once inside the stack it acts as the lowest precedence.
  • ): pop to the output until ( is seen; discard the (.
  • At the end: pop everything left on the stack to the output.

# (bottom marker)−1—
( has two precedences: highest when arriving (it goes in without popping anything) and lowest on the stack (any operator can sit on top of it). The # at the bottom of the stack stops the loop.

void postfix(const char *e, char *out) {
  char y[MAX] = {'#'};  int top = 0, k = 0;
  for (; *e; e++) {
    if (isalnum(*e)) out[k++] = *e;
    else if (*e == ')') {
      while (y[top] != '(')
        out[k++] = y[top--];
      top--;                /* drop '(' */
    } else {
      while (isp(y[top]) >= icp(*e))
        out[k++] = y[top--];
      y[++top] = *e;
    }
  }
  while (top > 0) out[k++] = y[top--];
  out[k] = '\0';
}

Infix → Prefix: Reverse, Postfix, Reverse

(a+b)*c-d/a

One way to get infix → prefix: reverse the expression.

a/d-c*)b+a(

Reversed. Now swap ( and ).

a/d-c*(b+a)

Parentheses fixed. Convert this to postfix, but don't pop on equal precedence (use >), because reversing the expression also reverses associativity.

ad/cba+*-

The postfix result.

-*+abc/da

Reverse it again: prefix. Same as row 3 of the table.

A direct way: scan the expression right to left; operands are prepended to the output, and operators follow the same stack rule. Both ways are O(n).

float prefix_eval(const char *e) {
  float y[MAX], op1, op2;  int top = -1;
  for (int i = strlen(e) - 1; i >= 0; i--) {
    if (isdigit(e[i])) y[++top] = e[i] - '0';
    else {
      op1 = y[top--];  op2 = y[top--];
      y[++top] = apply(e[i], op1, op2);
    }
  }
  return y[top];
}

bool balanced(const char *e) {
  char y[MAX];  int top = -1;
  for (; *e; e++) {
    if (*e=='(' || *e=='[' || *e=='{')
      y[++top] = *e;
    else if (*e==')' || *e==']' || *e=='}') {
      if (top < 0 || !matches(y[top], *e))
        return false;  /* extra/wrong */
      top--;
    }
  }
  return top == -1;       /* none left open? */
}

Other Applications

More Applications of Stacks and Queues

Undo / redo

Two stacks: each action goes on the undo stack, each undone action on the redo stack; a browser's back/forward buttons work the same way.

Non-recursive traversal

Inorder traversal becomes a loop with an explicit stack of node addresses: O(n) time, O(h) stack.

Next greater element

The first larger element to the right of each item, in one pass: a decreasing stack, O(n).

Sliding-window maximum

A deque finds the maximum of every window in O(n).

Shortest path with BFS

Use a queue in the maze and the first path found is a shortest one.

Hanoi, n-vezir, sudoku

Recursive backtracking; it can also be written with an explicit stack.

Common Mistakes

1Swapping op1 and op2 in postfix: 6 2 − becomes −4.
2Using the postfix order in prefix: there the first pop is the left operand.
3Not popping on equal precedence in infix → postfix: a−b−c converts wrongly.
4When ) arrives, leaving the ( on the stack or writing it to the output.
5Forgetting the mark in the maze and looping forever.
6Running off the array because the maze has no border of 1s.

Chapter Summary

Backtracking

Every fork in the maze goes on the stack; at a dead end, pop back to the last fork.

Worst case

A long, wrong first path: the whole wrong region gets explored.

Notations

Infix needs precedence; postfix/prefix are evaluated without parentheses or precedence.

Postfix evaluation

Push operands; on an operator pop op2, then op1; push the result. O(n).

Infix → postfix

Pop while isp ≥ icp; ( is high when arriving, low on the stack.

General principle

Wherever you see “last opened, first closed,” use a stack; wherever you see “in order,” use a queue.
