Chapter 20: Advanced Sorting Algorithms

Once the number of items climbs past tens of thousands, the elementary sorts become unusable because their running time grows like n². This note studies four algorithms that do the same job in time proportional to n lg n, with C code and step-by-step traces: quicksort, merge sort, heap sort, and radix sort. It also covers the C library routine qsort together with its comparison function. The time and memory cost of each algorithm is derived, and the figures quoted here were checked by running the programs.

20.1Speeding up sorting: divide and conquer

20.1.1The limit of the elementary sorts

Selection sort finds the smallest remaining item in each pass and puts it in place. Bubble sort compares neighbors and carries the largest item to the end. Each pass fixes exactly one item in its final position. Yet the next pass starts again with a problem of n − 1 items. The problem shrinks by only one item per pass, so the total work is n + (n − 1) + … + 1, which is of order n². Insertion sort runs in linear time on nearly sorted data, but on general input it too reaches n².

To break through this barrier it is not enough to place items; the problem itself has to shrink quickly at every step. There is also a known lower bound for every comparison-based sorting algorithm. To identify the correct one of the n! orderings of n items, at least ⌈lg n!⌉ ≈ n lg n − 1.44 n comparisons are needed in the worst case. Here lg is the base-2 logarithm. The algorithms in this note approach that bound to within a small constant factor.

20.1.2Divide and conquer

Definition 20.1

Divide and conquer is a design method that recursively splits a problem into smaller subproblems until they are small enough to solve directly, solves the subproblems, and combines their solutions. It has three steps: divide, conquer, and combine.

Quicksort and merge sort are two different readings of this method. Quicksort does the heavy work while dividing: it splits the array into two parts so that everything on the left is less than or equal to everything on the right. No combining is then needed; once the two parts are sorted separately, the whole array is sorted. Merge sort does the opposite. It splits the array blindly in the middle and does the heavy work when merging two sorted halves.

The cost of both algorithms is written as a recurrence relation. The cost of a problem of n items is expressed in terms of the costs of smaller problems and the cost of the dividing or combining work. For example, an algorithm that halves the problem at each step and spends n on the split satisfies Cn = 2Cn/2 + n.

The arrays sorted in this note are always int arrays. For comparison and swapping, the two macros used in the elementary sorts are kept unchanged:

#define less(A, B) ((A) < (B))
#define SWAP(A, B) do { int t_ = (A); (A) = (B); (B) = t_; } while (0)

less(A, B) is true when A < B. Collecting the comparison in one place makes it easy to add a counter or to change the item type. In this note's measurements, comparisons were counted by adding a counter to this macro. SWAP takes two arguments and declares its temporary variable internally. Wrapping the body in do { … } while (0) makes the macro behave like a single statement in a place such as if (…) SWAP(x, y); else …. If the body were written with braces alone, the trailing semicolon would orphan the else and cause a compile error.

20.2Quicksort

Quicksort is the algorithm published by C. A. R. (Tony) Hoare in 1962. On average it runs in time proportional to n lg n; in the worst case it degrades to n². It uses only a small stack as auxiliary storage. It is not stable, meaning it does not preserve the relative input order of items with equal keys. Despite this flaw it is one of the fastest known general-purpose sorting algorithms. The name of qsort in the standard C library comes from this algorithm.

The code below is taken from R. Sedgewick's Algorithms in C. Sedgewick was a doctoral student of Donald Knuth and did extensive work on quicksort. The code is short and carefully written; every line has a job.

20.2.1quicksort1

int partition(int a[], int L, int R);

void quicksort1(int a[], int L, int R) {
    if (R <= L) return;
    int i = partition(a, L, R);
    quicksort1(a, L, i - 1);
    quicksort1(a, i + 1, R);
}

The routine sorts the range a[L..R]. To sort a whole array, call quicksort1(a, 0, n - 1). The prototype on the first line lets the compiler check the call even though the definition of partition appears further down.

  • if (R <= L) return; is the base case of the recursion. If R < L the range is empty, and if R = L it holds a single item. In both cases there is nothing to do.
  • int i = partition(a, L, R); partitions the range. partition puts one item, the pivot, at the position it will occupy in the sorted array and returns that position. On return, every item in a[L..i-1] is less than or equal to the pivot, and every item in a[i+1..R] is greater than or equal to it.
  • The two recursive calls sort the left and right of the pivot separately. The pivot is already in place; no later call touches it.

The correctness of the routine follows easily from these three lines. Once the left part is sorted, all of its items stand in the correct order to the left of the pivot, because none of them is greater than the pivot. The same holds for the right part. All the real work is in partition.

20.2.2Partitioning: partition()

Definition 20.2

Partitioning the range a[L..R] means rearranging the items so that, for some position i, a[L..i−1] ≤ a[i] ≤ a[i+1..R]. The item at a[i] is called the pivot. The statement that stays true at every moment while partitioning proceeds is called the partition invariant.

int partition(int a[], int L, int R) {
    int i = L - 1, j = R, v = a[R]; /* pivot is a[R] */
    for (;;) {
        while (less(a[++i], v))
            ;
        while (less(v, a[--j]))
            if (j == L) break;
        if (i >= j) break;
        SWAP(a[i], a[j]);
    }
    SWAP(a[i], a[R]);
    return i;
}

partition chooses the rightmost item, v = a[R], as the pivot. It uses two indices: i scans from left to right and j from right to left. Line by line:

  • Line 2. The scan starts with i = L - 1 and j = R. Because the scans advance with ++i and --j before looking, the first items examined are a[L] and a[R-1]. The pivot itself does not take part in the scan.
  • Lines 4–5. i stops at the first item greater than or equal to v. This loop has no bounds check, and none is needed. In the worst case i reaches R, and a[R] = v stops the scan because less(v, v) is false. Here the pivot acts as a natural sentinel.
  • Lines 6–7. j stops at the first item less than or equal to v. This scan has no sentinel on its left: if the pivot is the smallest item in the range, j could run off the start of the array. The line if (j == L) break; prevents that.
  • Line 8. If i >= j, the indices have met or crossed. Every item has been scanned and the loop ends.
  • Line 9. Otherwise a[i] belongs on the right side and a[j] on the left side; both are on the wrong side. After the swap both are on the correct side, and the scans resume where they left off.
  • Lines 11–12. When the loop exits, a[i] is the first item of the right side. The pivot is swapped with it and i is returned.

The partition invariant is described by the four regions in the figure. At every step of the loop, the items to the left of i (a[L..i-1]) are not greater than v, and the items to the right of j (a[j+1..R-1]) are not less than v. Between them lies a region not yet scanned. Each swap shrinks the unscanned region by two items. When the indices cross, this region is empty.

Having both scans stop on equal keys is a deliberate choice. Consider an array whose items are all equal. If the scans did not stop on equality, i would always run to the end. Every split would produce parts of n − 1 and 0 items, and the running time would reach n². When the scans stop on equal keys, seemingly needless swaps are made, but the indices meet in the middle.

The cost of partition on a range of n = R − L + 1 items is Θ(n). i moves only right and j only left. Each item is examined once until they meet; at the crossing, at most a few items are examined a second time. The number of comparisons is n or n + 1. The extra memory is a few variables: O(1).

Deleting the line if (j == L) break; in the j loop on the reasoning “the i loop has no bounds check either, so none is needed here.” The two scans are not symmetric. 20.2.5Why is it fast?

In bubble sort and selection sort too, the correct position of one item is found at every step. The difference is this: they put one item in place but do nothing to shrink the problem. The subproblem of the next step has n − 1 items. Quicksort, while placing the pivot, also splits the problem into two smaller parts. With a good split, each part has about n/2 items. At the next level, four parts have n/4 items each, and so on. After lg n levels the parts shrink to single items. The total partitioning work at each level is around n, so the overall work is of order n lg n.

All the quicksort versions in this note use the same partition. Code this short cannot be grasped by reading it once; it should be traced on several different arrays and rewritten from its logic.

20.2.6Algorithms and computers

Students often ask: where did Hoare try this algorithm in the 1960s, and how did he test it? Where does the word “algorithm” come from; did al-Khwarizmi have a laptop in the 9th century?

The answer lies in the concept of an algorithm itself. An algorithm is a precise method that someone who knows nothing about the subject can carry out step by step and still reach the correct result; computers do not appear in the definition. Computers did exist in the 1960s, but the correctness and cost of an algorithm are proved on paper, and publishing the proof in a paper is enough. That is why this course is independent of any computer.

The origin of the word confirms this. Al-Khwarizmi (780–850) was a mathematician and astronomer who worked at the House of Wisdom in Baghdad. He wrote al-Kitab al-Mukhtasar fi Hisab al-Jabr wa-l-Muqabala, which gives a systematic solution of linear and quadratic equations. The word “algebra” comes from the name of the method al-jabr in this book. “Algorithm” derives from Algoritmi, the Latinized form of al-Khwarizmi's name. Al-Khwarizmi is also known for the works that introduced the decimal positional number system to the West.

20.3Analysis of quicksort

The only thing that determines quicksort's running time is how partition divides the range. Each partition call does work proportional to the length of its range. If the splits are balanced, the recursion tree stays shallow; if they are unbalanced, the tree turns into a chain. In this section cost is measured by the number of comparisons, because comparison is the real work of sorting and the number of swaps is proportional to it. Cn denotes the number of comparisons made while sorting an array of n items.

20.3.1Worst case: a sorted array

Suppose the array is already sorted. The pivot a[R] is the largest item of the range every time. The i scan passes the whole range and stops at R; j stops at the first item it looks at. The pivot stays in place, the left part has n − 1 items and the right part is empty. The next call again takes the largest item as pivot and again continues with one item fewer. The total work is

n + (n − 1) + … + 2 + 1 = n(n + 1)/2 = O(n²)

The exact count can also be computed. On a range of size s, partition makes exactly s + 1 comparisons: s for the i scan and 1 for the j scan. The n − 1 ranges of sizes n, n − 1, …, 2 are partitioned. For n = 10 the total is 11 + 10 + … + 3 = 63 comparisons.

Moreover, the recursion depth reaches n − 1; large sorted arrays can cause a stack overflow on systems with small stacks. A sorted array of 100,000 items took 0.95 seconds with -O2, while a random array of the same size took 0.008 seconds (times vary by machine). A reverse-sorted array is just as bad.

20.3.2Best case: splitting exactly in the middle

In the best case the pivot is exactly the median of the range every time. i and j together advance n steps, and two subproblems of n/2 items each remain:

Cn = 2Cn/2 + n, C1 = 0

The recurrence is expanded by substituting it into itself. Since Cn/2 = 2Cn/4 + n/2, we get Cn = 2(2Cn/4 + n/2) + n = 4Cn/4 + 2n. One more expansion gives 8Cn/8 + 3n. After k steps

Cn = 2k Cn/2k + k · n

Taking n = 2k, that is k = lg n, gives Cn/2k = C1 = 0 and so Cn = n lg n.

The lower bound for comparison sorting was ⌈lg n!⌉ ≈ n lg n − 1.44 n. The leading coefficient is again 1; the gap is only about 1.44 n. The real question is behavior on a random array: the answer to “what is fast about this?” lies in the average case.

20.3.4Average case: setting up the recurrence

Average-case analysis rests on mathematics, not intuition. When a coin is tossed a million times, the fraction of heads approaches ½; average-case analysis pins down in the same way where the outcomes concentrate. Saying “the probabilities are equal as far as I am concerned” is not enough; the equality has to be proved.

Let all n! orderings of the input be equally likely and the keys distinct. The pivot is a[R]. In a random ordering, the rank of the rightmost item in sorted order takes each of the values 1, 2, …, n with equal probability 1/n. If the pivot has rank k, partition places it at position k, leaving two subarrays of k − 1 and n − k items. One more thing is required: the subarrays must also be random. partition compares items only with the pivot, never with each other. So the orderings inside each part are again equally likely, and the parts obey the same analysis.

partition makes n + 1 comparisons against the pivot. Taking this count as the model, the average number of comparisons satisfies the following recurrence:

Cn = (n + 1) + (1/n) Σk=1n (Ck−1 + Cn−k), C0 = C1 = 0

The first term is the partitioning work. The sum is the cost of the two subproblems for each value of k; the factor 1/n comes from those values being equally likely. The two sums contain the same terms. For k = 1, …, n the terms Ck−1 are C0, C1, …, Cn−1. The terms Cn−k are the same values, only in reverse order. Therefore

Σk=1n (Ck−1 + Cn−k) = 2 Σk=1n Ck−1

can be written. Multiplying both sides of the recurrence by n removes the fraction:

n · Cn = n(n + 1) + 2 Σk=1n Ck−1 (1)

The real partition makes n or n + 1 comparisons in a comparison scan; if the indices meet at the same position it counts one fewer. In an experiment with 20,000 random arrays, about 90% of the calls made n + 1 comparisons and the rest made n. So the measured averages come out slightly below Cn (last column of the table). The recurrence is a slightly pessimistic model; the asymptotic result does not change.

20.3.5The subtraction trick and the solution

The sum in recurrence (1) contains all earlier values for every n. Recurrences of this kind are usually solved by substitution, and Horowitz's book does it that way. There is a shorter route: eliminate the sum. In (1), replace n by n − 1:

(n − 1) · Cn−1 = (n − 1)n + 2 Σk=1n−1 Ck−1 (2)

Subtracting (2) from (1), the common terms of the two sums cancel, leaving only 2Cn−1. The difference of the first terms on the right is n(n + 1) − n(n − 1) = 2n:

n · Cn − (n − 1) · Cn−1 = 2n + 2Cn−1 ⇒ n · Cn = (n + 1) · Cn−1 + 2n

Now the recurrence depends only on the previous term. Divide both sides by n(n + 1):

Cn/(n + 1) = Cn−1/n + 2/(n + 1)

The beauty of this form is that the left side and the first term on the right have the same shape. Let Dn = Cn/(n + 1); then Dn = Dn−1 + 2/(n + 1). This unrolls at once by iteration: Dn = Dn−1 + 2/(n + 1) = Dn−2 + 2/n + 2/(n + 1) = …. The subtraction step requires (2) to hold for n − 1 ≥ 2. So the expansion is stopped at C2 = 3, where D2 = 1:

Cn/(n + 1) = 1 + 2(1/4 + 1/5 + … + 1/(n + 1)) (n ≥ 2)

The sum in parentheses is the harmonic number Hn+1 = 1 + 1/2 + … + 1/(n + 1) with its first three terms removed. The dominant part is 2(n + 1)(1/4 + … + 1/(n + 1)), which is less than 2(n + 1) ln n. Since Hn ≈ ln n + 0.577,

Cn ≈ 2n ln n = 2 ln 2 · n lg n ≈ 1.39 n lg n

follows. The last step uses the identity ln n = ln 2 · lg n; and 2 ln 2 ≈ 1.386.

Theorem 20.1 (Average case of quicksort)

If every ordering of n items with distinct keys is equally likely and partition makes n + 1 comparisons, the average number of comparisons of quicksort1 is Cn = 2(n + 1)Hn+1 − 8(n + 1)/3 (n ≥ 2). Consequently Cn ≈ 2n ln n ≈ 1.39 n lg n and Cn = Θ(n lg n).

The closed form follows from the expansion above: Cn = (n + 1)(1 + 2(Hn+1 − 1 − 1/2 − 1/3)) = 2(n + 1)Hn+1 − (n + 1)(2 · 11/6 − 1), and 2 · 11/6 − 1 = 8/3. For n = 2 we get 3 · (2 · 11/6) − 8 = 3, which agrees with C2 = 3 + (2/2)(0 + 0) = 3 from the recurrence. Since Hn+1 = ln n + O(1), the leading term is 2n ln n.

20.4Improving quicksort

quicksort1 has two weaknesses. First, in the worst case the recursion depth reaches n and can exhaust the stack. Second, sorted or reverse-sorted input drags it to n². In addition, on small subarrays the cost of recursion exceeds the useful work. This section examines three improvements in turn: a non-recursive version with an explicit stack, choosing the pivot as the median of three items, and leaving small subarrays to insertion sort.

20.4.1The non-recursive version and the explicit stack

A recursive routine keeps its pending work on the call stack; every call opens a stack frame carrying its parameters, local variables, and return address. Each pending job of quicksort1 is a pair (L, R). If these pairs are pushed onto a stack implemented with an array, recursion is unnecessary; the call overhead disappears and the order in which jobs are done comes under control.

#define YMAX 64     /* > 2·lg n */
static int stack[YMAX], top;
void stack_init(void) { top = 0; }
int stack_empty(void) { return top == 0; }
void push(int x) { stack[top++] = x; }
int pop(void) { return stack[--top]; }
#define push_range(A, B) \
  do { push(B); push(A); } while (0)

The stack is a static int array of size YMAX. top is the index of the first free cell; top == 0 means the stack is empty. The static keyword makes the array and top visible only within this source file and keeps both alive for the whole program. push writes the value to stack[top] and increments top. pop first decrements top, then returns that cell. Both operations are O(1).

The macro push_range(A, B) pushes a pair. It pushes B first, then A. Since the first item popped is the last one pushed, the first item popped is A. When push_range(L, R) is written in quicksort2, the pop order is L, then R. The body of the macro is again wrapped in do { … } while (0) so that it can be used as a single statement in if–else branches. The backslash (\) at the end of a line tells the preprocessor that the macro definition continues on the next line.

The stack does no overflow checking; its size was chosen so that no input can exceed it. By Theorem 20.2, the stack holds at most ⌊lg n⌋ + 1 pairs, that is 2(⌊lg n⌋ + 1) ints. For n < 231 this does not exceed 62.

void quicksort2(int a[], int L, int R) {
  stack_init(); push_range(L, R);
  while (!stack_empty()) {
    L = pop(); R = pop();
    if (R <= L) continue;
    int i = partition(a, L, R);
    if (i - L > R - i) {       /* larger part first */
      push_range(L, i - 1); push_range(i + 1, R);
    } else {
      push_range(i + 1, R); push_range(L, i - 1);
    }
  }
}
  • Line 2. The stack is emptied and the first problem, the whole range, is pushed.
  • Lines 3–5. Until the stack is empty, a pair is popped. If the range is empty or has one item, continue moves to the next pair. These lines correspond to the base case of quicksort1.
  • Line 6. The range is partitioned. The left part is a[L..i-1] and the right part is a[i+1..R]; their sizes are i − L and R − i.
  • Lines 7–11. The larger part is pushed first and the smaller part last. Because the stack gives back the last item first, the next round always processes the smaller part. If the sizes are equal, the else branch runs and the left part stays on top.

20.4.3Why does the stack stay small?

Theorem 20.2 (Size of the explicit stack)

While quicksort2 sorts an array of n items, the stack holds at most ⌊lg n⌋ + 1 pairs at any one time. The extra memory is O(lg n).

When a range is partitioned, the larger and the smaller part are pushed. The smaller part has at most ⌊(s − 1)/2⌋ items, because the two parts total s − 1. The smaller part is popped immediately. Every pair pushed between that moment and the popping of the larger part comes from inside the smaller part. So at any moment the larger parts waiting on the stack are remnants of the partitioning of nested ranges: S1 ⊃ S2 ⊃ … ⊃ Sk. Each Si+1 lies inside the smaller part of Si, so |Si+1| < |Si|/2. Since |S1| ≤ n, we get |Sk| < n/2k−1. A range that gets partitioned contains at least two items: 2 ≤ |Sk| < n/2k−1, that is 2k < n and k ≤ ⌊lg n⌋. In addition to these k larger parts, at most one smaller part waits on the stack.

The same result follows from a memory recurrence: the smaller part has at most half the size and each level adds two ints to the stack; Tn = Tn/2 + 2 gives Tn = 2 lg n, as in binary search. The table compares the bound with measurements. On sorted input the stack stays almost empty, because the smaller part is empty.

20.4.4Median-of-three and the small-subarray cutoff

Quicksort performs worst on sorted data. Insertion sort, by contrast, performs best on exactly sorted data. The improved version combines these two observations:

#define M 10    /* leave subarrays shorter than this */
void quicksort3(int a[], int L, int R) {
    if (R - L <= M) return;
    SWAP(a[(L + R) / 2], a[R - 1]);
    if (a[R-1] < a[L]) SWAP(a[R-1], a[L]); // a[L] <= a[R-1]
    if (a[R] < a[L]) SWAP(a[R], a[L]);     // a[L] <= a[R]
    if (a[R] < a[R-1]) SWAP(a[R], a[R-1]); // a[R-1] <= a[R]
    int i = partition(a, L + 1, R - 1);
    quicksort3(a, L, i - 1);
    quicksort3(a, i + 1, R);
}
void hybrid_sort(int a[], int L, int R) {
    quicksort3(a, L, R);
    insertion(a, L, R);   /* leftover small parts */
}

Median-of-three, or median-3 for short, chooses the pivot as the median of three items instead of a single item. These three items are the first item of the range, the middle item, and the last item. Line by line:

  • Line 3. If the range has at most M + 1 items (R − L ≤ M), the routine returns without doing anything. Such parts are left unsorted.
  • Line 4. The middle item is moved to a[R-1]. The three candidates are now a[L], a[R-1], and a[R].
  • Lines 5–7. Three “compare, swap if needed” steps put these three items in order. At the end a[L] ≤ a[R−1] ≤ a[R] holds and the median is in a[R-1].
  • Line 8. Partitioning is done only on a[L+1..R-1]. partition takes the last item of this range, the median, as the pivot.
  • Lines 9–10. The two sides of the pivot are processed recursively.

In the three swap lines the order of the arguments matters. The pattern if (less(A, B)) SWAP(A, B) says “swap if A < B.” After the swap, the item in B is the smaller of the two and the item in A the larger. The first line of the code, if (a[R-1] < a[L]) SWAP(a[R-1], a[L]);, puts the smaller item into a[L]. If the arguments were given in the order (a[L], a[R-1]), the larger item would go to a[L] and partitioning would break. This wrong version was tried on 1000 random arrays; in every one, at least one partition left an item larger than the pivot on its left.

Median-3 has two benefits. On sorted and reverse-sorted input the pivot comes from the middle of the range and the n² case disappears. A sorted array of 100,000 items took 0.95 seconds with quicksort1 and 0.001 seconds with hybrid_sort. In addition, the end items become natural sentinels: since a[L] ≤ pivot ≤ a[R], the j scan stops at a[L] at the latest.

The second improvement is the cutoff M. On a range of a few items, the fixed cost of the call and its setup exceeds the real work, so quicksort3 leaves parts with R − L ≤ M untouched. The array stays “nearly sorted”: every item is out of place only inside its own small part, and the parts are in the correct order relative to each other. At the end, hybrid_sort applies a single insertion-sort pass:

void insertion(int a[], int L, int R) {
    for (int i = L + 1; i <= R; i++) {
        int v = a[i];      // item being inserted
        int j = i - 1;     // a[L..i-1] is sorted
        while (j >= L && a[j] > v) {
            a[j + 1] = a[j]; // shift right
            j--;
        }
        a[j + 1] = v;
    }
}

The cost of insertion sort depends on how many positions the items shift. Here no item moves outside its own part, so the final pass runs in O(n · M) time, linear for a fixed M.

20.5The C library and hybrid sorts

20.5.1qsort

The standard C library provides a general-purpose sorting routine in the header <stdlib.h>:

void qsort(void *base, size_t nmemb, size_t size,
           int (*compar)(const void *, const void *));

The parameters are the address of the array, the number of items, the size of one item in bytes, and the address of the comparison function. qsort does not know the item type; it sees the array as blocks of size bytes. For this reason the first parameter is a void pointer: a pointer that can carry the address of any object but carries no type information. A void * cannot be dereferenced directly; it is first converted to the real type.

The fourth parameter is a function pointer: the address of a function that takes two const void * and returns an int. In C, a function name written without parentheses yields the address of the function. When qsort compares two items, it calls this function with the addresses of the items; by changing the comparator, any type can be sorted.

int ascending(const void *p, const void *q) {
    int x = *(const int *)p;
    int y = *(const int *)q;
    return (x > y) - (x < y);  // -1, 0, +1
}
int main(void) {
    int a[] = {37, 15, 24, 33, 49};
    size_t n = sizeof a / sizeof a[0];
    qsort(a, n, sizeof a[0], ascending);
    for (size_t i = 0; i < n; i++)
        printf("%d ", a[i]);
    return 0;
}

The program is compiled with the headers <stdio.h> and <stdlib.h> and prints 15 24 33 37 49.

  • ascending. The incoming void pointers are converted to const int * and dereferenced. const states that the comparison function will not modify the items. The return value is (x > y) - (x < y). In C, a comparison operator yields 1 if true and 0 if false. If x > y the result is 1 − 0 = 1, if x < y it is 0 − 1 = −1, and if they are equal it is 0.
  • sizeof a / sizeof a[0]. The total size of the array is divided by the size of one item. With a 4-byte int this gives 20 / 4 = 5. This expression gives the correct result only where the array is defined. When the array is passed to a function as a parameter, it decays to a pointer and sizeof gives the size of the pointer.
  • qsort(a, n, sizeof a[0], ascending). ascending is written without parentheses; it is not called, its address is passed. The item size is written as sizeof a[0] rather than sizeof(int). If the type of the array changes, this expression stays correct automatically.

The comparison function must obey a contract. It returns a negative value if the first item must come before the second, a positive value if it must come after, and zero if they are equal. The magnitude of the return value is irrelevant; only its sign is used. The function must also be consistent: if it says a < b and b < c, it must say a < c. 20.5.3Sorting records

In real applications, what gets sorted is usually not a number but a record with several fields. In C, records are represented with struct. The comparison function determines which field the sort is based on:

typedef struct { char name[20]; int grade; } student;

int by_name(const void *p, const void *q) {
    const student *x = p, *y = q;
    return strcmp(x->name, y->name);        // alphabetical
}
int by_grade_desc(const void *p, const void *q) {
    const student *x = p, *y = q;
    return (y->grade > x->grade) - (y->grade < x->grade);
}
/* qsort(s, n, sizeof s[0], by_name); */

The student structure carries a 20-character name and a grade; its size is 24 bytes.

In C, a void * can be assigned to another object pointer without an explicit cast; const student *x = p is therefore valid. strcmp already returns a value that meets the contract of qsort. In by_grade_desc, x and y are swapped so that the higher grade comes first.

These two functions were tried on the array {Zeynep 85, Ali 70, Mehmet 85, Ayse 92, Can 70}. Sorting with by_name gives Ali, Ayse, Can, Mehmet, Zeynep. Sorting that sorted array afterwards with by_grade_desc gave Ayse 92, Mehmet 85, Zeynep 85, Can 70, Ali 70. The alphabetical order of the two students with grade 70 was disturbed. This is not a bug. The standard does not require qsort to be stable or to use a particular algorithm. If the order among equal keys matters, a secondary key is added to the comparison function:

int by_grade_then_name(const void *p, const void *q) {
    const student *x = p, *y = q;
    int k = (y->grade > x->grade) - (y->grade < x->grade);
    if (k != 0) return k;               /* grades differ: higher grade first */
    return strcmp(x->name, y->name);        /* grades equal: alphabetical */
}

With this function the result is Ayse 92, Mehmet 85, Zeynep 85, Ali 70, Can 70, independent of the order of the input.

Common mistake

Writing the comparison function as the shortcut return x - y;. It works for small values, but when the difference does not fit in an int, signed integer overflow occurs, which is undefined behavior in C. For x = INT_MIN, y = 1 the true difference is −2,147,483,649, which is below the lower limit of int. A program compiled with -fsanitize=undefined stopped on this line with the message “signed integer overflow.” In a build where overflow wraps around (-fwrapv), the result came out as +2,147,483,647, that is, INT_MIN was treated as greater than 1. (x > y) - (x < y) overflows for no value.

The price of the library routine is that every comparison is a function call. One million random ints were sorted in 0.21 seconds with qsort and in 0.10 seconds with hybrid_sort (-O2; times vary by machine). Even so, qsort is a tested, ready-made routine that works with every type, and in most programs it is the right choice. Which algorithm it uses varies from implementation to implementation.

20.5.4Hybrid sorts

No single algorithm is best in every situation. Quicksort is fast on average but degrades to n² in the worst case. Heap sort is n lg n even in the worst case, but its constant is large. Insertion sort is unrivaled on small and nearly sorted arrays. A hybrid sort combines these strengths:

  • Quicksort + insertion sort. On small parts the cost of recursion dominates. Parts smaller than M are finished with insertion sort. quicksort3 with hybrid_sort is an example.
  • Introsort (Musser, 1997). It starts as quicksort and monitors the recursion depth. If the depth exceeds about 2⌊lg n⌋, that signals that the splits are going badly, and that part is sorted with heap sort. This brings the worst case down to O(n lg n). Small parts are again finished with insertion sort. It is common in implementations of std::sort in the C++ library.
  • Timsort (Peters, 2002). It combines merge sort with insertion sort. It finds the ready-sorted stretches of the data, the “runs,” and merges them. Because it exploits the order present in real data, it approaches linear time on nearly sorted input. It is stable. Python's sort and Java's Arrays.sort for object arrays are Timsort.

The common idea has three layers: good asymptotic behavior at large scale (n lg n), a low constant at small scale (insertion sort), and an insurance policy for the worst case. This is why the sorting routines in real libraries differ from the pure algorithms in textbooks.

20.6Merge sort

20.6.1The idea

Merge sort is a divide-and-conquer algorithm described by John von Neumann in 1945. It can be stated in four sentences:

  1. A list of 0 or 1 items is already sorted.
  2. Otherwise the list is split into two parts that are as equal as possible.
  3. Each part is sorted by applying merge sort recursively.
  4. The two sorted sublists are merged into a single sorted list.

The algorithm rests on two observations. First, sorting a small list takes fewer steps. Second, producing one sorted list from two sorted lists is much cheaper than producing one from two unsorted lists. The smallest item of two sorted lists is always at the front; the next item of the merged list is the smaller of these two fronts. So merging finishes in a number of steps equal to the sum of the lengths of the two lists.

In quicksort every partition puts the pivot in its final place. In merge sort no item settles during the split; the algorithm exploits the advantage of two arrays being sorted. Splitting the input in the middle depended on luck in quicksort; here it is always the case.

20.6.2merge: merging from both ends

The code is the version in Sedgewick's book. Merging in place is hard, so an auxiliary array b of the same size as a is used.

void merge(int a[], int b[], int L, int m, int R) {
    int i, j, k;
    for (i = m + 1; i > L; i--) b[i - 1] = a[i - 1];
    for (j = m; j < R; j++) b[R + m - j] = a[j + 1];
    for (k = L; k <= R; k++)
        if (less(b[j], b[i]))
            a[k] = b[j--];
        else
            a[k] = b[i++];
}

merge(a, b, L, m, R) merges the halves a[L..m] and a[m+1..R], each sorted on its own, into a single sorted array in a[L..R]. Line by line:

  • Line 3. The left half is copied as is into b[L..m]. The loop starts at i = m + 1, performs the assignment b[i-1] = a[i-1], and ends when i = L. After the loop, i points to the first item of the left half.
  • Line 4. The right half is copied into b[m+1..R] in reverse order. For j = m, b[R] = a[m+1] is written; for j = R - 1, b[m+1] = a[R]. The loop ends with j = R; j points to the smallest item of the right half.
  • Lines 5–9. k is the position to be written in a. At each step b[i] and b[j] are compared and the smaller is written to a[k]. If the item comes from the right, j decreases; if from the left, i increases. On equality less(b[j], b[i]) is false, and the item on the left is taken.

The reverse copy is the subtlest point of the code. After the copy, b[L..R] first rises and then falls: it is a bitonic array. In an ordinary merge, every step needs the check “is this half finished?” Here, when the left half is exhausted, i enters the large items of the right half, and these are not smaller than b[j]; from then on the loop always takes from j. The situation for the right half is symmetric: each half is the sentinel of the other.

20.6.4mergesort and the auxiliary array

void mergesort(int a[], int b[], int L, int R) {
    if (R <= L) return;
    int m = (R + L) / 2;
    mergesort(a, b, L, m);
    mergesort(a, b, m + 1, R);
    merge(a, b, L, m, R);
}

The routine returns if the range is empty or has one item. Otherwise it finds the middle with m = (R + L) / 2, sorts the two halves, and merges them. If the range has an odd number of items, the left half gets one more: 17 items split as 9 + 8.

The auxiliary array b is passed as a parameter. If it were allocated afresh in every merge call, each call would perform a malloc and a free; that means the overhead of n − 1 memory requests. The right way is to allocate the array once and hand the same array to all calls. A wrapper function can do this:

int merge_sort_alloc(int a[], int n) {
    int *b = malloc(n * sizeof *b);   /* same size as a */
    if (b == NULL) return 0;          /* no memory: not sorted */
    mergesort(a, b, 0, n - 1);
    free(b);
    return 1;
}

If the pointer returned by malloc is NULL, memory could not be allocated. In that case the array is left unsorted and 0 is returned; the caller learns of the situation from this return value. The expression n * sizeof *b uses the size of the type that b points to, so it stays correct even if the type of b changes. When the work is done, the block is returned with free. If free were forgotten, 4n bytes would be lost on every call; this is a memory leak. The wrapper was tested with a 10-item array and a counting malloc/free pair: one allocation, one release.

Common mistake

Not allocating b[] at all, that is, declaring int *b; and calling mergesort(a, b, 0, n - 1) directly. b is an uninitialized pointer and points to a random address. merge writes to that address; the program either crashes or overwrites other variables. The opposite is also a mistake: allocating b with malloc inside merge on every call. The program runs correctly but slows down needlessly.

20.6.8Analysis and stability

An array of n items is split into two halves of ⌈n/2⌉ and ⌊n/2⌋ items; merging makes n comparisons. The number of comparisons an satisfies the recurrence

an = a⌈n/2⌉ + a⌊n/2⌋ + n, a1 = 0

For example, 16 items split as 8 + 8 and 17 items as 9 + 8. If n = 2k, the two halves are equal and the recurrence becomes an = 2an/2 + n. This is the best-case recurrence of quicksort and gives an = n lg n.

Theorem 20.3 (Cost of merge sort)

mergesort makes Θ(n lg n) comparisons on every array of n items; if n = 2k the count is exactly n lg n. It makes 2n − 1 calls and n − 1 merges. The extra memory is the n-item auxiliary array plus a call stack of depth O(lg n).

Each merge makes as many comparisons as there are items in its range, and this number does not depend on the order of the input. So the number of comparisons depends only on n and equals an. At every level of the frame tree the ranges cover the array, and the total work of a level is at most n; the number of levels is ⌈lg n⌉. Hence an ≤ n⌈lg n⌉. For the lower bound: every range at depth d < ⌊lg n⌋ has size at least ⌊n/2d⌋ ≥ 2; each of these first ⌊lg n⌋ levels makes exactly n comparisons, so an ≥ n⌊lg n⌋. For the number of calls, the recurrence Tn = T⌈n/2⌉ + T⌊n/2⌋ + 1, T1 = 1 gives Tn = 2n − 1: for n ≥ 2, (2⌈n/2⌉ − 1) + (2⌊n/2⌋ − 1) + 1 = 2n − 1. The tree has n leaves; the remaining n − 1 nodes perform merges.

Instrumented runs confirmed these values. For 10 items: 19 calls, 9 merges, and 34 comparisons; for 16 items: 31 calls, 15 merges, and exactly 16 · 4 = 64 comparisons; for 17 items: 33 calls and 70 comparisons. The recurrence can also be unrolled by hand: a10 = 2a5 + 10, a5 = a3 + a2 + 5 = 5 + 2 + 5 = 12, and a10 = 34.

The running time is independent of the state of the array: the best, average, and worst cases are all n lg n; there is no bad input. The price is O(n) extra memory. Ways of removing it raise the cost; if extra memory is unwelcome, heap sort comes to the fore.

Merging reads and writes sorted pieces sequentially. This property makes it the basis of external sorting, that is, sorting files on disk that do not fit in memory: pieces that fit in memory are sorted and written to disk, then merged.

Stability requires a distinction. The classic merge takes the item from the left half on equality and copies the remaining items separately; this merge is stable. Quicksort and heap sort are not stable; merge sort differs from them in this respect. However, the bitonic merge with reverse copying used here is not stable. When the left half is exhausted, i enters the reverse-ordered items of the right half and takes equal items in reverse order. With four equal keys [2a, 2b, 2c, 2d], the sort gave [2a, 2b, 2d, 2c]: 2c and 2d swapped places. In an experiment with 1000 random arrays of 2–10 items with values from 0 to 3, the order of equal items was disturbed in 194 arrays. If stability is needed, the right half is not copied in reverse and a check is made for whether one of the halves has run out.

20.7Linked merge sort

20.7.1Large records and the link field

In real applications an item may be a record of hundreds of bytes, for example one carrying a student's name and address. Copying such records between two arrays at every merge takes time. The solution is not to move the records at all: a link field is added to each record, and a linked list is built inside the array using indices. Sorting changes only the indices.

typedef struct {
    int key;   /* + large data fields */
    int link;       /* index of the next item, 0 = end */
} element;

int mergesort(element a[], int L, int R) {
    if (R <= L) return L;          /* single-item list */
    int m = (R + L) / 2;
    int right = mergesort(a, m + 1, R);
    int left = mergesort(a, L, m);
    return merge(a, left, right);     /* head index */
}

The element structure carries a key and a link. The comment “+ large data fields” reminds us that in a real application the structure may be much bigger. link is the index in the array of the item that follows this one in the list; 0 marks the end of the list. For this reason the data live in a[1..n] and a[0] is not used as an item. a[0] serves as a temporary list head during merging. Initially all link fields are 0: every item is a list by itself.

This time mergesort returns a value: the head index of the sorted list built from the items in a[L..R]. In a single-item range the list is the item itself and L is returned. In a larger range the two halves are sorted separately, the lists they return are merged with merge, and the head of the new list is returned.

In the code the right half is sorted first, and this order is deliberately written on two separate lines. If the two calls were written as the arguments of merge, it would be unclear which runs first: in C the order of evaluation of arguments is unspecified. The result comes out the same, but the intermediate states, and any hand-prepared trace table, would vary with the compiler.

20.7.2Linked merge

int merge(element a[], int first, int second) {
    int tail = 0;              // a[0]: temporary head
    int i1 = first, i2 = second;
    while (i1 && i2)
        if (a[i1].key <= a[i2].key) {
            a[tail].link = i1; tail = i1;
            i1 = a[i1].link;
        } else {
            a[tail].link = i2; tail = i2;
            i2 = a[i2].link;
        }
    a[tail].link = i1 ? i1 : i2;
    return a[0].link;
}

merge(a, first, second) merges the two sorted lists whose heads are first and second into a single sorted list and returns the head index of the new list. Line by line:

  • Line 2. tail is the last item of the merged list so far. At the start the list is empty and tail = 0, that is, the temporary head a[0]. This little trick removes the need to write a separate “is it the first item?” case. The first item added is also written through a[tail].link, that is, to a[0].link.
  • Line 3. i1 and i2 are the first items of the two lists not yet taken.
  • Lines 4–11. The loop continues while both lists have items left. The item with the smaller key is linked to the end of the merged list (a[tail].link = i1), tail advances to it, and the index of the list it came from moves to the next item. On equality, thanks to <=, the item in the first list is taken. As long as the first list comes from the left half, equal keys keep their input order; this version is stable.
  • Line 12. When one list runs out, the rest of the other is attached with a single link. As in the array version, there is no need to copy the remaining items one by one; the remainder is already a sorted list.
  • Line 13. The head of the merged list is in a[0].link and is returned.

No item moves; only links are rewritten. The cost of a merge is the number of loop iterations, which is less than the sum of the lengths of the two lists. The number of comparisons comes out slightly smaller than in the array version, because comparison also stops when one list ends.

Common mistake

20.8Heap sort

Merge sort is O(n lg n) in every case but needs O(n) extra memory. Quicksort works in place but degrades to n² in the worst case. Heap sort combines two good properties: it runs in O(n lg n) even in the worst case and uses no extra memory. It does this by building the heap structure, used to implement priority queues, inside the array being sorted.

20.8.1An array is a tree

The array is viewed as a[1..n]; a[0] is not used. This array is read like a complete binary tree: the root is a[1], the children of a[i] are a[2i] and a[2i+1], and its parent is a[i/2]. The nodes of the tree are placed in the array level by level, left to right. So no pointers are needed; the links come from index arithmetic. One-based indexing simplifies these formulas. In a zero-based array the children would be 2i + 1 and 2i + 2.

Definition 20.3

A complete binary tree in which the value of every node is not less than the values of its children is called a max-heap. In the array representation this condition means a[i/2] ≥ a[i] for every 2 ≤ i ≤ n. In a max-heap the largest item is at the root.

Heap sort works in two phases. First, the array is turned into a max-heap. Then the largest item at the root is moved to the end of the array, the heap shrinks by one item, and the remaining heap is repaired. When this step is repeated n − 1 times, the array is sorted from smallest to largest.

void heapify(int a[], int root, int n) {
    int t = a[root], j;
    for (j = 2 * root; j <= n; j *= 2) {
        if (j < n && a[j] < a[j + 1]) j++; // larger
        if (t >= a[j]) break;   // t fits here
        a[j / 2] = a[j];        // move the child up
    }
    a[j / 2] = t;
}
void heapsort(int a[], int n) {     /* a[1..n] */
    int i;
    for (i = n / 2; i >= 1; i--)     /* build the heap */
        heapify(a, i, n);
    for (i = n - 1; i >= 1; i--) {   /* sort */
        SWAP(a[1], a[i + 1]);    /* largest to the end */
        heapify(a, 1, i);            /* repair the heap */
    }
}

20.8.2heapify

heapify(a, root, n) finds the proper place for the value at the root, in the heap a[1..n], when the left and right subtrees of node root are already max-heaps. This is exactly the sift-down operation performed when removing the largest item from a priority queue; it appears in Horowitz's book under the name adjust. Line by line:

  • Line 2. The value at the root is taken into t. The root now holds a “hole.” t will finally be written wherever this hole ends up.
  • Line 3. j is the left child of the hole: 2 * root. At each round the loop descends one level (j *= 2) and ends when j leaves the heap.
  • Line 4. If the right child exists (j < n) and is larger than the left child, j moves to the right child. j now points to the larger child.
  • Line 5. If t is not smaller than the larger child, the hole is exactly in place and the loop exits.
  • Line 6. Otherwise the larger child is moved up into the hole, that is, to its parent a[j/2]. The hole descends to j.
  • Line 8. Wherever the loop ends, the hole is at a[j/2] and t is written there. When the exit is by break, j/2 is the hole itself. When the loop ends with j > n, j would be a child of the last hole; j/2 again gives the hole.

Shifting is done instead of swapping: one assignment per level and one final assignment for t. The cost of heapify is proportional to the number of levels the hole descends and cannot exceed lg n.

20.8.3Building the heap

The first way that comes to mind for turning an array into a heap is to insert the items one by one into an empty heap. In applications such as Kruskal's algorithm, the items arrive one at a time anyway, so the heap is built this way. Since each insertion takes O(lg n), the total is O(n lg n). If the items are already available in an array, there is a better way: bottom-up heap construction.

The leaves are already one-item heaps. Nodes with i > ⌊n/2⌋ have no children, because their left children would fall at position 2i > n. So the loop starts at ⌊n/2⌋ and goes backward toward the root: ⌊n/2⌋, ⌊n/2⌋ − 1, …, 1. For each i the subtrees of the node have already been repaired, so the precondition of heapify holds. When the loop reaches the root, the whole array is a max-heap.

Common mistake

Mixing one-based indices with a zero-based array. The formulas in which the children are 2i and 2i + 1 are correct only for a[1..n]. If a C array is declared as int a[10] and heapsort(a, 10) is called, the routine accesses a[10], outside the array, and the item in a[0] is never sorted. The correct approach is to declare the array with n + 1 items or to rewrite the formulas in their zero-based form.

20.8.5Analysis

By a crude analysis, heapify makes at most lg n shifts and is called n/2 times: O(n lg n). This bound is loose, because most calls happen in small subtrees.

For a finer analysis the tree is examined level by level. Let k be the number of levels of the tree; k ≈ lg(n + 1). Level i has at most 2i−1 nodes. A node on this level can sink at most k − i levels. In the worst case the total number of shifts is

Σi=1k 2i−1(k − i) = k Σi=1k 2i−1 − Σi=1k i · 2i−1

The first sum is a geometric series: 2k − 1. The second sum is found from the derivative of the geometric series. Let S(y) = 1 + y + … + yk = (yk+1 − 1)/(y − 1). Differentiating term by term gives S′(y) = Σi=1k i · yi−1; the sum we want is S′(2). Differentiating the fraction and setting y = 2 gives S′(2) = (k + 1)2k − (2k+1 − 1) = (k − 1)2k + 1. Thus

k(2k − 1) − (k − 1)2k − 1 = 2k − k − 1

Theorem 20.4 (Cost of heap sort)

In a tree with k levels, bottom-up heap construction makes at most 2k − k − 1 ≤ 2n shifts; heap construction is O(n). The sorting phase takes O(n lg n) with n − 1 heapify calls. Heap sort is O(n lg n) even in the worst case, uses O(1) extra memory, and is not stable.

The construction bound is the computation above. A complete binary tree with k levels has at least 2k−1 nodes; so n ≥ 2k−1 and 2k ≤ 2n. In the sorting phase heapify(a, 1, i) makes at most ⌊lg i⌋ shifts; Σi=1n−1 lg i ≤ n lg n. The routine uses only a few variables and is non-recursive. One example suffices for instability: the array [2a, 2b, 1] is sorted as [1, 2b, 2a].

That the bound is tight can be shown with the input that produces the worst case. In an ascending sorted array, the value of every internal node is smaller than its entire subtree, and every heapify sinks the hole all the way to a leaf. 20.8.6Advanced heap sort and knowing your data

About 2n lg n comparisons is more than quicksort's 1.39 n lg n, and heap sort accesses memory irregularly. It is a reasonable choice for data up to around fifty thousand items; for larger data there are versions that reduce the number of comparisons.

The best known of these is bottom-up heapsort. Its idea is this: the item t that replaces the one taken from the root almost always sinks all the way to a leaf, because it came from the end of the array and is small. So comparing t with the larger child at every level is mostly wasted. In the bottom-up version, the hole is sent down to a leaf along the larger children without comparing against t. Then t is placed, starting at the leaf and moving upward. This walk upward usually ends in a step or two. As a result, one comparison per level is made most of the time instead of two. Versions that are even better in theory are known.

If some properties of the data to be sorted are known, the algorithm is chosen according to them. In counting sort the keys are known to lie in a small range, and sorting takes linear time with no comparisons at all. There are also applications that use Shell sort and bucket sort together. A few basic methods of this kind should be known, and the structure of the data should be recognized. Radix sort is another example of this way of thinking.

20.9Radix sort

20.9.1Sorting on multiple keys

Some sorts are done on more than one key. A list of people can be sorted first by last name, with people sharing a last name sorted by first name. Let the keys be denoted K0, K1, …, Kr−1. K0 is the most significant key (most significant digit, MSD) and Kr−1 is the least significant key (least significant digit, LSD). In the list-of-people example, the last name is the most significant key. A three-digit number can be thought of in the same way: the hundreds digit is K0, the tens digit K1, and the units digit K2.

In the MSD approach, items are first divided into groups by the most significant key and each group is sorted internally; this approach is recursive and complicated. The LSD approach looks backward at first glance but is much simpler.

Definition 20.4

Radix sort, in its LSD form, sorts the items first by the least significant digit, then by successively more significant digits, and finally by the most significant digit. Each pass must be stable: items with equal digits must keep the order left by the previous pass.

The reason for the stability requirement is this. In the hundreds pass, 208 and 271 have the same hundreds digit, 2. This pass cannot tell them apart. The correct order was determined by the earlier passes: the tens pass put 208 (tens digit 0) before 271 (tens digit 7). If the hundreds pass does not disturb this order, the result is correct. Each pass preserves the work of the previous one and adds a more significant digit on top.

Radix sort never compares the numbers with each other. It is therefore a non-comparison sort and is not bound by the n lg n lower bound of comparison sorts. The price is that the structure of the keys, that is, their digits, must be known.

    item_ptr link;
};

Each item is a node of a linked list. The digit array holds the digits of the number: for 179, {1, 7, 9}. digit[0] is the hundreds digit (MSD), digit[1] the tens, and digit[2] the units digit (LSD). The numbers are in the range [0, 999]. link is the address of the next node in the list.

typedef struct item *item_ptr; comes before the structure definition and names the pointer type that points to struct item. Because the size of a pointer is independent of the contents of the structure, the structure may not yet be defined; this allows item_ptr link; to be written inside the structure. A typedef that gives no name, such as typedef struct item {…};, is meaningless. On x86-64, sizeof(struct item) is 24 bytes: a 12-byte array, 4 bytes of alignment padding, and an 8-byte pointer.

Building the list to be sorted also requires memory management. The following two routines were added to this note. build_list builds a list in the same order from an int array:

/* builds a linked list from 3-digit numbers; frees what was built if memory runs out */
item_ptr build_list(const int x[], int n) {
    item_ptr head = NULL, last = NULL;
    for (int k = 0; k < n; k++) {
        item_ptr d = malloc(sizeof *d);
        if (d == NULL) {               /* stopped midway: avoid a leak */
            free_list(&head);
            return NULL;
        }
        d->digit[0] = x[k] / 100;      /* hundreds */
        d->digit[1] = x[k] / 10 % 10;  /* tens */
        d->digit[2] = x[k] % 10;       /* units */
        d->link = NULL;
        if (last) last->link = d; else head = d;
        last = d;
    }
    return head;
}
/* frees every node of the list and sets the caller's pointer to NULL */
void free_list(item_ptr *pp) {
    while (*pp) {
        item_ptr next = (*pp)->link;
        free(*pp);
        *pp = next;
    }
}

build_list allocates one node per number. If malloc returns NULL, memory has run out. If the half-built list were not released, the nodes allocated up to that point would leak. So the routine first deletes the part it has built with free_list, then returns NULL. The digits are separated with integer division and remainder: 179 / 100 = 1, 179 / 10 % 10 = 7, 179 % 10 = 9. The pointer last holds the last node of the list; a new node is linked behind it, so the list keeps the input order.

free_list takes its parameter as item_ptr *pp, that is, a pointer to a pointer. This way it not only releases the nodes but also sets the caller's head pointer to NULL. At each round the loop first saves the address of the next node in next, then releases the node. If the order were reversed, that is, if free(*pp) came first and (*pp)->link were read afterwards, freed memory would be accessed. That is undefined behavior. The two routines were tested with a counting malloc/free pair: 500 random lists were built, sorted, and deleted, and 74,115 allocations were matched by 74,115 releases. In an experiment where memory ran out at the fourth node, the first three nodes were released and NULL was returned.

20.9.3radixsort

Written as a function, with the declaration of the bucket arrays, the loop body from the slides takes this form:

item_ptr radixsort(item_ptr p) {
    item_ptr front[RADIX], back[RADIX];  /* bucket heads and tails */
    for (int i = MAX_DIGIT - 1; i >= 0; i--) {
        for (int j = 0; j < RADIX; j++)
            front[j] = back[j] = NULL;
        for (; p; p = p->link) {     // distribute
            int b = p->digit[i];
            if (!front[b]) front[b] = p;
            else back[b]->link = p;
            back[b] = p;
        }
        for (int j = RADIX - 1; j >= 0; j--) // collect
            if (front[j]) { back[j]->link = p; p = front[j]; }
    }
    return p;
}

For each digit value there is a bucket in the form of a linked list. front[j] points to the first node of the bucket and back[j] to the last; as in a queue, keeping the last node allows appending at the back in constant time.

  • Outer loop. i goes down from MAX_DIGIT - 1 to 0: first the units digit (i = 2), then the tens, and finally the hundreds digit is processed. This is LSD order.
  • Emptying the buckets. At the start of every pass, the front and back pointers of the ten buckets are set to NULL.
  • Distributing. The list is walked from start to end. The i-th digit of each node is taken into b. If the bucket is empty, the node becomes the first node of the bucket. Otherwise the link of the bucket's last node is linked to this node. In both cases the node is the new end of the bucket. Because nodes are appended to the bucket in order of arrival, distribution is stable. The loop advances with p = p->link. This read uses the node's old link; the node's own link has not been changed yet, only the link of the previous node in the bucket. When the loop finishes, p is NULL.
  • Collecting. The buckets are walked from 9 down to 0. The last node of each non-empty bucket is linked to the head of the list built so far (back[j]->link = p), and the head of the list becomes the first node of the bucket (p = front[j]). The list is built from back to front; bucket 0, added last, stands at the very front. So the bucket with the small digit comes first. The link of the last node of the first bucket added is linked to p, which is NULL at that moment; the end of the list is closed correctly.
  • Return. After three passes the list is sorted and its head pointer is returned.

20.9.5Analysis

Each pass does three jobs: RADIX buckets are emptied, n nodes are distributed, and RADIX buckets are collected. The number of passes is MAX_DIGIT. The total time is

O(MAX_DIGIT · (RADIX + n + RADIX)) = O(MAX_DIGIT · (RADIX + n))

If the number of digits is denoted d and the radix r, this is written O(d(n + r)). In the example it is O(3 · (10 + n)) and looks linear. But this is a special case, as in counting sort: the number of digits and the radix are taken to be constants. To tell n distinct numbers apart, at least logr n digits are needed. If the range of the keys grows with n, d grows too, and the time again approaches order n lg n.

For the algorithm to be usable, the data must be (a) non-negative, (b) integers, and (c) in a small range. If the range grows, the algorithm still sorts, but the number of passes and the complexity rise quickly. That it can sort only integers is a real disadvantage. It can be adapted to floating-point numbers, but by the time that adaptation is done, the other algorithms would long since have finished the job.

The extra memory is 2 · RADIX pointers: the front and back pointers of the buckets. The list is relinked in place. The link pointer in every node is also a memory cost, but this cost comes from the linked-list representation, not from the algorithm. Radix sort is stable and makes no comparisons.

Which algorithm to choose in which situation can be summarized as follows:

  • General-purpose, in-memory sorting. Quicksort with median-3 and insertion sort on small parts, or the library qsort.
  • Worst-case guarantee. Heap sort, which works in place, or introsort.
  • Stability, linked lists, or disk. Merge sort: it is stable, merges sorted pieces, and is the basis of external sorting.
  • Large records. Sort indices or links, not the records themselves; linked merge sort is an example.
  • Fixed-length integer keys. Radix sort: d passes, each O(n + r).
  • Keys in a small range. Counting sort.

20.11Common mistakes

  1. Forgetting the j == L test in the j loop of partition: if the pivot is the smallest, the scan runs off the start of the array.
  2. Always choosing a[R] as the pivot on sorted input: the depth becomes n and the time n². The remedy is median-3 or a random pivot.
  3. Pushing the parts without looking at their sizes in the non-recursive version: the stack grows to O(n) and the fixed-size array overflows.
  4. Giving the SWAP arguments in reverse in median-3: the larger item goes to a[L] and partitioning breaks.
  5. Calling malloc for b[] on every call (slow) or never allocating it (undefined behavior); forgetting the NULL check and free.
  6. Writing i1 instead of i2 in the else branch of the linked merge; relying on the order of evaluation of arguments.
  7. Using one-based formulas with a zero-based array in heapify.
  8. Writing return x - y; in a qsort comparator, or using an inconsistent comparator.
  9. Adding a node to the front of a bucket in radix sort: distribution becomes unstable and the result is wrong.

20.12Exercises and solutions

The answers are the same as those in the slides; here the solution steps are also given and the code was verified by running it.

1. For [5, 9, 1, 7, 3], what are the array and the return value after partition(a, 0, 4)?

Solution. The pivot is v = a[4] = 3. i stops at a[0] = 5 (5 ≥ 3). j passes 7 and stops at a[2] = 1 (1 ≤ 3). i = 0 < j = 2: swap, the array is [1, 9, 5, 7, 3]. Then i stops at a[1] = 9; j passes 9 and stops at a[0] = 1. i = 1 ≥ j = 0: crossed. The pivot is swapped with a[1]. The array is [1, 3, 5, 7, 9] and the return value is 1.

2. How many partition calls does quicksort (quicksort1) make on a sorted array of 8 items? What is the recursion depth?

Solution. The pivot is the largest item of the range every time and stays in place. Ranges of sizes 8, 7, …, 2 are partitioned: 7 partition calls. Because each partition is done inside the previous one, the number of nested, waiting frames that call partition is n − 1 = 7. The number of comparisons is 9 + 8 + … + 3 = 42.

3. How many merge calls does merge sort make for 16 items? What is the largest number of comparisons?

Solution. The frame tree has 16 leaves and 16 − 1 = 15 internal nodes: 15 merge calls. The merge in this note makes exactly one comparison per placement. At each of the lg 16 = 4 levels of the tree, 16 items in total are merged: 4 × 16 = 64 comparisons. The count is independent of the input; the instrumented run also gave 64.

4. For [4, 10, 3, 5, 1] (a[1..5]), what is the array after heap construction?

Solution. Start at ⌊5/2⌋ = 2. heapify(a, 2, 5): t = 10, children 5 and 1; 10 ≥ 5, no change. heapify(a, 1, 5): t = 4, children 10 and 3; 10 moves up. The hole descends to 2; children 5 and 1, 4 < 5: 5 moves up. The hole descends to 4; it has no children and 4 is written there. The result is [10, 5, 3, 4, 1].

5. What order does radix sort give after the units pass on the list 170, 45, 75, 90, 802, 24, 2, 66?

Solution. The units digits are 0, 5, 5, 0, 2, 4, 2, 6 in turn. The buckets: 0: 170, 090; 2: 802, 002; 4: 024; 5: 045, 075; 6: 066. Stable distribution and collection give 170 090 802 002 024 045 075 066. The next two passes produce the lists 802 002 024 045 066 170 075 090 and 002 024 045 066 075 090 170 802.

6. Why is heap sort not stable? Give a small example.

Solution. The array [2a, 2b, 1] is already a max-heap. In the first round the 2a at the root is moved to the end: [1, 2b, 2a]. heapify brings 2b to the root, and in the second round 2b goes to the second position. The result is [1, 2b, 2a] and the order of the equal keys has changed. Heap sort swaps items between distant positions; these distant swaps do not preserve the relative order of equal items.

20.13Summary

  • Quicksort. partition puts the pivot in its final place and splits the range in two. Best case n lg n, average ≈ 1.39 n lg n, worst case n² comparisons; in place, unstable. The pivot is the sentinel of i; j needs j == L.
  • Average case. The recurrence is brought to the form Cn/(n + 1) = Cn−1/n + 2/(n + 1) by the subtraction trick and solved with harmonic numbers.
  • Improvements. If the larger part is pushed first, at most ⌊lg n⌋ + 1 pairs wait on the explicit stack. Median-3 removes the n² on sorted input; small parts are left to insertion sort. Introsort brings the worst case down to O(n lg n) with heap sort.
  • qsort. It sorts any type with void * and a function pointer; the comparator must be consistent and must not overflow. There is no stability guarantee.
  • Merge sort. Θ(n lg n) in every case; 2n − 1 calls, n − 1 merges, O(n) extra memory. The linked version moves no records and changes only link indices.
  • Heap sort. Heap construction is O(n) with at most 2k − k − 1 ≤ 2n shifts, sorting is O(n lg n); extra memory O(1), unstable.
  • Radix sort. LSD to MSD with stable buckets, O(d(n + r)); for non-negative integers and a small range, without comparisons.

20.15Try It Yourself

  1. partition(a, 0, 7) is called on the array [2, 8, 7, 1, 3, 5, 6, 4]. What happens to the array, and what value is returned?

    Answer

    The pivot is 4. i stops at 8 and j at 3: swap, [2, 3, 7, 1, 8, 5, 6, 4]. Then i stops at 7 and j at 1: swap, [2, 3, 1, 7, 8, 5, 6, 4]. Then i stops at 7 (position 3) and j at 1 (position 2), and they cross. The pivot goes to position 3: [2, 3, 1, 4, 8, 5, 6, 7], return 3.

  2. How many partition calls does quicksort1 make on the reverse-sorted array [6, 5, 4, 3, 2, 1]? Why is this input also bad?

    Answer

    5 calls. Each pivot falls at one end of the range and each split separates only one item; the depth is n − 1 and the work is of order n².

  3. Compute C2 and C3 from the average-case recurrence.

    Answer

    C2 = 3 + (2/2)(C0 + C1) = 3. C3 = 4 + (2/3)(C0 + C1 + C2) = 4 + 2 = 6. The closed form also gives, for n = 3, 2 · 4 · H4 − 32/3 = 50/3 − 32/3 = 6.

  4. While quicksort2 sorts an array of 1000 items, at most how many (L, R) pairs can be on the stack at one time? Why is YMAX = 64 enough?

    Answer

    ⌊lg 1000⌋ + 1 = 10 pairs, that is 20 ints. Even for n < 231 the bound is 2 · 31 = 62 ints, which does not exceed 64. The condition for this is that the larger part is pushed first.

  5. With a = [2, 9, 4, 5], merge(a, b, 0, 1, 3) is called. What is b after copying? What does a become?

    Answer

    The left half is copied as is and the right half in reverse: b = [2, 9, 5, 4]. Merging yields the order 2, 4, 5, 9: a = [2, 4, 5, 9].

  6. For 8 items, how many mergesort calls, how many merge calls, and how many comparisons does merge sort make?

    Answer

    2n − 1 = 15 calls, n − 1 = 7 merges, and 8 · lg 8 = 24 comparisons.

  7. Bottom-up heap construction is applied to a[1..8] = [3, 1, 4, 1, 5, 9, 2, 6]. What is the result?

    Answer

    [9, 6, 4, 1, 5, 3, 2, 1]. heapify is called for 4, 3, 2, and 1, with 5 shifts in total.

  8. Radix sort is applied to the list 512, 037, 208, 099. What is the list after the tens pass?

    Answer

    The units pass gives 512 037 208 099 (2, 7, 8, 9). The tens pass, on the digits 1, 3, 0, 9, gives 208 512 037 099. After the hundreds pass the list is 037 099 208 512.

  9. How do you write a comparison function that does not overflow and sorts an int array from largest to smallest with qsort?

    Answer

    int descending(const void *p, const void *q) { int x = *(const int *)p, y = *(const int *)q; return (y > x) - (y < x); }. In ascending, x and y are swapped. If return y - x; were written, large differences would overflow.
