2.2.1Compiling and running

A program written in Java goes through several stages before a result appears on the screen. The programmer writes the code in a text file. The compiler checks this text and translates it into an intermediate code. The Java Virtual Machine takes the intermediate code and executes it on the computer’s processor. This section takes the stages in order. Reading error messages correctly, and knowing what happens behind the “Run” button, become possible only once this chain is familiar.

2.2.1.1The source file

Definition 2.2.1

Source code is the human-readable program text that a programmer writes according to the rules of a programming language. Java source code lives in plain text files, and these files have the extension .java.

Plain text is a file made up of characters only. It carries no information about typeface, color, bold type, or page layout. A document saved by a word processor such as Word stores this formatting information next to the text, and the compiler does not understand that extra information. Java code is therefore written in a text editor such as Notepad, Notepad++, or VS Code, or in a development environment.

Plain text is convenient for three reasons:

  • It is readable. A person who opens the file sees the code directly. The code is easy to understand, can be sent by e-mail, and can be kept in a version control system.
  • It is portable. The same .java file opens on every operating system and in every development environment.
  • It is easy to edit. Any text editor is enough to fix a bug or update the code.

Java also imposes a rule on file names. If a file contains a public class, the file’s name must be exactly the same as the class name. Code that begins with public class HelloWorld is saved in a file named HelloWorld.java. Uppercase and lowercase matter in this match too. If the same code is saved as helloworld.java, the compiler gives this message:

helloworld.java:1: error: class HelloWorld is public, should be declared in a file named HelloWorld.java
public class HelloWorld {
       ^
1 error

Although the Windows file system does not distinguish uppercase from lowercase, javac does. The message says exactly what is wrong: the class HelloWorld is public and must be declared in a file named HelloWorld.java.

2.2.1.3The first program: HelloWorld

The program below is one of the shortest complete programs that can be written in Java. It prints a single line to the screen.

public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}

Short as it is, every part of the program follows a rule:

  • public class HelloWorld defines a class. Every Java program contains at least one class. The body of the class is the part between the { on this line and the } on the last line. Because the class is public, the file must be named HelloWorld.java.
  • public static void main(String[] args) is the entry point of the program. When the JVM starts the program, it begins running from this method. The header must be written exactly this way. If Main or main(String args) is written, the program compiles, but the JVM cannot find the entry point and refuses to run it.
  • System.out.println(...) writes the value in parentheses to the console and moves to the next line. Text is written in double quotes: "Hello, World!".
  • The semicolon at the end of the line shows that the statement is over. Every statement ends with ;. Blocks closed by braces need no ; after them, which is why there is no semicolon after the closing brace of the class or of the method.

The body of the program consists of two nested blocks. The outer block is the body of the class and the inner block is the body of the main method. Indentation, that is, the spaces at the beginning of the lines, makes this nesting visible to the eye. The compiler does not look at indentation; it only counts braces.

2.2.1.4Basic syntax rules

Definition 2.2.2

Syntax is the set of writing rules of a language: it determines which words, symbols, and orderings are valid. Java code that breaks the syntax rules does not compile.

In English, the phrase “Book the read I” has an unusual order but can be understood. The compiler is not so tolerant. It does not correct a line that breaks the rules by guessing; it reports an error and stops. The basic writing rules of Java are:

  • Every statement ends with ;.
  • Blocks are opened with { and closed with }. Every block that is opened must be closed.
  • Java is case-sensitive: num and Num are two different names; system cannot be written in place of System.
  • Spaces, tabs, and line breaks are unimportant to the compiler. A statement can be split over several lines. Indentation is used for readability.
  • Comments are written in two forms: // runs to the end of the line, and /* … */ can span several lines. The compiler ignores comments.

The program below shows all of these rules together.

/* Multi-line comment:
   the compiler ignores it. */
public class Rules {
    // Single-line comment
    public static void main(String[] args) {
        int num = 5;  // ends with ;
        int Num = 7;  // num ≠ Num
        System.out.println(num
                + Num);   // a line can be split
    }
}

The program gives this output:

12

The first two lines form a multi-line comment and add nothing to the compiled code. num and Num are two separate variables because of the difference in case: one holds 5 and the other 7. The println call is split over two lines. For the compiler this split is unimportant, because a statement ends only when a ; is seen. The 12 in the output is the sum of the two variables. That two variables can sit side by side shows how important a single letter in a name can be. In real programs, such similar names cause confusion and should be avoided; the aim here is only to show the rule.

Common mistake

Mixing up uppercase and lowercase. The three lines below are typical mistakes caused by habits of writing everything in lowercase. The compiler gives a separate message for each:

Case.java:3: error: package system does not exist
        system.out.println("a");
              ^
Case.java:4: error: cannot find symbol
        string s = "b";
        ^
  symbol:   class string
  location: class Case
Case.java:5: error: cannot find symbol
        Int n = 3;
        ^
  symbol:   class Int
  location: class Case
3 errors

When system.out is written, the compiler takes system to be a package name and cannot find that package. string and Int look like class names that are not defined. The correct forms are System, String, and int. String starts with an uppercase letter because it is a class, and int with a lowercase letter because it is a keyword.

2.2.1.5Levels of abstraction

A processor understands only commands encoded as binary numbers. A person thinks more like “add a and b and store the result in sum.” On the way from person to processor there are three levels, and each level hides the details of the one below it.

  • A high-level language is close to the problem domain. Java, C, and Python are at this level. The code is short, readable, and understandable, and the programmer works more productively.
  • Assembly language writes processor instructions with short names such as MOV and ADD. Each line often corresponds to a single machine instruction. It is a lower level of abstraction.
  • The hardware representation consists only of bits. Instructions and data go directly to the hardware in this form.

Figure 2.2.1 shows the counterparts of the line sum = a + b at the three levels. The example assumes that the variables a, b, and sum live in the registers ebx, ecx, and eax respectively. In assembly language, the value of a is first copied into eax (mov eax, ebx), and then b is added on top of it (add eax, ecx). The machine code is the real encoding for x86 processors: the first instruction is the hexadecimal bytes 89 D8 and the second is 01 C8. As abstraction increases, the code gets shorter and more readable. The translation to the lower level is done by a compiler or an assembler.

Java adds an intermediate layer to this picture. The Java compiler does not translate source code directly to x86 machine code. It first translates it to a code called bytecode, which belongs to no real processor. This intermediate code allows the same compiled program to run on different processors.

2.2.1.6Compilation

Definition 2.2.3

Compilation is the translation of source code, as a whole, into another language. The program that does this is called a compiler. The Java compiler javac translates source code not into the machine language of a processor but into bytecode, which the Java Virtual Machine understands, and writes the result to a file with the extension .class.

A computer cannot run .java text directly. The text has to be compiled first. The path from source code to the output on the screen is completed in four steps:

  1. The programmer writes the source code as plain text and saves it as HelloWorld.java.
  2. The command javac HelloWorld.java runs the compiler. The compiler checks the syntax and the types. If there are no errors, the file HelloWorld.class is created in the same folder.
  3. The command java HelloWorld runs the launcher. The launcher starts the JVM and loads the class. The JVM interprets the bytecode and translates the frequently executed parts into machine code with the JIT compiler.
  4. The operating system and the processor carry out the actual instructions; Hello, World! appears on the screen.

In Figure 2.2.2 there are two separate commands and two separate periods of time. Compile time is the time during which javac runs; during it the program does not run yet, it is only checked and translated. Run time begins with the java command. It matters at which time an error appears. A compile-time error means the program never runs at all. A run-time error appears while the program is running; division by zero is an example.

The greatest benefit of the compilation stage is that errors are caught before the program runs. The compiler finds a missing semicolon, an unclosed parenthesis, a misspelled name, and incompatible types. If there is an error, no .class file is produced. The file name:line information in the message shows where the error is. If the semicolon on line 3 of the HelloWorld program is forgotten, the line becomes:

System.out.println("Hello, World!")

For this line the compiler gives this message:

HelloWorld.java:3: error: ';' expected
        System.out.println("Hello, World!")
                                           ^
1 error

The first line of the message gives the file (HelloWorld.java), the line number (3), and the kind of error (';' expected, that is, a semicolon was expected). The second line repeats the faulty code. The ^ mark on the third line shows where the compiler expected the semicolon: immediately to the right of the closing parenthesis. The last line reports the total number of errors. The compilation stage also contributes to the speed of the program. The compiler does jobs such as type checking once, so they need not be repeated while the program runs. The JVM’s optimizations at run time come on top of this.

Common mistake

Not looking before the line that the message points to. When a semicolon is missing, the compiler usually notices it only when it reads the next token, so the message sometimes points one line down. If a puzzling ';' expected message appears on a line, first look at the end of the previous line.

2.2.1.7Compiling and running from the command line

There are three basic steps in working with Java. In the compile step the .java file is turned into a .class file: javac HelloWorld.java. In the run step the java command is given the class name without an extension: java HelloWorld. The third step is the output: the program prints Hello, World! on the screen. A command-line session looks like this:

> javac HelloWorld.java
> dir /b
HelloWorld.class
HelloWorld.java
> java HelloWorld
Hello, World!

If javac printed nothing, the compilation succeeded. The dir /b command that follows (ls on Linux and macOS) lists the files in the folder. The list shows the newly created HelloWorld.class next to the source file. The last command runs the program.

Common mistake

Writing the extension when running: java HelloWorld.class. The JVM expects a class name, not a file name. This command looks for a class named HelloWorld.class and stops with the message “Could not find or load main class.” The correct form is without the extension: java HelloWorld.

Java 11 added a shortcut for single-file programs. The command java HelloWorld.java compiles the file in memory and runs it at once. No .class file is written to disk this way. The shortcut is practical for small experiments, but programs made of several files use the two-step route.

2.2.1.8Bytecode

Definition 2.2.4

Bytecode consists of the instructions, independent of processor and operating system, that javac produces and the Java Virtual Machine executes. .class files do not contain machine code that a processor can understand directly; they contain bytecode. Bytecode is the “machine language” of the JVM.

The name comes from the structure of the instructions: the opcode of each instruction is a single byte. Any extra information the instruction needs, such as a constant or the number of an entry in a table, sits in the bytes after the opcode. A one-byte opcode means at most 256 different instructions, and that is enough for the JVM.

Bytecode is not tied to a processor or an operating system. The same .class file runs on Windows, on Linux, and on macOS. An analogy describes the relationship well: bytecode is like a musical score that reads the same in every country, and the JVM on each computer is the musician who plays that score on its own instrument. The score does not change; the instrument and the musician do.

A .class file is a binary file and looks like meaningless characters in a text editor. The command javap -c ClassName in the JDK lists the bytecode instructions in this file in readable form. Consider this two-line code: int x = 5; System.out.println(x);. When the code is placed inside a main method and compiled with JDK 21, javap -c gives this listing:

0: iconst_5
1: istore_1
2: getstatic     #7    // System.out
5: iload_1
6: invokevirtual #13   // println(int)
9: return

The number at the beginning of each line is the instruction’s byte position within the method. The positions go 0, 1, 2, 5, 6, 9. iconst_5 and istore_1 are one-byte instructions. getstatic and invokevirtual carry a two-byte table number after the opcode, so each takes three bytes.

The JVM is a stack machine. Real processors keep values in registers. The JVM’s instructions push values onto an operand stack and take them from it. A stack is like plates piled on top of one another: the one put on last is taken first. The instructions do the following in order:

  1. iconst_5: the constant 5 is pushed onto the operand stack. Its counterpart in the source is the right-hand side of int x = 5;.
  2. istore_1: the value on top of the stack is taken and written to local variable number 1, that is, x. The stack is empty again.
  3. getstatic #7: a reference to the System.out object is pushed onto the stack. #7 is entry number 7 in the class file’s constant pool.
  4. iload_1: the value of x (5) is copied onto the stack. Its counterpart in the source is the line System.out.println(x);.
  5. invokevirtual #13: the method println(int) is called. The method takes two values from the stack: the object it is to work on (System.out) and the number to print (5). 5 is written to the screen.
  6. return: main ends, and the program terminates.

Figure 2.2.4 shows three moments. The difference between (b) and (c) matters: iload_1 copies the value from the local variable onto the stack. x stays where it is and its value does not change. Reading a variable does not consume it; this holds at the bytecode level too.

2.2.1.9An addition on the JVM stack

The stack-machine idea is clearer in an addition. Consider these three lines:

int a = 5;
int b = 7;
int sum = a + b;
System.out.println(sum);

The compiled form of these lines is twelve instructions. The comments give the source-code counterpart of each instruction:

iconst_5        // push 5
istore_1        // a = 5
bipush 7        // push 7
istore_2        // b = 7
iload_1         // load a
iload_2         // load b
iadd            // add
istore_3        // sum = 12
getstatic       // System.out
iload_3         // load sum
invokevirtual   // println(int)
return

The JVM uses no register to add. It pushes the two numbers onto the stack, the iadd instruction pops the top two values and adds them, and it pushes the result back onto the stack. Slot 0 of the local variable table holds main’s parameter args; the table shows it as “…”. a, b, and sum take slots 1, 2, and 3 respectively.

The letter i in the instruction names indicates the type int. There are separate instructions such as ladd for long and dadd for double. The JVM knows which type it is working with in every operation. This is one reason types are checked at compile time: the compiler decides which instruction to generate by looking at the type. The same bytecode runs in this order on the JVM of every operating system.

2.2.1.10The Java Virtual Machine and the JIT compiler

Definition 2.2.5

The Java Virtual Machine (JVM) is the software that runs Java applications. It interprets bytecode and executes it in a way suited to the processor it is on. It translates frequently executed pieces of bytecode into machine code at run time with the JIT (just-in-time) compiler.

The name “virtual machine” comes from the fact that the JVM behaves like a computer with its own instruction set. This computer does not exist as hardware; it runs as a program on top of the real computer. The internal structure of the JVM has four main parts:

  • The class loader finds the needed .class files and brings them into memory.
  • The verifier checks that the loaded bytecode follows the rules. For example, it makes sure that an instruction does not try to take a value that is not on the stack. A corrupted or malicious file therefore cannot crash the JVM.
  • The interpreter reads the bytecode instructions one by one and does the work corresponding to each.
  • The JIT compiler notices code fragments that run many times and translates them directly into machine code. In later runs this machine code is used instead of interpretation.

Interpretation is flexible but slow: every instruction is decoded again each time it is run. Machine code is fast, but producing it takes time. The JIT strikes a balance between the two. Code that runs once is interpreted; a loop body that runs thousands of times is compiled. A Java program therefore speeds up over time. This effect is noticeable in long-running server programs.

The java command that starts the program is called the Java launcher tool in the JDK documentation. The launcher starts the JVM, loads the class whose name is given, and calls the main method of that class. When main ends, the JVM shuts down too.

2.2.1.11Platform independence and the Java platform

Definition 2.2.6

A platform is the hardware or software environment in which a program runs: the combination of a processor and an operating system. Platform independence means that the same compiled program runs, without being recompiled, on every platform that has a JVM.

Platform independence is one of the fundamental features of Java and is known by the slogan “Write Once, Run Anywhere.” The program is compiled once, and the same bytecode runs on different operating systems. What makes this possible is that JVMs have been written separately for many operating systems and processors. A JVM written for Windows translates bytecode into x86 machine code. The JVM on a Mac with an ARM processor translates the same bytecode into ARM machine code. The difference is in the JVM, not in the bytecode.

In languages such as C the situation is different. A C compiler produces machine code directly, and this code is tied to the platform it was compiled on. A C program compiled on Windows does not run on Linux; a separate build is needed for every platform. In Java this burden passes to those who write the JVMs. The programmer distributes a single .class file, and it is enough for the user’s computer to have a JVM.

The Java platform has two main components:

  • The JVM runs applications and provides portability across different hardware.
  • The API (Application Programming Interface) consists of ready-made class libraries. It provides many functions out of the box, such as graphical interfaces, databases, network communication, and file operations, and speeds up development. System, String, Math, and Scanner are classes in these libraries.

Figure 2.2.8 shows that the layers are nested. The runtime environment (JRE, Java Runtime Environment) contains what is needed to run a Java program, namely the JVM and the API libraries. The JDK adds the compiler and the other development tools on top of these. To develop programs, the JDK is installed. Since Java 11, Oracle has not distributed the JRE as a separate package; the JDK contains everything.

2.2.2Variables and data types

A program takes in data, processes it, and produces a result. At every moment of this process the data has to be held somewhere. Variables do this job. Java wants to know in advance what kind of data each variable holds; this information is called the type. This section covers variables, Java’s eight primitive types, and the limits of each type.

2.2.2.1Basic programming elements

Every program, in whatever language it is written, is built from a few basic elements. Variables store data. Every variable has a type. Values are computed with expressions: num > 0 and sum + 1 are expressions. Control flow determines in what order and how the program runs. Control flow has two basic forms:

  • Branching runs different parts of the program depending on a condition. if-else is an example.
  • Loops repeat an operation. for and while are examples.

The following fragment brings together a variable, a condition, and output:

int num = 5;
if (num > 0) {
    System.out.println("Positive.");
} else {
    System.out.println("Zero or negative.");
}
Positive.

Because num is 5, the expression num > 0 is true and the first block runs. The else block is skipped. If num were 0 or negative, the first block would be skipped and the second would run. Here the value of the expression num > 0 is not a number but a piece of true-or-false information. Java uses a separate type for this information: boolean.

2.2.2.2Variables and declarations

Definition 2.2.7

A variable is a location in memory that stores a value and has a name and a type. Introducing a variable before it is used is called a declaration. In a declaration the type is written first, then the name, and the declaration ends with ;.

A variable can be pictured as a box with a name written on it. The label on the box carries two pieces of information: its name and what kind of thing may be put in it. Only an integer goes into a box labeled int, and only a floating-point number into a box labeled double. The value inside the box can change while the program runs; its name and type do not.

In Java every variable must be declared before it is used. Several variables of the same type can be declared on one line, separated by commas:

int id, checkCount, stockCount;
double amount, interestRate;
char answer;

The first line declares three int variables, the second two double variables, and the third one char variable. A declaration has three forms: type name;, type name1, name2, name3;, and type name = initialValue;. The last also gives the variable its first value together with the declaration.

Names should be chosen to be descriptive and meaningful. The name x says nothing about what the variable holds. checkCount, on the other hand, makes it clear at once that it holds the number of checks in an account. The person who rereads the code a few months later is often the person who wrote it. Meaningful names make that person’s job easier.

A variable’s life proceeds through three events: it is declared, it receives a value, and that value is updated. The code below contains all three events:

int age;

age = age + 1;
char letter = 'K';

2.2.2.4The eight primitive types

Definition 2.2.8

A data type determines which values a variable can take, how much memory it occupies, and which operations can be performed on it. Java’s eight basic types built into the language are called primitive types: byte, short, int, long, float, double, char, and boolean.

The eight types fall into four groups:

  • Integer: byte, short, int, long.
  • Floating-point: float, double.
  • Character: char.
  • Logical: boolean.

Each type has its own size in memory and a range of values that follows from it. As the number of bits grows, a type can hold larger numbers but takes more memory. In C the size of int can vary with the compiler and the processor. In Java, sizes are fixed by the definition of the language: int is 32 bits on every platform. This fixedness is part of platform independence too.

In everyday use, int is the default choice for integers and double for floating-point numbers. byte and short are mostly used in special cases, such as saving memory in large arrays or reading bytes from a file. float is rarely preferred outside graphics and some embedded systems.

2.2.2.6Floating-point types

Numbers with fractional parts are stored in a computer in floating-point form. This form is the binary-base counterpart of scientific notation. A number consists of a sign, an exponent, and a fraction: in the number 6.02 × 1023, 6.02 is the fraction and 23 is the exponent. The fraction holds the significant digits and the exponent determines where the point goes. The point “floats” according to the magnitude of the number; hence the name.

2.2.2.7char and boolean

char holds a single character. It occupies 2 bytes (16 bits) in memory and is unsigned: its range is 0 to 65,535. Each value is a Unicode character code. Unicode is an international standard that gives a number to the characters of the world’s writing systems. char literals are written in single quotes: 'A', 'ş', '7'. The difference between single and double quotes matters: 'A' is a char, while "A" is a String of one character.

Knowing the code of a character makes it possible to compute with characters. Three codes are used often: 'A' = 65, 'a' = 97, '0' = 48. The codes of the letters and digits of the English alphabet are the same as those in the ASCII table and are consecutive: 'B' = 66, 'C' = 67, '1' = 49. The code of the character '7' is not 7 but 55. The digit character and the numeric value of the digit are different things.

boolean holds a logical value. It has only two values: true and false. The information it carries is one bit; how many bytes it takes in memory is determined by the JVM. Unlike in C, a boolean in Java is not a number. boolean done = 0; does not compile, and if (1) cannot be written. boolean values are used in conditions and for the results of comparisons:

boolean passed = score >= 50;

In this line the result of the comparison score >= 50, that is, true or false, is written into the variable passed. If score is 72, passed becomes true.

2.2.2.9Overflow

Definition 2.2.9

Overflow occurs when the result of an operation does not fit in the range of values of its type. In Java, integer overflow raises no error: the value wraps around to the other end of the range.

Overflow is easy to picture with a clock. If the hand is at 12 and moves one hour forward, it goes to 1, not 13. Integer types behave the same way: adding 1 to the largest value returns to the smallest. What matters is that this happens silently. The program gives neither a compile-time error nor a run-time error; it carries on with the wrong result.

int max = Integer.MAX_VALUE;
System.out.println(max);
System.out.println(max + 1);   // overflow!
byte n1 = 80;
byte n2 = 50;
byte sum = (byte) (n1 + n2);
System.out.println(sum);        // not 130
long fixed = (long) max + 1;
System.out.println(fixed);

The lines run as follows:

  • max holds the largest value of int, 2,147,483,647, and this value is printed on the first line.
  • max + 1 is an addition between two int values, and its result is an int too. The result does not fit and wraps around to the smallest value: -2147483648.
  • n1 + n2 gives 80 + 50 = 130. 130 exceeds 127, the limit of byte. The (byte) cast takes the last 8 bits of the result, and the value becomes 130 − 256 = −126.
  • In the expression (long) max + 1 the cast is done before the addition. The operation proceeds in long; the 64-bit range holds 2,147,483,648 comfortably.

The fix is to use a wider type. But where the cast goes matters. The line long wrong = max + 1; still gives −2147483648. The right-hand side is computed between two int values and overflows first; only the overflowed result is assigned to the long variable. The conversion must be done before the operation: (long) max + 1 or max + 1L.

Example 2.2.1

What comes out if the square of one million is computed with int? With int million = 1_000_000;, the true value of million * million is 1012, which is far beyond the limit of about 2.1 billion for int. The result Java gives is -727379968. This value is the signed reading of the last 32 bits of the binary representation of 1012. When the same computation is written (long) million * million, the correct result, 1000000000000, is obtained. Here the negative result gives the overflow away. Not every overflow is this obvious; the result may be positive but wrong.

Let us follow step by step how overflow arises at the bit level, using a byte counter:

byte b = 125;
for (int i = 1; i <= 4; i++) {
    b++;
    System.out.println(b);
}

The cause of overflow is binary addition itself. The binary representation of 127 is 01111111. When 1 is added, all the 1s turn to zero and the carry moves into the leftmost bit: 10000000. 2.2.2.10Primitive types and reference types

Definition 2.2.10

A variable of a primitive type stores the value itself. A variable of a reference type points to an object: the variable holds not the object itself but its location in memory, that is, a reference to the object.

There are eight primitive types, and their names begin with a lowercase letter. All the remaining types are reference types. String (a sequence of characters), arrays, classes, interfaces, and enums are in this group. The names of reference types begin with an uppercase letter. Objects are usually created with new. String is a common exception to this rule: a string literal such as "Ali" creates an object even without new.

A reference that points to no object has the value null. null must not be confused with the empty string. The empty string "" is a real object and has length zero: "".length() gives 0. null means “there is no object here.” If a method is called on a null reference, the program stops with NullPointerException. For a local String variable three situations are distinct. Code that prints a variable to which no value has been assigned does not compile. A variable assigned null prints null. A variable assigned "" prints an empty line.

The difference between the two groups of types shows in assignment too. After the lines int a = 5; int b = a;, b holds a separate copy of 5; when b changes, a is not affected. Two reference variables, however, can point to the same object. This distinction is one of the fundamental topics of object-oriented programming.

2.2.3Identifiers and keywords

Each of the variables, methods, and classes in a program has a name. The programmer is free to choose these names, but the limits of that freedom are clear. Some characters cannot be used in names, and some words are reserved for the language. There are also writing habits that the Java community follows. This section takes up the three levels in turn: the compiler’s mandatory rules, reserved words, and conventions.

2.2.3.1Identifier rules

Definition 2.2.11

An identifier is the name given to variables, classes, methods, and other program elements.

Identifiers follow these rules:

  • They may contain only letters, digits (0–9), the underscore _, and the dollar sign $. Characters such as spaces, -, @, and . cannot appear.
  • The first character must be a letter, _, or $. An identifier cannot start with a digit.
  • Keywords and the literals true, false, and null cannot be identifiers.
  • There is no length limit.
  • Uppercase and lowercase are distinct: personName and personname are different variables. A name written differently from its declaration gives a cannot find symbol error.

There is a reason for the ban on starting with a digit. When the compiler sees a digit, it starts reading a number. Meeting 2count, the compiler first reads the number 2 and then treats the count that follows as a separate word. For the same reason first-last is read as “first minus last,” because - is the subtraction operator.

Java accepts as letters not only English letters but all Unicode letters. A variable named öğrenci (“student” in Turkish) compiles and runs. Even so, it is recommended to use only ASCII letters in names. When files are opened with a different character encoding, accented letters can be corrupted, and the code may stop compiling on other systems. That is why names are written studentNo and counter, not with accented letters. Valid examples: userName, totalScore, student_name, data1, _counter.

2.2.4Assignment, literals, and conversion

After variables are declared they receive values, and those values change. This section explains how a value is put into a variable, how values written directly in code are read, and how a value moves from one type to another. Type conversion is one of the topics that causes the most errors in beginning Java programs.

2.2.4.1Assignment statements

Definition 2.2.13

Assignment gives a value to a variable. It is written with the assignment operator =: variable = expression;. First the expression on the right is computed, and then the result is written into the variable on the left.

The expression on the right can be a constant value, another variable, or an operation:

int num, result;
int num1 = 4, num2 = 6;
String name;

num = 10;             // literal
result = num1 + num2; // sum: 10
name = "Ahmet";        // text
num = num * 2;       // 10 → 20

The first three lines are declarations. num1 and num2 receive values together with their declarations; num, result, and name are still empty. Then come four assignments, each with a different right-hand side. The first is a constant (10), and the second is the sum of two variables (4 + 6 = 10). The third is a piece of text ("Ahmet"), and the fourth is an operation that uses the variable’s own value. After the last line num is 20.

The = sign is not the equality of mathematics. In mathematics x = x + 1 is a contradictory equation; no number can equal one more than itself. In Java, x = x + 1 means “let the new value of x be one more than its old value.” Reading “gets” instead of “equals” prevents this misunderstanding: “x gets x + 1.”

Only a variable can appear on the left side of an assignment. The line 5 = num; does not compile:

Left.java:4: error: unexpected type
        5 = num;
        ^
  required: variable
  found:    value
1 error

The message says that a variable was expected on the left (required: variable) but a value was found (found: value). Types must also be compatible in an assignment. A number cannot be assigned to a String variable, nor text to an int variable. The lines int x = 3; String s = x; give the message incompatible types: int cannot be converted to String.

An assignment is also an expression and produces a value: the value assigned. That is why a = b = 0; can be written. Assignment groups from right to left; first b = 0 is done, and the value of that expression, 0, is assigned to a. Both variables are zeroed.

Compound assignment has two subtleties. First, the right-hand side is computed as a whole, and then the operation is performed. The expression k *= 2 + 3 means k = k * (2 + 3), not k = k * 2 + 3; if k is 7, the result is 35. Second, a compound assignment converts the result to the type of the variable on the left by itself. byte b = 10; b += 5; compiles and b becomes 15. But b = b + 5; does not compile, because b + 5 is an int. This convenience has a price: int m = 10; m /= 0.3; compiles without error and m becomes 33. 10 / 0.3 = 33.33… is computed, and then the fraction is silently discarded.

2.2.4.3Initial and default values

A variable can be declared without a value. An initial value can also be given together with the declaration: int age = 25;. This is called initialization. When the value is given depends on two different rules, according to where the variable is declared.

Local variables, that is, variables declared inside a method, receive no default value. A local variable that is read before a value has been assigned prevents the program from compiling:

The compiler examines every possible path through the program and sees that the point where count is read can be reached without a value. This check prevents a random memory content from being used silently. In C the same mistake compiles, and the program may print a different, meaningless number each time it runs.

2.2.4.5The precision of floating-point numbers

Floating-point numbers are stored with a limited number of bits in base two. In base ten, 1/3 = 0.333… goes on forever and cannot be written exactly with a finite number of digits. A similar situation exists in base two: 1/10 = 0.000110011…2 repeats forever. The innocent-looking 0.1 in base ten is therefore stored approximately in a computer. The exact value of 0.1 in a double is a number like 0.1000000000000000055511151231257827….

System.out.println(1.0 / 3.0);
System.out.println(1.0/3 + 1.0/3 + 1.0/3);
System.out.println(0.1 + 0.2);
System.out.println(0.1 + 0.2 == 0.3);
double t = 0.0;

The results read line by line as follows:

  • 1.0 / 3.0 is an approximate value and is printed with 16 digits.
  • The sum of three 1.0/3 values comes out exactly 1.0. Here the rounding errors happened to cancel each other. This is luck, not a rule.
  • The result of 0.1 + 0.2 is 0.30000000000000004. The small errors of the two numbers add up, and the result differs from the stored value of the constant 0.3. That is why 0.1 + 0.2 == 0.3 gives false.
  • Adding 0.1 ten times does not give exactly 1: 0.9999999999999999. Small errors accumulate with each addition.
  • On the last line the absolute value of the difference of the two numbers is compared with a very small bound, 10−9. The difference is about 5.55 × 10−17; because it is smaller than the bound, the result is true.

This behavior is not specific to Java. All modern processors store floating-point numbers according to the IEEE 754 standard, and C, Python, and JavaScript give the same results. Two rules follow. First, floating-point numbers are not compared with ==; instead one checks whether the difference is very small: Math.abs(a - b) < 1e-9. Second, double is not used in money calculations that must be correct to the last cent. There is the BigDecimal class for this; the sum of new BigDecimal("0.1") and new BigDecimal("0.2") is exactly 0.3. Another way is to keep amounts in cents as long integers.

Common mistake

Building a loop with a floating-point counter. The loop for (double t = 0; t != 1.0; t += 0.1) never ends. t never reaches exactly 1.0; after 0.9999999999999999 it jumps to 1.0999999999999999, and t != 1.0 stays true forever. The loop counter must be an integer; if a floating-point value is needed, it is computed from the counter: double t = i * 0.1;.

2.2.4.6Named constants

Definition 2.2.16

A named constant is a variable declared with final whose value cannot be changed once it has been given. The class-level pattern is: public static final Type CONSTANT_NAME = value;.

Numbers embedded in code with no stated meaning are called magic numbers. That the 7 in the line days = 4 * 7; is the number of days in a week can be guessed only from context. When the same line is written days = 4 * DAYS_PER_WEEK;, the meaning shows by itself. If the value changes, it is also updated in a single place. Constant names are written in uppercase, with words separated by underscores.

2.2.4.7Assignment compatibility

A value cannot always be assigned to a variable of another type. Java’s rule is simple: if the value fits without loss, the assignment is done automatically; if loss is possible, the programmer must ask for it explicitly.

Definition 2.2.17

A widening conversion moves a value to a type with a wider range and is done automatically. A narrowing conversion moves to a type with a narrower range; because a value may be lost, it requires an explicit cast.

Figure 2.2.19 shows the chain: byte → short → int → long → float → double. A value can be assigned directly to a variable of a type further to the right in the chain. An int value goes to long, and a long value to double, without trouble. char enters the chain at int: a char value can be assigned to an int and to the types to its right; the reverse does not compile.

char ch = 'A';
int n;

Compat.java:5: error: incompatible types:
  possible lossy conversion from int to char
        ch = n;

In the line n = ch; the code of 'A', 65, is written into the int variable. The assignment in the other direction is rejected. Even if it is known that n is 65 at that moment, the compiler looks at the type, not the value. An int variable may also hold a value that does not fit in a char, such as −5 or 100,000.

The chain has a subtlety. long is 64 bits and float is 32 bits; yet long → float is automatically allowed. The reason is that the range of float is much wider than that of long. But float is precise to only about 7 digits. In a very large number, the last digits are rounded. When the value long big = 123456789123L; is assigned to a float and read back, 123456790528 is obtained. The same applies to int → float: when 16,777,217 is assigned to a float, it becomes 16,777,216. Widening is safe in terms of range, but not always in terms of precision.

2.2.4.8Implicit and explicit conversion

Definition 2.2.18

Type conversion is turning a value into another type. A conversion Java does by itself is called an implicit conversion; one the programmer asks for by writing the target type in parentheses is called an explicit conversion (a cast): (int) d.

Java converts from a smaller type to a larger type by itself. For a conversion from a larger type to a smaller one, the target type is written in parentheses. With this mark the programmer tells the compiler that the possible loss is accepted. The loss appears in two ways:

  • When going from a floating-point number to an integer, the fractional part is discarded; the number is not rounded. (int) 3.99 gives 3 and (int) -3.99 gives −3. The fraction is truncated toward zero.
  • An integer that does not fit overflows. (byte) 130 takes the last 8 bits of the value and gives −126.

Example 2.2.2

The formula that converts Celsius to Fahrenheit is F = C × 9 / 5 + 32. With int c = 37;, what are the results of three different ways of writing it?

  • c * 9 / 5 + 32: everything is int. 37 × 9 = 333; 333 / 5 = 66 (fraction discarded); 66 + 32 = 98. The result is 0.6 too small.
  • 9 / 5 * c + 32: operations go from left to right. 9 / 5 = 1 (integer division); 1 × 37 = 37; 37 + 32 = 69. The result is almost 30 degrees off.

In mathematics these three forms are the same. In Java the order of the operations and the types of the operands change the result. How early the integer division happens determines the size of the loss.

Operators are symbols that perform operations on values. +, <, and && are operators; the values they work on are called operands. Java’s operators fall into four groups: arithmetic, comparison, logical, and assignment operators. When an expression contains more than one operator, the precedence rules determine which is applied first.

  • Splitting units: jobs such as splitting seconds into hours, minutes, and seconds are done with / and %.
Example 2.2.3

How many hours, minutes, and seconds are 3725 seconds? With int s = 3725;:

  • s / 3600 = 1. One hour is 3600 seconds, and it fits once in 3725.
  • s % 3600 / 60 = 125 / 60 = 2. First the 125 seconds left over after the hour are found, then the whole minutes in them are counted. % and / have equal precedence and are applied from left to right.
  • s % 60 = 5. These are the seconds left over after the whole minutes.

The result: 1 hour, 2 minutes, 5 seconds. Check: 1 × 3600 + 2 × 60 + 5 = 3725.

Java has no exponentiation operator. 2 ** 3 does not compile, and 2 ^ 3 compiles but does not raise to a power: ^ is the bitwise exclusive or, and it gives 1. For powers, Math.pow(2, 3) is used; the result is 8.0 of type double. The + operator has a second meaning too. If one of its operands is a String, it performs concatenation: the expression "Age: " + 20 gives the text Age: 20.

In integer division, if the divisor is 0 the program stops with ArithmeticException: / by zero. In floating-point division no exception occurs: 5.0 / 0 gives Infinity and 0.0 / 0 gives NaN (not a number). This difference too comes from the types of the operands.

When i++; is written alone as a statement, the value of the expression is not used and there is no difference between the two forms. The difference shows only when the expression is part of another operation.

Let us see step by step how precedence is applied to one expression: System.out.println(2 + 3 * 4 - 6 / 2);

  1. 2 + 3 * 4 - 6 / 2: * and / come before + and -. Of the two, the left one first: 3 * 4 = 12.
  2. 2 + 12 - 6 / 2: the remaining high-precedence operation is 6 / 2 = 3.
  3. 2 + 12 - 3: the remaining + and - have equal precedence and go from left to right: 2 + 12 = 14.
  4. 14 - 3 = 11.

The result is 11. Parentheses change the order: (2 + 3) * 4 - 6 / 2 = 5 × 4 − 3 = 20 − 3 = 17. A few more short examples: 20 / 4 * 2 is computed from the left and gives 5 × 2 = 10, not 20 / 8. In the expression -2 * -3 the unary minuses are applied first and the result is 6.

String concatenation obeys the same left-to-right rule and can therefore give surprising results. In the expression 1 + 2 + "3" + 4 + 5, first 1 + 2 = 3 is computed; there is no text yet. Then 3 + "3" becomes text: "33". Every + after that is concatenation: "334", "3345". The result is 3345.

The mathematical notation 0 < x < 10 does not work in Java. In the expression 0 < x < 10, first 0 < x is computed and a boolean results. Then this boolean is compared with 10, and the compiler reports an error. The correct way joins the two comparisons with logical AND: 0 < x && x < 10.

Common mistake

Confusing = with ==. = is assignment and == is comparison. When if (x = 5) is written, an assignment takes the place of the condition. The value of the assignment is 5, that is, an int. Because Java accepts only boolean as a condition, the code does not compile:

Eq.java:4: error: incompatible types: int cannot be converted to boolean
        if (x = 5) { }
              ^
1 error

In C the same line compiles and the condition is always taken to be true; the error stays hidden. Java’s strict type checking catches this mistake at compile time. There is one exception: boolean done; … if (done = true) compiles, because the value of the assignment is a boolean. With boolean variables the safest way to write is not to use a comparison at all: if (done) and if (!done).

Definition 2.2.23

Logical operators combine boolean values. AND &&: true if both conditions are true. OR ||: true if at least one is true. NOT !: reverses the value.

The last line turns a rule into code: a person who is 18 or older and holds a license may drive. Since both conditions are met, the result is true.

The ! operator has high precedence. If !x < y is written, ! is applied to x alone, and since an int value cannot be negated logically, the code does not compile. The negation of a comparison is therefore written with parentheses: !(x < y). The same expression can be written more simply as x >= y.

2.2.5.6Short-circuit evaluation

Definition 2.2.24

Short-circuit evaluation means that in the && and || operators the right-hand side is not evaluated at all once the result is already known from the left-hand side.

In &&, if the left side is false, the result is already false; whatever the right side is, it cannot change that. In this case Java does not evaluate the right side at all. In ||, if the left side is true, the result is already true and the right side is skipped again. In the expression day == 6 || day == 7, if day is 6 the second comparison is never made. This expression means “weekend.” Its negation !(day == 6 || day == 7) means “weekday.”

Short-circuiting does not only save time; it is also used to guard a dangerous operation. First the program checks “is the divisor nonzero?”, and only if so does it divide:

int divisor = 0;
int num = 10;
if (divisor != 0 && num / divisor > 1) {
    System.out.println("Ratio above 1");
} else {
    System.out.println("Can't divide or too small");
}
Can't divide or too small

divisor is 0. divisor != 0 comes out false and && never moves on to the right side. The division num / divisor is therefore not performed, and the program goes to the else block. Order matters. If the condition had been written num / divisor > 1 && divisor != 0, the division would have been done first. The program would have stopped with a division-by-zero error, the message java.lang.ArithmeticException: / by zero. The guarding condition is always written on the left.

Java has two more operators that do not short-circuit: the single & and the single |. When used with boolean values they always evaluate both sides. The expression a != 0 & 10 / a > 1 performs the division even when the left side is false for a = 0, and throws the exception. In conditions the two-character && and || are almost always used.

2.2.5.7The conditional operator

Definition 2.2.25

The conditional operator (also called the ternary operator) is a short expression that chooses one of two values according to a condition: if the condition is true the result is value1, otherwise value2. It is the only Java operator with three operands.

result = (condition) ? value1 : value2;

To decide whether a number is positive or negative:

int num = -5;
String result = (num > 0) ? "Positive" : "Negative";
System.out.println("Result: " + result);
Result: Negative

Because num is −5, num > 0 is false and the value after the colon, "Negative", is chosen. The if-else that does the same job is:

String result;
if (num > 0) {
    result = "Positive";
} else {
    result = "Negative";
}

The basic difference between the two forms is this: if-else is a statement and does a job, while ?: is an expression and produces a value. That is why ?: is used on the right of an assignment or inside a println. It cannot be written alone as a statement:

Tern.java:4: error: not a statement
        x > 0 ? System.out.println("a") : System.out.println("b");
              ^
1 error

The types of the two alternatives must be compatible. A few examples: double abs = (num < 0) ? -num : num; gives the absolute value, and for −4.5 the result is 4.5. int bigger = (a > b) ? a : b; chooses the larger of two numbers; for 8 and 13 the result is 13. If the alternatives are of different numeric types, the result is promoted to the wider one: the value of true ? 1 : 2.0 is 1.0, not 1.

Conditional operators can be nested. Whether a number is zero, positive, or negative can be found in one line:

int num = -5;
String result = (num == 0) ? "Zero" : (num > 0) ? "Positive" : "Negative";
System.out.println("Result: " + result);

Control statements govern the flow of a program. They provide branching on a condition and the repetition of a task. Their detailed use is a topic in itself. Here the writing rule of each and the most common syntax traps are given.

In the if statement the condition is always written in parentheses and must be boolean. If the body is a single statement, the braces may be left out, but this habit invites mistakes. Only the first statement is attached to an if without braces; a second line written below it with indentation runs regardless of the condition. The compiler does not look at indentation. It is therefore safe to use braces even when the body is one line.

In the switch statement the value being tested can be int (and byte, short), char, String, or enum. long, double, and boolean cannot be used; the compiler gives a message such as selector type double is not allowed. In the classic form, break is written at the end of each case. If break is forgotten, the cases after the matching one run in turn as well. This behavior is called fall-through. Fall-through is sometimes used deliberately: writing case "Sat": case "Sun": ties two cases to one piece of code. The header of the for loop consists of three parts separated by semicolons. The initialization part runs only once, on entering the loop. The condition is checked before every pass; if it is false the loop ends. The update runs at the end of every pass. Every for loop can also be written as a while loop: the initialization moves before the loop and the update to the end of the body.

The difference between while and do-while is where the condition is. while checks the condition first; if the condition is false from the start, the body never runs. do-while runs the body first and checks the condition afterwards; the body runs at least once. The semicolon at the end of do-while is required, and if it is forgotten a ';' expected error results.

break leaves the nearest enclosing loop or switch at once. continue skips only the rest of that pass and moves to the next one. In a for loop the update part still runs after continue. If a switch is inside a loop, a break inside the switch leaves only the switch; the loop continues.

Example 2.2.4

The sum of the numbers from 1 to 100 that are not multiples of 3 can be found with continue as follows:

int sum = 0;
for (int i = 1; i <= 100; i++) {
    if (i % 3 == 0) continue;   // skip multiples of 3
    sum += i;
}

For an i that is a multiple of 3, continue runs, sum += i is skipped, and the loop goes on with i++. Check: the sum of the numbers from 1 to 100 is 5050. The multiples of 3 are 3, 6, …, 99; there are 33 of them and their sum is 3 × (1 + 2 + … + 33) = 3 × 561 = 1683. The result is 5050 − 1683 = 3367.

Common mistake

An infinite loop. A loop with no step that makes the condition false never ends. In the loop for (int i = 1; i <= 10; i--), as i decreases the condition stays true. In int i = 1; while (i <= 3) { System.out.println(i); }, i is never updated in the body and 1 is printed on the screen endlessly. Whenever a loop is written, the question to ask is: “at which step will the condition become false?”

2.2.8Summary

  • Compiling: javac Name.java checks the source code and writes it as bytecode to Name.class. java Name starts the JVM, loads the class, and calls main. The same bytecode runs on every platform that has a JVM.
  • The JVM is a stack machine: instructions push values onto the operand stack and take them from it. The interpreter runs the bytecode, and the JIT compiler turns frequently executed code into machine code.
  • Syntax: statements end with ;, blocks are opened and closed with { }, and Java is case-sensitive. Comments are written with // and /* */.
  • Primitive types: byte 1, short 2, int 4, long 8 bytes; float 4, double 8 bytes; char 2 bytes; boolean. An integer that exceeds the limit overflows without error and wraps to the other end of the range.
  • Floating-point numbers are stored approximately in binary: 0.1 + 0.2 is not 0.3. Floating-point numbers are not compared with ==.
  • Names contain letters, digits, _, and $; they do not start with a digit; they cannot be keywords. Classes are written in PascalCase, variables in camelCase, and constants in UPPER_CASE.
  • Assignment: the right-hand side is computed first. Compound assignments such as += do the conversion themselves. A local variable must be given a value before it is read. A final variable receives a value once.
  • Conversion: the direction byte → short → int → long → float → double is automatic. The reverse is done with (type); the fraction is discarded and a value that does not fit overflows. int / int is integer division, and the cast must be done before the division.
  • Operators: the order of precedence is unary > * / % > + - > comparison > && > || > ?: > assignment. && and || short-circuit. ?: is an expression that produces a value.
  • Flow: if/else, switch (+ break), for, while (0 or more passes), do-while (at least 1 pass). break exits, continue skips the rest of the pass.

2.2.10Test Yourself

  1. A file named Demo.java defines public class Test. The file is to be compiled with javac Demo.java. What happens? How can the program be made to run?

    Answer

    The compilation fails: class Test is public, should be declared in a file named Test.java. The name of a public class must be exactly the same as the file name. Save the file as Test.java, compile it with javac Test.java, and run it with java Test (without the extension).

  2. When the lines int a = 5, b = 7; int c = a * b; are compiled, which values are on the JVM’s operand stack while a * b is computed? What is left on the stack right after the imul instruction?

    Answer

    First iload_1 pushes 5 and then iload_2 pushes 7; the stack holds 5, 7 from bottom to top. imul pops these two values, multiplies them, and pushes the result: only 35 remains on the stack. Then istore_3 writes 35 into c and the stack is empty. The same pattern holds as for iadd in the addition.

  3. Why does the following line give a wrong result? How is the correct value obtained?
    long microseconds = 24 * 60 * 60 * 1000 * 1000;

    Answer

    All the constants are int and the multiplication is done in int. The true result is 86,400,000,000, which exceeds the int limit; the overflowed value is 500654080. Only this overflowed value is assigned to the long variable. When L is added to the first constant, the multiplication runs in long from the start: 24L * 60 * 60 * 1000 * 1000 = 86400000000.

  4. What is b after the lines byte b = 120; b += 10;? What would happen if the same thing were written b = b + 10;?

    Answer

    b becomes −126. 130 exceeds the byte limit of 127; the compound assignment converts the result to byte itself, and 130 − 256 = −126 remains. b = b + 10;, on the other hand, does not compile: b + 10 is an int expression and can be assigned to a byte only with (byte) (possible lossy conversion from int to byte).

  5. Which of these names are valid identifiers? _2x, x-2, int, Integer, total$, 9th

    Answer

    Valid: _2x (starts with an underscore), Integer (the name of a class, not a keyword; but using it as a name would surprise the reader), total$ ($ is allowed). Invalid: x-2 (- is the subtraction operator), int (a keyword), 9th (starts with a digit).

  6. With char c = '5';, what do System.out.println(c + 1); and System.out.println(c - '0' + 1); print?

    Answer

    The first line prints 54: the code of '5' is 53, and c + 1 is an int sum. The second line prints 6: c - '0' = 53 − 48 = 5, that is, the numeric value of the digit; 1 is added to it.

  7. After the lines int x = 7; int y = x-- - --x;, what are x and y?

    Answer

    The operands are evaluated from left to right. x-- gives the old value, 7, and x becomes 6. --x first makes x 5 and gives 5. y = 7 − 5 = 2, and x = 5.

  8. With int a = 0;, what is the difference between the conditions if (a != 0 & 10 / a > 1) and if (a != 0 && 10 / a > 1)?

    Answer

    The single & does not short-circuit and evaluates both sides. Even though the left side is false, the division 10 / a is performed and the program stops with ArithmeticException: / by zero. &&, by contrast, never looks at the right side once the left side is false; the condition counts as false and the program continues safely.

  9. What is k at the end of the two loops below, each starting with int k = 3;?
    do { k -= 4; } while (k > 5);
    while (k > 5) { k -= 4; } (again starting with k = 3)

    Answer

    do-while runs the body once: k becomes −1, -1 > 5 is false, and the loop ends; the result is −1. while checks the condition first: because 3 > 5 is false, the body never runs; the result is 3.
