Chapter 3.2: Methods

As a program grows, it no longer fits inside a single main method. The same calculation is needed in several places, and bugs get lost in a long pile of code. The method is the answer to both problems: write a job once, give it a name, and call it as often as you like. In Java every function lives inside a class and is called a method. These notes show how a method is defined and called, what happens in memory during a call, and why arguments are copied. They also cover how the compiler chooses between methods with the same name, the built-in Java methods, and the scope and lifetime of variables. The last sections discuss how to design a good method. Every program in the examples was compiled and run with JDK 21; the values in the trace tables and the compiler messages come from those runs.

3.2.1The function concept

So far every program has consisted of a single method: main. For short programs that is enough. But consider a student grade system. Grades are read, the average is computed, a letter grade is found, and the results are printed. If all of these steps are written one after another inside main, the result is one block of several hundred lines. If the average formula is needed in three places, it gets copied three times, and when the formula turns out to be wrong, all three copies must be fixed separately. Methods remove this mess.

3.2.1.1What is a function?

Definition 3.2.1

A function is a named piece of code that does one job and can be used again and again. It is defined by the parameters it takes and the type of the value it returns. In Java every function is written inside a class and is called a method.

A function is like a recipe. “Brew tea” is a recipe: it is written once and followed as often as needed. The ingredients are the inputs of the recipe; their counterpart in programming is the parameters. The tea that comes out is the result of the recipe; its counterpart is the return value. Whoever follows the recipe does not rethink every step; they just say “brew tea” and get the result. A program does the same: it calls a method by name and uses its result.

A function is not really a new idea. main, which every Java program has, is a method. System.out.println(...), used to print text, is a call to a method that comes with the Java library. The programmer does not know how println sends characters to the screen; they only know what it does. These notes show how to build the same structure with your own methods.

The benefits of using methods can be listed as follows:

  • Readability. A well-named method call says in one line what is being done. Someone reading computeAverage(grades) understands what happens without looking at the details of the loop.
  • Less duplicated code. The same job is written once and called whenever it is needed. When a bug appears, only one place has to be fixed.
  • Modularity. The program is split into small, manageable pieces. Each piece can be written and tested separately.
  • Structure. The links between the pieces are limited to parameters and return values. When the inside of one piece changes, the others are not affected.

In these notes the words “function” and “method” are mostly used interchangeably. The distinction is this: a function is the general programming concept, and a method is its form in Java. In languages such as C, functions can be written without belonging to any class. In Java, a method cannot be written outside a class.

3.2.1.2Input, process, output

Every function can be thought of in three stages. In the input stage the function is given data; these data are the parameters, and they determine what the function works on. In the process stage the statements in the body of the function work on the input. In the output stage a result is produced and handed back to the caller with the return statement. Figure 3.2.1 shows the three stages for the add function.

This diagram is the same as the function concept in mathematics. In the function f(x) = x², x is the input, squaring is the process, and x² is the output. When f(3) is written, 3 is put in place of x and the result is 9. A function in programming works the same way: it takes the input, computes, and gives the result.

Functions in programming differ from those in mathematics in two ways. First, some functions have no input. A function that prints a fixed greeting needs no data at all. Second, some functions return no value; their job is to leave an effect, such as writing to the screen. Java marks this case with the keyword void. In English “void” means “empty”: the method gives nothing back.

3.2.2Defining and calling methods

There are two separate steps in using a method. First the method is defined: its name, inputs, result type and body are written down. A definition on its own runs nothing; it only records the recipe. Then the method is called: control moves to the method, the body runs, and control returns to the place where the call was made. A method is defined once but can be called as many times as needed.

3.2.2.1Parts of a method header

A method definition has two parts: the header and the body. Figure 3.2.2 shows the parts of the add method, which adds two numbers, one by one.

Other modifiers can appear between the access modifier and the return type. The one seen most often in these notes is static, which says the method can be called without an object. The order in a header is fixed: modifiers first, then the return type, then the name, and finally the parameter list. The access modifier may be omitted; the method can then be called only from classes in the same package. The return type, however, can never be left out.

Java's naming convention is camelCase: the first word starts with a lowercase letter and the first letter of each following word is capitalized. computeAverage, isPrime and readGrades follow this rule. Because a method does something, its name states an action. For methods that return boolean, the name often reads like a question: isPrime(17) answers the question “is 17 prime?”.

Definition 3.2.2

The method signature is the name of the method together with the sequence of its parameter types. The signature of add is add(int, int). The return type, the parameter names and the access modifier are not part of the signature.

The signature matters in two places. First, the compiler looks at the signature to decide which method a call refers to. Second, a class cannot contain two methods with the same signature. This rule decides when methods with the same name can be written side by side.

The compiler catches most mistakes made when writing a header. Three typical examples and the messages JDK 21 gives for them follow. In the first, the type of the second parameter has been forgotten. 3.2.2.2Call, parameter and argument

To run a method you have defined, you write its name followed by its inputs in parentheses. The following program defines the add method and calls it from main.

public class AddExample {
    public static int add(int num1, int num2) {
        int result = num1 + num2;
        return result;
    }

    public static void main(String[] args) {
        int result = add(5, 3);
        System.out.println("Sum: " + result);
    }
}
Sum: 8
Definition 3.2.3

A method call runs a method with arguments. A parameter is the variable in the method definition that stands for an input. An argument is the actual value given to the parameter at the time of the call.

In the program, the expression add(5, 3) is a call. The 5 and 3 in the call are arguments; num1 and num2 in the definition are parameters. An easy way to remember the difference: a parameter is written in the definition and has a name, while an argument is written in the call and has a value. At the moment of the call the values of the arguments are copied into the parameters in order: num1 = 5, num2 = 3.

When the call is made, control goes to the method. The body runs, result becomes 8, and return result; gives this value back. Control returns to the place where the call was made. The expression add(5, 3) now has the value 8, and this value is assigned to the variable result in main. The println on the last line is also a method call; its argument is the expression "Sum: " + result, and Sum: 8 is printed.

Arguments must agree with the parameters in three respects: number, order and type. If a method with two parameters is given a single argument, the compiler rejects the call and prints the expected types next to the supplied ones:

    static int add(int num1, int num2) { return num1 + num2; }
    public static void main(String[] args) {
        int s = add(5);
    }
}

In the message, the line required: int,int shows the types the method expects, and found: int shows what the call supplied. The reason line says that the problem is the number of arguments. A type mismatch is also an error. In the call add(5, 2.5), 2.5 is a double, which does not fit into an int parameter without losing information:

The conversion in the opposite direction is allowed. An int argument can be given to a method with a double parameter; the value is automatically widened to double. This rule also determines the compiler's choice in overloading.

An argument does not have to be a constant number; it can be a variable or any expression. In the call square(a + 1), Java first evaluates the expression a + 1. If a is 3, the value of the argument is 4, and this 4 is copied into the parameter. The method sees neither the variable a nor the expression a + 1; it receives only the value 4. This rule is the basis of the topic of copying arguments.

3.2.2.3Tracing a call step by step

To understand what happens in memory when a method is called, two concepts are needed: the stack frame and the call stack.

Definition 3.2.4

A stack frame is the memory record that holds the parameters and local variables of one method call. The call stack is the structure that keeps the frames of the running methods on top of one another. Each call pushes a new frame onto the top of the stack; when the method finishes, its frame is removed from the stack.

A stack is like a pile of plates. The last plate put down is on top and is the first one taken. On the call stack, too, the frame of the most recently called method is on top. The running method always owns the topmost frame. When that method finishes, its frame is removed and the method below it continues where it left off.

In the first step the stack contains only the frame of main. A program always starts at the main method; args is the array that holds the command-line arguments, and here it is empty. In the second step add(5, 3) is called. A new frame is opened on top of the stack, and the arguments are copied into the parameters in this frame.

In the third step the body runs: result = 5 + 3 = 8. This result is a local variable of add and lives in the frame of add. Figure 3.2.3 shows this moment. The frame of main also has a variable named result, but its value is not yet known. The two variables have the same name, yet they are separate variables living in different frames.

In the fourth step return result; runs. The value 8 is sent to the caller, the method ends, and its frame is removed from the stack. Together with the removed frame, num1, num2 and the result of add disappear. In the fifth step control returns to line 7, where the call was made; the returned 8 is assigned to the variable result of main. In the sixth step println is called and Sum: 8 is printed. println is a method too; for the short time it runs, a frame for it is pushed onto the stack and popped again.

The lesson of this trace is that a method call is control temporarily going somewhere else and coming back. A new workspace is opened at the destination, and when the job is done this workspace is cleaned up. Only the value sent with return remains.

3.2.2.4Methods that return a value and methods that do not

The following program contains three methods that differ in their input and output.

        System.out.println("Hello, World!");

This time add returns the result directly without an intermediate variable: return num1 + num2;. Java first evaluates the expression and then returns the value. The two ways of writing it, with and without the intermediate variable, give the same result.

The call square(1.5) returns 1.5 × 1.5 = 2.25, and 2.25 is printed. Java writes decimal numbers with a point, both in code and in println output. The method helloWorld has neither a parameter nor a return value. The parentheses are still written: helloWorld() in the definition and helloWorld(); in the call. Writing helloWorld; without parentheses is a compile error, because Java does not recognize a name as a method call unless it sees parentheses.

The real difference between the two kinds of method is in how the call is used. A call to a method that returns a value is an expression; it has a value. This value can be assigned to a variable, used in another calculation, or passed as an argument to another method: in println(add(2, 7)) the result of add becomes the argument of println. A call to a void method has no value. It can be written only as a statement on its own.

A method that returns a value can also be called on its own: add(2, 7); is a valid statement. But because the returned value is not assigned anywhere, it is lost. The compiler gives no warning in this case. That is why, in most complaints of the form “I called the method but the result did not change”, the returned value was never assigned to a variable.

3.2.3return and void

The return statement gives the result of a method to the caller. Its rules are simple, but it is one of the places where beginners argue most with the compiler. This section explains how return works, when the type of the returned value is accepted, and how the compiler checks the rule “every path must end in a return”.

3.2.3.1The return statement

Definition 3.2.5

The return value is the value the method gives to the caller with return. The return type is the type of this value; it is written in the header before the method name. If the method returns no value, the return type is void.

The statement return expression; has two effects. First, the value of the expression is computed and handed to the caller. Second, the method ends immediately. Lines after return do not run. This property is used to leave a method early.

A void method returns no value, but it can still end early. For that, a bare return; is written. The following program checks the divisor before dividing. If the divisor is zero, it prints a warning and leaves the method at once.

public class EarlyReturn {
    static void printQuotient(int dividend, int divisor) {
        if (divisor == 0) {
            System.out.println("Cannot divide by zero!");
            return;                      // leave the method at once
        }
        System.out.println(dividend / divisor);
    }
    public static void main(String[] args) {
        printQuotient(10, 2);
        printQuotient(7, 0);
    }
}
5
Cannot divide by zero!

In the first call divisor is 2. The if condition is false, its body is skipped, and the result of 10 / 2, which is 5, is printed. In the second call divisor is 0. The condition is true; the warning is printed and return; ends the method. The line println(dividend / divisor) is never reached. Had it been reached, the integer division would have tried to divide by zero and the program would have stopped with ArithmeticException: / by zero.

The same method could have been written with else. The advantage of the early-return pattern is that it filters out the bad cases at the start of the method and leaves the real work unindented. As the number of conditions to check grows, this style is more readable than nested ifs.

Writing a statement right after return in the same block is a compile error. The compiler sees that this statement cannot be reached by any path and reports unreachable statement:

        return n * 2;

3.2.3.2Matching the return type

The type of the value that return returns must be compatible with the return type declared in the header. The compatibility rule is the same as for assignment: a value can be returned if it can be assigned to a variable of the return type. So an int value can be returned from a method with return type double; the value is widened automatically. The opposite means a loss of information, and the compiler does not accept it:

public class Narrowing {
    static int half(double x) { return x / 2; }
}
Narrowing.java:2: error: incompatible types: possible lossy conversion from double to int

Because widening is free, a trap arises that compiles but gives a wrong result. Both of the following methods return double, but their results differ.

public class Widening {
    // the int result is widened to the double return type
    static double half(int n) {
        return n / 2;
    }
    static double halfFixed(int n) {
        return n / 2.0;
    }

        System.out.println(half(7));
        System.out.println(halfFixed(7));

In other words, the return type decides not how the expression is evaluated, but which type the computed result is converted to. For the correct result the division itself must be made floating-point: the expression n / 2.0 gives 3.5.

3.2.3.3Every path must end in a return

In a method that returns a value, every path that control can follow must end in a return. If control can reach the closing brace at the end of the method without passing through any return, the compiler says missing return statement. The most surprising form of the error appears in chains of conditions that look complete to a human:

public class MissingReturn {
    static int sign(int n) {
        if (n > 0) return 1;
        if (n <= 0) return -1;
    }
}
MissingReturn.java:5: error: missing return statement
    }
    ^
1 error

To a human, the conditions n > 0 and n <= 0 cover all integers; one of the two is certainly true. The compiler, however, does not reason about the values of conditions. It looks only at the structure: there are two ifs, and both are treated as if they could be false. Control can then reach the end of the method, and there is no return there. The same error appears with an if/else if chain; as long as the last branch is an else if, the compiler assumes the chain can be left somewhere.

The fix is to turn the last condition into a plain else, or to put a default return at the end of the method:

static int sign(int n) {
    if (n > 0) return 1;
    return -1;          // every case with n <= 0 ends up here
}

void methods have no such requirement. When control reaches the end of the method, the method ends by itself; writing return; at the end is unnecessary.

3.2.4static methods and calls through an object

Every method so far had the word static in its header. This word determines how the method is called. Without going into the details of objects, it is enough for now to tell the two forms of call apart.

Definition 3.2.6

A static method belongs to the class, not to an object. No object is needed to call it. It is called by its name from inside the same class, and from another class in the form ClassName.method(). A method that is not static is called through an object: object.method().

The most familiar example of a static method is the Math class. To take a square root, no Math object is created; you simply write Math.sqrt(16). Inside the same class there is no need to write the class name:

static int add(int num1, int num2) {
    return num1 + num2;
}
// inside main, directly:
int result = add(5, 3);

To call a method that is not static, you first create an object of that class with new, and then call the method through the object:

public class Calculator {
    int add(int num1, int num2) {
        return num1 + num2;

3.2.5Pass by value

Can a method change a variable that is given to it as an argument? The answer is one of the most misunderstood points in Java. The short answer is no. The method receives a copy of the argument, not the argument itself. But for arrays and objects the thing that is copied is a reference, so the situation looks different at first sight. This section follows the two cases separately.

Definition 3.2.7

Pass by value means that at the time of the call the value of the argument is copied and given to the parameter. Java passes all arguments by value. If the argument is an array or an object, the value that is copied is the reference that points to the location of that array or object.

3.2.5.1A primitive argument

In the following program both main and increase have a variable named num. increase adds 10 to its own num.

static void increase(int num) {
  num = num + 10;
  System.out.println("increase: " + num);
}

public static void main(String[] args) {
  int num = 5;
  increase(num);
  System.out.println("main: " + num);
}

3.2.5.2An array argument: a copy of the reference

With methods that take an array parameter the situation looks different. First you need to know where an array lives in memory. In Java, memory is divided into two regions. Frames and local variables live on the stack. Arrays and objects are kept in a separate region called the heap. An array variable holds not the array itself but a reference to the location of the array on the heap.

The following method takes an array and an int. It tries to change the array and the integer, and then assigns a brand new array to its parameter.

static void modify(int[] d, int x) {
    d[0] = 50;
    x = 50;
    d = new int[2];
    d[1] = 50;
}

public static void main(String[] args) {
    int[] a = {1, 2};
    int x = 1;
    modify(a, x);
    System.out.println(a[0] + " " + a[1] + " " + x);
}

The program prints 50 2 1: the first element of the array has changed, the second has not, and x has not changed at all. In the eighth step the method ends and its frame is removed. The only reference to array B was d; now no variable points to B. Such an array can never be reached from the program again. The JVM's garbage collector reclaims the memory of such objects when the time comes. In the ninth step a[0], a[1] and x are printed: 50 2 1.

The rule that follows from this example is the following. Java passes everything by value; a reference is also a value that is copied. A method can change the array that the reference it received points to, because the array is shared. But assigning a new array to the parameter does not change the caller's variable, because the parameter is only a copy. Some sources write that Java passes objects “by reference”. This statement is wrong: with true pass by reference, the line d = new int[2] would have changed a in main as well.

3.2.5.3The swap trap

The best-known consequence of pass by value is that a method that exchanges the values of two variables cannot be written in Java. In the following program there are two versions of the swap method. The first takes two ints; the second takes an array and two indices.

import java.util.Arrays;

public class Swap {
    static void swap(int x, int y) {
        int tmp = x;
        x = y;
        y = tmp;
    }
    static void swap(int[] d, int i, int j) {
        int tmp = d[i];
        d[i] = d[j];
        d[j] = tmp;
    }
    public static void main(String[] args) {
        int[] arr = {4, 7, 9};
        swap(arr[0], arr[2]);
        System.out.println(Arrays.toString(arr));
        swap(arr, 0, 2);
        System.out.println(Arrays.toString(arr));
    }
}
[4, 7, 9]
[9, 7, 4]

The first call is swap(arr[0], arr[2]). The arguments are the values of the expressions arr[0] and arr[2], that is, 4 and 9. The method swaps these two copies inside itself: x becomes 9 and y becomes 4. When the method ends, the copies are removed and the array stays unchanged: [4, 7, 9].

The second call takes the array and the indices. This time the method writes to the cells of the array that the reference points to: d[0] becomes 9 and d[2] becomes 4. Because the array is shared, the change is visible from main: [9, 7, 4]. Arrays.toString is a built-in method that prints an array in square brackets.

The behavior of pass by value can also be followed step by step in the Pass-by-Value Lab simulator. The simulator draws the passing of a primitive value, an array, and an object separately on the call stack and the heap.

3.2.6Method overloading

Sometimes the same job has to be done with inputs of different types or in different numbers. Consider methods that add two integers, two floating-point numbers and three integers. It is possible to give each a separate name: sumTwoInts, sumTwoDoubles, sumThreeInts. But such names make use harder; the programmer has to remember the right name every time. Java allows the same name to be used for several methods.

3.2.6.1Same name, different parameter list

Definition 3.2.8

Method overloading means defining several methods with the same name in the same class. The parameter lists of the methods must differ: in the number, the types or the order of the parameters. In other words, overloaded methods have different signatures.

public class Overloading {
    static int sum(int a, int b) {
        return a + b;
    }
    static double sum(double a, double b) {
        return a + b;
    }
    static int sum(int a, int b, int c) {
        return a + b + c;
    }

    public static void main(String[] args) {
        System.out.println(sum(2, 3));
        System.out.println(sum(2.5, 1.2));
        System.out.println(sum(1, 2, 3));
    }
}

The class has three sum methods. Their signatures are sum(int, int), sum(double, double) and sum(int, int, int); all three differ from each other. The call sum(2, 3) carries two int arguments and runs the first method: 5. sum(2.5, 1.2) carries two doubles and runs the second: 3.7. sum(1, 2, 3) carries three arguments and runs the third: 6. The different appearance of 5 and 3.7 in the output also gives away the method chosen: the result of the method that returns int is printed without a decimal point.

It is the compiler that decides which method will run. The decision is made before the program runs, at compile time, and only by looking at the types of the arguments. In the compiled program every call is already bound to a specific method.

The Java library uses overloading heavily. println is not a single method: println(int), println(double), println(String), println(char), println(boolean) and the parameterless println() are defined separately. The programmer sees them all as a single name and uses the same name whatever type is printed. Math.abs and Math.max are also overloaded separately for int, long, float and double.

The criterion for overloading is the signature, and the return type is not part of the signature. For this reason two methods that differ only in their return type cannot exist in the same class:

3.2.6.2Which version does the compiler choose?

When the types of the arguments are exactly the same as the parameters, the choice is easy. The hard part is what happens when there is no exact match. In that case the compiler looks for methods that fit by widening the arguments. The widening conversions in Java follow this order:

byte → short → int → long → float → double  and  char → int

A type can automatically widen to every type that comes after it in this chain. Narrowing conversions in the opposite direction are never made automatically. The choice can be thought of in three steps:

  1. Methods whose number of parameters differs from the number of arguments are eliminated.
  2. Of the remaining methods, those in which each argument either has the same type or fits by widening are considered applicable.
  3. If several methods are applicable, the compiler chooses the most specific one. A method is more specific if all its parameter types can widen to the parameter types of the other. The (int, int) version is more specific than (double, double), because int widens to double.

3.2.7Methods calling methods

Methods are not called only from main; a method can also call another method. This is how a large task is split into small pieces. Each piece does its own job and hands its result to a higher level.

3.2.7.1Methods that call each other

In the following program, the sumOfSquares method, which finds the sum of the squares of two numbers, does not do the work itself. It has square do the squaring and sum do the adding.

public class Nested {
    public static int square(int num) {
        return num * num;
    }
    public static int sum(int num1, int num2) {
        return num1 + num2;
    }
    public static int sumOfSquares(int num1, int num2) {
        return sum(square(num1), square(num2));
    }
    public static void main(String[] args) {
        int result = sumOfSquares(3, 4);
        System.out.println(result);
    }
}
25

The result of the call sumOfSquares(3, 4) is 3² + 4² = 9 + 16 = 25. The key line of the code is return sum(square(num1), square(num2));. In this line the arguments of one call are other calls. Java evaluates such an expression from the inside out. Before sum can be called, the values of its two arguments must be known; so square(num1) runs first, then square(num2). When both results are ready, sum(9, 16) is called.

The order in which arguments are evaluated is precisely defined in Java: left to right. This rule matters when one of the arguments prints something or changes a variable. In the following program the value method both returns a value and prints its own name, so the order of the calls shows up in the output.

public class Order {
    static int value(String name, int v) {
        System.out.print(name + " ");
        return v;
    }
    static int diff(int a, int b) {
        return a - b;
    }
    public static void main(String[] args) {
        int s = diff(value("left", 10), value("right", 3));
        System.out.println("→ " + s);
    }
}
left right → 7

First left and then right is printed. Then diff(10, 3) runs and returns 7. Some languages, such as C, do not specify this order and leave it to the compiler. Java guarantees the order.

Having methods call each other makes the program readable and manageable. The body of sumOfSquares says in one line what it does: the sum of two squares. square and sum can be tested separately. If square works wrongly, the bug is fixed in one place and all the methods that use it are fixed.

3.2.9Scope

A variable cannot be used everywhere in a program. Where it is defined determines where it can be seen and how long it lives. These rules let methods work independently of each other: variable names inside one method do not get mixed up with names in other methods.

3.2.9.2Scope rules and nested blocks

Definition 3.2.10

The scope of a variable is the region of the program in which its name is valid. In Java the scope of a local variable begins at the line where it is declared and ends at the end of the braced block in which it is declared.

Scope determines two things: where the variable can be accessed and how long it will live. In Java, blocks can be nested. The body of the class is the outermost block. The methods are inside it. Inside the methods there can in turn be if blocks, loops, or blocks written as plain braces. Figure 3.2.9 shows these layers.

The rule is one-way: an inner scope sees the variables of the outer scope; an outer scope cannot see the variables inside. In the following program the inner block reaches the variables of both the method and the class.

public class InnerScope {
    static int globalVar = 10; // global (class field)
    static void method() {
        int outerVar = 10;       // local scope
        {
            int innerVar = 5;

            System.out.println(outerVar + innerVar
                    + globalVar);

        // innerVar does NOT exist here
    }
    public static void main(String[] args) {
        method();

After the closing brace of the block, innerVar no longer exists. If innerVar is used there, the compiler says cannot find symbol.

What programming languages call a “global variable”, one that is accessible everywhere and lives for the whole program, corresponds in Java to static fields. 3.2.10Abstraction and design

Getting a method to compile and run correctly is half the job. The other half is designing the method well: how much work it does, which inputs it takes, and what it is called. Well-designed methods get reused in other programs, are easy to test, and can still be understood years later. This section covers the ideas that design rests on, namely abstraction, generalization and decomposition, followed by practical principles.

3.2.10.1Abstraction and the black box

Definition 3.2.12

Abstraction means hiding the details and showing only the important features in order to reduce complexity.

Abstraction is everywhere in daily life. To drive a car you do not need to know what is inside the engine. The steering wheel, the pedals and the gear lever are an interface through which the driver talks to the car. Even if the engine changes, for example when an electric motor replaces a petrol engine, the driver uses the same steering wheel and the same pedals.

Methods are a kind of abstraction as well. In Figure 3.2.12 Math.sqrt is drawn as a black box. The user gives the box 16 and gets 4.0. How the square root is computed inside the box is hidden and does not concern the user.

Abstraction has two benefits. First, it makes the program understandable. A large program is split into pieces that can each be thought about separately; whoever uses a piece does not have to know its inside. Second, it makes change easier. When the inside of a method changes, the code that uses it is not affected as long as what the method does stays the same.

This kind of abstraction over computations is called functional abstraction or procedural abstraction. The basic idea is that what a function computes matters more than how it computes it. The user knows only the signature and the purpose of the method:

// The user knows only the signature:
static boolean isPrime(int num)
// "returns true if num is prime"
if (isPrime(17)) { ... }

All a programmer who writes the call isPrime(17) needs to know is that the method returns, as a boolean, whether a number is prime. Does the method divide the number by every number starting from 2, or does it try only up to the square root? This question is irrelevant to the user of the method. If a faster algorithm is written tomorrow, only the body of isPrime changes; the line if (isPrime(17)) stays exactly as it is.

The simplest example is again System.out.println("Hello"). This method writes the given text to the console. Details such as which encoding the characters are sent in, or which operating system call is used, are hidden from the programmer. Without abstraction, one would need to know all these details just to print a single line to the screen.

For abstraction to work, the purpose of the method must be clear. Since the user will not look at the body, the name, parameters and return type of the method must tell fully what it does. The header isPrime(int num) does this. The header doStuff2(int a), on the other hand, tells nothing; the user has to read the body, and the abstraction collapses.

3.2.10.2Generalization

The meaning of a piece of code depends on its surroundings. The value of a number is related to the other terms in an equation, and the meaning of a word to its place in a sentence. In code, too, what a statement does depends on which variables hold which values in the block it is in. These surroundings are called the context.

Definition 3.2.13

Generalization means making a solution that belongs to one context usable in other contexts too. In code the tool of generalization is the parameter: constant values embedded in the solution are turned into parameters.

        drawLine();

The embedded number 10 has become the parameter length, and the embedded character '-' has become the parameter ch. Generalization has a limit. Turning every constant into a parameter makes the method unusable. Calling a method with ten parameters can be harder than doing the job by hand. Generalization is limited to the values that are really expected to change.

3.2.10.3Decomposition

Definition 3.2.14

Decomposition means splitting a large problem into small, independent subproblems. In programming each subproblem becomes a method.

Consider a program that reads three grades of a student and prints the average and the letter grade. The problem splits into three subtasks: reading the grades, computing the average, and finding the letter grade from the average. Figure 3.2.14 shows this structure.

In the following program all four methods are written out in full. The thresholds in letterGrade are chosen according to a common letter-grade table; a different table requires changing only this method.

import java.util.Scanner;

public class GradeProgram {
    // readGrades and letterGrade are separate methods too
    static int[] readGrades(Scanner in, int n) {
        int[] grades = new int[n];
        for (int i = 0; i < n; i++) {
            grades[i] = in.nextInt();
        }
        return grades;
    }
    static double computeAverage(int[] grades) {
        int sum = 0;
        for (int n : grades) {
            sum += n;
        }
        return (double) sum / grades.length;
    }
    static String letterGrade(double avg) {
        if (avg >= 90) return "AA";
        if (avg >= 85) return "BA";
        if (avg >= 80) return "BB";
        if (avg >= 75) return "CB";
        if (avg >= 70) return "CC";
        if (avg >= 60) return "DC";
        if (avg >= 50) return "DD";
        return "FF";
    }
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int[] grades = readGrades(in, 3);
        double avg = computeAverage(grades);
        System.out.println("Average: " + avg + " -> " + letterGrade(avg));
    }
}

Average: 81.66666666666667 -> BB
Average: 52.333333333333336 -> DD

Each method does a single job. readGrades takes the Scanner object and the number of grades to read as parameters, and returns the grades it read as an array. The Scanner object is created once in main and passed to the method; this way the reading method does not have to know where the input comes from. computeAverage takes the array and returns the average. The explicit cast in the expression (double) sum / grades.length prevents integer division. 80 + 90 + 75 = 245; 245 / 3 would be 81 with integer division and 81.666… with floating-point division. letterGrade looks at the average and returns a String. The early-return pattern here takes the place of an else if chain: the conditions are tried from top to bottom, and the method ends at the first one that holds.

main now reads like a table of contents: read, compute, print. What is done is visible in main; how it is done is in the submethods. When a bug appears, it is also clear which method to look at. If the average is wrong, look at computeAverage; if the letter grade is wrong, look at letterGrade.

Another benefit of decomposition is that the methods can be tested separately. letterGrade can be tested without touching the keyboard at all: letterGrade(85) should return “BA” and letterGrade(84.99) should return “BB”. If reading and computing had been written intertwined, every test would require typing grades at the keyboard.

3.2.10.4When to write a method: the DRY principle

The clearest sign that a piece of code should be a method is repetition. The name of this principle is DRY (Don't Repeat Yourself). The moment you feel the need to copy and paste code, that code is a candidate to become a method.

Repetition is not the only criterion. A piece of code that is used only once can also deserve to be a method. There are two reasons: the piece does a meaningful job on its own, or gathering it under a name makes the calling code readable. letterGrade in the grade program is called only once, but being a separate method simplifies main and makes testing easier.

3.2.10.5Designing good methods

The properties of a good method can be gathered into six principles.

Single responsibility
Each method does only one job. If the task of a method is described with the word “and” (read and compute and print), the method should be split.
Descriptive name
The name of a method is a verb that tells what it does: computeAverage, isPrime, readGrades. Names such as doStuff2 say nothing.
Parameters
A method takes the data it needs through parameters; it does not secretly depend on outside variables. A small number of parameters improves readability.
Return value
The result is returned explicitly with return. A method that computes does not print; printing is done by the caller.
Short and focused
Methods of a few lines that fit on one screen are easy to understand and easy to test.
Called where needed
A method is called only where it is needed. Computing the same result again and again in a loop is wasted work; the result is computed once and kept in a variable.

The principle “a method that computes does not print” is the one most often broken. The design that first comes to a student's mind is usually this:

static void computeAndPrintAverage(int a, int b, int c) {
    System.out.println((a + b + c) / 3.0);
}

This method can only print the average to the screen. Code that wants to test whether the average is greater than 50, save the average to a file, or include it in the class average cannot use it; the result has stayed on the screen. A better design is to return the average and let the caller decide what to do:

static double average(int a, int b, int c) {
    return (a + b + c) / 3.0;
}
// the caller decides:
System.out.println(average(70, 80, 90));
if (average(40, 50, 45) < 50) System.out.println("failed");

The principle “do not secretly depend on outside variables” rests on the same reasoning. A method that reads its values from class fields depends on the current values of the fields. To understand what the method will return, you have to know where in the rest of the program the fields are changed. The result of a method that takes parameters, on the other hand, depends only on its arguments; with the same arguments it gives the same result every time.

3.2.10.6Naming

Choosing good names applies not only to methods but also to variables. Each variable should represent one thing. Using the same variable first for an age and then for a total confuses the reader and leads to logic errors. The name of a variable should tell what kind of data it holds.

int studentCount;      // a good name
int a;                  // a meaningless name
int age = 25;
String name = "Ahmet";
double average = 85.5;
String bookTitle;

Meaningless or single-letter names reduce readability. There are two exceptions: conventional names such as i and j as loop counters, and x and y in mathematical formulas. Table 3.2.14 compares a few bad names with better ones.

3.2.11Worked problems

The following problems use method calls, pass by value and overloading together. All solutions were run with Java.

Example 3.2.1

What does the following program print? Why does a not change? How many frames are on the stack at most while cube(2) is running?

static int f(int x) {
    x = x * 2;
    return x + 1;
}
public static void main(String[] args) {
    int a = 3;
    int b = f(a);
    System.out.println(a + " " + b);
    System.out.println(f(f(1)));
}
static int square(int n) { return n * n; }
static int cube(int n) { return n * square(n); }
// inside main:
System.out.println(cube(2) + square(3));
3 7
7
17

In the call f(a), the value of a, that is 3, is copied into the parameter x of f. x = x * 2 makes the copy 6, and x + 1, that is 7, is returned. b becomes 7. a does not change, because f changed only its copy: the first line is 3 7.

In the expression f(f(1)) the inner call runs first: f(1) = 1 × 2 + 1 = 3. The outer call runs with this value: f(3) = 3 × 2 + 1 = 7. The second line is 7.

In the expression cube(2) + square(3), cube(2) computes 2 * square(2). square(2) returns 4 and cube(2) becomes 8. Then square(3) = 9 is computed. The total is 8 + 9 = 17. While cube(2) runs, the deepest moment is when square(2) is running: there are 3 frames on the stack, main, cube(2) and square(2). When square(3) is called, the frame of cube has long been closed; at that moment there are only 2 frames on the stack.

Example 3.2.2

Which sum method do the first two println calls invoke? Why does the last line print 8.0 and not 8?

static int sum(int a, int b) { return a + b; }
static double sum(double a, double b) { return a + b; }
// inside main:
System.out.println(sum(2, 3.0));
System.out.println(sum(2, 3));
System.out.println(Math.max(Math.abs(-8), Math.sqrt(49)));
5.0
5
8.0

The arguments of the call sum(2, 3.0) are (int, double). The (int, int) version does not fit, because 3.0 cannot be narrowed to int. The (double, double) version fits: the value 2 is widened to 2.0. The result is 5.0. In the call sum(2, 3) both versions are applicable; the most specific, (int, int), is chosen and 5 is printed. On the last line, because Math.sqrt returns double, the (double, double) version of Math.max is chosen. The larger of 8 and 7.0 is 8.0.

Example 3.2.3

Let us write the following methods: isEven, which returns whether a number is even; largest, which finds the largest of three numbers with Math.max; power, which raises to a power without Math.pow; digitSum, which finds the sum of the digits; circleArea, which returns the area of a circle; and area, overloaded for a circle and a rectangle.

public class Exercises {
    static boolean isEven(int num) {
        return num % 2 == 0;
    }
    static int largest(int a, int b, int c) {
        return Math.max(a, Math.max(b, c));
    }
    static int power(int base, int exp) {
        int result = 1;
        for (int i = 0; i < exp; i++) result *= base;
        return result;
    }
    static int digitSum(int n) {
        int t = 0;
        while (n != 0) { t += n % 10; n /= 10; }
        return t;
    }
    static double circleArea(double r) {
        return Math.PI * r * r;
    }
    static double area(double r) {
        return Math.PI * r * r;
    }
    static double area(double width, double height) {
        return width * height;

    public static void main(String[] args) {
        System.out.println(isEven(7) + " " + isEven(10) + " " + isEven(-4));

        System.out.println(power(2, 10) + " " + power(5, 0));
        System.out.println(digitSum(2024) + " " + digitSum(-2024));

3.2.12Common mistakes

The compiler catches some mistakes with methods and points out their location in its message. Others produce programs that compile but give unexpected results. The second group is more dangerous, because the program runs wrongly without any warning.

Common mistake

Calling a non-static method from main. Message: non-static method add(int,int) cannot be referenced from a static context. Either static is added to the header of the method, or an object is created and the method is called through it.

Common mistake

Forgetting return on some paths. Message: missing return statement. The compiler does not reason about the values of conditions; a chain if (n > 0) ... if (n <= 0) ... gives an error even though it looks complete to a human. The last branch becomes a plain else, or a default return is put at the end of the method.

Common mistake

Using the result of a void method. The line int x = sayHello(); gives incompatible types: void cannot be converted to int, and println(sayHello()) gives 'void' type not allowed here. A void method produces no value; its call can only be a statement on its own.

Common mistake

Missing or extra arguments. Message: method add in class ... cannot be applied to given types; below it the lines required: int,int and found: int show the expected and the supplied types. The number, order and types of the arguments must match the signature.

Common mistake

Using a local variable outside its method. Message: cannot find symbol ... variable result. A local variable disappears when the method ends; its value is returned with return and the caller assigns it to its own variable.

Common mistake

The same name as an outer local variable in an inner block. Message: variable outerVar is already defined in method method(). The same rule applies to parameters. A local variable having the same name as a field, on the other hand, is allowed; then shadowing occurs.

Common mistake

Expecting a swap method to work. swap(int x, int y) swaps only copies; after the call swap(arr[0], arr[2]) the array stays the same. To swap array cells, the method takes the array and the indices: swap(int[] d, int i, int j).

Common mistake

Expecting an argument to change. After the call increase(num), num stays the same; what changed is the copy in the method. The new value is returned with return and assigned: num = increase(num);. The compiler gives no warning when the returned value is not assigned.

Common mistake

Overloading by return type. int f(int a) and double f(int a) cannot coexist: method f(int) is already defined. Only the name and the parameter types determine the signature; the return type and the parameter names are not part of it.

Common mistake

Forgetting the type of a Math result. The line int k = Math.sqrt(16); gives the message possible lossy conversion from double to int. sqrt and pow always return double; if an integer is needed, the (int) cast is written.

Common mistake

Expecting the return type to change the calculation. The method static double half(int n) { return n / 2; } returns 3.0 for 7. The division is done between two ints and the fraction is discarded; the double return type merely widens the result. The correct form is n / 2.0.

Common mistake

Printing inside a method that computes. The result of a method such as computeAndPrintAverage stays on the screen; it cannot be used in another calculation. The method returns the result, and the caller does the printing.

3.2.13Summary

  • A function is a named piece of code that does one job and can be reused. In Java it is always written inside a class and is called a method. The input comes in through parameters, and the output comes back with return.
  • Method header: access [static] returnType name(parameters). Each parameter carries its own type. The signature is the name plus the sequence of parameter types; the return type is not part of it. Methods cannot be defined inside one another.
  • A parameter is the variable in the definition, and an argument is the value in the call. Arguments are evaluated first (left to right) and then copied into the parameters. The number, order and types must match.
  • Every call opens a new frame on the call stack; the frame holds the parameters and local variables. When the method returns, the frame is removed. The depth of the stack equals the longest chain of nested calls.
  • return gives the value and ends the method at once; a statement after it cannot be reached. In a method that returns a value, every path must end in a return; the compiler does not reason about the values of conditions. A void method returns no value and can exit early with a bare return;.
  • The returned value can widen to the return type (int → double) but cannot narrow. The return type does not change how an expression is evaluated.
  • A static method belongs to the class; it is called directly or with ClassName.method(). A method that is not static is called through an object: object.method().
  • Java passes arguments by value. Even if the copy of a primitive argument changes, the caller's variable does not. With an array argument the reference is copied: the method can change the shared array, but assigning a new array to the parameter does not affect the caller.
  • Overloading: same name, different parameter list. The compiler makes the choice at compile time by looking at the argument types. An exact match is looked for first; if there is none, widening is tried (byte → short → int → long → float → double, char → int). If several versions are applicable, the most specific is chosen; if there is no most specific version, the call is ambiguous.
  • System.out.println adds a line break, print does not, and printf prints with formatting and uses the locale for the decimal separator. + concatenation works from left to right.
  • Math methods are static. sqrt and pow always return double, abs/max/min return the type of the argument, and round(double) returns long. Packages other than java.lang need an import.
  • A local variable lives in the block where it is defined and must be given a value before use. An inner scope sees the outside, and an outer scope cannot see the inside. An inner block cannot use the same name as an outer local; a local variable, however, shadows a field of the same name. static fields live for the whole program.
  • Design: abstraction (what it does matters, how it does it is hidden), generalization (constants become parameters), decomposition (each subtask becomes a method), DRY (repeated code goes into a method), single responsibility, descriptive names, returning the result and leaving the printing to the caller.

3.2.15Test Yourself

  1. The methods static int a(int n) { return b(n + 1) * 2; }, static int b(int n) { return c(n) + n; } and static int c(int n) { return n * n; } are given. If a(2) is called from main, what is returned? What is the greatest number of frames on the stack at the same time?

    Answer

    a(2) calls b(3). b(3) calls c(3), and c(3) returns 9. b(3) returns 9 + 3 = 12. a(2) returns 12 × 2 = 24. While c(3) runs, there are 4 frames on the stack, main, a, b and c; this is the deepest moment.

  2. The method static int change(int[] d, int k) { d[k] = d[k] + k; k = 0; return d[k]; } is called in main with int[] d = {3, 4, 5}; int k = 2; int r = change(d, k);. What are d, k and r after the call?

    Answer

    The method's d is a copy of the reference to the array in main; its k is a copy of 2. d[2] = 5 + 2 = 7 changes the shared array. k = 0 changes only the copy. return d[0] returns 3. Result: the array is {3, 4, 7}, k in main is still 2, and r = 3.

  3. A class has the methods m(long x), m(double x) and m(int x, int y); each returns its own parameter types as a string. After the declarations short s = 7; char ch = 'x';, which versions do m(s), m(ch), m(3.0f) and m(2, 'b') call?

    Answer

    In the calls with one argument, the version with two parameters is eliminated because of the count. short can widen to both long and double; long is more specific: m(s) → long. char widens first to int and from there to long; again long is chosen: m(ch) → long. float widens only to double: double. In m(2, 'b'), 'b' widens to int: int,int. JDK 21 output: long long double int,int.

  4. A class has the field static int count = 0; and the method static int increment(int count) { count++; TryIt.count += 2; return count; }. After the line int t = increment(5);, what are t and the class field count?

    Answer

    The parameter count shadows the field. count++ makes the parameter 6; the field is not affected. TryIt.count += 2 reaches the field through the class name and makes it 2. The method returns the parameter: t = 6. The field is 2.

  5. What does the method static double ratio(int a, int b) { return a / b; } return for ratio(7, 2) and ratio(1, 3)? How is the method fixed?

    Answer

    a / b is an integer division between two ints. 7 / 2 = 3 and 1 / 3 = 0; on the way out they are widened to double: 3.0 and 0.0. The return type does not change the calculation. Fix: return (double) a / b;. The results are then 3.5 and 0.333….

  6. Which of the following pairs of methods can exist together in the same class? (a) void g(int x) and int g(int y); (b) int h(int a, double b) and int h(double a, int b); (c) int k(int a) and int k(int a, int b).

    Answer

    (a) cannot: both signatures are g(int); the return type and the parameter name are not part of the signature. (b) can exist together, because the order of the parameter types differs. But a call such as h(1, 1) gives the error reference to h is ambiguous; the compiler cannot choose one of the two versions. (c) can exist together: the numbers of parameters differ.

  7. A method is written like this: static String status(int points) { if (points >= 50) return "pass"; else if (points < 50) return "fail"; }. Does it compile? If not, what is the smallest fix?

    Answer

    It does not compile: missing return statement. Although the two conditions cover every integer, the compiler does not evaluate the values of conditions; because the last branch of the chain is an else if, it assumes that control can reach the end of the method. The smallest fix is to write a plain else instead of else if (points < 50).

  8. What do the lines System.out.println("Result: " + 2 + 3); and System.out.println(2 + 3 + " result"); print? What does System.out.printf("%.1f%n", 2.25); print on a computer set to Turkish?

    Answer

    + works from left to right. In the first line "Result: " + 2 first becomes a string, and then 3 is appended: Result: 23. In the second line 2 + 3 is first added as numbers: 5 result. Because printf uses the locale, the decimal separator is a comma and the number is rounded to one digit: 2,3.

  9. You want to split the job “read a student's grades from the keyboard, compute the average, and print ‘pass’ if it is greater than 50” into methods instead of a single main. Which methods, with which parameters and return types, could be written?

    Answer

    One possible design: int[] readGrades(Scanner in, int n) reads and returns the array; double average(int[] grades) computes and returns; boolean hasPassed(double avg) decides. The printing stays in main. Each method does a single job, takes its data through parameters and returns its result. average and hasPassed can be tested without touching the keyboard.
