Chapter 4.1: Objects and Classes

The programs so far consisted of static methods and the variables passed to them. The data lived in one place and the code that processed it in another. Object-oriented programming brings the two together: a student's name, number and grade average live in the same unit as the methods that work on them. The blueprint for such a unit is a class; each concrete instance produced from the blueprint is an object. These notes show step by step how a class is written, what happens in memory when an object is created with new, and why a variable holds a reference to an object rather than the object itself. Instance and static members, initialization order, this and constructor chaining, the difference between == and equals, wrapper classes, records, enum and inner classes are also covered. The notes end by designing a fraction class from scratch. All programs were compiled and run with JDK 21; the outputs, the final values in the trace tables and the compiler messages come from those runs.

4.1.1Object-oriented programming

Imagine writing a student information system with static methods. Each student's name is kept in one array, the number in a second array and the grade average in a third. Methods such as computeAverage, registerCourse and printTranscript take these arrays as parameters. As the program grows, problems appear. Because the arrays are separate, only the index links the name of student 5 to the average of student 5. If one array is sorted and the other forgotten, names end up paired with other students' grades. Adding a new piece of information to a student, say the department, means a fourth array and new parameters to carry it. Every method that touches these arrays has to change.

Object-oriented programming answers this scattering with a different organization. All the information about a student is gathered in a single unit. The code that works on this information is written inside the same unit. The program is built from such units asking one another to do work.

Definition 4.1.1

Object-oriented programming (OOP) is a programming approach that builds a program from interacting objects. Each object carries its own data and offers operations that work on that data. Objects cooperate by calling one another's methods.

4.1.1.1Object: state and behavior

Every clearly distinguishable entity in the real world can be modeled as an object. A student, a desk, a circle, a button on the screen, even a loan taken from a bank is an object. Each of these objects has two things. The first is the object's state: the data it holds at that moment. A student's name, number and department make up the student's state. The second is the object's behavior: the things the object can do. A student can enroll in a course and view the grades. Table 4.1.1 puts the state and behavior of five objects side by side.

Table 4.1.1: Objects from the real world. State is represented by fields, behavior by methods.

In a programming language the counterparts of state and behavior are clear. The pieces of data an object stores are called fields, and the things it can do are called methods. Objects get work done by calling one another's methods. In a school program, student, teacher and course objects "send messages" to one another in this way. A teacher object calls the enterGrade method of a course object; the course object then updates the student's record. Sending a message means calling an object's method in Java.

The upper part of the box contains the fields name, id and dept with their values, and the lower part contains the methods greet(), addCourse(name, grade) and average(). The average() method takes no array parameter; the grades it needs are already inside the object. This togetherness of data and code makes the program better organized. The code becomes reusable, and because it resembles its real-world counterpart it is easier to understand.

4.1.1.2Procedural and object-oriented approaches

The programs so far were written in the procedural style. In this style the basic unit is the function. Data sits in separate variables and is passed as a parameter to every function that wants it. In the object-oriented style the basic unit is the object; data is stored inside the object and is exposed to the outside only through the paths the object allows. Table 4.1.2 compares the two approaches from five angles.

Table 4.1.2: Comparison of the procedural and object-oriented approaches.

The "Example" row of the table shows the difference in the shortest way. In the procedural call the area method expects the length and width of the rectangle as parameters. The caller has to store these two numbers somewhere and pass them in the right order. In the object-oriented call the length and width are inside the rectangle object. The caller only says whose area it wants: rect.area().

The "Large programs" row states the real gain. On the left of Figure 4.1.2 three functions depend on the same data. If the form of the data changes, say corner coordinates are stored instead of length and width, all three functions must change. In the layout on the right the data is closed inside a class. A change of form affects the methods of that class; the code that uses the class goes on writing the area() call unchanged.

In Java all code is written inside a class. So the programs so far did have a class, but those classes were only containers holding static methods together; no object was ever made from them. In object-oriented programming classes do their real job: they produce objects.

4.1.1.3Three basic features

Three features set object-oriented languages apart from procedural ones. The subject of these notes is the class and the object themselves. Still, knowing from the start what the three features are for makes it easier to understand the decisions made when writing a class.

  • Encapsulation. An object can hide the details of its fields and behavior from other objects. To the outside it is like a closed box, used only through the methods it permits. The circuits inside a television are in a closed case; the user reaches only the buttons of the remote control.
  • Inheritance. A class can take over the fields and methods of another class. In this way common code is written once and classes are organized in a hierarchy.
  • Polymorphism. An object can be seen as more than one type. The same call produces different behavior on different objects. The call shape.area() computes πr² for a circle and a² for a square.

A fourth feature, abstraction, is often added to this trio. Abstraction means hiding unnecessary detail and showing only the important features. A BankAccount class models not all the properties of a real account but those useful to the program, for example the owner's name and the balance. The color of the door of the branch where the account was opened does not enter the model.

4.1.2Class and object

A factory produces thousands of cars of the same model. Every car has a color, a chassis number and an odometer, and these values vary from car to car. But all of them come from the same drawing: the drawing determines which parts there will be and how the engine will work. In Java the counterpart of this drawing is the class, and the counterpart of each car produced is the object.

4.1.2.1Class: the blueprint of an object

Definition 4.1.2

A class is the blueprint of an object. It defines the data (fields) the objects will carry and the operations (methods) they can perform. Any number of objects carrying different data can be produced from one class.

Definition 4.1.3

An object is an instance of a class: the concrete form, created in memory, of the structure the class describes. Each object carries its own copy of the fields the class defines.

The relationship between class and object is well explained by a cookie cutter. The cutter is made once and determines the shape of the cookie. Each cookie cut with it is a separate cookie: one may get chocolate, another hazelnut. The cutter itself is not eaten. A class likewise carries no data by itself; the objects produced from it carry the data.

On the left of Figure 4.1.3 the dashed box is the Car class. The class defines the fields brand, model, year and color and the methods drive(), stop() and signal(). The three objects on the right are produced from the same class: a Toyota Corolla, a Ford Mustang and a Fiat Egea. All three have the same field names, but the values differ. Two objects produced from the same class carry the same field names; the field values of each belong to itself. Changing the color of one does not change the color of the other.

Classes are usually drawn with a UML class diagram (Unified Modeling Language). In the diagram a class is a box with three compartments: the name of the class at the top, the fields in the middle, the methods at the bottom. The sign before each member shows its access level: - means private and + means public. Types are written next to fields and return types next to methods. Objects are drawn with a similar box, but the header holds the object's name and class in the form car1 : Car, and the header is underlined.

4.1.2.2Defining a class

The code below is the first Java version of the Car class in Figure 4.1.4. In the diagram the fields are marked private; in this first version no access modifier is written. The fields therefore have package access, and another class in the same folder can assign values to them directly.

public class Car {
  // Fields
  String brand;
  String model;
  int year;
  String color;

  // Methods
  void drive() {
    System.out.println(brand + " is moving.");
  }

  void stop() {
    System.out.println(brand + " stopped.");
  }

  void signal() {
    System.out.println(brand + " is signaling.");
  }
}

A class definition begins with the class keyword and the name of the class. The body of the class is between curly braces. The name starts with a capital letter, and if it consists of several words the first letter of each word is capitalized: Car, BankAccount, Rational. A public class must be in a file with the same name as the class. The definition public class Car is written in the file Car.java. A file may contain several classes, but at most one of them can be public.

Fields are declared in the body of the class, outside the methods. The declaration resembles a local variable declaration: a type and a name. The line String brand; says that every Car object will have a String field called brand. Fields can be used directly from every method of the class. The drive() method does not take brand as a parameter; it recognizes it as a field of the class.

There is no static in the headers of the methods. All the methods so far were static and were called with the class name, without an object. The methods here, in contrast, are methods of a particular car. When drive() is called, the object through which the method is called determines whose brand is printed. Such methods are called instance methods.

The class has no main method. So Car cannot be run on its own; it is a building block that another class uses. Most classes in real programs are like this: only one class carries main, and the others define the types it uses.

4.1.2.3Using a class

The CarTest class creates two Car objects, gives values to their fields and calls their methods. If the two files are in the same folder, they are compiled with javac Car.java CarTest.java and run with java CarTest.

public class CarTest {
  public static void main(String[] args) {
    Car car1 = new Car();
    car1.brand = "Toyota";
    car1.model = "Corolla";
    car1.year = 2022;
    car1.color = "Gray";

    Car car2 = new Car();
    car2.brand = "Ford";
    car2.model = "Mustang";
    car2.year = 2023;
    car2.color = "Blue";

    car1.drive();
    car2.signal();
    car1.stop();
  }
}
Toyota is moving.
Ford is signaling.
Toyota stopped.

The new Car() in the first line creates a new Car object in memory. The declaration Car car1 opens a variable of type Car. After the assignment car1 points to the newly created object. The type of the variable is a class name; in Java every class is also a new type.

The next four lines assign values to the fields of the object. The dot in car1.brand = "Toyota"; means "the brand field of the object that car1 points to". This sign is called the dot operator. For the second object other values are given to the same fields. Now there are two separate brand fields in memory: one holds "Toyota" and the other "Ford".

The last three lines call methods. In the call car1.drive(), the brand in the body of the method is the brand of car1: Toyota is moving. is printed. In the call car2.signal() the same name denotes the brand of car2: Ford is signaling. The method code is written once; the object to the left of the dot decides whose data it works with.

Assigning values to fields directly from outside like this is not a good habit. The line car1.year = -5; also compiles and puts the object in a meaningless state. The right way to give the fields their initial values is constructors; the right way to change values later is methods that perform checks. The style here is only to introduce the dot operator.

4.1.2.4Members of a class

Everything defined in the body of a class is called a member of the class. There are two basic kinds of members:

  • Fields represent the data objects can carry. In a Student class, name and surname are fields.
  • Methods define the operations objects can perform. In a Dog class, bark() and run() are methods.

Every member has two further properties. The first is the access level: a member can be private, protected, public, or, when none of these is written, package-private. The access level determines who may use the member. The second is ownership: a member either exists separately in every object (instance member, the default) or is declared static and belongs to the class itself.

Two more kinds of constructs can appear in the body of a class. Constructors are written inside the class and resemble methods, but they run only when an object is created. The Java language specification counts them not as methods but as a separate kind of member. Other classes can also be defined inside a class; these are called inner classes.

4.1.2.5Access modifiers and data hiding

Definition 4.1.4

An access modifier is a keyword that specifies who can reach a member from outside the class. Java has four access levels: public (everyone), protected (the same package and subclasses), package access when nothing is written (classes in the same package) and private (only the class itself).

The general rule is simple: fields are declared private and the methods offered to the outside are declared public. The value of a field is read from outside with a getter; its name traditionally starts with get. The value is changed with a setter; its name starts with set. The real job of a setter is to check the incoming value and reject invalid ones.

public class BankAccount {
  private double balance;   // hidden field
  public double getBalance() {
    return balance;
  }
  public void setBalance(double b) {
    if (b >= 0) balance = b;  // reject invalid
  }
}
// in another class:
acct.balance = -500;

The balance field is private. A class outside BankAccount can neither read nor change this field. When the last line of the code is written in another class, the compiler gives this message:

class BankAccount {
  private double balance;   // hidden field
}
public class PrivateAccess {
  public static void main(String[] args) {
    BankAccount acct = new BankAccount();
    acct.balance = -500;
  }
}
PrivateAccess.java:7: error: balance has private access in BankAccount
    acct.balance = -500;

The only way in from outside is the two public methods. getBalance() returns the value. setBalance(b) checks the new value before writing it: if b is negative, no assignment is made. The test program below first tries to give a valid and then an invalid balance:

public class AccountTest {
  public static void main(String[] args) {
    BankAccount acct = new BankAccount();
    acct.setBalance(1500);
    acct.setBalance(-500);   // rejected
    System.out.println(acct.getBalance());
  }
}
1500.0

Because -500 is rejected, the balance stays 1500.0. The program cannot make the balance negative; the rule that prevents this is written in a single place, inside setBalance. Had the field been public, every line that changes the field would have had to check the same rule separately, and forgetting just one would corrupt the object.

Definition 4.1.5

Data hiding is the arrangement in which only the methods of the class itself can access the fields directly. Fields are made private, and the outside world talks to the object only through public methods. Data hiding is the foundation of encapsulation.

The second gain of data hiding is freedom to change. Suppose it is decided to keep the balance in a long field in cents instead of a double. Because the field is private, no line outside uses it. Only the bodies of two methods change; the code that uses the class does not change at all.

Common mistake

Adding a get and a set method to every private field without thinking. A method such as public void setBalance(double b) { balance = b; } that performs no check effectively makes the field public. A setter is written only if the field really has to be changed from outside, and it rejects invalid values. A field that must never change has no setter.

4.1.3Constructors and object creation

In CarTest each object was set up in five lines: first new Car(), then four separate assignments. In this arrangement, if one of the assignments is forgotten, the object is left half-built, and the error shows up only at run time, perhaps much later. Constructors make sure an object is put into a valid state at the moment it is created.

4.1.3.1What is a constructor?

Definition 4.1.6

A constructor is a special block of code that runs while an object is being created. It is called automatically whenever an object is created with new. Its name is exactly the same as the class name (including case) and it has no return type; not even void is written.

The job of a constructor is to give the fields their initial values and to do whatever else is needed to make the object ready for use. The constructor of the Student class below takes two parameters and writes them to the fields of the object.

public class Student {
  private String name;
  private int id;

  // Constructor: class name, no return type
  public Student(String name, int id) {
    this.name = name;
    this.id = id;
  }
}

// Usage:
Student s = new Student("Ali", 2012);

The header of a constructor resembles a method header, but with two differences. The name is the name of the class: Student. There is no return type before the name. A constructor does not return a value; the result of a new expression is always the new object itself. The line this.name = name; in the body writes the value of the name parameter to the name field of the object. Here this means "the object being created".

Constructors are usually declared public, because the code that creates the object is outside the class. Sometimes one wants to restrict object creation. In that case the constructor is made private and new cannot be called from outside the class. Singleton classes are built this way. A class may have several constructors with different parameter lists.

4.1.3.2The new expression

The general form of object creation is this:

ClassName objectName = new ClassName(arguments);

Car corolla = new Car("Toyota", "Corolla", 2022);
Scanner in = new Scanner(System.in);
Book book = new Book();

The first line shows the pattern and the next three lines show three examples. To the left of the equals sign is a variable declaration and to the right a new expression. Java's own classes are used the same way: to read from the keyboard one writes new Scanner(System.in), and for a modifiable text new StringBuilder("Java"). The program below creates and uses four objects.

import java.util.Scanner;
public class CreateDemo {
  public static void main(String[] args) {
    Scanner in = new Scanner(System.in);
    StringBuilder text = new StringBuilder("Java");
    String title = "Objects";           // shortcut
    String author = new String("Sercan");  // long way
    text.append(" 21");
    System.out.println(text + " / " + title);
    System.out.println(author.length());
    System.out.println(in.nextInt() * 2);
  }
}

When 21 is typed at the keyboard, the program prints:

Java 21 / Objects
6
42

The new expression works in three steps:

  1. new reserves space for the object in the region of memory called the heap. All the fields of the object first receive their default values: numbers become 0, boolean fields false, reference fields null.
  2. The constructor matching the arguments is called and gives the fields their initial values.
  3. The result of the new expression is the reference to the new object. This reference is assigned to the variable to the left of the equals sign.

With String there is a familiar exception to this rule: writing a text literal also yields a String object. The line String title = "Objects"; puts the reference of a String object into title without using new. Writing new String("Sercan") is also valid, but it needlessly produces a new object each time it runs. Writing just String title; creates no object at all; it only declares a variable that can hold a reference.

The 6 in the second line of the output is the result of the call author.length(): "Sercan" has six letters. This call is also an instance method call made with the dot operator. There is no difference in usage between the classes a programmer writes and Java's ready-made classes.

4.1.3.3References

An object cannot be touched directly. A program works with an object only through the reference that leads to it. A variable of a class type stores not the object itself but this reference.

Definition 4.1.7

A reference is a value that points to the location of an object on the heap. It can be thought of as the object's address in memory. Variables of class types (Car, String, Scanner, arrays) hold references. A reference that points to no object has the value null.

Variables of primitive types such as int, double and boolean hold the value themselves. After the line int x = 5; the number 5 sits in the box of x. After the line Car a = new Car(...);, however, the box of a holds not a car but an arrow pointing to where the car is. An easy way to remember this difference is an analogy: the variable is a television remote control and the object is the television. Copying the remote does not create a second television; two remotes switch the same television on and off.

Memory is divided into two regions. The frames and local variables of running methods are on the stack. Objects are kept on the heap. In Figure 4.1.5 the frame of main is on the left. The arrows leaving the boxes sportsCar and classicCar in the frame reach the two objects on the heap. The third variable, newCar, has been declared but no object has been assigned to it yet; its value is null. This drawing convention is used throughout the rest of the notes: a box is a variable, an arrow is a reference, and a framed box on the heap is an object.

In the fifth step the constructor ends and its frame is removed. The parameters and this vanish with it, but the object stays on the heap. The reference, the value of the new expression, is assigned to sportsCar. The sixth step does the same for the second object. A separate object with its own copies of model and color appears on the heap, and classicCar points to it.

In the seventh step sportsCar.printInfo() is called. The method's frame also has a this, and its value is the reference to the left of the dot: object number 1. The names model and color in the body of the method mean this.model and this.color. That is why 2022 - RED is printed. In the eighth step the same method is called through classicCar; this time this points to object number 2 and 2023 - WHITE is printed. The code is single; the data are separate for each object.

The space an object occupies in memory is the sum of its fields. Methods are not copied into every object; the class's code exists in memory once. So creating a thousand Car objects takes a thousand times the space of two references, but the code of printInfo occupies space only once.

The general form of a field declaration is: [access] [static] [final] type name [= initialValue];. The parts in square brackets are optional. The two classes below show different combinations.

public class Book {

  private String title;
  private String author;

A field declared final is given a value only once; it cannot be changed afterwards. The value is given either on the declaration line or in the constructor. A line that tries to assign a value later does not compile:

4.1.4.4Initializer blocks and initialization order

There are three ways to give a field an initial value: on the declaration line, in the constructor and in an initializer block. The third is used for preparation work that does not fit on one line.

Definition 4.1.10

An initializer block is a block of code written directly in the body of a class. A static initializer (static { ... }) runs only once, when the class is loaded into memory for the first time. An instance initializer ({ ... }) runs before the body of the constructor every time an object is created.

A static initializer is used to give a static field a complex initial value, for example to fill a table with a loop. An instance initializer gathers the work common to all constructors in one place. The order of the steps when an object is created is as follows:

  1. If the class is being used for the first time, the initial values of the static fields and the static blocks run once, in the order in which they are written.
  2. new allocates memory for the object; all fields receive default values.
  3. The initial values on the field declaration lines and the instance initializer blocks run in the order in which they are written.
  4. The body of the constructor runs.

The "order in which they are written" in the third step is important. Initial values on declaration lines and { } blocks do not run as separate groups; they run in whatever order they are written in the class, from top to bottom. If an initializer block is written before a field declaration, the block runs first. The Dog class below has both kinds of initializer.

4.1.5Methods

Methods define the behavior of a class. Defining a method, parameters, return values and the call stack are known from basic programming. The real question here is how methods relate to objects: whose data does a method work with, and how does it know?

4.1.5.1Instance methods and class methods

As with fields, there are two kinds of methods. An instance method is tied to an object and uses that object's fields: phone.call(...). A class method (static method) is tied to the class itself and is called through the class name: Phone.updateOS(...).

public class Rectangle {

4.1.6.1Access without an object

Definition 4.1.11

A static member is a field or method declared with the static keyword that belongs not to any object but to the class itself. To reach a static member no object needs to be created; the class name and a dot are used: ClassName.fieldName, ClassName.methodName(arguments).

public class MathUtil {
  // Static add method
  public static int add(int a, int b) {
    return a + b;
  }

  public static void main(String[] args) {
    int result = MathUtil.add(5, 3);
    System.out.println("Sum: " + result);
    System.out.println(Math.max(4, 9));
    System.out.println(Math.sqrt(16.0));
  }
}

4.0

The call MathUtil.add(5, 3) is made without creating any MathUtil object. Because main is inside the same class, add(5, 3) could also have been written without the class name. Math.max and Math.sqrt are calls of the same kind: static methods of the Math class. Java's ready-made library has many examples of this: Math.PI, Integer.parseInt("12"), Integer.MAX_VALUE. The main with which every program starts is also static. When the program starts, the JVM (Java Virtual Machine) has not yet created any object; for it to call main without an object, the method has to belong to the class.

A static member can also be reached through an object: h1.accountCount. Java accepts this notation, but it is discouraged. A reader of the code assumes the member belongs to the object and thinks the counter of h1 might differ from that of h2. The compiler treats this notation as BankAccount.accountCount; which object is used is irrelevant. If compiled with the -Xlint option, it also gives the warning static variable should be qualified by type name.

An instance method can use both instance members and static members directly. Such a method is always called through an object; that object is this, and the instance fields are its fields. 4.1.7References and this

The fact that a variable holds a reference, not an object, looks like a mere detail at first sight. But this detail determines how assignment, comparison and passing objects to methods behave.

4.1.7.1Reference assignment and aliasing

In Java objects are handled through references. Assigning one reference variable to another does not copy the object; it copies only the reference. After the assignment two variables point to the same object.

Definition 4.1.12

An alias is any one of several reference variables that point to the same object. There is one object; a change made through one of the aliases is visible through the others too.

There are similar situations in everyday life. The label on a library shelf is not the book itself; it shows where the book is. A car may have two keys; both keys open the same car. If someone gets in with one key and pushes the seat back, the person who gets in with the other key finds the seat pushed back. 4.1.7.2null and NullPointerException

null means that a reference variable points to no object. Reading a field or calling a method through a null reference causes an error at run time, because there is no object to read from.

public class Empty {
  String name;

  public static void main(String[] args) {
    Empty b = null;
    System.out.println(b.name.length());
  }
}
Exception in thread "main" java.lang.NullPointerException: Cannot read field "name" because "<local1>" is null
	at Empty.main(Empty.java:6)

The program compiles, because b has been given a value: null. When it runs, on line 6 it tries to read b.name and a NullPointerException is thrown. Since JDK 15 the message by default states the location of the error in detail: the name field could not be read because the variable is null. The notation "<local1>" in the message denotes local variable number 1 of main, that is, b. Had the program been compiled with debugging information (javac -g), the name of the variable would have appeared: because "b" is null.

If a local variable is used without ever being given a value, the situation is different: the program does not even compile (variable sb might not have been initialized). A NullPointerException, on the other hand, is an error the compiler cannot catch; it appears at run time. A field is its most frequent source: if a field of type String has not been given a value, its default value is null, and the first method called on it stops the program. The precaution is to check the reference before using it:

public class Empty2 {
  String name;

  public static void main(String[] args) {
    Empty2 b = new Empty2();
    if (b.name != null) {
      System.out.println(b.name.length());
    } else {
      System.out.println("name not set yet");
    }
    System.out.println(b.name.length());
  }
}
name not set yet
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.length()" because "<local1>.name" is null
	at Empty2.main(Empty2.java:11)

The if block sees that name is null and takes the safe path. The last line, however, uses the same field without a check. This time the message says "<local1>.name": it is not b but the name field of b that is null.

An object that no reference points to can never be reached from the program again. The memory of such objects is reclaimed by the JVM's garbage collector when the time comes. In Java there is no need to delete an object by hand, and no way to do so. Had car2 also been set to null in the reference assignment trace, the last reference to the object would have been lost and the object would have become eligible for garbage collection. When the garbage collector will run is not known in advance; a program can only be sure that the object is no longer reachable.

4.1.7.3The this keyword

Definition 4.1.13

this is, inside an instance method or constructor, the reference to the object the method was called on (in a constructor, the object being created). There is no this in static methods.

this is most often used in constructors, when the name of the field and the name of the parameter are the same: this.name = name;. In this case the bare name name refers to the parameter, because the nearest declaration is the parameter. The parameter shadows the field of the same name. To reach the field one writes this.name. What happens if this is forgotten?

public class Shadow {
  private String name;

  public Shadow(String name) {
    name = name;            // forgot this!
  }

  public static void main(String[] args) {
    Shadow g = new Shadow("Ali");
    System.out.println(g.name);
  }
}
null

Both names on either side of the line name = name; are the parameter. The line assigns the parameter to itself and changes nothing. The object's name field is never touched; it stays at its default value null. The program prints null. The most dangerous part is this: the compiler gives no error for this line. The code compiles and runs; the error shows up only when the field is used, perhaps somewhere quite different, as a NullPointerException.

Had the field been final, the compiler would have caught the error. In the declaration private final String name; the field must receive a value in the constructor. Since name = name; gives the field no value, the compiler gives the message variable name might not have been initialized. Making fields that will never change final is therefore not only documentation but also a safety measure.

4.1.7.4Passing the object with this

Because this is a reference, it can also be given to another method as an argument. This is the way to go when an object wants to introduce itself to another object.

public class Team {
  private String name;
  public Team(String name) {
    this.name = name;
  }
  public void addPlayer(Player player) {
    player.joinTeam(this);   // this object
  }
  public String getName() {
    return name;
  }
  public static void main(String[] args) {
    Team team = new Team("Giresunspor");
    Player player = new Player("Mert");

class Player {
  private String name;
  Player(String name) {
    this.name = name;
  }
  void joinTeam(Team team) {
    String t = team.getName();
    System.out.println(name + " -> " + t);

In the call team.addPlayer(player), the method's this is the team object. The player.joinTeam(this) in the body of the method hands this reference to the player. The team parameter of joinTeam now points to the same team object and reads the name with team.getName(). The Player class is defined inside the file Team.java, without public. A file can contain only one public class, but helper classes may be in the same file. These classes have package access; the other classes in the same folder can use them.

4.1.7.5Constructor chaining with this(...)

If a class has several constructors, most of them do the same things. Instead of copying the same assignments into every constructor, constructors can hand work over to each other.

Definition 4.1.14

this(...) is the notation that calls another constructor of the same class from inside a constructor. The sequence of constructors formed this way is called constructor chaining. this(...) must be the first statement of the constructor.

class Employee {
  private String name;
  private double salary;
  Employee(String name) {
    this(name, 20000.0);   // same-class constructor
  }
  Employee(String name, double salary) {
    this.name = name;        // init in one place
    this.salary = salary;
  }
}
Elif 20000.0

The common initial assignments are gathered in a single constructor; here this constructor is Employee(String, double). The other constructor adds the missing argument and delegates to it: this(name, 20000.0). Every employee created without a salary starts with 20000.0. If the default salary changes, a single number changes. If the assignment rules change, for example if one wants to check that the name is not empty, the check is written in a single constructor.

The chain has two rules, and the compiler checks both. this(...) must be on the first line of the constructor:

4.1.8Comparing objects: == and equals

Comparing two int variables with == compares the numbers. Comparing two reference variables with ==, however, compares not the objects but the references in the variables' boxes. The question is not "do these two objects have the same content?" but "do these two variables point to the same object?"

Definition 4.1.15

Reference equality means two references pointing to the same object and is tested with ==. Content equality means two objects carrying the same value in meaning and is tested with the equals() method. What equals counts as "the same" is decided by the programmer who writes the class.

In the program below, the Person class writes its own equals method: it counts two people as equal if their names and ages are the same. The Person0 class, on the other hand, does not write equals. The last part of the program reads a word from the keyboard and compares it with a text literal.

import java.util.Objects;
import java.util.Scanner;

  private String name;
  private int age;
  Person(String name, int age) {
    this.name = name;
    this.age = age;
  }
  @Override
  public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Person)) return false;
    Person k = (Person) o;
    return age == k.age && Objects.equals(name, k.name);
  }
  @Override
  public int hashCode() {
    return Objects.hash(name, age);
  }
  @Override
  public String toString() {
    return name + " (" + age + ")";
  }
}

  String name;
  Person0(String name) { this.name = name; }

The methods equals, hashCode, toString and getClass come to every class from Object, the topmost class of Java. The Object version of equals compares only references; that is, it behaves like ==. Because the Person0 class does not write equals, a.equals(b) gives false: there are two separate objects and the Object version does not look at the content. If the objects of a class are to be compared by content, equals must be overridden in that class.

The equals in Person works in three steps. First it checks with this == o whether it is the same object; if so, it returns true immediately. Then it checks with instanceof whether the incoming object is a Person; if not, or if o is null, it returns false. In the last step it compares the fields. age is an int, so it is compared with ==; name is a String, so it is compared with Objects.equals. This helper method also works safely when one of the two sides is null. The type of the parameter is Object, not Person. Had the type been written Person, the method would not have overridden the equals of Object but only overloaded it; the @Override annotation catches this error at compile time.

When equals is overridden, hashCode must be written too. The rule is: two objects that are equal according to equals must have equal hashCode values. The fourth line of the program verifies this. If the rule is broken, collections such as HashMap and HashSet look for equal objects in different places and fail to find them. Objects.hash(name, age) produces a value from the same fields used in equals. toString gives the text form of the object; println(k1) calls this method automatically and prints Ali (20). Had toString not been written, a text made of the class name and a number, such as Person@1b6d3586, would have been seen.

String and the wrapper classes are also objects and obey the same rule. The last two lines of the program show this. The "Java" read from the keyboard is a new String object created at run time. The "Java" literal in the code is another object. Although their contents are the same, == gives false and equals gives true. That == sometimes gives true when two text literals are compared is because Java stores the same literal as a single object. This is not a rule but an implementation detail; texts are always compared with equals.

4.1.9.1The object counterpart of a primitive type

Definition 4.1.16

A wrapper class is a class that carries the value of a primitive type inside an object. Each of the eight primitive types in Java has a wrapper class.

Most of the names are the primitive type with a capital first letter; the two exceptions are Integer and Character. These classes are needed for three reasons:

  • Sometimes an object is required. Generic collections such as ArrayList<Integer> cannot take a primitive type; the notation ArrayList<int> does not compile.
  • The "no value" case. null cannot be assigned to a primitive type; it can be assigned to a variable of the wrapper type. If the grade of an exam has not been entered yet, Integer grade = null; shows this explicitly. With int and a 0, "scored zero" and "no grade yet" could not be told apart.

Wrappers have a price. As seen in Figure 4.1.18, an int value sits in the variable's box; an Integer requires a separate object, a reference leading to it and an indirect access when read. In a loop that processes millions of numbers this difference is measurable. For this reason the primitive type is preferred unless there is a need.

4.1.9.2Autoboxing and unboxing

Definition 4.1.17

Autoboxing is the conversion of a primitive value into a wrapper object, when needed, through a call the compiler inserts. Unboxing is the conversion of the value in a wrapper object back into the primitive type.

In the first step Integer a = 127 turns into the call Integer.valueOf(127) through autoboxing. The values are the same, the objects are different. In the fifth step c.equals(d) compares the int values inside the objects and gives true. The trap is here: a trial with small numbers gives the impression that == works correctly; when the code meets large numbers it silently produces a wrong result. Wrapper objects are always compared with equals.

In the sixth step int t = c + d; runs. The + operator does not work with objects; both objects are unboxed (intValue()) and 128 + 128 = 256 is found. t is a primitive int and its value sits in its box on the stack. The same rule applies in comparison: if an Integer is compared with an int using ==, the Integer is unboxed and the numbers are compared. In the seventh step 256 is printed.

In the eighth step Integer empty = null; runs. null can be assigned to a wrapper variable. In the ninth step int x = empty; is quietly turned into the call empty.intValue(). Common mistake

Comparing wrapper objects with ==. Integer values in the range −128…127 seem to give the right result with ==; outside the range the same values give false. The upper limit of the cache can be raised with a JVM setting, so relying on the limit is not right either. Content is always compared with equals.

4.1.10Records and enums

Some classes are written only to carry a few pieces of data together: the two coordinates of a point, the name and number of a student. Some types, on the other hand, take one of a known, limited set of values: the days of the week, the seasons. Java offers a short and safe notation for each of these cases.

4.1.10.1Records

Definition 4.1.18

A record (Java 16 and later) is a kind of class designed to write classes that only carry data in a short form. All the fields of a record are private final and it has no setters; its objects are therefore immutable.

4.1.12.3A design example: Rational

By putting together the pieces so far, a class can be designed from scratch. The Rational class represents fractions of the form num/den. Three questions are asked when designing a class:

  • Interface: What will the code that uses the class see? Here a public constructor, add, which adds two fractions, and toString, which gives the fraction as text.
  • Representation: How will the data be stored? Two private int fields: num and den. The constructor stores the fraction in lowest terms; so every object is always in its simplest form.
  • Implementation: The bodies of the methods and the helpers not exposed to the outside. The greatest common divisor needed for simplification is found with Euclid's algorithm in a hidden gcd method.
public class Rational {
  // Representation: hidden fields
  private int num, den;
  // Interface: public constructor and methods
  public Rational(int num, int den) {
    int g = gcd(Math.abs(num), Math.abs(den));
    this.num = num / g;
    this.den = den / g;
  }
  public Rational add(Rational d) {
    int newNum = num * d.den + d.num * den;
    return new Rational(newNum, den * d.den);
  }
  @Override
  public String toString() { return num + "/" + den; }
  // Implementation detail: hidden helper
  private static int gcd(int a, int b) {
    while (b != 0) { int k = a % b; a = b; b = k; }
    return a;
  }
}

In the first step new Rational(6, 8) allocates the object; the fields are 0 at first and the constructor's parameters are 6 and 8. In the second step the hidden helper gcd(6, 8) is called. Because this method is private, the code that uses the class cannot see or call it. It is static because it works only with its parameters; it touches no object's fields.

The third, fourth and fifth steps are the three rounds of Euclid's algorithm. In each round k = a % b is computed, then a ← b and b ← k. In the first round 6 % 8 = 6; the numbers just swap places: a = 8, b = 6. In the second round 8 % 6 = 2: a = 6, b = 2. In the third round 6 % 2 = 0: a = 2, b = 0. When b becomes zero the loop ends and a, that is, 2, is returned. In the sixth step the constructor divides the numerator and denominator by 2 and stores them: the object becomes 3/4.

The seventh step does the same work for (1, 6). gcd(1, 6) returns 1; the fraction is already in lowest terms and is stored as 1/6. In the eighth step a.add(b) is called. The method's this is object number 1 and the parameter d is object number 2. newNum = num * d.den + d.num * den = 3 × 6 + 1 × 4 = 22. d.den is a private field of another object, but it can be read because the code is inside the same class.

In the ninth step new Rational(22, 24) is called. The constructor runs gcd again: b takes the values 24, 22, 2, 0 in turn and the result is 2. The new object is stored as 11/12. In the tenth step println prints first the returned result and then a: 11/12 3/4. add has not changed the existing object; it has returned a new one. Rational has no setters and no method changes the fields; its objects are immutable in this sense.

In terms of cost, the loop of gcd runs a number of rounds proportional to the number of digits of the smaller number; the number of rounds of Euclid's algorithm is O(log min(a, b)). The constructor and add are therefore very fast. Every call of add creates a new object; this is the price of the immutable design. In return, even if a variable holding a fraction is shared elsewhere, its value never changes unexpectedly.

The last two lines of the test program try boundary cases. new Rational(-4, 6) correctly becomes -2/3. For new Rational(0, 5), gcd(0, 5) = 5 is found and the fraction is stored as 0/1. On the last line 1/2 + 1/2 = 4/4 is computed and, simplified, becomes 1/1. These trials expose two limits of the design. new Rational(3, -9), however, is stored as 1/-3: the constructor does not move the sign from the denominator to the numerator. Because the same value can be stored in two different forms, an equals written for this class might count equal fractions as different. The fix is to flip the signs of both when den is negative in the constructor. The second limit is a zero denominator. In the call new Rational(0, 0), gcd(0, 0) returns 0 and the division gives this error:

Exception in thread "main" java.lang.ArithmeticException: / by zero
	at Rational.<init>(RationalZero.java:10)
	at RationalZero.main(RationalZero.java:3)

A constructor that does not allow a zero denominator should report the error at the moment the fraction is created and with a meaningful message. For example, the first line of the constructor could be if (den == 0) throw new IllegalArgumentException("den cannot be 0");. Keeping the representation hidden makes these fixes easy: the change affects only the constructor, and the code that uses the class stays as it is.

4.1.14Common mistakes

The compiler catches most of the errors related to objects and classes, and its message points directly to the location of the error. Some, however, lead to programs that compile but run wrongly; these are more dangerous.

Common mistake

Calling an instance method from main without an object. Message: non-static method greet() cannot be referenced from a static context. The call is made through an object (new Greeter().greet()); if the method really uses no object's data, it is made static.

Common mistake

Writing void on a constructor. public void CtorError(String m) is not a constructor but an ordinary method. new CtorError("hello") is rejected with this message: constructor CtorError in class CtorError cannot be applied to given types. A constructor has no return type.

Common mistake

Creating an object without arguments when there is only a parameterized constructor. When a constructor is written, the default constructor is not added; new Product() gives the message cannot be applied to given types. If needed, a no-argument constructor is written as well.

Common mistake

Forgetting new. The line Product u = Product("Pen"); reads like a method call, and the compiler looks for such a method:

ForgotNew.java:7: error: cannot find symbol
    Product u = Product("Pen");
             ^
  symbol:   method Product(String)
  location: class ForgotNew
1 error
Common mistake

Accessing a private field from outside. Message: balance has private access in BankAccount. The field is reached through the class's get and set methods.

Common mistake

Using this in a static method. Message: non-static variable this cannot be referenced from a static context. A static method has no object.

Common mistake

Forgetting this in a constructor (shadowing). name = name; compiles but assigns the parameter to itself; the field stays null. The correct form is this.name = name;. If the field is made final, the compiler catches the error.

Common mistake

Writing this(...) after the first line. Message: call to this must be first statement in constructor. Delegating to the other constructor must be the first statement of the constructor.

Common mistake

Comparing objects with ==. k1 == k2 gives false for two separate objects with the same content. Content is compared with equals(), including for String and the wrapper classes. If equals has not been written in one's own class, the Object version also behaves like ==.

Common mistake

Using a null reference. A method cannot be called on an object that has not been created or after null has been assigned; a NullPointerException is thrown. Reference fields that have not been given a value are also null. A null check is made before use.

Common mistake

Trying to change a record field. Message: x has private access in Point. A record is immutable; a new object is created for a new value.

Common mistake

Creating a member inner class directly in static main. Message: non-static variable this cannot be referenced from a static context. The correct form is outer.new MemberInner(); or the inner class is made static.

4.1.15Summary

  • Object-oriented programming builds a program from interacting objects. Every object has state (fields) and behavior (methods). The three basic features are encapsulation, inheritance and polymorphism; abstraction is often added.
  • A class is the blueprint of an object; an object is an instance produced with new. Objects of the same class carry the same field names, but each has its own values. The method code is single in the class.
  • Access modifiers: public, protected, package access, private. Fields are private and the methods offered to the outside are public; the value is read with a getter and written with a setter that performs checks (data hiding).
  • A constructor has the same name as the class and no return type. new allocates space on the heap, gives the fields default values, calls the constructor and returns the reference. If no constructor is written, the compiler adds a no-argument default constructor; once a constructor is written, it does not.
  • Default values of fields: numbers 0, boolean false, char '\u0000', references null. Local variables get no default value.
  • An instance field is separate in every object; a static field is single and shared in the class. A static method has no this; it reaches instance members only through an object. A final field is given a value once; class constants are static final and written in capitals.
  • Initialization order: static fields and static { } blocks once, when the class is first used; then at every new the default values, the field initial values and { } blocks (in the order written), and finally the body of the constructor.
  • A variable holds not the object but the reference. Assignment copies the reference and creates an alias. Passing an object to a method also gives a copy of the reference. Access through a null reference throws a NullPointerException; the garbage collector removes an object that has no reference left.
  • this is the object the method was called on; a shadowed field is reached with this.name, and the object can be passed to other methods with this. this(...) calls another constructor of the same class, must be on the first line and builds a single object.
  • == tests reference equality and equals tests content equality. When equals is overridden, hashCode is written too. String and the wrappers are compared with equals.
  • Wrapper classes carry primitive values as objects. Autoboxing is a call to valueOf and unboxing a call to xxxValue(). Integers between −128 and 127 come from the cache; unboxing a null wrapper throws a NullPointerException.
  • A record is an immutable data class; the constructor, accessors, equals, hashCode and toString are generated automatically. An enum is a fixed set of values; it is used with values(), valueOf(), ordinal() and ==.
  • Inner classes: static (no outer object needed), member (tied to an outer object, outer.new), local (inside a method) and anonymous (nameless, a single object).
  • An object belongs to a single class, but it can have many types. Kinds of classes: enum, singleton, abstract, sealed, final, record, utility and application class. In class design the interface, representation and implementation are separated; the representation is kept hidden.

4.1.17Test Yourself

  1. Three objects (p, q, r) are created in a row from the class class Counter2 { static int s = 0; int n; Counter2() { s += 2; n = s; } }. What are p.n, q.n, r.n and Counter2.s?

    Answer

    s is static and all three constructors increment the same box: 2, 4, 6. Each constructor copies the current value into the object's own n field. A later change of s does not affect the n of earlier objects. Result: 2 4 6 6.

  2. The class Cell has a single int v field and a constructor that assigns v. The method static void change(Cell h, Cell g) { h.v = 10; g = h; g.v = 20; } is called as change(a, b) with a = new Cell(1) and b = new Cell(2). What are a.v and b.v afterwards?

    Answer

    h points to the object of a; h.v = 10 makes it 10. g = h only points the local copy g at the object of a; b does not change. g.v = 20 now writes to the object of a. Result: a.v = 20, b.v = 2.

  3. Two objects are created from the class class C { static int t = 0; int a = ++t; { t *= 10; } C() { t++; } }. What are the a of the first object, the a of the second object and finally C.t?

    Answer

    For every object the order is: field initial value, then instance initializer, then constructor body. First object: a = ++t → t = 1, a = 1; t *= 10 → 10; t++ → 11. Second object: a = 12, t = 120, t = 121. Result: 1 12 121.

  4. The class Chain has the fields int x; String s = ""; and these constructors: Chain() { this(1); s += "a"; }, Chain(int x) { this(x, x + 1); s += "b"; }, Chain(int x, int y) { this.x = x * y; s += "c"; }. After new Chain(), what are x and s?

    Answer

    The chain descends to the innermost constructor: Chain(1, 2). The initial value s = "" is given once, immediately before the body of this constructor. The innermost body runs first: x = 2, s = "c". As the chain unwinds, each constructor runs its remaining line: "cb", then "cba". Result: 2 cba.

  5. After the declarations Integer i1 = 127, i2 = 127, i3 = 1000, i4 = 1000; Long l = 127L;, what do i1 == i2, i3 == i4, i3.equals(i4), l.equals(127) and l == 127 give?

    Answer

    true false true false true. 127 comes from the cache; for 1000 two separate objects are created. equals compares values. In l.equals(127) the 127 is boxed into an Integer; the equals of Long counts only another Long as equal, so the result is false. In l == 127, l is unboxed and the two numbers are compared: true.

  6. With the Rational class in this chapter, how is new Rational(10, -4) printed? What does new Rational(2, 6).add(new Rational(1, 6)) give?

    Answer

    gcd(10, 4) = 2; the numerator and denominator are divided by 2 and the sign stays in the denominator: 5/-2. In the second expression 2/6 is first stored as 1/3. 1/3 + 1/6 = (1 × 6 + 1 × 3) / 18 = 9/18, and the constructor simplifies it: 1/2.

  7. To get rid of the non-static method ... cannot be referenced from a static context error in main, a student makes all the fields and methods in the class static. The program compiles. What is the problem with this solution?

    Answer

    When the fields are static, a single copy of each field is left in the class. Even if two objects are created, they share the same fields; changing the name of one changes the name of the other. The program effectively becomes procedural. The right solution is to call the object-dependent methods through an object and to make static only those that are truly independent of any object.

  8. What happens with new Rational(0, 0) in the Rational class? Which method must be changed, and how, to remove this error and the sign problem? Does the code that uses the class have to change?

    Answer

    gcd(0, 0) returns 0 and the line num / g throws ArithmeticException: / by zero. Only the constructor changes: at the start, if den == 0, an IllegalArgumentException with a meaningful message is thrown; after simplification, if den is negative, the signs of numerator and denominator are flipped. Because the fields are private and the representation is hidden, the code that uses the class does not change at all.
