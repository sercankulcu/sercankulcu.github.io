It ends with three small applications: a mouse drawing program, a text converter, and a change calculator.

9.1Graphics programming

9.1.1Components, events, and painting

Most people use a computer through windows. A window has a title, buttons, menus, and text fields. The user clicks with the mouse, types on the keyboard, and resizes the window, and the program responds to these actions. An interface of this kind is called a graphical user interface.

Definition 9.1

A graphical user interface (GUI) is an interface in which the user interacts with a program through visual elements such as windows, buttons, menus, text fields, and drawings.

Java provides an extensive class library for building GUIs. To write a GUI program with it, you need to understand three concepts.

  • Component: The building blocks of the interface, such as windows, buttons, labels, and text fields. Every component is an object of some class. A button is an object created from the JButton class; its text, color, and size are stored in the fields of that object.
  • Event handling: User actions such as a mouse click or a key press are captured, and methods that respond to them are called.
  • Painting: Shapes are drawn, the screen is updated, and components are displayed.

A GUI program is like a shop waiting for customers. First the window display is prepared: the components are created and placed in the window. Then the program waits. Whatever the customer touches, the assistant responsible for that item springs into action. In the program, the display corresponds to the components, the touch to an event, and the assistant to a listener method (Figure 9.1).

9.1.2Console programs and GUI programs

In a console program the flow is sequential. The main method runs from beginning to end. When the program needs input, it asks the question itself and reads a line from the keyboard with Scanner. The result is printed with System.out.println. When main ends, the program ends.

A GUI program flows differently. main only builds the interface and returns. After that the program waits for the user's move. When the user presses a button or clicks a panel, the matching method runs. This style of execution is called event-driven programming.

Definition 9.2

An event is a user action, such as a click, a key press, or a mouse drag, or a notification from the system. In an event-driven program, the order in which events arrive, not the order of lines in the code, determines the flow.

Table 9.1: Comparison of console programs and GUI programs.
Console programGUI program
FlowSequential: main runs from start to end, and the program asks the questionsEvent-driven: the program waits for the user's move
InputA line is read from the keyboard with ScannerButtons, text fields, and the mouse; listener methods are called

The last two rows of the table matter. In a GUI program, the program keeps running even though main has finished. The reason is that Java starts a separate thread when a window opens. This thread waits on the event queue and passes each incoming event to the matching listener. The JVM does not exit while this thread is running.

In a GUI program, the answer to “what happens next?” is not the order of the code; it is the user's next action. That is why most of the code consists of listeners of the form “when this happens, do that.” The programmer writes a response for each action but does not know in what order the actions will arrive.

Common mistake

Trying to wait for user input in a while loop in a GUI program. A “loop until the user presses the button” written out of console habit keeps the event thread busy, and the window freezes. In a GUI program Java does the waiting; the programmer only registers the listener.

9.1.3AWT and Swing

Java's graphics classes are spread over two libraries. Both come with the JDK; nothing extra needs to be installed.

  • AWT (Abstract Window Toolkit), package java.awt: Java's first graphics library. Today it is used mostly for its shared classes: Graphics, Color, Font, Point, the layout managers, and the event classes (java.awt.event).
  • Swing, package javax.swing: a library built on top of AWT in which Java itself draws the components. Class names start with J: JFrame, JPanel, JButton, JLabel.

The difference between the two libraries lies in how components are drawn. When AWT needs a button, it uses the operating system's own button, so the same program looks different on Windows and on Linux. Swing paints the button itself, so the look is the same on every system and is under Java's control. In this chapter the components come from Swing, while the drawing and helper classes come from AWT. A typical GUI program therefore imports both packages: import java.awt.*; and import javax.swing.*;.

Figure 9.2 shows how inheritance is used in the GUI library. At the root of the tree is Component: anything with a position and size on the screen is a component. A Container is a component that can hold other components. Two branches leave Container. The first holds Window, Frame, and finally JFrame. The second holds JComponent, the common superclass of the Swing components. JPanel, JLabel, and the text components derive from JComponent directly or by a short path. JButton has the AbstractButton class in between.

This tree has a practical consequence. If a method expects a Component as a parameter, you can pass it a button, a label, or a panel. Polymorphism is an everyday tool here. For example, the panel.add(...) method accepts any component.

9.1.4Screen coordinates

A graphical application is built in three steps. First, components are added to the interface using Java's graphics classes. Second, event-handling methods are defined that respond to the user's actions. Finally, the visuals are produced with methods such as paint() or paintComponent(). Before we start drawing, we need to know how the screen is addressed.

The screen is a grid of pixels. Every pixel has a column number (x) and a row number (y). Coordinates are integers measured from the top-left corner of the component.

Definition 9.3

Screen coordinates identify a pixel inside a component by an integer pair (x, y). (0, 0) is the top-left pixel of the component. x grows to the right and y downward. The bottom-right pixel is (getWidth() − 1, getHeight() − 1).

The most important difference from the axes of mathematics is the direction of y. In mathematics y grows upward; on the screen it grows downward. This choice comes from the history of displays: cathode-ray tubes drew the picture from top to bottom, line by line. As a result, a point whose y value increases moves down the screen. Decreasing y moves the point up.

Example 9.1

A panel is 300 pixels wide and 160 pixels high. What are the coordinates of the top-right, bottom-left, and center pixels?

Columns are numbered 0 to 299 and rows 0 to 159. The top-right pixel is (299, 0) and the bottom-left pixel is (0, 159). For the center pixel, the width and height are divided by two: (300 / 2, 160 / 2) = (150, 80). If the numbers were odd, integer division would discard the fraction; for example, 261 / 2 = 130.

9.1.5Canvas, pen, color, and font

Drawing needs three things: a surface to draw on, a pen that does the drawing, and the pen's properties.

  • Canvas: a surface on which a picture can be drawn. In Swing, a JPanel is usually used. In AWT there is a Canvas class for this job. The programmer derives a subclass from JPanel and draws inside it.
  • The Graphics class: the “pen” that does the drawing. Its methods have names such as drawLine(), drawRect(), fillOval(), drawString(), and drawImage().
  • Color and Font: Color sets the pen's color and Font sets its typeface: g.setColor(Color.RED), g.setFont(new Font("Serif", Font.BOLD, 24)).

The pen analogy also explains a rule. The Graphics object is the pen in the programmer's hand. setColor changes the pen. Until the pen is changed again, all drawing uses the same color. The same holds for the font: after a call to setFont, every drawString uses the new font. A Graphics object is therefore a stateful object: it remembers its own color and font.

9.1.6Drawing with paintComponent

The way to draw permanently on a panel is to override the paintComponent method in a class derived from JPanel.

import java.awt.*;
import javax.swing.*;

class DrawPanel extends JPanel {
    @Override
    public void paintComponent(Graphics g) {
        super.paintComponent(g);     // clear background
        g.setColor(Color.BLUE);
        g.drawRect(20, 30, 50, 70);  // x, y, w, h
        g.drawString("Hello, Java Graphics!", 100, 100);
    }
}

The class extends JPanel and overrides the superclass's paintComponent(Graphics g) method. The @Override annotation tells the compiler that “this method replaces a method of the superclass.” If the method name is misspelled, the compiler sees the annotation and reports an error. The first line of the body is super.paintComponent(g): it performs the superclass's own painting, which fills the background with the background color. Then the pen is switched to blue. drawRect(20, 30, 50, 70) draws the outline of a rectangle whose top-left corner is at (20, 30), 50 pixels wide and 70 pixels high. The last line writes a text at the point (100, 100).

Notice something in this code: nothing in the program ever calls paintComponent. Swing calls it. Swing runs the method when the window first opens, when its size changes, when another window that covered it is dragged away, or when the program requests a repaint with repaint(). When it calls the method, it passes a ready-made Graphics g object, which is tied to the region currently being painted.

To see which drawing calls the method actually makes, we can use Swing's DebugGraphics class. It is a pen that writes each drawing call as a line of text. Running DrawPanel with this pen on a 300 × 160 image shows the following calls (abbreviated):

setColor(238, 238, 238)
fillRect(0, 0, 300, 160)
setColor(0, 0, 255)
drawRect(20, 30, 50, 70)
drawString("Hello, Java Graphics!", 100, 100)

The programmer did not write the first two lines. They are the work of super.paintComponent(g): the pen is switched to the panel's background color, the light gray (238, 238, 238), and the whole panel is filled with it. The next three lines are the calls the programmer wrote.

Definition 9.4

paintComponent(Graphics g) is the method with which a Swing component draws its own contents. Swing calls this method whenever the component needs to be repainted. A class that wants to do its own drawing overrides the method and writes super.paintComponent(g) first in the body.

A graphics object can also be obtained with panel.getGraphics(). However, drawing done with this object is not permanent. The next time the window is repainted, for example after it is minimized and restored, Swing calls paintComponent and whatever was drawn through getGraphics() is erased. The way to draw permanently is paintComponent. The data of the drawing is kept in fields, and the method regenerates the picture from this data on every call.

The position of text also has a subtlety. The y parameter of drawString is not the top edge of the text but its baseline. The baseline is the line on which the letters “sit.” In the call drawString("Hello, Java Graphics!", 100, 100), the bodies of the letters stay above row 100; only the tails of letters such as “g” and “j” drop below that line.

Common mistake

Writing drawString(text, x, 0) and expecting the text to appear at the very top of the panel. Because y = 0 is the baseline, almost all of the letters end up outside the panel, in the invisible region. For the text to be visible, y must be at least the height of the font; for a 24-point font, a value around 30–40 is safe.

9.1.7Graphics drawing methods

The commonly used methods of the Graphics class are collected in Table 9.2. The names follow a pattern: methods starting with draw… draw only the outline, and those starting with fill… draw the shape filled.

Table 9.2: The basic drawing methods of the Graphics class.

Ellipses and circles are specified not by their centers but by their bounding rectangles: you give the top-left corner and the size of the rectangle in which the ellipse fits.

Definition 9.5

The bounding rectangle of a shape is the smallest axis-parallel rectangle that completely encloses it. drawOval(x, y, w, h) draws the ellipse inside the rectangle whose top-left corner is (x, y) and whose size is w × h.

To draw a circle with center (cx, cy) and radius r, compute the top-left corner of the bounding square. The square extends r to the left of and above the center, and its side is 2r. The result is fillOval(cx − r, cy − r, 2r, 2r). Conversely, for a given call drawOval(x, y, w, h), the center of the ellipse is (x + w / 2, y + h / 2).

Example 9.2

Where is the center of the ellipse drawn by g.drawOval(50, 50, 100, 60)? Which range of pixels does it cover?

The center is (50 + 100 / 2, 50 + 60 / 2) = (100, 80). The ellipse starts at 50 horizontally and at 50 vertically. If it is drawn on an image and the painted pixels are counted, x runs from 50 to 150 and y from 50 to 110. Methods that draw outlines also paint the right and bottom edge of the boundary: a draw… shape is w + 1 pixels wide and h + 1 pixels high, whereas fill… paints exactly w × h pixels.

The difference in the last sentence is small but real. In the call drawRect(20, 30, 50, 40), the bottom-right corner pixel of the outline is (70, 70), and (71, 70) stays empty. With the same arguments, fillRect paints up to (69, 69). When an outline is drawn over a filled rectangle, this one-pixel difference becomes visible.

9.1.8Code trace: the drawing order of shapes

The following panel uses each of the basic methods once.

class ShapesPanel extends JPanel {
    @Override
    public void paintComponent(Graphics g) {
        super.paintComponent(g);
        g.drawLine(10, 10, 110, 60);
        g.drawRect(130, 10, 80, 50);
        g.fillRect(230, 10, 80, 50);
        g.drawOval(10, 80, 100, 60);
        g.fillOval(130, 80, 60, 60);
        g.drawString("Hello", 230, 115);
    }
}

There is no setColor call anywhere in the code. When no color is given, the pen draws with the panel's foreground color. In Swing's default look this is the dark gray (51, 51, 51); in a running program getForeground() returns this value. Table 9.3 traces the steps of the method.

The line in step 2 goes from (10, 10) to (110, 60). Because the second point has a larger y, the line goes right and down. Steps 3 and 4 draw two rectangles of the same size. One is only an outline; the other is filled with the pen's color. In step 5, the point (10, 80) is the corner of the bounding box, not of the ellipse.

In step 6, the width and height are equal, so a filled disk is drawn. The center is (130 + 30, 80 + 30) = (160, 110) and the radius is 30. In step 7, the baseline of the text is y = 115; the letters are written above this line. When the method ends, the panel is complete. Every time the window is repainted, the same calls are made again from the start in the same order.

Drawings are painted on top of one another. A shape drawn later covers an earlier one. In this program the shapes do not overlap, so the order is not visible. When shapes overlap, the one drawn last stays on top.

Common mistake

Forgetting the line super.paintComponent(g). This line clears the background. Without it the panel is not painted with its background, and leftover images from the previous drawing or from other windows may remain on the screen. In animations in particular, a moving shape leaves a trail wherever it has been.

9.2Windows and panels

9.2.1The JFrame class

All the components of a GUI program live inside a window. In Swing, a window is created with the JFrame class.

Definition 9.6

JFrame is a top-level window with a title bar and minimize and close buttons on the screen. It is not placed inside another component; other components are added to its content pane.

Table 9.4: Frequently used calls with JFrame.
CodePurpose
JFrame frame = new JFrame("Title");Creates a window with the given title (not yet visible)
frame.add(component);Adds a component to the window (to the content pane)
frame.setSize(400, 300);Width and height (pixels, including the borders)
frame.pack();Sets the size to the size preferred by the components inside
frame.setLocation(x, y);The position of the window on the screen; setLocationRelativeTo(null) centers it

There are two ways to size a window. setSize gives the size directly; this size includes the title bar and the borders. pack() adds up the sizes preferred by the components inside and makes the window exactly that large. In a window whose components are arranged by a layout manager, pack() usually gives a better result, because the content fits in the window even when the font or the screen resolution changes.

The add call actually adds the component not to the window itself but to its content pane. The content pane is the inner area below the title bar. In old Java versions you had to write frame.getContentPane().add(...). Since Java 5, frame.add(...) makes this call itself. The examples in this chapter use both forms; they mean the same thing.

9.2.2The first window

import javax.swing.JFrame;
import javax.swing.SwingUtilities;

public class JFrameDemo {
    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> {
            JFrame frame = new JFrame("Java JFrame Example");
            frame.setSize(400, 300);
            frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            frame.setVisible(true);
        });
    }
}

The program imports the JFrame and SwingUtilities classes. main does not build the window itself; it leaves the building to the event dispatch thread (EDT) with SwingUtilities.invokeLater. Swing components should be used only from this thread; the reason is explained in 9.6.5. The code running on the EDT creates a window titled “Java JFrame Example,” sets its size to 400 × 300, sets the close behavior, and makes the window visible. The window is empty. main ends as soon as it has queued the work, but the program keeps running until the window is closed.

This short program has three pitfalls:

  • If setVisible(true) is forgotten, the window is created in memory but never appears on the screen. The program raises no error; it simply looks as if nothing is happening.
  • If EXIT_ON_CLOSE is not given, the default behavior is HIDE_ON_CLOSE. When the user presses the × button, the window is hidden, but the program keeps running in the background. In a development environment this shows up as a pile of programs that were forgotten and never stopped.
  • If no size is given, the window opens at nearly 0 × 0, just the size of its title bar.

The four constants accepted by setDefaultCloseOperation are defined in the WindowConstants interface. DO_NOTHING_ON_CLOSE (0) prevents closing altogether. HIDE_ON_CLOSE (1) hides the window. DISPOSE_ON_CLOSE (2) destroys the window; if no other windows remain, the program may end. EXIT_ON_CLOSE (3) calls System.exit(0).

If this program is run in an environment with no display, it produces an interesting result. Java recognizes a display-less environment as headless mode. In this mode, the call new JFrame(...) throws java.awt.HeadlessException, because there is no screen to show it on. Components such as panels, buttons, and text fields can still be created in this mode. Most of the outputs given in this chapter were obtained this way, by running the components directly without opening a window.

9.2.3The JPanel class

Definition 9.7

A container is a component that holds other components. JPanel is the general-purpose container in the javax.swing package; it is used to group and arrange the components inside a window and to draw on.

JPanel has four uses:

  • Grouping: Complex layouts are built by nesting several panels. For example, the row of buttons at the bottom of a window is collected in a separate panel.
  • Customizing: setBackground(), setBorder(), and setPreferredSize() change its color, its border, and its preferred size.
  • Serving as a canvas: Drawings, animations, and graphics are done on a panel: derive from JPanel and override paintComponent.
  • Splitting up code: Each panel can be a class of its own. A large interface is thus divided into small pieces that can be understood separately.

The structure in Figure 9.9 is a tree. The root is the window and the leaves are components such as buttons and labels. The interior nodes are containers. When a container is repainted, it first paints itself and then the components inside it. The same rule applies at every level of the component tree.

9.2.4A panel example

import java.awt.Color;
import javax.swing.*;

public class PanelDemo {
    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> {
            JPanel panel = new JPanel();
            panel.setBackground(Color.LIGHT_GRAY);
            panel.add(new JButton("Click"));
            JFrame frame = new JFrame("JPanel Example");
            frame.add(panel);
            frame.setSize(300, 150);
            frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            frame.setVisible(true);
        });
    }
}

Like the previous example, the program builds the interface on the event dispatch thread with invokeLater. It creates a panel and sets its background to Color.LIGHT_GRAY, that is, the light gray (192, 192, 192). A button labeled “Click” is added to the panel. Then the window is created, the panel is added to it, and the window is shown at 300 × 150. The button has no listener; when clicked it looks pressed, but nothing happens.

In the window, the button sits at the top center of the panel, and the panel fills the whole window. Layout managers explain both observations. The default layout manager of JPanel is FlowLayout. This manager arranges components at their preferred sizes, row by row, centered. Since the panel holds a single button, the button is placed in the middle of the first row. The content pane of a JFrame uses BorderLayout. A panel added without a region goes to the center region, and the center takes all the remaining space.

Example 9.3

Let this panel be 284 × 111 pixels. If the preferred size of the “Click” button is 61 × 26, what is the position of the button?

By default, FlowLayout leaves a gap of 5 pixels between components and at the edges. The available width is 284 − 2 × 5 = 274. The button is placed in the middle of this width: x = 5 + (274 − 61) / 2 = 5 + 106 = 111. The row starts 5 pixels below the top edge: y = 5. 9.3.2The Color class

java.awt.Color holds the color of the interface and of drawings. Every color on the screen is a mixture of three primary colors: red, green, and blue. This scheme is called RGB.

Definition 9.9

9.4Layout managers

9.4.1What is a layout manager?

Suppose five buttons are to be put in a window. The position and size of each button could be given by hand: “the first button is at (10, 10), 80 × 30.” This approach runs into a problem. When the user enlarges the window, the buttons stay in the top-left corner. When the screen resolution or the font changes, the button texts no longer fit in the boxes. Java hands this job to an object.

Definition 9.10

A layout manager is an object that computes the position and size of the components inside a container according to rules. It is given to the container with setLayout: panel.setLayout(new GridLayout(2, 3));.

A layout manager is used instead of giving coordinates by hand. When the window grows, or the font or the screen resolution changes, the layout is recomputed automatically. The programmer only chooses the rule: “arrange row by row,” “place in five regions,” “divide into equal cells.” This chapter covers four of Java's standard managers.

The more flexible but more complicated GridBagLayout builds a grid of cells of different sizes. You rarely need it. It is enough to nest panels and give each one a simple manager. For example, the content pane of a window uses BorderLayout, while the button strip at the bottom is a separate panel that uses FlowLayout.

The behavior of layout managers can be followed interactively in the Swing Layout Managers simulator. As the window size changes, you can see how each of the four managers recomputes its layout.

9.4.3BorderLayout

BorderLayout divides the container into five regions: NORTH, SOUTH, WEST, EAST, and CENTER. It is suitable for showing components with different priorities in an orderly way: the toolbar at the top, the status line at the bottom, and the main content in the middle.

The manager's rules are as follows:

  • A component added without a region goes to the center: add(b) and add(b, BorderLayout.CENTER) are the same.
  • Each region holds a single component. A second addition to the same region replaces the first.
  • North and south take the whole width; their height is the component's preferred height. West and east take the height left between north and south; their width is the preferred width. The center fills everything that remains.
  • setHgap() and setVgap() set the horizontal and vertical gap between regions in pixels. The same values can also be given to the constructor: new BorderLayout(5, 5).

The second rule has a subtle side. When a second component is added to the same region, the first is not removed from the container. The container's component count is 2, but the manager attaches only the last one added to that region. The first component takes no part in the layout and keeps the size 0 × 0. It is not visible on the screen.

Common mistake

Adding two components to a window without specifying a region: f.add(new JButton("One")); f.add(new JButton("Two"));. Because the content pane uses BorderLayout, both go to the center and the last one added wins. Only “Two” is visible, and it fills the whole area. Tried on a 300 × 200 BorderLayout panel, “Two” comes out as (0, 0, 300, 200) and “One” as 0 × 0. Side-by-side arrangement is the behavior of FlowLayout; for that, put the buttons in a JPanel first.

9.4.5GridLayout and BoxLayout

GridLayout(rows, columns) divides the container into cells of equal size. Components are placed row by row, from left to right. Each component completely fills its cell; the preferred size is ignored.

Example 9.8

Five buttons are added in order to a 300 × 120 pixel panel that uses new GridLayout(2, 3). What are the position and size of the fifth button?

The cell width is 300 / 3 = 100 and the height is 120 / 2 = 60. Buttons 1–3 fill the top row. Button 4 goes into the first cell of the bottom row and button 5 into the second cell: (100, 60, 100, 60). The sixth cell stays empty. The cell size does not change with the number of components; the program run gave the same bounds.

One of the row or column counts may be given as 0. new GridLayout(0, 2) means “two columns, as many rows as needed.” If five buttons are added to a 200 × 150 panel, three rows are formed. The cells are 100 × 50, and the fifth button is placed at (0, 100). If the number of components exceeds rows × columns and neither is zero, Java keeps the number of rows and increases the number of columns. When seven buttons are added to GridLayout(2, 3), the grid becomes 2 × 4 and the cells narrow to 75 pixels.

BoxLayout arranges components in a single row or a single column. Its constructor also takes the container it manages as a parameter: panel.setLayout(new BoxLayout(panel, BoxLayout.Y_AXIS)). Y_AXIS stacks components vertically and X_AXIS places them side by side. It is used in forms to line up labels and fields one under another.

Common mistake

Setting a component's position with setBounds or setLocation in a container that has a layout manager. The manager overwrites these values at the next layout computation, and the position you set is lost. To influence a component's size, use setPreferredSize. The manager takes this preference into account or not, depending on its rule.

9.5Application: the no-entry sign

9.5.1Goal and layers

This application writes a panel that draws the “no entry” traffic sign. The sign consists of four layers painted on top of one another:

  1. A green background (with setBackground).
  2. A large white circle (the outer ring).
  3. A red circle, slightly smaller.
  4. A white horizontal bar in the middle.

The program makes one important design decision: all measurements are computed from getWidth() and getHeight(). No fixed pixel values are used. When the window is enlarged, the sign grows with it and always stays in the center. The drawing is recomputed from scratch each time, according to the current size of the panel.

9.5.2The paintComponent code

public class NoEntrySign extends JPanel {
    @Override
    public void paintComponent(Graphics g) {
        super.paintComponent(g);
        var c = new Point(getWidth() / 2, getHeight() / 2); // center
        var r = Math.min(getWidth() / 2, getHeight() / 2) - 5; // radius
        var r2 = (int) (r * 0.9);   // inner radius
        var bw = (int) (r2 * 1.4);  // bar width
        var bh = (int) (r2 * 0.35); // bar height
        g.setColor(Color.WHITE);
        g.fillOval(c.x - r, c.y - r, 2 * r, 2 * r);
        g.setColor(Color.RED);
        g.fillOval(c.x - r2, c.y - r2, r2 * 2, r2 * 2);
        g.setColor(Color.WHITE);
        g.fillRect(c.x - bw / 2, c.y - bh / 2, bw, bh);
    }
}

The code computes five variables and then draws three shapes. The variables are declared with var. Since Java 10, var lets the compiler infer the type of a local variable from the expression on the right. Here the type of c is Point and the others are int. The classic form is Point c = new Point(…); int r = …;. var does not remove the type; the type is determined at compile time and never changes afterward.

Let us read the lines in order:

  • c: The center of the panel. The width and height are divided by two. Since both operands are int, integer division is used.
  • r: The radius of the outer circle. The distance from the center to the shorter side is chosen (Math.min), and a margin of 5 pixels is left. This way the circle does not spill outside the panel.
  • r2: The radius of the inner circle, 90% of r. r * 0.9 is a double; the (int) cast discards the fractional part.
  • bw and bh: The width and height of the bar, 1.4 and 0.35 times the inner radius.

The drawing is done in three steps. First the pen is switched to white and the outer circle is drawn. Then the pen is switched to red and the inner circle is drawn. The red circle is painted on top of the white one, so only a thin ring of white remains on the outside. Finally the pen is switched back to white and the bar is drawn. The bar is given by the top-left corner of its bounding rectangle: from the center, half the width to the left and half the height up.

The necessary imports are java.awt.* and javax.swing.*. Point, Graphics, and Color come from the first, and JPanel from the second.

9.6Mouse events and the event dispatch thread

9.6.1Interactive graphics and the event loop

Computer graphics is the process of creating and manipulating visual content. In interactive graphics, the user changes the image with input devices such as the mouse and keyboard. Drawing programs, games, and maps are of this kind. Graphics libraries provide drawing and coloring shapes; interaction is built with an event loop.

The steps in the loop are as follows. The user presses the mouse. The operating system detects this action and notifies Java. Java creates an event object and puts it in the event queue. The event dispatch thread takes the next event in the queue and calls the method of the listener registered with that component. The listener method updates the program's data and requests a redraw with repaint(). At a suitable moment Swing calls paintComponent, and the screen is drawn with the new data. The event dispatch thread moves on to the next event.

This loop has a rule: a listener method does not paint the screen directly. It only changes the data and requests a repaint. The drawing is always done by paintComponent. This separation keeps the drawing in one place and ensures that the correct picture appears every time the window is repainted.

9.6.2Listener interfaces and adapter classes

Definition 9.11

An event listener is an interface that defines the methods to be called when an event occurs, or an object that implements this interface. A listener object is registered with a component using an add…Listener method.

For mouse events, Java's interface is MouseListener. The interface has five abstract methods. If a class implements this interface, it must write all five methods. The bodies of the methods it is not interested in stay empty.

class ClickListener implements MouseListener {
    public void mouseClicked(MouseEvent e) {
        System.out.println("click");
    }
    public void mousePressed(MouseEvent e) { }
    public void mouseReleased(MouseEvent e) { }
    public void mouseEntered(MouseEvent e) { }
    public void mouseExited(MouseEvent e) { }
}

Four of the five methods are empty. For a class interested only in clicks, this is extra typing. Java offers ready-made classes for this situation.

Definition 9.12

An adapter class is a ready-made class that implements all the methods of a listener interface with empty bodies. A class derived from it overrides only the method it is interested in.

class ClickAdapter extends MouseAdapter {
    @Override
    public void mouseClicked(MouseEvent e) {
        System.out.println("click");
    }
}
// panel.addMouseListener(new ClickAdapter());

MouseAdapter is an abstract class, but it has no abstract methods; all its methods have empty bodies. The purpose of declaring it abstract is to prevent creating an object of it directly. MouseAdapter implements three interfaces at once: MouseListener, MouseMotionListener, and MouseWheelListener. A single subclass can thus handle click, motion, and wheel events.

Motion events are in a separate interface: MouseMotionListener. This interface has two methods: mouseDragged and mouseMoved. Its own adapter is MouseMotionAdapter. Registration is separate too: click-type events are registered with addMouseListener(…) and motion events with addMouseMotionListener(…).

The listener class does not even need to be written in a separate file. Java allows a single-use class to be defined where it is used.

Definition 9.13

An anonymous inner class is an inner class that has no name and whose single object is created where it is defined. The notation new MouseAdapter() { … } defines a nameless class derived from MouseAdapter and immediately creates an object of it.

Common mistake

Implementing an interface and not writing some of its methods. If class ClickListener implements MouseListener writes only mouseClicked, the compiler gives this error:

ClickListener.java:6: error: ClickListener is not abstract and does not override abstract method mouseExited(MouseEvent) in MouseListener
class ClickListener implements MouseListener {

The compiler names only one of the missing methods. Even if mousePressed is written too, the message still points to mouseExited; the message is not a list of the missing methods. The solution is either to write all five methods or to derive from MouseAdapter.

9.6.5The event dispatch thread (EDT)

The main of a Swing program is written with the SwingUtilities.invokeLater pattern. The reason for this pattern is Swing's relationship with threads.

Definition 9.14

The event dispatch thread (EDT) is the single thread on which Swing components are built and modified and on which events are processed. It runs the tasks in the event queue one at a time, in order. In Java 21 its name is AWT-EventQueue-0.

Swing components are not thread-safe. If several threads touch the same component at the same time, the internal state of the component can become inconsistent. Swing solves this problem not with locks but with a simple rule: components are built and modified only from the event dispatch thread. Listener methods already run on the EDT, so it is safe to touch components from inside them.

An analogy explains the rule. In the kitchen there is a single cook: the EDT. The waiters do not cook the food themselves; they leave an order slip. The slip is a Runnable object, that is, a piece of code to be run. The cook prepares the slips one at a time, in the order they arrive. Since there is only one cook, two dishes never enter the same pan at the same time.

Table 9.13: The two invocation methods of SwingUtilities.
MethodBehavior
invokeLater(task)Puts the task in the queue and returns immediately (asynchronous). The standard way to start a GUI.
invokeAndWait(task)Waits until the task finishes on the EDT (synchronous). If called from inside the EDT, it throws an Error: the EDT cannot wait for itself.

Calling invokeAndWait from inside the EDT really does throw an Error. If the EDT waited for a task it had itself put in the queue, nobody would be left to run that task, and the program would hang forever. Swing catches this in advance:

AWT-EventQueue-0 daemon=false
java.lang.Error: Cannot call invokeAndWait from the event dispatcher thread

The first line shows which thread the task run with invokeAndWait is on: AWT-EventQueue-0. This thread is not a daemon (background) thread. The JVM does not exit while a non-daemon thread is running. This is why a GUI program continues after main ends.

A button listener runs System.out.println("1"), SwingUtilities.invokeLater(() -> System.out.println("3")), and System.out.println("2") in that order. What is the output? Is the order certain?

1, 2, 3. The listener runs on the EDT. invokeLater puts the task at the end of the queue and returns; the listener prints 2 and finishes. Only after that can the EDT take the next task in the queue. Common mistake

Building the interface directly on the main thread. In small programs this often causes no problem, so the mistake goes unnoticed for a long time. But once the window becomes visible, the EDT starts running and can touch the same components as main. The result is rare, random drawing glitches or exceptions. There is only one safe pattern: SwingUtilities.invokeLater(() -> { … }).

9.7Application: a drawing program

This application is a program in which you draw by pressing and dragging the mouse. The principle is summarized in three sentences:

  • On a press (mousePressed), a new curve starts.
  • As the mouse is dragged (mouseDragged), points are added to the end of the curve and a repaint is requested.
  • When painting (paintComponent), the consecutive points of each curve are joined with lines.

The basic design decision of the program is to store the drawing not as an image but as a list of points. The screen is redrawn from this data each time. The drawing is not lost even if the window is minimized and restored, or another window passes over it and is dragged away. Separating the data from the picture applies the rule of the event loop: listeners change the data, and paintComponent draws the data.

9.7.1Storing the curves

public class SimpleDrawPanel extends JPanel {
    private List<List<Point>> curves = new ArrayList<>();

    public SimpleDrawPanel() {
        addMouseListener(new MouseAdapter() {
            @Override
            public void mousePressed(MouseEvent e) {
                var curve = new ArrayList<Point>();
                curve.add(new Point(e.getX(), e.getY()));
                curves.add(curve);
            }
        });
        addMouseMotionListener(new MouseMotionAdapter() {
            @Override
            public void mouseDragged(MouseEvent e) {
                curves.get(curves.size() - 1)
                       .add(new Point(e.getX(), e.getY()));
                repaint(0, 0, getWidth(), getHeight());
            }
        });
    }
}

The class's only field is curves. Its type is List<List<Point>>, a list of lists. The outer list holds the curves. Each inner list holds the points of one curve in order.

The constructor registers two listeners. The first is an anonymous class derived from MouseAdapter that writes only mousePressed. The method creates a new, empty list of points, adds the pressed point to the list, and puts the list in the outer list. The second listener is derived from MouseMotionAdapter and writes only mouseDragged. The method takes the last element of the outer list, that is, the most recently started curve, and appends the new point to it. Then it has the panel repainted.

The last curve is reached with curves.get(curves.size() - 1). Since list indices start at 0, the index of the last element is size() - 1. get(size()) always asks for one position past the end of the list.

Common mistake

Asking for the last element with get(size()). When the list holds one curve, this call throws the following exception:

java.lang.IndexOutOfBoundsException: Index 1 out of bounds for length 1

The error is not caught at compile time; it appears on the first drag. The correct index is size() - 1.

The code has an import trap as well. If java.awt.* and java.util.* are imported together, the name List exists in both packages: java.awt.List is a list-box component, whereas java.util.List is the collection interface. The compiler cannot tell which one is meant:

Main.java:4: error: reference to List is ambiguous
  List<String> x;
  both interface java.util.List in java.util and class java.awt.List in java.awt match

The solution is to import the intended class explicitly as well: import java.util.List;. A single-type import takes precedence over an on-demand (star) import.

The repaint method is used in two forms, and both are only requests:

  • repaint() does not paint immediately; it puts a “repaint” request in the queue. Consecutive requests can be merged into a single painting. While the mouse produces dozens of events per second, this merging prevents unnecessary drawing.
  • repaint(x, y, w, h) asks for only that rectangle to be repainted. Swing clips everything outside this region: g does not paint outside the region, and the work is reduced. repaint(0, 0, getWidth(), getHeight()) is the same as repaint().
Definition 9.15

repaint() is the method that leaves a request in the event queue for a component to be redrawn. At a suitable moment Swing calls the component's paintComponent method. The programmer does not call paintComponent directly; the programmer changes the data and requests repaint().

Common mistake

Calling paintComponent(getGraphics()) from inside a listener. This call bypasses Swing's painting machinery. Double buffering, that is, preparing the image in memory first, is switched off, and the picture may flicker. At the next real painting, everything drawn is erased as well. The correct way is repaint().

9.8Buttons and text components

9.8.1The JButton class

JButton creates clickable buttons. Its text is set with setText() and its icon with setIcon(). setEnabled(false) disables the button: it looks faded and produces no event when clicked.

To respond to a click on a button, a listener is added with addActionListener(). The listener implements the ActionListener interface. This interface has a single method: actionPerformed(ActionEvent e). A button can also be triggered with the space bar; the same method is called in both cases. That is why we listen for an “action” event, not a mouse event, on a button.

Adding a listener is an example of the Observer design pattern. The button is the “subject”; it keeps a list of the observers registered with it. When a click occurs, it notifies every observer in the list. The button does not know what the observers do. To add new behavior, you do not need to touch the button's code; you only register a new observer.

class CounterPanel extends JPanel {
    private int count = 0;
    private JLabel label = new JLabel("Not clicked yet");

    CounterPanel() {
        JButton button = new JButton("Click");
        button.addActionListener(e -> {
            count++;
            label.setText(count + " click(s)");
        });
        add(button);
        add(label);
    }
}

9.8.3Anonymous classes and lambdas

The same listener can be written in two forms. The classic form is an anonymous inner class:

button.addActionListener(new ActionListener() {
    @Override
    public void actionPerformed(ActionEvent e) {
        count++;
        label.setText("Count: " + count);
    }
});

Since Java 8, the same job can be written with a lambda expression:

button.addActionListener(e -> {
    count++;
    label.setText("Count: " + count);
});

// one expression: no braces needed
button.addActionListener(e -> System.exit(0));

A lambda can be used because of the structure of ActionListener: the interface has only one abstract method.

Definition 9.16

A functional interface is an interface with a single abstract method. A lambda expression is taken as the body of the single method of such an interface: e -> … is the body of actionPerformed(e).

The compiler looks at the parameter type of addActionListener, sees ActionListener, and finds its single method. The lambda's parameter e becomes the ActionEvent parameter of that method. If the body is a single expression, the braces are not needed either: button.addActionListener(e -> System.exit(0));.

Since MouseListener has five methods, it cannot be written as a lambda. The compiler cannot tell which method's body is being written:

Main.java:9: error: incompatible types: MouseListener is not a functional interface
  p.addMouseListener(e -> System.out.println("click"));
    multiple non-overriding abstract methods found in interface MouseListener

That is why an adapter class is used for mouse events.

A lambda has one more limitation: a local variable cannot be modified from inside it. A lambda captures (copies) the value of the local variable it uses; it is not bound to the variable itself. For this reason a local variable must be final or “effectively final,” that is, never changed after it is defined.

Common mistake

Keeping the counter in a local variable: int count = 0; … b.addActionListener(e -> count++);. The compiler gives this message:

Main.java:10: error: local variables referenced from a lambda expression must be final or effectively final
  b.addActionListener(e -> count++);

A value that changes, such as a counter, must be a field of the class. Fields belong to the object; the lambda holds a reference to the object and can change the field. The counter panel therefore uses the field private int count.

9.8.4JLabel and JTextField

JLabel is a label. It displays text or an image; the user cannot change it. setText() sets the text, setIcon() the image, setFont() the font, and setForeground() the text color.

JTextField is a single-line text field. It is for the user to enter text; data from forms is collected this way. getText() and setText() read and write the field. setColumns() sets the number of visible columns. This number affects the preferred width of the field; it does not limit the length of text it can hold. In headless mode, a 12-column field asked for a width of 136 pixels and a 24-column field for 268. A listener added with addActionListener() runs when the user presses Enter in the field.

9.9Application: a text converter

This application converts the text in a text area to lowercase or uppercase with two buttons. The layout of the window is a good example of using two layout managers together:

  • In the center (CENTER) there is a JTextArea of 8 rows × 50 columns inside a JScrollPane.
  • At the bottom (SOUTH) there is a JPanel holding two buttons. Since the panel uses FlowLayout, the buttons are centered and side by side.
  • pack() computes the window size from the preferred sizes of these components.
  • The buttons convert the text with toLowerCase() or toUpperCase() and write it back to the area.
import java.awt.BorderLayout;
import javax.swing.*;

public class CaseConverter {
    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> {

            var lowerButton = new JButton("To Lowercase");

            panel.add(upperButton);

The whole interface is built inside a single lambda, on the EDT. First the text area and the two buttons are created. A listener is added to each button. The listener reads the text of the area, converts it, and writes the result back to the area. Then the buttons are put in a panel. The window is created, the scroll pane is added to the center and the button panel to the south. pack() computes the size, and the window is shown.

The code has three details:

  • area is a local variable, but it can be used inside the lambda. After it is defined, the variable is never redirected to another object; it is effectively final. The lambda uses not the variable area itself but the object it refers to, and it changes the text of that object.
  • toUpperCase() returns a new String. Since String is immutable, the original text does not change; the result must be written back to the area with setText. If area.getText().toUpperCase(); were written alone, nothing on the screen would change.
  • BorderLayout.CENTER is written with its full name. Writing only CENTER does not compile, because the constant is inside the BorderLayout class.

9.9.1What happens on a click?

Between the user's click on the “To Uppercase” button and the text changing on the screen, there are six steps.

  1. The user clicks the button; the operating system passes this to Java.
  2. Java creates an event object and puts it in the event queue.
  3. The EDT takes the next event. The button calls actionPerformed of all registered ActionListeners: our lambda runs.
  4. area.getText() reads the current text.
  5. toUpperCase() produces a new string; the old string does not change.
  6. setText updates the model of the area. The area has itself repainted with repaint. The EDT moves on to the next event.

Step 6 mentions the word “model.” In Swing, text components consist of two parts: a model that holds the text and a view that displays it on the screen. setText changes the model; the view notices the change and has itself redrawn. The change calculator application uses this separation directly.

9.9.2Uppercase and locale

When toUpperCase() and toLowerCase() are called without arguments, they use the computer's locale. Turkish is one of the languages with special rules for letter case conversion: there are two separate letters “i,” dotted and dotless. On a machine with English settings, "istanbul".toUpperCase() gives "ISTANBUL"; with Turkish settings it gives "İSTANBUL". The same program gives different results depending on the computer it runs on.

In Turkish rules, i → İ, ı → I, İ → i, and I → ı. In English rules, both ı and i become I in uppercase, while İ stays as it is. That is why the third line is KIŞ İZMIR. The last line shows once more that strings are immutable: after the three conversions, s is still "Kış İzmir".

Basing the logic of a program on a locale-dependent conversion. In a plain text field there is no style, so changedUpdate is never called. But all three methods of the interface are abstract, and all three must be written. All three do the same thing: they call updateReport().

If the field has text, two events arrive. At the first event the field is momentarily empty and the report shows the error message; the second event writes the correct report.

A negative number reveals a deficiency. -7 is a valid integer. In Java, integer division truncates toward zero and the remainder takes the sign of the dividend: -7 / 5 = -1, -7 % 5 = -2. The report contains meaningless lines such as -1 x 5c and -2 x 1c:

-7 cents in coins:
0 x 50c
0 x 25c
0 x 10c
-1 x 5c
-2 x 1c

The program should reject the negative value. A check right after parseInt is enough: if (amount < 0) { report.setText("Amount must be positive"); return; }.

The two catch blocks have different jobs. The first catches the expected error, that is, text that is not a number and values beyond the int limit. The second is a general safeguard for everything else. This block is necessary because getText(0, n) declares that it may throw BadLocationException, a checked exception. The compiler requires this exception to be handled; catch (Exception e) covers it too.

Example 9.15

What does the report show when 68 is typed into the change program?

68 / 50 = 1, remainder 18. 18 / 25 = 0, remainder 18. 18 / 10 = 1, remainder 8. 8 / 5 = 1, remainder 3. 3 / 1 = 3. The report begins with the line “68 cents in coins:” and continues with five lines:

68 cents in coins:
1 x 50c
0 x 25c
1 x 10c
1 x 5c
3 x 1c

9.11Best practices

A few habits determine the quality of GUI programs.

Use a layout manager
Do not give coordinates by hand. With a layout manager, the layout does not break at a different screen size, resolution, or font. Complex layouts are built with nested panels.
Choose meaningful names
Use names such as upperButton and amountField instead of b1 and t2. In an interface with dozens of components, the code stays readable only this way.
Think in terms of events
Design starts from the question “What should happen when the user does this?” A listener is written for each action; listeners do not rely on one another's order.
Separate the interface from the business logic
Rules such as the change calculation are kept in a separate method or class. That way they can be tested without the interface and used in another interface. Most of the outputs given in this chapter were obtained without opening a window, thanks to this separation.
Build the interface on the EDT
The body of main is a single call: SwingUtilities.invokeLater(() -> { … }).
Do not keep the EDT busy
If a listener does a long job (downloading a file, a large computation), the EDT cannot process any other event for that time and the window freezes. Such jobs are moved to a separate thread; the result is handed back to the EDT with invokeLater.
Example 9.16

How can the change calculation be separated from the interface?

The calculation is moved to a static method that takes an amount as input and returns the counts:

static int[] makeChange(int amount) {
    int[] coins = {50, 25, 10, 5, 1};
    int[] counts = new int[coins.length];
    for (int i = 0; i < coins.length; i++) {
        counts[i] = amount / coins[i];
        amount %= coins[i];
    }
    return counts;
}

updateReport now only reads the text, calls this method, and writes the result to the report. The method itself can be tried directly in a console program or a test: makeChange(93) returns [1, 1, 1, 1, 3].

9.12Solved problems

Example 9.17 (Problem 1)

If a button A and then a button B are added to the same NORTH region of a panel that uses BorderLayout, which one is visible in the north?

B. Each region holds a single component; the last one added wins. A remains in the panel (the component count is 2) but takes no part in the layout. In headless mode, on a 200 × 100 panel, B came out as (0, 0, 200, 26) and A as 0 × 0.

Example 9.18 (Problem 2)

If the user clicks the panel once and releases, which methods of MouseListener are called, and in what order?

mousePressed → mouseReleased → mouseClicked. If the pointer enters the panel from outside, mouseEntered arrives as well. If the mouse moves between the press and the release, mouseDragged events come in between and mouseClicked may not arrive.

Example 9.19 (Problem 3)

Which color does Color.RED.brighter() give?

Again (255, 0, 0). The red component is already at the maximum; 255 / 0.7 = 364 is capped at 255. The green and blue components are 0, and 0 / 0.7 = 0 stays.

Example 9.20 (Problem 4: a target)

A target made of five nested red and white rings, scaled to the size of the panel, is to be drawn. How is paintComponent written? Which calls are made on a 300 × 200 panel?

The center and the largest radius are computed as in the sign. In each round the loop reduces the radius by one fifth and alternates the colors:

int cx = getWidth() / 2, cy = getHeight() / 2;
int r = Math.min(cx, cy) - 5;
for (int i = 0; i < 5; i++) {
    int ri = r - i * r / 5;
    g.setColor(i % 2 == 0 ? Color.RED : Color.WHITE);
    g.fillOval(cx - ri, cy - ri, 2 * ri, 2 * ri);
}

On 300 × 200, cx = 150, cy = 100, and r = 95. i * r / 5 is evaluated left to right: first the multiplication, then the integer division. The radii are 95, 76, 57, 38, and 19; the calls are fillOval(55, 5, 190, 190), (74, 24, 152, 152), (93, 43, 114, 114), (112, 62, 76, 76), and (131, 81, 38, 38). The circles are drawn from largest to smallest. If they were drawn from smallest to largest, the last, large circle would cover all the others.

Example 9.21 (Problem 5: undo with the right button)

In the drawing program, let a right click delete the last curve, and let dragging with the right button not draw anything. Which changes are needed?

A check is added at the beginning of mousePressed. If it is the right button, the last curve is removed and the method returns:

if (e.getButton() == MouseEvent.BUTTON3) {
    if (!curves.isEmpty()) curves.remove(curves.size() - 1);
    repaint();
    return;
}

At the beginning of mouseDragged, write if (!SwingUtilities.isLeftMouseButton(e)) return; as well. Without this line, dragging with the right button would add points to the previous curve in place of the one just deleted. When the list is empty, a right drag would throw IndexOutOfBoundsException: Index -1 out of bounds for length 0 through get(-1). The changes were tried by sending events in headless mode: after two curves were drawn, a right click reduced the number of curves to 1, and a right drag changed no points.

Example 9.22 (Problem 6: a temperature converter)

When °C is entered in a JTextField and a button is pressed, °F should be shown. How is the listener written?

convert.addActionListener(e -> {
    try {
        double c = Double.parseDouble(field.getText());
        result.setText(c * 9 / 5 + 32 + " °F");
    } catch (NumberFormatException ex) {
        result.setText("Not a number");
    }
});

When 100 is entered, 212.0 °F is shown; when −40 is entered, -40.0 °F is shown; −40 is the only temperature at which the two scales are equal. When abc is entered, parseDouble throws NumberFormatException and “Not a number” appears. In the expression c * 9 / 5 + 32 + " °F" the order matters: the numeric operations are done first, from left to right, and the string is appended last. The exception parameter inside the lambda is named ex instead of e, because e is already the lambda's parameter.

Two smaller exercises use the same patterns. In a counter window, the buttons “−1,” “+1,” and “Reset” change a private int count field and update the label. After two clicks on “+1” and one on “−1,” the label shows 1; after “Reset,” it shows 0. To add a “Clear” button to the drawing program, the button's listener runs curves.clear(); repaint();. The panel and the button go in the CENTER and SOUTH regions of the window.

9.14Summary

  • A GUI program is event-driven: main only builds the interface, and the user's actions determine the flow. Most of the code consists of listeners.
  • The java.awt package contains Graphics, Color, Font, Point, the layout managers, and the event classes; the javax.swing package contains the components whose names start with J. Java itself draws the Swing components.
  • In screen coordinates, (0, 0) is the top-left corner of the component; x grows to the right and y downward.
  • For permanent drawing, derive from JPanel and override paintComponent(Graphics g). The first line of the body is super.paintComponent(g). Swing calls the method.
  • The draw… methods draw outlines and the fill… methods draw filled shapes. Ellipses and circles are given by their bounding rectangle: a circle with center (cx, cy) and radius r is fillOval(cx − r, cy − r, 2r, 2r). The y of drawString is the baseline.
  • A Graphics object remembers its color and font; setColor and setFont affect all later drawing. A shape drawn later covers an earlier one.
  • JFrame is a top-level window. The size is given with setSize or pack(), the close behavior is set with setDefaultCloseOperation(EXIT_ON_CLOSE), and setVisible(true) is called last. The default close behavior is HIDE_ON_CLOSE.
  • JPanel is both a container and a canvas; its default layout manager is FlowLayout. The content pane of a JFrame uses BorderLayout.
  • The fields x and y of Point are public int; getX() and getY() return double. translate moves relatively and setLocation moves absolutely.
  • Color is created from an RGB triple (0–255); it is immutable. darker() multiplies the components by 0.7 and brighter() divides them by 0.7; both truncate the result to integers and are not exact inverses of each other.
  • Font(name, style, size); the style constants are bit flags: BOLD | ITALIC = 3. deriveFont(float) changes the size and deriveFont(int) changes the style.
  • A layout manager computes the position and size of components by a rule. add only appends to the list; placement happens when the layout is computed.
  • FlowLayout arranges components row by row, centered, with a 5-pixel gap. BorderLayout places them in five regions: one component per region, the last one added wins, and the center takes the rest. GridLayout divides the container into equal cells. BoxLayout builds a single row or a single column.
  • A listener interface defines the methods for an event; a listener is registered with add…Listener. MouseListener reports press, release, click, enter, and exit; MouseMotionListener reports movement and dragging. Registration is by interface.
  • An adapter class (MouseAdapter) implements all the methods with empty bodies; a subclass writes only what it needs. An anonymous inner class suits a single-use listener.
  • A click produces pressed → released → clicked. MouseEvent gives the position relative to the component; getButton() tells the button (BUTTON3 is the right one).
  • Swing is single-threaded: components are built and modified only on the EDT. invokeLater puts a task in the queue and returns; invokeAndWait waits until the task finishes and throws an Error if called from inside the EDT. The queue is ordered.
  • A listener does not draw on the screen; it updates the data and requests repaint(). repaint() is a request; Swing calls paintComponent at a suitable moment.
  • ActionListener is a functional interface with a single method and can be written as a lambda. A local variable cannot be modified from inside a lambda; values that change become fields.
  • JLabel shows text, JTextField takes a single line and JTextArea multiple lines of text, and JScrollPane scrolls. getLineCount() is one more than the number of line breaks.
  • toUpperCase() depends on the locale; in Turkish, i → İ. To fix the result, give the locale explicitly.
  • In text components the model (Document) and the view are separate. A DocumentListener is called on every insertion and removal; setText produces two events on a non-empty field.
  • Best practices: use a layout manager, choose meaningful names, separate the business logic from the interface, build the interface on the EDT, and do not keep the EDT busy with long jobs.

9.16Test Yourself

  1. What is the bottom-right pixel painted by the calls g.drawRect(10, 20, 30, 40) and g.fillRect(10, 20, 30, 40)?

    Answer

    (40, 60) for drawRect and (39, 59) for fillRect. The outline also draws the right and bottom edge of the bounding rectangle and so is w + 1 pixels wide. The filled rectangle paints exactly w × h pixels. Both values were found by counting the painted pixels on an image.

  2. Which components does new Color(10, 20, 30).brighter() give?

    Answer

    (14, 28, 42). Each component is divided by 0.7 and truncated: 10 / 0.7 = 14.28 → 14; 20 / 0.7 = 28.57 → 28; 30 / 0.7 = 42.85 → 42. No component reaches 255, so the cap does not apply.

  3. A 300 × 200 pixel panel uses new BorderLayout(5, 5). Components preferring a height of 30 in the north and 20 in the south, a width of 60 in the west and 40 in the east, and one component in the center are added. What are the bounds of the center component?

    Answer

    (65, 35, 190, 140). The center starts to the right of the west region with a 5-pixel gap: x = 60 + 5. It starts below the north region with a 5-pixel gap: y = 30 + 5. The width is 300 − 60 − 40 − 2 × 5 = 190 and the height is 200 − 30 − 20 − 2 × 5 = 140. West and east have the same height and are at y = 35.

  4. The paintComponent method of the no-entry sign runs on a 300 × 300 pixel panel. What are r, r2, bw, and bh?

    Answer

    r = min(150, 150) − 5 = 145. r2 = (int) 130.5 = 130. bw = (int) (130 × 1.4) = 182. bh = (int) (130 × 0.35) = (int) 45.5 = 45. Truncation discards the half as well; with rounding the result would have been 46.

  5. What are the counts in the report when 41 is typed into the change program?

    Answer

    0 × 50, 1 × 25, 1 × 10, 1 × 5, 1 × 1. 41 / 50 = 0 (remainder 41), 41 / 25 = 1 (remainder 16), 16 / 10 = 1 (remainder 6), 6 / 5 = 1 (remainder 1), 1 / 1 = 1. Four coins in all.

  6. Does the following code compile?

    String name = " Ayşe ";
name = name.trim();
JButton b = new JButton("x");
b.addActionListener(e -> System.out.println(name));
    Answer

    It does not compile: local variables referenced from a lambda expression must be final or effectively final. The lambda only reads name, but because name is reassigned on the second line, it is not effectively final. The fix is to put the trimmed value in a new variable: String clean = name.trim(); and use clean inside the lambda.

  7. A MouseAdapter object that overrides only mouseClicked is registered with a panel using addMouseMotionListener. Does the method run when the panel is clicked?

    Answer

    It does not. Because MouseAdapter implements three interfaces at once, the registration compiles, but the panel recognizes this object only as a motion listener. Click events go only to listeners registered with addMouseListener. When a click event was sent to the panel, the method was called 0 times.

  8. What does getLineCount() return for a JTextArea whose text is "a\n\nb\n"?

    Answer

    4. The text has three line breaks: “a,” an empty line, “b,” and an empty line after the last line break. The line count is one more than the number of line breaks.
