Öğrenme Çıktıları

Kavram

İstisnayı (exception) tanımlamak; derleme, çalışma zamanı ve mantık hatalarını ayırt etmek.

Yakalama

try, catch, finally ve try-with-resources ile istisnaları ele almak; akışı adım adım izlemek.

Hiyerarşi

Throwable, Error, Exception, RuntimeException ilişkisini ve catch sırasının önemini açıklamak.

Türler

Kontrol edilen (checked) ve kontrol edilmeyen (unchecked) istisnaları ayırmak; “ele al veya bildir” kuralını uygulamak.

Fırlatma

throw ile istisna fırlatmak, throws ile bildirmek; istisnanın çağrı yığınında yayılımını izlemek.

Uygulama

Yaygın istisna sınıflarını tanımak, özel istisna sınıfı yazmak ve izleme listesini (stack trace) okumak.

İstisna Kavramı

İstisna Nedir?

  • İstisna (exception): program çalışırken ortaya çıkan, programın normal akışını bozan beklenmeyen bir durumdur.
  • Örnek: açılmak istenen dosyanın bulunamaması, sıfıra bölme, dizinin dışına erişim, null bir referansın kullanılması.
  • İstisnalar Java çalışma zamanı sistemi (JVM) tarafından otomatik olarak ya da programcı tarafından kodla (throw) oluşturulabilir.
  • Java'da istisna bir nesnedir: türünü, mesajını ve nerede oluştuğunu taşır.
  • İstisna mekanizması, programcıya anormal durumlarla düzenli bir şekilde başa çıkma şansı verir.
Java bir istisnayla karşılaştığında kabaca şunu der: “Pes ettim, şu an ne yapacağımı bilmiyorum. Sen hallet!”
Benzetme

Garson mutfakta yemeğin bittiğini öğrenir. Kendisi çözemez; durumu yöneticiye bildirir. Yönetici ya çözer (başka yemek önerir) ya da durumu bir üste iletir.

İstisna Kavramı

İstisnayla Başa Çıkmanın İki Yolu

1) Ele almak (handle)

Metot, istisna oluşturabilecek kodu try içine alır ve catch ile durumu kendisi çözer.

Örnek: dosya okuma metodu, dosya bulunamazsa (FileNotFoundException) kullanıcıya mesaj gösterip varsayılan ayarlarla devam eder.

2) Çağıranın sorunu yapmak (declare)

Metot istisnayı ele almaz; imzasında throws ile bildirir. İstisna, metodu çağıran kodun sorunu olur.

Çağıran kod da aynı seçimle karşılaşır: ya ele alır ya da bir üste iletir.

Hangi yol? İstisnayı anlamlı biçimde çözebilecek yer ele almalıdır. Örneğin dosya adını kullanıcıdan alan kod, “dosya yok” durumunda yeniden sorabilir; düşük seviyeli okuma metodu ise bunu bilemez.

try ve catch

Çoklu catch Bloğu

try {
  // Potansiyel hata içeren kodlar
} catch (ArithmeticException e) {
  // ArithmeticException ile başa çıkma
} catch (NullPointerException e) {
  // NullPointerException ile başa çıkma
} catch (Exception e) {
  // Diğer hata türleri için genel durum
}
  • Bir kod bloğunda birden çok türde istisna oluşabilir.
  • Her hata türü için ayrı bir catch bloğu eklenir; her blok o türe özgü tepkiyi içerir.
  • İstisna fırlatıldığında catch blokları yukarıdan aşağıya sırayla denenir; eşleşen ilk blok çalışır, diğerleri atlanır.
  • “Eşleşmek”: fırlatılan nesne, catch'teki türün kendisi veya alt sınıfıdır (instanceof mantığı).
  • Son sıradaki catch (Exception e) geri kalan tüm istisnaları yakalayan genel durumdur.

Hangi catch Çalışır?

1. çağrı: parseInt("abc") → NumberFormatException. Bölme satırı atlanır.

İlk catch eşleşir ve çalışır; diğer catch'lere bakılmaz.

Ardından finally.

2. çağrı: 10 / 0 → ArithmeticException.

1. catch eşleşmez (✗), 2. catch eşleşir (✓).

3. çağrı: dizinin tek elemanı var; girdi[1] → ArrayIndexOutOfBoundsException.

İlk iki catch eşleşmez, üçüncüsü eşleşir; sonra finally.

static void bol(String[] girdi) {
  try {
    int x = Integer.parseInt(girdi[0]);
    int y = Integer.parseInt(girdi[1]);
    System.out.println("Sonuç: " + (x / y));
  } catch (NumberFormatException e) {
    System.out.println("Sayı değil: " + e.getMessage());
  } catch (ArithmeticException e) {
    System.out.println("Sıfır: " + e.getMessage());
  } catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Eksik: " + e.getMessage());
  } finally {
    System.out.println("finally çalıştı");
  }
}
// main içinde
bol(new String[] {"10", "abc"});
bol(new String[] {"10", "0"});
bol(new String[] {"10"});

finally Bloğu

try {
  // Potansiyel hata içeren kodlar
} catch (Exception e) {
  // Diğer hata türleri için genel durum

  // Her durumda çalıştırılacak kodlar

  • try ve catch bloklarının ardından eklenir.
  • İstisna olsun veya olmasın, yakalansın veya yakalanmasın, her durumda çalışır.

  • Kodun belirli adımlarının çalışmasını güvence altına alır: dosya, ağ ve veritabanı bağlantılarını kapatmak gibi kaynak yönetimi ve temizlik işleri.
  • try'dan sonra en az bir catch veya finally gelmelidir; try { } finally { } geçerlidir.
  • Tek istisna: System.exit() JVM'i hemen durdurur; finally çalışmaz.

İç İçe try Blokları

try {
  // Dıştaki try bloğu
  try {
    // İçteki try bloğu
    // Potansiyel hata içeren kodlar
  } catch (Exception e) {
    // İçteki catch bloğu
  } finally {
    // İçteki finally bloğu
  }
} catch (Exception e) {
  // Dıştaki catch bloğu
} finally {
  // Dıştaki finally bloğu
}

Bir try bloğu içinde başka bir try bloğu bulunabilir. İçteki try'da bir istisna oluşursa:

  1. İçteki try'ın catch'lerinde uygun bir catch varsa o çalışır.
  2. Yoksa istisna dışa doğru ilerler; ilk uygun catch bulunur ve çalışır.
  3. Hiçbir catch eşleşmezse istisna metottan çıkar; sonunda kimse yakalamazsa JVM'in varsayılan işleyicisi programı sonlandırır.
  4. Her durumda, istisnanın geçtiği her seviyedeki finally (varsa) çalışır.

İç İçe try: İstisna Dışa Doğru İlerler

Dış try başlar.

İç try başlar; s = null.

null üzerinde metot çağrısı → NullPointerException.

İç catch yalnızca ArithmeticException yakalar: eşleşmez.

İstisna dışarı çıkmadan önce iç finally çalışır.

İstisna dış seviyeye geçti; “Dış try devam” atlandı. Dış catch eşleşir.

Dış finally çalışır.

İstisna ele alındı; program normal devam eder.

public static void main(String[] args) {
  try {
    System.out.println("Dış try");
    try {
      System.out.println("İç try");
      String s = null;
      System.out.println(s.length());
    } catch (ArithmeticException e) {
      System.out.println("İç catch");
    } finally {
      System.out.println("İç finally");
    }
    System.out.println("Dış try devam");
  } catch (NullPointerException e) {
    System.out.println("Dış catch: NPE");
  } finally {
    System.out.println("Dış finally");
  }
  System.out.println("Program sürüyor");
}

İstisna Hiyerarşisi

İstisnalar Hiyerarşisi

  • Java'da istisna sınıfları bir sınıf hiyerarşisi içindedir.
  • Throwable sınıfı, fırlatılabilen her şeyin atasıdır: yalnızca Throwable ve alt sınıflarının nesneleri throw edilebilir ve catch ile yakalanabilir.
  • Throwable'ın iki doğrudan alt sınıfı vardır: Error ve Exception.
  • Bir catch bloğu, yazılan türü ve tüm alt sınıflarını yakalar (kalıtımın doğal sonucu).
  • Java, yeni özel istisna sınıfları oluşturmayı destekler: uygulamaya özgü durumlara uyan sınıflar bu hiyerarşiye eklenir.
Neden hiyerarşi?

Aynı aileden istisnalar tek bir üst türle yakalanabilir: catch (IOException e) hem FileNotFoundException'ı hem de diğer giriş/çıkış hatalarını yakalar.

İstisna Hiyerarşisi

Error ve Exception

Error

  • Programın kurtarılamayacak ciddi bir sorunla karşılaştığını belirtir.
  • Bu durumlarla başa çıkmak çoğunlukla mümkün değildir; genellikle programın sonlanmasına yol açar.
  • Örnek: program belleğinin tükenmesi (OutOfMemoryError), çağrı yığınının taşması, disk sürücüsünün “kaybolması” gibi aşırı durumlar.
  • Uygulama kodunda yakalanması önerilmez.

Exception

  • Programın öngörebileceği ve çoğu zaman kurtarabileceği durumlar.
  • Dosya yok, ağ koptu, geçersiz girdi, null referans…
  • try-catch ile ele alınması beklenen türdür.
  • Alt sınıfı RuntimeException, çoğunlukla programcı hatalarını temsil eder.

Her ikisi de Throwable'dan türer; bu yüzden ikisi de fırlatılabilir. Ama “ele alınmalı” olan, Exception ailesidir.

İstisna Türleri

İstisna Türleri

Kontrol edilen (checked exceptions)

Derleme zamanında derleyici denetler; programcı ele almak ya da bildirmek zorundadır. Ortaya çıkabileceği önceden bilinen durumlar.

Kontrol edilmeyen (unchecked exceptions)

Derleme zamanında denetlenmez; çalışma zamanında ortaya çıkar. RuntimeException, Error ve alt sınıfları.

İstisna Türleri

Kontrol Edilen İstisna (Checked)

  • Kod tarafından ele alınması veya bildirilmesi gerekir: “catch or declare” (yakala ya da bildir) kuralı.
  • Metodun başında throws ile belirtilmeli veya try-catch içinde ele alınmalıdır.
  • Exception'dan türer ama RuntimeException'dan türemez.
  • Bu kural derleme zamanında denetlenir: uyulmazsa program derlenmez.
  • Örnek: var olmayan bir dosyayı okumaya çalışmak. Program ne kadar doğru yazılsa da dosya silinmiş olabilir; bu yüzden derleyici bir plan ister.

İstisna Fırlatma

İstisna Fırlatma (Throwing an Exception)

  • Java çalışma zamanı beklenmeyen bir durumla karşılaştığında, üst seviyedeki kodlara bildirmek için bir istisna nesnesi oluşturur ve fırlatır.
  • Programcı da aynısını throw anahtar kelimesiyle yapabilir.
  • İstisna, normal program akışını değiştirir: throw'dan sonraki satırlar çalışmaz; denetim uygun catch'e geçer.
  • Fırlatılabilen birçok tür vardır: IOException, NullPointerException, IllegalArgumentException, kendi özel sınıflarınız…
  • Fırlatılan istisna, çağıran kod tarafından try-catch ile yakalanabilir. Hiçbir yerde ele alınmazsa JVM programı sonlandırır ve neyin yanlış gittiğini, nerede olduğunu bildirir.

Söz dizimi

throw new Exception("Bu bir istisna durumu!");

new ile istisna nesnesi oluşturulur (yapıcıya mesaj verilir), throw ile fırlatılır.

try {
  throw new Exception("Bu bir istisna durumu!");
} catch (Exception e) {
  System.out.println(e);
}
Çıktı

İstisna Fırlatma

JVM İstisnayı Nasıl Ele Alır?

  1. JVM (veya throw) bir istisna nesnesi oluşturur: türü, mesajı ve oluştuğu yerin izleme listesi (stack trace) içindedir.
  2. İstisnanın oluştuğu metotta, onu saran bir try ve uyumlu bir catch aranır.
  3. Bulunamazsa metot o anda sona erer (varsa finally çalışır) ve istisna çağıran metoda geçer. Arama, çağrı yığınında aşağıya doğru sürer.
  4. Uygun bir catch bulunursa o çalışır; program catch'ten sonra devam eder.
  5. main de yakalamazsa JVM'in varsayılan işleyicisi izleme listesini yazdırır ve programı (o iş parçacığını) sonlandırır.
Bu arama sürecine yığın çözülmesi (stack unwinding) denir. Yakalanan istisna nesnesi catch bloğu bitince artık kullanılmaz ve çöp toplayıcı (garbage collector) tarafından temizlenir.
