Problem Solving

Algorithm First, Then Code

  • Step 1: A clear problem definition is the key to success: what is given, what is wanted?
  • Step 2: The algorithm gives step-by-step directions for solving the problem. Choosing the right one makes the program efficient.
  • Step 3: With the algorithm settled, we code it in the chosen language (Java, for us).
  • Step 4: Test cases verify the program and expose bugs; go back to earlier steps when needed.

Problem Solving

What Is an Algorithm?

Algorithm: a finite, ordered sequence of clear steps that solves a problem.

  • The word comes from the Latin spelling of the name of the 9th-century mathematician al-Khwarizmi.
  • A computer does not understand algorithms; it runs one once we translate it into a programming language.
  • Several algorithms may solve the same problem; we compare them by speed and memory.
Analogy: a recipe is an algorithm. The ingredients are the input, the steps the algorithm, the dish the output. A vague step like "add a little salt" is not good enough for a computer.
Input

Zero or more initial values.

Output

At least one result.

Definiteness

Every step is clear and unambiguous.

Finiteness

It ends after finitely many steps.

Effectiveness

Every step can actually be carried out.

The Fibonacci Sequence

Start
    // Enter the number of terms
    Read n

    a = 0
    b = 1

    If n ≥ 2 then Print b
    // Compute the remaining terms
    For i = 2 to n − 1
        result = a + b
        a = b
        b = result
        Print result
    End For
End

Definition: the first two terms are 0 and 1; each later term is the sum of the previous two.

The loop runs n − 2 times, for i = 2 … n − 1; the first two terms print before it. The lines a = b and b = result "shift" the values one step.

Sample Algorithms

Checking for a Prime

Start
    // Enter a number
    Read num
    // Flag: 0 and 1 are not prime
    If num < 2 then isPrime = False
    Else isPrime = True
    // Try divisors from 2 to half the number
    For divisor = 2 to num / 2
        If num % divisor = 0 then
            // If divisible, not prime
            isPrime = False
            Break
        End If
    End For
    // Print the result based on the flag
    If isPrime = True then
        Print num, " is a prime number."
    Else
        Print num, " is not a prime number."
    End If
End

Prime: a number greater than 1 divisible only by 1 and itself: 2, 3, 5, 7, 11, …

  • Flag: assume "prime" at first; lower the flag when a divisor turns up.
  • % gives the remainder: 21 % 3 = 0 → divisible.
  • Once a divisor is found there is no need to go on: Break.
  • No number above half of n (other than n) can divide it; num / 2 is integer division (7 / 2 = 3).
  • For 0 and 1 the loop never runs, so they are checked separately.

7 % 3 = 1 ≠ 0 → not divisible, go on.

The flag is True: 7 is prime.

Second test: the user enters 21.

Searching

Search Algorithms

  • Asks whether a given item is in a collection (and if so, where).
  • A basic operation for processing data and retrieving information.
  • It helps find specific items quickly and correctly.
  • Uses: finding a book in a library, a page on a website, a record in a database, a name in a phone book.
Problem definition

Input:

  • A collection of objects, say a "Basket".
  • A particular object, say an "Apple".

Output:

  • true if the "Apple" is in the basket.
  • false if it is not.

In code we usually return the index (position) of the item, or -1 if it is missing.

Searching

Three Search Methods

Random

Each step picks a random item and compares it with the target.

No order needed · no guarantee of finding it

Linear

Compares the items one by one from start to end.

No order needed · at most n comparisons

Binary

Looks at the middle item and discards half the range each step.

Array must be sorted · at most ≈ log₂ n comparisons

Searching

Random Search

  • Checks items at random: each step picks a random item.
  • Runs until it finds the target or runs out of tries.
  • Pseudocode:
  1. Pick a random item.
  2. Compare it with the target.
  3. If it is the target, stop.
  4. Otherwise repeat.

Pros

  • Simple.
  • The order of the data does not matter.

Cons

  • Not always effective: it may pick the same item again and again.
  • It can raise the odds of finding the item but guarantees nothing.
  • If the target is absent it runs forever; it needs a limit on tries.
  • In the worst case it scans the whole collection (or more).

Searching · Step by step

Random Search: Step by Step

We have an unsorted array; the target is 48.

Step 1: the random pick is 23; 23 ≠ 48, not found yet. Pick another.

Step 2: the random pick is 42; 42 ≠ 48, not found yet. Pick another.

Step 3: the random pick is 7; 7 ≠ 48, not found yet. Pick another.

Step 4: the random pick is 48 → target found; the search ends (4 tries).

Searching

Linear Search

  • The most basic way to find an item in a collection.
  • It checks the items in order looking for the target.
  • The items need not be sorted.
  • Good for small collections.

Steps:

  1. Put the items in a list (array).
  2. Starting from the first, compare each item with the target in turn.
  3. If it is the target, stop and return its position.
  4. Otherwise move to the next item.
  5. Continue to the end of the list; reaching the end means the item is absent.

Pros

  • Simple and easy to follow.
  • Works in any order (on unsorted data).
  • The result is certain: if the item is there, it is found.

Cons

  • Slow on large collections: it may have to check every item (worst case n comparisons).

Searching · Step by step

Linear Search: Step by Step

Step 1: the target is 23. Start with the first item (42) and compare it with the target.

Step 2: the first item (42) does not match 23. Move on: 17.

Step 3: the second item (17) does not match either. Next: 8.

Step 4: the third item (8) does not match either. Next: 23.

Step 5: the fourth item (23) matches; the search ends here (4 comparisons).

Searching

Binary Search

  • A fast way to find an item in a collection.
  • Works on sorted data (ascending or descending).
  • Each step discards half of the list.
  • Ideal for searching large collections.

Steps:

  1. Take the middle item and compare it with the target.
  2. If it is the target, stop.
  3. If the target is smaller, focus on the left half.
  4. If the target is larger, focus on the right half.
  5. Repeat until the target is found or the range is empty.

Pros

  • Fast: at most 20 comparisons for 1,000,000 items.
  • Very fast on large collections.

Cons

  • The data must be sorted (and sorting has a cost).
  • On an unsorted array it can give a wrong answer (without any error!).

Searching · Step by step

Binary Search: Step by Step

We have a sorted array; the target is 48. At first the range is the whole array: low = 0, high = 8.

Step 1: take the middle item (42) and compare it with the target (48).

Step 2: 48 is greater than the middle item (42), so the target is in the right half. The left half is dropped: [48, 55, 64, 77].

Step 3: take the middle of the right half. With 4 items there are two middles (55 and 64); (low + high) / 2 picks the left one, 55.

Step 4: 48 is less than the middle item (55); the right side is dropped. Only [48] remains.

Step 5: the middle item, 48, equals the target: found. Just 3 comparisons in a 9-item array.

Searching

Binary vs. Linear Search

Linear search
  • Checks the items one by one, in order.
  • Runs until it finds the target or the list ends.
  • Data may be unsorted.
  • Can be slow on large collections.
Binary search
  • Finds the target quickly in sorted data.
  • Data must be sorted (ascending or descending).
  • Each step discards half of what remains.
  • Very fast on large collections.

Sorting

Sorting Algorithms

  • Arrange the items of a collection by some rule.
  • Usually in ascending or descending order.
  • A basic step for data analysis and searching.
  • Sorted data speeds up search: binary search works only on sorted arrays.
Random

Shuffles the items; no guarantee of order.

Selection sort

Selects the smallest and puts it first.

Bubble sort

Compares neighbors and moves the larger toward the end.

Faster methods exist (merge sort, quicksort); Java's built-in Arrays.sort uses refined versions of them.

Sorting

Random Sorting (Shuffling)

  • Putting a collection into a random order: the items are shuffled.
  • Uses: shuffling a deck of cards, reordering exam questions, generating test data.
  • Some algorithms (e.g. quicksort) shuffle their input first to avoid bad cases.

Pros

  • Gives a different arrangement every time.
  • Built into Java: Collections.shuffle(list).

Cons

  • Does not sort the data.
  • "Shuffle until sorted" (bogosort) is hopelessly slow: only one of the 3,628,800 orderings of 10 items is sorted.

Sorting · Step by step

Random Sorting: Step by Step

We start with an unsorted array: [42, 17, 8, 23, 31].

Step 1: the items are put in a random order: [31, 17, 42, 8, 23]. Each shuffle gives a different result.

Step 2: shuffled again: [8, 23, 31, 42, 17].

Step 3: shuffled again: [8, 23, 17, 31, 42]. Closer, but still not sorted: shuffling guarantees nothing.

Sorting

Selection Sort

  • A simple comparison-based sorting algorithm.
  • It repeatedly finds the smallest (or largest) item and swaps it into place.

Steps:

  1. Find the smallest item.
  2. Move it to the front (swap with the first item).
  3. Find the smallest of the rest.
  4. Move it to the second position.
  5. Repeat to the end.

Pros

  • Simple and easy to follow.
  • Good for small collections.
  • At most n − 1 swaps.

Cons

  • Slow on large collections: always n(n − 1)/2 comparisons (even if already sorted).

Selection Sort: Step by Step

We start with an unsorted array: [64, 25, 12, 22, 11, 36, 48].

Step 1: the minimum of the unsorted part (indices 0–6) is 11; it will swap with the 64 at index 0.

After step 1: [11, 25, 12, 22, 64, 36, 48]. The green part is sorted and in place.

Step 2: the minimum of the unsorted part (indices 1–6) is 12; it will swap with the 25 at index 1.

After step 2: [11, 12, 25, 22, 64, 36, 48]. The green part is sorted and in place.

Step 3: the minimum of the unsorted part (indices 2–6) is 22; it will swap with the 25 at index 2.

After step 3: [11, 12, 22, 25, 64, 36, 48]. The green part is sorted and in place.

Step 4: the minimum of the unsorted part (indices 3–6) is 25. Already in place: no change.

After step 4: [11, 12, 22, 25, 64, 36, 48]. The green part is sorted and in place.

Step 5: the minimum of the unsorted part (indices 4–6) is 36; it will swap with the 64 at index 4.

After step 5: [11, 12, 22, 25, 36, 64, 48]. The green part is sorted and in place.

Step 6: the minimum of the unsorted part (indices 5–6) is 48; it will swap with the 64 at index 5.

After step 6: [11, 12, 22, 25, 36, 48, 64]. The green part is sorted and in place. The last item falls into place on its own: 6 steps suffice for 7 items.

Sorting

Bubble Sort

  • A simple algorithm that sorts by comparing items in sequence.
  • It compares neighbors and carries the larger one toward the end, like a bubble rising to the surface.

Steps:

  1. Start at the beginning.
  2. Compare two neighbors; swap if needed so the larger moves right.
  3. Repeat to the end of the collection (one pass).
  4. The largest item is now last, so treat it as sorted.
  5. Repeat for the rest; stop when a pass makes no swaps.

Pros

  • Simple and easy to follow.
  • Good for small or nearly sorted collections (with early exit).

Cons

  • Very slow on large collections: in the worst case n(n − 1)/2 comparisons and as many swaps.

Sorting · Step by step

Bubble Sort: Step by Step

We start with an unsorted array: [64, 25, 12, 22, 11, 36, 48].

Step 1 (pass 1): compare 64 and 25; 64 > 25, so swap → [25, 64, 12, 22, 11, 36, 48].

Step 2 (pass 1): compare 64 and 12; 64 > 12, so swap → [25, 12, 64, 22, 11, 36, 48].

Step 3 (pass 1): compare 64 and 22; 64 > 22, so swap → [25, 12, 22, 64, 11, 36, 48].

Step 4 (pass 1): compare 64 and 11; 64 > 11, so swap → [25, 12, 22, 11, 64, 36, 48].

Step 5 (pass 1): compare 64 and 36; 64 > 36, so swap → [25, 12, 22, 11, 36, 64, 48].

Step 6 (pass 1): compare 64 and 48; 64 > 48, so swap → [25, 12, 22, 11, 36, 48, 64].

Step 7 (pass 2): compare 25 and 12; 25 > 12, so swap → [12, 25, 22, 11, 36, 48, 64].

Step 8 (pass 2): compare 25 and 22; 25 > 22, so swap → [12, 22, 25, 11, 36, 48, 64].

Step 9 (pass 2): compare 25 and 11; 25 > 11, so swap → [12, 22, 11, 25, 36, 48, 64].

Step 10 (pass 2): compare 25 and 36; 25 < 36, no change.

Step 11 (pass 2): compare 36 and 48; 36 < 48, no change.

Step 12 (pass 3): compare 12 and 22; 12 < 22, no change.

Step 13 (pass 3): compare 22 and 11; 22 > 11, so swap → [12, 11, 22, 25, 36, 48, 64].

Step 14 (pass 3): compare 22 and 25; 22 < 25, no change.

Step 15 (pass 3): compare 25 and 36; 25 < 36, no change.

Step 16 (pass 4): compare 12 and 11; 12 > 11, so swap → [11, 12, 22, 25, 36, 48, 64].

Step 17 (pass 4): compare 12 and 22; 12 < 22, no change.

Step 18 (pass 4): compare 22 and 25; 22 < 25, no change.

Step 19 (pass 5): compare 11 and 12; 11 < 12, no change.

Step 20 (pass 5): compare 12 and 22; 12 < 22, no change.

Pass 5 made no swaps: the array is sorted and the algorithm stops. In total 20 comparisons, 11 swaps.

Common Mistakes: Algorithms

Wrong accumulator startStarting with factorial = 0 makes every product 0. Start sums at 0 and products at 1.
Off-by-one loop boundsWriting 2 … n instead of 2 … n − 1 in Fibonacci gives n + 1 terms. Check bounds with a small dry run.
Binary search on unsorted dataSearching [77, 42, 64, 12, 23, 55, 7, 48, 31] for 77 returns -1: no error message, wrong answer.
Forgetting edge casesTest 0 and 1 for primes, 0! for factorial and n = 1 for Fibonacci separately.
Random search with no stopping ruleIf the target is absent the loop runs forever; it needs a limit on tries.
Swapping without a temporarya = b; b = a; makes both equal to b. Save temp = a first.

Exercises

  1. Write pseudocode and a Java program that find the largest of three integers; test all 6 orders.
  2. Sum 1 to n with a loop. For n = 100, compare with the formula n(n + 1)/2.
  3. Find the digit sum of a number (hint: % 10 and / 10). What is it for 1234?
  4. Change linear search to count how many times the target occurs.
  5. Change bubble sort to sort in descending order.
  6. Write Fibonacci in Java with int and run it for n = 50. After which term do the results go wrong? Why?
Answers / hints
  1. max = first; compare second and third with max in turn and assign when larger. No need for 6 nested branches.
  2. Start with sum = 0, then sum = sum + i; for n = 100, 5050 = 100 · 101 / 2.
  3. while (num > 0) { sum += num % 10; num = num / 10; } → 1 + 2 + 3 + 4 = 10.
  4. Instead of return, increment a count and let the loop run to the end; return count at the end.
  5. Only the comparison flips: swap if arr[j] < arr[j + 1].
  6. F(46) = 1,836,311,903 is the last correct term; F(47) exceeds the int limit (2,147,483,647) and comes out negative (−1,323,752,223). Use long.
