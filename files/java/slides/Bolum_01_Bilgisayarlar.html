Giriş

Öğrenme Çıktıları

Donanım

İşlemci, bellek, disk ve veri yolunun görevini açıklamak; bir programın işlemcide Getir–Çöz–Çalıştır döngüsüyle nasıl yürüdüğünü izlemek.

Sayılar

Sayıları ikili, sekizli, onaltılı ve ondalık tabanlar arasında çevirmek; ikili toplama ve ikiye tümleme ile negatif sayıları hesaplamak.

Metin

ASCII, Unicode ve UTF-8 arasındaki farkı açıklamak; bir dizgenin bellekte sayılarla nasıl temsil edildiğini göstermek.

Java ile bağlantı

int, byte, char, double türlerinin sınırlarını, taşmayı ve Java kodunun makine koduna giden yolunu açıklamak.

Bilgisayarın Temelleri

Bir Bilgisayarın Temel Parçaları

  • İşlemci (CPU, Central Processing Unit): bilgisayarın “beyni”; tüm aritmetik ve mantıksal hesaplamaları yapar.
  • Bellek (RAM, Random Access Memory): çalışan programı ve verilerini geçici olarak saklar. Kapasitesi ve erişim hızı, bilgisayarın hızını doğrudan etkiler.
  • Sabit disk (HDD / SSD): verileri kalıcı olarak saklar; elektrik kesilince silinmez.
Mutfak benzetmesi: aşçı = işlemci, tezgâh = RAM (küçük ama hemen elinin altında), kiler = disk (büyük ama uzakta). Aşçı malzemeyi kilerden tezgâha alır, orada çalışır.

Bilgisayarın Temelleri

Bilgisayarın İşleyişi ve Programlama

Temel adımlar:

  1. İşlemciye talimatlar (komutlar) gönderilir.
  2. İşlemci talimatları sırayla işler.
  3. Sonuçlar kullanıcıya veya diğer yazılımlara sunulur.

Programlama, bilgisayarın istenen görevi yerine getirmesi için ona anlayacağı biçimde talimatlar yazma sürecidir.

İlk Java programımız: tek bir talimat, “ekrana yaz”.

public class MerhabaDunya {
    public static void main(String[] args) {
        System.out.println("Merhaba, Dünya!");
    }
}

Çıktı:

Merhaba, Dünya!

Java gibi bir dilde yazılan talimatlar, işlemcinin anladığı makine koduna çevrilerek çalıştırılır; bu yolculuğu bölümün sonunda göreceğiz.

Bilgisayarın Temelleri

Bir Bilgisayar Nasıl İnşa Edilir?

Bilgisayarı katman katman kuracağız. Her katman bir alttakinin üzerine oturur:

  • Önce elektrik sinyallerini sayılara dönüştürürüz.
  • Sayılarla harfleri, harflerle metinleri temsil ederiz.
  • Sayı dizileriyle resim, ses ve film gibi yapılandırılmış bilgiyi saklarız.
  • Komutları da sayı olarak bellekte saklarız.
  • Hepsini von Neumann mimarisi bir araya getirir.

Sayılar

Elektrik Sinyalinden Bite

  • Bilgisayarın temel işi, elektrik sinyallerini belirli kurallara göre işlemektir; bu kurallar sayesinde pek çok işlev gerçekleşir.
  • Sinyalleri insanın anlayacağı sayı ve sembollerle ilişkilendirince bilgisayar bize anlamlı bilgi sunabilir.
  • Sinyaller ikili (binary, taban 2) temsille işlenir: her basamak, yani bit (binary digit), yalnızca 0 ya da 1 olabilir.
  • Bütün işlemler bu ikili temelin üzerine inşa edilmiştir.

8 bit = 1 bayt (byte). Bellek ve dosya boyutları bayt ile ölçülür: 1 KB ≈ 1000 bayt, 1 KiB = 1024 bayt.

Sayılar

Basamak Değeri: 13 = 1101₂

  • Tam sayılar, 2'nin kuvvetlerinin toplamı olarak yazılır. Her kuvvet 0 ya da 1 kez kullanılır.
  • 4 ardışık kuvvetle (2⁰, 2¹, 2², 2³) 0–15 arasındaki tam sayılar temsil edilir.
  • 13₁₀ = 1·2³ + 1·2² + 0·2¹ + 1·2⁰ = 1101₂

Diğer tabanlarda aynı kural:

Ondalık (10)603₁₀ = 6·10² + 0·10¹ + 3·10⁰
Sekizli (8)207₈ = 2·8² + 0·8¹ + 7·8⁰ = 135₁₀
Onaltılı (16)FF₁₆ = 15·16¹ + 15·16⁰ = 255₁₀

Alt simge tabanı gösterir: 1101₂ “bir bir sıfır bir, ikili” diye okunur, “bin yüz bir” diye değil.

Ondalıktan İkiliye: 2'ye Bölme Yöntemi

sayi = 13 ile başlıyoruz.

Sonuç dizgesi boş başlar: ikili = "".

Koşul 13 > 0 doğru → döngüye gir.

Kalan 13 % 2 = 1; bu, sayının en sağdaki henüz yazılmamış bitidir.

Kalan dizgenin önüne eklenir → "1"; sayı yarıya iner: 13 / 2 = 6 (tam sayı bölmesi).

Koşul 6 > 0 doğru → döngüye gir.

Kalan 6 % 2 = 0; bu, sayının en sağdaki henüz yazılmamış bitidir.

Kalan dizgenin önüne eklenir → "01"; sayı yarıya iner: 6 / 2 = 3 (tam sayı bölmesi).

Koşul 3 > 0 doğru → döngüye gir.

Kalan 3 % 2 = 1; bu, sayının en sağdaki henüz yazılmamış bitidir.

Kalan dizgenin önüne eklenir → "101"; sayı yarıya iner: 3 / 2 = 1 (tam sayı bölmesi).

Koşul 1 > 0 doğru → döngüye gir.

Kalan 1 % 2 = 1; bu, sayının en sağdaki henüz yazılmamış bitidir.

Kalan dizgenin önüne eklenir → "1101"; sayı yarıya iner: 1 / 2 = 0 (tam sayı bölmesi).

Koşul 0 > 0 yanlış → döngü biter. Kalanlar aşağıdan yukarı okunur.

Sonuç yazdırılır: 13₁₀ = 1101₂.

public static void main(String[] args) {
  int sayi = 13;
  String ikili = "";
  while (sayi > 0) {
    int kalan = sayi % 2;
    System.out.println(sayi + " % 2 = " + kalan);
    ikili = kalan + ikili;
    sayi = sayi / 2;
  }
  System.out.println("Sonuç: " + ikili);
}

Toplama Her Tabanda Aynı Kurallarla Yapılır

Hangi taban kullanılırsa kullanılsın geçerli ilkeler: basamak değerleri, elde (taşıma, carry) ve doğru sonuç.

Onlukta 7 + 8 = 15 → 5 yaz, 1 elde. İkilide 1 + 1 = 2 = 10₂ → 0 yaz, 1 elde.

İki sayıyı alt alta yazarız: 57 = 00111001₂ ve 28 = 00011100₂. Toplama sağdan başlar.

Sütun 1: 1 + 0 = 1 → 1 yaz, elde yok.

Sütun 2: 0 + 0 = 0 → 0 yaz, elde yok.

Sütun 3: 0 + 1 = 1 → 1 yaz, elde yok.

Sütun 4: 1 + 1 = 2 = 10₂ → 0 yaz, 1 elde.

Sütun 5: 1 + 1 + 1 (elde) = 3 = 11₂ → 1 yaz, 1 elde.

Sütun 6: 1 + 0 + 1 (elde) = 2 = 10₂ → 0 yaz, 1 elde.

Sütun 7: 0 + 0 + 1 (elde) = 1 → 1 yaz, elde yok.

Sütun 8: 0 + 0 = 0 → 0 yaz, elde yok. Sonuç: 01010101₂ = 64 + 16 + 4 + 1 = 85 ✓

Sayılar

Negatif Sayılar: İkiye Tümleme

  • Negatif tam sayılar genellikle ikiye tümleme (two's complement) ile temsil edilir.
  • Kural: pozitif sayının bitlerini ters çevir, sonra 1 ekle.
  • En soldaki bit işaret biti gibi davranır: 0 → pozitif, 1 → negatif.
  • 8 bitle aralık: −128 … 127. n bitle: −2n−1 … 2n−1 − 1.

8 bitlik bir bilgisayarda 3 sayısı: 00000011.

1. adım: bütün bitler ters çevrilir (0 ↔ 1): 00000011 → 11111100 (birler tümleyeni).

2. adım: 1 eklenir: 11111100 + 1 → 11111101. Bu, −3'ün temsilidir.

Neden işe yarar? 3 + (−3) toplandığında taşan 9. bit atılır ve sonuç tam olarak 0 olur: toplama devresi aynen kullanılır.

Başka bir bakış: en soldaki bitin ağırlığı −128'dir. Bu yüzden en soldaki bit 1 ise sayı negatiftir.

Çok Büyük ve Çok Küçük Sayılar: Kayan Nokta

  • Sınırlı sayıda rakamla ancak sınırlı sayıda değer temsil edilebilir.
  • Çok büyük / küçük sayılar için sayı kesir (mantis) ve üs olarak iki parçaya ayrılır; parçalar ayrı ayrı saklanır.
  • Örnek: 8 rakamlık 31415901 gösteriminde ilk altı rakam (314159) kesri, son iki rakam (01) 10'un kuvvetini, yani 10¹'i belirtir.
  • Bilgisayarlar aynı fikri ikili tabanda uygular: IEEE 754 standardı. Java'da float 32 bit, double 64 bittir.

Adı buradan gelir: “kayan nokta” (floating point), üs değiştikçe ondalık noktanın yerinin kaymasıdır: 0.314159 × 10³ = 314.159.

Deneyin: Bitlerle Oynayın

Bir bite tıklayınca 0 ↔ 1 olur. −3'ü elde etmek için: 3 yazın → ters çevir → +1. İşaretli değer, en soldaki bitin ağırlığı −128 sayılarak bulunur.

Harf ve Dizgeler

Harfleri Sayılarla Temsil Etmek: ASCII

  • Metin işlemek için her harfe bir sayı karşılık getirilmelidir: buna karakter kodlaması (character encoding) denir.
  • ASCII (American Standard Code for Information Interchange), 1963'te ABD standartlar kurumu ASA (bugünkü ANSI) tarafından yayımlanmıştır.
  • Büyük ve küçük harfleri, rakamları, noktalama ve özel karakterleri sayıyla temsil eder.
  • 7 bitlik bir koddur: 128 karakter (0–127). 0–31 ve 127 kontrol karakteri, 32–126 yazdırılabilir.
  • 8 bitlik genişletmeler (örneğin Türkçe için ISO 8859-9, Windows-1254) 128–255 arasına ek harfler koyarak 256 sembole çıkar.
  • Tek bir 8 bitlik tablo, dünyanın tüm dillerine yetersizdir.

Bütün Diller İçin Tek Tablo: Unicode

  • Unicode, dünyadaki tüm yazı sistemlerinin harf, sembol ve işaretlerine birer numara (kod noktası, code point) verir: U+0041 = A, U+00E7 = ç.
  • Unicode Konsorsiyumu tarafından geliştirilir (1991); uluslararası karşılığı ISO/IEC 10646 ile eşzamanlı tutulur.
  • İlk sürüm 16 bitlikti (65.536 karakter). Bu yetmeyince alan U+10FFFF'e genişletildi: 1.114.112 kod noktası, bugün 150.000'den fazla karakter.
  • Her karakteri sabit 32 bitle (UTF-32) saklamak, İngilizce gibi metinlerde gereğinden fazla yer harcar. Bu yüzden UTF (Unicode Transformation Format) kodlamaları tanımlanmıştır.

Harf ve Dizgeler

Dizge (String)

  • Dizge (string), karakterlerden oluşan bir veri türüdür: "Merhaba Dünya!" bir dizgedir.
  • Metin işleme ve iletişimde en sık kullanılan türdür.
  • Dizgedeki her karakterin (harf, rakam, sembol) bir sayı değeri vardır.
  • Dizgenin uzunluğu ayrıca bir uzunluk alanında (length field) tutulur; böylece metnin nerede bittiği bilinir.
  • Örnek: "çikolata" → 231, 105, 107, 111, 108, 97, 116, 97.
Dikkat: “ç” ASCII'de yoktur. 231 onun Unicode kod noktasıdır (U+00E7); aynı değer Latin-1 ve Türkçe ISO 8859-9 tablolarında da 231'dir. Diğer yedi harf ASCII ile aynıdır.

Dizge bellekte karakter dizisi ve uzunluk olarak durur.

i = 0: charAt(0) = 'ç'; (int) dönüşümü kodunu verir: 231. (Unicode U+00E7)

i = 1: charAt(1) = 'i'; (int) dönüşümü kodunu verir: 105.

i = 2: charAt(2) = 'k'; (int) dönüşümü kodunu verir: 107.

i = 3: charAt(3) = 'o'; (int) dönüşümü kodunu verir: 111.

i = 4: charAt(4) = 'l'; (int) dönüşümü kodunu verir: 108.

i = 5: charAt(5) = 'a'; (int) dönüşümü kodunu verir: 97.

i = 6: charAt(6) = 't'; (int) dönüşümü kodunu verir: 116.

i = 7: charAt(7) = 'a'; (int) dönüşümü kodunu verir: 97.

i = 8: koşul 8 < 8 yanlış → döngü biter.

Satır sonu ve uzunluk yazdırılır: length() = 8.

for (int i = 0; i < kelime.length(); i++) {
  char ch = kelime.charAt(i);
  System.out.print((int) ch + " ");
}
System.out.println();
System.out.println("Uzunluk: " + kelime.length());

Sayı dizileri, bilgiyi saklamamızı ve bilgisayarla etkileşim kurmamızı sağlar.

ResimlerHer piksel kırmızı, yeşil, mavi miktarını veren üç sayıdır (0–255). Mavi piksel: (0, 0, 255).
SeslerHavadaki ses basıncı zaman içinde düzenli aralıklarla ölçülür (örnekleme); CD kalitesi saniyede 44.100 örnek.

Yapılandırılmış Bilgi

Örnek: Bir Video Ne Kadar Yer Tutar?

long piksel = 1920L * 1080;  // Full HD bir kare
long kare = piksel * 3;      // R, G, B: 3 bayt
long saniye = kare * 30;     // saniyede 30 kare
System.out.println("Piksel: " + piksel);
System.out.println("Kare (bayt): " + kare);
System.out.println("1 saniye (bayt): " + saniye);
System.out.println("1 dakika (MB): "
    + saniye * 60 / 1_000_000);
// 44,1 kHz, 16 bit (2 bayt), stereo, 1 dakika
long ses = 44_100L * 2 * 2 * 60;
System.out.println("1 dk CD sesi (bayt): " + ses);

Saklanan Program

Saklanan Program Kavramı

  • Modern bilgisayarların temel ilkesidir: komutlar da veriler gibi sayıdır ve aynı bellekte saklanır.
  • Bellekte saklanan komutlar ve veriler birlikte programı oluşturur. Her komut bir görevi veya işlemi temsil eder.
  • Komutlar ardışık olarak işlenir.
  • Bir koşul sağlandığında program farklı bir komuta atlayabilir; böylece programlar duruma göre farklı yollar izler (ileride if ve döngüler bunu kullanır).

ENIAC (1945)

  • Program, kablolar ve anahtarlarla elle kurulur.
  • Yeni bir program için günlerce yeniden kablolama.

EDVAC tasarımı (1945)

  • Komutlar ve veriler bellekte sıralı saklanır.
  • Program değiştirmek = belleğe yeni sayılar yazmak: esnek ve genişletilebilir.

Fikri J. von Neumann'ın 1945 tarihli EDVAC raporu yaydı; saklanan programı ilk çalıştıran makine Manchester “Baby” oldu (1948).

Saklanan Program

Bellek Hiyerarşisi

  • Bellek, çalışan programların ve verilerin geçici olarak saklandığı yerdir.
  • L1 önbellek (cache): en hızlısı, işlemcinin içinde.
  • L2 önbellek: L1'i destekler, daha büyüktür. Çoğu işlemcide bir de L3 vardır.
  • Ana bellek (RAM): çok daha büyük ama daha yavaş.
  • İşlemciye yakın bellek daha hızlı ama daha küçük ve pahalıdır; hiyerarşi performansı doğrudan etkiler.

Boyut ve süreler yaklaşık değerlerdir, işlemciye göre değişir. 1 ns = saniyenin milyarda biri.

Saklanan Program

İşlemci (CPU) ve Veri Yolu (Bus)

Merkezi İşlem Birimi (CPU)

  • Bilgisayarın “beyni”; tüm hesaplamalar burada yapılır.
  • Aritmetik Mantık Birimi (ALU, Arithmetic Logic Unit): toplama, çıkarma, karşılaştırma gibi hesapları yapar.
  • Kontrol Birimi (Control Unit): komutları yorumlar, işlemleri sıraya koyar ve yönlendirir.
  • Yazmaçlar (register): geçici veriler için çok küçük ama çok hızlı saklama alanları.

Veri Yolu (Bus)

  • Birçok paralel telden oluşan bir iletişim yolu sistemidir.
  • Adres sinyalleri: hangi bellek hücresine veya aygıta erişileceğini seçer.
  • Veri sinyalleri: işlenecek ya da saklanacak asıl veriyi taşır.
  • Kontrol sinyalleri: işlemi yönlendirir; ör. “oku” mu “yaz” mı.
Elektronik bağlantısı: 32 hatlı bir adres yolu 2³² farklı adres seçebilir → 4 GiB bellek. Bu yüzden 32 bitlik sistemler en fazla yaklaşık 4 GB RAM kullanabiliyordu.

Saklanan Program

CPU – Bellek – Veri Yolu – Yazmaçlar

  • CPU, adres yolundan hangi hücreyi istediğini söyler.
  • Hücrenin içeriği veri yolundan gelir (okuma) ya da gider (yazma).
  • PC (program sayacı): sıradaki komutun adresi.
  • IR (komut yazmacı): o an çözülen komut.
  • R1, R2, AC (akümülatör): ara sonuçlar.
  • ALU yazmaçlardaki sayılarla hesap yapar.

Saklanan Program

Bellek, Adresler ve Program Sayacı

  • Bellek, veri ve talimatların saklandığı alandır; bir program uzun bir talimat listesidir.
  • Her bellek hücresinin bir adresi vardır; hücrede bir talimatın ya da verinin sayıyla kodlanmış hali bulunur.
  • Talimatlar bellekten tek tek alınıp işlemcideki yazmaçlara yüklenir ve sırayla çalıştırılır.
  • En önemli yazmaçlardan biri program sayacıdır (PC, program counter): sıradaki talimatın adresini tutar.
  • İşlemci normalde adres sırasıyla ilerler; ama bazı talimatlar bu sırayı değiştirir: 204'teki “JUMP 7” PC'yi 211 yapar.

Saklanan Program

Getir–Çöz–Çalıştır Döngüsü

Getir–Çöz–Çalıştır (Fetch–Decode–Execute) döngüsü, programların işlemcide nasıl yürütüldüğünü tanımlar.

  1. Getir (Fetch): işlemci, PC'nin gösterdiği adresteki sıradaki komutu bellekten alır; PC bir sonraki adrese ilerler.
  2. Çöz (Decode): komut çözülür: hangi işlem, hangi yazmaçlar, hangi adres? Her komutun belirli bir işlevi vardır.
  3. Çalıştır (Execute): komutun gerektirdiği işlem yapılır: veri işleme, sonuç hesaplama ya da bir işlemi başlatma.

Ardından bir sonraki komut alınır ve döngü, bilgisayar açık olduğu sürece sürekli tekrarlanır.

3 GHz'lik bir işlemcinin saati saniyede 3 milyar kez “tık” eder; modern işlemciler birden çok komutu üst üste bindirerek (boru hattı, pipeline) işler.

Saklanan Program · Adım adım

Oyuncak Bir Bilgisayarda 102 + 25

Program ve veriler bellekte. Başlangıçta PC = 200.

Getir: 200'deki komut IR'ye alınır, PC 201'e ilerler.

Çöz: işlem = LOAD (yükle), hedef = R1, adres = 205.

Çalıştır: bellek[205] = 102 okunur, R1'e yazılır.

Getir: PC = 201'deki komut alınır, PC 202 olur.

Çöz: işlem = ADD (topla), R1 ile bellek[206] toplanacak.

Çalıştır: ALU 102 + 25 = 127 hesaplar, sonuç R1'e.

Getir: 202'deki STORE alınır, PC 203 olur.

Çöz: R1'in değeri 207 adresine yazılacak (kontrol yolu: “yaz”).

Çalıştır: bellek[207] ← 127. Sonuç artık bellekte.

Getir: 203'teki HALT alınır, PC 204 olur.

Çöz + Çalıştır: HALT → işlemci durur. Java'daki toplam = a + b; satırı da sonunda bu tür komutlara dönüşür.

200: LOAD  R1, [205] ; R1 ← bellek[205]
201: ADD   R1, [206] ; R1 ← R1 + bellek[206]
202: STORE R1, [207] ; bellek[207] ← R1
203: HALT            ; dur
204: ...
205: 102             ; veri
206: 25              ; veri
207: 0               ; sonuç buraya

von Neumann Mimarisi

von Neumann Mimarisi

  • Saklanan program fikrinin donanım planıdır: işlemci, bellek, giriş/çıkış ve bunları bağlayan veri yolu.
  • Komutlar ve veriler aynı bellekte durur ve aynı yoldan taşınır.
  • Her komut bir işlem kodu (opcode) ile temsil edilir; işlem kodu hangi işlemin yapılacağını belirtir.
  • Tek yol, işlemciyi bekletebilir: von Neumann darboğazı. Önbellekler bu yüzden vardır.

Karşılaştırma: Harvard mimarisinde komut ve veri belleği ayrıdır; Arduino'daki AVR gibi pek çok mikrodenetleyici bu yapıyı kullanır.

von Neumann Mimarisi

Komutlar da Sayıdır: Kodlama

Bir oyuncak bilgisayar düşünelim: 8 bit, 4 yazmaç (R0–R3), 256 adet 8 bitlik bellek hücresi ve 4 komut: toplama (00), çıkarma (01), çarpma (10), bölme (11).

  • İlk 2 bit işlem kodu (4 komut → 2 bit).
  • Sonraki 2 bit hedef yazmaç (destination register).
  • Son 4 bit, iki işlenen yazmaç (2'şer bit).

“R0 ile R2'nin içeriğini topla, sonucu R3'e yaz” = 0 3 0 2 → 00110010

İşlemcinin “çöz” adımı Java'da: basamak değeriyle bölme!

int komut = 0b00110010;
int islemKodu = komut / 64;     // ilk 2 bit
int hedef = (komut / 16) % 4;   // sonraki 2 bit
int kaynak1 = (komut / 4) % 4;  // sonraki 2 bit
int kaynak2 = komut % 4;        // son 2 bit
System.out.println(komut);
System.out.println(islemKodu + " " + hedef
    + " " + kaynak1 + " " + kaynak2);

Çıktı:

50
0 3 0 2

von Neumann Mimarisi

Programlamanın Soyutlama Seviyeleri

  • Yüksek seviye dil (high-level language): problem alanına yakındır; daha üretken, okunabilir ve anlaşılır yazılım sağlar. Java, C, Python…
  • Çevirici dili (assembly language): komutları metin olarak (ADD, MOV) ifade eder; donanım temsiline çevrilir. Daha düşük seviyeli bir soyutlamadır.
  • Donanım temsili (hardware representation): yalnızca bitler. Komutlar ve veriler doğrudan donanım tarafından anlaşılır.

Örnekte a, b, toplam sırasıyla ebx, ecx, eax yazmaçlarında varsayılmıştır; makine kodu x86'nın gerçek kodlamasıdır (89 D8, 01 C8).

von Neumann Mimarisi

Çevirici Dili (Assembly)

  • Çevirici dili belirli bir işlemci mimarisine özeldir: x86 için yazılan kod ARM'da çalışmaz.
  • Her satır genellikle tek bir makine komutuna karşılık gelir.
  • Bilgisayarın alt seviyede nasıl çalıştığını anlamak için önemlidir.
  • Performans optimizasyonu ve donanımla doğrudan etkileşim (sürücüler, gömülü sistemler) için kullanılır.

MOV AX, BXBX'teki değeri AX'e kopyala66 89 D8
ADD EAX, 10EAX'e 10 ekle83 C0 0A
XOR EAX, EAXEAX'i sıfırla (x XOR x = 0)31 C0
61h = 0x61 = 97 = ASCII 'a'. Bellekteki bir bayt sayı mı, harf mi, komut mu? Bunu programın onu nasıl kullandığı belirler.

Peki Java Programı Nasıl Çalışır?

int a = 5;
int b = 7;
int toplam = a + b;
System.out.println(toplam);   // 12

Java derleyicisi kodu doğrudan işlemcinin diline değil, Java Sanal Makinesi'nin (JVM) diline, bayt koduna çevirir.

javap -c ile görülen bayt kodu:

iconst_5      // 5'i yığına koy
istore_1      // a = 5
bipush 7
istore_2      // b = 7
iload_1       // a'yı yükle
iload_2       // b'yi yükle
iadd          // topla
istore_3      // toplam = 12
“Bir kez yaz, her yerde çalıştır.” Aynı bayt kodu Windows, Linux ve macOS'taki JVM'lerde çalışır; JVM onu o makinenin işlemcisine uygun makine koduna çevirir. Java'nın platform bağımsızlığı buradan gelir.

Sık Yapılan Hatalar

Aralık dışı sabitbyte b = 200; → error: incompatible types: possible lossy conversion from int to byte. byte en fazla 127'dir.
L ekini unutmaklong x = 3000000000; → error: integer number too large. Doğrusu: 3000000000L.
Karakter ile dizgeyi karıştırmakchar c = "A"; → error: incompatible types: String cannot be converted to char. Karakter tek tırnakla: 'A'.
Başta sıfırint x = 010; sekizlidir, değeri 8! int y = 08; ise derlenmez (error: ';' expected): sekizlide 8 rakamı yoktur.
Taşmayı fark etmemekInteger.MAX_VALUE + 1 hata vermez, −2147483648 olur. Büyük çarpımlarda long kullanın: 1920L * 1080.
Kesirlerde ==0.1 + 0.2 == 0.3 → false. Farkın küçük olup olmadığına bakın. Ayrıca "😀".length() 1 değil 2'dir.

Örnek Problemler

  1. 45 sayısını 8 bit ikili olarak yazın.
  2. 10110110₂ işaretsiz olarak kaçtır? 8 bit ikiye tümleme ile işaretli olarak kaçtır?
  3. −20'yi 8 bit ikiye tümleme ile yazın.
  4. 0x3F ondalık, ikili ve sekizli olarak nedir?
  5. 01101101₂ + 00110110₂ toplamını bulun. Sonuç 8 bit işaretli byte olarak ne olur?
  6. System.out.println('a' + 'b'); ve System.out.println("" + 'a' + 'b'); ne yazdırır?
  7. Oyuncak bilgisayarda 10011100 komutu ne yapar?
Cevapları göster
  1. 45 = 32 + 8 + 4 + 1 → 00101101.
  2. 128 + 32 + 16 + 4 + 2 = 182; işaretli: −128 + 54 = −74 (= 182 − 256).
  3. 20 = 00010100 → ters 11101011 → +1 → 11101100 (= 236 = 256 − 20).
  4. 3·16 + 15 = 63; ikili 111111; sekizli 77.
  5. 109 + 54 = 163 = 10100011₂; byte olarak en soldaki bit 1 → −93 (taşma).
  6. 195 (97 + 98, iki char sayı olarak toplanır) ve ab (önce dizge, sonra eklenir).
  7. 10 = çarpma, 01 = R1, 11 = R3, 00 = R0 → R1 ← R3 × R0.

Alıştırmalar

  1. 16 bitlik işaretli bir tam sayının (Java short) aralığı nedir?
  2. "Java" dizgesinin karakter kodlarını ondalık ve ikili olarak yazın.
  3. 1024 × 768 boyutlu, piksel başına 3 bayt kullanan sıkıştırmasız bir resim kaç bayttır?
  4. "ağaç" için length() ve UTF-8 bayt sayısı nedir?
  5. 0'dan 15'e kadar sayıları 4 basamaklı ikili olarak yazdıran bir Java programı yazın.
  6. 32 hatlı bir adres yolu kaç farklı bayt adresleyebilir?
Cevaplar / ipuçları
  1. −2¹⁵ … 2¹⁵ − 1 = −32768 … 32767 (Short.MIN_VALUE, Short.MAX_VALUE).
  2. J = 74 = 1001010, a = 97 = 1100001, v = 118 = 1110110, a = 97 = 1100001.
  3. 1024 · 768 · 3 = 2.359.296 bayt = 2,25 MiB.
  4. length() = 4; UTF-8: a(1) + ğ(2) + a(1) + ç(2) = 6 bayt.
  5. for (int i = 0; i < 16; i++) içinde String.format("%4s", Integer.toBinaryString(i)).replace(' ', '0') yazdırın → 0000, 0001, …, 1111.
  6. 2³² = 4.294.967.296 bayt = 4 GiB.
