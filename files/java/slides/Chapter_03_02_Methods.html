Methods

What Is a Method?

A function is a piece of code that does one job, has a name, and can be used again and again. In Java, functions always live inside a class and are called methods.

  • A method is defined by the parameters it takes and its return type.
  • Methods make code more readable and reduce repetition.
  • They encourage modular, well-organized code.
  • They split a program into small, manageable pieces.
Analogy: a recipe

"Brew tea" is a recipe: written once, followed as often as you like. The ingredients are the parameters, and the tea you get is the return value. Whoever follows the recipe doesn't have to rethink every step.

The main we have been writing is also a method; System.out.println(...) is a call to a built-in method.

Methods

Input – Process – Output

Every method can be seen in three stages:

Input

The method receives data: parameters. They determine what the method works on.

Process

The method processes the input with the statements in its body and performs a specific task.

Output

The process produces a result, which return hands back to the caller.

Like f(x) = x² in math: x is the input, squaring is the process, x² is the output. Some methods have no input or no output (void).

Calling a Method

public class AddExample {
    public static int add(int num1, int num2) {
        int result = num1 + num2;
        return result;
    }

    public static void main(String[] args) {
        int result = add(5, 3);
        System.out.println("Sum: " + result);
    }
}
Output
Sum: 8
  • add(5, 3) is a call: control goes to the method and, when it finishes, comes back to where the call was made.
  • In the call, 5 and 3 are arguments; in the definition, num1, num2 are parameters.
  • The call returns 8; this value is assigned to the result variable.
  • The number, order and types of the arguments must match the parameters.
  • static: the method can be called directly from main, without creating an object.

Call and Return: Step by Step

A program always starts in its main method. The stack holds only the main frame.

add(5, 3) is called: a new frame is pushed, and the arguments are copied.

The body runs: result = 5 + 3 = 8. This result is add's local variable.

return result; sends 8 back to the caller and ends the method; the frame is popped.

Control returns to the calling line: the returned 8 is assigned to main's result variable. The two result variables are different.

println is also a method call: it prints Sum: 8.

Definition and Calls

return and void

  • return expression; hands the value to the caller and ends the method at once; the lines after it don't run.
  • The returned value's type must be compatible with the declared return type (widening int → double is allowed).
  • In a value-returning method, every path must end with a return; otherwise the compiler reports missing return statement.
  • void methods return no value; a bare return; can be used to exit early.

    }

        printQuotient(10, 2);
        printQuotient(7, 0);

Pass by Value

Can a method change the variable it is given?

main: num = 5.

The call sends a copy of the value (5). increase's num is a separate box; sharing the same name means nothing.

Only the copy changes: increase's num becomes 15, main's is still 5.

increase prints 15.

increase is done; its frame and copy are gone. main's num 5 remains: Java passes arguments by value.

static void increase(int num) {
  num = num + 10;
  System.out.println("increase: " + num);
}

public static void main(String[] args) {
  int num = 5;
  increase(num);
  System.out.println("main: " + num);
}

A Copy of the Reference: Tracing the Code

a is a reference: the array object lives on the heap, and a holds its address.

x = 1: the primitive value is stored right in the frame.

The call: d gets a's reference copy, x gets a copy of 1. d and a refer to the same array.

d[0] = 50: the shared array changes; main will see the change too.

x = 50: only modify's copy changes.

d = new int[2]: d now refers to a new array. a is unaffected; the link is broken.

d[1] = 50 is written to the new array; main's array is unchanged.

The method is done; its frame is gone. Nothing refers to the new array any more (the garbage collector will reclaim it).

50 2 1: the array's contents changed, x did not. Java passes everything by value; a reference is just a value that gets copied.

static void modify(int[] d, int x) {
    d[0] = 50;
    x = 50;
    d = new int[2];
    d[1] = 50;
}

public static void main(String[] args) {
    int[] a = {1, 2};
    int x = 1;
    modify(a, x);
    System.out.println(a[0] + " " + a[1] + " " + x);
}

Method Overloading

public class Overloading {
    static int sum(int a, int b) {
        return a + b;
    }
    static double sum(double a, double b) {
        return a + b;
    }
    static int sum(int a, int b, int c) {
        return a + b + c;
    }

    public static void main(String[] args) {

        System.out.println(sum(2.5, 1.2));
        System.out.println(sum(1, 2, 3));
    }
}
Output
5
3.7
6

Overloading: several methods with the same name can live in one class as long as their parameter lists differ.

  • They can differ in the number, type or order of parameters.
  • The compiler looks at a call's arguments and decides which method runs at compile time.
  • Two methods that differ only in return type are not overloads: method sum(int,int) is already defined is what you get.
  • println is overloaded too: println(int), println(String), println(double)…

Which sum Runs? Step by Step

There are three methods named sum. The first call's arguments are (int, int): the three-parameter version is ruled out; (int, int) matches exactly, so it is chosen.

sum(int, int) runs: a = 4, b = 6.

10 is returned and printed.

(int, double): 2.5 to int? Not implicitly, so (int, int) is out. 4 is widened to 4.0 → sum(double, double).

a = 4.0, b = 2.5: the parameters are double.

6.5 is returned and printed.

Three arguments: only the three-parameter version fits.

a = 7, b = 1, c = 2.

10 is returned and printed.

(char, int): char can widen to both int and double; the compiler picks the most specific one, (int, int).

'A' → 65: a = 65, b = 1.

66 is returned and printed. The choice is made at compile time, from the argument types alone.

Methods Calling Methods

Methods Calling Methods

public class Nested {
    public static int square(int num) {
        return num * num;
    }
    public static int sum(int num1, int num2) {
        return num1 + num2;
    }
    public static int sumOfSquares(int num1, int num2) {
        return sum(square(num1), square(num2));
    }
    public static void main(String[] args) {
        int result = sumOfSquares(3, 4);
        System.out.println(result);
    }
}
Output
25
  • A method can call another method.
  • A complex task is split into small pieces: sumOfSquares delegates the work to square and sum.
  • The code becomes readable and manageable; each piece can be tested on its own.
  • sum(square(num1), square(num2)) evaluates the arguments first (left to right), then makes the outer call.
3² + 4² = 9 + 16 = 25.

Methods Calling Methods · Step-by-step code trace

sumOfSquares(3, 4): The Call Stack

main calls sumOfSquares(3, 4).

sum needs its arguments before it can be called: first square(num1).

A third frame is pushed: square(3) → 3 × 3 = 9 is returned.

square's frame is popped; the first argument (arg1) = 9. Next: square(num2).

square(4) → 4 × 4 = 16 is returned.

The arguments are ready: sum(9, 16) is called → 25. Here num1 = 9; sumOfSquares's is still 3.

sum's result becomes sumOfSquares's return value: 25 is returned.

Back in main: result = 25.

The screen shows 25. At most 3 frames were on the stack at once.

Scope

Scope

Scope is the region of code where a variable is declared and can be used.

  • Every variable has a scope: in Java, it is the brace-delimited block.
  • Scope determines a variable's accessibility and lifetime.
  • Local and global scopes have different access rules.
  • In nested scopes, the inner scope can access the outer scope's variables; the outer scope cannot see the inner one.
  • Using the same name in different scopes can lead to name clashes; misused scope causes bugs.

Scope

Local and Global Scope

public class InnerScope {
    static int globalVar = 10; // global (class field)
    static void method() {
        int outerVar = 10;       // local scope
        {
            int innerVar = 5;
            // outerVar and innerVar are visible here
            System.out.println(outerVar + innerVar
                    + globalVar);
        }
        // innerVar does NOT exist here
    }
    public static void main(String[] args) {
        method();
    }
}
Output
25

10 + 5 + 10 = 25: the inner block sees both the method's and the class's variables.

Local scope

Inside a method or block; lives as long as that block runs.

Global scope

Accessible everywhere, lives for the whole program. In Java, class fields play this role.

Nested scope

A scope within a scope; the inner one can access the outer one's variables.

Shadowing: Tracing the Code

The class field value = 10 is created when the program starts and lives as long as it runs. main calls show().

show gets a new frame; it has no local variables yet.

The local value = 5 is declared. Inside this method the name now means the local: the field is shadowed.

value is looked up in the innermost scope first → the local 5 is printed.

Shadow.value uses the class name to reach the field → 10.

show has ended; the local value is gone. main has no local value: the name means the field → 10.

When Are Variables Born, and When Do They Die?

The class field callCount is created when the program starts and lives as long as it runs. multiply(2, 3) is being called.

The method can access the class field: callCount becomes 1.

The local result is born now: 6.

multiply returned: num1, num2, result are gone. The value was assigned to first.

New frame: result = 24, counter 2.

second is a local variable that lives only inside the inner block.

Inside the block, second is accessible: 24 is printed.

The block ended, and second is gone: 6 2.

Abstraction and Design

Abstraction

Abstraction means ignoring details to reduce complexity.

Why?

It makes code more readable and simpler; it keeps large, complex programs understandable.

How?

It splits code into pieces that can be thought about separately. Whoever uses a method doesn't need to know its insides.

Everyday analogy: you don't need to know how the engine works to drive a car; the wheel and pedals are an "interface".

Abstraction and Design

Procedural Abstraction

Abstraction over computations, a.k.a. functional or procedural abstraction.

  • What matters is what a method computes, not how it computes it.
  • As long as you know its job, you don't care how it does it.
  • You don't worry about the method's implementation (its body).
  • Even if the body changes (say, a faster algorithm), the calling code stays the same.
System.out.println("Hello");

The method prints the given text to the console; you don't need to know how (character encoding, OS calls…).

// the caller only knows the signature:
static boolean isPrime(int num)
// "returns true if num is prime"
if (isPrime(17)) { ... }

Generalization

Context:

  • how a number relates to the other parts of an equation,
  • how a word's meaning depends on its place and role in a sentence,
  • the state and interactions inside a block of code.

The meaning of an expression can depend on the words around it.

Generalization:

  • adapting a solution from one context to fit others,
  • making a product more general and versatile.

In code, the tool for generalization is the parameter: fixed values become parameters.

public class Generalization {

    static void drawLine() {

Decomposition

Breaking a problem into small pieces (decomposition) is a basic step in programming. Each piece becomes a method, so the code is organized, readable, reusable and maintainable.

static double computeAverage(int[] grades) {
    int sum = 0;
    for (int n : grades) {
        sum += n;
    }
    return (double) sum / grades.length;

public static void main(String[] args) {
    Scanner in = new Scanner(System.in);

Abstraction and Design

When to Write a Method?

A rule of thumb: DRY (Don't Repeat Yourself). The moment you feel like copying and pasting code, that code is a candidate for a method.

Repeated code

double avg1 = (70 + 80 + 90) / 3.0;
System.out.println(avg1);
double avg2 = (55 + 60 + 100) / 3.0;
System.out.println(avg2);
// if the formula changes, every copy
// must be fixed separately

With a method

static double average(int a, int b, int c) {
    return (a + b + c) / 3.0;
}
System.out.println(average(70, 80, 90));
System.out.println(average(55, 60, 100));
Output
80.0
71.66666666666667

This matters for reuse and easy maintenance. A good method does one thing and is easy to read.

Abstraction and Design

Good Method Design

Single responsibility

Each method should do one thing. If you describe it with "and" (read and compute and print), split it.

Descriptive name

A verb that says what it does: computeAverage, isPrime, readGrades. doStuff2 and similar names say nothing.

Parameters

Take the data you need as parameters; don't secretly depend on outside variables. Few parameters read better.

Return value

Return the result explicitly with return. A method that computes shouldn't print; let the caller do the printing.

Short and focused

Methods of a few lines that fit on one screen are easy to understand and test.

Call where needed

Call a method only where you need it; recomputing the same result again and again in a loop is wasted work.

Abstraction and Design

Naming Variables

Each variable should represent one thing

  • A variable should hold a single object or piece of data; using the same variable first for an age and then for a total is confusing.
  • This makes code more readable and reusable, and reduces logic errors.

A good name

  • Is descriptive and meaningful; reflects the nature of the data it stands for.
  • Says what the variable holds and how it is used; meaningless or one-letter names hurt readability (the loop counter i and the mathematical x are exceptions).
  • Java convention: camelCase (studentCount), classes capitalized (Book), constants MAX_SIZE.

Expecting a swap method to workswap(int x, int y) only swaps the copies; after swap(arr[0], arr[2]) the array is unchanged. For array cells use swap(int[] d, int i, int j).
Overloading by return typeint f(int a) and double f(int a) cannot coexist: method f(int) is already defined. Only the name and parameter types make up the signature.
Expecting the argument to changeincrease(num) leaves num unchanged: the copy changes. Return the new value with return.
Forgetting Math's result typeint k = Math.sqrt(16); → possible lossy conversion from double to int. sqrt and pow return double.

Summary

Practice Problems (1)

static int f(int x) {
    x = x * 2;
    return x + 1;
}
public static void main(String[] args) {
    int a = 3;
    int b = f(a);
    System.out.println(a + " " + b);
    System.out.println(f(f(1)));
}
static int square(int n) { return n * n; }
static int cube(int n) { return n * square(n); }
// in main:
System.out.println(cube(2) + square(3));
  1. What does the program on the left print? Why didn't a change?
  2. What does the line on the right print? At most how many frames are on the stack while cube(2) runs (including main)?
Show answers
  1. 3 7 and 7. f doubles a copy of a; a stays 3. f(f(1)) = f(3) = 7.
  2. 8 + 9 = 17. main → cube(2) → square(2): at most 3 frames.

Practice Problems (2)

static int sum(int a, int b) { return a + b; }
static double sum(double a, double b) { return a + b; }
// in main:
System.out.println(sum(2, 3.0));
System.out.println(sum(2, 3));
System.out.println(Math.max(Math.abs(-8), Math.sqrt(49)));
  1. In the first two println calls, which sum method runs, and what is printed?
  2. Why does the last line not print 8 but 8.0?
Show answers
  1. sum(2, 3.0) → the double version (2 is widened to double): 5.0; sum(2, 3) → the int version: 5.
  2. Math.sqrt returns a double; max(int, double) picks the double version: 8.0.

Summary

Exercises

  1. boolean isEven(int num): return true if the number is even.
  2. int largest(int a, int b, int c): find the largest of three numbers with Math.max.
  3. int power(int base, int exp): compute the power with a loop (without Math.pow).
  4. int digitSum(int n): sum the digits of a number with a loop.
  5. double circleArea(double r) — write it, then print the result with printf to 2 decimal places.
  6. Overloaded double area(double r) (circle) and double area(double width, double height) (rectangle).
Answers / hints
  1. return num % 2 == 0; → isEven(7) = false, isEven(10) = true.
  2. return Math.max(a, Math.max(b, c)); → largest(4, 9, 2) = 9.
  3. int result = 1; for (int i = 0; i < exp; i++) result *= base; return result; → power(2, 10) = 1024.
  4. while (n != 0) { t += n % 10; n /= 10; } → digitSum(2024) = 8.
  5. return Math.PI * r * r; → printf("%.2f%n", circleArea(2)) → 12,57.
  6. area(1) → 3.14159…; area(3, 4) → 12.0. The number of arguments decides which version is called.
