The Array Concept

What Is an Array?

  • Array: a structure that stores data of the same type in an orderly way under a single name.
  • Think of it as one variable that can hold one or more values.
  • Elements are accessed by index number; indexing makes access very fast.
  • The first index is 0; in an array of n elements the last index is n − 1.
  • To access an element, write the array name followed by the index in square brackets: arr[0].
Apartment flatsOne address (the array name) and numbered flats (the indices). Saying "number 3" is enough to find the flat.
Egg cartonThe number of cells is fixed up front; the carton never grows. Each cell holds the same kind of thing.

Example: arr = [10, 20, 30, 40, 50], so arr[0] is the first element, with value 10; arr[4] is the last (50).

The Array Concept

Why Arrays?

Without arrays: 50 variables for 50 students

int grade1 = 70;
int grade2 = 85;
int grade3 = 90;
// ... up to grade50
int sum = grade1 + grade2 + grade3 /* + ... */;

Computing the mean means typing all 50 names; if the class size changes, so does the code.

With an array: one name, a loop does the work

int[] grades = new int[50];
// ... fill grades
int sum = 0;
for (int i = 0; i < grades.length; i++) {
    sum += grades[i];
}

The same code works for 5 grades or 5000: the index can be a variable (grades[i]), so the loop visits every element.

Here is the power of arrays: in grades[i] the cell to read is decided at run time by the value of i.

The Array Concept

Pros and Cons

Advantages
  • Stores data in order, contiguously.
  • Indexing gives fast access to elements: arr[i] takes the same time for every i.
  • Groups related data together; easy to process with loops.
  • Lean memory use: only the elements and the length are stored.
Disadvantages
  • Fixed size: once created, an array cannot be resized.
  • To add an element when it is full, you must create a larger new array and copy.
  • Inserting into or deleting from the middle requires shifting elements (extra cost).
  • Holds elements of one type only.

For lists that change size, Java offers ArrayList; it uses an array internally and grows it when full (java.util collections).

Access and length

  • Array elements are accessed by index; the index starts at 0.
  • arr[i] is used both for reading and writing.
  • The size of an array comes from the length field: the number of elements it holds.

The for-each Loop

int[] grades = {70, 85, 90};
// classic for: we have the index
for (int i = 0; i < grades.length; i++) {
    System.out.println("grade " + i + ": " + grades[i]);
}
// for-each: values only
int sum = 0;
for (int g : grades) {
    sum += g;
}
System.out.println("Sum: " + sum);

Output

grade 0: 70
grade 1: 85
grade 2: 90
Sum: 245
  • Enhanced for (for-each): for (type item : arr) puts the next element into item on each pass.
  • No index is written, so it cannot go out of bounds.
  • Only for reading: g = 0; changes only the copy, not the element in the array.
  • If you need the index (to write, report a position, compare neighbors), use a classic for.

for-each: You Get the Value, Not the Cell

A three-cell array lives on the heap; scores holds its reference.

sum starts at 0.

First pass: the loop takes scores[0] and puts a copy of it into p, so p = 60. No index is written.

sum += p → 60.

Second pass: p = 75 (the loop supplies the next element itself).

sum = 60 + 75 = 135.

Last pass: p = 95.

sum = 230. No elements left; the loop ends.

Sum: 230 is printed.

Second loop: p is again a copy of scores[0], 60.

p = 0 changes only the copy; the 60 in the array stays put. The remaining passes are the same.

60 95: the array never changed. for-each cannot write to the array; writing needs a classic for and scores[i].

An Array Variable Is a Reference

An array is created on the heap; the variable a holds not the array itself but its address (reference).

b = a only copies the address. Now both variables refer to the same array (aliasing).

b[0] = 99 changes the shared array…

…so a[0] also becomes 99.

clone() creates a new array on the heap and copies the elements; c refers to this new array.

c[1] = 77 changes only the copy; the original is unaffected.

a[1] is still 2, while c[1] is 77.

== compares references (addresses): a == b is true (same array), a == c is false (different arrays).

int[] a = {1, 2, 3};
int[] b = a;         // not a copy!
b[0] = 99;
System.out.println(a[0]);
int[] c = a.clone(); // a real copy
c[1] = 77;
System.out.println(a[1] + " " + c[1]);
System.out.println(a == b);
System.out.println(a == c);

Memory and Errors

Where Do Arrays Live in Memory?

String[] plates = {"", "Adana", "Adıyaman", "Afyon"};
System.out.println(plates[1]);
int[] dynamicArr = new int[10]; // allocated on the heap
System.out.println(dynamicArr.length);
dynamicArr = null; // reference dropped
System.out.println(dynamicArr == null);
  • In C/C++, int a[10]; is on the stack; a raw array from malloc/new[] is freed by hand with free/delete[] (C++'s std::vector does it for you).
  • Output: Adana, 10, true.
  • In Java, all arrays are on the heap; the size can be set at run time, then stays fixed. Freeing is automatic.

Both arrays are on the heap; only the reference variables are on the stack. (A String[]'s cells are references to separate String objects.)

dynamicArr = null does not delete the array; it only breaks the link. The array is now unreachable, so the garbage collector reclaims it later.

When the method returns, its stack frame and references go automatically; unreferenced arrays are collected in time. Java has no free/delete.

Memory and Errors

Index Out of Bounds

  • Accessing an index outside the array's bounds (0 … length − 1) makes Java throw, at run time, an ArrayIndexOutOfBoundsException (a subclass of IndexOutOfBoundsException).
  • If not caught, the program crashes at that line; it does not silently corrupt other memory as C does.
int[] arr = {10, 20, 30, 40, 50};
int index = 5;
// check the array length
if (index >= 0 && index < arr.length) {
    int value = arr[index];
    System.out.println("Value: " + value);
} else {
    System.out.println("Invalid index: " + index);
}
// unchecked access:
System.out.println(arr[index]);

Output

Invalid index: 5
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5
	at OutOfBounds.main(OutOfBounds.java:13)

The message gives the bad index (5), the array length (5) and the line number: the first place to look.

Memory and Errors

Classic Bug: Looping with <=

int[] arr = new int[3];
for (int i = 0; i <= arr.length; i++) {
    arr[i] = i * 10;
}
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
	at BoundsLoop.main(BoundsLoop.java:5)
  • i = 3: the condition 3 <= 3 is still true, and the loop tries to write arr[3].
  • Correct condition: i < arr.length; with a constant (i < 3) in place of length, the code would break when the size changes.

Median

MedianThe value in the middle of the sorted array. With an even count, it is the mean of the two middle values.

Statistics Examples

Median: Odd and Even Counts

The input is unsorted: the middle cell (9.0) is not the median.

Arrays.sort(arr) has run. Size 5 (odd): arr[5 / 2] = arr[2] → median 5.0. Integer division truncates 2.5 to 2.

Size 4 (even; input 7 3 9 5): mid1 = 4/2 − 1 = 1, mid2 = 4/2 = 2 → (5.0 + 7.0) / 2 = 6.0.

Why sort?The median is defined by order. The middle element of an unsorted array is just an arbitrary value.
Side effectArrays.sort changes the array in place; the input order is lost. To keep it, first take arr.clone().

ModeThe value that occurs most often in the array. For 4 2 7 2 4 2 9 the mode is 2 (3 times).

  • Then a single pass finds the longest "run": each element is compared with the one before it.

Statistics Examples · Step-by-step code trace

Mode: Counting Runs Step by Step

The array has already been sorted: equal values are now adjacent. The first element is the candidate for both current and mode (1 time).

arr[1] = 2 == arr[0] = 2 → the run continues, currentCount = 2. 2 > previous best → mode is 2 (2 times).

arr[2] = 2 == arr[1] = 2 → the run continues, currentCount = 3. 3 > previous best → mode is 2 (3 times).

arr[3] = 4 ≠ arr[2] = 2 → a new run starts: currentValue = 4, count 1.

arr[4] = 4 == arr[3] = 4 → the run continues, currentCount = 2.

arr[5] = 7 ≠ arr[4] = 4 → a new run starts: currentValue = 7, count 1.

arr[6] = 9 ≠ arr[5] = 7 → a new run starts: currentValue = 9, count 1.

i = 7: the loop ends. Mode = 2, occurring 3 times. With runs of equal length, the > comparison would keep the first one found.

int modeValue = arr[0];
int modeCount = 1;
int currentValue = arr[0];
int currentCount = 1;
for (int i = 1; i < size; i++) {
    if (arr[i] == arr[i - 1]) {
        currentCount++;
    } else {
        currentCount = 1;
        currentValue = arr[i];
    }
    if (currentCount > modeCount) {
        modeCount = currentCount;
        modeValue = currentValue;
    }
}

Array Algorithms · Step-by-step code trace

Linear Search

The simplest way to find an element in an array: look at every element in order, from first to last.

main, linearSearch(arr, 30): main calls it. The method receives the array's reference and 30.

item = 10: 10 == 30 is false → go to the next element.

item = 20: 20 == 30 is false → go to the next element.

item = 30: 30 == 30 → true. The loop stops early and returns true.

The method's frame is popped off the stack: result = true. 3 comparisons were enough; 40 and 50 were never examined. For a target of 35 it would return false after 5 comparisons.

static boolean linearSearch(int[] arr, int target) {
    for (int item : arr) {
        if (item == target) {
            return true;
        }
    }
    return false;
}

// in main:
int[] arr = {10, 20, 30, 40, 50};
boolean result = linearSearch(arr, 30);

Array Algorithms

Cost of Linear Search

  • In the worst case the whole array is scanned: n comparisons for n elements.
  • Time complexity is O(n) (n: array size): work grows in direct proportion to input size.
  • Best case: the target is first: 1 comparison.
  • Worst case: the target is last or absent.
  • Unsorted, nothing beats this: "absent" needs a look at every element.
int[] arr = {10, 20, 30, 40, 50};
// search an array for a given element
int key = 30;
boolean found = false;
for (int item : arr) {
    if (item == key) {
        found = true;
        break;
    }
} // this is O(n)

break exits as soon as the target is found: only 3 elements are checked and found = true.

Binary Search

static int binarySearch(int[] arr, int target) {
    int lo = 0, hi = arr.length - 1;
    while (lo <= hi) {
        int mid = (lo + hi) / 2;
        if (arr[mid] == target) {
            return mid;          // found
        } else if (target < arr[mid]) {
            hi = mid - 1;       // left half
        } else {
            lo = mid + 1;       // right half
        }
    }
    return -1;                    // range is empty
}

int[] arr = {3, 9, 14, 27, 42, 48, 55, 61, 70};

  • For 48 the middle indices are 4 (42), 6 (55), 5 (48): 3 comparisons. For 50 the range becomes empty once 6 > 5, and the method returns -1.
  • Each step halves the search range: O(log n). For n = 1000 at most 10 comparisons, for n = 1,000,000 at most 20.
  • Arrays.binarySearch uses the same method; on an unsorted array its result is meaningless.

Array Algorithms

Selection Sort

static void selectionSort(int[] arr) {
    for (int i = 0; i < arr.length - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < arr.length; j++) {
            if (arr[j] < arr[minIdx]) {
                minIdx = j;
            }
        }
        int tmp = arr[minIdx];
        arr[minIdx] = arr[i];
        arr[i] = tmp;
    }
}
  • Selection sort: at each step the smallest element is found and placed at the front of the unsorted part.
  • The outer loop runs n − 1 times, the inner loop scans the rest → O(n²) comparisons, at most n − 1 swaps.
  • Swap inside the array, using a temporary variable.
swap(int x, int y) as a swap method does not work: the method receives only copies of the elements. A working version takes the array itself: swap(int[] a, int i, int j).

Bubble Sort

static void bubbleSort(int[] arr) {
    int n = arr.length;
    for (int pass = 0; pass < n - 1; pass++) {
        boolean swapped = false;
        for (int j = 0; j < n - 1 - pass; j++) {
            if (arr[j] > arr[j + 1]) {  // out of order
                int tmp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = tmp;
                swapped = true;
            }
        }
        System.out.println(Arrays.toString(arr));
        if (!swapped) break;  // no swaps: sorted
    }
}

  • Bubble sort: two neighbors out of order are swapped; on each pass the largest element “bubbles up” to the end.
  • Each line is the result of one pass. After each pass the largest element is at the end, so the inner loop only runs up to n - 1 - pass.
  • swapped flag: on pass 5 there are no swaps, so the array is sorted and break stops early. A sorted array needs just one pass: O(n).
  • In the worst case it is still O(n²) comparisons; unlike selection sort, the number of swaps can also be O(n²).

Reversing an Array

static void reverse(int[] arr) {
    int left = 0;
    int right = arr.length - 1;
    while (left < right) {
        // swap the end elements
        int tmp = arr[left];
        arr[left] = arr[right];
        arr[right] = tmp;
        // move both indices inward
        left++;
        right--;
    }
}
  • The two-pointer technique: one index comes from the front, one from the back; each pass swaps the two end elements.
  • About n/2 swaps → O(n); no extra array is needed (in place).
  • The method is void, but since it receives a copy of the array's reference, the caller's array changes.

static Scanner scanner = new Scanner(System.in);

public static void makeMove(char[][] board, char player) {
    int row, col;
    do {
        System.out.print("Player " + player
                + ", enter row and column (1-3): ");

        col = scanner.nextInt() - 1;

            || board[row][col] != ' ');
    board[row][col] = player;
}

do-whileWhile an invalid or taken cell is chosen, the prompt repeats; a valid choice ends the loop.

        (board[0][0] == player && board[1][1] == player && board[2][2] == player) ||

static int mystery(int[] d) {
    int s = 0;
    for (int i = 0; i < d.length; i += 2) {
        s += d[i];
    }

}
static void modify(int[] d, int x) {
    d[0] = 100;
    x = 100;
}
// main:
int[] d = {4, 8, 15, 16, 23, 42};
int[] a = {1, 2, 3};
int x = 1;
modify(a, x);
  1. mystery(d): what does it return? What does the method compute?
  2. d[d.length / 2] = ?
  3. modify(a, x): what are a[0] and x? Why do they differ?
Show answers
  1. 42: the sum of the even-index elements, 4 + 15 + 23.
  2. 6 / 2 = 3 → d[3] = 16.
  3. 100 1: the method gets a copy of the array's reference, so the cell changes; x is a copy, and the original variable stays 1.

Worked Problems (2)

int[][] m = {{1, 2, 3}, {4, 5, 6}, {7, 8, 9}};
int trace = 0;
for (int i = 0; i < m.length; i++) {
    trace += m[i][i];
}
// ---
int[] b = new int[5];
for (int i = 1; i < b.length; i++) {
    b[i] = b[i - 1] + i;
}
System.out.println(Arrays.toString(b));
// ---
int[] p = {3, 1, 2};
int[] q = p;
q[2] = q[0] + q[1];
System.out.println(Arrays.toString(p));
  1. In the first snippet, what is trace? Which cells are added?
  2. What does the second snippet print?
  3. What does the third snippet print?
Show answers
  1. 15: the diagonal m[0][0] + m[1][1] + m[2][2] = 1 + 5 + 9 (the trace of the matrix).
  2. [0, 1, 3, 6, 10]: each cell adds its index to the previous one (0, 0+1, 1+2, 3+3, 6+4).
  3. [3, 1, 4]: q and p are the same array; writing q[2] = 3 + 1 changes p too.
