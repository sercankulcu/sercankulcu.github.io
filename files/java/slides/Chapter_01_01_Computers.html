Computer Basics

The Basic Parts of a Computer

  • Processor (CPU, central processing unit): the “brain” of the computer; it does all arithmetic and logical work.
  • Memory (RAM, random access memory): holds the running program and its data temporarily. Its size and access speed directly affect how fast the computer is.
  • Disk (HDD / SSD): stores data persistently; nothing is lost when the power goes off.
Kitchen analogy: the cook is the CPU, the counter is RAM (small but within reach), the pantry is the disk (large but far away). The cook brings ingredients from the pantry to the counter and works there.

Computer Basics

How a Computer Works, and Programming

The basic steps:

  1. The processor receives instructions.
  2. It carries them out in order.
  3. The results go to the user or to other software.

Programming is writing instructions, in a form the computer understands, so that it performs the task we want.

Our first Java program: a single instruction, “print to the screen”.

public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}

Output:

Hello, World!

Instructions written in a language like Java run only after they are translated into machine code the processor understands.

Computer Basics

How Do You Build a Computer?

We build the computer layer by layer, each resting on the one below:

  • First we turn electrical signals into numbers.
  • Numbers represent letters; letters make up text.
  • Sequences of numbers store structured information such as images, sound and video.
  • Instructions too are stored in memory as numbers.
  • The von Neumann architecture ties it all together.

Numbers

From Electrical Signal to Bit

  • At bottom, a computer processes electrical signals by fixed rules; those rules give rise to everything it does.
  • Once signals are tied to numbers and symbols people understand, the computer can give us meaningful information.
  • Signals are handled in binary (base 2): each digit, or bit (binary digit), is either 0 or 1.
  • Every operation is built on this binary foundation.

8 bits = 1 byte. Memory and file sizes are measured in bytes: 1 KB ≈ 1000 bytes, 1 KiB = 1024 bytes.

Decimal to Binary: Repeated Division by 2

Start with n = 13.

The result string starts empty: bits = "".

13 > 0 is true → enter the loop.

Remainder 13 % 2 = 1: the rightmost bit not yet written.

The remainder goes in front of the string → "1"; n is halved: 13 / 2 = 6 (integer division).

6 > 0 is true → enter the loop.

Remainder 6 % 2 = 0: the rightmost bit not yet written.

The remainder goes in front of the string → "01"; n is halved: 6 / 2 = 3 (integer division).

3 > 0 is true → enter the loop.

Remainder 3 % 2 = 1: the rightmost bit not yet written.

The remainder goes in front of the string → "101"; n is halved: 3 / 2 = 1 (integer division).

1 > 0 is true → enter the loop.

Remainder 1 % 2 = 1: the rightmost bit not yet written.

The remainder goes in front of the string → "1101"; n is halved: 1 / 2 = 0 (integer division).

0 > 0 is false → the loop ends. The remainders are read bottom to top.

The result is printed: 13₁₀ = 1101₂.

public static void main(String[] args) {
  int n = 13;
  String bits = "";
  while (n > 0) {
    int rem = n % 2;
    System.out.println(n + " % 2 = " + rem);
    bits = rem + bits;
    n = n / 2;
  }
  System.out.println("Result: " + bits);
}

Addition Follows the Same Rules in Every Base

Whatever the base, the same principles apply: place values, the carry, and a correct result.

In decimal 7 + 8 = 15 → write 5, carry 1. In binary 1 + 1 = 2 = 10₂ → write 0, carry 1.

Write the two numbers one above the other: 57 = 00111001₂ and 28 = 00011100₂. Addition starts at the right.

Column 1: 1 + 0 = 1 → write 1, no carry.

Column 2: 0 + 0 = 0 → write 0, no carry.

Column 3: 0 + 1 = 1 → write 1, no carry.

Column 8: 0 + 0 = 0 → write 0, no carry. Result: 01010101₂ = 64 + 16 + 4 + 1 = 85 ✓

Numbers

Negative Numbers: Two's Complement

  • Negative integers are usually stored in two's complement.
  • Rule: invert the bits of the positive number, then add 1.
  • The leftmost bit acts as a sign bit: 0 → positive, 1 → negative.
  • Range with 8 bits: −128 … 127. With n bits: −2n−1 … 2n−1 − 1.

On an 8-bit computer, 3 is 00000011.

Step 1: invert every bit (0 ↔ 1): 00000011 → 11111100 (the ones' complement).

Step 2: add 1: 11111100 + 1 → 11111101. That is −3.

Why does it work? Adding 3 + (−3), the 9th bit overflows and is dropped, leaving exactly 0: the ordinary adder does the job.

Another view: the leftmost bit has weight −128, so when it is 1 the number is negative.

Numbers

Very Large and Very Small Numbers: Floating Point

  • A fixed number of digits can represent only a fixed number of values.
  • For very large or small numbers, the value is split into a fraction (mantissa) and an exponent, stored separately.
  • Example: in the 8-digit form 31415901, the first six digits (314159) are the fraction and the last two (01) the power of 10, i.e. 10¹.
  • Computers apply the same idea in binary: the IEEE 754 standard. In Java, float is 32 bits and double 64.

Hence the name floating point: as the exponent changes, the decimal point moves: 0.314159 × 10³ = 314.159.

Letters and Strings

Letters as Numbers: ASCII

  • To process text, every letter must be mapped to a number: a character encoding.
  • ASCII (American Standard Code for Information Interchange) was published in 1963 by the US standards body ASA (today ANSI).
  • It assigns numbers to upper- and lowercase letters, digits, punctuation and special characters.
  • It is a 7-bit code: 128 characters (0–127). 0–31 and 127 are control characters; 32–126 are printable.
  • 8-bit extensions (e.g. ISO 8859-9 and Windows-1254 for Turkish) put extra letters in 128–255, for 256 symbols.
  • No single 8-bit table is enough for all the world's languages.

One Table for Every Language: Unicode

  • Unicode gives every letter, symbol and mark of the world's writing systems a number, its code point: U+0041 = A, U+00E7 = ç.
  • It is developed by the Unicode Consortium (1991) and kept in sync with the international standard ISO/IEC 10646.
  • The first version was 16-bit (65,536 characters). When that ran out, the range grew to U+10FFFF: 1,114,112 code points, over 150,000 characters today.
  • Storing every character in a fixed 32 bits (UTF-32) wastes space on text like English. Hence the UTF (Unicode Transformation Format) encodings.

Stored Program

The Stored-Program Concept

  • The core principle of modern computers: instructions are numbers, just like data, and live in the same memory.
  • Together, the instructions and data in memory form the program. Each instruction stands for one task or operation.
  • Instructions are executed sequentially.
  • When a condition holds, the program can jump to a different instruction, so it can take different paths (if and loops build on this later).

ENIAC (1945)

  • Programs are set up by hand with cables and switches.
  • A new program means days of rewiring.

EDVAC design (1945)

  • Instructions and data are stored in sequence in memory.
  • Changing the program = writing new numbers to memory: flexible and extensible.

J. von Neumann's 1945 EDVAC report spread the idea; the first machine to run a stored program was the Manchester “Baby” (1948).

Stored Program

The Memory Hierarchy

  • Memory temporarily holds running programs and their data.
  • L1 cache: the fastest, inside the processor.
  • L2 cache: backs up L1 and is larger. Most processors also have an L3.
  • Main memory (RAM): much larger but slower.
  • Memory close to the processor is faster but smaller and costlier; the hierarchy directly affects performance.

Sizes and times are approximate and vary by processor. 1 ns = one billionth of a second.

Stored Program

The Processor (CPU) and the Bus

Central Processing Unit (CPU)

  • The “brain” of the computer; all computation happens here.
  • Arithmetic logic unit (ALU): does addition, subtraction, comparison and the like.
  • Control unit: decodes instructions and sequences operations.
  • Registers: tiny but very fast storage for temporary values.

The Bus

  • A communication pathway made of many parallel wires.
  • Address signals select which memory cell or device to access.
  • Data signals carry the actual data to process or store.
  • Control signals direct the operation, e.g. “read” or “write”.
The electronics link: a 32-line address bus can select 2³² addresses → 4 GiB of memory. That is why 32-bit systems could use at most about 4 GB of RAM.

Stored Program

CPU – Memory – Bus – Registers

  • The CPU names the cell it wants on the address bus.
  • The cell's contents travel over the data bus: in (read) or out (write).
  • PC (program counter): address of the next instruction.
  • IR (instruction register): the instruction being decoded.
  • R1, R2, AC (accumulator): intermediate results.
  • The ALU computes with the numbers in registers.

Stored Program

Memory, Addresses and the Program Counter

  • Memory holds data and instructions; a program is a long list of instructions.
  • Every memory cell has an address and holds an instruction or a piece of data encoded as a number.
  • Instructions are fetched one at a time into the processor's registers and executed in order.
  • One of the most important registers is the program counter (PC): it holds the address of the next instruction.
  • Normally the processor moves through addresses in order, but some instructions change the order: “JUMP 7” at 204 sets the PC to 211.

Stored Program

The Fetch–Decode–Execute Cycle

The fetch–decode–execute cycle describes how the processor runs a program.

  1. Fetch: the processor reads the next instruction from the address in the PC; the PC advances to the next address.
  2. Decode: the instruction is decoded: which operation, which registers, which address? Each instruction has a specific function.
  3. Execute: the operation is carried out: processing data, computing a result or starting an action.

Then the next instruction is fetched, and the cycle repeats continuously as long as the computer is on.

A 3 GHz processor's clock “ticks” 3 billion times a second; modern processors overlap several instructions (a pipeline).

Stored Program · Step by step

102 + 25 on a Toy Computer

Program and data are in memory. Initially PC = 200.

Fetch: the instruction at 200 goes into IR; PC advances to 201.

Decode: operation = LOAD, target = R1, address = 205.

Execute: mem[205] = 102 is read into R1.

Fetch: the instruction at PC = 201 is read; PC becomes 202.

Decode: operation = ADD: add R1 and mem[206].

Execute: the ALU computes 102 + 25 = 127 into R1.

Fetch: the STORE at 202 is read; PC becomes 203.

Decode: R1 is to be written to address 207 (control bus: “write”).

Execute: mem[207] ← 127. The result is now in memory.

Fetch: the HALT at 203 is read; PC becomes 204.

Decode + Execute: HALT → the processor stops. A Java line like sum = a + b; ends up as instructions like these.

200: LOAD  R1, [205] ; R1 ← mem[205]
201: ADD   R1, [206] ; R1 ← R1 + mem[206]
202: STORE R1, [207] ; mem[207] ← R1
203: HALT            ; stop
204: ...
205: 102             ; data
206: 25              ; data
207: 0               ; result here

von Neumann Architecture

The von Neumann Architecture

  • The hardware blueprint of the stored-program idea: processor, memory, input/output and the bus that connects them.
  • Instructions and data sit in the same memory and travel over the same bus.
  • Each instruction carries an opcode that says which operation to perform.
  • A single bus can leave the processor waiting: the von Neumann bottleneck. That is why caches exist.

By contrast, the Harvard architecture keeps instruction and data memory separate; many microcontrollers, such as the AVR in an Arduino, use it.

von Neumann Architecture

Instructions Are Numbers Too: Encoding

Take a toy computer: 8 bits, 4 registers (R0–R3), 256 8-bit memory cells and 4 instructions: add (00), subtract (01), multiply (10), divide (11).

  • The first 2 bits are the opcode (4 instructions → 2 bits).
  • The next 2 bits are the destination register.
  • The last 4 bits are two source registers (2 bits each).

“Add R0 and R2, store the result in R3” = 0 3 0 2 → 00110010

The processor's “decode” step in Java: division by place value!

int instr = 0b00110010;
int opcode = instr / 64;     // first 2 bits
int dest = (instr / 16) % 4;   // next 2 bits
int src1 = (instr / 4) % 4;  // next 2 bits
int src2 = instr % 4;        // last 2 bits
System.out.println(instr);
System.out.println(opcode + " " + dest
    + " " + src1 + " " + src2);

Output:

50
0 3 0 2

von Neumann Architecture · Code trace

Decoding an Instruction: Code Trace

The instruction is an 8-bit number: 00 11 00 10 = 50. Its bits split into four pairs.

Dividing by 64 = 2⁶ drops the right 6 bits, leaving the first 2: 00 = 0, i.e. add.

Dividing by 16 drops the right 4 bits (0011 = 3); % 4 keeps the last 2: 3 → R3.

Dividing by 4 drops the right 2 bits (001100 = 12); 12 % 4 = 0 → R0.

% 4 gives the last 2 bits directly: 10 = 2 → R2.

The instruction prints as a number: 50.

Fields: 0 3 0 2. To the processor, the number 50 means “R3 ← R0 + R2”.

int instr = 0b00110010;
int opcode = instr / 64;     // first 2 bits
int dest = (instr / 16) % 4;   // next 2 bits
int src1 = (instr / 4) % 4;  // next 2 bits
int src2 = instr % 4;        // last 2 bits
System.out.println(instr);
System.out.println(opcode + " " + dest
    + " " + src1 + " " + src2);

Common Mistakes

Literal out of rangebyte b = 200; → error: incompatible types: possible lossy conversion from int to byte. A byte tops out at 127.
Forgetting the L suffixlong x = 3000000000; → error: integer number too large. Write 3000000000L.
Mixing up char and Stringchar c = "A"; → error: incompatible types: String cannot be converted to char. A char takes single quotes: 'A'.
A leading zeroint x = 010; is octal, so its value is 8! And int y = 08; won't compile (error: ';' expected): octal has no digit 8.
Ignoring overflowInteger.MAX_VALUE + 1 raises no error; it becomes −2147483648. Large products need long: 1920L * 1080.
== on floating point0.1 + 0.2 == 0.3 → false. Check that the difference is small instead. Also, "😀".length() is 2, not 1.
