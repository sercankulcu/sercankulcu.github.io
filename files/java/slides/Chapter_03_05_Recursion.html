The Concept of Recursion

What Is Recursion?

  • Recursion: a method solving a task by breaking it into smaller pieces and calling itself.
  • Each call solves a smaller instance of the same problem; the smallest instance is solved directly.
  • The process is self-similar: a structure contains a smaller structure of the same kind.
  • For some problems (trees, series, divide and conquer) it gives clearer and cleaner solutions than loops.
Java has no keyword for recursion: a method simply calls itself by name in its body.
Matryoshka dollsEach doll holds a smaller one; the smallest does not open (the base case).

The Concept of Recursion

Base Case and Recursive Step

1. Base caseThe smallest problem, whose answer is known directly. The method does not call itself here, so the recursion stops. E.g. 1! = 1.
2. Recursive stepThe method makes the problem one step smaller, calls itself on it and builds its answer from the result. E.g. 4! = 4 × 3!.

It mirrors the inductive definition in mathematics:
n! = 1 (if n ≤ 1),   n! = n × (n − 1)! (if n > 1)

The Concept of Recursion

Call Stack

  • Each method call opens a stack frame in memory, holding the parameters, local variables and return address.
  • Frames are stacked on the call stack; only the top frame runs, the others wait.
  • In recursion, several frames of the same method are alive at once, each with its own n.
  • When the method executes return, its frame is removed and the value goes to the frame below (last in, first out: LIFO).
  • The stack is limited in size; very deep recursion ends with StackOverflowError.

Factorial and Sum

Computing a Factorial

int factorial(int n) {
    if (n == 0 || n == 1) {
        return 1;   // base case
    } else {
        return n * factorial(n - 1); // recursion
    }
}
Mathematicsn! = 1 × 2 × … × n
n! = n × (n − 1)!,  0! = 1! = 1
Lines 2–3: base case0! = 1! = 1; recursion stops here.
Line 5: recursive stepn! is (n − 1)! times n.
ProgressEach call decreases n by 1 → for n ≥ 0 the base case is always reached.
Overflowint cannot hold 13!: factorial(13) = 1932053504 (wrong!). long works up to 20!.

Calls: factorial(5) → 120 · factorial(0) → 1

Factorial and Sum

Expanding factorial(4)

factorial(4)
  = 4 * factorial(3)
  = 4 * (3 * factorial(2))
  = 4 * (3 * (2 * factorial(1)))
  = 4 * (3 * (2 * 1))
  = 4 * (3 * 2)
  = 4 * 6
  = 24
Descent (calls)In the first four lines each call opens another; the multiplications are deferred, because the right-hand value is not known yet.
Bottom (base case)factorial(1) returns 1 directly. Since the code stops at n == 1, factorial(0) is never called.
Ascent (returns)The pending multiplications complete from the inside out: 2 × 1, 3 × 2, 4 × 6.

Factorial and Sum

Computing a Sum

int sum(int n) {
    if (n == 1) {
        return 1;
    } else {
        return n + sum(n - 1);
    }
}

Sum of the numbers from 1 to n: sum(n) = n + sum(n − 1), sum(1) = 1.

sum(5) = 5 + sum(4)
       = 5 + (4 + (3 + (2 + sum(1))))
       = 5 + (4 + (3 + (2 + 1)))
       = 15

Same pattern as factorial; only × becomes +, and the base case differs. sum(100) = 5050.

The only base case is n == 1. sum(0) or a negative argument never makes n equal 1: 0, −1, −2, … infinite recursion → StackOverflowError.

A safe version uses the base case if (n <= 0) return 0;, which also catches every invalid input.

Series

Fibonacci Series

  • Starts with 0, then 1: F(0) = 0, F(1) = 1.
  • General formula: F(n) = F(n − 1) + F(n − 2): each term is the sum of the previous two.
  • The method calls itself twice: the calls form a tree (tree recursion).
int fibonacci(int n) {
    if (n <= 1) {
        return n;
    } else {
        return fibonacci(n - 1) + fibonacci(n - 2);
    }
}
n0123456789101112
F(n)01123581321345589144

Known from the rabbit-breeding problem (Leonardo Fibonacci, 1202). The ratio of consecutive terms approaches the golden ratio (≈ 1.618): 144 / 89 ≈ 1.618.

Series

Lucas Series

  • Starts with 2, then 1: L(0) = 2, L(1) = 1.
  • Same general formula as Fibonacci: L(n) = L(n − 1) + L(n − 2).
  • Only the starting values differ → two separate base cases are needed.
int lucas(int n) {
    if (n == 0) {
        return 2;
    } else if (n == 1) {
        return 1;
    } else {
        return lucas(n - 1) + lucas(n - 2);
    }
}

L(n)18294776123

The two series are linked: L(n) = F(n − 1) + F(n + 1). E.g. L(5) = F(4) + F(6) = 3 + 8 = 11.

Series

Catalan Series

  • Starts with 1: C(0) = 1, C(1) = 1.
  • Closed form: C(n) = (2n)! / ((n + 1)! · n!).
  • Recursive formula used by the code: C(n) = Σ C(i) · C(n − 1 − i), i = 0 … n − 1.
  • The recursion runs inside a loop: each C(n) is built from all smaller C values.
long catalan(int n) {
    if (n <= 1) {
        return 1;
    }
    long result = 0;
    for (int i = 0; i < n; i++) {
        result += catalan(i) * catalan(n - i - 1);
    }
    return result;
}

112514421324291430

What does it count? The valid arrangements of n pairs of parentheses. n = 3 → C(3) = 5:

((()))(()())(())()()(())()()()

Also the ways to parenthesize a product of n + 1 numbers, and the binary trees with n nodes.

Series

Bell Series

  • Starts with 1: B(0) = 1, B(1) = 1.
  • General formula: B(n) = Σ C(n − 1, k) · B(k), k = 0 … n − 1; here C(n, k) is the binomial coefficient.
int bell(int n) {
    if (n == 0) { return 1; }
    int count = 0;
    for (int k = 0; k < n; k++) {
        count += choose(n - 1, k) * bell(k);
    }
    return count;
}

int choose(int n, int k) {       // C(n, k)
    return factorial(n) / (factorial(k) * factorial(n - k));
}

Values:

11251552203877

What does it count? The ways to partition a set of n elements into groups. {a, b, c} → B(3) = 5:

abca|bcb|acc|aba|b|c
choose uses factorial, which returns int; 13! overflows, so the code is correct only for n ≤ 13.

Writing Recursive Methods

Two Basic Rules

Rule 1: Base case

At least one base case is needed to avoid infinite recursion. For example, when n is 0 or 1 the method must finish without calling itself.

Rule 2: Make progress

Every recursive call must move toward the base case: the parameter shrinks (or grows), the string gets shorter, the range narrows.

  • Infinite recursion (no base case, or it is never reached) and insufficient progress (the parameter does not change) are the two most common errors.
  • Each recursive call should work on a smaller part of the problem.
  • The base case is always tested before the recursive call.
  • Consider every possible input: do a negative number, 0 and an empty string reach the base case?

Writing Recursive Methods

Infinite Recursion

public class Sum {
    static int sum(int n) {
        if (n == 1) {
            return 1;
        } else {
            return n + sum(n - 1);   // line 6
        }
    }
    public static void main(String[] args) {
        System.out.println(sum(0));
    }
}
Exception in thread "main" java.lang.StackOverflowError
	at Sum.sum(Sum.java:6)
	at Sum.sum(Sum.java:6)
	at Sum.sum(Sum.java:6)
	...

sum(0): n = 0, −1, −2, … never reaches 1. Each call opens a new frame; after some ten thousand calls the stack is full and the JVM stops the program.

The compiler does not catch this error; it appears at run time. In the stack trace, the same line repeating is the sign of infinite recursion.

Fix: widen the base case (n <= 1), validate the input, or switch to a loop when the depth is very large.

sum(0): How Does the Stack Fill Up?

main calls sum(0). The only base case is n == 1.

n = 0: 0 == 1 is false → 0 + sum(-1) must be computed: a new call.

n = -1: still not 1. With each call n moves away: the base case will never be reached.

Each call pushes a new frame; none can return, since each waits for the next one's result.

After a thousand calls the stack holds 1001 frames; still no error.

The memory reserved for the stack is full: the JVM throws StackOverflowError. On this machine the measured depth is ≈ 10,200 calls; it depends on JVM settings.

Writing Recursive Methods

Thinking Recursively

  1. Reduce: express the problem in terms of a smaller copy of itself.
  2. Base case: find the smallest input whose answer is known directly.
  3. Trust: the smaller copy is assumed to be solved correctly (the leap of faith); do not unfold the call in your head.
  4. Combine: build the big answer from the small one.

Example: the number of digits in a number.

  • Digits of 48729 = 1 + digits of 4872.
  • A one-digit number (n < 10) → 1.
int countDigits(int n) {
    if (n < 10) {                       // base case
        return 1;
    }
    return 1 + countDigits(n / 10);     // reduce + combine
}

countDigits(48729) → 5 · countDigits(7) → 1

Examples

Digit Sum

int digitSum(int n) {
    if (n < 0) {
        return digitSum(-n);
    } else if (n < 10) {
        return n;
    } else {
        return digitSum(n / 10) + (n % 10);
    }
}
  • A negative number is first made positive (lines 2–3).
  • A one-digit number is its own digit sum: base case (lines 4–5).
  • Otherwise: last digit + sum of the remaining digits.
  • For Integer.MIN_VALUE, -n is still negative: infinite recursion (compute with long).

n / 10 (integer division) drops the last digit; n % 10 yields the last digit. Each call shortens the number by one digit → progress is guaranteed.

The first call fixes the sign; after that each step leaves its last digit (9, 2, 7, 8) outside as a pending addition.

Base case digitSum(4) → 4. On the way back the additions run from the inside out: 4 + 8 + 7 + 2 + 9 = 30.

6 calls in total (1 for the sign + 5 digits).

Checking a Palindrome

static boolean isPalindrome(String s) {
    if (s.length() <= 1) {
        return true;
    } else if (s.charAt(0) == s.charAt(s.length() - 1)) {
        return isPalindrome(s.substring(1, s.length() - 1));
    }
    return false;
}

isPalindrome("kayak") → true · isPalindrome("abba") → true · isPalindrome("java") → false

  • Palindrome: a string that reads the same backward (kayak, never odd or even).
  • s.charAt(i): the character at index i (from 0).
  • s.substring(1, s.length() - 1): the string without its first and last letters.
  • Two base cases: length ≤ 1 → true; ends differ → false.
  • Case-sensitive: "Kayak" → false.

Greatest Common Divisor

static int gcd(int x, int y) {
    if (y == 0) {
        return x;
    }
    return gcd(y, x % y);
}
  • Euclid's algorithm: gcd(x, y) = gcd(y, x mod y).
  • Base case: if y = 0, then gcd = x.
  • The remainder shrinks at every step → it must reach 0.
  • gcd(93, 444): its first step is gcd(444, 93); the order does not matter.
gcd(444, 93)
  = gcd(93, 72)     // 444 % 93 = 72
  = gcd(72, 21)     // 93 % 72 = 21
  = gcd(21, 9)      // 72 % 21 = 9
  = gcd(9, 3)       // 21 % 9 = 3
  = gcd(3, 0)       // 9 % 3 = 0
  = 3

gcd: greatest common divisor. gcd(48, 18) → 6.

Examples

Towers of Hanoi

Three pegs (A, B, C) and n disks on A, largest at the bottom. Move them all to C:

  • Move only one disk at a time, always the top one.
  • A larger disk is never placed on a smaller one.

Recursive idea: move the top n − 1 disks to the spare peg, the largest disk to the target, then the n − 1 disks from the spare onto the target.

Number of moves 2ⁿ − 1: 3 disks → 7, 10 disks → 1023, 64 disks → about 1.8 × 10¹⁹.

public class TowersOfHanoi {
    static void solve(int n, char from,
                      char to, char via) {
        if (n == 1) {   // one disk: move it
            System.out.println(n + ": " + from + "->" + to);
        } else {
            solve(n - 1, from, via, to);
            System.out.println(n + ": " + from + "->" + to);
            solve(n - 1, via, to, from);
        }
    }
    public static void main(String[] args) {
        solve(3, 'A', 'C', 'B');
    }
}

Hard to write with loops, this problem takes only a few lines with recursion.

Examples · Step-by-step code trace

Towers of Hanoi: solve(3, 'A', 'C', 'B')

Start: 3 disks on A. solve(3, 'A', 'C', 'B'): move three disks to C, using B as the spare.

The deepest call solve(1, A, C, B): base case, disk 1 goes straight from A to C.

solve(2, A, B, C): disk 1 is out of the way; disk 2 goes from A to B.

Disk 1 goes on top of disk 2: solve(1, C, B, A). The top 2 disks are now on B.

solve(3, …) reaches its middle line: the largest disk (3) goes from A to C.

Now the 2 disks on B go to C: solve(2, B, C, A) → first, disk 1 goes from B to A.

Disk 2 goes from B to C, on top of disk 3.

Last move: disk 1 from A to C. 2³ − 1 = 7 moves; the puzzle is solved.

static void solve(int n, char from,
                  char to, char via) {
    if (n == 1) {
        System.out.println(n + ": " + from + "->" + to);
    } else {
        solve(n - 1, from, via, to);
        System.out.println(n + ": " + from + "->" + to);
        solve(n - 1, via, to, from);
    }
}

Efficiency

Efficiency

  • Recursive methods can sometimes be slow: every call has a cost (opening a frame, copying parameters).
  • As recursive calls are made, the system keeps the pending partial results on the call stack.
  • If the stack overflows, the program ends with StackOverflowError.
  • When this is a problem, the fix is an iterative solution built on loops.
  • Iterative solutions keep no partial results: one frame and a few variables suffice.
Memoryfactorial(n), recursive: n frames, O(n) memory. With a loop: O(1).
Depth limitWith the default stack, a depth of a few tens of thousands of calls gives StackOverflowError.
RepetitionTree recursion (Fibonacci) may compute the same values many times.

Efficiency

Factorial with a Loop

Recursive

int factorial(int n) {
    if (n == 0 || n == 1) {
        return 1;
    } else {
        return n * factorial(n - 1);
    }
}

Iterative (loop)

int factorial(int n) {
    int product = 1;
    for (int i = 1; i <= n; i++) {
        product *= i;
    }
    return product;
}
Same result (factorial(5) → 120). The loop version uses one frame and constant memory; the variable product accumulates the product. n ≥ 0 is assumed: for negative n the recursive version throws StackOverflowError, the loop version returns 1; 13! overflows int.

Efficiency

Digit Sum and Palindrome with Loops

Digit sum

int digitSum(int n) {
    int sum = 0;
    int rest = Math.abs(n);
    while (rest > 0) {
        sum += rest % 10;
        rest /= 10;
    }
    return sum;
}

digitSum(-48729) → 30: same as the recursive version. A digit sum cannot be negative; the sign is simply dropped with Math.abs (for Integer.MIN_VALUE, Math.abs stays negative; long rest = Math.abs((long) n) fixes it).

Palindrome

boolean isPalindrome(String s) {
    s = s.toLowerCase();
    int len = s.length();
    for (int i = 0; i < len / 2; i++) {
        if (s.charAt(i) != s.charAt(len - 1 - i)) {
            return false;
        }
    }
    return true;
}

i moves from the start, len − 1 − i from the end. toLowerCase() makes "Kayak" return true. Prefer toLowerCase(Locale.ROOT): in the default tr locale, I → ı.

Tail Recursion

Tail Recursion

  • The method's last operation is the recursive call itself; nothing is left to do on return.
  • The result is carried in an extra accumulator parameter.
  • This form lets the compiler apply tail call optimization (TCO): the call is treated like a loop and frames do not pile up → memory efficiency.
  • Java (the JVM) does not do this: tail-recursive Java code still uses O(n) stack. Languages such as Scheme, Scala (@tailrec), Kotlin (tailrec) do it.

Not tail-recursive

return n * factorial(n - 1);
// multiply AFTER the call returns

Tail-recursive

return factorial(n - 1, n * acc);
// multiply first; the call is last

Tail Recursion

Tail-Recursive Examples

int digitSum(int num, int sum) {
    if (num == 0) {
        return sum;
    } else {
        return digitSum(num / 10,
                        sum + num % 10);
    }
}

Digit sum: the last digit is added to sum before the call. digitSum(48729, 0) → 30 (for n ≥ 0).

int factorial(int n, int acc) {
    if (n == 0) {
        return acc;
    } else {
        return factorial(n - 1, n * acc);
    }
}

Factorial: the product goes into acc before the call. factorial(5, 1) → 120.

The accumulator starts at the identity element of the operation: for addition 0, for multiplication 1. A wrapper method spares the caller from passing it: int factorial(int n) { return factorial(n, 1); }

Memoization

Memoization

  • The results of repeated computations are stored and reused (the method carries state).
  • Results go into a cache (Map); when the same argument comes again, it is returned without recomputation.
  • For each n the work is done once: the exponential number of calls drops to linear.
  • Map<Integer, Long>: key n, value F(n).

fibonacci(90) → 2880067194370816120 (instantly).

import java.util.HashMap;
import java.util.Map;

static Map<Integer, Long> memo = new HashMap<>();

static long fibonacci(int n) {
    if (memo.containsKey(n)) {
        return memo.get(n);    // computed before
    }
    if (n == 0 || n == 1) {
        return n;
    }
    long result = fibonacci(n - 1) + fibonacci(n - 2);
    memo.put(n, result);        // store the result
    return result;
}

n = 1: base case, 1 is returned.

n = 0: base case, 0 is returned.

fibonacci(3)'s second call, fibonacci(1): base case, 1.

Memoization

Memoized Factorial

static Map<Integer, Long> memo = new HashMap<>();

static long factorial(int n) {
    if (memo.containsKey(n)) {
        return memo.get(n);
    }
    if (n == 0 || n == 1) {
        return 1;
    }
    long result = n * factorial(n - 1);
    memo.put(n, result);
    return result;
}
  • Same pattern: check the memo; if absent, compute, store, return.
  • long is exact up to 20!: factorial(20) = 2432902008176640000.
  • A single factorial(n) call has no repetition; the memo does not speed it up.
  • The gain appears when the program asks for factorials many times: after factorial(10), factorial(12) needs only 2 new multiplications.
  • The cost is memory: memoization trades memory for speed.

Summary

ConceptMeaning
RecursionA method calling itself on a smaller input
Base caseThe smallest case, solved directly; stops the recursion
ProgressEach call moves toward the base case (n − 1, n / 10, substring, x % y)
Call stackOne frame per call, popped in LIFO order. Too deep → StackOverflowError
Tree recursionSeveral calls (Fibonacci, Hanoi); the call count can grow exponentially
Iterative solutionLoop + accumulator variable; constant memory, usually faster
Tail recursionThe last step is the call; the result is in the accumulator. Java has no TCO
MemoizationStoring computed results in a Map and reusing them

Common Mistakes

Missing / unreachable base case

sum(0), for example: Exception in thread "main" java.lang.StackOverflowError.

No progress

return n * factorial(n); does not shrink the parameter; again StackOverflowError.

Missing return

if … else if as the last branch of a method: error: missing return statement. Fix: make the last branch else.

Ignoring the call's result

factorial(n - 1); on its own line loses the value; it should be return n * factorial(n - 1);.

Overflow

int factorial goes wrong at 13!, the Bell coefficient after 13, with no error message. Fix: long.

Needless tree recursion

Without memoization, fibonacci(50) takes minutes. Fix: a loop or memoization.

Exercises

  1. long power(int base, int exp): compute base to the power exp recursively. power(2, 10) = ?
  2. void binary(int n): print the binary representation of n. binary(13) → ?
  3. int arraySum(int[] a, int i): the sum of the array from index i to the end. {3, 1, 4, 1, 5} → ?
  4. Write Fibonacci with a loop and with tail recursion (fibT(n, a, b)).
  5. lucas(5): how many calls does it make? How many with memoization?
  6. How many moves do the Towers of Hanoi need for 4 disks? What is the first move?
Answers / hints
  1. if (exp == 0) return 1; return base * power(base, exp - 1); → 1024.
  2. if (n > 1) binary(n / 2); System.out.print(n % 2); → 1101 (printing on the way back: high digits first).
  3. if (i == a.length) return 0; return a[i] + arraySum(a, i + 1); → 14.
