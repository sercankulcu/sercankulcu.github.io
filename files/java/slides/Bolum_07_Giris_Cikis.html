Akışlar

Akış (Stream)

  • Akış (stream), veriyi bir kaynaktan bir hedefe sırayla, parça parça taşıyan yapıdır. Veri karakter, sayı veya ham byte olabilir.
  • Girdi akışı (input stream): verinin programa girdiği akış. Örnek: System.in (klavye).
  • Çıktı akışı (output stream): verinin programdan çıktığı akış. Örnek: System.out (ekran).
  • Benzetme: su borusu. Bir uçtan giren su öbür uçtan aynı sırayla çıkar; borunun öbür ucunda musluk mu depo mu olduğu sizi ilgilendirmez.

Kaynak ister klavye, ister dosya, ister ağ olsun, program aynı read() / write() metotlarını kullanır. Java G/Ç (giriş/çıkış, I/O) kütüphanesinin gücü bu ortak arayüzdedir.

import java.util.Scanner;

public class AkisOrnek {
  public static void main(String[] args) {
    // Giriş akışından veri okuma

    System.out.println("Girdiğiniz sayı: " + kullaniciGirdisi);
    System.err.println("Bu satır hata akışına yazıldı.");
  }
}

Dosyalar ve Kodlama

Dosyalar

  • Dosya, veriyi diskte kalıcı olarak saklar: program kapansa, bilgisayar yeniden başlasa da veri durur (RAM'deki değişkenler ise kaybolur).
  • Her dosyadaki veri sonuçta 0'lar ve 1'ler, yani byte dizisidir. Farkı, bu byte'ların nasıl yorumlandığı yaratır.
  • Metin dosyaları (text): byte'lar bir karakter kodlamasına göre harflere çevrilir; insanlar okuyabilir.
  • İkili dosyalar (binary): byte'lar sayı, piksel, ses örneği, makine komutu gibi verilerdir; ancak onları bilen bir program anlamlandırır.

dosya.txt bir onaltılık (hex) düzenleyicide:

0000  4D 65 72 68 61 62 61 2C  Merhaba,
0008  20 64 C3 BC 6E 79 61 21   d..nya!

Solda konum, ortada her byte'ın onaltılık değeri, sağda ASCII karşılığı. 4D = 77 = M. 15 harf 16 byte tutar: ü UTF-8'de iki byte'tır (C3 BC).

Dosyalar ve Kodlama

Metin Dosyaları

  • Metin dosyaları yazdırılabilir karakterler (harf, rakam, noktalama, boşluk, satır sonu) içerir.
  • Not Defteri, VS Code gibi metin düzenleyicileriyle açılıp düzenlenebilir. Örnek: kaynak kodlar (.java, .c), .txt, .csv, .html.
  • Karakter kümesi / kodlama (character set / encoding): her karakterin hangi sayıyla (byte'larla) saklanacağını belirleyen tablodur. Yazan ve okuyan aynı kodlamayı kullanmalıdır.
ASCII

7 bit, 128 karakter: İngilizce harfler, rakamlar, noktalama, kontrol karakterleri.

ISO-8859-1

8 bit, 256 karakter: Batı Avrupa (Latin-1). é, ü, ö, ç var; ş, ğ, ı yok.

ISO-8859-9

8 bit, Latin-5: Türkçe sürüm. Latin-1'deki 6 harfin yerine ğ, Ğ, ı, İ, ş, Ş gelir.

UTF-8

Unicode'un evrensel kodlaması: tüm dünya dilleri, 1–4 byte. Web'in ve Java 18+ sürümünün varsayılanı.

Dosyalar ve Kodlama

İkili Dosyalar

  • Byte'ları karakter olarak değil, programın belirlediği biçimde (format) saklar: sayılar, pikseller, ses örnekleri, makine kodu.
  • Bilgisayar (doğru program) için anlamlıdır; insanlar doğrudan okuyamaz.
  • Örnekler: çalıştırılabilir dosyalar (.exe, Java'nın .class dosyaları), görüntü (.png, .jpg), müzik (.mp3), video (.mp4), veri dosyaları (.dat).

Bir Dosyaya Sayı (127) Yazma

  • Bir sayının dosyada nasıl saklanacağı veri türüne, kullanım amacına ve dosya biçimine bağlıdır.
  • Metin olarak: sayı önce karakterlere çevrilir; her rakam bir ASCII byte'ı tutar. Dikkat: '1' karakterinin kodu 49'dur, 1 değil.
  • İkili olarak: sayının ikilik değeri (0111 1111) türün boyutu kadar byte'a doğrudan yazılır. Sayısal veri için daha verimlidir.

Kodla Doğrulama: 127

public class Sayi127 {
  static void metinYaz(String ad, Charset kod) throws IOException {
    Writer w = new OutputStreamWriter(new FileOutputStream(ad), kod);
    w.write(String.valueOf(127));            // "127": 3 karakter
    w.close();
  }
  static void ikiliYaz(String ad, int boyut) throws IOException {
    FileOutputStream fos = new FileOutputStream(ad);
    DataOutputStream d = new DataOutputStream(fos);
    if (boyut == 1) d.writeByte(127);        // 01111111
    else if (boyut == 2) d.writeShort(127);  // 00000000 01111111
    else d.writeInt(127);                    // 4 byte
    d.close();
  }
  public static void main(String[] args) throws IOException {
    metinYaz("metin.txt", StandardCharsets.US_ASCII);
    metinYaz("metin16.txt", StandardCharsets.UTF_16BE);
    ikiliYaz("b.dat", 1);  ikiliYaz("s.dat", 2);  ikiliYaz("i.dat", 4);
    String[] adlar = {"metin.txt", "metin16.txt",
             "b.dat", "s.dat", "i.dat"};
    for (String ad : adlar)
      System.out.println(ad + ": " + new File(ad).length());
  }
}

public class ScannerDosya {
  public static void main(String[] args) {
    Scanner scanner = null;
    try {
      scanner = new Scanner(new File("ornekDosya.txt"));
      // Dosyanın içeriğini okuma ve ekrana yazdırma
      while (scanner.hasNextLine()) {
        String satir = scanner.nextLine();
        System.out.println(satir);
      }
    } catch (FileNotFoundException e) {
      System.err.println("Dosya bulunamadı: " + e.getMessage());
    } finally {
      if (scanner != null)
        scanner.close();
    }
  }
}

Tamponlama

Tamponlama (Buffering)

  • Temel metotlar: read() bir byte veya byte dizisi okur, write() bir byte veya byte dizisi yazar.
  • Her byte için ayrı disk erişimi uygulamayı ciddi şekilde yavaşlatır: disk, bellekten binlerce kat yavaştır.
  • Çözüm: veriyi bellekte bir tamponda (buffer) biriktirip diskten okuma / diske yazma işlemlerini toplu yapmak. Fiziksel disk erişimi sayısı azalır.
Benzetme: marketten 10 ürünü tek tek, her biri için ayrı yolculukla taşımak yerine bir sepete doldurup tek seferde taşımak.

Tamponsuz yazma: her write() çağrısı doğrudan diske gider.

Tamponlu yazma: write() çağrıları byte'ları önce bellekteki tampona koyar.

Tampon dolunca, flush() veya close() çağrılınca tamponun tamamı tek seferde diske yazılır.

public class TamponOlcum {
  static long oku(InputStream in) throws IOException {
    long bas = System.nanoTime();
    while (in.read() != -1) { }          // her seferinde 1 byte
    in.close();
    return (System.nanoTime() - bas) / 1_000_000;
  }
  public static void main(String[] args) throws IOException {
    File f = new File("buyuk.dat");
    try (FileOutputStream fos = new FileOutputStream(f)) {
      fos.write(new byte[2 * 1024 * 1024]);   // 2 MB

    System.out.println("Tamponlu : " + t2 + " ms");
    f.delete();
  }
}

PipedInputStream ve PipedOutputStream

  • InputStream / OutputStream sınıflarından türetilmiştir; iki iş parçacığı (thread) arasında güvenli veri iletişimi sağlar.
  • Bir iş parçacığı PipedOutputStream ile veri yazar, diğeri PipedInputStream ile bu veriyi okur. İki uç new PipedOutputStream(pis) ile bağlanır.
  • Okuma ve yazma senkronizedir: boru boşsa okuyucu bekler, doluysa yazıcı bekler.
  • Yalnızca tek yönlü veri iletimini destekler; çift yön için iki boru gerekir.
  • İki ucu aynı iş parçacığında kullanmak kilitlenmeye (deadlock) yol açabilir. İş parçacıkları Bölüm 9'da ayrıntılı işlenecek.

Dosya Kopyalama

Bayt Bayt Dosya Kopyalama

  • Kaynak dosyadan okunan her byte'ı hedef dosyaya yazar: her tür dosyayı (metin, resim, .exe) bozmadan kopyalar.
  • BufferedInputStream ve BufferedOutputStream giriş ve çıkışı hızlandırır: önbellek kullanarak okuma ve yazmayı toplu yapar.
  • bis.read(): bir byte okur, dosyanın sonunda −1 döner. bos.write(veri): okunan byte'ı çıkış dosyasına yazar.
  • Okunan değer int bir değişkende tutulmalıdır: −1 ile 255 byte değerini ayırt etmek için.

Kopyalama döngüsü tek satırdır: while ((veri = bis.read()) != -1) bos.write(veri);

public class ParcaKopya {
  public static void main(String[] args) throws IOException {
    // Veri, 16K'lık parçalar hâlinde okunacak
    byte[] parca = new byte[1024 * 16];
    File dosya = new File("dosya.txt");
    File dosya2 = new File("dosya2.txt");
    FileInputStream fis = new FileInputStream(dosya);
    FileOutputStream fos = new FileOutputStream(dosya2);
    BufferedInputStream bis = new BufferedInputStream(fis);
    BufferedOutputStream bos = new BufferedOutputStream(fos);
    int boyut;
    // 16K'ya kadar oku. Dosyanın sonunda -1 dönecektir.
    while ((boyut = bis.read(parca)) > -1)
      bos.write(parca, 0, boyut);   // Okunan parçayı çıkışa yaz
    bos.close();
    bis.close();
    System.out.println(dosya2.length() + " byte kopyalandı");
  }
}

Dosya Erişimi: Sıralı ve Rasgele




Sıralı erişim (sequential)
  • Her okuma/yazma bir sonraki konumdan devam eder; geri dönülemez.
  • Dosya içeriğinin yapısı bilinmediğinde veya kopya oluşturulurken kullanılır.

Serileştirme (Serialization)


  • Serileştirme: bir nesnenin durumunu (alan değerlerini) byte dizisine çevirmek; bu sayede nesne dosyaya yazılabilir, ağ üzerinden başka bir ortama taşınabilir. Tersi serileştirmeyi geri alma (deserialization).
  • Bir sınıfın nesneleri serileştirilebilmesi için sınıf java.io.Serializable arayüzünü gerçeklemelidir (metodu olmayan bir işaret arayüzü).
  • Sınıfın sürüm kimliği serialVersionUID ile belirtilmesi önerilir; yazılmazsa derleyici sınıf yapısından üretir ve sınıf değişince eski dosyalar okunamaz.
  • static alanlar (sınıfa aittir) ve transient (geçici) olarak işaretlenen alanlar serileştirilmez; şifre gibi alanları dışarıda bırakmak için kullanılır.
Kullanım alanları: oyun kayıtları, önbellekler, nesnelerin ağ üzerinden başka bir JVM'e gönderilmesi. Uzun süreli ve diller arası veri saklamak için JSON gibi metin biçimleri daha çok tercih edilir.

NIO: Avantajlar ve Dezavantajlar




Avantajlar
  • Performans: bloklar hâlinde, klasik G/Ç'den verimli aktarım
  • Esneklik: tampon ve kanallarla esnek veri işleme; çift yönlü kanallar
  • Dosya ve ağ için aynı yöntem
  • Çoklu bağlantı: seçiciyle birden çok kanal tek iş parçacığında; yalnızca etkin kanallar işlenir


Dezavantajlar
  • Karmaşıklık: klasik G/Ç'ye göre daha zor
  • Tampon durumunu ve hata durumlarını (yarım okuma, kopan bağlantı) yönetmek gerekir
  • Seçici için öğrenme eğrisi: çok kanalın durumunu doğru izlemek gerekir


Kural: tek bir dosyayı satır satır okuyacaksanız BufferedReader veya Files yeterlidir. Kanallar, çok büyük dosyalar ve çok sayıda ağ bağlantısı için öne çıkar.

Seçici ile Sunucu




public class SeciciGoster {
  public static void main(String[] args) throws IOException {
    ServerSocketChannel kanal = ServerSocketChannel.open();
    Selector secici = Selector.open();
    kanal.bind(new InetSocketAddress(8080));
    kanal.configureBlocking(false);
    kanal.register(secici, SelectionKey.OP_ACCEPT);
    while (true) {
      int hazirKanallar = secici.select();
      if (hazirKanallar > 0) {
        Set<SelectionKey> secilenler = secici.selectedKeys();
        for (SelectionKey secilen : secilenler) {
          if (secilen.isAcceptable()) {
            // Bağlantı kabul
          } else if (secilen.isReadable()) {
            // Veri okuma
          }
        }
        secilenler.clear(); // İşlenen anahtarları temizle
      }
    }
  }
}


  • Sunucu kanalı 8080 portuna bağlanır, bloklamayan moda alınır, OP_ACCEPT için kaydedilir.
  • select() hazır kanal sayısını, selectedKeys() hazır anahtarları verir.
  • İşlenen anahtarlar clear() ile temizlenmezse sonraki turda yine gelir.
  • Gerçek sunucuda kabul edilen istemci OP_READ ile kaydedilir ve veri okunur.
