Giriş

Öğrenme Çıktıları

Soyut sınıf

abstract sınıf ve metot tanımlamak; soyut sınıftan neden nesne oluşturulamadığını ve alt sınıfın neyi gerçekleştirmek zorunda olduğunu açıklamak.

Dinamik bağlama

Soyut tipten bir referansla çağrılan metodun, çalışma zamanında nesnenin gerçek sınıfından seçildiğini kodu izleyerek göstermek.

Arayüz

interface tanımlamak, implements ile bir ya da birden çok arayüzü gerçekleştirmek; default, static ve private metotları kullanmak.

Tasarım kararı

Mühürlü (sealed) tipleri tanımak; bir problem için arayüz mü soyut sınıf mı (ya da ikisi birden) gerektiğine karar vermek; jenerik tipleri ve etiketleri (annotation) kullanmak.

Soyutlama

Soyutlama (Abstraction)

  • Soyutlama: karmaşık ayrıntıları gizleyip yalnızca temel özellikleri göstermek.
  • Araba kullanan kişi direksiyonu ve pedalları bilir; motorun içini bilmek zorunda değildir.
  • “Şekil” bir kavramdır: her şeklin alanı vardır, ama genel bir şeklin alanı hesaplanamaz. Formülü yalnızca Kare, Çember, Üçgen bilir.
  • Java'da soyutlamanın iki aracı vardır: soyut sınıflar (abstract class) ve arayüzler (interface).
  • İkisi de ne yapılacağını söyler; nasıl yapılacağını alt sınıflara bırakır.

Ortak kavram yukarıda, ayrıntı aşağıda.

Soyut Sınıflar

Soyut Sınıf (Abstract Class)

  • abstract anahtar kelimesiyle tanımlanır: public abstract class Sekil.
  • Hem soyut (gövdesiz) hem de somut (concrete, gövdeli) metotlar içerebilir.
public abstract class Sekil {
    // Soyut olmayan (somut) metot
    void tasi(int x, int y) {
        System.out.println("(" + x + ", " + y + ") noktasına taşındı");
    }
    // Soyut metot (alt sınıflarca gerçeklenmeli)
    abstract void ciz();
}
Somut metot: tasi

Gövdesi hazırdır. Alt sınıflar onu olduğu gibi kalıtımla alır; isterse geçersiz kılar (override).

Soyut metot: ciz

Yalnızca imzası vardır. Her somut alt sınıf kendi ciz() gövdesini yazmak zorundadır.

Soyut sınıf yarım kalmış bir plan gibidir: bazı odalar bitmiş, bazılarının yalnızca yeri belli.

Soyut Sınıflar

Soyut Sınıfın Özellikleri

  • Soyut sınıftan nesne oluşturulamaz (örneği, instance'ı olamaz).
  • Başka sınıflar onu extends ile genişletir (kalıtım).
  • Somut bir alt sınıf, tüm soyut metotları gerçekleştirmek (implement) zorundadır.
  • Ortak durumu (alanlar) ve davranışları tek yerde toplar → kod yeniden kullanılır.
  • Alt sınıflar soyut metotları kendi ihtiyacına göre doldurur.
  • Yapıcı metotları (constructor) olabilir; alt sınıf onları super(...) ile çağırır.

UML'de soyut sınıf ve soyut metot eğik yazılır.

Soyut Sınıflar

Soyut Sınıftan Nesne Oluşturulamaz

Sekil s1 = new Sekil("?");     // HATA
Sekil s2 = new Kare(3);        // Doğru: değişkenin türü soyut olabilir
Sekil[] dizi = new Sekil[3];   // Doğru: dizi yalnızca referans tutar

Derleyici mesajı (1. satır)

error: Sekil is abstract; cannot be instantiated
Neden yasak?

Sekil'in alan() metodunun gövdesi yok. new Sekil() olsaydı s1.alan() çağrısında çalıştırılacak kod bulunmazdı.

Referans tipi olarak serbest

Değişken, parametre, dizi öğesi ve dönüş tipi Sekil olabilir. new Sekil[3] nesne değil, 3 boş (null) referans oluşturur.

abstract final class yazılamaz: final genişletmeyi yasaklar, abstract genişletmeyi gerektirir → illegal combination of modifiers: abstract and final.

Soyut Sınıflar

Soyut Metotlar (Abstract Methods)

  • Gerçekleştirme (implementation) olmadan tanımlanır.
  • Süslü parantez içermez, noktalı virgülle biter:
public abstract void ciz();
  • Soyut metodu olan sınıf soyut olmak zorundadır.
  • Soyut sınıflar genellikle kalıtım hiyerarşisinin tepesinde yer alır.
public abstract class Sekil {
    // Soyut metot
    public abstract void ciz();
}

// Ayrı bir dosyada:
public class Cember extends Sekil {
    // ciz metodunu gerçeklemek zorunlu
    public void ciz() {
        System.out.println("Çember çiziliyor");
    }
}

new Cember().ciz(); çıktısı

Çember çiziliyor

Soyut Sınıflar · Kodu adım adım çalıştır

new Kare(3): Yapıcı Zinciri

new Kare(3): önce heap'te bir Kare nesnesi ayrılır. Alanlar varsayılan değer alır: null ve 0.0.

Kare'nin yapıcısı çalışır. Parametre kenar = 3.0 (int 3, double'a genişletildi).

İlk iş super("Kare"): üst sınıfın yapıcısı çağrılır. Soyut sınıfın da yapıcısı olabilir.

Sekil yapıcısı çalışıyor. Ayrı bir Sekil nesnesi oluşmaz: aynı nesnenin Sekil'den gelen kısmı kuruluyor.

this.isim = isim: nesnenin isim alanı "Kare" olur.

Mesaj yazdırılır. Sekil yapıcısı biter, çerçevesi yığından çıkar.

Kare yapıcısına dönülür: this.kenar = 3.0. Nesne artık tamamen kurulmuştur.

Nesnenin referansı s'ye atanır. Değişkenin tipi Sekil (soyut), gösterdiği nesne Kare.

s.alan(): Sekil'de alan() soyut. Çalışma zamanında nesnenin tipine bakılır → Kare.alan(): 3.0 · 3.0.

Dönen 9.0 yazdırılır.

abstract class Sekil {
    private String isim;
    Sekil(String isim) {
        this.isim = isim;
        System.out.println(isim + " kuruldu");
    }
    abstract double alan();
}
class Kare extends Sekil {
    private double kenar;
    Kare(double kenar) {
        super("Kare");
        this.kenar = kenar;
    }
    double alan() { return kenar * kenar; }
}
// main içinde:
Sekil s = new Kare(3);
System.out.println(s.alan());

Soyut Sınıflar · Kodu adım adım çalıştır

Soyut Tipte Dizi: Dinamik Bağlama

Dizi iki referans tutar. Öğelerin tipi Sekil, gösterdikleri nesneler Kare ve Cember.

1. tur: t, dizi[0]'daki Kare nesnesini gösterir.

t.alan(): derleyici yalnızca Sekil'de alan() olduğunu bilir; JVM nesneye bakar → Kare.alan(): 2.0 · 2.0.

Dönen 4.0 yazdırılır.

Kare ciz()'i geçersiz kılmadı (override etmedi) → Sekil'deki somut ciz() kalıtımla alınan metot olarak çalışır.

2. tur: t artık Cember nesnesini gösterir. Aynı satır, farklı nesne.

Bu kez Cember.alan() seçilir: π · 1.0 · 1.0.

Dönen değer yazdırılır: Math.PI.

Cember ciz()'i geçersiz kılmış → kendi sürümü: dinamik bağlama (dynamic binding).

Öğe kalmadı, döngü biter. Yeni bir şekil (ör. Ucgen) eklemek için bu döngüyü değiştirmek gerekmez.

abstract class Sekil {
    // isim alanı ve yapıcısı
    abstract double alan();
    void ciz() {
        System.out.println(isim + " çiziliyor");
    }
}
class Kare extends Sekil {
    // kenar alanı ve yapıcısı
    double alan() { return kenar * kenar; }
}
class Cember extends Sekil {
    // r alanı ve yapıcısı
    double alan() { return Math.PI * r * r; }
    void ciz() {
        System.out.println("Çember, r = " + r);
    }
}
// main içinde:
Sekil[] dizi = { new Kare(2), new Cember(1) };
for (Sekil t : dizi) {
    System.out.println(t.alan());
    t.ciz();
}

Somut Metot Soyut Metodu Çağırır

Değişken tipi Icecek (soyut), nesne Cay. Cay tek soyut metodu demle()'yi gerçekleştirdiği için somuttur.

Cay'da hazirla() yok → Icecek'ten kalıtımla alınan somut metot çalışır. final: alt sınıflar bu sırayı değiştiremez.

1. adım: suyuKaynat(), yani this.suyuKaynat() çağrılır.

Icecek'teki somut suyuKaynat() çalışır.

2. adım: demle(). Icecek'te gövdesi yok, ama this bir Cay nesnesi…

…bu yüzden Cay.demle() çalışır. Soyut sınıftaki kod, henüz yazılmamış alt sınıf kodunu çağırabilir.

3. adım: servis mesajı yazdırılır.

İskelet soyut sınıfta, değişen adım alt sınıfta: şablon metot (template method). Bir Kahve sınıfı yalnızca demle()'yi yazar.

abstract class Icecek {
    final void hazirla() {
        suyuKaynat();
        demle();
        System.out.println("Servis edildi");
    }
    void suyuKaynat() {
        System.out.println("Su kaynadı");
    }
    abstract void demle();
}
class Cay extends Icecek {
    void demle() {
        System.out.println("Çay demlendi");
    }
}
// main içinde:
Icecek i = new Cay();
i.hazirla();

Arayüzler

Arayüz (Interface) Nedir?

  • Bir sistemin belirli işlevlere sahip olacağını garanti eden sözleşmedir (contract).
  • İki sistem arasındaki entegrasyon noktasını temsil eder: kullanan taraf yalnızca arayüzü bilir.
  • interface anahtar kelimesiyle tanımlanır.
  • Arayüzdeki metotlar, public yazılsın ya da yazılmasın public'tir.
  • static, default ya da private değilse metot otomatik olarak abstract'tır.
  • Alan olarak yalnızca public static final sabitler içerebilir.
Benzetme: priz ve fiş

Priz bir sözleşmedir: hangi cihaz takılırsa takılsın aynı gerilimi verir. Ütü de bilgisayar da prizin standardına uyar; şebeke cihazın içini, cihaz şebekenin içini bilmez.

Soyut sınıf “bir türüdür” (is-a) ilişkisi kurar; arayüz “yapabilir” (can-do) yeteneği tanımlar.

Arayüzler

Arayüz Tanımlama

Yazdığımız

public interface GeometrikSekil {
    // Soyut metot (public abstract)
    void ciz();
    // Sabit (public static final)
    int KENAR_SAYISI = 4;
}

Derleyicinin gördüğü

public interface GeometrikSekil {
    public abstract void ciz();
    public static final int KENAR_SAYISI = 4;
}
  • Sabitlere arayüz adıyla erişilir: GeometrikSekil.KENAR_SAYISI → 4. Adları BÜYÜK_HARF ile yazılır.
  • Sabite değer vermek zorunludur: int deger; → error: = expected.
  • Sabit değiştirilemez: GeometrikSekil.KENAR_SAYISI = 5; → error: cannot assign a value to static final variable KENAR_SAYISI.
  • Arayüzden de nesne oluşturulamaz: new GeometrikSekil() → error: GeometrikSekil is abstract; cannot be instantiated.

Arayüzler

Arayüz Gerçekleştirme (implements)

  • Bir sınıf, bir arayüzü implements anahtar kelimesiyle gerçekleştirir.
  • Arayüzdeki tüm soyut metotları gerçekleştirmeli ya da kendisi abstract olmalıdır.
  • Eksik metot: Kare is not abstract and does not override abstract method ciz() in GeometrikSekil.
  • Gerçekleştiren metot public olmalıdır. void ciz() yazılırsa: attempting to assign weaker access privileges; was public.
  • Arayüz tipinde değişken, onu gerçekleştiren her sınıfın nesnesini gösterebilir.
public class Kare implements GeometrikSekil {
    // ciz metodunu gerçeklemek zorunlu
    public void ciz() {
        System.out.println("Kare çiziliyor");
    }
}
// main içinde:
GeometrikSekil g = new Kare();
g.ciz();
System.out.println(GeometrikSekil.KENAR_SAYISI);

Arayüzler

Bir Sınıf, Birden Fazla Arayüz

  • Bir sınıf en fazla bir üst sınıfı genişletebilir (extends)…
  • …ama sıfır ya da daha çok arayüzü gerçekleştirebilir (implements A, B, …).
  • Önce extends, sonra implements yazılır.
  • class C extends A, B → error: '{' expected.
class Hayvan {
    String isim;
    Hayvan(String isim) { this.isim = isim; }
}
interface Ucabilir { void uc(); }
interface Yuzebilir { void yuz(); }
class Ordek extends Hayvan implements Ucabilir, Yuzebilir {
    Ordek(String isim) { super(isim); }
    public void uc() { System.out.println(isim + " uçuyor"); }
    public void yuz() { System.out.println(isim + " yüzüyor"); }
}

Arayüzler · Kodu adım adım çalıştır

Aynı Nesne, Farklı Arayüz Referansları

Heap'te tek bir Ordek nesnesi oluşur; o onu gösterir.

Atama nesneyi kopyalamaz: u aynı nesneyi gösterir. Ordek bir Ucabilir'dir → dönüşüm otomatik.

y da aynı nesneyi gösterir. Bir nesne, üç farklı tipten “bakış”.

u.uc(): u'nun tipi Ucabilir; ondan yalnızca uc() çağrılabilir. Çalışan, nesnenin kendi uc()'su.

y.yuz(): Yuzebilir tipi yuz()'ü bilir.

u.yuz() yazılsaydı: error: cannot find symbol. Nesnede yuz() var, ama derleyici referansın tipine bakar.

o'nun tipi Ordek: alan isim dahil her şey erişilebilir.

== referansları karşılaştırır: hepsi aynı nesneyi gösterir → true.

Ordek o = new Ordek("Donald");
Ucabilir u = o;
Yuzebilir y = o;
u.uc();
y.yuz();
// u.yuz();   derleme hatası!
System.out.println(o.isim);
System.out.println(u == o);

Arayüzler

Arayüzden Kalıtım

Bir arayüz, başka bir arayüzü extends ile genişletebilir; virgülle birden çok arayüzü de genişletebilir: interface C extends A, B.

public interface KareSekli extends GeometrikSekil {
    // Ek metotlar veya sabitler eklenebilir
    void ozelFonksiyon();
}
class OzelKare implements KareSekli {
    public void ciz() {
        System.out.println("Özel kare çiziliyor");
    }
    public void ozelFonksiyon() {
        System.out.println("Köşegen: " + Math.sqrt(2));
    }
}
// main içinde:
KareSekli k = new OzelKare();
k.ciz();
k.ozelFonksiyon();
GeometrikSekil g = k;   // üst arayüze atanabilir

Arayüzler

Arayüz Tipiyle Programlama

  • Kullanan kod somut sınıfa değil, arayüze bağlanır: değişken, parametre ve dönüş tipi arayüz olur.
  • satinAl(OdemeYontemi y, double toplam) kartla mı havaleyle mi ödendiğini bilmez; y.ode(toplam) der, gerisini nesne yapar.
  • Yeni bir ödeme türü (Kripto) yalnızca arayüzü gerçekleştirir; satinAl hiç değişmez (gevşek bağlılık).
  • Test kolaylaşır: gerçek banka yerine arayüzü gerçekleştiren sahte bir sınıf verilir.
  • Java kütüphanesi de böyledir: List<String> l = new ArrayList<>();

Arayüzler · Kodu adım adım çalıştır

Ödeme Arayüzü: Kod İzleme

Parametre y'nin tipi arayüzdür; gelen nesne bir KrediKarti.

y.ode(toplam) dinamik bağlanır: nesne kart olduğu için KrediKarti.ode() çalışır.

Çağrı biter; kart nesnesini artık gösteren referans yoktur, çöp toplayıcı onu silebilir.

Aynı satinAl, bu kez bir Havale nesnesiyle.

Aynı satır bu kez Havale.ode()'yi çalıştırır; 5 TL masraf ekler: 125.0.

satinAl iki farklı sınıfla çalıştı ama hiçbirinin adını bilmiyor; yeni bir sınıf eklense de değişmez.

interface OdemeYontemi { void ode(double tutar); }
class KrediKarti implements OdemeYontemi {
    public void ode(double tutar) {
        System.out.println("Kart: " + tutar + " TL");
    }
}
class Havale implements OdemeYontemi {
    public void ode(double tutar) {
        System.out.println("Havale: " + (tutar + 5) + " TL");
    }
}
static void satinAl(OdemeYontemi y, double toplam) {
    y.ode(toplam);
}
satinAl(new KrediKarti(), 250.0);   // main
satinAl(new Havale(), 120.0);

Arayüz Metotları

Varsayılan Metotlar (default, Java 8+)

  • Arayüz, gövdesi olan varsayılan (default) metotlara sahip olabilir.
  • Gerçekleştiren sınıf onu kalıtımla alır; isterse geçersiz kılar. Amaç: arayüze yeni metot eklerken onu gerçekleştiren eski sınıfları bozmamak.
interface Collection {
    void add(Object o);
    void remove(Object o);
    int size();
    default boolean isEmpty() {
        return size() == 0;
    }
}

Arayüz Metotları · Kodu adım adım çalıştır

Varsayılan Metot: Kod İzleme

Sepet yalnızca iki soyut metodu yazdı; isEmpty()'i yazmadı.

Arama Sepet'te isEmpty() bulamaz; arayüzdeki default gövde çalışır.

Default metot soyut size()'ı çağırır; hangi gövdenin çalışacağını nesne belirler: Sepet.size() → 0.

0 == 0: true.

add Sepet'in sürümüdür: adet 1 olur.

Aynı default gövde bu kez 1 görür: false. Arayüz yazıldıktan sonra eklenen bir default metot, eski sınıfları bozmadan onlara da gelir.

interface Collection {
    void add(Object o);
    int size();
    default boolean isEmpty() {
        return size() == 0;
    }
}
class Sepet implements Collection {
    private int adet = 0;
    public void add(Object o) { adet++; }
    public int size() { return adet; }
}
Collection c = new Sepet();      // main
System.out.println(c.isEmpty());
c.add("elma");
System.out.println(c.isEmpty());

Arayüz Metotları

static Metotlar (Java 8+)

interface Geometry {
    static double circleArea(double r) { return Math.PI * r * r; }
    static double squareArea(double s) { return s * s; }
    static double perimeter(double s) { return s * 4.0; }
    static double boxVolume(double w, double h, double d) {
        return w * h * d;
    }
}
// main içinde:
System.out.println(Geometry.circleArea(2));
System.out.println(Geometry.squareArea(3));
System.out.println(Geometry.perimeter(2.5));
System.out.println(Geometry.boxVolume(2, 3, 4));

Mühürlü Tipler

Mühürleme: sealed, non-sealed, permits

  • Sınıflar ve arayüzler mühürlenebilir (Java 17+).
  • sealed: tipi yalnızca izin verilen alt tipler genişletebilir ya da gerçekleştirebilir.
  • permits: izin verilen alt tiplerin listesi.
  • İzin verilen her alt tip birini seçmek zorundadır:
    final: hiyerarşi burada biter;
    sealed: yeniden kısıtlar;
    non-sealed: kısıtı kaldırır, herkes genişletebilir.
  • Yarar: derleyici tüm alt tipleri bilir (kapalı hiyerarşi).

Hangisini Seçmeli?

Soyut sınıf seçin

  • Alt sınıflar yakın akraba: Kare, Çember birer Sekil'dir.
  • Ortak alanlar ve yapıcı gerekiyor (isim).
  • Ortak kodun bir kısmı hazır (şablon metot).

  • İlgisiz sınıflara aynı yetenek: Kus, Ucak, Drone hepsi Ucabilir.

  • Kullanan kodla gerçekleştiren kod arasında sözleşme (API).

abstract class Hayvan implements Sesli { … }

Jenerikler · Kodu adım adım çalıştır

enBuyuk: Kod İzleme

İki dizi de uygun: Integer ve String, Comparable'ı kendi tipleriyle gerçekleştirir. Sayılar otomatik kutulanır.

Derleyici T'yi Integer olarak çıkarır. İlk öğe en büyük aday: eb = 7.

compareTo pozitifse öğe daha büyüktür: eb = 12.

Negatif sonuç: 5 daha küçük, eb değişmez.

Döngü biter, 12 döner. Dönüş tipi T = Integer: dönüşüm gerekmez.

Aynı metot, bu kez T = String. compareTo artık sözlük sırasıyla karşılaştırır.

İlk farklı harfler 'k' − 'e' = 6: pozitif, eb = "kiraz".

'a' − 'k' = −10: negatif, eb değişmez.

kiraz döner. Tek gerçekleştirme iki tipte çalıştı; sınır sayesinde compareTo çağrısı derleme zamanında güvence altında.

static <T extends Comparable<T>> T enBuyuk(T[] dizi) {
    T eb = dizi[0];
    for (int i = 1; i < dizi.length; i++) {
        if (dizi[i].compareTo(eb) > 0) {
            eb = dizi[i];
        }
    }
    return eb;
}
// main içinde:
Integer[] sayilar = {7, 12, 5};
String[] adlar = {"elma", "kiraz", "armut"};
System.out.println(enBuyuk(sayilar));
System.out.println(enBuyuk(adlar));

Özet

Sık Yapılan Hatalar (1): Soyut Sınıflar

Soyut sınıftan nesne

new Sekil("?") → Sekil is abstract; cannot be instantiated. Somut bir alt sınıf kullanın.

Soyut metodu unutmak

Cember is not abstract and does not override abstract method ciz() in Sekil. Metodu yazın ya da sınıfı abstract yapın.

Soyut metoda gövde

abstract void ciz() { } → abstract methods cannot have a body. Ya abstract ya da gövde.

Sınıfı abstract yapmamak

class Sekil { abstract void ciz(); } → Sekil is not abstract and does not override abstract method ciz() in Sekil.

Çelişen belirteçler

abstract final, private abstract, static abstract → illegal combination of modifiers.

İmzayı yanlış yazmak

double Alan() ya da double alan(int x) yeni bir metottur, soyut alan() hâlâ eksiktir. @Override bunu yakalar.

Özet

Sık Yapılan Hatalar (2): Arayüzler

public'i unutmak

void ciz() { … } → attempting to assign weaker access privileges; was public. Arayüz metodunu public yazın.

Sabiti değiştirmek

GeometrikSekil.KENAR_SAYISI = 5; → cannot assign a value to static final variable KENAR_SAYISI.

İki sınıftan türetmek

class C extends A, B → '{' expected. Tek extends, çok sayıda implements.

Referans tipinde olmayan metot

Ucabilir u = new Ordek(); u.yuz(); → cannot find symbol. Uygun tipte referans kullanın.

class Gorevli inherits unrelated defaults for selam(). Metodu sınıfta geçersiz kılın.

Mühürleme hataları

İzinsiz alt tip: class is not allowed to extend sealed class: Hayvan. İzinli alt tipte belirteç yok: sealed, non-sealed or final modifiers expected.

Alıştırmalar (2)

  1. sealed abstract class Sekil permits Kare, Cember yazın; Kare final, Cember non-sealed. Elips extends Cember ve Ucgen extends Sekil derlenir mi?
  2. Soyut sınıf mı, arayüz mü? (a) plakası ve yapıcısı olan Tasit; (b) Ogrenci ve Fatura'nın ortak kaydet() yeteneği; (c) hem Hayvan hem yüzebilen Balik.
  3. class Kare implements GeometrikSekil içinde public void Ciz() { … } yazıldı. Ne olur? Metodun üstüne @Override eklenirse?
Cevaplar / ipuçları
  1. Elips derlenir (Cember non-sealed); Ucgen: class is not allowed to extend sealed class: Sekil.
  2. (a) soyut sınıf (ortak alan + yapıcı); (b) arayüz (ilgisiz sınıflar); (c) class Balik extends Hayvan implements Yuzebilir.
  3. Ciz ≠ ciz (büyük/küçük harf): Kare is not abstract and does not override abstract method ciz() in GeometrikSekil. @Override ile ek olarak method does not override or implement a method from a supertype.
