Object-Oriented Programming

Object-Oriented Programming

  • Object-oriented programming (OOP) builds a program out of interacting objects.
  • An object represents a clearly identifiable entity in the real world: a student, a table, a circle, a button on screen, even a loan.
  • Every object has state (its data) and behavior (what it can do).
Analogy: a school works through student, teacher and course objects sending messages to one another (calling methods).

Object-Oriented Programming

Objects: Fields and Behavior

  • A class has members: fields, methods and constructors.
  • Objects store data: these pieces of data are called fields.
  • Objects perform operations: these operations are called behavior (methods).
  • Bundling data with the code that works on it makes a program more organized, reusable and intuitive.

The static-method programs we have written so far were procedural. In Java all code lives in a class; in OOP, classes are used to create objects.

Object-Oriented Programming

Three Core Properties

Encapsulation

An object can hide its internal details from other objects. It acts like a closed box, used only through permitted methods.

Inheritance

A class can inherit the fields and methods of another class. This enables code reuse and class hierarchies.

Polymorphism

An object can take many forms (types); the same call behaves differently on different objects, giving flexibility and dynamic behavior.

A fourth is often added: abstraction, hiding needless detail and showing only the essential features.

Classes and Objects

Class: The Blueprint of an Object

  • A class is the blueprint of an object; one class can produce many objects carrying different data.
  • A class specifies the data (fields) an object holds and the operations (methods) it can perform.
  • An object is an instance of a class: its concrete form in memory.
  • Classes let us model real-world entities: a Car class can represent any automobile; each make and model is an object of that class.

Analogy: the class is a cookie cutter; objects are the cookies cut with it.

Defining a Class

public class Car {
  // Fields
  String brand;
  String model;
  int year;
  String color;

  // Methods
  void drive() {
    System.out.println(brand + " is moving.");
  }

  void stop() {
    System.out.println(brand + " stopped.");
  }

  void signal() {
    System.out.println(brand + " is signaling.");
  }
}
  • The class keyword and the class name come first; the body goes between { }.
  • Class names start with a capital letter (Car, BankAccount); a public class must be in a file of the same name (Car.java).
  • Fields are declared in the class body, outside the methods; every method can use them directly.
  • The methods have no static: each belongs to a particular car (object).
  • This class has no main; it does not run on its own; another class uses it.

Classes and Objects

Members of a Class

Fields

Represent the data objects can hold. Example: a Student class with name and surname.

Methods

Define the operations objects can perform. Example: a Dog class with bark() and run().

Access level

Each member can be private, protected, default (nothing written) or public: this decides who may use it.

Ownership

Each member can belong to the object (instance, the default) or, with static, belong to the class.

Constructors are also written inside the class, but they run only when an object is created and are technically a separate kind of member, not methods. A class can also contain other classes (inner classes).

Classes and Objects

Access Modifiers and Data Hiding

  • Access modifiers (public, protected, private; package access if none is written) specify who can reach a member from outside the class.
  • Rule of thumb: fields private, methods offered to others public.
  • A field's value is read by an accessor (getter, get...) and changed by a mutator (setter, set...); the setter rejects invalid values.
  • This arrangement is data hiding: only the class's own methods access its fields directly. It is the basis of encapsulation.
public class BankAccount {
  private double balance;   // hidden field
  public double getBalance() {
    return balance;
  }
  public void setBalance(double b) {
    if (b >= 0) balance = b;  // reject invalid
  }
}
// in another class:
acct.balance = -500;
error: balance has private access in BankAccount

Constructors

Constructors

  • A constructor is a special method; new calls it automatically when creating an object.
  • Its job is to give the fields their initial values and do any other setup.
  • Its name matches the class name (including case).
  • It has no return type, not even void; it cannot return a value.
  • Usually declared public; it can also be private to restrict object creation (e.g. the singleton pattern).
  • A class can have more than one constructor (with different parameters).
public class Student {
  private String name;
  private int id;

  // Constructor: class name, no return type
  public Student(String name, int id) {
    this.name = name;
    this.id = id;
  }
}

// Usage:
Student s = new Student("Ali", 2012);

Constructors

References

  • An object cannot be used directly; it is reached only through a reference. Variables store the object's reference, not the object itself.
  • A reference can be thought of as an address telling where the object is in memory.
  • int, double, boolean and other primitive variables hold the value itself; class-type variables (Car, String, Scanner) hold a reference.
  • A reference that points to no object has the value null.
Analogy: the variable is a TV remote; the object is the TV. Copying the remote does not create a second TV.

Local variables live on the stack, objects on the heap; arrow = reference.

Constructors · Step-by-step code trace

new Car(...): Step by Step

new allocates a new object on the heap; String fields first get the default value null.

The constructor is called: parameters receive copies of the arguments; this refers to the new object.

this.model = model: the left side is the object's field, the right side the parameter.

this.color = color: the object is now ready.

The constructor returns and its frame is removed. The new expression yields a reference, which is stored in sportsCar.

Same steps again: a separate object is created, with its own model and color copies.

sportsCar.printInfo(): inside the method, this = #1, so #1's fields are printed.

Same method, but now this = #2. The code is shared; the data is separate per object.

Constructors

No-Arg and Parameterized Constructors

public class Vehicle {
  private String brand;
  private String model;
  private int year;
  public Vehicle() {                 // no-arg constructor
    brand = "Unknown";
    model = "Unknown";
    year = 0;
  }
  public Vehicle(String brand, String model, int year) {
    this.brand = brand;
    this.model = model;
    this.year = year;
  }
  public void printInfo() {
    System.out.println(brand + " " + model + " " + year);
  }
  public static void main(String[] args) {
    Vehicle v1 = new Vehicle();
    Vehicle v2 = new Vehicle("Renault", "Clio", 2021);
    v1.printInfo();
    v2.printInfo();
  }
}
Output
Unknown Unknown 0
Renault Clio 2021
  • Vehicle() is our own no-arg constructor; it sets the fields to meaningful initial values.
  • The two constructors share a name but differ in parameters: constructor overloading. The arguments decide which one runs.
  • Once a class has any constructor, the compiler no longer adds the default one. If only a parameterized constructor exists, new Vehicle() does not compile: constructor Vehicle in class Vehicle cannot be applied to given types.

Fields

Initializer Blocks

Static initializer

The static { ... } block runs when the class is first loaded, and only once. It initializes complex static fields.

Instance initializer

The { ... } block runs every time an object is created, just before the constructor body. It holds work common to all constructors.

Order when creating an object: (1) on first use of the class, static fields and static blocks → (2) new allocates memory, fields get default values → (3) field initializers and instance initializer blocks (in source order) → (4) the constructor body.

Dog has both. Note: the value bark() returns is not printed; with System.out.println(d2.bark()); the last line would be "Gece woof woof!".

Dog: Initializer Order

main runs only after the class is loaded: the static block runs once. (var, Java 10+: infers the type from the right side; String... = String[].)

new Dog("Kara"): space is allocated for the object, name = null.

The instance initializer runs before the constructor body.

Now the constructor body: this.name = name.

The constructor prints the name: Kara.

Second object: initializer + constructor again; the static block does not run again.

Methods

Kinds of Methods

  • Methods are blocks of code in a class that do a specific job; they define the class's behavior.
  • Instance methods are tied to an object: phone.call(...). They use that object's fields.
  • Class methods (static) belong to the class itself and are shared by all objects: called through Phone.
  • Static methods belong to no particular object, so instance data (such as model) cannot be accessed directly.
public class Phone {
  private String model;
  private static String osVersion = "Version 1";

  // Instance method
  public void call(String number) {
    System.out.println(model + " calling: " + number);
  }

  // Instance method
  public void sendMessage(String to, String msg) {
    System.out.println(to + " <- " + msg);
  }

  // Class method (static)
  public static void updateOS(String newVersion) {
    osVersion = newVersion;
  }
}

The Rectangle Class

public class Rectangle {
  private double length;     // rectangle's length
  private double width;    // rectangle's width

  // Constructor
  public Rectangle(double length, double width) {
    this.length = length;
    this.width = width;
  }

  public double area() {      // computes the area
    return length * width;
  }

  public double perimeter() {     // computes the perimeter
    return 2 * (length + width);
  }
}
  • Fields are private: used from outside only through methods.
  • The constructor takes the two sides and stores them in the object.
  • area() and perimeter() take no parameters: the data they need is inside the object.
  • The procedural version would be area(5.0, 3.0); with an object it is rect.area().

Rectangle: Step by Step

Two objects, each with its own length and width values.

rect.area(): this = #1, result 5.0 × 3.0 = 15.0.

area = 15.0. perimeter(): 2 × (5.0 + 3.0) = 16.0.

double values print as 15.0.

Same methods, but now this = #2 (square): 25.0 and 20.0. The old values are overwritten.

The second line is printed. A long statement can span two lines; it lasts until the ;.

public class RectangleTest {

    Rectangle rect = new Rectangle(5.0, 3.0);
    Rectangle square = new Rectangle(5.0, 5.0);
    double area = rect.area();
    double perimeter = rect.perimeter();
    System.out.println("Area: " + area
        + " Perimeter: " + perimeter);
    area = square.area();
    perimeter = square.perimeter();
    System.out.println("Area: " + area
        + " Perimeter: " + perimeter);
  }
}

Reference Assignment

  • In Java, objects are handled through references (addresses).
  • car2 = car1; does not copy the object, only the reference: both variables point to the same object (an alias).
  • A change made through one is visible through the other.
Library labelThe label on the shelf is not the book itself; it shows where it is.
Car keyA key points to a car; two keys open the same car.

References and this · Step-by-step code trace

Reference Assignment: Step by Step

An object is created; car1 refers to it.

car2 = car1: the reference is copied. There is still a single object.

Both variables read the same object: both say Toyota.

car2.setBrand("Ford") changes the shared object.

car1 now reads Ford too: the change is shared.

car1 = null: only this variable lets go; the object is not deleted, and car2 still refers to it.

When the last reference to an object is gone, the garbage collector removes it.

public static void main(String[] args) {
  Car car1 = new Car("Toyota");
  Car car2 = car1;
  System.out.println("Car 1: " + car1.getBrand());
  System.out.println("Car 2: " + car2.getBrand());
  car2.setBrand("Ford");
  System.out.println("Car 1: " + car1.getBrand());
  car1 = null;
  System.out.println("Car 2: " + car2.getBrand());
}

this(...) and Constructor Chaining

  • this(...) calls another constructor of the same class. Shared initialization lives in one constructor; the others delegate to it, supplying the missing arguments.
  • this(...) must be the first statement of the constructor; placed after another statement, it does not compile.
  • The called constructor's body finishes first, then the caller's remaining lines run; however long the chain, only one object is built.
  • If constructors call each other in a cycle, the compiler catches it.
class Employee {
  private String name;
  private double salary;
  Employee(String name) {
    this(name, 20000.0);   // same-class constructor
  }
  Employee(String name, double salary) {
    this.name = name;        // init in one place
    this.salary = salary;
  }
}

Not on the first line: A() { x = 1; this(2); }

error: call to this must be first statement in constructor

Cycle: A() { this(1); } and A(int x) { this(); }

error: recursive constructor invocation

Comparing Objects

== and equals()

  • Variables store only references to objects.
  • == compares memory addresses, not fields: do both variables point to the same object?
  • Content equality of two objects is checked with equals(), which compares all properties; in our own classes it must be overridden.
  • String and wrappers are objects too: for "Java" read from the keyboard and the literal "Java", == gives false, equals gives true.
  • equals, hashCode, toString and getClass come to every class from Object; when equals is overridden, hashCode must be too.
ExpressionResult
k1 == k3true: same object
k1 == k2false: different objects
k1.equals(k2)true: same content*

* equals if overridden; otherwise Object's version behaves like ==.

Design Example: Rational

public class Rational {
  // Representation: hidden fields
  private int num, den;
  // Interface: public constructor and methods
  public Rational(int num, int den) {
    int g = gcd(Math.abs(num), Math.abs(den));
    this.num = num / g;
    this.den = den / g;
  }
  public Rational add(Rational d) {
    int newNum = num * d.den + d.num * den;
    return new Rational(newNum, den * d.den);
  }
  @Override
  public String toString() { return num + "/" + den; }
  // Implementation detail: hidden helper
  private static int gcd(int a, int b) {
    while (b != 0) { int k = a % b; a = b; b = k; }
    return a;
  }
}
  • Interface: public constructor, add, toString.
  • Representation: private int num, den; the constructor reduces the fraction.
  • Implementation: method bodies and the hidden gcd helper (Euclid's algorithm).
  • add does not change the current object; it returns a new object.

Rational: Code Trace

new Rational(6, 8): the object's fields start at 0; the constructor's parameters are 6 and 8.

The hidden helper gcd(6, 8) is called (Euclid's algorithm). Users cannot see this method.

6 % 8 = 6; a ← 8, b ← 6. In the first round the numbers swap.

8 % 6 = 2; a ← 6, b ← 2.

6 % 2 = 0; a ← 2, b ← 0. b == 0: the loop ends.

gcd returns 2; the constructor stores the reduced fraction: the object is 3/4. The representation always stays reduced.

Same steps for (1, 6): gcd returns 1; the fraction is already reduced: 1/6.

a.add(b): this = #1, d = #2. Since this is the same class, private fields such as d.den can be read.

new Rational(22, 24): gcd finds 2 via 24, 22, 2, 0; the new object is 11/12.

First the result (#3), then a is printed: add does not change the current object; it returns a new one.

  5. record StudentRecord(String name, int id) { } → StudentRecord[name=Ali, id=7]
