Veriyi ve onu işleyen metotları tek sınıfta toplamayı, iç ayrıntıları gizlemeyi (bilgi saklama) ve “ne / nasıl” ayrımını örnekle anlatmak.

Metot sözleşmesi yazmak

Bir metodun ön koşulunu ve son koşulunu yorum satırıyla belirtmek ve kodda kontrol etmek.

Erişimi doğru seçmek

public, private, protected ve paket erişiminin kimlere açık olduğunu tablo ile söylemek.

Getter ve setter yazmak

Arayüz ile gerçekleştirimi ayırmak

Sınıfın dış yüzünü değiştirmeden iç yapısını değiştirebilmek; interface ve implements ile tanışmak.

Paket kullanmak

package ve import ile sınıfları gruplamak, derleyip çalıştırmak; metot ve sınıf adı çakışmalarını çözmek.

Sarmalama ve Bilgi Saklama

Sarmalama (Encapsulation)

  • Sarmalama (encapsulation): bir nesnenin verisini (alanlar) ve bu veriyi işleyen metotları tek birimde, sınıfta toplamak.
  • Veri dışarıya kapatılır (private); dışarıdan yalnızca sınıfın sunduğu metotlar çağrılabilir.
  • Benzetme: ilaç kapsülü. İçindeki toz görünmez, yalnızca kapsülü yutarsınız. Sınıf da kendi verisinin bekçisidir: geçersiz bir değer (ör. 75. saniye) içeri giremez.

Sarmalama, nesne yönelimli programlamanın dört temel ilkesinden biridir (diğerleri: kalıtım, çok biçimlilik, soyutlama).

Sarmalama ve Bilgi Saklama

Bilgi Saklama

  • Bilgi saklama (information hiding), soyutlama (abstraction) olarak da adlandırılır. Tasarım, ne yapıldığını nasıl yapıldığından ayırmalıdır.
  • Bir metot, iç ayrıntıları bilinmeden de kullanılabilmelidir: metodun ne işe yaradığını bilmek yeterli olmalıdır.
  • Arabada fren, gaz pedalı ve direksiyonu görür, kullanırız; bu parçaların iç mekaniğini bilmeyiz.

Aynı fikir koddadır: System.out.println metodunu sürekli kullanırız ama ekrana yazmanın nasıl gerçekleştiğini bilmemiz gerekmez.

Ön ve Son Koşullar

Ön ve Son Koşullar

Ön koşul (precondition)

Metot çağrılmadan önce doğru olduğu varsayılan koşul. Sağlamak çağıranın sorumluluğudur.

public class VeriIslemleri {
    // Ön koşul: veri != null
    public void veriEkle(String veri) {
        // verinin null olup olmadığını kontrol et
        // ...
    }
}

Son koşul (postcondition)

Ön koşul sağlandıysa, metot bittikten sonra doğru olacağı garanti edilen durum. Sağlamak metodun sorumluluğudur.

public class VeriIslemleri {
    // Son koşul: veri tabanına veri eklendiyse true döner
    public boolean veriEkle(String veri) {
        // veriyi ekleyip eklemediğini kontrol et
        // ...
        return true;
    }
}
İkisi birlikte metodun sözleşmesidir (contract): “Sen bana boş olmayan bir veri ver, ben de onu ekleyip true döndüreyim.” Kullanıcı yalnızca sözleşmeyi bilir, gövdeyi bilmez.

Ön ve Son Koşullar

Sözleşme: Tam Örnek

public class VeriIslemleri {
  private int kayitSayisi = 0;

  /**
   * Veri tabanına bir kayıt ekler.
   * Ön koşul: veri null değil ve boş değil.
   * Son koşul: eklendiyse true döner,
   *            kayitSayisi 1 artar.
   */
  public boolean veriEkle(String veri) {
    if (veri == null || veri.isEmpty()) {
      return false;   // ön koşul bozuk
    }
    // ... veriyi veri tabanına ekle ...
    kayitSayisi++;
    return true;      // son koşul sağlandı
  }

  public int getKayitSayisi() {
    return kayitSayisi;
  }
}
// main içinde:
VeriIslemleri islem = new VeriIslemleri();
System.out.println(islem.veriEkle("Ali"));
System.out.println(islem.veriEkle(""));
System.out.println(islem.veriEkle(null));
System.out.println(islem.getKayitSayisi());

Erişim Belirleyiciler

Erişim Belirleyiciler

  • Erişim belirleyici (access modifier): bir sınıfa, alana veya metoda kimin erişebileceğini belirleyen anahtar kelime.
  • public: diğer sınıflar tarafından doğrudan erişilebilir.
  • private: yalnızca sınıfın içinden erişilebilir; dışarıdan erişim derleyici tarafından engellenir.
  • Sınıflar genellikle public tanımlanır.
  • Sınıfın nitelikleri (alanları) genellikle private tanımlanır.
  • Niteliklere erişmek ve onları değiştirmek için public metotlar kullanılır.
public class Ogrenci {      // herkese açık sınıf
    private String ad;      // gizli alan
    private int not;        // gizli alan

    public int getNot() {   // açık metot
        return not;
    }
}

Kural: alanlar gizli, davranışlar açık.

Setter Koruması: Adım Adım

Nesne oluşturulur, saniye alanı 0 ile başlar. s nesneyi gösterir.

setSaniye(45): parametre saniye = 45. this, metodu çağıran nesnedir. Koşul doğru.

this.saniye = saniye; soldaki nesnenin alanı, sağdaki parametredir. Alan 45 olur.

setSaniye(75): koşul yanlış, atama satırı atlanır. Geçersiz değer nesneye giremez.

getSaniye() alanın değerini döndürür: 45. Alan hâlâ geçerli.

Ekrana 45 yazılır. Nesnenin durumu baştan sona geçerli kaldı: sarmalamanın amacı budur.

public class DijitalSaat {

    return this.saniye;
  }
  public void setSaniye(int saniye) {
    if (saniye >= 0 && saniye < 60) {
      this.saniye = saniye;
    }
  }
}

public class BankaHesabi {

  private double bakiye;      // Hesap bakiyesi
  private String hesapTuru;   // "Vadesiz" / "Vadeli"

  public BankaHesabi(int hesapNumarasi,

    this.bakiye = bakiye;
    this.hesapTuru = hesapTuru;
  }

  public int getHesapNumarasi() {
    return hesapNumarasi;
  }
  public double getBakiye() {
    return bakiye;
  }
  public String getHesapTuru() {
    return hesapTuru;
  }
  // ... işlemler sonraki slaytlarda
  • Üç alan da private: hesap numarasını veya bakiyeyi kimse doğrudan değiştiremez.
  • Yapıcı (constructor) nesneyi ilk değerleriyle kurar; this.bakiye = bakiye kalıbı.
  • Yalnızca getter var, setter yok: setBakiye olmadığı için bakiye yalnızca işlemlerle değişir.

BankaHesabi: Yatırma ve Çekme

  // ...
  // Para yatırma işlemi
  public void paraYatir(double miktar) {
    if (miktar > 0) {
      bakiye += miktar;
      System.out.println(miktar
          + " TL yatırıldı. Yeni bakiye: " + bakiye);
    } else {
      System.out.println("Yatırılan miktar geçersiz.");
    }
  }

  // Para çekme işlemi
  public void paraCek(double miktar) {
    if (miktar <= bakiye && miktar > 0) {
      bakiye -= miktar;
      System.out.println(miktar
          + " TL çekildi. Kalan bakiye: " + bakiye);
    } else if (miktar > bakiye) {
      System.out.println("Yetersiz bakiye.");
    } else {
      System.out.println("Çekilen miktar geçersiz.");
    }
  }
  • Her işlem önce ön koşulu kontrol eder: miktar > 0, çekmede ayrıca miktar ≤ bakiye.
  • Koşul bozuksa bakiye değişmez, yalnızca bir mesaj yazılır.
  • Bakiye hiçbir yoldan eksiye düşemez: bu, sınıfın değişmezidir.

  // ...
  // Faiz ekleme (yalnızca vadeli hesap)
  public void faizEkle(double oran) {
    if (hesapTuru.equals("Vadeli") && oran > 0) {
      double faiz = bakiye * oran / 100;
      bakiye += faiz;
      System.out.println("Faiz ekleniyor: " + faiz
          + " TL. Yeni bakiye: " + bakiye);
    } else if (!hesapTuru.equals("Vadeli")) {
      System.out.println(
          "Faiz yalnızca vadeli hesaplarda uygulanabilir.");
    } else {
      System.out.println("Geçersiz faiz oranı.");
    }
  }
  • Faiz yalnızca vadeli hesapta ve pozitif oranla eklenir.
  • Metinler == ile değil, equals ile karşılaştırılır.
  • faiz bir yerel değişkendir: yalnızca metot çalışırken vardır, nesnenin parçası değildir.

BankaHesabi: Transfer

  // ...
  // Başka bir hesaba transfer
  public void transfer(BankaHesabi hedefHesap,
                       double miktar) {
    if (miktar <= bakiye && miktar > 0) {
      bakiye -= miktar;
      hedefHesap.paraYatir(miktar);
      System.out.println(miktar
          + " TL transfer edildi. Yeni bakiye: " + bakiye);
    } else {
      System.out.println(
          "Yetersiz bakiye veya geçersiz miktar.");
    }
  }
}
  • transfer, aynı sınıftan başka bir nesnenin metodunu çağırır: hedefHesap üzerinde paraYatir.
  • Hedef hesabın bakiye alanına doğrudan yazmak da mümkündü (aynı sınıf, private sınıf düzeyindedir), ama metot çağırmak kuralların tek yerde kalmasını sağlar.
  • Sonraki slayt bu çağrıları adım adım izler.

Örnek: Banka Hesabı · Kodu adım adım çalıştır

İki Hesap, Bir Transfer: Adım Adım

Yapıcı çalışır: ilk nesne heap'te 2000.0 bakiye ile kurulur.

İkinci, bağımsız nesne. Her nesnenin kendi bakiye alanı vardır.

this = hesap1. miktar > 0 doğru: bakiye += miktar → 2500.0.

Bu kez this = hesap2. 200 ≤ 1500: bakiye 1300.0 olur; hesap1 etkilenmez.

Hesap vadeli: faiz = 2500.0 × 5 / 100 = 125.0, bakiye 2625.0.

transfer: koşul doğru, önce kendi bakiyesinden düşer: 2625.0 − 300.0 = 2325.0.

hedefHesap.paraYatir(miktar): yığında 3 çerçeve; şimdi this = hesap2, bakiye 1600.0.

paraYatir biter, transfer kaldığı yerden devam eder ve kendi mesajını yazar.

Getter'lar son bakiyeleri okur. Toplam para korunur: 2325 + 1600 = 3925 = 2625 + 1300.

// main içinde:
BankaHesabi hesap1 =
    new BankaHesabi(123456, 2000.0, "Vadeli");
BankaHesabi hesap2 =
    new BankaHesabi(789012, 1500.0, "Vadesiz");
hesap1.paraYatir(500.0);
hesap2.paraCek(200.0);
hesap1.faizEkle(5.0);
hesap1.transfer(hesap2, 300.0);
System.out.println(hesap1.getBakiye());
System.out.println(hesap2.getBakiye());

Sınıf Tasarımı

Sınıf Tasarımı

  • Sınıf tanımı iki kısma ayrılır: arayüz (interface) ve gerçekleştirim (implementation).
  • Arayüz, sınıfın ne yaptığını ve nasıl kullanılacağını belirtir: public metotların adları, parametreleri, dönüş türleri ve yorumları.
  • Gerçekleştirim, sınıfın iç mekanik ayrıntılarını ve özel (private) niteliklerini içerir. Bunlar yalnızca sınıfın içinde önemlidir.
  • Gerçekleştirim değişse bile arayüz değişmeyebilir; öz nitelikler sınıfın dışına gizlidir.

Arayüz

    public void dur();
}
  • Java'da interface, bir sınıfın ne yapacağını söyleyen sözleşmedir: metotların yalnızca imzası vardır, gövdesi yoktur.
  • Arabayı kullanan kişi yalnızca hareketEt() ve dur() metotlarını bilir.
  • Arayüzler ayrıntılı olarak Soyut Sınıflar bölümünde ele alınır.

Eski: iki ayrı alan

public class DijitalSaat {

Yeni: tek alan

public class DijitalSaat {
  // gece yarısından beri geçen saniye
  private int toplamSaniye = 0;
  public int getDakika() {
    return toplamSaniye / 60 % 60;
  }
  public int getSaniye() {
    return toplamSaniye % 60;
  }
  public void setDakika(int dakika) {
    if (dakika >= 0 && dakika < 60) {
      int fark = dakika - getDakika();
      toplamSaniye += fark * 60;
    }
  }
  public void setSaniye(int saniye) {
    if (saniye >= 0 && saniye < 60) {
      toplamSaniye += saniye - getSaniye();
    }
  }
}
Kullanan kod değişmez: setDakika(12); setSaniye(45); setSaniye(75); sonrası iki sürüm de 12:45 verir.

Sınıf Tasarımı

Tavsiyeler

  1. Sınıf içindeki tüm değişkenler (alanlar) private tanımlanmalı.
  2. Değişkenlere erişim için gerektiği kadar public erişim metodu sağlanmalı (her alana otomatik setter yazmak şart değildir).
  3. Her metodun nasıl kullanılacağını belirten yorum satırları eklenmeli: ne yapar, ön ve son koşulları neler.
  4. Yalnızca sınıf içinde kullanılan yardımcı metotlar private tanımlanmalı.
public class Ogrenci {
    private int not;
    private boolean gecerliMi(int deger) {
        return deger >= 0 && deger <= 100;
    }
    public void setNot(int not) {
        if (gecerliMi(not)) this.not = not;
    }
}

Başka sınıftan o.gecerliMi(50) çağrılırsa:

error: gecerliMi(int) has private access in Ogrenci

Sınıf Tasarımı

Sarmalamanın Faydaları

Soyutlama

Nesne ile kullanıcısı arasındaki ilişkiyi sadeleştirir: kullanıcı yalnızca metotları bilir.

Koruma

Nesneyi kullanıcının istenmeyen, hatalı erişimlerine karşı korur.

Değiştirilebilirlik

Arayüzü değiştirmeden sınıfın iç yapısı değiştirilebilir; kullanan kod etkilenmez.

Geçerli durum (değişmez)

Nesnenin durumu her zaman kurallara uyar (sınıf değişmezi, class invariant):

  • yalnızca pozitif koordinatlı noktalar,
  • saniye ve dakika 0–59 arasında,
  • saat negatif olamaz.
Bu bölümün örneklerinde: setSaniye(75) reddedilir, paraCek bakiyeyi asla eksiye düşürmez, BankaHesabi'nın iç yapısı değişse bile paraYatir çağıran kod aynı kalır.

Sınıf Tasarımı

Gözlemler

  • Arayüzler, gerçekleştirimden çok daha nadir değişir: bu, kodun kararlı olmasını sağlar.
  • Gerçekleştirim değiştiğinde, ona doğrudan bağımlı olan kodların da değişmesi gerekir.
  • Gerçekleştirimi gizlemek, diğer sınıfların bağımlılığını azaltır: değişiklik sınıfın içinde kalır (gevşek bağlılık, loose coupling).

Paketler

Paketler

  • Paket (package): bir klasör içinde gruplanmış sınıflar topluluğu. Klasörün adı paketin adıdır.
  • Her public sınıf ayrı bir dosyada, sınıfla aynı adlı dosyada tanımlanır.
  • Dosyanın ilk satırı ait olduğu paketi bildirir: package paket_adi;
  • Derleyici ve JVM paketleri sınıf yolu (classpath) köklerinden başlayarak arar; paket adı bu kökten itibaren klasör yolunu söyler. Varsayılan sınıf yolu bulunulan dizindir (.).
  • İç içe klasörlerde / veya \ yerine nokta kullanılır: okul/yonetim → okul.yonetim.
  • Paket adları küçük harfle yazılır; Java'nın kendi paketleri: java.lang, java.util, java.io…
proje/
├── src/
│   ├── banka/
│   │   ├── Hesap.java      // package banka;
│   │   └── Yardimci.java   // package banka;
│   └── uygulama/
│       └── Ana.java        // package uygulama;
└── out/                    // derleme çıktısı
    ├── banka/
    │   ├── Hesap.class
    │   └── Yardimci.class
    └── uygulama/
        └── Ana.class

Sınıfın tam adı paketini de içerir: banka.Hesap, uygulama.Ana.

Ad Çakışmaları

Metot Adı Çakışmaları

public class Yazici {
  static void yazdir(int x)        { System.out.println("int: " + x); }
  static void yazdir(double x)     { System.out.println("double: " + x); }
  static void yazdir(String s)     { System.out.println("String: " + s); }
  static void yazdir(int a, int b) { System.out.println("iki int: " + a + ", " + b); }

  public static void main(String[] args) {
    yazdir(7);       // int: 7
    yazdir(7.5);     // double: 7.5
    yazdir("yedi");  // String: yedi
    yazdir(3, 4);    // iki int: 3, 4
    yazdir('A');     // int: 65       (char → int)
    yazdir(5L);      // double: 5.0   (long → double)
    yazdir(2.5f);    // double: 2.5   (float → double)
  }
}
  • Aynı adlı birden fazla metot olabilir (aşırı yükleme, overloading); parametre sayısı ve türleri ayırt eder. (Yorumlar gerçek çıktıdır.)
  • Tam eşleşme yoksa genişletme dönüşümü denenir: char → int, long → double.
  • Hiçbiri uymazsa derleme hatası: yazdir(true) → no suitable method found for yazdir(boolean)
  • Dönüş türü tek başına ayırt etmez; parametre listesi farklı olmalıdır.
