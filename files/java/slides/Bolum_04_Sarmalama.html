Sarmalama ve Bilgi Saklama

Sarmalama (Encapsulation)

  • Sarmalama (encapsulation): bir nesnenin verisini (alanlar) ve bu veriyi işleyen metotları tek birimde, sınıfta toplamak.
  • Veri dışarıya kapatılır (private); dışarıdan yalnızca sınıfın sunduğu metotlar çağrılabilir.
  • Benzetme: ilaç kapsülü. İçindeki toz görünmez, yalnızca kapsülü yutarsınız. Sınıf da kendi verisinin bekçisidir: geçersiz bir değer (ör. 75. saniye) içeri giremez.

Sarmalama, nesne yönelimli programlamanın dört temel ilkesinden biridir (diğerleri: kalıtım, çok biçimlilik, soyutlama).

Sarmalama ve Bilgi Saklama

Bilgi Saklama

  • Bilgi saklama (information hiding), soyutlama (abstraction) olarak da adlandırılır. Tasarım, ne yapıldığını nasıl yapıldığından ayırmalıdır.
  • Bir metot, iç ayrıntıları bilinmeden de kullanılabilmelidir: metodun ne işe yaradığını bilmek yeterli olmalıdır.
  • Arabada fren, gaz pedalı ve direksiyonu görür, kullanırız; bu parçaların iç mekaniğini bilmeyiz.

Aynı fikir koddadır: System.out.println metodunu sürekli kullanırız ama ekrana yazmanın nasıl gerçekleştiğini bilmemiz gerekmez.

Ön ve Son Koşullar

Ön ve Son Koşullar

Ön koşul (precondition)

Metot çağrılmadan önce doğru olduğu varsayılan koşul. Sağlamak çağıranın sorumluluğudur.

public class VeriIslemleri {
    // Ön koşul: veri != null
    public void veriEkle(String veri) {
        // verinin null olup olmadığını kontrol et
        // ...
    }
}

Son koşul (postcondition)

Ön koşul sağlandıysa, metot bittikten sonra doğru olacağı garanti edilen durum. Sağlamak metodun sorumluluğudur.

public class VeriIslemleri {
    // Son koşul: veri tabanına veri eklendiyse true döner
    public boolean veriEkle(String veri) {
        // veriyi ekleyip eklemediğini kontrol et
        // ...
        return true;
    }
}
İkisi birlikte metodun sözleşmesidir (contract): “Sen bana boş olmayan bir veri ver, ben de onu ekleyip true döndüreyim.” Kullanıcı yalnızca sözleşmeyi bilir, gövdeyi bilmez.

Erişim Belirleyiciler

Erişim Belirleyiciler

  • Erişim belirleyici (access modifier): bir sınıfa, alana veya metoda kimin erişebileceğini belirleyen anahtar kelime.
  • public: diğer sınıflar tarafından doğrudan erişilebilir.
  • private: yalnızca sınıfın içinden erişilebilir; dışarıdan erişim derleyici tarafından engellenir.
  • Sınıflar genellikle public tanımlanır.
  • Sınıfın alanları genellikle private tanımlanır.
  • Alanlara erişmek ve onları değiştirmek için public metotlar kullanılır.
public class Ogrenci {      // herkese açık sınıf
    private String ad;      // gizli alan
    private int not;        // gizli alan

    public int getNot() {   // açık metot
        return not;
    }
}

Kural: alanlar gizli, davranışlar açık.

Sınıf Tasarımı

  • Sınıf tanımı iki kısma ayrılır: arayüz (interface) ve gerçekleştirme (implementation).
  • Arayüz, sınıfın ne yaptığını ve nasıl kullanılacağını belirtir: public metotların adları, parametreleri, dönüş tipleri ve yorumları.

Tavsiyeler

  1. Sınıf içindeki tüm değişkenler (alanlar) private tanımlanmalı.
  2. Değişkenlere erişim için gerektiği kadar public erişim metodu sağlanmalı (her alana otomatik setter yazmak şart değildir).
  3. Her metodun nasıl kullanılacağını belirten yorum satırları eklenmeli: ne yapar, ön ve son koşulları neler.
  4. Yalnızca sınıf içinde kullanılan yardımcı metotlar private tanımlanmalı.

Sor Değil, Söyle

Her alana bir getter ve bir setter yazmak sarmalama değildir: kurallar yine sınıfın dışında uygulanıyorsa veri yalnızca bir adım uzağa taşınmıştır.

Sormak: kural kullanan kodda

        return kurus / 100 + ","
            + String.format("%02d", kurus % 100) + " " + birim;
    }
}

Kurallar

  1. Setter yok; durum yalnızca yapıcıda kurulur.
  2. Alanlar private final.
  3. Sınıf final: değiştirilebilir bir alt sınıf yazılamasın.
  4. “Değiştiren” metotlar yeni bir nesne döndürür.
  5. Değiştirilebilir alanlar varsa savunmacı kopya.

Kazanç

  • Değişmez yalnızca yapıcıda denetlenir; sonra hiç bozulamaz.
  • Nesne kopyalanmadan paylaşılabilir, HashMap anahtarı olabilir, iş parçacıkları arasında güvenlidir.
  • String ve record bu kuralların hazır örnekleridir.

public class Yazici {
  static void yazdir(int x)        { System.out.println("int: " + x); }
  static void yazdir(double x)     { System.out.println("double: " + x); }
  static void yazdir(String s)     { System.out.println("String: " + s); }
  static void yazdir(int a, int b) { System.out.println("iki int: " + a + ", " + b); }

  public static void main(String[] args) {
    yazdir(7);       // int: 7
    yazdir(7.5);     // double: 7.5
    yazdir("yedi");  // String: yedi
    yazdir(3, 4);    // iki int: 3, 4
    yazdir('A');     // int: 65       (char → int)
    yazdir(5L);      // double: 5.0   (long → double)
    yazdir(2.5f);    // double: 2.5   (float → double)
  }
}
  • Aynı adlı birden fazla metot olabilir (aşırı yükleme, overloading); parametre sayısı ve tipleri ayırt eder. (Yorumlar gerçek çıktıdır.)

  • Hiçbiri uymazsa derleme hatası: yazdir(true) → no suitable method found for yazdir(boolean)
  • Dönüş tipi tek başına ayırt etmez; parametre listesi farklı olmalıdır.
