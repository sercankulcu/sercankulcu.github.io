Graphics Programming

Graphics Programming

  • Java offers a powerful, complete toolkit for building graphical user interfaces (GUIs): windows, buttons, text fields, drawings.
  • With it you can write interactive, visual applications. Three ideas are key:
Components

The building blocks of the interface: windows, buttons, labels, text fields. Each is an object of some class.

Event handling

Captures user actions such as mouse clicks and key presses, and calls the methods that respond to them.

Painting

Draws shapes, updates the screen and renders the components.

Analogy: a GUI program is like a shop waiting for customers. The window display (components) is set up, then the program waits; whenever a customer touches something (an event), the right clerk (a listener method) steps in.

Rule: in a GUI program, “what happens next?” is decided not by the order of the code but by the user's next action. Most of the code is listeners of the form “when this happens, do that”.

Graphics Programming

AWT and Swing

AWT (Abstract Window Toolkit), java.awt

Java's first graphics library. Today it is used mostly for its shared classes: Graphics, Color, Font, Point, layout managers and event classes (java.awt.event).

Swing, javax.swing

Built on top of AWT; Java draws the components itself. Class names start with J: JFrame, JPanel, JButton, JLabel…

Hollow triangle: “extends” (inheritance). JFrame is an AWT window; the other Swing components extend JComponent (JButton via AbstractButton).

Graphics Programming

Building a GUI App

  1. Add components to the interface using Java's graphics classes.
  2. Define event-handling methods that respond to user actions.
  3. Render the visuals with methods such as paint() or paintComponent().

The screen is a grid of pixels. Coordinates are integers measured from the component's top-left corner. Unlike the axes in math, y grows downward: (0, 0) is the top-left pixel, (getWidth() − 1, getHeight() − 1) the bottom-right one.

Graphics Programming

Basic Graphics Concepts

Canvas

A surface you can draw on. Swing usually uses a JPanel (AWT has Canvas): we extend JPanel and draw inside it.

The Graphics class

The “pen” that does the drawing. Methods: drawLine(), drawRect(), fillOval(), drawString(), drawImage()…

Color and Font

Color sets the pen's color and Font its typeface: g.setColor(Color.RED), g.setFont(new Font("Serif", Font.BOLD, 24)).

The pen analogy: the Graphics object is the pen in the programmer's hand. setColor swaps the pen; until you swap it again, everything is drawn in the same color.

Graphics Programming

Drawing with paintComponent

import java.awt.*;
import javax.swing.*;

class DrawPanel extends JPanel {
    @Override
    public void paintComponent(Graphics g) {
        super.paintComponent(g);     // clear background
        g.setColor(Color.BLUE);
        g.drawRect(20, 30, 50, 70);  // x, y, w, h
        g.drawString("Hello, Java Graphics!", 100, 100);
    }
}
  • We never call paintComponent ourselves: Swing calls it when the window first opens, when it is resized or when repaint() is requested, and hands us a ready Graphics g.
  • panel.getGraphics() also returns a graphics object, but anything drawn with it is erased the next time the window repaints. For lasting drawings, use paintComponent.

A line between two points. Since y grows downward, the line runs right and down.

drawOval: the ellipse that fits the dashed box. (10, 80) is the box's corner, not the ellipse's.

Width = height, so it is a filled circle: center (160, 110), radius 30.

In drawString, y is the text's baseline: the letters sit above 115.

The method ends; every time the window repaints (resize, repaint()), everything is drawn again from scratch in the same order.

Windows and Panels

The JPanel Class

  • A container in the javax.swing package: it holds other GUI elements.
  • Used to group and arrange the components inside a window; nesting several panels builds complex layouts.
  • Customize color, border and size with setBackground(), setBorder(), setPreferredSize().
  • The canvas for our own drawings, animations and graphics: extend JPanel and override paintComponent.
  • Helps split the code up: each panel can be its own class.

Layout Managers

Layout Managers

A layout manager computes the size and position of the components in a container by rule: panel.setLayout(new GridLayout(2, 3));. We use one instead of hard-coding coordinates because the layout is recomputed automatically when the window grows or the font or screen resolution changes.

FlowLayout

Left to right; wraps when a row fills. JPanel default.

BorderLayout

Five regions. Default for a JFrame's content pane.

GridLayout

A grid of equal cells: new GridLayout(2, 3).

BoxLayout

A single row or column: BoxLayout.Y_AXIS.

The more flexible but complex GridBagLayout builds a grid of cells of different sizes. Nesting panels, each with a simple manager, is usually enough.

Layout Managers · Step-by-step trace

How FlowLayout Fills Its Rows

int[] w = {90, 60, 110, 70, 80};
JPanel panel = new JPanel();   // FlowLayout(CENTER, 5, 5)
panel.setSize(260, 120);
for (int i = 0; i < w.length; i++) {
    JButton b = new JButton("B" + i);
    b.setPreferredSize(new Dimension(w[i], 30));
    panel.add(b);
}
panel.doLayout();              // compute positions
for (Component c : panel.getComponents())
    System.out.println(c.getX() + ", " + c.getY());

JPanel's default manager is FlowLayout: centered, with a 5-pixel gap between components. The dashed lines are the margins.

add only appends the button to a list; its position is still (0, 0), its size 0 × 0.

Loop done: five buttons added, none placed. Placement happens only when the layout is computed.

doLayout(): usable width 260 − 2 × 5 = 250. B0 and B1 fit: 155 pixels.

Adding B2 would make the row 270 pixels: it doesn't fit, so it goes to the next row.

Row 1 is centered: B0 x = 52, B1 x = 52 + 90 + 5 = 147, y = 5.

Row 2: B2 and B3 (185 pixels); adding B4 would make 270. Centering: x0 = 5 + (250 − 185)/2 = 37.

B4 sits alone on row 3; y = 5 + 30 + 5 + 30 + 5 = 75.

The computed bounds are printed. If the panel widens, the rows are recomputed and the buttons move.

Layout Managers

The BorderLayout Class

  • Places components in five regions: NORTH, SOUTH, WEST, EAST, CENTER.
  • Good for components of different priority: toolbar on top, status bar at the bottom, main content in the middle.
  • A component added without a region goes to the center: add(b) = add(b, BorderLayout.CENTER).
  • Each region holds one component; adding a second to the same region replaces the first.
  • North and south take the full width, west and east the remaining height; the center fills everything left.
  • setHgap() and setVgap() set the horizontal and vertical gaps between regions (pixels).

No Entry Sign

The paintComponent Code

public class NoEntrySign extends JPanel {
    @Override
    public void paintComponent(Graphics g) {
        super.paintComponent(g);
        var c = new Point(getWidth() / 2, getHeight() / 2); // center
        var r = Math.min(getWidth() / 2, getHeight() / 2) - 5; // radius
        var r2 = (int) (r * 0.9);   // inner radius
        var bw = (int) (r2 * 1.4);  // bar width
        var bh = (int) (r2 * 0.35); // bar height
        g.setColor(Color.WHITE);
        g.fillOval(c.x - r, c.y - r, 2 * r, 2 * r);
        g.setColor(Color.RED);
        g.fillOval(c.x - r2, c.y - r2, r2 * 2, r2 * 2);
        g.setColor(Color.WHITE);
        g.fillRect(c.x - bw / 2, c.y - bh / 2, bw, bh);
    }
}

var (Java 10+): the compiler infers the type from the right-hand side; here c is a Point, the others int. Classic form: Point c = new Point(…); int r = …;. The (int) cast drops the fractional part. Imports needed: java.awt.* and javax.swing.*.

Interactive Computer Graphics

  • Computer graphics is the creation and processing of visual content. In interactive graphics the user changes the image with input devices such as the mouse and keyboard: drawing programs, games, maps.
  • Graphics libraries draw, color and transform graphical objects; interaction happens through the event loop below.

A listener doesn't paint the screen directly: it updates the data and requests a repaint with repaint(). Swing calls paintComponent at the right moment.

Mouse Events

Listener Interface and Adapter

Interface: all five methods must be written

class ClickListener implements MouseListener {
    public void mouseClicked(MouseEvent e) {
        System.out.println("click");
    }
    public void mousePressed(MouseEvent e) { }
    public void mouseReleased(MouseEvent e) { }
    public void mouseEntered(MouseEvent e) { }
    public void mouseExited(MouseEvent e) { }
}

MouseAdapter: override only what you need

class ClickListener extends MouseAdapter {
    @Override
    public void mouseClicked(MouseEvent e) {
        System.out.println("click");
    }
}
// panel.addMouseListener(new ClickListener());
  • MouseAdapter is a ready-made class that implements MouseListener (and MouseMotionListener, MouseWheelListener) with empty bodies. A subclass writes only the method it cares about.
  • Motion events live in a separate interface: MouseMotionListener (mouseDragged, mouseMoved); its adapter is MouseMotionAdapter. Register with addMouseListener(…), addMouseMotionListener(…).
  • The new MouseAdapter() { … } form is an anonymous inner class: a nameless, single-use subclass.

SwingUtilities and the Event Thread

  • javax.swing.SwingUtilities holds helper methods.
  • Swing components are not thread-safe: if several threads touch them at once, they can become inconsistent.
  • Rule: components are created and modified only on the Event Dispatch Thread (EDT). Listener methods already run on the EDT.
  • Analogy: the kitchen has a single cook (the EDT); everyone else leaves an order ticket (a Runnable) instead of cooking.
MethodBehavior
invokeLater(task)Queues the task and returns immediately (asynchronous). The standard way to start a GUI.
invokeAndWait(task)Waits until the task finishes on the EDT (synchronous). Called from the EDT itself, it throws an Error (the EDT can't wait for itself).

The Event Queue: invokeLater and invokeAndWait

public static void main(String[] a) throws Exception {
  System.out.println("1 main");
  SwingUtilities.invokeLater(
      () -> System.out.println("3 task A"));
  SwingUtilities.invokeLater(
      () -> System.out.println("4 task B"));
  System.out.println("2 main goes on");
  SwingUtilities.invokeAndWait(() -> System.out.println(
      "5 task C, EDT? " + SwingUtilities.isEventDispatchThread()));
  System.out.println("6 main, EDT? "
      + SwingUtilities.isEventDispatchThread());
}

The program starts on the main thread. The event thread (EDT) doesn't exist yet.

invokeLater queues task A and returns at once. The EDT starts.

Task B is queued too; main still doesn't wait.

main carries on. (In this run the EDT hasn't picked up a task yet; the two threads are independent.)

invokeAndWait queues task C and blocks main.

The EDT runs task A from the head of the queue (the thread is named AWT-EventQueue-0).

Order is preserved: task B runs after task A.

Task C also runs on the EDT (true). When it finishes, the waiting main wakes up.

main is not the EDT (false). That's why components are touched only from the EDT.

A program for drawing by holding down the mouse button and dragging.

  • On press (mousePressed) a new curve starts.
  • While dragging (mouseDragged) points are appended to the curve and a repaint is requested.
  • When painting (paintComponent) the consecutive points of each curve are joined with lines.

The program stores the drawing not as an image but as lists of points; the screen is redrawn from this data every time.

public class BasitDrawPanel extends JPanel {
    private List<List<Point>> curves = new ArrayList<>();

    public BasitDrawPanel() {
        addMouseListener(new MouseAdapter() {
            @Override
            public void mousePressed(MouseEvent e) {
                var curve = new ArrayList<Point>();
                curve.add(new Point(e.getX(), e.getY()));
                curves.add(curve);
            }
        });
        addMouseMotionListener(new MouseMotionAdapter() {
            @Override
            public void mouseDragged(MouseEvent e) {
                curves.get(curves.size() - 1)
                       .add(new Point(e.getX(), e.getY()));
                repaint(0, 0, getWidth(), getHeight());
            }
        });
    }
}
  • List<List<Point>>: a list of lists. The outer list holds the curves; each inner list holds one curve's points.
  • The last curve: curves.get(curves.size() - 1). The last index is size() - 1; get(size()) throws IndexOutOfBoundsException.

Tracing the Mouse Events

mousePressed: pressed at (40, 120): a new inner list is created, gets its first point and goes into the outer list.

mouseDragged: dragged to (60, 60): a point is added to the last curve; repaint requests a redraw and the line appears.

mouseDragged: dragged to (80, 120): the same curve grows. In reality dozens of mouseDragged events arrive per second.

mouseReleased: released. We didn't write mouseReleased, so MouseAdapter's empty body runs and nothing happens.

mousePressed: pressed again at (50, 95): a second curve starts. The old curve stays as it is.

mouseDragged: dragged to (70, 95): the point again goes to the last curve, curve 1.

Drawing the Curves: paintComponent

The background is cleared; nothing of the previous drawing remains.

The first curve; prev is its first point.

The inner loop starts at the first point: it joins itself, so a single pixel is drawn. Then prev = p.

The line (40,120) → (60,60).

(60,60) → (80,120). Curve 0 is done.

The outer loop moves to the second curve; prev is reset to its first point, so the two curves are not joined.

@Override
public void paintComponent(Graphics g) {
    super.paintComponent(g);
    for (var c : curves) {
        var prev = c.get(0);
        for (var p : c) {
            g.drawLine(prev.x, prev.y, p.x, p.y);
            prev = p;
        }
    }
}

  • repaint() does not draw right away: it queues a “repaint” request. Back-to-back requests may be merged.
  • repaint(x, y, w, h) asks to redraw only that rectangle. Swing clips everything else: g can't paint outside the region, so there is less work. repaint(0, 0, getWidth(), getHeight()) = repaint().
  • Forget super.paintComponent(g) and the background isn't cleared; leftovers of the old image may remain.
  • We never call paintComponent ourselves; we change the data and request repaint().

As the object is created, its fields are initialized first: count is 0, the label is ready.

The constructor creates a button; button is a local variable.

The lambda is not run, only registered with the button. Its body will run on a click.

The button and label are added to the panel (FlowLayout: side by side). The constructor ends.

The user clicks: the EDT calls actionPerformed, the lambda body. count is a field, so it can be incremented.

setText changes the label's text; Swing repaints the label.

Second click: the same lambda is called again; the field becomes 2.

The label updates. Between clicks the program runs no code at all; it just waits for events.

ActionListener: Anonymous Class and Lambda

Anonymous inner class (classic)

button.addActionListener(new ActionListener() {
    @Override
    public void actionPerformed(ActionEvent e) {
        count++;
        label.setText("Count: " + count);
    }
});

Lambda expression (Java 8+)

button.addActionListener(e -> {
    count++;
    label.setText("Count: " + count);
});

// one expression: no braces needed
button.addActionListener(e -> System.exit(0));
  • ActionListener has just one abstract method (a functional interface), so the compiler accepts the lambda e -> … as the body of actionPerformed.
  • MouseListener has five methods, so it can't be a lambda; use an adapter class there.
  • A lambda cannot modify a local variable: int count = 0; … e -> count++ won't compile. Changing values such as counters must be fields.

Text Converter: The Window

CaseConverter–  □  ×
Edit the text and convert it with the buttons.
  • In the CENTER, an 8-row × 50-column JTextArea inside a JScrollPane.
  • At the bottom (SOUTH), a JPanel holding two buttons (FlowLayout: centered).
  • pack() computes the window size from these components' preferred sizes.

Note: toUpperCase() uses the machine's locale. On an English-locale machine "istanbul" → "ISTANBUL"; on a Turkish one, "İSTANBUL". To pin the result: toUpperCase(Locale.ROOT) or toUpperCase(Locale.forLanguageTag("tr")). This demo uses English rules.

Case Converter

Text Converter: The Code

import java.awt.BorderLayout;
import javax.swing.*;

public class CaseConverter {
    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> {
            var area = new JTextArea("Java Programming", 8, 50);
            var lowerButton = new JButton("To Lowercase");
            var upperButton = new JButton("To Uppercase");
            lowerButton.addActionListener(e ->
                    area.setText(area.getText().toLowerCase()));
            upperButton.addActionListener(e ->
                    area.setText(area.getText().toUpperCase()));
            var panel = new JPanel();
            panel.add(lowerButton);
            panel.add(upperButton);
            var frame = new JFrame("CaseConverter");
            frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
            frame.getContentPane().add(new JScrollPane(area),
                    BorderLayout.CENTER);
            frame.getContentPane().add(panel, BorderLayout.SOUTH);
            frame.pack();
            frame.setVisible(true);
        });
    }
}
  • The whole GUI is built inside one lambda, on the EDT.
  • area is a local variable, but the lambda only reads it (never reassigns it), so it may use it (effectively final).
  • toUpperCase() returns a new String; since String is immutable, the result must be written back with setText.
  • Write BorderLayout.CENTER in full; a bare CENTER won't compile.

Case Converter

What Happens on a Click?

The user clicks “To Uppercase”; the operating system passes this to Java.

Java creates an event object and puts it on the event queue.

The EDT takes the next event; the button calls actionPerformed on every registered ActionListener, so our lambda runs.

area.getText() reads the current text.

toUpperCase() makes a new string; the old one is unchanged.

setText updates the area's model; the area repaints itself with repaint. The EDT moves on to the next event.

Fields and Constructor

public class ChangeCalculator extends JFrame {
    private JTextField amountField = new JTextField(12);
    private Document doc = amountField.getDocument();
    private JTextArea report = new JTextArea(8, 40);

    public ChangeCalculator() {
        var topPanel = new JPanel();
        topPanel.add(new JLabel("Amount:"));
        topPanel.add(amountField);
        getContentPane().add(topPanel, BorderLayout.NORTH);
        getContentPane().add(new JScrollPane(report),
                BorderLayout.CENTER);
        setBackground(Color.LIGHT_GRAY);
        report.setEditable(false);
        doc.addDocumentListener(new DocumentListener() {
            public void insertUpdate(DocumentEvent e) { updateReport(); }
            public void removeUpdate(DocumentEvent e) { updateReport(); }
            public void changedUpdate(DocumentEvent e) { updateReport(); }
        });
    }
  • The class extends JFrame. Swing separates data from display (MVC): the JTextField is the view; the Document from getDocument() is the model holding the text.
  • DocumentListener: insertUpdate (text added), removeUpdate (removed), changedUpdate (style changed; never called for plain text). It is an interface, so all three are written.

void updateReport() {
    try {
        var amount = Integer.parseInt(
                doc.getText(0, doc.getLength()));
        int[] coins = {50, 25, 10, 5, 1};
        report.setText(amount
                + " cents in coins:\n");
        for (int x : coins) {
            report.append(amount / x + " x " + x + "c\n");
            amount %= x;
        }
    } catch (NumberFormatException e) {
        report.setText("Not an integer or out of range");
    } catch (Exception e) {
        report.setText(e.toString());
    }
}

Summary

Good Practices

Layout managers

Don't hard-code coordinates; with a layout manager the layout survives different screen sizes and resolutions.

Meaningful names

upperButton, amountField instead of b1, t2: code with dozens of components stays readable.

Think event-driven

Design around “what should happen when the user does this?”; one listener per action.

Separate the GUI from the logic

Keep rules such as making change in a separate method or class; it can be tested without a GUI and reused in another one.

Build the GUI on the EDT

The body of main: SwingUtilities.invokeLater(() -> { … }).

Don't block the EDT

A long job in a listener (a download, a big computation) freezes the window; move such work to a separate thread.

Common Mistakes

Forgetting the import

Without import javax.swing.*; for JFrame: cannot find symbol … class JFrame.

No setVisible(true) or EXIT_ON_CLOSE

The window never appears, or the program keeps running in the background after it closes.

Misspelling the method name

paintcomponent is a new method that is never called. With @Override: method does not override or implement a method from a supertype.

Forgetting super.paintComponent(g)

The background isn't cleared; leftovers of old drawings stay on screen.

Not writing every interface method

ClickListener is not abstract and does not override abstract method mouseExited(MouseEvent) in MouseListener. Fix: MouseAdapter.

get(size()) for the last element

IndexOutOfBoundsException: Index 1 out of bounds for length 1. The last element is size() - 1.

Changing a local variable in a lambda

e -> count++: local variables referenced from a lambda expression must be final or effectively final. Fix: make the counter a field.

Writing a constant without its class

add(comp, CENTER): cannot find symbol … variable CENTER. Use BorderLayout.CENTER.
