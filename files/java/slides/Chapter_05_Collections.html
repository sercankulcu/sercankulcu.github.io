The Collections Framework

Why Collections?

  • Collection: a data structure that stores and manages several elements in a single object.
  • Java Collections Framework: the ready-made interfaces, classes and algorithms in package java.util.
  • Powerful, well-tested tools for storing, sorting, searching and processing data, optimized for performance and safety.
  • Unlike an array, the size is dynamic, and methods such as add, remove and contains come built in.
  • Picking the right structure matters: each collection type is designed for a different need.

Array: size fixed up front

int[] arr = new int[3];      // size fixed: 3
arr[0] = 10;
arr[1] = 20;
arr[2] = 30;

Analogy: an array is a bus with a fixed number of seats; an ArrayList is a bus that grows as passengers board.

The ArrayList Class

  • Dynamic array: stores elements in an internal array, in insertion order.
  • Extends AbstractList and implements the List interface.
  • Dynamic size: the internal array grows automatically when it fills up.
  • get(i) / set(i, e) are very fast: O(1).
  • Appending is fast on average; inserting or removing in the middle shifts elements, so it is slow: O(n).

Lists

How Does an ArrayList Grow?

Take a list created with new ArrayList<>(4), initial capacity 4: inside is a 4-cell array, 3 cells in use.

add("D"): there is a free cell; D goes straight to the end. Nothing moves: O(1).

add("E"): the array is full! A larger array is allocated and the 4 old elements are copied one by one: O(n).

E is written at index 4 of the new array. The old array is left to the garbage collector.

The default capacity is 10; each growth makes it about 1.5 times larger. Since copying happens only now and then, appending is O(1) on average (amortized). Capacity is not size(): size() is the number of occupied cells.

Inserting and Removing in the Middle

Start: [10, 20, 30, 40]. Now add(1, 15) runs.

First the elements after index 1 shift one place right (starting from the end); cell 1 becomes free.

15 goes into the free cell. In a list of n elements the worst case is n shifts: O(n).

remove(0): 10 is removed and the 4 elements behind it shift one place left.

Result. Removing from the end needs no shifting: O(1). Removing from the front or middle is O(n).

Lists

The LinkedList Class

  • Doubly linked list: elements live in nodes; each node holds its value and references to the previous (prev) and next (next) node.
  • Extends AbstractSequentialList; implements the List and Deque interfaces.
  • Flexible size: there is no capacity; each insertion creates a new node and nothing is shifted.
  • Insertion and removal at the ends are O(1); but get(i) walks the nodes one by one: O(n).

Analogy: a line of people holding hands. If someone joins in the middle, only two people let go and regrab; but to find the 3rd person you must count from the start.

The Stack Class

  • LIFO (Last In, First Out): the last element in is the first out.
  • The newest element sits on top, the oldest at the bottom (base).
  • It extends the Vector class.
  • Uses: undo, parsing text and expressions (bracket matching), depth-first search, the method call stack.
  • Modern code should use ArrayDeque (or LinkedList), which implements the Deque interface.

Analogy: a pile of plates; you always take from and put on the top.

Queues

The Queue Interface

  • FIFO (First-In-First-Out): the first element in is the first out.
  • Elements leave in the order they arrived; new elements join at the tail, and the next one to process is taken from the head.
  • Elements are usually handled with offer, poll and peek.
  • Implementations: LinkedList (doubly linked list), PriorityQueue (by priority, not FIFO), ArrayDeque (dynamic array).
  • Uses: print queues, task queues, breadth-first search.

Analogy: a supermarket checkout. You join at the back; the person at the front pays.

On an empty queue remove() and element() throw NoSuchElementException, while poll() and peek() return null. size(): number of elements.

The PriorityQueue Class

  • Priority queue: the element that leaves is always the highest-priority one, not the earliest added.
  • The default priority is natural order: the smallest element leaves first. Pass a comparator for the reverse.
  • Elements must be comparable (Comparable), or a Comparator must be supplied.
  • Internally a binary heap: add/poll O(log n), peek O(1); grows dynamically.
  • Uses: task scheduling, emergency-room triage, shortest-path algorithms.

Queues · Step-by-step code trace

PriorityQueue: The Heap Rule Step by Step

Inside, an empty array: a binary heap. Rule: every parent is less than or equal to its children.

30 goes to the root (index 0).

10 is appended (index 1); it is smaller than its parent 30, so it moves up and they swap. The root is now 10.

40 goes to index 2; it is larger than its parent 10 and stays.

20 goes to index 3; smaller than its parent 30 → swap; larger than 10 → stop.

peek(): the root, i.e. the smallest element: 10. The queue is unchanged; O(1).

println prints the internal array as is: [10, 20, 40, 30] is not sorted.

poll(): the root 10 leaves; the last element, 30, moves to the root and swaps with its smaller child 20, sinking down.

20 leaves; 40 moves to the root and swaps with 30.

30 leaves; only 40 is left.

40 leaves; the queue is empty and the loop ends. They came out sorted: 10 20 30 40.

A newline is printed. Each poll follows only one branch: O(log n).

Setting the Priority

class Task implements Comparable<Task> {
    String name;
    int priority;          // smaller = more urgent

    Task(String name, int priority) {
        this.name = name;
        this.priority = priority;
    }

    @Override
    public int compareTo(Task o) {
        return Integer.compare(priority, o.priority);
    }

    @Override
    public String toString() {
        return name + "(" + priority + ")";
    }
}

Sets

The Set Interface

  • Stores unique elements; like a set in mathematics, and suited to set operations.
  • Each element appears only once: add does not add an existing element and returns false.
  • In general there is no order guarantee (the order depends on the implementation).
  • Insertion, removal and lookup are fast.
  • HashSet: no order. LinkedHashSet: insertion order. TreeSet: sorted (natural order or a Comparator).

Changing an Object Inside a Set: The Lost Element

HashSet uses a 16-bucket hash table internally. Point’s equals and hashCode are computed from x and y.

Objects.hash(1, 2) = 994. The bucket number is the last 4 bits of the hash: 994 → bucket 2.

add(p): the object lands in bucket 2.

contains(p): bucket 2 is checked again and equals is true → true.

A field of the object in the set has changed! Its hashCode is now 1118 → bucket 14. But the object still sits in bucket 2.

contains(p): bucket 14 is checked; it is empty → false. The object is in the set but cannot be found.

The new Point(1, 2) goes to bucket 2; the object there is now (5, 2), so equals is false → false.

add(p): bucket 14 looks empty, so the same object is added a second time.

size() = 2: the set is corrupted. Never change the fields used by equals/hashCode of an object in a hashed collection; choose immutable keys such as String or Integer.

Removing Inside for-each: Why the Exception?

The list has 3 elements; modCount (the structural modification counter) is 0.

for-each secretly calls s.iterator(): cursor = 0, and the iterator saves the current modCount: expectedModCount = 0.

hasNext(): cursor (0) ≠ size (3) → true.

next(): first the counters are compared (0 = 0); x = 6, cursor = 1.

6 is even.

s.remove(x) is the list’s own method: 9 and 12 shift left, size becomes 2, modCount becomes 1. The iterator does not know.

hasNext(): cursor (1) ≠ size (2) → true; the loop goes on.

next(): modCount (1) ≠ expectedModCount (0) → ConcurrentModificationException. With {6, 9}, hasNext would be false: no exception, and 9 would go unchecked.

List<Integer> s = new ArrayList<>();
Collections.addAll(s, 6, 9, 12);
for (Integer x : s) {      // hidden Iterator
    if (x % 2 == 0) {
        s.remove(x);
    }
}
System.out.println(s);

The fail-fast check is best-effort, not a guarantee: never rely on the exception.

Checks the middle of a sorted collection, then goes left or right; each step halves the range. O(log n). The collection must be sorted.

The Stream API

Lazy Evaluation and Single Use

List<String> names =
    Arrays.asList("Arda", "Ece", "Ayse", "Can");
Stream<String> pipe = names.stream()
    .filter(s -> s.startsWith("A"))
    .map(String::toUpperCase);
// nothing processed yet.
List<String> result =
    pipe.collect(Collectors.toList());
System.out.println(result);  // [ARDA, AYSE]
pipe.count();   // IllegalStateException
  • Lazy: intermediate operations only record a recipe; elements are processed when the terminal operation is called.
  • Elements pass through the pipeline one at a time: the first goes through filter and map, then the second comes.
  • findFirst and limit stop once they have the result; the remaining elements are never processed.
  • A stream is single-use: reusing it after a terminal operation throws IllegalStateException; get a new stream from the source if needed.

Side Effects and Parallel Streams

List<Integer> list = new ArrayList<>();
IntStream.range(0, 10000).parallel()
    .forEach(list::add);          // WRONG: shared list

List<Integer> safe = IntStream.range(0, 10000).parallel()
    .boxed()
    .collect(Collectors.toList()); // RIGHT: 10000 items
Result of the first pipeline (differs per run)
ArrayIndexOutOfBoundsException
or fewer than 10000 items
  • Lambdas should not modify outside variables; build the result with map, collect, reduce.
  • parallel() / parallelStream() splits the work across the common ForkJoinPool threads. ArrayList is not thread-safe, so the first pipeline breaks.
  • A parallel stream is not always faster: small data, cheap or I/O-bound work and order-dependent operations (sorted, findFirst) can slow it; measure first.
Common mistakes: reusing a stream; doing the real work inside peek; filling an outside collection with forEach; assuming a parallel stream is automatically faster.

static boolean isBalanced(String expr) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : expr.toCharArray()) {
        if (c == '(' || c == '[') {
            stack.push(c);
        } else if (c == ')' || c == ']') {
            if (stack.isEmpty()) return false;
            char open = stack.pop();
            if (c == ')' && open != '(') return false;
            if (c == ']' && open != '[') return false;
        }
    }
    return stack.isEmpty();
}

static String mostFrequent(String[] words) {
    Map<String, Integer> counter = new HashMap<>();
    for (String k : words) {
        counter.put(k, counter.getOrDefault(k, 0) + 1);
    }
    String best = null;
    int maxCount = 0;
    for (Map.Entry<String, Integer> g : counter.entrySet()) {
        if (g.getValue() > maxCount) {
            maxCount = g.getValue();
            best = g.getKey();
        }
    }
    return best;
}
