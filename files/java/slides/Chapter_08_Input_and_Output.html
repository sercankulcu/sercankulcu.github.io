Streams

Streams

  • A stream carries data from a source to a destination in order, piece by piece. The data may be characters, numbers or raw bytes.
  • Input stream: data flows into the program. Example: System.in (keyboard).
  • Output stream: data flows out of the program. Example: System.out (screen).
  • Think of a water pipe: water leaves the far end in the order it went in, and the program doesn't care whether a tap or a tank sits at the other end.

Keyboard, file or network: the program uses the same read() / write() methods. That shared interface is the strength of Java's I/O library.

Streams

Keyboard and Screen: Standard Streams

  • Transient data: keyboard and screen data is not stored; it is gone when the program ends.
  • Live flow: input arrives as the user types; output appears as the program writes.
  • Every Java program starts with three ready-made streams:
StreamJava objectType
standard inputSystem.inInputStream
standard outputSystem.outPrintStream
standard errorSystem.errPrintStream
System.err also writes to the screen, but on a separate channel: even when output is redirected to a file (java App > out.txt), error messages stay on screen.

Files and Encoding

Files

  • A file stores data persistently on disk: it survives the program exiting and the computer restarting (variables in RAM do not).
  • Every file is ultimately 0s and 1s, a sequence of bytes. What differs is how those bytes are interpreted.
  • Text files: bytes are turned into letters by a character encoding; people can read them.
  • Binary files: bytes are numbers, pixels, audio samples, machine instructions; only a program that knows the format can make sense of them.

file.txt in a hex editor:

0000  4D 65 72 68 61 62 61 2C  Merhaba,
0008  20 64 C3 BC 6E 79 61 21   d..nya!

Offset on the left, each byte in hex in the middle, the ASCII view on the right. 4D = 77 = M. The 15 characters (Turkish for “Hello, world!”) take 16 bytes: ü is two bytes in UTF-8 (C3 BC).

Files and Encoding

Text Files

  • Text files contain printable characters: letters, digits, punctuation, spaces, line breaks.
  • Any text editor (Notepad, VS Code) can open and edit them. Examples: source code (.java, .c), .txt, .csv, .html.
  • A character set / encoding is the table that says which number (which bytes) stores each character. Writer and reader must use the same encoding.
ASCII

7 bits, 128 characters: English letters, digits, punctuation, control characters.

ISO-8859-1

8 bits, 256 characters: Western Europe (Latin-1). Has é, ü, ö, ç; no ş, ğ, ı.

ISO-8859-9

8 bits, Latin-5: the Turkish variant. Six Latin-1 letters are replaced by ğ, Ğ, ı, İ, ş, Ş.

UTF-8

The universal Unicode encoding: every language, 1–4 bytes. The default on the web and in Java 18+.

Files and Encoding

Binary Files

  • Bytes are stored not as characters but in a format the program defines: numbers, pixels, audio samples, machine code.
  • Meaningful to a computer (the right program); people cannot read them directly.
  • Examples: executables (.exe, Java's .class files), images (.png, .jpg), music (.mp3), video (.mp4), data files (.dat).
  • Advantage: smaller and faster to process; no number-to-text conversion.

Extended ASCII and Turkish Characters

  • Extended ASCII uses 8 bits (1 byte) to represent 28 = 256 characters.
  • 0–127: standard ASCII, the same in every table. 128–255: special characters, symbols and national letters.
  • There is no single “extended ASCII”: the upper half depends on the code page. Turkish uses ISO-8859-9 (Latin-5) and Windows-1254.

Files and Encoding

Writing a Number (127) to a File

  • How a number is stored depends on its data type, its purpose and the file format.
  • As text: the number is first turned into characters, one ASCII byte per digit: the code of '1' is 49, not 1.
  • As binary: the binary value (0111 1111) is written directly, using as many bytes as the type needs. More efficient for numeric data.

public class Number127 {
  static void writeText(String name, Charset cs) throws IOException {
    Writer w = new OutputStreamWriter(new FileOutputStream(name), cs);
    w.write(String.valueOf(127));            // "127": 3 chars
    w.close();
  }
  static void writeBinary(String name, int size) throws IOException {
    FileOutputStream fos = new FileOutputStream(name);
    DataOutputStream d = new DataOutputStream(fos);
    if (size == 1) d.writeByte(127);        // 01111111
    else if (size == 2) d.writeShort(127);  // 00000000 01111111
    else d.writeInt(127);                    // 4 bytes

try-with-resources: Closing Order

class Res implements AutoCloseable {
  String name;
  Res(String name) { this.name = name; System.out.println(name + " opened"); }
  public void close() { System.out.println(name + " closed"); }
}
public class CloseOrder {
  public static void main(String[] args) {
    try (Res a = new Res("A"); Res b = new Res("B")) {
      System.out.println("block running");
      throw new IllegalStateException("error!");
    } catch (IllegalStateException e) {
      System.out.println("caught: " + e.getMessage());
    } finally { System.out.println("finally"); }
  }
}

The first resource in the parentheses is created; its constructor prints a message. a is now open.

The second resource, b, is opened. Resources are created left to right.

The block body runs; both resources are open.

An exception is thrown. Before control reaches catch, the resources are closed automatically.

Closing runs in reverse order: first close() on b, the last one opened.

Then a.close() runs. The exception is still in flight, not yet caught.

Only after the resources are closed does catch catch the exception. By now a and b are out of scope.

finally runs last. Order: open A, open B, body, close B, close A, catch, finally.

Buffering

Buffering

  • The basic methods: read() reads a byte or a byte array, write() writes a byte or a byte array.
  • A separate disk access per byte slows the program badly: the disk is thousands of times slower than memory.
  • The fix: collect data in a buffer in memory and read from or write to the disk in bulk. Fewer physical disk accesses.
Analogy: instead of carrying 10 items home from the store one trip at a time, put them in a basket and carry them in one go.

Unbuffered: every write() call goes straight to the disk.

Buffered: write() calls first put the bytes in a buffer in memory.

When the buffer fills up, or on flush() or close(), the whole buffer is written to disk at once.

Other Byte Streams

PipedInputStream and PipedOutputStream

  • Derived from InputStream / OutputStream; they let two threads pass data safely.
  • One thread writes with a PipedOutputStream, the other reads it with a PipedInputStream. The ends are connected with new PipedOutputStream(pis).

Copying Files

Copying a File Byte by Byte

  • Writes every byte read from the source file to the target: copies any kind of file (text, image, .exe) intact.
  • BufferedInputStream and BufferedOutputStream speed up I/O by reading and writing through a buffer in bulk.
  • bis.read() reads one byte and returns −1 at end of file. bos.write(b) writes that byte to the output file.
  • Keep the value in an int, so that −1 can be told apart from the byte value 255.

Random Access

File Access: Sequential and Random

Sequential access

  • Each read or write continues from the next position; going back needs special support (e.g. mark/reset, within a limited buffer); you cannot jump around freely.
  • Used when the file's structure is unknown, or when making a copy.
  • All streams (FileInputStream, BufferedReader…) are sequential.

Random access

  • Move to any position in the file and read or write there.
  • Works when the size and position of records are known: record k = k × record size.
  • Handy for reading one record or updating it in place.

Random Access to Records, Step by Step

"rw": the file is created if missing. The pointer is at 0.

Five grades to write.

Each writeInt writes 4 bytes and advances the pointer by 4.

Loop done: 5 × 4 = 20 bytes; the pointer is at the end (20).

length() = 20.

The 3rd record (index 2) starts at byte 8: we jump straight there without reading the others.

readInt() reads bytes 8–11: 90. The pointer moves to 12.

getFilePointer() = 12.

The 4th record also starts at 12; the pointer is already there.

50 replaces 45 in place; the rest of the file is untouched. A sequential stream can't do this.

Back to the start.

Read until the pointer reaches the length: 70 + 85 + 90 + 50 + 60 = 355.

The result is printed; then the file is closed.

import java.io.*;

public class Records {
  public static void main(String[] args) throws IOException {
    RandomAccessFile f = new RandomAccessFile("n.dat", "rw");
    int[] grades = {70, 85, 90, 45, 60};
    for (int n : grades)
      f.writeInt(n);              // 4 bytes each
    System.out.println("Length: " + f.length());
    f.seek(2 * 4);                  // go to record 3
    System.out.println("Grade 3: " + f.readInt());
    System.out.println("Position: " + f.getFilePointer());
    f.seek(3 * 4);                  // record 4
    f.writeInt(50);                 // 50 replaces 45
    f.seek(0);
    int total = 0;
    while (f.getFilePointer() < f.length())
      total += f.readInt();
    System.out.println("Total: " + total);
    f.close();
  }
}

Serialization

Serialization

  • Serialization turns an object's state (its field values) into a byte sequence, so the object can be written to a file or sent over the network. The reverse is deserialization.
  • For its objects to be serializable, a class must implement java.io.Serializable (a marker interface with no methods).
  • Declaring a version ID, serialVersionUID, is recommended; otherwise one is computed from the class structure, and old files become unreadable once the class changes.
  • static fields (they belong to the class) and fields marked transient are not serialized; use this to leave out fields such as passwords.
Uses: game saves, caches, sending objects to another JVM over the network. For long-term or cross-language storage, text formats such as JSON are usually preferred.

Serialization

The Serialization Flow

A Student object lives in memory.

ObjectOutputStream.writeObject turns the object into bytes; the file starts with the magic number AC ED.

ObjectInputStream.readObject builds a new object from the bytes: same values, different object.

public class ChannelRead {
  public static void main(String[] args) throws IOException {
    try (FileChannel channel = FileChannel.open(
        Paths.get("file.txt"), StandardOpenOption.READ)) {
      ByteBuffer buffer = ByteBuffer.allocate(1024);
      // Read from the file

      // Switch to read mode

      // Print the data

        System.out.print((char) buffer.get());
      }
    }
  }
}

NIO: Pros and Cons

Pros

  • Performance: transfers in blocks, more efficiently than classic I/O
  • Flexibility: buffers and channels; two-way channels
  • One approach for both files and the network
  • Many connections: a selector serves many channels from one thread; only active channels are processed

Cons

  • Complexity: harder than classic I/O
  • You must manage buffer state and failures (partial reads, dropped connections)
  • Selectors have a learning curve: tracking many channels' state correctly
Rule of thumb: to read one file line by line, BufferedReader or Files is enough. Channels shine with very large files and many network connections.

NIO Selectors

  • A mechanism for watching many channels from a single thread.
  • Selector.open() creates a new selector.
  • A channel is put in non-blocking mode and registered with the selector: channel.register(selector, ops).
  • SelectionKey constants say which events the channel waits for. select() blocks until at least one channel is ready.
SelectionKeyMeaning
OP_READthe channel can be read
OP_WRITEthe channel can be written
OP_CONNECTconnection established
OP_ACCEPTa connection can be accepted

NIO

A Server with a Selector

public class SelectorDemo {
  public static void main(String[] args) throws IOException {
    ServerSocketChannel server = ServerSocketChannel.open();
    Selector selector = Selector.open();
    server.bind(new InetSocketAddress(8080));
    server.configureBlocking(false);
    server.register(selector, SelectionKey.OP_ACCEPT);
    while (true) {
      int ready = selector.select();
      if (ready > 0) {
        Set<SelectionKey> keys = selector.selectedKeys();
        for (SelectionKey key : keys) {
          if (key.isAcceptable()) {
            // accept a connection
          } else if (key.isReadable()) {
            // read data
          }
        }
        keys.clear(); // drop handled keys
      }
    }
  }
}
  • The server channel binds to port 8080, switches to non-blocking mode and registers for OP_ACCEPT.
  • select() returns the number of ready channels; selectedKeys() gives their keys.
  • Keys not removed with clear() come back on the next round.
  • A real server registers each accepted client for OP_READ and reads its data.

Common Mistakes (1)

Ignoring a checked exceptionerror: unreported exception FileNotFoundException; must be caught or declared to be thrown

new FileReader("a.txt") must sit inside try-catch, or the method must declare throws IOException.

Forgetting the importerror: cannot find symbol symbol: class Scanner

import java.util.Scanner; (and import java.io.*; for I/O classes).

Single backslash in a Windows patherror: illegal escape character new File("C:\courses\notes.txt")

\c and \n count as escape sequences. Write "C:\\courses\\notes.txt" or "C:/courses/notes.txt".

No null check in finallyException in thread "main" java.lang.NullPointerException: Cannot invoke "java.util.Scanner.close()"

If the file can't be opened, scanner stays null. You need if (scanner != null) or try-with-resources.

Common Mistakes (2)

nextLine after nextIntAge: 19⏎ Name: Ayşe⏎ → output: [] 19

nextInt() leaves the newline in the buffer, so the following nextLine() reads an empty line. Add a keyboard.nextLine(); in between.

Not closing a buffered writerbw.write("entry"); // no close note.txt size: 0

The data stays in the buffer and the file looks empty. Call close() (or flush()); better yet, use try-with-resources.

Forgetting flip()b.put((byte) 'J'); b.put((byte) 'A'); b.get() → 0 (empty cell at position 2)

You must flip() between writing and reading; otherwise you read what comes after the data, not the data.

Forgetting Serializablejava.io.NotSerializableException: Car

The class passed to writeObject (and its field types) must implements Serializable.

Storing read() in a bytebyte b; while ((b = (byte) in.read()) != -1)

A byte of value 255 (it becomes −1) is mistaken for end of file. The right type is int.

Writing write(buf)out.write(buf); // stale data in last block

The last block doesn't fill the array; the right call is write(buf, 0, size).
