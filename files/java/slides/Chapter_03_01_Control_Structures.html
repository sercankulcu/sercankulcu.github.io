Introduction

Control Structures

  • Control structures direct a program's flow: which statements run, in what order, how often.
  • Java has three basic control structures; any program can be built from them:
Sequence

Statements run top to bottom, once each.

Decisions

A condition picks one of two (or more) paths: if-else, switch.

Loops

Work repeats while a condition holds: for, while, do-while.

Why it matters: decisions let a program react to different situations and user input; loops automate repetitive work.

Introduction · Step-by-step code trace

Sequential Execution

Code runs top to bottom, line by line; one operation finishes before the next starts. A program with no control structures is sequential.

The first line runs: x gets 5. The next line does not start until this one finishes.

Second line: y gets 10.

The third line uses the results of the first two: 5 + 10 = 15.

The last line prints the result. If the lines were reordered (e.g. line 3 first), the program would not compile.

int x = 5;
int y = 10;
int result = x + y;
System.out.println(result);

Decisions: if

Making Decisions

  • Decision making means the program chooses which path to follow at run time.
  • It lets the program carry out different actions depending on conditions.
  • In Java this is done with if-else and switch-case.
  • A condition is a true- or false-valued boolean expression.
  • Analogy: a sign at a fork in the road. “If it's raining, take an umbrella; otherwise don't.”
  • Why it matters: the program responds to different situations and user input, the flow is steered, and flexibility increases.

Decisions: if

The if-else Statement

if (condition) {
    // runs if the condition is true
} else {
    // runs if the condition is false
}
  • First the condition is evaluated.
  • If the condition is true (true), the if block runs and the else block is skipped.
  • If the condition is false (false), the if block is skipped and the else block runs.
  • The else is optional. Of the two blocks, at most one runs.
  • The condition always goes in parentheses: if (condition).

Decisions: if

if Alone, and Braces

else-less if

int temp = 35;
if (temp > 30) {
    System.out.println("It's hot!");
}
System.out.println("The program continues.");
It's hot!
The program continues.

If the condition were false (e.g. temp = 20), only “The program continues.” would print. After if, the next line always runs.

Pitfall: no braces

int temp = 35;
if (temp > 40)
    System.out.println("Very hot!");
    System.out.println("Drink water.");
Drink water.

Without braces, if owns only the first statement. Indentation means nothing to Java: “Drink water.” runs regardless of the condition. That's why braces { } are used even for one-line blocks.

else-if Chain: Letter Grade

grade = 75.

75 >= 90 → false. On to the next else if.

75 >= 80 → false. On to the next condition.

75 >= 70 → true: the first true condition is found.

“C” is printed.

    System.out.println("B");
} else if (grade >= 70) {
    System.out.println("C");

    System.out.println("D");
} else {
    System.out.println("F");
}

Decisions: if

Nested Decisions

  • Inside the block of one decision you can place another decision.
  • Useful for more complex conditions: once the outer condition holds, a second question is asked.
  • The inner if is tested only if the outer condition is true.
  • Deep nesting hurts readability; indent properly and, where possible, flatten with && or else if: if (age >= 18) { if (hasLicense) … } and if (age >= 18 && hasLicense) … do the same thing.
  • Range checks are also written with &&: grade >= 60 && grade < 90; 60 <= grade < 90 does not compile.
if (cond1) {
    if (cond2) {
        // cond1 AND cond2 true
    }
} else {
    // cond1 false
}

Short-Circuit: Tracing the Code

b = 0: a / b would cause a division-by-zero error (ArithmeticException) if evaluated. count will count whether the right-hand sides run.

&& first evaluates the left side: b != 0 → false.

If the left is false, &&'s result is already false: a / b > 2 is never evaluated, so no error occurs. s1 = false.

||: left side b == 0 → true.

If the left is true, ||'s result is already true: ++count does not run, count stays 0. s2 = true.

Again &&; the left side b == 0 → true. The result is not yet known.

The right side must be evaluated: ++count → 1, 1 > 0 → true. s3 = true.

The three results are printed: false true true.

count = 1: only one of the three right-hand sides ran. Side effects (++) on the right of &&/|| are therefore misleading.

int a = 10, b = 0, count = 0;
boolean s1 = b != 0 && a / b > 2;
boolean s2 = b == 0 || ++count > 0;
boolean s3 = b == 0 && ++count > 0;
System.out.println(s1 + " " + s2 + " " + s3);
System.out.println("count = " + count);

Decisions: switch

The switch-case Statement

  • switch-case compares the value of a variable against a set of constant values and acts according to the match.
  • It is used to choose one path among several options.
  • When the same variable gets many == comparisons, it is tidier than an else if chain.
  • Analogy: elevator buttons. The floor number you press picks where you go.
switch (variable) {  // value being checked
    case value1:     // one value per case
        // statements 1
        break;
    case value2:
        // statements 2
        break;
    // ...
    default:         // if nothing matches
        // default statements (optional)
}

Decisions: switch

How switch-case Works

  • The variable is compared with the case values top to bottom.
  • If a matching case is found, that case's statements run, and then break exits the switch.
  • If no case matches, the default section (if any) runs.
  • default absent as well? Then the switch exits without doing anything.
  • break missing? Execution falls into the next case (fall-through).

Example: Finding the Season

month = 4.

season is declared, with no value yet.

switch (month): the value 4 is computed once, then the case labels are searched.

case 4 matches. The three case labels on that line lead to the same code.

season = "Spring".

break: switch ends; execution jumps past its closing brace (line 18).

default guarantees that season gets a value on every path; without it: variable season might not have been initialized.

int month = 4;
String season;
switch (month) {
    case 3: case 4: case 5:
        season = "Spring";
        break;
    case 6: case 7: case 8:
        season = "Summer";
        break;
    case 9: case 10: case 11:
        season = "Autumn";
        break;
    case 12: case 1: case 2:
        season = "Winter";
        break;
    default:
        season = "Unknown";
}
System.out.println(month + ": " + season);

Decisions: switch · Step-by-step code trace

Forgetting break: Fall-Through

day = 2.

The case matching 2 is searched for.

case 1 is skipped, case 2 matches.

“Tuesday” is printed. There is no break here!

The case 3: label is not a test; execution falls through to the code below.

“Wednesday” is printed too, even though the day is not 3.

break exits the switch; default does not run.

Execution continues after the switch. To avoid fall-through, end every case with break.

int day = 2;
switch (day) {
    case 1:
        System.out.println("Monday");
    case 2:
        System.out.println("Tuesday");
    case 3:
        System.out.println("Wednesday");
        break;
    default:
        System.out.println("Other day");
}
System.out.println("switch done");

String command = "stop";

Decisions: switch

switch Rules

  • The selector (the expression in parentheses) can be: byte, short, char, int (and their wrappers), String, enum.
  • long, float, double, boolean cannot be used with a classic switch.
  • case values must be compile-time constants (5, 'a', "stop", final constants).
  • The same value cannot appear in two cases.
  • Ranges (month >= 3 && month <= 5) or complex conditions need if-else.
double d = 2.5;
switch (d) { ... }
error: selector type double is not allowed
int b = 2;
switch (a) { case b: break; }
error: constant expression required
switch (a) { case 1: break; case 1: break; }
error: duplicate case label

Decisions: switch

The New switch (Java 14+)

int month = 11;
String season = switch (month) {
    case 3, 4, 5 -> "Spring";
    case 6, 7, 8 -> "Summer";
    case 9, 10, 11 -> "Autumn";
    case 12, 1, 2 -> "Winter";
    default -> "Unknown";
};
System.out.println(season);
Autumn
  • Java 14 introduced the arrow form: case 3, 4, 5 -> …
  • A case can take several values separated by commas.
  • The arrow form has no fall-through; no break is needed.
  • A switch expression produces a value that can be assigned directly; it ends with ;.
  • The expression form must cover every possibility: for int, default is required.
  • This course uses the classic form; the arrow form is available from Java 14 on.

Application: Temperature

Temperature Conversion: One Value

public class Program {
    public static void main(String[] args) {
        double celsius = 25.0;
        double fahrenheit = (celsius * 1.8) + 32;
        double kelvin = celsius + 273.15;
        System.out.println(celsius + " °C = " + fahrenheit + " °F = " + kelvin + " K");
    }
}
25.0 °C = 77.0 °F = 298.15 K
  • A sequential program: three lines of computation, one line of output; no decisions or loops.
  • Use double for decimal values. Parentheses make the order explicit: first celsius * 1.8, then + 32.
  • + used with a string performs concatenation; double values print as 25.0.
  • Every computed value should be used: had kelvin not been printed, computing it would have been wasted.

Loops

Loops and Their Kinds

A loop repeats the same operation several times. Analogy: running 10 laps on a track; every lap has the same moves, and the lap counter goes up by one.

for

When the number of repetitions is known; works over a range of values.

for (int i = 0; i < 5; i++) { … }

while

Runs while a condition holds; the number of repetitions may not be known in advance.

while (condition) { … }

do-while

The condition comes last; the body runs at least once.

do { … } while (condition);

  • Loops are handy for processing a data set in order and for repeating work; they matter especially with arrays and lists.
  • One loop instead of writing the same line 100 times: the code becomes shorter, tidier and more readable.

Loops

The for Loop

  • The header sets the loop's init, condition and update (increment) steps on one line, separated by ;.
  • The condition is checked before every pass (iteration); the update step changes the loop variable.
  • Order of execution: 1 → 2 → 4 → 3 → 2 → 4 → 3 → … → 2 false → exit the loop.
  • i = 0, 1, 2, 3, 4: the body runs 5 times; i reaching 5 makes the condition false. i exists only inside the loop.

Loops

How Loops Work

  • The loop starts with the init step.
  • The condition is checked.
    • If it holds, the statements in the loop body run.
    • The update (increment) step is applied (for loops).
    • If the condition still holds, the body runs again.
  • When the condition fails, the loop exits and execution continues with the next statement.
  • If the condition is false on the first check, the body never runs.

1. Init: the loop variable gets its first value (once).

2. The condition is checked.

3. If the condition is true, the body runs.

4. Update: the loop variable changes.

5. Back to the condition; steps 3–4–5 repeat while it is true.

6. When the condition is false, the loop exits.

Summing Numbers (for)

sum starts at 0 (the identity element of addition).

Init: count = 1 (once).

Condition: 1 <= 10 → true.

Pass 1: sum = 0 + 1 = 1.

count++ → 2, condition: 2 <= 10 → true.

Pass 2: sum = 1 + 2 = 3.

count++ → 3, condition: 3 <= 10 → true.

Pass 3: sum = 3 + 3 = 6. The update and condition repeat the same way on every pass.

Pass 4: sum = 6 + 4 = 10.

Pass 5: sum = 10 + 5 = 15.

Pass 6: sum = 15 + 6 = 21.

Pass 7: sum = 21 + 7 = 28.

Pass 8: sum = 28 + 8 = 36.

Pass 9: sum = 36 + 9 = 45.

Pass 10: sum = 45 + 10 = 55.

count++ → 11, condition: 11 <= 10 → false. The loop ends; the body ran exactly 10 times.

After the loop, sum is printed. count no longer exists: it lives only inside the loop.

int sum = 0;
for (int count = 1; count <= 10; count++) {
    sum += count;
}
System.out.println("Sum: " + sum);

Summing a Range

import java.util.Scanner;

public class RangeSum {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        System.out.print("Start value (a): ");
        int a = input.nextInt();
        System.out.print("End value (b): ");
        int b = input.nextInt();
        int sum = 0;
        for (int i = a; i <= b; i++) {
            sum += i;
        }
        System.out.println("Sum of the numbers: " + sum);
    }
}

End value (b): 7
Sum of the numbers: 25

The loop variable i starts not at a fixed number but at the user's input a: 3 + 4 + 5 + 6 + 7 = 25.

Inputs: 7 and 3

Start value (a): 7
End value (b): 3
Sum of the numbers: 0

On the first check 7 <= 3 is false: the body never runs, and the sum stays 0. Fix: if a > b, swap the two first (with an if).

Loops

The while Loop

int i = 0;
while (i < 5) {
    // statements in the loop
    i++;
}
  • Only a condition is checked; init and update are written separately, outside and inside the loop.
  • Runs as long as the condition holds; the condition is tested before the body.
  • The natural choice when the number of repetitions isn't known in advance (e.g. “until the user enters 0”).
  • Beware of infinite loops! i++ missing → i stays 0, the condition stays true and the program never ends.

Loops

for vs. while

for

int sum = 0;
for (int count = 1; count <= 10; count++) {
    sum += count;
}
System.out.println("Sum: " + sum);

while

int sum = 0;
int count = 1;
while (count <= 10) {
    sum += count;
    count++;
}
System.out.println("Sum: " + sum);
Sum: 55

Both loops have the same three parts: init count = 1, condition count <= 10, update count++. for puts them on one line; while scatters them, and the update is easy to forget. Both print 55.

5! = 1 × 2 × 3 × 4 × 5

Goal: 5! = 1 × 2 × 3 × 4 × 5. The product starts at 1 (if it were 0, the result would always be 0).

factorial = 1 × 1 = 1

1 <= 5 → true. factorial *= count: 1 × 1 = 1.

count = 2

count++ → 2. Back to the condition.

factorial = 1 × 2 = 2

2 <= 5 → true. factorial *= count: 1 × 2 = 2.

factorial = 2 × 3 = 6

3 <= 5 → true. factorial *= count: 2 × 3 = 6.

factorial = 6 × 4 = 24

4 <= 5 → true. factorial *= count: 6 × 4 = 24.

factorial = 24 × 5 = 120

5 <= 5 → true. factorial *= count: 24 × 5 = 120.

count = 6

5! = 120

Computing Powers (for)

import java.util.Scanner;

public class Power {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter base and exponent: ");
        int base = sc.nextInt();
        int exp = sc.nextInt();
        long result = 1;
        for (int i = 1; i <= exp; i++) {
            result = result * base;
        }
        System.out.println("Result: " + result);
        System.out.println("Math.pow: " + Math.pow(base, exp));
        sc.close();
    }
}
Enter base and exponent: 3 4
Result: 81
Math.pow: 81.0

Java's built-in Math.pow(base, exp) method does the same job but returns a double (81.0). Our own loop shows how the algorithm works; real programs prefer the library methods.

Loops

The do-while Loop

int i = 0;
do {
    // statements in the loop
    i++;
} while (i < 5);
  • Does the work first, then checks the condition.
  • Repeats while the condition holds.
  • The body runs at least once.
  • while (condition) must be followed by a semicolon.
  • Typical uses: asking again until the user gives a valid value; menus.

Loops

do-while: Input Validation

import java.util.Scanner;

public class DoWhileInput {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);
        int num;
        do {
            System.out.print("Enter a number (1-10): ");
            num = input.nextInt();
        } while (num < 1 || num > 10);
        System.out.println("Accepted number: " + num);
    }
}

Inputs: 15, 0, 7

Enter a number (1-10): 15
Enter a number (1-10): 0
Enter a number (1-10): 7
Accepted number: 7
  • The question must be asked at least once: do-while is made exactly for this.
  • 15 and 0 are out of range: the condition num < 1 || num > 10 is true → ask again.
  • 7 is valid: the condition is false → exit the loop.
  • num is declared before the loop because it is used in the condition and after the loop.

Loops · Step-by-step code trace

Input Validation: Tracing the Code

The user will type 12, −3, 4 in turn. num is declared before the loop; it is used in the condition and after the loop.

The question is asked without checking the condition. nextInt() reads the first input: num = 12.

12 < 1 || 12 > 10: the right side is true → the condition is true, so the question is asked again.

The second input is read: num = -3.

-3 < 1 is true; || skips the right side → the condition is true, again.

Third input: num = 4.

4 < 1 false, 4 > 10 false → the condition is false: the loop exits.

The valid number is accepted. The question was asked 3 times; the loop runs until a valid number arrives.

i = 10

i = 10.

Nested Loops

          
Nested Loops

          

            
    
              
  • A nested loop is a loop inside the body of another loop.
    • 
              
  • Used for more complex work: matrices and multidimensional arrays, tables, patterns.
    • 
              
  • Analogy: a clock. Each time the hour hand (outer loop) moves one step, the minute hand (inner loop) goes all the way round.
    • 
              
  • The total number of passes is a product: 3 outer × 2 inner = 6 runs of the body.
    • 
              
  • The number of nested loops and their conditions affect complexity. Too much nesting leads to complex, slow code: three loops × 1000 passes = 1 billion operations!
    • 
            

            

              
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 2; j++) {
        // nested loop body
    }
}

How Nested Loops Work






Outer loop starts: i = 1, 1 <= 3 → true.


Inner loop starts: j = 1. Body: i = 1, j = 1 is printed.


Body: i = 1, j = 2 is printed.


j = 3 → 3 <= 2 false: the inner loop is done. Back to the outer loop: i++ → 2, 2 <= 3 → true; the inner loop starts over.


Inner loop starts: j = 1. Body: i = 2, j = 1 is printed.


Body: i = 2, j = 2 is printed.


j = 3 → 3 <= 2 false: the inner loop is done. Back to the outer loop: i++ → 3, 3 <= 3 → true; the inner loop starts over.


Inner loop starts: j = 1. Body: i = 3, j = 1 is printed.


Body: i = 3, j = 2 is printed.


j = 3 → 3 <= 2 false: the inner loop is done. i++ → 4, 4 <= 3 false: the outer loop ends too. The body ran 3 × 2 = 6 times.

break in Loops

          
break is used to end a loop: once its condition holds, execution leaves the loop.






i = 1: 1 == 5 false, break is skipped; the step is printed.


i = 2: 2 == 5 false → printed.


i = 3: 3 == 5 false → printed.


i = 4: 4 == 5 false → printed.


i = 5: condition true → break. The loop ends immediately; 5 is not printed and 6–10 are never tried.


Statements after the loop continue. i no longer exists.

Prime Check: A Flag and break




import java.util.Scanner;

public class PrimeCheck {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter a number: ");
        int num = sc.nextInt();
        boolean isPrime = true;            // flag
        if (num < 2) isPrime = false;     // 0 and 1 are not prime
        for (int divisor = 2; divisor <= num / 2; divisor++) {
            if (num % divisor == 0) {      // divides evenly
                isPrime = false;
                break;                    // break out of the loop
            }
        }
        if (isPrime) {
            System.out.println(num + " is prime.");
        } else {
            System.out.println(num + " is not prime.");
        }
        sc.close();
    }
}




Enter a number: 21
21 is not prime.

Enter a number: 97
97 is prime.


Faster: if a number has a divisor, one of them is at most √num. With the condition divisor * divisor <= num, only 8 divisors are tried for 97 instead of 47.

break and continue

          
break vs. continue

          

            
break: ends the loop
The loop ends completely; execution moves to the statement after the loop.

            
continue: skips a pass
The rest of the pass is skipped; the loop goes on with the update and the condition.

          

          
Both are usually used inside an if; they also work in while and do-while; in while, a continue that skips the update can cause an infinite loop.

break ends only the inner loop

              
for (int i = 1; i <= 3; i++) {

outer:
for (int i = 1; i <= 3; i++) {

            break outer;
        }

}

In the left example, for each i only j = 1 is printed and the outer loop goes on. On the right, the outer: label names the outer loop; when i * j == 4 (i = 2, j = 2) break outer; exits both loops at once. Use labels sparingly.

Labeled break: Tracing the Code






The outer: label names the outer loop. i = 1, j = 1: 1 × 1 = 1 ≠ 4, printed.


j = 2: 1 × 2 = 2, printed.


j = 3: 1 × 3 = 3, printed. The inner loop ends; the outer loop moves to i = 2.


i = 2, j = 1: 2 × 1 = 2, printed.


i = 2, j = 2: 2 × 2 = 4 → the condition is true.


break outer; exits not just the inner loop but the labeled outer loop too. The remaining cells are never visited.


Flow jumps past both loops: done is printed. With an unlabeled break, the i = 3 pass would run too.




outer:
for (int i = 1; i <= 3; i++) {
    for (int j = 1; j <= 3; j++) {
        if (i * j == 4) {
            break outer;
        }
        System.out.println(i + " x " + j);
    }
}
System.out.println("done");

Common Mistakes: Decisions

          

            
Comparing with =if (x = 5) → error: incompatible types: int cannot be converted to boolean. Correct: x == 5.

            
Semicolon after ifif (x > 5); { … } compiles, but the ; is an empty statement: the block always runs.

            
Blockless bodyif (c) a(); b(); else c(); → error: 'else' without 'if'. Braces { } are required for more than one statement.

            
Forgetting breakswitch: with no break, the cases below run too (fall-through). The compiler doesn't warn you.

            
Assigning without defaultIf the variable is assigned only in the cases: error: variable season might not have been initialized. Fix: add a default.

            
Dot in decimal inputWith a Turkish locale, nextDouble() given -7.5 → InputMismatchException. -7,5 is what you must type.

          

        


        

          
Summary

          
Common Mistakes: Loops

          

            
Infinite loopwhile: forgetting the update (i++) or updating in the wrong direction (i-- with i <= 10). The compiler won't catch it; the program never stops.

            
; in the loop headerfor (int i = 0; i < 3; i++); or while (i < 5); is a loop with an empty body; the block below doesn't belong to it.

            
Off-by-one errorFor “from 1 to 10”, writing i < 10 skips 10; i = 0 with i <= 10 runs 11 times. Check the first and last pass separately.

            
Using the loop variable outsidefor (int i …) { } followed by println(i) → error: cannot find symbol. If needed, declare i before the loop.

            
Code after breakbreak; System.out.println(i); → error: unreachable statement. break: the line after it can never be reached.

            
Sum/product initial valueA sum starts at 0, a product at 1. factorial = 0 makes the result always 0. Resetting the variable inside the loop is wrong too.
