Kavram

Çok biçimliliği (polymorphism) tanımlamak; derleme zamanı ve çalışma zamanı çok biçimliliğini ayırt etmek.

Referans kuralı

Üst sınıf referansına alt sınıf nesnesi atanabildiğini, tersinin neden derleme hatası verdiğini açıklamak; is-a ilişkisini kullanmak.

Tür dönüşümü

Yukarı ve aşağı dönüşümü (upcasting, downcasting) yazmak; ClassCastException'ı instanceof ile önlemek.

Dinamik bağlama

Çağrılan metodun nesnenin gerçek sınıfına göre seçildiğini adım adım izlemek; metot aramasını hiyerarşide göstermek.

Aşırı yükleme ve ezme

Overloading ile overriding'i karşılaştırmak; hangisinin derleyici, hangisinin JVM tarafından seçildiğini bilmek.

Tasarım

Şekil dizisi, tanksavar oyunu ve toString/equals örnekleriyle üst sınıf türüyle genel kod yazmak.

Çok Biçimlilik Kavramı

Çok Biçimlilik (Polymorphism)

  • Yunanca poly (çok) + morph (biçim): aynı ifadenin, farklı nesnelerde farklı davranışa yol açmasıdır.
  • Bir referans, kendi türündeki veya bir alt sınıfa ait bir nesneye atıfta bulunabilir.
  • hayvan.sesCikar() çağrısı köpek nesnesinde Hav hav!, kedi nesnesinde Miyav! yazdırır.
  • Kodu üst sınıf türüyle bir kez yazarız; her nesne çağrıya kendi sürümüyle cevap verir.
Nesne yönelimli programlamanın dört temel ilkesi: sarmalama, kalıtım, çok biçimlilik ve soyutlama. Çok biçimlilik, kalıtımın üzerine kurulur.
Uzaktan kumandaAynı "aç" düğmesi televizyonu, klimayı ve projektörü açar; her cihaz bunu kendi bildiği gibi yapar.
Sürücü belgesiB sınıfı belgeyle her marka otomobili sürersiniz: "otomobil" arayüzüyle konuşursunuz, motorun ayrıntısı markaya aittir.
Hayvanat bahçesiBakıcı "herkes ses çıkarsın" der; her hayvan kendi sesini çıkarır.

Çok Biçimlilik Kavramı

Bölüm Boyunca Kullanılan Hiyerarşi

  • Boş üçgenli ok kalıtımı (extends) gösterir: ok alt sınıftan üst sınıfa yönelir.
  • Her sınıf, yazmasak da Object'ten türer; toString() ve equals() herkeste vardır.
  • Kopek, sesCikar() ve kos() metotlarını ezer (override), havla() metodunu ekler.
  • Kedi yalnızca sesCikar()'ı ezer ve tirmala()'yı ekler; kos() ve uyu() Hayvan'dan gelir.
Kopek bir Hayvan'dır (is-a); Kedi de bir Hayvan'dır. Bu yüzden ikisi de Hayvan türündeki bir değişkende tutulabilir.

Çok Biçimlilik Kavramı

Sınıfların Kodu

class Hayvan {
    public void sesCikar() {
        System.out.println("Hayvan sesi");
    }

    public void kos() {
        System.out.println("Hayvan koşuyor");
    }

    public void uyu() {
        System.out.println("Hayvan uyuyor");
    }
}
class Kedi extends Hayvan {
    @Override
    public void sesCikar() {
        System.out.println("Miyav!");
    }
    public void tirmala() {
        System.out.println("Kedi tırmalıyor");
    }
}
class Kopek extends Hayvan {
    @Override
    public void sesCikar() {
        System.out.println("Hav hav!");
    }

    @Override
    public void kos() {
        System.out.println("Köpek koşuyor");
    }

    public void havla() {
        System.out.println("Köpek havlıyor");
    }
}

@Override notu (annotation), derleyiciye "bu metot üst sınıftaki bir metodu ezer" der; imza yanlış yazılırsa derleme hatası alınır.

Referanslar ve Tür Uyumu

Referans, Alt Sınıf Nesnesini Gösterebilir

// Köpek nesnesine referans
Kopek kopek = new Kopek();
// Hayvan referansı Kopek'i gösterebilir
Hayvan hayvan = kopek;
// Object referansı da gösterebilir
Object nesne = hayvan;
System.out.println(kopek == hayvan);
System.out.println(hayvan == nesne);
System.out.println(nesne.getClass());

new Kopek() öbekte bir nesne oluşturur; kopek referansı onu gösterir.

Yeni nesne oluşmaz: hayvan, aynı nesneyi gösteren ikinci referanstır. Kopek bir Hayvan olduğu için atama geçerlidir.

Her sınıf Object'ten türediği için Object referansı da aynı nesneyi gösterebilir.

== referansları karşılaştırır: ikisi de aynı nesneyi gösterdiği için true.

Yine aynı nesne: true. Üç referans, tek nesne.

Referansın türü Object olsa da nesnenin gerçek sınıfı değişmez: Kopek.

Nesne Oluşturulurken Yapıcılar Zinciri

class Kopek extends Hayvan {

// main içinde:

new öbekte yer ayırır ve Kopek() yapıcısını çağırır.

Kopek() başlar. İlk satır her zaman super(…) ya da this(…) çağrısıdır.

super(): önce üst sınıfın parçası kurulmalıdır.

Hayvan() çalışır; o da gizli super() ile Object()'i çağırmış ve bitirmiştir.

Hayvan kısmının gövdesi çalışır.

Hayvan() döner; şimdi Kopek()'in kalan gövdesi çalışır.

Nesne tamamlandı; adresi kopek'e atanır. Yapıcılar yukarıdan aşağıya çalıştı.

Referanslar ve Tür Uyumu

Referans Kuralı

  • Bir nesnenin alt türünü, üst sınıf türündeki bir referansa atayabiliriz.
  • Ancak üst sınıfın nesnesini, alt sınıf türündeki bir referansa atayamayız.

Geçerli

// Kopek, Hayvan'ın alt türüdür
Hayvan hayvan = new Kopek();
Object nesne = new Kedi();

Her köpek bir hayvandır: hayvandan beklenen her şeyi köpek de yapabilir.

Hatalı

// Hayvan, Kopek'in üst sınıfıdır
Kopek kopek = new Hayvan();
error: incompatible types:
  Hayvan cannot be converted to Kopek

Bir hayvan havla() bilmeyebilir; derleyici buna izin vermez.

Dikkat: Hayvan h = new Kopek(); Kopek k = h; de aynı hatayı verir. Derleyici h'nin gösterdiği nesneyi değil, bildirilen türünü (Hayvan) görür; çözüm açık dönüşümdür.

Referanslar ve Tür Uyumu

Üst Sınıf ve Alt Sınıf: is-a İlişkisi

  • is-a ilişkisi yalnızca alt sınıftan üst sınıfa doğru geçerlidir.
  • Köpek is a Hayvan: her köpek bir hayvandır.
  • Hayvan is not only a Köpek: her hayvan bir köpek değildir.
  • Bir üst sınıf nesnesi, alt sınıflardan herhangi birinin nesnesi değildir.

Tür Dönüşümü

Aşağı Dönüşüm (Downcasting)

  • Bir üst sınıf referansı, alt sınıf türüne açıkça (explicitly) dönüştürülebilir: (AltSinif) referans.
  • Üst sınıf referansı, ancak bu dönüşümle bir alt sınıf değişkenine atanabilir.
  • Amaç: üst sınıfta bulunmayan (yalnızca alt sınıfa ait) metotları çağırmak.
  • Dönüşüm nesneyi değiştirmez; yalnızca derleyiciye "bu referansı Kopek olarak gör" der.
Hayvan h2 = new Kopek();
Kopek k = (Kopek) h2;
k.havla();
((Kopek) h2).havla(); // tek satırda
Köpek havlıyor
Köpek havlıyor

Öncelik tuzağı

Nokta (.) dönüşümden önce uygulanır. Parantezler unutulursa (Kopek), havla() çağrısının sonucuna uygulanmak istenir:

(Kopek) h2.havla();   // hatalı
error: not a statement
String s = (Kopek) h2.isim();
// h2.isim() önce aranır → Hayvan'da yok
error: cannot find symbol
  symbol:   method isim()
  location: variable h2 of type Hayvan

Doğrusu: ((Kopek) h2).havla();

Tür Dönüşümü

Dikkatli Kullanın: ClassCastException

Hayvan h4 = new Kedi();
Kopek k4 = (Kopek) h4; // derlenir!
k4.havla();
Exception in thread "main" java.lang.ClassCastException:
class Kedi cannot be cast to class Kopek
Kopek k5 = (Kopek) new Hayvan(); // derlenir!
java.lang.ClassCastException:
class Hayvan cannot be cast to class Kopek
  • Derleyici izin verir: Hayvan türündeki bir referans pekâlâ bir Kopek'i gösteriyor olabilir.
  • JVM, dönüşüm anında nesnenin gerçek sınıfını denetler: nesne bir Kedi ya da düz bir Hayvan ise program istisnayla durur.
  • Yani üst sınıf nesnesi, alt sınıf referansına hiçbir zaman atanamaz; dönüşüm yalnızca nesne gerçekten o alt sınıftansa başarılı olur.
B objB = (B) objA; derlenir, ama yalnızca objA gerçekten bir B nesnesini gösteriyorsa çalışır. Emin değilseniz önce instanceof.

İlgisiz türler arasında dönüşümü derleyici hiç kabul etmez: (Kedi) kopek → incompatible types: Kopek cannot be converted to Kedi.

Uzun instanceof zincirleri çoğunlukla bir tasarım uyarısıdır: davranışı alt sınıflarda ezilen bir metoda taşımak daha iyidir (Alıştırma 5).

Dinamik Bağlama

Hatırlatma: Metot Ezme (Overriding)

  • Alt sınıf, üst sınıftan aldığı bir metodu aynı imzayla (ad + parametre listesi) yeniden yazar.
  • Dönüş türü aynı olmalıdır (ya da bir alt türü: kovaryant dönüş).
  • Erişim belirleyici daraltılamaz: public metot public kalmalıdır.
  • private, static ve final metotlar ezilemez.
  • @Override yazmak zorunlu değildir, ama yazım hatalarını derleme anında yakalar.
  • Ezilen sürüme alt sınıfın içinden super.metot() ile ulaşılabilir.
class Kopek extends Hayvan {
    @Override
    public void kos() {
        super.kos(); // Hayvan sürümü
        System.out.println("...ve havlıyor");
    }
}
Ezme ≠ aşırı yüklemeEzme: aynı imza, farklı sınıf. Aşırı yükleme: aynı ad, farklı parametreler.

Dinamik Bağlama

Dinamik Bağlama (Dynamic Binding)

  • Referans bir alt sınıf nesnesini gösteriyorsa, alt sınıfın metodu çağrılır.
  • Çağrılacak sürüm, değişkenin bildirilen türüne göre değil, nesnenin gerçek sınıfına göre belirlenir.
  • Bu seçim derleme sırasında değil, çalışma zamanında yapıldığı için dinamik (geç) bağlama denir.
Hayvan h = new Kopek();
h.kos();      // Kopek sınıfının metodu
h.sesCikar(); // Kopek sınıfının metodu
h.uyu();      // Kopek'te yok → Hayvan'ınki
Köpek koşuyor
Hav hav!
Hayvan uyuyor

h.kos() iki aşamada çözülür

1. Derleme zamanıDerleyici h'nin türüne (Hayvan) bakar: kos() var mı? Var → çağrı derlenir. Yoksa derleme hatası.
2. Çalışma zamanıJVM nesneye bakar: gerçek sınıf Kopek → Kopek.kos() çalışır.
Kural: derleyici "var mı?" diye, JVM "hangisi?" diye sorar.

Dinamik Bağlama

Metot Araması Hiyerarşinin En Altından Başlar

Hayvan h = new Kopek();
h.kos();
h.uyu();
System.out.println(h.toString());
// h.havla(); → derleme hatası

Nesne bir Kopek: aramalar hep en alttan, gerçek sınıftan başlar.

kos() Kopek'te var → arama biter, Kopek sürümü çalışır.

uyu() Kopek'te yok → bir üste çık: Hayvan'da bulundu.

toString() en tepede, Object'te bulunur: sınıf adı + @ + onaltılık karma kod (çalıştırmaya göre değişir).

h.havla() derlenmez: derleyici aramayı referans türü Hayvan'dan yukarı yapar ve bulamaz.

Aşırı Yükleme

Aşırı Yükleme (Overloading)

public class HesapMakinesi {
    public int topla(int sayi1, int sayi2) {
        return sayi1 + sayi2;
    }
    public double topla(double sayi1, double sayi2) {
        return sayi1 + sayi2;
    }
    public int topla(int sayi1, int sayi2, int sayi3) {
        return sayi1 + sayi2 + sayi3;
    }
    // dizinin elemanlarını topla
    public int topla(int[] sayilar) {
        int toplam = 0;
        for (int sayi : sayilar) {
            toplam += sayi;
        }
        return toplam;
    }
}
  • Aynı sınıfta aynı adlı, parametre listesi farklı (sayı, tür, sıra) metotlar.
  • Derleyici argümanlara bakarak derleme zamanında seçer.
  • Yalnızca dönüş türü farklı olan iki metot aşırı yükleme değildir.
HesapMakinesi hm =
        new HesapMakinesi();
int[] sayilar = {1, 2, 3, 4, 5};
int s1 = hm.topla(5, 3);
double s2 = hm.topla(3.5, 2.7);
int s3 = hm.topla(4, 6, 8);
int s4 = hm.topla(sayilar);

Değerler

s1 = 8, s2 = 6.2,
s3 = 18, s4 = 15

Kalıtım ve Çok Biçimlilik

Kalıtım ve Çok Biçimlilik

  • Kalıtım, sınıf hiyerarşileri oluşturmak için gereklidir.
  • Çok biçimlilik için kalıtım gereklidir: bir sınıf hiyerarşisine sahip olmalıyız.
  • Kalıtımı kullanmak için çok biçimlilik gerekli değildir: yalnızca kod yeniden kullanımı için de kalıtım yapılabilir.
  • B sınıfı A'nın alt sınıfıysa, B'nin nesnesi A'nın nesnesi gibi davranabilir (tersi değil).
  • A referansını B referansına atamak için daraltma dönüşümü (casting) gerekir; parantezle yapılır.
A objA = new B(); // B, A gibi davranır
B objB = (B) objA; // geçerli, ancak
                   // dikkatli kullanılmalı
Son satır derlenir; çalışırken objA gerçekten bir B nesnesini göstermiyorsa ClassCastException fırlatılır.

Java'da arayüzler (interface) de çok biçimlilik sağlar: implements eden her sınıf, arayüz türündeki referansa atanabilir.

Kalıtım ve Çok Biçimlilik

Örnek: Şekil Hiyerarşisi

abstract class Sekil {
    private String isim;

    public Sekil(String isim) {
        this.isim = isim;
    }

    public String getIsim() {
        return isim;
    }

    public abstract double alanHesapla();

    public abstract double cevreHesapla();

    public void ciz() {
        System.out.println(isim + " çiziliyor.");
    }
}

abstract: gövdesiz metot; her alt sınıf yazmak zorundadır, new Sekil(…) yapılamaz. Ayrıntılar bir sonraki bölümde.

Kalıtım ve Çok Biçimlilik

Alt Sınıflar Metotları Ezer

class Kare extends Sekil {
    private double kenar;
    public Kare(double kenar) {
        super("Kare");
        this.kenar = kenar;
    }
    @Override
    public double alanHesapla() {
        return kenar * kenar;
    }
    @Override
    public double cevreHesapla() {
        return 4 * kenar;
    }
    @Override
    public void ciz() {
        System.out.println("Kare çiziliyor: kenar " + kenar);
    }
}

Kare: yapıcı super("Kare") ile ismi üst sınıfa verir; üç metodu da ezer.

class Dikdortgen extends Sekil {
    private double genislik;
    private double yukseklik;
    public Dikdortgen(double genislik, double yukseklik) {
        super("Dikdörtgen");
        this.genislik = genislik;
        this.yukseklik = yukseklik;
    }
    @Override
    public double alanHesapla() {
        return genislik * yukseklik;
    }
    @Override
    public double cevreHesapla() {
        return 2 * (genislik + yukseklik);
    }
    // ciz() ezilmedi → Sekil'inki kullanılır
}

Dikdortgen: alan ve çevreyi ezer, ciz()'i ezmez → Sekil.ciz() kullanılır.

class Cember extends Sekil {
    private double yaricap;
    public Cember(double yaricap) {
        super("Çember");
        this.yaricap = yaricap;
    }
    @Override
    public double alanHesapla() {
        return Math.PI * yaricap * yaricap;
    }
    @Override
    public double cevreHesapla() {
        return 2 * Math.PI * yaricap;
    }
    @Override
    public void ciz() {
        System.out.println("Çember çiziliyor: yarıçap " + yaricap);
    }
}

Cember: Math.PI ile hesaplar; ciz()'i kendi bilgisiyle ezer.

Kalıtım ve Çok Biçimlilik

Şekiller Dizisi: Kodu Adım Adım İzle

Sekil[] sekiller = new Sekil[3];
sekiller[0] = new Kare(5);
sekiller[1] = new Dikdortgen(4, 6);
sekiller[2] = new Cember(7);

for (Sekil sekil : sekiller) {
    System.out.println(sekil.getIsim()
        + " alanı: " + sekil.alanHesapla());
    sekil.ciz();
}

Dizi Sekil türünde; elemanlar üç farklı alt sınıf nesnesini gösterir.

sekil.alanHesapla() → Kare.alanHesapla() çalışır.

ciz() ezilmiş → Kare.ciz() çalışır.

sekil.alanHesapla() → Dikdortgen.alanHesapla() çalışır.

Dikdortgen ciz()'i ezmedi → arama yukarı çıkar, Sekil.ciz() çalışır.

sekil.alanHesapla() → Cember.alanHesapla() çalışır.

ciz() ezilmiş → Cember.ciz() çalışır.

Kalıtım ve Çok Biçimlilik

Neden Çok Biçimlilik?

Tür sınayarak

static double alanKotu(Sekil s) {
    double alan;
    if (s instanceof Kare) {
        alan = ((Kare) s).alanHesapla();
    } else if (s instanceof Dikdortgen) {
        alan = ((Dikdortgen) s).alanHesapla();
    } else if (s instanceof Cember) {
        alan = ((Cember) s).alanHesapla();
    } else {
        alan = 0; // yeni tür unutuldu!
    }
    return alan;
}

Yeni bir şekil eklenince bu metot da değişmeli; unutulursa alanKotu(new DikUcgen(3, 4)) sessizce 0.0 döner.

Çok biçimli

static double toplamAlan(Sekil[] dizi) {
    double toplam = 0;
    for (Sekil sekil : dizi) {
        // her nesne kendi alanını
        toplam += sekil.alanHesapla();
    }
    return toplam;
}
  • Yeni DikUcgen extends Sekil sınıfı eklemek yeter; bu kod hiç değişmez.
  • { Kare(5), Dikdortgen(4, 6), DikUcgen(3, 4) } → 55.0
  • Kod kısalır, ClassCastException riski ortadan kalkar.

İlke: genişletmeye açık, değiştirmeye kapalı kod (open/closed principle).

Kalıtım ve Çok Biçimlilik

Örnek: Tanksavar Oyunu

TS Jawelin: TanksavarJawelin, TS Tow2A: TanksavarTow2A. Tank sınıfının da TankT90MS ve TankLeopard2A4 alt sınıfları vardır.

  • Swing ile yazılmış oyunda düşen tanklar vurulur; skor 10'un katı olunca tanksavar türü değişir.
  • Oyun döngüsü yalnızca Tanksavar ve Tank türlerini bilir.
Tanksavar tanksavar = new TanksavarJawelin(x, y);
...
// hangi top? nesneye bağlı (dinamik bağlama)
toplar.add(tanksavar.topAt());
...
if (tanksavar instanceof TanksavarJawelin) {
    tanksavar = new TanksavarTow2A(tanksavar.x, tanksavar.y);
}

Sınama çıktısı

// → Top37mm, yükseklik 30
tanksavar = new TanksavarTow2A(100, 540);
Top t2 = tanksavar.topAt();
// → Top57mm, yükseklik 40
Aynı topAt() çağrısı, tanksavar değişince farklı bir top üretir; oyun kodunda hiçbir if gerekmez.

Kalıtım ve Çok Biçimlilik

Object Metotlarını Ezmek: toString ve equals

public class Kisi {
    private String ad;
    private int yas;
    public Kisi(String ad, int yas) {
        this.ad = ad;
        this.yas = yas;
    }
    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof Kisi)) return false;
        Kisi kisi = (Kisi) obj; // aşağı dönüşüm
        return yas == kisi.yas
            && ad.equals(kisi.ad);
    }

    @Override
    public String toString() {
        return "Kisi[Ad=" + ad
            + ", Yas=" + yas + "]";
    }
}
Kisi k1 = new Kisi("Ali", 25);
Kisi k2 = new Kisi("Ali", 25);
System.out.println(k1 == k2);
System.out.println(k1.equals(k2));
Object nesne = k1;
System.out.println(nesne);
System.out.println(nesne.equals(k2));
false
true
Kisi[Ad=Ali, Yas=25]
true
  • println(nesne), toString()'i çağırır: dinamik bağlamayla Kisi sürümü.
  • equals(Object): önce instanceof, sonra aşağı dönüşüm.
  • equals ezilince hashCode() da ezilmelidir.

İlgili Sayfalar

Java Interfaces (Arayüzler)

Arayüz tanımlama ve implements, arayüz türündeki referanslarla çok biçimlilik, çoklu arayüz kalıtımı, default/static/private arayüz metotları. Sayfa İngilizcedir.

Bu bölümle bağlantısı

Bir sınıf tek bir üst sınıftan türeyebilir, ama birçok arayüzü uygulayabilir: Hayvan h yerine SesCikarabilen s gibi arayüz türleriyle de aynı dinamik bağlama çalışır.

Sık Yapılan Hatalar (2): Çalışma Zamanı ve Mantık

Denetimsiz aşağı dönüşüm

(Kopek) h yazıp h'nin bir Kedi gösterebileceğini unutmak → ClassCastException. Önce instanceof.

"Dönüşüm nesneyi değiştirir" sanmak

(Hayvan) kopek köpeği hayvana çevirmez; sesCikar() yine "Hav hav!" yazar.

Alanların da ezildiğini sanmak

h.tur referans türüne göre okunur ("hayvan"). Alanları private yapıp getter metodu ezin.

Aşırı yüklemeyi ezme sanmak

Alt sınıfta equals(Kisi k) yazmak equals(Object)'i ezmez, aşırı yükler; koleksiyonlar sizin metodunuzu çağırmaz. @Override bu hatayı yakalar.

== ile nesne karşılaştırmak

== referansları karşılaştırır; içerik için ezilmiş equals kullanın.

Her yerde instanceof zinciri

Yeni alt sınıf eklendikçe kırılır. Davranışı ezilen bir metoda taşıyın.

Örnek Problem 1: Çıktı Nedir?

class A {
    void yaz() {
        System.out.println("A.yaz");
    }

    void cagir() {
        yaz(); // this.yaz()
    }
}

class B extends A {
    @Override
    void yaz() {
        System.out.println("B.yaz");
    }
}

// main içinde:
A a = new B();
a.cagir();
new A().cagir();

cagir() yalnızca A'da tanımlı ve içinden yaz()'ı çağırıyor. B ise yalnızca yaz()'ı eziyor. Program ne yazdırır?

Cevap 
B.yaz
A.yaz
  • a.cagir(): B'de cagir yok → A.cagir() çalışır.
  • İçerideki yaz() aslında this.yaz()'dır; this bir B nesnesi → dinamik bağlama ile B.yaz().
  • new A().cagir(): nesne A → A.yaz().
  • Ders: üst sınıfın kodu, alt sınıfın ezdiği metodu farkında olmadan çağırabilir.

Hayvan h = new Kedi();

Örnek Problem 3: Aşırı Yükleme + Ezme

class Ust {
    void f(Object o) {
        System.out.println("Ust.f(Object)");
    }

    void f(String s) {
        System.out.println("Ust.f(String)");
    }
}

class Alt extends Ust {
    @Override
    void f(Object o) {
        System.out.println("Alt.f(Object)");
    }
}

// main içinde:
Ust u = new Alt();
Object o = "merhaba";
u.f(o);
u.f("merhaba");

Ust'te iki aşırı yüklenmiş f var; Alt yalnızca f(Object)'i eziyor. İki çağrı ne yazdırır?

Cevap 
Alt.f(Object)
Ust.f(String)
  1. Derleyici sürümü seçer: o'nun bildirilen türü Object → f(Object). Çalışırken nesne Alt → ezilmiş sürüm: Alt.f(Object).
  2. Argüman String → en uygun sürüm f(String). Alt bunu ezmediği için Ust.f(String).

Önce aşırı yükleme (derleme zamanı, bildirilen tür), sonra ezme (çalışma zamanı, nesne türü).

Alıştırmalar (1)

  1. Calisan (maas() = temel maaş), Mudur (temel × 1,5) ve Stajyer (sabit 5000) sınıflarını yazın. Calisan[] = { Ayşe 20000, Müdür Mehmet 30000, Stajyer Can } için toplam maaş?
  2. X: ad() → "X", yaz() → println(ad()). Y extends X: ad() → "Y". Z extends Y: yaz() → println("Z:" + ad()). { new X(), new Y(), new Z() } için her birinde yaz() çağrılırsa çıktı?
  3. Object o = new Kopek(); ardından o.sesCikar(); neden derlenmez? Nasıl düzeltilir, düzeltilince ne yazar?
Cevaplar / ipuçları
  1. Mudur.maas(), return temelMaas * 1.5; ile ezilir; döngüde toplam += c.maas(); → 20000 + 45000 + 5000 = 70000.0.
  2. X, Y, Z:Y. Y'de yaz() X'ten gelir ama içindeki ad() Y'ninkidir; Z'de ad() Y'den gelir.
  3. Object'te sesCikar() yok (cannot find symbol). ((Hayvan) o).sesCikar(); → Hav hav!

Alıştırmalar (2)

  1. Şekil hiyerarşisine DikUcgen(a, b) ekleyin (alan = a·b/2, çevre = a + b + hipotenüs). DikUcgen(3, 4) için alan, çevre ve ciz() çıktıları nedir? Şekil döngüsünde ne değişir?
