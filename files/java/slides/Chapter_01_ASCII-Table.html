ASCII Table

    
Browse character codes from 0 to 255, search by decimal value, hexadecimal value (0x41) or displayed character, and compare the standard ASCII range with two common 8-bit extensions.

    
How to use

    
    
      
  • 0–127 / 128–255 switches the half of the table that is shown; the column header is the low hex digit, the row header the high hex digit (row 4_, column 1 → 0x41 = 65 = 'A').
    • 
      
  • Click a cell, or move with the arrow keys (Home / End jump to the first / last cell). The right panel shows the code in decimal, hexadecimal, octal and binary, its Unicode code point, its UTF-8 bytes and the Java char literal.
    • 
      
  • Typing in the search box dims the cells that do not match; Enter selects the first match.
    • 
    

    
Encodings

    
    
      
  • Codes 0–127 are standard ASCII: 0–31 and 127 are control characters (e.g. 9 TAB '\t', 10 LF '\n', 13 CR '\r'), 32 is the space.
    • 
      
  • Codes 128–255 are not part of ASCII itself. In ISO-8859-1 byte n is exactly the Unicode code point U+00nn, so this view is also the first 256 Unicode code points (128–159 are C1 control characters).
    • 
      
  • Windows-1254 is the Turkish code page: it places Ğ ğ İ ı Ş ş at 208, 240, 221, 253, 222, 254 and uses 128–159 for printable symbols such as € and “ ”. Cells that differ from ISO-8859-1 are shaded; five codes are undefined. Here the Java char value differs from the byte: byte 208 decodes to 'Ğ' = U+011E = 286.
    • 
      
  • A Java char is a 16-bit UTF-16 code unit, so (int) 'A' is 65 and (char) 65 is 'A'. In UTF-8, codes 0–127 take one byte, the rest of this table two or three bytes.
    • 
    

    
The Windows-1254 mapping and the UTF-8 bytes were generated with Java (new String(bytes, "windows-1254"), getBytes("UTF-8")).
