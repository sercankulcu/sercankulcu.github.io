Giriş

Öğrenme Çıktıları

Kavram

Özyinelemeyi (recursion), temel durumu ve özyinelemeli adımı tanımlamak; bir problemi kendisinin küçük bir kopyasına indirgemek.

Çalışma biçimi

Çağrı yığınında çerçevelerin nasıl biriktiğini ve geri döndüğünü adım adım izlemek; çağrı ağacı çizmek.

Yazma

Faktöriyel, toplam, seri, rakamlar toplamı, palindrom, EBOB ve Hanoi kuleleri için özyinelemeli Java metotları yazmak.

Hatalar

Sonsuz özyinelemeyi, StackOverflowError'ı ve eksik return hatalarını tanımak ve önlemek.

Verimlilik

Özyinelemeli ve ilerlemeli (iterative) çözümleri karşılaştırmak; gerektiğinde döngüye çevirmek.

İleri teknikler

Kuyruk özyinelemesini ve hafızalamayı (memoization) açıklamak; tekrarlanan hesaplamaları ortadan kaldırmak.

Özyineleme Kavramı

Özyineleme Nedir?

  • Özyineleme (Recursion): bir metodun, görevini küçük parçalara bölerek kendini çağırmasıdır.
  • Her çağrı, problemin daha küçük ama aynı türden bir kopyasını çözer; en küçük kopya doğrudan çözülür.
  • Tekrarlama süreci kendini benzer biçimde tekrar eder: bir yapının içinde aynı türden bir yapı bulunur.
  • Bazı problemleri (ağaçlar, seriler, böl ve yönet) döngülerden daha anlaşılır ve temiz çözer.
Java'da özyineleme için özel bir anahtar kelime yoktur: metot, gövdesinde kendi adını çağırır.
Matruşka bebekleriHer bebeğin içinde daha küçük bir bebek vardır; en küçüğü açılmaz (temel durum).
Sinemada kaçıncı sıra?Öndekine sorarsınız, o da öndekine… İlk sıradaki "1" der; cevaplar geri gelirken her kişi 1 ekler.
Karşılıklı aynalarGörüntünün içinde görüntü: temel durumu olmayan özyineleme sonsuza gider.

Özyineleme Kavramı

Temel Durum ve Özyinelemeli Adım

1. Temel durum (base case)Cevabı doğrudan bilinen en küçük problem. Burada metot kendini çağırmaz ve özyineleme durur. Örn. 1! = 1.
2. Özyinelemeli adım (recursive step)Problemi bir adım küçültüp kendine sorar, gelen cevabı kullanarak kendi cevabını kurar. Örn. 4! = 4 × 3!.

Matematikteki tümevarımsal tanımın birebir karşılığıdır:
n! = 1 (n ≤ 1 ise),   n! = n × (n − 1)! (n > 1 ise)

Özyineleme Kavramı

Çağrı Yığını

  • Her metot çağrısı için bellekte bir çerçeve (stack frame) açılır: parametreler, yerel değişkenler ve dönülecek yer burada tutulur.
  • Çerçeveler çağrı yığınına (call stack) üst üste konur; yalnızca tepedeki çerçeve çalışır, alttakiler bekler.
  • Özyinelemede aynı metodun birden çok çerçevesi aynı anda yaşar; her birinin kendi n'si vardır.
  • Metot return ettiğinde çerçevesi silinir ve değer, bir alttaki çerçeveye iletilir (son giren ilk çıkar: LIFO).
  • Yığının boyutu sınırlıdır; çok derin özyineleme StackOverflowError ile biter.

Faktöriyel ve Toplam

Faktöriyel Alma

int faktoriyel(int n) {
    if (n == 0 || n == 1) {
        return 1;   // temel durum
    } else {
        return n * faktoriyel(n - 1); // özyineleme
    }
}
Matematikn! = 1 × 2 × … × n
n! = n × (n − 1)!,  0! = 1! = 1
Satır 2–3: temel durum0! = 1! = 1; burada özyineleme durur.
Satır 5: özyinelemeli adımn!, (n − 1)!'in n ile çarpımıdır.
İlerlemeHer çağrıda n 1 azalır → n ≥ 0 için temel duruma mutlaka ulaşılır.
Taşmaint 13!'i taşıyamaz: faktoriyel(13) = 1932053504 (yanlış!). long 20!'e kadar yeter.

Çağrı: faktoriyel(5) → 120 · faktoriyel(0) → 1

Faktöriyel ve Toplam

faktoriyel(4) Açılımı

faktoriyel(4)
  = 4 * faktoriyel(3)
  = 4 * (3 * faktoriyel(2))
  = 4 * (3 * (2 * faktoriyel(1)))
  = 4 * (3 * (2 * 1))
  = 4 * (3 * 2)
  = 4 * 6
  = 24
İniş (çağrılar)İlk dört satırda her çağrı yeni bir çağrı açar; çarpımlar bekletilir, çünkü sağ taraftaki değer henüz bilinmiyor.
Dip (temel durum)faktoriyel(1) doğrudan 1 döndürür. Kod n == 1'de durduğu için faktoriyel(0) hiç çağrılmaz.
Çıkış (dönüşler)Bekleyen çarpımlar içten dışa doğru tamamlanır: 2 × 1, 3 × 2, 4 × 6.

faktoriyel(4): Kodu Adım Adım İzle

main, faktoriyel(4) çağrısını yapar; sonucu yazdırmak için beklemeye başlar.

Yeni çerçeve: n = 4. Koşul n == 0 || n == 1 yanlış → temel durum değil.

4 * faktoriyel(3) hesaplanmalı. Çarpım bekler; önce faktoriyel(3) çağrılır.

Yeni çerçeve: n = 3. Koşul n == 0 || n == 1 yanlış → temel durum değil.

3 * faktoriyel(2) hesaplanmalı. Çarpım bekler; önce faktoriyel(2) çağrılır.

Yeni çerçeve: n = 2. Koşul n == 0 || n == 1 yanlış → temel durum değil.

2 * faktoriyel(1) hesaplanmalı. Çarpım bekler; önce faktoriyel(1) çağrılır.

n = 1: temel durum. Yeni çağrı yapılmaz, 1 döndürülür. Artık çerçeveler geri dönmeye başlar.

faktoriyel(1) çerçevesi yığından çıktı, 1 getirdi: 2 * 1 = 2 döner.

faktoriyel(2) çerçevesi yığından çıktı, 2 getirdi: 3 * 2 = 6 döner.

faktoriyel(3) çerçevesi yığından çıktı, 6 getirdi: 4 * 6 = 24 döner.

24 main'e döndü ve yazdırıldı. 4 çağrı yapıldı; en derin anda yığında 5 çerçeve vardı.

static int faktoriyel(int n) {
    if (n == 0 || n == 1) {
        return 1;
    } else {
        return n * faktoriyel(n - 1);
    }
}

public static void main(String[] args) {
    System.out.println(faktoriyel(4));
}

Faktöriyel ve Toplam

Toplam Bulma

int toplam(int n) {
    if (n == 1) {
        return 1;
    } else {
        return n + toplam(n - 1);
    }
}

1'den n'ye kadar sayıların toplamı: toplam(n) = n + toplam(n − 1), toplam(1) = 1.

toplam(5) = 5 + toplam(4)
          = 5 + (4 + (3 + (2 + toplam(1))))
          = 5 + (4 + (3 + (2 + 1)))
          = 15

Faktöriyelle aynı kalıp; yalnızca × yerine + ve temel durum farklı. toplam(100) = 5050.

Dikkat: temel durum yalnızca n == 1. toplam(0) ya da negatif bir sayı çağrılırsa n hiç 1 olmaz: 0, −1, −2, … sonsuz özyineleme → StackOverflowError.

Güvenli sürüm: temel durumu if (n <= 0) return 0; yapın; tüm geçersiz girdiler de yakalanır.

Seriler

Fibonacci Serisi

  • 0 ile başlar, ardından 1 gelir: F(0) = 0, F(1) = 1.
  • Genel formül: F(n) = F(n − 1) + F(n − 2): her terim önceki iki terimin toplamı.
  • Metot kendini iki kez çağırır: çağrılar bir ağaç oluşturur (ağaç özyinelemesi).
int fibonacci(int n) {
    if (n <= 1) {
        return n;
    } else {
        return fibonacci(n - 1) + fibonacci(n - 2);
    }
}

Tavşan çoğalması problemiyle tanınır (Leonardo Fibonacci, 1202). Ardışık terimlerin oranı altın orana (≈ 1,618) yaklaşır: 144 / 89 ≈ 1,618.

Lucas Serisi

  • 2 ile başlar, ardından 1 gelir: L(0) = 2, L(1) = 1.
  • Genel formül Fibonacci ile aynı: L(n) = L(n − 1) + L(n − 2).
  • Yalnızca başlangıç değerleri farklıdır → iki ayrı temel durum gerekir.
int lucas(int n) {
    if (n == 0) {
        return 2;
    } else if (n == 1) {
        return 1;
    } else {
        return lucas(n - 1) + lucas(n - 2);
    }
}
n012345
L(n)2134711

L(n)18294776123

İki seri birbirine bağlıdır: L(n) = F(n − 1) + F(n + 1). Örn. L(5) = F(4) + F(6) = 3 + 8 = 11.

Seriler

Catalan Serisi

  • 1 ile başlar: C(0) = 1, C(1) = 1.
  • Kapalı formül: C(n) = (2n)! / ((n + 1)! · n!).
  • Kodun kullandığı özyinelemeli formül: C(n) = Σ C(i) · C(n − 1 − i), i = 0 … n − 1.
  • Özyineleme bir döngünün içinde yapılır: her C(n), daha küçük tüm C değerlerinden kurulur.
long catalan(int n) {
    if (n <= 1) {
        return 1;
    }
    long sonuc = 0;
    for (int i = 0; i < n; i++) {
        sonuc += catalan(i) * catalan(n - i - 1);
    }
    return sonuc;
}

Bell Serisi

  • 1 ile başlar: B(0) = 1, B(1) = 1.
  • Genel formül: B(n) = Σ C(n − 1, k) · B(k), k = 0 … n − 1; burada C(n, k) kombinasyondur.
int bell(int n) {
    if (n == 0) { return 1; }
    int sayi = 0;
    for (int k = 0; k < n; k++) {
        sayi += katsayi(n - 1, k) * bell(k);
    }
    return sayi;
}

int katsayi(int n, int k) {       // C(n, k)
    return faktoriyel(n) / (faktoriyel(k) * faktoriyel(n - k));
}

Değerler:

11251552203877

Ne sayar? n elemanlı bir kümeyi gruplara ayırma yollarını. {a, b, c} → B(3) = 5:

abca|bcb|acc|aba|b|c
katsayi, int döndüren faktoriyel'i kullanır; 13! taşar. Bu yüzden kod yalnızca n ≤ 13 için doğrudur.

Özyinelemeli Metot Yazma

İki Temel Kural

Kural 1: Temel durum (Base Case)

Sonsuz özyinelemeye girmemek için en az bir temel duruma ihtiyaç vardır. Örneğin n sayısı 0 veya 1 olduğunda metot kendini çağırmadan sonlanmalıdır.

Kural 2: İlerleme sağlama

Her özyinelemeli çağrı temel duruma doğru ilerlemelidir: parametre her çağrıda azaltılır (ya da artırılır), dizgi kısalır, aralık daralır.

  • Sonsuz özyineleme (temel durum yok ya da hiç ulaşılamıyor) ve yetersiz ilerleme (parametre değişmiyor) gibi hatalardan kaçının.
  • Her özyinelemeli çağrı problemin daha küçük bir alt kümesine odaklanmalıdır.
  • Temel durumu her zaman özyinelemeli çağrıdan önce kontrol edin.
  • Tüm olası girdileri düşünün: negatif sayı, 0, boş dizgi temel duruma ulaşıyor mu?

Çözüm: temel durumu genişletin (n <= 1), girdiyi kontrol edin ya da derinliği çok büyük olan problemler için döngü kullanın.

Özyinelemeli Metot Yazma

Özyinelemeli Düşünme

  1. Küçült: problemi kendisinin daha küçük bir kopyası cinsinden ifade et.
  2. Temel durumu bul: cevabı doğrudan bilinen en küçük girdi.
  3. Güven: küçük kopyanın doğru çözüldüğünü varsay (inanç sıçraması, leap of faith); çağrının içini kafanda açma.
  4. Birleştir: küçük cevaptan büyük cevabı kur.

Örnek: bir sayının basamak sayısı.

  • 48729'un basamak sayısı = 1 + 4872'nin basamak sayısı.
  • Tek basamaklı sayı (n < 10) → 1.
int basamakSayisi(int n) {
    if (n < 10) {                       // temel durum
        return 1;
    }
    return 1 + basamakSayisi(n / 10);   // küçült + birleştir
}

basamakSayisi(48729) → 5 · basamakSayisi(7) → 1

Rakamlar Toplamı

int rakamlarToplami(int n) {
    if (n < 0) {
        return rakamlarToplami(-n);
    } else if (n < 10) {
        return n;
    } else {
        return rakamlarToplami(n / 10) + (n % 10);
    }
}
  • Negatif sayı önce pozitife çevrilir (satır 2–3).
  • Tek basamaklı sayı kendisidir: temel durum (satır 4–5).
  • Aksi halde: son basamak + kalan basamakların toplamı.

n / 10 tam sayı bölmesi son basamağı atar; n % 10 son basamağı verir. Her çağrıda sayı bir basamak kısalır → ilerleme garantilidir.

Örnekler

rakamlarToplami(-48729) Açılımı

rakamlarToplami(-48729)
  = rakamlarToplami(48729)
  = rakamlarToplami(4872) + 9
  = (rakamlarToplami(487) + 2) + 9
  = ((rakamlarToplami(48) + 7) + 2) + 9
  = (((rakamlarToplami(4) + 8) + 7) + 2) + 9
  = (((4 + 8) + 7) + 2) + 9
  = ((12 + 7) + 2) + 9
  = (19 + 2) + 9
  = 21 + 9
  = 30

İlk çağrı işareti düzeltir; sonra her adımda son basamak (9, 2, 7, 8) bekleyen toplama olarak dışarıda kalır.

Temel durum rakamlarToplami(4) → 4. Dönüşte toplamlar içten dışa yapılır: 4 + 8 + 7 + 2 + 9 = 30.

Toplam 6 çağrı yapılır (1 işaret + 5 basamak).

Palindrom Kontrolü

static boolean palindromMu(String s) {
    if (s.length() <= 1) {
        return true;
    } else if (s.charAt(0) == s.charAt(s.length() - 1)) {
        return palindromMu(s.substring(1, s.length() - 1));
    }
    return false;
}

palindromMu("kayak") → true · palindromMu("abba") → true · palindromMu("java") → false

  • Palindrom: tersten okunuşu aynı olan dizgi (kayak, ey edip adanada pide ye).
  • s.charAt(i): i. karakter (0'dan başlar).
  • s.substring(1, s.length() - 1): ilk ve son harfi atılmış dizgi.
  • İki temel durum: uzunluk ≤ 1 → true; uçlar farklı → false.
  • Büyük-küçük harfe duyarlıdır: "Kayak" → false.

Örnekler · Kodu adım adım çalıştır

s = "racecar": uzunluk 7 > 1. İlk harf 'r' ile son harf 'r' karşılaştırılır → eşit.

Uçlar eşleşti; iç kısım s.substring(1, 6) = "aceca" için yeni çağrı yapılır.

s = "aceca": uzunluk 5 > 1. İlk harf 'a' ile son harf 'a' karşılaştırılır → eşit.

Uçlar eşleşti; iç kısım s.substring(1, 4) = "cec" için yeni çağrı yapılır.

s = "cec": uzunluk 3 > 1. İlk harf 'c' ile son harf 'c' karşılaştırılır → eşit.

Uçlar eşleşti; iç kısım s.substring(1, 2) = "e" için yeni çağrı yapılır.

Uzunluk 1 ≤ 1 → temel durum: tek harfli dizgi palindromdur, true döner.

palindromMu("cec") çerçevesi true aldı ve aynen true döndürür.

palindromMu("aceca") çerçevesi true aldı ve aynen true döndürür.

palindromMu("racecar") çerçevesi true aldı ve aynen true döndürür. Sonuç: "racecar" bir palindromdur.

En Büyük Ortak Bölen

static int gcd(int x, int y) {
    if (y == 0) {
        return x;
    }
    return gcd(y, x % y);
}
  • Öklid algoritması: EBOB(x, y) = EBOB(y, x mod y).
  • Temel durum: y = 0 ise EBOB = x.
  • Kalan her adımda küçülür → mutlaka 0'a ulaşır.
  • gcd(93, 444): ilk adım gcd(444, 93) olur; sıra önemsizdir.
gcd(444, 93)
  = gcd(93, 72)     // 444 % 93 = 72
  = gcd(72, 21)     // 93 % 72 = 21
  = gcd(21, 9)      // 72 % 21 = 9
  = gcd(9, 3)       // 21 % 9 = 3
  = gcd(3, 0)       // 9 % 3 = 0
  = 3

gcd (greatest common divisor) = EBOB. gcd(48, 18) → 6.

Örnekler

Hanoi Kuleleri

Üç çubuk (A, B, C) ve A'da büyükten küçüğe dizili n disk var. Hepsi C'ye taşınacak:

  • Her hamlede yalnızca bir disk, en üstteki taşınır.
  • Büyük disk asla küçük diskin üstüne konmaz.

Özyinelemeli fikir: üstteki n − 1 diski yardımcıya taşı, en büyüğü hedefe taşı, n − 1 diski yardımcıdan hedefe taşı.

Hamle sayısı 2ⁿ − 1: 3 disk → 7, 10 disk → 1023, 64 disk → yaklaşık 1,8 × 10¹⁹.

public class HanoiKuleleri {
    static void coz(int n, char kaynak,
                    char hedef, char yardimci) {
        if (n == 1) {   // tek disk: doğrudan taşı
            System.out.println(n + ": " + kaynak + "->" + hedef);
        } else {
            coz(n - 1, kaynak, yardimci, hedef);
            System.out.println(n + ": " + kaynak + "->" + hedef);
            coz(n - 1, yardimci, hedef, kaynak);
        }
    }
    public static void main(String[] args) {
        coz(3, 'A', 'C', 'B');
    }
}

Döngüyle yazması zor olan bu problem, özyinelemeyle birkaç satırdır.

Verimlilik

Verimlilik (Efficiency)

  • Özyinelemeli metotlar bazen yavaş çalışabilir: her çağrının bir maliyeti (çerçeve açma, parametre kopyalama) vardır.
  • Özyinelemeli çağrılar yapıldıkça sistem, bekleyen kısmi sonuçları çağrı yığınında biriktirir.
  • Yığın aşırı dolarsa program StackOverflowError (bellek taşması) ile sonlanır.
  • Sorunlu durumlarda çözüm, döngülerle çalışan ilerlemeli (iterative) çözümlerdir.
  • İlerlemeli çözümler kısmi sonuçları biriktirmez: tek bir çerçeve ve birkaç değişken yeter.
Bellekfaktoriyel(n) özyinelemeli: n çerçeve, O(n) bellek. Döngüyle: O(1).
Derinlik sınırıVarsayılan yığınla birkaç on bin çağrı derinliğinden sonra StackOverflowError alınır.
TekrarAğaç özyinelemesi (Fibonacci) aynı değerleri defalarca hesaplayabilir.

Kuyruk Özyinelemesi

Kuyruk Özyinelemesi (Tail Recursion)

  • Metodun son işlemi özyinelemeli çağrının kendisidir; dönüşte yapılacak iş kalmaz.
  • Sonuç, ek bir biriktirici (accumulator) parametrede taşınır.
  • Bu biçim, derleyicinin kuyruk çağrısı optimizasyonu (TCO) yapmasını mümkün kılar: çağrı bir döngü gibi işlenir, çerçeveler yığılmaz → bellek verimliliği.
  • Java (JVM) bu optimizasyonu yapmaz: kuyruk özyinelemeli Java kodu yine O(n) yığın kullanır. Scheme, Scala (@tailrec), Kotlin (tailrec) gibi dillerde yapılır.

Kuyruk özyinelemeli değil

return n * faktoriyel(n - 1);
// çağrı döndükten SONRA çarpma var

Kuyruk özyinelemeli

return faktoriyel(n - 1, n * birikim);
// çarpma çağrıdan ÖNCE; son iş çağrı

Kuyruk Özyinelemeli Örnekler

int rakamlarToplami(int sayi, int toplam) {
    if (sayi == 0) {
        return toplam;

                               toplam + sayi % 10);

Hafızalama

Hafızalama (Memoization)

  • Tekrarlanan hesaplamaların sonuçlarını saklayıp yeniden kullanma yöntemidir (durum bilgisi taşıma).
  • Sonuçlar bir önbelleğe (Map) alınır; aynı argüman tekrar gelince hesaplamadan döndürülür.
  • Her n için hesap bir kez yapılır: üstel çağrı sayısı doğrusala iner.
  • Map<Integer, Long>: anahtar n, değer F(n).

fibonacci(90) → 2880067194370816120 (anında).

import java.util.HashMap;
import java.util.Map;

static Map<Integer, Long> hafiza = new HashMap<>();

static long fibonacci(int n) {
    if (hafiza.containsKey(n)) {
        return hafiza.get(n);    // daha önce hesaplandı
    }
    if (n == 0 || n == 1) {
        return n;
    }
    long sonuc = fibonacci(n - 1) + fibonacci(n - 2);
    hafiza.put(n, sonuc);        // sonucu sakla
    return sonuc;
}
