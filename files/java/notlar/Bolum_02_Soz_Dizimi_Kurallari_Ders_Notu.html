Bölüm 2.2: Söz Dizimi Kuralları

Bir Java programı derleyiciye bir metin olarak verilir. Derleyici bu metni harf harf okur ve dilin kurallarına uyup uymadığına bakar. Tek bir noktalı virgül eksikse ya da bir harf büyük yerine küçük yazılmışsa program çalışmaz. Bu not, Java'nın yazım kurallarını ve bu kuralların arkasındaki çalışma düzenini anlatır. İlk kesim bir .java dosyasının javac ile bytecode'a, java komutuyla da çalışan bir programa dönüşmesini izler. JVM'in yığın üzerinde nasıl çalıştığı ve aynı .class dosyasının neden her işletim sisteminde çalıştığı burada açıklanır. Ardından değişkenler, sekiz ilkel tip ve bu tiplerin sınırları gelir. Tanımlayıcılar, anahtar kelimeler ve isimlendirme kuralları adların nasıl seçileceğini belirler. Atama, sabit değerler ve tip dönüşümü kesimi, sayıların bir tipten ötekine geçerken nasıl değiştiğini gösterir. Son kesimler operatörleri, işlem önceliğini, kısa devre değerlendirmeyi, üçlü operatörü ve kontrol deyimlerinin söz dizimini işler. Her kesimde sunumdaki kodlar satır satır anlatılır ve derleyicinin gerçek hata iletileri verilir.

2.2.1Derleme ve çalıştırma

Java ile yazılan bir program, ekranda bir sonuç görünene kadar birkaç aşamadan geçer. Programcı kodu bir metin dosyasına yazar. Derleyici bu metni denetler ve ara bir koda çevirir. Java Sanal Makinesi ara kodu alır ve bilgisayarın işlemcisinde yürütür. Bu kesim aşamaları sırayla ele alır. Hata iletilerini doğru okumak ve “Çalıştır” düğmesinin arkasında ne olduğunu bilmek, ancak bu zinciri tanıyınca mümkündür.

2.2.1.1Kaynak kod dosyası

Tanım 2.2.1

Kaynak kod (source code), programcının bir programlama dilinin kurallarına göre yazdığı, insanın okuyabildiği program metnidir. Java kaynak kodu düz metin (plain text) dosyalarında durur ve bu dosyaların uzantısı .java'dır.

Düz metin, yalnız karakterlerden oluşan bir dosyadır. İçinde yazı tipi, renk, kalın yazı ya da sayfa düzeni bilgisi yoktur. Word gibi bir kelime işlemcinin kaydettiği belge ise metnin yanında bu biçim bilgilerini de saklar. Derleyici bu ek bilgiyi anlamaz. Bu yüzden Java kodu Not Defteri, Notepad++ ya da VS Code gibi bir metin düzenleyiciyle ya da bir geliştirme ortamıyla yazılır.

Düz metin üç açıdan elverişlidir:

  • Okunaklıdır. İnsan dosyayı açınca doğrudan kodu görür. Kod kolayca anlaşılır, e-postayla gönderilir, bir sürüm denetim sisteminde saklanır.
  • Taşınabilirdir. Aynı .java dosyası her işletim sisteminde ve her geliştirme ortamında açılır.
  • Kolay düzeltilir. Bir hatayı düzeltmek ya da kodu güncellemek için herhangi bir metin düzenleyici yeterlidir.

Java bir dosya adı kuralı da koyar. Bir dosyada public bir sınıf varsa dosyanın adı sınıfın adıyla birebir aynı olmalıdır. public class MerhabaDunya diye başlayan bir kod MerhabaDunya.java adlı dosyaya kaydedilir. Bu eşleşmede büyük ve küçük harf de önemlidir. Aynı kod merhabadunya.java adıyla kaydedilirse derleyici şu iletiyi verir:

merhabadunya.java:1: error: class MerhabaDunya is public, should be declared in a file named MerhabaDunya.java
public class MerhabaDunya {
       ^
1 error

Windows'un dosya sistemi büyük ve küçük harfi ayırmasa da javac ayırır. İleti tam olarak neyin yanlış olduğunu söyler: MerhabaDunya sınıfı public'tir ve MerhabaDunya.java adlı bir dosyada bildirilmelidir.

2.2.1.3İlk program: MerhabaDunya

Aşağıdaki program, Java'da yazılabilecek en kısa tam programlardan biridir. Ekrana tek bir satır yazar.

public class MerhabaDunya {
    public static void main(String[] args) {
        System.out.println("Merhaba, Dünya!");
    }
}

Kısa olmasına karşın programın her parçası bir kurala bağlıdır:

  • public class MerhabaDunya bir sınıf tanımlar. Her Java programı en az bir sınıf içerir. Sınıfın gövdesi, bu satırdaki { ile son satırdaki } arasında kalan kısımdır. Sınıf public olduğu için dosyanın adı MerhabaDunya.java olmalıdır.
  • public static void main(String[] args) programın giriş noktasıdır. JVM programı başlatınca çalışmaya bu metottan başlar. Başlığın yazımı birebir böyle olmalıdır. Main ya da main(String args) yazılırsa program derlenir, ama JVM giriş noktasını bulamaz ve çalıştırmayı reddeder.
  • System.out.println(...) parantez içindeki değeri konsola yazar ve alt satıra geçer. Metinler çift tırnak içinde yazılır: "Merhaba, Dünya!".
  • Satırın sonundaki noktalı virgül, deyimin bittiğini gösterir. Her deyim (statement) ; ile biter. Süslü parantezle kapanan bloklardan sonra ; gerekmez; bu yüzden sınıfın ve metodun kapanış parantezinden sonra noktalı virgül yoktur.

Programın gövdesi iç içe iki bloktan oluşur. Dıştaki blok sınıfın, içteki blok main metodunun gövdesidir. Girinti, yani satır başlarındaki boşluklar, bu iç içeliği göze görünür kılar. Derleyici girintiye bakmaz; yalnız süslü parantezleri sayar.

2.2.1.4Temel söz dizimi kuralları

Tanım 2.2.2

Söz dizimi (syntax), bir dilin yazım kurallarıdır: hangi sözcüklerin, işaretlerin ve sıralamaların geçerli olduğunu belirler. Söz dizimi kurallarına uymayan Java kodu derlenmez.

Türkçede “kitabı okudum ben” cümlesi alışılmadık bir sıradadır ama anlaşılır. Derleyici bu kadar hoşgörülü değildir. Kurala uymayan bir satırı tahmin yoluyla düzeltmez, hata verip durur. Java'nın temel yazım kuralları şunlardır:

  • Her deyim ; ile biter.
  • Bloklar (block) { ile açılır, } ile kapanır. Açılan her blok kapanmalıdır.
  • Java büyük-küçük harfe duyarlıdır (case-sensitive): sayi ile Sayi iki ayrı addır; System yerine system yazılamaz.
  • Boşluk, sekme ve satır sonu derleyici için önemsizdir. Bir deyim birkaç satıra bölünebilir. Okunabilirlik için girinti kullanılır.
  • Açıklamalar (comments) iki biçimde yazılır: // satırın sonuna kadar, /* … */ ise birden çok satır boyunca sürer. Derleyici açıklamaları yok sayar.

Aşağıdaki program bu kuralların hepsini bir arada gösterir.

/* Çok satırlı açıklama:
   derleyici bunu yok sayar. */
public class Kurallar {
    // Tek satırlık açıklama
    public static void main(String[] args) {
        int sayi = 5;  // ; ile biter
        int Sayi = 7;  // sayi ≠ Sayi
        System.out.println(sayi
                + Sayi);   // satır bölünebilir
    }
}

Program şu çıktıyı verir:

12

İlk üç satır çok satırlı bir açıklamadır ve derlenen koda hiçbir şey katmaz. sayi ile Sayi büyük-küçük harf farkı yüzünden iki ayrı değişkendir: biri 5, öteki 7 değerini tutar. println çağrısı iki satıra bölünmüştür. Derleyici için bu bölünme önemsizdir, çünkü deyim ancak ; görülünce biter. Çıktıdaki 12, iki değişkenin toplamıdır. İki ayrı değişkenin yan yana bulunabilmesi, adlardaki tek bir harf farkının ne kadar önemli olduğunu gösterir. Gerçek programlarda böyle benzer adlar karışıklığa yol açar ve kaçınılması gerekir; buradaki amaç yalnız kuralı göstermektir.

Sık yapılan hata

Büyük-küçük harfi karıştırmak. Aşağıdaki üç satır, Türkçe yazarken alışılan küçük harf kullanımından kaynaklanan tipik hatalardır. Derleyici her biri için ayrı bir ileti verir:

Harf.java:3: error: package system does not exist
        system.out.println("a");
              ^
Harf.java:4: error: cannot find symbol
        string s = "b";
        ^
  symbol:   class string
  location: class Harf
Harf.java:5: error: cannot find symbol
        Int n = 3;
        ^
  symbol:   class Int
  location: class Harf
3 errors

system.out yazılınca derleyici system'i bir paket adı sanar ve bu paketi bulamaz. string ve Int ise tanımlı olmayan sınıf adları gibi görülür. Doğru yazımlar System, String ve int'tir. String bir sınıf olduğu için büyük harfle, int bir anahtar kelime olduğu için küçük harfle başlar.

2.2.1.5Soyutlama seviyeleri

Bir işlemci yalnız ikili sayılarla kodlanmış komutları anlar. İnsan ise “a ile b'yi topla, sonucu toplama yaz” gibi düşünür. Bu iki uç arasında üç seviye vardır ve her seviye bir altındakinin ayrıntılarını gizler.

  • Yüksek seviyeli dil (high-level language) problem alanına yakındır. Java, C ve Python bu seviyededir. Kod kısa, okunur ve anlaşılırdır; programcı daha üretken çalışır.
  • Assembly dili (assembly language) işlemci komutlarını MOV ve ADD gibi kısa adlarla yazar. Her satır çoğu zaman tek bir makine komutuna karşılık gelir. Daha düşük seviyeli bir soyutlamadır.
  • Donanım temsili (hardware representation) yalnız bitlerden oluşur. Komutlar ve veriler bu biçimde doğrudan donanıma gider.

Şekil 2.2.1 toplam = a + b satırının üç seviyedeki karşılığını gösterir. Örnekte a, b ve toplam değişkenlerinin sırasıyla ebx, ecx ve eax yazmaçlarında durduğu varsayılmıştır. Assembly dilinde önce a'nın değeri eax'e kopyalanır (mov eax, ebx), sonra b bunun üstüne eklenir (add eax, ecx). Makine kodu x86 işlemcilerinin gerçek kodlamasıdır: birinci komut onaltılık 89 D8, ikinci komut 01 C8 baytlarıdır. Soyutlama arttıkça kod kısalır ve okunur hâle gelir. Alt seviyeye çevirme işini bir derleyici ya da bir assembler yapar.

Java bu tabloya bir ara katman ekler. Java derleyicisi kaynak kodu doğrudan x86 makine koduna çevirmez. Önce bytecode denilen ve hiçbir gerçek işlemciye ait olmayan bir koda çevirir. Bu ara kod, aynı derlenmiş programın farklı işlemcilerde çalışabilmesini sağlar.

2.2.1.6Derleme

Tanım 2.2.3

Derleme (compilation), kaynak kodun bütünüyle başka bir dile çevrilmesidir. Bu işi yapan programa derleyici (compiler) denir. Java derleyicisi javac, kaynak kodu işlemcinin makine diline değil, Java Sanal Makinesi'nin anladığı bytecode'a çevirir ve sonucu .class uzantılı bir dosyaya yazar.

Bilgisayar .java metnini doğrudan çalıştıramaz. Metnin önce derlenmesi gerekir. Kaynak koddan ekrandaki çıktıya giden yol dört adımda tamamlanır:

  1. Programcı kaynak kodu düz metin olarak yazar ve MerhabaDunya.java adıyla kaydeder.
  2. javac MerhabaDunya.java komutu derleyiciyi çalıştırır. Derleyici söz dizimini ve tipleri denetler. Hata yoksa aynı klasörde MerhabaDunya.class dosyası oluşur.
  3. java MerhabaDunya komutu başlatıcıyı (launcher) çalıştırır. Başlatıcı JVM'i açar ve sınıfı yükler. JVM bytecode'u yorumlar, sık çalışan kısımları JIT derleyicisiyle makine koduna çevirir.
  4. İşletim sistemi ve işlemci asıl komutları yürütür; ekranda Merhaba, Dünya! görünür.

Şekil 2.2.2'de iki ayrı komut ve iki ayrı zaman dilimi vardır. Derleme zamanı, javac'ın çalıştığı süredir; bu sürede program henüz çalışmaz, yalnız denetlenir ve çevrilir. Çalışma zamanı ise java komutuyla başlar. Bir hatanın hangi zamanda ortaya çıktığı önemlidir. Derleme hatası programın hiç çalışmamasına yol açar. Çalışma zamanı hatası ise program çalışırken belirir; sıfıra bölme bunun örneğidir.

Derleme aşamasının en büyük yararı, hataların program çalışmadan önce yakalanmasıdır. Derleyici eksik noktalı virgülü, kapanmamış parantezi, yanlış yazılmış bir adı ve uyumsuz tipleri bulur. Hata varsa .class dosyası oluşmaz. İletideki dosya adı:satır bilgisi hatanın yerini gösterir. MerhabaDunya programının 3. satırındaki noktalı virgül unutulursa satır şöyle olur:

System.out.println("Merhaba, Dünya!")

Derleyici bu satır için şu iletiyi verir:

MerhabaDunya.java:3: error: ';' expected
        System.out.println("Merhaba, Dünya!")
                                             ^
1 error

İletinin ilk satırı dosyayı (MerhabaDunya.java), satır numarasını (3) ve hatanın türünü (';' expected, yani noktalı virgül bekleniyordu) verir. İkinci satır hatalı kodu yineler. Üçüncü satırdaki ^ işareti, derleyicinin noktalı virgülü beklediği yeri gösterir: kapanış parantezinin hemen sağı. Son satır toplam hata sayısını bildirir. Derleme aşaması programın hızına da katkı sağlar. Derleyici tip denetimi gibi işleri bir kez yapar; çalışma sırasında bu işlerin tekrarlanmasına gerek kalmaz. JVM'in çalışma sırasındaki iyileştirmeleri de buna eklenir.

Sık yapılan hata

Hatayı iletinin gösterdiği satırdan önce aramamak. Noktalı virgül eksik olduğunda derleyici bunu çoğu zaman bir sonraki simgeyi okuyunca fark eder. Bu yüzden ileti bazen bir alt satırı gösterir. Bir satırda anlamsız görünen bir ';' expected iletisi çıkarsa önce bir önceki satırın sonuna bakılır.

2.2.1.7Komut satırında derleme ve çalıştırma

Java ile temel işlem adımları üç tanedir. Derleme adımında .java dosyası .class dosyasına dönüştürülür: javac MerhabaDunya.java. Çalıştırma adımında java komutuna uzantısız sınıf adı verilir: java MerhabaDunya. Üçüncü adım çıktıdır: program ekrana Merhaba, Dünya! yazar. Bir komut satırı oturumu şöyle görünür:

> javac MerhabaDunya.java
> dir /b
MerhabaDunya.class
MerhabaDunya.java
> java MerhabaDunya
Merhaba, Dünya!

javac hiçbir şey yazmadıysa derleme başarılıdır. Ardından gelen dir /b komutu (Linux ve macOS'ta ls) klasördeki dosyaları listeler. Listede kaynak dosyanın yanında yeni oluşan MerhabaDunya.class görülür. Son komut programı çalıştırır.

Sık yapılan hata

Çalıştırırken uzantı yazmak: java MerhabaDunya.class. JVM bir dosya adı değil, bir sınıf adı bekler. Bu komut MerhabaDunya.class adlı bir sınıf arar ve “Could not find or load main class” iletisiyle durur. Doğrusu uzantısız yazmaktır: java MerhabaDunya.

Java 11 ile tek dosyalık programlar için bir kısayol geldi. java MerhabaDunya.java komutu dosyayı bellekte derler ve hemen çalıştırır. Bu yolda diske .class dosyası yazılmaz. Kısayol küçük denemeler için pratiktir. Ancak birden çok dosyadan oluşan programlarda iki aşamalı yol kullanılır.

2.2.1.8Bytecode

Tanım 2.2.4

Bytecode (ara kod), javac'ın ürettiği ve Java Sanal Makinesi'nin çalıştırdığı, işlemciden ve işletim sisteminden bağımsız komutlardır. .class dosyaları işlemcinin doğrudan anlayabileceği makine kodu içermez; içlerinde bytecode bulunur. Bytecode, JVM'in “makine dili”dir.

Adı komutların yapısından gelir: her komutun işlem kodu (opcode) tek bir bayttır. Komutun gerektirdiği ek bilgi, örneğin bir sabit ya da bir tablo kaydının numarası, işlem kodundan sonraki baytlarda durur. Tek baytlık işlem kodu en çok 256 farklı komut demektir ve bu sayı JVM için yeterlidir.

Bytecode bir işlemciye ya da işletim sistemine bağlı değildir. Aynı .class dosyası Windows'ta, Linux'ta ve macOS'ta çalışır. Bir benzetme bu ilişkiyi iyi anlatır: bytecode her ülkede aynı okunan bir nota gibidir. Her bilgisayardaki JVM ise o notayı kendi çalgısında çalan müzisyendir. Nota değişmez; çalgı ve müzisyen değişir.

Bir .class dosyası ikili bir dosyadır ve metin düzenleyicide anlamsız karakterler olarak görünür. JDK'daki javap -c Sinif komutu bu dosyadaki bytecode komutlarını okunur biçimde listeler. İki satırlık şu kodu ele alalım: int x = 5; System.out.println(x);. Kod bir main metodunun içine yazılıp JDK 21 ile derlendiğinde javap -c şu listeyi verir:

0: iconst_5
1: istore_1
2: getstatic     #7    // System.out
5: iload_1
6: invokevirtual #13   // println(int)
9: return

Her satırın başındaki sayı, komutun metot içindeki bayt konumudur. Konumlar 0, 1, 2, 5, 6, 9 diye ilerler. iconst_5 ve istore_1 tek baytlık komutlardır. getstatic ve invokevirtual ise işlem kodundan sonra iki baytlık bir tablo numarası taşır; bu yüzden üç bayt yer kaplar.

JVM bir yığın makinesidir. Gerçek işlemciler değerleri yazmaçlarda tutar. JVM'in komutları ise değerleri bir işlenen yığınına (operand stack) iter ve oradan alır. Yığın, üst üste konmuş tabaklar gibidir: en son konan en önce alınır. Komutlar sırayla şunu yapar:

  1. iconst_5: sabit 5 işlenen yığınına itilir. Kaynaktaki karşılığı int x = 5; satırının sağ tarafıdır.
  2. istore_1: yığının üstündeki değer alınır ve 1 numaralı yerel değişkene, yani x'e yazılır. Yığın yeniden boşalır.
  3. getstatic #7: System.out nesnesine bir başvuru yığına itilir. #7, sınıf dosyasındaki sabitler tablosunun 7 numaralı kaydıdır.
  4. iload_1: x'in değeri (5) yığına kopyalanır. Kaynaktaki karşılığı System.out.println(x); satırıdır.
  5. invokevirtual #13: println(int) metodu çağrılır. Metot iki değeri yığından alır: hangi nesne üzerinde çalışacağını (System.out) ve yazacağı sayıyı (5). Ekrana 5 yazılır.
  6. return: main biter, program sonlanır.

Şekil 2.2.4 üç anı gösterir. (b) ile (c) arasındaki fark önemlidir: iload_1 değeri yerel değişkenden yığına kopyalar. x yerinde kalır ve değeri değişmez. Bir değişkeni okumak onu tüketmez; bu durum bytecode düzeyinde de geçerlidir.

2.2.1.9JVM yığınında bir toplama

Yığın makinesi fikri bir toplama işleminde daha açık görülür. Şu üç satırı ele alalım:

int a = 5;
int b = 7;
int toplam = a + b;
System.out.println(toplam);

Bu satırların derlenmiş hâli on iki komuttur. Açıklamalar, her komutun kaynak koddaki karşılığını verir:

2.2.1.10Java Sanal Makinesi ve JIT

Tanım 2.2.5

Java Sanal Makinesi (Java Virtual Machine, JVM), Java uygulamalarını çalıştıran yazılımdır. Bytecode'u yorumlar ve bulunduğu işlemciye uygun biçimde yürütür. Sık çalışan bytecode parçalarını JIT (just-in-time, tam zamanında) derleyicisiyle çalışma sırasında makine koduna çevirir.

“Sanal makine” adı, JVM'in kendi komut kümesi olan bir bilgisayar gibi davranmasından gelir. Bu bilgisayar donanım olarak yoktur; bir program olarak gerçek bilgisayarın üzerinde çalışır. JVM'in iç yapısı dört ana parçadan oluşur:

  • Sınıf yükleyici, gerekli .class dosyalarını bulur ve belleğe alır.
  • Doğrulayıcı, yüklenen bytecode'un kurallara uyduğunu denetler. Örneğin bir komutun yığında bulunmayan bir değeri almaya çalışmadığından emin olur. Böylece bozuk ya da kötü niyetli bir dosya JVM'i çökertemez.
  • Yorumlayıcı, bytecode komutlarını tek tek okur ve her birinin karşılığı olan işi yapar.
  • JIT derleyicisi, çok kez çalışan kod parçalarını fark eder ve onları doğrudan makine koduna çevirir. Sonraki çalışmalarda yorumlama yerine bu makine kodu kullanılır.

Yorumlama esnektir ama yavaştır: her komut her çalıştırılışında yeniden çözümlenir. Makine kodu ise hızlıdır ama üretilmesi zaman alır. JIT bu ikisi arasında bir denge kurar. Bir kez çalışan kod yorumlanır, binlerce kez çalışan bir döngü gövdesi derlenir. Bu yüzden bir Java programı zamanla hızlanır. Uzun süre çalışan sunucu programlarında bu etki belirgindir.

Programı başlatan java komutu, JDK belgelerinde Java başlatıcı aracı (launcher tool) diye geçer. Başlatıcı JVM'i başlatır, adı verilen sınıfı yükler ve o sınıfın main metodunu çağırır. main bitince JVM de kapanır.

2.2.1.11Platform bağımsızlığı ve Java platformu

Tanım 2.2.6

Platform, bir programın çalıştığı donanım ya da yazılım ortamıdır: işlemci ile işletim sisteminin birleşimi. Platform bağımsızlığı (platform independence), aynı derlenmiş programın JVM bulunan her platformda yeniden derlenmeden çalışmasıdır.

Platform bağımsızlığı Java'nın temel özelliklerinden biridir ve “Bir kez yaz, her yerde çalıştır” (Write Once, Run Anywhere) sloganıyla anılır. Program bir kez derlenir; aynı bytecode farklı işletim sistemlerinde çalıştırılır. Bunu mümkün kılan, JVM'in birçok işletim sistemi ve işlemci için ayrı ayrı yazılmış olmasıdır. Windows için yazılmış JVM bytecode'u x86 makine koduna çevirir. ARM işlemcili bir Mac'teki JVM aynı bytecode'u ARM makine koduna çevirir. Farklılık bytecode'da değil, JVM'dedir.

C gibi dillerde durum farklıdır. C derleyicisi doğrudan makine kodu üretir ve bu kod derlendiği platforma bağlıdır. Windows'ta derlenen bir C programı Linux'ta çalışmaz; her platform için ayrı derleme gerekir. Java'da bu yük JVM'i yazanlara geçer. Programcı tek bir .class dosyası dağıtır, kullanıcının bilgisayarında JVM bulunması yeterlidir.

Java platformunun iki ana bileşeni vardır:

  • JVM uygulamaları çalıştırır ve farklı donanımlara taşınabilirlik sağlar.
  • API (Application Programming Interface, uygulama programlama arayüzü) hazır sınıf kütüphanelerinden oluşur. Grafik arayüz, veri tabanı, ağ iletişimi ve dosya işlemleri gibi birçok işlevi hazır sunar ve geliştirmeyi hızlandırır. System, String, Math ve Scanner bu kütüphanelerdeki sınıflardır.

Şekil 2.2.8 katmanların iç içe olduğunu gösterir. Çalışma ortamı (JRE, Java Runtime Environment) bir Java programını çalıştırmak için gerekenleri, yani JVM'i ve API kütüphanelerini içerir. JDK bunların üstüne derleyiciyi ve öteki geliştirme araçlarını ekler. Program geliştirmek için JDK kurulur. Oracle, Java 11'den beri JRE'yi ayrı bir paket olarak dağıtmaz; JDK hepsini içerir.

2.2.2Değişkenler ve veri tipleri

Bir program veri alır, veriyi işler ve sonuç üretir. Bu sürecin her anında verinin bir yerde durması gerekir. Değişkenler bu işi görür. Java her değişkenin hangi türden veri tuttuğunu baştan bilmek ister; bu bilgiye tip denir. Bu kesim değişkenleri, Java'nın sekiz ilkel tipini ve her tipin sınırlarını ele alır.

2.2.2.1Temel programlama unsurları

Her program, hangi dille yazılmış olursa olsun, birkaç temel unsurdan kurulur. Değişkenler verileri saklar. Her değişkenin bir tipi vardır. Değerler ifadelerle (expressions) hesaplanır: sayi > 0 ve toplam + 1 birer ifadedir. Kontrol akışı (control flow) ise programın hangi sırayla ve nasıl çalışacağını belirler. Kontrol akışının iki temel biçimi vardır:

  • Dallanma (branching), bir koşula göre programın farklı kısımlarını çalıştırır. if-else buna örnektir.
  • Döngüler (loops), bir işlemi tekrarlar. for ve while buna örnektir.

Aşağıdaki kod parçası bir değişkeni, bir koşulu ve çıktıyı bir araya getirir:

int sayi = 5;
if (sayi > 0) {
    System.out.println("Sayı pozitif.");
} else {
    System.out.println("Sayı negatif veya sıfır.");
}
Sayı pozitif.

sayi 5 olduğu için sayi > 0 ifadesi doğrudur ve ilk blok çalışır. else bloğu atlanır. sayi 0 ya da negatif olsaydı ilk blok atlanır, ikinci blok çalışırdı. Burada sayi > 0 ifadesinin değeri bir sayı değil, doğru ya da yanlış bilgisidir. Java bu bilgi için ayrı bir tip kullanır: boolean.

2.2.2.2Değişken ve bildirim

Tanım 2.2.7

Değişken (variable), bellekte bir değeri saklayan, adı ve tipi olan bir alandır. Değişkenin kullanılmadan önce tanıtılmasına bildirim (declaration) denir. Bildirimde önce tip, sonra ad yazılır ve bildirim ; ile biter.

Değişken, üzerinde ad yazan bir kutu gibi düşünülebilir. Kutunun etiketinde iki bilgi vardır: adı ve içine ne tür bir şey konabileceği. int etiketli bir kutuya yalnız tam sayı, double etiketli bir kutuya yalnız ondalıklı sayı konur. Kutunun içindeki değer program çalışırken değişebilir; adı ve tipi ise değişmez.

Java'da her değişken kullanılmadan önce bildirilmelidir. Aynı tipten birden çok değişken virgülle ayrılarak tek satırda bildirilebilir:

int numara, cekSayisi, mevcutSayisi;
double miktar, faizOrani;
char cevap;

Birinci satır üç int değişken, ikinci satır iki double değişken, üçüncü satır bir char değişken bildirir. Bildirimin üç biçimi vardır: tip ad;, tip ad1, ad2, ad3; ve tip ad = ilkDeğer;. Sonuncusu bildirimle birlikte değişkene ilk değerini de verir.

Adlar açıklayıcı ve anlamlı seçilmelidir. x adı değişkenin ne tuttuğu hakkında hiçbir şey söylemez. cekSayisi ise bir hesaptaki çek sayısını tuttuğunu hemen belli eder. Birkaç ay sonra kodu yeniden okuyan kişi, çoğu zaman kodu yazan kişinin kendisidir. Anlamlı adlar bu kişinin işini kolaylaştırır.

2.2.2.3Bildirim, atama, güncelleme

Bir değişkenin yaşamı üç olayla ilerler: bildirilir, bir değer alır ve bu değer güncellenir. Aşağıdaki kod üç olayı da içerir:

int yas;

yas = yas + 1;

System.out.println(yas + " " + boy + " " + harf);

2.2.2.4Sekiz ilkel tip

Tanım 2.2.8

Veri tipi (data type), bir değişkenin hangi değerleri alabileceğini, bellekte ne kadar yer kapladığını ve üzerinde hangi işlemlerin yapılabileceğini belirler. Java'nın dile gömülü sekiz temel tipine ilkel tip (primitive type) denir: byte, short, int, long, float, double, char ve boolean.

Sekiz tip dört gruba ayrılır:

  • Tam sayı: byte, short, int, long.
  • Kesirli (ondalıklı) sayı: float, double.
  • Karakter: char.
  • Mantıksal: boolean.

Her tipin bellekte kendine özgü bir boyutu ve buna bağlı bir değer aralığı vardır. Bit sayısı arttıkça tip daha büyük sayıları tutar, ama bellekte daha çok yer kaplar. C dilinde int'in boyutu derleyiciye ve işlemciye göre değişebilir. Java'da ise boyutlar dilin tanımında sabittir: int her platformda 32 bittir. Bu sabitlik de platform bağımsızlığının bir parçasıdır.

Günlük kullanımda tam sayılar için int, ondalıklı sayılar için double varsayılan seçimdir. byte ve short çoğunlukla büyük dizilerde bellek kazanmak ya da dosyadan bayt okumak gibi özel durumlarda kullanılır. float ise grafik ve bazı gömülü sistemler dışında pek tercih edilmez.

Sayı bir işaret, bir üs ve bir kesirden oluşur: 6,02 × 1023 sayısında 6,02 kesir, 23 üstür. Kesir anlamlı basamakları, üs ise virgülün yerini belirler. Virgül sayının büyüklüğüne göre “kayar”; ad buradan gelir.

2.2.2.7char ve boolean

char tek bir karakter tutar. Bellekte 2 bayt (16 bit) yer kaplar ve işaretsizdir: değer aralığı 0 ile 65.535 arasındadır. Her değer bir Unicode karakter kodudur. Unicode, dünyadaki yazı sistemlerinin karakterlerine birer numara veren uluslararası bir standarttır. char sabitleri tek tırnakla yazılır: 'A', 'ş', '7'. Tek tırnak ile çift tırnak arasındaki fark önemlidir: 'A' bir char, "A" ise tek karakterlik bir String'dir.

Bir karakterin kodunu bilmek, karakterlerle hesap yapmayı mümkün kılar. Üç kod sık kullanılır: 'A' = 65, 'a' = 97, '0' = 48. İngilizce alfabedeki harflerin ve rakamların kodları ASCII tablosundakilerle aynıdır ve ardışık dizilir: 'B' = 66, 'C' = 67, '1' = 49. '7' karakterinin kodu 7 değil, 55'tir. Rakam karakteri ile rakamın sayı değeri ayrı şeylerdir.

boolean mantıksal bir değer tutar. Yalnız iki değeri vardır: true (doğru) ve false (yanlış). Taşıdığı bilgi bir bittir; bellekte kaç bayt tutacağını JVM belirler. C dilinin aksine Java'da boolean bir sayı değildir. boolean bitti = 0; derlenmez, if (1) de yazılamaz. boolean değerler koşullarda ve karşılaştırma sonuçlarında kullanılır:

boolean gectiMi = puan >= 50;

Bu satırda puan >= 50 karşılaştırmasının sonucu, yani true ya da false, gectiMi değişkenine yazılır. puan 72 ise gectiMi true olur.

2.2.2.9Taşma

Tanım 2.2.9

Taşma (overflow), bir işlemin sonucunun tipin değer aralığına sığmamasıdır. Java'da tam sayı taşması hata vermez: değer aralığın öbür ucuna sarar.

Taşmayı saatle düşünmek kolaydır. Saat 12'yi gösterirken bir saat ilerletilirse 13'e değil, 1'e döner. Tam sayı tipleri de böyle davranır: en büyük değere 1 eklenince en küçük değere dönülür. Önemli olan, bu dönüşün sessizce olmasıdır. Program ne derleme hatası ne de çalışma hatası verir; yanlış sonuçla yoluna devam eder.

int enBuyuk = Integer.MAX_VALUE;
System.out.println(enBuyuk);
System.out.println(enBuyuk + 1);   // taşma!
byte sayi1 = 80;
byte sayi2 = 50;
byte toplam = (byte) (sayi1 + sayi2);
System.out.println(toplam);        // 130 değil
long dogru = (long) enBuyuk + 1;
System.out.println(dogru);
2147483647
-2147483648
-126
2147483648

Satırlar şöyle çalışır:

  • enBuyuk int'in en büyük değerini, 2.147.483.647'yi tutar ve ilk satırda bu değer yazılır.
  • enBuyuk + 1 iki int arasındaki bir toplamadır ve sonucu da int'tir. Sonuç sığmaz ve en küçük değere sarar: -2147483648.
  • sayi1 + sayi2 80 + 50 = 130 verir. 130, byte sınırı olan 127'yi aşar. (byte) dönüşümü sonucun son 8 bitini alır ve değer 130 − 256 = −126 olur.
  • (long) enBuyuk + 1 ifadesinde dönüşüm toplamadan önce yapılır. İşlem long tipinde yürür; 64 bitlik aralık 2.147.483.648'i rahatça tutar.

Çözüm daha geniş bir tip kullanmaktır. Ancak dönüşümün yeri önemlidir. long yanlis = enBuyuk + 1; satırı yine −2147483648 verir. Sağ taraf iki int arasında hesaplanır ve önce taşar; long değişkene ancak taşmış sonuç atanır. Dönüşüm işlemden önce yapılmalıdır: (long) enBuyuk + 1 ya da enBuyuk + 1L.

Örnek 2.2.1

Bir milyonun karesi int ile hesaplanırsa ne çıkar? int milyon = 1_000_000; iken milyon * milyon ifadesinin gerçek değeri 1012'dir; bu sayı int'in yaklaşık 2,1 milyarlık sınırını çok aşar. Java'nın verdiği sonuç -727379968'dir. Bu değer, 1012'nin ikili gösteriminin son 32 bitinin işaretli okunuşudur. Aynı hesap (long) milyon * milyon diye yazılınca doğru sonuç, 1000000000000 elde edilir. Sonucun negatif çıkması burada taşmayı ele verir. Her taşma bu kadar belirgin değildir; sonuç pozitif ama yanlış da olabilir.

Taşmanın bit düzeyinde nasıl oluştuğunu bir byte sayacı üzerinde adım adım izleyelim:

byte b = 125;
for (int i = 1; i <= 4; i++) {
    b++;

}

2.2.2.10İlkel tipler ve referans tipleri

Tanım 2.2.10

İlkel tipteki bir değişken değerin kendisini saklar. Referans tipindeki (reference type) bir değişken ise bir nesneyi gösterir: değişkende nesnenin kendisi değil, bellekteki yeri, yani nesneye bir başvuru tutulur.

İlkel tipler sekiz tanedir ve adları küçük harfle başlar. Geri kalan bütün tipler referans tipidir. String (karakter dizisi), diziler, sınıflar, arayüzler ve enum'lar bu gruptadır. Referans tiplerinin adları büyük harfle başlar. Nesneler genellikle new ile oluşturulur. String bu kuralın sık görülen bir istisnasıdır: "Ali" gibi bir dizgi sabiti, new yazılmadan da bir nesne oluşturur.

Hiçbir nesneyi göstermeyen bir referansın değeri null'dır. null ile boş dizgi karıştırılmamalıdır. Boş dizgi "" gerçek bir nesnedir ve uzunluğu sıfırdır: "".length() 0 verir. null ise “burada nesne yok” demektir. null bir referans üzerinde metot çağrılırsa program NullPointerException ile durur. Yerel bir String değişkeni için üç durum birbirinden ayrıdır. Değer atanmamış değişkeni yazdıran kod derlenmez. null atanmış değişken null yazar. "" atanmış değişken ise boş bir satır yazar.

İki tip grubunun farkı atamada da görülür. int a = 5; int b = a; satırlarından sonra b, 5'in ayrı bir kopyasını tutar; b değişince a etkilenmez. İki referans değişkeni ise aynı nesneyi gösterebilir. Bu ayrım nesne yönelimli programlamanın temel konularından biridir.

2.2.3Tanımlayıcılar ve anahtar kelimeler

Bir programdaki değişkenlerin, metotların ve sınıfların her birinin bir adı vardır. Programcı bu adları seçmekte özgürdür, ama bu özgürlüğün sınırları bellidir. Bazı karakterler adlarda kullanılamaz, bazı sözcükler ise dile ayrılmıştır. Ayrıca Java topluluğunun uyduğu yazım alışkanlıkları vardır. Bu kesim üç düzeyi sırayla ele alır: derleyicinin zorunlu kuralları, ayrılmış sözcükler ve uzlaşımlar.

2.2.3.1Tanımlayıcı kuralları

Tanım 2.2.11

Tanımlayıcı (identifier), değişkenlere, sınıflara, metotlara ve öteki program öğelerine verilen addır.

Tanımlayıcılar şu kurallara uyar:

  • Yalnız harf, rakam (0–9), alt çizgi _ ve dolar işareti $ içerebilir. Boşluk, -, @, . gibi karakterler bulunamaz.
  • İlk karakter harf, _ ya da $ olmalıdır. Tanımlayıcı rakamla başlayamaz.
  • Anahtar kelimeler ve true, false, null sabitleri tanımlayıcı olamaz.
  • Uzunluk sınırı yoktur.
  • Büyük ve küçük harf ayrıdır: kisiAdi ile kisiadi farklı değişkenlerdir. Bildirimdeki yazımdan farklı yazılan bir ad cannot find symbol hatası verir.

Rakamla başlama yasağının bir nedeni vardır. Derleyici bir rakam gördüğünde sayı okumaya başlar. 2yas ile karşılaşan derleyici önce 2 sayısını okur, ardından gelen yas'ı ayrı bir sözcük sayar. Aynı nedenle ad-soyad, “ad eksi soyad” diye okunur; çünkü - çıkarma operatörüdür.

Java harf olarak yalnız İngilizce harfleri değil, bütün Unicode harflerini kabul eder. öğrenci adlı bir değişken derlenir ve çalışır. Yine de adlarda yalnız İngilizce harfler kullanılması önerilir. Dosyalar farklı karakter kodlamasıyla açılınca Türkçe harfler bozulabilir ve kod başka sistemlerde derlenmez hâle gelebilir. Bu yüzden adlar öğrenciNo yerine ogrenciNo, sayaç yerine sayac biçiminde yazılır. Geçerli örnekler: kullaniciAdi, toplamPuan, ogrenci_adi, veri1, _sayac.

2.2.4Atama, sabitler ve dönüşüm

Değişkenler bildirildikten sonra değer alır ve bu değerler değişir. Bu kesim, değerin değişkene nasıl konduğunu, kodda doğrudan yazılan değerlerin nasıl okunduğunu ve bir değerin bir tipten ötekine nasıl geçtiğini anlatır. Tip dönüşümü, başlangıç düzeyindeki Java programlarında en çok hata çıkan konulardan biridir.

2.2.4.1Atama ifadeleri

Tanım 2.2.13

Atama (assignment), bir değişkene değer vermektir. = atama operatörüyle yazılır: değişken = ifade;. Önce sağ taraftaki ifade hesaplanır, sonra sonuç sol taraftaki değişkene yazılır.

Sağ taraftaki ifade bir sabit değer, başka bir değişken ya da bir işlem olabilir:

int sayi, sonuc;
int sayi1 = 4, sayi2 = 6;
String isim;

sayi = 10;             // sabit değer
sonuc = sayi1 + sayi2; // toplam: 10
isim = "Ahmet";        // metin
sayi = sayi * 2;       // 10 → 20

İlk üç satır bildirimdir. sayi1 ve sayi2 bildirimle birlikte değer alır; sayi, sonuc ve isim ise henüz boştur. Ardından dört atama gelir ve her birinin sağ tarafı farklıdır. Birincisi bir sabittir (10), ikincisi iki değişkenin toplamıdır (4 + 6 = 10). Üçüncüsü bir metin ("Ahmet"), dördüncüsü değişkenin kendi değerini kullanan bir işlemdir. Son satırdan sonra sayi 20 olur.

= işareti matematikteki eşitlik değildir. Matematikte x = x + 1 çelişkili bir denklemdir; hiçbir sayı kendisinin bir fazlasına eşit olamaz. Java'da ise x = x + 1 “x'in yeni değeri, eski değerinin bir fazlası olsun” demektir. Okurken “eşittir” yerine “alır” demek bu yanılgıyı önler: “x, x + 1'i alır.”

Atamanın sol tarafında yalnız bir değişken bulunabilir. 5 = sayi; satırı derlenmez:

Sol.java:4: error: unexpected type
        5 = sayi;
        ^
  required: variable
  found:    value
1 error

İleti, sol tarafta bir değişken beklendiğini (required: variable) ama bir değer bulunduğunu (found: value) söyler. Atamada tipler de uyumlu olmalıdır. String bir değişkene sayı, int bir değişkene metin atanamaz. int x = 3; String s = x; satırları incompatible types: int cannot be converted to String iletisini verir.

Atama aynı zamanda bir ifadedir ve bir değer üretir: atanan değeri. Bu yüzden a = b = 0; yazılabilir. Atama sağdan sola gruplanır; önce b = 0 yapılır, bu ifadenin değeri olan 0 da a'ya atanır. İki değişken birden sıfırlanmış olur.

2.2.4.3İlk değer ve varsayılan değerler

Bir değişken değer atanmadan bildirilebilir. İlk değer bildirimle birlikte de verilebilir: int yas = 25;. Bu işleme ilk değer verme (initialization) denir. Değerin ne zaman verildiği, değişkenin nerede bildirildiğine göre iki farklı kurala bağlıdır.

Yerel değişkenler, yani bir metodun içinde bildirilen değişkenler, varsayılan değer almaz. Değer atanmadan okunan yerel değişken programın derlenmesini engeller:

2.2.4.5Ondalık sayıların hassaslığı

Ondalık sayılar sınırlı sayıda bitle ve ikili tabanda saklanır. Onluk tabanda 1/3 = 0,333… sonsuza dek sürer ve sonlu basamakla tam yazılamaz. Döngü sayacı tam sayı olmalıdır; ondalıklı değer gerekiyorsa sayaçtan hesaplanır: double t = i * 0.1;.

2.2.4.6İsimlendirilmiş sabitler

Tanım 2.2.16

İsimlendirilmiş sabit (named constant), final ile bildirilen ve değeri bir kez verildikten sonra değiştirilemeyen değişkendir. Sınıf düzeyindeki kalıbı şudur: public static final Tip SABIT_ADI = değer;.

Kodun içine gömülü, anlamı belirtilmemiş sayılara sihirli sayı denir. gun = 4 * 7; satırındaki 7'nin haftanın gün sayısı olduğu, ancak bağlamdan tahmin edilebilir. Aynı satır gun = 4 * GUNLER_HAFTADA; diye yazılınca anlam kendiliğinden ortaya çıkar. Değer değişirse de tek bir yerden güncellenir. Sabit adları büyük harfle yazılır, kelimeler alt çizgiyle ayrılır.

    public static final int GUNLER_HAFTADA = 7;

        double r = 2.0;
        double alan = PI * r * r;

Java'nın kendisi de daha duyarlı bir değer sunar: Math.PI. Aynı yarıçapla Math.PI * r * r 12,566370614359172 verir.

İkinci ileti bir tip dönüşümü sorunudur. PI * r * r bir double ifadesidir ve float daha dar bir tiptir. Derleyici “olası kayıplı dönüşüm” (possible lossy conversion) uyarısıyla atamayı reddeder.

2.2.4.7Atama uyumluluğu

Bir değer, başka tipte bir değişkene her zaman atanamaz. Java'nın kuralı basittir: değer kayıpsız sığıyorsa atama kendiliğinden yapılır, kayıp olabilecekse programcının açıkça istemesi gerekir.

Tanım 2.2.17

Genişletme dönüşümü (widening conversion), bir değerin daha geniş aralıklı bir tipe geçmesidir ve otomatik yapılır. Daraltma dönüşümü (narrowing conversion) ise daha dar aralıklı bir tipe geçiştir; değer kaybı olabileceği için açık dönüşüm ister.

Şekil 2.2.19 zinciri gösterir: byte → short → int → long → float → double. Bir değer, zincirde daha sağdaki bir tipin değişkenine doğrudan atanabilir. int bir değer long'a, long bir değer double'a sorunsuz geçer. char zincire int'ten girer: bir char değeri int'e ve onun sağındaki tiplere atanabilir, tersi derlenmez.

Uyum.java:5: error: incompatible types:
  possible lossy conversion from int to char
        karakter = tamsayi;
                   ^

tamsayi = karakter; satırında 'A''nın kodu olan 65, int değişkene yazılır. Ters yöndeki atama ise reddedilir. tamsayi'nın o anda 65 olduğu bilinse bile derleyici değere değil, tipe bakar. int bir değişken −5 ya da 100.000 gibi char'a sığmayan bir değer de taşıyabilir.

Zincirin bir inceliği vardır. long 64 bit, float ise 32 bittir; yine de long → float otomatik izinlidir. Bunun nedeni, float'ın aralığının long'unkinden çok daha geniş olmasıdır. Ancak float yalnız 7 basamak kadar duyarlıdır. Çok büyük bir sayıda son basamaklar yuvarlanır. long buyuk = 123456789123L; değeri float'a atanıp geri okununca 123456790528 elde edilir. Aynı durum int → float için de geçerlidir: 16.777.217 float'a atanınca 16.777.216 olur. Genişletme aralık bakımından güvenlidir, ama duyarlık bakımından her zaman değil.

2.2.4.8Örtük ve açık dönüşüm

Tanım 2.2.18

Tip dönüşümü (type conversion), bir değeri başka bir tipe çevirmektir. Java'nın kendiliğinden yaptığı dönüşüme örtük dönüşüm (implicit), programcının hedef tipi parantez içinde yazarak istediği dönüşüme açık dönüşüm (explicit conversion, cast) denir: (int) d.

Küçük tipten büyük tipe dönüşümü Java kendiliğinden yapar. Büyük tipten küçük tipe dönüşümde ise hedef tip parantez içinde yazılır. Programcı bu işaretle olası kaybı kabul ettiğini derleyiciye bildirmiş olur. Kayıp iki biçimde ortaya çıkar:

  • Sığmayan bir tam sayı taşar. (byte) 130 değerin son 8 bitini alır ve −126 verir.

2.2.5Operatörler

Operatörler değerler üzerinde işlem yapan simgelerdir. +, < ve && birer operatördür (operator); üzerinde işlem yaptıkları değerlere işlenen (operand) denir.   • s / 3600 = 1. Bir saat 3600 saniyedir ve 3725'in içinde bir kez vardır.
  • s % 3600 / 60 = 125 / 60 = 2. Önce saatten artan 125 saniye bulunur, sonra bunun içindeki tam dakikalar sayılır. % ve / eşit önceliklidir ve soldan sağa uygulanır.

Üs için Math.pow(2, 3) kullanılır; sonuç double tipinde 8.0'dır. + operatörünün de ikinci bir anlamı vardır. İşlenenlerinden biri String ise birleştirme (concatenation) yapar: "Yaş: " + 20 ifadesi Yaş: 20 metnini verir.

Dizgi birleştirme de aynı soldan sağa kuralına uyar ve bu yüzden şaşırtıcı sonuçlar verebilir. 1 + 2 + "3" + 4 + 5 ifadesinde önce 1 + 2 = 3 hesaplanır; henüz metin yoktur. Sonra 3 + "3" metin olur: "33". Bundan sonraki her + birleştirmedir: "334", "3345". Sonuç 3345'tir.

2.2.5.6Kısa devre değerlendirme

Tanım 2.2.24

Kısa devre değerlendirme (short-circuit evaluation), && ve || operatörlerinde sonuç sol taraftan belli olunca sağ tarafın hiç hesaplanmamasıdır.

&&'de sol taraf false ise sonuç zaten false'tur; sağ taraf ne olursa olsun bunu değiştiremez. Java bu durumda sağ tarafı hiç hesaplamaz. ||'de sol taraf true ise sonuç zaten true'dur ve sağ taraf yine atlanır. gun == 6 || gun == 7 ifadesinde gun 6 ise ikinci karşılaştırma hiç yapılmaz. Bu ifade “hafta sonu” anlamına gelir. Tersi !(gun == 6 || gun == 7) ise “hafta içi” demektir.

Kısa devre yalnız hız kazandırmaz; tehlikeli bir işlemi korumak için de kullanılır. Önce “bölen sıfır değil mi?” diye bakılır, ancak öyleyse bölme yapılır:

int bolen = 0;
int sayi = 10;
if (bolen != 0 && sayi / bolen > 1) {
    System.out.println("Oran 1'den büyük");
} else {
    System.out.println("Bölünemez ya da küçük");
}
Bölünemez ya da küçük

bolen 0'dır. bolen != 0 yanlış çıkar ve && sağ tarafa hiç geçmez. Böylece sayi / bolen bölmesi yapılmaz ve program else bloğuna geçer. Sıra önemlidir. Koşul sayi / bolen > 1 && bolen != 0 diye yazılsaydı bölme önce yapılırdı. Program sıfıra bölme hatasıyla, java.lang.ArithmeticException: / by zero iletisiyle dururdu. Koruyucu koşul her zaman sola yazılır.

Java'da kısa devre yapmayan iki operatör daha vardır: tek & ve tek |. Bunlar boolean değerlerle kullanıldığında iki tarafı da her zaman hesaplar. a != 0 & 10 / a > 1 ifadesi a = 0 iken sol taraf yanlış olsa bile bölmeyi yapar ve istisna fırlatır. Koşullarda neredeyse her zaman çift karakterli && ve || kullanılır.

    sonuc = "Pozitif";
} else {
    sonuc = "Negatif";
}

İki yazım arasındaki temel fark şudur: if-else bir deyimdir ve bir iş yapar, ?: ise bir ifadedir ve bir değer üretir. Bu yüzden ?: atamanın sağında ya da bir println'ın içinde kullanılır. Tek başına bir deyim olarak yazılamaz:

Tern.java:4: error: not a statement
        x > 0 ? System.out.println("a") : System.out.println("b");
              ^
1 error

İki seçeneğin tipi uyumlu olmalıdır. Birkaç örnek: double mutlak = (sayi < 0) ? -sayi : sayi; mutlak değeri verir ve −4.5 için 4.5 bulunur. int buyuk = (a > b) ? a : b; iki sayının büyüğünü seçer; 8 ve 13 için 13 bulunur. Seçenekler farklı sayısal tiplerdeyse sonuç geniş olana yükseltilir: true ? 1 : 2.0 ifadesinin değeri 1 değil, 1.0'dır.

Üçlü operatörler iç içe kullanılabilir. Bir sayının sıfır mı, pozitif mi, negatif mi olduğu tek satırda bulunur:

int sayi = -5;
String sonuc = (sayi == 0) ? "Sıfır" : (sayi > 0) ? "Pozitif" : "Negatif";
System.out.println("Sayı " + sonuc);

2.2.6Kontrol deyimlerinin söz dizimi

Kontrol deyimleri programın akışını yönetir. Bir koşula göre dallanmayı ya da bir işin tekrarlanmasını sağlarlar. Ayrıntılı kullanımları kendi başına bir konudur. Burada her birinin yazım kuralı ve en sık rastlanan söz dizimi tuzakları verilir.

if deyiminde koşul her zaman parantez içinde yazılır ve boolean olmalıdır. Gövde tek bir deyimse süslü parantez yazılmayabilir, ama bu alışkanlık hataya açıktır. Parantezsiz bir if'e yalnız ilk deyim bağlıdır; altına girintili yazılan ikinci satır koşuldan bağımsız çalışır. Derleyici girintiye bakmaz. Bu yüzden gövde tek satır olsa bile süslü parantez kullanmak güvenlidir.

switch deyiminde denetlenen değer int (ve byte, short), char, String ya da enum olabilir. long, double ve boolean kullanılamaz; derleyici selector type double is not allowed gibi bir ileti verir. Klasik biçimde her case'in sonuna break yazılır. break unutulursa eşleşen durumdan sonraki durumlar da sırayla çalışır. Bu davranışa aşağı düşme (fall-through) denir. Aşağı düşme bazen bilinçli kullanılır: case "Cmt": case "Paz": yazımı iki durumu tek bir koda bağlar. Java 14 ile gelen ok (->) biçiminde ise aşağı düşme yoktur ve switch bir değer üretebilir. İki biçim aynı switch içinde karıştırılamaz (different case kinds used in the switch).

for döngüsünün başlığı noktalı virgülle ayrılmış üç bölümden oluşur. Başlangıç bölümü yalnız bir kez, döngüye girerken çalışır. Koşul her turdan önce denetlenir; yanlışsa döngü biter. Güncelleme her turun sonunda çalışır. Her for döngüsü bir while döngüsüyle de yazılabilir: başlangıç döngüden önceye, güncelleme gövdenin sonuna taşınır.

while ile do-while arasındaki fark koşulun yeridir. while koşulu önce denetler; koşul baştan yanlışsa gövde hiç çalışmaz. do-while ise gövdeyi önce çalıştırır, koşulu sonra denetler; gövde en az bir kez çalışır. do-while'ın sonundaki noktalı virgül zorunludur ve unutulursa ';' expected hatası alınır.

break içinde bulunduğu en yakın döngüden ya da switch'ten hemen çıkar. continue ise yalnız o turun kalanını atlar ve bir sonraki tura geçer. for döngüsünde continue'dan sonra güncelleme bölümü yine çalışır. switch bir döngünün içindeyse, switch içindeki break yalnız switch'ten çıkar; döngü sürer.

Örnek 2.2.4

1'den 100'e kadar olan sayılardan 3'ün katı olmayanların toplamı continue ile şöyle bulunur:

int toplam = 0;
for (int i = 1; i <= 100; i++) {
    if (i % 3 == 0) continue;   // 3'ün katlarını atla
    toplam += i;
}

3'ün katı olan bir i için continue çalışır, toplam += i atlanır ve döngü i++ ile sürer. Sağlama: 1'den 100'e kadar sayıların toplamı 5050'dir. 3'ün katları 3, 6, …, 99'dur; 33 tanedir ve toplamları 3 × (1 + 2 + … + 33) = 3 × 561 = 1683'tür. Sonuç 5050 − 1683 = 3367'dir.

Sık yapılan hata

Sonsuz döngü. Koşulu yanlışa götüren bir adımı olmayan döngü hiç bitmez. for (int i = 1; i <= 10; i--) döngüsünde i azaldıkça koşul hep doğru kalır. int i = 1; while (i <= 3) { System.out.println(i); } döngüsünde ise i gövdede hiç güncellenmez ve ekrana durmadan 1 yazılır. Her döngü yazılırken “koşul hangi adımda yanlış olacak?” sorusu sorulmalıdır.

2.2.8Özet

  • Derleme: javac Ad.java kaynak kodu denetler ve Ad.class dosyasına bytecode olarak yazar. java Ad JVM'i başlatır, sınıfı yükler ve main'i çağırır. Aynı bytecode JVM bulunan her platformda çalışır.
  • JVM bir yığın makinesidir: komutlar değerleri işlenen yığınına iter ve oradan alır. Yorumlayıcı bytecode'u çalıştırır, JIT derleyicisi sık çalışan kodu makine koduna çevirir.
  • Söz dizimi: deyimler ; ile biter, bloklar { } ile açılıp kapanır, Java büyük-küçük harfe duyarlıdır. Açıklamalar // ve /* */ ile yazılır.
  • İlkel tipler: byte 1, short 2, int 4, long 8 bayt; float 4, double 8 bayt; char 2 bayt; boolean. Sınırı aşan tam sayı hata vermeden taşar ve aralığın öbür ucuna sarar.
  • Ondalıklı sayılar ikili tabanda yaklaşık saklanır: 0.1 + 0.2 0,3 değildir. Ondalıklı sayılar == ile karşılaştırılmaz.
  • Adlar harf, rakam, _ ve $ içerir; rakamla başlamaz; anahtar kelime olmaz. Sınıflar PascalCase, değişkenler camelCase, sabitler BÜYÜK_HARF yazılır.
  • Atama: sağ taraf önce hesaplanır. += gibi bileşik atamalar dönüşümü kendileri yapar. Yerel değişkene okunmadan önce değer verilmelidir. final değişken bir kez değer alır.
  • Dönüşüm: byte → short → int → long → float → double yönü otomatiktir. Ters yön (tip) ile yapılır; kesir atılır, sığmayan değer taşar. int / int tam sayı bölmesidir ve dönüşüm bölmeden önce yapılmalıdır.
  • Operatörler: öncelik sırası tekli > * / % > + - > karşılaştırma > && > || > ?: > atama. && ve || kısa devre yapar. ?: bir değer üreten ifadedir.
  • Akış: if/else, switch (+ break), for, while (0 ya da daha çok tur), do-while (en az 1 tur). break çıkar, continue turun kalanını atlar.

2.2.10Kendini Dene

  1. Deneme.java adlı bir dosyada public class Test tanımlı. Dosya javac Deneme.java ile derlenmek isteniyor. Ne olur? Program nasıl çalıştırılır hâle getirilir?

    Cevap

    Derleme başarısız olur: class Test is public, should be declared in a file named Test.java. Public bir sınıfın adı dosya adıyla birebir aynı olmalıdır. Dosya Test.java adıyla kaydedilir, javac Test.java ile derlenir ve java Test ile (uzantısız) çalıştırılır.

  2. int a = 5, b = 7; int c = a * b; satırları derlendiğinde a * b hesaplanırken JVM'in işlenen yığınında hangi değerler bulunur? imul komutundan hemen sonra yığında ne kalır?

    Cevap

    Önce iload_1 5'i, sonra iload_2 7'yi yığına iter; yığında alttan üste 5, 7 durur. imul bu iki değeri çıkarır, çarpar ve sonucu iter: yığında yalnız 35 kalır. Ardından istore_3 35'i c'ye yazar ve yığın boşalır. Toplamadaki iadd ile aynı düzen geçerlidir.

  3. Aşağıdaki satır neden yanlış sonuç verir? Doğru değer nasıl elde edilir?
    long mikrosaniye = 24 * 60 * 60 * 1000 * 1000;

    Cevap

    Bütün sabitler int'tir ve çarpma int tipinde yapılır. Gerçek sonuç 86.400.000.000'dir ve int sınırını aşar; taşan değer 500654080 olur. long değişkene ancak bu taşmış değer atanır. İlk sabite L eklenince çarpma baştan long yürür: 24L * 60 * 60 * 1000 * 1000 = 86400000000.

  4. byte b = 120; b += 10; satırlarından sonra b kaçtır? Aynı iş b = b + 10; diye yazılsa ne olur?

    Cevap

    b = −126 olur. 130, byte sınırı 127'yi aşar; bileşik atama sonucu kendisi byte'a çevirir ve 130 − 256 = −126 kalır. b = b + 10; ise derlenmez: b + 10 bir int ifadesidir ve byte'a ancak (byte) ile atanabilir (possible lossy conversion from int to byte).

  5. Şu adlardan hangileri geçerli tanımlayıcıdır? _2x, x-2, int, Integer, toplam$, 9lu

    Cevap

    Geçerli: _2x (alt çizgiyle başlar), Integer (bir sınıf adıdır, anahtar kelime değildir; ama ad olarak kullanılması okuyanı şaşırtır), toplam$ ($ izinlidir). Geçersiz: x-2 (- çıkarma operatörüdür), int (anahtar kelime), 9lu (rakamla başlar).

  6. char c = '5'; iken System.out.println(c + 1); ve System.out.println(c - '0' + 1); ne yazdırır?

    Cevap

    Birinci satır 54 yazar: '5''in kodu 53'tür ve c + 1 bir int toplamıdır. İkinci satır 6 yazar: c - '0' = 53 − 48 = 5, yani rakamın sayı değeridir; buna 1 eklenir.

  7. int x = 7; int y = x-- - --x; satırlarından sonra x ve y kaçtır?

    Cevap

    İşlenenler soldan sağa hesaplanır. x-- eski değeri, 7'yi verir ve x 6 olur. --x önce x'i 5 yapar ve 5'i verir. y = 7 − 5 = 2, x = 5 olur.

  8. int a = 0; iken if (a != 0 & 10 / a > 1) ile if (a != 0 && 10 / a > 1) koşulları arasında ne fark vardır?

    Cevap

    Tek & kısa devre yapmaz ve iki tarafı da hesaplar. Sol taraf yanlış olsa da 10 / a bölmesi yapılır ve program ArithmeticException: / by zero ile durur. && ise sol taraf yanlış olunca sağ tarafa hiç bakmaz; koşul yanlış sayılır ve program güvenle sürer.

  9. int k = 3; ile başlayan iki döngünün sonunda k kaçtır?
    do { k -= 4; } while (k > 5);
    while (k > 5) { k -= 4; } (yine k = 3 ile başlayarak)

    Cevap

    do-while gövdeyi bir kez çalıştırır: k = −1 olur, -1 > 5 yanlıştır ve döngü biter; sonuç −1. while koşulu önce denetler: 3 > 5 yanlış olduğu için gövde hiç çalışmaz; sonuç 3.
