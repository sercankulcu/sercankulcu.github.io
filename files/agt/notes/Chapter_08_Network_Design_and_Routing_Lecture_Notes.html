Chapter 8: Network Design and Routing

How fast a road is depends on how many people choose it. This simple observation turns route choice in traffic and communication networks into a game: every user tries to shorten his or her own travel time, but the choice also changes everyone else's. These notes start from the basic notions of networks and routing and then develop selfish routing, Wardrop equilibrium and the system optimum; Braess's paradox, which shows that a new road can slow everybody down; congestion games and Rosenthal's potential; network formation games, in which the players build the network itself; and the tension between efficiency and fairness in networks.

8.1Networks and routing

All the ideas in this chapter revolve around a single tension: the users of a network want to shorten their own trips, but each user's choice also lengthens everyone else's. A small game makes this tension concrete. The basic notions of network, link, capacity and latency then form the language of all the calculations that follow.

8.1.1A first game: Braess's paradox

N drivers want to get from point S to point T. There are two routes: S→A→T (the upper route) and S→B→T (the lower route). Each route has one narrow road and one wide road. The time on a narrow road grows with the number of drivers using it: if x drivers are on a narrow road, the trip takes 40 · x / N minutes. If all drivers enter the same narrow road, the time rises to 40 minutes; if nobody does, the road is empty. The wide roads, on the other hand, are independent of traffic and always take 45 minutes.

The rule of the game is simple: every driver picks his or her own fastest route. Nobody cares about the others' travel times; everyone looks only at his or her own trip. This is “selfish” behavior, but it is not malicious. A commuter on the way to work also takes the fastest route suggested by a navigation app and is not expected to think about anyone else's trip.

Figure 8.1 shows the network of the game. Without the shortcut the two routes mirror each other. If the drivers split evenly between the two routes, each narrow road carries N/2 drivers and takes 40 · (N/2)/N = 20 minutes. Each route therefore takes 20 + 45 = 65 minutes. The game asks two questions:

  • If a shortcut taking 0 minutes opens from A to B, do trips get shorter?
  • When everyone picks his or her own fastest route, is the average time as small as possible?

Common sense answers “yes” to both. A new road adds capacity, and more capacity seems to mean less congestion. If everybody picks the fastest route, the result should surely be “fastest”. The most surprising result of this chapter is that the answer to both questions can be “no”. When the shortcut opens, every driver switches to the zigzag route (S→A→B→T) and everyone's time rises from 65 minutes to 80 minutes. All the steps of the calculation are given in 8.3.1.

8.1.2Network design and routing

Decisions about a network are made at two levels. The first level is building the network itself: which points will be connected, how much traffic can each link carry, and how much will construction cost? The second level is using the built network: along which paths will the traffic from one point to another flow?

Definition 8.1

Network design is the problem of determining the nodes, the links, and the capacities and costs of those links. Routing is the problem of determining which paths the flow between a source and a destination will use in a given network.

Figure 8.2 shows a small network with five nodes. The designer asks “should there be a link between a and b, and if so, how wide should it be?” Routing asks, once the network is built, “which edges should a packet or vehicle from s to t pass through?” The two problems are linked: a good design must take into account how users will choose paths in that network. Braess's paradox is exactly the price of ignoring this link.

Algorithmic game theory adds a new viewpoint to these problems. In classical network engineering, traffic is something that is “routed”: a central authority decides which path packets or vehicles take. In most real networks, however, the users themselves make the decisions. In a city every driver chooses his or her own route; on the Internet every network operator directs traffic according to its own interests. Algorithmic game theory studies such traffic and communication networks, in which users try to reduce their own costs. The main application areas are urban traffic, Internet backbones and power grids.

8.1.3Basic concepts: node, link, capacity, cost

Mathematically, a network is modeled as a graph. A graph consists of points and the lines joining them. Four basic concepts are used throughout this chapter.

  • Node: a point in the network. In urban traffic it is an intersection, on the Internet a router, in a power grid a substation.
  • Link or edge: a line joining two nodes. It may be a road, a fiber-optic line or a transmission line. A directed edge (s→a) can be used in one direction only, like a one-way street.
  • Capacity and bandwidth: the flow a link can carry per unit time, such as the number of vehicles a road can pass per hour or the number of bits a line can carry per second. When capacity is exceeded, latency rises rapidly.
  • Cost: of two kinds. Construction cost is paid when the network is built and affects design decisions. Usage cost is paid when the network is used: latency, energy spent or fees. Usage cost affects routing decisions.

How the nodes are connected to each other is called the topology of the network. Figure 8.3 shows four basic topologies.

Each topology has pros and cons. A star needs few links (n − 1 links for n nodes) and every node is one step from the hub, but if the hub fails the whole network fails. A ring also needs few links (n links) and survives a single break, but distant nodes are many steps apart. A full mesh connects every pair directly; distances are shortest, but the number of links is n(n − 1)/2 and grows quickly. A tree builds a layered structure and contains no cycles. Trees or layered topologies are common in data centers; a road network in a city is close to a mesh, because there are often several options between two points.

These topologies reappear in 8.5. The question asked there is which topology players who buy the links themselves finally settle on. When links are cheap, a full mesh emerges; when they are expensive, networks close to a star emerge.

8.1.4Classical routing algorithms

Finding the shortest path in a network where each edge has been assigned a number (a weight) is one of the basic problems of computer engineering. The weight can be a distance, a time or a cost. Table 8.1 summarizes four classical methods used in routing.

Table 8.1: Classical routing algorithms.
MethodWhat it doesNote
DijkstraSingle-source shortest paths with nonnegative weightsO((V + E) log V); the core of OSPF (Open Shortest Path First, a link-state protocol)
Bellman–FordAllows negative weights; updates by learning from neighborsO(V · E); its distributed version is RIP (a distance-vector protocol)
Dynamic routingRecomputes paths when link state and cost changeAdapts to traffic and failures
Load balancingSpreads traffic over several paths or serversE.g. ECMP (equal-cost multipath)

In the table, V is the number of nodes and E the number of edges. Dijkstra's algorithm starts at the source and, at each step, finalizes “the closest node among those whose distance is not yet final”. For the algorithm to work correctly the weights must be nonnegative: a distance that has been finalized cannot later be shortened by a negative edge. In the OSPF (Open Shortest Path First) protocol on the Internet, every router keeps a map of the whole network and runs Dijkstra on that map.

Example 8.1

The network of Figure 8.2 is given the following edge weights: s→a 2, s→b 4, a→b 3, a→c 3, b→c 2, c→t 1. Dijkstra starts at s.

  1. Initially the distance of s is 0 and the others are unknown (∞). s is finalized. Its neighbors are updated: 0 + 2 = 2 for a and 0 + 4 = 4 for b.
  2. Among the nonfinalized nodes the smallest estimate is a's (2). a is finalized. Its neighbors: 2 + 3 = 5 for b, but b's estimate is already 4; since 5 > 4 it does not change. 2 + 3 = 5 for c.
  3. The next smallest is b (4). b is finalized. For its neighbor c, 4 + 2 = 6 > 5; c does not change.
  4. Next is c (5). c is finalized. For its neighbor t, 5 + 1 = 6.
  5. Finally t is finalized (6). Tracing back, the path is t ← c ← a ← s: the shortest path is s→a→c→t, of length 2 + 3 + 1 = 6. This is the red path in the figure.

The Bellman–Ford algorithm works differently: each node updates its own estimate by looking at the distances its neighbors report, and this continues until the estimates stop changing. At most V − 1 rounds suffice and each round scans all the edges; that is why the running time is O(V · E). It is slower than Dijkstra but accepts negative weights. Its most important property is that it can run in a distributed way: no node needs to know the whole network, and everyone learns only from neighbors. The RIP protocol on the Internet is a distance-vector protocol built on this idea of “learning from the neighbor”.

Dynamic routing recomputes paths when a link goes down or its cost changes. Load balancing spreads traffic over several paths or servers instead of piling it onto one. ECMP (equal-cost multipath) is a simple form of this: if there are several shortest paths of equal length, the traffic is split among them.

All these algorithms share one assumption: the edge weights are fixed. Dijkstra accepts that edge a→c takes 3 minutes and treats this number as independent of who uses the edge. In reality, latency depends on how many people choose that path. In the example above, if every driver is told to take s→a→c→t, edge a→c becomes congested and no longer takes 3 minutes. When strategic users can deviate from the recommended route, the equilibrium of the network and the distribution that minimizes total latency come apart. This is what turns routing into a game: each user's “shortest path” depends on the others' choices.

8.1.5Latency depends on load

To model load-dependent latency, each edge is assigned a function instead of a number.

Definition 8.2

The latency function ℓe(x) of an edge e is the time a user spends on that edge when the flow on it is x. A latency function is nondecreasing: as the flow grows, the latency either stays the same or rises; it never falls.

The “nondecreasing” condition rests on common sense: a road does not get faster as more vehicles enter it. Four kinds of latency function are used in this chapter.

  • Constant: ℓ(x) = b. A wide highway unaffected by traffic. The 45-minute wide roads of the Braess example are like this.
  • Linear: ℓ(x) = a · x + b. Here b is the time on an empty road and a is how much each additional vehicle lengthens the time. The two-route network and the Braess examples use this kind; for instance ℓ(x) = 5 + x/100 takes 5 minutes on an empty road and every 100 vehicles add one minute.
  • BPR (US Bureau of Public Roads): ℓ(x) = t0 (1 + 0.15 (x/c)4). Here t0 is the free-flow time and c is the capacity of the road. It is the standard in traffic planning.
  • Queueing delay: ℓ(x) = 1/(c − x), only for 0 ≤ x < c. This is the average delay of a single-server queue (the M/M/1 queue). c is the number of packets that can be served per second and x the number arriving per second.

Figure 8.4 compares the shapes of the functions. The behavior of the BPR curve matches everyday experience: when a road is half full traffic is nearly free-flowing, near capacity the slowdown becomes noticeable, and once capacity is exceeded travel time grows rapidly. The fourth power ((x/c)4) produces this “slow at first, then fast” growth.

Example 8.2

Consider a road that takes t0 = 10 minutes when empty and has a capacity of c = 2,000 vehicles per hour.

  1. x = 1,000: x/c = 0.5, 0.54 = 0.0625. The latency is 10 · (1 + 0.15 · 0.0625) ≈ 10.09 minutes; it differs from the empty road by only 6 seconds.
  2. x = 2,000: x/c = 1. The latency is 10 · 1.15 = 11.5 minutes. At capacity the trip is 15% longer.
  3. x = 3,000: x/c = 1.5, 1.54 = 5.0625. The latency is 10 · (1 + 0.759) ≈ 17.6 minutes. The flow grew by only 50%, but the increase in latency is more than five times the increase at capacity (7.6 minutes against 1.5 minutes).

The same “wall” appears in queueing delay. Let c = 100 packets per second. At x = 50 the latency is 1/50 = 0.02 seconds (20 ms), at x = 90 it is 1/10 = 0.1 seconds (100 ms), and at x = 99 it is 1 second.

One property of queueing delay deserves a separate remark: as x approaches c, 1/(c − x) grows without bound. When x ≥ c the formula loses its meaning: more packets arrive than can be served per second, so the queue grows forever and there is no stable average delay. The formula is therefore valid only for x < c.

Common mistakes
  • Treating latency as constant: The time on a road depends on the number of users. Saying “this road takes 20 minutes” really means “this road takes 20 minutes with this many vehicles”.
  • Confusing edge latency with path latency: ℓe is the latency of a single edge. The latency of a path is the sum of the latencies of the edges on it (8.2.1).
  • Using the queueing formula above capacity: 1/(c − x) is undefined or negative for x ≥ c; this is not a “fast road” but an undefined (ever-growing) queue.

8.2Selfish routing

In a network with load-dependent latencies two questions stand out: how does traffic distribute itself when users choose on their own, and how good is that distribution in terms of total latency? The answer to the first question is the Wardrop equilibrium; the yardstick for the second is the system optimum.

8.2.1The model: flow, path latency, total latency

Definition 8.3

Selfish routing is routing in which every user picks the route that minimizes his or her own latency. If there are very many users and each is very small, the flow is taken to be nonatomic (divisible): the effect of a single user on the flow is neglected.

The nonatomic assumption is an approximation. A city has thousands of drivers, and one driver entering a road changes its travel time too little to notice. Thinking of traffic as a fluid rather than as individual vehicles makes the calculations easier. When there are few drivers and each one's effect is noticeable (four drivers, say), the model becomes atomic; this case is treated in 8.4.

The components of the model are the following:

  • r units of traffic go from the source s to the destination t. For example r = 3,000 cars.
  • fP: the flow on path P, that is, the amount of traffic choosing that path. The flows on all paths add up to r.
  • fe: the total flow on edge e. An edge can be part of several paths; the flows of all the paths containing that edge are added up: fe = ΣP ∋ e fP.

With these components two measures are defined. The latency of a path is the sum of the latencies of the edges on it:

ℓP(f) = Σe ∈ P ℓe(fe)

The total latency of the network is the sum over all edges of flow times latency:

C(f) = Σe fe · ℓe(fe)

An example shows why the total latency is written this way. If an edge carries 2,000 cars and each spends 25 minutes on it, the total time spent on that edge is 2,000 × 25 = 50,000 car-minutes. The unit “car-minute” denotes the sum of the minutes spent by every car. Adding these products over all edges gives the total time spent in the network.

The same total can also be computed over paths: multiply the flow of each path by that path's latency and add, C(f) = ΣP fP · ℓP(f). The two expressions give the same result. The reason is this: in the product fP · ℓP, since ℓP is a sum of edge latencies, the latency of each edge is multiplied by the flows of all the paths through that edge, and these flows add up to fe. Dividing the total latency by r gives the average travel time.

Individual route choices can drift away from the distribution that minimizes total latency. Braess's paradox is the most extreme form of this: adding a new link can increase the equilibrium latency. First we need to define how to measure this drift.

8.2.2Wardrop's principles

The British transport engineer John Glen Wardrop argued in 1952 that traffic flow can distribute itself in two different ways (Wardrop, 1952). These two principles are still the foundation of traffic planning.

Definition 8.4

Wardrop's first principle (user equilibrium). A flow f is a Wardrop equilibrium if the latency of every used path is no greater than the latency of any path:

fP > 0 ⇒ ℓP(f) ≤ ℓQ(f) for every path Q.

Wardrop's second principle (system optimum). A flow f* is a system optimum if it minimizes the total latency C(f) over all feasible flows.

The first principle can be read in three equivalent ways:

  • All used paths have equal latency, and it is the lowest.
  • An unused path is slower (or exactly as fast as the used ones).
  • A single user cannot reduce his or her travel time by switching paths.

Why must the latencies of used paths be equal? Suppose both paths are used but Route 1 is faster. Then a driver on Route 2 gains by switching to Route 1. This is incompatible with an equilibrium; an equilibrium is a state in which nobody wants to deviate alone. The third reading shows that the Wardrop equilibrium is in fact the idea of Nash equilibrium adapted to divisible traffic: every user plays a best response to the others' choices.

The second principle is the viewpoint of a planner. A central authority that can manage all traffic by itself chooses the distribution that minimizes the average (total) latency. In this distribution some users may be “sacrificed” to a slower route: their being on the slower route is compensated, in total, by the speed-up of the others. Implementing a system optimum is therefore hard; the sacrificed users must be willing to comply.

In short, the equilibrium explains the individual choices of the users, but it need not coincide with the system optimum. With linear latencies (more generally, with continuous nondecreasing latencies) a Wardrop equilibrium always exists. Moreover, even when there are several equilibria, the equilibrium latency of every edge is the same; whichever equilibrium is found, the travel times the users experience do not change. This result is explained with the Beckmann potential in 8.2.5.

8.2.3Wardrop equilibrium in a two-route network

The two-route network used throughout the chapter is as follows. 3,000 cars travel from A to B. Route 1 is short but narrow: it takes 5 minutes when empty, but every 100 cars add one minute. Route 2 is long but wide: it takes 20 minutes when empty, and every 200 cars add one minute.

ℓ1(x1) = 5 + x1/100, ℓ2(x2) = 20 + x2/200, x1 + x2 = 3,000

Since each route consists of a single edge, path latency and edge latency coincide here. To find the equilibrium we first make two “trials”; these trials show why the equilibrium must lie at a particular point.

The graph in Figure 8.5 lets us evaluate each trial at a glance. The horizontal axis shows the number of cars on Route 1, x1; the number on Route 2 is 3,000 − x1. The blue line rises as x1 grows (Route 1 gets crowded) and the red line falls as x1 grows (Route 2 empties). The point where the two lines cross is the point where the two routes take equally long.

Example 8.3
  1. Trial 1: everyone on Route 1. ℓ1(3,000) = 5 + 30 = 35 minutes; the empty Route 2 takes ℓ2(0) = 20 minutes. Every driver on Route 1 who switches to Route 2 gains 15 minutes. This is not an equilibrium.
  2. Trial 2: 1,500 / 1,500. ℓ1 = 5 + 15 = 20, ℓ2 = 20 + 7.5 = 27.5 minutes. This time those on Route 2 move to Route 1. Again this is not an equilibrium.
  3. The equilibrium condition. The two trials show that the equilibrium lies somewhere between 1,500 and 3,000. If both routes are used, the latencies must be equal: 5 + x1/100 = 20 + (3,000 − x1)/200.
  4. Solution. To get rid of the fractions, multiply both sides by 200: 1,000 + 2x1 = 4,000 + 3,000 − x1. Collecting the terms in x1 on one side gives 3x1 = 6,000, that is, x1 = 2,000 and x2 = 1,000.
  5. Latencies. ℓ1 = 5 + 20 = 25, ℓ2 = 20 + 5 = 25 minutes. The two routes take equally long.
  6. Check. A single driver who switches routes would also experience about 25 minutes on the other route (because the flow is divisible, the effect of a single driver is neglected). Nobody gains: this is a Wardrop equilibrium. The total latency is 3,000 × 25 = 75,000 car-minutes.

Figure 8.6 shows the equilibrium. To the left of the equilibrium point the blue line lies below the red one: Route 1 is faster and cars move to Route 1, so the point moves right. To its right the blue line is on top: Route 1 is slower and cars move to Route 2, so the point moves left. This “push” from both directions carries the flow to the crossing point. The equilibrium is therefore stable.

The equalization method is valid only when both routes are used. Can a route be faster than the other, empty route even while carrying all the traffic? For instance, if Route 1 were wide enough to stay faster than the empty Route 2 even with 3,000 cars (ℓ1(3,000) ≤ ℓ2(0)), the equilibrium would be the state in which everyone is on Route 1. Then the only used route is Route 1 and the unused Route 2 is slower; the second reading of the definition covers exactly this case. In short, if the solution of the equalization equation does not fall between 0 and r, the equilibrium is at an endpoint.

Example 8.4

6,000 cars; Route 1: ℓ1 = 10 + x1/200, Route 2: ℓ2 = 25 + x2/100.

  1. First the extreme cases are checked. If everyone is on Route 1, ℓ1 = 10 + 30 = 40 > ℓ2(0) = 25; those on Route 1 flee. If everyone is on Route 2, ℓ2 = 25 + 60 = 85 > ℓ1(0) = 10; those on Route 2 flee. So both routes are used.
  2. Equality: 10 + x1/200 = 25 + (6,000 − x1)/100. Multiply both sides by 200: 2,000 + x1 = 5,000 + 12,000 − 2x1.
  3. Collecting terms, 3x1 = 15,000, x1 = 5,000, x2 = 1,000.
  4. Check: ℓ1 = 10 + 25 = 35, ℓ2 = 25 + 10 = 35 minutes. Both are 35 minutes; the total latency is 6,000 × 35 = 210,000 car-minutes.

8.2.4Equilibrium is not the system optimum

At the equilibrium everyone travels 25 minutes and the total is 75,000 car-minutes. Is this the smallest possible total latency? To find out, write the total latency as a function of x1:

C(x1) = x1 · ℓ1(x1) + x2 · ℓ2(x2), x2 = 3,000 − x1

A few values of this function are given in Table 8.3. The table shows that the lowest point of the curve is not at the equilibrium (2,000) but at 1,500.

To find the optimum exactly, without scanning a table, we use the notion of marginal cost. The marginal cost of a route is the amount that adding one more car to that route adds to the total latency.

Why this amount exceeds the route's own latency can be seen as follows. With x1 cars on Route 1, add one more car. The new car itself experiences a latency of ℓ1. But it also makes the road slightly more crowded: the latency rises by ℓ1′ = 1/100 minute for every car, and all the other x1 cars on the road experience this increase. In total an extra latency of x1 · ℓ1′ arises. The marginal cost is the sum of these two parts:

(x · ℓ(x))′ = ℓ(x) + x · ℓ′(x)

This formula is the product rule ((uv)′ = u′v + uv′) applied to this case. Here the derivative can be read as “how much the output grows when the input grows by one unit”. For linear latencies the calculation is easy:

  • Route 1: x1 · ℓ1 = 5x1 + x1²/100. The derivative of 5x1 is 5; the derivative of x1²/100 is 2x1/100 = x1/50. The marginal cost is 5 + x1/50.
  • Route 2: x2 · ℓ2 = 20x2 + x2²/200. The marginal cost is 20 + x2/100.

At the system optimum the marginal costs of the two routes must be equal. The reason is the same argument as for the equilibrium, now from the planner's point of view: if the marginal cost of Route 1 were higher, moving one car from Route 1 to Route 2 would reduce the total latency. The planner keeps moving cars until no such improvement remains; where it stops, the marginal costs are equal.

Figure 8.7 shows the total latency curve. The curve is bowl-shaped: at the ends (all traffic on one route) the total latency is very large, and somewhere in the middle it is smallest. The equilibrium point lies to the right of the bottom of the bowl.

Example 8.5
  1. The marginal costs are equalized: 5 + x1/50 = 20 + (3,000 − x1)/100.
  2. Multiply both sides by 100: 500 + 2x1 = 2,000 + 3,000 − x1, that is, 3x1 = 4,500.
  3. x1 = x2 = 1,500. The traffic is split evenly between the two routes.
  4. Latencies: ℓ1 = 20, ℓ2 = 27.5 minutes. Total: 1,500 × 20 + 1,500 × 27.5 = 30,000 + 41,250 = 71,250 car-minutes.
  5. Check: the marginal costs are 5 + 1,500/50 = 35 and 20 + 1,500/100 = 35; they are equal.

Why does the optimum not arise on its own? At the optimum a driver on Route 1 experiences 20 minutes and a driver on Route 2 experiences 27.5 minutes. Every driver on Route 2 sees that switching to Route 1 would gain 7.5 minutes, and switches. So the optimum is not an equilibrium: traffic left to itself does not stay at the optimum but slides to the equilibrium. To maintain the optimum, the 1,500 drivers on Route 2 would have to accept being “sacrificed”.

The source of the inefficiency at equilibrium can also be seen through marginal costs. At the equilibrium (x1 = 2,000) the marginal cost of Route 1 is 5 + 2,000/50 = 45 and that of Route 2 is 20 + 1,000/100 = 30. Moving one car from Route 1 to Route 2 would reduce the total latency by about 45 − 30 = 15 car-minutes. But the driver of that car does not see this: he or she looks only at his or her own time and, experiencing 25 minutes on both routes, is content where he or she is.

Example 8.6

Find the system optimum of the network of Example 8.4 (6,000 cars; ℓ1 = 10 + x1/200, ℓ2 = 25 + x2/100).

  1. Marginal costs: for Route 1, 10 + 2x1/200 = 10 + x1/100; for Route 2, 25 + 2x2/100 = 25 + x2/50.
  2. Equality: 10 + x1/100 = 25 + (6,000 − x1)/50. Multiply both sides by 100: 1,000 + x1 = 2,500 + 12,000 − 2x1, that is, 3x1 = 13,500.
  3. x1 = 4,500, x2 = 1,500. The latencies are ℓ1 = 10 + 22.5 = 32.5, ℓ2 = 25 + 15 = 40 minutes.
  4. Total: 4,500 × 32.5 + 1,500 × 40 = 146,250 + 60,000 = 206,250 car-minutes. This is 3,750 less than the 210,000 at equilibrium. At the optimum the drivers on Route 2 are 7.5 minutes slower and want to switch to Route 1.

8.2.5Two different minimizations: the Beckmann potential

The system optimum is the minimum point of a function (C). Can the Wardrop equilibrium also be written as the minimum point of a function? Martin Beckmann, C. B. McGuire and C. B. Winsten showed in 1956 that it can (Beckmann, McGuire, Winsten, 1956).

Definition 8.5

In a nonatomic routing problem the Beckmann potential is

Φ(f) = Σe ∫0fe ℓe(t) dt

The integral in the formula is not as hard as it looks. ∫0fe ℓe(t) dt is the area under the latency curve between 0 and fe. It is easy to think of it as a sum: let the traffic enter the edge a little at a time. The first driver sees the empty road, that is ℓe(0); the next ones see a slightly more crowded road; the last one sees ℓe(fe). The area is the sum of the latencies each driver sees at the moment of entering. The total latency fe · ℓe(fe), by contrast, charges everyone the latency of the final state; this is why the potential is generally smaller than the total latency.

For a linear latency ℓ(t) = b + a · t the area is a trapezoid and is easy to compute: ∫0x (b + a t) dt = b x + a x²/2. In the two-route network:

Φ(x1) = 5x1 + x1²/200 + 20x2 + x2²/400

Take the derivative of this function with respect to x1. Since x2 = 3,000 − x1, when x1 grows by one unit x2 shrinks by one unit. The derivative of the Route 1 part is 5 + x1/100 = ℓ1; the Route 2 part decreases by ℓ2. The result:

Φ′(x1) = ℓ1(x1) − ℓ2(x2)

The point where the derivative is zero is the point where ℓ1 = ℓ2; this is exactly the Wardrop condition. The derivative of the potential is the latency seen by “the last driver”. A selfish driver looks at exactly this: on entering a route, he or she sees the current latency.

Theorem 8.1 (Beckmann, McGuire, Winsten)

If the latency functions are continuous and nondecreasing, a flow f is a Wardrop equilibrium if and only if it minimizes the Beckmann potential Φ over all feasible flows. The system optimum, on the other hand, is the flow that minimizes the total latency C(f) = Σe fe · ℓe(fe).

The theorem has two important consequences. The first is existence: the set of feasible flows is closed and bounded, and a continuous function attains its minimum on such a set; hence a Wardrop equilibrium always exists. The second is uniqueness: since the latencies are nondecreasing, Φ is a “bowl-shaped” (convex) function. A bowl-shaped function can have several minimum points, but on the line segment between two minimum points Φ stays constant. This is possible only if the latency of every edge whose flow changes is constant along that segment; so at all minimum points the edge latencies are the same. This is the basis of the sentence in 8.2.2 that “whichever equilibrium is found, the edge latencies are the same”.

Figure 8.8 puts the two curves side by side. The numbers in Table 8.3 say the same thing: Φ takes its smallest value at 2,000 (52,500) and C takes its smallest value at 1,500 (71,250). The equilibrium is the bottom of the potential; the optimum is the bottom of the total latency. The two bottoms are in different places because the derivatives of the two functions differ:

  • The derivative of Φ with respect to an edge is ℓe: the latency seen by the last driver to arrive.
  • The derivative of C with respect to an edge is ℓe + fe · ℓe′: the marginal cost.

The difference comes from a single term: fe · ℓe′. This term is the extra latency a driver imposes on the others merely by being there. The driver does not take this externality into account. At the equilibrium on Route 1 this term is 2,000 × 1/100 = 20 car-minutes: every new driver entering Route 1 slows each of the 2,000 people there by 1/100 minute. The notion of externality is studied separately in 8.5.1.

8.2.6Code trace: find_eq()

In the two-route network it is easy to find the equilibrium by solving an equation. When the latencies are not linear (BPR, for example), solving the equation by hand becomes hard, and a numerical method is used instead. The function below searches for the equilibrium by bisection. Its inputs are the two latency functions l1 and l2, the total traffic r and the desired precision eps.

def find_eq(l1, l2, r, eps=50):
  if l1(0) >= l2(r): return 0   # route 1 unused
  if l1(r) <= l2(0): return r   # all on route 1
  lo, hi = 0, r
  while hi - lo > eps:
    x = (lo + hi) / 2
    if l1(x) < l2(r - x):
      lo = x      # route 1 faster: raise
    else:
      hi = x      # route 1 slower: lower
  return (lo + hi) / 2

The code works as follows:

  • The first two lines check the extreme equilibria. If Route 1, even when empty, is no faster than a completely full Route 2 (l1(0) >= l2(r)), nobody uses Route 1 and the equilibrium is 0. If Route 1, even when completely full, is no slower than an empty Route 2, everyone uses Route 1 and the equilibrium is r.
  • lo and hi are the ends of the interval known to contain the equilibrium. At first the interval is [0, r]: the number of cars on Route 1 must be between 0 and r.
  • The loop runs as long as the width of the interval is greater than eps.
  • In each round the midpoint x of the interval is tried. There are x cars on Route 1 and r - x on Route 2.
  • If l1(x) < l2(r - x), Route 1 is still faster. Cars want to move to Route 1; the equilibrium lies further right. The left end of the interval moves to x.
  • Otherwise Route 1 is too crowded; the equilibrium lies further left. The right end of the interval moves to x.
  • When the loop ends, the middle of the interval is returned.

The reason the method works is this: the difference g(x) = ℓ1(x) − ℓ2(r − x) never decreases with x, because as x grows Route 1 gets slower and Route 2 gets faster. If the latencies are strictly increasing, g is strictly increasing too; a strictly increasing function has at most one zero, and that zero is the equilibrium. If Route 1 is faster at x = 0 (g < 0) and slower at x = r (g > 0), as in the example, the zero lies between the two. If one route is faster in every case (for example g(r) ≤ 0), the equilibrium is at an endpoint and everyone uses that route; the first two lines of the code catch this case beforehand and return the endpoint exactly. Since each round halves the interval and always keeps the zero inside it, the search closes in on the zero.

This method works only in two-route networks, because there is a single unknown (x1). In general networks with many routes, the equilibrium is the flow that minimizes the Beckmann potential and is found with convex optimization methods. The method most widely used in traffic planning is the Frank–Wolfe algorithm: at each step it finds shortest paths under the current latencies (with Dijkstra, for example) and shifts the flow a little toward those paths.

8.2.7Common mistakes in selfish routing

Common mistakes
  • Taking the equilibrium to be an “even split”: The equilibrium does not split traffic evenly among the routes; it equalizes the latencies. In the two-route network the even split (1,500 / 1,500) is not the equilibrium but the optimum.
  • Using the equalization equation blindly: The equation is valid only when both routes are used. If the solution comes out negative or greater than r, the equilibrium is at an endpoint.
  • Equalizing latencies at the optimum: At the optimum what is equalized is the marginal costs (ℓ + x · ℓ′), not the latencies. At the optimum the route times are usually different (20 and 27.5).
  • Doubling the constant when differentiating: (x · (5 + x/100))′ = 5 + x/50, not 10 + x/50. The extra term comes only from x · ℓ′.
  • Mistaking total latency for an average: 75,000 car-minutes is a total; the average travel time is 75,000 / 3,000 = 25 minutes.
  • Confusing the potential with the total latency: Φ is not a “cost” but an auxiliary function used to find the equilibrium. Its value (52,500) does not represent an actual total time.

8.3Braess's paradox

In 1968 the German mathematician Dietrich Braess published a short paper on traffic planning (Braess, 1968). What it showed was simple but disturbing: adding a new road to a network can lengthen everyone's trip, because of selfish route choice.

8.3.1Braess's paradox step by step

The setup is the same as the game in 8.1.1, except that the number of drivers is now concretely 4,000. 4,000 cars go from s to t. s→A and B→t are narrow roads: with x cars they take x/100 minutes. A→t and s→B are wide highways: they take 45 minutes regardless of traffic. Putting N = 4,000 into the formula 40 · x/N of the game gives x/100; the two descriptions are the same.

Example 8.8
  1. Without the shortcut. There are two routes: upper (s→A→t) and lower (s→B→t). The network is symmetric; each route has one narrow and one wide road. If there are x cars on the upper route, the upper route takes x/100 + 45 and the lower route (4,000 − x)/100 + 45 minutes. Equality gives x = 2,000. Each route takes 20 + 45 = 65 minutes. A driver who switches routes gains nothing: this is a Wardrop equilibrium. By symmetry it is also the optimum.
  2. The shortcut opens. The city opens a very short connecting road from A to B that takes 0 minutes. At first nobody uses it.
  3. The first driver tries it. A single driver tries the zigzag route (s→A→B→t). There are 2,000 cars on s→A (20 minutes), A→B takes 0 minutes, and there are 2,000 cars on B→t (20 minutes). The total is 20 + 0 + 20 = 40 minutes. On the old route this driver experienced 65 minutes; he or she gains 25 minutes. Individually this is very profitable, and the driver switches.
  4. The shift continues. Say 1,000 drivers have moved to the zigzag; 1,500 drivers remain on each old route. Each narrow road now carries 1,500 + 1,000 = 2,500 cars and takes 25 minutes. The old routes take 25 + 45 = 70 and the zigzag takes 25 + 0 + 25 = 50 minutes. The zigzag is still much faster; the shift continues.
  5. Everyone on the zigzag. All 4,000 drivers are on the zigzag. Each narrow road carries 4,000 cars (40 minutes). The zigzag takes 40 + 0 + 40 = 80 minutes.
  6. Equilibrium check. A driver who goes back to an old route uses one narrow road (40 minutes) and one wide road (45 minutes): 40 + 45 = 85 minutes. Since 85 > 80, nobody goes back. This is the new Wardrop equilibrium.

Result: a road was added and everyone lost 15 minutes. The total latency rose from 260,000 to 4,000 × 80 = 320,000 car-minutes.

In the same network (narrow roads x/100, wide roads 45 minutes) let the number of cars be 6,000. Find the equilibrium time before and after the new road.

  1. Before: by symmetry 3,000 / 3,000. Each route takes 30 + 45 = 75 minutes.
  2. After: can everyone be on the zigzag? With 6,000 cars on the narrow roads the zigzag takes 60 + 0 + 60 = 120 minutes. A driver who goes back to an old route experiences 60 + 45 = 105 minutes. Since 105 < 120, going back pays; this is not an equilibrium.
  3. The equilibrium in which traffic splits. Let z cars be on the zigzag and y on each old route. Both the upper route and the zigzag use the road s→A; the flow on it is y + z. The same holds for B→t. The three used routes must take equal time: the zigzag takes 2(y + z)/100 and an old route (y + z)/100 + 45. Equality gives (y + z)/100 = 45, that is, y + z = 4,500.
  4. Flow conservation. All the cars must be counted: 2y + z = 6,000. The two equations give y = 1,500 and z = 3,000.
  5. Time. 4,500 cars on the narrow roads (45 minutes). Every route takes 45 + 45 = 90 minutes. The paradox appears again: from 75 to 90. This time some drivers stay on the old routes, but everyone's time is 15 minutes longer.

8.3.2Why does everyone take the zigzag?

In the 4,000-car example, everyone's switching to the zigzag is no coincidence. The zigzag route is faster than the old routes however the remaining traffic is distributed. To see this, let z be the number of cars on the zigzag and split the remaining 4,000 − z cars evenly between the two old routes.

  • Each old route carries (4,000 − z)/2 = 2,000 − z/2 cars.
  • The flow on s→A is the sum of those on the upper route and those on the zigzag: 2,000 − z/2 + z = 2,000 + z/2. The time is 20 + z/200 minutes. The same holds for B→t.
  • Old route: one narrow road and one wide road, 20 + z/200 + 45 = 65 + z/200 minutes.
  • Zigzag: two narrow roads and the shortcut, 2 · (20 + z/200) + 0 = 40 + z/100 minutes.

Figure 8.13 shows the two lines. The zigzag would be slower than the old routes only if 40 + z/100 ≥ 65 + z/200; that means z/200 ≥ 25, that is, z ≥ 5,000. But there are only 4,000 cars. So the zigzag is faster in every case.

The same conclusion can be reached by a shorter route. The second half of the zigzag is B→t; even when it is most crowded it takes at most 4,000/100 = 40 minutes. The first half of the old lower route, s→B, always takes 45 minutes. So going from s to B by way of A (s→A takes at most 40 minutes) is always faster than taking the highway directly (45 minutes). Symmetrically, going from A to t by way of B is always faster. The zigzag is a dominant choice for every driver: it is better whatever the others do.

The resemblance to the Prisoner's Dilemma is clear. In that game betrayal is the dominant strategy for each player, but when everybody betrays everybody ends up worse off. Here too the zigzag is dominant for everyone, but each driver who switches loads the narrow roads. At z = 4,000 everyone experiences 80 minutes; had the shortcut never existed, everyone would have experienced 65.

8.3.3The system optimum of the network with the shortcut

The shortcut itself is not bad. What is bad is its selfish use. To see this, compute the system optimum of the network with the shortcut: how should a planner distribute the traffic to make the average time as small as possible?

Example 8.10
  1. By symmetry the two old routes are given equal numbers of cars (y); z cars are on the zigzag, 2y + z = 4,000. The flow on the narrow roads is a = y + z.
  2. The total latency is written edge by edge. On each narrow road a cars spend a/100 minutes: the two narrow roads together contribute 2 · a · a/100 = a²/50. On the wide roads a total of 2y cars spend 45 minutes: 90y. The shortcut contributes 0. Since y = 4,000 − a, C(a) = a²/50 + 90 (4,000 − a).
  3. Set the derivative to zero: C′(a) = a/25 − 90 = 0, that is, a = 2,250. From this y = 1,750 and z = 500.
  4. Total: 2,250²/50 + 90 · 1,750 = 101,250 + 157,500 = 258,750 car-minutes. The average is 258,750 / 4,000 ≈ 64.7 minutes.
  5. In this distribution the narrow roads take 22.5 minutes. The 500 drivers on the zigzag experience 22.5 + 22.5 = 45 minutes, and the 3,500 drivers on the old routes 22.5 + 45 = 67.5 minutes.

At the optimum the zigzag is given a small share (500 cars) and the average time falls slightly from 65 to 64.7. Used correctly, the shortcut brings a small improvement. But this distribution is not an equilibrium: drivers on the old routes experience 67.5 minutes and those on the zigzag 45, so all the drivers on the old routes want to switch to the zigzag. 8.3.4The lesson of the paradox and real examples

Definition 8.6

Braess's paradox is the phenomenon that adding a new link to a network can, because of selfish route choice, increase the equilibrium latency, even the latency of all users (Braess, 1968).

The logic of the paradox is this: the new road looks attractive individually, but the traffic pattern the users form together moves to a worse equilibrium. The converse is also true: closing a road can sometimes speed everybody up. In the Braess network, closing A→B lowers everyone's time from 80 to 65 minutes.

The paradox has not stayed on paper. There are a few frequently cited examples:

  • Stuttgart (1969). After a new road investment in the city center, traffic is said to have worsened, and to have improved when a street was closed (Knödel, 1969).
  • New York (1990). When 42nd Street was closed to traffic on Earth Day, the expected congestion is reported not to have materialized (Kolata, 1990).
  • Seoul. The elevated highway over the Cheonggyecheon stream was removed in the early 2000s and turned into an urban park. It is often cited that city traffic afterwards did not worsen as much as expected.
  • Mechanical and electrical networks. A similar paradox has been demonstrated in networks built from springs and resistors: cutting a spring can raise a hanging weight (Cohen and Horowitz, 1991).
  • Laboratory experiments. When subjects chose routes in a computer environment, they drifted over time to the slower equilibrium predicted by the paradox once a shortcut was added (Rapoport et al., 2009).

These examples must be interpreted carefully. Real networks are far more complicated; when a street is closed, some drivers switch to public transport and some change their travel time. The examples are therefore not conclusive proof of the paradox but an indication that it is possible. The lesson is clear, though: building or closing a road must be judged not only by capacity but by the equilibrium the drivers will reach. There are also ways to reduce the effect of the paradox: pricing, access restrictions or centralized routing. These are discussed in 8.6.

8.3.5Code trace: best_subnet()

Braess's paradox makes the network designer ask a new question: which edges of the given network should be closed to lower the equilibrium time the most? The function below solves a simple version of this question: it tries closing a single edge.

def best_subnet(net, r):
  best, cut = eq_time(net, r), None
  for e in net:
    sub = [k for k in net if k != e]
    d = eq_time(sub, r)   # inf if no path
    if d < best:
      best, cut = d, e
  return cut, best

The function uses a helper function called eq_time(net, r). It returns the common time of the paths used in the Wardrop equilibrium of the given subnetwork. In the script this time is computed by minimizing the Beckmann potential (8.2.5). If no path from s to t remains, it returns infinity (inf). The code works line by line as follows:

  • best is the smallest equilibrium time found so far; at first it is the time of the network with nothing removed. cut holds which edge was removed; at first it is None (none).
  • The loop tries each edge e of the network in turn.
  • sub is the subnetwork consisting of all edges other than e.
  • d is the equilibrium time of this subnetwork.
  • If d is strictly smaller than the best so far, the candidate is updated.
  • At the end the edge to remove and the new equilibrium time are returned.

8.3.6Network design for selfish users

The question can be stated formally: for which subnetwork of the given network is the time at the Wardrop equilibrium smallest? Here, closing a road rather than building one is also a design decision. Two results outline the difficulty and the limits of this problem.

Hardness. In 2006 Tim Roughgarden showed that this problem is computationally hard (Roughgarden, 2006). With linear latencies, even closing no edge at all is at most 4/3 times worse than the best choice. But guaranteeing anything better than this efficiently is NP-hard: an efficient algorithm cannot be expected to find, on every network, a subnetwork noticeably better than the option of “closing nothing”. In the Braess example the ratio is below this bound: 80/65 ≈ 1.23 < 4/3 ≈ 1.33.

Topology. In 2006 Igal Milchtaich determined in which networks the paradox can never occur (Milchtaich, 2006). In series-parallel networks Braess's paradox never occurs, however the latencies are chosen. A series-parallel network is one built by joining edges one after another (in series) or side by side (in parallel). The two-route example is of this kind: two edges are connected in parallel between s and t. In other networks the paradox can occur with suitable latencies.

Figure 8.15 compares the two structures. The Braess network is the Wheatstone network on the right; it takes its name from the Wheatstone bridge in electrical circuits. The A→B bridge “crosses” two parallel routes. Such a cross cannot be built by series and parallel composition. By Milchtaich's result, a necessary and sufficient condition for a two-terminal network to be immune to the paradox is that it contain no Wheatstone structure, which is the same as the network being series-parallel. Networks with cycles, or complete graphs, generally contain a Wheatstone structure and give no such guarantee.

8.3.7Common mistakes about Braess's paradox

Common mistakes
  • Taking the shortcut to be a “bad road”: The shortcut itself is not bad; it is used at the optimum and lowers the average slightly (64.7). The problem is selfish use.
  • Forgetting flow conservation: The flow on s→A is not only those on the upper route; those on the zigzag use that road too (y + z).
  • Assuming everyone always switches to the zigzag: With 6,000 cars the zigzag is not dominant; the equilibrium splits the traffic (3,000 on the zigzag, 1,500 on each old route).
  • Assuming the paradox appears in every network and at every traffic level: It never appears in series-parallel networks. Even in the Braess network, when traffic is very light the shortcut can be genuinely useful; the paradox arises in a certain range of traffic.
  • Limiting the closing decision to a single edge: The best subnetwork may require closing several edges; trying a single edge is only a heuristic.

8.4Congestion games

The nonatomic traffic model suits thousands of small users. But in some cases the number of players is small and each one's effect is noticeable: a few large freight companies, a few data centers, or a few applications sending packets over a network. The model in which the players can be counted one by one is called the atomic model. For this model too there is a powerful tool showing that selfish choices reach an equilibrium: Rosenthal's potential.

8.4.1Congestion games: atomic and nonatomic

Definition 8.7

A congestion game consists of the following components:

  • n players and a set of resources E (for example the edges of a network).
  • The strategy of each player is a subset of the resources (for example an s–t path, that is, the edges of that path).
  • The cost ce(ne) of each resource e depends only on the number ne of players using it and increases with this load.
  • A player's cost is the sum of the costs of the resources chosen: ci(s) = Σe ∈ si ce(ne).

The important point in the definition is that the cost of a resource depends on how many use it, not on who uses it. It makes no difference whether a path carries Ali and Ayşe or Can and Deniz; if there are two users, the cost is ce(2). While the players try to reduce their own latencies, the total network cost may rise; Braess's paradox appears in the atomic model too (8.4.3).

In the atomic model, when a player switches paths, the user count of every edge on the new path rises by one. The player must therefore count himself or herself when computing the cost of the new path: a player moving to an edge currently used by 2 people pays ce(3), not ce(2). This small detail is the source of the most frequent mistake in atomic calculations.

In 1973 Robert Rosenthal showed an important property of congestion games: every finite congestion game has a potential function, so a pure Nash equilibrium always exists (Rosenthal, 1973). This is a remarkable result. In general games a pure equilibrium may not exist; in Rock–Paper–Scissors only a mixed equilibrium exists. In congestion games mixed strategies are not needed.

8.4.2Rosenthal's potential function

Definition 8.8

In a strategy profile s, let ne be the number of players using resource e. Rosenthal's potential is

Φ(s) = Σe [ ce(1) + ce(2) + … + ce(ne) ]

On each edge the costs from 1 up to the number of users ne are added. This is not the total cost. In the total cost each of the ne users on that edge pays ce(ne), and the edge contributes ne · ce(ne). In the potential, the users are imagined to enter the edge one after another: the first to arrive “pays” ce(1), the second ce(2), the last ce(ne). This is the atomic counterpart of the “area under the curve” in the Beckmann potential: a sum replaces the integral.

Figure 8.16 shows this sum as bars. On edge s→A, whose cost grows with the number of users, the bars rise like a staircase; on edge A→t, whose cost is constant, they are all the same height.

Example 8.11

The atomic version of the Braess network has 4 drivers. Edge costs: ce(k) = k on s→A and B→t (k: number of users), 4 on s→B and A→t, 0 on A→B. All 4 drivers are on the path s→A→t (upper).

  1. There are 4 users on s→A: the contribution is 1 + 2 + 3 + 4 = 10.
  2. There are 4 users on A→t: the contribution is 4 + 4 + 4 + 4 = 16.
  3. s→B, B→t and A→B are empty: the contribution is 0.
  4. Φ = 10 + 16 = 26.
  5. For comparison, the total cost: each driver pays c(s→A) + c(A→t) = 4 + 4 = 8; the total is 4 × 8 = 32. The potential (26) differs from the total cost (32).

What makes the potential valuable is the following identity.

Theorem 8.2 (Rosenthal)

In a congestion game, if a single player i changes strategy (the others fixed), the change in the potential is exactly equal to the change in that player's cost:

ΔΦ = ci(new) − ci(old)

Therefore every finite congestion game has a pure Nash equilibrium, and any sequence of improving moves always stops after a finite number of steps.

Let player i move from the old strategy P to the new strategy P′. The edges fall into three groups, and we look at how Φ changes in each group.

(1) Edges on both P and P′: i keeps using these edges and their user counts do not change. The contribution of these edges to Φ stays the same. The cost i pays on these edges also stays the same.

(2) Edges only on P: i leaves these edges and the user count falls from ne to ne − 1. The last term ce(ne) of the sum for this edge is deleted. This term is the cost i paid on that edge in the old state.

(3) Edges only on P′: i enters these edges and the user count rises from ne to ne + 1. A new term ce(ne + 1) is added to the sum. This term is the cost i will pay on that edge in the new state.

Combining the three groups, the change in Φ is “the added terms minus the deleted terms”; this is i's new cost minus the old cost. The common edges cancel in the difference because they are the same on both sides. Thus ΔΦ = ci(new) − ci(old).

If a player makes a move that lowers his or her cost (ci(new) < ci(old)), Φ strictly decreases. Since the game is finite, the number of strategy profiles is finite, and Φ therefore takes only finitely many values. A strictly decreasing sequence cannot go on forever among finitely many values. So the improving moves stop at some point. Where they stop, no player can lower his or her cost alone; by definition this is a pure Nash equilibrium. ∎

The proof has one more consequence: the profile that gives the smallest value of Φ over all profiles is also a pure Nash equilibrium. For there, a move lowering any player's cost would lower Φ still further, which contradicts being at the minimum.

8.4.4Potential games: what have we gained?

Rosenthal's idea generalizes beyond congestion games. In 1996 Dov Monderer and Lloyd Shapley gave this generalization a name (Monderer and Shapley, 1996).

Definition 8.9

A game is called an (exact) potential game if there is a function Φ that reproduces exactly the cost change of every player under every unilateral deviation: for every i, every si, si′ and every s−i

Φ(si′, s−i) − Φ(si, s−i) = ci(si′, s−i) − ci(si, s−i)

Φ is called the potential function.

The potential function gathers the selfish moves of all the players into a single “common measure”. Every player wants to lower his or her own cost; in a potential game every move that does so also lowers the common measure. The players are, without knowing it, working to minimize the same function. This viewpoint brings several gains:

  • Existence. The state that gives the smallest value of Φ is a pure Nash equilibrium; an equilibrium always exists.
  • Convergence. A sequence of improving moves cannot go on forever. This property is called the finite improvement property. Every best-response dynamics stops.
  • Learning. The players do not need to “know” the equilibrium. Best-responding in turn is enough to reach it. This is a strong explanation of why equilibria can arise in real life.
  • Efficiency. The equilibrium that minimizes Φ is one way to choose a good equilibrium among the equilibria, because Φ is closely related to the total cost. But this is no guarantee: in the network of Example 8.13, Φ = 20 in all four equilibria, while their total costs range from 26 to 32.
  • Generality. Every (exact) potential game is equivalent to a congestion game (Monderer and Shapley, 1996). In other words, congestion games are not merely a “typical” example of potential games; they are exactly equivalent to them.

There is also a limit: speed. The dynamics are guaranteed to stop, not to stop quickly. Φ decreases by at least some amount at each step, but its initial value can be very large and the number of steps can grow exponentially with the number of players. In 2004 Alex Fabrikant, Christos Papadimitriou and Kunal Talwar showed that finding a pure equilibrium in general congestion games is PLS-complete (Fabrikant, Papadimitriou, Talwar, 2004). PLS is the complexity class of problems of finding a “locally optimal” solution. Being PLS-complete means that no fast method is known for finding an equilibrium in some congestion games. In simple cases (for example symmetric network games, in which all players go from the same source to the same destination) the equilibrium can be found quickly by reduction to a flow problem.

8.4.5Common mistakes with potentials

Common mistakes
  • Taking the potential to be the total cost: On an edge with ce(k) = k and 4 users, the contribution to Φ is 1 + 2 + 3 + 4 = 10, while the contribution to the total cost is 4 · 4 = 16.
  • Not counting oneself on the new route: A player moving to an edge raises that edge's user count by one. A player moving to an edge currently used by 3 people pays ce(4).
  • Changing a common edge twice: A player who is on an edge in both the old and the new route stays there; the user count of that edge does not change (had driver 1 moved to the zigzag instead of the lower route, 4 people would have stayed on s→A).
  • Taking the equilibrium to be a maximum of Φ: Cost-reducing moves decrease Φ; an equilibrium is a (local) minimum of Φ.
  • Taking stopping to mean speed: The finite improvement property says that the dynamics stop, not in how many steps; in general this number can be exponential.

8.5Network formation

Up to here the network was taken as given; the users decided only which route to take. In network formation games the players build the network itself. On the Internet, network operators decide for themselves which links to set up with each other; in social networks people choose whom to befriend; in peer-to-peer (P2P) file-sharing networks every computer chooses which computers to connect to. The basic concept behind these decisions is externality.

8.5.1Network externalities: negative and positive

Definition 8.10

Externality: a user's decision changes the cost or the benefit of others, but the user does not include this effect in his or her own calculation. If the effect harms others it is a negative externality; if it benefits them, a positive one.

Negative externality: congestion. Every additional driver entering a road slows each of the other x people on the same road by ℓ′(x), imposing a total latency of x · ℓ′(x). In the two-route example, with 2,000 cars on Route 1 (ℓ1′ = 1/100) this burden is 2,000 × 1/100 = 20 car-minutes. The new driver sees his or her own 25 minutes, not the 20 car-minutes imposed on the others. The result: the crowded route is used more than it should be. This is the reason the equilibrium deviates from the optimum in 8.2.4. The remedy is a congestion toll: if the driver is charged an amount equal to the latency imposed on others, the driver takes this effect into account too (8.6.2).

Positive externality: network effect. For some networks the value of joining grows with the number of participants. A telephone owned by one person is useless; two people can call each other; in a network of a hundred people every user can reach 99 others. Messaging apps and social networks are like this too. In a network with n users there are n(n − 1)/2 possible connections: 45 with 10 users, 4,950 with 100 users. The claim that the value of a network therefore grows as n² is called Metcalfe's law. This claim is not an exact law but a rough estimate: not all connections are equally valuable, and most users communicate with only a small fraction of those in the network.

The network effect also involves an externality: when a new user joins the network, he or she adds value for the others (they can now reach one more person), but when deciding whether to join, he or she looks only at his or her own benefit. Adoption therefore stays slow until a critical mass is passed: joining a network used by few people appeals to nobody.

In a network formation game both externalities are present. A link shortens the distances not only of the one who builds it: everyone who passes through that link benefits (a positive externality). But only the one who buys the link pays for it. The players may therefore build fewer links than is best for society.

8.5.2Network formation games

In network formation models a link is simply called a link or an edge. Each link has a construction cost; being well connected, that is, being at a short distance from the others, is valuable. This is the basic tension of the model: balancing the cost of links against reach. There are two basic models.

Definition 8.11

The one-sided network formation game (Fabrikant et al., 2003). There are n players. Each player i buys links to the nodes he or she wants; each link costs α. Whoever buys it, a link is used by everyone in both directions. The player's cost:

costi = α · (number of links bought by i) + Σj distance(i, j)

The distance is the number of links on the shortest path between two nodes; if the network is disconnected, the distance to an unreachable node is infinite. The solution concept is Nash equilibrium. The social cost is the sum of the costs of all players.

The two-sided model (Jackson and Wolinsky, 1996). A link is formed only if the players at both ends want it; if either one wants to cut it, it is cut. The solution concept is pairwise stability.

The two models correspond to different real-life situations. The one-sided model resembles a website linking to other sites, or a network operator leasing a line on its own: the one who builds the link pays, and the other side's consent is not needed. The two-sided model resembles friendship, or a mutual peering agreement between two network operators: both sides must agree.

Three questions are asked in both models. Which networks are in equilibrium? Which network is best for society? How different can the two be? These questions are the network-formation counterpart of the question “equilibrium or optimum?” in selfish routing.

8.5.3Two-sided links: pairwise stability

Definition 8.12

A network that satisfies the following two conditions is called pairwise stable:

  1. no player gains by cutting one of his or her own links;
  2. no missing link would make both of its endpoints better off (if one gains strictly and the other does not lose, the link is formed).

The definition differs slightly from Nash equilibrium. In Nash equilibrium the deviation of a single player is examined. In pairwise stability, cutting a link is one person's decision, but forming a link is the joint decision of two people. In evaluating a link that has not been formed, the gains of both ends are considered.

For a concrete example take n = 4 players (A, B, C, D). A player's benefit depends on the distance to the others as follows: 4 from each player at distance 1, 2.2 from one at distance 2, and 1 from one at distance 3. The cost of each link is 2 for each of the players at its two ends. The player's net benefit is the sum of the distance benefits minus the link costs. 8.5.5Code trace: cost()

To compute a player's cost the distances to the others must be known. Since all links have equal length (1), the shortest distances are found by breadth-first search (BFS). BFS starts at the start node; it first visits all its neighbors (distance 1), then their not-yet-seen neighbors (distance 2), and so on.

def cost(i, links, alpha):
  dist = {i: 0}; queue = [i]
  while queue:
    u = queue.pop(0)
    for v in nbrs(links, u):
      if v not in dist:
        dist[v] = dist[u] + 1
        queue.append(v)
  bought = sum(1 for (a, b) in links if a == i)
  return alpha * bought + sum(dist.values())

The function uses a helper function called nbrs(links, u). It returns the neighbors of u without looking at who bought the link: whoever buys a link, everyone uses it. The list links consists of pairs (a, b); (a, b) means that the link was bought by a. The code works line by line as follows:

  • The dictionary dist holds the known distances; at first it contains only i (distance 0). queue is the list of nodes to be visited.
  • Until the queue is empty, the node u at the front is removed.
  • For each neighbor v of u: if v has not been seen before, its distance is set to one more than that of u and v is appended to the end of the queue.
  • bought is the number of links bought by i: the pairs whose first element is i are counted.
  • The cost is alpha times the number of links bought plus the sum of all the distances.

The code assumes the network is connected; if it is not, unreachable nodes never enter dist and the sum comes out wrongly small. In a real implementation one must return infinity when len(dist) < n.

8.5.6Equilibrium and optimum as the link price changes

When the link price α changes, both the optimum and the equilibria change. The optimum is examined first. The social costs of two candidate networks on four players are computed as follows:

The two lines cross at 3α + 18 = 6α + 12, that is, at α = 2 (Figure 8.26). For α < 2 the complete graph is cheaper; for α > 2 the star is. The reason is clear: the complete graph has 3 more links than the star (cost 3α), and these links reduce the sum of distances by 6 (each brings two leaves 2 steps closer to each other).   • 1 < α < 2: in between. The optimum is still the complete graph, but the complete graph is no longer an equilibrium: a player who drops a link saves α and loses only 1. The equilibria at α = 1.5 (star 22.5, cycle 22) cost more than the optimum (21).
  • α > 2: links are expensive. The optimum is the star, and the star is also an equilibrium. But more expensive equilibria can appear alongside it. At α = 2.5 the path network (3 · 2.5 + 20 = 27.5) is also an equilibrium. This requires that the links be bought by the two middle players: had a player at an end bought his or her own link, that player could have reduced the distance by moving the link to a node closer to the middle.

A general result: as long as α ≥ 1, the star is always an equilibrium. If the center drops a link the network is disconnected; if a leaf buys a new link it gains at most 1 in distance and pays at least 1. But the equilibrium is often not unique, and some equilibria are markedly worse than the optimum. This loss ratio of selfish behavior is again studied under the name price of anarchy in network formation games.

8.5.7Common mistakes in network formation

Common mistakes
  • Charging the cost of a link to both sides: In the one-sided model only the buyer pays for a link. In the two-sided (Jackson–Wolinsky) example the cost is charged separately to each end. The models must not be mixed up.
  • Counting distances once in the social cost: Each player sums his or her own distances; so in the social cost the distance of every pair is counted twice (in the complete graph there are 6 pairs and the sum of distances is 12).
  • Taking the distance to be infinite once a link is dropped: When a link is dropped in the complete graph, the distance to that neighbor only rises to 2; there are other paths. A network becomes disconnected only if the sole path is cut.
  • Trying only adding links: Deviations include adding a link, dropping one, and swapping (dropping one and buying another).
  • Looking at the gain of only one end in pairwise stability: To form a link both ends must gain (or at least not lose).
  • Assuming the optimum is an equilibrium: At α = 1.5 the optimum (the complete graph) is not an equilibrium.

8.6Control and incentives

The common conclusion of the previous sections is that the equilibrium reached by selfish users can differ from what is best for society. There are three ways to deal with this gap: gather the decisions in a center, change the users' incentives, or share the resources by a fairness criterion.

8.6.1Centralized or distributed?

Who makes the routing decisions in a network is a basic design choice. Table 8.15 compares the two extreme approaches.

Table 8.15: Centralized and distributed (selfish) routing.

There are examples of centralized routing in real networks. In software-defined networking (SDN) the routers do not decide on their own; a controller program sees the state of the whole network and tells each router what to do. An Internet service provider also does traffic engineering inside its own network, distributing traffic evenly over its lines. In these cases the center owns its network, and the packets it routes do not object.

The most important example of distributed routing is the Internet itself. The Internet is formed by the union of thousands of independent networks, and routes between these networks are chosen with BGP (Border Gateway Protocol, the inter-domain routing protocol). Each network chooses its routes according to its own commercial interests. In city traffic too, each driver follows his or her own navigation app.

The strengths and weaknesses of the two approaches complement each other. Centralized routing can aim at the optimum, but it needs all the demand and latency information and depends on the users complying. At the optimum some users are on the slower route (in the two-route example those on Route 2 experience 27.5 minutes while those on Route 1 experience 20); these users want to deviate. Moreover, if the center fails the whole system is affected. Distributed routing works with local information only and has no compliance problem, because everyone is doing what he or she wants anyway; but it can reach inefficient equilibria, as in Braess's paradox.

Hence intermediate solutions are common in networks. The center does not control everything; it influences only part of it:

  • Price: The center does not tell users what to do, but makes some routes more expensive (a congestion toll).
  • Information: The center recommends routes; the user is free to follow the recommendation or not.
  • Partial control: The center routes part of the traffic itself and the users choose the rest. This is called Stackelberg routing. The name comes from Stackelberg games, in which a leader moves first and the followers then respond to it: the center places its own traffic so as to improve the equilibrium reached by the selfish users.

8.6.2Incentives, load balancing and applications

The right incentives steer users toward using network resources in a balanced way and raise efficiency. In traffic, tolls or warnings reduce congestion. In smart power grids, time-of-use tariffs balance the load at peak hours: if electricity is expensive in the evening, the washing machine is run at night. The cleanest example of incentives is the congestion toll mentioned in 8.5.1.

The idea is this: the reason the Wardrop equilibrium deviates from the optimum is that the driver does not see the latency x · ℓ′(x) imposed on others. If each route is charged a toll equal to this externality at the optimum, the driver now looks at “time + toll”. This sum equals the marginal cost of that route. When the drivers equalize these sums, the optimum, where the planner equalizes marginal costs, is reached.

Example 8.16

In the two-route network (ℓ1 = 5 + x1/100, ℓ2 = 20 + x2/200, 3,000 cars) let the tolls be measured in units of time (the equivalent in minutes).

  1. The optimum is 1,500 / 1,500. The externalities at the optimum: on Route 1, x1 · ℓ1′ = 1,500 / 100 = 15; on Route 2, x2 · ℓ2′ = 1,500 / 200 = 7.5.
  2. A toll worth 15 minutes is put on Route 1 and one worth 7.5 minutes on Route 2. The driver now compares 5 + x1/100 + 15 with 20 + x2/200 + 7.5.
  3. The new equilibrium: 20 + x1/100 = 27.5 + (3,000 − x1)/200. Multiply both sides by 200: 4,000 + 2x1 = 5,500 + 3,000 − x1, that is, 3x1 = 4,500 and x1 = 1,500.
  4. At the tolled equilibrium the traffic splits exactly as at the optimum. Every driver's “time + toll” is 35 (20 + 15 = 27.5 + 7.5). The total travel time falls to 71,250 car-minutes.

The tolls collected do not vanish from society; they can be channeled into road building or public transport. But from the driver's own viewpoint, time plus toll (35) is higher than the old equilibrium time (25). This is one reason why road pricing is politically difficult.

Wrong incentives, on the other hand, backfire. Strategic, selfish behavior increases and the result is congestion and low efficiency. Two examples are common. First, a navigation app that recommends the same “fastest” route to everyone can fill up side roads: the app sends each driver to the fastest road individually, but when everyone goes to the same road, that road slows down. Second, if a toll is chosen badly, traffic shifts to another bottleneck: when a bridge becomes tolled, all the vehicles may head for a free but narrow side bridge.

The concepts of this chapter are used in three major application areas:

  • The Internet. ISPs route data packets; inter-domain route selection is done with BGP. Load balancing (ECMP) and traffic engineering reduce congestion.
  • Traffic management. Route optimization, smart signaling and navigation apps. Traffic planners evaluate the effect of a new road by computing the Wardrop equilibrium the drivers will reach.
  • Energy. Energy distribution and load shifting in smart power grids. The timing of consumers’ electricity use forms a structure similar to a congestion game: if everyone uses it at the same hour the grid is strained.

8.6.3Efficiency versus fairness: sharing bandwidth

Minimizing the total latency is not the only criterion. When the resources of a network are shared among users, fairness matters too. A small example shows this. Two links each have capacity 1. Flow A uses both; flow B uses only link 1; flow C uses only link 2. Each flow is given a rate (xA, xB, xC). The capacity constraints are:

xA + xB ≤ 1, xA + xC ≤ 1

Which allocation should be chosen? Three criteria give three different answers (Table 8.16).

Table 8.16: Three criteria for sharing bandwidth.
CriterionWhat is optimized?(xA, xB, xC)Total
Largest total flowΣ xi(0, 1, 1)2 (A starves)
Max-min fairness (egalitarian criterion)First the smallest share is made as large as possible, then the next(1/2, 1/2, 1/2)1.5
Proportional fairness (Nash social welfare)The product of the shares is maximized (Kelly, 1997)(1/3, 2/3, 2/3)≈ 1.67
Example 8.17
  1. Largest total flow. A uses capacity on both links; every unit given to it takes one unit from B and one from C. In terms of the total, it is best to give A nothing: xA = 0, xB = xC = 1, total 2. But A starves completely.
  2. Max-min fairness. All shares are raised together at the same rate. When the shares reach 1/2, link 1 (xA + xB = 1) and link 2 (xA + xC = 1) fill up at the same time. Now no share can be increased without decreasing someone else's. The result is (1/2, 1/2, 1/2), total 1.5.
  3. Proportional fairness. The product of the shares xA · xB · xC is maximized. To maximize the product no capacity is wasted: xB = xC = 1 − xA. The product becomes xA (1 − xA)².
  4. Maximizing the product is the same as maximizing its logarithm, because the logarithm is an increasing function: log xA + 2 log(1 − xA). The derivative of log x is 1/x. Setting the derivative to zero: 1/xA − 2/(1 − xA) = 0, that is, 1/xA = 2/(1 − xA).
  5. By cross-multiplication 1 − xA = 2xA, xA = 1/3. The allocation is (1/3, 2/3, 2/3), total 5/3 ≈ 1.67.

The difference between the three criteria is a value judgment. The largest-total-flow criterion cares about the total and is willing to shut one user out completely. Max-min fairness cares about the worst-off user; it equalizes everyone but sacrifices from the total. Proportional fairness stands between the two. A, which uses both links, gets less, because it consumes shares of two resources; but nobody falls to zero, because a zero share makes the product zero. The total (≈ 1.67) is higher than that of max-min and lower than the largest total flow.

It is no coincidence that proportional fairness is the same thing as Nash social welfare: both concepts ask for maximizing the product of the shares. The logarithmic form shows that this criterion means “raising any user's share by 10% is worth the same, whoever the user is”. In 1998 Frank Kelly and coauthors interpreted the congestion control of the Internet (TCP-like protocols) from this angle (Kelly et al., 1998). Each link announces a congestion price that grows as the load on it grows; each flow adjusts its rate by looking at the prices along its own path. This distributed algorithm converges to the proportionally fair allocation without any center.

8.6.4Discussion questions

The concepts of this chapter shed light on three questions that have no definite answer but are worth thinking about.

When navigation apps recommend the “fastest” route to everyone, does traffic approach the Wardrop equilibrium or the system optimum? Why? If the app recommends to each driver the fastest route under the current latencies, each driver finds his or her own best response more easily. This speeds up convergence to the Wardrop equilibrium, not to the system optimum. If the app deliberately sent some drivers to slower routes, the optimum could be approached; but those drivers might not follow the recommendation. If a single app has very many users, it can act as a kind of Stackelberg leader.

A city is planning a new bridge. How can the equilibrium the drivers will reach once the bridge opens be computed in advance, to foresee a Braess effect? First the network is modeled: a latency function (for example BPR) for each road and the demands between source–destination pairs are determined. Then the Wardrop equilibrium is computed in the two networks, with and without the bridge; this means minimizing the Beckmann potential with a method such as Frank–Wolfe. The total latencies of the two equilibria are compared. If the total at the equilibrium with the bridge is higher, the bridge may do harm through selfish use; the remedy may be tolls or access restrictions.

Are routers on the Internet (BGP) selfish agents? Whose cost do they minimize? Individual routers follow a program; it is the networks that operate them that are selfish. Each network (an ISP, for example) chooses its routes according to its own commercial interests: it prefers networks that pay it, or with which it peers for free, over networks it has to pay. This is why Internet routes are often not the shortest or the fastest. What BGP minimizes is not the packet's delay but the network operator's cost.

8.7Summary

  • Latency depends on load. The latency of each edge is a nondecreasing function of the flow on it: constant, linear, BPR or queueing (1/(c − x)). Classical shortest-path algorithms (Dijkstra, Bellman–Ford) assume fixed weights; load-dependent latency turns routing into a game.
  • In selfish routing each user minimizes his or her own latency. The latency of a path is the sum of the edge latencies; the total latency is C(f) = Σ fe ℓe(fe).
  • At a Wardrop equilibrium all used paths have equal and lowest latency. In the two-route example (3,000 cars) the equilibrium is 2,000 / 1,000, everyone takes 25 minutes, and the total is 75,000 car-minutes.
  • At the system optimum the marginal costs (ℓ + x · ℓ′) are equalized: 1,500 / 1,500, total 71,250. The optimum is not an equilibrium; the gap comes from the externality x · ℓ′, which the driver does not take into account.
  • The Beckmann potential Φ = Σ ∫ ℓe is minimized at the Wardrop equilibrium; an equilibrium always exists and the edge latencies are unique. Bisection (find_eq) finds the equilibrium of a two-route network by halving the interval in each round.
  • Braess's paradox: in the 4,000-car network a shortcut of 0 minutes raises everyone's time from 65 to 80 minutes; the zigzag is dominant for everyone. The optimum of the network with the shortcut is ≈ 64.7. The paradox does not occur in series-parallel networks; choosing which roads to close is hard in general networks.
  • In congestion games Rosenthal's potential Φ = Σe Σk ≤ ne ce(k) changes by exactly the cost difference of the single player who deviates. Hence a pure Nash equilibrium exists and best-response dynamics stop (26 → 23 → 21 → 20); but in general they may not stop quickly (PLS-complete).
  • In network formation there is a tension between link cost and reach. In the two-sided model the star and the cycle are pairwise stable; in the one-sided model at α = 1.5 the star and the cycle are equilibria, and the optimum, the complete graph, is not. The optimum is the complete graph for α ≤ 2 and the star for α ≥ 2.
  • Control and incentives: centralized routing aims at the optimum but needs information and compliance; intermediate solutions (congestion tolls, route recommendations, Stackelberg routing) are common. In sharing bandwidth, largest total flow, max-min fairness and proportional fairness choose different allocations.

8.9Test Yourself

  1. 5,000 cars go from A to B. Route 1: ℓ1 = 10 + x1/100, Route 2: ℓ2 = 20 + x2/400 (minutes). What are the Wardrop equilibrium, the latency and the total latency?

    Answer

    The extreme cases are not equilibria: if everyone is on Route 1, ℓ1 = 60 > 20; if everyone is on Route 2, ℓ2 = 32.5 > 10. Equality: 10 + x1/100 = 20 + (5,000 − x1)/400. Multiplying by 400, 4,000 + 4x1 = 8,000 + 5,000 − x1, 5x1 = 9,000, x1 = 1,800, x2 = 3,200. The latencies are 10 + 18 = 28 and 20 + 8 = 28 minutes. The total is 5,000 × 28 = 140,000 car-minutes.

  2. What are the system optimum and its total latency in the same network? How many car-minutes of extra latency does selfish routing produce?

    Answer

    Marginal costs: Route 1 10 + x1/50, Route 2 20 + x2/200. Equality: 10 + x1/50 = 20 + (5,000 − x1)/200; multiplying by 200, 2,000 + 4x1 = 4,000 + 5,000 − x1, 5x1 = 7,000, x1 = 1,400, x2 = 3,600. The latencies are 24 and 29 minutes. The total is 1,400 × 24 + 3,600 × 29 = 33,600 + 104,400 = 138,000. The difference is 140,000 − 138,000 = 2,000 car-minutes. At the optimum those on Route 2 are 5 minutes slower and want to move to Route 1.

  3. Let the Braess network have 3,000 cars; the narrow roads take x/100 and the wide roads 50 minutes. What is the equilibrium time before and after the shortcut (A→B, 0 minutes) opens? Does the paradox occur?

    Answer

    Before: 1,500 / 1,500, each route 15 + 50 = 65 minutes. After: suppose everyone is on the zigzag; 3,000 cars on the narrow roads (30 minutes), the zigzag takes 30 + 0 + 30 = 60. A driver who goes back to an old route experiences 30 + 50 = 80; nobody goes back. The equilibrium is 60 minutes. The shortcut speeds everyone up by 5 minutes; the paradox does not occur. Because the most crowded narrow road (30) is much faster than the wide road (50), the shortcut is genuinely useful. The paradox appears only in a certain range of traffic.

  4. In the atomic Braess network (s→A and B→t: ce(k) = k; s→B and A→t: 4; A→B: 0), 3 drivers are in the profile (upper, lower, zigzag). What are Φ and the costs? How does Φ change if the driver on the upper route moves to the zigzag?

    Answer

    User counts: s→A 2 (upper, zigzag), A→t 1, s→B 1, B→t 2 (lower, zigzag), A→B 1. Φ = (1 + 2) + 4 + 4 + (1 + 2) + 0 = 14. Costs: upper 2 + 4 = 6, lower 4 + 2 = 6, zigzag 2 + 0 + 2 = 4. If the upper driver moves to the zigzag, he or she stays on s→A (2), A→B 0, and there are 3 people on B→t (3): the new cost is 2 + 0 + 3 = 5. The gain is 1; therefore Φ falls from 14 to 13. Check: 4 is deleted from A→t, 0 is added to A→B and 3 to B→t; −4 + 3 = −1. The only pure equilibrium of this game is the profile in which all three drivers are on the zigzag (6 each, total 18); the profile with the smallest total cost is (upper, lower, zigzag) (16).

  5. In the one-sided network formation game let n = 5 players and α = 3. What is the social cost of the star and of the complete graph? Which is the optimum? Is the star a Nash equilibrium?

    Answer

    Star: 4 links, cost 4 · 3 = 12. Distances: center 4 · 1 = 4, each leaf 1 + 3 · 2 = 7; total 4 + 4 · 7 = 32. Social cost 44. Complete graph: 10 links (5 · 4/2), cost 30; sum of distances 5 · 4 = 20; social cost 50. Since α = 3 > 2, the optimum is the star. The star is an equilibrium: a leaf gains only 1 in distance with a new link and pays 3; if the center drops a link the network is disconnected.

  6. In the two-sided four-player example (benefit: 4 for distance 1, 2.2 for distance 2, 1 for distance 3) let the cost of a link to each end be c. For which range of c is the complete graph pairwise stable? The star?

    Answer

    Complete graph: a player who cuts a link saves c; the distance to that neighbor rises from 1 to 2 and he or she loses 4 − 2.2 = 1.8. For stability c ≤ 1.8 is needed; there is no link to add. Star: if two leaves form a link each gains 1.8 and pays c; for it not to be formed, c ≥ 1.8. If the center cuts a link it loses that leaf completely (4) and saves c; c ≤ 4 is needed. If a leaf cuts its link it loses 8.4. The star is stable for 1.8 ≤ c ≤ 4. At c = 1.8 both are stable.

  7. In the two-route network (ℓ1 = 5 + x1/100, ℓ2 = 20 + x2/200, 3,000 cars) a toll τ (the equivalent in minutes) is to be put on Route 1 only. For which value of τ does the tolled equilibrium coincide with the system optimum?

    Answer

    The optimum is 1,500 / 1,500; there ℓ1 = 20, ℓ2 = 27.5. For the tolled equilibrium to be at 1,500 the driver must see the two routes as equal: 20 + τ = 27.5, that is, τ = 7.5. With a smaller toll Route 1 is still too crowded; with a larger one it is too empty. This single toll gives the same toll difference (7.5) as putting separate marginal tolls (15 and 7.5) on the two routes; the driver's decision depends only on the difference.

  8. If find_eq(l1, l2, 3000) is called with eps = 10, how many rounds does the loop run and what is the width of the final interval?

    Answer

    Each round halves the width: after k rounds the width is 3,000/2k. The loop runs as long as the width is greater than 10. For 28 = 256 the width is ≈ 11.7 > 10; for 29 = 512 it is ≈ 5.86 ≤ 10. The loop runs 9 rounds; the final width is about 5.86 cars. Compared with eps = 50 this is only 3 more rounds.
