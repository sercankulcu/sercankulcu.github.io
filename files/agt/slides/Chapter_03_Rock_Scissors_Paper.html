    How to play

    • Click Rock, Paper, or Scissors (or press R, P, S). The computer chooses at the same time.
    • Rock beats scissors, scissors beats paper, paper beats rock. Identical choices are a draw.
    • The panel on the left counts wins, losses, and draws and shows how often you use each move.
    • If Show move reasoning (left panel) is ticked, after every round the screen shows what the computer looked at when it chose its move.

    Opponents

    • Random: plays each move with probability 1/3. This is the game's only Nash equilibrium; no strategy beats it on average, and it cannot exploit you either.
    • Frequency learner: counts your past moves and plays whatever beats your most frequent move (fictitious play).
    • Pattern learner: looks at what you played after your previous move in earlier rounds and counters your most likely next move.

    What does it show?

    Rock-paper-scissors is a symmetric, zero-sum game with no pure-strategy equilibrium: every predictable choice has a best response that beats it. The only equilibrium is the mixed strategy (1/3, 1/3, 1/3). Against learning opponents a biased or repetitive pattern loses; mixing uniformly brings the expected score back to zero.

    How does the computer choose?

    There is no tree search in this game: depending on the Opponent menu, the computer applies one of three rules. Moves are numbered 0 = rock, 1 = paper, 2 = scissors, and beats(m) = (m + 1) % 3 is the move that beats m (paper beats rock, scissors beats paper, rock beats scissors).

    1. Random: it ignores the history and plays Math.floor(Math.random() * 3): every move has probability 1/3.
    2. Frequency: it takes the counts of the moves you have played so far, c = [c0, c1, c2], picks the largest one (at random among ties) and plays the move that beats it: beats(argmax c). In the first round there are no counts, so it plays at random.
    3. Pattern: it looks at your last move, counts what you played right after that move in earlier rounds (c[next]++) and plays against the most frequent follow-up. If you have never played after that move before, or it is the first round, it plays at random.

    Is this an optimal strategy?

    The Random opponent is the game's mixed Nash equilibrium (1/3, 1/3, 1/3), the subject of Chapter 3. At equilibrium every pure move earns the same expected payoff: against (1/3, 1/3, 1/3) it is 1/3·(+1) + 1/3·0 + 1/3·(−1) = 0. So whatever you play, your expected score is 0; there is nothing to learn about it and it cannot be exploited. This is the indifference principle: at equilibrium the opponent's mix is chosen so that it leaves you indifferent between all your moves.

    The Frequency and Pattern opponents are not in equilibrium. Each applies a best response: it forms a belief (a prediction) from your history and plays the best move against that belief. If you are biased or repetitive, it wins. But they are also predictable: once you know the rule you know their reply in advance and can beat it. In this zero-sum game, being predictable loses.

    Worked example (Frequency). Your last 6 moves: Rock, Paper, Rock, Scissors, Rock, Scissors. Counts c = [3, 1, 2]. The largest is 3 (rock). The computer plays beats(0) = 1, that is Paper. If you play rock again you lose; if you play scissors you win. The panel shows this row as 🪨 Rock 3/6 = 50% → beats the expected move: 📄 Paper.
    Worked example (Pattern). Your history: Rock, Paper, Rock, Paper, Rock. Your last move is Rock. After Rock you have played Paper twice before: c = [0, 2, 0]. The computer expects Paper next and plays beats(1) = 2, that is Scissors.
    How much does exploiting earn? Against someone who plays rock 50%, paper 25%, scissors 25%, Paper has expected payoff 0.5·(+1) + 0.25·0 + 0.25·(−1) = +0.25 per round, Rock and Scissors have 0 and −0.25. The Frequency opponent finds exactly this best response. If you mix uniformly, every move is worth 0.

    The Frequency learner is a fictitious play player. In zero-sum games, if both sides play this way the long-run frequencies of their moves approach the equilibrium mix; but the move in any single round stays predictable.

    The panel shows, after each round, the counts the computer used (or "uniform random: 1/3 each"), the reply it chose, and whether its prediction was right. The gold row is the chosen prediction; a faint row is a tied candidate (the pick among them is random).

    The code on this page (JavaScript)

    The function that picks the computer's move. (The real page also has a few small recording lines that feed the reasoning panel; they do not change how it plays and are left out here.)

    /* Helpers: 0 = rock, 1 = paper, 2 = scissors */
function beats(m) { return (m + 1) % 3; }        /* the move that beats m */
function rnd3() { return Math.floor(Math.random() * 3); }

/* pick one of the largest counts at random */
function argmaxRandom(arr) {
  const max = Math.max(...arr);
  const idx = arr.map((v, i) => v === max ? i : -1).filter(i => i >= 0);
  return idx[Math.floor(Math.random() * idx.length)];
}

/* hist: finished rounds, each { you, cpu, res } */
function cpuMove() {
  const mode = oppSelect.value;
  if (mode === 'random' || !hist.length) return rnd3();   /* uniform random */
  if (mode === 'freq') {
    const c = [0, 0, 0];
    hist.forEach(h => c[h.you]++);                         /* count your moves */
    return beats(argmaxRandom(c));                         /* beat the most frequent */
  }
  /* 'pattern': look at what you played after your last move */
  const last = hist[hist.length - 1].you;
  const c = [0, 0, 0];
  for (let i = 1; i < hist.length; i++) {
    if (hist[i - 1].you === last) c[hist[i].you]++;
  }
  if (c[0] + c[1] + c[2] === 0) return rnd3();             /* no example: random */
  return beats(argmaxRandom(c));
}

    The same idea in Python

    In the style of the course repo's mixed_2x2.py, with exact fractions: the equilibrium check and the computer's rules.

    from fractions import Fraction as F
import random

# 0 = rock, 1 = paper, 2 = scissors; A[i][j] = computer's payoff
A = [[0, -1, 1], [1, 0, -1], [-1, 1, 0]]

def payoffs(A, q):
    # expected payoff of each pure move against the mix q
    return [sum(A[i][j] * q[j] for j in range(3)) for i in range(3)]

def best_response(A, q):
    u = payoffs(A, q)
    return u.index(max(u))

def beats(m):
    return (m + 1) % 3

def argmax_random(c):
    top = max(c)
    return random.choice([i for i, v in enumerate(c) if v == top])

def cpu_move(mode, hist):          # hist: your past moves
    if mode == 'random' or not hist:
        return random.randrange(3)
    if mode == 'freq':
        c = [hist.count(m) for m in range(3)]
        return beats(argmax_random(c))
    last = hist[-1]
    c = [0, 0, 0]
    for prev, nxt in zip(hist, hist[1:]):
        if prev == last:
            c[nxt] += 1
    if sum(c) == 0:
        return random.randrange(3)
    return beats(argmax_random(c))


if __name__ == "__main__":
    third = [F(1, 3)] * 3
    print(*payoffs(A, third))
    print(*payoffs(A, [F(1, 2), F(1, 4), F(1, 4)]))
    print(best_response(A, [F(1, 2), F(1, 4), F(1, 4)]))
    print(cpu_move('freq', [0, 1, 0, 2, 0, 2]))
    print(cpu_move('pattern', [0, 1, 0, 1, 0]))

    Try it yourself

    1. Predict first, then look. Set the opponent to Frequency and tick Show move reasoning. Play eight rounds; before each one, predict from the counts what the computer will play, then play the round and compare with the row in the panel. Were you ever wrong? If so, was it a tie?
    2. Beat the pattern learner. Set the opponent to Pattern. First play Rock, Paper, Rock, Paper, Rock. The panel should now say "your last move was Rock; after it you played Paper twice", and the computer will play Scissors. Since you know that, play Rock (rock beats scissors). Repeat the idea a few more times: does the score move your way?
    3. Try to exploit the Random opponent. Set the opponent to Random and spend 30 rounds on every tactic you can think of (always Rock, a cycle, your gut feeling). The panel says "uniform random: 1/3 each" every time. How close is your final score to the expected value 0? Compare it with the standard deviation √(2n/3) (n = number of rounds).
    4. Measure your own mix. Against the Frequency opponent play only Rock and Paper for 20 rounds, with more Rock. From the percentages in "Your mix" on the left, compute by hand the computer's expected gain per round from its usual reply (Paper) and compare it with the real score.

    Discussion questions

    • Why can the Random opponent never be exploited?
      Answer

      Because each of your pure moves has the same expected payoff against it: 1/3·(+1) + 1/3·0 + 1/3·(−1) = 0. However clever your sequence looks, the average is 0. Since the opponent does not base its choice on your history, there is also no pattern to learn. This is the definition of the mixed Nash equilibrium: nobody gains by deviating alone.

    • When does the Frequency opponent win and when does it lose? How does a human who knows its rule beat it?
      Answer

      It wins against a biased player (say, mostly rock), because the counts reveal the bias. Against a player who mixes uniformly the counts are noise and the expected score is 0. Someone who knows the rule beats it in two stages: first play one move (say rock) a lot so that the computer settles on paper, then play scissors. Once a learner's rule is known, the rule itself becomes exploitable.

    • Why does the Pattern opponent not win against someone who plays uniformly at random? Can it look lucky for a few rounds?
      Answer

      For a uniform random player the move after any given move is also independent and 1/3, so the "what follows Rock" counts even out in the long run and the prediction is just noise. With few rounds the counts are small and a prediction can hit by chance (for instance seeing 1/1 from a single example). Because the standard deviation of the score is about √(2n/3), swings in short games are normal; the expected value stays 0.

    • If you play uniformly at random yourself, can you still lose in the long run?
      Answer

      The expected score is 0, but a single game depends on luck; over n rounds the standard deviation is about √(2n/3), e.g. about 8 after 100 rounds. So you do not lose on average (equilibrium gives safety), but you do not gain against an opponent who deviates either: equilibrium protects you from being exploited, it does not exploit the opponent's mistakes. Deviating to exploit a mistake you have spotted is possible, but it has a price: you become predictable yourself.
