Game Trees

Game Trees: Positions and Moves

  • A node is a position (board and player to move); an edge is a move. The root is the current position.
  • Two players alternate, there is no chance, and both see the board: a perfect-information, zero-sum game.
  • The player to move at the root is MAX (▲) and wants a large value. The opponent is MIN (▽) and wants a small one.
  • Levels alternate between MAX and MIN; going down one level is one ply (one move by one player).
  • The same position can be reached by different move orders; it then appears as several nodes in the tree.

Game Trees

Leaves and Utilities

  • A leaf (terminal position): the game is won or the board is full; it has no children.
  • Every leaf has a utility. In tic-tac-toe, from MAX's (X's) view: +1 if X wins, 0 for a draw, −1 if O wins.
  • The game is zero-sum: O's utility is minus X's (uO = −uX), so one number per node is enough.
  • The values of inner nodes are not known yet; minimax computes them from the leaves.
Utility is defined only at the leaves. A judgment like "the center is a good square" becomes a number only once the tree is searched down to the leaves.

Game Trees

Branching Factor and Depth

  • Branching factor b: the number of legal moves in a position (average or maximum). Depth d: the length of the game in plies.
  • If every node has b children, there are bd leaves at depth d: tree size ≈ bd. One more ply multiplies the work by b.

Minimax

The Minimax Value

The minimax value of a position s is the utility MAX gets at the end of the game if both sides play optimally:

minimax(s) =
  utility(s)                      if s is terminal
  max  minimax(result(s, a))      if MAX to move
   a
  min  minimax(result(s, a))      if MIN to move
   a
  • The definition is recursive: the search goes depth-first, and values rise from the leaves to the root.
  • At the root, MAX picks the move leading to the child with the largest value.
Cost
  • Time: each node once → O(bd).
  • Space: only the path from the root to the current node plus sibling information → O(b·d).
  • Against a perfect opponent the minimax move is optimal; if the opponent errs, MAX gets at least the minimax value.

Code Trace: The Minimax Function

from math import inf
T = {"A": ["B", "C", "D"], "B": [3, 5],
     "C": [2, 9], "D": [6, 4]}
def minimax(n, maxi):
  if isinstance(n, int):        # leaf
    return n
  best = -inf if maxi else inf
  for c in T[n]:
    v = minimax(c, not maxi)
    if maxi:
      best = max(best, v)
    else:
      best = min(best, v)
  return best
print(minimax("A", True))

Minimax

Minimax, Backward Induction and Maximin

  • Minimax is the two-player zero-sum special case of backward induction: in a general game the player to move at each node maximizes its own payoff; in a zero-sum game B's payoff is minus A's, so "B maximizes" = "B minimizes A's payoff".
  • Maximin: the best value MAX can guarantee, maxs mint u(s, t). Minimax: the lowest value MIN can hold MAX to, mint maxs u(s, t).
  • In finite games of perfect information the two are equal and pure strategies suffice (Zermelo, 1913; Kuhn, 1953). The minimax value of the tree is this common value.
The difference in simultaneous games

In Matching Pennies (A gets +1 on a match, −1 otherwise), with pure strategies maximin is −1 and minimax +1: the gap does not close.

von Neumann (1928): once mixed strategies are allowed, maximin = minimax in every finite two-player zero-sum game (the minimax theorem). In Matching Pennies the common value is 0.

Minimax

The Minimax Assumption: A Perfect Opponent

What does it guarantee?

Whatever the opponent does, MAX gets at least the minimax value. If the opponent errs, MAX may get more, never less.

What does it not guarantee?

It does not find the move earning the most against a weak opponent: of two equally valued moves, it cannot tell which one sets a trap.

With chance

In dice games such as backgammon, chance nodes are added to the tree and averaged over (expectiminimax); pruning becomes harder.

In a two-player zero-sum game, assuming "my opponent plays its best move" yields a safe lower bound: the minimax move maximizes the worst-case payoff.

P and N Positions = Minimax Values

  • N position: the next player (to move) wins. P position: the previous player (not the one to move) wins.

Minimax and Bouton's XOR Rule

Bouton (1901): a position is P ⇔ the nim-sum (XOR) of the heaps is 0. The winning move makes the XOR 0. Compared with the move minimax finds on the full tree:

The minimax tree grows exponentially with the number of chips; the XOR rule takes as many operations as there are heaps. When a game-specific theory exists, no search is needed; when it does not, minimax always works.

Minimax in Tic-Tac-Toe

Explaining the Move

  • The values alone make the choice; the reason is found by asking, in order, what the chosen move achieves:
  • 1) Does it complete three in a row? → wins. 2) Does it block the opponent's one-move threat? → blocks.
  • 3) Does it create two threats at once? → forks. 4) Otherwise, the sign of the value: forces a win / holds a draw / delays the loss.
Instead of writing rules one by one

A good tic-tac-toe player can also be written with rules such as "win first, then block, then fork". Minimax knows none of these rules; it discovers them all by searching the tree. The same program works for Connect Four; the rules do not.

Alpha-Beta Pruning

Some Branches Need Not Be Read

  • A (MAX) secured 3 from its first child B: B = min(3, 12, 8) = 3.
  • C's first leaf is 2. C is a MIN node, so its value is at most 2.
  • With 3 in hand, A will never choose C, worth at most 2: whatever C's remaining leaves (4 and 6) are, the root's value does not change.
  • These two leaves are never read: they are pruned. In chess a "leaf" is a deep subtree; pruning saves millions of nodes.
Alpha-beta pruning finds the same root value as minimax and (with the same move order) the same move, but skips branches that cannot affect the result.

Alpha-Beta Pruning

α and β

α (alpha): MAX's lower bound

The best value MAX has already secured along the path from the root to this node. Starts at −∞. Grows only at MAX nodes: α = max(α, value).

β (beta): MIN's upper bound

The best (smallest) value MIN has already secured along the same path. Starts at +∞. Shrinks only at MIN nodes: β = min(β, value).

  • Each node takes the window [α, β] from its parent and passes it unchanged to its children; only the value goes back to the parent.
  • If a node's value falls outside this window it cannot affect the result: below α, MAX will not choose it; above β, MIN will not.
  • Once the window is empty (α ≥ β), the node's remaining children need not be examined.

Alpha-Beta Pruning

The Pruning Condition: α ≥ β

The MIN root secured 6 from B (β = 6). C is a MAX node; its first leaf is 7 → α = 7 ≥ β = 6. C gives at least 7, so MIN will not choose C: leaf 4 is pruned.

Both cases are the same condition: α ≥ β. Some books call the cutoff at a MIN node an α-cutoff and the one at a MAX node a β-cutoff.

Alpha-Beta Pruning

Why Pruning Does Not Change the Result

  • Called with the window [α, β], alpha-beta guarantees (v the true minimax value, r the returned value):
if α < v < βr = v (exact value)
if v ≤ αr ≤ α (only known to be "bad enough")
if v ≥ βr ≥ β (only known to be "good enough")
  • The root is called with (−∞, +∞); v always lies inside, so the root's value is exact.
  • Whatever the true value of a pruned branch, it cannot change the parent's max or min: for MAX a value ≤ α cannot exceed α, and for MIN a value ≥ β cannot drop below β.
  • Numbers returned at inner nodes may be bounds; the move chosen at the root is still minimax's move.

Alpha-Beta Pruning

Code Trace: The Alpha-Beta Function

from math import inf
T = {"A": ["B", "C", "D"], "B": [3, 5],
     "C": [2, 9], "D": [6, 4]}
def alphabeta(n, a, b, maxi):
  if isinstance(n, int):        # leaf
    return n
  best = -inf if maxi else inf
  for c in T[n]:
    v = alphabeta(c, a, b, not maxi)
    if maxi:
      best = max(best, v); a = max(a, best)
    else:
      best = min(best, v); b = min(b, best)
    if a >= b:
      break                  # prune
  return best
print(alphabeta("A", -inf, inf, True))

Alpha-Beta Pruning

Alpha-Beta by Hand: Solution

B receives [−∞, +∞]. D (MAX) reads 3 and 7: D = 7. B (MIN) sets β = 7.

E receives [−∞, 7]. First leaf 9 → α = 9 ≥ β = 7: E gives at least 9, B will not choose it; leaf 1 is pruned. B = min(7, 9) = 7.

At the root α = 7. C receives [7, +∞], and so does F. F (MAX) reads 4 and 2: F = 4 (α stays 7).

At C, β = min(+∞, 4) = 4 ≤ α = 7: C gives at most 4, the root will not choose it. All of G (6 and 8) is pruned.

Root = max(7, 4) = 7: MAX picks B. 5 of the 8 leaves were read and 3 pruned. Same result as minimax.

Move Ordering

Move Ordering

  • How much alpha-beta prunes depends on the order in which children are tried; the root value does not.
  • Best ordering (largest child first at MAX, smallest first at MIN): b⌈d/2⌉ + b⌊d/2⌋ − 1 ≈ bd/2 leaves evaluated (Knuth and Moore, 1975).
  • Worst ordering: no pruning at all; all bd leaves are read.
  • Result: about twice the depth in the same time; the effective branching factor drops from b to √b.
  • Where does a good ordering come from? Game knowledge (the center column in Connect Four, center and corners in tic-tac-toe, captures first in chess) and the best move of the previous search.

Connect Four

Connect Four: Why Not a Full Search?

  • 7 columns, 6 rows; a disc drops to the lowest empty cell of the chosen column. The first to line up four discs horizontally, vertically or diagonally wins.
  • The branching factor is at most 7, and a game lasts at most 42 plies. There are 4,531,985,219,092 ≈ 4.5·1012 legal positions (John Tromp).
  • The game was solved independently in 1988 by James D. Allen and Victor Allis: the first player can force a win by starting in the middle column.
  • The solution was found not by brute force but with game-specific rules and very strong search. No browser can do this in a second.
What do we do?

The search is cut off at a fixed depth. Positions there are not terminal, so their utilities are unknown; instead an evaluation function estimates how good a position is.

From the start position, even depth 7 means 960,793 nodes for minimax.

Connect Four

Depth-Limited Search

H(s, d) =
  utility(s)          if s is terminal
  E(s)                if d = 0
  max  H(result(s, a), d − 1)  MAX
   a
  min  H(result(s, a), d − 1)  MIN
   a

Utility in the lab: +(1000 − k) if Red (MAX) wins on ply k, −(1000 − k) if Blue wins, 0 if the board fills up. Numbers near 1000 appear on the column buttons as "win" or "loss".

  • Cutoff test: stop descending if the game is over or the depth limit is reached.
  • E(s) is an estimate, not an exact value: large if the position looks good for MAX, small if it looks bad.
  • Terminal values must lie above or below every value of E: wins are around ±1000, E is at most a few hundred.
  • The depth penalty applies here too: quick wins and slow losses are preferred.
  • Alpha-beta works unchanged; at the cutoff, E values are used like leaves.

Connect Four

The Horizon Effect

  • Since the search stops at the depth limit, it cannot see events just beyond it: this is the horizon effect.
  • In the figure the position below B looks best with E = +6; yet one move later an unavoidable loss follows.
  • A sneakier form: pointless moves that push an unavoidable loss beyond the horizon (useless checks in chess). The loss does not go away; it just becomes invisible.
  • Remedies: search deeper, keep searching in volatile positions (quiescence search), extend one more ply when there are threats.
  • In Connect Four, an AI playing at depth 1 or 2 cannot see double threats and can be beaten.

The Search in the Lab

from math import inf
def alphabeta(s, d, a, b, maxi):
  if s.over():                # game over
    return s.utility()           # ±(1000 − k) or 0
  if d == 0:
    return E(s)                # evaluation
  best = -inf if maxi else inf
  for m in ordered(s.moves()):
    v = alphabeta(s.play(m), d-1, a, b, not maxi)
    if maxi:
      best = max(best, v); a = max(a, best)
    else:
      best = min(best, v); b = min(b, best)
    if a >= b:
      break
  return best
def best_move(s, d):     # root: MAX
  a, best = -inf, None
  for m in ordered(s.moves()):
    v = alphabeta(s.play(m), d-1,
                  a, inf, False)
    if v > a:
      a, best = v, m
  return best
  • It is game-independent: only over, utility, moves, play and E are game-specific.
  • At the root, α is carried across the root's children: after the first child, the rest are searched with a narrower window.
  • To show each column's score, the lab also runs plain minimax and compares the two results.

Connect Four

Iterative Deepening and Transposition Tables

Iterative deepening
  • Search to depth 1, then 2, 3, … until time runs out; then play the move of the last completed search.
  • Little work is repeated: the last level outweighs all the others combined (for b = 7 the total is about 7/6 times the work).
  • The previous search's best move is tried first: move ordering improves automatically.
Transposition table
  • The same position is reached by different move orders (transposition). Search it once and store the result in a hash table.
  • Entry: value, search depth, whether the value is exact or a lower/upper bound, best move.
  • In tic-tac-toe, 5,478 positions instead of 549,946 nodes. Chess programs map a position to a hash key with Zobrist's (1970) method.
The skeleton of strong game programs: iterative deepening + alpha-beta + good move ordering + transposition table + a good evaluation function.

Wrap-up

Common Mistakes

Passing α and β the wrong way

The window goes down unchanged from parent to child; only the value comes back up. An α or β updated in a child is not carried to the parent. MAX updates only α, MIN only β.

Counting a pruned branch

Pruned leaves are not read; feeding them into a min or max when solving by hand is wrong. The number returned by a cut-off node is a bound, not an exact value.

Viewpoint and sign errors

E(s) must always be written from the same player's view (here Red/MAX). If the AI moves second it picks the smallest; with negamax the sign flips at every level.

Forgetting the depth penalty

If all wins get the same value, the AI postpones a ready win, and when losing it may pick the fastest loss. Utility must also reflect how many moves away the win is.

Wrap-up

Game-Tree Search in the Real World

Deep Blue (1997)

IBM's computer beat world champion Kasparov 3½–2½ in a six-game match: parallel alpha-beta on custom chess chips, about 200 million positions per second.

Chess engines

Programs such as Stockfish still use alpha-beta-style search: iterative deepening, transposition tables, strong pruning heuristics; since 2020, neural-network evaluation (NNUE).

Go and MCTS

In Go b ≈ 250 and a good E(s) is very hard to write. Monte Carlo tree search (Coulom, 2006; UCT: Kocsis and Szepesvári, 2006) evaluates with random playouts. AlphaGo combined MCTS with deep neural networks and beat Lee Sedol 4–1 in March 2016.

The core idea is unchanged: look ahead assuming the opponent plays best. What changed is how much of the tree is searched and how the leaves are evaluated.

Wrap-up

Summary

Game trees

Nodes are positions, edges moves; MAX ▲ maximizes, MIN ▽ minimizes. Size ≈ bd.

Minimax

Values rise from leaves to root: max at MAX levels, min at MIN levels. The best move against a perfect opponent; O(bd) time.

Nim and tic-tac-toe

In Nim, minimax = P/N = the XOR rule. Tic-tac-toe is worth 0; a depth penalty favors quick wins and slow losses.

Alpha-beta

The window [α, β] comes down from above; when α ≥ β the remaining children are pruned. The root value and move are unchanged.

Move ordering

≈ bd/2 leaves with the best ordering, bd with the worst. Center-out ordering saves 189× in Connect Four.

Depth limit

An evaluation function estimates; the horizon effect, iterative deepening and transposition tables.
