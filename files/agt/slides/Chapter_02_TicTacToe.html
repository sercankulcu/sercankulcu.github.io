How to play

  1. You play X and the AI plays O. Click a square to place your mark (or focus it with Tab and press Enter).
  2. The first player to fill three squares in a row, column, or diagonal wins; if the board fills up, the game is a draw.
  3. The First move option decides who starts.

Colors and marks on the board

  • Orange square: the search is trying this move right now.
  • Green square and its number: the minimax value of this move (from the AI's point of view).
  • If Animate the search is off, the AI moves immediately.
  • With Show move reasoning ticked, empty squares show their number and the panel under the board lists every square the AI tried at each move, with its value. The AI's last move gets an outline.
  • The nodes examined counter on the right shows how many positions the search looked at for that move.

Link to game theory

Tic-tac-toe is a small, zero-sum game of perfect information. If both sides play perfectly the result is a draw: an opponent who plays minimax cannot be beaten, and the best you can hope for against it is a draw.

What is searched?

For every empty square the AI (O) makes that move and then tries all continuations to the end of the game: every possible move of its own (O) and of yours (X), in turn. This is a game tree: the root is the current board, each edge is a move, each leaf is a finished game. The full tree from the empty board has 549,946 nodes (255,168 different games), which is a small number for a computer. So there is no depth limit and every branch is searched to the very end. The values at the leaves are real outcomes, not estimates, so no evaluation function is needed.

Leaf scores

Finished gameScore (from O's side)
O won10 − depth
X won−10 + depth
Draw0

Depth is the number of moves played after the move the AI is trying (the tried move itself is depth 0). If the AI wins with that very move the score is +10, if it wins with its next move +8, and if the opponent wins right after it is −9. Depth is mixed into the score so that winning sooner (or losing later) counts as better. The number 10 has no special meaning: a game lasts at most 9 moves, so 10 − depth never reaches 0, which means a win is always worth more than a draw.

Values move up the tree (minimax)

Work from the leaves to the root. The value of a node where it is O's turn is the maximum of its children (O wants a larger score). The value of a node where it is X's turn is the minimum of its children: the game is zero-sum, so X's gain is O's loss and X picks the move that makes O's score smallest. The value at the root is what O gets if both sides play without mistakes; the AI plays the move that has this value.

Alpha-beta pruning

The search carries two bounds: alpha (the best score O is already guaranteed) and beta (the best score X is already guaranteed). When beta ≤ alpha the remaining squares of that branch are skipped, because the other side would never let the game enter it. The chosen move and its value never change; only fewer nodes are looked at. The counter and the panel show this: from the empty board 34,202 nodes are examined instead of 549,945. Each move at the root is searched with the window (−∞, +∞), so every value you see in the panel is exact, not a bound.

The largest value is +10, so the AI plays 6. Thanks to pruning, this position takes 24 nodes instead of 33. Now from the empty board: if you open in a corner (1), the AI answers 5 (the center); the center has value 0 and every other square has value −5 (X wins three moves later). So the center is the only correct reply, and the search finds this with certainty.

Why can't the AI lose?

Because the search sees every branch to the end, the values it finds are exact game values. The value of tic-tac-toe is a draw (Zermelo's theorem: a finite, zero-sum game of perfect information has a value). So against every first move of X there is a reply worth at least 0 for O, and since the AI always plays the highest-valued move, it never lets the value drop. If you make a mistake the value turns positive and the AI converts it into a win. The best result you can get against it is a draw.

What does the panel show?

With Show move reasoning ticked, after the AI moves the panel lists: every square it tried, that square's minimax value (green positive, red negative), a verbal reading of the result, and the number of nodes searched for that square. The chosen row is highlighted in yellow. The header gives the total number of nodes and the number that would have been searched without pruning. Related lecture: Minimax and Alpha-Beta Pruning.

The JavaScript on this page

Below is the real code that runs the AI; only the animation lines are shortened with .... The page calls these functions and there is no hidden extra rule anywhere.

/* root: the AI (O) tries every empty square; each is searched with a full window */
async function aiMove(version) {
  var anim = animateBox.checked;
  var bestScore = -Infinity;
  var move;
  var rows = [];                         /* record for the reasoning panel */
  nodes = 0;
  for (var i = 0; i < 9; i++) {
    if (gameBoard[i] !== "") continue;   /* empty squares only */
    ...                                  /* (orange square animation) */
    gameBoard[i] = "O";                  /* try the move */
    var n0 = nodes;
    var score = await minimax(gameBoard, 0, false, -Infinity, Infinity, version, anim);
    gameBoard[i] = "";                   /* undo it */
    rows.push({ sq: i, v: score, n: nodes - n0 });
    ...                                  /* (green value animation) */
    if (score > bestScore) { bestScore = score; move = i; }  /* on a tie the first square stays */
  }
  ...
  gameBoard[move] = "O";                 /* play the move with the highest value */
  ...
}

/* b: board, depth: depth, isMaximizing: is it O's turn (MAX) */
async function minimax(b, depth, isMaximizing, alpha, beta, version, anim) {
  nodes++;                               /* the panel's node counter */
  if (version !== gameVersion) return 0; /* search of an old game: give up */
  var result = checkWinner(b);
  if (result === "X") return -10 + depth;  /* X won */
  if (result === "O") return 10 - depth;   /* O won */
  if (result === "draw") return 0;         /* board full */
  ...
  var best = isMaximizing ? -Infinity : Infinity;
  for (var i = 0; i < 9; i++) {
    if (b[i] !== "") continue;
    ...
    b[i] = isMaximizing ? "O" : "X";     /* try the move */
    var v = await minimax(b, depth + 1, !isMaximizing, alpha, beta, version, anim);
    b[i] = "";                           /* undo it */
    ...
    if (isMaximizing) { best = Math.max(best, v); alpha = Math.max(alpha, v); }
    else { best = Math.min(best, v); beta = Math.min(beta, v); }
    if (beta <= alpha) break;            /* pruning: the remaining squares are skipped */
  }
  return best;
}

/* a complete line means a winner, a full board means "draw" */
function checkWinner(b) {
  var l = winLineOf(b);
  if (l) return b[l[0]];
  if (b.every(function (c) { return c !== ""; })) return "draw";
  return null;
}

The same idea in Python

The same structure as alphabeta and best_move in the course repository; the board is a 9-character string. Try it: best_move('XX.OO...X') returns 6.

from math import inf

LINES = [(0, 1, 2), (3, 4, 5), (6, 7, 8), (0, 3, 6),
    (1, 4, 7), (2, 5, 8), (0, 4, 8), (2, 4, 6)]

def winner(b):                          # b: 9-character string of 'X', 'O', '.'
  for i, j, k in LINES:
    if b[i] != '.' and b[i] == b[j] == b[k]:
      return b[i]
  return 'draw' if '.' not in b else None

def alphabeta(b, depth, maxi, a, beta):
  w = winner(b)
  if w == 'X': return -10 + depth     # X wins: the later, the better for O
  if w == 'O': return 10 - depth      # O wins: the sooner, the better
  if w == 'draw': return 0
  best = -inf if maxi else inf
  for i in range(9):
    if b[i] != '.': continue
    c = b[:i] + ('O' if maxi else 'X') + b[i+1:]
    v = alphabeta(c, depth + 1, not maxi, a, beta)
    if maxi:
      best = max(best, v); a = max(a, v)
    else:
      best = min(best, v); beta = min(beta, v)
    if beta <= a:
      break                       # pruning
  return best

def best_move(b):                       # root: O (MAX), full window per move
  best, move = -inf, None
  for i in range(9):
    if b[i] != '.': continue
    v = alphabeta(b[:i] + 'O' + b[i+1:], 0, False, -inf, inf)
    if v > best:
      best, move = v, i + 1
  return move

print(best_move('XX.OO...X'), best_move('X........'))

Try it yourself

  1. Predict, then look. Tick Show move reasoning and play one of the corners. Before the AI answers, predict which square will have value 0 and which will be negative. Then read the panel. The negative values describe when X wins; what does −5 mean in moves? (Look at the Outcome column.)
  2. Compute a value by hand. Late in a game, with three or four squares empty, pick a row in the panel. Fill that square, draw a small tree with the remaining empty squares, write 10 − depth / −10 + depth / 0 on the leaves and back them up with min and max. Does your number match the panel?
  3. Measure what pruning saves. Let the AI start (First move: AI) and note the two numbers in the header, nodes examined and without pruning. Then look at the same two numbers in later moves. How does the ratio change, and why?
  4. Try to beat the AI. Play several games with different openings and, before each move, use the panel values to think about whether your move gives the AI a draw or something better. Can you never win? Which moves push the AI's value above 0?
  5. Turn on the animation. With Animate the search ticked, watch the AI walk over the squares and compare the values on the squares with the panel.

Discussion questions

  • Why do the leaves get 10 − depth and −10 + depth instead of just +1 and −1?
    Answer

    With +1 and −1, winning at once and winning ten moves later get the same value; the AI plays the first winning move it finds and may drag the win out for no reason. In a lost position the opposite happens: it does not put up the longest resistance. Mixing depth into the score gives the preference "win sooner, lose later". It does not change the ordering: a win is still better than a draw and a draw still better than a loss.

  • If both sides play perfectly, why is the result always a draw?
    Answer

    Because the minimax value of the game is 0. No first move forces a win for X; against every move of X, O has a reply that gives at least a draw. In zero-sum games of perfect information (Zermelo) such a value always exists; in tic-tac-toe it is zero, in Connect Four it is a win for the first player.

  • What would change in the panel if alpha-beta carried the root's alpha across moves (starting each root move with the best value so far instead of -Infinity)?
    Answer

    The chosen move and its value would stay the same, but fewer nodes would be searched. The values of the non-best root moves would no longer be exact: the search stops with "this move is worth at most that much", so the panel would show upper bounds such as "≤ v". This page searches every root move with a full window, so it can show all values as exact; trading that away for speed is common in real programs.

  • Would the same method work for 4×4 tic-tac-toe or Connect Four?
    Answer

    Not with a full search: the tree grows very fast (an upper bound of 9! ≈ 363 thousand move orders for 3×3, 16! ≈ 20 trillion for 4×4; about 1013 positions in Connect Four). So a depth limit is introduced, and positions at the limit whose result is unknown are estimated with an evaluation function. You can see this in the Chapter 2 Connect Four game: depth 7 and heuristic scores.
