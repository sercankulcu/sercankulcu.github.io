Nim-sum

Click a token: it and every token to its right are taken.

How to play

  1. The game starts with several heaps holding different numbers of tokens.
  2. On your turn you pick exactly one heap and take one or more tokens from it; you may take the whole heap.
  3. Click a token on the board: it and all tokens to its right are taken (hovering shows a preview).
  4. Under the normal play rule used here, the player who takes the last token wins.

The nim-sum

Write each heap size in binary and combine the values with XOR. The result is the nim-sum. A position with nim-sum zero is lost for the player to move if the opponent plays perfectly; from any position with nonzero nim-sum there is at least one move that leaves the opponent a nim-sum of zero. Tick Binary + nim-sum to show the binary columns during play.

Strategy tips

  • Do not pick a move just because it takes many tokens.
  • The goal is to leave a nim-sum of zero after your own move.
  • If the nim-sum is already zero, no move can keep it that way; the aim becomes leaving the opponent the hardest practical reply.
  • Comparing your intuition with the Optimal computer shows how the mathematical strategy works.

Link to game theory

Nim is one of the clearest examples of a game with a complete mathematical solution. It illustrates winning and losing positions, backward induction, invariant-based strategies, and how a short algebraic description can replace brute-force search.

No search: one rule

Unlike the board-game pages that search a game tree, this computer applies a rule taken from the mathematical solution of Nim (function ai). The rule depends on the Computer setting:

  1. Nim-sum. XOR all heap sizes: x = h1 ⊕ h2 ⊕ … ⊕ hn. In binary: write the sizes in columns; a column of the result is 1 when it contains an odd number of 1s.
  2. Optimal, x ≠ 0 (winning position). Go through the heaps from first to last. The first heap with h ⊕ x < h is reduced to h ⊕ x, so the computer takes h − (h ⊕ x) tokens. The new nim-sum is 0.
  3. Optimal, x = 0 (losing position). No move can leave nim-sum 0, so the computer takes 1 token from a random non-empty heap.
  4. Random. A random non-empty heap, then a random number of tokens from 1 to its size. The nim-sum is ignored.
Worked example. Heaps 3, 5, 5 are 011, 101, 101 in binary, so x = 011 = 3. Heap 1: 3 ⊕ 3 = 0 < 3, so take 3 − 0 = 3 tokens, leaving 0, 5, 5 with nim-sum 0. Heap 2 would not work: 5 ⊕ 3 = 6 ≥ 5, and you cannot add tokens. A 4-heap example: 1, 4, 6, 8 gives x = 1011 = 11; only heap 4 can shrink (8 ⊕ 11 = 3 < 8), so the computer takes 5 and leaves 1, 4, 6, 3 with nim-sum 0.

Is the rule optimal?

Yes in a winning position. This is Bouton's theorem (1901): the positions with nim-sum 0 are exactly the losing positions for the player to move. The proof is a backward-induction argument in three steps:

  • The final position (all heaps empty) has nim-sum 0, and the player to move there has lost, because the opponent took the last token.
  • From a position with nim-sum 0, every move changes exactly one heap, so the new nim-sum cannot be 0.
  • From a position with nim-sum ≠ 0 there is always a move to 0: take the leftmost 1-bit of x, pick a heap that has a 1 in that column (one must exist) and reduce it to h ⊕ x.

So the player who leaves nim-sum 0 every time can never be forced into a loss. All three starting layouts have a nonzero nim-sum (1⊕3⊕5 = 7, 3⊕5⊕7 = 1, 1⊕4⊕6⊕8 = 11), so you, moving first, are in a winning position; the Optimal computer wins only after you leave a nonzero nim-sum once.

In a losing position nothing is optimal: every move loses against perfect play. Taking a single token is just a practical choice that keeps the game as long as possible and gives the opponent the most chances to err; the random heap makes it less predictable. The Random computer has no strategy at all.

Why a rule instead of a search?

For heaps 3, 5, 7 there are only 4·6·8 = 192 positions, so labelling every position as winning or lost by backward induction (as in Minimax) is easy. But the table grows with the product of the heap sizes and is hopeless for heaps of a million tokens, while the XOR rule needs only n operations. Nim is the clearest case of an algebraic description replacing brute-force search; by the Sprague–Grundy theorem every impartial game is equivalent to a Nim heap. See Chapter 2 · Games and Representations for winning and losing positions and backward induction.

What the panel shows

1. The computer's move: ai

function ai() {
  aiTimer = null;
  if (over || turn !== 1) return;
  // nim-sum: XOR of all heap sizes
  var x = heaps.reduce(function (a, b) { return a ^ b; }, 0);
  var move = null;                  // [heap index, tokens to take]
  if (E('nimAI').value === 'Optimal' && x) {
    for (var i = 0; i < heaps.length; i++) {
      var t = heaps[i] ^ x;         // size this heap would need
      if (t < heaps[i]) {           // it can only shrink, not grow
        move = [i, heaps[i] - t];
        break;                      // first heap that works
      }
    }
  }
  if (!move) {                      // losing position, or Random computer
    var ids = heaps.map(function (h, i) { return h ? i : -1; })
                   .filter(function (i) { return i >= 0; });   // non-empty heaps
    var j = ids[Math.floor(Math.random() * ids.length)];
    move = E('nimAI').value === 'Optimal'
      ? [j, 1]                                                 // Optimal: just 1 token
      : [j, 1 + Math.floor(Math.random() * heaps[j])];         // Random: any amount
  }
  take(move[0], move[1], true);     // remove the tokens, check for the end
}

2. The same idea in Python

The nim-sum loop is the one in nim_xor.py (Chapter 2 code trace); here it is wrapped into a function that also covers the fallback.

import random

def nim_sum(heaps):
    x = 0
    for h in heaps:
        x ^= h                       # nim-sum (XOR), as in nim_xor.py
    return x

def computer_move(heaps, optimal=True):
    x = nim_sum(heaps)
    if optimal and x:                # winning position: make the nim-sum 0
        for i, h in enumerate(heaps):
            if h ^ x < h:            # this heap can shrink to h ^ x
                return i, h - (h ^ x)
    ids = [i for i, h in enumerate(heaps) if h]   # non-empty heaps
    j = random.choice(ids)
    return (j, 1) if optimal else (j, random.randint(1, heaps[j]))

print(computer_move([3, 5, 5]))      # (0, 3): take 3 from heap 0 -> [0, 5, 5]
print(computer_move([1, 4, 6, 8]))   # (3, 5): take 5 from heap 3 -> [1, 4, 6, 3]

A brute-force check that the XOR rule labels positions correctly (backward induction over all positions with heaps up to 3, 5, 7):

from functools import lru_cache

@lru_cache(None)
def wins(heaps):                     # heaps: sorted tuple; True if the player to move wins
    return any(not wins(tuple(sorted(heaps[:i] + (h - k,) + heaps[i + 1:])))
               for i, h in enumerate(heaps) for k in range(1, h + 1))

# backward induction over all positions agrees with the nim-sum:
print(all(wins(p) == (nim_sum(p) != 0)
          for p in [(a, b, c) for a in range(4) for b in range(a, 6) for c in range(b, 8) if c]))
# True

Try it yourself

  1. Predict first, then look. Tick Binary + nim-sum and Show move reasoning. Make a move, and before the computer answers work out the nim-sum of the position you left and which heap the computer must reduce. Then read the panel: did you get the same heap and the same number of tokens?
  2. Beat the computer. With Medium (3, 5, 7) the nim-sum is 1, so you are in a winning position. Find your first move (hint: more than one works). Then leave nim-sum 0 at every turn. What does the panel say each time the computer has to move?
  3. Make a deliberate mistake. In a new game play a move that leaves a nonzero nim-sum. Read the panel: which heaps are marked as possible (the chosen one plus the greyed ones)? Check by hand that the move it made leaves nim-sum 0.
  4. Hard layout and Random. Switch to Hard (1, 4, 6, 8) and recompute the nim-sum in four binary columns by hand before you click. Then set the computer to Random and play a few games: does the panel use the nim-sum at all? How often does the Random computer leave nim-sum 0 by luck?

Discussion questions

  • In a losing position (nim-sum 0) the computer just takes 1 token from a random heap. Is there a better rule?
    Answer

    No. Every move changes one heap and so leaves a nonzero nim-sum, which means the opponent can answer with a winning move; against perfect play every move loses. Taking 1 token is only a practical choice: it keeps the game long so that a fallible opponent has the most chances to slip. Against a perfect opponent all moves are equal.

  • Why does the nim-sum, an XOR, tell us who wins? What stays the same during the game?
    Answer

    The invariant is “nim-sum 0 after my move”. The empty position has nim-sum 0; from nim-sum 0 every move breaks it (one heap changes, so the XOR changes); from nim-sum ≠ 0 some move restores it. A player who can always restore it never runs out of moves before the opponent does, and the last token is taken by that player. This is the pattern of backward induction: the winning and losing labels propagate backward from the end position.

  • The computer takes the first heap that works. Can there be several winning moves? Does the choice matter?
    Answer

    Yes, there can be several: every heap that has a 1 in the leftmost 1-bit column of x works (for 3, 5, 7 all three heaps do). Against a perfect opponent the choice does not matter: each one leaves nim-sum 0 and wins. The panel greys the other working heaps to show this.

  • This game uses the normal play rule: the player who takes the last token wins. Would the same rule be optimal if the last taker lost (misère Nim)?
    Answer

    Not quite. In misère Nim you play exactly as in normal Nim until every heap has at most 1 token; then you must leave an odd number of heaps of size 1 (normal play would leave an even number). Near the end the two games need opposite moves, which shows that a small change in the payoffs can change the optimal strategy.
