Networks and Routing

Network Design and Routing

  • Network design decides the nodes, links, capacities and costs.
  • Routing decides which paths the flow takes from source to destination.
  • Algorithmic game theory studies traffic and communication networks whose users each try to reduce their own cost.
  • Key applications: city traffic, Internet backbones, power grids.

Networks and Routing

Basic Network Design Concepts

Nodes and links

Node: an intersection, router or substation. Link: a road, fiber line or transmission line.

Capacity and bandwidth

The flow a link can carry per unit time; beyond it, latency rises sharply.

Cost

Building cost (design) and usage cost: latency, energy, tolls (routing).

Example

Tree/layered topology in a data center; a near-mesh road network in a city.

Classic algorithms assume fixed edge weights. In reality latency depends on how many people choose a path; when strategic users can deviate from the suggested route, the network equilibrium and the system optimum diverge. This turns routing into a game.

Networks and Routing

Latency Depends on Load: ℓe(x)

  • Each edge's latency is a nondecreasing function of its flow x: ℓe(x).
  • Constant: a wide highway, ℓ = b.
  • Linear: ℓ = a·x + b (the two-route and Braess examples).
  • BPR (US Bureau of Public Roads): ℓ = t0(1 + 0.15 (x/c)4); t0: free-flow time, c: road capacity. Standard in traffic planning.
  • Queueing delay in networks: ℓ = 1/(c − x), only for 0 ≤ x < c (single-server queue, M/M/1; c: packets served per second, x: packets arriving per second). As x approaches c, latency grows without bound; for x ≥ c the queue grows forever.

Selfish Routing

Selfish Routing

  • Each user picks the route that minimizes their own latency.
  • With many small users, flow is treated as splittable (nonatomic): a single user's effect is negligible.
  • Individual route choices can drift away from the system optimum, which minimizes total latency.
  • In Braess's paradox, adding a link can increase the equilibrium latency.
Modelr units of traffic s → t
fP: flow on path P

A path's latency is the sum of its edges' latencies; total latency is flow × latency summed over edges.

Selfish Routing

Wardrop's Principles (1952)

1st principle: user equilibrium

  • All used paths have equal, minimal latency.
  • Unused paths are no faster.
  • No single user can cut their travel time by switching.

2nd principle: system optimum

  • Average (total) latency is minimal.
  • The split a central planner would choose.
  • Some users may be “sacrificed” to a slower road.
In short: no used path is slower than any other path. Equilibrium explains users' individual choices, but it need not match the system optimum. With linear latencies an equilibrium exists, and every equilibrium gives each edge the same latency.

Selfish Routing

Step by Step: Wardrop Equilibrium on Two Routes

Setup: 3,000 cars travel from A to B. Route 1 is short but narrow (latency rises fast); Route 2 is long but wide.

Try 1: everyone on Route 1 → ℓ₁ = 35 min, while the empty Route 2 takes 20. Route 1 drivers want to switch: not an equilibrium.

Try 2: 1,500 / 1,500 → ℓ₁ = 20, ℓ₂ = 27.5 min. Now Route 2 drivers move to Route 1: still not an equilibrium.

Equilibrium condition: if both routes are used, their latencies must be equal: 5 + x₁/100 = 20 + (3000 − x₁)/200.

×200: 1000 + 2x₁ = 4000 + 3000 − x₁ → 3x₁ = 6000 → x₁ = 2,000, x₂ = 1,000; both take 25 min.

Check: a driver who switches still faces ≈ 25 min → nobody gains. Total latency 3,000 × 25 = 75,000 car·min.

Selfish Routing

Equilibrium and Optimum: Two Different Minimizations

Wardrop equilibrium

Minimizes the Beckmann potential (Beckmann, McGuire, Winsten, 1956):
Φ(f) = Σe ∫0fe ℓe(t) dt
Derivative ℓe: the latency seen by the “last driver in”.

System optimum

Minimizes total latency:
C(f) = Σe fe·ℓe(fe)
Derivative ℓe + fe·ℓ′e: the marginal cost.

The two curves bottom out in different places: Φ at x₁ = 2,000 (equilibrium, Φ = 52,500), C at x₁ = 1,500 (optimum, C = 71,250). The gap comes from one term: a driver ignores the x·ℓ′ externality their presence imposes on others.

Selfish Routing

Code Trace: find_eq(l1, l2, r)

Call: the two-route network (ℓ₁ = 5 + x/100, ℓ₂ = 20 + x/200), 3,000 cars. Goal: the x with ℓ₁(x) = ℓ₂(r − x).

Search interval [0, 3,000]: the equilibrium must lie here (at x = 0 Route 1 is faster, at x = r slower).

Round 1: x = 1,500 → ℓ₁ = 20 < ℓ₂ = 27.5. Route 1 is still faster, so more cars move to it: lo = 1,500.

Round 2: x = 2,250 → ℓ₁ = 27.5 ≥ ℓ₂ = 23.75. Route 1 is too crowded: hi = 2,250.

Round 3: x = 1,875 → ℓ₁ = 23.75 < ℓ₂ = 25.63. Route 1 is still faster, so more cars move to it: lo = 1,875.

Round 4: x = 2,062.5 → ℓ₁ = 25.63 ≥ ℓ₂ = 24.69. Route 1 is too crowded: hi = 2,062.5.

Round 5: x = 1,968.75 → ℓ₁ = 24.69 < ℓ₂ = 25.16. Route 1 is still faster, so more cars move to it: lo = 1,968.75.

Round 6: x = 2,015.63 → ℓ₁ = 25.16 ≥ ℓ₂ = 24.92. Route 1 is too crowded: hi = 2,015.63.

Width 46.88 ≤ 50 → stop. Result ≈ 1,992.19 (true equilibrium 2,000). Each round halves the interval: after k rounds the error is ≤ r/2k.

def find_eq(l1, l2, r, eps=50):
  if l1(0) >= l2(r): return 0   # route 1 unused
  if l1(r) <= l2(0): return r   # all on route 1
  lo, hi = 0, r
  while hi - lo > eps:
    x = (lo + hi) / 2
    if l1(x) < l2(r - x):
      lo = x      # route 1 faster: raise
    else:
      hi = x      # route 1 slower: lower
  return (lo + hi) / 2

Since ℓ₁(x) − ℓ₂(r − x) is nondecreasing, its zero is the equilibrium; the first two lines catch the corner cases. In general networks the Beckmann potential is minimized by convex optimization (e.g. Frank–Wolfe).

Braess's Paradox

Step by Step: Braess's Paradox (4,000 Cars)

Setup: 4,000 cars from s to t. s→A and B→t are narrow roads (x/100 min); A→t and s→B are wide highways (always 45 min).

Symmetry: 2,000 / 2,000 → both paths take 2000/100 + 45 = 65 min. Switching doesn't help: a Wardrop equilibrium (and the optimum).

The city opens a very short, 0-minute link road from A to B. At first nobody uses it.

One driver tries s→A→B→t: 20 + 0 + 20 = 40 min < 65. Very profitable individually → they switch.

1,000 drivers have switched: 2,500 cars on the narrow roads → 25 min. Old paths 70, zigzag 50 min: switching continues.

Everyone zigzags: 40 + 0 + 40 = 80 min. Going back to an old path costs 40 + 45 = 85 min → nobody goes back: a new equilibrium.

Result: a road was added and everyone lost 15 min. More capacity + selfish choice = a worse equilibrium. The system optimum with the shortcut is ≈ 64.7 min (only 500 cars on the zigzag).

Braess's Paradox

Why Does Everyone Zigzag?

If the rest of the traffic splits evenly over the two old paths, they take 65 + z/200 and the zigzag 40 + z/100 min. The zigzag is faster for every z (B→t is at most 40 min < 45), so it is a dominant choice for everyone. But each switching driver loads the narrow roads: at z = 4,000 everyone takes 80 min.

Braess's Paradox

Braess's Paradox: Lessons and Examples

  • Adding a link to a network can increase the latency of all users because of selfish route choice (Braess, 1968).
  • The new road looks attractive individually, but the traffic pattern users create together moves to a worse equilibrium.
  • Conversely, closing a road can sometimes speed everyone up.
Stuttgart (1969)

Traffic that worsened after a new road investment is often said to have improved once a street was closed (Knödel, 1969).

New York (1990)

When 42nd Street was closed on Earth Day, the expected gridlock reportedly never came (Kolata, 1990).

Mechanical / electrical

A similar paradox appears in networks of springs and resistors (Cohen and Horowitz, 1991).

Tolls, access restrictions or central routing can reduce the effect.

Braess's Paradox

Back to the Warm-up: Braess's Paradox

The theory's answer: no

No shortcut20 + 45 = 6565
With shortcut40 + 0 + 40 = 80≈ 64.7

With the shortcut everyone picks S→A→B→T. Going back to an old road costs 40 + 45 = 85, so nobody does: equilibrium 80. The optimum with the shortcut gives the zigzag a small share (1,750 / 1,750 / 500 cars → 258,750 / 4,000 ≈ 64.7).

In practice

In laboratory experiments, too, subjects drifted over time toward the slower equilibrium the paradox predicts once the shortcut was added (Rapoport et al., 2009).

In cities: besides Stuttgart and New York, removing the elevated highway over Seoul's Cheonggyecheon in the early 2000s is often said not to have worsened traffic as feared. Real networks are far more complex; these cases are not proof, only signs that the paradox is possible.

Building or closing a road should be judged by the equilibrium drivers will reach, not by capacity alone.

Braess's Paradox

Code Trace: best_subnet(net, r)

Call: the Braess network, 5 edges, 4,000 cars. Question: closing which edge cuts the equilibrium time the most?

Equilibrium of the full network: everyone zigzags, 80 min. Removing nothing is the initial candidate.

Close s→A: only s→B→t remains: 40 + 45 = 85 min.

85 < 80 is false → candidate unchanged.

Close A→t: the zigzag and the lower path remain; the zigzag dominates: 80 min.

80 < 80 is false → candidate unchanged.

Close s→B: the upper path and the zigzag remain; the zigzag dominates: 80 min.

80 < 80 is false → candidate unchanged.

Close B→t: only s→A→t remains: 40 + 45 = 85 min.

85 < 80 is false → candidate unchanged.

Close A→B: the pre-Braess network: 2,000 / 2,000, 20 + 45 = 65 min.

65 < previous best → update: new best subnetwork “A→B closed”.

Result: close A→B; equilibrium 80 → 65 min. The designer asks “which edges should stay open?”; in general networks this choice is hard.

def best_subnet(net, r):
  best, cut = eq_time(net, r), None
  for e in net:
    sub = [k for k in net if k != e]
    d = eq_time(sub, r)   # inf if no path
    if d < best:
      best, cut = d, e
  return cut, best

eq_time(net, r): the common time of the used paths in the subnetwork's Wardrop equilibrium (computed in the script by minimizing the Beckmann potential). The code only tries removing one edge; a full search needs 2m subnetworks.

Braess's Paradox

Network Design for Selfish Users

Problem

Which subnetwork of a given network, left open, minimizes the Wardrop equilibrium time? Closing a road, not only building one, is a design decision.

Further reading: hardness

Choosing the best edges to close is hard in general: with linear latencies, closing nothing is at most 4/3 times worse than the best choice, and guaranteeing anything better efficiently is NP-hard (Roughgarden, 2006).

Further reading: topology

In networks built from parallel paths and their series connections (series-parallel), Braess's paradox never occurs; other networks can show it with suitable latencies (Milchtaich, 2006).

Congestion Games

Congestion Games

  • n players, a set of resources E (edges). Each player's strategy is a subset of resources (e.g. an s–t path).
  • A resource's cost ce(ne) depends only on the number of players using it and grows with that load.
  • A player's cost: the sum of the costs of the chosen resources.
  • As players try to cut their own latency, the total network cost can rise.
AtomicNonatomic
Playersfinite, n playerscontinuous flow
Effectone player adds 1 to the loadone player is negligible
Equilibriumpure NashWardrop
PotentialRosenthal (sum)Beckmann (integral)
Rosenthal (1973): every finite congestion game has a potential function, so a pure Nash equilibrium always exists. No mixed strategies needed.

Congestion Games

Rosenthal's Potential Function

Φ(s) = Σe [ ce(1) + ce(2) + … + ce(ne) ]
On each edge, add the costs from 1 up to the number of users ne (this is not the total cost).
Example: all 4 drivers on s→A→t. s→A: ce(k) = k → 1 + 2 + 3 + 4 = 10; A→t: ce(k) = 4 → 16; other edges empty. Φ = 26 (total cost 4 × 8 = 32).
Key identity. When driver i leaves an edge, the last term ce(ne) of that edge's sum disappears (that is what i paid there); entering a new edge adds ce(ne + 1) (i's new cost). So the change in Φ is exactly i's change in cost: ΔΦ = ci(new) − ci(old).
Consequence. Every improving move strictly decreases Φ; Φ takes finitely many values → the dynamics stop. Where they stop, nobody can improve → a pure Nash equilibrium exists (Rosenthal, 1973).

Congestion Games

Step by Step: Best-Response Dynamics and Φ

Edge costs: k (number of users) on s→A and B→t, 4 on s→B and A→t, 0 on A→B. Everyone on s→A→t: cost 4 + 4 = 8, Φ = 26.

Driver 1's options: top 8, bottom 4 + 1 = 5, zig 4 + 0 + 1 = 5. Ties go to the first → bottom (8 → 5). Φ: 26 → 23 (Δ = −3).

Driver 2: top 7, bottom 4 + 2 = 6, zig 3 + 0 + 2 = 5 → zig (7 → 5). Φ: 23 → 21 (Δ = −2).

Driver 3: top 7, bottom 4 + 3 = 7, zig 3 + 0 + 3 = 6 → zig (7 → 6). Φ: 21 → 20 (Δ = −1).

Driver 4 (top, 7): bottom 4 + 4 = 8, zig 3 + 0 + 4 = 7 → nothing better, stays. Each drop in Φ equaled the mover's gain.

In the second round nobody can improve → pure Nash equilibrium (Φ = 20). Total 7 + 6 + 6 + 7 = 26; without A→B a 2+2 split would give 24: atomic Braess!

Congestion Games

Potential Games: What Do We Gain?

Existence

A state minimizing Φ is a pure Nash equilibrium; an equilibrium always exists.

Convergence

No sequence of improving moves is infinite (the finite improvement property): best-response dynamics with strict improvements always stop (a player already best-responding stays put).

Speed (further reading)

Stopping is guaranteed, speed is not: for some congestion games no fast method for finding an equilibrium is known (Fabrikant, Papadimitriou, Talwar, 2004).

Generality

Every (exact) potential game is equivalent to a congestion game (Monderer and Shapley, 1996).

Learning

If players best-respond in turn, they reach an equilibrium.

Efficiency

The equilibrium minimizing Φ is one way to select a good equilibrium among many, but it is no guarantee.

Network Formation

Network Externalities: Negative and Positive

  • Externality: a user's decision changes others' costs or benefits, but the user ignores this in their own calculation.

Negative: congestion

  • Each extra driver imposes a total latency of x·ℓ′(x) on the x others on the same road.
  • In the two-route example, with 2,000 cars on Route 1: 2,000 × 1/100 = 20 car·min.
  • Result: the busy road is overused; the remedy is a congestion toll.

Positive: network effects

  • The value of joining grows with the number of members: phones, messaging, social networks.
  • n users have n(n − 1)/2 possible connections; the claim that value grows like n² (Metcalfe) is a heuristic.
  • A new user ignores the benefit they bring others: adoption stays slow until a critical mass is reached.
Network formation games have both: a link shortens distances for others as well as its builder (a positive externality), but only the buyer pays for it.

Network Formation

Network Formation Games

  • So far the network was given; now the players build it themselves: Internet peering, social networks, P2P networks.
  • Every link has a building cost; being well connected (short distances) is valuable. The tension: link cost ↔ reach.
Fabrikant et al. (2003): unilateral

Player i buys links to any nodes (α each). Cost: α·(links bought) + Σj dist(i, j). Equilibrium: Nash.

Jackson–Wolinsky (1996): bilateral

A link needs both sides' consent to form; either side can cut it. Solution concept: pairwise stability.

Questions: Which networks are equilibria? Which is socially best? How far apart can they be?

Network Formation

Bilateral Links: Pairwise Stability (n = 4)

  • Benefit: 4 from each player at distance 1, 2.2 at distance 2, 1 at distance 3.
  • Each link costs 2 to each of its two endpoints.
  • Pairwise stable: (i) no player gains by cutting one of their links; (ii) no missing link would benefit both endpoints together.

Network Formation

Step by Step: A Network Formation Game (n = 4, α = 1.5)

Each player chooses which links to buy themselves; everyone may use a link, whoever bought it.

Path network: 1 buys one link (1.5) and its distances are 1 + 2 + 3 = 6 → 7.5. The end players are far from everyone.

If player 1 buys a second link to 4, its distances drop from 6 to 4: 3 + 4 = 7 < 7.5 → a profitable deviation.

The complete graph is socially cheapest (21). But a player who bought a link saves 1.5 by dropping it and loses only 1 in distance → not an equilibrium.

Star: a new link saves a leaf only 1 in distance (1 < 1.5); if the center drops a link the network splits → nobody deviates.

Brute-force search: at α = 1.5 the equilibria are the star (22.5) and the 4-cycle (22); the optimum (21) is not an equilibrium.

def cost(i, links, alpha):
  dist = {i: 0}; queue = [i]
  while queue:
    u = queue.pop(0)
    for v in nbrs(links, u):
      if v not in dist:
        dist[v] = dist[u] + 1
        queue.append(v)
  bought = sum(1 for (a, b) in links if a == i)
  return alpha * bought + sum(dist.values())

nbrs(links, u): neighbors regardless of who bought the link (everyone uses links); the network is assumed connected. A player pays only for the links they bought.

Control and Incentives

Incentives, Load Balancing and Real Life

Right incentives

  • Steer users toward balanced use of network resources → efficiency improves.
  • Traffic: tolls or warnings reduce congestion.
  • Smart grid: time-of-use pricing balances load at peak hours.

Wrong incentives

  • Strategic, selfish behavior grows → congestion and low efficiency.
  • An app sending everyone the same “fastest” route can flood side streets.
  • A badly chosen toll shifts traffic to another bottleneck.
Internet

ISPs route data packets; BGP picks routes between networks.

Traffic management

Route optimization, smart signals, navigation apps.

Energy

Energy distribution and load shifting in smart grids.

Efficiency vs. Fairness: Sharing Bandwidth

Two links have capacity 1. Flow A uses both, B only link 1, C only link 2: xA + xB ≤ 1, xA + xC ≤ 1. Which allocation should we pick?

CriterionWhat is optimized?(xA, xB, xC)Total
Maximum total flowΣ xi(0, 1, 1)2 (A starves)
Max-min fairness (egalitarian)Raise the smallest share as far as possible, then the next(1/2, 1/2, 1/2)1.5
Proportional fairness (Nash social welfare)Maximize the product of shares (Kelly, 1997)(1/3, 2/3, 2/3)≈ 1.67
Under proportional fairness A, which uses both links, gets less, but nobody drops to zero: a zero share zeroes the product. Maximizing xA(1 − xA)² is the same as maximizing log xA + 2 log(1 − xA); since the derivative of log x is 1/x, 1/xA = 2/(1 − xA) ⇒ xA = 1/3. Kelly et al. (1998) interpret TCP-like congestion control as a distributed algorithm that converges to this allocation via per-link congestion prices.
