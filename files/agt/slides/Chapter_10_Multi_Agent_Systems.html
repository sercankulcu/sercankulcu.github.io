Warm-up: The Shapley Coalition Game

The rules

Each player has a stand-alone value; a coalition's value is its members' stand-alone values plus a synergy bonus for every pair inside it. The grand coalition's value v(N) is split among the players.

Agents and Multi-Agent Systems

What Is a Multi-Agent System (MAS)?

  • A system of several autonomous agents that perceive, decide and act in a shared environment.
  • Agents may share a common goal or compete in their own interest.
  • Each agent's knowledge is local, so coordination and communication are central design problems.
  • Examples: robot teams, autonomous vehicle fleets, distributed sensor networks, traffic and economic simulations.
The game theory link: if agents are affected by each other's decisions, the interaction is a game; whoever designs the agents' rules is a mechanism designer.

The Agent Concept and Its Properties

The four properties in Wooldridge and Jennings's (1995) "weak agent" definition:

AutonomyMakes its own decisions and manages its own state without human intervention.a drone picks its own route

ProactivenessDoes not just react; takes the initiative and plans to reach its goals.heads to a charger before the battery dies

In game theory an agent = a rational player: its preferences are captured by a utility function, and it tries to maximize its expected utility.

Cooperation and Coordination

The Spectrum of Interests: Three Small Games

  • On the left interests are identical: communication or a shared convention (e.g. “keep right”) is enough (a coordination problem).
  • In the middle interests partly conflict: individual incentives work against the common good, so incentives must be designed.
  • On the right one's gain is the other's loss (zero-sum): being unpredictable, i.e. a mixed strategy, matters.

Orange cells: pure Nash equilibria (both players best-responding).

Cooperation and Coordination

Communication, Learning and Emergent Behavior

Communication and informationAgents know different things; who knows what (the information structure) changes the equilibrium (games of incomplete information). This needs a shared language and messaging protocol.
Learning and adaptationAgents update strategies from feedback: best-response dynamics, fictitious play (each agent best-responds to the average of its opponents' past moves), reinforcement learning. Since other agents learn too, each agent's environment is nonstationary; convergence is not guaranteed.
Emergent behaviorSimple local rules produce unexpected system-level patterns: in Schelling's (1971) model a mild neighbor preference produces stark residential segregation.
System behavior cannot be read off individual agents: equilibrium analysis and simulation are used together. Traffic jams and price swings are also patterns emerging from agent interaction.

Task Allocation

The Contract Net Protocol

Smith (1980): the agent with a task acts as manager; agents able to do it act as contractors. Roles can change from task to task.

The manager does not know the costs; bids reveal this private information. Bidding is a reverse auction (lowest bid wins). If the winner is paid its own bid, a contractor wants to inflate its bid; if paid the second-lowest bid (Vickrey), bidding truthfully is best for a single task.

Task Allocation

Contract Net Step by Step: 3 Tasks, 3 Robots

The manager auctions three tasks (T1–T3) in order. Each robot takes at most one task; only the robot knows its own cost (estimated time); the manager never sees the table.

Announce: the manager broadcasts task T1 to the free robots: Robot 1, Robot 2, Robot 3.

Bids: each free robot reports its cost for T1: R1 → 2, R2 → 3, R3 → 6.

Award: Robot 1 bids lowest (2 min), so T1 goes to it; the robot is now busy.

Announce: the manager broadcasts task T2 to the free robots: Robot 2, Robot 3.

Bids: each free robot reports its cost for T2: R2 → 7, R3 → 8.

Award: Robot 2 bids lowest (7 min), so T2 goes to it; the robot is now busy.

Announce: the manager broadcasts task T3 to the free robots: Robot 3.

Bids: each free robot reports its cost for T3: R3 → 9.

Award: Robot 3 bids lowest (9 min), so T3 goes to it; the robot is now busy. With only one bid, there is no choice.

Result: the contract net totals 18 min (red). The optimum, trying all 6 assignments, is 13 min (dashed blue): T1→R3, T2→R1, T3→R2. Greedy sequential auctioning costs 38% more.

Legend: dashed arrow = announce · orange = bid · thick red arrow / frame = award · faded robot = busy · dashed blue frame = optimal assignment.

Code Trace: contract_net(tasks, cost)

tasks = [T1, T2, T3] are auctioned in order. All robots are free; nothing assigned yet.

Announce: T1. Free robots bid: R1 → 2, R2 → 3, R3 → 6.

Award: lowest bid R1 (2 min).

assign[T1] = R1, total = 2; R1 is now busy.

Announce: T2. Free robots bid: R2 → 7, R3 → 8.

Award: lowest bid R2 (7 min).

assign[T2] = R2, total = 9; R2 is now busy. R1, which took T1 cheaply, was also cheapest for T2 (3) but is gone.

Announce: T3. Free robots bid: R3 → 9.

Award: lowest bid R3 (9 min). A single bid: no choice.

assign[T3] = R3, total = 18; R3 is now busy.

Result 18 min: the best local decision at each step, but not the optimal total.

def contract_net(tasks, cost):
  free = set(cost)
  assign, total = {}, 0
  for g in tasks:
    bids = {r: cost[r][g] for r in free}
    winner = min(bids, key=bids.get)
    assign[g] = winner
    total += bids[winner]
    free.remove(winner)
  return assign, total

Task Allocation

Code Trace: optimum(tasks, cost)

The centralized solution: a manager who knows all costs tries all 3! = 6 orderings of the 3 robots.

p = (R1, R2, R3): t = 2 + 7 + 9 = 18 ⇒ new best.

p = (R1, R3, R2): t = 2 + 8 + 4 = 14 ⇒ new best.

p = (R2, R1, R3): t = 3 + 3 + 9 = 15 ≥ 14: unchanged.

p = (R2, R3, R1): t = 3 + 8 + 5 = 16 ≥ 14: unchanged.

p = (R3, R1, R2): t = 6 + 3 + 4 = 13 ⇒ new best.

p = (R3, R2, R1): t = 6 + 7 + 5 = 18 ≥ 13: unchanged.

Optimum 13 min: T1→R3, T2→R1, T3→R2; the contract net takes 18 min (38% more). But n robots have n! assignments: 3,628,800 at n = 10 (the Hungarian algorithm solves it in O(n³)).

from itertools import permutations
def optimum(tasks, cost):
  best = None
  for p in permutations(cost):
    t = sum(cost[r][g]
            for g, r in zip(tasks, p))
    if best is None or t < best[0]:
      best = (t, p)
  return best

Task Allocation

The Contract Net: Strengths and Weaknesses

Strengths

  • Distributed: the manager finds a good assignment without knowing the cost table.
  • O(n) messages per task: one announcement + n bids + one award.
  • Adding robots is easy; a failed robot's task is simply re-auctioned.

Weaknesses

  • Greedy and sequential: 18 min in the example vs. the optimal 13 (38% more). R1, which took T1 cheaply, was busy although it was the best candidate for T2.
  • Robots can strategically inflate their costs.
  • Task order changes the outcome.
Improvements: re-auctioning (fixing assignments by swaps), combinatorial auctions (robots bid on task bundles), and VCG payments choosing the whole assignment at once for truthful bids (one-by-one second-price auctions are not enough).

Coalitional Games

Coalition Formation

  • Agents that cannot reach a goal alone may form temporary or lasting coalitions: shipping firms share vehicles, drones carry a heavy load together.
  • These games are cooperative: binding agreements are possible; the question is not "which strategy?" but "who joins whom, and how is the gain shared?"
  • If the split is unfair, the coalition falls apart: stability depends directly on the sharing rule.
Shapley valueFairness: everyone gets their average marginal contribution.
The coreStability: no subgroup can get more by breaking away.

Coalitional Games

Coalition Structures: Who Joins Whom?

  • A coalition structure partitions the agents into disjoint coalitions. Society's question: which structure has the largest total value?
  • The number of structures is the number of ways to split n agents into nonempty disjoint groups (the Bell number): 5 for n = 3, 15 for n = 4, 4,140 for n = 8, 115,975 for n = 10.
  • The example game is superadditive: merging never hurts, so the best structure is the grand coalition {A, B, C} (120).
  • In general, finding the best structure is NP-hard (Sandholm et al., 1999); what remains is how to split the 120.

Coalitional Games

Coalitional Games and the Characteristic Function

  • Player set N = {1, …, n}; for every coalition S ⊆ N, v(S) is the total value S's members can secure together, independently of the others.
  • v assigns each coalition the total value the group can earn together; the empty coalition is worth 0. v is called the characteristic function. Because the gain can be shared freely within the group, these are transferable utility (TU) games.
  • Superadditive: for disjoint S, T, v(S ∪ T) ≥ v(S) + v(T) → merging never hurts; the grand coalition N maximizes total value.
  • In the example, three logistics firms A, B, C earn 120 together, at most 70 as the best pair and at most 30 alone.

Coalitional Games

The Shapley Value

  • Players arrive in a random order and join the coalition. Each player is credited with the value it adds on arrival (its marginal contribution).
  • Shapley value: the average marginal contribution over all n! orders.
  • Cost: n! orders (or 2n−1 subsets); for large n it is approximated by sampling.
  • Shapley (1953): the only rule satisfying the four axioms shown. It is also used to explain models (SHAP: splitting a model's decision into feature contributions).
EfficiencyΣ φi = v(N).
SymmetryTwo players who contribute equally get equal shares.
Dummy playerIf it adds nothing to any coalition, φi = 0.
AdditivityIf two games' values are added, so are the Shapley shares.

from itertools import permutations
def shapley(N, v):
  phi = {i: 0 for i in N}
  orders = list(permutations(N))
  for order in orders:
    S = frozenset()
    for i in order:
      gain = v[S | {i}] - v[S]
      phi[i] += gain
      S = S | {i}
  return {i: phi[i] / len(orders) for i in N}

Coalitional Games

The Core

  • An imputation x is in the core ⇔ Σi∈N xi = v(N) and Σi∈S xi ≥ v(S) for every S ⊆ N.
  • That is, no coalition can give its members more by breaking away (blocking) from the grand coalition.
  • The core is a system of linear inequalities (Gillies, 1959): it may be empty, a single point or a region.
Singleton constraintsxA ≥ 10, xB ≥ 20, xC ≥ 30
Pair constraintsxA+xB ≥ 50, xA+xC ≥ 60, xB+xC ≥ 70
EfficiencyxA+xB+xC = 120
Shapley measures fairness, the core stability; they do not always agree. In a convex game a player's contribution never shrinks as the coalition it joins grows. Our example is such a game, and in convex games the Shapley value is always in the core (Shapley, 1971).

Coalitional Games

The Geometry of the Core Step by Step

All individually rational, efficient splits form a triangle; at a corner one agent takes all 60 of the surplus.

{A, B}: xA + xB ≥ 50 ⇔ xC ≤ 70: if C gets more than 70, A and B break away and take their own 50. The C corner is cut off.

{A, C}: xA + xC ≥ 60 ⇔ xB ≤ 60: the B corner is cut off.

{B, C}: xB + xC ≥ 70 ⇔ xA ≤ 50: the A corner is cut off too. The remaining orange hexagon is the core.

φ = (30, 40, 50) and the equal split are in the core (blue). y = (10, 25, 85) is outside (red): xA + xB = 35 < 50.

Coalitional Games

A Game with an Empty Core: The Majority Game

  • Three agents share a prize of 1; any two agents who agree get it: v(S) = 1 (|S| ≥ 2), otherwise 0.
  • Core constraints: xA+xB ≥ 1, xA+xC ≥ 1, xB+xC ≥ 1.
  • Adding them gives 2(xA+xB+xC) ≥ 3, so the total is ≥ 3/2. But the total must be 1 ⇒ the core is empty.
  • In every imputation some pair gets ≤ 2/3 and wants to exclude the third and share the 1: endless bargaining.
Shapleyφ = (1/3, 1/3, 1/3): fair but not stable.
LessonA stable split does not exist in every game. Relaxed rules are then used, such as “no group gains too much by leaving” (e.g. the ε-core: no coalition gains more than ε by breaking away).

Coalitional Games

Weighted Voting: Weight ≠ Power

  • Weighted voting game [q; w1, …, wn]: a coalition wins if its total weight reaches q, v(S) = 1; otherwise 0.
  • Shapley–Shubik index (1954) = the Shapley value of this game: the share of orders in which i is pivotal.
  • Parliament [51; 50, 49, 1]: despite a 48-seat gap, B and C have equal power (1/6); the Banzhaf index counts critical memberships: A is critical in three winning coalitions ({A, B}, {A, C}, {A, B, C}), B and C in one each ⇒ (3/5, 1/5, 1/5).
  • 1958 EEC Council of Ministers [12; 4, 4, 4, 2, 2, 1]: Luxembourg's vote could never change any coalition's outcome; power = 0.

Coalitional Games

Code Trace: power_index(N, w, q)

w = {A: 50, B: 49, C: 1}, q = 51. 3! = 6 arrival orders; in each, the player who crosses the quota is pivotal.

Order A → B → C: with the total at 50 < 51, B arrives and the total is 99 ≥ 51.

B is pivotal: pivots[B] = 1; break moves on to the next order.

Order A → C → B: with the total at 50 < 51, C arrives and the total is 51 ≥ 51.

C is pivotal: pivots[C] = 1; break moves on to the next order.

Order B → A → C: with the total at 49 < 51, A arrives and the total is 99 ≥ 51.

A is pivotal: pivots[A] = 1; break moves on to the next order.

Order B → C → A: with the total at 50 < 51, A arrives and the total is 100 ≥ 51.

A is pivotal: pivots[A] = 2; break moves on to the next order.

Order C → A → B: with the total at 1 < 51, A arrives and the total is 51 ≥ 51.

A is pivotal: pivots[A] = 3; break moves on to the next order.

Order C → B → A: with the total at 50 < 51, A arrives and the total is 100 ≥ 51.

A is pivotal: pivots[A] = 4; break moves on to the next order.

Power = pivots / 6 ⇒ (2/3, 1/6, 1/6). B's 49 seats bring no more power than C's single seat.

from itertools import permutations
def power_index(N, w, q):
  pivots = {i: 0 for i in N}
  orders = list(permutations(N))
  for order in orders:
    total = 0
    for i in order:
      total += w[i]
      if total >= q:
        pivots[i] += 1
        break
  return {i: pivots[i] / len(orders) for i in N}

The Public Goods Game

The Public Goods Game

  • A public good: nobody can be excluded from it, and one person's use does not reduce another's (e.g. open-source software, clean air, a shared dataset).
  • The game: n players with e tokens each. Player i puts ki tokens, between 0 and e, into a common pool. The pool is multiplied by r and split equally among everyone.
  • Payoff: ui = e − ki + (r/n)·Σj kj (Σj kj: total tokens in the pool)
  • r/n: the part of a token that returns to its contributor (MPCR: marginal per capita return). There is a dilemma if 1/n < r/n < 1.
Our examplen = 4, e = 10, r = 1.6 ⇒ r/n = 0.4
IndividualContributing 1 token: 0.4 returns to the contributor ⇒ net −0.6
SocialContributing 1 token: 1.6 returns to the group ⇒ net +0.6

The Public Goods Game

Why Free Riding?

  • u1 = 10 − k1 + 0.4·(k1 + others). One more token from P1: −1 from the pocket, +0.4 from the pool, net −0.6.
  • Whatever others do, each token costs P1 0.6: k = 0 is dominant.
  • Unique equilibrium: all give 0 → 10 each. All giving 10 yields 16 each: not Pareto optimal.
  • Red: others give fully, P1's payoff falls from 22 to 16. Blue: all give the same k, 10 up to 16.
  • Multi-agent versions: a file-sharing peer that never uploads; a federated-learning client that never sends updates.
The n-player Prisoner's Dilemma: the individual incentive (−0.6) and social welfare (+0.6) point in opposite directions.
