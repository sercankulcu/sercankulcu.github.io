    How to play

    Each arm is an action with a hidden probability of paying a reward of 1. Click an arm to pull it; every pull returns 1 or 0. The goal is to find out which arm is best while keeping cumulative regret low. Every new experiment draws new hidden probabilities, so memorizing the previous winner does not help.

    • Reward is the number of successes; Round counts all pulls.
    • Each arm card shows the number of pulls and the observed average (bar). If “True probabilities” is checked, the red line shows the hidden value.
    • Regret = expected reward of always pulling the truly best arm − reward actually obtained.
    • The “Algorithm: 50 rounds” button lets the selected algorithm continue the same experiment, for comparison.
    • The Show the calculation box in the side column displays, in the main area, the values the algorithm computes for each arm (pulls, average, UCB bonus, score) and why it picked that arm; while it is off the screen does not change.

    Contribution to game theory

    Bandit algorithms balance exploration of uncertain options against exploitation of the best known option. This is the basic learning problem behind repeated games, recommender systems and online advertising.

    Modes

    • Benchmark: you choose every arm and compare your reward and regret with the algorithm runs. Check whether you explored enough before deciding.
    • With advice: the arm the selected algorithm would exploit is marked “Recommended”. You can follow or reject the advice; useful for discussing automation bias.
    • Computer learns: the algorithm plays the first 50 rounds; continue in blocks of 50 to watch convergence.

    Levels

    • Level 1: 3 arms: stationary; the best introduction to the exploration–exploitation dilemma.
    • Level 2: 4 arms: stationary; the extra arm spreads out exploration and makes early commitment more costly.
    • Level 3: Changing rewards: four arms; after round 40 the hidden probabilities change. Old observations become misleading; watch whether the learner starts exploring again.

    Algorithms

    • ε-greedy: with probability ε = 0.15 a random arm is pulled, otherwise the arm with the highest observed average. It is simple and never stops exploring, so it can notice a change, but it wastes pulls on clearly weak arms.
    • UCB1: the arm with the highest score is pulled; score = average + √(2 ln t / pulls). Rarely pulled arms get a large bonus, so exploration is directed rather than random. It is strong in stationary environments and slow after abrupt changes, because old evidence stays in the averages.

    Suggested order

    1. Benchmark + Level 1 + ε-greedy: at least 20 manual pulls.
    2. Repeat with UCB1 and compare how evenly the arms are sampled.
    3. Level 2: see how an extra option raises the cost of exploration.
    4. Advice mode: deliberately reject some recommendations and judge the result.
    5. Computer learns + Level 3: compare the two algorithms after the change at round 40.

    Note on interpretation: a single run is not enough to say that one algorithm is better. Rewards are random; compare several experiments by average reward, regret and speed of adaptation.

    Model

    • Each arm is a Bernoulli machine with a hidden success probability pi: a pull pays 1 with that probability and 0 otherwise. At the start of an experiment pi = 0.15 + 0.70·U (U uniform random) is drawn; level 1 has 3 arms, the others 4.
    • In level 3, at the first pull after 40 pulls, every pi gets a random number from [−0.25, +0.25] added and the result is clipped to [0.1, 0.9]. Earlier observations are stale from then on.
    • The page keeps, for every arm, the pull count Ni and the reward sum Si. The estimate is Qi = Si / Ni (shown as 0 for an arm never pulled).
    • Regret = (sum over rounds of the current p of the best arm) − (total reward collected). Rewards are random, so a lucky streak can briefly push regret below zero.

    The two algorithms

    ε-greedy (ε = 0.15): draw u ∈ [0,1). If u < ε, explore: a uniformly random arm. Otherwise exploit: the arm with the largest Qi; an untried arm counts as 1 (optimistic start); on ties the lower index wins.

    UCB1: score Ui = Qi + √(2 ln t / Ni); the arm with the largest score is pulled. An untried arm has infinite score, so every arm is pulled once first. Here t is the number of pulls made so far (the page uses ln(max(1, t))). UCB1 has no randomness: the same history always picks the same arm.

    Worked example

    Take a three-armed experiment after 10 pulls (the Show the calculation panel shows these columns too). t = 10, ln 10 ≈ 2.303:

    UCB1 picks Arm 2: its average is the lowest, but it has been pulled only twice, so its bonus is large (directed exploration). ε-greedy in the same state would pick Arm 3 (highest average) with probability 0.85 and a random arm with probability 0.15. Once Arm 2 gets its third pull its bonus drops to √(2·2.303/3) = 1.24; as evidence accumulates the bonus shrinks and the choice drifts towards the average.

    Game-theory connection

    • Exploration and exploitation: pulling the current best arm (exploitation) pays now, trying other arms (exploration) buys information. You cannot do both at once; the algorithm fixes a rule for the trade-off.
    • Regret compares the algorithm with a player who knew the best arm from the start. While ε stays fixed, ε-greedy keeps spending pulls on weak arms every round, so its regret grows in proportion to the number of rounds (linearly). The UCB1 bonus shrinks as pulls accumulate; its regret grows only like ln t.
    • The bandit is a game against nature: the arms do not react to you. If the other players are learning too (repeated games) the stationarity assumption breaks; for that, and for other algorithms that shrink regret (Hedge, fictitious play), see Chapter 13 · Learning and Adaptation.

    What the calculation panel shows

    When an algorithm picks an arm the panel shows, for every arm at that moment, the pull count, the average, (for UCB1) the bonus and the score; for ε-greedy it shows the ε draw and whether it was exploration or exploitation, and highlights the chosen arm in yellow. If you picked the arm yourself, the panel shows the scores the algorithm would compute now and which arm it would choose. The panel changes no computation; it only records.

    1. Choice and pull: choose, exploitArm, pull

    const EPS = 0.15;                       // exploration probability

function mean(i) {                      // observed average Q_i = S_i / N_i
  return count[i] ? sum[i] / count[i] : 0;
}

function argmax(values) {               // first maximum; on ties the lower index
  let best = 0;
  for (let i = 1; i < values.length; i++)
    if (values[i] > values[best]) best = i;
  return best;
}

function exploitArm() {                 // the arm the algorithm would "exploit"
  if (alg.value === 'eg') {
    // ε-greedy: an untried arm counts as 1 (optimistic start)
    return argmax(count.map((c, i) => c ? mean(i) : 1));
  }
  // UCB1: average + exploration bonus; an untried arm scores infinity
  return argmax(count.map((c, i) =>
    c ? mean(i) + Math.sqrt(2 * Math.log(Math.max(1, t)) / c) : Infinity));
}

function choose() {
  if (alg.value === 'eg' && Math.random() < EPS)
    return Math.floor(Math.random() * probs.length);   // explore: a random arm
  return exploitArm();                                  // exploit
}

function pull(index) {
  if (level.value === '3' && t === 40 && !changed) {   // level 3: at round 40
    changed = true;                                     // the hidden probabilities drift
    probs = probs.map(p => Math.min(.9, Math.max(.1, p + (Math.random() - .5) * .5)));
  }
  const r = Math.random() < probs[index] ? 1 : 0;      // Bernoulli reward
  bestSum += Math.max(...probs);                        // expectation of the best arm
  t++; count[index]++; sum[index] += r; totalR += r;
  /* ... log and chart bookkeeping ... */
}

    2. The same idea in Python

    The same names as Chapter13/egreedy.py and ucb.py in the course's Python repository. Two small differences: the page gives an untried arm the value 1 in ε-greedy (optimistic start), whereas Q starts at 0 in the repository code; and in UCB1 the page uses the number of pulls so far as t, whereas t starts at 1 in the repository.

    import math, random

def egreedy(mu, T, eps, rng):           # mu: the arms' hidden probabilities
    N, Q = [0] * len(mu), [0.0] * len(mu)
    for t in range(1, T + 1):
        if rng.random() < eps:          # explore
            a = rng.randrange(len(mu))
        else:                           # exploit
            a = Q.index(max(Q))
        r = 1 if rng.random() < mu[a] else 0
        N[a] += 1
        Q[a] += (r - Q[a]) / N[a]       # incremental update of the average
    return N, Q

def ucb(mu, T, rng):
    K = len(mu)
    N, Q = [0] * K, [0.0] * K
    for t in range(1, T + 1):
        b = [math.inf if n == 0 else
             math.sqrt(2 * math.log(t) / n) for n in N]   # exploration bonus
        a = max(range(K), key=lambda i: Q[i] + b[i])      # highest score
        r = 1 if rng.random() < mu[a] else 0
        N[a] += 1
        Q[a] += (r - Q[a]) / N[a]
    return N, Q

N, Q = ucb([0.3, 0.5, 0.7], 8, random.Random(3))
print(N, [round(q, 2) for q in Q])      # [2, 2, 4] [0.5, 0.0, 1.0]

    Try it yourself

    1. Predict, then look. Mode: With advice, algorithm: UCB1; tick Show the calculation. Before each pull, without looking at the panel, predict which arm will have the highest score, then compare with the panel's yellow row. When does an arm that does not have the highest average turn yellow?
    2. Recompute a score yourself. Pick a row in the panel; take t (the Round count), the arm's pull count and its average, and compute Q + √(2 ln t / N) on a calculator. Does it match the panel? After you pull an arm, how do that arm's bonus and the other arms' bonuses change, and why?
    3. Compare the two algorithms. Mode: Computer learns, level 1. Run ε-greedy for 200 rounds (four presses of 50), then UCB1 for 200 rounds, and write down the regret. Repeat with three new experiments. Why is a single trial not enough? In the panel the last ε-greedy decision is usually exploitation and occasionally exploration; UCB1 never involves a random draw.
    4. Watch the change. In level 3 with Computer learns, run 50 rounds, then add several more blocks of 50 after the change at round 40. Does the old best arm still get the highest score? Which algorithm recovers faster? Use the panel to find why a large pull count slows the average down.

    Discussion questions

    • Why does the regret of ε-greedy never level off, while that of UCB1 flattens out?
      Answer

      Because ε stays fixed, even after it has found the best arm ε-greedy pulls a random arm with probability 0.15 every round, and (K−1)/K of those go to a weak arm. The expected loss per round stays constant, so regret grows linearly. In UCB1 the bonus √(2 ln t / N) shrinks with the arm's pull count; weak arms are tried only about ln t times, so the curve flattens more and more. It is logarithmic rather than truly flat, and the difference shows on long experiments.

    • Why does an untried arm get the value 1 in ε-greedy and an infinite score in UCB1? What would happen if it started at 0?
      Answer

      The aim is that every arm is tried at least once. If ε-greedy started at 0, the first arm that paid would stay at the highest average forever and the exploit branch would never go anywhere else; only the ε exploration could save it. An optimistic start (1) does the opposite: every arm looks best until it disappoints once. An arm whose average stays at 1 ties with the untried ones, and on ties the lower index wins, so it is pulled until the first failure; you can see this in the panel. In UCB1 the infinite-score rule gives the same guarantee explicitly.

    • In level 3 both algorithms adapt slowly after round 40. Why? What could change in the average to fix it?
      Answer

      Qi = Si/Ni adds up the whole history with equal weight. The average of a heavily pulled arm moves only in proportion to the pull count as new observations arrive, and the UCB1 bonus is small too, so the old arm stays ahead for a long time. The remedy is forgetting: a sliding window or a constant step size (Q ← Q + α(r − Q)) weights recent observations more, at the cost of a noisier estimate in a stationary environment.

    • If the arms were the other players of a game, and they were learning too, would these algorithms still work?
      Answer

      There is no guarantee. The bandit model assumes the arms' reward distributions are fixed (a game against nature); if the other players react to you, rewards depend on your own strategy and the averages chase a moving target. For this, algorithms that shrink regret whatever the opponent does (Hedge) are used; in self-play their average play converges to the minimax equilibrium in zero-sum games and to a coarse correlated equilibrium in general games. This is covered in Chapter 13.
