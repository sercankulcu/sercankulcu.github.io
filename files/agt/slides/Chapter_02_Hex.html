How to play

  1. Players take turns placing a stone on any empty hexagonal cell. Blue moves first.
  2. Blue tries to build an unbroken chain joining the left edge to the right edge (the blue edges).
  3. Purple tries to join the top edge to the bottom edge (the purple edges).
  4. Stones are never moved or captured, so every move permanently changes the geometry of the board.
  5. The first player whose stones form a connected path between the required edges wins at once; the winning path is marked on the board.
  6. Undo takes back the last move (in computer mode, your move together with the computer's reply). Cells can also be chosen with Tab and Enter.

Computer levels

  • Easy plays at random.
  • Medium takes or blocks a winning cell; otherwise, most of the time, it plays the cell that shortens its own path the most.
  • Hard also takes or blocks a winning cell first; otherwise it always picks the cell that most improves the difference between the opponent's and its own remaining shortest path (the number of empty cells each side still needs).

If you tick Show move reasoning, the computation behind each computer move appears under the board and its last move is ringed on the board.

Reading the board

Connections do not have to form a straight line. Neighbouring hexagons touch in six directions, so links that look diagonal can still be part of one unbroken path. A useful pattern is the bridge: two stones placed so that two possible connection points remain between them. Since the opponent can usually block only one point at a time, bridges create robust future paths.

Strategy tips

  • Build flexible networks of connections instead of a single fragile line.
  • Block a cell when a single move would hand the opponent a decisive connection.
  • Cells near the centre usually support more possible paths than edge cells.
  • Do not judge a position by stone count alone; connectivity and future path options matter more.

Hex is a deterministic, perfect-information, two-player, zero-sum game: there are no chance events or hidden cards. Why it can never end in a draw, and why the first player has a winning strategy, is explained in the How the AI decides tab.

This AI does not search a tree, it applies a rule

The computer (Purple) uses neither Minimax nor Alpha-Beta; it looks only one move ahead. The reason is the branching factor: on a 9×9 board there are 81 options on the first move, then 80, 79 and so on, and a game lasts at most 81 moves, so there are up to 81! ≈ 6×10120 move sequences. Even a few plies deep is more work than the page can do on every move. So instead of a tree the program uses a heuristic evaluation: it scores each candidate by looking at the board right after the move. The code is in the function aiMove and applies one of three rules, depending on the level.

  1. Easy: picks one of the empty cells at random. No computation.
  2. Medium and Hard, step 1 (tactics): tries the empty cells in row order. It first looks for the first cell that wins for Purple (a BFS with winningPath); if there is none, it looks for the first cell that would win for Blue and takes it. This is the terminal-position check at depth 1 and 2 (the +∞ / −∞ values in Minimax).
  3. Hard, step 2: with no tactical move, it tries a stone on every empty cell, computes this score and plays the highest:

    score = d(Blue) − d(Purple) − 0.02 × (distance from centre) + noise (< 0.01)

  4. Medium, step 2: with probability 60% it uses score = −d(Purple) + noise (0–0.5) (it only shortens its own path and ignores the opponent); in the remaining 40% it plays at random.

d(p) is the shortest remaining path of player p: passing through one of its stones costs 0, passing through an empty cell costs 1, and opponent stones are impassable. So d(p) is the least number of stones p still has to place to join its two edges. On an empty 9×9 board d = 9; on a won board d = 0.

The score has three layers: on Hard the integer difference d(Blue) − d(Purple) makes the real decision; the centre penalty (at most 0.2) only prefers the cell nearer the centre among cells with the same difference; the noise (< 0.01) separates the cells that are still equal. On Medium the noise is 0–0.5, so it also only decides among cells with the same path length. The randomness never makes a worse move beat a better one.

A real numerical example

On a 9×9 board, at the Hard level, Blue put its first stone on the centre cell (5,5). Before the move d(Blue) = 8 (the centre stone shortens the path by one cell) and d(Purple) = 9. In the tactics step there is no winning or blocking cell, so each of the 80 empty cells is tried:

  • (4,5): a Purple stone brings its path from 9 to 8; Blue's path is still 8 (it has other routes). Difference 8 − 8 = 0. Distance from the centre |4−5| + |5−5| = 1, penalty 0.02 × 1, so the score is −0.02.
  • (1,1) (corner): d(Purple) is again 8, d(Blue) again 8, difference 0. Distance from the centre 8, penalty 0.16, so the score is −0.16.

Because a single stone cannot lengthen Blue's path, all the best candidates have difference 0 and the centre penalty decides. The four cells next to the centre cell (−0.02) are equal, and the noise picks one of them at random. Purple only catches up with Blue; since it is Blue's turn again, Blue stays ahead. You can see these numbers in the panel yourself.

Is this rule the best?

No. The Hard level is a reasonable heuristic, not a proven strategy. (1) It does not look ahead: it measures the result of its move one position later and does not compute the opponent's reply. (2) It does not know bridges: d counts two stones with a single empty cell between them, but cannot tell whether the opponent can fill that gap; a link made safe by a bridge counts the same as a link that depends on one fragile route. (3) It is greedy: it takes whatever looks best for this move. Strong Hex programs use this kind of distance only as an evaluation function and add Alpha-Beta or Monte Carlo tree search, bridge patterns and "virtual connection" logic on top of it.

Why Hex can never end in a draw

When every cell is filled, the two colours split the board completely: either Blue has a left-right chain or Purple has a top-bottom chain. Not both, and not neither. The intuition: if Blue has no chain, the Blue stones reachable from the left edge never reach the right edge; along the border of that region the Purple stones form an unbroken line that joins the top edge to the bottom edge. This is the Hex theorem, equivalent to Brouwer's fixed-point theorem. So Hex, unlike tic-tac-toe, is not a game that ends in draws: every game has a winner.

Strategy stealing: the first player wins, but how?

Because there are no draws, suppose the second player has a winning strategy. The first player places a first stone anywhere, then copies the second player's strategy: he pretends to be the second player and follows it. If the strategy ever asks for the cell that already holds his extra stone, he places another arbitrary stone instead. In Hex an extra stone never hurts, so the first player wins; since both cannot win, the assumption is contradicted. Conclusion: the first player has a winning strategy.

The proof is not constructive: it says the strategy exists, not what it is. Small boards have been solved by computer search (up to about 9×9); on large boards nobody knows the winning move. That is why Hex relies on heuristic programs like the Hard level, and why people often play with the pie rule for a fair game: the first player makes a move, then the second player may swap sides.

On this page Blue always moves first, so in theory the advantage is yours, but you still have to find the right moves to use it.

1. Terminal test and remaining path

In Hex both "has someone won?" and "how many stones are left?" are shortest-path questions: one is an ordinary BFS, the other a 0-1 BFS.

/* Is cell i on the start / goal edge of player p?
   Blue (1): left column -> right column, Purple (2): top row -> bottom row */
function isStart(i, p) { return p === 1 ? i % n === 0 : i < n; }
function isGoal(i, p)  { return p === 1 ? i % n === n - 1 : Math.floor(i / n) === n - 1; }

/* Do p's stones join the two edges? BFS from the stones on the start edge.
   Returns the path if they do, otherwise null. neighbors(i): the 6 neighbours on the board. */
function winningPath(b, p) {
  var prev = {}, queue = [];
  for (var i = 0; i < n * n; i++)
    if (b[i] === p && isStart(i, p)) { queue.push(i); prev[i] = -1; }
  while (queue.length) {
    var cur = queue.shift();
    if (isGoal(cur, p)) { /* ... walk back along prev and return the path ... */ }
    neighbors(cur).forEach(function (nb) {
      if (b[nb] === p && !(nb in prev)) { prev[nb] = cur; queue.push(nb); }
    });
  }
  return null;
}

/* p's shortest remaining path = number of stones p still has to place (0-1 BFS).
   Passing through an own stone costs 0, an empty cell costs 1; opponent stones are blocked. */
function distance(b, p) {
  var INF = 1e9, dist = Array(n * n).fill(INF), dq = [];
  for (var i = 0; i < n * n; i++) {
    if (isStart(i, p) && b[i] !== 3 - p) {
      dist[i] = b[i] === p ? 0 : 1;
      if (dist[i] === 0) dq.unshift(i); else dq.push(i);
    }
  }
  var best = INF;
  while (dq.length) {
    var cur = dq.shift();
    if (isGoal(cur, p)) best = Math.min(best, dist[cur]);
    neighbors(cur).forEach(function (nb) {
      if (b[nb] === 3 - p) return;                 /* opponent stone: blocked */
      var w = b[nb] === p ? 0 : 1;                 /* own stone free, empty cell 1 */
      if (dist[cur] + w < dist[nb]) {
        dist[nb] = dist[cur] + w;
        if (w === 0) dq.unshift(nb); else dq.push(nb);
      }
    });
  }
  return best;
}

2. Choosing the move: aiMove

First the tactical check, then, depending on the level, a heuristic or random choice. An argmax: the cell with the highest score is kept.

/* The computer's move (Purple, p = 2). Easy: only the random cell drawn first. */
function aiMove() {
  var b = board.slice(), empty = [];
  for (var i = 0; i < b.length; i++) if (!b[i]) empty.push(i);
  var difficulty = difficultySelect.value;
  var move = empty[Math.floor(Math.random() * empty.length)];   /* default: random */

  if (difficulty !== 'Easy') {
    /* 1) tactics: can Purple win now (p = 2)? else can Blue win now (p = 1)?
          Cells are tried in row order and the first hit is taken. */
    var tactical = null;
    [2, 1].forEach(function (p) {
      if (tactical !== null) return;
      for (var k = 0; k < empty.length; k++) {
        b[empty[k]] = p;
        var w = winningPath(b, p);
        b[empty[k]] = 0;
        if (w) { tactical = empty[k]; return; }
      }
    });
    if (tactical !== null) move = tactical;

    /* 2) heuristic: Hard always, Medium with probability 60%; Medium's other 40% stays random */
    else if (difficulty === 'Hard' || Math.random() < 0.6) {
      var best = -Infinity, mid = (n - 1) / 2;
      empty.forEach(function (j) {
        var r = Math.floor(j / n), c = j % n, score;
        b[j] = 2;                                   /* place the stone to try it */
        if (difficulty === 'Hard')
          score = distance(b, 1) - distance(b, 2)   /* Blue's path - Purple's path */
                - 0.02 * (Math.abs(r - mid) + Math.abs(c - mid))   /* closeness to centre */
                + Math.random() * 0.01;             /* tie-breaker */
        else
          score = -distance(b, 2) + Math.random() * 0.5;
        b[j] = 0;                                   /* take the stone back */
        if (score > best) { best = score; move = j; }
      });
    }
  }
  play(move, true);
}

3. The same idea in Python

A shortened version, written in the style of the course's Python repository (distance, ai_move).

from collections import deque
import random

# neighbors, is_start, is_goal and has_won are the same as the JavaScript on the page

def distance(board, p, n):
    """Shortest remaining path of p: own stone 0, empty cell 1, opponent stone blocked."""
    INF = 10 ** 9
    dist = [INF] * (n * n)
    dq = deque()
    for i in range(n * n):
        if is_start(i, p, n) and board[i] != 3 - p:
            dist[i] = 0 if board[i] == p else 1
            (dq.appendleft if dist[i] == 0 else dq.append)(i)
    best = INF
    while dq:
        cur = dq.popleft()
        if is_goal(cur, p, n):
            best = min(best, dist[cur])
        for nb in neighbors(cur, n):
            if board[nb] == 3 - p:
                continue
            w = 0 if board[nb] == p else 1
            if dist[cur] + w < dist[nb]:
                dist[nb] = dist[cur] + w
                (dq.appendleft if w == 0 else dq.append)(nb)
    return best

def ai_move(board, n, level):
    """The computer is player 2 (Purple)."""
    empty = [i for i in range(n * n) if board[i] == 0]
    move = random.choice(empty)
    if level == "easy":
        return move
    for p in (2, 1):                       # win first, then block
        for i in empty:
            board[i] = p
            won = has_won(board, p, n)
            board[i] = 0
            if won:
                return i
    if level == "hard" or random.random() < 0.6:
        mid, best = (n - 1) / 2, float("-inf")
        for j in empty:
            r, c = divmod(j, n)
            board[j] = 2
            if level == "hard":
                score = (distance(board, 1, n) - distance(board, 2, n)
                         - 0.02 * (abs(r - mid) + abs(c - mid))
                         + random.random() * 0.01)
            else:
                score = -distance(board, 2, n) + random.random() * 0.5
            board[j] = 0
            if score > best:
                best, move = score, j
    return move

Discussion questions

  • Why does exactly one of the two players win on a full Hex board?
    Answer

    If Blue has no left-right chain, the region reachable from the left edge through Blue stones never reaches the right edge. The cells along the border of that region are Purple and form an unbroken chain whose ends lie on the top and bottom edges. So if Blue has not won, Purple has. Conversely, two such chains would cross, so both cannot exist. There is no final position that is a draw.

  • The strategy-stealing argument proves the first player can win. Why is that not enough for a computer to find the winning move?
    Answer

    The argument is an existence proof: "if the second player had a winning strategy, the first player could steal it, a contradiction". It never names a single move. To find the winning strategy you really have to search, and on large boards that is impossible because the number of moves grows exponentially. The proof gives a result "without solving the tree" but no algorithm that uses it.

  • Why does this AI work with a single rule instead of Minimax? How many positions does a depth-2 search mean?
    Answer

    On 9×9, depth 2 is 80 × 79 = 6,320 positions, each needing two shortest-path computations; that is still feasible. But depth 4 is about 80 × 79 × 78 × 77 ≈ 38 million positions, to be redone at every move; Alpha-Beta cuts this to roughly its square root in the best case, but it stays expensive. More importantly, the heuristic already carries the "remaining path" information, so extra depth buys less. A simple evaluation and a one-move look were chosen. This is an example of bounded rationality.

  • Why does the pie rule (the first player moves, the second may swap sides) make Hex fair?
    Answer

    Since the first player's advantage is certain, whoever picks the first move must make it weak enough. A very strong first move makes the second player swap; a very weak one makes the second player accept it. The player choosing the move wants to make the worst case as good as possible (maximin), so they look for a move where both options are worth the same. This is the Minimax idea of Chapter 2 built into the rules.
