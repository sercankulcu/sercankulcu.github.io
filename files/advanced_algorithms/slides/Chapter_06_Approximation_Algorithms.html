Introduction

Approximation Algorithms

  • For some problems finding the exact (optimal) solution is very hard or impossible in practice: TSP, vertex cover, machine scheduling and knapsack are NP-hard; if P ≠ NP they have no polynomial-time exact algorithms.
  • Instead of looking for the perfect solution, approximation algorithms produce solutions as close as possible to the optimum.
  • They run in polynomial time: hard problems can be solved in reasonable time.
  • It can often be proven that the solution is within a fixed ratio or percentage of the optimum.
  • Preferred when computing resources (time, memory) are limited.
The trade-off: give up a little optimality, gain efficiency and a guarantee on solution quality.

Introduction

The Balance Scale Analogy

  • When a weight is placed on one pan of a scale, it can be hard to put exactly the same weight on the other pan.
  • Instead, we use the small weights at hand to balance the large one as closely as possible.
  • If we only have 20, 10, 5 and 1 kg, each usable once, the closest balance to 37 kg is 36 kg.
An approximation algorithm works the same way: instead of searching for the exact balance (the optimum), it settles for one that is found quickly and whose error is bounded.

Introduction

Approximation Ratio

C: cost of the solution the algorithm finds, C*: cost of the optimal solution. If for every input the algorithm satisfies

max( C / C*, C* / C ) ≤ ρ(n)

it is a ρ(n)-approximation algorithm (ρ ≥ 1; ρ = 1 means the algorithm is optimal).

MinimizationC ≤ ρ · C*. Example: a 2-approximation for vertex cover picks at most twice as many vertices as the optimum.
MaximizationC ≥ C* / ρ. Example: a 2-approximation for knapsack guarantees at least half the optimal value.

The ratio is a worst-case guarantee; in practice solutions are often much closer to the optimum.

Traveling Salesman

The Traveling Salesman Problem (TSP)

  • Optimization problem: a salesman wants to visit each of a set of cities once with the shortest total distance and return to the starting city.
  • Combinatorial problem: a solution is the order in which the cities are visited (a permutation).
  • NP-hard: finding the best route for many cities is hard in practice. The shortest path between two vertices (Dijkstra), however, is solvable in polynomial time; do not confuse the two problems.
  • Input: n cities (0, 1, 2, … or A, B, C, …) and dij: the distance between cities i and j.
  • Symmetric TSP: dij = dji; in graph terms: the lightest Hamiltonian cycle in a complete graph.

Traveling Salesman

The Nearest Neighbor Heuristic

  1. Pick a start city and mark it visited.
  2. From the current city go to the nearest unvisited city (greedy choice).
  3. Repeat step 2 until every city is visited.
  4. Return to the start city from the last one to close the tour.

Pros

  • Very simple; O(n²) time.
  • Usually gives a tour about 25% above the optimum.
  • A good initial tour for local search.

Cons

  • There is no constant approximation ratio; even for metric TSP the ratio can be Θ(log n).
  • The final return edge can be very long.

tour[2] = 3, total += 25 → 35; now cur = 3.

tour[3] = 2, total += 30 → 65; now cur = 2.

Scan row 2, unvisited: d[2][4] = 35 → the smallest is 4 (35).

tour[4] = 4, total += 35 → 100; now cur = 4.

Tour 0 → 1 → 3 → 2 → 4 → 0, length 125. (Checked by brute force: optimal for this example.)

int[] nearestNeighbor(int[][] d, int start) {
  int n = d.length, total = 0, cur = start;
  boolean[] visited = new boolean[n];
  int[] tour = new int[n + 1];
  tour[0] = start; visited[start] = true;
  for (int k = 1; k < n; k++) {
    int nearest = -1, minD = Integer.MAX_VALUE;
    for (int j = 0; j < n; j++)
      if (!visited[j] && d[cur][j] < minD) {
        minD = d[cur][j]; nearest = j; }
    // go to the nearest city
    tour[k] = nearest; visited[nearest] = true;
    total += minD; cur = nearest;
  }
  // return to the start
  tour[n] = start; total += d[cur][start];
  return tour;
}

Traveling Salesman

MST-Based 2-Approximation for Metric TSP

A metric example: 7 cities in the plane; distances are Euclidean (the triangle inequality holds).

1) Build a minimum spanning tree (MST) with Prim: total weight w(T) = 228.8. Deleting one edge of a tour leaves a spanning tree → w(T) ≤ OPT.

2) Walk the tree depth-first from A, twice (each edge once down, once back): A → D → B → C → E → F → E → C → B → D → G → D → A. Length 2 · w(T) = 457.6.

3) Skip repeated cities (shortcut): preorder A → D → B → C → E → F → G → A. Thanks to the triangle inequality, shortcuts never lengthen the path: tour = 287.7.

Result: tour ≤ 2 · w(T) ≤ 2 · OPT. Here tour = 287.7, optimum (brute force, 360 tours) = 282.5 → ratio 1.02 ≤ 2.

Local Search

Local Search: The 2-opt Move

Before: edges (a, b) and (c, d) cross.

After: (a, c) and (b, d); the path between them is reversed.

  • Remove two edges of the tour and reconnect the ends crosswise: the subpath from b to c is reversed.
  • Make the move if the gain Δ = d(a,c) + d(b,d) − d(a,b) − d(c,d) < 0. In the Euclidean plane every crossing can be removed this way.
  • When no improving move remains, the tour is a 2-opt local optimum (not necessarily the global optimum).

Local Search

2-opt Local Search: Java

void twoOpt(int[] tour, double[][] d) {
  int n = tour.length;
  boolean improved = true;
  while (improved) {
    improved = false;
    for (int i = 0; i < n - 1; i++)
      for (int j = i + 2; j < n; j++) {
        int a = tour[i], b = tour[i + 1];
        int c = tour[j], e = tour[(j + 1) % n];
        double delta = d[a][c] + d[b][e]
                     - d[a][b] - d[c][e];
        if (delta < -1e-9) {  // shorter
          reverse(tour, i + 1, j);
          improved = true;
        }
      }
  }
}
One pass over the tourO(n²) candidate moves; each is evaluated in O(1), a reversal costs O(n).
Local optimumThe loop ends when no move gives a gain. The number of passes can be exponential in the worst case but is small in practice.
A good startStarting from a nearest-neighbor tour instead of a random one needs fewer moves. Generalizations: 3-opt, Lin–Kernighan.

Local Search

Escaping Local Optima: Metaheuristics

Simulated annealing

A worsening move is also accepted with probability e−Δ/T; the "temperature" T is lowered slowly. It can escape local optima.

Genetic algorithm

A population of tours improved over generations by selection, crossover and mutation.

Ant colony

Ants leave more pheromone on the edges of short tours; later ants prefer edges with dense pheromone.

  • All three are common in TSP, vehicle routing, job scheduling and assignment problems.
  • None of them guarantees an approximation ratio; the result depends on the initial solution and the parameters. Typical settings: T₀ = 100, T ← 0.997 · T at each step; a population of 100, crossover at a random cut point, mutation probability 0.05.

Local search that accepts only improving moves stays in the left valley. Simulated annealing can climb over the hill at high T; as T drops, moves become pickier.

Job Scheduling

Job Scheduling

  • Optimization problem: planning jobs on given resources (workers, machines, processors) as efficiently as possible.
  • Goal: minimize the completion time of the jobs, or optimize other criteria (profit, lateness, deadlines).
Machine scheduling (makespan)

n jobs, m identical machines; job j takes pj. Minimize the time the last job finishes, Cmax (the makespan). NP-hard for m ≥ 2.

Job sequencing with deadlines

Each job takes 1 unit and has a profit and a deadline. Maximize the total profit of the jobs finished by their deadlines.

The first problem has greedy approximation algorithms (list scheduling, LPT); the second is solved optimally by a greedy algorithm.

Assigning Jobs to Machines: List Scheduling

Three identical machines M1–M3. Jobs arrive in order: J1 (2), J2 (8), J3 (6) ready at t = 0; J4 (3) arrives at t = 3. List scheduling (Graham): the next job goes to the machine that becomes free first.

J1 (time 2) → M1, runs in [0, 2] (all machines are free; the first one is chosen).

J2 (time 8) → M2, runs in [0, 8] (M1 is busy until t = 2).

J3 (time 6) → M3, runs in [0, 6] (M1 is busy until t = 2; M2 until t = 8).

t = 2: M1 is free but no job is waiting; the machine stays idle until t = 3 (hatched area).

J4 (time 3) → M1, runs in [3, 6] (M2 is busy until t = 8; M3 until t = 6).

All jobs assigned: Cmax = 8 (M2). Lower bound: OPT ≥ the longest job = 8 → this schedule is optimal. In general, though, list scheduling only guarantees a ratio of (2 − 1/m).

Job Scheduling

List Scheduling: A (2 − 1/m)-Approximation

Two lower bounds: OPT ≥ Σpj / m (the work must be shared) and OPT ≥ max pj.

  1. Let job j, the last to finish, start at time sj.
  2. Before sj all machines were busy (otherwise j would have started earlier) → sj ≤ (Σp − pj) / m.
  3. Cmax = sj + pj ≤ Σp / m + (1 − 1/m) · pj ≤ OPT + (1 − 1/m) · OPT.
Cmax ≤ (2 − 1/m) · OPT; time O(n log m) (the earliest-free machine is kept in a heap).
The bound is tightm = 2, jobs in the order 1, 1, 2:
• List: M1 = 1 + 2 = 3, M2 = 1 → Cmax = 3
• Optimum: {1, 1} and {2} → 2
Ratio 3/2 = 2 − 1/2.In general, m(m − 1) jobs of 1 unit followed by a single job of m units reach the ratio 2 − 1/m.

Job Scheduling

Longest Processing Time First (LPT): A 4/3-Approximation

LPT (Longest Processing Time first): sort the jobs by decreasing time, then apply list scheduling. Jobs: 2, 3, 4, 6, 2, 2 and m = 3.

Given order: Cmax = 8

LPT order 6, 4, 3, 2, 2, 2: Cmax = 7 = OPT (≥ ⌈19/3⌉ = 7)

  • With long jobs first, the short jobs left at the end even out the imbalance: Cmax ≤ (4/3 − 1/(3m)) · OPT (Graham, 1969). Time O(n log n).
  • Tight example (m = 3): 5, 5, 4, 4, 3, 3, 3 → LPT 11, optimum 9 ({5, 4}, {5, 4}, {3, 3, 3}).

LPT Scheduling: Trace the Code

Jobs 2, 3, 4, 6, 2, 2 and m = 3 machines. List scheduling in this order gives Cmax = 8.

LPT: sort the jobs by time in decreasing order → 6, 4, 3, 2, 2, 2.

All three machines have load 0. Each job goes to the least loaded machine at that moment.

p = 6: the least loaded machine is k = 0 (load 0) (on ties, < keeps the first machine) → load = [6, 0, 0].

p = 4: the least loaded machine is k = 1 (load 0) → load = [6, 4, 0].

p = 3: the least loaded machine is k = 2 (load 0) → load = [6, 4, 3].

p = 2: the least loaded machine is k = 2 (load 3) → load = [6, 4, 5].

p = 2: the least loaded machine is k = 1 (load 4) → load = [6, 6, 5].

p = 2: the least loaded machine is k = 2 (load 5) → load = [6, 6, 7].

Makespan Cmax = 7. Since the lower bound is ⌈19/3⌉ = 7, this schedule is optimal.

int lpt(Integer[] jobs, int m) {
  Arrays.sort(jobs, Comparator.reverseOrder());
  int[] load = new int[m];
  for (int p : jobs) {
    int k = 0;              // least loaded
    for (int i = 1; i < m; i++)
      if (load[i] < load[k]) k = i;
    load[k] += p;
  }
  return Arrays.stream(load).max().getAsInt();
}

Vertex Cover

Vertex Cover

  • Covering problem: choose the fewest vertices that cover every edge of a graph. An edge is covered if at least one of its endpoints is chosen.
  • Goal: find a set C ⊆ V covering all edges with as few vertices as possible. The decision version ("is there a cover of k vertices?") is NP-complete.

A valid cover of size 6 (every edge is watched by a "guard")

Example: A Four-Vertex Graph

  • Vertices: A, B, C, D
  • Edges: (A, B), (A, C), (B, C), (B, D), (C, D)
  • {A, B, C} is a vertex cover: every edge has at least one endpoint in the set.
  • But it is not the smallest: {B, C} also covers all five edges.

Vertex Cover

Vertex Cover Algorithm

Naive idea:

  1. Start with an empty cover.
  2. Pick an uncovered edge and add one of its endpoints to the set.
  3. Repeat until every edge is covered.

Adding only one endpoint gives no guarantee. The correct 2-approximation:

  1. Pick an uncovered edge (u, v) and add both u and v.
  2. Every edge touching u or v is now covered; repeat until no edges remain.

If the leaf end of every edge is chosen: 5 vertices; the optimum is {m}, 1 vertex. On a star with n leaves the ratio is n.

The cover is empty. The edges are visited in order: (A,B), (A,C), …, (J,L).

(A, D): A is already in the cover → the edge is covered, skip.

(A, E): A is already in the cover → the edge is covered, skip.

(A, F): A is already in the cover → the edge is covered, skip.

(B, C): B is already in the cover → the edge is covered, skip.

(G, H): neither endpoint is in the cover → add G and H. These edges form a matching.

(G, I): G is already in the cover → the edge is covered, skip.

(H, I): H is already in the cover → the edge is covered, skip.

(H, K): H is already in the cover → the edge is covered, skip.

Set<Character> vertexCover(char[][] edges) {
  Set<Character> cover = new HashSet<>();
  for (char[] e : edges) {
    char u = e[0], v = e[1];
    if (!cover.contains(u) && !cover.contains(v)) {
      cover.add(u); cover.add(v); }  // both endpoints
  }
  return cover;
}

Vertex Cover

Why At Most 2 × Optimum?

  1. Let M be the set of edges the algorithm picks. Both endpoints of each picked edge are added, so the edges of M share no endpoints (M is a matching).
  2. Any cover must contain a distinct vertex for each edge of M → OPT ≥ |M|.
  3. The algorithm picks exactly |C| = 2 |M| vertices → |C| ≤ 2 · OPT.
TimeO(V + E): each edge is examined once.
Greedy by degreePicking the highest-degree vertex is intuitive, but its ratio is only O(log n).
LP roundingSolve the relaxation xu + xv ≥ 1 and pick the vertices with xv ≥ 1/2 → again a 2-approximation.

No constant ratio noticeably better than 2 is known; a ratio of 2 − ε has been shown impossible (under the Unique Games Conjecture).

NP-Completeness: Reducing 3-SAT to Vertex Cover

φ = (x₁ ∨ x₁ ∨ x₂) ∧ (¬x₁ ∨ ¬x₂ ∨ ¬x₂) ∧ (¬x₁ ∨ x₂ ∨ x₂). One edge per variable (top boxes), one triangle per clause; each literal in a clause is joined to the variable vertex with the same name. l = 2 variables, m = 3 clauses → k = l + 2m = 8.

Assignment x₁ = false: pick ¬x₁ from the variable edge. Covered edges fade.

Assignment x₂ = true: pick x₂. Each variable edge is covered by exactly one vertex (l = 2 vertices).

In C₁ the true literal x₂ (its link edge is already covered) is left out; the other two vertices (x₁, x₁) are added.

In C₂ the true literal ¬x₁ is left out; the vertices ¬x₂ and ¬x₂ are added.

In C₃ the true literal ¬x₁ is left out; x₂ and x₂ are added. 8 vertices, all 20 edges covered: φ is satisfiable ⇔ a cover of size k = l + 2m exists.

  • For the fractional knapsack this rule is optimal; for the 0/1 version there is no guarantee.
  • Bad example: (value 2, weight 1) and (value W, weight W). Greedy takes 2, the optimum is W: ratio 5 for W = 10, W/2 in general; it grows without bound as W grows.
  • Improved rule: max(greedy value, the most valuable single item that fits) → a 2-approximation (at least half the optimum).
  • Better still: an FPTAS that scales the values and runs DP, (1 − ε) · OPT, O(n³/ε).

Power Iteration

The Power Iteration Algorithm

  • An iterative method that approximates a matrix's largest (dominant, largest in absolute value) eigenvalue λ1 and a corresponding eigenvector v1.
  • Instead of computing all eigenvalues exactly (O(n³)), it gives only an approximate estimate of the dominant eigenvalue and eigenvector.
  • Each step is just one matrix–vector product (O(n²), or O(nonzeros) for a sparse matrix): effective on very large matrices.

A = [[2, 0], [0, 1]], x₀ = (1, 1): xk ∝ (2k, 1). Each product doubles the v₁ component and leaves the other unchanged; the normalized vector turns step by step toward v₁ = (1, 0) (error ∝ (1/2)k).

Two ideas meet here: the result is an approximation (an estimate) rather than an exact value, and the iterates converge to the true value. Google's PageRank is the most famous application of the method.

Power Iteration

Power Iteration: Steps and Why It Works

  1. Fix a matrix A and choose a random (nonzero) start vector x0.
  2. Multiply the vector by the matrix to get a new vector: y = A · xk.
  3. Normalize the new vector to norm (length) 1: xk+1 = y / ‖y‖.
  4. Repeat for the desired number of steps or until the change is small.
  5. xk → v1; the eigenvalue estimate is the Rayleigh quotient λ ≈ xkT A xk.

Why? If x0 = c1v1 + c2v2 + … then

Akx0 = λ1k [ c1v1 + c2(λ2/λ1)k v2 + … ]
  • Since |λ2/λ1| < 1, the other components die out geometrically.
  • The error shrinks by a factor of ≈ |λ2/λ1| per step: if the ratio is close to 1, convergence is slow.
  • Condition: c1 ≠ 0 (x0 must not be orthogonal to v1) and |λ1| > |λ2|.

Power Iteration

Power Iteration: Java and a 3 × 3 Example

double[] power(double[][] a, int steps) {
  int n = a.length;
  double[] x = new double[n];
  Arrays.fill(x, 1.0); // x₀ ≠ 0, not ⊥ v₁
  for (int k = 0; k < steps; k++) {
    double[] y = new double[n];
    for (int i = 0; i < n; i++)  // y = A·x
      for (int j = 0; j < n; j++)
        y[i] += a[i][j] * x[j];
    double norm = 0;
    for (double yi : y) norm += yi * yi;
    norm = Math.sqrt(norm);
    if (norm == 0) break; // A·x = 0
    for (int i = 0; i < n; i++)  // ‖x‖ = 1
      x[i] = y[i] / norm;
  }
  return x;
}

Power Iteration

Power Iteration: Limits and Applications

Strengths

  • Very simple; only matrix–vector products.
  • Works on sparse, huge matrices (billions of rows).
  • Memory O(n): the matrix is not modified.

Limits

  • Finds only the dominant eigenvalue.
  • Very slow if |λ2| ≈ |λ1|; may not converge if |λ1| = |λ2|.
  • Fails in theory if x0 is orthogonal to v1 (c1 = 0).
  • PageRank: the dominant eigenvector of the web link matrix gives the importance of pages.
  • Variants: inverse iteration (smallest eigenvalue), shifted iteration, Lanczos/Arnoldi; the first principal component in PCA.

Common Mistakes

Taking a heuristic for an approximation algorithmNearest neighbor and 2-opt give good results but have no ratio guarantee; an approximation algorithm needs a proven ρ.
Writing the ratio backwardsFor minimization C ≤ ρ · C*, for maximization C ≥ C*/ρ. ρ is always ≥ 1.
Adding one endpoint in vertex coverAdding only one endpoint of an edge can be n times worse on a star graph; the 2-approximation adds both endpoints.
Forgetting the triangle inequalityThe shortcut step of the MST-based 2-approximation keeps the path from growing only for metric TSP.
Treating metaheuristics as exactSimulated annealing and genetic algorithms do not guarantee convergence to the optimum; run them several times with different seeds and parameters and keep the best result.
Skipping normalizationIf x is not normalized at every step of power iteration, the numbers overflow (|λ₁| > 1) or shrink to zero.

Sample Problems

  1. A minimization algorithm finds 30; the optimum is 20. What is the ratio on this input?
  2. Nearest neighbor from city 2 on the 5-city TSP example: tour and length?
  3. Path 1–2–3–4–5–6, edges taken in order (1,2), …, (5,6): how many vertices does the 2-approximation pick? The optimum?
  4. m = 2, jobs 3, 3, 2, 2, 2: what are Cmax for list scheduling and LPT, and the optimum?

  1. C/C* = 30/20 = 1.5.

Exercises

  1. a(0,0), b(4,3), c(4,0), d(0,3), and the tour has edges (a,b), (c,d). What is the 2-opt gain Δ?
