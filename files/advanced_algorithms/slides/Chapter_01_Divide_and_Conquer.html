Paradigm

The Divide–Break Down–Conquer Paradigm

An effective way to solve complex problems (divide and conquer). It follows these steps:

  1. Divide: split the problem into smaller, manageable subproblems.
  2. Break down: keep splitting until the subproblems are small enough to solve directly (recursion).
  3. Conquer: solve each subproblem separately.
  4. Combine: merge the subproblem solutions into a solution of the original problem.
Key: the subproblems are of the same kind as the original, only smaller, and independent of each other, so the same function calls itself recursively.

Paradigm

Why Divide and Conquer?

  • It breaks a complex problem into small, manageable pieces that are easier to understand and solve.
  • The same method (the same function) is reused at every level: short, reusable code.
  • Used in sorting, searching, computational geometry, big-number and matrix arithmetic, and game-playing AI.

Advantages

  • Often an asymptotic gain: O(n²) → O(n log n), O(n) → O(log n).
  • Independent subproblems can be solved in parallel.
  • Small subproblems fit in cache: good memory locality.
  • Correctness proofs by induction are easy.

Disadvantages

  • Recursion overhead: call stack, extra memory (e.g., O(n) for merge sort).
  • If subproblems overlap, the same work is repeated → exponential time.
  • For small n the constant factors dominate; in practice, switch to a simple method below a threshold.

Paradigm

General Template and Recurrence

Result divideAndConquer(Problem p) {
  if (p.size() <= THRESHOLD)
    return solveDirectly(p);        // base case
  Problem[] subs = divide(p);       // a subproblems of size n/b
  Result[] sols = new Result[subs.length];
  for (int i = 0; i < subs.length; i++)
    sols[i] = divideAndConquer(subs[i]); // conquer: recurse
  return combine(sols);             // combine
}
Running time:
T(n) = a·T(n/b) + f(n)
a: number of subproblems · n/b: subproblem size · f(n): cost of dividing + combining
  • Without a base case, the recursion never ends.
  • The split should be balanced: n/2 + n/2 is good, 1 + (n − 1) is bad.
  • Speedups usually come from reducing a (Karatsuba, Strassen) or shrinking f(n).

The Template in Action: Maximum Element

int findMax(int[] a, int lo, int hi) {
  if (lo == hi) return a[lo];       // base case
  int mid = (lo + hi) / 2;
  int left = findMax(a, lo, mid);
  int right = findMax(a, mid + 1, hi);
  return Math.max(left, right);     // combine
}

Recurrences

The Master Theorem and This Chapter's Algorithms

T(n) = a·T(n/b) + f(n), a ≥ 1, b > 1. Compare f(n) with the total leaf work nlogb a: if f(n) is polynomially smaller, Θ(nlogb a) (case 1, leaves dominate); if it is of the same order, Θ(nlogb a · log n) (case 2); if it is polynomially larger and the regularity condition holds, Θ(f(n)) (case 3, root dominates).

All of the gain in Karatsuba and Strassen comes from reducing a by one: 4 → 3 and 8 → 7. Quickhull (T(n₁) + T(n₂) + n) and unbalanced quicksort (T(n − 1) + n) have unequal splits, so the master theorem does not apply; solve them with a recursion tree.

Merge Sort: A Divide-and-Conquer View

Array: [38, 27, 43, 3, 9, 82, 10], n = 7.

Divide: mid = (0 + 6)/2 = 3 → [38 27 43 3] and [9 82 10].

The halves are split again: [38 27] [43 3] [9 82] [10].

One-element arrays are already sorted: the base case.

Combine: pairs are merged in order: [27 38] [3 43] [9 82] [10].

[3 27 38 43] and [9 10 82]: each merge takes as many steps as the two halves have elements.

Final merge: [3 9 10 27 38 43 82]. Each level costs O(n); ⌈log₂ 7⌉ = 3 levels.

  • Divide: split the array in the middle, O(1). Conquer: sort both halves recursively. Combine: merge the sorted halves in one pass, Θ(n).
  • T(n) = 2T(n/2) + Θ(n) → case 2 → Θ(n log n) in the best, average, and worst case alike. The real work happens in the merge.

Fast Exponentiation: Tracing 3¹³

long power(long x, int n) {
  if (n == 0) return 1;         // base case
  long y = power(x, n / 2);
  if (n % 2 == 0) return y * y; // even

Basic Examples

When Does It Fail? Overlapping Subproblems

long fib(int n) {
  if (n < 2) return n;
  return fib(n - 1) + fib(n - 2);
}
  • 15 calls for F(5): F(3) is computed 2 times, F(2) 3 times.
  • The subproblems are not independent; they overlap → T(n) = T(n−1) + T(n−2) + O(1) = O(φⁿ) ≈ O(1.618ⁿ).
  • Fix: store the results → dynamic programming, O(n).
The Fibonacci recursion can be written in divide-and-conquer form and gives the right answer, but it is a bad example: divide and conquer is efficient only when the subproblems are independent.

Convex Hull

Convex Hull

  • Let S be a set of n points in the plane. The convex hull of S is the smallest convex polygon containing S.
  • Hammer a nail into each point and stretch a rubber band around them: the shape it takes is the hull.
  • The hull's vertices are points of S; the output is the list of these vertices in counterclockwise order.
  • Convex: the segment joining any two points inside lies entirely within the polygon.
Uses: collision detection (games, robotics), geographic information systems, shape analysis in image processing, farthest pair of points, clustering.

Convex Hull

The Quickhull Algorithm

  1. The points with the smallest (A) and largest (B) x are on the hull.
  2. Line AB splits the points into two subsets: above and below it.
  3. In a subset, the point C farthest from AB is on the hull.
  4. Points inside triangle ACB are discarded: they cannot be on the hull.
  5. Recurse on the points outside AC and outside CB.
  6. Stop when no points remain; the points found form the hull.

Steps 1–2: the leftmost A and the rightmost B are on the hull; line AB splits the points into two sets (upper / lower).

Steps 3–5: C (13,27), farthest from AB in the upper set, is on the hull. The 4 points inside ACB are discarded; recurse outside AC and CB.

Step 6: recurse until no point is left outside → a 7-vertex hull.

Like quicksort (hence the name): the farthest point is the pivot, and the triangle's sides partition the rest.

Convex Hull

Geometry: Orientation Test and Distance

Quickhull needs only integer multiplication; no angles, square roots, or division:

long cross(Point A, Point B, Point P) {
  return (long)(B.x - A.x) * (P.y - A.y)
       - (long)(B.y - A.y) * (P.x - A.x);
}
  • cross > 0: P is to the left of A→B; < 0: to the right; = 0: on the line.
  • |cross| = 2 × (area of triangle ABP) = |AB| × distance. Since |AB| is fixed, farthest point = largest cross.
Example: A = (2,18), B = (35,11). For C = (13,27), cross = 33·9 − (−7)·11 = 374; for (28,23), 33·5 + 7·26 = 347. C has the largest value → C is the farthest point.

Convex Hull

Quickhull Analysis and Other Hull Algorithms

  • Each call scans S once (farthest point + two partitions): O(|S|).
  • T(n) = T(n₁) + T(n₂) + O(n), n₁ + n₂ ≤ n − 1.
  • Average (balanced splits, many points discarded): O(n log n); often even faster for uniformly random points.
  • Worst case: only one point is split off at each step → T(n) = T(n − 1) + O(n) = O(n²).
  • Output-sensitive bound: O(n·h) for a hull with h vertices.

Closest Pair of Points

Closest Pair of Points

Problem: among n points in the plane, find the pair with the smallest Euclidean distance d(p, q) = √((pₓ − qₓ)² + (py − qy)²).

double bruteForce(List<Point> p) {
  double best = Double.MAX_VALUE;
  for (int i = 0; i < p.size(); i++)
    for (int j = i + 1; j < p.size(); j++)
      best = Math.min(best, dist(p.get(i), p.get(j)));
  return best;
}
  • Brute force: n(n − 1)/2 pairs → O(n²). For n = 10⁶, ≈ 5·10¹¹ distances.
  • Easy in one dimension: sort and compare only neighbors → O(n log n).
  • In two dimensions, neighbors in x order are not enough; divide and conquer achieves O(n log n).
Applications: the two closest aircraft in air traffic control, clustering, collision detection, nearby facilities in geographic data.

Closest Pair of Points

Divide and Conquer: The Middle Strip

  1. Sort the points once by x and once by y.
  2. Divide: split into two halves with the line L through the x of the middle point.
  3. Conquer: recursively find δL and δR in the halves; δ = min(δL, δR).
  4. Combine: a closer pair must cross L → check only the strip points with |x − L| < δ.
  5. Scan the strip in y order; compare each point only with the following points whose y differs by less than δ.
Why at most 7? Split the δ × 2δ rectangle above p into 8 squares of side δ/2. Two points in one square would lie in the same half at distance < δ, which is impossible → ≤ 1 point per square → p is compared with at most 7 points.

double closest(List<Point> X, List<Point> Y) {
  int n = X.size(), mid = n / 2;
  if (n <= 3) return bruteForce(X);
  Point m = X.get(mid);  // YL/YR: the halves of Y
  double dL = closest(X.subList(0, mid), YL);
  double dR = closest(X.subList(mid, n), YR);
  double d = Math.min(dL, dR);
  List<Point> s = new ArrayList<>();  // strip
  for (Point p : Y)                   // in y order
    if (Math.abs(p.x - m.x) < d) s.add(p);
  for (int i = 0; i < s.size(); i++) {
    Point p = s.get(i);
    for (int j = i + 1; j < s.size()
         && s.get(j).y - p.y < d; j++)
      d = Math.min(d, dist(p, s.get(j)));
  }
  return d;
}

Karatsuba Multiplication

Karatsuba: 3 Multiplications Instead of 4

Split the n-digit numbers x, y at m = ⌊n/2⌋: x = a·10m + b, y = c·10m + d.

Naive divide and conquerx·y = ac·102m + (ad + bc)·10m + bd
4 products: ac, ad, bc, bd
T(n) = 4T(n/2) + O(n) = O(n²) → no gain!
Karatsuba (1962)(a + b)(c + d) = ac + (ad + bc) + bd
⇒ ad + bc = (a + b)(c + d) − ac − bd
3 products: z2 = ac, z0 = bd, z1 = (a + b)(c + d)
T(n) = 3T(n/2) + O(n) = O(n1.585)
Example: 1234 · 5678 (m = 2, 10m = 100)
a = 12, b = 34, c = 56, d = 78z2 = 12·56 = 672 · z0 = 34·78 = 2652
z1 = (12 + 34)(56 + 78) = 46·134 = 6164z1 − z2 − z0 = 6164 − 672 − 2652 = 2840 (= ad + bc)
672·10⁴ + 2840·10² + 2652 = 6,720,000 + 284,000 + 2652 = 7,006,652 ✓

long karatsuba(long x, long y) {
  if (x < 10 || y < 10) return x * y; // base case
  int n = Math.max(digits(x), digits(y));
  long p = (long) Math.pow(10, n / 2);
  long a = x / p, b = x % p;   // x = a·p + b
  long c = y / p, d = y % p;   // y = c·p + d
  long z0 = karatsuba(b, d);
  long z1 = karatsuba(a + b, c + d);
  long z2 = karatsuba(a, c);
  return z2 * p * p + (z1 - z2 - z0) * p + z0;
}

Karatsuba Analysis

  • T(n) = 3T(n/2) + O(n) → case 1 → Θ(nlog₂3) ≈ Θ(n1.585).
  • Addition, subtraction, and shifting by 10m cost O(n); cutting the products from 4 to 3 lowers the exponent from 2 to 1.585.
  • The example makes 16 calls and 11 base-case products (the schoolbook method needs 16 one-digit products).
  • Slower on small numbers because of the extra additions → use the schoolbook method below a threshold.
  • Java's BigInteger.multiply uses Karatsuba and Toom-Cook for large numbers. Faster still: Schönhage–Strassen O(n log n log log n), Harvey–van der Hoeven O(n log n) (2019).

Matrix Multiplication: Classic and Block

Classic: Θ(n³) 
for (int i = 0; i < n; i++)
  for (int j = 0; j < n; j++)
    for (int k = 0; k < n; k++)
      C[i][j] += A[i][k] * B[k][j];

n² cells, each needing n products → n³ products.

Block divide and conquer

Split A, B, and C into four n/2 × n/2 blocks:

C11 = A11·B11 + A12·B21
C12 = A11·B12 + A12·B22
C21 = A21·B11 + A22·B21
C22 = A21·B12 + A22·B22
8 block products + 4 block additions: T(n) = 8T(n/2) + Θ(n²) → nlog₂8 = Θ(n³). Splitting alone is not enough; the number of products must go down.

Strassen Multiplication

Strassen Analysis and Practice

  • T(n) = 7T(n/2) + Θ(n²) → case 1 → Θ(nlog₂7) ≈ Θ(n2.807).
  • Scalar products for n = 2k: 7k (classic: 8k). For n = 1024: 7¹⁰ ≈ 2.8·10⁸ vs. 8¹⁰ ≈ 1.07·10⁹ → about 3.8 times fewer.
  • If n is not a power of 2, the matrix is padded with zeros.
  • Threshold: 18 extra additions and temporary matrices make it slow for small n; libraries switch to the classic method for n ≲ 64–128.
  • Numerical stability: with floating-point numbers, the subtractions can amplify errors.
  • Memory: temporary blocks at every level → extra O(n²).
  • The theoretical record is ω < 2.372 (2024); the constants are huge, so it is not used in practice.
Lesson: trading a product for additions lowers the exponent by reducing a by one. Same idea in Karatsuba (4 → 3) and Strassen (8 → 7).

Where the gain comes from: either the work is split evenly and each level is combined in O(n) (sorting, closest pair), or the number of subproblems is reduced (Karatsuba, Strassen), or half is thrown away (search, exponentiation).

Common Mistakes

Forgetting the base caseOr writing one that is never reached: infinite recursion, StackOverflowError. In Karatsuba: x < 10 || y < 10.
Unbalanced splitsThe last element as pivot on a sorted array, or a single point per step in Quickhull: T(n) = T(n − 1) + n = O(n²).
Overlapping subproblemsPlain recursive Fibonacci takes exponential time; dynamic programming, which stores results, is needed.
Underestimating the combine costSorting the strip in every call gives O(n log² n); 2T(n/2) + n log n ≠ Θ(n log n).
Misapplying the master theoremIt does not apply to T(n) = T(n − 1) + n, to unequal splits, or to f(n) = n/log n.
Sign errorsIn Strassen, C22 = P5 + P1 − P3 − P7; a single sign error silently produces a wrong matrix. Comparing with the classic method on a small example catches it.

Exercises

  1. Find the maximum element of an array with divide and conquer; solve the recurrence.
  2. Modify merge sort to count inversions (i < j, a[i] > a[j]). What is the result for [2, 4, 1, 3, 5]?
  3. Maximum subarray: give a divide-and-conquer solution for [−2, 1, −3, 4, −1, 2, 1, −5, 4] and its running time.
  4. Compute A = [[1, 2], [3, 4]] times B = [[5, 6], [7, 8]] with Strassen; try C22 with ± P7.
  5. Describe an input on which Quickhull takes O(n²) time.
  6. What would change in the closest pair algorithm if the base case were n ≤ 1 instead of n ≤ 3?
Answers / hints
  1. max(left half, right half); T(n) = 2T(n/2) + O(1) → case 1 → Θ(n).
  2. When the merge takes an element from the right, add the number of elements left on the left side; O(n log n). Result 3.
  3. max(left, right, crossing the middle); 2T(n/2) + O(n) = O(n log n). Result 6 ([4, −1, 2, 1]).
  4. P1..P7 = −2, 24, 35, 8, 65, −30, −22 → C = [[19, 22], [43, 50]]; C22 = 65 − 2 − 35 + 22 = 50 ✓ (6 with +P7 ✗).
  5. Points on a convex curve where the farthest point is always next to one end (exponentially spaced): T(n) = T(n − 1) + O(n).
  6. A one-point half returns ∞; the result is still correct (the strip finds the missed pair), but the number of calls grows.
