Introduction

Algorithms That Gamble

  • Some problem-solving techniques resemble games of chance.
  • The algorithm uses randomness when making decisions: it flips a coin, rolls a die, or picks a random element.
  • Example game: roll two dice; the player wins if the sum is 7 or 11.
P(7) = 6/36, P(11) = 2/36 → P(win) = 8/36 = 2/9 ≈ 0.22. Expected number of rolls until a win = 1 / (2/9) = 4.5.

Introduction

Randomized Algorithms

  • A randomized algorithm uses random numbers in addition to its input.
  • Two runs on the same input may take different steps: the running time (and sometimes the output) can vary from run to run.
  • The running time is now a random variable, so we study the expected time E[T(n)]. The expectation is over the algorithm's own coin flips, not over the input.

Introduction

Why Randomness?

Protection against bad inputs

Deterministic quicksort takes O(n²) on a sorted array. With a random pivot, no input is always bad: the worst case arises only from unlucky coin flips.

Simplicity

A randomized algorithm is often much shorter and clearer than the best deterministic one (Karger's min cut, randomized quickselect).

Speed

Miller–Rabin decides whether a number with hundreds of digits is prime in milliseconds, with a tiny error probability.

Sampling and symmetry breaking

Monte Carlo simulation, random sampling and leader election in distributed systems are hard without randomness.

The price: time or correctness is guaranteed only probabilistically, and we need a good random number generator.

Types of Algorithms

Reducing the Error Probability

Amplification by repetition

If one round errs with probability at most q, then after k independent rounds the error is ≤ qk.

  • Miller–Rabin: q ≤ 1/4 → with k = 20 rounds, ≤ 4−20 ≈ 9 · 10−13.
  • Karger: success ≥ 2/(n(n−1)); with n(n−1)/2 · ln n repetitions, failure ≤ 1/n.
Converting between types
  • Las Vegas → Monte Carlo: stop the algorithm after 2 · E[T] steps. Markov: P(T ≥ 2 E[T]) ≤ 1/2 → "no answer" with probability at most 1/2.
  • Monte Carlo → Las Vegas: if an answer can be verified quickly (e.g., multiply the factors found), repeat until it checks out. Expected repetitions = 1/p.

Miller–Rabin error bound 4−k (log scale): each round divides the bound by 4. k = 10 rounds suffice to get below 10−6.

Shuffling

Example: Shuffling

  • Randomness is used to shuffle the elements of a list: a deck of cards, random test data, a playlist.
  • Correctness: every element lands in every position with equal probability; more strongly, each of the n! permutations must have probability 1/n!.
  • Running time: Fisher–Yates always performs exactly n − 1 swaps: Θ(n). What varies is the result, not the time.
  • Built into Java: Collections.shuffle(list) (Fisher–Yates).

static void shuffle(int[] a) {
  for (int i = a.length - 1; i > 0; i--) {
    int j = rng.nextInt(i + 1); // 0 ≤ j ≤ i
    int t = a[i]; a[i] = a[j]; a[j] = t;
  }
}

BogoSort

BogoSort

  • One of the worst-performing sorting algorithms ("stupid sort", permutation sort).
  • Basic idea: shuffle randomly until the list is sorted.
  • A fun and instructive Las Vegas algorithm; never used in practice.
  1. Is the list sorted? Yes → stop.
  2. No → shuffle the list randomly and go back to step 1.
static void bogoSort(int[] a) {
  while (!isSorted(a))
    shuffle(a);         // Fisher–Yates
}
static boolean isSorted(int[] a) {
  for (int i = 0; i + 1 < a.length; i++)
    if (a[i] > a[i + 1]) return false;
  return true;
}

BogoSort

Analysis of BogoSort

  • With n distinct elements, a random shuffle is sorted with probability p = 1/n!.
  • Trials are independent → geometric distribution: the expected number of shuffles is 1/p = n!.
  • Each round: shuffle O(n) + check O(n) → expected time Θ(n · n!). This is the same order as O((n + 1)!), since (n + 1)! = (n + 1) · n!.
  • Best case: the array is already sorted → one check, O(n).
  • Worst case: unbounded. Unlucky shuffles can go on forever (with probability tending to 0). O((n + 1)!) bounds only the expected time, not the worst case.

Randomized Quicksort

Randomized Quicksort: Code

static Random rng = new Random();

static void quickSort(int[] a, int lo, int hi) {
  if (lo < hi) {
    int p = partition(a, lo, hi); // random
    quickSort(a, lo, p - 1);
    quickSort(a, p + 1, hi);
  }
}

static int partition(int[] a, int lo, int hi) {
  int r = lo + rng.nextInt(hi - lo + 1);
  swap(a, r, hi);          // pivot to end
  int pivot = a[hi], k = lo;
  for (int i = lo; i < hi; i++)
    if (a[i] <= pivot)
      swap(a, i, k++);     // smaller left
  swap(a, k, hi);          // pivot in place
  return k;
}
  • The pivot is uniformly random. The output is always correct (Las Vegas); only the running time depends on the pivots.
  • partition moves the random pivot to the end, then runs Lomuto: for [6, 5, 3, 1, 8, 7, 2, 4], r = 2 (pivot 3) → [1, 2, 3, 6, 8, 7, 5, 4], returns 2.
  • Extra space: the recursion stack, expected depth O(log n); recursing on the smaller part first makes it O(log n) in the worst case too.
  • With many duplicate keys, use three-way partitioning (<, =, >).

Expected Number of Comparisons

  • Label the elements in sorted order: z1 < z2 < … < zn. Indicator Xij = 1 ⇔ zi and zj are compared.
  • Two elements are compared only if one is the pivot. If the first pivot from {zi, …, zj} lies strictly between them, they are split apart and never compared.
  • That first pivot is uniformly random → P(Xij = 1) = 2 / (j − i + 1).
  • Linearity: E[X] = Σi<j 2/(j − i + 1) < 2n Hn ≈ 1.39 n log₂ n.
  • Exact value: E[X] = 2(n + 1)Hn − 4n.

Randomized Selection (Quickselect)

static int select(int[] a, int lo, int hi, int s) {
  if (lo == hi) return a[lo];
  int p = partition(a, lo, hi);
  if (s == p) return a[p];
  if (s < p) return select(a, lo, p - 1, s);
  return select(a, p + 1, hi, s);
}
  • Goal: find the s-th smallest element (e.g., the median) without sorting.
  • It uses the same random partitioning but recurses on one side only.
  • Expected time O(n) (≈ 3.39 n comparisons for the median); worst case O(n²).
  • Example: [6, 5, 3, 1, 8, 7, 2, 4] with s = 2 (0-based). Partitioning around pivot 3 gives p = 2 → the answer 3 on the first try.

Monte Carlo Algorithms

Monte Carlo Estimate of π

  • Throw uniformly random points into the unit square. The quarter circle has area π/4 and the square area 1 → P(inside) = π/4, so π ≈ 4 · inside / n.
  • The error falls like 1/√n: one more correct digit needs 100 times as many points.
static double estimatePi(int n) {
  int inside = 0;
  for (int t = 0; t < n; t++) {
    double x = rng.nextDouble(), y = rng.nextDouble();
    if (x * x + y * y <= 1) inside++;
  }
  return 4.0 * inside / n;
}

300 points: 239 inside → π ≈ 4 · 239/300 = 3.187.

Monte Carlo Algorithms

Miller–Rabin Primality Test

  • Fermat's little theorem: if n is prime and 1 < a < n, then an−1 ≡ 1 (mod n). If this fails, n is certainly composite; but some composites (Carmichael numbers) satisfy it for every base.
  • Square-root property: if n is prime, x² ≡ 1 (mod n) holds only for x ≡ ±1.
  • Write n − 1 = 2s · d (d odd); for a random a, examine the sequence ad, a2d, …, a2s−1d (mod n).
  • If the sequence does not start with 1 and n − 1 never appears, a is a witness that n is composite. Otherwise n "passes" this round.
  • For composite n, at most 1/4 of the bases are liars → with k independent rounds the error is ≤ 4−k. Each round takes O(log n) modular multiplications: O(k log³ n) bit operations in total.
One-sided error: the answer "composite" is certain; the answer "prime" is only probably right.

Monte Carlo Algorithms

Miller–Rabin: Code

static boolean isPrime(long n, int k) {
  if (n < 4) return n == 2 || n == 3;
  if (n % 2 == 0) return false;
  long d = n - 1; int s = 0;     // n-1 = 2^s·d
  while (d % 2 == 0) { d /= 2; s++; }
  for (int round = 0; round < k; round++) {
    long a = 2 + rng.nextLong(n - 3); // [2, n-2]
    long x = modPow(a, d, n);    // a^d mod n
    if (x == 1 || x == n - 1) continue;
    boolean witness = true;
    for (int r = 1; r < s && witness; r++) {
      x = x * x % n;
      if (x == n - 1) witness = false;
    }
    if (witness) return false;   // certainly composite
  }
  return true;                  // probably prime
}
  • modPow: fast modular exponentiation (square-and-multiply), O(log d) multiplications.
  • The base a is drawn uniformly from [2, n − 2].
  • With long, x * x does not overflow only for n < 3 · 109; for larger n use BigInteger.modPow or isProbablePrime.

modPow: 2³⁵ mod 561 Step by Step

Compute 2³⁵ mod 561. Since 35 = 32 + 2 + 1, 2³⁵ = 2³² · 2² · 2¹. Initially result = 1, a = 2.

Bit 0 = 1: result = 1 · 2 mod 561 = 2 (2¹ included). Then a = 2² mod 561 = 4.

Bit 1 = 1: result = 2 · 4 mod 561 = 8 (2² included). Then a = 4² mod 561 = 16.

Bit 2 = 0: result unchanged (8). Only square: a = 16² mod 561 = 256.

Bit 3 = 0: result unchanged (8). Only square: a = 256² mod 561 = 460.

Bit 4 = 0: result unchanged (8). Only square: a = 460² mod 561 = 103.

Bit 5 = 1: result = 8 · 103 mod 561 = 263 (2³² included). Then a = 103² mod 561 = 511.

d = 0: loop done. return 263 = 2³⁵ mod 561, using only 6 squarings + 3 multiplications instead of 34.

static long modPow(long a, long d, long n) {
  long result = 1;
  a %= n;
  while (d > 0) {
    if ((d & 1) == 1)          // bit is 1
      result = result * a % n;
    a = a * a % n;             // square
    d >>= 1;                   // next bit
  }
  return result;
}

Karger's Min-Cut Algorithm

Start: 6 vertices, 8 edges. The minimum cut is 2 (e.g., {3, 4} | the rest). Dark vertex: the supervertex formed by the last contraction.

Random edge (0, 2) contracted: its endpoints merge into one supervertex, edges between them (self-loops) are deleted, parallel edges (×k) are kept. Remaining: 7 edges.

Random edge (1, 5) contracted: its endpoints merge into one supervertex, edges between them (self-loops) are deleted, parallel edges (×k) are kept. Remaining: 6 edges.

Random edge (3, 4) contracted: its endpoints merge into one supervertex, edges between them (self-loops) are deleted, parallel edges (×k) are kept. Remaining: 5 edges.

Random edge (0, 1) contracted: its endpoints merge into one supervertex, edges between them (self-loops) are deleted, parallel edges (×k) are kept. Remaining: 2 edges. Two supervertices left → cut found = 2 (minimum; a successful run).

  • Problem: find a cut with the fewest edges that splits the graph into two parts (global min cut).
  • Algorithm: contract a uniformly random edge until 2 vertices remain; the remaining edges form a cut.
  • One run finds a minimum cut with probability at least 2/(n(n−1)) (n = 6: ≥ 1/15). On this graph, 200,000 simulations gave ≈ 0.46.
  • The output can be wrong (a larger cut) → Monte Carlo. E.g., if the first edges chosen are (1,2), (4,5), (3,4), (0,1), we get the cut {0,1,2} | {3,4,5} with 3 edges.
  • n(n−1)/2 · ln n repetitions → failure ≤ 1/n; O(n4 log n) in total (simple implementation).

Other Applications

Graph coloringTries random colorings, searching for one in which no two neighbors share a color.
Randomized DFSVisits neighbors in random order to find connectivity and spanning trees (e.g., maze generation).
MatchingRandomized incremental algorithms add edges in random order to approach a maximum matching.
Approximate countingCount-Min Sketch uses random hash functions to estimate frequencies in large data streams with controlled error.
Matrix computationsRandomized matrix approximation yields low-rank approximations: dimensionality reduction, data compression.

Pseudorandom Numbers

  • Computers produce pseudorandom numbers rather than true randomness: a deterministic sequence that looks random.
  • Linear congruential generator (LCG): Xk+1 = (a · Xk + c) mod m. java.util.Random: a = 25214903917, c = 11, m = 248.
  • The same seed gives the same sequence: runs with new Random(42) are reproducible (debugging, experiments).
  • Use SecureRandom for cryptography and ThreadLocalRandom in multithreaded code.
Random ranges
  • rng.nextInt(n) → 0 … n − 1
  • lo + rng.nextInt(hi − lo + 1) → lo … hi
  • rng.nextDouble() → [0, 1)
  • rng.nextInt(6) + 1 → a die roll: 1 … 6

Common Mistakes

Naive shuffleSwapping with nextInt(n) for every i is biased (nn paths, n! permutations). Use nextInt(i + 1).
"A random pivot eliminates the worst case"No: the worst case is still O(n²). What changes is that no input is always bad, and the worst case becomes very unlikely.
Confusing average and expected timeThe average case assumes an input distribution; expected time is computed for each input over the algorithm's coin flips.
Treating a Monte Carlo answer as certainIn Miller–Rabin, "prime" means only probably prime; the number of rounds k sets the error bound.
OverflowWith int, x * x % n can overflow for n > 46,341. Use long, Math.multiplyHigh or BigInteger.modPow.
new Random() on every callCreates needless objects, and the seeds may be correlated. Share a single Random; in Karger, pick the edge uniformly (choosing a vertex first and then a neighbor is not uniform).

Sample Problems

  1. Fisher–Yates is applied to [1, 2, 3, 4]; for i = 3, 2, 1 the drawn values of j are 1, 2, 0. What is the result?
  2. For an array of 5 distinct elements, what is the probability that BogoSort finishes after the first shuffle, and what is the expected number of shuffles?
  3. In randomized quicksort, with what probability are the smallest and largest elements compared? Two elements adjacent in sorted order?
  4. Miller–Rabin: run the test on n = 25 with bases a = 7 and a = 2.
  5. In a Monte Carlo run, 787 of 1000 points fell inside the quarter circle. What is the estimate of π?
Show answers
  1. i = 3, j = 1 → [1, 4, 3, 2]; i = 2, j = 2 → unchanged; i = 1, j = 0 → [4, 1, 3, 2].
  2. P = 1/5! = 1/120; expected number of shuffles 120 (geometric distribution).
  3. z1 and zn: 2/n (the first pivot must be one of the two). Neighbors zi, zi+1: 2/2 = 1, always compared.
  4. 24 = 23 · 3. a = 7: 73 ≡ 18, 18² ≡ 24 = n − 1 → passes (7 is a strong liar for 25). a = 2: 8, 14, 21 → 24 never appears → composite.
  5. π ≈ 4 · 787/1000 = 3.148.

Exercises

  1. partition is called on [3, 8, 2, 5, 1, 4, 7, 6] and draws r = 5 (pivot 4). What are the array after partitioning and the return value?
  2. How many comparisons does quicksort make on a sorted 8-element array when the first element is the pivot?
  3. How many Miller–Rabin rounds are needed to push the error probability below 10−6?
  4. On a 6-vertex graph (success ≥ 1/15), how many times must Karger be repeated to bring the failure probability below 1/6?
  5. Convert a Monte Carlo algorithm with success probability 1/3 and a verifiable result into a Las Vegas algorithm. What is the expected number of repetitions?
Show answers
  1. Pivot to the end: [3, 8, 2, 5, 1, 6, 7, 4]; the elements ≤ 4 (3, 2, 1) move left → [3, 2, 1, 4, 8, 6, 7, 5], returns 3.
  2. The part shrinks by one at each level: 7 + 6 + … + 1 = n(n − 1)/2 = 28.
  3. 4−k < 10−6 → k ≥ 10 (4−10 ≈ 9.5 · 10−7).
  4. (14/15)T ≤ e−T/15 ≤ 1/6 → T ≥ 15 ln 6 ≈ 26.9 → 27 repetitions suffice.
  5. Repeat until verification succeeds: the answer is always correct (Las Vegas); expected repetitions 1/(1/3) = 3.
