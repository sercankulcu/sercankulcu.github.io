Introduction

Weighing the Best Options

  • Solving a hard problem is sometimes like picking the right way at a fork in the road.
  • Branch and bound algorithms explore the possible solution paths systematically to find the best option.
  • Goal: an exact (optimal) solution to combinatorial optimization problems. Trying every candidate takes exponential or factorial time.
  • Idea: estimate in advance how good a branch can possibly be; if that is not good enough, never enter the branch.

Introduction

Branch and Bound Algorithms

  • Think of it as a tree that branches and gets pruned.
  • First the problem is split into smaller subproblems (branching).
  • For each subproblem the best reachable value is estimated (the bound).
  • Options whose bound is no better than the best solution found so far are discarded (pruning).
  • The process repeats for all remaining subproblems; as useless branches are pruned, the search gets shorter.
  • Applications: the traveling salesman, knapsack, scheduling and more.

Introduction

Basic Concepts

State-space treeRoot = no decisions made yet; each level is one decision (e.g. "take item i?"); leaves are complete solutions.
BranchingGenerating a node's subproblems (children). The node being expanded is the E-node (expanding node).
BoundAn optimistic value that no solution below the node can beat: an upper bound for maximization, a lower bound for minimization.
Live nodeA promising node that has been generated but not yet expanded. Live nodes wait in a queue.
Dead nodeA node that has been expanded, or pruned as infeasible or with an insufficient bound; it is never considered again.
best (incumbent)The value of the best complete solution found so far. Pruning decisions are made against it.

Paradigm

General Scheme (Maximization)

int best = -∞;
queue.add(root);
while (!queue.isEmpty()) {
  Node u = queue.remove();    // strategy
  if (bound(u) <= best) continue;
  for (Node c : u.children()) {
    if (!isFeasible(c)) continue;
    if (isComplete(c) && value(c) > best)
      best = value(c);       // new incumbent
    if (bound(c) > best)
      queue.add(c);          // live node
  }
}
return best;
  1. Select: remove a live node from the queue. The strategy decides which one (FIFO, LIFO, best bound).
  2. Re-test: best may have grown while the node was waiting; if its bound is no longer enough, discard it.
  3. Branch: generate the children; drop infeasible ones.
  4. Update: if a complete solution is better, raise best.
  5. Bound: enqueue only children whose bound can beat best.

For minimization the directions flip: use a lower bound and prune when lb(c) ≥ best.

Paradigm

How to Choose a Bound

It must be valid (optimistic)For maximization bound(u) ≥ every solution in the subtree; for minimization lb(u) ≤ every solution. Otherwise the optimum may be pruned and the result is wrong.
It should be tightThe closer it is to the true value, the more branches are pruned. An infinitely large "bound" is valid but prunes nothing.
It should be cheapThe bound is computed at every node. A very expensive bound can cost more time than the nodes it prunes.
Build it by relaxationDrop a hard constraint and solve the easy problem: fractional knapsack, LP relaxation, cheapest outgoing edges.
Success depends heavily on a good bound. In minimization the lower bound is the minimum achievable in the best case; a weak lower bound makes the search longer.

Paradigm

When Is a Node Pruned?

1. InfeasibilityThe node violates a constraint: weight > capacity, a second visit to the same city, an LP with no solution. No valid solution lies below it.
2. Boundbound(u) ≤ best (maximization) or lb(u) ≥ best (minimization). No solution below it can beat the best.
3. CompletenessThe node is a complete solution (a leaf), or the relaxation's solution is already feasible (e.g. the LP solution is integral). Its value is compared with best; no branching is needed.

Backtracking uses only rule 1 (and completeness). What sets branch and bound apart is rule 2: a node is cut even when feasible if it is "not good enough".

  • All three strategies find the same optimum; what changes is the number of generated nodes and the memory.
  • In LC search the cost function ĉ(u) is the bound value (or the estimate f(u) + ĝ(u)); A* search is the path-finding version of this idea.

Paradigm

Least-Cost (LC) Search: ĉ(x) = f(x) + ĝ(x)

  • f(x): distance from the root (cost paid so far); ĝ(x): estimate of the remaining cost from x to a solution.
  • Expand the live node with the smallest ĉ. ĝ = 0 → only the cost paid: uniform-cost search (FIFO/BFS with unit steps when f is the depth); f = 0 → greedy best-first search.
  • In the 8-puzzle ĝ = number of misplaced tiles: each misplaced tile needs at least one move, so ĝ never overestimates.
  • Initially 5 and 8 are misplaced (ĝ = 2). The child with the smallest ĉ is “blank down”; its child “blank right” reaches the goal: 2 moves, only 2 expansions.

A TSP or maximum-clique search with no bound test is really backtracking; add a single bound line and it becomes branch and bound.

Paradigm

Pros and Cons

Pros

  • Finds the exact optimum of hard optimization problems.
  • Narrows the search space and discards useless options.
  • Ideal for problems that ask for the best route or selection.
  • Applies to a wide range of problems whose solutions can be represented as a tree.
  • If stopped early, it still holds a good solution and its bound (a quality guarantee).

Cons

  • Solution time can grow when there are very many options: exponential time in the worst case.
  • With FIFO and best-first strategies, memory can also grow exponentially.
  • Success depends on a good bound; a weak bound prunes almost nothing.
  • Needs a problem-specific bound and branching rule; harder to implement than backtracking.

0/1 Knapsack

Example: The 0/1 Knapsack Problem

  • Notation: profit pᵢ, weight wᵢ, capacity W, decision xᵢ ∈ {0, 1}; maximize Σ pᵢxᵢ subject to Σ wᵢxᵢ ≤ W.
  • Items are sorted by decreasing pᵢ/wᵢ ratio; the bound computation relies on this order.
  • The state-space tree is binary: at level i the left branch is "item i taken" (1), the right one "not taken" (0). The full tree has 2⁵ − 1 = 31 nodes.

0/1 Knapsack

Upper Bound: Fractional Knapsack Relaxation

  • Relaxation: drop the "items cannot be split" constraint. The greedy method solves the fractional knapsack optimally.
  • At node u (profit k, weight a, level i): add the remaining items in ratio order whole while they fit, then a fraction of the first item that does not fit:
bound(u) = k + Σj = i+1m−1 pⱼ + (W − a − Σ wⱼ) · pm / wm    (m: first item that does not fit)
Why valid?Every 0/1 solution is also a fractional solution. Fractional optimum ≥ 0/1 optimum, so the bound never understates the true best.
For the root40 + 30 = 70 (weight 7); item 3 does not fit, 9 units left → 9 · 50/10 = 45. bound(root) = 115. If a > W the node is infeasible (bound 0).

bound(root): Code Trace

double bound(Node u) {
  if (u.weight > W) return 0;   // infeasible
  double result = u.profit;
  int totW = u.weight;
  int j = u.level + 1;
  while (j < n && totW + w[j] <= W) {
    totW += w[j];
    result += p[j];
    j++;
  }
  if (j < n)                // fractional part
    result += (W - totW) * (double) p[j] / w[j];
  return result;
}

Root node: level −1, profit 0, weight 0. Since 0 ≤ 16, the node is feasible.

The bound starts from the current profit; j points to the next item (index 0 = item 1).

0 + w[0] = 2 ≤ 16 → item 1 fits entirely.

totW = 2, result = 40, j = 1.

2 + w[1] = 7 ≤ 16 → item 2 fits entirely too.

totW = 7, result = 70, j = 2.

7 + w[2] = 17 > 16 → item 3 does not fit entirely; the loop ends.

Remaining capacity 9: 9/10 of item 3 → 9 · 50/10 = 45 is added, result = 115.

bound(A) = 115: no solution below this node can earn more than 115.

0/1 Knapsack

Best-First Branch and Bound: Java

int branchAndBound() {
  PriorityQueue<Node> queue = new PriorityQueue<>(
      (a, b) -> Double.compare(b.bound, a.bound));
  Node root = new Node(-1, 0, 0);
  root.bound = bound(root);
  queue.add(root);  int best = 0;
  while (!queue.isEmpty()) {
    Node u = queue.poll();             // largest bound
    if (u.bound <= best || u.level == n - 1) continue;
    int i = u.level + 1;
    // left child: take item i
    Node take = new Node(i, u.profit + p[i],
                         u.weight + w[i]);
    if (take.weight <= W && take.profit > best)
      best = take.profit;
    take.bound = bound(take);
    if (take.bound > best) queue.add(take);
    // right child: skip item i
    Node skip = new Node(i, u.profit, u.weight);
    skip.bound = bound(skip);
    if (skip.bound > best) queue.add(skip);
  }
  return best;
}
  • Node: level, profit, weight, bound (a boolean[] or bitmask can be added for the chosen items).
  • The comparator is reversed: the largest bound comes out first.
  • The test after poll discards nodes that went stale while waiting in the queue (C and G in the example).
  • For FIFO, ArrayDeque + add()/poll() is enough; for LIFO, push()/pop(); the rest of the code is the same.
  • Worst case O(2ⁿ) nodes, O(n) bound computation per node.

FIFO Branch and Bound: Code Trace

int fifoBranchAndBound() {
  ArrayDeque<Node> queue = new ArrayDeque<>();
  queue.add(root);  int best = 0;
  while (!queue.isEmpty()) {
    Node u = queue.poll();            // first in
    if (u.bound <= best || u.level == n - 1) continue;
    for (int take = 1; take >= 0; take--) { // take first
      Node c = child(u, take);        // computes bound(c)
      if (c.weight <= W && c.profit > best)
        best = c.profit;                // new incumbent
      if (c.bound > best) queue.add(c);
    }
  }
  return best;
}

Traveling Salesman

Traveling Salesman Problem (TSP): Lower Bound

  • Minimization: we want the shortest tour; node bounds are lower bounds.
  • Node = a partial path starting at 0; children = the next unvisited city.
  • Lower bound: every city not yet left (the current city + the unvisited ones) must be left by at least one edge:

Symmetric 4-city distance matrix d.

lb(path) = cost(path) + minOut[last city] + Σv unvisited minOut[v]

Root: 2 + 3 + 2 + 5 = 12. Path 0 → 1: 3 + 3 + (2 + 5) = 13. No real tour can cost less than this sum, so the bound is valid.

Traveling Salesman · Run the code step by step

tsp(0, 0, 1): Bounded Depth-First Search

void tsp(int city, int cost, int count) {
  if (count == n) {           // tour complete
    int tour = cost + d[city][0];
    if (tour < best) best = tour;
    return;
  }
  for (int s = 0; s < n; s++) {
    if (visited[s]) continue;
    int next = cost + d[city][s];
    visited[s] = true;
    if (lowerBound(s, next) < best) // bound
      tsp(s, next, count + 1);
    visited[s] = false;      // undo
  }
}

1 → 2: next = 3 + 21 = 24; lb = 31 < ∞ → branch.

2 → 3: next = 24 + 8 = 32; lb = 37 < ∞ → branch.

Tour 0 → 1 → 2 → 3 → 0 = 32 + 15 = 47 < ∞ → best = 47.

1 → 3: next = 3 + 5 = 8; lb = 15 < 47 → branch.

3 → 2: next = 8 + 8 = 16; lb = 18 < 47 → branch.

Tour 0 → 1 → 3 → 2 → 0 = 16 + 2 = 18 < 47 → best = 18.

0 → 2: next = 0 + 2 = 2; lb = 12 < 18 → branch.

2 → 1: next = 23; lb = 31 ≥ best = 18 → pruned.

lowerBound(3, 8): Code Trace

int lowerBound(int last, int cost) {
  int lb = cost + minOut[last];
  for (int v = 0; v < n; v++)
    if (!visited[v])        // not visited
      lb += minOut[v];
  return lb;
}

Step 1 → 3 of the TSP trace: path 0 → 1 → 3, cost 3 + 5 = 8; visited = {0, 1, 3}. The last city 3 must be left once more: lb = 8 + minOut[3] = 8 + 5 = 13.

v = 0: visited (on the path) → no contribution; its outgoing edge is already in the cost.

v = 1: visited (on the path) → no contribution; its outgoing edge is already in the cost.

v = 2: not yet visited → must be left by at least minOut[2] = 2: lb = 15.

v = 3: visited (on the path) → no contribution; 3's exit was added at the start.

Returns lb = 15. Every tour in this branch is ≥ 15; the real tour 0 → 1 → 3 → 2 → 0 = 18. Since 15 < best = 47, the TSP trace entered the branch.

Traveling Salesman

A Tighter Lower Bound: Two Shortest Edges

  • A tour enters each city by one edge and leaves it by another: every city touches exactly two tour edges.
  • These two edges cannot be shorter than the two shortest edges touching the city. Summed over all cities, each edge is counted twice:
tour ≥ ½ · Σv (v's two shortest edges)

On the same matrix the “cheapest outgoing edge” bound gave 12; this bound gives 18, equal to the optimal tour 0 → 1 → 3 → 2 → 0 = 3 + 5 + 8 + 2 = 18. Since bound = optimum at the root, all remaining branches are pruned as soon as the first complete tour is found.

Traveling Salesman · Run the code step by step

twoEdgeBound(): Code Trace

double twoEdgeBound() {
  int sum = 0;
  for (int v = 0; v < n; v++) {
    int m1 = INF, m2 = INF;     // two smallest
    for (int u = 0; u < n; u++) {
      if (u == v) continue;
      if (d[v][u] < m1) { m2 = m1; m1 = d[v][u]; }
      else if (d[v][u] < m2) m2 = d[v][u];
    }
    sum += m1 + m2;
  }
  return sum / 2.0;  // each edge counted twice
}

Symmetric 4-city matrix. sum = 0; we look for the two shortest edges of each city.

v = 0, u = 1: d = 3 < m1 = ∞ → m1 = 3 (the old m1 shifts to m2).

u = 2: d = 2 < m1 = 3 → m2 = 3, m1 = 2. The two minima shift along.

u = 3: 15 is larger than both, no change. sum += 2 + 3 = 5.

v = 1: edges 3, 21, 5 → m1 = 3, m2 = 5. sum = 13.

v = 2: edges 2, 21, 8 → 2 + 8. sum = 23.

v = 3: edges 15, 5, 8 → 5 + 8. sum = 36.

Returns 36 / 2 = 18. The bold edges form exactly the optimal tour (0-1-3-2-0), which is why the bound is tight. On a partial path the same idea applies with the path's edges fixed.

Traveling Salesman

Lower Bound from the Reduced Cost Matrix

  • Set the diagonal to ∞. Subtract the minimum of each row, then the minimum of each column.
  • Every tour uses exactly one cell in each row and each column; the total subtracted comes off every tour's cost → a lower bound.
  • Example: rows 2 + 3 + 2 + 5 = 12, 2 from column 3 → root bound 14.
  • Branching on edge i → j: set row i and column j to ∞, set (j, i) to ∞, and reduce the matrix again. Child bound = parent + reduced c[i][j] + the new reduction.

reduce(): Row and Column Reduction

int reduce(int[][] m) {
  int sum = 0;
  for (int i = 0; i < n; i++) {       // rows
    int mn = rowMin(m, i);
    if (mn > 0 && mn < INF) {
      subtractRow(m, i, mn); sum += mn;
    }
  }
  for (int j = 0; j < n; j++) {       // columns
    int mn = colMin(m, j);
    if (mn > 0 && mn < INF) {
      subtractCol(m, j, mn); sum += mn;
    }
  }
  return sum;
}

4 × 4 distance matrix with ∞ on the diagonal; sum = 0.

Row 0: minimum 2 → subtract 2 from the row: 1, 0, 13. sum = 2.

Row 1: minimum 3 → 0, 18, 2. sum = 5.

Row 2: minimum 2 → 0, 19, 6. sum = 7.

Row 3: minimum 5 → 10, 0, 3. Row reduction done: sum = 12 (the same as the cheapest-exit bound).

Column 0: minimum 0 → no change. Columns 1 and 2 already contain a 0.

Column 3: values 13, 2, 6 → minimum 2; subtracted: 11, 0, 4. sum = 14. The column step adds the fact that “each city is entered once” to the bound.

Returns bound 14: tighter than 12, looser than the two-edge bound (18). The matrix is kept for computing the children's bounds.

Assignment Problem

Assignment Problem: n People, n Jobs

  • c[i][j]: the cost of person i doing job j. Give each person a different job so that the total is minimized; there are n! possible assignments.
  • State space: at level i, pick a free job for person i.
  • Lower bound: each remaining person pays at least the minimum of their own row (job clashes are ignored):
lb = next + restMin[i + 1],  restMin[i] = Σr ≥ i minj c[r][j]

Cut the branch if lb ≥ best. Row minima 4, 3, 2 → restMin = [9, 5, 2, 0]: the root bound is 9.

Assignment Problem · Run the code step by step

assign(0, 0): Code Trace

void assign(int i, int cost) {
  if (i == n) {                     // complete assignment
    best = Math.min(best, cost);
    return;
  }
  for (int j = 0; j < n; j++) {
    if (taken[j]) continue;
    int next = cost + c[i][j];
    if (next + restMin[i + 1] >= best)
      continue;                     // bound
    taken[j] = true;
    assign(i + 1, next);
    taken[j] = false;               // undo
  }
}

p1: job 0 is taken, skipped. Job 1: next = 8, lb = 8 + 2 = 10 → branch.

p2: only job 2 is free: next = 13 → i = 3, complete assignment: best = 13.

Back up. p1 → job 2: next = 11, lb = 11 + 2 = 13 ≥ 13 → cut.

p0 → job 1: next = 8, lb = 8 + 5 = 13 ≥ 13 → cut; the 2 assignments below it are never tried.

p0 → job 2: next = 4, lb = 9 < 13 → branch.

p1 → job 0: next = 11, lb = 13 ≥ 13 → cut.

p1 → job 1: next = 7, lb = 9 → branch.

p2 → job 0: next = 9 → complete assignment, best = 9 (4 + 3 + 2). It equals the bound, so nothing better exists. 7 calls; a search without pruning would visit all 3! = 6 assignments (16 calls).

Other Applications

Integer Linear Programming (ILP)

  • Every variable of the linear program must be an integer. This is the most common industrial use of branch and bound (Land and Doig, 1960).
  • Bound: drop the integrality condition and solve the LP relaxation. The LP optimum is an upper bound on the ILP optimum.
  • Branching: for a fractional variable (y = 1.5), two subproblems: y ≤ 1 and y ≥ 2. The fractional region in between is discarded; no integer point is lost.
Example: maximize Z = 5x + 4y; 6x + 4y ≤ 24, x + 2y ≤ 6, x, y ≥ 0 integers.

Second example: Z = 3x + 2y; x + y ≤ 4, x ≤ 3, y ≤ 2. Brute force tries all 12 points of the grid 0 ≤ x ≤ 3, 0 ≤ y ≤ 2 → (3, 1), Z = 11. Here the LP relaxation also gives (3, 1): branch and bound ends at the root.

ILP: Branching on LP Relaxations

Root: the integrality condition is relaxed (LP relaxation). The LP optimum (3, 1.5), Z = 21 → upper bound. y is fractional → branch on y.

Branch y ≤ 1: LP optimum (3.33, 1), Z = 20.67. x is fractional → open branches x ≤ 3 and x ≥ 4.

Branch x ≤ 3: the LP solution (3, 1) is integral → first incumbent, best = 19.

Branch x ≥ 4: the LP solution (4, 0) is integral, Z = 20 > 19 → best = 20.

Branch y ≥ 2: LP bound Z = 18 ≤ 20 → pruned. Optimum: x = 4, y = 0, Z = 20.

Rounding the LP optimum (3, 1.5) gives (3, 1) → Z = 19, or (3, 2) → infeasible. The true optimum (4, 0) cannot be found by rounding.

Maximum Clique

  • Clique: a set of vertices in which every two are adjacent.
  • Bound: if |K| + |cand| ≤ |best|, the current clique cannot beat best however much it grows.
void clique(List<Integer> K, int start) {
  if (K.size() > best.size())
    best = new ArrayList<>(K);
  List<Integer> cand = new ArrayList<>();
  for (int v = start; v < n; v++)
    if (adjToAll(v, K)) cand.add(v); // adjacent to K
  if (K.size() + cand.size() <= best.size())
    return;                        // bound
  for (int v : cand) {
    K.add(v);
    clique(K, v + 1);
    K.remove(K.size() - 1);          // undo
  }
}

Other Applications

A Tighter Bound for Clique: Coloring

  • Every pair of vertices in a clique is adjacent, so all vertices of a clique get different colors.
  • If the candidates can be colored with k colors, at most k of them can join the clique: prune if |K| + colors(cand) ≤ |best|.
  • Greedy coloring takes O(cand²) and, even if not optimal, gives a valid upper bound (extra colors only loosen the bound).
  • Example: the candidates form a 5-vertex ring, K is empty, best = 3. The old bound 0 + 5 > 3 → the branch is opened; the color bound 0 + 3 ≤ 3 → pruned (the largest clique in a ring is 2).
Most of the fastest exact clique algorithms in practice (Tomita's MCQ / MCS family) rest on this idea: try candidates in color order and prune with the color bound.

Other Problems Solved by Branch and Bound

Hamiltonian pathA path visiting every vertex exactly once; the weighted version is solved with bounds much like TSP's.
Satisfiability (SAT)Assign truth values to variables; prune conflicting partial assignments (DPLL). For MAX-SAT the bound is the most clauses that can still be satisfied.
SchedulingMinimize makespan or tardiness; bound: the best-case load of the remaining jobs.
Bin packingPack items into as few bins as possible; lower bound ⌈Σ size / bin capacity⌉.
Maximum coverageChoose k sets covering the most elements; bound: the elements the largest remaining sets could add.
Assignment problemAssign n jobs to n people at minimum cost; lower bound: the minimum cost of each unassigned row.

Problems with polynomial-time algorithms, such as maximum flow, do not need branch and bound; the method makes sense for NP-hard problems.

Common Mistakes

Invalid (pessimistic) boundIn knapsack, summing only the items that fit whole is not an upper bound; the branch containing the optimum may be pruned.
Mixing up the directionPrune when bound ≤ best for maximization and lb ≥ best for minimization. Writing the reverse either misses the optimum or prunes nothing.
Not re-testing after removalThe node was promising when it was added; if best grew while it waited, it is now useless (C and G in the example).
Not sorting the itemsThe fractional bound is not a valid upper bound unless items are in decreasing order of pᵢ/wᵢ.
Updating best only at leavesIn knapsack every feasible node is a solution; updating early gives more pruning.
Confusing it with backtrackingCode without a bound test (e.g. a TSP search with no pruning) is not branch and bound; it just walks the whole tree.
