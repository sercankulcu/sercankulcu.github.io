The Greedy Approach

Winning Step by Step

  • Greedy algorithms proceed by choosing, at each step, the option that looks best right now.
  • Like a treasure hunter: at every stage, take the option with the largest immediate gain.
  • It works in stages: instead of looking at the problem as a whole, it focuses on the best option at hand.
  • A decision is never undone; there is no backtracking.
  • Like planning a trip by taking the road that looks shortest at every junction.
Gain and risk

Fast and simple; the code is usually short and clear.

However, it does not guarantee an optimal solution; in many cases it yields a good approximate one.

The Greedy Approach

The Greedy Paradigm: General Template

Solution greedy(Candidate[] candidates) {
  Solution s = new Solution(); // empty
  sort(candidates);        // by criterion
  for (Candidate a : candidates) {
    if (s.isFeasible(a))   // constraints hold
      s.add(a);            // never undone
  }
  return s;
}
  1. Define the set of feasible solutions (which choices keep the constraints satisfied?).
  2. Pick a greedy criterion: cheapest, earliest finishing, most profitable, most frequent…
  3. Choose the locally best candidate by the criterion; add it to the solution if feasible.
  4. Repeat until the solution is complete.
The cost of most greedy algorithms comes from sorting or priority queue operations: typically O(n log n).

The Greedy Approach

When Is Greedy Correct?

Greedy-choice property

There is at least one optimal solution that contains the locally best choice. The first greedy choice never leads us "down the wrong path".

Optimal substructure

Once a choice is made, an optimal solution of the remaining subproblem, together with that choice, gives an optimal solution of the whole problem.

Proof technique: the exchange argument

Take any optimal solution O. If O does not contain the greedy choice, exchange one of its elements for the greedy choice; the solution stays feasible and does not get worse. So an optimal solution containing the greedy choice exists; induction extends this to every step.

If neither property holds, the greedy algorithm is only a heuristic: fast, but its result may be worse than optimal.

The Greedy Approach

Advantages and Disadvantages

Advantages

  • Easy to understand and implement; short code.
  • Fast: usually a sort plus one pass, O(n log n).
  • Little memory: only the current solution is kept.
  • Optimal on the right problems (MST, Huffman, activity selection).
  • On hard problems it gives a good approximation or a starting point.

Disadvantages

  • No guarantee of optimality (making change with {1, 3, 4}, 0/1 knapsack).
  • Correctness must be proved separately for each problem.
  • The criterion is critical: the wrong one gives the wrong result.
  • Decisions are never undone; there is no chance to fix a mistake.

The Greedy Approach

The Change-Making Problem (Coin Change)

Pay a given amount with the fewest coins.

Greedy criterion: take the largest coin not exceeding the remaining amount; repeat until the amount is zero.

// coins[] sorted in decreasing order
static int makeChange(int[] coins, int amount) {
  int count = 0;
  for (int p : coins) {
    while (amount >= p) {
      amount -= p;
      count++;
    }
  }
  return count;
}
Is it always correct?

Yes for canonical coin systems such as {50, 25, 10, 5, 1}: 68 = 50 + 10 + 5 + 1 + 1 + 1.

With {4, 3, 1}, greedy pays 6 as 4 + 1 + 1 (3 coins); the optimum is 3 + 3 (2 coins). In general, dynamic programming is needed.

Time: O(k + count), where k is the number of coin types.

p = 4: 10 ≥ 4 → this coin can be used.

amount −= 4 → 6, count = 1. The loop continues.

amount −= 4 → 2, count = 2. 2 < 4: the while loop ends.

p = 3: 2 < 3 → the 3-coin is never used; move on to the next coin.

p = 1: 2 ≥ 1 → this coin can be used.

amount −= 1 → 1, count = 3. The loop continues.

amount −= 1 → 0, count = 4. 0 < 1: the while loop ends.

Greedy returns 4 coins (4 + 4 + 1 + 1), yet 3 coins (4 + 3 + 3) suffice (found by DP). Taking two 4-coins first blocked the use of the 3-coins.

The Greedy Approach · Step by step

Making Change: Step by Step

Example 1: coins {50, 25, 10, 5, 1}, amount 68. Start with the largest coin.

The largest coin that fits is 50 → 68 − 50 = 18 left.

The largest coin that fits is 10 → 18 − 10 = 8 left.

The largest coin that fits is 5 → 8 − 5 = 3 left.

The largest coin that fits is 1 → 3 − 1 = 2 left.

The largest coin that fits is 1 → 2 − 1 = 1 left.

The largest coin that fits is 1 → 1 − 1 = 0 left. 6 coins in total — optimal for this coin system.

Example 2: coins {4, 3, 1}, amount 6. Start with the largest coin.

The largest coin that fits is 4 → 6 − 4 = 2 left.

The largest coin that fits is 1 → 2 − 1 = 1 left.

The largest coin that fits is 1 → 1 − 1 = 0 left.

Greedy gave 4 + 1 + 1 = 3 coins, yet 3 + 3 = 2 coins suffice. The locally best choice (4) missed the global optimum.

Activity Selection

Activity Selection

  • Each activity has a start time si and a finish time fi; only one activity can run at a time (one hall).
  • Goal: select the maximum number of mutually compatible activities. [si, fi) and [sj, fj) are compatible ⇔ sj ≥ fi or si ≥ fj.
  • Greedy criterion: select the activity that finishes earliest, discard those that overlap it, and repeat with the rest.

static void select(Activity[] e) {
  Arrays.sort(e, (x, y) -> x.finish - y.finish);
  int i = 0;                 // last selected
  System.out.print(e[i].id + " ");
  for (int j = 1; j < e.length; j++) {
    if (e[j].start >= e[i].finish) {
      System.out.print(e[j].id + " ");
      i = j;
    }
  }
}

Activity Selection

Why Earliest Finish?

Other natural criteria do not guarantee an optimal result (orange: greedy's choice, green: optimal solution):

The "fewest overlaps" criterion has a counterexample too.

Exchange argument

Let a1 be the earliest-finishing activity and O an optimal solution. If the first activity of O is b ≠ a1, replace b with a1: since f(a1) ≤ f(b), it overlaps no other activity of O, and the count stays the same.

So some optimal solution contains a1. After discarding the activities that overlap a1, the remaining problem has the same structure (optimal substructure).

Job Sequencing

Job Sequencing with Deadlines

  • Each job takes 1 unit of time and has a deadline and a profit.
  • The profit is earned only if the job finishes by its deadline; one job runs at a time.
  • Goal: maximize the total profit.
  • Greedy criterion: take the jobs in decreasing order of profit; put each in the latest free slot at or before its deadline; if no slot is free, skip the job.
  • Choosing the latest slot leaves the early slots for jobs with closer deadlines.

Time: sorting O(n log n) + slot search O(n · dmax) → worst case O(n²). With Union-Find, the slot search drops to nearly O(n).

Sorting jobs by deadline is wrong: for (profit 10, deadline 1) and (profit 40, deadline 1), deadline order earns 10, profit order earns 40. Decreasing profit order is optimal: the feasible job sets form a matroid.

static int jobSequencing(Job[] jobs, int n) {
  Arrays.sort(jobs, (a, b) -> b.profit - a.profit);
  int[] slot = new int[n];
  Arrays.fill(slot, -1);
  int total = 0;
  for (int i = 0; i < n; i++) {
    int j = Math.min(n, jobs[i].deadline) - 1;
    for (; j >= 0; j--) {
      if (slot[j] == -1) {
        slot[j] = jobs[i].id;
        total += jobs[i].profit;
        break;
      }
    }
  }
  return total;
}

Knapsack

Fractional Knapsack

Capacity W = 50. If items can be split, the greedy criterion is: take the one with the largest profit/weight ratio.

Itemprofitweightratio
160106
2100205
3120304

Fractional: items 1 + 2 in full, 20/30 of item 3 → 60 + 100 + 80 = 240 (optimal). Time O(n log n).

Why optimal?

Each unit of the highest-ratio item earns at least as much as any other option of the same weight. If an optimal solution does not take as much of this item as it can, swap in an equal weight of it for another item; the profit does not drop (exchange argument).

If items cannot be split (0/1 knapsack), the ratio criterion does not guarantee the optimum; that problem is solved with dynamic programming.

Knapsack · Run the code step by step

fractional(s, 50): Code Trace

Items sorted by decreasing profit/weight ratio: 1 (6), 2 (5), 3 (4). The knapsack is empty; remaining capacity 50.

Item 1: weight 10 ≤ cap 50 → fits entirely.

cap −= 10 → 40, profit += 60 → 60.

Item 2: weight 20 ≤ cap 40 → fits entirely.

cap −= 20 → 20, profit += 100 → 160.

Item 3: weight 30 > cap 20 → does not fit entirely, else branch.

For the remaining 20 units, 20/30 of item 3: 120 · 20/30 = 80 → profit = 240. The knapsack is full, break.

Result 240: optimal for the fractional problem. The cost comes from sorting: O(n log n); the scan is O(n).

static double fractional(Item[] s, int W) {
  Arrays.sort(s, (a, b) -> Double.compare(b.ratio(), a.ratio()));
  double profit = 0;
  int cap = W;
  for (Item x : s) {
    if (x.weight <= cap) {           // fits entirely
      cap -= x.weight;
      profit += x.profit;
    } else {                         // fractional part
      profit += x.profit * (double) cap / x.weight;
      break;
    }
  }
  return profit;
}

Minimum Spanning Tree

Minimum Spanning Trees and the Cut Property

  • Minimum spanning tree (MST): a tree connecting all vertices of a connected, weighted, undirected graph with the minimum total weight; V − 1 edges.
  • Cut property: if the vertices are split into S and V − S, the lightest edge crossing this cut belongs to an MST.
  • Kruskal, Prim, and Borůvka are greedy algorithms that use this property with different cuts: every edge added is the lightest edge crossing some cut, so no choice is ever undone.
  • If the weights are distinct, the MST is unique.

Edges crossing the cut: 9, 4, 8, 11. The lightest, r–s (4), is in the MST.

Huffman Coding

Huffman Coding

  • A lossless data compression method (David Huffman, 1952).
  • Uses variable-length codes: frequent characters get short codes, rare ones get long codes.
  • Produces prefix-free codes: no code is a prefix of another → decodes unambiguously without separators.
  • Greedy step: merge the two lowest-frequency trees.
Why prefix-free?

Let a = 0, b = 01, c = 1. Is "01" "ab" or "b"? Ambiguous: 0 is a prefix of 01.

Huffman codes sit at the leaves of a binary tree, so no code can be a prefix of another.

Used in: the entropy-coding stage of ZIP/DEFLATE, gzip, PNG, JPEG, and MP3.

Huffman Coding

Huffman Coding: Steps

  1. Step 1: Count the frequency of each character.
  2. Step 2: Build a Huffman tree from the frequencies: each character is a leaf; repeatedly merge the two lowest-frequency nodes into a new internal node.
  3. Step 3: Read each character's code from the tree: left edge 0, right edge 1.
  4. Step 4: Encode the data with these Huffman codes.

Building the Huffman Tree: Code Trace

New internal node 5 = 2 + 3 with children F2 and O3, added back to the queue.

New internal node 8 = 4 + 4 with children G4 and R4, added back to the queue.

poll() twice: the smallest frequencies are (5) (left) and E5 (right). (5) and E5 tie; which comes out first depends on the heap, and the code lengths do not change.

New internal node 10 = 5 + 5 with children (5) and E5, added back to the queue.

poll() twice: the smallest frequencies are T7 (left) and (8) (right).

New internal node 15 = 7 + 8 with children T7 and (8), added back to the queue.

poll() twice: the smallest frequencies are (10) (left) and (15) (right).

New internal node 25 = 10 + 15 with children (10) and (15), added back to the queue. One node is left in the queue: the root.

The loop ends and the root (25) is returned. Left edge 0, right edge 1: F=000, O=001, E=01, T=10, G=110, R=111.

static Node huffman(char[] ch, int[] f) {
  PriorityQueue<Node> pq =
    new PriorityQueue<>((a, b) -> a.f - b.f);
  for (int k = 0; k < ch.length; k++)
    pq.add(new Node(ch[k], f[k]));
  while (pq.size() > 1) {
    Node left = pq.poll();
    Node right = pq.poll();
    Node parent = new Node('\0', left.f + right.f);
    parent.left = left;
    parent.right = right;
    pq.add(parent);
  }
  return pq.poll();
}

  • Fixed length: 6 characters → 3 bits, 25 × 3 = 75 bits. Huffman: 63 bits (16% savings, 2.52 bits on average).
  • Encoding: "FORTE" → 000 001 111 10 01 = 13 bits (15 with a fixed code).
  • Decoding: start at the root, 0 → left, 1 → right; at a leaf, output the character and return to the root: 1100110 → 110 | 01 | 10 → "GET".
  • Which child goes left or right is arbitrary (e.g., T could be the right child): the codes change, but the code lengths and the 63 bits do not.

Generating Codes from the Tree: Code Trace

static void genCodes(Node d, String code) {
  if (d.left == null) {     // leaf
    System.out.println(d.ch + " = " + code);
    return;
  }
  genCodes(d.left, code + "0"); // left: 0
  genCodes(d.right, code + "1"); // right: 1
}

Internal node (10), code = "0" (reached via a left edge) → not a leaf; descend left with "00".

Internal node (5), code = "00" (reached via a left edge) → not a leaf; descend left with "000".

Huffman Coding

Why Is Huffman Optimal?

Greedy choice

There is an optimal code tree in which the two lowest-frequency characters x and y are siblings at the deepest level: swapping with a deeper character does not increase the total bits (exchange argument).

Optimal substructure

Merge x and y into a single character "z" with frequency f(x) + f(y); expanding z in an optimal tree of the smaller problem gives an optimal tree of the original problem.

Cost

Total bits = Σ freq(c) · depth(c). Among prefix-free codes, Huffman makes this minimal.

Complexity

Counting frequencies O(m) (m = text length); tree O(n log n); encoding O(m). The tree (or the code table) must also be sent to the decoder.

Applications

Other Greedy Algorithms

Dijkstra and PrimAt each step, permanently select the vertex with the smallest distance / connection cost. Dijkstra finds shortest paths in graphs without negative edges; Prim finds an MST for any weights.
Graph coloringColor the vertices in order, each with the smallest color its neighbors do not use. Fast, but the number of colors may not be minimal (NP-hard).
Bin packingFirst fit: put each item in the first bin it fits (best fit: the bin that leaves the least space). First fit decreasing uses at most ≈ 11/9 · OPT + 1 bins.
Maximum coverageAt each step, pick the set that covers the most new elements: guarantees at least (1 − 1/e) ≈ 63% of the optimum.
For NP-hard problems, greedy algorithms are valuable as approximation algorithms with proven ratios.

Common Mistakes

Assuming greedy is correct without proof6 with coins {1, 3, 4}: greedy uses 3 coins, the optimum 2. The greedy-choice property must be shown for each problem.
The wrong criterionIn activity selection, the earliest start or the shortest activity is wrong; the right criterion is the earliest finish.
Ratio in the 0/1 knapsackThe ratio criterion, optimal for the fractional problem, does not guarantee the optimum for indivisible items.
Earliest free slotIn job sequencing, placing a job in the earliest free slot at or before its deadline leaves no room for jobs with tight deadlines; choose the latest free slot.
Misreading the cut propertyThe safe edge is the lightest edge crossing a cut. Taking the lightest edges of the whole graph in order can create a cycle; that is why Kruskal discards edges that form one.
Decoding Huffman without the treeWithout the code table or the tree, the data cannot be decoded. For a one-character text the root is a leaf: its code still needs at least 1 bit.

Sample Problems

  1. How many coins does greedy use to pay 63 with {1, 5, 10, 25}? What are the greedy and optimal results for 14 with {1, 7, 10}?
  2. Activities (s, f): (1,4), (3,5), (0,6), (5,7), (3,9), (5,9), (6,10), (8,11), (8,12), (2,14), (12,16). What is the maximum number of activities that can be selected?
  3. Frequencies a:5, b:9, c:12, d:13, e:16, f:45. Find the Huffman code lengths and the total bits.
  4. The vertices are split into {A, B} and {C, D}; the edges crossing the cut are A–C 5, B–C 3, B–D 4. Which edge is in every MST?
  5. Can Kruskal, Prim, and Borůvka find different spanning trees on the same graph?
Show answers
  1. 63 = 25 + 25 + 10 + 1 + 1 + 1 → 6 coins. 14: greedy 10 + 1 + 1 + 1 + 1 = 5 coins; optimal 7 + 7 = 2 coins.
  2. Sort by finish time and take the earliest finishing: (1,4), (5,7), (8,11), (12,16) → 4 activities.
