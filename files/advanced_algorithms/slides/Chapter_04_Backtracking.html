Introduction

Hard Problems: P, NP and NP-Hard

PDecision problems solvable in polynomial time (e.g. “a path of length ≤ k?”, “a spanning tree of weight ≤ k?”).
NPDecision problems whose proposed solutions can be verified in polynomial time.
NP-hardEvery problem in NP reduces to it in polynomial time; it is at least as hard as the hardest problem in NP.
NP-completeBoth in NP and NP-hard. Examples: SAT, 3-SAT, Hamiltonian path and cycle, graph 3-coloring.
  • Hamiltonian path, graph coloring, SAT and subset sum (as decision problems) are NP-complete; optimization TSP and knapsack are NP-hard.
  • If P ≠ NP, none has a polynomial-time exact algorithm. Exact methods are exponential in the worst case, so we shrink the search by pruning (backtracking, branch and bound) or settle for an approximate solution.

Core Idea

Go Back and Try Again

  • Some problems can only be solved by trying different paths and backing out of wrong ones.
  • Backtracking applies this strategy systematically to hard problems.
  • The solution is built step by step as a partial solution; if a step violates a constraint, that branch is abandoned.
  • Unlike brute force, which blindly generates every possibility, it never extends an invalid partial solution.

Path found (orange) and dead ends tried and abandoned (✗)

Core Idea

A Traveler in a Maze

  • Backtracking is like a person walking through a maze.
  • At every junction the person makes a decision and moves on.
  • If the chosen path does not lead to the exit, they go back and try another.
  • Each step is a decision, and we check whether it was right.
  • This trial and error continues until the problem is solved (or every option is exhausted).
  • Uses: puzzles and AI games such as mazes, Sudoku and chess.
Key point: To go back, you must remember where you came from. Recursion gives this for free: the call stack is the list of junctions.

Core Idea

State-Space Tree

Partial solutionThe path from the root to a node: the choices made so far.
CandidateThe choices available at the next level: the node's children.
ConstraintIf the partial solution is invalid, the node's subtree is pruned.
Goal testHave we reached a complete, valid solution? (a leaf)

Core Idea

General Template: Choose → Explore → Undo

void backtrack(State partial) {
  if (isSolution(partial)) {
    record(partial);
    return;
  }
  for (Candidate c : candidates(partial)) {
    if (isValid(partial, c)) {
      add(partial, c);      // choose
      backtrack(partial);   // explore
      remove(partial, c);   // undo
    }
  }
}
  1. Goal test: if the partial solution is complete, record it (or stop).
  2. Choose: add the next candidate to the partial solution.
  3. Explore: recurse one level deeper.
  4. Undo: remove the candidate; the state returns to what it was before the call, and the next candidate is tried.
Pruning happens inside isValid: for an invalid candidate the recursive call is never made, so the whole subtree below it is skipped. If one solution is enough, backtrack returns a boolean and stops at the first true.

The Template in Action: Permutations of 1, 2, 3

void permute(int[] p, boolean[] used, int k) {
  if (k == p.length) {               // solution
    System.out.println(Arrays.toString(p));
    return;
  }
  for (int a = 1; a <= p.length; a++) {
    if (!used[a]) {                  // valid
      p[k] = a; used[a] = true;      // choose
      permute(p, used, k + 1);         // explore
      used[a] = false;               // undo
    }
  }
}

p[0..2] is empty and no number is used (k = 0). Candidates 1, 2, 3 are tried in order: a = 1 is chosen, used[1] = true, and we go one level deeper.

k = 1: a = 2 is unused → chosen, used[2] = true.

k = 2: only 3 is unused → chosen. k = 3 = p.length: solution, [1, 2, 3] is printed.

Undo: used[3] = false, used[2] = false. k = 1: a = 3 is unused → chosen, used[3] = true.

k = 2: only 2 is unused → chosen. k = 3 = p.length: solution, [1, 3, 2] is printed.

Undo: used[2] = false, used[3] = false, used[1] = false. k = 0: a = 2 is unused → chosen, used[2] = true.

k = 1: a = 1 is unused → chosen, used[1] = true.

k = 2: only 3 is unused → chosen. k = 3 = p.length: solution, [2, 1, 3] is printed.

Undo: used[3] = false, used[1] = false. k = 1: a = 3 is unused → chosen, used[3] = true.

k = 2: only 1 is unused → chosen. k = 3 = p.length: solution, [2, 3, 1] is printed.

After undoing, the branch starting with 3 is explored the same way: [3, 1, 2] and [3, 2, 1]. 3! = 6 permutations, 15 choose / 15 undo steps; used[] is restored on every return.

Core Idea

Pros and Cons

Pros

  • A general method that applies to a wide range of problems.
  • Often efficient for problems whose solutions can be expressed as a tree.
  • Easy to understand and implement: short, recursive code.
  • Finds all solutions, or proves there are none (exhaustive search).

Cons

  • Worst-case time is exponential (2ⁿ, n!, 9ᵐ …).
  • Slow when the number of candidate solutions is huge; needs good pruning and heuristics.
  • Deep recursion uses stack memory: O(depth).
  • The same subproblem may be solved again and again along different paths (nothing is stored, unlike DP).

n-Queens Problem

The Eight Queens Problem

  • Place 8 queens on an 8×8 chessboard.
  • Goal: a placement in which no queen attacks another. A queen attacks pieces on the same row, column and diagonal.
  • General form: n queens on an n×n board (N-Queens). A solution exists for every n ≥ 1 except n = 2 and n = 3.
  • 8 queens has 92 solutions (12 fundamental ones up to symmetry).
  • Backtracking is the standard way to solve problems like this.

One solution: a1, b7, c4, d6, e8, f2, g5, h3

n-Queens Problem

Backtracking Solution: Steps

  1. Every square of the board starts empty.
  2. The first queen goes into some column of the first row.
  3. Check whether the new queen conflicts with earlier queens (column and both diagonals).
  4. If there is no conflict, the position is valid; the next queen goes into the next row.
  5. If every column of a row has been tried and none is safe, the previous queen is moved (backtrack).
  6. Once all 8 queens are placed, a solution has been found.
Why row by row? Every row must hold exactly one queen. This observation builds the row constraint into the structure: only column and diagonal checks remain, and the search space drops from 64⁸ to 8⁸.

n-Queens Problem

n-Queens: Java Code

boolean isSafe(int[][] b,
        int r, int c) {
  // same column
  for (int i = 0; i < r; i++)
    if (b[i][c] == 1) return false;
  // upper-left diagonal
  for (int i = r-1, j = c-1;
       i >= 0 && j >= 0; i--, j--)
    if (b[i][j] == 1) return false;
  // upper-right diagonal
  for (int i = r-1, j = c+1;
       i >= 0 && j < n; i--, j++)
    if (b[i][j] == 1) return false;
  return true;
}
boolean solve(int[][] b, int row) {
  if (row == n)
    return true;
  for (int col = 0; col < n;
       col++) {
    if (isSafe(b, row, col)) {
      b[row][col] = 1; // place
      if (solve(b, row + 1))
        return true;
      b[row][col] = 0; // undo
    }
  }
  return false;
}
  • b[i][j] == 1: a queen at (i, j); n is a field of the class. Queens exist only in the rows above, so isSafe looks in three directions: up, upper-left and upper-right.
  • solve proceeds row by row; at the first solution it returns true, which propagates up the stack. solve visits O(n!) nodes; each node calls the O(n) isSafe n times → a rough bound of O(n² · n!).

n-Queens Problem

A Faster Safety Test: O(1)

boolean[] cols = new boolean[n];
boolean[] d1 = new boolean[2*n-1]; // r+c
boolean[] d2 = new boolean[2*n-1]; // r-c+n-1

void solve(int r) {
  if (r == n) { count++; return; }
  for (int c = 0; c < n; c++) {
    int a = r + c, b = r - c + n - 1;
    if (cols[c] || d1[a] || d2[b])
      continue;
    cols[c] = d1[a] = d2[b] = true;
    solve(r + 1);
    cols[c] = d1[a] = d2[b] = false;
  }
}
  • Cells on the same anti-diagonal have a constant r + c (0 … 2n − 2).
  • Cells on the same diagonal have a constant r − c; adding n − 1 makes the index start at 0.
Each queen sets three flags: column, anti-diagonal, diagonal. isSafe becomes O(1) instead of O(n), and the board array is no longer needed (just pos[row] = col).

Min-Conflicts

Min-Conflicts Heuristic

  • A different idea: first place all the queens (one per column), then repair conflicts with local changes.
  • The number in each cell: how many queens a queen moved to that row would conflict with (row + diagonals).
  • Start: column by column, pick the row with the fewest conflicts (ties broken at random).
  • Repair: pick a conflicted queen and move it, within its column, to the row with the fewest conflicts. Stop when no conflicts remain.
  • This is a local search method: the state is a complete but possibly invalid placement, and there is no backtracking stack. It is not complete: it can wander on a plateau, needs a step limit, finds only one solution and cannot prove that none exists. On the other hand, even for n = 1,000,000 it solves the problem in a few dozen steps on average.
minConflicts(n, maxSteps):
  // start: greedy placement
  for k = 0 .. n-1:
    pos[k] = row with fewest conflicts
  for step = 1 .. maxSteps:
    if no conflicts: return pos
    k = random conflicted column
    pos[k] = argmin_r conflicts(k, r)
             // ties broken at random
  return failure

Min-Conflicts

Min-Conflicts: Repair Steps

Greedy start [7, 2, 4, 1, 4, 0, 3, 6]: only columns 2 and 4 (row 4) conflict. Column 4 is chosen; the minimum is 1 (row 7) → the queen moves to row 7.

The move created a new conflict: columns 0 and 4 are now in the same row (7). Column 0's options: minimum 1 (rows 0, 5). Conflicting pairs in total: 1.

A few repair steps later: the queen in column 5 is in row 3, conflicting with column 2. The minimum is 1 (rows 4, 5) → row 4.

In row 4 there is now a diagonal conflict with (6, 7) (1). Rows 3, 4, 5 all have 1 conflict: a plateau. A random choice moves it to row 5.

In row 5 it shares a row with column 1. Column 5 goes back and forth on the plateau 3 ↔ 4 ↔ 5 a few times; thanks to random choice, another queen is eventually picked.

Column 1 is chosen (row 5, 1 conflict). The minimum is 1 (row 7) → row 7.

Now columns 1 and 4 conflict in row 7. Column 4's minimum is 1 (rows 0, 2) → row 2.

Columns 0 and 4 conflict in row 2. In column 0, row 4 has 0 conflicts → the queen moves there.

No conflicted queens remain: solution [4, 7, 3, 0, 2, 5, 1, 6]. The algorithm placed all 8 queens up front, then removed the conflicts using only local changes.

Sudoku

Sudoku

  • The goal of Sudoku is to use the digits 1 to 9 exactly once in every row, every column and every 3×3 box of a 9×9 grid.
  • Some cells are given up front (clues); the rest must be filled in.
  • It is a constraint satisfaction problem: the variables are the empty cells, the domain is {1, …, 9}, and the constraints say "all different within a unit".

Sudoku

Sudoku: Backtracking Algorithm

  1. Assign a digit to an empty cell.
  2. If the digit is valid (not in its row, column or box), move on to the next empty cell.
  3. If not, try the next digit.
  4. If every digit has been tried in a cell, go back to the previous cell (backtrack) and try a different digit there.
  5. Repeat until every cell is filled.
This is the general template applied directly: partial solution = filled cells, candidate = 1–9, constraint = isValid, goal = no empty cells left.

Sudoku

Sudoku: Java Code

boolean solve(int[][] g) {
  for (int r = 0; r < 9; r++)
    for (int c = 0; c < 9; c++)
      if (g[r][c] == 0) {
        for (int d = 1; d <= 9; d++)
          if (isValid(g, r, c, d)) {
            g[r][c] = d;
            if (solve(g)) return true;
            g[r][c] = 0;   // undo
          }
        return false;  // no digit fits
      }
  return true;  // no empty cell
}
boolean isValid(int[][] g,
    int r, int c, int d) {
  for (int i = 0; i < 9; i++)
    if (g[r][i] == d || g[i][c] == d)
      return false;
  int br = r / 3 * 3;
  int bc = c / 3 * 3;
  for (int i = br; i < br + 3; i++)
    for (int j = bc; j < bc + 3; j++)
      if (g[i][j] == d)
        return false;
  return true;
}

Each call to solve scans from the start for the first empty cell (O(81)); if no digit fits a cell, return false triggers the backtrack.

Graph Coloring (m-Coloring)

A six-vertex graph, m = 3 colors (1 blue, 2 green, 3 orange). Vertices are colored in the order 0, 1, 2, …; at each vertex colors 1, 2, 3 are tried in order.

Vertex 4: colors 1, 2, 3 are all on its neighbors → dead end, return false. Back up: colors[3] = 0; the next color for vertex 3 will be tried.

Vertex 3: no colors left to try → dead end. Back up: colors[2] = 0 (color 1 is erased).

Vertex 2: color 2 (green) fits → assigned.

Colors 1, 2 are on neighbors; vertex 3: color 3 (orange) fits → assigned.

Vertex 4: color 1 (blue) fits → assigned. v = 5 = n: every vertex is colored; the valid 3-coloring [1, 2, 2, 3, 1] has been found.

Other Problems

Hamiltonian Path

A path that visits every vertex exactly once. Partial solution: path[0..pos−1]; constraint: the new vertex is adjacent to the last one and not already on the path.

path[0] = 0; pos = 1. At each position vertices 0, 1, 2, … are tried in order: a vertex can be added if it is adjacent to the previous one and not on the path.

Position 1: vertex 1 fits → path[1] = 1.

Position 2: vertex 3 fits → path[2] = 3.

Position 3: vertex 2 fits → path[3] = 2.

Position 4: the last vertex, 2, has no (untried) neighbor off the path → dead end. Backtrack: path[3] = −1 (vertex 2 is removed).

Position 3: vertex 4 fits → path[3] = 4.

Position 4: the last vertex, 4, has no (untried) neighbor off the path → dead end. Backtrack: path[3] = −1 (vertex 4 is removed).

Position 3: the last vertex, 3, has no (untried) neighbor off the path → dead end. Backtrack: path[2] = −1 (vertex 3 is removed).

Position 2: vertex 4 fits → path[2] = 4.

Position 3: vertex 3 fits → path[3] = 3.

Position 4: vertex 2 fits → path[4] = 2. pos == 5: every vertex is on the path; Hamiltonian path found: 0 → 1 → 4 → 3 → 2.

Hamiltonian Path: Java Code

boolean find(int[][] graph, int[] path, int pos) {
  if (pos == graph.length) return true;
  for (int v = 0; v < graph.length; v++) {
    if (isSafe(v, graph, path, pos)) {
      path[pos] = v;
      if (find(graph, path, pos + 1)) return true;
      path[pos] = -1;      // undo
    }
  }
  return false;
}

boolean isSafe(int v, int[][] graph,
               int[] path, int pos) {
  if (graph[path[pos - 1]][v] == 0) return false;
  for (int i = 0; i < pos; i++)
    if (path[i] == v) return false;
  return true;
}
  • graph: adjacency matrix; start with path[0] = 0 and call find(graph, path, 1).
  • In the example path 0 → 1 → 4 → 3 → 2, the last vertex 2 is also adjacent to the start 0; such a path is also a Hamiltonian cycle.
  • Worst case O(n!) paths; isSafe is O(n) → O(n · n!).

Word Search

Is there a path through adjacent (up/down/left/right) cells of a letter grid that spells the word? Each cell can be used at most once on a path.

The word is "SEE". Every cell is tried as a start (row by row); neighbor directions: up, down, left, right. A cell cannot be used twice on the same path.

(1, 0) = 'S' matches letter 0 of the word → marked as visited.

No neighbor of (1, 0) continues with 'E' → backtrack, the mark is removed.

(1, 3) = 'S' matches letter 0 of the word → marked as visited.

(0, 3) = 'E' matches letter 1 of the word → marked as visited.

No neighbor of (0, 3) continues with 'E' → backtrack, the mark is removed.

(2, 3) = 'E' matches letter 1 of the word → marked as visited.

(2, 2) = 'E' matches letter 2 of the word → marked as visited. The last letter matched too: "SEE" found.

Word Search: Java Code

boolean search(char[][] grid, String word, int i,
            int r, int c, boolean[][] visited) {
  if (i == word.length()) return true;
  if (r < 0 || r >= grid.length || c < 0
      || c >= grid[0].length || visited[r][c]
      || grid[r][c] != word.charAt(i))
    return false;
  visited[r][c] = true;
  for (int d = 0; d < 4; d++)
    if (search(grid, word, i + 1, r + dr[d],
            c + dc[d], visited))
      return true;
  visited[r][c] = false;   // undo
  return false;
}

Analysis

Stronger Pruning: Heuristics

Variable ordering (MRV)Pick the variable with the fewest options left first. In Sudoku it can remove backtracking entirely.
Value orderingTry the least constraining value first (the min-conflicts idea). Solutions are found sooner.
Forward checkingAfter an assignment, remove conflicting values from the neighbors' domains; if a domain becomes empty, backtrack at once.
Fast constraint testColumn/diagonal flags in n-queens, row/column/box bitmasks in Sudoku: the test is O(1).
Symmetry breakingIn n-queens, try the first queen only in the left half and mirror the results: about half the work.
BoundIn optimization, cut a branch if the best possible value of its partial solution is worse than the best known solution: branch and bound.

Analysis

What Sets Backtracking Apart?

ParadigmIdeaDifference from backtracking
Divide and conquerSplit into independent subproblems, combineNo choosing or trying; each subproblem is solved exactly once
GreedyLocally best choice at each step; never goes backFollows a single branch; a wrong choice cannot be fixed
Dynamic programmingSolve overlapping subproblems once and store themAll options are tried but results are stored; subproblems must be polynomially many
BacktrackingExtend the partial solution, undo if invalidChoices are tried and undone; constraint satisfaction, all solutions, decision problems
Backtracking is depth-first search (DFS) on the state-space tree; the tree is not built in advance but generated during the walk, and invalid branches are never generated.

Common Mistakes

Forgetting to undoIf g[r][c] = 0 or visited = false is skipped after the recursive call returns, the old choice corrupts later branches.
Not propagating the resultWriting just solve(...) instead of if (solve(...)) return true;: the search continues even after a solution and the board is undone.
Early return falseLeaving the loop at the first invalid candidate; the remaining candidates are never tried.
Recording a shared listWhen collecting all solutions, add a copy (new ArrayList<>(path)) instead of results.add(path).
Missing constraint checksForgetting one diagonal in n-queens or the 3×3 box in Sudoku: invalid "solutions".
Treating local search as completeMin-conflicts cannot prove that no solution exists; hitting the step limit does not mean "no solution".
