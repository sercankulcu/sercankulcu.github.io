Chapter 5: Branch and Bound

In many optimization problems the number of possible solutions grows exponentially or factorially with the input. Trying every candidate one by one becomes impossible even with a few dozen items. Branch and bound shortens this search intelligently. Solutions are built step by step on a tree. For each branch, an estimate is made in advance of how good that branch can possibly be. If the estimate cannot beat the best solution found so far, the branch is never entered. These notes first present the concepts of the method, its general scheme, how the bound is chosen, and the three search strategies. They then apply the method step by step to five problems: the 0/1 knapsack, the traveling salesman, assignment, integer linear programming, and maximum clique. In each application we show why the bound is valid, explain the code line by line, and run it with a trace table. The notes end with a comparison of design paradigms.

5.1The idea of branch and bound

Solving a complex problem is sometimes like finding the right direction at a fork in the road. At each fork there are several options, and each option leads to new forks. The goal is to find the path that finally reaches the best point. Walking every path to its end gives a sure result but takes far too long. Branch and bound proposes a middle way: at each fork, we estimate where we could get to in the best case in that direction. If the estimate is worse than the best result in hand, we never go that way.

5.1.1Combinatorial optimization and the limits of brute force

The targets of branch and bound are combinatorial optimization problems. In these problems a solution is built from a finite number of discrete choices: which items to take, in what order to visit the cities, which person gets which job. The number of possible solutions is finite but very large. What we look for is the solution that maximizes or minimizes an objective function. The method aims at an exact, that is, optimal solution; it is not content with an approximate one.

The simplest solution to such problems is brute force: all candidates are generated, each is evaluated, and the best is chosen. The trouble is the growth rate of the number of candidates. In a knapsack problem with n items, each item is either taken or not; there are 2n subsets. In a traveling salesman problem with n cities, once the starting city is fixed, every ordering of the remaining cities is a separate tour; there are (n − 1)! tours. Most of these problems are NP-hard: no known algorithm can solve them in polynomial time in the worst case. Branch and bound does not change the worst case either. What it changes is the number of candidates examined in practice.

The basic idea of the method can be stated in one sentence: how good a branch can possibly be is estimated in advance, and if the estimate is not good enough, that branch is never entered. If this estimate is built correctly, the optimal solution is never lost, but most candidates are eliminated without ever being generated.

5.1.2Branching, bounding, pruning

Definition 5.1

Branch and bound is an algorithm design method that splits the solution space of an optimization problem into subproblems in the form of a tree. For each subproblem, the best value that can be reached is estimated. Subproblems whose estimate is no better than the best solution found so far are eliminated without being examined.

The name of the method comes from its two basic operations. It can be summarized in four steps:

  1. Branching: The problem is split into smaller subproblems. In the knapsack, the question “should item 1 be taken?” produces two subproblems: the cases in which item 1 is taken and in which it is not.
  2. Bounding: For each subproblem, the best value that can be reached is estimated. This estimate is called the bound.
  3. Pruning: Subproblems whose bound is no better than the best solution found so far are eliminated. No solution below an eliminated subproblem is generated.
  4. Repeat: The process continues for all the remaining subproblems. As unnecessary branches are pruned, the search gets shorter.

Figure 5.1 shows the method on a tree. We start at the root and descend by making a decision at each node. The node at the upper right has been pruned. The seven nodes below it are drawn faintly, because the algorithm never generates them. This saving grows exponentially as the depth of the tree increases. A node pruned just below the root eliminates almost half of the tree in one stroke.

The method is used in a wide range of areas. The traveling salesman, knapsack, scheduling, bin packing, and integer programming are among the first. In industry, branch and bound is also at the core of commercial optimization software that solves problems such as production planning, airline crew assignment, and logistics routing.

5.1.3Basic concepts

Branch and bound algorithms work on a tree, and the nodes of this tree can be in various states. Putting the names of the concepts down at the start makes the later traces easier to read.

Definition 5.2

The state-space tree is a tree that shows all the partial and complete solutions of a problem. The root is the state in which no decision has been made. Each level of the tree corresponds to a decision; for example, at level i the question “should item i be taken?” is answered. The leaves are the complete solutions, in which all the decisions have been made.

The state-space tree is not built in full in the program. The algorithm generates nodes as needed and forgets the nodes it has finished with. It is therefore necessary to name the states of the nodes:

  • Branching and the E-node. Generating the children of a node, that is, its subproblems, is called branching. The node whose children are being generated at that moment is called the E-node (expanding node).
  • Bound. An optimistic value that no solution below the node can exceed. In maximization it is an upper bound; in minimization, a lower bound.
  • Live node. A node that has been generated but not yet expanded and still looks promising. All the live nodes wait in a queue-like structure. This structure can be an ordinary queue, a stack, or a priority queue.
  • Dead node. A node that has been expanded, found infeasible, or pruned because its bound is insufficient. A dead node is never considered again.
  • Incumbent. The value of the best complete solution found so far. Pruning decisions are made against this value. As the search proceeds, best only improves: it increases in maximization and decreases in minimization.

A solution is feasible if it satisfies all the constraints of the problem. A node that violates one of the constraints is called an infeasible node. For example, a knapsack whose weight exceeds the capacity is infeasible.

Figure 5.2 shows these types in a single tree. The life cycle of a node is as follows. The node is generated and its bound is computed. If the bound is promising, it enters the queue as a live node; if not, it is pruned at once. When its turn comes it leaves the queue and becomes the E-node. After its children have been generated, it turns into a dead node.

5.2The paradigm

All branch and bound algorithms follow the same skeleton. Three things change from problem to problem: how a node is represented, how the children are generated, and how the bound is computed. This section first gives the skeleton and then discusses the choice of the bound, the pruning rules, and the search strategy.

5.2.1The general scheme

The code below is the branch and bound skeleton for a maximization problem. It is pseudocode close to Java: queue, bound(), isFeasible(), isComplete(), and value() take on a different meaning in each problem.

int best = -∞;
queue.add(root);
while (!queue.isEmpty()) {
  Node u = queue.remove();   // strategy
  if (bound(u) <= best) continue;
  for (Node c : u.children()) {
    if (!isFeasible(c)) continue;
    if (isComplete(c) && value(c) > best)
      best = value(c);      // new incumbent
    if (bound(c) > best)
      queue.add(c);        // live node
  }
}
return best;

The code is a single loop. Each pass of the loop has five steps:

  1. Select: A live node is removed from the queue. Which node comes out is decided by the search strategy: first in (FIFO), last in (LIFO), or the one with the best bound.
  2. Test again: The line if (bound(u) <= best) continue; tests the node once more. The node looked promising when it entered the queue. But while it waited, best may have grown. If its bound is now insufficient, the node is discarded without ever being expanded.
  3. Branch: The for loop generates the children of the node. Infeasible children are eliminated at once by continue.
  4. Update: If a child is a complete solution and its value is greater than best, best is raised. This solution is the new incumbent.
  5. Bound: Only children whose bound can beat best are put in the queue. The others are pruned.

The loop stops when the queue is empty. At that moment best is the value of the optimal solution. The reason for this claim is simple. Every node has either been expanded or pruned. The solutions below pruned nodes cannot beat best, because the bound guarantees it. The solutions below expanded nodes have been examined one by one. So no solution better than best has been skipped.

The code is written for maximization. In minimization the directions are reversed. The bound is a lower bound, best starts at +∞, and a node with lower(c) ≥ best is pruned. The traveling salesman and assignment problems are solved in this form.

The skeleton stores only the value of the solution, not the solution itself. If we also want to know which items were taken or in what order the tour visits the cities, each node carries its own partial solution. A boolean[] array or a bit mask is enough for this. When best is updated, this information is copied as well.

5.2.2How is the bound chosen?

The whole success of branch and bound depends on the bound function. A good bound has four properties. One of them is mandatory; the other three concern efficiency.

Definition 5.3

In a maximization problem, the bound of a node u is valid if it is greater than or equal to the value of every feasible solution in the subtree of u: bound(u) ≥ value(x) for every x. In minimization the condition is reversed: lower(u) ≤ value(x). A valid bound is also called an optimistic bound, because it assumes the branch looks better than it can actually be.

  • It must be valid (optimistic). This property is mandatory. If the bound falls below the true value (in maximization), the branch containing the optimum may be pruned as “not good enough.” The algorithm then returns a wrong result without raising any error.
  • It must be tight. The closer the bound is to the true value, the more branches are pruned. An infinitely large “bound” is valid but prunes nothing; the algorithm degenerates into brute force.
  • It must be cheap to compute. The bound is computed at every node. A very expensive bound can cost more time than the nodes it prunes.
  • It is built by relaxation. The general way to obtain a bound is relaxation. One of the hard constraints of the problem is removed and the easy problem that remains is solved. When a constraint is removed, the set of feasible solutions grows. So the optimal value of the relaxed problem cannot be worse than the optimal value of the original problem; it is a valid bound.

Three examples of relaxation are treated in detail in these notes. In the knapsack, the constraint “items cannot be split” is removed and the fractional knapsack is solved. In integer programming, the constraint “the variables must be integers” is removed and an ordinary linear program is solved. In the traveling salesman problem, the constraint “the chosen edges must form a single tour” is removed and each city is left by its cheapest edge.

There is a trade-off between tightness and cheapness. In minimization, the lower bound is the smallest value that can be obtained in the best scenario. A weak lower bound prunes almost nothing and lengthens the search. A very strong lower bound requires an expensive computation at every node. The choice is made according to the balance between the number of nodes pruned and the work done per node.

Common mistake

Using a pessimistic value as the bound. In the knapsack, adding up the profits of just the items that fit completely seems plausible. But this value is the profit of a feasible solution, that is, a lower bound; it is not an upper bound. Let the items be (20, 2), (30, 5), (35, 7), (12, 3) and the capacity 9. At the root the items that fit completely give 20 + 30 = 50, whereas the optimum is 55 (the first and third items). The moment best is 50, this “bound” cuts the branch of the optimum and the algorithm returns 50.

5.2.3When is a node pruned?

In branch and bound algorithms a node is pruned for three reasons. All three rules answer the same question: could there be a solution better than best below this node?

  1. Infeasibility. If the node violates a constraint, there is no valid solution below it. Examples: the weight has exceeded the capacity, a city has been visited a second time, the linear program has no solution.
  2. Bound. If bound(u) ≤ best in maximization, or lower(u) ≥ best in minimization, the solutions below cannot beat the best. The node is pruned even if it is feasible.
  3. Completeness. If the node is a complete solution (a leaf), or if the solution of the relaxation is already feasible, there is no need to branch. For example, in integer programming, if the solution of the linear program turns out to be integral, there is no better integer solution below that node. Its value is compared with best and the node is closed.

Note the case of equality. A node with bound(u) = best is pruned too. Below it there is at most a solution as good as best, and a solution of that value is already in hand. If not only the value of the best solution but all the best solutions are wanted, nodes are not pruned on equality; that is a separate problem.

Backtracking uses only the first rule and completeness. What sets branch and bound apart from it is the second rule: even if the node is feasible, it is cut if it is “not good enough.” So adding a single bound line to a search written as backtracking turns it into branch and bound.

5.2.4Search strategies

In the general scheme we said “a live node is removed from the queue.” Which live node comes out depends on the type of the queue structure. There are three common strategies (Table 5.2).

Table 5.2: Strategies for selecting live nodes.
StrategyQueue structureHow it traversesPros / cons
FIFO branch and boundqueue (ArrayDeque)level by level, breadth-firstfinds shallow solutions early; the number of live nodes can grow exponentially
LIFO branch and boundstack (or recursion)depth-firstmemory proportional to the depth; an early complete solution raises best quickly
Least cost (LC, best-first)priority queue (PriorityQueue)the node with the most promising bound firstusually expands the fewest nodes; the queue consumes memory, and each operation costs O(log k)

In the FIFO (first in, first out) strategy the live nodes wait in an ordinary queue. The tree is traversed level by level; this is breadth-first search. The children of the root are expanded, then the grandchildren, then their children. Solutions at shallow levels are found early. But before descending to the deep levels, all the shallow nodes accumulate in the queue. In a tree with branching factor 2, level k contains 2k nodes; if pruning is weak, the queue grows exponentially.

In the LIFO (last in, first out) strategy the live nodes wait on a stack, or the search is written directly with recursion. The tree is traversed depth-first. The stack holds only the not-yet-tried siblings of the nodes on the current path. So memory is bounded by the product of the depth and the branching factor. Another benefit is that it reaches a leaf quickly. A complete solution found early gives best a value, and pruning starts in the very first steps.

In the least cost (LC) strategy the live nodes wait in a priority queue. At each step the node with the most promising bound is expanded: in maximization the node with the largest bound, in minimization the one with the smallest. This strategy is also called best-first search. Because the most promising branch is looked at first, a good solution is found early and most of the remaining nodes are pruned. The price is the memory consumption of the priority queue and the O(log k) cost of each insertion and removal, where k is the number of nodes in the queue.

As long as the bound is valid, all three strategies find the same optimal value. The strategy changes only the amount of work, that is, the number of nodes generated and expanded, and the memory. These differences will be seen with numbers in the knapsack example.

5.2.5Least-cost search and cost estimation

In the general form of LC search, each node is assigned an estimated cost:

ĉ(x) = f(x) + ĝ(x)

Here f(x) is the cost already paid from the root to x; for example, the depth of x or the length of the path traveled so far. ĝ(x) is an estimate of the remaining cost from x to a solution. Of the live nodes, the one with the smallest ĉ is expanded.

The two extreme choices give the other strategies. If ĝ = 0, only the cost paid is considered; this is uniform-cost search. If the steps have unit cost, that is, if f is the depth of the node, the shallowest node is always chosen and the search is FIFO, that is, breadth-first. If f = 0, only the estimate of the remaining cost is considered; this is greedy best-first search, which chooses the node that looks closest to the goal. The sum of the two weighs the cost paid and the estimate of what remains together.

A good property of the estimate is that it is never greater than the true remaining cost. Such an estimate is called an admissible heuristic. This property corresponds to the valid bound in branch and bound: the remaining cost is shown as less than it is, that is, the estimate is optimistic.

The classic example is the 8-puzzle. In a 3 × 3 frame there are tiles numbered 1 to 8 and one blank. In one move, a tile adjacent to the blank slides into the blank. The goal is to bring the tiles to the arrangement 1 2 3 / 4 5 6 / 7 8, with the blank in the lower-right corner. In this problem f(x) is the number of moves made so far and ĝ(x) is the number of tiles not in place. Every misplaced tile needs at least one move. So ĝ never overestimates the number of remaining moves.

Figure 5.4 shows the first step of the search. The initial state is 1 2 3 / 4 □ 6 / 7 5 8 (□ is the blank). Only 5 and 8 are out of place; the ĉ value of the root is 0 + 2 = 2. When the root is expanded, four children arise:

  • Blank up: 2 moves down; 1 □ 3 / 4 2 6 / 7 5 8. Misplaced tiles 2, 5, 8: ĉ = 1 + 3 = 4.
  • Blank down: 5 moves up; 1 2 3 / 4 5 6 / 7 □ 8. Only 8 is misplaced: ĉ = 1 + 1 = 2.
  • Blank left: 4 slides right; 1 2 3 / □ 4 6 / 7 5 8. Misplaced tiles 4, 5, 8: ĉ = 4.
  • Blank right: 6 slides left; 1 2 3 / 4 6 □ / 7 5 8. Misplaced tiles 6, 5, 8: ĉ = 4.

The child with the smallest ĉ is “blank down,” and it is the one expanded. Of its children, “blank right” slides the 8 to the left and reaches the goal: ĉ = 2 + 0 = 2. The solution takes 2 moves and only 2 expansions were made. FIFO, by contrast, does not look at the ĉ values. It expands the nodes of the first level in the order they were generated and wastes time on a hopeless branch such as “blank up.” The A* algorithm of path finding is the counterpart of this idea on weighted graphs; the relation is discussed separately at the end of the notes.

5.2.6Comparison with backtracking

Branch and bound and backtracking traverse the same tree and their code is very similar. Both extend partial solutions and cut hopeless branches. They differ in what they look for and what they cut by (Table 5.3).

Table 5.3: Backtracking and branch and bound.
PropertyBacktrackingBranch and bound
Problem typedecision and search: one or all valid solutions (n-queens, Sudoku)optimization: the best solution (largest profit, shortest tour)
Pruning criterionfeasibility: is a constraint violated?feasibility + bound: can it beat best?
Traversalalways depth-first (recursion)depth-first, breadth-first, or best-first
Extra informationonly the partial solutionpartial solution + bound function + best
MemoryO(depth)O(depth) in the depth-first version; the size of the queue in FIFO and LC
Worst caseexponentialstill exponential; far fewer nodes in practice

When solving the n-queens problem, backtracking checks whether one queen attacks another. If there is an attack, it cuts the branch. All solutions or one solution are sought; there is no ordering of “better” among the solutions. Branch and bound is meaningful when there is an ordering among solutions. Even if a branch violates no constraint, it is cut if the best solution that can come out of it is worse than the one in hand.

The code counterpart of this difference is a single line. A search written for the traveling salesman or maximum clique that contains no bound test is really backtracking; it traverses the whole tree. When a single bound line such as if (lowerBound(...) < best) is added, the search turns into branch and bound.

5.2.7Advantages and disadvantages

The strengths of the method are the following:

  • It finds the exact optimal solution of complex optimization problems. Unlike approximate methods, the optimality of the result is proven.
  • It narrows the search space and eliminates unnecessary possibilities. With a good bound, a very small fraction of the tree is traversed.
  • It is a natural framework for problems that require finding the best route or selection.
  • It applies to a wide variety of problems whose solutions can be represented as a tree.
  • It can be stopped early. If the search is cut off midway, a solution (best) and the best bound in the queue are in hand. The difference between the two tells how far the solution in hand can be from the optimum at most. This information is a quality guarantee.

It has weaknesses as well:

  • In the worst case the time is still exponential. In cases with a great many possibilities where the bound does not prune well, the time becomes unacceptably long.
  • In the FIFO and best-first strategies, memory too can grow exponentially.
  • Success depends on a good bound estimate; a weak bound prunes almost nothing.
  • A bound and a branching rule specific to each problem must be designed. The implementation is more complex than backtracking.

5.3The 0/1 knapsack

To see all the parts of the method, the 0/1 knapsack problem is chosen as the first application. The problem is familiar, its state-space tree is binary, and its bound is easy to compute. The same example will be run with three different strategies and the results compared.

5.3.1The problem and its state-space tree

A brief reminder of the problem is enough. There are n items; item i has profit pi and weight wi. The capacity of the knapsack is W. A decision is made for each item: xi ∈ {0, 1}. An item is either taken whole (1) or not taken at all (0); it cannot be split. The goal is to make the decisions so that

Σ pi xi is maximal subject to Σ wi xi ≤ W

These notes do not use the dynamic programming solution of the knapsack. Dynamic programming builds a table that depends on the capacity W and takes O(nW). If W is very large or the weights are not integers, this table cannot be built; branch and bound is not affected by the size of the weights.

For branch and bound, the items are first sorted in decreasing order of profit-to-weight ratio. This order is needed for the bound computation to be valid. The state-space tree is binary. The root is the state in which no decision has been made. At level i the decision for item i is made: the left branch is “item i taken” (1), the right branch “not taken” (0). In a problem with four items the tree has five levels, and the full tree contains 25 − 1 = 31 nodes. Of these, 16 are leaves; each leaf corresponds to a subset.

The example used in these notes is given in Table 5.4. The capacity is W = 16. The items are already in decreasing order of ratio: 20, 6, 5, 2.

5.3.2Upper bound: the fractional knapsack relaxation

The knapsack is a maximization problem; an upper bound is needed for every node. This bound is built by relaxation. When the constraint “items cannot be split” is removed, the problem becomes the fractional knapsack. In the fractional knapsack, any desired fraction of an item can be taken and the same fraction of its profit is obtained. The greedy method solves this problem optimally: the items are taken whole in ratio order as long as they fit; of the first item that does not fit, the fraction that fits is taken, and the knapsack is full.

The bound of a node is computed with the same idea. At node u the decisions already made are fixed: let the profit of u be k, its weight a, and its level i. The items not yet decided, i + 1, i + 2, …, are added whole in ratio order as long as they fit. Let the first item that does not fit be m; the fraction of it that fits is added:

bound(u) = k + Σj = i+1m−1 pj + (W − a − Σj = i+1m−1 wj) · pm / wm

If all the remaining items fit, there is no m and the last term is not added. If the node itself is infeasible, that is, a > W, the bound is taken to be 0. This guarantees that the node can never beat best and will not enter the queue.

Theorem 5.1 (The fractional bound is valid)

If the items are in decreasing order of pi/wi, then for every node u, bound(u) is greater than or equal to the profit of every feasible 0/1 solution in the subtree of u.

Any feasible 0/1 solution in the subtree of u keeps the decisions made at u and chooses a subset of the remaining items. This choice is also a solution of the fractional problem: the fraction of every item is 0 or 1. So the profit of the 0/1 solution cannot exceed the optimal value of the fractional problem built for the remaining items and the remaining capacity W − a. Because the items are in ratio order, the greedy method gives the optimal value of the fractional problem: every unit of remaining capacity is spent on the item that gives the highest profit per unit among the remaining items. Adding k to this value gives bound(u). ∎

The proof has two supports: every 0/1 solution is a fractional solution, and the greedy method is optimal for the fractional problem. The second support depends on the ratio order. If the items are not in ratio order, the greedy method does not find the optimum even for the fractional problem. In that case the computed value can fall below the true optimum and the bound loses its validity.

The bound of the root is computed in the example as follows. Items 1 and 2 fit completely: 40 + 30 = 70, weight 7. Item 3 has weight 10 and does not fit into the remaining 9 units. 9/10 of item 3 is taken: 9 · 50/10 = 45. So bound(root) = 70 + 45 = 115. The meaning of this number is: whichever subset of the four items is chosen, the profit cannot exceed 115. The true optimum is 90; the bound is optimistic but valid.

Common mistake

Forgetting to sort the items by ratio. Suppose the items are given in the order (10, 5), (40, 2), (30, 5), (50, 10) and the bound is computed in that order. At the root the first three items fit completely (weight 12, profit 80); for the remaining 4 units, 4/10 of item 4 is taken: 80 + 20 = 100. This number is smaller than 115 and does not reflect the true fractional optimum. In this example 100 is still greater than 90, but in another example the unsorted computation can fall below the optimum and the right branch is pruned.

5.3.3Code trace: bound(root)

The Java counterpart of the bound function is below. Arrays start at zero: p[0] and w[0] belong to item 1. n is the number of items and W the capacity. The class Node carries the fields level, profit, weight, and bound. The level of the root is −1; no item has been decided yet.

double bound(Node u) {
  if (u.weight > W) return 0;   // infeasible
  double result = u.profit;
  int totalW = u.weight;
  int j = u.level + 1;
  while (j < n && totalW + w[j] <= W) {
    totalW += w[j];
    result += p[j];
    j++;
  }
  if (j < n)                // fractional part
    result += (W - totalW) * (double) p[j] / w[j];
  return result;
}

The lines do the following:

  • if (u.weight > W) return 0; catches an infeasible node. If the weight has exceeded the capacity, there is no feasible solution below the node; the bound of 0 keeps it out of the queue.
  • result starts with the node's own profit and totalW with its own weight. j points to the first undecided item.
  • The while loop adds items whole as long as they fit. The condition has two parts: there must be an item left (j < n) and item j must fit completely into the remaining capacity.
  • When the loop ends, either no items are left or j is the first item that does not fit. In the second case a fractional profit of (W - totalW) * (double) p[j] / w[j] is added. The (double) cast prevents integer division.

For one node the function looks at no more than n items; its time is O(n). It uses no extra memory. Table 5.5 is the trace of the call for the root.

5.3.4Best-first branch and bound, step by step

Now the main example (W = 16) is solved with the best-first strategy. Each node is named with a letter and is given with its “profit / weight” pair and its bound (s). The queue is a priority queue; at each step the node with the largest bound comes out. When a child is generated, if it is feasible and its profit is greater than best, best is updated at once. In the knapsack every feasible node is a valid solution made up of the items taken; there is no need to descend to a leaf to update.

  1. Start. Root A: no item chosen; 0 / 0, s = 115. best = 0. Queue: A (115).
  2. A is removed and branched. B (item 1 taken): 40 / 2, feasible; best = 40. The bound of B is the same as that of the root, because the bound of the root already took item 1 whole: s = 115. C (no item 1): 0 / 0. In the bound computation, items 2 and 3 fit whole: 30 + 50 = 80, weight 5 + 10 = 15. Item 4 does not fit; for the remaining 1 unit, 1 · 10/5 = 2 is added. s = 82. Queue: B (115), C (82).
  3. B is removed and branched. D (item 2 taken): 70 / 7; best = 70, s = 115. E (no item 2): 40 / 2; item 3 fits whole (90, weight 12), 4/5 of item 4 is added (8): s = 98. Queue: D (115), E (98), C (82).
  4. D is removed and branched. F (item 3 taken): weight 7 + 10 = 17 > 16; infeasible, its bound is 0, pruned. G (no item 3): 70 / 7; item 4 fits whole (80, weight 12), no more items: s = 80. Because 80 > 70, G enters the queue. Queue: E (98), C (82), G (80).
  5. E is removed and branched. H (item 3 taken): 90 / 12, feasible; best = 90. The bound of H is 90 + 4 · 2 = 98 and it enters the queue. I (no item 3): 40 / 2; item 4 fits whole: s = 50 ≤ 90, pruned. Queue: H (98), C (82), G (80).

Common mistake

Updating best only at the leaves. In the knapsack every feasible node is a solution: the chosen items go into the knapsack and the rest are not taken. In the trace above best rises to 40 in step 2, to 70 in step 3, and to 90 in step 5. If the update were held back until the leaf, best would stay at 0 for a long time and nodes like I could not be pruned.

5.3.5Java code: branchAndBound()

The Java code of best-first branch and bound is below. PriorityQueue is used as the priority queue.

int branchAndBound() {
  PriorityQueue<Node> queue = new PriorityQueue<>(
      (a, b) -> Double.compare(b.bound, a.bound));
  Node root = new Node(-1, 0, 0);
  root.bound = bound(root);
  queue.add(root);  int best = 0;
  while (!queue.isEmpty()) {
    Node u = queue.poll();           // largest bound
    if (u.bound <= best || u.level == n - 1) continue;
    int i = u.level + 1;
    // left child: take item i
    Node take = new Node(i, u.profit + p[i],
                         u.weight + w[i]);
    if (take.weight <= W && take.profit > best)
      best = take.profit;
    take.bound = bound(take);
    if (take.bound > best) queue.add(take);
    // right child: skip item i
    Node skip = new Node(i, u.profit, u.weight);
    skip.bound = bound(skip);
    if (skip.bound > best) queue.add(skip);
  }
  return best;
}

The important points of the code are these:

  • The comparator is reversed. By default PriorityQueue returns the smallest element first. The comparator (a, b) -> Double.compare(b.bound, a.bound) reverses the order, so poll() returns the node with the largest bound.
  • The second test. The line if (u.bound <= best || u.level == n - 1) continue; catches two things. The first is nodes that have gone stale while waiting in the queue (C and G in the example). The second is nodes at the last level; they have no children. The bound itself does not change in the queue; what changes is best.
  • The left child. The node take adds item i. If the weight does not exceed the capacity and the profit is greater than best, best is updated. Then its bound is computed, and if the bound exceeds best it enters the queue. An infeasible take node has bound 0; it never enters the queue.
  • The right child. The node skip carries its parent's profit and weight unchanged. If the parent is feasible, skip is feasible too and its profit does not change best. So only its bound is checked.
  • Changing the strategy. For FIFO, an ArrayDeque with add()/poll() is used; for LIFO, push()/pop(). The rest of the code is the same.

The code returns only the best value. If the chosen items are wanted as well, a boolean[] array or a bit mask is added to the class Node. Each child copies its parent's array and records its own decision. When best is updated, this array is saved too.

Cost. In the worst case all the nodes of the full tree are generated: O(2n) nodes. At each node the bound computation takes O(n) and the queue operation O(log k). The worst-case time is O(n · 2n). Memory is proportional to the number of nodes in the queue, which in the worst case is also exponential. In practice, with a good bound, the number of nodes generated stays far below this.

5.3.6FIFO branch and bound: code trace

The same example is now solved with a FIFO queue. The code uses an ArrayDeque instead of a priority queue. Children are generated by the helper method child(u, take); the method builds the child and computes its bound as well. The loop first generates the “take” child (take = 1) and then the “skip” child (take = 0).

int fifoBranchAndBound() {
  ArrayDeque<Node> queue = new ArrayDeque<>();
  queue.add(root);  int best = 0;
  while (!queue.isEmpty()) {
    Node u = queue.poll();          // first in
    if (u.bound <= best || u.level == n - 1) continue;

      Node c = child(u, take);        // includes bound(c)
      if (c.weight <= W && c.profit > best)
        best = c.profit;               // new incumbent
      if (c.bound > best) queue.add(c);
    }
  }
  return best;
}

5.3.7Comparing the three strategies

5.4The traveling salesman problem

The traveling salesman problem (TSP) is a minimization problem. As a brief reminder: n cities are given, together with the distance between every pair of cities. We look for the shortest tour that visits every city exactly once and returns to the start. The distances are kept in a matrix d; d[i][j] is the cost of going from i to j. If d[i][j] = d[j][i], the problem is symmetric. The problem is NP-hard and brute force tries (n − 1)! tours. In this section the same four-city example is examined with three different lower bounds.

5.4.1State space and the cheapest-outgoing-edge bound

The tour always starts at city 0. Each node of the state-space tree is a partial path starting at 0. The root contains only 0. The children of a node are obtained by going from the last city of the path to a city not yet visited. Nodes at depth n − 1 contain all the cities; when we return from the last city to 0, the tour is complete.

Because the problem is a minimization, each node needs a lower bound: no tour that completes that partial path can cost less than this value. The simplest lower bound rests on the following observation. To complete the tour, we must leave the current last city and each unvisited city exactly once. Each departure costs at least the cheapest edge of that city. Let the cost of the cheapest outgoing edge of city v be cheapest[v]. These values are computed once before the search begins. The lower bound is:

lower(path) = cost(path) + cheapest[last city] + Σv unvisited cheapest[v]

This bound is a relaxation. In the original problem the outgoing edges must form a single tour. In the relaxation this condition is removed: each city leaves by its own cheapest edge, and whether the edges form a tour is not examined. Because of the removed constraint, the value of the relaxation cannot exceed the cost of any tour.

Theorem 5.2 (The cheapest-outgoing-edge bound is valid)

For every partial path starting at 0, the cost of every tour that completes the path is greater than or equal to lower(path).

Any tour that completes the path contains the edges of the path unchanged; their sum is cost(path). In the rest of the tour, the last city is left once and every unvisited city is left once; there is no other departure. The edge leaving city v costs at least cheapest[v]. Adding these inequalities, the cost of the tour is at least lower(path). ∎

5.4.2Code trace: tsp(0, 0, 1)

Branch and bound for the traveling salesman is written as a bounded depth-first search. It is a LIFO branch and bound; recursion plays the role of the stack.

void tsp(int city, int cost, int count) {
  if (count == n) {           // tour complete
    int tour = cost + d[city][0];
    if (tour < best) best = tour;
    return;
  }
  for (int c = 0; c < n; c++) {
    if (visited[c]) continue;
    int next = cost + d[city][c];
    visited[c] = true;
    if (lowerBound(c, next) < best) // bound
      tsp(c, next, count + 1);
    visited[c] = false;      // unchoose
  }
}

The parameters of the method are the last city of the path (city), the cost of the path (cost), and the number of cities on the path (count). The visited array marks the cities on the path; best is initially infinite. Before the first call, visited[0] = true is set and tsp(0, 0, 1) is called. The lines do the following:

  • if (count == n) is the base case. All the cities are on the path; we return from the last city to 0 and the tour is complete. If the tour is shorter than best, best is updated.
  • The for loop is the branching. Each unvisited city c is a child. Visited cities are skipped by continue; this is the infeasibility rule.
  • visited[c] = true; adds the city to the path. The bound is computed after this marking, so that lowerBound sees city c as “visited” and counts it only as the last city.
  • if (lowerBound(c, next) < best) is the bound rule. If the lower bound is less than best, the branch is entered; otherwise it is pruned.
  • visited[c] = false; is the undo. The path returns to its old state before the loop moves on to the next city.

5.4.4A tighter bound: the two shortest edges

The cheapest-outgoing-edge bound counts only one edge per city. But in a tour each city is entered by one edge and left by one edge. In a symmetric problem there is no distinction between entering and leaving: every city touches exactly two edges of the tour. The sum of these two edges of a city cannot be smaller than the sum of the two shortest edges touching it. If this observation is summed over all the cities, each tour edge is counted twice: once at one end and once at the other. This gives a tighter lower bound:

tour ≥ ½ · Σv (the sum of the two shortest edges touching v)

Theorem 5.3 (The two-shortest-edges bound)

In a symmetric traveling salesman problem, the cost of every tour cannot be smaller than half of the sum, over all cities, of the two shortest edges touching each city.

Let T be a tour. Every city v touches exactly two edges of T; if the sum of these two edges is called t(v), then Σv t(v) = 2 · cost(T), because each edge is counted once at each of its ends. Let the sum of the two shortest edges touching v be e(v). Both edges of T touching v are edges touching v; their sum cannot be smaller than e(v): t(v) ≥ e(v). Summing gives 2 · cost(T) ≥ Σv e(v). ∎

The code that computes this bound at the root is:

double twoEdgeBound() {
  int total = 0;
  for (int v = 0; v < n; v++) {
    int m1 = INF, m2 = INF;     // two smallest
    for (int u = 0; u < n; u++) {
      if (u == v) continue;
      if (d[v][u] < m1) { m2 = m1; m1 = d[v][u]; }
      else if (d[v][u] < m2) m2 = d[v][u];
    }
    total += m1 + m2;
  }
  return total / 2.0;  // each edge twice
}

The outer loop goes through the cities. The inner loop finds, among the edges touching the city, the two smallest values, with m1 ≤ m2. If a new edge is smaller than m1, the old m1 moves to second place and the new edge becomes first. If it is smaller only than m2, it is written to second place. This is the update of a two-element “smallest values list.” Because the total counts every edge twice, the result is divided by 2.0; double division keeps the half if the total is odd. The time is O(n2).

Since at the root the bound equals the optimum, as soon as the first complete tour is found all the remaining branches are pruned by the condition lower ≥ best. On partial paths the same idea is applied by fixing the edges on the path. One or both of the edges of a city on the path are already known. The shortest edges are sought only for those that are missing.

5.4.5The reduced cost matrix

A third lower bound looks at the rows and columns of the cost matrix. The idea is this. Every tour uses exactly one cell from each row of the matrix (a departure from a city) and exactly one cell from each column (an arrival at a city). If the same number is subtracted from all the cells of a row, the cost of every tour decreases by exactly that number. The ordering of the tours does not change. The sum of the numbers subtracted from the rows and columns has been taken off the cost of every tour. Because the remaining matrix is nonnegative, this sum is a lower bound.

The procedure is as follows. The diagonal is set to ∞; one cannot go from a city to itself. From each row the minimum of that row is subtracted. Then from each column the minimum of that column is subtracted. In the end every row and every column contains at least one 0. This matrix is called the reduced cost matrix.

int reduce(int[][] m) {
  int total = 0;
  for (int i = 0; i < n; i++) {       // rows
    int mn = rowMin(m, i);
    if (mn > 0 && mn < INF) {
      subtractRow(m, i, mn); total += mn;
    }
  }
  for (int j = 0; j < n; j++) {       // columns
    int mn = colMin(m, j);
    if (mn > 0 && mn < INF) {
      subtractCol(m, j, mn); total += mn;
    }
  }
  return total;
}

rowMin, subtractRow, colMin, and subtractCol are simple helper methods. The subtraction is applied only to cells that are not ∞. The condition mn > 0 skips subtracting zero. The condition mn < INF skips rows and columns that are entirely ∞; such rows arise during branching. The method modifies the matrix in place and returns the total subtracted. Both passes take O(n2).

The reduced matrix method rests on the paper published by Little and colleagues in 1963. The method has an important advantage: it does not require symmetry. It is valid for asymmetric problems with d[i][j] ≠ d[j][i] as well. One-way streets, or vehicles that burn different amounts of fuel uphill and downhill, are examples of asymmetric problems. The two-shortest-edges bound, by contrast, depends on symmetry and cannot be used directly in an asymmetric problem.

5.5The assignment problem

The assignment problem is suitable for showing the minimization direction of branch and bound on a small, easy-to-follow example. The code structure is very similar to the traveling salesman search; the bound is even simpler.

5.5.1The problem and a lower bound

Definition 5.4

The assignment problem: given n people and n jobs, c[i][j] is the cost of person i doing job j. Each person is given a different job so that the total cost is minimized.

Each assignment is a permutation of the jobs; there are n! possible assignments. At level i of the state-space tree, person i is given a job that nobody has yet been given. The root is the state in which no person has a job; the leaves are complete assignments.

The lower bound rests on the following observation: every person who has not yet been given a job pays at least the smallest cost in their own row. This is a relaxation. The constraint “a single person per job” is removed; two people may choose the same cheap job. Because job clashes are ignored, the bound cannot rise above the true cost. To compute the bound quickly at every node, the suffix sums of the row minima are kept in advance:

remainingMin[i] = Σr ≥ i minj c[r][j],   remainingMin[n] = 0

After person i has been given a job, if the cost of the path is next, the lower bound of that node is next + remainingMin[i + 1]. The computation takes O(1). If lower ≥ best, the branch is cut.

void assign(int i, int cost) {
  if (i == n) {                     // complete assignment
    best = Math.min(best, cost);
    return;
  }
  for (int j = 0; j < n; j++) {
    if (used[j]) continue;
    int next = cost + c[i][j];
    if (next + remainingMin[i + 1] >= best)
      continue;                     // bound
    used[j] = true;
    assign(i + 1, next);
    used[j] = false;          // unchoose
  }
}

The structure of the method is the same as that of the tsp method. i is the next person and cost is the total of the assignments made so far. The used array marks the jobs already given; this is the infeasibility rule. The bound test is made before a job is added to the partial assignment. If the branch is cut, used never changes, so no undo is needed. In the base case best is updated with Math.min.

5.6Integer linear programming

The most widespread industrial use of branch and bound is integer linear programming. The method was put forward in this field in the 1960 paper of Land and Doig. Today the commercial software that solves production planning, scheduling, and distribution problems uses advanced versions of the same idea.

5.6.1The problem and the LP relaxation

Definition 5.5

Integer linear programming (ILP) is the problem of maximizing or minimizing a linear objective function subject to linear inequality constraints. All the variables are required to be integers.

Without the integrality condition the problem would be an ordinary linear program (LP). Linear programs are solved very fast in practice by the simplex method, and in polynomial time by interior-point methods. In small examples with two variables the solution can be found graphically: the constraints define a polygon in the plane (the feasible region), and the best value is attained at one of the corners of this polygon. The integrality condition is what makes the problem NP-hard.

Branch and bound combines these two facts:

  • Bound: The integrality condition is removed and the LP relaxation is solved. The feasible region of the relaxation contains all the integer points. So in maximization the LP optimum is an upper bound for the ILP optimum.
  • Branching: If a variable in the LP solution is fractional, for example y = 1.5, two subproblems are built: the constraint y ≤ 1 is added to one and y ≥ 2 to the other. The fractional region in between, 1 < y < 2, is thrown away. Since there are no integer points in this region, no integer solution is lost.
  • Completeness: If the LP solution of a node is already integral, there is no better integer solution below that node. This solution becomes a candidate and the node is closed.

The example problem is:

maximize Z = 5x + 4y;   6x + 4y ≤ 24,   x + 2y ≤ 6,   x, y ≥ 0 integers

The optimum of the LP relaxation is at the intersection of the two constraint lines. 6x + 4y = 24 and x + 2y = 6 are solved together. Multiplying the second equation by 2 and subtracting it from the first gives 4x = 12, that is, x = 3; from this y = 1.5. The value is Z = 15 + 6 = 21. The other corners are (0, 0), (4, 0), and (0, 3); their values are 0, 20, and 12. Figure 5.16 shows the region and the two optima.

5.6.2Branching with LP relaxations

The branch and bound tree is built step by step as follows:

  1. Root. The LP optimum is (3, 1.5), Z = 21. This value is an upper bound: no integer solution can exceed 21. y is fractional; we branch on y.
  2. Branch y ≤ 1. In the new LP we press against the limit y = 1. From 6x + 4 ≤ 24 comes x ≤ 3.33, and from x + 2 ≤ 6 comes x ≤ 4. The LP optimum is (3.33, 1), Z = 20.67. x is fractional; the branches x ≤ 3 and x ≥ 4 are opened.
  3. Branch y ≤ 1, x ≤ 3. The LP optimum is (3, 1), Z = 19. The solution is integral: the first candidate, best = 19.
  4. Branch y ≤ 1, x ≥ 4. The constraint 6 · 4 + 4y ≤ 24 forces y = 0. The LP optimum is (4, 0), Z = 20. It is integral and 20 > 19: best = 20.
  5. Branch y ≥ 2. The constraint x + 2y ≤ 6 forces x ≤ 2. The LP optimum is (2, 2), Z = 18. Because 18 ≤ 20, the branch is pruned. Even if the LP solution of this branch were integral, it could not beat best.

The optimum is x = 4, y = 0, Z = 20. This example also shows why rounding the LP solution is not enough. If (3, 1.5) is rounded down, (3, 1) is obtained and Z = 19; it is not the best. If it is rounded up, (3, 2) is obtained: 6 · 3 + 4 · 2 = 26 > 24, which is infeasible. The true optimum (4, 0) is not near the LP point; it is found only by branching.

Common mistake

Branching wrongly on a fractional variable. For y = 2.6 the correct subproblems are y ≤ 2 and y ≥ 3. Branching as y = 2 and y = 3 loses all the other values of y. Branching as y ≤ 2.6 and y ≥ 2.6 leaves the existing LP solution in both subproblems and the search makes no progress. y ≤ 3 and y ≥ 2, in turn, give two overlapping subproblems; the same points are searched twice.

A second example shows the completeness rule: maximize Z = 3x + 2y; x + y ≤ 4, x ≤ 3, y ≤ 2. Brute force tries all 12 points of the grid 0 ≤ x ≤ 3, 0 ≤ y ≤ 2 and finds Z = 11 at the point (3, 1). The optimum of the LP relaxation is also (3, 1): the corner resting on the limit of x (3) and the line x + y ≤ 4. Because the solution is already integral, branch and bound ends at the root; a single LP has been solved.

Real software improves this basic scheme in several directions. The fractional variable to branch on is chosen intelligently. Extra constraints (cutting planes), which cut off the fractional solution without cutting off integer points, are added to the LP relaxation. This combination is called branch and cut. In addition, the LP of a subproblem is re-solved in a few steps starting from the solution of its parent.

5.7Maximum clique

The last application is a graph problem. The clique problem is used to find tightly connected groups in social networks, clusters of interacting proteins in biology, and error-correcting codes in coding theory.

5.7.1The problem and the bound

Definition 5.6

In an undirected graph, a set of vertices in which every two vertices are adjacent is called a clique. The maximum clique problem is the problem of finding the clique with the most vertices.

The problem is NP-hard. The search grows the current clique K step by step. The vertices that can be added to K are called candidates. For a vertex to be a candidate, it must be adjacent to all the vertices in K. To prevent the same clique from being generated again and again in different orders, vertices are added in increasing order of number: only vertices with a number greater than the last vertex added to K can be candidates.

The bound is a maximization bound and is very simple. In the best case K grows with all the candidates. So the largest clique that can be found in this branch cannot exceed |K| + |candidates| vertices. If |K| + |candidates| ≤ |best|, the current clique cannot beat best however far it is extended; the branch is pruned. The bound is valid, because every clique in the branch is the union of K and a subset of the candidates.

void clique(List<Integer> K, int start) {
  if (K.size() > best.size())
    best = new ArrayList<>(K);
  List<Integer> cands = new ArrayList<>();
  for (int v = start; v < n; v++)
    if (compatible(v, K)) cands.add(v);  // adjacent to K
  if (K.size() + cands.size() <= best.size())
    return;                        // bound
  for (int v : cands) {
    K.add(v);
    clique(K, v + 1);
    K.remove(K.size() - 1);        // unchoose
  }
}

The lines of the method work as follows:

  • The first two lines update best. A clique is a feasible solution at every moment; there is no need to descend to a leaf. new ArrayList<>(K) makes a copy, because K changes during the rest of the search.
  • The for loop collects the candidates. compatible(v, K) checks whether v is adjacent to every vertex in K. The loop starts at start; smaller numbers have already been tried.
  • if (K.size() + cands.size() <= best.size()) return; is the bound rule.
  • The last loop is the branching. Each candidate is added to K in turn, the search continues from v + 1, and the candidate is removed again.

In one call the candidate list is built in O(n · |K|) time; if adjacency is kept in a matrix, each compatible check is O(|K|). Without the bound line, the method is ordinary backtracking and traverses all the cliques.

5.7.3A tighter bound: coloring

The bound |K| + |cands| assumes that every candidate can enter the clique. If there are non-adjacent pairs among the candidates, this assumption is very optimistic. A tighter bound comes from graph coloring. Every pair of vertices of a clique is adjacent; so all the vertices in a clique must receive different colors. If the candidates can be properly colored with k colors, at most k of the candidates can enter the same clique. The new bound is: if |K| + colors(cands) ≤ |best|, the branch is pruned.

Finding the minimum number of colors is also NP-hard. But the best coloring is not needed. Greedy coloring goes through the vertices in order and gives each vertex the smallest color not used among its neighbors. It takes O(cands2). It may use extra colors; this only loosens the bound, it does not invalidate it. The bound still cannot exceed |cands|, because in the worst case each vertex gets its own color.

In the example in Figure 5.20 the candidates form a ring of five vertices; K is empty and |best| = 3. The old bound gives 0 + 5 = 5 > 3 and the branch is opened. Greedy coloring gives vertex 0 color 1, vertex 1 color 2, vertex 2 color 1, and vertex 3 color 2. Vertex 4 is adjacent to both 3 and 0; it takes color 3. The color bound gives 0 + 3 ≤ 3 and the branch is pruned. The largest clique in the ring has only 2 vertices anyway. Most of the fastest exact clique algorithms rest on this idea. Tomita's MCQ and MCS algorithms try the candidates in color order and prune with the color bound.

5.8Other problems and the relation to A*

5.8.1Other problems solved by branch and bound

The method can be applied to almost any optimization problem whose solution is built from a sequence of decisions. The two questions to ask in each application are the same: how is the branching done, and which relaxation gives a valid bound?

  • Hamiltonian path. We look for a path that visits every vertex exactly once. The weighted version is very similar to the traveling salesman and is solved with similar bounds.
  • Boolean satisfiability (SAT). Truth values are assigned to the variables; partial assignments that contradict are pruned. This is the essence of the DPLL algorithm. In the maximum SAT version we want as many clauses as possible to be true; the bound is the largest number of clauses that can still be satisfied by the remaining assignments.
  • Scheduling. Jobs are distributed among machines; the maximum load (makespan) or the total tardiness is minimized. The lower bound is the load the remaining jobs would create in the best case; for example, splitting the total of the remaining jobs equally among the machines.
  • Bin packing. Items are placed into the smallest number of bins. The lower bound is ⌈Σ size / bin capacity⌉: even if the bins were filled perfectly, this many bins would be needed.
  • Maximum coverage. k sets are chosen that cover the most elements. The upper bound is the number of elements the largest remaining sets can add.
  • The assignment problem and its variants with extra constraints. The lower bound is the smallest cost of each unassigned row.

Branch and bound is meaningful for NP-hard problems. For problems with a known polynomial-time algorithm, such as maximum flow, shortest path, or minimum spanning tree, there is no need for branch and bound. For these problems the polynomial algorithm is always preferred; branch and bound takes exponential time in the worst case.

When choosing a paradigm for a problem, the questions are asked in a certain order. Are the subproblems independent? Then divide and conquer is suitable. Do the subproblems overlap, and is their number polynomial? Dynamic programming is suitable. Does the locally best choice lead to the global best, and can this be proved? The greedy approach is suitable. If none of these holds and the problem is NP-hard, two options remain. If an exact result is wanted, backtracking or branch and bound is used. If an approximate result of guaranteed quality in polynomial time is enough, an approximation algorithm is used.

The same problem can be solved with more than one paradigm. The 0/1 knapsack is a good example. Dynamic programming solves it in O(nW); if the capacity is small, it is the best choice. If the capacity is very large or the weights are fractional, branch and bound comes to the fore. The greedy method, on the other hand, does not guarantee the optimum in the 0/1 version; it is correct only in the fractional version. Branch and bound takes this greedy method inside itself as a bound computation. The paradigms are not rivals of one another; they are often used as parts inside one another.

5.10Common mistakes

  • Using an invalid (pessimistic) bound. In the knapsack, adding up the profits of just the items that fit completely is not an upper bound; it is the value of a feasible solution. The branch containing the optimum can be pruned, and the algorithm returns a wrong result without raising any error.
  • Mixing up the direction. In maximization a node is pruned when bound ≤ best, in minimization when lower ≥ best. Writing the reverse either misses the optimum or never prunes. Remember also that best must start at +∞ in minimization and at −∞ or 0 in maximization.
  • Not testing again after leaving the queue. The node looked promising when it was added. If best grew while it waited, it is now unnecessary. In the knapsack example C and G are such nodes. Without the second test the result does not change, but unnecessary nodes are expanded.
  • Not sorting the items. The fractional bound may not be a valid upper bound if the items are not in decreasing order of the ratio pi/wi.
  • Updating best only at the leaves. In the knapsack and in clique, every feasible node is a solution. Updating early raises best quickly and brings more pruning.
  • Taking branch and bound to be the same as backtracking. Code with no bound test, for example an unpruned TSP search, is not branch and bound; it traverses the whole tree.
  • Forgetting to undo. In recursive versions, if the line visited[c] = false, used[j] = false, or K.remove(...) is forgotten, later branches run with a wrong state and feasible solutions are lost.
  • Storing best without copying. In the clique search, writing best = K stores the list that keeps changing. When the search ends, best shows an empty list. A copy (new ArrayList<>(K), path.clone()) is essential.

5.11Summary

  • Branch and bound traverses the solution space of an optimization problem as a state-space tree. The loop is: a live node is selected, its bound is tested again, the node is branched, the bounds of the children are computed, and the hopeless ones are pruned. best holds the value of the best complete solution found so far.
  • The bound must be valid (optimistic), tight, and cheap. Validity is mandatory; tightness and cheapness determine efficiency. The bound is mostly built by relaxation. An upper bound is used in maximization and a lower bound in minimization.
  • A node is pruned for three reasons: infeasibility, an insufficient bound (bound ≤ best or lower ≥ best), and completeness (a leaf, or an LP solution that turns out integral). The bound rule is what separates branch and bound from backtracking.
  • FIFO traverses breadth-first and uses a queue. LIFO traverses depth-first, uses a stack or recursion, and needs little memory. LC (best-first) selects the most promising node with a priority queue and usually generates the fewest nodes. All three find the same optimum.
  • In the knapsack the fractional knapsack relaxation gives the upper bound. In the example bound(root) = 115 and the optimum is 90. Best-first generates 11 of the 31 nodes, FIFO and LIFO 13.
  • In the traveling salesman problem, the cheapest-outgoing-edge bound adds to the cost of the path the cheapest departures of the last city and of the unvisited cities. With four cities 10 nodes are generated instead of 16. The reduced matrix (14) and the two shortest edges (18) are tighter but take O(n2) per node.
  • In assignment the lower bound is the sum of the row minima of the remaining people. In integer programming the LP relaxation gives the upper bound, and a fractional variable is branched into two subproblems. In clique the bound |K| + |cands| ≤ |best| is used; coloring gives a tighter bound.
  • The method is exponential in the worst case. Its practical success depends on the quality of the bound. It is not used for problems that have a polynomial algorithm.
  • Independent subproblems lead to divide and conquer, overlapping subproblems to dynamic programming, and a proven greedy choice to the greedy approach. For an exact result on an NP-hard problem, backtracking or branch and bound is used.

5.13Test Yourself

  1. Let the items (p, w) be (30, 3), (40, 5), (45, 9), (10, 4) and W = 12. What is the fractional upper bound of the root? Which nodes does best-first branch and bound expand, how many nodes does it generate, and what is the optimum?

    Answer

    The ratios are 10, 8, 5, 2.5; the items are in order. At the root items 1 and 2 fit whole (70, weight 8); 4/9 of item 3 is taken: 4 · 45/9 = 20. bound(root) = 90. The root is expanded: B (item 1 taken) 30/3, bound 90, best = 30; C (no item 1) bound 40 + 7 · 5 = 75. B is expanded: D 70/8, bound 90, best = 70; E 30/3, bound 75. D is expanded: the “take” child 115/17 is infeasible; G (no item 3) 70/8, bound 70 + 10 = 80. G is expanded: H (item 4 taken) 80/12, best = 80; the bound of H is 80 and it does not enter the queue. I (no item 4) has bound 70 and is pruned. E (75) and C (75) in the queue are discarded. 4 expansions (A, B, D, G), 9 nodes. The optimum is 80: items 1, 2, and 4.

  2. If the same example is solved with a FIFO queue, how many nodes are generated and how many are expanded? Where does the difference come from?

    Answer

    FIFO generates 13 nodes and expands 6: A, B, C, D, E, and G. The result is again 80. FIFO expands C (bound 75) early, in level order; at that moment best is only 70 and C cannot be discarded. E is also expanded; its child 75/12 is not infeasible and raises best to 75. Best-first leaves C and E to the end; by then best is 80 and both are discarded.

  3. Let the symmetric distances be d(0,1) = 10, d(0,2) = 15, d(0,3) = 20, d(1,2) = 35, d(1,3) = 25, d(2,3) = 30. What are the cheapest-outgoing-edge, reduced matrix, and two-shortest-edges bounds at the root? How long is the shortest tour?

    Answer

    The cheapest departures are 10, 10, 15, 20: the bound is 55. In the reduction the row minima are 10 + 10 + 15 + 20 = 55. After the row reduction, the minimum in column 2 is 5 and in column 3 is 10: the bound is 55 + 5 + 10 = 70. The sums of the two shortest edges are 25, 35, 45, 45: 150 / 2 = 75. The shortest tour is 0 → 1 → 3 → 2 → 0: 10 + 25 + 30 + 15 = 80. The order is again cheapest outgoing edge ≤ reduced matrix ≤ two edges ≤ optimum. With the cheapest-outgoing-edge bound, the tsp search generates 15 of the 16 nodes in this example; the loose bound prunes almost nothing.

  4. For the assignment problem with cost matrix [[4, 7, 3], [2, 6, 1], [3, 9, 4]], what is remainingMin? What is the optimal assignment, and how many calls does assign(0, 0) make?

    Answer

    The row minima are 3, 1, 3: remainingMin = [7, 4, 3, 0]; the lower bound of the root is 7. The search finds complete assignments of cost 14, 13, and 11 in turn. The optimum is p0 → job 1 (7), p1 → job 2 (1), p2 → job 0 (3), with a total of 11. The search makes 12 calls; a search without pruning makes 16. In this example the first branch (p0 → job 0) is bad, so pruning starts late.

  5. Maximize Z = 3x + 5y; x + 2y ≤ 7, 3x + y ≤ 9, x, y ≥ 0 integers. How does the tree take shape when branch and bound is applied with LP relaxations (branching first on y, then on x if it is fractional)?

    Answer

    Root: the intersection of the two lines (2.2, 2.4), Z = 18.6; y is fractional. Branch y ≤ 2: (2.33, 2), Z = 17; x is fractional. Below it, x ≤ 2: (2, 2), Z = 16, integral, best = 16. x ≥ 3: (3, 0), Z = 9 ≤ 16, pruned. Branch y ≥ 3: (1, 3), Z = 18, integral, best = 18. The optimum is x = 1, y = 3, Z = 18. Rounding the LP solution down would have given (2, 2) and 16.

  6. What is the largest clique in the graph with edges 0–1, 0–2, 0–3, 1–2, 1–3, 2–3, 3–4, 3–5, 4–5? How many calls does the method clique make with and without the bound?

    Answer

    The largest clique is {0, 1, 2, 3} (4 vertices). The bounded search makes 13 calls and the unbounded search 22. The number of unbounded calls is the number of cliques, counting the empty set: the 16 subsets of {0, 1, 2, 3} plus {4}, {5}, {3, 4}, {3, 5}, {4, 5}, {3, 4, 5}. In the bounded search, after {0, 1, 2, 3} has been found, for example the branch K = {3}, cands = {4, 5} is cut by 1 + 2 ≤ 4.

  7. If, in the knapsack bound, the profits of all the remaining items are added instead of the fractional piece, is the bound valid? What does it give at the root in the W = 16 example?

    Answer

    It is valid: no 0/1 solution can earn more than taking all the remaining items. But because it ignores the capacity entirely, it is very loose. At the root it gives 40 + 30 + 50 + 10 = 130; the fractional bound is 115. A looser bound prunes less; the result stays correct but more nodes are generated.

  8. In the best-first knapsack code, if the comparator is mistakenly written as Double.compare(a.bound, b.bound), does the result stay correct? What changes?

    Answer

    The result stays correct. As long as the pruning rule and the bound are valid, the optimum is not lost whatever the order of traversal. What changes is the order: at each step the node with the smallest bound comes out of the queue. The search busies itself with the most hopeless branches and best rises late. So more nodes are expanded; the strategy is no longer “best first” but “worst first.”
