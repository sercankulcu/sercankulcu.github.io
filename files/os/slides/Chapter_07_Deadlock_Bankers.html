Resource-Request Algorithm

How Banker’s Algorithm Works

1. Compute Need = Maximum − Allocation.

2. Set Work = Available and mark every process unfinished.

3. Find an unfinished process whose Need is less than or equal to Work.

4. Pretend that process finishes, then add its Allocation back into Work.

5. If every process can finish, the state is safe. Otherwise, no safe sequence exists from the current state.

Tie rule: this simulator scans P0, P1, … in index order and, during each pass, lets every process whose Need fits in Work finish; passes repeat until no process can proceed. Other scan orders can yield a different (equally valid) safe sequence.

Resource request by Pi: (1) if Request > Need, raise an error (the process exceeded its maximum claim); (2) if Request > Available, Pi must wait; (3) otherwise pretend to allocate: Available −= Request, Allocation[i] += Request, Need[i] −= Request; (4) run the safety algorithm — if the new state is safe, grant the request; otherwise restore the old state and Pi waits.

A safe state guarantees that no deadlock will occur: there is at least one completion order in which every process can finish. An unsafe state does not necessarily mean a deadlock has occurred; it only means the system can no longer guarantee to avoid one.
