Concept Guide

Polling: the CPU repeatedly checks device status. Simple, but wastes CPU cycles while the device is not ready.

Interrupt-driven I/O: the CPU starts the operation and continues other work. The controller interrupts the CPU each time a unit (word or character) is ready, so an n-unit transfer causes n interrupts, and the handler copies each unit.

DMA: the CPU configures a DMA transfer, then a controller moves blocks directly between memory and the device. The CPU is interrupted only once, when the whole block has been transferred.

This is a conceptual simulator rather than a cycle-accurate hardware model. Its purpose is to make control flow and CPU involvement visible.
