The umask lists the bits that are removed from the default creation mode: umask 022 gives files 644 and directories 755; umask 033 gives files 644 and directories 744; umask 077 gives 600 and 700. It is a bit mask, not a subtraction.

Concept Guide

Owner / Group / Others: the kernel picks exactly one class, in order: if the user owns the file, the owner bits are used; otherwise, if the user belongs to the file's group, the group bits are used; otherwise the others bits are used. The first match wins and the other classes are never consulted, so with mode 044 the owner cannot read the file even though everyone else can.

r = 4, w = 2, x = 1: add the enabled bits to obtain each octal digit. A leading fourth digit holds setuid = 4, setgid = 2, sticky = 1.

On directories: r lists the names in the directory, w creates, deletes, or renames entries (and needs x too), and x means search/traverse: entering the directory with cd and reaching files inside it by name.

Special bits: setuid on an executable runs it with the file owner's user ID (e.g. passwd, mode 4755); setgid runs it with the file's group, and on a directory makes new files inherit the directory's group; the sticky bit on a directory (e.g. /tmp, 1777) lets users delete only their own files. In ls -l they appear as s/t in the execute position, or S/T when the underlying x bit is off.

Example: chmod 640 file.txt means owner can read/write, group can read, and others have no permissions.

Least privilege: give users and processes only the permissions they actually need.

This simulator models basic discretionary access control for ordinary users; it does not model root's override, sticky-bit deletion checks, or path traversal of parent directories. Real systems may also apply ACLs, capabilities, SELinux/AppArmor policies, namespaces, and other security layers.
