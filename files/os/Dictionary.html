Operating Systems Dictionary

Terms used in the course, each with a short definition and the chapter where it is explained. The chapter column links to that chapter's lecture notes.

TermDefinitionChapter
abstractionHiding the complicated details of hardware and presenting concepts such as processes, files, and address spaces instead.1 · Introduction
access control list (ACL)A list that states who may access an object and with which rights.13 · Security
access matrixA protection model whose rows are domains and columns are objects, with the permitted rights stored in each cell.13 · Security
address spaceThe set of memory addresses that a process can use.2 · Operating-System Structures
address space layout randomization (ASLR)Choosing the addresses of code, stack, and libraries at random on every run to make attacks harder.13 · Security
agingRaising the priority of a waiting process over time to prevent starvation; also a counter technique in page replacement.5 · CPU Scheduling
Amdahl's lawThe law stating that the serial part of a program limits the maximum speedup from parallelism.4 · Threads
application programming interface (API)The library functions a programmer calls, which use system calls underneath.2 · Operating-System Structures
atomic instructionA hardware instruction that performs a read and a write without being interrupted (TSL, XCHG, CAS).6 · Synchronization
authenticationVerifying that a user is who they claim to be.13 · Security
authorizationThe step that decides which resources an authenticated user may access and with which rights.13 · Security
backing store (swap space)The disk area that holds pages not currently in memory.9 · Virtual Memory
banker's algorithmAn avoidance algorithm that knows maximum claims in advance and allows only safe states.7 · Deadlocks
barrierA synchronization tool that makes a group of processes or threads meet at a point; none may pass until all have arrived.6 · Synchronization
base and limit registersRegisters that hold the start and the size of a process's memory region.8 · Memory Management
batch systemAn early type of system in which jobs run one after another without user interaction.1 · Introduction
Belady's anomalyThe fact that with FIFO, increasing the number of frames can increase the number of page faults.9 · Virtual Memory
binding timeThe moment when a name is bound to an object: compile time, load time, or run time.14 · Operating-System Design
bitmapA structure that records free or used status with one bit per unit.8 · Memory Management
block / character deviceClasses of devices that transfer data as addressable blocks or as a stream of bytes.11 · Input/Output
blocking / nonblocking / asynchronous I/OI/O interfaces that make the caller wait, return immediately, or notify the caller when finished.11 · Input/Output
bootingThe process that starts from firmware at power-on and loads the kernel into memory.2 · Operating-System Structures
bootloaderA small program that runs after the firmware and loads the kernel (GRUB).15 · Linux
bounded waitingThe condition that a process waits only a bounded number of turns before entering its critical section.6 · Synchronization
Brooks's lawThe observation that adding people to a late software project makes it later.14 · Operating-System Design
buddy systemAn allocator that splits memory into power-of-two blocks and merges buddy blocks.9 · Virtual Memory
buffer / bufferingHolding transferred data temporarily in memory.11 · Input/Output
buffer cacheA cache that keeps disk blocks in memory.10 · File Systems

busA shared communication line that connects components (PCIe, USB).11 · Input/Output
busy waitingWaiting by repeatedly testing a condition in a loop; it consumes CPU time.6 · Synchronization
cacheA memory that holds frequently used data at a faster level.8 · Memory Management
cache coherenceKeeping copies of the same data in different caches consistent.12 · Multiprocessor Systems
cache hit / missThe wanted data is found in the cache (hit) or not found (miss).8 · Memory Management
cache lineThe smallest block transferred between cache and memory (usually 64 bytes).8 · Memory Management
capabilityAn unforgeable token held by a process that grants access to an object with specific rights.13 · Security
cascading terminationTerminating all children when a parent process terminates; in UNIX the children are instead adopted by a new parent.3 · Processes
certificateA document that proves, with a trusted authority's signature, to whom a public key belongs.13 · Security
certificate authority (CA)An organization that vouches with its signature that the public key in a certificate belongs to its owner.13 · Security
checkpointThe moment when a process's state is saved to disk; after a deadlock the process can be rolled back to this point.7 · Deadlocks
circular waitProcesses waiting for one another in a way that forms a cycle.7 · Deadlocks
client–server modelA structure in which services run in server processes and exchange messages with clients.2 · Operating-System Structures
clock algorithmAn implementation of second chance using a circular list and a hand (pointer).9 · Virtual Memory

Coffman conditionsMutual exclusion, hold and wait, no preemption, and circular wait.7 · Deadlocks
compactionShifting used regions together to merge the free space.8 · Memory Management
compare-and-swap (CAS)An atomic instruction that writes a new value if the value at the address equals the expected one, and always returns the old value.6 · Synchronization

compression (lossy / lossless)Representing data with fewer bits, with or without losing information.9 · Virtual Memory
concurrencySeveral activities making progress interleaved over time; they need not run at the same instant.3 · Processes
condition variableAn object on which a thread waits with wait until a condition holds and is woken with signal.6 · Synchronization
conditional compilationIncluding or leaving out parts of the code at compile time according to preprocessor conditions.14 · Operating-System Design
confidentiality / integrity / availability (CIA)The three basic goals of security.13 · Security
containerA group of processes that share the same kernel but are isolated with namespaces and cgroups.12 · Multiprocessor Systems
context switchSaving the state and loading a new one in order to move the CPU from one process to another.3 · Processes
contiguous allocationGiving each process (or file) a single, consecutive region.8 · Memory Management
control group (cgroup)A Linux mechanism that limits and measures the CPU, memory, and I/O use of groups of processes.15 · Linux

cooperative multitaskingAn arrangement in which the operating system can take back the processor only when the program yields it or makes a system call.3 · Processes
copy-on-write (COW)Copying a shared page only when one of the sharers writes to it.9 · Virtual Memory

covert channelA channel that leaks information along a path the security policy did not anticipate.13 · Security
CPU burstThe time a process uses the CPU continuously between two I/O operations.5 · CPU Scheduling
CPU schedulingDeciding which of the ready processes gets the CPU.5 · CPU Scheduling
CPU-bound / I/O-boundA process that spends most of its time computing or waiting for I/O, respectively.3 · Processes
critical section (region)The piece of code that accesses shared data and that only one process may be in at a time.6 · Synchronization
crossbar switchAn interconnect that joins every processor to every memory module with a separate crosspoint; it is conflict-free but expensive.12 · Multiprocessor Systems
C-SCANA SCAN variant that serves in one direction only: on reaching the end, the head returns to the start of the disk without serving.11 · Input/Output
data / task parallelismIn data parallelism the data is split and each core performs the same operation on its part; in task parallelism each core runs a different task.4 · Threads

deadlock preventionMaking one of the four conditions structurally impossible.7 · Deadlocks

demand pagingBringing pages into memory only when they are first accessed.9 · Virtual Memory

digital signatureA digest signed with a private key and verified with the public key.13 · Security

direct memory access (DMA)A controller transferring data directly to memory without keeping the CPU busy.11 · Input/Output
directoryA special file that maps file names to files.10 · File Systems
directory entryA record in a directory that maps a name to an i-node number.10 · File Systems
discretionary access control (DAC)Access control in which the owner of an object decides who gets which permission.13 · Security

entry / exit / remainder sectionThe code that asks permission before entering the critical section, the code that announces leaving it, and the rest of the code.6 · Synchronization
